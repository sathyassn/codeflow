# Commit Format

**Purpose:** Format requirements and structure for conventional commits. Reference when creating any commit to ensure proper type selection, subject formatting, and body structure.

**These rules are automatically enforced by git hooks** (`commit-msg`, `pre-commit`) and GitHub workflows. Invalid commits will be blocked.

## Format Structure

```text
type: subject description

- First bullet point (optional)
- Second bullet point (optional)
- Third bullet point (optional)
```

## Subject Line Requirements

**REQUIRED:**

- **Maximum 50 characters** (strictly enforced by hooks)
- **No period at end**
- **Imperative mood** ("add" not "added", "fix" not "fixed")
- **Lowercase type prefix**
- **Lowercase first word of description**

**Example:**

```text
feat: add progressive disclosure for skills
```

## Message Body (Optional)

**REQUIRED (if body included):**

- **Maximum 3 bullet points**
- **72 characters per line** (strictly enforced)
- **One blank line after subject**
- **Focus on what and why, not how**

## Commit Types

| Type | Purpose | Example |
|------|---------|---------|
| `feat` | New feature or capability | `feat: add worktree isolation` |
| `fix` | Bug fix | `fix: correct permission validation` |
| `bugfix` | Bug fix (alias for fix) | `bugfix: resolve edge case` |
| `hotfix` | Urgent production fix | `hotfix: patch security issue` |
| `docs` | Documentation only | `docs: update agent framework` |
| `refactor` | Code restructuring (no behavior change) | `refactor: simplify session logs` |
| `test` | Add or update tests | `test: add commit format validation` |
| `chore` | Maintenance, dependencies | `chore: update markdownlint` |
| `style` | Formatting, whitespace only | `style: fix markdown formatting` |
| `perf` | Performance improvement | `perf: optimize git checks` |
| `build` | Build system changes | `build: update npm scripts` |
| `ci` | CI/CD pipeline changes | `ci: add GitHub Actions workflow` |
| `revert` | Revert previous changes | `revert: undo commit abc123` |
| `merge` | Merge conflict resolution | `merge: integrate feature branch` |
| `plan` | Planning documents | `plan: add decision framework` |
| `refine` | Process improvements | `refine: integrate analysis` |

**Total:** 16 commit types (synced with scripts/hooks/commit-msg)

## CRITICAL: AI Attribution Policy

**Git hooks block 53+ patterns including:**

- AI tool names: Claude, ChatGPT, Copilot, Gemini, Cursor, Codeium, Tabnine
- Attribution phrases: "Generated with", "Generated by", "AI-generated", "Co-Authored-By: AI/Claude/ChatGPT"
- Emojis in attribution context

**Rationale:** Commits represent project decisions, not tool usage. Attribution belongs in documentation, not version history.

## Quick Reference

**Minimal commit (subject only):**

```text
feat: add skills system foundation
```

**With body (up to 3 bullets):**

```text
docs: reorganize agent framework

- Split protocol into focused documents
- Add decision-making tiers with examples
- Document memory organization patterns
```

## Commit Command Format

**CORRECT - use printf:**

```bash
git commit -m "$(printf 'type: subject\n\n- bullet 1\n- bullet 2')"
```

**FORBIDDEN - heredoc:**

```bash
# DO NOT USE - heredoc format is forbidden
git commit -m "$(cat <<'EOF'
...
EOF
)"
```

**FORBIDDEN - AI attribution:**

```text
Co-Authored-By: Claude <noreply@anthropic.com>
```
