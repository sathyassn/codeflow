# Pull Request Description Format

**Purpose:** Structure and content guidelines for writing clear, reviewable PR descriptions. Reference when creating pull requests to ensure all necessary information is included.

## Format Structure

```markdown
## Summary
[1-2 sentences: What changed and why]

## Changes
- Key change 1
- Key change 2
- Key change 3

## Testing
[How to verify: commands, expected behavior, or "No testing needed"]

## Related Issues
Closes #123
Related to #456

## Additional Notes
[Optional: Known limitations, follow-up work, breaking changes]
```

## Section Guidelines

**Summary** (required)

- **What changed:** Describe the net change in explicit prose
- **Why it matters:** Business/engineering goal or problem solved
- Keep to 1-2 sentences, focus on impact

**Changes** (optional, recommended for 3+ files)

- Bullet list of key changes (3-5 items max)
- Focus on WHAT not HOW
- Omit for trivial PRs (1-2 files)

**Testing** (required)

- Commands to run OR expected behavior to verify
- For docs/config: "No testing needed (documentation-only)"
- For features: Specific steps to validate functionality
- For fixes: Steps to reproduce original bug + verification

**Related Issues** (optional, recommended)

- `Closes #123` - Auto-closes issue when PR merges
- `Fixes #123` - Alternative to Closes
- `Related to #456` - Reference without closing
- Link issues AFTER explaining change in Summary

**Additional Notes** (optional)

- Known limitations or trade-offs
- Follow-up work needed
- Breaking changes or migration steps
- Areas needing extra review attention

## Examples by PR Size

### Small PR (1-3 files, docs/config)

```markdown
## Summary
Updates branch naming guide to include experiment/ prefix for exploratory work.

## Testing
No testing needed (documentation-only).

## Related Issues
Closes #89
```

### Medium PR (4-10 files, single feature)

```markdown
## Summary
Adds memory cleanup command to archive completed work after grace period. Reduces memory folder size by 60-70%.

## Changes
- Created /wf-cleanup-memory command with --audit flag
- Added 7-day grace period and 30-day trash retention
- Implemented cross-domain dependency checks
- Updated wf-resume to suggest cleanup weekly

## Testing
1. Complete work and delete work-agreement.md
2. Wait 7 days (or modify timestamps for testing)
3. Run `/wf-cleanup-memory --audit` - should show eligible topics
4. Run `/wf-cleanup-memory` - should move to trash
5. Run `/wf-cleanup-memory --restore topic-name` - should restore

## Related Issues
Closes #67 - Memory bloat from completed work
Related to #45 - Context loading efficiency
```

### Large PR (10+ files, complex feature)

Include all sections with detailed Testing steps and comprehensive Additional Notes about architectural decisions or breaking changes.

## Quick Tips

**Good PR descriptions:**

- Explain WHY before linking issues
- Include specific testing steps with commands
- Keep Summary to 1-2 sentences (concise)
- Use active voice: "Adds X" not "X was added"

**Bad PR descriptions:**

- Just linking issues: "Fixes #123" (no explanation)
- Vague testing: "Tested locally, works fine"
- Wall of text in Summary (break into sections)
- Missing testing instructions entirely

## Common Mistakes

- **No testing instructions:** Reviewer doesn't know how to verify
- **Issue-only description:** "Closes #123" without explaining change
- **Too technical in Summary:** Save implementation details for code comments
- **Overly long:** If description is >20 lines, consider breaking PR into smaller pieces

## AI Attribution Policy

**FORBIDDEN in PR titles and descriptions (enforced by PreToolUse hooks):**

| Category | Blocked Patterns |
|----------|------------------|
| AI Tools | Claude, ChatGPT, Copilot, Gemini, Cursor, Codeium, Tabnine, CodeWhisperer |
| Attribution | "Generated with", "Generated by", "AI-generated", "AI generated" |
| Co-authors | "Co-Authored-By: Claude/AI/ChatGPT/Copilot" |

**Rationale:** PRs represent project decisions, not tool usage. Attribution belongs in documentation or internal notes, not version control history.
