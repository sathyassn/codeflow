## Summary

This spec pins the 4.0.0 baseline replacement for its builders: the
installed manifest without a per-file digest, the shipped bases of every
published release carried in the binary, and the tracked sparse pack that
holds what the binary cannot reproduce. TSK-1085 fills and approves it;
TSK-1086, TSK-1087 and TSK-247 build against its numbered requirements.

The settled inputs are the operator's decisions in the workspace
`RELEASE-PLAN.md`: option A, an incompatible manifest and a major release
(2026-10-15); the tracked sparse pack (2026-10-15); every published
release's bases kept in the binary, about 0.6 MB then, with an advisory
2 MB budget whose crossing triggers a review (2026-10-17). The design
Codex approved on 2026-10-15 (`design-baseline-05.md`) is not recoverable;
this spec re-derives it from those decisions and the current code.

## Delta against current capability

Against CAP-002 (`scaffold-update`, `docs/capabilities.md`).

ADDED: bases read from the binary for every published release; a sparse
pack beside the manifest; a read-only preview (`codeflow update --plan`,
TSK-247).

MODIFIED: `.codeflow/manifest.json` records no `sha256`; each entry names
the version it was installed from; the drift check and every update
decision compare bytes with the base instead of a hash.

REMOVED: `.codeflow/.baseline/` in adopting projects and in this
repository (317 files here).

## Behavior

To be written by TSK-1085. It states, as numbered requirements, the
outcome of every `ManagedStep` arm (`crates/codeflow-core/src/scaffold/update.rs:795-860`),
`prune_orphans`, `init`'s judgement of a recorded file and
`doctor --check managed-drift` for a base read from the binary, a base
read from the sparse pack and no base; the one-step migration of a 3.x
project; and how the invariants of TSK-405, TSK-401, TSK-225, ADR-0011,
the release repair rules and the eval kit scrub hold.

## Interfaces and formats

To be written by TSK-1085: the manifest schema, the sparse pack's location
and format, the retained bases' layout and encoding in the binary, and the
release step that adds a release's bases.

## Edge cases

To be written by TSK-1085. At least: a recorded version that is not a
retained release (a development build); a rendered template whose render
inputs changed since install; a 3.x binary reading a 4.0.0 manifest; a
manifest newer than the binary; a linked path under `.codeflow/.baseline/`
at removal; a baseline entry pointing outside the root.
