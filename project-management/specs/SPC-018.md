# SPC-018: Personal and identifying information stays out of repositories

## Summary

This spec pins CodeFlow's privacy check: a general check, shipped to every
adopter on Linux and macOS, that stops an agent or a person from adding
personal or identifying information to a repository. It has five layers:
a privacy lens in the reviewers and review prompts (layer 1), pattern
detectors with no maintained list (layer 2), the contributor's own machine
identity read at push time and never stored (layer 3), an optional
person-name engine on changed prose, local and warn only (layer 4), and an
optional keyed list of organisation terms (layer 5).

The request is the operator's, relayed by the agent-workstation-kit
session and the Director on 2026-11-23. It also asks that this check and
every CodeFlow check be configurable in `.codeflow/policy.json` with
sensible defaults, and that exemptions be tracked records with an exact
path and value or pattern, a reason, an approver and an expiry, changed
only through a reviewed pull request and always shown in the output. That
cross-cutting rule extends TSK-424's exemption register (EPC-024), as the
plan note records; this spec consumes it.

How to read it: requirements are numbered R-1 onward; "Requirement
citations" names the task that serves each; "Disclosed choices" lists what
this spec settles that the request worded differently; one question, Q3,
is still the operator's. Every example value below is a placeholder.

## Settled decision, 2026-11-23 (operator)

Relayed by the agent-workstation-kit session and the Director on
2026-11-23:

- Layers 2 and 3, the deterministic layers, block in the pre-push check
  and in CI. They stay fast: well under a second on a typical change
  (R-9a).
- Layer 4 runs locally only, before push, and only warns. It covers
  changed prose lines only: docs, comments, commit and pull request text.
  It uses the small spaCy model with a time budget of about 2 to 3
  seconds; over budget it skips with a note and never delays or blocks
  the push. It does not run in CI unless later evidence shows it earns a
  place there. The skip is the operator's explicit choice for a warn-only
  layer, not a fail-open gap.
- Each layer is configurable like every check, with tracked exemptions.
- Fail closed applies to the blocking deterministic layers: when a
  detector or an identity read cannot run, they refuse.

This decision replaces the earlier open questions on the default level per
layer and on the person-name engine's dependency.

Relation to TSK-1372: TSK-1372 makes its commit-identity checks off by
default for adopters, following the operator's rule of 2026-11-06 ("any
such stricter stuff should have optionality that's configurable",
`TSK-1372.md:23-25` at `origin/main`). For layers 2 and 3 the operator
has now decided `block` as the shipped default. The 2026-11-06 rule still
holds through configurability: an adopter can set either layer to `warn`
or `off` in `.codeflow/policy.json` on its default branch, and the lowered
level is reported as a relaxation in every run by the privacy check itself
(R-2a). TSK-1372's own checks and defaults are unchanged.

Other settled inputs this spec follows:

- ADR-0091: the default branch at one commit is the only policy authority;
  no line, record or working copy supplies an exception or a level
  (`ADR-0091...md:44`, both revisions).
- ADR-0019: enforcement is the floor at every tier, so layers 2, 3 and 5
  ship from `--minimal` up.
- ADR-0016: the model reviewers own PII reasoning and use scanner output
  as evidence (`ADR-0016...md:97`); layer 1 extends that lens.
- TSK-1078 moves the commit hooks' levels to the authority; the privacy
  hooks read their levels the same way and depend on it.
- TSK-1372's non-goal "detecting a real name in general, which cannot be
  done reliably" (`TSK-1372.md:25`) holds: layer 4 never blocks.

## Behavior

### Terms

- **Finding**: one privacy match, reported as layer, kind, rule id, path,
  line and column range. A finding never carries the matched value.
- **Added content**: the lines a change adds to text files, the paths it
  adds or renames, and the commit messages it introduces.
- **Changed prose**: added lines in documentation files (Markdown, plain
  text, reStructuredText, AsciiDoc), added comment lines in source files,
  commit messages, and a pull request body given to a local `codeflow ci
  --pr-body-file` run (`crates/codeflow-cli/src/cmd/ci.rs` main `:95` to
  `:97`), the one local producer of pull request text CodeFlow has. Pull
  request text written or edited elsewhere (the forge's web editor,
  another tool) is outside the local scan.
- **Placeholder form**: a value from the shared placeholder table, such as
  `user@example.com`, `<name>`, `192.0.2.10`, `2001:db8::1`,
  `00:00:5e:00:53:01`, `host.example` or `/home/<user>`.
- **Identity value**: a value read from the contributor's machine by layer
  3 for the duration of one hook run.
- **Typical change**: the speed fixture of R-9a.

### Levels and placement

- R-1 Each layer shall have its own level key: `privacy.patterns`,
  `privacy.identity` and `privacy.terms` take `off`, `warn` or `block`;
  `privacy.names` takes `off` or `warn` only. Any other value, `allow`
  included, shall be refused when the policy is read (the TSK-1372 AC-1
  precedent). Layer 1 is instruction text and has no key.
- R-2 Shipped defaults (the operator's decision of 2026-11-23):
  `privacy.patterns: block`, `privacy.identity: block`, `privacy.names:
  off` (a project turns it on at `warn`), `privacy.terms: off` (it needs a
  project's own terms and key). A project may set any allowed value; a
  level below the shipped default is a relaxation (R-2a).
- R-2a The privacy check itself shall print one relaxation line on every
  run of every placement (the hooks, `codeflow ci`) and in `codeflow
  doctor --check privacy` whenever a privacy level is below its shipped
  default or `privacy.pattern_kinds` or `privacy.identity_sources` is
  narrowed. This line does not depend on TSK-424's activation key or its
  generic relaxation report: with the key unset the line still prints,
  and the key keeps governing only the generic report, as the Director
  ruled on 2026-11-23 (TSK-424 amendment E10).
- R-2b Delivery order. Each layer's key and shipped default are installed
  by the task that lands that layer's detector, so no release advertises a
  default for a layer it cannot run: EPC-059 installs `privacy.patterns`
  (and `pattern_kinds`); EPC-060's placement task (TSK-1594) installs
  `privacy.identity: block` (and `identity_sources`) when the identity
  detector lands; EPC-061 installs `privacy.names` and `privacy.terms`
  at `off`. Between EPC-059 and EPC-060 reaching `main`, the identity
  layer does not exist: no key, no default, no finding. The final defaults
  are those of R-2 and I1.
- R-3 Levels and every privacy setting shall be read from the default
  branch at one commit as ADR-0091 and TSK-1078 state; a working copy may
  only raise a level. No privacy level is suspended by bootstrap grace,
  as `git.secret_scan` is not (`policy-reference.md` main `:80`, tip
  `:85`).
- R-4 Placement:

  | Layer | pre-commit, commit-msg | pre-push | `codeflow ci` |
  |---|---|---|---|
  | 2 patterns | at the level, for early feedback | at the level (blocking point) | at the level (blocking point) |
  | 3 identity | at the level, for early feedback | at the level (blocking point) | open question Q3 |
  | 4 names | no | warn, within budget | no hosted CI; a local `--pr-body-file` run scans the body file, warn only, within budget (R-26a) |
  | 5 terms | at the level | at the level | at the level, only in the trusted terms job of R-27a; a missing CI key fails closed at the level |

  Pre-push judges each commit of the pushed range; `codeflow ci` judges
  each commit the range introduces; `commit-msg` covers a merge Git
  concludes itself, as the secret scan does. In hosted CI the blocking
  privacy passes run in the trusted admission workflow
  (`assets/base/ci/codeflow-policy.yml`, run from the default branch on
  `pull_request_target`), which fetches the base and head as git data and
  never runs them (`codeflow-policy.yml` main `:12` to `:13`); never in
  `codeflow-ci.yml`, which checks out and runs head code on
  `pull_request` (main `:26`, `:53`, `:167`, `:191`).
- R-5 Content scope follows the secret scan's history scope
  (`ADR-0091...md:154`, both revisions): every introduced commit is
  judged, so a value added and later deleted in the same range is still a
  finding. History outside the range is never judged or rewritten.
- R-5a Binary classification is made from the blob's bytes alone: a blob
  is binary when its first 8000 bytes hold a NUL byte (git's own default
  rule), read from the git object directly. No `.gitattributes` entry,
  diff driver or textconv from any revision is applied, so a head that
  marks a prose file `binary` or `-diff` still has its added lines
  scanned. A blob that is binary by this rule is not scanned; the run
  prints one line naming its path (redacted as R-7a says) and that it was
  not read.
- R-6 The privacy check shall be installed at every tier, minimal included
  (ADR-0019).

### Findings and output

- R-7 A finding shall print `privacy.<layer>.<kind>` as its rule, the
  level, the path, the line and the column range, and a remedy naming the
  placeholder form for the kind and the register route. It shall never
  print, log, annotate, cache, write to a file or pass in an argument or
  environment variable the matched value, a hash of it, or an excerpt of
  the line. The CI annotation carries file and line only, as the managed
  gitleaks step already does (`codeflow-ci.yml` main `:914`, tip `:892`).
  One input is required and allowed: layer 4 sends changed prose to the
  local pinned name engine on its standard input, in memory, and reads
  entity spans back (R-24); that prose is never logged, written to a file
  or kept after the run, and the engine is the only process that receives
  it.
- R-7a A path that itself holds a matched value (a home path or identity
  value in a file or folder name) is printed with the matched segment
  replaced by the kind's placeholder (for example `/Users/<home>/notes.md`
  or `logs/<host>.txt`), in the hooks, CI annotations, `codeflow doctor`,
  the binary-skip line and the exemption report. Every place that prints a
  path applies this rule.
- R-8 A run that applies a register entry shall print the entry's id,
  rule, path (redacted as R-7a says, or the entry id alone when the path is
  bound by fingerprint, R-32), approver, approval pull request and expiry
  in that run's output, in the hooks as in `codeflow ci` (TSK-424 as
  amended).
- R-9 A finding at `block` refuses the commit or push and fails `codeflow
  ci`; at `warn` it prints and passes; at `off` the layer does not run.
- R-9a Speed: layers 2 and 3 together shall finish in under 500 ms, well
  under the one second the operator set, on the typical-change fixture:
  one commit adding 2,000 lines across 20 text files (about 200 KB), with
  a mix of Rust, Markdown, JSON and YAML and 20 placeholder values and 5
  findings spread through it, on the hosted Linux runner and an Apple
  silicon macOS machine. The suite measures it in the optimised test
  profile, as the median of five runs, and fails over the bound; the
  pre-push output prints the layer time in one line. The measured span is
  the wall-clock time of the privacy pass inside the real pre-push hook:
  from the start of the policy authority read, through reading the range's
  diffs, paths and messages and every identity source, to the last
  finding printed. Each task that adds a detector keeps a component
  benchmark green, but the bound is proven only by the final run after the
  real hook is wired: TSK-1589 for layer 2 alone, TSK-1595 for layers 2
  and 3 together. Any source served by a stand-in in that run is named,
  with the real cost measured for it in TSK-1591 or b3.

### Layer 1: the review lens

- R-10 `cf-reviewer` and `cf-security-reviewer` shall ask, on every review,
  whether the change adds a personal or identifying value (an email,
  phone, address, real name, account or tenant id, internal host, home
  path, chat or tracker id, or the contributor's own machine names) and
  whether every example, fixture and test value is a placeholder form.
- R-11 The managed review, delegation and brief templates CodeFlow ships
  shall use placeholder forms only, and a test shall fail when a shipped
  template holds a layer 2 finding outside the placeholder table.
- R-12 The minimal-tier contract shall carry one line: examples, fixtures
  and records use placeholders only.

### Layer 2: pattern detectors

Every detector is structural; none reads a list that a project or
CodeFlow must maintain. A small fixed set of reserved values is part of
each detector's code and is named in its rule text.

- R-13 Contact: email addresses, and phone numbers in E.164 form or in a
  national form with a country or area prefix and at least 7 digits.
  Accepted: addresses at `example.com`, `example.org`, `example.net` and
  any `.example`, `.test`, `.invalid` or `.localhost` domain (RFC 2606,
  RFC 6761); the reserved fictional number ranges the placeholder table
  lists. Version strings, dates, IP addresses and hex ids shall not match
  as phones.
- R-14 Network: IPv4 and IPv6 addresses outside the documentation ranges
  (192.0.2.0/24, 198.51.100.0/24, 203.0.113.0/24, 2001:db8::/32),
  loopback, the unspecified address and broadcast; private (RFC 1918),
  shared (100.64.0.0/10) and link-local addresses are findings. MAC
  addresses outside the documentation block 00-00-5E-00-53-00 to -FF
  (RFC 7042) and the all-zero and all-one addresses. Host names under the
  reserved private suffixes `.local`, `.lan`, `.internal`, `.home.arpa`,
  `.corp` and the vendor suffix `.ts.net`.
- R-15 Home paths: `/Users/<segment>`, `/home/<segment>` and
  `C:\Users\<segment>` where the segment is not a placeholder form (angle
  brackets, a `$VAR`, `${VAR}` or `%VAR%` reference, `~`, or a
  placeholder word from the table).
- R-16 Accounts and tenants: AWS account ids in an ARN or next to an
  account key; Azure tenant, subscription and directory GUIDs next to
  those keys or in a portal or login URL; Google Cloud project numbers in
  a resource path.
- R-17 Chat and tracker ids: workspace URLs of chat and tracker services
  (a chat message or channel link, an issue URL on a named workspace
  host), and member, channel or workspace ids in those forms.
- R-18 A project can narrow layer 2's kinds with `privacy.pattern_kinds`
  (default all); narrowing is a relaxation and is reported (R-2a).

### Layer 3: the contributor's own identity

- R-19 Sources, read once per hook run, in memory only:

  | Source | Linux | macOS |
  |---|---|---|
  | git identity | `user.name`, `user.email` as git resolves them for this repository, through `codeflow_core::git` | the same |
  | account name | the login name of the effective user (`getpwuid`) | the same |
  | full name | the GECOS name of that entry | the same entry's real name |
  | home path | the user segment of the home directory | the same |
  | host name | `gethostname`; `hostnamectl` static, pretty and transient names where systemd is present, else `/etc/hostname` and `/etc/machine-info` | `gethostname`; the system configuration's `ComputerName`, `LocalHostName` and `HostName` |
  | Tailscale | the self node's host name and MagicDNS name from the `tailscale` CLI's status in JSON | the same, from the CLI on `PATH` or the app's bundled CLI |

- R-20 Matching shall use case folding and NFC, on token boundaries, the
  whole value and its separator variants (a full name as written, joined
  with a dot, a dash, an underscore or nothing); a value shorter than 4
  characters, or one in the fixed generic set the placeholder table names
  (such as `root`, `admin`, `user`, `runner`, `localhost`), is skipped and
  the skip is counted without the value.
- R-21 Layer 3 judges added content (R-4) and never a commit's author or
  committer header, which TSK-1372 owns.
- R-22 No identity value shall be written to disk, a log, a cache, the
  coordination ledger, an environment variable of a child process, a
  command argument or the output; matching runs in the hook process.
  Tailscale peers and the daemon's state files are never read. No
  credential helper, SSH configuration or secret store is read.
- R-23 A source the platform lacks (no `tailscale` on `PATH`, no systemd)
  is absent: it is skipped and `codeflow doctor --check privacy` names it.
  A source that is present but fails, times out (200 ms per source, so
  R-9a holds) or is denied is unreadable: a finding at the layer's level
  naming the source kind, never its value, so at `block` the push is
  refused (fail closed).
- R-23a What layer 3 does in `codeflow ci` is open question Q3.

### Layer 4: optional person-name engine

- R-24 With `privacy.names: warn`, pre-push shall run the pinned engine
  (Presidio with the small spaCy English model) on changed prose only. A
  person entity above the pinned score threshold is a warning naming the
  path and line; it never blocks.
- R-25 The engine runs locally with no network request; CodeFlow verifies
  the pinned versions before running it; a missing engine or another
  version is a warning that the layer could not run.
- R-26 Budget and skip: the engine's run has a budget of 2.5 seconds,
  settable between 2 and 3 seconds as `privacy.names_budget_ms`. When the
  budget runs out, the run stops the engine, prints one note that layer 4
  was skipped over budget with the count of lines not checked, and the
  push goes on with no delay beyond the budget. This skip is the
  operator's explicit choice for a warn-only layer (2026-11-23), not a
  fail-open gap: layer 4 never blocks in any outcome.
- R-26a Layer 4 does not run in hosted CI or in `pre-commit`. Its one
  run outside pre-push is local: a `codeflow ci --pr-body-file` run on the
  contributor's machine, the pull request preparation step, scans that
  body file only, warn only and within the same budget; the run detects
  hosted CI by the CI marker `codeflow ci` already reads and never runs
  layer 4 there. A later
  proposal to run it in CI needs evidence that it earns the place (its
  precision on this project's prose and its time) and the operator's
  decision.
- R-26b The engine is installed by the adopter, at the versions and hashes
  CodeFlow pins, by one documented step; `codeflow doctor --check privacy`
  reports it; no hook or command downloads it (the gitleaks engine
  precedent, `policy-reference.md` "The commit-time gitleaks engine",
  main `:1093`).

### Layer 5: optional keyed term list

- R-27 `privacy.terms_digests` holds HMAC-SHA256 digests of normalised
  organisation terms, never the terms. The key is read from a file in the
  user's CodeFlow configuration folder (`$XDG_CONFIG_HOME/codeflow/` on
  Linux, `~/Library/Application Support/codeflow/` on macOS), or in CI
  from a secret held only by the trusted terms job of R-27a.
- R-27a In hosted CI the terms pass runs in its own job in the trusted
  admission workflow (`assets/base/ci/codeflow-policy.yml`), never in
  `codeflow-ci.yml`. The job runs from the default branch on
  `pull_request_target`, checks out the authority commit, installs the
  pinned `codeflow`, fetches the base and head only as git data, and reads
  the key from a secret held in a GitHub environment that only this job
  names. No head file is executed while the key is present: no setup
  script, test, hook, build step, `.gitattributes` driver or head
  workflow. The verdict job keeps holding no secret (`codeflow-policy.yml`
  main `:15` to `:16`). The job's check name is a required check on the
  default branch, produced and guarded like the verdict job's names
  (refusal of another producer of the name; under Mode A, concluded into
  the `authority:` checks by the GitHub App). Its level and digests come
  from the authority's policy, so a head cannot skip, lower or narrow the
  pass.
- R-28 `codeflow privacy terms add` reads a term from standard input,
  writes its digest to the working copy's policy and never echoes the
  term. A digest takes effect only when it is on the default branch at one
  commit, so enrollment is a reviewed change to the default branch's
  policy; a digest added in a head does not apply in that head's runs.
  The command refuses to run in an agent session (the session markers the
  git guard already reads).
- R-28a Disclosed limit: anyone who can run the enrollment command or a
  hook with the key can test a chosen candidate term against the
  published digests (the command computes the digest; the hook reports a
  match). Denying direct reads of the key file (R-29) does not stop that.
  The design relies on the key being held only by contributors and the
  trusted CI job, and on the agent-session refusal of R-28; it does not
  make the digests resistant to a key holder.
- R-29 The key file shall be added to the shipped read denials of the
  harness presets and to the secret stores `security.secret_reads` judges.
- R-30 With the layer at `warn` or `block` and the key unreadable, the
  layer fails closed at its level, naming the key's location symbolically
  (`$XDG_CONFIG_HOME/codeflow/<key file>`, `~/Library/Application
  Support/codeflow/<key file>` or the CI secret's name), never an expanded
  home path.

### Exemptions

- R-31 A privacy exemption is a TSK-424 register entry of kind
  `exception` with rule `privacy.<layer>.<kind>`, one exact path (or a
  path fingerprint, R-32), a value fingerprint or a pattern, a reason, a
  task, `approver` (a role, never a person's name), `approved_in` (the
  number of the pull request that approved it), a grant date and an
  expiry within `max_exemption_days`.
- R-31a The checks on by default are those whose shipped default level
  (I1) is `block` or `warn`: today every `privacy.patterns.<kind>` rule of
  the kinds in `pattern_kinds` and every `privacy.identity.<source>` rule
  of the sources in `identity_sources`. `privacy.names` and
  `privacy.terms` ship `off` and are not on the list. Their exception
  entries are read from the register whether or not TSK-424's activation
  key is set (TSK-424 AC-15 as amended 2026-11-23); a project's own level
  never adds to or removes from this list, and the list is fixed here,
  never inferred at run time. With the register file absent, nothing is
  read.
- R-32 The value is bound by fingerprint, `sha256(rule, path, normalised
  value)`, never as plain text, so the register does not itself hold the
  value. When the path itself holds a privacy value (R-7a), the entry
  binds the path by fingerprint too (`path_fingerprint`,
  `sha256(rule, normalised path)`), never as text, and reports print the
  entry id in place of the path. A pattern is allowed for layer 2 kinds
  only, shall match no value outside the path it names, and shall hold no
  literal identifying value: it may use only the non-literal forms the
  placeholder table lists for its kind (for example "any address at the
  reserved domain of this file's fixtures" or "any address in the
  documentation range"); an exact value always uses a fingerprint. A
  pattern holding a literal email, address, name or id is refused.
- R-33 An entry applies only when the default branch at one commit holds
  it (ADR-0091; TSK-424 AC-4). A head that adds, widens (a broader
  pattern, another path, a later expiry) or re-dates an entry is shown as
  such in the pull request evidence and takes effect only once it lands.
- R-34 Every applied entry is printed (R-8). An expired entry keeps
  TSK-424's existing refusal (TSK-424 AC-1 and AC-6: an exception past its
  expiry is refused) and also stops applying, so the privacy finding it
  covered shows again at its level; the run prints both the refused
  entry, as expired, and the finding.

### Failing closed

- R-35 For the blocking deterministic layers (2 and 3) and for layer 5:
  when a detector or an identity read cannot run (an unreadable diff, an
  unreadable authority, an unreadable identity source, a missing key), the
  result is a finding at that layer's level naming what could not be
  read; at `block` the push, the commit or the `codeflow ci` run is
  refused. Layer 4 warns or skips (R-25, R-26).

## Interfaces and formats

### I1. Policy keys (shipped defaults)

```json
{
  "privacy": {
    "patterns": "block",
    "pattern_kinds": ["contact", "network", "home_path", "account", "chat_tracker"],
    "identity": "block",
    "identity_sources": ["git", "account", "full_name", "home", "host", "tailscale"],
    "names": "off",
    "names_budget_ms": 2500,
    "terms": "off",
    "terms_digests": []
  }
}
```

### I2. Finding and skip lines

```
codeflow pre-push: BLOCKED - policy rule privacy.patterns.email (block)
  possible email address at docs/setup.md:12:5-24 in commit <short sha> (value not shown)
  use a placeholder such as user@example.com, or a register exception (docs/policy-reference.md#privacy)
codeflow pre-push: privacy.names skipped over its 2500 ms budget; 140 changed prose lines not checked (warn-only layer; push continues)
```

### I3. Register entry

```json
{
  "id": "EXC-0001",
  "kind": "exception",
  "rule": "privacy.identity.full_name",
  "paths": ["LICENSE"],
  "value_fingerprint": "sha256:<64 hex>",
  "reason": "copyright holder line",
  "task": "TSK-NNN",
  "owner_role": "maintainer",
  "approver": "maintainer",
  "approved_in": 123,
  "granted": "2026-11-23",
  "expires": "2027-02-21",
  "revisit": "licence change"
}
```

### I4. Doctor

`codeflow doctor --check privacy` prints each layer's effective level, the
commit it was read from and any relaxation; each identity source as read,
absent or unreadable (never its value); the engine and key state; and the
register entries that name a privacy rule.

## Security reading

- Identity values live only in the hook process (R-22); a canary test
  plants unique placeholder identity values through a test seam and
  searches every output, log, written file and child argument for them.
- The detectors read the same inputs as the secret scan (the staged diff,
  the message file, the commits of a range) plus, for layer 3, the
  sources in R-19. None of these is a secret store the presets deny, and
  the hooks run inside the git command the guard already judged, so no
  new agent-controlled read path opens. Layer 5's key is a new secret and
  is denied to agents (R-29); in hosted CI it exists only in the trusted
  terms job, where no head code runs (R-27a). Its limit as a digest oracle
  for a key holder is stated in R-28a.
- Head-controlled inputs cannot weaken a blocking pass: levels,
  selectors, digests and exemptions come from the authority (R-3, R-33);
  binary classification ignores `.gitattributes`, diff drivers and
  textconv (R-5a); the hosted passes run in the trusted admission workflow
  with the head as data only (R-4, R-27a).
- No output carries a matched value through a path: a path holding one is
  redacted (R-7a), and an exemption for such a path binds it by
  fingerprint (R-32).
- Every child process starts with a cleared environment, no prompt and a
  bounded time; every git process goes through `codeflow_core::git` (the
  git spawn contract).
- The blocking layers fail closed (R-35); exemptions are authority-only
  and never widen silently (R-33).

## Edge cases

| Case | Outcome |
|---|---|
| `user@example.com` in a test | passes |
| a GitHub no-reply address in content | finding: it names a login |
| `10.0.0.5` in a doc | finding (private address) |
| `192.0.2.10` in a doc | passes |
| the contributor's host name inside a longer word | finding only on a token boundary |
| the copyright holder's name in `LICENSE` | finding; a register exception with a fingerprint clears it |
| a binary file added (a NUL byte in its first 8000 bytes) | not scanned; one line reports it, without content (R-5a) |
| a head `.gitattributes` marking a prose file `binary` or `-diff` | ignored; the file's added lines are scanned (R-5a) |
| a home path or the contributor's login only in an added file or folder name | finding; the path is printed with the segment redacted (R-7a) |
| a head that edits `.codeflow/ci-setup.sh`, tests or workflows to read the CI terms key | no head code runs in the trusted terms job; the pass still runs (R-27a) |
| identity source denied by a sandbox | unreadable: refused at `block` (R-23) |
| a commit made on another machine, pushed here | pre-push judges it with this machine's identity only; disclosed limit |
| layer 4 over budget | skipped with a note; push continues (R-26) |

## Limits

- Image metadata (EXIF location, camera serials) and archives are not read.
- A genuine binary file (R-5a) is not scanned at all, so a personal value
  inside one, or inside a text file that holds a NUL byte in its first
  8000 bytes, is not found by layers 2, 3 or 5.
- A key holder can test candidate terms against the digests (R-28a).
- Pull request text written outside a local `codeflow ci --pr-body-file`
  run is not seen by layer 4.
- Layer 3 knows only the pushing machine's identity.
- A fingerprint of a short value can be guessed by trying candidates; the
  register never holds plain values, which is the property relied on.
- Layer 4 is probabilistic, local and warn only, and may skip.

## Disclosed choices

- Layers 2 and 3 also run in `pre-commit` and `commit-msg` at the same
  level, beside the decided blocking points (pre-push and CI), so a
  finding can be fixed before the commit exists, as the secret scan does
  (TSK-412). They count toward the same speed bound.
- Exemptions bind a value by fingerprint, not plain text (R-32); the
  request said "value or pattern", and a plain value in the register would
  put the value in the repository.
- `allow` is not a privacy level (R-1), following TSK-1372 AC-1.
- The reserved suffix and placeholder sets are fixed in code, not a list a
  project maintains.
- Privacy levels are not suspended by bootstrap grace (R-3).
- The 500 ms bound (R-9a) and the 200 ms identity-source timeout (R-23)
  are this spec's reading of "well under a second".
- The engine is adopter-installed and pinned (R-26b); the operator's
  decision makes it local and optional, and this follows the gitleaks
  engine's route.
- The approver is two fields, `approver` (a role) and `approved_in` (the
  approving pull request number), never a person's name, so the register
  adds no identifying value.
- A path that holds a privacy value is redacted in output and bound by
  fingerprint in an exemption (R-7a, R-32); the request asked for an
  "exact path", and a plain path would put the value in the register.
- The local pull request preparation run (`codeflow ci --pr-body-file`)
  is the one place layer 4 runs outside pre-push (R-26a): the operator's
  decision names pull request text as covered prose, and pre-push has no
  pull request body to read. It is local, warn only and never in hosted
  CI.
- Each layer's key and default are installed with its detector (R-2b), so
  no intermediate release advertises a layer it cannot run.
