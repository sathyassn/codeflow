# SPC-002 — durable delegate turn lifecycle

## Summary

This is the consolidated, durable form of Workstream A plan v4, jointly
approved by Fable and GPT-5.6 Sol and authorized by the operator on 2026-07-23.
It pins the lifecycle contract that PR1 implements and PR2 adopts and
stress-tests. It supersedes the temporary v2/v3/v4 working drafts; a substantive
change requires a new jointly approved plan version before implementation. The
Plan v5 amendment recorded below (2026-07-24) is such a version: a jointly
approved provenance clarification that changes no lifecycle behavior.

## Delta against current capability

**ADDED:** a schema-v2 lifecycle that proves a delegated Claude session reached
startup, accepted the one armed prompt, and produced a terminal event bound to
that turn.

**MODIFIED:** the Codex-to-Claude lane may reuse one interactive session for
sequential turns because each turn has durable request, acceptance, and result
records. Host delivery remains external to the binary.

**UNCHANGED:** legacy `hook delegate-turn --result`, the Claude-to-Codex
official-plugin lane, duo roles and quality gates, and the ban on headless peer
execution.

## Behavior

The state directory is absolute, owner-only, outside every Git worktree, and
bound to the exact `(run_id, state-directory spelling)` supplied at `init`.
Each run permits one outstanding turn:

1. `SessionStart(source=startup)` creates `ready.json`. Any resume, clear,
   compact, or fork event writes durable poison.
2. `arm` records `turns/<turn-id>/request.json` with the SHA-256 digest of the
   exact prompt bytes, never the prompt.
3. `UserPromptSubmit` commits `accepted.json` only when session and digest
   match. Missing prompt, an unarmed submission, a digest mismatch, or a new
   prompt ID after acceptance exits 2 and blocks the submission. An exact retry
   is idempotent.
4. Stop or StopFailure binds first as an exact retry of an existing result,
   otherwise to the sole accepted turn without a result. No candidate,
   conflicting session or prompt ID, or ambiguous prior-result retry writes
   poison before returning failure.
5. Poison blocks every later transition: `arm` refuses a poisoned run, hook
   events fail before committing, and `wait` checks poison before every
   success. SIGINT after acceptance poisons; timeout never becomes success.
   Recovery from poison is a fresh run and state directory.

`prompt_id`, when present, is a bounded UUID and must agree across acceptance
and terminal records. Its absence selects a recorded pre-2.1.196 compatibility
path that permits exactly one armed turn for the run. A prior result cannot be
treated as an idempotent retry for a different accepted turn without equal
`prompt_id` proof.

In-turn AskUserQuestion and permission answers keep the same fail-closed
submission rules. If a harness version routes such an answer through
UserPromptSubmit and it collides with the armed-turn guard, interactive-dialog
turns are unsupported on that lane until a separately reviewed one-shot
authorization mechanism exists; the one-outstanding-turn invariant is never
relaxed.

## Interfaces and formats

```text
codeflow delegate init --run-id ID --state-dir ABSOLUTE_PATH
codeflow delegate arm --run-id ID --state-dir ABSOLUTE_PATH \
  --turn-id ID --prompt-file FILE
codeflow delegate wait --run-id ID --state-dir ABSOLUTE_PATH \
  --until ready|accepted|terminal [--turn-id ID] --timeout-seconds N

codeflow hook delegate-turn --run-id ID --state-dir ABSOLUTE_PATH
codeflow hook delegate-turn --run-id ID --result FILE
```

The two hook modes are mutually exclusive and never fall back to one another.
Schema-v2 uses file polling only; it never invokes tmux, including on exact
retry. The legacy result mode retains byte-compatible tmux signalling.

State files are write-once JSON installed by temp write, file sync, no-clobber
link, and directory sync:

```text
ready.json
poison.json
turns/<turn-id>/request.json
turns/<turn-id>/accepted.json
turns/<turn-id>/result.json
```

Every mutation holds the run lock with a one-second acquisition bound.
Directories are `0700`; files are regular, nonsymlink, same-UID `0600` files,
revalidated on every open and retry. Prompt bytes are capped at 1 MiB, terminal
messages at 4 MiB, and errors at 1 MiB.
Raw schema-v2 hook input is capped at 32 MiB before parsing so those
decoded-field limits cannot be bypassed through an unbounded allocation.

Hook exits are 0 for committed or exact retry, 2 for a rejected
UserPromptSubmit or unreadable/oversized schema-v2 input, and 1 for other
failures. `wait` exits 0 for a valid observed state, 10 for a failed terminal,
11 for poison/unsafe/malformed state, 124 for timeout, and 130 for SIGINT.
`init` and `arm` exit 0 or 1.

## Host delivery and cleanup

The host, not CodeFlow, launches the harness and transmits the bytes. The
current reverse lane waits for READY, arms the turn, uses a uniquely named tmux
buffer with literal paste into the exact pane, allows a bounded 300 ms input
settle, sends one Enter separately, waits for ACCEPTED, then waits for RESULT.
Prompt files must be canonical UTF-8 text with internal LF line endings, no
terminal line break, and no NUL bytes; `arm` rejects other bytes before
creating turn state. Pane appearance is
never completion evidence. After consuming the bounded result and retaining
the required verification evidence, the host removes the state directory. An
acceptance timeout permits one diagnosis-bound retry only when the dedicated
pane explicitly shows an unsent paste attachment; blind or repeated Enter
retries are prohibited.

## Platform and verification boundary

Supported protocol state uses Unix ownership semantics on macOS, Linux, and
WSL2 distro filesystems. Mode-unreliable filesystems and native Windows fail
closed; native Windows directs the operator to WSL2. PR1 establishes the
deterministic state machine, doctor round trip, focused coverage, and scoped
macOS arm64 canaries. PR2 owns the sibling-hook rejection test, fake-TUI/PTY
matrix, scaffold adoption, and available native-platform canaries. A platform
without native evidence is recorded as unverified, never inferred from another
host.

## Plan v5 provenance clarification (2026-07-24)

Jointly settled by the Fable and Codex seats and operator-authorized as the
Plan v5 amendment to this spec. It clarifies evidence doctrine for TSK-002-003
and changes no lifecycle behavior above.

- Both adapters satisfy one five-obligation evidence contract — launch,
  provenance, return, failure, recheck — while remaining distinct: the
  Claude-to-Codex lane is the vendor-owned official plugin/app-server
  transport; the Codex-to-Claude lane is this CodeFlow-owned lifecycle.
- Forward-lane output counts as Codex only with a native Codex thread ID,
  recheckable through the plugin or the native Codex surface. A generic
  Claude subagent or an unverified relay never counts as Codex. Model and
  effort are recorded as observed only when the transport exposes actual
  values, otherwise labeled requested — never silently upgraded — and
  inferred completion is graded explicitly as inferred.
- The reverse-lane sibling Stop-hook preflight rejects any sibling Stop hook
  not deterministically known to be nonblocking. The currently known official
  Codex plugin hook may be treated as nonblocking only when its exact command
  is recognized and the operator confirms its effective `stopReviewGate` is
  off through the plugin's own surface; CodeFlow does not read or infer
  plugin-private state.
- CodeFlow adds no semantic prompt-policing and does not couple to
  plugin-private state: it deterministically enforces the reverse lifecycle
  it owns and verifies vendor-owned forward work by native evidence. CodeFlow
  does not become a model router or a forward-lane plugin implementation.
- Every cross-harness task begins with an explicit `ROLE: peer` or
  `ROLE: worker`, stays bounded to that assignment, and forbids starting the
  top-level orchestrator or delegating back to the host lineage. A generic
  same-lineage subagent does not satisfy a named cross-lineage assignment.
