# SPC-007 — agentic estimation and forecast verification

## Summary

Pin the optional method's adoption and data boundary before parallel skill and
checker implementation. Existing Markdown tasks/specs remain work authority;
JSON forecast snapshots are linked calculation inputs, never another tracker.
This adds CAP-017; it does not reinterpret Task.estimate (XS/S/M/L/XL).

## Behavior

Recognize agentic operating/development/estimation, capacity and deadline
requests in ordinary language. Inspect project purpose, scope, existing method/
tracker, repository maturity, quality obligations, tool/model binding, real
resources and human availability first. Offer a useful context-specific preview
when relevant; an estimate request alone permits answering, not adopting,
installing, replacing a tracker, creating work, or executing a risky probe.
Confirm new adoption, reuse a compatible adopted profile without repeated
interviews, and honor a decline until its stated material re-offer event.

Project-owned `.codeflow/estimate.json` records schema_version 1, status
(adopted/declined), rationale, method_version, root (nullable if declined), and
re_offer_when (explicit event description, not an elapsed-time reminder).
It is absent from the scaffold manifest and never automatically written by the
CLI. Full-tier default record home is `project-management/estimates/`; standard
uses its existing planning home. Minimal does not acquire a skill or work graph.
The skill may explain the method on explicit request without forcing a tier
upgrade. Project profiles, forecasts and actuals are not scaffold-managed.

The profile records execution/measurement boundary, resources, qualified binding
reference, local grade ranges only where justified, evidence comparability and
prospective evaluation rules. A snapshot freezes profile/rubric/source versions;
a later revision links its predecessor and reason. Preserve all started outcomes,
including ongoing, failed, cancelled and reopened; never replace historical
predictions with as-built grades or pass labels.

## Method contract

Keep provisional S1–S7/C/X/T/R anchored scoring and the four candidate cuts
0–1 / 2–4 / 5–8 / 9+. Repair unknown ownership, label-dependent refusal counts,
consumed-surface integration effort, missing scale/coupling explanations and
confusion between consequence and effort. UNSIZED means material scope/proof
missing; duration uncertainty alone does not prevent estimating.
Grade is an initial local grouping key, not a model-effort setting or universal
hours lookup. No default source hour table or magic calibration sample size.

Agents return populated favorable/planning/adverse estimates from comparable
full-delivery evidence, a safe authorized representative probe, or explicit
judgment. Human input supplies genuinely owner-held facts, not all estimates.
Every basis covers implementation, independent review, verification and expected
rework; integration and human/release activities are explicit in the full
forecast. Probe execution requires authorization before risky actions.
Use existing orchestration/development/review contracts rather than copy them.
Separate resource consumption, elapsed active stages, and calendar lead time;
sessions are only a project-defined unit. Preserve disagreements and sensitivity.
Scenario names are not probabilities. Declare judgment/analogue/local-validation
evidence accurately; actual predictive usefulness requires prospective holdout
comparison and uncertainty, separately from deterministic and behavior tests.

## CLI and report

`codeflow estimate check <forecast-path> [--json]` is read-only. Exactly one
verb. No writes, subprocesses, network, model calls, grading, duration inference,
automatic scheduling, permission/approval decisions or status mutation.
Exit 0: no checker findings; exit 1: findings or unreadable input.
The independently versioned JSON report (schema_version 1) has deterministic
finding codes/messages, checked package count, computed source assurance,
input/source digests, per-scenario validity, elapsed seconds and per-resource
consumption seconds. Invalid scenarios never masquerade as valid totals.
Human text is diagnostic, not the machine contract. A golden CLI test pins JSON.

Core entry: `check_forecast(repo_root: &Path, forecast_path: &Path)` returns a
report. It reads no adoption state. Never construct MarkdownStore: its constructor
creates directories. Use canonical/legacy enumerators and existing frontmatter
parsing without creating an absent project-management directory.
The CLI exempts this verb from the existing best-effort user registry touch;
read-only includes the user registry, not only repository files. Other commands
retain their existing registry behavior. Test a fresh isolated CODEFLOW_HOME.

## Input format v1

Strict typed JSON objects; no free-form maps. Arrays have explicit uniqueness
checks. Deny unknown/duplicate fields and unknown versions at every level.
Machine-checkable fields below are required unless explicitly marked optional.
Use serde tagged variants and existing dependencies; any JSON Schema resource
documents the same contract, not an additional validator.

- Root: `schema_version`, `id`, `anchor_epoch_seconds`, `horizon_seconds`,
  `profile`, `rubric`, `packages`, `boundaries`, `resources`, `scenarios`.
- Pin: `path` (project-relative regular file), `sha256` (64 lowercase hex).
  Profile and rubric each use a Pin. Full-record SHA-256 includes Markdown body,
  not frontmatter alone. Whole-file changes intentionally invalidate current
  source matching; historical snapshots remain unchanged.
- Package: `id`, `source`, `context_pins`, `grade`, `grade_evidence`,
  `duration_basis`, `stage_exclusions`. Context pins include relevant
  acceptance/spec references; canonical directly linked and inherited specs
  must be pinned. Exclusions name `stage` and `reason`.
- Source tagged by `kind`: `codeflow_task` has `task_id`, `sha256`;
  `external` or `declared` has `pin`, `reference`. External/declared
  source assurance is limited even if local bytes match; no URL fetch.
- Grade enum: `easy|medium|hard|very_hard|unsized`. `duration_basis` is the enum
  `judgment|analogue|probe`; `grade_evidence` is a non-empty array of strings
  carrying anchors and explanations. Activity `basis` records the duration
  explanation/evidence; missing knowledge is never fabricated.
  UNSIZED cannot pass as an unconditional implementation allocation.
- Boundary: `id`, `source`, `evidence`, `availability` containing exactly
  three rows of `scenario` and `available_at_seconds`. It represents a
  prerequisite outside scheduled scope. Availability is declared with evidence,
  never inferred from task status, including complete.
- Resource: `id`, positive integer `capacity`, `windows`; each window has
  `start_seconds`, `end_seconds`. Windows are sorted, non-overlapping,
  half-open, finite, and within the horizon. No recurring-load formula.
- Scenario: `name` (exactly favorable/planning/adverse once each),
  non-empty `assumptions`, `activities`, `milestones`.
- Activity: `id`, `package_id` (null for whole-forecast activity), `stage`,
  `start_seconds`, positive `duration_seconds`, `demands`,
  `after` (activity IDs), `after_boundaries` (boundary IDs), and `basis`
  (evidence/assumption explanation). Both prerequisite arrays may be empty;
  demands must be non-empty. Waiting is represented by start offsets and
  explicit boundary availability, not by an unresourced working activity.
  Stage enum: `discovery|implement|review|verify|rework|integrate|human|release`.
  Each demand has `resource_id` and positive integer `units`.
- Milestone: `id`, `after` (non-empty activity IDs). Its time is the latest
  named finish. A release window is a resource on an explicit release activity,
  not an unverified milestone date.

No package status, copied acceptance or package depends_on arrays. Canonical
dependencies come from pinned task records. Activity edges express in-package
steps or whole-forecast integration/release links, not a competing package DAG.
External work uses its pinned authority and explicit activity dependencies with
limited assurance rather than claiming canonical workgraph validation.

## Feasibility and source checks

Every canonical direct predecessor is another package or pinned boundary.
Do not recursively chase beyond a boundary. A declared boundary whose canonical
record depends directly on scheduled scope is contradictory and fails.
All canonical IDs resolve uniquely, including legacy layouts. Unknown/missing
records and stale pins are findings. No edge waivers or status-derived readiness.
Guarded/not-selected scope needs explicit reviewed boundary evidence, not a
checker-invented guard decision.

Every activity reference resolves, IDs are unique, and the graph is acyclic.
For canonical packages, an activity edge connecting two different non-null
package IDs is invalid: use the canonical dependency instead. In-package edges
and links involving a null-package whole-forecast activity are valid. External/
declared packages may use cross-package activity edges only when both sources
are external/declared, with the already-required limited source assurance and
pinned authority evidence. This does not claim the remote graph was verified.
Each after_boundaries reference resolves and its declared scenario availability
must precede the activity start; this is how an external prerequisite constrains
an allocation without fabricating a canonical task or status.
For each scenario, predecessor activities finish before successors start.
Each canonical predecessor package's latest finish (or boundary availability)
precedes its dependent package's earliest start. Missing allocations fail.
Each package must represent implement, review, verify and expected rework in
every scenario, or supply a matching stage_exclusions reason for an absent
stage. The report surfaces all exclusions; it never approves their adequacy.
This checks forecast completeness, not execution ordering or quality approval.
Discovery-only UNSIZED work needs a bounded discovery allocation and explicit
exclusions; UNSIZED implementation remains invalid. Integration, human and
release scope is reviewed across the whole forecast, not required per package.
Every activity interval lies within the finite horizon, regardless of sources.
Check both resource containment and capacity: every non-preemptive activity fits
one contiguous availability span for every simultaneous demand, and total demand
never exceeds capacity at any sweep event. Finishes precede starts at equal
offsets. An interval crossing a gap fails; splitting is explicit, not automatic.

All seconds/units are bounded unsigned integers. Check epoch+offset+duration and
resource-product/sum arithmetic for overflow. No default all-hours calendars,
zero-duration invented stages, unbounded recurrence or optimization. Report
resource-seconds separately from elapsed seconds. No dimensionless capacity
ratio, percentile addition, optimality claim or prediction of actual completion.

## Bounds and security

At most 1 MiB forecast JSON, 1 MiB per pinned source and 16 MiB aggregate source
bytes, 256 packages/boundaries combined, 64 resources, 256 windows/resource,
1024 activities/scenario, 4096 total activity edges/scenario, 256 context pins,
and a finite 366-day horizon. These are parser/work bounds, not project sizing
advice. Reject excessive input before expensive work. IDs and explanations are
length-bounded; serde's recursion limit remains enabled. No unordered output.

Confine referenced pins to the explicit project root; reject traversal, links/
reparse escapes, non-regular files, protected credential locations and secret
file patterns. Reuse a bounded regular-file reader where its guarantees fit;
do not weaken other callers or add a third divergent copy. Reports never dump
source contents or untrusted parser input. Cross-platform path and filesystem
cases, denied reads, symlinks, size limits and absence of writes need tests.
The checker validates supplied allocation/data, not source truth, authorization,
quality completeness or predictive accuracy; make that limit explicit on success.

## Distribution and evaluations

C2 ships skill and all referenced resources to both standard/full mirrors and
baselines, with manifest and reviewed artifact ratchet together. A short root
entry must fit by harmless factoring or an explicit at-most-1KiB root budget
increase documented in the charter; never remove existing duties to fit.
Minimal receives no new method, profile, data or CLI-required operating policy.

C3a proves init tiers, ordinary/repeated update and project-owned profile/
history preservation; deterministic adversarial parser/source/graph/calendar/
arithmetic tests do not count as native behavior evidence. C3b uses isolated
native trials with grading keys withheld: ordinary-language offer, cold start,
reuse, decline, external authority, quality/security gates, independent rubric
scoring, semantic refusal deduplication, boundaries, scale, and unavailable peer.
Freeze a representative real-work forecast before delivery and retain outcomes;
a pilot is a measurement rehearsal, not statistical qualification.
