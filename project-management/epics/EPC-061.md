# EPC-061: Reviewers and optional detectors catch personal data patterns cannot

## Summary

Real names of other people and organisation terms have no pattern, and
reviewers today look at runtime data flow (`cf-security-reviewer.md:79`
at `origin/main`) rather than at what a change writes into the
repository. This epic adds the privacy lens to the reviewers and review
prompts with one shared placeholder table (SPC-018 layer 1), an optional
person-name engine on prose that only warns (layer 4), and an optional
keyed list of organisation terms whose digests, not terms, live in the
policy (layer 5).

Value line: a reviewer checks every change for personal data against the
same placeholder table the detectors use, and a project that wants more
can turn on name warnings and its own term list without publishing the
terms.

## Outcome

After this merges, the managed reviewers ask the privacy question on
every review, CodeFlow's shipped prompts and templates hold placeholder
forms only, `privacy.names: warn` runs the pinned engine locally on
changed prose at pre-push and on the body file of a local `codeflow ci
--pr-body-file` run, and `privacy.terms` matches keyed digests with a key
no agent can read directly, locally and in a trusted CI job that runs no
head code (SPC-018 R-27a). `privacy.names` and `privacy.terms` are added,
at `off`, by the tasks that implement them (SPC-018 R-2b). The digest
oracle that enrollment and matching expose is a disclosed limit (SPC-018
R-28a), not a closed one.

## Planning notes

- The placeholder table has one home, written by TSK-1583; the review
  lens (c1) points at it and never copies it (define once). TSK-1597's
  test over shipped templates runs the layer 2 detectors, so it follows
  TSK-1587, the last detector task.
- Layer 4 follows the operator's decision of 2026-11-23: local only,
  before push, warn only, changed prose only, a 2 to 3 second budget with
  a skip note, no hosted CI run. The engine is adopter-installed and pinned
  (TSK-1599, settled in the plan).
- Pull request text: the one local producer of a pull request body is the
  file given to `codeflow ci --pr-body-file`; layer 4 runs on it in a
  local run only (SPC-018 R-26a). Text written in the forge's editor or
  another tool is outside the local scan, and TSK-1598's docs say so.
  Running layer 4 in that local command goes beyond the operator's
  "before push" wording for layer 4; coord/records settled it on
  2026-11-23 (R-26a, plan note), and it no longer awaits a ruling.
- Keyed terms in CI run in their own job in the trusted admission
  workflow `codeflow-policy.yml`, from the default branch with the head
  fetched as data, never in the head-executing `codeflow-ci.yml`
  (TSK-1600, SPC-018 R-27a).
- Shared surfaces, one writer at a time: TSK-1598 and TSK-1600 both
  write the `privacy` section of `policy_schema.rs`, the hook and CI
  wiring and the doctor privacy check, which TSK-1594 (EPC-060) also
  writes. On this line c3 and c5 take those surfaces one at a time; across
  lines, whichever lands first on `main` goes first and the other starts
  from a base holding it.
