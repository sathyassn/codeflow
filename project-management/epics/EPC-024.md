# EPC-024: quality defaults, local scan parity and seat capacity

## Summary

Five feature requests from adopters in October 2026 ask CodeFlow to
change its defaults rather than fix a defect: a define-once gate with a
tracked exemption register (issue 274), strict typing and linting by
default with an explicit opt-out (275), a repository that holds only
what it needs long term (279), a local run of the managed secret scan
and dependency audit (252), per-project account profiles with
limit-aware seat routing (234), and the supervisor and separate-account
layers of lane isolation (286, items 2 and 3; item 1 is TSK-437 in
3.2.0). The operator placed them on 2026-10-22
in one separate epic, smaller than EPC-022, sized by issue 280's
guidance; this epic is that placement.

Value line: after this merges, an adopting project gets strict,
define-once and lean-repository checks by default with every relaxation
recorded and reported, runs the managed scans locally with the hosted
verdict, and keeps its seats running by their remaining capacity.

That line holds three value statements, which issue 280's own guidance
(TSK-419) says is a reason to plan two or more epics. The operator chose
one epic; the recommended split, if the operator wants it later, is the
quality defaults (TSK-424 to TSK-429, value: strict, define-once and
lean by default with recorded relaxations), then local scan parity
(TSK-430), then seat capacity and lane isolation (TSK-431, TSK-432, TSK-438), in
that merge order.
Each group is a root-to-leaf chain of the graph below, so the split
needs no re-planning of edges.

It serves adopters who run several languages, several seats and hosted
scans. Done means each task has landed on this epic's line with its
cross-lineage review, the integrated body passes the full gate and the
journeys below on the installed candidate, and its pull request to
`main` is ready for a human merge.

Release slot: under the release plan of 2026-10-18 the next numbers are
4.0.0 (the baseline replacement only) and 4.1.0 (EPC-023), so this epic
is the 4.2.0 epic unless the operator orders it earlier; its line,
`integration/EPC-024-quality-defaults-local-scan-parity-and-seat-capacity`,
is cut from `main` after 3.2.0 ships, and the amendment that cuts it
retargets the tasks, whose `integration_target` is `main` until then
(the EPC-023 precedent of 2026-10-18). Issue 234's GitHub milestone is
4.1.0; moving it is the operator's edit when the slot is settled.

## Acceptance Criteria

- AC-1 When a project relaxes a default check or exempts one occurrence, the entry shall carry id, kind, rule, paths, value, reason, task id, owner role, date, expiry and revisit trigger in one register every managed check reads; a malformed, expired, class-wide or uncited entry, or a head-introduced entry that matches nothing, shall be refused, and a base entry that matches nothing at the head shall be reported stale and retired in that pull request; admitted debt shall be admitted once, inside the pull request that first introduces the check and only when the trusted base holds no baseline for it, and shall only shrink thereafter against the previously admitted baseline, by stable occurrence identity with a fix task per occurrence, widening being forbidden by the ratchet; and `codeflow ci` shall report the register's health in the pull request evidence; evidence: TSK-424.
- AC-2 When a `define-once` target runs, a hand-copied value outside its one home and a copied block the configured adapters find shall fail naming the home, discovery mode shall list cross-file literals without failing, and an exemption from AC-1 shall clear an occurrence; evidence: TSK-425.
- AC-3 When `cf-stack` sets up a language, it shall configure the strict tooling of issue 275 at the strictest settings each tool allows, the managed gate shall run it in quick and CI modes, unexplained and unused suppressions shall fail, and a relaxation shall apply only through AC-1's register; evidence: TSK-426.
  - Amended 2026-10-27: widened by the quality asks amendment: `cf-stack` also sets up, per profile, the boundary-data checks TSK-426's capability matrix marks applicable (a validating typed-model library with the rules that flag untyped boundary data, or a schema check), the gate reports each unsupported check with its recorded treatment, and `cf-stack` sets up TypeScript for a new JavaScript project and type-checks an existing one's JavaScript in place (TSK-426 AC-6 and AC-7).
  - Amended 2026-10-28: the operator's typing decision of 2026-10-27 (TypeScript for new projects and files; existing JavaScript checked in place with `checkJs` and JSDoc types).
- AC-4 A relaxation of the typing default shall be a register entry, and CodeFlow's own code in every language it holds (vendored and repository Python, the present web and portal TypeScript and JavaScript, tooling scripts, shell and workflows, Rust) shall pass the same defaults, typed data at its boundaries included, or sit in the baseline with a fix task and a named deferral; evidence: TSK-427.
  - Amended 2026-10-27: narrowed by the quality asks amendment: the instruction default and the `cf-reviewer` check moved to EPC-022 AC-140 (TSK-1032, 3.2.0); the relaxation route and the boundary rule for CodeFlow's own code are added here (TSK-427 AC-6 and AC-7).
- AC-5 The quick gate shall refuse build output, run output, review records, per-task evidence folders and superseded iterations unless an AC-1 exemption names a reason, shall warn in the PR evidence on large evidence additions, byte-identical files, draft siblings, tool-output-like files and uncited research, and shall refuse a live citation of removed evidence that has no resolvable commit pin; evidence: TSK-428.
  - Amended 2026-10-27: the instruction and the `cf-reviewer` question moved to EPC-022 AC-138 (TSK-1030, 3.2.0) by the operator's decision of that day; the block and warn tiers and citation safety from issue #279's comments of that day are added (TSK-428 AC-3, AC-6 to AC-8).
- AC-6 An adopter's tree shall hold each managed skill once, or each extra copy shall be documented with its reason and measured size, and `codeflow doctor` shall report the managed footprint; evidence: TSK-429.
- AC-7 One local command shall give the verdict of the managed `secret scan` and `security review` jobs for the same base and head, with the pinned tools, the base commit's ignore and configuration files and the configured levels, and a project shall be able to run it at pre-push; evidence: TSK-430.
- AC-8 A project shall be able to map each family to a config home and an optional capped API-key fallback in an untracked file that never holds a token, every managed launch shall set only that family's config-home variable, and the limit state of each family shall be readable where the CLI exposes it; evidence: TSK-431.
- AC-9 At the configured threshold, pending work shall move to a seat with capacity in the order the issue states (the other family, the capped fallback, a prompted manual switch between separate accounts), each switch recorded, and a seat stopped by a limit shall resume with its brief and state; evidence: TSK-432.
- AC-11 An adopter shall be able to read one approved specification of the optional supervisor layer and one tested guide to a separate agent account, each citing the socket behaviours TSK-437 established; evidence: TSK-438.
- AC-12 In `essential` and `full` mode, a test-executing target shall pass only when its own report shows tests executed and every skipped, flaky, disabled or CI-skipped item has an AC-1 register entry, and the gate evidence shall name those items; evidence: TSK-1005.
- AC-13 Every enabled test-executing target shall resolve an aggregate coverage floor of at least 80 from its own rules or the defaults, or carry an AC-1 entry, and builder runs shall evaluate it; evidence: TSK-1006.
  - Amended 2026-10-27: widened by the quality asks amendment: project tooling (scripts, build helpers, generators) counts as test-running code, and doctor names tooling no target covers (TSK-1006 AC-8).
- AC-14 On a code range, `codeflow ci` shall require the Testing section's `Coverage:`, `New tests:`, `Not tested:` and tested-revision lines outside fenced blocks, unless an AC-1 entry names the line; evidence: TSK-1007.
- AC-15 A `verified` criterion shall name a test that exists at the reviewed commit, a command with a gate-run id, or a `manual:` entry with its evidence, and a fix shall carry its regression test with a failing and a passing run, or a recorded `regression: none:` line; evidence: TSK-1008.
- AC-16 Changed paths that a project's triggers bind to evidence kinds shall fail the full gate and `codeflow ci` when the owed kind did not run or the PR body lacks its Whole-flow section and `UI:` line, unless an AC-1 entry clears them; evidence: TSK-1009.
- AC-17 Every executable CodeFlow installs shall be covered by an upstream test suite and the strict checks of AC-4, each release shall ship a generated assurance record per managed executable, and `codeflow doctor` shall check the installed files against it; evidence: TSK-1043.
- AC-10 (journey) On the installed combined candidate, a fresh `codeflow init --standard` TypeScript and Python project shall fail its quick gate on a planted `any`, a copied known value and an added `dist/` folder, pass after each is repaired or exempted with a reported entry, give the hosted scan verdict locally, and route a build to the other family when one family's fixture limit is past the threshold; evidence: the final integration run.

## Strict evidence defaults amendment (2026-10-26)

Five issues filed on 2026-10-23 (#299 to #303) ask CodeFlow to make its
evidence checks strict by default, each with a recorded opt-out. Issue
#303 says it is a deliberate tightening of designed behaviour, not a bug
fix, and the other four are written the same way, so they belong with
this epic's quality defaults, not in 3.2.0. They add five tasks and the
criteria AC-12 to AC-16; graph v2 adds them.

| Issue | Task | Outcome |
|---|---|---|
| [#303](https://github.com/sathyassn/codeflow/issues/303) | TSK-1005 | a target's test report decides its result |
| [#299](https://github.com/sathyassn/codeflow/issues/299) | TSK-1006 | every test-running target meets the coverage floor or records why not; the defect half, ignored `defaults.coverage`, is TSK-1014 in EPC-022 |
| [#300](https://github.com/sathyassn/codeflow/issues/300) | TSK-1007 | `codeflow ci` checks the Testing section's lines |
| [#301](https://github.com/sathyassn/codeflow/issues/301) | TSK-1008 | acceptance evidence names its test or command; a fix proves it failed before |
| [#302](https://github.com/sathyassn/codeflow/issues/302) | TSK-1009 | changed paths that owe end-to-end, UI or mutation evidence are checked |

Notes:

- One register. The issues each propose their own exception list
  (`skip_allow`, `quarantine`, `disabled_reason`, coverage exemptions,
  policy exceptions per line or trigger). Here each is a kind of entry in
  TSK-424's register, so AC-1's one register stays the only home of a
  relaxation; TSK-1005, TSK-1006, TSK-1007 and TSK-1009 depend on
  TSK-424. TSK-1008's opt-outs live in the acceptance block it judges.
- TSK-1005 adds the target `kinds` field and TSK-1009 extends it with the
  evidence kinds, hence the edge between them.
- Each task ships report-only for existing projects and turns on at
  `block` through a reviewed policy change; new scaffolds write it on.
  Making these checks the default adds evidence to every adopter's work,
  which "Only the operator adds process" reserves to the operator; each
  record names that decision before dispatch.
- Size. With these, this epic holds fifteen tasks and four value
  statements. The split recommended in the summary gains a fourth part,
  strict evidence defaults (TSK-1005 to TSK-1009, after TSK-424); the
  tracked revisit of the split falls due at this amendment, and the
  operator decides it.
- TSK-1008 extends the acceptance block that TSK-436 (EPC-022) changes
  in 3.2.0; this epic's line is cut after 3.2.0 ships, so no cross-epic
  edge is needed.

## Issue 372 amendment (2026-10-28)

and check assurance behind every executable it installs. The adopter's
manual route works (it excludes byte-identical managed copies from its
