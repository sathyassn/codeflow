# EPC-055: A task lands on its epic's line without a pull request, and the epic reaches main only when complete

## Summary

Every task of an epic now reaches `main` through its own pull request, and issue 770 measured about 14 hosted runs, 3 to 4 review passes and one maintainer merge per task. This epic lets a reviewed task land on its epic's line with no pull request, keeps reviews across a clean merge of `main`, and lets a marked epic reach `main` once, through one pull request, only when it is complete (ADR-0102). Epics planned before the marker exists keep their checkpoint pull requests until they close.

## Outcome

After this merges, a maintainer or agent can land a reviewed task of a marked epic on its line with no pull request, merge `main` into the line cleanly with every review kept, and take the epic to `main` through one pull request only when it is complete.

## Deliverables

- the task records below: `project-management/tasks/`
- the review binding, clean-merge and epic gates in `codeflow ci`: `crates/codeflow-cli/src/cmd/ci.rs`, `crates/codeflow-cli/src/cmd/ci/`, `crates/codeflow-core/src/workgraph/acceptance.rs`, `crates/codeflow-core/src/workgraph/main_sync.rs` and `crates/codeflow-core/src/workgraph/record_text.rs`

- the rules, managed block, skills, docs and model evals: the files TSK-1438 and TSK-1439 name
- release notes: `changelog.d/`

## Acceptance Criteria

- AC-1 (journey) In a scratch adopter with the built binary, a marked epic's three tasks shall land on its line with no pull request; `main` shall move and merge into the line cleanly with every review kept; the line's pull request into `main` shall be refused with one task open and pass when the epic is complete; an unmarked epic's checkpoint pull request shall pass; and a line that sets its own marker shall be refused; evidence: the command output.
- AC-2 No file that TSK-1438 and TSK-1439 own shall say one pull request per task or use "batch" as a delivery unit; evidence: the search output.
- AC-3 TSK-1433, TSK-1434 and TSK-1437 shall each carry a cross-lineage security verdict; evidence: the review rows in their Closeouts.
- AC-4 (after release) With EPC-057 on `main`, the next new marked CodeFlow epic shall record issue 770's five numbers: hosted runs per task, review passes per task, time from a task finishing to `main`, maintainer actions per task, and conflicts per merge of `main`; evidence: that epic's record.
- AC-5 The epic shall close only when every task is complete, computed by `codeflow epic status`, its criteria are as planned or amended by a recorded planning amendment, its proof commit holds `main`'s tip, one whole-epic cross-lineage review names that commit, and the full hosted run of the epic's pull request into `main`, Windows included, is green on that commit; evidence: `codeflow epic status`, the review row and the run link.

## Out of scope

- Changing epics planned before the marker: they stay unmarked and keep checkpoint pull requests until they close.
- Guard code: no task of this epic changes it.
