# EPC-057: Hosted CI runs once per epic, and main reuses that run

## Summary

Hosted CI now runs per task and again on line pushes, and the push to `main` repeats what the pull request into `main` already proved. Under the operator's ruling of 2026-11-11 (ADR-0102), no line push starts a hosted run, a pull request into a line runs only the short checks, the full set runs once on the pull request into `main`, and the push to `main` reuses that run only under strict equality. This epic makes that the shipped default for adopters and CodeFlow's own placement.

Amended 2026-11-26: Sathya's CI/CD rulings of 2026-11-26 (ADR-0102, decision history) replace "the full set runs once on the pull request into `main`" above: every pull request into `main` runs the short checks, one that touches gate, build or workflow files also runs the heavy suites, the heavy suites run nightly on `main` unless its tip already has a green full run, and the push to `main` reuses every check, the security, policy and admission jobs included, only under strict equality.

## Outcome

After this merges, a project on CodeFlow's CI templates, and CodeFlow itself, runs one hosted run per landing into `main`, on its pull request, with the heavy suites on that run only when it touches gate, build or workflow files and otherwise nightly; none on a line push; and reuses that run on the push to `main` only when nothing it proved has changed. For CodeFlow itself this placement and its reuse start with TSK-1452's restore of `main`'s relaxed checks. Adopters take it from the first published CodeFlow release that contains the proven EPC-057 templates (TSK-1352, TSK-1444 and TSK-1576) and, where an adopter's route needs it, EPC-055's direct-landing route.
