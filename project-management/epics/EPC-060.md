# EPC-060: Commits never carry the contributor's own machine identity

## Summary

The values most likely to leak are the contributor's own: the git name and
email, the account and full name, the home path, the host names macOS and
Linux keep, and the Tailscale node name. A pattern cannot know them; the
machine can. This epic reads them at commit and push time, keeps them in
memory only, and judges added content against them (SPC-018 layer 3).
The headers of a commit stay with TSK-1372.

Value line: a contributor can rely on a commit or push that adds their own
name, account, host or tailnet name being refused or warned, on Linux and
macOS, with the value never stored, logged or printed.

## Outcome

After this merges, the hooks SPC-018 R-4 names read each identity source
in SPC-018 R-19 once per run, match added content with the rules of R-20,
report a finding by kind and a redacted place, treat an absent source as
absent and an unreadable one as a finding at the level, and leave no
identity value anywhere outside the hook process. TSK-1594, which wires
the detector into the hooks, is also the task that installs
`privacy.identity: block` and `privacy.identity_sources` in the shipped
policy, `codeflow init` and `codeflow update` (SPC-018 R-2b), so the
identity default is advertised only once its detector runs. The final
defaults are the operator's decision of 2026-11-23, unchanged.
