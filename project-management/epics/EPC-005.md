# EPC-005 — presentation, design, and documentation system

## Summary

Give consuming projects a coherent way to settle product design intent, present
complex agent responses for human feedback, and publish durable repository
documentation without coupling the product's design system or technical stack
to CodeFlow utilities. Done means the language, appearance, security, history,
cleanup, scaffold, and evaluation contracts are explicit; the two utility
surfaces are reusable rather than rebuilt per use; and CodeFlow, Agent OS, and
the public portal can adopt the result in that dependency order.

## Acceptance Criteria

- [ ] When product design intent is material, `cf-design` resolves contextual
      language/voice and applicable appearance modes without offering or
      imposing fixed CodeFlow product themes; bounded conformance still
      collapses without ceremony.
- [ ] When a complex response benefits from an interactive review surface,
      `cf-present` renders a validated declarative document through reusable,
      accessible blocks, uses proportionate prose/bullets/visuals, supports
      curated utility themes in light and dark modes, and returns attributable
      feedback without requiring the agent to build a page from scratch.
- [ ] The default `cf-present` and `cf-docs-portal` experiences are deliberately
      modern, elegant, visually coherent, pleasing, and functional because each
      is designed as a CodeFlow utility product through the `cf-design` process;
      neither mistakes paragraphs inside decorative cards for visual
      explanation.
- [ ] Presentation sessions are private, authenticated, history-aware,
      bounded, clearable, and isolated from product code, operator browser
      state, untrusted documents, remote resources, and project-tracked
      executable extensions in v1.
- [ ] When a repository needs durable explanatory documentation,
      `cf-docs-portal` builds from authoritative sources, supports layered
      navigation and verified source links, updates incrementally, and uses
      appropriate visuals and curated light/dark utility themes without
      becoming the consuming product's design system.
- [ ] The portal direction follows independent Claude-led and Codex research,
      several materially distinct prototypes, rendered comparison, and joint
      review; Linear and other strong modern products may inform the work, but
      no single product or generic technical style guide becomes a template.
- [ ] Contextual language remains credible and audience-fit across product,
      temporary presentation, and durable documentation surfaces without a
      lexical blacklist, AI detector, tone score, or duplicated smell catalog.
- [ ] Deterministic tests, native-interactive Fable 5/high and GPT-5.6 Sol/high
      evaluations, cross-lineage review, clean init/update canaries, and full
      local gates prove the exact contracts before each implementation PR is
      marked ready.
- [ ] After CodeFlow lands, Agent OS consumes the exact released artifacts and
      the separate portal aligns last; each downstream repository owns its own
      durable work records, validation, and human-merge PR.

## Out of scope

- Prescribe themes, brand voice, frontend stack, or a design system for a
  consuming product.
- Share product components or runtime dependencies with `cf-present` or
  `cf-docs-portal`, or share a visual/component runtime between the utilities.
- Add cloud sharing, implicit remote serving, a component SDK, project-tracked
  executable presentation extensions, or a SQLite presentation index in v1.
- Turn presentations into a second task, specification, ADR, or decision-log
  authority; accepted durable outcomes move to their existing canonical home.
- Copy one external documentation site, design system, or writing guide as a
  house style, or mechanically force visuals, bullets, modes, pronouns, or
  emoji regardless of context.

## Affected surfaces and interfaces

- Product-design and editorial skills, orchestrator quality/evaluation
  contracts, scaffold manifests and managed mirrors.
- Rust CLI/local-service boundary for authenticated presentation sessions,
  schemas, state, history, export, and cleanup.
- Skill-owned documentation-portal scaffold, source contract, prototype and
  validation assets, plus CodeFlow dogfood output.
- Downstream integration boundaries: Agent OS consumes released CodeFlow;
  `agent-os-portal` consumes the merged Agent OS and CodeFlow truth.
