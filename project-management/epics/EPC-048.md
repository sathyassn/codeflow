# EPC-048: The gate runs what a change selects

## Summary

Pre-merge and pre-push runs execute every target whatever the change touches, and target commands cannot see the comparison base, so runs are slow and changed-line coverage cannot be judged. It was split out of EPC-028 on 2026-11-04 by the stricter consolidation pass (the operator's rule, relayed by the Director at 21:5x: epics of "around 5 - 10" tasks that reach `main` "in very few days", with "medium to hard" tasks). Planned version: 4.0.0, the version of EPC-028, whose placement reasons carry over.

Value line: a builder waits only for the tests a change can affect before merge and push, sees changed-line coverage on each pull request, and every landing still runs the full gate.

## Outcome

After this merges, a builder or adopter gets pre-merge and pre-push runs that test what the change selects, with changed-line coverage and coverage defaults that apply, while every landing run stays full.
