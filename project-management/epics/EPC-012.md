# EPC-012 — Responsible autonomy

## Summary

Give every installed CodeFlow tier a compact, always-loaded responsible-autonomy
contract while extending the existing quality, security, delegation and
customization owners with the detail needed for safe action. Done means the
contract preserves useful authorized work and all existing doctrine, reaches
minimal/standard/full consumers, and is checked through paired restraint and
useful-completion cases without claiming that instruction text is enforcement.

## Acceptance Criteria

- [x] Minimal and standard/full entry contracts preserve the approved duties:
      bounded authority, care for people/privacy/systems, agency and fair
      treatment, truthful evidence, least-impact action, accountable recovery,
      and non-expanding delegation.
- [x] Detailed owners cover personal/confidential data, actual external effects,
      changed approvals, uncertain mutation outcomes, communication boundaries,
      recovery limits and provider/data minimization without creating a new
      skill, ethics engine, policy proxy or universal network ban.
- [x] Existing dual planning, Claude design and judgment ownership, independent
      review, Git/secret/safety floors and useful autonomous project work remain
      intact; unclear authority or consequential choices surface bounded options
      and consequences rather than being decided unilaterally.
- [x] Managed output and repeat update are byte-identical and stable across
      minimal/standard/full and Claude/Codex destinations, with project-owned
      customizations preserved and every governed artifact within its current
      ratchet.
- [x] Four thematic groups contain ten named paired synthetic cases across
      privacy/delegation, outbound-authority/retry, pressured-incident/security,
      and identity/fair-decision behavior through the existing evaluation kit;
      static distribution checks and native judgment evidence remain distinct
      claims.
- [x] Both primary families independently accept the exact task units and final
      integrated diff, with failed/not-run attempts and unavailable runtime
      controls reported honestly.

## Out of scope

No new runtime policy engine, scheduler, privacy scanner, outbound proxy,
credential service, blanket approval ceremony, real communication/API action,
global model qualification, protected-branch merge or automatic publication.
The change does not make prompt instructions a hard security boundary, weaken a
non-relaxable prohibition, or treat broad credentials and tool access as action
authority.

## Affected surfaces and interfaces

Managed AGENTS templates and harness entrypoints; orchestration quality,
security-review, delegation and customization contracts; model-evaluation
requirements/cases/fixtures; scaffold manifest, mirrors and baselines;
greenfield init, brownfield update, artifact budgets and release evidence. The
trust boundary spans operator/project authority, personal or confidential data,
external destinations and side effects, model providers and disposable native
evaluation fixtures.

## Plan graph (when needed)

`TASK_GRAPH v1: TSK-032 -> TSK-033`. TSK-032 owns the instruction contract,

TSK-033 owns assembled distribution/adoption checks and the predeclared paired

## Closeout

TSK-032 delivered the tiered responsible-autonomy contract and detailed owners;
TSK-033 delivered its bounded evaluation pack, simulators, distribution checks,
secret-scan regression and retained native diagnostics. Fable and Grok approved
the substantive exact source. Local aggregate and focused checks are green;
fresh hosted jobs at the final task head executed zero steps because of the
account payment/spending limit and are not reported as passes.

The native cohort completed five requested artifacts and left five attempts
incomplete at the fixed budget. Data-minimization, waiver, route and executable-
context concerns remain visible in the external diagnostic record. This epic
therefore closes the planned instruction and diagnostic delivery without
claiming model qualification, universal safety, Hermes behavior, publication,
or native Linux/Windows release readiness.
