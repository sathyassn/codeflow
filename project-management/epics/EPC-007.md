# EPC-007 — simplify documentation portal ownership and updates

## Summary

Preserve the opt-in source-linked documentation portal while replacing tracked
pristine runtime copies and automatic source merging with a clearer ownership
boundary. Ordinary adopters configure a replaceable CodeFlow runtime; projects
needing deep customization explicitly take responsibility for the whole runtime.
Existing local edits survive migration and updates without silent ownership changes.

## Acceptance Criteria

- [ ] Fresh adoption and repeated upgrades need no tracked pristine directory;
  source/configuration authority and the useful portal experience remain intact.
- [ ] SPC-008's ownership, migration, integrity and interrupted-update cases pass
  deterministic tests; conflicts stop before portal state or content advances.
- [ ] Whole-runtime transfer survives future setup/update and keeps evidence
  validation honest; no implicit update abandonment or validation bypass.
- [ ] Distributed skills, manifests and repository examples agree; native behavior
  trials and real-browser qualification cover adoption, customization and transfer.

## Out of scope

Visual redesign, product design-system changes, package-registry infrastructure,
per-file ownership mixing, arbitrary source auto-merging, a new restore command,
or publishing/migrating the separate Agent OS portal without its own authority.

## Affected surfaces and interfaces

CAP-015; portal setup/update/transfer, adoption state, transactional migration,
Rust and detached evidence validators, starter/distribution, portal guidance and
release checks. SPC-008 owns the public behavior. ADR-0048's old reconciliation
decision is superseded only for the specific ownership behavior in this spec.
