# EPC-016: visual guide doctrine and portal rebuild

## Summary

The documentation portal that EPC-014 landed presents the guide's sources, but
it explains them with text in boxes: a row of labelled cards for Concept, a
table for Architecture, prose for Technical. The TSK-014 design boards under
`docs/verification/tsk-014-w5/` had already shown, on this repository's own
facts, what a figure that explains looks like: extent along an axis, travel
that stops, coverage as a grid of distinct marks, layers whose bar length is
their cadence with a spine crossing them. None of that reached the skills, so
neither portal nor present can ask for it.

This epic writes the visual explanation doctrine and its figure grammar into
cf-docs-portal and cf-present, gives the portal and the present review surface
one figure runtime with a gate that enforces the grammar, and ships the
approved round 2 design as a working reference kit inside both skills: token,
chrome and figure sheets, a chrome runtime, and one live reference page per
surface, so every consuming project receives the design system, its thinking
and its quality through `codeflow init` and `codeflow update`. The real portal
and the real present are then rebuilt on that kit: three skins (Graphite,
Slate, Sage) with one identity each in light and dark, a Display panel, a
search dialog, collapsible and resizable panels, and the altitude tab strip.
Present annotation is completed so every non-chrome block is annotatable by
text, element and area, with image crops that reach the agent. Every page of
the CodeFlow guide and of the Agent OS guide is then composed with a figure at
each altitude and in each how-to section, with short plain prose. The
doctrine is graded in the evaluation kit. Done is: every page of both portals
reviewed rendered and observed answer-blind, the full gate and both validators
green, the CLI code paths and the browser-driven UI both tested, and an
EPC-016 PR prepared for a human to land after EPC-014's.

## Acceptance Criteria

- [ ] One visual explanation doctrine, with nine figure families keyed to the
      relationship they encode, twelve figure rules, and the altitude contract
      (including the how-to rule: an ordinary how-to section carries a figure
      in the sequence, state or extent family), lives byte-identically in
      `cf-docs-portal/resources/figure-grammar.md` and
      `cf-present/resources/figure-grammar.md`, carries one inline SVG
      specimen per family, names `docs/verification/tsk-014-w5/` as the
      evidence board with its baselines as the negative controls, and is
      recorded by a new ADR that supersedes the stage grammar as the default
      form; evidence: the two files, the ADR, the manifest hashes and the
      mirror test.
- [ ] The portal and the present review surface render a figure block from
      one shared grammar module in two binding modes, authored and derived,
      drawing with the token sheet and the kit's figure classes only, with a
      legend, an accessible description and a table twin on every figure;
      `browser-verify` fails a build in which an explanatory page lacks a
      figure at any altitude, a figure has an unkeyed mark or a literal
      colour, any two drawn states differ on fewer than two rendered channels
      measured off the render in both modes, any drawn inner mark falls under
      the declared floor at either width, any text overprints text or a mark,
      the narrow render reuses the wide mark set instead of its declared

      the adapter and verifier tests with one failing fixture per rule that a
