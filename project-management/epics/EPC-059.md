# EPC-059: Commits and pushes refuse personal data that a pattern can find

## Summary

Agents and people add emails, phone numbers, internal addresses, home
paths with real user names, and account, tenant, chat and tracker ids to
repositories, and a value in a public history cannot be taken back.
CodeFlow's secret scan finds credentials only (`hooks/scan.rs`,
`hooks/gitleaks.rs`). This epic adds the privacy check's frame and its
pattern detectors (SPC-018 layer 2) to the commit hooks, pre-push and
`codeflow ci`, with exemptions through TSK-424's register. Requested by
the operator on 2026-11-23 through the agent-workstation-kit session and
the Director.

Value line: an adopter on Linux or macOS can rely on a commit or push that
adds a contact, network, home-path, account or chat id being refused or
warned at the level their policy sets, with the value never printed.

## Outcome

After this merges, every CodeFlow project, minimal tier included, has a
`privacy` policy section whose pattern layer judges added content in
`pre-commit`, `commit-msg`, `pre-push` and `codeflow ci`, prints kind and
a redacted place but never the value, fails closed when it cannot run,
prints its own relaxation line whenever a level is lowered or a kind
narrowed, and accepts only authority-held register exceptions, each shown
in the output. Only the pattern layer (`privacy.patterns`) is installed
and advertised by this epic; the identity, name and term keys are added
by the tasks that implement them (SPC-018 R-2b), so the epic is valid on
`main` alone with no default that has no detector behind it.
