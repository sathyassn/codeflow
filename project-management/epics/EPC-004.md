# EPC-004 — whole-flow verification and UI resource isolation

## Summary

Make end-to-end evidence mean one faithful vertical run through the material
changed journey, keep concurrent browser work isolated and self-cleaning, and
close proven-landed worktrees without risking dirty or unproven work.

## Acceptance Criteria

- [x] A material changed journey records its affected topology and cannot be
      approved from disconnected unit/integration passes or a mocked changed
      boundary.
- [x] Concurrent UI tasks allocate isolated browser state, applicable
      endpoints, test-data namespaces, artifacts, and teardown evidence without
      taking over the operator's browser or desktop.
- [x] Customization leaves allocator/range, namespace, artifacts, retention,
      and teardown stack-owned while canarying the effective route.
- [x] `codeflow status` inventories linked worktrees and unattached branches
      without mutation; closeout removes clean proven-landed resources only
      after owner clearance and preserves dirty or unproven work.
- [x] Deterministic and native-interactive model evaluation covers each duty,
      and all repository gates plus cross-lineage review pass.

## Out of scope

- A universal E2E framework, browser daemon, fixed port range, test database
  manager, artifact service, worktree sweeper, or deletion command.
- Requiring live third-party systems where a controlled seam and contract check
  is the safer faithful boundary.
- Using the operator's browser profile, tabs, or active desktop for test
  convenience.
