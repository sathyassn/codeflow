# INF-TSK-023-004: Wire claims into PreToolUse hooks

## Description

This task integrates Loro CRDT claims into the existing PreToolUse hook pipeline. Before an Edit or Write tool call proceeds, the gate-check hook must acquire an exclusive claim on the target file pattern via `LoroCoordinator`. This is the enforcement mechanism that prevents two parallel sessions from modifying the same files.

Per Decision #5 (Two-phase claim UX), the initial implementation is advisory: conflicting claims produce a warning (exit 2) but do not hard-block the session. Data is collected to inform the future switch to enforcing mode.

Claims are released when the stage completes (detected via STAGE-COMPLETE message pattern in the PostToolUse hook). This ensures claims are held for the duration of a work stage, not indefinitely.

## Approach

1. In `gate-check` PreToolUse handler, after existing pf-3 sentinel check passes for Edit/Write:
   a. Extract target file path from the tool input
   b. Call `LoroCoordinator.acquire(pattern, session_id, ttl=5m)`
   c. If conflict (another session holds claim): return exit 2 with advisory warning message
   d. If success: proceed with existing gate-check logic
2. In `sentinel-write` PostToolUse handler, detect STAGE-COMPLETE message:
   a. Release all claims held by the completing session's stage
   b. Emit `claim_released` events to coordination ledger
3. Add claim lifecycle events: `claim_created`, `claim_released`, `claim_conflict` to coordination ledger
