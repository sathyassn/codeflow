# INF-TSK-023-020: Add worktree field to pathflow-events.jsonl events

## Description

PathFlow events in `.state/logs/pathflow-events.jsonl` currently have a `session_id` field but no worktree identifier. When multiple sessions run in parallel, events from different worktrees are interleaved in the same JSONL file. Adding a `worktree` field enables consumers to filter events by both session and worktree path, which is essential for debugging parallel session issues.

The field is `Option<String>` because some events (like the initial `session_start`) are emitted before the worktree is created (Section 2b of SessionStart). These events will have `worktree: null`.

## Approach

1. Add `worktree: Option<String>` field to all PathFlow event structs (using `#[serde(skip_serializing_if = "Option::is_none")]` for backward compat)
2. In event emission code, populate from `CODEFLOW_WORKTREE_PATH` environment variable:
   a. If env var set: `worktree = Some(path.to_string())`
   b. If env var not set: `worktree = None` (field omitted in JSON)
3. Verify existing event parsers/readers handle the new optional field via `#[serde(default)]`
4. Write tests: serialize event with worktree, deserialize event without worktree (backward compat)

## Notes

- serde's `#[serde(skip_serializing_if = "Option::is_none")]` + `#[serde(default)]` ensure full backward compatibility
- This enables `grep` and `jq` filtering: `jq 'select(.worktree == "/path/to/worktree")' pathflow-events.jsonl`
