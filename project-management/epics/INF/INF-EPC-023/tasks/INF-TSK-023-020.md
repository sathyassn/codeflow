# INF-TSK-023-020: Add worktree field to pathflow-events.jsonl events

## Description

PathFlow events in `.state/logs/pathflow-events.jsonl` currently have a `session_id` field but no worktree identifier. When multiple sessions run in parallel, events from different worktrees are interleaved in the same JSONL file. Adding a `worktree` field enables consumers to filter events by both session and worktree path, which is essential for debugging parallel session issues.

The field is `Option<String>` because some events (like the initial `session_start`) are emitted before the worktree is created (Section 2b of SessionStart). These events will have `worktree: null`.

## Approach

1. Add `worktree: Option<String>` field to the Event struct in `ledger/mod.rs` (first-class field, mirrors session_id pattern) AND to the 5 PathFlow variants in `types/events.rs` (using `#[serde(skip_serializing_if = "Option::is_none")]` for backward compat)
2. In TransitionWriter methods (`pathflow/transitions.rs`), populate worktree from `std::env::var("CODEFLOW_WORKTREE_PATH").ok()` when constructing each Event:
   a. If env var set: `worktree = Some(path.to_string())`
   b. If env var not set: `worktree = None` (field omitted in JSON)
3. Verify existing event parsers/readers handle the new optional field via `#[serde(default)]`
4. Write tests: serialize event with worktree, deserialize event without worktree (backward compat)

## Notes

- JSONL is append-only, so new events with the worktree field coexist with old events without it
- serde's `#[serde(skip_serializing_if = "Option::is_none")]` + `#[serde(default)]` ensure full backward compatibility
- This enables `grep` and `jq` filtering: `jq 'select(.worktree == "/path/to/worktree")' pathflow-events.jsonl`
- Follow `.claude/skills/cf-rust-standards/SKILL.md` for naming conventions, unsafe usage restrictions, error handling patterns, and clippy configuration
- Test configuration: `codeflow-cli/config/testing/test-config.json` (85% per-file coverage threshold, cargo-nextest runner, cargo llvm-cov tool).
- Follow cf-rust-standards. Event structs are in `codeflow-cli/core/src/types/events.rs`. PathFlow transition writers are in `codeflow-cli/core/src/pathflow/transitions.rs`. Use `#[serde(default)]` on new optional fields for backward-compat deserialization.
- CONCURRENCY: JSONL writes use exclusive sidecar locks (fs2::lock_exclusive) in ledger/jsonl.rs:38-71. Adding a field to Event does not change locking. No additional concurrency handling needed.
- The Event struct uses `#[serde(flatten)] data: HashMap` for event-specific fields. worktree is added as a first-class `Option<String>` field (same pattern as session_id) for type safety.
- cargo clippy must use --workspace flag
- Reference: `.codeflow/docs/analysis/parallel-work/worktree-architecture.md` (Section 4 — state paths and event logging)
