# INF-TSK-023-014: Add worktree cleanup to SessionEnd hook

## Description

Completes the worktree lifecycle by adding cleanup at SessionEnd. When a session ends (normally via PF7 or abnormally via crash), the worktree must be removed to avoid accumulating stale worktrees. This task handles three scenarios:

1. **Normal exit**: SessionEnd reads `CODEFLOW_WORKTREE_PATH`, calls `Manager.cleanup()`.
2. **Abnormal termination**: Session crashed without PF7. SessionEnd still fires and must force-cleanup the worktree.
3. **Stale recovery**: At next startup, `handle_stale_cleanup` detects worktrees from sessions that never ran SessionEnd (e.g., machine reboot) and removes them.

## Approach

1. In `session_end.rs` `end_cleanup()` handler:
   a. Read `CODEFLOW_WORKTREE_PATH` from environment or codeflow-env.sh
   b. If present, call `Manager::cleanup(worktree_name, force=true)`
   c. `cleanup()` internally calls git2 crate's `repo.find_worktree()` and `worktree.prune()` (or equivalent) to remove the worktree
   d. Deregister from `.state/worktrees.yaml`
   e. Call git2 `repo.worktree_prune()` to clean stale git internal references
2. In `handle_stale_cleanup()` (called at session start):
   a. Read `.state/worktrees.yaml` for all registered worktrees
   b. For each worktree: check if the session is still active (PID check or session record)
   c. If session is dead: call `Manager::cleanup(worktree_name, force=true)` and remove stale env file
3. Write tests for normal, abnormal, and stale cleanup paths
