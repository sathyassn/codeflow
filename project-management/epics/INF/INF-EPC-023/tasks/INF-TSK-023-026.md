## Description

Implement sync daemon auto-start/stop lifecycle tied to `WorktreeRegistry` active count. Daemon reads `sync.interval_secs` from `parallel-work-config.json` (default 5s — the current code has `DEFAULT_SYNC_INTERVAL_SECS=30` and must be updated). Add CLI subcommands for manual control. Sync daemon detects dead worker PIDs and force-releases their claims (crash cleanup). Implement auto-rebase strategy for merge conflict resolution before PR creation. Document the TTL vs sync relationship: sync is the fast path (5-10s cleanup for normal exits), TTL (4200s) is the nuclear fallback for crash scenarios.

7. Write integration test: start → verify PID → stop → verify cleanup
8. Update CLAUDE.md and cf-doctor.md

SIGTERM handling should use `signal_hook` or `ctrlc` crate (check existing Cargo.toml dependencies). PidFile write must be atomic to avoid race between daemon start and status check. The daemon interval is config-driven (default 5s) — the existing hardcoded `DEFAULT_SYNC_INTERVAL_SECS=30` in `sync.rs` must be changed to 5. Auto-rebase runs only when `merge.auto_rebase` is true in the config.

**TTL vs sync relationship:** Sync is the fast cleanup path (triggers on each 5s cycle when PIDs are found dead). TTL (4200s from `claims.ttl_secs`) is the nuclear fallback — claims expire automatically if neither sync cleanup nor explicit `release_all()` fires (e.g., catastrophic crash with no daemon). These are complementary, not redundant: sync handles the normal exit case quickly, TTL handles the unrecoverable crash case eventually.

**Crash cleanup:** On each sync cycle, the daemon checks claim holders' PIDs via `kill(pid, 0)`. If a PID is dead, the daemon calls `release_all(session_id)` for that worker's claims before propagating CRDT state to peers.
