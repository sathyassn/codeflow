## Description

Connect the autorun command to spawn parallel workers in isolated worktrees. Create `parallel-work-config.json` as the single configuration source for all parallel execution settings (4 sections: worktree, sync, merge, claims). Wire `session_start` to read `worktree.mode` config (`autorun`/`always`/`disabled`). Wire `locked_register_with_limit` to read `max_concurrent` from config. Workers pre-acquire claims for their `file_scope` at startup, set `scope_policy` from task metadata (default: `soft`), and write `scope_policy` + `file_scope` to `active-task.json`. Workers emit coordination events (ClaimAcquired, ClaimConflict, ClaimReleased, ScopeExpansion) to `coordination-events.jsonl` via `ledger/routing.rs`.

## Approach

1. Read `codeflow-cli/core/src/autorun/worker.rs` to understand the `WorktreeProvider` trait interface
2. Read `codeflow-cli/core/src/worktree/mod.rs` for `WorktreeManager::setup_detached()` signature
3. Read `codeflow-cli/core/src/coordination/claims.rs` for `acquire_batch()` and `release_all()`
4. Read `codeflow-cli/core/src/coordination/merge_queue.rs` for enqueue/dequeue API
5. Read `codeflow-cli/core/src/git/conflict.rs` for `check_merge_conflicts()` signature
6. Create `parallel-work-config.json` with 4 sections: worktree, sync, merge (max_rebase_attempts: 3), claims (default_scope_policy: "soft", ttl_secs: 4200, capture_events: true)
7. Add `scope_policy` field to `WorkerConfig` struct in `orchestrator.rs`; set from task metadata (default: "soft")
8. Wire `loro.rs` to read `claims.ttl_secs` from config (default 4200)
9. Add coordination event types in `types/events.rs` and routing in `ledger/routing.rs` for `coordination-events.jsonl`
10. Implement `WorktreeProvider` for the autorun worker spawner in `autorun/worker.rs`
11. Wire worktree lifecycle into the batch dispatch loop in `codeflow-cli/cli/src/cmd/autorun.rs`
12. Add integration test for 2 concurrent workers
13. Update `.claude/commands/cf-autorun.md` with worker spawning procedure
14. Update `.claude/CLAUDE.md` Autorun Mode subsection

## Acceptance Criteria

1. Create `.codeflow/config/parallel-work/parallel-work-config.json` with 4 sections: worktree (mode, max_concurrent, base_dir), sync (interval_secs, auto_start), merge (auto_rebase, queue_enabled, max_rebase_attempts), and claims (default_scope_policy, ttl_secs, capture_events)
2. `session_start.rs` reads `worktree.mode` from config — creates worktree only when `mode=always` OR (`mode=autorun` AND session is autorun). Worktree modes are `autorun`, `always`, `disabled` (no other values)
3. `locked_register_with_limit` reads `worktree.max_concurrent` from config (default 3)
4. Autorun batch command spawns workers into separate worktrees (one worktree per worker)
5. WorktreeProvider trait is implemented by the autorun worker spawner
6. `orchestrator.rs` `WorkerConfig` struct includes `scope_policy` field
7. Workers set `scope_policy` from task metadata (default: `soft` when not specified in task definition)
8. `loro.rs` reads `claims.ttl_secs` from config (default 4200s — 70 min, matching worker timeout + buffer)
9. Each worker pre-acquires claims for its `file_scope` at startup via `acquire_batch()`
10. Each worker writes `scope_policy` and `file_scope` to `active-task.json`
11. Workers use WorktreePaths for all state file access (no hardcoded `.state/` paths)
12. PR merge uses merge queue (enqueue before merge, dequeue after)
13. `merge.max_rebase_attempts` defaults to 3
14. Merge conflict detection runs before PR creation via `check_merge_conflicts()`
15. Worktree cleanup runs on worker completion (success or failure)
16. Claims released on worker completion via `release_all()`
17. Coordination events (ClaimAcquired, ClaimConflict, ClaimReleased, ScopeExpansion) defined in `types/events.rs` and emitted to `coordination-events.jsonl` via routing in `ledger/routing.rs`
18. Integration tests: 2 concurrent workers run without conflicts, config loading works
19. Update `.claude/CLAUDE.md` Section 4 (Autorun) and Section 9 (Project Structure) with config path
20. Update `.claude/commands/cf-autorun.md` with worker spawning procedure and config references

Final config structure:
```json
{
  "worktree": { "mode": "autorun", "max_concurrent": 3, "base_dir": ".git-worktrees" },
  "sync": { "interval_secs": 30, "auto_start": true },
  "merge": { "auto_rebase": true, "queue_enabled": true, "max_rebase_attempts": 3 },
  "claims": { "default_scope_policy": "soft", "ttl_secs": 4200, "capture_events": true }
}
```

Workers must use `WorktreePaths` for all `.state/` file access — no hardcoded paths. Cleanup must run in both success and failure paths (use Rust `Drop` impl or explicit `defer`-style pattern). The config file is the single source of truth for all parallel execution settings — no hardcoded defaults for values that exist in config. TTL of 4200s (70 min) matches worker timeout + buffer. No `max_expansion_files` — Loro CRDT provides natural limits via other workers' existing claims.
