# INF-TSK-023-032: Wire autorun DB + event recording

## Description

The orchestrator at `orchestrator.rs:91-131` and workers at `worker.rs:160-356` currently write no data to the database or JSONL ledger. All autorun execution is fire-and-forget with results printed to stdout only.

This task wires the three-tier data model into the autorun system:
- Tier 0 (JSONL): Autorun-specific events to `autorun-events.jsonl`
- Tier 1 (SurrealDB): Records in `autorun_session`, `autorun_worker`, `autorun_task_run`
- Schema extensions for missing fields (pid, skipped_tasks, file_scope, scope_policy, blocked_reason, claim_conflicts, merge_conflicts)

## Approach

1. Extend `schema.surql` with new fields for the three autorun tables
2. Add corresponding `surreal.rs` CRUD functions for the autorun tables
3. Define `AutorunEvent` enum in `coordination/types/events.rs` with 9 variants
4. Add `AUTORUN_EVENTS` constant to `ledger/mod.rs` (file constants at lines 16-20)
5. Add routing for `batch_*` and `worker_*` event types in `ledger/routing.rs`
6. Inject `Store` trait object into `Orchestrator` constructor; pass through `WorkerConfig` or via a separate parameter
7. In `Orchestrator::execute()`, write batch start/end records and events
8. In `TmuxWorker::run()`, write worker and task_run records at start and end
