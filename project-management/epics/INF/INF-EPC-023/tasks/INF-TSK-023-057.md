# INF-TSK-023-057: Merge conflict detection before PR creation

## Description

When multiple sessions work in parallel and merge back to the target branch, later sessions may encounter merge conflicts. Currently, conflicts are only discovered at GitHub PR merge time, which wastes CI time and requires manual intervention. This task adds proactive conflict detection at PF6-COMPLETE (before `gh pr create`) so conflicts are caught early.

## Approach

1. Before PR creation in the ship/PR workflow:
   a. Fetch latest target branch: `git fetch origin {target_branch}`
   b. Use `git2` crate to perform merge analysis between current HEAD and target branch
   c. If merge analysis reports conflicts: collect list of conflicting files
2. Interactive mode handling:
   a. Display conflicting files list to user
   b. Suggest: "Merge conflicts detected. Rebase onto {target} and resolve before creating PR."
   c. Block PR creation until user resolves
3. Autorun mode handling:
   a. Mark task status as `blocked` with `blocked_reason: merge_conflict`
   b. Record conflicting files in task metadata
   c. Skip PR creation, proceed to PF7-END
4. Clean merge handling: pass through silently without user intervention
5. Write unit tests using git2 test fixtures for merge scenarios
