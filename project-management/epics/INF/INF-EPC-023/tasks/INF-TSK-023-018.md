# INF-TSK-023-018: Parallel session coordination (worktree registry, FIFO merge queue)

## Description

This task implements the coordination layer that makes parallel sessions aware of each other. Two components:

1. **Worktree registry** (`.state/worktrees.yaml`): A YAML file tracking all active worktrees with their session ID, task ID, creation time, branch, and status. Sessions query this to discover peers and their claimed files.

2. **FIFO merge queue** (LoroList container): When sessions complete and are ready to merge, they enqueue a merge request into a LoroList. The merge queue processes in first-completed-first-merged order, ensuring deterministic ordering even when multiple sessions complete near-simultaneously. Loro CRDT handles concurrent enqueue operations deterministically.

## Approach

1. Implement worktree registry CRUD in `worktree/registry.rs`:
   a. `register(session_id, task_id, worktree_path, branch)` -- add entry
   b. `deregister(session_id)` -- remove entry
   c. `list_active()` -- return all active entries
   d. `count_active()` -- return count for max concurrent enforcement
   e. File format: YAML at `.state/worktrees.yaml` with flock for atomicity
2. Implement FIFO merge queue in `coordination/merge_queue.rs`:
   a. Use LoroList container named `merge_queue` in the LoroDoc
   b. `enqueue(session_id, task_id, branch, pr_ready_at)` -- append to LoroList
   c. `dequeue()` -- pop from front of LoroList
   d. `peek()` -- read front without removing
   e. `position(session_id)` -- return queue position for status display
3. Add `codeflow autorun status` display showing active workers and queue
4. Enforce max 3 concurrent sessions at worktree creation time via `count_active()` check
5. Write concurrency tests: three threads enqueue simultaneously, verify deterministic order
6. Write 4 integration test scenarios covering the parallel execution matrix:
   a. Scenario A: two interactive sessions on same machine (separate worktrees, env files, no singleton collision)
   b. Scenario B: autorun batch with 3 workers (unique worktrees, non-conflicting claims, correct merge queue ordering)
   c. Scenario C: interactive session + autorun worker concurrent (coexistence, registry shows both)
   d. Scenario D: same-file conflict (second session gets advisory exit 2 from Loro claim system)
