# INF-TSK-023-008: Add SetupDetached method to worktree manager

## Description

At SessionStart, the worktree must be created before the feature branch is known (branch creation happens at PF3-CLASSIFY). The existing `setup()` method requires a branch name. This task adds `setup_detached()` which uses `git worktree add --detach` to create a worktree on a detached HEAD, allowing the branch to be set later at PF3.

The detached worktree has the same `.state/` directory structure as a regular worktree: shared directories (db, ledger, registry, backups, coordination, logs) are symlinked to the main project, while session-specific directories (runtime, session, sentinels) are created fresh per-worktree.

## Approach

1. Add `setup_detached(name: &str) -> Result<WorktreePath>` method to the worktree Manager
2. Internally call `git worktree add --detach {base_dir}/{name}` where `base_dir` is `.git-worktrees/`
3. Create `.state/` directory structure inside the worktree:
   a. Symlink shared directories: `db/`, `ledger/`, `registry/`, `backups/`, `coordination/`, `logs/` -> main project `.state/{dir}`
   b. Create fresh directories: `runtime/`, `session/`, `sentinels/`
4. Register the worktree in `.state/worktrees.yaml` with `session_id`, `created_at`, `status: active`, `branch: null`
5. Return the absolute path to the created worktree
6. Write unit tests covering creation, symlink verification, registry entry
