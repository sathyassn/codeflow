# INF-TSK-023-035: Orchestrator graceful shutdown

## Description

The orchestrator at `orchestrator.rs:91-131` has no signal handling. If a user presses Ctrl+C during a batch, the process terminates immediately, leaving orphan tmux sessions, unreleased claims, and stale worktrees.

This task adds graceful shutdown: on SIGINT, stop dispatching new tasks, cancel running workers with proper cleanup, skip pending tasks, and return partial results.

## Approach

1. Add `abort: Arc<AtomicBool>`, `handles: Arc<Mutex<Vec<JoinHandle<()>>>>`, `tmux_sessions: Arc<Mutex<Vec<String>>>` to `ExecutionState`
2. Replace the bare dispatch loop with `tokio::select!` racing dispatch against `tokio::signal::ctrl_c()`
3. Add abort gate at the start of `dispatch_ready_tasks()`: if abort flag set, return false immediately
4. Modify `spawn_worker()` to return the `JoinHandle<()>` and construct the tmux session name; store both in `ExecutionState` at call site
5. On abort: kill all tracked tmux sessions via `std::process::Command`, wait up to 10s for JoinHandles via `tokio::time::timeout`, skip remaining pending tasks
6. Condition post-loop DB update and event emission: abort -> Cancelled + BatchAborted; normal -> Failed/Completed + BatchCompleted
7. Worker cleanup (claims, worktree, tmux) runs automatically via existing TmuxWorker::run() cleanup path (worker.rs:536-565) -- no worker.rs changes needed
