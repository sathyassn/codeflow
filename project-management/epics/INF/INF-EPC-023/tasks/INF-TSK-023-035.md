# INF-TSK-023-035: Orchestrator graceful shutdown

## Description

The orchestrator at `orchestrator.rs:91-131` has no signal handling. If a user presses Ctrl+C during a batch, the process terminates immediately, leaving orphan tmux sessions, unreleased claims, and stale worktrees.

This task adds graceful shutdown: on SIGINT, stop dispatching new tasks, cancel running workers with proper cleanup, skip pending tasks, and return partial results.

## Approach

1. Add `Arc<AtomicBool>` abort flag to `ExecutionState`
2. Spawn `tokio::signal::ctrl_c()` handler that sets the abort flag
3. In the dispatch loop, check abort flag at the start of each iteration; if set, break out of loop
4. After loop exits due to abort, cancel running workers: for each running task, send SIGTERM to its tmux session
5. Mark all non-completed, non-failed tasks as skipped with `"batch_aborted"` reason
6. Collect and return partial results
7. Ensure worker cleanup (claims, worktree, tmux) still runs via the existing cleanup path in `TmuxWorker::run()`
