# INF-TSK-023-028: Implement Claude invoker (hybrid tmux + file-marker)

## Description

The current `RealClaude` implementation at `cli/src/cmd/autorun.rs:156-170` is a no-op stub that returns a hardcoded success result. The task prompt at `worker.rs:243-244` is a generic string `"Execute autorun task {id}"` with no acceptance criteria or PathFlow context.

This task replaces both with a real implementation:
1. The Claude invoker sends commands via tmux send-keys, sets environment variables, and polls for a file-marker indicating completion.
2. The task prompt is constructed from the task markdown file, extracting description, approach, acceptance criteria, and file scope.

Design reference: `.codeflow/docs/analysis/parallel-work/autorun-spec.md` Section 5 (Claude Invocation).

## Approach

1. Read `InvokeConfig` fields and construct the Claude command string with `--dangerously-skip-permissions --output-format json`
2. Use `TmuxRunner::send_command()` to set env vars (AUTORUN_SESSION_ID, AUTORUN_TASK_ID, AUTORUN_ACCEPTANCE as base64-encoded JSON, CODEFLOW_WORKTREE_PATH) before sending the Claude command
3. Send the main command that redirects output to `worker-output.json` and writes exit code to `worker-exit-code`
4. Poll for `{work_dir}/.state/runtime/worker-exit-code` at 1s intervals
5. On marker found: read exit code, parse `worker-output.json` for structured results, get branch name via `git branch --show-current`
6. Add a `build_task_prompt()` function in `worker.rs` that reads task markdown, parses YAML frontmatter for acceptance criteria, and constructs a PathFlow-aware prompt
7. Update `TmuxWorker::run()` to call `build_task_prompt()` instead of using a hardcoded string
8. Handle timeout with SIGTERM -> 10s -> SIGKILL sequence
