# INF-TSK-023-030: Wire merge conflict remediation

> **MANDATORY VALIDATION:** Files created from this template MUST be validated against the task validation script before committing:
> `bash .codeflow/scripts/validation/validate-task.sh project-management/epics/INF/INF-EPC-023/tasks/INF-TSK-023-030.md`

## Description

The current merge conflict handling at `worker.rs:281-297` detects conflicts via `check_merge_conflicts()` but only logs a warning. The existing `attempt_rebase()` function at `conflict.rs:148` and `MergeConfig` with `auto_rebase` and `max_rebase_attempts` fields at `config.rs:120-127` are fully implemented but not wired into the worker.

This task wires them together: when conflicts are detected, read the merge config, attempt rebase with retry, and set `status="merge_conflict"` on exhausted retries.

## Approach

1. In `TmuxWorker::run()`, after `check_merge_conflicts()` returns `has_conflicts=true`:
   - Load `MergeConfig` from `ParallelWorkConfig` via `load_config()` (falls back to `ParallelWorkConfig::default()` on error)
   - If `auto_rebase=true`, call `attempt_rebase(worktree_path, target_branch)` in a retry loop up to `max_rebase_attempts`
   - Between retries, use `tokio::time::sleep(Duration::from_secs(2)).await` (async-compatible, not std::thread::sleep)
   - On `RebaseResult::Success`, continue to merge queue
   - On `RebaseResult::ConflictAborted` after max attempts, return `WorkerResult { status: "merge_conflict" }`
   - On `attempt_rebase()` returning `Err(GitError)`, warn to stderr and continue to merge queue (matching existing error pattern at worker.rs:291-293)
2. If `auto_rebase=false`, return `merge_conflict` immediately on conflict detection
