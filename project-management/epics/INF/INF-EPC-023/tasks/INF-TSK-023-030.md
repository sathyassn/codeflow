# INF-TSK-023-030: Wire merge conflict remediation

## Description

The current merge conflict handling at `worker.rs:254-270` detects conflicts via `check_merge_conflicts()` but only logs a warning. The existing `attempt_rebase()` function at `conflict.rs:148` and `MergeConfig` with `auto_rebase` and `max_rebase_attempts` fields at `config.rs:102-108` are fully implemented but not wired into the worker.

This task wires them together: when conflicts are detected, read the merge config, attempt rebase with retry, and set `status="merge_conflict"` on exhausted retries.

## Approach

1. In `TmuxWorker::run()`, after `check_merge_conflicts()` returns `has_conflicts=true`:
   - Load `MergeConfig` from `ParallelWorkConfig` (already loaded by orchestrator, pass through `WorkerConfig` or load separately)
   - If `auto_rebase=true`, call `attempt_rebase(worktree_path, target_branch)` in a retry loop up to `max_rebase_attempts`
   - Between retries, sleep 2 seconds to allow competing workers to complete
   - On `RebaseResult::Success`, continue to merge queue
   - On `RebaseResult::ConflictAborted` after max attempts, return `WorkerResult { status: "merge_conflict" }`
2. If `auto_rebase=false`, return `merge_conflict` immediately on conflict detection
