# INF-TSK-023-031: Comprehensive batch validation

> **MANDATORY VALIDATION:** Files created from this template MUST be validated against the task validation script before committing:
> `bash .codeflow/scripts/validation/validate-task.sh project-management/epics/INF/INF-EPC-023/tasks/INF-TSK-023-031.md`

## Description

The current `validate_batch()` at `batch.rs:119-177` only validates structural properties: empty tasks, duplicate IDs, dependency references, and protected branch merges. It does not read task markdown files or verify autorun-specific requirements.

For production autorun, validation must:
- Read each task's markdown to check autorun_eligible, acceptance, scope_policy, file_scope
- Detect file_scope overlaps between concurrent tasks (would cause claim conflicts at runtime)
- Verify target_branch exists and is not protected (when auto_merge=true)
- Reconcile max_workers with the global max_concurrent limit

## Approach

1. Add `validate_batch_extended()` in `batch.rs` that takes `project_dir` and `ParsedBatch`
2. For each task ID, construct the markdown path using the task format ID pattern, read and parse frontmatter via `validate::parse_frontmatter()`
3. Check `autorun_eligible`, `acceptance`, `scope_policy`, `file_scope` from frontmatter
4. Build a map of task_id -> file_scope patterns; for each pair of non-dependent concurrent tasks, check for path overlaps
5. If batch has a target, verify it exists via `git rev-parse --verify refs/heads/{target}` or `refs/remotes/origin/{target}`
6. Read enforcement-policy.json for merge_protection list (existing at `.codeflow/config/enforcement/enforcement-policy.json`)
7. Set effective max_workers = min(batch.max_workers, config.worktree.max_concurrent) and store in ParsedBatch
8. Call `validate_batch_extended()` from the CLI command after `parse_batch_file()`
