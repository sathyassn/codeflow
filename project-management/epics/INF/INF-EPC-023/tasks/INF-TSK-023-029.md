# INF-TSK-023-029: Fix worker coordination bugs

> **MANDATORY VALIDATION:** Files created from this template MUST be validated against the task validation script before committing:
> `bash .codeflow/scripts/validation/validate-task.sh project-management/epics/INF/INF-EPC-023/tasks/INF-TSK-023-029.md`

## Description

Five coordination bugs exist in the autorun worker lifecycle that must be fixed before autorun is production-ready:

1. **Blind dequeue** (`worker.rs:311-313`): `locked_dequeue()` pops the front merge queue entry regardless of which session it belongs to. In concurrent batches, Worker B could dequeue Worker A's entry.
2. **Warn-only claims** (`worker.rs:213-218`): When `acquire_batch()` fails due to claim conflicts, the worker logs a warning and continues, ignoring the conflict entirely.
3. **Missing daemon auto-stop** (`worker.rs:316-318`): After worktree cleanup, the worker does not call `maybe_auto_stop_daemon()` to stop the sync daemon when worktree count drops to 1.
4. **Non-unique tmux names** (`orchestrator.rs:209`): All workers across all batches use the prefix `codeflow-worker-{N}`, causing collisions when multiple batches run simultaneously.
5. **Missing worktree limit** (`orchestrator.rs:188`): The semaphore is bounded only by `max_workers` from the batch, ignoring the global `max_concurrent` worktree limit.

## Approach

1. Add `session_id` parameter to `dequeue()` and `locked_dequeue()`; peek at front entry, only pop if `session_id` matches
2. In `TmuxWorker::run()`, check `acquire_batch()` result; if any claims failed, read `blocked_behavior` from config and either skip (return `WorkerResult { status: "blocked" }`) or fail (return `Err`)
3. After `self.worktree.cleanup()` call at `worker.rs:316`, add call to `maybe_auto_stop_daemon(registry_path, project_dir)`
4. Change `WorkerConfig::tmux_prefix` from `"codeflow-worker"` to `format!("codeflow-{}", &session_id[..8])` in orchestrator dispatch
5. Change semaphore initialization in `ExecutionState::new()` to use `min(max_workers, config.worktree.max_concurrent)`
