# INF-TSK-023-011: Scope active-task.json per worktree

## Description

`active-task.json` is the second CRITICAL singleton blocking parallel execution. Currently at `.state/runtime/active-task.json`, it stores the currently active task for hook context (stage routing, sentinel naming, checkpoint operations). When two sessions run concurrently, the second session overwrites the first's active task, causing hooks to operate on the wrong task.

This task scopes `active-task.json` per worktree, ensuring each session's hooks see only their own active task.

## Approach

1. Modify `set_active_task()` to write to `{worktree}/.state/runtime/active-task.json`:
   a. Accept worktree path parameter (from `CODEFLOW_WORKTREE_PATH`)
   b. Write active task JSON to worktree-local path
2. Modify `get_active_task()` to read from worktree-local path:
   a. Check `CODEFLOW_WORKTREE_PATH` env var
   b. If set, read from `{CODEFLOW_WORKTREE_PATH}/.state/runtime/active-task.json`
   c. If not set, fall back to main project path (backward compat)
3. Modify `cleanup_active_task()` (called at session start) to only clean the worktree-local file
4. Update all 7 hook call sites: session_start.rs (cleanup_active_task, detect_compact_recovery, output_active_task), session_end.rs (handle_active_task), prompt_validate.rs (active_task_id), logging/stop.rs (read_task_context), logging/session.rs (read_active_task_id)
5. Write tests verifying two concurrent sessions maintain separate active tasks
