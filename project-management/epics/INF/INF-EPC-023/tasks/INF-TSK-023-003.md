# INF-TSK-023-003: Replace state.json with state.loro using Loro Map CRDT

## Description

The current claims system uses a plain JSON file (`state.json`) with a read-modify-write cycle that has a TOCTOU race condition. Two sessions calling `Acquire()` concurrently can both read the same state, both add their claim, and one write overwrites the other -- losing a claim. This is the central coordination bug blocking parallel execution.

This task replaces `state.json` with `state.loro` using Loro Map CRDT as the sole coordination mechanism (Decision #8). `LoroCoordinator` implements a new `Coordinator` trait (defined in this task). Loro's Map CRDT resolves concurrent inserts deterministically via last-writer-wins on the same key, eliminating the race entirely.

Per Decision #23, the LoroDoc namespace must reserve containers for future knowledge graph sync (Epic C): `kg_entities`, `kg_relationships`, `kg_metadata`, `extraction_queue`.

## Approach

1. Define `Coordinator` trait in `coordination/mod.rs` and `LoroCoordinator` struct implementing it
2. Initialize `LoroDoc` with named containers: `claims` (LoroMap), `merge_queue` (LoroList), `kg_entities` (LoroMap, reserved), `kg_relationships` (LoroMap, reserved), `kg_metadata` (LoroMap, reserved), `extraction_queue` (LoroList, reserved)
3. Implement `acquire(pattern, session_id)`: insert claim into LoroMap with `{owner, token, ttl, timestamp}` value
4. Implement `release(pattern, session_id)`: remove claim from LoroMap
5. Implement `check(pattern)`: read claim from LoroMap, check TTL expiry
6. Persist LoroDoc to `.state/coordination/state.loro` via `doc.export(Snapshot)` with atomic temp+rename
7. Load state on startup via `LoroDoc::from_snapshot(bytes)`
8. Write concurrency tests using Rust's `std::thread` with two threads acquiring the same pattern

12. Property-based test (proptest): concurrent claims are commutative -- Loro CRDT merge produces same final state regardless of operation order, at least 100 random test cases
13. LoroDoc namespace reserves kg_entities, kg_relationships, kg_metadata, extraction_queue containers for Epic C (Decision #23)
14. Code coverage >= 85% per file (measured by cargo-llvm-cov)
