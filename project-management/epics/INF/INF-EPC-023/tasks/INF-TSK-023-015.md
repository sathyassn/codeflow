# INF-TSK-023-015: Pre-created worktree detection in SessionStart

## Description

In the autorun flow, the batch orchestrator may pre-create worktrees for workers before invoking Claude. When a worker's SessionStart fires, it must detect the pre-created worktree and skip creation rather than attempting to create a second one (which would fail or produce a duplicate).

Detection is dual-condition: the worktree path directory must exist AND contain the `.state/` directory structure (symlinks + fresh directories). This prevents false positives from stale directory remnants.

## Approach

1. In SessionStart run() Section 2b (lines 191-209), add pre-created detection BEFORE create_session_worktree():
   a. Call detect_precreated_worktree() -- checks process env first, then env file, then validates directory + .state/runtime/ structure
   b. If detected: return (Some(paths), None) -- no WorktreeHandle (orchestrator manages lifecycle, not worker's RAII guard)
   c. If not detected: fall through to create_session_worktree() as before
2. New methods (following public/inner split pattern):
   a. detect_precreated_worktree() -- reads std::env::var, delegates to inner
   b. detect_precreated_worktree_inner() -- takes explicit params for testability
3. Detection logic (dual-condition per AC #4):
   a. Primary signal: std::env::var("CODEFLOW_WORKTREE_PATH") (process env from orchestrator)
   b. Fallback: session::read_env_file(runtime_dir) -> env.worktree_path
   c. If path found: check directory exists AND .state/runtime/ exists
   d. If both pass: pre-created worktree confirmed
   e. If directory exists but .state/runtime/ missing: warn, return None
4. When pre-created detected, also:
   a. Update registry session_id (mirrors create_session_worktree lines 960-967)
   b. Update main env file with worker's session_id (mirrors lines 971-986)
5. Write tests for detection with and without pre-created worktrees
