# INF-TSK-023-017: Merge conflict detection before PR creation

## Description

When multiple sessions work in parallel and merge back to the target branch, later sessions may encounter merge conflicts. Currently, conflicts are only discovered at GitHub PR merge time, which wastes CI time and requires manual intervention. This task adds proactive conflict detection at PF6-COMPLETE (before `gh pr create`) so conflicts are caught early.

## Approach

1. Create core git module for merge conflict detection:
   a. Create codeflow-cli/core/src/git/mod.rs
   b. Create codeflow-cli/core/src/git/conflict.rs with:
      - pub fn check_merge_conflicts(repo_path, target_branch) -> Result<ConflictResult, GitError>
      - Uses git2::Repository::open(repo_path)
      - Finds target branch ref (remote or local)
      - Gets merge base
      - Performs in-memory merge via merge_trees
      - Checks index.has_conflicts()
      - Collects conflicting file paths
      - Returns ConflictResult { has_conflicts, conflicting_files, target_branch }
2. Add CLI subcommand: `codeflow git check-conflicts --target <branch>`
3. Handle edge cases (target not found, no common ancestor, etc.)
4. Write tests per AC #6

**Implementation Summary:**
Created a new `git` module in `codeflow-core` with merge conflict detection using git2's in-memory tree merge. The core function `check_merge_conflicts()` opens the repo, finds the target branch ref (remote or local), computes the merge base, and performs an in-memory `merge_trees()` to detect conflicts without modifying the working tree. A CLI subcommand `codeflow git check-conflicts --target <branch>` wraps the core function with exit codes: 0 (clean), 1 (conflicts, JSON output), 2 (error).
