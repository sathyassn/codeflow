### DEV Report

> Populated by cf-development before STAGE-COMPLETE: WS-DEV

**Implementation Summary:**
Restructured `codeflow worktree` from a flat command to a subcommand-based CLI (list/cleanup/prune), following the Coordination command pattern. Added two new public methods to `WorktreeManager` (`cleanup_stale`, `reconcile_registry`) for bulk operations. Created `codeflow parallel status` as a new top-level command aggregating worktree registry, Loro CRDT claims, merge queue, and coordination events into a single dashboard. Updated three documentation files with CLI integration guidance.

Key design decisions:
- `cleanup_stale` iterates all registry entries, detects state, and removes matching entries. Active worktrees are never removed.
- `reconcile_registry` compares registry vs filesystem bidirectionally: stale entries (registry but no dir) are deregistered; orphaned dirs (on disk but not in registry) are reported only.
- All registry mutations use locked variants (`locked_read_registry`, `locked_deregister_worktree`) for concurrent safety.
- `parallel status` reads coordination-events.jsonl directly (last 10 lines) rather than requiring a Loro coordinator, keeping the display path simple.
