## Description

Implement `codeflow worktree cleanup` (remove stale worktrees, deregister from YAML), `codeflow worktree prune` (reconcile registry vs filesystem), and `codeflow parallel status` (live dashboard of active worktrees, per-worker claims, merge queue position).

## Approach

1. Read `codeflow-cli/cli/src/cmd/worktree.rs` to understand existing `list` command structure
2. Read `codeflow-cli/core/src/worktree/cleanup.rs` for `CleanupOpts` and existing cleanup logic
3. Read `codeflow-cli/core/src/worktree/registry.rs` for `locked_deregister_worktree()` and `read_registry()`
4. Read `codeflow-cli/core/src/worktree/mod.rs` for `WorktreeState` enum values
5. Add `cleanup` and `prune` subcommands to `worktree.rs` CLI handler
6. Implement prune logic: diff registry entries against `git worktree list` output
7. Add unit tests for both commands
8. Add integration test: create → delete dir → prune → verify
9. Update `cf-cleanup.md` and `cf-doctor.md`

## Files

### To Modify

- `codeflow-cli/cli/src/cmd/worktree.rs` — add `cleanup` and `prune` subcommand handlers
- `codeflow-cli/core/src/worktree/cleanup.rs` — extend `CleanupOpts` with prune flags if needed
- `.claude/commands/cf-cleanup.md` — worktree cleanup integration
- `.claude/commands/cf-doctor.md` — worktree health check using new commands

## Acceptance Criteria

1. `codeflow worktree cleanup` removes all worktrees with WorktreeState::Stale status
2. `codeflow worktree cleanup --force` removes all non-active worktrees regardless of state
3. `codeflow worktree prune` detects and fixes registry/filesystem inconsistencies
4. Prune reports orphaned worktrees (on disk not in registry) and stale entries (in registry not on disk)
5. `codeflow parallel status` shows active worktrees (count + name/branch/task), active claims (per-worker file list), merge queue entries with position, and recent coordination events (conflicts, expansions) from `coordination-events.jsonl`
6. Both cleanup/prune commands use WorktreeManager methods (no raw git commands)
7. CleanupOpts configuration respected (force, dry-run, prune flags)
8. Unit tests for cleanup, prune, and status commands
9. Integration test: create worktree, delete directory manually, run prune, verify registry updated
10. Update `.claude/commands/cf-cleanup.md` with worktree cleanup integration
11. Update `.claude/commands/cf-doctor.md` worktree health checks to use these commands
12. Update `.codeflow/docs/analysis/parallel-work/worktree-architecture.md` with CLI operations section

- `codeflow-cli/core/src/worktree/cleanup.rs` — `CleanupOpts`, `cleanup_worktree()`

- `codeflow-cli/cli/src/cmd/parallel.rs` — `parallel status` command
- `codeflow-cli/core/src/coordination/claims.rs` — per-worker claim data for status display
- `codeflow-cli/core/src/coordination/merge_queue.rs` — queue position for status display

The prune command should use `git worktree list --porcelain` as the filesystem source of truth, then diff against the registry YAML. Orphaned = in git but not in registry. Stale = in registry but directory missing. The `parallel status` command aggregates data from worktree registry, claims coordinator, and merge queue into a single dashboard view.
