# INF-TSK-042-001: Fix worktree cleanup output, classification, and force-id scoping

## Description

Fix 8 findings in the `codeflow worktree cleanup` command identified as follow-up to PR #245:

1. **Single classify_entry function** — cleanup_stale and cleanup_orphan both classify entries but with duplicated/inconsistent logic. Extract a single `classify_entry(entry, force_names)` function used by both paths.
2. **force_names scoping** — `--force <id>` should only bypass protection for the specific entry matching that ID, not all entries sharing the same name.
3. **Configurable Unknown threshold** — The age threshold for classifying a worktree entry as Unknown (currently hardcoded) should be configurable via `parallel-work-config.json`.
4. **Status-aware classification** — cleanup_stale shows entries as "Active" even when their `WorktreeStatus` is Stale or Unknown. Should reflect actual computed status.
5. **Unified output** — cleanup_stale and cleanup_orphan produce differently formatted messages for removed/skipped/dry-run items. Unify format.
6. **Dry-run orphan reporting** — `--dry-run` suppresses orphan reporting entirely. Should list orphans that would be removed.
7. **force-id orphan message** — `--force <id>` targeting an orphan silently skips it. Should produce an informative message.
8. **Removal count includes orphans** — The summary "Removed N worktrees" only counts stale entries, not orphans. Should include orphans in the count.
