# INF-TSK-021-036: Migrate protection management scripts to Go

> **MANDATORY VALIDATION:** Files created from this template MUST be validated against the task validation script before committing:
> `bash .codeflow/scripts/validation/validate-task.sh <file-path>`
> Fix all errors (exit code 1) before requesting a commit. Warnings are advisory. Script is at `.codeflow/scripts/validation/validate-task.sh`.

## Description

Three shell scripts manage the CodeFlow protected resource system. Two are pure text file I/O and suitable for Go migration; one requires sudo for filesystem permission changes and must remain as shell.

### Migration scope

| Script | Lines | Sudo? | Strategy |
|---|---|---|---|
| `cf-promote-protection.sh` | 179 | No | FULL migration → `codeflow protection promote <path>` |
| `cf-reload-protection.sh` | 246 | No | FULL migration → `codeflow protection reload` |
| `cf-protect-resources.sh` | 420 | Yes (chown root + chmod 444) | RETAINED AS SHELL |

Note: The migration analysis doc previously marked `cf-promote-protection.sh` and `cf-reload-protection.sh` as requiring sudo. This was incorrect — only `cf-protect-resources.sh` truly needs sudo. The other two are pure text file I/O (reading and writing `.list` files and building a cache JSON).

### Promote command

`codeflow protection promote <path>` moves a resource path from the ad-hoc protection list (`protected-adhoc.list`) to the extended permanent list (`protected-extended.list`). The ad-hoc list entry is removed and the extended list entry is added. Both list files live under the project's config directory.

### Reload command

`codeflow protection reload` reads all three protection config sources, validates their structure, and builds a combined cache JSON at `/tmp/claude/managed/protection-cache.json`. The cache is read by hooks to resolve protection level without re-parsing config on every hook invocation.

Config sources:

1. `enforcement-policy.json` (core protection rules)
2. `protected-extended.list` (permanent extended protection paths)
3. `protected-adhoc.list` (session-scoped ad-hoc protection paths)

## Approach

1. Create `codeflow-cli/internal/protection/` package:
   - `promote.go`:
     - `func Promote(projectDir, path string) error` -- reads `protected-adhoc.list`, removes the path entry, appends to `protected-extended.list`
     - Handles: path not in ad-hoc list (error), path already in extended list (idempotent), missing list files (create if absent)
   - `reload.go`:
     - `type ProtectionCache struct { CorePolicies []string; Extended []string; AdHoc []string; BuildTime time.Time }`
     - `func Reload(projectDir string) (*ProtectionCache, error)` -- validates all 3 sources, builds combined cache
     - `func WriteCacheJSON(cache *ProtectionCache) error` -- writes to `/tmp/claude/managed/protection-cache.json`
     - Handles: missing config files (treat as empty, not error), invalid JSON in enforcement-policy.json (error)
2. Create `codeflow-cli/cmd/codeflow/protection.go`:
   - Register `protection` subcommand with child commands: `promote`, `reload`
3. Create `codeflow-cli/internal/protection/protection_test.go`:
   - Tests for promote: valid path move, path not in ad-hoc list, already in extended, missing files
   - Tests for reload: valid sources, missing sources, invalid JSON, cache write
4. Update `config/testing/test-config.json`:
   - Add `./internal/protection/...` to business_packages

## Notes

- The migration analysis doc incorrectly marks `cf-promote-protection.sh` and `cf-reload-protection.sh` as requiring sudo. Only `cf-protect-resources.sh` truly needs sudo (chown root + chmod 444). The other two are pure text file I/O.
- `cf-protect-resources.sh` is intentionally NOT migrated. Requiring sudo for filesystem ownership changes is fundamentally incompatible with a Go CLI binary running in non-root context.
- The protection cache at `/tmp/claude/managed/protection-cache.json` is ephemeral (not git-tracked). It is regenerated by `protection reload` when the config sources change.
- Both list files (`protected-extended.list`, `protected-adhoc.list`) use one-path-per-line format. Blank lines and lines starting with `#` are treated as comments.
- **Go test conventions:** Go tests must achieve >= 85% coverage on new business packages per test-config.json. All test functions must use `t.Parallel()`. Do not use `context.Background()` (use `context.TODO()` or test-specific context). New packages registered in test-config.json business_packages (or noted in INF-TSK-021-028 for batch registration).
