# INF-TSK-021-023: Integration testing -- full PathFlow lifecycle with Go hooks

## Description

The critical pre-cutover verification task (Phase C). After all Go subcommands are built, this task runs a complete PathFlow lifecycle test by calling Go subcommands directly (not via settings.json wiring). This tests the Go implementations in isolation: session start, phase progression, sentinel creation, gate enforcement, security checks, and session end. Any failure here means a Go subcommand has a bug that must be fixed before the cutover task (INF-TSK-021-022) can proceed. Note: this tests Go subcommands directly; the separate shadow testing task (INF-TSK-021-029, if created) would test Go-vs-shell comparison.

## Approach

1. Create `codeflow-cli/internal/integration/` package:
   - `lifecycle_test.go`:
     - `func TestFullPathFlowLifecycle(t *testing.T)` -- end-to-end test:
       1. Create temp project dir with required config files (enforcement-policy.json, pathflow-config.json)
       2. Set `CODEFLOW_SESSION_ID=ses-test-{timestamp}` env var
       3. Call `session.StartInit()` -- verify session dir created, pathflow-active flag set, checkpoint initialized for 7 phases
       4. Simulate PF1-PF3 phase tasks: call `pathflow.RegisterTask()` + `pathflow.CompleteTask()` for each, verify pf-1, pf-2, pf-3 sentinels created
       5. Call `gate.Check()` with Edit tool input -- verify ALLOWED (pf-3 exists)
       6. Call `gate.Check()` with Edit tool input WITHOUT pf-3 sentinel -- verify BLOCKED (exit 2)
       7. Simulate WS-DEV stage: call `sentinel.CheckAndCreateStageSentinel()` with STAGE-COMPLETE pattern -- verify `pathflow-ws-dev` sentinel created
       8. Call `security.Check()` with dangerous command input -- verify BLOCKED
       9. Call `security.Check()` with safe command input -- verify ALLOWED
       10. Call `team.CheckTeamDelete()` with pathflow-active flag -- verify BLOCKED
       11. Call `team.CheckTeamDelete()` with pf-6 sentinel -- verify ALLOWED
       12. Simulate WS-REV, WS-QA stages, PF5-PF7 phases
       13. Call `session.EndCleanup()` -- verify pathflow-active removed, state archived, session_end event in JSONL
       14. Verify all 7 phase sentinels exist (pf-1 through pf-7)
       15. Verify JSONL ledger has session_start and session_end events with correct schema
     - `func TestGateEnforcementIndependent(t *testing.T)` -- table-driven:
       - Edit before pf-3 (block), Edit after pf-3 (allow), git push before pf-5+ws-rev (block), git push after pf-5+ws-rev (allow), role spawn before pf-3 (block), no pathflow-active (allow all)
     - `func TestSecurityEnforcementIndependent(t *testing.T)` -- table-driven:
       - `rm -rf /` (block), `sudo` (block), `git push --force` (block), `ls` (allow), `cat file.txt` (allow)
     - `func TestSentinelPipelineIndependent(t *testing.T)` -- table-driven:
       - STAGE-COMPLETE pattern creates sentinel, no pattern no sentinel, checkpoint register/complete lifecycle, phase sentinel created when all tasks done
   - `testdata/`:
     - `enforcement-policy.json` -- test enforcement policy
     - `pathflow-config.json` -- test pathflow config
     - `hook-stdin-samples/` -- sample stdin JSON for each hook event type
   - `runbook.md`:
     - Step-by-step manual verification procedure
     - How to run integration tests: `cd codeflow-cli && go test -v -timeout 300s ./internal/integration/...`
     - Expected output for each test
2. Run `./codeflow test` to verify existing test suite not regressed
3. Run `go test -race ./internal/integration/...` to verify no race conditions
