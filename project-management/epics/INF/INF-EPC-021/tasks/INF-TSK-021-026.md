# INF-TSK-021-026: Normalize ledger JSONL schemas and rebuild SurrealDB

## Description

Normalize all 4 canonical ledger JSONL files (.state/ledger/) to consistent field names, drop internal DB artifacts, add `codeflow normalize ledger` CLI subcommand, and verify SurrealDB rebuild from normalized JSONL. Logs normalization (.state/logs/) deferred to post-cutover.

This task is Phase D in the build-coexist-cutover migration strategy. It sits between integration testing (INF-TSK-021-023, Phase C) and the atomic cutover (INF-TSK-021-022, Phase E) -- the schema must be clean before the cutover retires old infrastructure.

## Approach

1. Create `codeflow-cli/internal/ledger/normalize.go`:
   - `NormalizeFile()` reads JSONL line-by-line, applies normalization consistent with `db/sync.go:normalizeEvent()`, writes atomically via temp file + `os.Rename`
   - `NormalizeAll()` normalizes all 4 canonical files from `CanonicalFiles()`
   - Normalization rules: rename `type`/`e` -> `event`, `ts` -> `timestamp`, `sid` -> `session_id`, map `op`+`table` -> semantic event, drop unmappable records
   - Idempotent, dry-run capable, preserves malformed lines
2. Create `codeflow-cli/cmd/codeflow/normalize.go`:
   - `codeflow normalize ledger [--dry-run] [--ledger-dir PATH]` at root command level
3. Verify SurrealDB rebuild via `codeflow db sync` after normalization
4. Add mixed-schema sync tests to `sync_test.go`
