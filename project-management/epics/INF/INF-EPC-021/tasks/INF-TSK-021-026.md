# INF-TSK-021-026: Normalize JSONL schema and rebuild SQLite

## Description

The JSONL ledger files have accumulated schema inconsistencies over time. `memory-events.jsonl` uses `type` instead of `event` and `ts` instead of `timestamp`, which differs from the other 3 JSONL files. It also contains raw `op:INSERT` entries that are internal DB artifacts rather than semantic events. Before the final cutover to Go-only hooks, the JSONL schema should be normalized so the Go binary can enforce a single canonical schema. After normalization, SQLite is rebuilt from the cleaned JSONL to ensure consistency.

This task sits between integration testing (INF-TSK-021-023) and final script retirement (INF-TSK-021-025) in the migration sequence -- the schema must be clean before the old infrastructure is removed.

## Approach

1. Create `codeflow-cli/internal/ledger/normalize.go`:
   - `type NormalizeConfig struct { DryRun bool }` -- controls whether changes are written
   - `type NormalizeResult struct { File string; RecordsRead int; RecordsWritten int; RecordsDropped int; FieldsRenamed int }` -- reports changes
   - `func NormalizeFile(filePath string, config NormalizeConfig) (*NormalizeResult, error)` -- main entry point:
     1. Open JSONL file for reading line by line
     2. For each line: `json.Unmarshal` into `map[string]any`
     3. Apply normalization rules per file:
        - `memory-events.jsonl`: rename `"type"` key to `"event"`, rename `"ts"` key to `"timestamp"`, drop records where `"op"` == `"INSERT"` (internal DB artifacts)
        - `pathflow-events.jsonl`: drop records where `"op"` == `"INSERT"` if present
        - `work-graph.jsonl`: already canonical (validate, no changes)
        - `session-events.jsonl`: already canonical (validate, no changes)
     4. `json.Marshal` back to single-line JSON
     5. Write to temp file, then `os.Rename` to original (atomic replacement)
     6. Return result with counts
   - `func NormalizeAll(ledgerDir string, config NormalizeConfig) ([]*NormalizeResult, error)` -- normalizes all 4 JSONL files
   - Idempotency: running twice produces identical output (field rename is no-op if already renamed, INSERT filter is no-op if already filtered)
   - `normalize_test.go`:
     - Table-driven: memory-events with `type` field renamed to `event`, memory-events with `ts` renamed to `timestamp`, op:INSERT records dropped, already-canonical records unchanged, empty file (no-op), dry-run mode reports but doesn't write, idempotent (normalize twice = same output), malformed JSON line (skip with warning, preserve)
2. Add `codeflow ledger normalize` CLI subcommand:
   - `codeflow ledger normalize [--dry-run]` -- normalizes all JSONL files
   - `--dry-run` reports what would change without writing
   - Outputs summary: files processed, records read, records written, records dropped, fields renamed
3. Enhance `codeflow db rebuild` (in `codeflow-cli/internal/db/rebuild.go`):
   - `func RebuildFromJSONL(dbPath, ledgerDir string) error` -- drops all tables, re-creates schema, reads all JSONL files, inserts records into SQLite
   - Must handle both old field names (`type`, `ts`) and new field names (`event`, `timestamp`) during transition period -- normalize internally if needed
   - `rebuild_test.go`:
     - Rebuild from normalized JSONL (all records present), rebuild from mixed schema (old+new field names), rebuild with empty JSONL (empty tables), record count verification
