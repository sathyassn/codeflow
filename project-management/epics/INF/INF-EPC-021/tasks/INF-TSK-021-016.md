# INF-TSK-021-016: Migrate settings and staging scripts to Go binary

## Description

Two settings management scripts and five security staging scripts handle operational configuration. The settings scripts manage approval modes and initial settings setup. The staging scripts implement a staged-edit workflow for protected files (stage an edit, review, apply/reject). All are straightforward shell scripts suitable for Go migration.

## Approach

1. Create `codeflow-cli/internal/settings/` package:
   - `approval.go`:
     - `type ApprovalMode string` -- `const ModePlan ApprovalMode = "plan"`, `const ModeSuggest = "suggest"`, `const ModeAutoEdit = "auto-edit"`
     - `func GetApprovalMode(settingsPath string) (ApprovalMode, error)` -- reads `.claude/settings.json`, extracts `permissions.allow` array to determine mode
     - `func SetApprovalMode(settingsPath string, mode ApprovalMode) error` -- reads settings JSON, modifies `permissions.allow` array, writes back atomically (tmp+rename), preserves all other settings
     - `func ValidateMode(mode string) (ApprovalMode, error)` -- validates input string against known modes
     - Replaces: `cf-change-approval-mode.sh` (558 lines)
   - `managed.go`:
     - `func SetupManagedSettings(projectDir string) error` -- creates `.claude/settings.json` if missing, merges managed settings template (hook entries, permissions) from `.codeflow/config/` into existing settings without overwriting user customizations
     - `func MergeSettings(existing, managed map[string]any) map[string]any` -- deep merge with managed values taking precedence for hook entries only
     - Replaces: `setup-managed-settings.sh` (417 lines)
   - `settings_test.go`:
     - Get/set approval mode (plan, suggest, auto-edit), set invalid mode (error), settings.json preserved on mode change, managed settings merge (new file, existing file, no overwrite of custom keys)
2. Create `codeflow-cli/internal/staging/` package:
   - `staging.go`:
     - `type StagedEdit struct { ID string; FilePath string; OriginalContent []byte; ProposedContent []byte; StagedAt time.Time; ExpiresAt time.Time }`
     - `type Manager struct { StagingDir string; DefaultTTL time.Duration }` -- manages staged edits in `.state/staging/`
     - `func (m *Manager) Stage(filePath string, proposedContent []byte) (*StagedEdit, error)` -- reads original, saves both to staging dir, returns edit ID
     - `func (m *Manager) Apply(editID string) error` -- reads staged edit, writes proposed content to target file atomically, removes staging record
     - `func (m *Manager) Reject(editID string) error` -- removes staging record without applying
     - `func (m *Manager) Rollback(editID string) error` -- restores original content from staging record, removes staging record
     - `func (m *Manager) CleanupExpired() (int, error)` -- removes all expired staging records (TTL check), returns count removed
     - Replaces: 5 staging scripts totaling 1,099 lines
   - `staging_test.go`:
     - Stage + apply (file updated), stage + reject (file unchanged), stage + rollback (file restored), cleanup expired (removed), cleanup non-expired (preserved), concurrent staging
3. Add CLI subcommands:
   - `codeflow settings approval-mode [plan|suggest|auto-edit]` -- get or set mode
   - `codeflow settings setup-managed` -- initialize managed settings
   - `codeflow staging stage --file <path>` -- stage an edit
   - `codeflow staging apply --id <edit-id>` -- apply staged edit
   - `codeflow staging reject --id <edit-id>` -- reject staged edit
   - `codeflow staging rollback --id <edit-id>` -- rollback to original
   - `codeflow staging cleanup` -- remove expired staged edits
4. Replace shell scripts with Go binary invocations
