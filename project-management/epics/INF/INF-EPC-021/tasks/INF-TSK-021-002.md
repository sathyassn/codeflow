# INF-TSK-021-002: Migrate ULID generation and format ID to Go CLI

## Description

Currently, `ulid.sh` shells out to `python3` to generate ULIDs (via `codeflow_py_lib/ulid_generator.py`), and `generate-format-id.sh` calls `sqlite3` directly to compute sequential format IDs. Both are fragile: ulid.sh fails if python3 is missing, and generate-format-id.sh has shell quoting issues with sqlite3 queries. This task replaces both with native Go implementations, eliminating the python3 dependency for ID generation and providing type-safe SQLite queries.

## Approach

1. Create `codeflow-cli/internal/idgen/` package:
   - `ulid.go` -- `NewULID() string`: generates ULID using `oklog/ulid` with `crypto/rand` entropy source and `time.Now()` timestamp; `NewPrefixedULID(prefix string) string`: returns `{prefix}-{ulid}` for `task-{ulid}`, `epic-{ulid}`, `ses-{ulid}` patterns
   - `formatid.go` -- `NextFormatID(db *sql.DB, tableName string, areaType string) (string, error)`: queries `SELECT MAX(CAST(SUBSTR(format_id, -3) AS INTEGER)) FROM {table} WHERE area_type = ?`, increments, zero-pads to 3 digits, returns `{AREA}-{PREFIX}-{NNN}`
   - `idgen_test.go` -- table-driven tests: ULID format (26 chars, Crockford base32), prefix patterns, format ID sequencing from empty table, from existing IDs, gap handling
2. Add CLI subcommands:
   - `codeflow internal ulid [--prefix <prefix>]` -- prints ULID to stdout
   - `codeflow db generate-id --table <tasks|epics> --area <AREA>` -- prints next format ID

- The `oklog/ulid` library is likely already a dependency via the session package. Check `go.mod` before adding.
