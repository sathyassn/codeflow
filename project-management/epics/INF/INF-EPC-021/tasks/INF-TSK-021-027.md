# INF-TSK-021-027: Update git hooks and CI workflows for post-migration compatibility

## Description

After the atomic cutover (INF-TSK-021-022) retires shell scripts and INF-TSK-021-035 writes the thin shell wrappers for git hooks, CI workflows need updates to reflect the new file structure. The CI workflow still has Python-specific steps that become dead weight. The coverage pairing check still expects shell test files for migrated hooks. This task ensures the retained CI infrastructure works correctly in the post-migration environment.

**Scope boundary:** Git hook thin wrapper content (pre-commit, post-commit, commit-msg, pre-push, prepare-commit-msg) is owned by INF-TSK-021-035. This task does NOT modify git hook scripts — only CI workflows and coverage pairing tooling are updated here.

## Approach

1. Update `check-test-coverage-pairing.sh`:
   - Remove expectations for .sh test files paired with migrated hook .sh files (hooks are now thin wrappers, no shell test files expected)
   - Add validation that Go test coverage exists for migrated packages in `internal/githooks/`
2. Update `.github/workflows/test-suite.yml`:
   - Remove Python venv creation, pip install, and pytest steps
   - Retain and update Go test job (`make test-cover`)
   - Ensure test-go job runs `make build` before `make test-cover` to ensure compiled binary is available for integration tests
3. Verify (do not modify) all 5 git hook tests still pass after cutover:
   - `bash .codeflow/testing/scripts/git-hooks/test-pre-commit.sh`
   - `bash .codeflow/testing/scripts/git-hooks/test-commit-msg.sh`
   - `bash .codeflow/testing/scripts/git-hooks/test-post-commit.sh`
   - `bash .codeflow/testing/scripts/git-hooks/test-pre-push.sh`
   - `bash .codeflow/testing/scripts/git-hooks/test-prepare-commit-msg.sh`

## Notes

- This task is a terminal task in the dependency chain (post-cutover, blocked by INF-TSK-021-035 only).
- The git hooks are in `.codeflow/scripts/git-hooks/`, separate from the Claude Code hooks in `.claude/hooks/codeflow/`.
- The pre-commit hook uses the hybrid pattern: thin wrapper calls `codeflow git-hooks pre-commit-validate` for pure-logic checks; shell wrapper retains linting tool invocations (shellcheck, ruff, markdownlint with auto-fix+re-staging) because linting tools must remain as shell subprocesses.
- commit-msg, post-commit, pre-push, and prepare-commit-msg are fully migrated to Go via INF-TSK-021-035; their thin wrappers simply call `codeflow git-hooks <hook-name>`.
- See INF-TSK-021-035 for the git hooks Go migration build task.
- **Go test conventions:** Go tests must achieve >= 85% coverage on new business packages per test-config.json. All test functions must use `t.Parallel()`. Do not use `context.Background()` (use `context.TODO()` or test-specific context). New packages registered in test-config.json business_packages (or noted in INF-TSK-021-028 for batch registration).
