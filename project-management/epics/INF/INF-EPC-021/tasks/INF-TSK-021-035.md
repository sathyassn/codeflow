# INF-TSK-021-035: Migrate git hooks to Go with thin shell wrappers

> **MANDATORY VALIDATION:** Files created from this template MUST be validated against the task validation script before committing:
> `bash .codeflow/scripts/validation/validate-task.sh <file-path>`
> Fix all errors (exit code 1) before requesting a commit. Warnings are advisory. Script is at `.codeflow/scripts/validation/validate-task.sh`.

## Description

The git hooks in `.codeflow/scripts/git-hooks/` contain 5 scripts totalling ~1,445 lines of shell. Four hooks are pure logic (string validation, JSON logging, branch protection, template generation) with no tool invocation dependency — these are suitable for full Go migration. One hook (`pre-commit`) invokes linting tools (shellcheck, ruff, markdownlint) that must remain as shell subprocesses, making it suitable for a hybrid pattern.

The migration pattern is:

- **Thin shell wrapper**: Replaces the existing shell hook with a minimal script that calls `exec codeflow git-hooks <hook-name> "$@"` (or the hybrid pattern for pre-commit).
- **Go subcommand**: Implements the full hook logic as `codeflow git-hooks <hook-name>` reading the same stdin/args as the original shell hook.
- **Config-driven**: All tunable parameters (protected branches, commit types, AI attribution patterns, subject length limits) come from `enforcement-policy.json`. Downstream project teams customize via config, not shell code.

`git core.hooksPath` is already set to `.codeflow/scripts/git-hooks/` so the wrappers are picked up automatically.

### Migration scope

| Hook | Lines | Strategy | Go command |
|---|---|---|---|
| `commit-msg` | 309 | FULL migration | `codeflow git-hooks commit-msg <file>` |
| `post-commit` | 73 | FULL migration | `codeflow git-hooks post-commit` |
| `pre-push` | 275 | FULL migration | `codeflow git-hooks pre-push <remote> <url>` (reads refs from stdin) |
| `prepare-commit-msg` | 116 | FULL migration | `codeflow git-hooks prepare-commit-msg <file> <source>` |
| `pre-commit` | 672 | HYBRID | Shell retains linting; `codeflow git-hooks pre-commit-validate` for pure-logic checks |

### Pre-commit hybrid pattern

The pre-commit hook retains shell for linting tool invocations (shellcheck, ruff, markdownlint with auto-fix+re-staging), but delegates pure-logic checks to Go:

1. Shell wrapper calls `codeflow git-hooks pre-commit-validate` for: branch protection, sensitive file detection, JSON validation, Go test conventions (t.Parallel requirement), coverage enforcement check
2. If `pre-commit-validate` exits non-zero, shell wrapper exits non-zero (blocks commit)
3. Shell wrapper then invokes linting tools (shellcheck, ruff, markdownlint)

## Approach

1. Create `codeflow-cli/internal/githooks/` package:
   - `commitmsg.go`: Validates conventional commit format (type, scope, subject length, body rules, AI attribution detection). All config from enforcement-policy.json.
   - `postcommit.go`: Collects commit metadata (hash, author, timestamp, message), writes JSON log entry to `.state/logs/git/commits-{date}.jsonl`. Eliminates jq JSON construction bug by using `encoding/json`.
   - `prepush.go`: Reads pushed refs from stdin, checks each ref against protected branch list, detects force-push via `git merge-base`, supports TTY override via `os.Open("/dev/tty")`.
   - `preparecommitmsg.go`: Reads branch name via `git symbolic-ref HEAD`, extracts task ID prefix from branch name pattern, writes template to commit message file.
   - `precommitvalidate.go`: Pure-logic checks: branch protection, sensitive file patterns, JSON syntax validation, Go test convention checks (t.Parallel, context.TODO), coverage pairing check.
2. Create `codeflow-cli/cmd/codeflow/githooks.go`:
   - Register `git-hooks` subcommand with child commands: `commit-msg`, `post-commit`, `pre-push`, `prepare-commit-msg`, `pre-commit-validate`
3. Update thin shell wrappers in `.codeflow/scripts/git-hooks/`:
   - `commit-msg`: `exec codeflow git-hooks commit-msg "$1"`
   - `post-commit`: `exec codeflow git-hooks post-commit`
   - `pre-push`: `exec codeflow git-hooks pre-push "$1" "$2"`
   - `prepare-commit-msg`: `exec codeflow git-hooks prepare-commit-msg "$1" "${2:-}"`
   - `pre-commit`: Hybrid — call `codeflow git-hooks pre-commit-validate`, then shell linting
4. Update `config/testing/test-config.json`:
   - Add `./internal/githooks/...` to business_packages
5. Update existing git hook tests in `.codeflow/testing/scripts/git-hooks/` to test against Go implementations

## Notes

- This task changes the migration analysis classification of git hooks from "permanently retained shell" to "partially migrated (hybrid)." Pre-commit remains hybrid due to linting tool invocations (shellcheck, ruff, markdownlint) that must remain as shell subprocesses. All other hooks are fully migrated.
- The thin wrapper pattern: `#!/usr/bin/env bash` + `exec codeflow git-hooks commit-msg "$@"`. The `exec` replaces the shell process with the Go binary, reducing process overhead.
- `post-commit` eliminates the jq JSON construction bug present in the shell implementation. Using `encoding/json` in Go produces correct JSON escaping without manual string manipulation.
- `pre-push` needs TTY access for interactive override prompts. Use `os.Open("/dev/tty")` to read from terminal when stdin is the push ref stream.
- All commit types and protected branch patterns come from `enforcement-policy.json` — no hardcoded values in Go source.
- **Go test conventions:** Go tests must achieve >= 85% coverage on new business packages per test-config.json. All test functions must use `t.Parallel()`. Do not use `context.Background()` (use `context.TODO()` or test-specific context). New packages registered in test-config.json business_packages (or noted in INF-TSK-021-028 for batch registration).
