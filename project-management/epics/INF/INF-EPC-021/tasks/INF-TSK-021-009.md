# INF-TSK-021-009: Migrate sentinel pipeline hooks to Go binary

## Description

The sentinel pipeline is a three-hook system that manages PathFlow phase progression:

1. `cf-post-tool-use-pathflow-sentinel.sh` -- creates stage sentinels (ws-dev, ws-rev, etc.) by pattern-matching STAGE-COMPLETE messages
2. `cf-post-tool-use-phase-checkpoint.sh` -- registers PF{N}-TSK-{NN} tasks in the checkpoint when TaskCreate fires
3. `cf-task-completed-phase-checkpoint.sh` -- marks tasks complete and creates phase sentinels (pf-1 through pf-7)

These are the most performance-critical hooks as they fire on every tool call. Shell sourcing overhead is highest here.

## Approach

1. Create `codeflow-cli/internal/hooks/sentinel/` package:
   - `stage.go`:
     - `func CheckAndCreateStageSentinel(stdin io.Reader, sentinelDir string) error` -- parses PostToolUse stdin JSON, scans `tool_output` for `STAGE-COMPLETE: WS-{STAGE}` pattern via `regexp.MustCompile("STAGE-COMPLETE:\\s*WS-(DEV|REV|QA|DOCS|PLAN|TEST)")`, creates sentinel file `pathflow-ws-{stage}` in sentinelDir
     - Also handles `TeamDelete` pattern for pathflow-active flag removal
   - `checkpoint.go`:
     - `func RegisterCheckpointTask(stdin io.Reader, sessionDir string) error` -- parses PostToolUse stdin for TaskCreate calls, extracts task subject matching `PF{N}-TSK-{NN}` pattern, delegates to `pathflow.RegisterTask()`; blocks cross-phase registration (exit 2) if previous phase sentinel missing
     - `func CompleteCheckpointTask(stdin io.Reader, sessionDir string) error` -- parses TaskCompleted event, delegates to `pathflow.CompleteTask()`; auto-creates phase sentinel when all tasks done/skipped
   - `sentinel_test.go`:
     - Stage pattern matching: "STAGE-COMPLETE: WS-DEV" creates `pathflow-ws-dev`, no match -> no sentinel
     - Checkpoint registration: valid PF task registered, cross-phase block, non-PF task ignored
     - Checkpoint completion: all tasks done -> phase sentinel created, partial -> no sentinel
     - Concurrency: two goroutines completing tasks simultaneously
2. Add CLI subcommands (registered in `codeflow-cli/cmd/codeflow/hooks.go`):
   - `codeflow hooks post-tool-use sentinel-write` -- PostToolUse hook for stage sentinels; reads stdin, pattern-matches, creates sentinel
   - `codeflow hooks post-tool-use checkpoint-register` -- PostToolUse hook for phase checkpoint; reads stdin, registers PF task
   - `codeflow hooks task-completed checkpoint-complete` -- TaskCompleted hook; reads stdin, completes PF task, may create phase sentinel
3. Replace shell scripts:
   - `.claude/hooks/codeflow/post-tool-use/cf-post-tool-use-pathflow-sentinel.sh` (267 lines): `exec "$CODEFLOW_CLI" hooks post-tool-use sentinel-write`
   - `.claude/hooks/codeflow/post-tool-use/cf-post-tool-use-phase-checkpoint.sh` (180 lines): `exec "$CODEFLOW_CLI" hooks post-tool-use checkpoint-register`
   - `.claude/hooks/codeflow/task-completed/cf-task-completed-phase-checkpoint.sh` (237 lines): `exec "$CODEFLOW_CLI" hooks task-completed checkpoint-complete`
4. **settings.json hook entry changes:**
   - Sentinel before: `"command": "bash \"$CLAUDE_PROJECT_DIR\"/.claude/hooks/codeflow/post-tool-use/cf-post-tool-use-pathflow-sentinel.sh"`
   - Sentinel after: `"command": "\"$CLAUDE_PROJECT_DIR\"/codeflow-cli/bin/codeflow hooks post-tool-use sentinel-write"`
   - Phase-checkpoint before: `"command": "bash \"$CLAUDE_PROJECT_DIR\"/.claude/hooks/codeflow/post-tool-use/cf-post-tool-use-phase-checkpoint.sh"`
   - Phase-checkpoint after: `"command": "\"$CLAUDE_PROJECT_DIR\"/codeflow-cli/bin/codeflow hooks post-tool-use checkpoint-register"`
   - Task-completed before: `"command": "bash \"$CLAUDE_PROJECT_DIR\"/.claude/hooks/codeflow/task-completed/cf-task-completed-phase-checkpoint.sh"`
   - Task-completed after: `"command": "\"$CLAUDE_PROJECT_DIR\"/codeflow-cli/bin/codeflow hooks task-completed checkpoint-complete"`

## Notes

- Stage sentinel patterns: "STAGE-COMPLETE: WS-DEV", "STAGE-COMPLETE: WS-REV", etc.
- Sentinel files are empty touch files. The name is the sentinel (e.g., `pathflow-ws-dev`).
- The PostToolUse hook also handles TeamDelete detection for pathflow-active flag cleanup.
- These hooks fire on EVERY tool call, so performance is critical. The Go binary should start and complete in < 10ms.
- See `.codeflow/docs/analysis/go-cli-migration-comprehensive.md` Section 4.2.4 (post-tool-use/ hooks) and Section 4.1.10 (security/sentinel/) for detailed mapping.
- **Go test conventions:** Go tests must achieve >= 85% coverage on new business packages per test-config.json. All test functions must use `t.Parallel()`. Do not use `context.Background()` (use `context.TODO()` or test-specific context). New packages registered in test-config.json business_packages (or noted in INF-TSK-021-028 for batch registration).
