# INF-TSK-021-006: Build Go CLI for security enforcement stack

## Description

The security enforcement stack is the most complex target in this epic. Currently, `cf-pre-tool-use-security.sh` sources `security-lib.sh`, which sources `context-lib.sh`, which then dispatches to 9 enforcement modules. Each shell invocation sources all libraries on every tool call (~150ms overhead). This task builds a Go binary that consolidates everything into a single compiled function call, reducing latency to near-zero while preserving all security checks.

The 9 enforcement modules are:

1. `cf-dangerous-commands.sh` -- blocks rm -rf, chmod 777, etc.
2. `cf-branch-file-protection.sh` -- protects branch-specific files
3. `cf-network-protection.sh` -- blocks unauthorized network access
4. `cf-file-operations.sh` -- validates file operation scope
5. `cf-path-protection.sh` -- protects sensitive paths
6. `cf-git-protection.sh` -- validates git commands
7. `cf-tmp-protection.sh` -- validates tmp file operations
8. `cf-pattern-matching.sh` -- regex pattern matching engine
9. `cf-privilege-protection.sh` -- blocks privilege escalation

## Approach

1. Create `codeflow-cli/internal/hooks/security/` package:
   - `checker.go` -- main orchestrator:
     - `type SecurityChecker struct { Modules []Module; Policy EnforcementPolicy }`
     - `type Module interface { Check(ctx ToolContext) (Verdict, error) }`
     - `type Verdict struct { Allow bool; Reason string; ExitCode int }`
     - `func (c *SecurityChecker) CheckBash(stdin io.Reader) (Verdict, error)` -- parses stdin JSON, extracts tool_input.command, runs all modules, returns first block or allow
     - Loads `enforcement-policy.json` from `$CLAUDE_PROJECT_DIR/.codeflow/config/enforcement/`
   - `context.go` -- Go equivalent of `context-lib.sh` (194 lines):
     - `type ToolContext struct { ToolName string; Command string; FilePath string; SessionID string; ProjectDir string }`
     - `ParseToolContext(stdin io.Reader) (ToolContext, error)` -- parses Claude Code hook JSON via `encoding/json`
   - `readers.go` -- Go equivalent of `bash-file-readers-lib.sh` (581 lines):
     - `ReadEnforcementPolicy(projectDir string) (EnforcementPolicy, error)` -- reads and caches enforcement-policy.json
     - `ReadActiveTask(runtimeDir string) (ActiveTask, error)` -- reads active-task.json
   - `dangerous.go` -- Go equivalent of `cf-dangerous-commands.sh` (180 lines):
     - `type DangerousModule struct{}` implementing `Module`
     - Pattern list: `rm -rf /`, `chmod 777`, `mkfs`, `dd if=`, etc.
   - `branch.go` -- Go equivalent of `cf-branch-file-protection.sh` (241 lines):
     - Protects `.git/`, `.github/workflows/`, branch config files
   - `network.go` -- Go equivalent of `cf-network-protection.sh` (87 lines):
     - Blocks `curl`, `wget` to non-allowlisted hosts
   - `fileops.go` -- Go equivalent of `cf-file-operations.sh` (153 lines):
     - Validates file operations against scope policy
   - `path.go` -- Go equivalent of `cf-path-protection.sh` (422 lines):
     - Blocks writes to protected paths from enforcement-policy.json `protected_paths` section
   - `git.go` -- Go equivalent of `cf-git-protection.sh` (238 lines):
     - Blocks `git push --force`, `git reset --hard`, `git branch -D` on protected branches
   - `tmp.go` -- Go equivalent of `cf-tmp-protection.sh` (70 lines):
     - Validates tmp file operations stay within allowed directories
   - `pattern.go` -- Go equivalent of `cf-pattern-matching.sh` (264 lines):
     - `MatchPattern(command string, patterns []string) bool` -- Go regexp matching engine
   - `privilege.go` -- Go equivalent of `cf-privilege-protection.sh` (163 lines):
     - Blocks `sudo`, `su`, `doas`, `pkexec` invocations
2. Add CLI subcommand in `codeflow-cli/cmd/codeflow/hooks.go`:
   - `codeflow hooks pre-tool-use security` -- reads stdin, runs all security modules, outputs verdict JSON
   - Exit codes: 0 = allow, 2 = block (with reason on stdout for Claude Code)

## Notes

- This is the largest single task (XL) due to 9 enforcement modules with complex regex patterns.
- The enforcement-policy.json at `.codeflow/config/enforcement/enforcement-policy.json` defines configurable rules. The Go binary should read this file at startup.
- Security rules must be EXACTLY preserved -- no relaxation during migration. Port tests first, then code.
- `cf-hook-bypass.sh` is dead code and should NOT be migrated (handled by INF-TSK-021-020).
- See `.codeflow/docs/analysis/go-cli-migration-comprehensive.md` Section 6.2 (Security Enforcement Stack Priority) and Section 4.1.7-4.1.12 (security/) for detailed mapping.
- **Go test conventions:** Go tests must achieve >= 85% coverage on new business packages per test-config.json. All test functions must use `t.Parallel()`. Do not use `context.Background()` (use `context.TODO()` or test-specific context). New packages registered in test-config.json business_packages (or noted in INF-TSK-021-028 for batch registration).
