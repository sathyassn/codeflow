# INF-TSK-021-018: Build Go CLI for edit-write, protected-resource, and user-prompt-submit hooks

## Description

Three remaining PreToolUse hooks (edit-write, protected-resource) and the user-prompt-submit hooks are bundled together. The edit-write hook validates file paths for scope compliance. The protected-resource hook enforces tiered protection (critical/high/moderate) for sensitive files. The user-prompt-submit hooks handle validation and logging on prompt submission. This task builds the Go equivalents of these hooks. The shell hook scripts remain unchanged during this build task.

## Approach

1. Create `codeflow-cli/internal/hooks/edit/` package:
   - `edit.go`:
     - `type ScopeChecker struct { AllowedPaths []string; DeniedPaths []string; TaskScope []string }` -- loaded from enforcement-policy.json `edit_write_scope` section + active task's `file_scope`
     - `func (c *ScopeChecker) Check(stdin io.Reader) (Verdict, error)` -- parses stdin JSON (PreToolUse for Edit/Write), extracts `tool_input.file_path`, validates:
       1. Path is within project directory (no escape via `..`)
       2. Path matches task `file_scope` if active task has `scope_policy: hard`
       3. Path not in denied paths list (e.g., `.claude/settings.json`, `.state/db/`)
       4. If `scope_policy: soft`, warn but allow paths outside file_scope
     - Exit code: 0=allow, 2=block with descriptive stderr message explaining which scope rule was violated
     - Go equivalent of: `cf-pre-tool-use-edit-write.sh` (315 lines)
   - `edit_test.go`:
     - Table-driven: path within scope (allow), path outside scope with hard policy (block), path outside scope with soft policy (allow+warn), denied path (block), path traversal attempt (block), no active task (allow all), Edit vs Write tool name handling
2. Create `codeflow-cli/internal/hooks/resource/` package:
   - `resource.go`:
     - `type ProtectionTier string` -- `const TierCritical = "critical"`, `const TierHigh = "high"`, `const TierModerate = "moderate"`
     - `type ResourceChecker struct { Resources map[string]ProtectionTier }` -- loaded from enforcement-policy.json `resource_protection` section
     - `func (c *ResourceChecker) Check(stdin io.Reader) (Verdict, error)` -- parses stdin JSON (PreToolUse for Edit/Write/Bash), extracts target file path, checks against protection tiers:
       - Critical (e.g., `.claude/settings.json`, `.state/db/codeflow.db`): BLOCK all direct modifications; require staged edit workflow
       - High (e.g., `.claude/CLAUDE.md`, `pathflow-config.json`): WARN to stderr, allow with caution message
       - Moderate (e.g., `.claude/agents/*.md`): allow, log access
     - Go equivalent of: `cf-pre-tool-use-protected-resource.sh` (290 lines)
   - `resource_test.go`:
     - Table-driven: critical resource (block), high resource (allow+warn), moderate resource (allow+log), unprotected resource (allow), Bash command targeting protected path
3. Create `codeflow-cli/internal/hooks/prompt/` package:
   - `prompt.go`:
     - `func CheckPrompt(stdin io.Reader, projectDir string) error` -- parses stdin JSON (UserPromptSubmit event), validates prompt content:
       1. Not empty
       2. Detects potential injection patterns (optional, configurable)
       3. Logs prompt metadata to session log via ledger
     - Go equivalent of: `cf-user-prompt-submit.sh` (220 lines)
   - `prompt_test.go`:
     - Valid prompt (allow), empty prompt (allow with warning), prompt metadata logged
4. Add CLI subcommands:
   - `codeflow hooks pre-tool-use edit-write-guard` -- PreToolUse hook for Edit/Write scope enforcement
   - `codeflow hooks pre-tool-use protected-resource` -- PreToolUse hook for resource protection tiers
   - `codeflow hooks user-prompt-submit validate` -- UserPromptSubmit hook for prompt validation
