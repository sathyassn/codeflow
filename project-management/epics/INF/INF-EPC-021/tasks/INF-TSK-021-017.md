# INF-TSK-021-017: Migrate logging hooks to Go binary

## Description

Five separate logging hooks fire at different lifecycle points (session-start, session-end, stop, user-prompt-submit, post-tool-use). Each is a simple shell script that reads stdin JSON and appends log entries. They share the same UUID session ID bug. This task consolidates all five into a single Go entry point parameterized by event type, fixing the session ID bug and reducing hook overhead.

## Approach

1. Create `codeflow-cli/internal/hooks/logging/` package:
   - `logging.go`:
     - `type EventType string` -- `const EventSessionStart EventType = "session-start"`, `EventSessionEnd = "session-end"`, `EventStop = "stop"`, `EventUserPromptSubmit = "user-prompt-submit"`, `EventPostToolUse = "post-tool-use"`
     - `type HookLogger struct { LogDir string; SessionID string }` -- manages log file writing
     - `func NewHookLogger(projectDir string) *HookLogger` -- resolves `LogDir` to `{projectDir}/.state/logs/` and reads `SessionID` from `os.Getenv("CODEFLOW_SESSION_ID")` (NOT stdin session_id -- fixes UUID bug)
     - `func (l *HookLogger) Log(eventType EventType, stdin io.Reader) error` -- main entry point:
       1. Parse stdin JSON into `map[string]any` (Claude Code hook format)
       2. Select log file by event type: `session-events.jsonl` for session-start/session-end, `hook-events.jsonl` for stop/post-tool-use/user-prompt-submit
       3. Build structured log record: `{"event": "{eventType}", "timestamp": "{ISO8601}", "session_id": "{CODEFLOW_SESSION_ID}", "data": {extracted fields}}`
       4. Append to log file via `ledger.AppendEvent()` (atomic, file-locked)
     - `func (l *HookLogger) extractFields(eventType EventType, input map[string]any) map[string]any` -- event-type-specific field extraction:
       - session-start: extracts `session_id`, `project_dir`
       - session-end: extracts `session_id`, `duration`
       - stop: extracts `reason`, `tool_name`
       - user-prompt-submit: extracts `prompt` (truncated to 500 chars for log)
       - post-tool-use: extracts `tool_name`, `tool_input` (summary), `result` (truncated)
   - `logging_test.go`:
     - Table-driven: each event type logs to correct file, stdin JSON parsed correctly, CODEFLOW_SESSION_ID used (not stdin), timestamp in ISO8601, log record valid JSON, missing session ID (warning logged to stderr but not fatal)
2. Add CLI subcommand:
   - `codeflow hooks session-start logging` / `codeflow hooks session-end logging` / `codeflow hooks stop logging` / `codeflow hooks user-prompt-submit logging` / `codeflow hooks post-tool-use logging` -- reads stdin, logs event, exits 0
