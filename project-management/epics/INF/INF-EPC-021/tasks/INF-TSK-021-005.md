# INF-TSK-021-005: Migrate validation scripts to Go CLI

## Description

`validate-task.sh` and `validate-epic.sh` validate YAML frontmatter and structural integrity of task and epic markdown files. Currently implemented in shell with basic regex matching, these scripts miss edge cases and provide poor error messages. The Go implementation uses a proper YAML parser for frontmatter validation and structural analysis for section checking.

## Approach

1. Create `codeflow-cli/internal/validate/` package:
   - `frontmatter.go`:
     - `ParseFrontmatter(content []byte) (map[string]any, []byte, error)` -- extracts YAML between `---` delimiters using `gopkg.in/yaml.v3`; returns parsed map + remaining body
   - `task.go`:
     - `ValidateTask(path string) ([]ValidationError, []ValidationWarning, error)` -- validates task markdown:
       - Required YAML fields: `format_id`, `epic_format_id`, `title`, `description`, `status`, `area_type`, `work_type`, `domain`, `origin`, `estimate`, `priority`
       - Enum validation: `status` in `[todo, blocked, in_progress, complete, cancelled]`; `work_type` in `[FEAT, FIX, HTFX, RFCT, DOCS, TEST, CHOR, CICD, SPKE, PLAN]`; `estimate` in `[XS, S, M, L, XL]`
       - Pattern validation: `format_id` matches `{AREA}-TSK-{NNN}-{NNN}`
       - Conditional: if `autorun_eligible: true`, `acceptance` must be non-empty
       - Conditional: code-producing work types must have non-empty `tests`
       - Section checks: `## Description`, `## Approach`, `## Files`, `## Acceptance Criteria`, `## Dependencies`, `## Verification`, `## Stage Reports`, `## Notes`
       - PII warning: scan `file_scope` for PII-sensitive patterns (`session`, `user`, `token`)
   - `epic.go`:
     - `ValidateEpic(path string) ([]ValidationError, []ValidationWarning, error)` -- validates epic markdown with similar field/section checks
   - `validate_test.go`:
     - Table-driven tests using fixture files in `codeflow-cli/internal/validate/testdata/`
     - Valid task, valid epic, missing required fields, invalid enum, bad format_id pattern, autorun without acceptance, code task without tests
     - Replaces shell tests: `.codeflow/testing/scripts/validation/test-validate-task.sh` and `test-validate-epic.sh`
2. Add CLI subcommands in `codeflow-cli/cmd/codeflow/validate.go`:
   - `codeflow validate task <file>` -- exit 0 for valid, exit 1 for errors; errors to stderr, warnings to stderr with `[WARN]` prefix
   - `codeflow validate epic <file>` -- same exit code convention
