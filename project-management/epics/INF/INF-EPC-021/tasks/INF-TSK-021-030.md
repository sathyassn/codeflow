# INF-TSK-021-030: Shadow testing -- run Go alongside shell and verify output parity

## Description

Before the Phase E cutover (replacing shell scripts with Go binary invocations in settings.json), we need confidence that the Go implementations produce identical behavior to the shell scripts they replace. This task creates a shadow testing harness that runs both implementations side-by-side with identical inputs and compares their outputs.

The shadow test harness captures stdin, environment variables, exit codes, stdout, and stderr from both the Go subcommand and its shell equivalent. Any divergence is logged with full context for investigation. The goal is zero divergences across a full test cycle before cutover proceeds.

## Approach

1. Create `codeflow-cli/internal/shadowtest/` package:
   - `harness.go`:
     - `type ShadowTest struct { Name string; GoCommand []string; ShellCommand string; Stdin []byte; Env map[string]string }`
     - `type ShadowResult struct { GoExitCode int; GoStdout string; GoStderr string; ShellExitCode int; ShellStdout string; ShellStderr string; Divergences []Divergence }`
     - `func (t *ShadowTest) Run() (*ShadowResult, error)` -- executes both commands, captures output, compares
     - `func CompareOutputs(goResult, shellResult *ExecResult) []Divergence` -- exit code comparison, stdout diff, stderr diff (ignoring timing/debug lines)
   - `registry.go`:
     - `func AllShadowTests(projectDir string) []ShadowTest` -- returns all registered shadow test cases with realistic stdin payloads
     - Registered hooks: security (Bash tool stdin), pathflow-gate (Edit/Write/Bash stdin), sentinel-write (PostToolUse stdin with STAGE-COMPLETE), checkpoint-register (TaskCreate stdin), checkpoint-complete (TaskCompleted stdin), session-start (SessionStart stdin), session-end (SessionEnd stdin)
     - Registered commands: ledger append, validate task, validate epic, sentinel create/check/list/delete
   - `shadowtest_test.go`:
     - Tests the harness itself: matching outputs (zero divergences), different exit codes (caught), stdout diff (caught), stderr diff with noise filtering
2. Create shadow test runner script:
   - `.codeflow/testing/shadow/run-shadow-tests.sh` -- iterates all registered shadow tests, aggregates results, exits non-zero if any divergences found
3. Add CLI subcommand:
   - `codeflow test shadow` -- runs all shadow tests from Go, outputs divergence report

## Notes

- Shadow testing is Phase C in the Build-Coexist-Cutover strategy. It runs after all Phase B build tasks are complete.
- The harness must handle timing differences (Go is faster than shell) -- compare output content, not timing.
- Stderr comparison should filter out debug/logging lines that differ between implementations.
- Some shell scripts source multiple libraries which produce debug output -- the Go version will not have this. Filter accordingly.
- See `.codeflow/docs/analysis/go-cli-migration-comprehensive.md` Section 10.1 for the Build-Coexist-Cutover strategy.
- **Go test conventions:** Go tests must achieve >= 85% coverage on new business packages per test-config.json. All test functions must use `t.Parallel()`. Do not use `context.Background()` (use `context.TODO()` or test-specific context). New packages registered in test-config.json business_packages (or noted in INF-TSK-021-028 for batch registration).
