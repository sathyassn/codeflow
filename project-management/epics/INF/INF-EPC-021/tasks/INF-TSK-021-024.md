# INF-TSK-021-024: Performance benchmarking and hook latency verification

## Description

One of the primary motivations for the Go CLI migration is reducing hook latency. Each shell hook sources multiple libraries, adding ~300ms per tool call. With 3-5 hooks firing per tool call, this adds ~1-1.5 seconds of overhead. The Go binary should reduce this to ~50ms total. This task measures and documents the actual improvement.

## Approach

1. Document shell baseline from historical reference: go-cli-migration-comprehensive.md Section 7. Use ~300ms per hook as documented baseline.
   - Focus on high-frequency hooks: security (~120ms), gate check (~10ms), sentinel (~10ms), checkpoint (30-80ms)
   - Total per-tool-call overhead: ~300ms (sum of all hooks firing on a typical tool call)
   - Record in markdown table: Hook | Shell Time (ms) | Notes
2. Create `codeflow-cli/internal/benchmark/` package:
   - `benchmark_test.go`:
     - `func BenchmarkSecurityCheck(b *testing.B)` -- measures `security.Check()` with typical Bash stdin JSON
     - `func BenchmarkGateCheck(b *testing.B)` -- measures `gate.Check()` with Edit tool stdin JSON
     - `func BenchmarkSentinelWrite(b *testing.B)` -- measures `sentinel.CheckAndCreateStageSentinel()` with PostToolUse stdin
     - `func BenchmarkCheckpointRegister(b *testing.B)` -- measures `pathflow.RegisterTask()` with TaskCreate stdin
     - `func BenchmarkCheckpointComplete(b *testing.B)` -- measures `pathflow.CompleteTask()` with TaskCompleted stdin
     - `func BenchmarkLogging(b *testing.B)` -- measures `logging.Log()` for post-tool-use event
     - `func BenchmarkSessionStart(b *testing.B)` -- measures `session.StartInit()` full initialization
     - `func BenchmarkSessionEnd(b *testing.B)` -- measures `session.EndCleanup()` full cleanup
     - `func BenchmarkTotalPerToolCall(b *testing.B)` -- measures combined overhead of all hooks that fire on a typical tool call
     - Each benchmark uses `b.ResetTimer()` after setup to exclude initialization from timing
     - Each benchmark reports memory allocations via `b.ReportAllocs()`
3. Measure Go binary startup time:
   - `func BenchmarkBinaryStartup(b *testing.B)` -- measures `exec.Command("codeflow", "--version")` cold start time
   - Target: < 10ms cold start
4. Document results in `.codeflow/docs/analysis/inf-epc-021-performance.md`:
   - Shell baseline table (before migration)
   - Go benchmark results table
   - Improvement ratios per hook
   - Total per-session improvement estimate
   - Memory usage comparison
   - Methodology notes
