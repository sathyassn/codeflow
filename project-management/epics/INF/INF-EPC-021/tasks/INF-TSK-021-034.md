# INF-TSK-021-034: Build Go CLI for session-start instructions hook

## Description

The `cf-session-start-instructions.sh` hook fires at session start and injects working protocol instructions, session context, and active task reminders into the agent's context. This task builds the Go equivalent as `codeflow hooks session-start instructions`, replacing the shell implementation after the cutover task (INF-TSK-021-022) maps this hook to the Go command.

The Go implementation reads the same hook stdin JSON format as the shell script, detects the active task from `.state/runtime/active-task.json`, loads the cf-working-protocol skill content, and writes the formatted instruction context to stdout. Because this is a SessionStart hook, the implementation must always exit 0 — blocking a session start would prevent any work from proceeding.

## Approach

1. Create `codeflow-cli/internal/hooks/session/instructions.go`:
   - `func RunInstructions(stdin io.Reader, stdout io.Writer, projectDir string) error` -- entry point
   - Parse SessionStart stdin JSON (fields: session_id [Claude UUID, metadata only], source [startup/resume/compact/clear])
   - Note: CODEFLOW_SESSION_ID is NOT from stdin session_id — it comes from the env file (`.state/runtime/codeflow-env.sh`) or current-session-id file
   - Read `.codeflow/config/instructions/instructions-config.json`
   - Find all entries under `.hooks.SessionStart` where `enabled == true`
   - For each enabled entry, load the referenced `.txt` file from the same `.codeflow/config/instructions/` directory and write its content to stdout followed by a blank line
   - Graceful degradation: if config file is absent or parsing fails, write a hardcoded fallback string to stdout
   - Load active task from `.state/runtime/active-task.json` if present
   - Format and write instruction context to stdout
   - Return nil always (exit 0 — never block)
2. Create `codeflow-cli/internal/hooks/session/instructions_test.go`:
   - Test with valid stdin: verify output contains working protocol content
   - Test with missing active-task.json: verify graceful omission (no error, no panic)
   - Test with empty active-task.json: verify graceful omission
   - Test with missing skill file: verify graceful degradation (empty output acceptable)
   - Table-driven tests with `t.Parallel()` on all test functions
3. Wire into `codeflow-cli/cmd/codeflow/hooks.go`:
   - Add `hooks session-start instructions` subcommand
   - Calls `session.RunInstructions(os.Stdin, os.Stdout, projectDir)`
4. Implement Section 3 — PathFlow context (in the same RunInstructions function):
   - Read CODEFLOW_SESSION_ID: try env var first, then read `.state/runtime/current-session-id` file
   - Check if PathFlow is active: check for file existence at `.state/session/{SESSION_ID}/pathflow/is-pathflow-active`
   - If active:
     - Call `pathflow/sentinel.List(sentinelDir)` where `sentinelDir = .state/sentinels/pathflow/{SESSION_ID}/`
     - Filter results to only `pathflow-pf-*` prefixed sentinel names
     - Write PATHFLOW SESSION ACTIVE header and list completed phase names
     - Write compact recovery checklist (5-step numbered list)
   - Always exit 0 even if pathflow detection fails
