# INF-TSK-021-028: Update test-config.json business_packages with migration packages

## Description

As INF-EPC-021 tasks create new Go packages (hooks, ledger, pathflow, sentinel, validate, etc.), each package needs to be registered in `codeflow-cli/config/testing/test-config.json` under the `business_packages` array to enable 85% per-file coverage enforcement. This task serves as the batch registration point after integration testing confirms which packages exist and meet the coverage threshold.

## Approach

1. List all Go packages created by INF-EPC-021 tasks:
   - `./internal/ledger/...` (from INF-TSK-021-001, INF-TSK-021-026)
   - `./internal/hooks/...` (from INF-TSK-021-007 through INF-TSK-021-018) with sub-packages for each event type
   - `./internal/pathflow/...` (from INF-TSK-021-003)
   - `./internal/sentinel/...` (from INF-TSK-021-009, INF-TSK-021-012)
   - `./internal/workstate/...` (from INF-TSK-021-004)
   - `./internal/validate/...` (from INF-TSK-021-005)
   - `./internal/idgen/...` (from INF-TSK-021-002)
   - `./internal/shellutil/...` (from INF-TSK-021-015)
   - `./internal/settings/...` (from INF-TSK-021-016)
   - `./internal/staging/...` (from INF-TSK-021-016)
   - `./internal/worktree/...` (from INF-TSK-021-019)
   - `./internal/report/...` (from INF-TSK-021-019)
2. Add each to the `business_packages` array in test-config.json
3. Run `make test-cover` to verify all pass at 85%
4. Document any exceptions (thin wrappers, OS-specific code) in the config
5. Update conventions section if hook stdin test helpers or other new patterns emerged
