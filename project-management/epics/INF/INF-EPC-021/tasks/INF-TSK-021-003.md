# INF-TSK-021-003: Build Go CLI for checkpoint engine

## Description

The checkpoint engine in `cf-pathflow-state.sh` (~400 lines) manages phase task registration, completion tracking, and automatic sentinel creation. It's the backbone of PathFlow phase ordering. Currently implemented in shell with JSON manipulation via `jq`-style string operations (error-prone), this task builds a Go equivalent with proper JSON marshaling, file locking, and type safety. The checkpoint engine is used by two hooks: `cf-post-tool-use-phase-checkpoint.sh` (registration) and `cf-task-completed-phase-checkpoint.sh` (completion).

## Approach

1. Create `codeflow-cli/internal/pathflow/` package:
   - `checkpoint.go`:
     - `type Checkpoint struct { Phases map[string]PhaseCheckpoint }` with JSON tags
     - `type PhaseCheckpoint struct { Expected []string; Registered []string; Completed []string; Skipped []string; SentinelCreated bool }`
     - `InitAllPhases(sessionDir string) error` -- creates `pathflow-phase-tasks.json` with PF1-PF7 entries
     - `RegisterTask(sessionDir string, phase string, taskID string) error` -- adds task to Registered list; blocks cross-phase registration if previous phase sentinel missing
     - `CompleteTask(sessionDir string, phase string, taskID string) error` -- moves task to Completed; checks if all tasks done, auto-creates phase sentinel via `sentinel.Create()`
     - `SkipTask(sessionDir string, phase string, taskID string) error` -- marks task as skipped (counts as done for sentinel logic)
     - `GetStatus(sessionDir string) (Checkpoint, error)` -- returns full checkpoint state
     - All operations use `syscall.Flock` for file locking
   - `sentinel.go`:
     - `Create(sentinelDir string, name string) error` -- creates sentinel file at `.state/sentinels/pathflow/{session-id}/{name}`
     - `Exists(sentinelDir string, name string) bool` -- checks sentinel existence
     - `List(sentinelDir string) ([]string, error)` -- lists all sentinels for session
2. Create `codeflow-cli/cmd/codeflow/pathflow.go`:
   - `codeflow hooks post-tool-use checkpoint-register --phase <PFN> --task <PFN-TSK-NN>` -- used by PostToolUse hook
   - `codeflow hooks task-completed checkpoint-complete --phase <PFN> --task <PFN-TSK-NN>` -- used by TaskCompleted hook
   - `codeflow hooks session-start checkpoint-init` -- used by SessionStart init
   - `codeflow pathflow checkpoint-status` -- diagnostic query

**Implementation Summary:**
Built `internal/pathflow` Go package replacing ~400 lines of shell checkpoint functions in `cf-pathflow-state.sh`. The package provides checkpoint CRUD (InitAllPhases, RegisterTask, CompleteTask, SkipTask, GetStatus) with sidecar `.lock` file locking via `syscall.Flock`, atomic write via temp file + `os.Rename`, and custom JSON marshal/unmarshal for the mixed "context" + phase keys structure. Sentinel management (Create, Exists, List) supports automatic phase sentinel creation when all tasks complete. Cross-phase gating blocks registration of PF{N} tasks when PF{N-1} sentinel is missing (exit code 2). CLI exposes all operations under `codeflow pathflow checkpoint {init|register|complete|skip|status}` following the established cobra pattern. Condition-based auto-skip logic handles `adhoc_only` and `if_pipeline_includes_qa` conditions.

## Notes

- The checkpoint JSON file is at `.state/session/{SID}/pathflow/pathflow-phase-tasks.json`.
- Sentinels are created at `.state/sentinels/pathflow/{session-id}/pathflow-pf-{N}`.
- The `CODEFLOW_SESSION_ID` env var provides the session ID. The Go binary reads it from the environment.
- Cross-phase blocking: attempting to register a PF3 task when pf-2 sentinel doesn't exist must return exit code 2 (matching current hook behavior).
- See `.codeflow/docs/analysis/go-cli-migration-comprehensive.md` Section 4.1.1 (state/ scripts) and Section 4.2.7 (task-completed/ hooks) for detailed mapping.
- **Go test conventions:** Go tests must achieve >= 85% coverage on new business packages per test-config.json. All test functions must use `t.Parallel()`. Do not use `context.Background()` (use `context.TODO()` or test-specific context). New packages registered in test-config.json business_packages (or noted in INF-TSK-021-028 for batch registration).
