# INF-TSK-021-013: Wire codeflow session start into SessionStart hook

## Description

Currently, the session ID is generated in shell and written to `codeflow-env.sh`. The Go CLI already has `session.Start()` which generates session IDs and records them in the database. This task wires `session.Start()` into `StartInit()` as a Go function call (not subprocess), replacing the shell-generated `ses-{timestamp}{hex}` format with DB-backed `ses-{ULID}` format. The session ID is then written to `codeflow-env.sh` for downstream hook consumption. File removal of `current-session-id` is deferred to cutover task 022.

## Approach

1. Modify `codeflow-cli/internal/hooks/session/start.go` (from INF-TSK-021-010):
   - Add `SessionStarter` interface and `dbSessionStarter` implementation wrapping `session.Start()`
   - Update `StartInit()` Section 2 to call `SessionStarter.StartSession()` instead of `generateSessionID()`
   - Generate session ID via `session.Start()` (INF-EPC-015 existing code): produces `ses-{ULID}` format
   - Write session ID to `codeflow-env.sh` via existing `writeEnvFile()` for downstream hook consumption
   - Record session in SurrealDB + JSONL via `session.Start()` (DB-backed tracking)
   - Remove dead `generateSessionID()` function
   - Update `sessionIDRe` to accept both legacy and ULID formats
   - Note: `current-session-id` file removal deferred to cutover task 022; `session.Start()` still writes it
2. Update `start_test.go`:
   - Add mock `SessionStarter` for unit test isolation
   - Add test: session ID generated in `ses-{ULID}` format
   - Add test: environment output JSON contains CODEFLOW_SESSION_ID
   - Add test: `SessionStarter` error propagation
   - Add test: claudeID passed through correctly
   - Add test: `dbSessionStarter` integration with real DB
   - Update `validateSessionID` tests for ULID format
