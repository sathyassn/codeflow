# INF-TSK-021-040: Wire and expand HandlePostTeamDelete for proper PathFlow cleanup

## Description

`HandlePostTeamDelete` in the Go CLI currently exists but is not wired into the CLI dispatcher and performs incomplete cleanup. On a clean TeamDelete event, the following PathFlow state should be removed or reset:

1. The sentinel directory (`.state/sentinels/pathflow/{SID}/`) — session is over, sentinels are no longer valid
2. The `pathflow-team.json` file from the session pathflow dir — team config is destroyed on TeamDelete
3. The `pathflow-phase-tasks.json` file should be **reset** (not deleted) back to a fresh SessionStart state, preserving the checkpoint structure but clearing all task registrations

The `is-pathflow-active` flag must NOT be removed here — it is session-scoped (created by SessionStart hook) and removed by a different cleanup path (the sentinel-write PostToolUse hook after TeamDelete succeeds).

This task also wires `HandlePostTeamDelete` into the CLI's PostToolUse dispatcher in `hooks.go` so it is actually invoked when a TeamDelete tool call completes.

## Approach

1. Locate current `HandlePostTeamDelete` implementation in `codeflow-cli/cmd/codeflow/` or `codeflow-cli/internal/hooks/`
2. Expand the handler to:
   a. Read session ID from `.state/runtime/current-session-id`
   b. Remove sentinel directory: `.state/sentinels/pathflow/{SID}/`
   c. Remove `pathflow-team.json` from `.state/session/{SID}/pathflow/`
   d. Reset `pathflow-phase-tasks.json` to a clean initial state (empty phase tasks, preserving structure)
   e. Do NOT touch `is-pathflow-active`
3. Add file locking around `pathflow-phase-tasks.json` reset to prevent race conditions
4. Wire `HandlePostTeamDelete` into the PostToolUse dispatcher in `hooks.go`
5. Write tests covering all cleanup behaviors
