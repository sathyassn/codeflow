# INF-TSK-021-001: Migrate JSONL ledger writes to Go CLI

## Description

The JSONL ledger is the Tier 0 source of truth for CodeFlow. Currently, `ledger.sh` (~200 lines) constructs JSON events via shell string concatenation and writes them with simple redirects. This is error-prone: shell quoting bugs corrupt JSON, no schema validation catches malformed events, and concurrent writes can interleave. The Go CLI already has a `db` package with SQLite operations; this task adds a `ledger` package and `codeflow ledger append` command that performs atomic, validated JSONL writes.

## Approach

1. Create `codeflow-cli/internal/ledger/` package:
   - `writer.go` -- `AppendEvent(file string, event Event) error`: atomic append with `encoding/json.Marshal`, file locking via `syscall.Flock` on `os.OpenFile(path, O_WRONLY|O_APPEND|O_CREATE, 0644)`
   - `schema.go` -- `ValidateEvent(event Event) error`: schema validation against canonical field names per event type; rejects unknown event types
   - `routing.go` -- event-type-to-file routing map: `begin_work`/`complete_work`/`task_status_update` -> `work-graph.jsonl`; `session_start`/`session_end` -> `session-events.jsonl`; `memory_event`/`memory_store` -> `memory-events.jsonl`; `phase_transition`/`stage_transition`/`sentinel_created` -> `pathflow-events.jsonl`
   - `event.go` -- `Event` struct with canonical fields: `event string`, `timestamp string`, `session_id string`, `data map[string]any`; auto-generates RFC 3339 timestamp if not provided via `time.Now().UTC().Format(time.RFC3339)`
2. Create `codeflow-cli/cmd/codeflow/ledger.go`:
   - `codeflow ledger append --file <ledger-file>` reads event JSON from stdin
   - `codeflow ledger validate <file>` validates JSONL integrity (bonus, used by task 026)
   - Registers under root command via cobra
3. Update `.codeflow/scripts/state/ledger.sh` (408 lines):
   - Replace `ledger_append_event()` body: instead of `printf '%s\n' "$json" >> "$file"`, call `echo "$json" | "$CODEFLOW_CLI" ledger append --file "$file"`
   - Replace `memory.sh` (195 lines) write calls similarly (memory.sh sources ledger.sh)
4. Write Go tests in `codeflow-cli/internal/ledger/writer_test.go`:
   - Table-driven: valid append to each of 4 files, schema rejection for missing fields, schema rejection for wrong event-type-to-file, concurrent writes (goroutines), missing file creation, file permission errors
   - Replaces shell tests at `.codeflow/testing/scripts/state/test-ledger.sh` (1,078 lines)

## Notes

- The current `ledger.sh` uses `printf '%s\n' "$json_event" >> "$file"` which is not atomic. Go's file locking via `syscall.Flock` provides true atomicity.
- The 4 canonical ledger files and their event types are defined in `.codeflow/scripts/state/ledger.sh` (see `LEDGER_*` constants).
- LLM data layer risk: LLMs have historically written events to wrong files (memory_event in work-graph.jsonl). The Go binary's event-type routing enforces correctness at write time.
- This is the highest-priority migration task because all other state operations depend on correct JSONL writes.
- See `.codeflow/docs/analysis/go-cli-migration-comprehensive.md` Section 3.1 (Tier 1 Data Integrity) and Section 4.1.1 (state/ scripts) for detailed mapping.
- **Go test conventions:** Go tests must achieve >= 85% coverage on new business packages per test-config.json. All test functions must use `t.Parallel()`. Do not use `context.Background()` (use `context.TODO()` or test-specific context). New packages registered in test-config.json business_packages (or noted in INF-TSK-021-028 for batch registration).
