# INF-TSK-021-031: Post-cutover verification -- full lifecycle test with Go hooks

## Description

After the Phase E single-session cutover (settings.json updated, shell scripts retired), this task verifies the entire system works correctly with Go hooks. It runs a full PathFlow lifecycle, checks system health with `codeflow doctor`, measures hook performance, and completes one full interactive session to confirm end-to-end functionality.

This is the final verification gate before the Go CLI migration epic is marked complete.

## Approach

1. Create verification test suite:
   - `codeflow-cli/internal/verification/verification_test.go`:
     - `TestFullPathFlowLifecycle` -- simulates PF1 through PF7 by triggering each hook type with realistic stdin payloads:
       - SessionStart: init hook, verify session directory and checkpoint created
       - PreToolUse: gate-check (Edit before pf-3 = block, after pf-3 = allow), security (safe command = allow, dangerous = block)
       - PostToolUse: sentinel-write (STAGE-COMPLETE pattern creates sentinel), checkpoint-register (PF task registered)
       - TaskCompleted: checkpoint-complete (all tasks done = phase sentinel created)
       - SessionEnd: cleanup hook, verify state archived
     - `TestDoctorClean` -- runs `codeflow doctor` and asserts clean output
     - `TestNoPython3` -- greps production code paths for `python3` invocations, asserts zero matches
     - `TestHookLatency` -- benchmarks each hook category, asserts < 50ms per invocation
2. Create performance benchmark script:
   - `.codeflow/testing/benchmarks/hook-latency.sh` -- measures real hook invocation latency by timing actual Go binary hook calls with realistic stdin, outputs comparison table
3. Manual verification checklist (in this document's Verification section)

## Notes

- This is Phase F in the Build-Coexist-Cutover strategy -- the final verification before marking the migration epic complete.
- Hook latency target: < 50ms per invocation. Shell hooks average ~300ms due to library sourcing. Go binary starts in ~5ms.
- The full PathFlow lifecycle test should create real sentinel files, checkpoint entries, and session state to verify the complete chain.
- `codeflow doctor` checks: binary exists, database accessible, configuration valid, no stale state.
- See `.codeflow/docs/analysis/go-cli-migration-comprehensive.md` Section 10.1 for the Build-Coexist-Cutover strategy.
- **Go test conventions:** Go tests must achieve >= 85% coverage on new business packages per test-config.json. All test functions must use `t.Parallel()`. Do not use `context.Background()` (use `context.TODO()` or test-specific context). New packages registered in test-config.json business_packages (or noted in INF-TSK-021-028 for batch registration).
