## Description

Five T1 pathflow shell scripts handle PathFlow lifecycle events by writing JSONL event records via raw string concatenation. This approach is error-prone (no schema validation, no atomic writes) and platform-specific. This task builds Go equivalents for all 5 scripts under the `codeflow pathflow` subcommand group, delegating all JSONL writes via `ledger.Append()` library call (not CLI subprocess) (INF-TSK-021-001, complete).

**Scripts replaced (733 total lines):**

|--------|-------|---------------|
| `cf-pathflow-phase-transition.sh` | 144 | `codeflow pathflow phase-transition` |
| `cf-pathflow-stage-transition.sh` | 193 | `codeflow pathflow stage-transition` |
| `cf-pathflow-session-register.sh` | 133 | `codeflow pathflow session-register` |
| `cf-pathflow-task-update.sh` | 141 | `codeflow pathflow task-update` |
| `cf-pathflow-session-metadata.sh` | 122 | `codeflow pathflow session-metadata` |

This is a Phase B (Build) task. The shell scripts remain unchanged and active during this task. The Go implementations are built and tested in isolation. Cutover (wiring Go into settings.json and deleting shell scripts) happens in INF-TSK-021-022.

## Notes

- This is a Phase B (Build) task. Shell scripts at `.codeflow/scripts/pathflow/` are NOT modified or deleted.
- The 5 pathflow scripts use CODEFLOW_SESSION_ID from the environment (or stdin JSON) and write events to the pathflow JSONL ledger. Read each script before implementing to capture the exact event schema.
- Go implementation must accept the same CLI flags or stdin JSON as the shell scripts to support shadow testing in INF-TSK-021-030.
- All JSONL writes must delegate via `ledger.Append()` library call (not CLI subprocess) — do not use raw string concatenation or direct file I/O in the pathflow package.
- **Go test conventions:** All test functions must use `t.Parallel()`. Use `context.TODO()` not `context.Background()`. Use table-driven tests. New packages registered in test-config.json business_packages.
- See `.codeflow/docs/analysis/go-cli-migration-comprehensive.md` for the full migration strategy and script inventory.
- **Schema decision:** Go commands emit canonical ledger schema (`event`/`timestamp` JSON field names), NOT the shell schema (`type`/`ts`). This creates intentional divergence during coexistence. TSK-026 normalizes historical `type`/`ts` records before cutover. TSK-030's shadow test harness must normalize field names before comparison.
- **session-register dual-write:** session-register writes TWO events per invocation: (1) `session_register` event with `tracking_level:"pending"`, (2) `session_register` event with `interaction_mode`. Returns the first event's ID on stdout.
- **verdict omission semantics:** stage-transition: When `--verdict` flag is not provided, the `verdict` key must be omitted from the JSONL entirely (not null, not empty string -- absent). Use `json:"verdict,omitempty"` in Go struct.
