# INF-TSK-021-037: Build Go CLI for pathflow transition and registration scripts

> **MANDATORY VALIDATION:** Files created from this template MUST be validated against the task validation script before committing:
> `bash .codeflow/scripts/validation/validate-task.sh <file-path>`
> Fix all errors (exit code 1) before requesting a commit. Warnings are advisory. Script is at `.codeflow/scripts/validation/validate-task.sh`.

## Description

Five T1 pathflow shell scripts handle PathFlow lifecycle events by writing JSONL event records via raw string concatenation. This approach is error-prone (no schema validation, no atomic writes) and platform-specific. This task builds Go equivalents for all 5 scripts under the `codeflow pathflow` subcommand group, delegating all JSONL writes to `codeflow ledger append` (INF-TSK-021-001, complete).

**Scripts replaced (733 total lines):**

| Script | Lines | Go Subcommand |
|--------|-------|---------------|
| `cf-pathflow-phase-transition.sh` | 144 | `codeflow pathflow phase-transition` |
| `cf-pathflow-stage-transition.sh` | 193 | `codeflow pathflow stage-transition` |
| `cf-pathflow-session-register.sh` | 133 | `codeflow pathflow session-register` |
| `cf-pathflow-task-update.sh` | 141 | `codeflow pathflow task-update` |
| `cf-pathflow-session-metadata.sh` | 122 | `codeflow pathflow session-metadata` |

This is a Phase B (Build) task. The shell scripts remain unchanged and active during this task. The Go implementations are built and tested in isolation. Cutover (wiring Go into settings.json and deleting shell scripts) happens in INF-TSK-021-022.

## Approach

1. Read each of the 5 shell scripts to understand stdin/stdout/flag interface, JSONL event schema, and error conditions:
   - `.codeflow/scripts/pathflow/cf-pathflow-phase-transition.sh`
   - `.codeflow/scripts/pathflow/cf-pathflow-stage-transition.sh`
   - `.codeflow/scripts/pathflow/cf-pathflow-session-register.sh`
   - `.codeflow/scripts/pathflow/cf-pathflow-task-update.sh`
   - `.codeflow/scripts/pathflow/cf-pathflow-session-metadata.sh`
2. Create `codeflow-cli/internal/pathflow/transitions.go` with the shared JSONL construction logic for all 5 subcommands.
3. Create corresponding `*_test.go` file with table-driven tests covering valid input, missing required flags, and output format verification.
4. Wire subcommands into `codeflow-cli/cmd/codeflow/pathflow.go` under the `pathflow` cobra command group.
5. Register all 5 subcommands in `codeflow-cli/cmd/codeflow/main.go`.
6. Run `make test-cover` and verify >= 85% coverage on the pathflow package.
7. Register new test files in `codeflow-cli/config/testing/test-config.json` business_packages if not already covered.

## Notes

- This is a Phase B (Build) task. Shell scripts at `.codeflow/scripts/pathflow/` are NOT modified or deleted.
- The 5 pathflow scripts use CODEFLOW_SESSION_ID from the environment (or stdin JSON) and write events to the pathflow JSONL ledger. Read each script before implementing to capture the exact event schema.
- Go implementation must accept the same CLI flags or stdin JSON as the shell scripts to support shadow testing in INF-TSK-021-030.
- All JSONL writes must delegate to `codeflow ledger append` (INF-TSK-021-001) — do not use raw string concatenation or direct file I/O in the pathflow package.
- **Go test conventions:** All test functions must use `t.Parallel()`. Use `context.TODO()` not `context.Background()`. Use table-driven tests. New packages registered in test-config.json business_packages.
- See `.codeflow/docs/analysis/go-cli-migration-comprehensive.md` for the full migration strategy and script inventory.
