## Description

Fix three related bugs in the worktree cleanup subsystem that were identified after PR #238 (worktree cleanup consolidation). The bugs are:

1. **Logic bug in cleanup path**: A conditional or branching error in `cleanup.rs` causes incorrect behavior in one or more cleanup scenarios (e.g., force cleanup, dry-run, or prune).
2. **Typed status enum**: The worktree status enum (`WorktreeStatus` or equivalent) may be inconsistently used — string literals where the typed enum should be used, or missing exhaustive match arms.
3. **Locked writes**: Registry mutation functions (`write_registry`, `deregister`, `mark_pending_cleanup`, `purge_removed_entries`) may not use file-level locking, opening a race condition window when multiple sessions run concurrently.

These are targeted fixes with no scope creep into the coordination/CRDT subsystem or autorun orchestration.
