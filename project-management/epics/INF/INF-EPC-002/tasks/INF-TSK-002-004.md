# INF-TSK-002-004: Fix PF6-COMPLETE gaps: epic status rollup and PR event recording

## Description

Two gaps exist in the current PF6-COMPLETE implementation:

1. **Epic status rollup missing from `complete-work`** (cf-knowledge-layer): When a task is completed, the agent marks the task complete in the DB and updates the Tier 2 markdown, but does not check whether all sibling tasks in the epic are now complete. If they are, the epic should be automatically promoted to `status='complete'` with an `epic_status_changed` event appended to `work-graph.jsonl`.

2. **PR event recording missing from cf-git-operations**: After `create-pr` (PF6-TSK-05) and `verify-pr-and-sync` (PF6-TSK-06), no events are recorded to the PR events JSONL. This means the session history lacks PR numbers, URLs, CI status, and merge mode -- critical context for cross-session continuity.

## Acceptance Criteria

1. `cf-knowledge-layer.md` complete-work step: after task status update, check if all sibling tasks in the epic are complete; if so, UPDATE epics SET status='complete' and append `epic_status_changed` event to `work-graph.jsonl`
2. `cf-git-operations.md` create-pr step: after `gh pr create` succeeds, append `pr_created` event to pr-events JSONL with pr_number, pr_url, branch, and target
3. `cf-git-operations.md` verify-pr-and-sync step: after PR verified, append pr lifecycle event to pr-events JSONL with pr_number, ci_status, merge_mode
4. `pathflow-config.json` PF6-TSK-05 and PF6-TSK-06 operation fields updated to reflect PR event recording responsibilities
5. No regressions: existing tests in `.codeflow/testing/` continue to pass
