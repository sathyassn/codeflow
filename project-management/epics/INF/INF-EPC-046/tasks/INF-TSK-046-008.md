# INF-TSK-046-008: Full consolidation — retire legacy shell testing scaffolding, converge on generic engine

> **MANDATORY VALIDATION:** `codeflow validate task <file-path>` — fix all errors before committing.

## Description

INF-EPC-046 shipped the generic testing engine and migrated CodeFlow self-host to it as the first adopter, but left a dual-config footprint: the generic engine at `.codeflow/config/testing/test-config.json` alongside the legacy shell structural checker at `.codeflow/testing/test-config.json` with its `run-all-tests.sh` orchestrator and `lib/*.sh` helpers. §23 of the testing analysis doc (committed as 4deb873f on the `chore/post-migration-cleanup` branch) documents the convergence plan. This task executes that plan in a single PR.

Scope covers three concurrent tracks:

1. **Engine consolidation (net-new capabilities).** Port `validate_structural_integrity` from shell to Rust as `codeflow test structural-check`. Add per-test tag support (`critical`/`high`/`medium`/`low`) and matching `--only-tag`/`--skip-tag` CLI filters. Extend the config schema with an optional `structural` block.
2. **Legacy retirement.** Delete `run-all-tests.sh`, the full `lib/*.sh` set (10 files), the shell `test-config.json`, the testing-specific README, and collapse or empty the `.codeflow/testing/` tree. Migrate CI to use only `codeflow test` subcommands.
3. **Documentation + adopter sweep.** Rewrite §20 for single-config world; mark §23 phases executed with commit/date citations; add §24 (structural check) and §25 (test tags) capability docs; author ADR-002 (or update ADR-001); refresh the user guide with Rust/Python/TypeScript/pure-shell/mixed fixtures; refresh CLAUDE.md, agent defs, command defs, task template, and repo README.

The 43 acceptance criteria trace every link of the delivery chain: Rust port (creation + content + error paths + integration), schema extension (content + validation), CLI wiring (integration), deletions (retirement + grep invariants), CI migration (integration + verification), doc sweep (content across ≥10 files), tests (unit + integration + adopter simulation), standards (clippy + fmt + schema validator), and observable verification (2 clean runs + coverage preserved).

## Approach

1. **Branch + baseline.** Start from main with PR #295 merged. Run `codeflow test --mode full` to capture green baseline.
2. **Schema extension.** Add `structural` block + `tags` field to `test-config.schema.json`. Bump schema version if breaking; add backward-compat layer in `config/mod.rs` if non-breaking (prefer non-breaking — adopters with `schema_version: 1.0` keep working).
3. **Port structural check to Rust.** New `codeflow-cli/core/src/testing/structural/mod.rs` with `validate_structural_integrity(config) -> StructuralResult` mirroring shell semantics (bidirectional test↔source mapping via configurable globs). Add `codeflow test structural-check --format json|human` in `cli/src/cmd/test.rs`.
4. **Tag support.** Extend `TestTarget`/`TestFile` models in `core/src/testing/config/mod.rs` with optional `tags: Vec<Tag>`. Add `--only-tag`/`--skip-tag` CLI flags. Thread through runner selection logic in `core/src/testing/runner/mod.rs` so tag filters compose with existing `--only`/`--skip` target filters.
5. **Canonical config migration.** Port priorities from `.codeflow/testing/test-config.json` into the canonical `.codeflow/config/testing/test-config.json` as per-test-file `tags` entries on the `shell-scripts` target (CRITICAL → `critical`, HIGH → `high`, etc.). Rewrite shell-scripts target `runner` to invoke each test file directly (`bash <path>`) instead of calling `run-all-tests.sh`.
6. **Integration tests.** Author `integration_structural_check.rs`, `integration_tag_filter.rs`, `integration_adopter_simulation.rs`. Register paths in canonical config.
7. **CI migration.** Replace every shell-scaffolding invocation in `.github/workflows/test-suite.yml` with `codeflow test structural-check` → `codeflow test --mode full` sequence. Drop reproduce-hint references to shell paths.
8. **Delete legacy.** `git rm` `run-all-tests.sh`, all 10 `lib/*.sh`, `test-config.json`, `README.md`. If any shell test BODY (a `test-*.sh` that tests actual shell scripts, not framework) survives, keep it and document why in DEV report; otherwise empty the `.codeflow/testing/` dir or delete it entirely.
9. **Grep invariants.** Run the two grep invariants (criteria 14 and 36) locally. Expect zero hits in the scoped set.
10. **Documentation rewrite pass.** §20 (single-config world), §23 (mark phases executed), new §24 (structural check — cite `core/src/testing/structural/mod.rs:validate_structural_integrity`), new §25 (test tags — cite config + CLI wiring). Author ADR-002 OR append retirement decision to ADR-001. Update user guide with 4+ fixture configs and migration section. Update CLAUDE.md §7, all relevant agent defs (QA + dev + review + git-ops), command defs, task template, README.
11. **Adopter simulation validation.** Run `integration_adopter_simulation.rs` on a tempdir scaffold for Rust, Python, TypeScript, empty-project cases. Fix any rough edges in `codeflow test setup --auto` detection.
12. **Coverage + lint + format.** `cargo clippy --all-targets --all-features -- -D warnings`, `cargo fmt --check --all`, `codeflow validate test-config`. Verify rust-core coverage ≥90% overall; all 10 pre-existing exceptions preserved.
13. **Final verification.** `codeflow test --mode full` twice consecutively clean. `codeflow test structural-check` detects a planted missing-test fixture. Commit in logical chunks (schema → engine port → tag + config → deletion → CI → docs) or squash per commit-hook constraints.
