# INF-TSK-046-006: Post-migration cleanup + binary verification

> **MANDATORY VALIDATION:** Files created from this template MUST be validated against the task validation command before committing:
> `codeflow validate task <file-path>`

## Description

After PR #293 merges, this task verifies the full generic testing engine pipeline end-to-end using the rebuilt binary. It also cleans up stale migration artifacts (`codeflow-cli/cli/.codeflow/`), adds missing `.gitignore` entries for ephemeral test artifacts, creates the deferred parity integration test (`integration_self_host_parity.rs`), verifies the `report show` subcommand, and documents the dual-config architecture that results from having both the shell-based structural checker (`.codeflow/testing/test-config.json`) and the generic engine config (`.codeflow/config/testing/test-config.json`).

This task also removes the backwards-compatible `--coverage` and `--report` no-op CLI flags that were retained during TSK-005 for caller safety. TSK-005 intentionally left these flags in place to avoid a flag-before-caller problem during the migration PR. Now that PR #293 is merged and the binary is rebuilt, all callers must be updated first: `pre_tool_use.rs:842`, `gh_pr_guard.rs` (3 locations), `integration_artifact_generalization.rs`, CLAUDE.md (9 references), agent definitions (cf-quality-assurance.md 13+ refs, cf-development.md 2 refs, cf-review.md 1 ref), and command definitions (cf-test.md, cf-ship.md). Once all callers are updated, the `--coverage` and `--report` fields are deleted from `TestArgs` in `codeflow-cli/cli/src/cmd/test.rs`.

## Notes

**Flag removal scope:** The `--coverage` and `--report` flags in `codeflow test` are being removed by this task. TSK-005 intentionally did NOT remove them — doing so in the same PR as introducing the generic engine would have created a flag-before-caller problem (the old binary would be called with the new syntax during deployment). Now that PR #293 is merged and the binary is rebuilt, the flag-before-caller window is closed and the flags can be safely removed. All callers must be updated BEFORE deleting the flags from `TestArgs`.

**`--coverage` in setup/detect.rs is NOT codeflow's flag:** The `--coverage` occurrences in `codeflow-cli/core/src/testing/setup/` and `codeflow-cli/core/src/testing/detect.rs` are framework-level flags (e.g., `vitest --coverage`, `jest --coverage`, `pnpm test --coverage`) that the testing subsystem detects and passes through to the underlying test runner. These are NOT codeflow CLI flags and MUST NOT be changed.

The dual-config situation (`.codeflow/testing/test-config.json` for shell structural checking + `.codeflow/config/testing/test-config.json` for the generic engine) is intentional and complementary. This task documents the architecture; it does NOT merge the two configs.
