# INF-TSK-015-014: Welcome screen V4 PathFlow enhancements

## Description

Extend the V3 welcome screen to show PathFlow-specific information when an active PathFlow session is detected. When the `is-pathflow-active` flag file exists, the welcome screen adds sections for the current phase (PF1-PF7), work stage (WS-DEV/WS-REV/WS-QA), rework count, team name, and active teammates. When the flag is absent, the standard V3 layout is shown. Includes a benchmark test targeting < 1ms render time.

## Approach

1. Modify `internal/welcome/welcome.go`:
   - Add `WithPathFlow(phase, stage, reworkCount string)` functional option that injects PathFlow state data
   - Add `WithTeam(name string, teammates []string)` functional option that injects team data
   - Add `renderPathFlowSection()` -- renders from injected data (no filesystem I/O in welcome.go)
   - Add `renderTeamSection()` -- renders from injected data (no filesystem I/O in welcome.go)
   - Conditionally include these sections in `Show()` when PathFlow/Team data is injected
2. Modify caller file (`cmd/codeflow/main.go` or the file that calls `welcome.Show()`):
   - Read session ID from `CODEFLOW_SESSION_ID` env var (set by `codeflow-env.sh` SessionStart hook). See Notes for session ID source details.
   - Check pathflow-active flag at `.state/session/{SID}/pathflow/is-pathflow-active`
   - Read phase from sentinel files at `.state/sentinels/pathflow/{SID}/`
   - Read rework count from `.state/logs/pathflow-events.jsonl` (count `phase_transition` events with `rework_iteration` field; note inconsistent naming: some events use `iteration`, some `rework_iteration`)
   - Read team name from `.state/session/{SID}/pathflow/pathflow-team.json` (primary source, session-scoped, ephemeral -- cleared on session exit); fall back to `~/.claude/teams/` directory listing if pathflow-team.json is absent
   - Pass all data into welcome.Show() via WithPathFlow() and WithTeam() options
3. Extend `welcome_test.go` with V4-specific test cases (using injected data, no filesystem dependency)
4. Create `welcome_bench_test.go` with BenchmarkRender (benchmarks rendering path only, pre-injected data)

## Notes

- See `.codeflow/docs/analysis/inf-epc-015-go-cli-design.md` Section 2 for package structure.
- **Architecture:** The welcome package (`welcome.go`) is a pure renderer using the functional options pattern (WithVersion, WithProject, WithActiveWork, etc.). It has zero filesystem I/O. New `WithPathFlow()` and `WithTeam()` options follow this established pattern. The caller is responsible for reading filesystem state and injecting data.
- **Session ID source:** `codeflow-env.sh` (CODEFLOW_SESSION_ID env var), generated by the SessionStart init hook. `.state/runtime/current-session-id` is a Go CLI pre-staging artifact (`session.go` writes it, but nothing calls `codeflow session start` yet); it will be consolidated when the init hook migrates to calling the Go CLI per existing `TODO(go-cli)` comments. Do NOT read `current-session-id` for any V4 work; use `CODEFLOW_SESSION_ID` exclusively.
- **Pathflow-active flag path:** `.state/session/{SID}/pathflow/is-pathflow-active`
- **Rework count data source:** Rework counts exist in `.state/logs/pathflow-events.jsonl` -- events contain a `rework_iteration` field (inconsistent naming: some events use `iteration`, some `rework_iteration`). There is NO dedicated DB column for rework counts. The caller should parse JSONL events to derive the count.
- **Team name discovery:** Primary source is `.state/session/{SID}/pathflow/pathflow-team.json` (session-scoped, ephemeral -- created by `cf-session-start-init.sh`, cleared by `cf-session-end-cleanup.sh`). Contains `team_name`, `lead_pid`, `codeflow_session_id`. Fallback: list `~/.claude/teams/` directories (fragile -- may return stale teams from previous sessions). Team config is at `~/.claude/teams/{team-name}/config.json` when a team is active.
- **Sentinel files:** `.state/sentinels/pathflow/{session-id}/` indicate which phases are complete.
- **Shared state reader:** Consider creating a shared `internal/pathflow/` package that both welcome and doctor (INF-TSK-015-015) can use for PathFlow state reading.
