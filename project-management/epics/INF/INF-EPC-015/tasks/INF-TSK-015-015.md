# INF-TSK-015-015: Doctor V4 health checks (3 new)

## Description

Add 3 new V4-specific health checks to the doctor command, bringing the total from 13 to 16. These checks are PathFlow-aware and only run when relevant context exists (pathflow-active flag, team configuration). The checks detect stuck phases, unhealthy teammates, and sentinel state drift.

## Approach

0. Extend `Options` struct in `checks.go` with `SessionID string` field -- all 3 new checks need this to locate the correct sentinel directory, pathflow-active flag, and session-scoped state paths
1. Modify `internal/doctor/checks.go` to add 3 new checks:
   - `pathflow-stuck` -- read `StateDir + "/logs/pathflow-events.jsonl"` (NOT LedgerDir) for latest phase_transition event, check if age > 30 minutes
   - `team-health` -- read team name from `.state/session/{SID}/pathflow/pathflow-team.json` (primary, session-scoped); fall back to `~/.claude/teams/` directory listing. Read `~/.claude/teams/{name}/config.json`, verify each member's tmux pane is alive via `ExecCommand("tmux", "list-panes", "-a")`
   - `sentinel-drift` -- compare sentinel files at `.state/sentinels/pathflow/{SID}/` against current phase from events
2. Add conditional execution: skip these checks when pathflow-active flag is absent or team does not exist
3. Extend `checks_test.go` with 2 test cases per new check (pass and fail scenarios)
4. Populate SessionID in the caller from `CODEFLOW_SESSION_ID` env var (set by `codeflow-env.sh` SessionStart hook). See Notes for session ID source details.

## Notes

- See `.codeflow/docs/analysis/inf-epc-015-go-cli-design.md` Section 2 for package structure.
- **pathflow-events.jsonl path:** Located at `.state/logs/pathflow-events.jsonl`, NOT in the ledger directory. The `Options` struct has `LedgerDir` pointing to `.state/ledger/`. The new checks MUST use `StateDir + "/logs/pathflow-events.jsonl"`, NOT `LedgerDir`.
- **SessionID field:** The current `Options` struct (`internal/doctor/checks.go`) has DBPath, LedgerDir, ProjectDir, StateDir, LookPath, ExecCommand -- but NO SessionID field. A `SessionID string` field must be added to Options for locating session-scoped sentinel directories and pathflow-active flags.
- **Session ID source:** `codeflow-env.sh` (CODEFLOW_SESSION_ID env var), generated by the SessionStart init hook. `.state/runtime/current-session-id` is a Go CLI pre-staging artifact (`session.go` writes it, but nothing calls `codeflow session start` yet); it will be consolidated when the init hook migrates to calling the Go CLI per existing `TODO(go-cli)` comments. Do NOT read `current-session-id` for any V4 work; use `CODEFLOW_SESSION_ID` exclusively. Populate `Options.SessionID` from `os.Getenv("CODEFLOW_SESSION_ID")`.
- **Team name discovery:** Primary source is `.state/session/{SID}/pathflow/pathflow-team.json` (session-scoped, ephemeral -- created by `cf-session-start-init.sh`, cleared by `cf-session-end-cleanup.sh`). Contains `team_name`, `lead_pid`, `codeflow_session_id`. Fallback: list `~/.claude/teams/` directories (fragile -- may return stale teams from previous sessions). Recommend documenting this fragility.
- The 30-minute threshold for pathflow-stuck is based on `stage_timeout_minutes: 60` from pathflow-config.json -- phases should not exceed half the stage timeout.
- team-health check uses `tmux list-panes -a` to verify pane liveness. If tmux is not running, the check returns warn (not fail).
- sentinel-drift compares: if current phase is PF4 but pf-3 sentinel is missing, that is drift.
- **Shared state reader:** Consider creating a shared `internal/pathflow/` package for PathFlow state reading, reusable by both doctor and welcome (INF-TSK-015-014).
