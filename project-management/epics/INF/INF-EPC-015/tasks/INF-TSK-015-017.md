# INF-TSK-015-017: JSONL normalization and cross-compilation verification

## Description

Final verification task with two parts. Part A: Create a JSONL normalization script that reads all 4 canonical JSONL files, normalizes every event to canonical format, and rewrites the files. Part B: Cross-compilation verification -- `make build-all` produces 5 platform binaries, verify size constraints, no CGO, startup performance, and run end-to-end integration tests.

## Approach

### Part A: JSONL Normalization

1. Create `.codeflow/scripts/db/normalize-jsonl.sh`:
   - Read each of the 4 JSONL files from `.state/ledger/`
   - For each line, parse JSON and normalize the REAL inconsistencies found:
     - `"type":"memory_stored"` -> `"event":"memory_store"` (in memory-events.jsonl)
     - `"ts":"T"` -> `"timestamp":"T"` (in memory-events.jsonl, inconsistent across entries)
     - Handle raw `"op":"INSERT"` DB format entries in memory-events.jsonl
   - REMOVED phantom rules (not present in actual data):
     - ~~`"sid"` -> `"session_id"`~~ -- data already uses `"session_id"`
     - ~~`"wid"` -> `"work_id"`~~ -- data already uses `"work_id"`
     - ~~`"from_status"` -> `"old_status"`~~ -- data already uses `"old_status"`/`"new_status"`
   - Note: `work-graph.jsonl` and `sessions.jsonl` are already canonical (use `"event"` and `"timestamp"`). `config.jsonl` is typically empty. The real normalization work is in `memory-events.jsonl`.
   - Write normalized output to temp file, verify event counts match, then replace original
   - Backup original files before normalization
2. Write test script validating normalization

### Part B: Cross-Compilation Verification (VERIFICATION ONLY -- infrastructure already exists)

3. Run `make build-all` and verify 5 binaries exist (Makefile already has `build-all` target with 5 PLATFORMS defined and `CGO_ENABLED=0`)
4. Verify each binary < 20MB
5. Verify no CGO: confirm `CGO_ENABLED=0` is set in Makefile (already true)
6. Benchmark startup: `time ./bin/codeflow --version` < 50ms
7. Extend `main_test.go` with integration tests: version and help (already partially covered by existing TestRootCmd_VersionFlag, TestRootCmd_HelpOutput, TestVersionCmd, TestVersionCmd_JSONOutput), plus doctor smoke test (runs without panic, shows check names)

- **Actual JSONL inconsistencies found (verified against current data):**

  | File | Key Issue | Current Format | Canonical Target |
  |------|-----------|----------------|------------------|
  | `memory-events.jsonl` | Uses `"type"` instead of `"event"` | `"type":"memory_stored"` | `"event":"memory_store"` |
  | `memory-events.jsonl` | Uses `"ts"` instead of `"timestamp"` | `"ts":"2026-02-11T..."` | `"timestamp":"2026-02-11T..."` |
  | `memory-events.jsonl` | Mixed formats across entries | Some use `"ts"`, some use `"timestamp"` | All `"timestamp"` |
  | `memory-events.jsonl` | Some raw DB format entries | `"op":"INSERT"` | Needs handling |
  | `work-graph.jsonl` | Already canonical | `"event":"task_status_changed"` | No change needed |
  | `sessions.jsonl` | Already canonical | `"event":"session_start"` | No change needed |
  | `config.jsonl` | Empty file | N/A | N/A |

Similarly, `"from_status"`/`"to_status"` are not present -- data already uses `"old_status"`/`"new_status"`. These rules have been removed.
- **Cross-compilation:** `make build-all` already works (Makefile has 5 platforms, CGO_ENABLED=0, LDFLAGS). This scope is VERIFICATION ONLY -- confirm existing infrastructure works, do not reimplement.
- **Existing integration tests:** `main_test.go` already has: `TestRootCmd_VersionFlag`, `TestRootCmd_HelpOutput`, `TestVersionCmd`, `TestVersionCmd_JSONOutput`. Missing: doctor smoke test. Adding a full doctor output test requires state directory setup -- recommend a smoke test (command runs without panic, shows check names).
