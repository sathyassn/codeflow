# INF-TSK-015-017: JSONL normalization and cross-compilation verification

## Description

Final verification task with two parts. Part A: Create a JSONL normalization script that reads all 4 canonical JSONL files, normalizes every event to canonical format, and rewrites the files. Part B: Cross-compilation verification -- `make build-all` produces 5 platform binaries, verify size constraints, no CGO, startup performance, and run end-to-end integration tests.

## Approach

### Part A: JSONL Normalization

1. Create `.codeflow/scripts/db/normalize-jsonl.sh`:
   - Read each of the 4 JSONL files from `.state/ledger/`
   - For each line, parse JSON and normalize:
     - `"e":"X"` -> `"event":"X"`
     - `"ts":"T"` -> `"timestamp":"T"`
     - `"type":"memory_stored"` -> `"event":"memory_store"`
     - `"from_status"` -> `"old_status"`, `"to_status"` -> `"new_status"`
     - `"sid"` -> `"session_id"`, `"wid"` -> `"work_id"`
   - Write normalized output to temp file, verify event counts match, then replace original
   - Backup original files before normalization
2. Write test script validating normalization

### Part B: Cross-Compilation Verification

3. Run `make build-all` and verify 5 binaries exist
4. Verify each binary < 20MB
5. Verify no CGO: `go build` with `CGO_ENABLED=0`
6. Benchmark startup: `time ./bin/codeflow --version` < 50ms
7. Extend `main_test.go` with integration tests for version, help, doctor output

## Acceptance Criteria

1. `.codeflow/scripts/db/normalize-jsonl.sh` normalizes all 4 JSONL files to canonical format
2. Canonical format: all events use `event` key, consistent field names (old_status/new_status not from_/to_)
3. Normalization preserves all data (no events lost, counts match before/after)
4. Normalization is idempotent (running twice produces same output)
5. `make build-all` produces 5 platform binaries (linux-amd64, linux-arm64, darwin-amd64, darwin-arm64, windows-amd64)
6. All binaries < 20MB
7. No CGO dependencies (`go build` with CGO_ENABLED=0)
8. `./bin/codeflow --version` startup < 50ms
9. Integration tests in `main_test.go` cover: version, help, doctor output
10. `.codeflow/testing/scripts/db/test-normalize-jsonl.sh` has 5+ test cases: canonical format, idempotency, data preservation, all 4 patterns handled, empty file handling
11. Code coverage >= 85% across entire Go project
