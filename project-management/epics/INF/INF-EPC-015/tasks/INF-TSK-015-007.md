# INF-TSK-015-007: Welcome screen package (V3 base)

## Description

Implement the V3 base welcome screen that displays when the CodeFlow CLI launches. Uses double-line Unicode box-drawing characters to render a structured display with: 6-line CODEFLOW block logo, tagline with versions, project name/status, active work with emoji icon and timestamp, context-aware Quick Start commands, conditional update notification, and interactive prompt. Gracefully degrades when project config or active work data is unavailable.

## Approach

1. Implement `internal/welcome/welcome.go`:
   - `Show(w io.Writer)` function renders the full welcome screen to a writer
   - Read project name from `.codeflow/` config files
   - Read active work from DB (fallback to `.state/runtime/active-task.json`)
   - Detect Claude Code version from `claude --version` or similar
   - Use double-line Unicode box-drawing characters (`╔═╗╚═╝╠═╣║`) for the 78-col frame
   - 6-line block logo using filled-block Unicode characters (`██████╗` etc.) with full "W" rendering, shown once per session
   - Logo fallback: omit block logo when terminal < 78 cols, show compact text "CODEFLOW v{version}"
   - Tagline "AI-Powered Software Development Workflow" below the logo with version
   - ANSI color output per color palette (see Implementation Details); respect `NO_COLOR` env var and `isatty()`
   - Active work section with emoji icon (e.g. `🔨`) and "Started: X ago" timestamp
   - Context-aware Quick Start commands (vary based on state: active work vs no active work vs new project)
   - Update Available section (`⚠️  UPDATE AVAILABLE: vX.Y.Z`) shown conditionally when updates exist
   - Interactive prompt "Press Enter to continue, or 'q' to quit..." at the bottom
   - `--quiet`/`-q` flag skips welcome screen (for automation/autorun workers)
   - Unknown flags/arguments passed through to Claude Code
2. Write tests using `io.Writer` capture and assertions
3. Data sources for each section:
   - Header: version from ldflags, Claude Code version from exec
   - Project: `.codeflow/config/` or `PROJECT.md`
   - Active work: DB query or `.state/runtime/active-task.json`
   - Quick start: context-aware command list (depends on active work state)
   - Update: GitHub API (async check)

### Implementation Details

#### Color & Theme

**Color Palette (ANSI 256):**

| Element | ANSI Code | Example |
|---------|-----------|---------|
| Logo | Cyan (36) / Bright cyan (96) | Brand color, high visibility |
| Box borders (`╔═║` etc.) | Dim white / gray (245) | Structural, non-distracting |
| Section headers (`PROJECT`, `ACTIVE WORK`, `QUICK START`) | Bold white (1;37) | Section labels |
| Status "Ready" | Green (32) | Healthy state |
| Status "Warning" / "Issues" | Yellow (33) | Degraded state |
| Status "Error" | Red (31) | Broken state |
| Active work task ID | Cyan (36) | Matches logo brand color |
| Active work branch | Blue (34) | Git convention |
| Commands (`/cf-resume` etc.) | Bold cyan (1;36) | Actionable items stand out |
| Command descriptions | Default / white | Secondary text |
| Update available banner | Yellow (33) with `⚠️` | Attention-worthy |
| Tagline | Dim italic (2;3) | Subtle, secondary |
| Version numbers | Dim (2) | De-emphasized metadata |

**Theme Support:**

- Default: Dark terminal background assumed (light text on dark)
- `NO_COLOR` env var: Respect <https://no-color.org/> -- disable all ANSI codes when set
- `CODEFLOW_THEME` env var: Reserved for future light/dark/custom themes
- `--no-color` flag: Same as `NO_COLOR`, force monochrome output
- Fallback: When terminal does not support 256-color, degrade to basic 8-color ANSI

**Terminal Capability Detection:**

- Check `TERM` env var for color support level
- Check `isatty()` -- no colors when piped to file
- Check `COLORTERM` for truecolor support (future use)

#### Layout & Rendering

**Box Width:**

- Minimum: 78 columns (accommodates full CODEFLOW block logo with proper "W")
- Maximum: 100 columns (cap for ultra-wide terminals)
- Responsive: Detect terminal width via `COLUMNS` env var or ioctl, fit box accordingly
- Logo fallback: If terminal < 78 cols, omit block logo, show compact text `CODEFLOW v{version}` instead

**Rendering Order:**

1. Detect terminal capabilities (width, color, isatty)
2. Query data sources (DB for active work, version file, git config for project)
3. Render sections top-to-bottom, streaming to writer
4. If `--quiet`: skip entirely, output nothing

#### Section Behavior

| Section | Visibility | Behavior |
|---------|-----------|----------|
| Header (logo + version + tagline) | Always | Block logo or compact fallback + version + tagline |
| Project (name + status) | Always | Project name from `.codeflow/` config or cwd; status from doctor pre-flight |
| Active Work | Conditional | Shown only when `active_work` table has `in_progress` record |
| No Active Work | Conditional | Shown when no active work: "NO ACTIVE WORK / Start with /cf-plan or pick up existing tasks" |
| Quick Start | Always | Commands adapt: active work shows `/cf-resume` first; no work shows `/cf-plan`, `/cf-develop` first; issues shows `/cf-doctor` |
| Update Available | Conditional | Shown only when version check finds newer release |
| Footer prompt | Interactive only | "Press Enter to continue, or 'q' to quit..." -- skip in `--quiet` or pipe |
