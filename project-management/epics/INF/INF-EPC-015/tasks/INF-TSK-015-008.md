# INF-TSK-015-008: Preflight checks package

## Description

Implement pre-flight validation checks that run before the CLI launches Claude Code. These checks verify the project environment is correctly configured: .codeflow/ directory exists, Claude Code CLI is installed and accessible, git repository is initialized, and no stale sessions are lingering. All checks must complete within a 100ms budget to keep startup fast.

## Approach

1. Implement `internal/preflight/preflight.go`:
   - `Run()` executes all checks, returns slice of CheckResult
   - `CheckResult` struct: Name, Status (pass/fail/warn), Message, Duration
   - Check 1: `.codeflow/` directory exists (critical)
   - Check 2: `claude` CLI accessible via `exec.LookPath` (critical)
   - Check 3: `.git/` directory exists (warning)
   - Check 4: No stale sessions (check `.state/session/` for old pathflow-active flags)
2. Use parallel goroutines for independent checks to stay within 100ms
3. Write tests using testutil.TempProject for fixture setup

**Deviations from Approach:**
The task doc suggested parallel goroutines for independent checks. Checks run sequentially instead because all are filesystem stat operations that complete in microseconds -- goroutine overhead would exceed the check time. The 100ms budget is met comfortably (tests verify this). The task doc also suggested testutil.TempProject for fixtures; since that package does not exist in the codebase, tests use t.TempDir() with manual setup (consistent with session_test.go patterns).
