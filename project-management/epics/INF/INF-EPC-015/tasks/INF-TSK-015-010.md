# INF-TSK-015-010: Doctor command (13 V3 health checks)

## Description

Implement the `codeflow doctor` command with 13 V3 health checks covering all aspects of the CodeFlow infrastructure. Each check returns a structured result with pass/fail/warn status. Includes repair actions for common issues like corrupted databases and incorrect permissions. Supports running individual checks via `--check` flag.

## Approach

1. Create `cmd/doctor.go` registering the `doctor` cobra command with `--check`, `--json`, `--reset`, and `--repair` flags
2. Implement `internal/doctor/checks.go` with 13 checks:
   - `database` -- PRAGMA integrity_check via DB core
   - `jsonl` -- verify 4 canonical files exist and contain valid JSONL
   - `crdt` -- verify .state/ structure consistency
   - `python` -- python3 availability
   - `hooks` -- .claude/hooks/ scripts exist and are executable
   - `claude` -- Claude Code CLI accessible
   - `auth` -- Claude Code authenticated (NOT git credentials)
   - `config` -- .codeflow/config/ files valid JSON
   - `embedding` -- embedding model availability (warn if missing)
   - `vector` -- vector store health (warn if not configured)
   - `permissions` -- file/directory permissions correct
   - `version` -- version compatibility check
   - `network` -- network connectivity (optional, warn if offline)
3. Implement `internal/doctor/repair.go` with repair actions: DB rebuild, permission fix, config repair
4. `--json` flag outputs machine-readable JSON (for agent parsing and automated monitoring)
5. `--reset` flag resets state directories with confirmation prompt
6. Output formatted table with check results, durations

**Implementation Summary:**
Implemented the `codeflow doctor` command with 13 concurrent health checks, 3 repair actions, and CLI flags (--check, --json, --reset, --repair, --yes). Key design decisions: (1) Checks run concurrently using sync.WaitGroup + channel for results, maintaining canonical ordering. (2) Options struct with injectable LookPath and ExecCommand for full test isolation. (3) checkDatabase delegates to db.NewDB + db.CheckHealth for integrity checking. (4) JSON output uses a custom jsonResult type with duration_ms instead of raw time.Duration. (5) checkAuth verifies Claude Code authentication (not git credentials) via `claude auth status`. (6) Network check always returns warn (never fail) when offline.
