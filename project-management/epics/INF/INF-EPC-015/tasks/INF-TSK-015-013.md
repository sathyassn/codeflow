# INF-TSK-015-013: Autorun orchestrator and worker commands

## Description

Implement the autorun system: batch file parsing (YAML), task sequencing with dependency resolution, worker lifecycle management (tmux session creation, Claude Code invocation, result collection), and CLI subcommands (run, status, list). Workers run in parallel up to max_session_workers. Integrates with sessions, autorun_sessions, autorun_workers, and autorun_task_runs tables.

## Approach

1. Create `cmd/autorun/start.go` -- `codeflow autorun start batch.yaml` command
2. Create `cmd/autorun/status.go` -- `codeflow autorun status` command
3. Create `cmd/autorun/sessions.go` -- `codeflow autorun sessions` command
4. Implement `internal/autorun/batch.go`:
   - Parse YAML batch files with task lists, dependencies, worker config
   - Validate: no dependency cycles, tasks exist in WorkGraph, auto_merge constraints (D4)
5. Implement `internal/autorun/orchestrator.go`:
   - Task sequencer respecting blocked-by dependencies
   - Worker pool management (up to max_session_workers, default 3)
   - Status tracking in autorun_sessions/autorun_workers tables
   - Error handling: worker failure, timeout, cancellation
6. Implement `internal/autorun/worker.go`:
   - Create tmux session for each worker
   - Invoke Claude Code via exec with appropriate environment
   - Collect results (exit code, PR number, verification)
   - Worker lifecycle: queued -> starting -> running -> completed/failed
   - Cleanup on completion or timeout
7. Write comprehensive tests for each component

> Populated by cf-development before STAGE-COMPLETE: WS-DEV

**Implementation Summary:**

Implemented the complete autorun system: YAML batch file parsing with validation and topological sort (Kahn's algorithm), orchestrator with dependency-aware task sequencing and semaphore-based worker pool, worker management via tmux sessions with Claude Code invocation, and 3 CLI subcommands (start, status, sessions). Architecture uses interface-based dependency injection (WorkerRunner, TmuxRunner, ClaudeInvoker) for full testability.

Key design decisions:

- `Start()` returns immediately; `execute()` runs in a goroutine for async orchestration
- Workers skip tasks whose dependencies failed (cascade failure)
- Protected branch validation at batch parse time (auto_merge + main/master/production/release/* = error)
- Session/worker/task-run IDs use ULID with prefixes (ars-, arw-, atr-)
- Non-blocking semaphore select for worker slot acquisition; blocking channel read when waiting for results
