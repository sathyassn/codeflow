# INF-TSK-027-007: xterm.js Terminal Widget

## Description

Implement the frontend terminal widget using xterm.js with the WebGL addon for GPU-accelerated rendering. The `TerminalView` component initializes xterm.js, subscribes to `StreamOutput` Tauri events, handles resize via the Fit addon, and sends keyboard input to the backend via `write_stream()`. Includes a stream header bar with model name, branch, phase badge, and controls. A thinking indicator appears after 2 seconds of no output. A chat-style input area at the bottom supports Enter to send and Shift+Enter for newline.

## Approach

1. Install npm dependencies: `@xterm/xterm`, `@xterm/addon-webgl`, `@xterm/addon-fit`, `@xterm/addon-search`
2. Create `src/lib/api/streams.ts`:
   - `spawnStream(config: StreamConfig): Promise<StreamId>` -- invokes Tauri `spawn_stream` command
   - `killStream(id: StreamId): Promise<void>` -- invokes `kill_stream`
   - `resizeStream(id: StreamId, cols: number, rows: number): Promise<void>` -- invokes `resize_stream`
   - `writeStream(id: StreamId, data: Uint8Array): Promise<void>` -- invokes `write_stream`
   - `listStreams(): Promise<StreamInfo[]>` -- invokes `list_streams`
   - `onStreamOutput(callback: (event: StreamOutputEvent) => void): UnlistenFn` -- listens to Tauri events
   - `onStreamStatus(callback: (event: StreamStatusEvent) => void): UnlistenFn` -- listens to status events
3. Create `src/lib/components/terminal/StreamHeader.svelte`:
   - Model name badge (e.g., "Claude Opus 4.6")
   - Branch name text
   - Phase badge (reuse `PhaseBadge` from Task 005)
   - Control buttons placeholder (implemented in Task 010)
   - Thinking indicator (animated dots) — visible when `isThinking` is true
4. Create `src/lib/components/terminal/TerminalView.svelte`:
   - Props: `streamId: StreamId`, `config: StreamConfig`
   - `$effect` on mount:
     - Create `Terminal` instance with options: `scrollback: 10000`, `fontFamily: "var(--font-mono)"`, `theme: { background: "var(--bg-primary)", foreground: "var(--text-primary)" }`
     - Load WebGL addon for GPU rendering
     - Load Fit addon for auto-sizing
     - Open terminal in container div
     - Call `fit()` to size terminal
   - Subscribe to `stream_output` Tauri event filtered by `streamId`:
     - Write received bytes to terminal: `terminal.write(new Uint8Array(event.data))`
     - Reset thinking indicator timer
   - Resize handling:
     - `ResizeObserver` on container div
     - On resize: call `fitAddon.fit()`, then `resizeStream(streamId, terminal.cols, terminal.rows)`
   - Keyboard input:
     - `terminal.onData(data => writeStream(streamId, encoder.encode(data)))`
   - Thinking indicator:
     - Start 2-second timer after each output chunk
     - If timer fires without new output, set `isThinking = true`
     - Reset on next output
   - Cleanup on unmount:
     - Unsubscribe from Tauri events
     - Dispose terminal instance
     - Disconnect ResizeObserver
5. Create chat-style input area at bottom of TerminalView:
   - `<textarea>` with monospace font
   - Enter key: send content as `writeStream()`, clear textarea
   - Shift+Enter: insert newline in textarea
   - Placeholder: "Type a message..."
6. Apply CSS variables for colors:
   - Terminal background: `--bg-primary`
   - Terminal text: `--text-primary`
   - Selection: `--accent-primary` with opacity
   - Cursor: `--accent-primary`

## Notes

- xterm.js v5+ uses `@xterm/xterm` package naming (not the old `xterm` package).
- WebGL addon provides GPU-accelerated rendering — significantly faster than the default canvas renderer for high-throughput output.
- The Fit addon must be loaded AFTER the terminal is opened (attached to DOM), not before.
- `ResizeObserver` is preferred over `window.resize` event for detecting container size changes, as it handles sidebar toggle and split pane scenarios.
- The thinking indicator is a UX affordance — it reassures the user that the process is still running when there's a pause in output (common with AI models "thinking").
- The chat input area is separate from the terminal's own input handling. Terminal keyboard input goes to PTY stdin directly; chat input is for structured messages (useful for AI CLI prompts).
