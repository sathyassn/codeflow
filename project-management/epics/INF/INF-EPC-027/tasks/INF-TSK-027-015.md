# INF-TSK-027-015: Config Backend and File Watcher

## Description

Implement the Tauri backend config reader and file watcher system. This provides the data layer for the Config tab, reading and parsing 5 config files (both JSON and TOML formats), watching them for external changes, and emitting `AppEvent::ConfigChanged` events to the frontend when files are modified by external processes.

The config reader parses each file into a `Vec<ConfigSection>` structure, where each section contains a title and a list of `ConfigField` key-value pairs. The file watcher uses the `notify` crate to detect changes, handling edge cases like file deletion and recreation. Config parsing errors are returned as structured `AppError::ConfigParse` errors.

The 5 config files are:
1. `.codeflow/config/enforcement/enforcement-policy.json` (JSON)
2. `.codeflow/config/pathflow/pathflow-config.json` (JSON)
3. `.codeflow/config/orchestration.toml` (TOML)
4. `project/project-config.json` (JSON)
5. `.codeflow/config/model-orchestration.toml` (TOML)

## Approach

1. Define `ConfigSection` and `ConfigField` structs in `src-tauri/src/commands/config.rs`:
   - `ConfigSection { title: String, fields: Vec<ConfigField> }`
   - `ConfigField { key: String, value: serde_json::Value, field_type: String }`
2. Implement config file parsers for JSON (`serde_json`) and TOML (`toml`) formats
3. Create a config path resolver that looks for files relative to the project root and falls back to `~/.codeflow/`
4. Implement `get_config(file_id: String)` Tauri command that reads and parses a config file, returning `Vec<ConfigSection>`
5. Implement `get_config_path(file_id: String)` Tauri command that returns the resolved absolute path for a config file
6. Implement `watch_config(file_id: String)` Tauri command that registers a file watcher using the `notify` crate
7. Set up the file watcher in `AppState` to persist across Tauri command calls
8. Emit `AppEvent::ConfigChanged { file_id: String }` via Tauri event system when a watched file changes
9. Handle file deletion gracefully (emit event with `deleted: true` flag) and re-watch on recreation
10. Define `AppError::ConfigParse { file: String, message: String }` error variant for parse failures
11. Write unit tests for JSON and TOML parsers, integration test for the file watcher, and error case tests

## Notes

- Use `notify` crate v6+ for file watching (cross-platform, async-compatible)
- The file watcher should debounce rapid changes (e.g., 200ms debounce window) to avoid flooding the frontend with events
- Config path resolution order: project root first, then `~/.codeflow/` fallback
- Consider using `notify::RecommendedWatcher` for platform-optimal file system events
- The `ConfigSection` structure is intentionally flat (not recursive) to simplify frontend rendering
