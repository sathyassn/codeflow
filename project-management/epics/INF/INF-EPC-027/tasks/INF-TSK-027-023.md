# INF-TSK-027-023: Playground Mode

## Description

Implement a playground mode that provides standalone model CLI sessions without any PathFlow context or session tracking. Playground items appear in the sidebar alongside the regular project streams, each spawning a PTY session on click. Playground streams are marked with a "Playground" badge and are not persisted in SurrealDB. Users can add custom models by providing a CLI command, which is validated via `which` to ensure the binary exists. Multiple concurrent playground sessions are supported. All sessions are cleaned up on app exit.

This feature enables quick model interactions (code generation, Q&A, experimentation) without the overhead of tracked PathFlow sessions.

## Approach

1. Add a "Playground" section to the sidebar below the project streams section
2. Create pre-configured playground items for each available model (from orchestration config)
3. On click, spawn a new PTY session with `is_playground: true` flag -- bypass all PathFlow context injection and session registration
4. Create the `src/routes/playground/+page.svelte` view that renders the selected playground stream
5. Add a "Playground" badge to playground stream tabs to visually distinguish them from tracked sessions
6. Skip SurrealDB persistence for playground sessions: do not write `begin_work`, `session_start`, or any ledger events
7. Implement "Add Custom Model" option:
   - Show a dialog with a text input for the CLI command
   - Validate the command using `which` (via a Tauri command) to check binary existence
   - Add the custom model to the playground sidebar if validation passes
8. Support multiple concurrent playground sessions (each gets its own PTY and tab)
9. Set tab header to show model name only (no session ID or project context)
10. Ensure all stream controls (input, kill, clear) work in playground mode
11. Register cleanup on `beforeunload` / Tauri `CloseRequested` event to kill all playground PTY processes
12. Write component tests for playground sidebar items, badge rendering, and session spawn/kill

## Notes

- Playground mode is the "quick scratch pad" for model interactions -- zero ceremony, zero persistence
- The `is_playground` flag should be set on the PTY spawn request, not just the frontend state, so the backend knows not to register the session
- Custom model validation via `which` should happen asynchronously with a loading spinner in the dialog
- Consider persisting custom model configurations in a local JSON file (not SurrealDB) for convenience across app restarts
- Cleanup on app exit must handle the case where the Tauri process is forcefully killed (SIGKILL) -- orphan PTY processes should be handled by the daemon's session monitor
