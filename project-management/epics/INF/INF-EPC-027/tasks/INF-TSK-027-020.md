# INF-TSK-027-020: Cross-Project Task Aggregation

## Description

Extend the Kanban board with a cross-project mode toggle that aggregates tasks from all accessible projects. When enabled, task cards include a project name badge, a project filter dropdown appears, and a summary bar shows task counts per project. The existing Kanban filters (Epic, Type, Status) continue to work in cross-project mode. Data is fetched via a `get_cross_project_tasks()` Tauri command that queries the daemon's SurrealDB across all `can_access` projects.

Performance target: the aggregation query must return within 500ms for 200 tasks across 10 projects.

## Approach

1. Add a cross-project toggle switch to the Kanban board header (e.g., "All Projects" toggle)
2. When cross-project mode is active:
   - Call `get_cross_project_tasks()` instead of `get_tasks()` for task data
   - Show a project name badge on each task card (colored by project)
   - Add a "Project" filter dropdown alongside existing Epic/Type/Status filters
   - Display a summary bar above the Kanban columns showing task count per project
3. Create `get_cross_project_tasks()` Tauri command in `src-tauri/src/commands/tasks.rs`:
   - Query the daemon SurrealDB for tasks across all projects where `can_access = true`
   - Include the project name and ID in each task result
   - Apply pagination or streaming if result set is large
   - Return within 500ms performance budget
4. Add project context switch handling: clicking a card from a different project should switch the app's active project context before navigating to the task detail
5. Implement loading state with a progress indicator while cross-project data is being aggregated
6. Ensure all existing Kanban filters work correctly in cross-project mode (filters are additive with project filter)
7. Write component tests for cross-project toggle, project badges, and filter interactions; backend performance test
