# INF-TSK-027-003: Daemon IPC Client and Connection Manager

## Description

Implement the Tauri backend daemon connection manager. Reuses Epic C's `IpcClient` from `codeflow-core` to connect to the daemon Unix domain socket at `~/.codeflow/db.sock`. The `DaemonConnection` struct provides: `connect()`, `reconnect()` (exponential backoff), `health_check()` (periodic ping), and `query()` (SurrealQL passthrough). It emits `AppEvent::DaemonStatus` events to the frontend and is registered as Tauri managed state.

## Approach

1. Create `src-tauri/src/ipc/mod.rs` as module root
2. Create `src-tauri/src/ipc/connection.rs` with `DaemonConnection` struct:
   - Fields: `client: Option<IpcClient>`, `status: ConnectionStatus`, `app_handle: tauri::AppHandle`
   - `ConnectionStatus` enum: `Connected`, `Disconnected`, `Reconnecting { attempt: u32, next_retry: Duration }`
3. Implement `DaemonConnection::connect()`:
   - Locate socket at `~/.codeflow/db.sock`
   - Use `codeflow-core::ipc::IpcClient::connect()` to establish connection
   - Emit `AppEvent::DaemonStatus { connected: true, message: "Connected" }` on success
   - Return `AppError::DaemonConnection` on failure
4. Implement `DaemonConnection::reconnect()` with exponential backoff:
   - Delays: 1s, 2s, 4s, 8s, 16s, capped at 30s
   - Emit `DaemonStatus` events on each attempt
   - Stop after successful connection
5. Implement `DaemonConnection::health_check()`:
   - Spawn a tokio task that pings daemon every 10 seconds
   - On ping failure: trigger `reconnect()`
   - Emit `DaemonStatus` events reflecting current state
6. Implement `DaemonConnection::query()`:
   - Accept SurrealQL query string and optional bindings
   - Forward to `IpcClient` for daemon execution
   - Return deserialized result or `AppError::QueryError`
7. Create convenience methods:
   - `get_projects() -> Vec<ProjectInfo>` -- query daemon for registered projects
   - `get_project_sessions(project_path: &str) -> Vec<SessionInfo>` -- query active sessions
8. Create `src-tauri/src/state/app_state.rs`:
   - `AppState` struct with `daemon: Arc<Mutex<DaemonConnection>>`
   - Register as Tauri managed state in `main.rs`
9. Create `src-tauri/src/commands/daemon.rs`:
   - `#[tauri::command] async fn connect_daemon(state: State<AppState>)` -- initiate connection
   - `#[tauri::command] async fn get_daemon_status(state: State<AppState>)` -- return current status
   - `#[tauri::command] async fn get_projects(state: State<AppState>)` -- return project list
   - `#[tauri::command] async fn get_project_sessions(state: State<AppState>, path: String)` -- return sessions
10. Create frontend Svelte store `src/lib/stores/daemon.ts`:
    - Listen to `DaemonStatus` Tauri events
    - Export `daemonStatus` store: `{ connected: boolean, message: string }`
11. Wire commands into `main.rs` command registration

## Notes

- `Arc<Mutex<>>` is used for thread safety since Tauri commands run on async runtime and may access state concurrently. Consider `tokio::sync::Mutex` for async-friendly locking.
- The `query()` method is a SurrealQL passthrough — it sends raw SurrealQL to the daemon and returns deserialized JSON. Higher-level query functions (like `get_projects()`) build SurrealQL strings internally.
- Graceful degradation means the app shell and navigation render even without daemon connection; data-dependent views show "Disconnected" placeholder.
- The health check task should be cancellable — store the `JoinHandle` and abort on app shutdown.
- Epic C's `IpcClient` handles the Unix domain socket protocol; this task wraps it with Tauri-specific lifecycle management.
