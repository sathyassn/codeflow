# INF-TSK-027-002: Core Types, IPC Protocol, and Event Definitions

## Description

Define all Rust domain types for the app backend and all TypeScript mirror types for the frontend. Set up the Tauri IPC protocol: `#[tauri::command]` function signatures for all backend operations, and `AppEvent` enum for backend-to-frontend streaming. If using specta for auto-generation, configure the build pipeline to generate `types.ts` from Rust types. Define the `AppError` enum with `thiserror` and `Serialize` impl for Tauri compatibility. Import and re-export domain types from `codeflow-core` — do NOT redefine them.

## Approach

1. Define newtype wrappers in `src-tauri/src/types/`:
   - `StreamId(String)` -- wraps stream identifiers, ULID-based with `stream-{ulid}` format
   - `TabId(String)` -- wraps tab identifiers, ULID-based with `tab-{ulid}` format
   - Both with `Display`, `FromStr`, `Serialize`, `Deserialize`, `Clone`, `Debug`, `PartialEq`, `Eq`, `Hash`
   - Validation on construction via `TryFrom<String>`
2. Define `AppEvent` enum (backend -> frontend events):
   - `StreamOutput { stream_id: StreamId, data: Vec<u8> }` -- PTY output chunk
   - `StreamStatus { stream_id: StreamId, status: StreamState }` -- stream lifecycle
   - `DaemonStatus { connected: bool, message: String }` -- daemon connection state
   - `SubStreamDetected { parent_id: StreamId, child_id: StreamId, model: String, stage: String }` -- delegation
   - `Notification { level: NotificationLevel, title: String, body: String }` -- user notification
   - Each variant tagged with `#[serde(tag = "type")]` for TypeScript discriminated union
3. Define `StreamState` enum: `Starting`, `Running`, `Completed { exit_code: i32 }`, `Failed { error: String }`, `Killed`
4. Define `NotificationLevel` enum: `Info`, `Warning`, `Error`, `Success`
5. Define `StreamConfig` struct: `command: String`, `args: Vec<String>`, `cwd: Option<String>`, `env: HashMap<String, String>`, `model_name: Option<String>`
6. Define `ProjectInfo` struct (mirrors daemon data): `path: String`, `name: String`, `active_sessions: u32`
7. Define `SessionInfo` struct: `id: String`, `branch: Option<String>`, `phase: Option<String>`, `work_type: Option<String>`, `status: String`
8. Define `AppError` enum via `thiserror::Error` with `Serialize` impl:
   - `DaemonConnection { message: String }`, `StreamError { stream_id: StreamId, message: String }`
   - `ConfigError { path: String, message: String }`, `QueryError { query: String, message: String }`
   - `NotFound { resource: String, id: String }`, `Internal { message: String }`
9. Re-export domain types from `codeflow-core` in `src-tauri/src/types/mod.rs` (e.g., `ModelId`, `WorkStage`)
10. Create TypeScript mirror types in `src/lib/types/`:
    - `events.ts` -- AppEvent discriminated union with `type` field
    - `streams.ts` -- StreamId, TabId, StreamState, StreamConfig
    - `projects.ts` -- ProjectInfo, SessionInfo
    - `errors.ts` -- AppError type
    - `index.ts` -- re-exports
11. If using specta: configure `tauri-specta` in `build.rs` to auto-generate TypeScript types
12. If manual: create `TYPES.md` documenting the Rust-to-TypeScript mapping for ongoing maintenance

## Notes

- `AppEvent` uses `#[serde(tag = "type")]` for TypeScript discriminated union compatibility — each variant becomes `{ type: "StreamOutput", stream_id: string, data: number[] }` etc.
- `AppError` must implement both `thiserror::Error` (for Rust error handling) and `serde::Serialize` (for Tauri IPC error responses). Tauri v2 requires command errors to be serializable.
- Re-exporting `codeflow-core` types avoids duplication and ensures consistency across the workspace.
- specta + tauri-specta can auto-generate TypeScript bindings from Rust types; evaluate feasibility during implementation. Manual mapping is the fallback with `TYPES.md` as the maintenance contract.
