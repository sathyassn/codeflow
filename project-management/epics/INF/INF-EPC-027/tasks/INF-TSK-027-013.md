# INF-TSK-027-013: Task Detail View with Criteria Matrix

## Description

Implement the task detail view at `/tasks/[id]` that displays full task information including YAML metadata fields, description rendered as markdown, the acceptance criteria stage evaluation matrix with color-coded status cells, collapsible stage reports, and a PR link. The view must handle loading states with skeleton UI and 404 states for non-existent task IDs.

This component is the primary inspection point for individual tasks, showing the complete lifecycle status of a task through its pipeline stages. The criteria matrix provides at-a-glance visibility into which acceptance criteria have been evaluated at each stage (DEV/REV/QA for FEAT, PLAN/REV for PLAN, etc.).

## Approach

1. Create the SvelteKit route at `src/routes/tasks/[id]/+page.svelte` with dynamic parameter extraction
2. Create the `TaskDetail.svelte` component with sections for metadata, description, criteria matrix, stage reports, and PR link
3. Add a Tauri command `get_task(id)` in the tasks command module (or extend existing) to fetch a single task by format_id from daemon SurrealDB
4. Implement markdown rendering for the description and stage report sections using a markdown library (e.g., marked or mdsvex)
5. Build the Criteria Status table component that dynamically renders pipeline-appropriate columns based on the task's `work_type`
6. Apply color-coding to status cells: DONE/PASS = green background, FAIL = red, PARTIAL = yellow, `--` = gray
7. Implement collapsible sections for Stage Reports using Svelte's `<details>` or a custom accordion
8. Add PR link rendering using Tauri's `shell-open` API for external URL navigation
9. Implement back button that navigates to the previous Tasks sub-view (Kanban, Timeline, or Graph)
10. Add skeleton loading state while task data is being fetched
11. Add 404 error state when the task ID does not exist in the database
12. Write component tests with mock data covering FEAT, PLAN, and DOCS pipeline task types
