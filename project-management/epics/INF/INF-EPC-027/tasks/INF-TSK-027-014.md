# INF-TSK-027-014: Task Dependency Graph Visualization

## Description

Implement an interactive force-directed dependency graph visualization using D3.js. Tasks are rendered as nodes and dependencies as directed edges. Nodes are color-coded by work type and sized proportionally to their estimate. The graph supports zoom, pan, click-to-navigate, filtering by epic/status/work type, and critical path highlighting. Data is sourced from the daemon SurrealDB via a dedicated `get_task_dependencies()` Tauri command.

This visualization provides a structural overview of work item relationships, making it easy to identify bottlenecks, critical paths, and isolated work items across the project.

## Approach

1. Create the SvelteKit route at `src/routes/tasks/graph/+page.svelte` as a sub-route under the Tasks tab
2. Create the `DependencyGraph.svelte` component that wraps a D3.js force-directed graph
3. Add `get_task_dependencies()` Tauri command in `src-tauri/src/commands/tasks.rs` that returns tasks with their dependency edges from SurrealDB
4. Initialize D3 force simulation with nodes (tasks) and links (blocked_by/blocks relationships)
5. Apply node styling: color by work type (FEAT=blue, FIX=red, DOCS=purple, TEST=green, PLAN=orange, etc.), size by estimate (XS=8px, S=12px, M=16px, L=20px, XL=24px)
6. Render directed edges with arrowheads showing dependency direction
7. Implement zoom and pan using D3's `d3.zoom()` behavior
8. Add click handler on nodes to navigate to `/tasks/[id]` detail view
9. Implement hover tooltip showing title, status, estimate, and dependency count
10. Add filter controls (dropdowns for epic, status, work type) that filter the graph reactively
11. Implement critical path highlighting: identify the longest dependency chain and render those edges with a distinct color and increased stroke width
12. Add node labels showing `format_id` (positioned below nodes)
13. Write component tests with mock graph data covering zoom, pan, and filter interactions
