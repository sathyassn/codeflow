# INF-TSK-027-011: Kanban Board

## Description

Implement a Kanban board view in the Tasks tab. The board has four columns: Open, In Progress, Review, and Done, each showing an item count in the header. Each task is rendered as a card showing the task format_id, title, work type badge (color-coded), and estimate badge, with a left-side color stripe matching the work type. Cards in the Done column have reduced opacity (0.7). A filter bar provides three dropdown filters: Epic, Type, and Status, with filtering reactive via a Svelte store and filter state persisted in URL query params. Task data is fetched from the daemon SurrealDB via a `get_tasks(project_id, filters)` Tauri command. Cards are read-only -- clicking a card navigates to the task detail view. Empty columns show placeholder text. Cards have a hover shadow elevation effect.

## Approach

1. Create `codeflow-app/src-tauri/src/commands/tasks.rs`:
   - Define `TaskRecord` Rust struct: `id`, `format_id`, `title`, `status`, `work_type`, `area_type`, `estimate`, `epic_id`, `epic_format_id`, `priority`, `updated_at`
   - Define `TaskFilter` struct: `epic_id: Option<String>`, `work_type: Option<String>`, `status: Option<String>`
   - `#[tauri::command] async fn get_tasks(state: State<AppState>, project_id: String, filter: Option<TaskFilter>) -> Result<Vec<TaskRecord>, AppError>`:
     - Build SurrealQL: `SELECT * FROM tasks WHERE {conditions} ORDER BY updated_at DESC`
     - Execute via `DaemonConnection.query()`
   - `#[tauri::command] async fn get_epics_summary(state: State<AppState>) -> Result<Vec<EpicSummary>, AppError>`:
     - Returns epic format_id + title for filter dropdown
   - Register commands in `main.rs`
2. Create `codeflow-app/src/lib/stores/tasks.ts`:
   - `tasks` store: `$state<TaskRecord[]>([])` -- all tasks
   - `taskFilter` store: `$state<TaskFilter>({})` -- current filter, synced with URL query params
   - `loadTasks(projectId, filter?)`: invokes `get_tasks` Tauri command, updates store
   - `filteredTasks` derived: apply `taskFilter` to `tasks`
   - Group tasks by status into columns: Open (todo), In Progress (in_progress), Review (review), Done (complete)
3. Create `codeflow-app/src/lib/components/kanban/TaskCard.svelte`:
   - Props: `task: TaskRecord`
   - Display: format_id (small, muted), title (bold), work type badge (reuse WorkTypeBadge), estimate badge (pill)
   - Left-side color stripe (4px) based on work type: FEAT=blue, FIX=red, RFCT=purple, DOCS=teal, TEST=amber, PLAN=indigo, CICD=orange, CHOR=gray
   - Background: `--bg-secondary` with hover shadow elevation effect
   - Done column cards: `opacity: 0.7`
   - Click handler: navigate to task detail view (`/tasks/{format_id}`)
   - Read-only: no drag handles or status change interactions
4. Create `codeflow-app/src/lib/components/kanban/KanbanColumn.svelte`:
   - Props: `title: string`, `tasks: TaskRecord[]`, `color: string`
   - Header: column title + task count badge (e.g., "In Progress (3)")
   - Body: scrollable list of `TaskCard` components
   - Empty state: centered placeholder text "No tasks"
   - Column background: slightly different shade for visual separation
5. Create `codeflow-app/src/lib/components/kanban/FilterBar.svelte`:
   - Epic dropdown: list of epics from `get_epics_summary()`, "All Epics" default
   - Type dropdown: work type options (FEAT, FIX, RFCT, DOCS, TEST, PLAN, CICD, CHOR, HTFX, SPKE)
   - Status dropdown: status options or "All" default
   - On change: update `taskFilter` store (reactive), sync filter state to URL query params
6. Create `codeflow-app/src/lib/components/kanban/KanbanBoard.svelte`:
   - CSS Grid layout: 4 equal columns (`grid-template-columns: repeat(4, 1fr)`)
   - Gap between columns: `--spacing-md`
   - Render `FilterBar` above the board
   - Render 4 `KanbanColumn` instances with filtered + grouped tasks
   - Responsive: columns stack vertically below 768px viewport width
7. Create `codeflow-app/src/routes/tasks/+page.svelte`:
   - Render `KanbanBoard` component
   - Read filter state from URL query params on mount
   - Load tasks on mount via `$effect(() => loadTasks(projectId))`
8. Wire the Tasks tab in `+page.svelte` (root) to route to `tasks/+page.svelte`

## Notes

- The four columns (Open, In Progress, Review, Done) map to task statuses: `todo` -> Open, `in_progress` -> In Progress, `review` (stage review) -> Review, `complete` -> Done. Tasks with `blocked` or `cancelled` status are hidden by default but can be shown via the Status filter dropdown.
- CSS Grid `repeat(4, 1fr)` ensures equal column widths. Below 768px, switch to `grid-template-columns: 1fr` for single-column stacking.
- Cards are intentionally read-only in the initial implementation. Drag-and-drop for status changes is a future enhancement.
- The `get_tasks` Tauri command builds SurrealQL query strings and sends them through the daemon IPC. This avoids embedding a SurrealDB client in the app.
- Work type badge colors must be consistent with the design system specification and the sidebar WorkTypeBadge component from Task 005.
- Done column cards use `opacity: 0.7` to visually de-emphasize completed work while keeping it visible.
- Filter state is persisted in URL query params (e.g., `?epic=INF-EPC-027&type=FEAT`) so that users can bookmark or share filtered views.
- Hover shadow elevation effect uses `box-shadow` transition for smooth visual feedback on card interaction.
