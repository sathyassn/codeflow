# INF-TSK-027-006: PTY Bridge Backend (Tauri Rust)

## Description

Implement the Rust-side PTY bridge that spawns model CLI processes and streams their output via Tauri events. Reuses Epic D's `PtyCapture` from `codeflow-core` for cross-platform PTY allocation and VT100 parsing. The `PtyBridge` struct manages multiple concurrent PTY sessions with a bounded channel for backpressure. Tauri commands expose stream lifecycle operations: spawn, kill, resize, write, and list.

## Approach

1. Create `src-tauri/src/pty/mod.rs` as module root
2. Create `src-tauri/src/pty/bridge.rs` with `PtyBridge` struct:
   - Fields: `sessions: HashMap<StreamId, PtySession>`, `app_handle: tauri::AppHandle`, `max_concurrent: usize`
   - `PtySession` struct: `id: StreamId`, `handle: PtyHandle`, `config: StreamConfig`, `status: StreamState`, `created_at: Instant`
3. Implement `PtyBridge::spawn_stream(config: StreamConfig) -> Result<StreamId, AppError>`:
   - Check concurrent session count against `max_concurrent` (default 5)
   - Generate `StreamId` with ULID
   - Create `PtyCapture` from `codeflow-core` with command and args from config
   - Spawn read loop in tokio task:
     - Read PTY output into bounded channel (capacity 1024)
     - Forward chunks as `AppEvent::StreamOutput { stream_id, data }` via Tauri emit
   - Register `PtySession` in sessions map
   - Emit `AppEvent::StreamStatus { stream_id, status: Starting }` then `Running`
   - Return `StreamId`
4. Implement `PtyBridge::kill_stream(id: StreamId) -> Result<(), AppError>`:
   - Send SIGTERM to PTY child process
   - Wait 5 seconds grace period
   - If still alive, send SIGKILL
   - Emit `AppEvent::StreamStatus { stream_id, status: Killed }`
   - Remove from sessions map
5. Implement `PtyBridge::resize_stream(id: StreamId, cols: u16, rows: u16)`:
   - Forward resize to `PtyHandle::resize(cols, rows)`
6. Implement `PtyBridge::write_stream(id: StreamId, data: Vec<u8>)`:
   - Write data to PTY stdin via `PtyHandle::write()`
7. Implement process exit detection:
   - In the read loop tokio task, detect EOF on PTY output
   - Read exit code from child process
   - Emit `StreamStatus::Completed { exit_code }` or `StreamStatus::Failed { error }`
   - Update session state
8. Implement `Drop` for `PtyBridge`:
   - Kill all active PTY sessions on app exit
   - Log cleanup actions
9. Create `src-tauri/src/state/stream_state.rs`:
   - `StreamState` struct wrapping `Arc<Mutex<PtyBridge>>`
   - Register as Tauri managed state
10. Create `src-tauri/src/commands/stream.rs`:
    - `#[tauri::command] async fn spawn_stream(state, config: StreamConfig) -> Result<StreamId, AppError>`
    - `#[tauri::command] async fn kill_stream(state, id: StreamId) -> Result<(), AppError>`
    - `#[tauri::command] async fn resize_stream(state, id: StreamId, cols: u16, rows: u16) -> Result<(), AppError>`
    - `#[tauri::command] async fn write_stream(state, id: StreamId, data: Vec<u8>) -> Result<(), AppError>`
    - `#[tauri::command] async fn list_streams(state) -> Result<Vec<StreamInfo>, AppError>`
11. Wire commands into `main.rs` command registration

## Notes

- The bounded channel (capacity 1024) prevents memory exhaustion when the frontend can't consume events fast enough. If the channel is full, the PTY read loop should apply backpressure (block on send, not drop data).
- SIGTERM -> grace period -> SIGKILL is the standard Unix process termination pattern. The 5-second grace period allows processes to clean up.
- `max_concurrent = 5` is a reasonable default for a desktop app. This matches the orchestration layer's `max_concurrent_processes` default.
- The `Drop` implementation must not block — use `tokio::spawn` for async cleanup if needed, but ensure all child processes are signaled.
- Epic D's `PtyCapture` handles the cross-platform PTY allocation (openpty on macOS, /dev/ptmx on Linux) and VT100 parsing via `vte` crate.
