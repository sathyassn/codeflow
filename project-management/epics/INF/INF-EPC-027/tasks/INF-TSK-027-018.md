# INF-TSK-027-018: File Viewer and Diff Viewer

## Description

Implement reusable read-only file viewer and diff viewer utility components used across multiple views in the CodeFlow App. The file viewer uses `shiki` for syntax highlighting with support for 10 languages, line numbers, and large file handling. The diff viewer uses `diff2html` to render side-by-side and unified diff views styled for the dark theme. An "Open in Editor" button detects installed code editors (VS Code, Cursor, Sublime Text, Vim) and opens the file at a specific line number.

Backend Tauri commands `read_file(path)` and `detect_editors()` provide the data layer.

## Approach

1. Create `FileViewer.svelte` component that accepts a file path and renders its content with syntax highlighting
2. Integrate `shiki` for syntax highlighting:
   - Configure with a dark theme (e.g., `github-dark` or `one-dark-pro`)
   - Register language grammars for: Rust, TypeScript, JavaScript, JSON, TOML, Markdown, Shell, YAML, HTML, CSS
   - Map file extensions to language IDs
3. Add line number display as a gutter column alongside highlighted code
4. Implement large file handling: if file exceeds 5000 lines, use virtual scrolling (render only visible viewport) or truncate with a "Show more" button
5. Create `DiffViewer.svelte` component using `diff2html`:
   - Accept a unified diff string as input
   - Support toggle between side-by-side and unified views
   - Apply dark theme styling to match the app's color scheme
6. Create `read_file(path: String)` Tauri command in `src-tauri/src/commands/files.rs`:
   - Read file content as UTF-8 string
   - Return file content with metadata (size, line count)
   - Handle binary files gracefully (return error or "(binary file)" message)
7. Create `detect_editors()` Tauri command:
   - Check for installed editors using `which` (Unix) command: `code`, `cursor`, `subl`, `vim`
   - Return list of detected editor names with their CLI commands
8. Implement "Open in Editor" button that:
   - Shows detected editors in a dropdown
   - Opens the file at the current line number using the editor's CLI (e.g., `code --goto file:line`, `cursor file:line`, `subl file:line`, `vim +line file`)
   - Uses Tauri's `Command::new()` to spawn the editor process
9. Write component tests for highlighting, diff rendering, and editor detection

## Notes

- `shiki` is a high-quality syntax highlighter that uses VS Code's TextMate grammars; it loads lazily per-language
- `diff2html` is the standard library for rendering git diffs in HTML; use `Diff2HtmlUI` for interactive features
- Editor CLI flag formats: `code --goto file:line:col`, `cursor file:line`, `subl file:line`, `vim +line file`
- The `read_file` command should validate that the path is within the project root for security (prevent arbitrary file reads)
- Consider caching shiki highlighter instances to avoid re-initialization overhead on each file view
