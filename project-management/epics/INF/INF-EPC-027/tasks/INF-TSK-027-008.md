# INF-TSK-027-008: Multi-Tab Stream Management

## Description

Implement a multi-tab system for concurrent model streams. Each active PTY session gets its own tab. Tab switching uses display-swap (CSS `display: none` / `display: block`) to preserve xterm.js scrollback and terminal state without destroying and recreating instances. The `streams` Svelte store manages the collection of `StreamSession` objects. Sidebar session clicks activate the corresponding stream tab.

## Approach

1. Create `src/lib/stores/streams.ts`:
   - `StreamSession` type: `{ id: StreamId, config: StreamConfig, status: StreamState, tabId: TabId, createdAt: Date }`
   - `streams` store: `$state<StreamSession[]>([])` -- all stream sessions
   - `activeStreamId` store: `$state<StreamId | null>(null)` -- currently visible stream
   - `addStream(config: StreamConfig): Promise<StreamId>`:
     - Check tab count against maximum (10)
     - Call `spawnStream(config)` via API
     - Create `StreamSession` entry
     - Set as `activeStreamId`
   - `removeStream(id: StreamId)`:
     - Remove from `streams` array
     - If was active, switch to next stream or null
   - `activateStream(id: StreamId)`:
     - Set `activeStreamId` to given stream
   - Subscribe to `stream_status` events:
     - Update `StreamSession.status` on status changes
     - On `Completed`/`Failed`/`Killed`: mark tab as inactive (but don't remove — user must close)
2. Create `src/lib/components/terminal/StreamTabs.svelte`:
   - Horizontal tab strip below the main tab bar
   - One tab per `StreamSession` in `streams` store
   - Tab content: status dot + model name (from config) + close button (x)
   - Active tab: bottom border indicator (2px `--accent-primary`)
   - Inactive tabs: no border
   - Click handler: `activateStream(session.id)`
   - Close button: show confirmation dialog if stream is still running, then `killStream()` + `removeStream()`
   - Tab order: preserved as created (insertion order)
3. Implement display-swap in terminal container:
   - Each `TerminalView` wrapped in a `<div>` with `style:display={activeStreamId === session.id ? 'block' : 'none'}`
   - This preserves xterm.js instances and scrollback across tab switches
   - On tab activation, call `fitAddon.fit()` to recalculate dimensions (container may have resized while hidden)
4. Wire sidebar session binding:
   - When user clicks a session in sidebar, check if a corresponding stream tab exists
   - If exists: `activateStream(matchingStream.id)`
   - If not: optionally spawn a new stream for that session (future enhancement)
5. Enforce maximum 10 concurrent tabs:
   - On `addStream()`, check `streams.length >= 10`
   - If exceeded: show notification "Maximum stream tabs reached"

## Notes

- Display-swap (CSS `display: none`) is critical for xterm.js because destroying and recreating terminal instances loses scrollback history and terminal state. This is the standard pattern for tabbed terminal applications.
- After switching tabs, `fitAddon.fit()` must be called because the terminal container may have changed size while the tab was hidden. xterm.js does not auto-detect size changes when `display: none`.
- The 10-tab maximum is a UX guardrail — each tab holds an xterm.js instance with up to 10,000 lines of scrollback, which consumes memory.
- Tab close confirmation only appears for running streams. Completed/failed streams can be closed without confirmation.
