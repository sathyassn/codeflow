# INF-TSK-027-016: Structured Config Viewer Components

## Description

Implement the Config tab UI providing a structured, read-only view of all 5 CodeFlow config files. The layout uses a left navigation listing config files and a right panel displaying the selected config as titled tables. A "Read-only view" banner with a "Request Change" button is displayed prominently. Config data refreshes automatically when the backend emits `ConfigChanged` events.

Each config file has a tailored table layout:
- **Enforcement Policy**: Merge Protection rules, Hook Configuration, Branch Access tables
- **PathFlow Config**: Phase Definitions, Work Pipelines tables
- **Orchestration**: Model Routing, Parallelism settings tables
- **Project Config**: Project Metadata, Repositories tables
- **Model Orchestration**: Model profiles, stage routing tables

## Approach

1. Create the SvelteKit route at `src/routes/config/+page.svelte` with a two-panel layout (left nav + right content)
2. Create a `config` Svelte store in `src/lib/stores/config.ts` that manages the active config file selection and cached config data
3. Create the `ConfigNav.svelte` component with 5 nav items, highlighting the active selection
4. Create the `ConfigViewer.svelte` wrapper that renders the appropriate config-specific component
5. Create config-specific display components:
   - `EnforcementPolicyView.svelte` -- Merge Protection, Hook Configuration, Branch Access
   - `PathFlowConfigView.svelte` -- Phase Definitions, Work Pipelines
   - `OrchestrationView.svelte` -- Model Routing, Parallelism
   - `ProjectConfigView.svelte` -- Project Metadata, Repositories
   - `ModelOrchestrationView.svelte` -- Model profiles, stage routing
6. Render config sections as titled HTML tables with monospace font for code values (paths, commands, patterns)
7. Add "Read-only view" banner at the top of the right panel with a "Request Change" button
8. Subscribe to Tauri `ConfigChanged` events and refresh the active config when its file changes
9. Fetch config data from the backend using `get_config(file_id)` Tauri command
10. Write component tests for each config view, nav switching, and responsive layout

## Notes

- Table styling should use CSS Grid or HTML tables with consistent column widths
- Code values (file paths, regex patterns, command strings) should use `font-family: monospace` with a slightly different background color for visual distinction
- The nav should use the config file's display name, not the raw file path (e.g., "Enforcement Policy" not "enforcement-policy.json")
- Consider lazy-loading config data per file (fetch only when nav item is selected) to reduce initial load time
