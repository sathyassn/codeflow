# INF-TSK-027-012: Epic Timeline and Roadmap

## Description

Implement an epic timeline/roadmap view as a sub-route under the Tasks tab (`/tasks/timeline`). The timeline displays epics as horizontal bars ordered by dependency, with phase segments within each bar showing task completion progress. Dependency arcs are drawn between connected epics using SVG lines/curves. Epic bars are color-coded by status: planning=purple, active=blue, complete=green. A hover tooltip shows title, phase count, task count, and status. Clicking an epic navigates to the Kanban board filtered to that epic. The view includes a legend showing color meanings and status icons, and the current phase is highlighted with a pulsing indicator. The layout is responsive with horizontal scroll and vertical stack for narrow viewports.

## Approach

1. Add `get_epics` Tauri command to `codeflow-app/src-tauri/src/commands/tasks.rs`:
   - `EpicTimelineRecord` struct: `format_id`, `title`, `status`, `area_type`, `phases` (Vec of PhaseSegment), `task_count`, `completed_count`, `current_phase`, `blocked_by` (Vec of epic format_ids), `blocks` (Vec of epic format_ids)
   - `PhaseSegment` struct: `name`, `task_count`, `completed_count`
   - `#[tauri::command] async fn get_epics(state: State<AppState>, project_id: String) -> Result<Vec<EpicTimelineRecord>, AppError>`:
     - Query daemon for epics with task counts, phase breakdown, current phase, and dependency info
   - Register command in `main.rs`
2. Create `codeflow-app/src/lib/components/kanban/EpicTimeline.svelte`:
   - Props: `epics: EpicTimelineRecord[]`
   - Layout: vertical list of epic bars, ordered by dependency (topological sort)
   - Epic bar structure:
     - Left label: epic format_id + title (fixed width, ~200px)
     - Bar: horizontal, divided into phase segments proportional to task count
     - Fill: progress fill (completed tasks / total tasks) overlaid on each phase segment
     - Color: based on epic status (planning=purple, active=blue, complete=green)
   - Current phase: highlighted with pulsing CSS animation (`@keyframes pulse`)
   - Phase segments: subtle borders between phases, phase label on hover
   - Dependency arcs: SVG lines connecting blocked_by/blocks relationships between epic bars
     - Curved arcs from the end of blocking epic to the start of blocked epic
     - Arrow at the target end
     - Arcs styled with `--text-muted` color, dashed stroke
   - Hover tooltip: epic title, phase count, task count, status, completion percentage
   - Click handler: navigate to Kanban board filtered to the clicked epic (`/tasks?epic={format_id}`)
   - Legend: color key (planning=purple, active=blue, complete=green) and status icons
3. Create `codeflow-app/src/routes/tasks/timeline/+page.svelte`:
   - Load epics timeline data on mount via `$effect`
   - Render `EpicTimeline` component
   - Back link to Kanban board: `/tasks`
4. Add navigation between Kanban and Timeline:
   - In `KanbanBoard.svelte`: add "Timeline" link/button in the filter bar area
   - In `EpicTimeline`: add "Board" link/button to return to Kanban
5. Responsive layout:
   - Default: horizontal bars with horizontal scroll for many phases
   - Narrow viewports (< 768px): vertical stack layout
   - SVG dependency arcs adapt to layout direction
6. Rendering approach:
   - SVG preferred for dependency arcs (curved lines trivial in SVG, hard in pure CSS)
   - Epic bars can be CSS divs positioned within the SVG container, or pure SVG rects
   - Ensure 60fps scrolling for large epic lists

## Notes

- SVG is recommended for the timeline because dependency arcs require curved lines which are trivial in SVG (`<path>` with cubic bezier) but very difficult in pure CSS.
- Phase segments are proportional to task count, not time. An epic with 5 tasks in Phase E1 and 3 in Phase E2 would show E1 taking 5/8 of the bar width.
- The completion fill uses a semi-transparent overlay on each phase segment, so the phase borders remain visible underneath.
- Dependency arcs use the `blocked_by` and `blocks` fields from the epic markdown frontmatter, queried via daemon.
- The timeline view is a sub-route of Tasks (`/tasks/timeline`) rather than a separate tab, keeping the navigation simple. Tab count stays at 6.
- The EpicTimeline component is placed in the `kanban/` directory because it shares the same task data infrastructure and is navigated from the Kanban board.
- Color scheme changed from the initial design: planning=purple (not blue), active=blue (not green), complete=green (not gray). This provides better visual distinction between states.
- The pulsing indicator on the current phase uses a CSS `@keyframes pulse` animation with a subtle scale/opacity change to draw attention without being distracting.
- Clicking an epic navigates to the Kanban board with the epic filter pre-applied (`/tasks?epic={format_id}`), leveraging the URL query param filter persistence from Task 011.
