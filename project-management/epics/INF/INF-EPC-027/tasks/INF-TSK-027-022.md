# INF-TSK-027-022: Team Analytics Dashboard

## Description

Implement an analytics dashboard providing visibility into team development metrics. The dashboard displays 5 metric panels: session frequency (bar chart), stage pass rates (horizontal bar chart), rework rates (metric card with trend indicator), model usage (stacked bar chart), and cost tracking (line chart with budget overlay). A time range selector allows filtering by 7 days, 30 days, 90 days, or all time. A per-project/cross-project toggle allows viewing metrics for the active project or aggregated across all accessible projects.

All charts use SVG rendering with the app's theme colors. Data is sourced from the daemon SurrealDB via `get_session_stats()` and `get_model_usage()` Tauri commands. This task depends on INF-TSK-025-008 (Project Registration and Discovery), INF-TSK-025-010 (Sync Engine -- Ledger Replay), and INF-TSK-025-011 (Global SurrealDB Schema -- Project-Scoped Tables) for the session statistics and model usage data collection infrastructure.

## Approach

1. Create the SvelteKit route at `src/routes/analytics/+page.svelte` with a grid layout for 5 metric panels
2. Create a shared `Chart.svelte` base component for SVG chart rendering with theme-aware colors
3. Create metric panel components:
   - `SessionFrequencyChart.svelte` -- vertical bar chart showing session count per day/week
   - `StagePassRatesChart.svelte` -- horizontal bar chart with pass/fail percentages per stage (DEV, REV, QA)
   - `ReworkRatesCard.svelte` -- metric card showing rework rate percentage with up/down trend arrow
   - `ModelUsageChart.svelte` -- stacked bar chart showing token/cost breakdown by model (Opus, Sonnet, Haiku)
   - `CostTrackingChart.svelte` -- line chart with cumulative cost over time and a horizontal budget line
4. Add time range selector component with options: 7d, 30d, 90d, All
5. Add per-project / cross-project toggle (reuse pattern from Kanban cross-project toggle)
6. Create `get_session_stats(time_range, project_id?)` Tauri command in `src-tauri/src/commands/analytics.rs`:
   - Query daemon SurrealDB for session counts, stage verdicts, rework iterations
   - Aggregate by time period based on selected range
7. Create `get_model_usage(time_range, project_id?)` Tauri command:
   - Query daemon for model token usage, cost data, and budget limits
   - Return time-series data for chart rendering
8. Apply SVG rendering for all charts using the app's CSS custom properties for colors
9. Write component tests for chart rendering and time range filtering; backend tests for data aggregation

## Notes

- SVG charts are preferred over canvas for theme integration (CSS custom properties work with SVG fill/stroke)
- Consider using a lightweight charting library like `layercake` (SvelteKit-native) or hand-rolled SVG for full control
- The budget line on the cost chart should be configurable (default: read from project config)
- Rework rate trend is calculated as (current period rework rate - previous period rework rate); positive = trending up (worse), negative = trending down (better)
- Model usage data should include both token counts and estimated costs
