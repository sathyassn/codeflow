# INF-TSK-018-001: Fix test-commands.sh cross-platform reliability for Linux CI

## Description

The test file `.codeflow/testing/scripts/commands/test-commands.sh` uses `echo -e` with inline UTF-8 checkmarks (✓ ✗) and ANSI color codes for test output. On Linux CI (ubuntu-latest), these patterns can fail due to locale/encoding differences or shell portability issues.

The fix replaces the non-portable `echo -e "  ${GREEN}✓${NC} ..."` / `echo -e "  ${RED}✗${NC} ..."` inline patterns with cross-platform alternatives — either using `printf` (POSIX-portable) or delegating to the shared `assert_*` functions from `test-helpers.sh` that already handle this correctly.

## Approach

1. Audit all `echo -e` usages in `test-commands.sh` that include UTF-8 characters (✓ ✗) or ANSI escape codes
2. Replace each `echo -e "  ${GREEN}✓${NC} ..."` pattern with `printf "  ${GREEN}✓${NC} %s\n" "..."` (printf is POSIX)
3. Replace each `echo -e "  ${RED}✗${NC} ..."` pattern with `printf "  ${RED}✗${NC} %s\n" "..."`
4. Audit for any remaining `echo "$var" | grep` patterns and replace with `grep "pattern" <<< "$var"` or direct file-based grep
5. Verify the test runs cleanly on both macOS and Linux (simulate with `bash --posix` or `env LANG=C bash`)

## Files

## Notes

The `echo -e` behavior is not POSIX-standardized — different implementations handle it differently. `printf` is POSIX-portable and handles format strings consistently across Linux/macOS. The UTF-8 checkmarks (✓ ✗) in the source file are fine as long as the locale supports them; the issue is the `echo -e` flag itself. Note: `test-helpers.sh` already uses `echo -e` — this fix only targets `test-commands.sh`'s inline patterns that bypass the shared helper functions.
