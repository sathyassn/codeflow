# INF-TSK-036-001: Add dirty worktree guard to push/PR gate

> **MANDATORY VALIDATION:** Files created from this template MUST be validated against the task validation command before committing:

## Description

Add a dirty worktree check to `check_cumulative_push_pr_gate()` in `pre_tool_use.rs` so that `git push` and `gh pr` commands are blocked when the worktree has uncommitted changes. The `has_dirty_files()` helper already exists in `cleanup.rs` — this task wires it into the push/PR gate logic.

This prevents a race condition where a developer (or autorun worker) attempts to push while staged or unstaged changes are present, which would result in pushing an incomplete state.

## Approach

1. Check visibility of `has_dirty_files()` in `cleanup.rs` — currently `fn` (private). Make `pub(crate)` or add a public wrapper in `worktree/mod.rs`.
2. In `pre_tool_use.rs` `check_cumulative_push_pr_gate()`, after existing sentinel checks, add a call to the dirty-file check using the resolved worktree path.
3. Return a `HookResult::Block` with a clear message: `"Worktree has uncommitted changes. Commit or stash before pushing."`.
4. Add unit tests in `pre_tool_use.rs` test module covering: dirty worktree blocked, clean worktree allowed.
