# INF-TSK-009-001: Add persistent test enforcement requirements

## Description

Add persistent test requirement enforcement across task templates, validation scripts, and agent definitions. Currently, the `tests` field exists in task-template.md but is not validated by `validate-task.sh`. Agent definitions for cf-development, cf-review, and cf-quality-assurance do not explicitly mandate test file creation/update for every code file touched. This task makes test enforcement persistent and machine-checkable.

## Approach

1. Verify current state of `validate-task.sh` tests-field validation (may be absent)
2. Add validation in `validate-task.sh`: for code-producing work types (FEAT, FIX, RFCT, HTFX, CHOR, CICD, TEST), require `tests` field to be non-empty array
3. Add `work_type` enum validation in `validate-epic.sh`
4. Update `cf-development.md`: add explicit rule — for every .sh/.py file created or modified, a corresponding test file must be created/updated
5. Update `cf-review.md` CODE_REVIEW checklist: add test file presence check as a required verification step
6. Update `cf-quality-assurance.md` WS-QA gate: add cross-reference of `file_scope` against test-config.json to flag unregistered scripts
