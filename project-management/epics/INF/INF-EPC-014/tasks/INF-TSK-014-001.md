# INF-TSK-014-001: Implement PID-based stale session cleanup and teammate detection

## Description

The stale session cleanup (PR #63) warned about stale sessions but could not reliably determine whether teammates were truly alive. This task implements PID-based detection: at session start, the hook writes `pathflow-team.json` containing the current process PID and teammate metadata. On subsequent sessions, the hook reads existing `pathflow-team.json` files and uses `kill -0 $pid` to test whether the process is still alive. Dead PID = truly stale session (safe to clean up). Live PID = active session (warn and back off).

Additionally, the worktree setup script is updated to use selective `.state/` symlinks: shared state directories (db, ledger, registry, backups, coordination, logs) are symlinked to the main repo for unified tracking, while local per-worktree directories (runtime, session, sentinels) are created fresh to prevent cross-worktree session contamination.

## Approach

1. Write design analysis doc to `.codeflow/docs/analysis/stale-session-pid-detection.md`
2. Define `pathflow-team.json` schema and write location
3. Update `cf-session-start-init.sh`: write pathflow-team.json at session init, add PID-based stale detection
4. Update `cf-session-end-cleanup.sh`: remove pathflow-team.json on clean exit
5. Update `cf-worktree-setup.sh`: selective `.state/` symlinks (shared: db, ledger, registry, backups, coordination, logs; local: runtime, session, sentinels)
6. Write/update tests in `test-cf-session-start-init.sh` for PID detection logic

## Notes

- PID check idiom: `kill -0 $pid 2>/dev/null` returns 0 if process alive,
  non-zero if dead
- pathflow-team.json is ephemeral — not git-tracked (add to .gitignore if needed)
- Worktree `.state/` symlink approach: shared dirs (db, ledger, registry, backups, coordination, logs) → symlinked to main repo; local dirs (runtime, session, sentinels) → created fresh per-worktree to isolate session state

  this task adds PID-based ground truth
