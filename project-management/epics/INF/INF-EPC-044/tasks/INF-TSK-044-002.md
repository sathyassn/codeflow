# INF-TSK-044-002: Autorun Worker Reliability Fixes

## Description

Fix six reliability issues in the autorun worker subsystem that cause lost work, stuck sessions, and wasted compute. These are the highest-priority fixes identified in the autorun reliability analysis.

The fixes target three files primarily: `worker.rs` (invoke loop, serialized merge, worktree cleanup), `orchestrator.rs` (panic guard, dispatch audit), and `config.rs`/`batch.rs` (configurable timeout). One agent definition update (`cf-git-operations.md`) adds pre-PR rebase instructions.

**Expected Outcome:** Autorun workers recover gracefully from timeouts (merge PRs created before timeout), detect PathFlow completion proactively (shorter effective timeouts), handle panics without leaking resources, and retry worktree cleanup to prevent pool exhaustion.
**Deployment:** PR merge to main. Changes take effect on next autorun batch execution.

## Approach

1. **Post-timeout PR detection (autorun.rs + worker.rs)**
   - **Two-file architecture:** `autorun.rs` (CLI crate) contains the inner poll loop (`RealClaude::invoke()`, line 2713) and PR detection (line 2772). `worker.rs` (core crate) contains the outer timeout (`TmuxWorker::run()`, line 778) and serialized merge logic (line 907).
   - In `autorun.rs:2734`: when timeout fires, do NOT return immediately with `exit_code: 124`. Instead, fall through to the branch detection (line 2755) and `gh pr list` PR detection (lines 2772-2805) before returning the InvokeResult
   - In `autorun.rs:2772`: remove the `exit_code == 0` gate from the PR detection condition. Change to `if pr_number == 0 && !branch_name.is_empty()` so it runs for both normal exits AND timeouts
   - In `worker.rs:907-909`: modify the serialized_merge condition to check `invoke_result.pr_number > 0` independently of `exit_code == 0`

2. **PathFlow sentinel polling (autorun.rs)**
   - Create new function `check_pathflow_progress(worktree_path: &Path, session_id: &str) -> PathFlowState`
   - PathFlowState enum: `Unknown`, `InProgress(String)`, `PrCreated`, `Complete`
   - In the inner poll loop at `autorun.rs:2713`: add a 30-second secondary sentinel check alongside the 1-second exit_code_file poll. Every 30 iterations (30s at POLL_INTERVAL=1s), call `check_pathflow_progress()`
   - When `PrCreated` detected: reduce remaining timeout to 120s (modify the timeout Duration or track separately)
   - When `Complete` detected: break poll loop with 10s grace for exit_code_file

3. **Pre-PR rebase in cf-git-operations.md**
   - Add to PF6-TSK-05 (Create PR) section: before `gh pr create`, run `git fetch origin {target_branch} && git rebase origin/{target_branch}`
   - On rebase conflict: report to team lead with file list
   - On success: `git push --force-with-lease origin {branch}`

4. **Configurable per-task timeout (config.rs, batch.rs, worker.rs, autorun.rs)**
   - Change `AutorunConfig::default()` `worker_timeout_secs` from 3600 to 7200
   - Add `timeout_secs: Option<u64>` to `TaskSpec` struct with `#[serde(default)]`
   - In `TmuxWorker::run()`, compute effective timeout: `task_config.timeout_secs.unwrap_or(global_config.worker_timeout_secs)` for the OUTER timeout (worker.rs:778)
   - Add `worker_timeout_secs: u64` field to `InvokeConfig` struct (worker.rs:106-124). Pass the effective timeout through: worker.rs:780-791 sets the field when building InvokeConfig
   - In `RealClaude::invoke()` (autorun.rs:2710): replace `self.worker_timeout` with `Duration::from_secs(cfg.worker_timeout_secs)` so the INNER poll loop timeout matches the per-task override
   - This ensures the per-task timeout propagates to BOTH outer timeout (worker.rs:778 tokio::time::timeout) AND inner timeout (autorun.rs:2710 poll loop)

5. **Worker panic guard (orchestrator.rs)**
   - In `spawn_worker()`, after the tokio::spawn async block, the JoinHandle is already returned but panics are not caught
   - Add `std::panic::AssertUnwindSafe` wrapper with `futures::FutureExt::catch_unwind()` around the async block body
   - On panic: remove from running set, add to failed set, push WorkerResult with status "failed" and error "worker panicked"
   - Store JoinHandles in a task_id-keyed map: `handles: Arc<Mutex<HashMap<String, JoinHandle<()>>>>` (not a Vec). `spawn_worker()` inserts with task_id key, dispatch loop removes on completion
   - In `dispatch_ready_tasks()`: after each dispatch cycle, iterate `handles` map, check `is_finished()` for each. If finished AND task_id still in `running` set: panic or silent failure detected -- clean up (remove from running, add to failed, push WorkerResult)

6. **Worktree cleanup retry (worker.rs)**
   - Replace single `self.worktree.cleanup(&wt_name)` (worker.rs:1009) with retry loop: 3 attempts, 2s backoff between attempts
   - On final failure: log error, call `WorktreeRegistry::deregister()` directly to prevent pool exhaustion
   - Emit a coordination event for cleanup failure

## Notes

**Two-file architecture:** The autorun worker spans TWO files across TWO crates:
- `codeflow-cli/cli/src/cmd/autorun.rs` (CLI crate): contains `RealClaude` implementing `ClaudeInvoker`. The inner poll loop (line 2713), timeout/SIGTERM handling (line 2718), branch detection (line 2755), and PR detection via `gh pr list` (line 2772) all live here. This is the "Claude-specific" layer.
- `codeflow-cli/core/src/autorun/worker.rs` (core crate): contains `TmuxWorker::run()` which owns the outer timeout (line 778), merge conflict detection (line 803), serialized merge (line 907), DB updates (line 1051), and worktree cleanup (line 1009). This is the "worker lifecycle" layer.
- `InvokeConfig` (worker.rs:106) is the bridge: worker.rs builds it and passes to `ClaudeInvoker::invoke()` in autorun.rs.

**Sentinel path construction:** Sentinel files are at `{worktree}/.state/sentinels/pathflow/{session_id}/pathflow-pf-{N}` and `pathflow-ws-{stage}`. The session_id for autorun workers is the `worker_session_id` (worker_sid variable in run()), NOT the batch session_id.

**gh pr list requires sandbox bypass:** The `gh pr list` command used for post-timeout PR detection requires `dangerouslyDisableSandbox: true` or must be run from within the worker context where sandbox is already bypassed.
