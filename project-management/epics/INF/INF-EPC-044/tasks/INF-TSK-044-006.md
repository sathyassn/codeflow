# INF-TSK-044-006: TUI Status Accuracy, tmux Interactive Sessions, and Autorun Improvements

## Description

Fix a cluster of related issues discovered after shipping INF-TSK-044-004 and INF-TSK-044-005:

1. **TUI status accuracy** -- stale sessions are not detected (no PID liveness check in fetch_session_views), duration keeps counting for completed/stale sessions, and phase shows raw data instead of "Unknown" when filesystem data is absent.

2. **Config cleanup** -- the `timeout` field in parallel-work-config.json is obsolete; the code default of 7200s should take effect without requiring config-file override.

3. **Status display improvements** -- non-watch status only shows active/running items; should show ALL. Status should auto-select TUI when TTY, text when piped. `--once` forces text. Interactive `list` command is redundant with `status --once`.

4. **tmux session launch** -- interactive sessions should launch inside tmux for reattach capability, with `--no-tmux` fallback for non-tmux environments.

5. **Autorun reliability** -- timeout salvage should push the branch before worktree cleanup (best-effort); last_phase needs to be stored in autorun_task_run for post-cleanup display; --interval default should be unified to 2s; status functions should use resolve_repo_root() for consistency.

6. **Batch report** -- batch report should be committed to the integration branch before the final PR is created.
