## Description

Build the shared TUI module architecture and the first consumer: an interactive autorun status dashboard. This replaces the current plain-text `run_status_watch()` (autorun.rs:1364) which clears the screen and reprints text every 2 seconds with no interactivity.

The shared `tui/` module in `codeflow-core` provides data fetching, theming, and reusable widgets that will be consumed by both the autorun dashboard (this task) and the interactive session dashboard (INF-TSK-044-005).

**Expected Outcome:** `codeflow autorun status --watch` launches a full-screen interactive dashboard showing real-time task status with keyboard navigation, task attachment via tmux, and task abort/retry actions. The shared tui/ module is ready for reuse by INF-TSK-044-005.
**Deployment:** PR merge to main. Available immediately via `codeflow autorun status --watch`.

## Approach

1. **Add ratatui dependency**
   - `codeflow-cli/cli/Cargo.toml`: add `ratatui = "0.29"` to `[dependencies]`
   - `codeflow-cli/core/Cargo.toml`: add `ratatui = { version = "0.29", optional = true }` to `[dependencies]` and `tui = ["ratatui"]` to `[features]`
   - `codeflow-cli/cli/Cargo.toml`: enable the tui feature on core: `codeflow-core = { path = "../core", features = ["tui"] }`
   - Verify: `cargo build --workspace` succeeds

2. **Create shared tui/ module in core**
   - Create `codeflow-cli/core/src/tui/mod.rs` -- module exports, feature-gated with `#[cfg(feature = "tui")]`
   - Create `data.rs` -- `BatchView`, `TaskView`, `SessionView`, `StageInfo` structs. Functions: `fetch_batch_view()`, `fetch_session_views()`. Data from SurrealDB tables + filesystem sentinel scans + PID liveness checks
   - Create `theme.rs` -- color constants (ratatui::style::Color values), unicode symbol constants (char values), border style (BorderType::Rounded), text style preset functions: `header()`, `selected()`, `dim()`, `error()`, `success()`
   - Create `widgets/mod.rs` -- widget module re-exports
   - Create `widgets/status_badge.rs` -- `StatusBadge` struct implementing Widget trait. Maps TaskStatus to colored Span
   - Create `widgets/phase_badge.rs` -- `PhaseBadge` struct. Maps phase string to colored Span with semantic coloring
   - Create `widgets/duration_cell.rs` -- `DurationCell` struct. Formats seconds to MM:SS or HH:MM:SS with color thresholds
   - Create `widgets/detail_pane.rs` -- `DetailPane` struct. Renders bordered panel with branch, PR, stages pipeline, worktree path

3. **Build autorun TUI dashboard (autorun.rs)**
   - Replace `run_status_watch()` function body with ratatui Terminal setup
   - Event loop: 2-second tick interval, keyboard/mouse event handling via crossterm EventStream
   - Layout: 4 vertical sections using Layout::vertical() with Constraint::Length (header 2 lines, table fill, detail 5 lines, keys 1 line)
   - Header: batch name, status badge, active worker count, elapsed time, target branch
   - Task table: StatefulWidget with TableState for selection. Columns: task_id, status (badge), phase (badge), branch, PR#, duration (colored)
   - Detail pane: shows selected task details. Stage pipeline rendered as "WS-DEV [symbol] -> WS-REV [symbol] -> WS-QA [symbol]"
   - Keybinding bar: displays available actions
   - Enter: exec `tmux attach-session -t {tmux_name}` (exit alternate screen first, re-enter after)
   - `a`: call `run_cancel()` for selected task
   - `r`: retry selected failed/timed-out task by running `codeflow autorun resume --batch {session_id}` as a subprocess (this re-creates a mini-batch with just the failed tasks). Only enabled for failed/timed-out tasks, disabled (no-op) for running/pending/completed
   - Mouse: click to select, scroll to navigate
   - Handle no-batch gracefully: show "No active autorun batches" with recent completed batches list

4. **Enhanced plain-text status (autorun.rs)**
   - In `run_status()` (non-watch): add branch, PR#, and phase columns to the text table
   - Add `--json` flag: when set, serialize the BatchView to JSON and print to stdout
   - Phase data: read from sentinel dirs for running tasks (best-effort, show "--" if unavailable)

## Notes

**ratatui version rationale:** v0.29 is the latest stable release as of the knowledge cutoff. crossterm is bundled as `ratatui::crossterm` -- no separate crossterm dependency needed.

**Feature flag rationale:** The `tui` feature in core is optional because not all consumers of codeflow-core need the TUI rendering code. The CLI crate enables it via feature dependency. This keeps the core crate lean for library consumers.

**Testing strategy for TUI:** ratatui widgets can be tested by rendering to a `Buffer` and asserting on cell content/style. The `ratatui::buffer::Buffer` type has `get(x, y)` for cell inspection. data.rs tests use mock DB/filesystem. Theme tests verify constant values. Widget tests verify rendered Span/Line output.

**Terminal restoration:** The TUI MUST call `ratatui::restore()` (which disables raw mode and leaves alternate screen) in all exit paths: normal quit, panic, Ctrl+C. Use a `Drop` guard or `std::panic::set_hook` wrapper. Failure to restore leaves the user's terminal in raw mode (broken).
