# INF-TSK-044-003: Queue Lifecycle and Session Management

> **MANDATORY VALIDATION:** Files created from this template MUST be validated against the task validation command before committing:
> `codeflow validate task <file-path>`
> Fix all errors (exit code 1) before requesting a commit. Warnings are advisory.

## Description

Fix four issues related to autorun queue lifecycle and session management: (1) enable cancellation of pending tasks (not just running ones), (2) add a graceful wrap-up signal mechanism when PathFlow detects PR creation, (3) fix DB update ordering to prevent stale status counts, and (4) populate interactive session DB fields (branch, work_type, team_name) that are currently always NONE.

This task depends on INF-TSK-044-002 because the wrap-up signal mechanism builds on the sentinel polling infrastructure introduced there.

**Expected Outcome:** Pending autorun tasks can be cancelled without waiting for them to start. Workers detect PathFlow completion proactively and signal Claude to wrap up. Status displays show accurate counts immediately after task completion. Interactive sessions display branch, work_type, and phase information.
**Deployment:** PR merge to main. Changes take effect on next autorun batch and interactive session.

## Approach

1. **Individual pending task abort (autorun.rs, orchestrator.rs)**
   - In `run_cancel()` (autorun.rs:1484): extend status handling to include `Pending` alongside `Running`
   - For Pending tasks: update `autorun_task_run` status to `Skipped` in DB with `error_message: "user_cancelled"`
   - In `dispatch_ready_tasks()` (orchestrator.rs:538): DB status check must happen AFTER semaphore permit acquisition but BEFORE spawning the worker. Sequence: `try_acquire_owned()` -> check DB status -> if `Skipped`/`Cancelled`, release permit (drop) and skip -> else `spawn_worker()`
   - CLI: `codeflow autorun cancel <task_id> [--batch <sid>]` works for both running AND pending tasks

2. **Graceful wrap-up signal (autorun.rs, pre_tool_use.rs, worker.rs)**
   - Three-way split:
     - **autorun.rs** (inner poll loop at line 2713): sentinel polling via `check_pathflow_progress()` (from INF-TSK-044-002) detects pf-6. When `PrCreated` detected, write `{worktree}/.state/runtime/local/wrap-up-signal` file from the poll loop
     - **pre_tool_use.rs** (inside the Claude session): detects wrap-up-signal file existence. When found, print advisory to stderr: "PathFlow PF6 complete. Please expedite PF7-END."
     - **autorun.rs** (poll loop continuation): if wrap-up-signal file exists for > 120s and exit_code_file still absent, treat as effective completion -- fall through to branch detection and PR detection (lines 2755-2805), then return InvokeResult
   - The wrap-up-signal file write and 120s timeout check both happen in autorun.rs's inner poll loop. worker.rs handles the resulting InvokeResult normally.

3. **DB update ordering (worker.rs)**
   - The primary DB updates are in worker.rs:1051-1100 (`update_autorun_worker`, `update_autorun_task_run`), NOT in orchestrator.rs (which only manages in-memory sets)
   - Wrap the worker.rs DB update calls with `tokio::time::timeout(Duration::from_secs(10), ...)`
   - Ensure DB updates complete BEFORE the WorkerResult is returned to the orchestrator (which then updates in-memory completed/failed sets)
   - If DB update times out: log warning via eprintln, but still return WorkerResult so in-memory set updates proceed
   - This ensures `codeflow autorun status` shows accurate DONE/FAIL counts within 1s of completion

4. **Interactive session DB field population (post_tool_use.rs, interactive.rs)**
   - In `post_tool_use.rs`: add update logic to populate interactive_session fields:
     - `team_name`: set during TeamCreate handling (PF1)
     - `branch` and `work_type`: set when pf-3 sentinel is created (PF3 completion)
   - Read values from `pathflow-session-status.json` which already tracks these
   - In `interactive.rs`: update `run_status()` display to show branch, work_type, and phase columns

## Concurrency Considerations

| Shared Resource | Access Pattern | Safety Mechanism |
|----------------|---------------|-----------------|
| SurrealDB autorun_task_run | Concurrent read/write from cancel command and dispatch loop | SurrealDB transaction isolation |
| completed/failed/running sets in orchestrator | Concurrent write from multiple workers | Arc<Mutex<HashSet>> |
| wrap-up-signal file | Write from worker, read from PreToolUse hook | Atomic create (write to temp + rename) |
| interactive_session DB record | Write from PostToolUse, read from status command | SurrealDB MERGE (idempotent) |
| Cancel-dispatch race | Cancel sets Skipped in DB; dispatch reads DB after permit | DB check after permit acquisition but before spawn. Worst case: task dispatches but reads Skipped from DB and exits early |
