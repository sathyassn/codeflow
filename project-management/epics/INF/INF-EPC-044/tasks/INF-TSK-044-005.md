## Description

Build three TUI features using the shared tui/ module from INF-TSK-044-004: (1) interactive session dashboard (`codeflow interactive status --watch`), (2) full onboarding wizard (`codeflow init`), and (3) welcome screen (`codeflow welcome`). All three are currently stubs or plain-text implementations.

The interactive session dashboard mirrors the autorun dashboard design but targets interactive sessions. The onboarding wizard replaces the Go implementation (wizard.go, now deleted) with a Rust ratatui version. The welcome screen provides a formatted project overview.

## Approach

1. **Interactive session TUI dashboard (interactive.rs)**
   - Add `--watch` flag to `codeflow interactive status` subcommand
   - Reuse shared tui/ module: data.rs for `fetch_session_views()`, theme.rs for styling, widgets for rendering
   - Layout: same 4-section pattern as autorun TUI (header, table, detail, keys)
   - Header: "CodeFlow Interactive Sessions" with Active/Stale/Complete counts
   - Table columns: session_id (truncated to first 16 chars), status badge, PF phase badge, branch, work_type, duration
   - Data sources: interactive_session DB table, pathflow-session-status.json for phase, worktrees.yaml for branch/worktree path
   - Detail pane: full session_id, worktree path, team name, PID with "(alive)" or "(dead)" indicator via `kill(pid, 0)`
   - Keyboard: Up/Down navigate, Enter attaches, `c` cleans up stale session, `q` quits
   - 2-second refresh interval

2. **Onboarding wizard (init.rs)**
   - Replace stub with full 7-step wizard
   - Reference spec: `project-management/epics/INF/INF-EPC-015/tasks/INF-TSK-015-009.md`
   - Layout: horizontal split -- left panel (30%) shows step progress list, right panel (70%) shows step content
   - Step progress: list widget with colored symbols -- checkmark (complete), circle-dot (current), circle (pending)
   - Each step is a separate function returning `StepResult` (Continue, Back, Quit)
   - Step 1 (Location): detect project directory state (empty dir = new, has .codeflow = existing, has .git = join)
   - Step 2 (Prerequisites): check `git --version`, `claude --version`. Display as checklist with pass/fail
   - Step 3 (Auth): selection widget -- subscription vs API key. Run `claude login` via Command::new
   - Step 4 (Git provider): selection widget -- GitHub/GitLab/Bitbucket. Install gh if needed, run `gh auth login`
   - Step 5 (Config): text input widget for project name and description
   - Step 6 (Setup): create .codeflow/, .state/, project-management/ dirs. Init SurrealDB. Show progress
   - Step 7 (Verify): run `codeflow doctor` checks. Display results as pass/fail checklist
   - CLI flags: `--existing`, `--join`, `--skip-auth`, `--yes`
   - Ctrl+C: register panic hook that cleans up partially-created directories
   - Non-TTY: detect `is_terminal()`, use sequential text prompts instead of TUI

3. **Welcome screen (welcome.rs)**
   - Replace stub with formatted display
   - Show: project name (from PROJECT.md or .codeflow config), version (from Cargo.toml), active sessions count, recent work summary
   - Use ratatui for bordered panel with styled text when TTY, plain text otherwise
   - Read from SurrealDB for active sessions and recent completed work

Error path: DB query failure returns `DbError`. Empty DB returns empty vec. Path traversal in session_id/worktree_path returns None for phase.

Keyboard: Up/Down wrap around, Enter checks tmux session existence before attach, c validates session is stale before cleanup. Data refresh on every tick; stale data kept on fetch error.

- `WizardState` struct holds all mutable wizard state, making the wizard a pure state machine
- Non-TTY and --yes both route to `run_non_interactive()` for predictable headless behavior
- Cleanup on cancel iterates `created_dirs` in reverse, only removing empty directories (safety)

## Notes

**Wizard testability:** Each wizard step should accept injectable dependencies (e.g., a `CommandRunner` trait for executing external commands like `git --version`, `claude --version`). This allows unit testing without actual command execution. The Go implementation used similar patterns.

**Session attachment:** For interactive sessions, "attach" depends on how the session was created. If created via `codeflow -i` (tmux mode), use `tmux attach-session`. If created without tmux, attachment may not be possible -- show a message instead.

**Welcome screen data:** The welcome command reads from SurrealDB which may not be initialized yet (first run). Handle gracefully: show "No CodeFlow project found. Run `codeflow init` to get started." when DB is absent.

**Wizard cleanup on Ctrl+C:** Register a handler via `ctrlc` crate or `tokio::signal::ctrl_c()` that removes partially-created directories listed in a cleanup stack built during steps 5-6. The handler must also restore the terminal from raw mode.
