# INF-TSK-013-001: Fix stale session cleanup in SessionStart hook

## Description

The SessionStart hook (`cf-session-start-init.sh`) currently detects stale team configs (teams whose members have dead tmux panes) and emits a WARNING to stderr, but takes no cleanup action. This leaves stale config files on disk, causing confusion at the next session start and breaking teammate name re-use (numbered suffix spawns).

This task upgrades Section 9 from advisory-only to active cleanup.

## Approach

1. Read stale detection loop in Section 9 of `cf-session-start-init.sh`
2. Write design analysis to `.codeflow/docs/analysis/stale-session-cleanup-design.md`
3. Modify Section 9: after detecting stale members, rewrite team config JSON removing dead entries
4. If all members are stale (or member count becomes 0 after cleanup), delete the config file
5. Retain advisory stderr warning after cleanup
6. Update `.claude/commands/cf-cleanup.md` to document when cleanup is automatic vs manual
7. Add/update tests in `.codeflow/testing/claude-hooks/session-start/`

## Files

### To Modify

- `.claude/hooks/codeflow/session-start/cf-session-start-init.sh` — upgrade Section 9 from warn-only to active cleanup
- `.claude/commands/cf-cleanup.md` — document auto-cleanup behavior

### To Create

- `.codeflow/docs/analysis/stale-session-cleanup-design.md` — design rationale and edge cases

## Acceptance Criteria

1. Section 9 of cf-session-start-init.sh removes stale member entries from team config JSON when their tmux pane is dead
2. If all members in a team config are stale, the entire team config file is deleted
3. Advisory warning still emitted to stderr after cleanup
4. Cleanup is idempotent: running on a clean team config (no dead panes) makes no changes
5. New tests in `.codeflow/testing/claude-hooks/session-start/` cover stale cleanup scenarios
