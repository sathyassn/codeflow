# INF-TSK-050-010: Hook correctness in worktree mode: scope_policy=hard enforcement + active-task path consolidation

> **MANDATORY VALIDATION:** Files created from this template MUST be validated against the task validation command before committing:
> `codeflow validate task <file-path>`
> Fix all errors (exit code 1) before requesting a commit. Warnings are advisory.

## Description

This task fixes three composite bugs that silently disable `scope_policy=hard` enforcement in interactive worktree sessions, plus adds regression-prevention infrastructure to prevent active-task.json path divergence from recurring.

**Bug 1A — file_scope hardcoded None in CLI write path (`state.rs:106`):**
`codeflow state set-active-task` hardcodes `file_scope: None` when writing `active-task.json`. The hook reads back an empty Vec, so `is_in_scope([])` returns `true` regardless of policy.

**Bug 1B — `is_in_scope([])` returns `true` in hard mode (`pre_tool_use.rs:518-520`):**
The scope check treats an empty scope list as "allow all" even under `scope_policy=hard`. This is correct for `permissive`, wrong for `hard` — the semantics should be "no files declared = reject all edits" for hard mode.

**Bug 1C — Coordination events never emitted (`ledger/routing.rs`):**
`acquire_claim()` and `acquire_claim_or_block()` use `eprintln!` for diagnostics but never call `ledger/routing.rs` to emit `ClaimAcquired`, `ClaimConflict`, or `ScopeExpansion` events to `coordination-events.jsonl`. The audit trail is silent even when blocking is correct.

**Block A — active-task.json path divergence (regression prevention):**
`WorktreePaths::runtime_dir()` (flat) vs legacy `runtime_local_dir()` produced different paths for active-task.json depending on binary version. The TUI (`data.rs:840`) also constructs its own path directly. Consolidating all reads/writes through `WorktreePaths::active_task()` plus a lint guard prevents the divergence from recurring.

### Pre-Work Analysis Context

> Why existing unit tests didn't catch this:
>
> The existing unit test `test_scope_policy_hard_blocks_out_of_scope` at `pre_tool_use.rs:5503` constructs an `ActiveTask` in-memory with `file_scope` set, bypassing the CLI write path. It passes. Production fails because `state.rs:106` hardcodes `file_scope: None` when the CLI subcommand writes active-task.json — so the hook reads back `Vec::new()`, `is_in_scope([])` returns `true` (line 518-520), and the hard branch routes to `acquire_claim()` (in-scope auto-acquire), never to `Block`. Additionally, neither `acquire_claim()` (lines 568-620) nor `acquire_claim_or_block()` (lines 625+) actually emit ledger events despite their doc comments — only stderr eprintln. End-to-end gap: existing tests don't traverse the CLI write path, so the gap is invisible to the unit test suite.

**Implementation Summary:**

Three composite bugs that silently disabled `scope_policy=hard` enforcement in interactive worktree sessions are now fixed, plus regression-prevention infrastructure for the active-task.json path-divergence bug class.
