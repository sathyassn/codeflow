## Description

Tier-C delivery from the EPC-050 follow-up audit
(`project-management/epics/INF/INF-EPC-050/analysis/2026-05-03-autorun-interactive-comprehensive-audit.md`,
section 4.1 through 4.7).

The audit surfaced 7 areas where the right choice is non-obvious and
requires design discussion before code changes. Each one ships as an
ADR (for architectural decisions with alternatives) or a design note
(for narrower technical questions). Each artifact MUST list a follow-up
implementation ticket ID (INF-TSK-050-006 through INF-TSK-050-012, or
similar) so a future implementer knows where to find the work.

This is a SPKE (spike) work_type -- design only, no code. Each ADR
captures the decision context now so it does not need to be
re-investigated later. The implementer ticket(s) are not in scope here.

## Approach

For each of the 7 artifacts, follow this template:

1. **Investigate** -- read the relevant module(s) to understand the current behavior. Use Grep + Read; do NOT make code changes.
2. **Generate options** -- at least 2 alternatives per question, with explicit pros/cons.
3. **Recommend** -- pick one with rationale.
4. **Identify follow-up ticket** -- assign a placeholder INF-TSK-050-006 through INF-TSK-050-012 ID (or similar). The follow-up ticket itself is created later; this just reserves the ID.
5. **Write the artifact** -- ADR template (Status / Context / Decision / Consequences) for ADRs; design note template (Problem / Options / Decision / Follow-up) for DESIGN-005/006/007.
6. **Cross-reference** -- each artifact links back to the audit doc.

Stage each ADR/note as its own commit (7 commits). cf-review can verify
each independently.
