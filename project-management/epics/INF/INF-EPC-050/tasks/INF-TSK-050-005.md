> Populated by cf-planning before STAGE-COMPLETE: WS-PLAN

**Implementation Summary:**

Authored 7 design records (4 ADRs + 3 design notes) covering the
deferred design questions documented in section 4 of the EPC-050
audit. Each record was anchored on the actual source-code state
(post PR #311 / #313 / #315) rather than the audit's snapshot, so
recommendations reflect current behavior. Key decisions:

- **ADR-001 (CI retry):** Keep the existing 30-minute / 30-second
  envelope; treat `Timeout` as a distinct verdict separate from
  `RequiredFailed` and `GhUnavailable(permanent)`. The audit's
  "treated as fatal" critique is already addressed by the
  `is_transient` classifier at `ci_wait.rs:402`. Implementation
  ticket adds `--ci-timeout-secs` CLI override + `ci_wait_summary`
  ledger event.
- **ADR-002 (integration branch resume):** Keep state on resume
  (option b), with a verify-and-recreate-if-missing fallback. Reset
  to `origin/{target}` would corrupt the DB-vs-git invariant by
  losing merged worker output.
- **ADR-003 (sync daemon supervision):** Orchestrator-as-supervisor
  with 30 s detection interval. Adds `SyncDaemonDied` /
  `Restarted` / `RestartFailed` events. Interactive-only sessions
  remain susceptible (documented limitation).
- **ADR-004 (reaper daemonization):** Add periodic reaper to the
  EXISTING sync daemon's main loop (60 s cadence). Avoids a third
  long-running process. Flock guards concurrent on-demand +
  periodic invocations.
- **DESIGN-005 (env file hardening):** Split `write_pid_env_file`
  into fail-loud (load-bearing call sites) and best-effort
  (cleanup). Add `verify_env_file_readable` post-write check. Hooks
  fail-closed on missing env file. New `EnvFileWriteFailed` /
  `EnvFileMissing` SessionError variants. Originally planned to
  reference INF-TSK-050-005 follow-up; instead the team lead filed
  INF-TSK-050-013 as a new task — DESIGN-005 references that ID.
- **DESIGN-006 (stage timeout cadence):** Keep 30 s default;
  promote to configurable `parallel-work-config.json:autorun.stage_timeout_poll_interval_secs`
  with [5, 300] s range and `poll*2 < timeout` invariant.
- **DESIGN-007 (periodic-task stop-signal):** Introduce
  `codeflow-cli/core/src/util/periodic.rs` with a `PeriodicTask`
  type that encapsulates the canonical `oneshot + select!`
  pattern. The signal-hook variant for long-running daemons stays
  separate (different primitive). Three template tests required
  per call site.
