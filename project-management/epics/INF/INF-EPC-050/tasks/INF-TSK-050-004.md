# INF-TSK-050-004: Tier-B Autorun Worker Robustness Fixes

> **MANDATORY VALIDATION:** Files created from this template MUST be validated against the task validation command before committing:
> `codeflow validate task <file-path>`

## Description

Tier-B delivery from the EPC-050 follow-up audit
(`project-management/epics/INF/INF-EPC-050/analysis/2026-05-03-autorun-interactive-comprehensive-audit.md`,
sections 3.1 through 3.5).

The autorun worker has five hidden failure modes that swallow errors
silently or report task success when the underlying operation failed.
Each is a `let _` or a fall-through path that masks a real problem from
both the operator (autorun status reports completed for a task that
never merged) and from the orchestrator (worker continues running after
a CREATE that should have failed it).

This task replaces each silent-failure path with the appropriate
escalation: SIGKILL on tmux failure, retry-with-backoff on claim release,
non-zero exit on protected-branch merge failure, hard failure on DB
CREATE failure, and a pre-`gh pr create` conflict check so we never
create a PR for a known-conflicting branch.

## Background / Context

See `project-management/epics/INF/INF-EPC-050/analysis/2026-05-03-autorun-interactive-comprehensive-audit.md`
sections 3.1 through 3.5 for per-bug root cause and citations.

This task depends on TSK-050-003 (Tier-A) merging first because:

- The chokepoint world established by TSK-050-003 is the basis for the
  worker's exit semantics (non-zero exit_code is what the chokepoint-
  driven status display uses to render Failed).
- The DB retry-with-backoff helper added by TSK-050-003 AC-12 is the
  same pattern used in AC-04 here for the pre-CREATE retry decision.
  Sequencing avoids two parallel patterns.

**Expected Outcome:** Operator never sees a worker reported as
"completed" when the underlying operation failed. tmux daemon crash no
longer leaves orphan claude processes. Claim contention no longer
leaves stale claims that block successor workers. Protected-branch hook
blocks (e.g., `gh pr merge` rejected by branch protection) cause the
task to fail visibly so the operator can intervene. DB transient errors
fail the worker fast rather than letting it run silently without a DB
row.

**Deployment:** PR merge to main on a `fix/inf-tsk-050-004-*` branch.
Validation: a manual test on a branch with intentional conflicts must
fail fast with `merge_conflict` status; a manual test killing the tmux
session out-of-band must result in the orphan claude process being
SIGKILL'd within seconds.

## Concurrency Considerations

| Shared Resource | Access Pattern | Safety Mechanism |
|----------------|---------------|-----------------|
| tmux daemon | external process; concurrent kill_session attempts possible | SIGKILL fallback is idempotent (kill -9 on dead PID = ESRCH = ignored) |
| `state.loro` (CRDT) for claims | read-modify-write under sync daemon contention | `locked_binary_rmw` (existing); retry layer added on top |
| SurrealDB | concurrent CREATE/UPDATE from parallel workers | TSK-050-003 AC-12 retry-with-backoff (reused in this task's AC-04 decision -- if CREATE fails after the existing retry layer, fail the worker) |
| `gh pr merge` GitHub API | external; rate limits and branch-protection checks | non-zero exit interpreted as failure; no automatic retry (operator action required) |

## Expected Outcome

User-observable, demonstrable verification of what shipping this ticket
gives the user.

1. **Orphan claude processes are killed when tmux dies.**
   - Verify: User runs an autorun batch. From another terminal: `tmux kill-session -t codeflow-autorun-{worker-sid}`. Within seconds, the underlying claude process is gone (verifiable with `ps aux | grep claude` -- no surviving worker process for that session).
2. **Workers do not silently lie about success.**
   - Verify: User runs a batch where merge to a protected branch is attempted (configure `target_branch: main` and trigger a hook block; or simulate via fault injection). After batch ends, `codeflow autorun status` shows `failed` for the worker (not `completed`). The worker's PR is left open with no auto-merge attempted.
3. **DB issues fail workers cleanly.**
   - Verify: With DB temporarily made read-only (e.g., `chmod -w .state/db/codeflow.db/`), `codeflow autorun run --batch <batch>` fails immediately with a clear error in the worker log. No hung "Running" status remains in `codeflow autorun status`.
4. **Claim release recovers from transient contention.**
   - Verify: With `coordination/state.loro` under heavy contention (e.g., sync daemon polling at 1s interval), worker shutdown does not leave stale claims. After worker exits, `cat .state/coordination/state.loro` (or equivalent inspection) shows the worker's claims are released.
5. **Pre-PR conflict check prevents wasted PR creation.**
   - Verify: User runs a batch where one task's branch will conflict with target. Worker fails fast with `merge_conflict` BEFORE `gh pr create` runs. No PR appears in `gh pr list` for that worker.
