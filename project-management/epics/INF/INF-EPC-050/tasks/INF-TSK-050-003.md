## Description

Tier-A delivery from the EPC-050 follow-up audit
(`project-management/epics/INF/INF-EPC-050/analysis/2026-05-03-autorun-interactive-comprehensive-audit.md`).

The audit identified 15 user-blocking correctness issues in the autorun
+ interactive status subsystems. The dominant root cause is that the
canonical `is_session_alive` chokepoint added in PR #311 was never
consumed by `codeflow autorun status` (text + TUI modes) or
`codeflow interactive status` (text mode). This task migrates those call
sites, deletes the dead heartbeat writer + reader, adds DB recovery
tooling (`codeflow doctor --reset-db`), fixes the final-PR gate, hardens
DB updates with retry/backoff, and adds a CI lint guard so the migration
stays migrated.

After this task ships, the user can: run autorun batches end-to-end on
a clean DB; trust `codeflow autorun status` and `codeflow interactive
status` to show real liveness; recover from schema deserialization
errors with one command; and never see a final PR for a batch with
merge_conflict workers.

## Concurrency Considerations

| Shared Resource | Access Pattern | Safety Mechanism |
|----------------|---------------|-----------------|
| `pathflow-session-status.json` | concurrent read by multiple TUI/CLI invocations; single write by SessionStart | atomic temp+rename in writer (already in place) |
| `state.loro` (CRDT) | concurrent read + read-modify-write by sync daemon and merge queue | `locked_binary_rmw` in `file_lock.rs` (existing) |
| `codeflow.db` (SurrealDB) | concurrent worker writes to `autorun_worker`/`autorun_task_run` | SurrealDB transactions + new retry-with-backoff (AC-12) |
| `.state/db/codeflow.db.backup-*` | new write target on `--reset-db` | `chrono::Utc::now()` ISO timestamp suffix prevents collision |

The merge queue stale-head detection (AC-10) must use the same
`locked_binary_rmw` pattern as the rest of the merge queue API to avoid
introducing a new race with the sync daemon.
