## Description

A comprehensive sweep addressing 23 confirmed correctness issues across the autorun and interactive status subsystems. Issues were surfaced across PRs #300, #302, #307 and post-merge audits. This task unifies fixes that were previously scattered across epics INF-EPC-047, INF-EPC-048, INF-EPC-049 to eliminate the root causes rather than treating symptoms.

The six issue layers addressed:

1. **Schema/lifecycle** — autorun session status enum canonicalization and state-machine enforcement
2. **Reaper/liveness** — stale detection must use PID liveness, not age thresholds; reaper must not kill live workers
3. **Display semantics** — TUI columns must show format_id not raw ULIDs; layout must not overlap for long names
4. **Autorun TUI** — freeze-on-terminal, [r]/[s] keybindings, IDLE/running semantics
5. **Interactive TUI** — heartbeat-based liveness, cleanup correctness, list pagination
6. **Hooks/cross-cutting** — permission prompt suppression in autorun, pathflow-events.jsonl per-worktree write path

## Pre-Work Analysis

Issues confirmed across post-merge audits of PRs #300, #302, #307 and INF-EPC-024 autorun reliability work:

- autorun session status can be set to arbitrary strings (no enum enforcement)
- TUI TASK column uses raw DB id (ULID) instead of format_id for autorun sessions
- Stale detection in stale.rs uses elapsed time, not PID liveness
- Reaper in autorun.rs kills any worktree older than threshold, including live ones
- Interactive heartbeat-based liveness implemented but not wired into cleanup
- [r]/[s] keybindings added to autorun TUI but freeze-on-terminal not propagated to all views
- pathflow-events.jsonl write target still uses shared symlink path in some code paths
- network.rs blocks autorun workers at permission prompts (AUTORUN_SESSION_ID check missing)
- Comprehensive unit test coverage missing for liveness, filter, and lifecycle behaviors; no integration test for live-monitor filter end-to-end

**Key catches caught and fixed during WS-DEV:**

1. **Wave 0 MockStore silent-drop bug:** `update_autorun_session*`
   silently dropped writes for post-Wave-0 fields (`final_pr_url`,
   `target_branch`, `current_task_*`, `updated_at`,
   `last_heartbeat_at`). Centralized in `apply_session_update`;
   adding a new field now needs ONE site, not three. Exposed by my
   Wave 1A `final_pr_url_single_task` test failing despite correct
   orchestrator code.
2. **Wave 0/2 schema TYPE mismatch:** `abort_started_at` was typed
   `option<datetime>` in Wave 0 schema but the Rust model writes
   RFC 3339 strings. SurrealDB SCHEMAFULL MERGE doesn't auto-coerce,
   so writes were silently dropped. Caught at Wave 2 test time when
   3 pre-existing `test_run_abort_*` tests failed; retyped to
   `option<string>` for parity with surrounding timestamp fields.
3. **Wave 1A reaper race:** the legacy `cleanup_stale_session` had
   a `Running`-only gate that prevented `Aborting` rows from being
   reconciled even when their abort had timed out. Removed the gate
   and split the function into idempotent reconcile + destructive
   resource cleanup.
4. **Wave 1A PID-reuse race:** the bare `kill -0` liveness probe
   would treat a recycled PID as alive, leaving sessions stuck in
   `Running` indefinitely. Wrapped `validate_claude_pid` in
   `is_session_pid_alive` with fail-secure invariants (cf-security
   flagged this as load-bearing).
5. **Wave 3 staged-edit iteration:** first cp-relay had test code
   using `codeflow_core::store::SurrealStore` (only resolves outside
   the crate) and `apply_schema()` (requires `DataStore` trait
   import). Second iteration matched the sibling test patterns in
   each file.

#### Wave 0 — Foundation (schema, models, types, config)

**Implementation Summary:**

Foundation layer for the wider AC sweep: introduces the abort-timeout
infrastructure, narrows the autorun-session status enum, and adds an explicit
`ids` filter for the autorun-session list query so future TUI fetches can
union "recent rows" with "still-on-screen rows" in a single round trip.

Key decisions:

- `Pending` removed from `AutorunSessionStatus`. The orchestrator writes
  `Running` at row creation, so no production path observed `Pending`. The
  variant only existed in tests and TUI special-cases, creating a misleading
  "queued" semantic. Removing it forces the type system to reflect actual
  behavior. Test fixtures that used `Pending` as an arbitrary placeholder
  were switched to `Cancelled` (terminal) or `Aborting` (non-terminal) per
  the test's intent.
- `abort_started_at: Option<datetime>` is additive and nullable, so the
  schema bump is fully backward-compatible: existing rows deserialize with
  `None` via `#[serde(default)]`. No migration needed.
- The `INSIDE` operator (`id INSIDE array::map($filter_ids, |$x|
  type::thing('autorun_session', $x))`) handles the RecordId vs string-key
  mismatch so callers continue passing plain string ids. `since` and `ids`
  OR-combine: a row matches if either gate accepts it; an empty
  `Some(vec![])` is treated as filter-inactive at both the surreal and mock
  layers (otherwise the WHERE clause would degenerate to `id INSIDE []`,
  matching nothing).
- `abort_timeout_secs` defaults to 300s with a 60s minimum (rejected by
  `validate_config`). Reusing the worker/stage timeout floor keeps
  configuration mental model consistent.
- Removing `Pending` exposed an unused wildcard arm in
  `status_badge_text` (clippy `match_wildcard_for_single_variants`); the
  arm was expanded to a named `Paused` arm to force a deliberate UI
  decision when future variants are added.

#### Wave 1A — Autorun Lifecycle (stale.rs + orchestrator.rs)

**Implementation Summary:**

Autorun reaper and orchestrator hardened to the new lifecycle: split
the cleanup pipeline into reconcile (DB-only, idempotent) +
resources (destructive, gated by five-veto liveness); extended
detection to `Aborting` rows past `abort_timeout_secs`; replaced the
bare PID liveness probe with name-verified `validate_claude_pid` to
close the PID-reuse race; added mid-run counter propagation, worker
`interactive_session` completion, `final_pr_url` population, and
end-of-batch auto-prune to the orchestrator. AC-05's orchestrator
side (abort marker cleanup on exit) is in; the CLI side
(`run_abort` idempotency) is reserved for Wave 2.

Key decisions:

- `cleanup_stale_session` is preserved as the public composite
  entry point: it now calls `reconcile_session_status` (DB-only) +
  `cleanup_session_resources` (destructive). External callers in
  `cli/cmd/autorun.rs` see no API change. The split lets the TUI
  call reconcile alone for fast DB-only state cleanup without
  triggering destructive worker resource teardown.
- `Aborting` → `Cancelled` mapping in reconcile (vs Running →
  Failed) captures user/orchestrator abort intent at the type level.
  The legacy code mapped everything to Failed, masking the
  distinction in the UI.
- `validate_claude_pid` is wrapped in `is_session_pid_alive` with
  fail-secure invariants: missing PID → false; out-of-range → false;
  alive but wrong name → false; lookup failed → false. Never returns
  true under uncertainty (cf-security flagged this as load-bearing).
  The internal `_with` variant accepts a custom validator so unit
  tests can exercise the hot path without spawning a real Claude
  Code process.
- `compute_abort_age_secs` prefers `abort_started_at`, falls back to
  `updated_at` for legacy rows. Returns `None` (defensive
  "not yet stuck") when no anchor exists — protects a freshly-
  aborting row whose timestamp hasn't landed yet.
- Mid-run counters: published only when changed since last write,
  CAS-guarded on Running so we never overwrite a terminal status
  set by the stale detector concurrently. Avoids 50ms write storms
  while keeping the TUI within ~50ms of truth.
- `final_pr_url` populated only on the unambiguous single-PR case;
  multi-PR and zero-PR batches leave the field None.
- Auto-prune is fire-and-forget via `tokio::spawn` so the
  orchestrator return is not blocked.
- `update_interactive_session` on the DataStore trait did not exist
  yet; rather than adding a generic update method I introduced the
  bulk-specific `complete_worker_interactive_sessions` method —
  matches the access pattern (one query per batch end) and avoids
  shipping a row-by-row update API the codebase doesn't need.
- MockStore's `update_autorun_session` was silently dropping writes
  for `final_pr_url`, `target_branch`, `current_task_*`,
  `updated_at`, `last_heartbeat_at` (all post-Wave-0 fields).
  Centralized the mutator in `apply_session_update` so adding a
  field needs one site, not three.

- **Filter overload, not signature change.** The brief allowed me to
  change `fetch_batch_list_*` signatures, but Dev1 was actively writing
  in the same crate; a signature change would break the build between
  my commit and the Wave 2 cli adoption. Adding `_filtered` variants is
  a Tier 1 reversible decision — the Wave 2 caller picks up the new
  variant and the older zero-arg wrappers can be deleted in a follow-up
  once no caller remains. Same trade-off applied to `fetch_batch_view`.
- **`format_task_cell` lives in core, not cli.** The original
  `format_task_cell` is in `cli/src/cmd/autorun.rs:4320`. Moving it
  unilaterally would have required touching a Wave-2-owned file;
  instead I added the new function (with the AC #8 signature change) in
  `tui/data.rs` and let Wave 2 swap the import in cli. The two functions
  share the same precedence rule so behavior is consistent during the
  transition window.
- **Em-dash everywhere.** AC #8 mandates a single Unicode character for
  the empty cell; `"—"` (U+2014) replaces the historical empty string
  / two-dash mix so the column never looks like padding.

#### Wave 2 — CLI Command Layer (cli/cmd/autorun.rs + cli/cmd/interactive.rs)

**Implementation Summary:**

Closes the user-facing surfaces: `run_abort` is now idempotent and
records the watchdog timestamp; the `codeflow autorun status --watch`
TUI gains a live-window filter with `[a]`/`[c]` keybindings + a
startup auto-reconcile pass; `codeflow interactive list/status`
filters out autorun-worker rows (`session_kind='autorun'`); cleanup
covers stale rows in addition to active ones; PID liveness in
interactive uses the name-verified `validate_claude_pid` for parity
with the autorun reaper.

Key decisions:

- `AutorunSessionUpdate.abort_started_at: Option<Option<String>>` —
  touch-or-not outer Option, value (or `None`-clear) inner. Mirrors
  the existing `tmux_session` / `stale_reason` pattern. Wired
  through Surreal `merge_fields!` and Mock `apply_session_update`.
- `run_abort` idempotency uses `compute_abort_age_secs` (Wave 1A) to
  decide between three branches:
  1. fresh `Aborting` (within `abort_timeout_secs`) → print "in
     progress for {sid} ({age}s ago)" and return Ok
  2. stuck `Aborting` (past `abort_timeout_secs`) → call
     `reconcile_session_status` to force-finalize, remove marker,
     return Ok with "force-finalized" suffix
  3. fresh abort (status=Running) → run the full SIGTERM/cancel/
     skip/finalize loop, write `abort_started_at` on the first
     transition, remove marker on clean completion
- Schema fix-up (caught at test time): `abort_started_at` was typed
  `option<datetime>` in Wave 0; SCHEMAFULL MERGE writes pass strings
  and SurrealDB doesn't auto-coerce, causing `run_abort` writes to
  fail silently. Changed to `option<string>` (RFC 3339), matching
  the surrounding timestamp fields.
- `LiveWindowFilter` is a 3-field POD shared via `tokio::sync::watch`
  so the background fetcher reads the current filter on every tick
  without restart. The fetcher branches between `fetch_batch_list_bulk`
  (show_all) and `fetch_batch_list_bulk_filtered` (live window).
- `[a]` toggles `show_all`. `[c]` re-snapshots `t0` and re-collects
  active session ids. Both publish to the watch channel and trigger
  an immediate refresh signal for instant feedback. Status-message
  toasts confirm the action took effect.
- Header indicator: `(showing all)` when show_all=true, `since HH:MM`
  when show_all=false. Empty-state hint differentiates "no batches
  exist" (show_all) from "no live batches; press [a] to see history"
  (filtered).
- TUI startup auto-reconcile bounded at 3s; on timeout/error, log
  warning and proceed silently. A toast surfaces the count when > 0
  reconciles fired, so the user sees "Reconciled N stuck batch(es)".
- `query_sessions` SQL adds `AND (session_kind = 'interactive' OR
  session_kind = NONE)` defensively. The schema's DEFAULT lands
  `'interactive'` for new rows; the OR-NONE branch handles any
  pre-migration rows whose column wasn't filled.
- `run_cleanup` extends from `Some("active")` to `query_sessions`
  for both active and stale; the inner action is status-aware:
  active rows promote to stale via dead-PID predicate; stale rows
  back-fill `completed_at` if missing (idempotent — `WHERE
  completed_at = NONE` skips already-finalized rows).
- `is_session_stale` switches from `is_process_alive` to
  `validate_claude_pid` for parity with the autorun reaper. This
  changes test semantics — the test runner is alive but not named
  "claude", so several existing tests had to be updated to expect
  the new "name-aware DEAD" outcome.
- `format_task_cell` (CLI-local copy) updated to take `total_tasks`
  and emit `"—"` when `total_tasks <= 0` — matches Dev2's
  `tui::data::format_task_cell`. Existing 8 tests updated; 3 new
  tests cover the em-dash branches (zero, negative, no-id).

**FINDING-01 (LOW path traversal) — CLOSED**

Added a positive-allowlist character validator before path construction in `run_abort` at `codeflow-cli/cli/src/cmd/autorun.rs:3600`:

```rust
#[must_use]
fn is_valid_session_id_for_path(s: &str) -> bool {
    if s.is_empty() {
        return false;
    }
    s.bytes()
        .all(|b| b.is_ascii_alphanumeric() || b == b'-' || b == b'_')
}
```

Called immediately before `runtime_dir.join(format!("abort-{session_id}"))`:

```rust
if !is_valid_session_id_for_path(&session_id) {
    anyhow::bail!(
        "invalid session_id format: '{session_id}' \
         (only alphanumeric, hyphen, and underscore characters allowed)"
    );
}
```

**Rationale (allowlist vs blocklist):** The cf-security finding suggested either a regex matching `ses-{alphanumeric}` OR a blocklist (`contains(['/', '\\', '.'])`). Chose a positive allowlist over a blocklist because (1) blocklists are bypass-prone — `contains(['/', '\\', '.'])` misses null bytes (`\0`), Unicode separators, control characters, NTFS alternate data stream colons (`:`), etc.; (2) the allowlist matches the actual production session_id format (`ses-{ULID}`) without coupling to the `ses-` prefix specifically; (3) `is_ascii_alphanumeric()` rejects all non-ASCII characters including UTF-8 separators. The allowlist is strictly tighter than the regex would be (also rejects `.` which is alphanumeric in regex `\w` but not in our format).

**Tests added:** 12 new unit tests covering the canonical accept case + 9 explicit rejection categories (empty, forward-slash, backslash, parent-directory dots, null byte, whitespace, control chars, non-ASCII Unicode, colon) + 1 end-to-end `run_abort` rejection test that asserts the path-escape is blocked at the entry point.

**Defense-in-depth gap noted (not exploited):** `cleanup_session_resources` in `autorun/stale.rs` also constructs paths from session_ids (`runtime_dir.join(format!("session-{session_id}"))` style). The session_ids reaching that function come from `list_autorun_sessions` returning DB rows already validated at write time, so there is no current vulnerability — but if a future caller passes user-supplied session_ids into `cleanup_session_resources`, the same guard would be needed. Captured as a follow-on note for the audit doc; not a finding for this task.
