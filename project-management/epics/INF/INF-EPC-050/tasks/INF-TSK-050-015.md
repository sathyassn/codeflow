# INF-TSK-050-015: Post-PR auto-save runtime gap fix

## Description

PR #287 (`fix/pathflow-dynamic-gates-cleanup`, merged 2026-04-12)
introduced the `pr_pushed` gate sentinel to suppress
`rescue_uncommitted_work` after a session has already pushed its PR.
The fix is source-level — a Claude session running an older CLI
binary (one that predates PR #287) does not check the gate and
still fires auto-save AFTER its own PR has merged, leaving stray
`wip: auto-save from crashed session ...` commits on the remote
branch. Observed live on 2026-04-12 against
`ses-01knzv7z4h44zarntkpfjqr4fw`; the orphan commit `97f5efb6` was
cleaned up manually.

The current gate ladder in
`codeflow-cli/core/src/worktree/cleanup.rs:295-440` (verified live)
already includes:

- 0a: not a git repo
- 0b: `no-rescue` marker
- 0c: `session_complete` gate sentinel
- 0d: `pr_pushed` gate sentinel (the PR #287 fix)
- 0e: legacy `pr_pushed` flag in `pathflow-session-status.json`
- 0f: ledger `pr_created` event
- 0g (Gate 8): `branch_on_origin` (zero commits ahead of `@{u}`)
- 0h (Gate 9): `gh pr list --head <branch>` fallback

The remaining gap: an old-binary session has none of the gates 0c,
0d, 0e, 0f, 0g, 0h available because either (a) the gate sentinels
do not exist (sentinel-write hooks predate the binary), (b) the
ledger/status flags were not written by the session's binary, or
(c) the `@{u}` upstream is unset because the PR's branch was
deleted from origin after merge.

The fix adds two strictly runtime-derived gates:

1. **Ref-walk gate (Gate 0i):** is HEAD already a commit on
   `refs/remotes/origin/{default-branch}`? If yes, every change
   has been merged regardless of what flags / sentinels say.
2. **`pr-merged` sentinel:** cf-knowledge-layer writes this
   sentinel during PF6-TSK-08 (`record-pr-outcome`) when the PR's
   `merged_at` is non-null. Read by `rescue_uncommitted_work` as
   a separate gate. New-binary sessions get this for free; old-
   binary sessions still rely on the ref-walk gate.

**Expected Outcome:** A session whose PR has already merged (whether
the binary detected the merge via the new sentinel or only via the
git ref state) does NOT write a rescue bundle when the worktree
shuts down. Old-binary sessions running against the new gate logic
in a future session's binary cannot reach this code, but
NEW-binary sessions on a worktree previously occupied by an old-
binary session will now see Gate 0i and skip rescue correctly.

**Deployment:** PR merge to main on `fix/inf-tsk-050-015-*`. Standard
autorun pipeline (WS-DEV → WS-SEC → WS-REV → WS-QA). The
`pr-merged` sentinel is a new file path under
`.state/session/{sid}/pathflow/`; cf-knowledge-layer writes it
during the existing `record-pr-outcome` operation, which means
the sentinel-write integration is a single-call addition.

## Approach

1. **Add `head_is_descendant_of_remote_main` helper** in
   `codeflow-cli/core/src/autorun/rescue.rs` that:
   - Resolves the default branch name via
     `git symbolic-ref refs/remotes/origin/HEAD` (parse the
     trailing branch name) with fallback to `"main"`.
   - Runs `git merge-base --is-ancestor HEAD refs/remotes/origin/<default>`.
     (WS-REV iter-1 Finding 5 corrected: original Approach text named
     `git rev-list --is-ancestor` which is not a valid git subcommand.)
   - Maps exit 0 → `BranchOriginStatus::OnOrigin`, exit 1 →
     `OffOrigin`, anything else (including ref missing) →
     `Inconclusive`.
2. **Insert Gate 0i in `rescue_uncommitted_work_with_reason`**
   immediately BEFORE the existing Gate 8 block:
   ```rust
   // Step 0i: ref-walk gate. If HEAD is a descendant of
   // refs/remotes/origin/{default-branch}, every change is
   // already merged — old-binary safety net for the case
   // where @{u} is unset because the branch was deleted post-merge.
   let on_remote_main =
       crate::autorun::rescue::head_is_descendant_of_remote_main(wt_path);
   if matches!(on_remote_main, crate::autorun::rescue::BranchOriginStatus::OnOrigin) {
       diagnostics::warn(
           "worktree",
           &format!("{session_hint}: skipping rescue — HEAD descended from origin/main"),
       );
       return Ok(());
   }
   ```
3. **Insert Gate 0d.5: pr-merged sentinel check**
   immediately AFTER the existing Gate 0d (`pr_pushed` gate), reading
   from `.state/session/{sid}/pathflow/pr-merged`:
   ```rust
   if gate_sentinel_present(wt_path, session_hint, "pr-merged") {
       diagnostics::warn(
           "worktree",
           &format!("{session_hint}: skipping rescue — pr-merged sentinel"),
       );
       return Ok(());
   }
   ```
4. **Add `pr-merged` sentinel writer** in
   `codeflow-cli/core/src/hooks/session_end.rs` (or wherever the
   record-pr-outcome flow lives — verify in pre-work). The writer
   is a single `atomic_write_file` call alongside the existing
   `pr_pushed` writer, gated on `pr.merged_at.is_some()`.
5. **Tests:** AC-04, AC-05 unit + integration tests as specified.

1. **Gate 0i — runtime-agnostic ref-walk** (cleanup.rs, before existing Gate 8): calls a new `crate::autorun::rescue::head_is_descendant_of_remote_main(wt_path)` helper that runs `git merge-base --is-ancestor HEAD refs/remotes/origin/<default>` to detect "HEAD is on origin/main but `@{u}` is unset because the branch was deleted post-merge". `Inconclusive` falls through so a missing ref or git-spawn failure cannot accidentally suppress legitimate rescue.

2. **Gate 0d.5 — `pr-merged` sentinel reader** (cleanup.rs, between Gate 0d `pr_pushed` and Gate 0e legacy-flag): reads `{wt_path}/.state/session/{sid}/pathflow/pr-merged` via a new `pr_merged_sentinel_present` helper. The session ID is path-sanitised against `[A-Za-z0-9_-]+` before joining (same defense-in-depth pattern as `session_pushed_pr`).

The helper crate-design decision: AC-02 mandated git plumbing — git2 was available as a dep but `git merge-base --is-ancestor` matches the existing pattern in `branch_on_origin` (subprocess git) so plumbing was chosen for consistency. The Approach §1 incorrectly named `git rev-list --is-ancestor`; `git rev-list` does NOT accept `--is-ancestor` (verified via `git rev-list --help`), the correct subcommand is `git merge-base --is-ancestor`.

A new `remote_default_branch_name` private helper resolves the default branch via `git symbolic-ref --quiet --short refs/remotes/origin/HEAD` with a `"main"` fallback per AC-02.

## Notes

The original memory note also mentioned an alternative
approach — "version the CLI binary and fail auto-save when binary
version < minimum-safe-version". This task explicitly rejects that
approach because (a) it requires every session start to validate
its own binary against a moving target, and (b) it crashes
intentional old-binary sessions which is too aggressive for a
fix that is fundamentally about preventing one specific stray
write.

The chosen design (ref-walk gate + sentinel) is purely defensive:
new-binary sessions get the sentinel; old-binary sessions get the
ref-walk gate when a future-binary session shuts down on the same
worktree path. Together they close the gap without breaking
backward compatibility.
