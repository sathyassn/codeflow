# INF-TSK-050-013: Implement DESIGN-005 env-file write hardening

> **MANDATORY VALIDATION:** Files created from this template MUST be validated against the task validation command before committing:
> `codeflow validate task <file-path>`
> Fix all errors (exit code 1) before requesting a commit. Warnings are advisory.

## Description

Implements the design recommended in
[DESIGN-005-env-file-hardening.md](../decisions/DESIGN-005-env-file-hardening.md).

Today, `write_pid_env_file` in `codeflow-cli/core/src/session/env.rs:139`
discards write errors with `let _ = ...`. This is correct for cleanup
contexts but wrong for SessionStart, where a failed env-file write
leaves the next hook invocation unable to resolve `CODEFLOW_SESSION_ID`
and `CODEFLOW_WORKTREE_PATH`. The failure surfaces several layers later
as a vague "file not found" or as wrong-session leakage.

The fix has three parts:

1. Split the writer into a fail-loud variant (load-bearing call sites
   propagate errors) and a best-effort variant (cleanup / migration
   sites continue to silently absorb errors).
2. Add a post-write readback (`verify_env_file_readable`) so a
   silent-success-but-empty-file failure mode is also caught.
3. Make hooks fail closed when the env file is missing for the active
   session, blocking the tool call with exit 2 instead of routing it
   to a stale or wrong session context.

## Deliverables

| Deliverable | Type | Location | Integration Point |
|-------------|------|----------|-------------------|
| `write_pid_env_file_required` (fail-loud) | new function | `codeflow-cli/core/src/session/env.rs` | Called from `session_start.rs` for active-session writes |
| `try_write_pid_env_file` (best-effort) | new function (renamed) | `codeflow-cli/core/src/session/env.rs` | Called from cleanup / migration paths |
| `verify_env_file_readable` | new function | `codeflow-cli/core/src/session/env.rs` | Called immediately after every load-bearing SessionStart write |
| `SessionError::EnvFileWriteFailed` + `EnvFileMissing` | new error variants | `codeflow-cli/core/src/session/mod.rs` | Surfaced through the existing `anyhow::Result` plumbing |
| Fail-closed hook behavior | modified | `codeflow-cli/core/src/hooks/pre_tool_use.rs` | Hook bus blocks tool call (exit 2) on missing env file |

**Expected Outcome:** A SessionStart that cannot write its env file
fails IMMEDIATELY at session start with a clear OS-error message
naming the path and the underlying error. A pre-tool-use hook fired
against a session with a missing env file blocks the tool call with
exit 2 and a structured stderr message, instead of routing the call
to whatever stale state remains in `.state/runtime/`.

**Deployment:** PR merge to main on `fix/inf-tsk-050-013-*`. Standard
autorun pipeline (WS-DEV → WS-SEC → WS-REV → WS-QA). No config changes

## Approach

1. **session/mod.rs** — add `EnvFileWriteFailed { path: PathBuf, reason: String }`
   and `EnvFileMissing { path: PathBuf }` to the `SessionError` enum.
   Implement `From<std::io::Error>` mapping for the write-path so
   callers can `?` the result naturally.
2. **session/env.rs** — rename current `write_pid_env_file` to
   `try_write_pid_env_file` (preserving signature `pub fn (..., ...) -> ()`).
   Add `pub fn write_pid_env_file_required(...) -> Result<PathBuf, SessionError>`
   that uses the same atomic tmp+rename pattern but returns the typed
   error on every failure mode (`fs::create_dir_all`, `File::create`,
   `write_all`, `sync_all`, `fs::rename`).
3. **session/env.rs** — add
   `pub fn verify_env_file_readable(state_dir: &Path) -> Result<EnvFile, SessionError>`
   wrapping `read_env_file` and mapping `Ok(None)` to `EnvFileMissing`.
4. **hooks/session_start.rs** — replace every load-bearing
   `write_pid_env_file(...)` call with `write_pid_env_file_required(...)?`
   and immediately follow with `verify_env_file_readable(...)?`. Cleanup
   / migration call sites switch to `try_write_pid_env_file`.
5. **hooks/pre_tool_use.rs** — locate the env-file lookup path used
   to resolve the active session's `CODEFLOW_SESSION_ID` /
   `CODEFLOW_WORKTREE_PATH`. When that lookup returns `Ok(None)` for
   the active session, return a `HookOutput::Block` with stderr message
   `EnvFileMissing: cannot resolve session env at {path}; refusing tool call`.
6. **Tests** — add unit tests in the inline `#[cfg(test)] mod tests`
   blocks of `env.rs` and `pre_tool_use.rs` per AC-06.

## Concurrency Considerations

| Shared Resource | Access Pattern | Safety Mechanism |
|----------------|---------------|-----------------|
| `.state/runtime/codeflow-env.sh` | atomic tmp+rename write | Existing pattern preserved; per-PID files give per-process isolation |
| `.state/runtime/shared/codeflow-env-{pid}.sh` | atomic tmp+rename write | Per-PID; no contention |

The env-file lookup in pre-tool-use is read-only; no locking needed.
The post-write `verify_env_file_readable` is a single read after rename,
which is atomic on the same filesystem; cross-filesystem races are
documented in DESIGN-005 as out-of-scope (network-FS edge case).

**Implementation Summary:**

DESIGN-005 env-file write hardening landed across 5 source files + 1 test fixture file + 1 task doc. The work has three load-bearing pieces:

1. **Writer split (AC-01)** in `codeflow-cli/core/src/session/env.rs`: added `write_pid_env_file_required(runtime_dir, pid, worktree_path) -> Result<PathBuf, SessionError>` using atomic tmp+rename with typed `SessionError::EnvFileWriteFailed { path, reason }` on every failure mode (`create_dir_all`, `File::create`, `write_all`, `sync_all`, `fs::rename`). Added `try_write_pid_env_file(runtime_dir, pid, worktree_path)` as the explicit best-effort variant. The bare `write_pid_env_file` is kept as a backward-compat alias delegating to `try_write_pid_env_file` so out-of-scope CLI callers in `cli/src/cmd/interactive.rs` and `cli/src/helpers.rs` continue to compile without an edit.

2. **Post-write verification (AC-03)** in env.rs: added `verify_env_file_readable(state_dir) -> Result<EnvFile, SessionError>` that maps `read_env_file == Ok(None)` to `SessionError::EnvFileMissing { path }`. Called immediately after every load-bearing `write_env_file_with_worktree` / `write_env_file` in `session_start.rs` (5 verification call sites added).

3. **Hook fail-closed (AC-05)** in `codeflow-cli/core/src/hooks/pre_tool_use.rs`: added `GateCheck::check_env_file_present()` method and wired it into `GateCheck::handle`'s `EditWrite` branch between the pf-3 sentinel check and `try_acquire_claim`. The check is dual-gated: it only fires when (a) `CODEFLOW_SESSION_ID` env var is set (marker of a real SessionStart, distinguishes from test fixtures) AND (b) an active task is present. On `current_env_file == Ok(None)` it emits stderr `EnvFileMissing: cannot resolve session env at {path}; refusing tool call` and returns `HookOutput::Block` (exit code 2) with `BlockCategory::Gate`.

Migration of the 5 production `write_pid_env_file` call sites in `session_start.rs`: for functions returning `Result<_, HookError>` (teammate-mode, create_session_worktree), call `_required` and propagate via `.map_err(|e| HookError::Config(e.to_string()))?`. For functions returning a tuple or `Option<_>` (handle_stale_cleanup, detect_precreated_worktree_inner), call `_required` and on Err emit `eprintln!` with structured `EnvFileWriteFailed` prefix + push `result.warnings` — the function contract can't carry the error but stderr/warnings remain observable.

The fail-loud `_required` writer uses atomic tmp+rename matching the existing `write_env_file` shape; no retries (DESIGN-005 §Numeric Tuning: ENOSPC/EACCES/EROFS are not transient, retrying adds latency without changing outcomes).

## Notes

DESIGN-005 explicitly recommends "no retry on write failure" — ENOSPC,
EACCES, and EROFS are not transient. Implementer should NOT add retry
logic; failing fast is the correct behavior.

The autorun batch executing this task should run with
`scope_policy=hard` to prevent accidental edits outside the listed
file_scope; the env writer pattern is shared infrastructure and any
out-of-scope edit risks introducing inconsistency between fail-loud and
fail-silent call sites.
