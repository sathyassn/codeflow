## Description

Follow-up to INF-EPC-048 (PR #300). Audit identified 9 distinct bugs across the autorun and interactive status TUIs. This task delivers all fixes in one PR.

PR #300 introduced the freeze-on-terminal elapsed pattern for the `codeflow autorun status` batches LIST view only. This task propagates the same pattern to every remaining time/duration display and resolves collateral layout, filtering, and UX bugs found during the audit.

### DEV Report

> Populated by cf-development before STAGE-COMPLETE: WS-DEV

**Implementation Summary:**

Propagates the freeze-on-terminal ELAPSED/DURATION pattern introduced in PR #300 to every remaining TUI surface, introduces a shared `freeze_on_terminal_secs` helper via a new `HasLifecycleTimestamps` trait implemented for both `AutorunSession` and `InteractiveSession`, adds a `session_kind` column with one-shot migration to separate autorun worker sessions from real interactive sessions, makes the stale-promotion write synchronous to eliminate the "00:01 blip", re-balances the autorun batches list column layout, preserves `current_task_id`/`current_task_format_id` on terminal rows with format-id preferred for display, and wires `[r]` force-refresh + `[last updated Ns ago]` age indicators on both TUI detail views plus `[s]` session-scoped toggle on the interactive list.

Key design choices:

- **Shared helper via trait**: `HasLifecycleTimestamps` trait lets the helper be entity-agnostic while keeping the live/frozen rule in one place (AC #7). Autorun's existing `status_driven_elapsed_secs` is now a thin wrapper. Interactive's inline block now also routes through the helper, passing a mutated clone for promoted-to-stale rows so the first render sees the frozen duration (AC #12).
- **session_kind default + migration**: Schema field defaults to `'interactive'` so existing rows are treated correctly without touching. Migration `UPDATE ... WHERE session_kind='interactive' AND session_id IN (SELECT VALUE record::id(id) FROM autorun_session)` runs inside `apply_schema` and is idempotent.
- **TASK column preservation**: Rather than plumbing `task_format_id` through every test fixture, the worker reads the format id directly from the task markdown at dispatch via a new `read_task_format_id` helper. The field is retained on task finish instead of being cleared.
- **BatchDetail `[r]` dual behaviour**: Kept backward compatibility by having `[r]` ALSO retry the selected task when failed/timeout, but ALWAYS additionally force-refresh. This preserves the existing retry UX while fulfilling the force-refresh requirement.

### DEV Report — Batch 2: Autorun Reliability

> Populated by cf-development before STAGE-COMPLETE: WS-DEV (batch 2).

**Implementation Summary:**

Batch 2 delivers the autorun reliability redesign motivated by the `codeflow autorun resume` failure on `inf-epc-024-phase1.yaml` (task 028 timed out exit 124 after ~50 min, work already pushed, rescue fired into the MAIN repo dirtying git status, task 035 skipped because 028 was marked failed). The fix reshapes rescue as an XDG-rooted cache subsystem, adds two gates that short-circuit when work is demonstrably safe, and reclassifies the "pushed but timed out" outcome as success-with-warning so dependents proceed.

Key design choices:

- **Rescue lives outside git** — `codeflow-cli/core/src/autorun/rescue.rs` is new. `xdg_rescue_root()` resolves via `dirs::cache_dir().join("codeflow").join("rescue")`; `derive_project_root` was renamed to `derive_main_repo_root` and now serves ONLY read-only gate-config/ledger lookups. `write_rescue_bundle` takes the bundle root as a parameter; callers pass `xdg_rescue_root()` so no rescue write ever targets a git working tree (AC #24, #26). An assertion in `test_rescue_writes_bundle_on_dirty_worktree` rejects bundle paths containing `.git-worktrees` to keep the contract load-bearing.
- **Single append-only sessions log** — `sessions_log_path() = {xdg_rescue_root}/sessions.jsonl`. No per-session fragment files under `.state/ledger/sessions/` (AC #25). Legacy fragments are appended into the host-wide log during migration.
- **Two new gates** — Gate 8 runs `git rev-list --count @{u}..HEAD`; OnOrigin (count=0) skips rescue, AheadOfOrigin continues, Inconclusive (no upstream, spawn failure) falls through to Gate 9. Gate 9 runs `gh pr list --head <branch> --state all --limit 1 --json number`, gated on `rescue.gh_pr_check` (default true); gh failure → Inconclusive, never skip on outage (AC #27, #28). A defensive branch-name sanitiser rejects anything outside `[A-Za-z0-9._/-]`.
- **Shared `branch_on_origin` helper (AC #40)** — three call sites use ONE implementation: (1) rescue Gate 8, (2) `classify_invoke_outcome` (W1), (3) serialized_merge fallback (W2). Returns a tri-state `BranchOriginStatus` so callers can distinguish "definitely on origin" from "cannot tell".
- **`codeflow rescue` subcommand reworked** — list/show/apply/drop/clean/pin/unpin all backed by xdg root. `apply --repo <path>` lets the user choose a target; `clean` is an alias for `drop`; `pin`/`unpin` toggle a `.pinned` marker; auto-prune and `clean --all` respect pin. Bundle IDs are validated against null byte, slash, `..`, backslash (AC #29).
- **Config placement** — added `RescueConfig { retention_days, gh_pr_check, banner_enabled }` to `ParallelWorkConfig` (alongside the existing `RetentionConfig`). Default retention = 30 days; NO hardcoded `30` constant in code paths (AC #30). `validate_config` rejects `retention_days < 1`.
- **Startup hooks** — `main.rs::rescue_startup_hooks()` runs `migrate_legacy(project_dir)` then `auto_prune(retention_days)` on every CLI invocation (AC #31, #33). Migration is marker-guarded and fail-safe: per-bundle failures abort without writing the marker so survivors get retried next run. Banner (AC #32) fires once-per-24h via `.last-scan` mtime touch; `autorun status`, `interactive status` both call `maybe_emit_rescue_banner()`; suppressed by `CODEFLOW_NO_RESCUE_BANNER=true`.
- **W1: exit 124 → completed-with-warning** — `classify_invoke_outcome(wt_path, exit_code, pr_number, auto_merge)` is a pure function tested for all three branches (exit 0 / exit 124 on-origin / exit 124 not-on-origin / other non-zero). Wrapper-level timeout (`Err(_)`) branch also consults `branch_on_origin`; if on-origin, returns `status="completed"` + warning. Adds `warning: Option<String>` to `WorkerResult` (with `Default`) (AC #34).
- **W2: serialized_merge fallback** — when `invoke_result.pr_number == 0` AND branch on origin AND `rescue.gh_pr_check`, `gh_pr_number_for_branch` runs `gh pr list --head <branch> --state open --limit 1 --json number`. Parses `[{"number": n}]` → `Some(n)`; any other shape → None (fail-safe, never fabricate) (AC #35).
- **W3: cascade-completion** — `spawn_worker` routes `status == "completed" || warning.is_some()` to the `completed` set. Two tests: direct-case (status=completed + warning=Some) and defensive-case (status=timeout + warning=Some) both let dependents proceed (AC #36).
- **W4: batch-launch flock** — `check_batch_guard` acquires an exclusive flock on `{project}/.state/autorun/batch-launch.lock` via `fs2::FileExt::try_lock_exclusive` (non-blocking first, falls back to blocking `lock_exclusive` with a user-visible "waiting for other launch" message). Entire lock dance runs in `tokio::task::spawn_blocking` so it doesn't park the runtime. Returns a `BatchLaunchGuard` that callers bind to `_batch_launch_guard` for the rest of `run_with_dir` / the resume path. Concurrent-launch test verifies the second task waits ≥ 150ms (AC #37).
- **W5: gh-pr-guard --base enforcement regression test** — added `autorun_missing_base_is_hard_block_w5_regression` to `gh_pr_guard` test module asserting Block output with both the expected autorun branch and "none" in the reason. Staged via protected-edit workflow (gh_pr_guard.rs is HIGH tier).
