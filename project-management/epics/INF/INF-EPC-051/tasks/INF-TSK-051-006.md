## Expected Outcome

1. **A bridged `agent()` runs one stage end-to-end and the anchor fires exactly once on finish** -- an operator running one bridged stage observes a single STAGE-FINISH anchor invocation at completion.
   - Verify: run one bridged stage (integration test); assert exactly one anchor call on stage finish.
2. **The claim acquire->release lifecycle is observable in `coordination-events.jsonl`** -- a stage acquires its claim at start and the claim is released by stage finish, both events emitted to the coordination event log.
   - Verify: run one bridged stage, then `grep -E "ClaimAcquired|ClaimReleased" .state/ledger/coordination-events.jsonl` (or the active worktree's `coordination-events.jsonl`) shows the acquire followed by the release for the stage.
3. **WorkGraph progress is recorded through cf-knowledge-layer, not via direct `.state/` writes** -- the stage row advances in WorkGraph and no direct `.state/` file write bypasses cf-knowledge-layer.
   - Verify: after the bridged stage, cf-knowledge-layer query shows the WorkGraph row updated; confirm the runtime routes the update through cf-knowledge-layer (no direct `.state/` write in the stage path).
4. **Git hand-off goes through cf-git-operations** -- any git action taken by the stage is performed by cf-git-operations.
   - Verify: confirm the stage's git hand-off is issued to cf-git-operations (no direct git write command in the runtime).

## Integration Requirements

1. **Bridge `agent()` invokes the T05 STAGE-FINISH LIFECYCLE ANCHOR exactly once on stage finish** -- the runtime calls the anchor defined by INF-TSK-051-005 at the stage-finish point, once per stage.
   - Verify: integration test asserts one anchor call per bridged stage; cross-check the anchor invocation point against the INF-TSK-051-005 contract.
2. **Claim is released on stage finish (the #1 claim-leak regression must not recur)** -- on every stage finish the anchor releases the claim, leaving no held claim after the stage completes.
   - Verify: run one bridged stage; assert a `ClaimReleased` event in `coordination-events.jsonl` after the `ClaimAcquired`, and assert no residual held claim for the stage's session/worktree.
3. **WorkGraph row is updated through cf-knowledge-layer for the bridged stage** -- the integration test confirms the stage's WorkGraph row advanced.
   - Verify: integration test queries cf-knowledge-layer and asserts the WorkGraph row for the stage was updated after the bridged run.
