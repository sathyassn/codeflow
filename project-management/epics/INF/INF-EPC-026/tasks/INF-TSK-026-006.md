# INF-TSK-026-006: PTY-Based Subprocess Output Capture

## Description

Implement cross-platform PTY (pseudo-terminal) allocation and real-time output capture for model CLI subprocesses. This layer sits below the T1 and T3 executors, providing rich terminal output that preserves ANSI colors, cursor movements, and other VT100 escape sequences -- essential for accurately capturing model CLI output that uses terminal formatting.

The implementation uses two crates from the wezterm ecosystem: `portable-pty` for cross-platform PTY allocation (openpty on macOS, /dev/ptmx on Linux) and `vte` for VT100/ANSI escape sequence parsing. Raw PTY bytes are read in a tokio-spawned task and parsed through the `vte` state machine into typed `PtyEvent` values, which are sent through a bounded `mpsc` channel for backpressure control.

This PTY infrastructure is shared with Epic E (CodeFlow App) -- the same `portable-pty` + `vte` pipeline feeds both CLI capture and the Tauri desktop app's xterm.js terminal rendering.

## Approach

1. Create `pty.rs` in `codeflow-rs/codeflow-core/src/orchestrator/`
2. Add `portable-pty` and `vte` crate dependencies to `codeflow-core/Cargo.toml`
3. Define `PtySize` struct: `cols: u16` (default 120), `rows: u16` (default 40)
4. Define `PtyEvent` enum:
   - `Text(String)` -- parsed text content (escape sequences stripped)
   - `ControlSequence(Vec<u8>)` -- raw control sequence bytes for consumers that need them
   - `Bell` -- terminal bell (\x07)
   - `Resize(u16, u16)` -- PTY resize event (cols, rows)
5. Define `PtyHandle` struct:
   - `child: Box<dyn portable_pty::Child + Send>` -- child process handle
   - `master: Box<dyn portable_pty::MasterPty + Send>` -- master PTY for resize/write
   - Methods: `kill()`, `resize(cols, rows)`, `write(data)`, `wait() -> ExitStatus`
6. Implement `VteEventHandler` struct implementing `vte::Perform`:
   - Collects text characters into a buffer
   - On escape sequence dispatch, flushes text buffer as `PtyEvent::Text` and emits `PtyEvent::ControlSequence`
   - On `\x07` (BEL), emits `PtyEvent::Bell`
   - Sends events through a `tokio::sync::mpsc::Sender<PtyEvent>`
7. Define `PtyCapture` struct (stateless builder):
   - `buffer_size: usize` -- mpsc channel buffer (default 1024)
8. Implement `PtyCapture::spawn`:
   - Create PTY pair via `portable_pty::native_pty_system().openpty(PtySize { rows, cols, ..})`
   - Build `CommandBuilder` with command, args, working directory
   - Spawn child process in the slave PTY
   - Create bounded `mpsc::channel<PtyEvent>(buffer_size)`
   - Spawn tokio task that:
     - Reads bytes from master PTY reader in a loop
     - Feeds bytes through `vte::Parser` with `VteEventHandler`
     - Handler sends `PtyEvent` values through the sender
     - Loop exits when reader returns EOF (child exited) or channel is closed
   - Return `(PtyHandle, Receiver<PtyEvent>)`
9. Add module to `orchestrator/mod.rs` re-exports
10. Write tests:
    - PTY creation succeeds on current platform
    - `echo "hello"` via PTY produces `PtyEvent::Text("hello\r\n")`
    - VT100 escape sequences are parsed into `PtyEvent::ControlSequence`
    - Bounded channel applies backpressure (sender blocks when receiver is slow)
    - `PtyHandle::kill()` terminates the child process
    - `PtyHandle::resize()` changes PTY dimensions
    - Integration test: spawn `ls --color=auto` and verify colored output produces both Text and ControlSequence events

## Notes

- This module is the shared PTY infrastructure between Epic D (CLI capture) and Epic E (desktop app terminal rendering)
- `portable-pty` abstracts platform differences: `openpty()` on macOS, `/dev/ptmx` on Linux
- `vte` is from the wezterm project -- battle-tested VT100/ANSI parser
- The bounded mpsc channel prevents memory exhaustion if the consumer (response normalizer) is slower than the PTY producer
- `PtyEvent::Text` contains text with escape sequences stripped; `PtyEvent::ControlSequence` preserves raw sequences for consumers that need them (e.g., xterm.js in Epic E)
- File descriptor cleanup is critical -- PTY master/slave FDs must be closed when PtyHandle is dropped
