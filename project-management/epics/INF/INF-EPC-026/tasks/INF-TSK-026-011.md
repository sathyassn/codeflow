# INF-TSK-026-011: Multi-Model Audit Log

## Description

Implement the audit logging subsystem for the Model Orchestration Layer. Every model routing decision, execution lifecycle event, and cost event is appended to a JSONL ledger file at `.state/ledger/orchestration-events.jsonl`. This provides a complete, immutable audit trail of all model orchestration activity -- which model was selected for which stage, how long it ran, whether it succeeded or failed, and how much it cost.

The audit logger follows the same patterns as the existing JSONL ledger system (Tier 0 in the three-tier data model): append-only, file-level flock for concurrent safety, and serde serialization for structured events. It implements the `LedgerWriter` trait from Epic 0.

## Approach

1. Create `audit.rs` in `codeflow-rs/codeflow-core/src/orchestrator/`
2. Define `AuditEventType` enum with 8 variants:
   - `ModelSelected` -- routing engine selected a model for a stage
   - `ExecutionStarted` -- model execution (T1 or T3) has started
   - `ExecutionCompleted` -- model execution finished successfully
   - `ExecutionFailed` -- model execution finished with error
   - `ExecutionTimeout` -- model execution timed out
   - `SessionSpawned` -- T3 tmux session created
   - `SessionTerminated` -- T3 tmux session terminated
   - `CostIncurred` -- cost event recorded after completion
3. Define `AuditEvent` struct:
   - `timestamp: DateTime<Utc>` -- when the event occurred
   - `event: AuditEventType` -- event type
   - `session_id: Option<ModelSessionId>` -- associated session
   - `task_id: Option<String>` -- associated task (if applicable)
   - `model: ModelId` -- which model
   - `stage: Option<WorkStage>` -- which work stage
   - `work_type: Option<String>` -- which work type
   - `details: serde_json::Value` -- event-specific details (exit_code, duration, cost, error message, etc.)
4. Define `AuditLogger` struct:
   - `log_path: PathBuf` -- path to the JSONL file
5. Implement `AuditLogger::new(state_dir: &Path) -> Self`:
   - Set `log_path` to `{state_dir}/ledger/orchestration-events.jsonl`
   - Create parent directories if needed
6. Implement `AuditLogger::log(&self, event: AuditEvent) -> Result<(), OrchestratorError>`:
   - Serialize event to JSON string via serde_json
   - Open file with append mode
   - Acquire file-level flock (advisory lock)
   - Write JSON line + newline
   - Release flock
7. Implement convenience methods for common events:
   - `log_model_selected(model, stage, work_type, reason: &str)` -- creates ModelSelected event
   - `log_execution_started(session_id, model, tier)` -- creates ExecutionStarted event
   - `log_execution_completed(session_id, model, exit_code, duration, tokens)` -- creates ExecutionCompleted
   - `log_execution_failed(session_id, model, error)` -- creates ExecutionFailed
   - `log_cost_incurred(session_id, model, cost, tokens)` -- creates CostIncurred
8. Implement `LedgerWriter` trait (if applicable from Epic 0):
   - `fn append(&self, event: impl Serialize) -> Result<()>`
9. Add module to `orchestrator/mod.rs` re-exports
10. Write tests:
    - Each event type serializes to valid JSON
    - Append-only: events accumulate, never overwrite
    - Concurrent append safety (two loggers writing simultaneously)
    - Insta snapshots for all 8 event types JSON format
    - File is created if it does not exist
    - Parent directory is created if needed

## Notes

- The orchestration-events.jsonl file follows the same Tier 0 pattern as existing .state/ledger/*.jsonl files
- The `details` field is a flexible serde_json::Value allowing event-specific data without rigid schema per event type
- Convenience methods reduce boilerplate at call sites -- the raw `log()` method is available for custom events
- flock ensures safe appends even when multiple codeflow processes (e.g., autorun workers) are orchestrating simultaneously
- This audit log is the "rebuild authority" for orchestration history -- if SurrealDB session records are lost, they can be reconstructed from the JSONL
