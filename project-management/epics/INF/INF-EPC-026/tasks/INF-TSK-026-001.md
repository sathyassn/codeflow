# INF-TSK-026-001: Orchestration Config Schema and Domain Types

## Description

Define the complete type foundation for the Model Orchestration Layer. This task establishes the orchestration config schema (parsed from `.codeflow/config/orchestration.toml`), all domain types used throughout Epic D, and the error enum covering all orchestrator error domains.

The config schema uses serde deserialization from TOML, defining how work stages map to model profiles. Domain types use Rust's type system extensively: newtype wrappers for type-safe identifiers (`ModelId`, `ModelSessionId`), enums for categorical values (`ApiType`, `ExecutionTier`, `WorkStage`), and tagged unions for execution results (`ExecutionStatus`). Error handling uses `thiserror` derive macros for a single `OrchestratorError` enum.

These types are consumed by every subsequent task in the epic and establish the Rust idioms used throughout the orchestrator module.

## Approach

1. Create the `orchestrator` module directory under `codeflow-rs/codeflow-core/src/` with `mod.rs` re-exporting public types
2. Define newtype wrappers in `types.rs`:
   - `ModelId(String)` -- wraps model identifier strings (e.g., "claude-sonnet", "codex-cli")
   - `ModelSessionId(String)` -- wraps `model-{ulid}` format identifiers, validated on construction via `TryFrom<String>` with regex check
   - Derive: `Display`, `FromStr`, `Serialize`, `Deserialize`, `PartialEq`, `Eq`, `Hash`, `Clone`, `Debug`
3. Define `ApiType` enum: `ClaudeSubagent`, `ExternalCli`, `LocalCli` with `serde(rename_all = "snake_case")`
4. Define `ExecutionTier` enum: `T1`, `T3` with `serde(rename_all = "snake_case")`
5. Define `WorkStage` enum: `WsDev`, `WsPlan`, `WsDocs`, `WsRev`, `WsQa`, `WsTest` with `serde(rename_all = "snake_case")`
6. Define `ModelProfile` struct:
   - `id: ModelId` -- unique profile identifier
   - `name: String` -- human-readable display name
   - `api_type: ApiType` -- how to invoke this model
   - `cli_command: Option<String>` -- CLI binary name (None for ClaudeSubagent)
   - `default_tier: ExecutionTier` -- default execution tier for this model
   - `max_tokens: Option<u64>` -- maximum context window
   - `timeout_seconds: u64` -- default timeout (serde default = 300)
   - `completion_pattern: Option<String>` -- regex for completion detection
   - `env_vars: HashMap<String, String>` -- environment variables to set
7. Define `StageRouting` struct:
   - `default_model: ModelId` -- model to use when no override matches
   - `work_type_overrides: HashMap<String, ModelId>` -- work_type -> model override
8. Define `OrchestrationConfig` struct (the top-level config):
   - `profiles: HashMap<ModelId, ModelProfile>` -- all model profiles
   - `routing: HashMap<WorkStage, StageRouting>` -- stage -> routing rules
   - `default_model: ModelId` -- global default when no stage routing matches
   - `max_concurrent_processes: usize` -- (serde default = 5)
   - `default_timeout_seconds: u64` -- (serde default = 300)
9. Define `ExecutionStatus` enum with variants:
   - `Pending` -- queued, not yet started
   - `Running` -- subprocess active
   - `Completed { exit_code: i32, duration: std::time::Duration }` -- finished successfully
   - `Failed { error: String }` -- finished with error
   - `Timeout { after: std::time::Duration }` -- killed due to timeout
   - `Killed` -- manually terminated
10. Define `ModelResponse` struct:
    - `session_id: ModelSessionId`
    - `model_id: ModelId`
    - `stdout: String`
    - `stderr: String`
    - `exit_code: Option<i32>`
    - `duration: std::time::Duration`
    - `tokens_used: Option<u64>`
    - `status: ExecutionStatus`
11. Define `OrchestratorError` enum in `errors.rs` via `thiserror::Error`:
    - `ConfigLoad { path: PathBuf, source: std::io::Error }` -- failed to read config file
    - `ConfigValidation { message: String }` -- config schema validation failed
    - `ModelNotFound { model_id: ModelId }` -- referenced model profile not in registry
    - `ExecutionFailed { model_id: ModelId, message: String }` -- model execution error
    - `Timeout { model_id: ModelId, after: std::time::Duration }` -- execution timed out
    - `ProcessSpawn { command: String, source: std::io::Error }` -- failed to spawn subprocess
    - `SessionNotFound { session_id: ModelSessionId }` -- tmux session not found
    - `RegistryError { message: String }` -- profile registry error
    - `PtyError { message: String }` -- PTY allocation or capture error
    - `BudgetExceeded { model_id: ModelId, budget: f64, cost: f64 }` -- cost exceeds budget
12. Implement `OrchestrationConfig::validate(&self) -> Result<(), OrchestratorError>`:
    - Check all model IDs referenced in routing exist in profiles
    - Check `default_model` exists in profiles
    - Check no `ClaudeSubagent` models are assigned `T1` tier (they use Agent tool, not subprocess)
    - Return `ConfigValidation` error with descriptive message on failure
13. Create default `orchestration.toml` with built-in profiles and example routing
14. Write proptest tests for newtype roundtrips (serialize -> deserialize identity)
15. Write insta snapshot tests for JSON serialization of all enums and config structures

## Notes

- Source: product-strategy.md Section 10 (D1 task) and decisions.md D21, D24
- Source: cf-model-orchestrator SKILL.md for T1/T3 model and session tracking patterns
- `WorkStage` enum mirrors the existing PathFlow work stages but is defined independently in the orchestrator module to avoid coupling with PathFlow internals
- `ModelSessionId` uses the same `model-{ulid}` naming convention from the archived cf-model-orchestrator skill
- `ApiType::ClaudeSubagent` is defined but T1 execution returns an error directing users to the Agent tool -- this type exists for config completeness and future extension
- The `env_vars` field on `ModelProfile` allows per-model environment variable injection (e.g., API keys, config paths)
- `completion_pattern` on `ModelProfile` is a regex string used by the response normalizer (Task 007) for custom completion detection
