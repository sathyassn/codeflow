# INF-TSK-026-008: Process Lifecycle Manager

## Description

Implement the `ProcessManager` -- a centralized tracker for all model CLI processes (both T1 subprocesses and T3 tmux sessions). The manager provides a unified view of what is running, enforces a maximum concurrent process limit, performs health checks, and automatically cleans up dead processes.

The manager uses `dashmap` for a concurrent HashMap that is safe for access from multiple async tasks without explicit locking. A background cleanup task runs on a 10-second interval to detect and remove processes that have exited without being explicitly terminated (e.g., a model CLI that crashes).

## Approach

1. Create `process.rs` in `codeflow-rs/codeflow-core/src/orchestrator/`
2. Add `dashmap` crate dependency to `codeflow-core/Cargo.toml`
3. Define `ProcessEntry` struct:
   - `model_id: ModelId` -- which model is running
   - `session_id: ModelSessionId` -- session identifier
   - `pid: u32` -- OS process ID
   - `started_at: Instant` -- when the process was spawned
   - `execution_tier: ExecutionTier` -- T1 or T3
   - `status: ProcessStatus` -- current status
4. Define `ProcessStatus` enum:
   - `Active` -- process is running
   - `Dead { exit_code: Option<i32> }` -- process has exited
   - `Killing` -- SIGTERM sent, waiting for exit
5. Define `ProcessManager` struct:
   - `processes: DashMap<ModelSessionId, ProcessEntry>` -- concurrent map
   - `max_concurrent: usize` -- max allowed processes (from config, default 5)
   - `cleanup_handle: Option<tokio::task::JoinHandle<()>>` -- background cleanup task
6. Implement `ProcessManager::new(max_concurrent: usize) -> Self`
7. Implement `ProcessManager::spawn(&self, model_id, pid, session_id, tier) -> Result<(), OrchestratorError>`:
   - Check `self.processes.len() < self.max_concurrent` -- if not, return `OrchestratorError::ExecutionFailed` with "max concurrent processes reached"
   - Insert `ProcessEntry` with `ProcessStatus::Active`
8. Implement `ProcessManager::kill(&self, session_id) -> Result<(), OrchestratorError>`:
   - Look up entry -- if not found, return `SessionNotFound`
   - Update status to `Killing`
   - Send SIGTERM via `libc::kill(pid, libc::SIGTERM)`
   - Wait 5 seconds with `tokio::time::sleep`
   - Check if still alive via `libc::kill(pid, 0)`
   - If still alive, send SIGKILL via `libc::kill(pid, libc::SIGKILL)`
   - Remove from map
9. Implement `ProcessManager::kill_all(&self)`:
   - Iterate all entries, kill each
10. Implement `ProcessManager::list(&self) -> Vec<ProcessEntry>`:
    - Clone all entries into a Vec
11. Implement `ProcessManager::health_check(&self, session_id) -> Result<bool, OrchestratorError>`:
    - Look up entry
    - Check `libc::kill(pid, 0)` -- returns 0 if alive, -1 if dead
    - If dead, update status to `Dead`
    - Return alive status
12. Implement `ProcessManager::start_cleanup_task(&self)`:
    - Spawn tokio task that runs every 10 seconds
    - For each entry, call `health_check`
    - Remove entries with `ProcessStatus::Dead`
    - Log removed entries via `tracing::debug`
13. Implement `Drop for ProcessManager`:
    - Cancel cleanup task if running
    - Call `kill_all()`
14. Add module to `orchestrator/mod.rs` re-exports
15. Write tests:
    - Spawn and list processes
    - Kill a specific process
    - kill_all terminates everything
    - Max concurrent limit enforcement
    - Health check detects dead process
    - Dead process cleanup removes entries
    - Concurrent access from multiple tasks (spawn from 3 tokio tasks simultaneously)

## Notes

- Uses `DashMap` instead of `Mutex<HashMap>` (as in TSK-005's `SessionRegistry`) because `ProcessManager` requires frequent concurrent reads from the background cleanup task and multiple async executor threads. `DashMap` provides lock-free reads and fine-grained write locks, reducing contention. `SessionRegistry` uses `Mutex` because T3 session operations are less frequent and `Mutex` provides simpler semantics for the poll/update pattern.
- `dashmap` provides a concurrent HashMap that is lock-free for reads and uses fine-grained locking for writes
- `libc::kill(pid, 0)` is a standard Unix way to check if a process is alive without sending a signal
- The background cleanup interval (10s) balances responsiveness with CPU overhead
- `Drop` on ProcessManager ensures all managed processes are terminated when the orchestrator shuts down
- The max concurrent limit (default 5) prevents resource exhaustion from too many simultaneous model CLIs
