# INF-TSK-026-005: T3 Persistent Session Executor

## Description

Implement the T3 (persistent session) execution tier for the Model Orchestration Layer. T3 sessions maintain a long-running tmux session where a model CLI stays active across multiple exchanges. This is used for complex, multi-turn tasks that require persistent context (e.g., a Codex session working on a feature with multiple files).

The T3 executor manages the full session lifecycle: spawning a detached tmux session with `model-{ulid}` naming, sending task prompts via `tmux send-keys`, polling output via `tmux capture-pane`, detecting completion via configurable markers, enforcing idle timeouts, and terminating sessions cleanly. A `SessionRegistry` tracks all active T3 sessions and the `Drop` trait ensures cleanup when the executor is dropped.

## Approach

1. Create `session.rs` in `codeflow-rs/codeflow-core/src/orchestrator/` for session state management
2. Define `SessionState` struct:
   - `session_id: ModelSessionId` -- tmux session name
   - `model_id: ModelId` -- which model is running
   - `profile: ModelProfile` -- full profile copy for reference
   - `working_dir: PathBuf` -- session working directory
   - `spawned_at: Instant` -- when the session was created
   - `last_activity: Instant` -- last output or input timestamp
   - `idle_timeout: Duration` -- max idle time before auto-terminate
   - `status: ExecutionStatus` -- current session status
3. Define `SessionRegistry` struct wrapping `HashMap<ModelSessionId, SessionState>`
   - `insert(session_id, state)` -- register a new session
   - `get(session_id) -> Option<&SessionState>` -- look up session
   - `get_mut(session_id) -> Option<&mut SessionState>` -- mutable lookup
   - `remove(session_id) -> Option<SessionState>` -- unregister session
   - `active_sessions() -> Vec<&SessionState>` -- list all non-terminated sessions
   - `stale_sessions(now: Instant) -> Vec<&ModelSessionId>` -- sessions past idle timeout
4. Define `T3Executor` struct:
   - `registry: Mutex<SessionRegistry>` -- thread-safe session tracking
5. Implement `ModelExecutor for T3Executor`:
   - The trait's `execute()` method for T3 delegates to `spawn_session` + `send_task` + `poll_until_complete`
   - This provides a high-level "run to completion" interface matching the T1 pattern
6. Implement `T3Executor::spawn_session`:
   - Generate `ModelSessionId` via `model-{ulid}`
   - Build tmux command: `tmux new-session -d -s {session_id} -c {working_dir}`
   - Send model CLI startup command: `tmux send-keys -t {session_id} '{cli_command}' Enter`
   - Create `SessionState` with `ExecutionStatus::Running`
   - Register in `SessionRegistry`
   - Return `ModelSessionId`
7. Implement `T3Executor::send_task`:
   - Validate session exists and is `Running`
   - Send prompt: `tmux send-keys -t {session_id} '{prompt}' Enter`
   - Update `last_activity` timestamp
8. Implement `T3Executor::poll_output`:
   - Capture pane: `tmux capture-pane -t {session_id} -p` (stdout)
   - Check for completion markers in output (using `profile.completion_pattern` regex)
   - Update `last_activity` if new output detected
   - Return `(output_text, is_complete: bool)`
9. Implement `T3Executor::terminate_session`:
   - Kill tmux session: `tmux kill-session -t {session_id}`
   - Update session status to `ExecutionStatus::Killed`
   - Remove from registry
10. Implement `T3Executor::health_check`:
    - Run `tmux has-session -t {session_id}` -- returns `true` if exit code 0
11. Implement `T3Executor::check_idle_timeouts`:
    - Iterate `registry.stale_sessions(Instant::now())`
    - Terminate each stale session
    - Return list of terminated session IDs
12. Implement `Drop for T3Executor`:
    - Iterate all sessions in registry
    - Call `terminate_session` for each
    - Log cleanup via `tracing::info`
13. Add module to `orchestrator/mod.rs` re-exports
14. Write tests:
    - Session lifecycle: spawn -> send -> poll -> terminate
    - Idle timeout detection and cleanup
    - Health check (session exists vs not)
    - Completion detection via marker pattern
    - Drop cleanup
    - Registry operations (insert, get, remove, active_sessions, stale_sessions)

## Notes

- tmux session naming convention `model-{ulid}` matches the archived cf-model-orchestrator skill pattern
- `poll_output` returns the full captured pane buffer -- incremental output detection is handled by comparing against previous poll results
- The `Mutex<SessionRegistry>` ensures thread-safe access from async contexts
- Tests should use a trait for tmux command execution to allow mocking without actual tmux
- The `idle_timeout` defaults to 300 seconds (from `ModelProfile.timeout_seconds`) but can be overridden per session
- `Drop` trait cleanup is best-effort -- if tmux kill-session fails, the error is logged but not propagated
