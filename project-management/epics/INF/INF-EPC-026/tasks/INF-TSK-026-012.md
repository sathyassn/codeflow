# INF-TSK-026-012: Cost Tracking and Subscription Configuration

## Description

Implement cost tracking and budget management for the Model Orchestration Layer. This enables teams to monitor and control AI model spending across work sessions. The system aggregates costs from completed model sessions, enforces per-model budgets with pre-execution checks, supports subscription model bypass (for models on unlimited plans), and provides automatic fallback routing when a model's budget is exceeded.

The subscription leverage pitch is central to CodeFlow's value proposition: "Stop burning API tokens. Use your existing model subscriptions more effectively with CodeFlow routing." Teams already paying for Claude Code ($20/dev/month) and Codex can route planning/review to Claude (reasoning quality) and routine code generation to Codex (throughput), using the same subscriptions with better cost/quality ratios.

## Approach

1. Create `cost.rs` in `codeflow-rs/codeflow-core/src/orchestrator/`
2. Define cost configuration in `OrchestrationConfig` (extend the config from Task 001):
   - `budget: Option<BudgetConfig>` -- optional budget configuration
3. Define `BudgetConfig` struct:
   - `monthly_limit: f64` -- total monthly budget in USD
   - `per_model_limits: HashMap<ModelId, f64>` -- per-model monthly limits
   - `alert_threshold: f64` -- percentage (0.0-1.0) at which to alert (default 0.8)
   - `prefer_subscription: bool` -- route to subscription models first (default true)
4. Define `CostRecord` struct:
   - `month: String` -- YYYY-MM format
   - `model_id: ModelId`
   - `cumulative_cost: f64`
   - `session_count: u32`
   - `total_tokens: u64`
5. Define `CostTracker` struct:
   - `session_store: Arc<ModelSessionStore>` -- reference to session store
   - `audit_logger: Arc<AuditLogger>` -- reference to audit logger
6. Implement `CostTracker::aggregate_costs(month: &str) -> Result<Vec<CostRecord>, OrchestratorError>`:
   - Query `ModelSessionStore` for all completed sessions in the given month
   - Group by `model_id`, sum `cost_estimate` and `tokens_used`
   - Return aggregated `CostRecord` per model
7. Implement `CostTracker::total_cost(month: &str) -> Result<f64, OrchestratorError>`:
   - Sum all model costs for the month
8. Define `BudgetManager` struct:
   - `config: BudgetConfig`
   - `cost_tracker: Arc<CostTracker>`
   - `registry: Arc<ModelProfileRegistry>`
   - `router: Arc<StageRouter>`
9. Implement `BudgetManager::check_budget(model_id, estimated_cost) -> Result<(), OrchestratorError>`:
   - If model is subscription (`prefer_subscription` and model has no per-token cost), return Ok (bypass)
   - Get current month's cumulative cost for this model
   - Check against `per_model_limits[model_id]` if set, else `monthly_limit`
   - If `cumulative + estimated > limit`, return `OrchestratorError::BudgetExceeded { model_id, budget, cost }`
   - If `cumulative + estimated > limit * alert_threshold`, log alert via AuditLogger
10. Implement `BudgetManager::suggest_fallback(stage, work_type, excluded_model) -> Option<ModelId>`:
    - Get all models configured for the stage via `registry.models_for_stage(stage)`
    - Exclude the over-budget model
    - Sort remaining by estimated cost (subscription first, then cheapest API-token models)
    - Return the first model that passes `check_budget`
11. Implement monthly budget tracking in SurrealDB:
    - Table: `model_budget` with fields: `month`, `model_id`, `cumulative_cost`, `session_count`, `total_tokens`
    - Upsert on cost incurred events
    - New month resets automatically (no cumulative carry-over)
12. Add module to `orchestrator/mod.rs` re-exports
13. Write tests:
    - Budget check passes when under limit
    - Budget check fails when over limit
    - Subscription model bypasses budget check
    - Fallback routing suggests cheapest alternative
    - Alert threshold triggers audit event with alert flag
    - Monthly reset: new month starts at zero
    - Aggregate costs across multiple sessions

## Notes

- Estimate differs from product-strategy.md (M -> S) because the core logic (budget check, fallback routing, alert threshold) is straightforward arithmetic over pre-aggregated cost records. The SurrealDB upsert and monthly partitioning are well-known patterns. The scope is narrower than initially estimated.
- Cost estimates are approximate -- actual API costs vary by provider and plan
- Subscription models have zero marginal cost per invocation (fixed monthly subscription)
- The `prefer_subscription` flag defaults to `true` because most CodeFlow users have model subscriptions
- `suggest_fallback` enables graceful degradation: if Codex API budget is exceeded, fall back to Ollama (free, local)
- Monthly budget tracking uses YYYY-MM format as the partition key -- no explicit reset action needed
- The `model_budget` SurrealDB table is separate from `active_work` to keep aggregation queries fast
- Budget configuration is optional (`budget: Option<BudgetConfig>`) -- when None, no budget enforcement is applied
- 'Cheapest alternative' sorting uses per-token cost for external models and zero marginal cost for subscription models (Claude Code with existing subscription). Subscription models are always preferred when available.
