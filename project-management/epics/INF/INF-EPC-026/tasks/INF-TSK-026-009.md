# INF-TSK-026-009: CLI Subcommands (orchestrate)

## Description

Implement the `codeflow orchestrate` CLI subcommand group, providing the user-facing interface for the Model Orchestration Layer. Four subcommands are defined: `exec` (run a model for a stage), `status` (list active sessions), `kill` (terminate sessions), and `config` (validate and display configuration).

All subcommands use clap derive macros for argument parsing and support a `--json` flag for machine-readable output. The `exec` subcommand is the primary entry point -- it loads the config, selects a model via the routing engine, spawns the executor, captures output, and returns results.

## Approach

1. Create `orchestrate/` directory under `codeflow-rs/codeflow-cli/src/commands/`
2. Create `mod.rs` defining the `Orchestrate` clap subcommand enum:
   ```rust
   #[derive(Subcommand)]
   pub enum OrchestrateCommand {
       Exec(ExecArgs),
       Status(StatusArgs),
       Kill(KillArgs),
       Config(ConfigArgs),
   }
   ```
3. Implement `exec.rs` with `ExecArgs`:
   - `--stage <STAGE>` (required) -- work stage (ws-dev, ws-plan, etc.)
   - `--work-type <TYPE>` (optional) -- work type for routing precedence
   - `--model <MODEL_ID>` (optional) -- explicit model override (bypasses router)
   - `--prompt <TEXT>` (optional) -- prompt text as string
   - `--prompt-file <PATH>` (optional) -- path to prompt file
   - `--tier <TIER>` (optional, default from profile) -- execution tier override (t1/t3)
   - `--timeout <SECONDS>` (optional) -- timeout override
   - `--json` (optional) -- JSON output format
   - Execution flow:
     a. Load and validate OrchestrationConfig
     b. Create ModelProfileRegistry
     c. If `--model` provided, look up directly; else use StageRouter.select_model()
     d. If prompt not provided via flags, read from stdin
     e. Determine execution tier: explicit `--tier` > profile default
     f. Create appropriate executor (T1Executor or T3Executor)
     g. Execute with prompt and options
     h. Output result (human-readable or JSON based on `--json` flag)
4. Implement `status.rs` with `StatusArgs`:
   - `--json` (optional) -- JSON output format
   - Execution flow:
     a. Query ProcessManager for active processes
     b. Format output as table (human) or JSON array
     c. Include: session_id, model_id, tier, pid, started_at (duration), status
5. Implement `kill.rs` with `KillArgs`:
   - `<session-id>` (positional, optional) -- specific session to kill
   - `--all` (optional) -- kill all active sessions
   - `--force` (optional) -- skip SIGTERM grace period, send SIGKILL immediately
   - Execution flow:
     a. If `--all`, call ProcessManager.kill_all()
     b. If `<session-id>`, call ProcessManager.kill(session_id)
     c. If `--force`, modify kill behavior to skip SIGTERM grace
     d. Print confirmation
6. Implement `config.rs` with `ConfigArgs`:
   - `--validate` (optional) -- run config validation and report errors/warnings
   - `--show` (optional) -- display the routing table with explain_selection for each stage
   - `--json` (optional) -- JSON output format
   - Execution flow:
     a. Load OrchestrationConfig
     b. If `--validate`: run validation, display results
     c. If `--show`: create StageRouter, iterate all stages, call explain_selection
7. Register `OrchestrateCommand` in the main CLI dispatch (`codeflow-cli/src/main.rs` or `commands/mod.rs`)
8. Write tests:
   - Argument parsing for each subcommand (valid and invalid args)
   - `--json` output format validation
   - `config --validate` with valid and invalid configs
   - Integration test: `exec --stage ws-dev --prompt "echo test" --model codex` with mock executor

## Notes

- CLI commands are thin dispatch layers -- all business logic is in `codeflow-core`
- The `--json` flag follows existing codeflow CLI patterns for machine-readable output
- `exec` reads stdin only when neither `--prompt` nor `--prompt-file` is provided
- `kill --force` is useful for CI/autorun contexts where the 5-second SIGTERM grace is unnecessary
- `config --show` uses `explain_selection` from the StageRouter to display routing decisions
