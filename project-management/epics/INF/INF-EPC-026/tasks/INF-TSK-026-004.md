# INF-TSK-026-004: T1 One-Shot Executor

## Description

Implement the T1 (one-shot) execution tier for the Model Orchestration Layer. T1 execution spawns a model CLI as a subprocess, sends the prompt via stdin or command-line argument, captures stdout/stderr, and returns a `ModelResponse` with exit code, duration, and captured output. This is the simpler of the two execution tiers -- no tmux, no persistent sessions, no multi-turn exchanges.

The executor uses `tokio::process::Command` for async subprocess management, providing non-blocking I/O and timeout enforcement. Timeout handling follows a graceful shutdown sequence: SIGTERM first, 5-second grace period, then SIGKILL if the process is still alive. This prevents zombie processes and ensures resource cleanup.

A `ModelExecutor` trait is defined as the common interface for both T1 and T3 executors, allowing the CLI command layer to work with either tier through a single abstraction.

## Approach

1. Create `executor.rs` in `codeflow-rs/codeflow-core/src/orchestrator/`
2. Define `ExecutionOptions` struct:
   - `timeout: Option<Duration>` -- override profile default timeout
   - `working_dir: PathBuf` -- working directory for subprocess (default: project root)
   - `extra_env: HashMap<String, String>` -- additional environment variables
   - `prompt_via_stdin: bool` -- whether to pass prompt via stdin (true) or as CLI argument (false)
3. Define `ModelExecutor` trait:
   ```rust
   #[async_trait]
   pub trait ModelExecutor: Send + Sync {
       async fn execute(
           &self,
           profile: &ModelProfile,
           prompt: &str,
           options: ExecutionOptions,
       ) -> Result<ModelResponse, OrchestratorError>;
   }
   ```
4. Define `T1Executor` struct (unit struct -- stateless):
   ```rust
   pub struct T1Executor;
   ```
5. Implement `ModelExecutor for T1Executor`:
   - Check `profile.api_type` -- if `ClaudeSubagent`, return `OrchestratorError::ExecutionFailed` with message "ClaudeSubagent models cannot be invoked as subprocesses. Use the Agent tool to delegate to Claude."
   - Generate `ModelSessionId` via `model-{ulid}` (one-shot still gets a session ID for tracking)
   - Build `tokio::process::Command`:
     - Command: `profile.cli_command.as_ref()` (unwrap or error if None)
     - Args: model-specific argument construction (e.g., codex uses `exec --full-auto`)
     - Env: merge `profile.env_vars` with `options.extra_env`
     - Working dir: `options.working_dir`
     - Stdin: piped (if `prompt_via_stdin`)
     - Stdout/stderr: piped
   - Spawn the child process
   - If `prompt_via_stdin`, write prompt to child stdin and close it
   - Determine timeout: `options.timeout.unwrap_or(Duration::from_secs(profile.timeout_seconds))`
   - Use `tokio::time::timeout()` to wait for child output
   - On timeout:
     - Send SIGTERM via `child.kill()` (on Unix, signal SIGTERM via nix crate or child.id() + libc::kill)
     - Wait 5 seconds with `tokio::time::sleep`
     - If still alive, force kill via `child.kill()`
     - Return `ModelResponse` with `ExecutionStatus::Timeout { after: timeout_duration }`
   - On success:
     - Capture stdout and stderr as strings
     - Capture exit code from `output.status.code()`
     - Record duration
     - Return `ModelResponse` with `ExecutionStatus::Completed { exit_code, duration }`
   - On error (spawn failure):
     - Return `OrchestratorError::ProcessSpawn { command, source }`
6. Add module to `orchestrator/mod.rs` re-exports
7. Write tests:
   - Mock command (`echo "hello"`) verifies stdout capture
   - Mock command (`sh -c 'echo error >&2'`) verifies stderr capture
   - Exit code capture (exit 0 vs exit 1)
   - Timeout test with `sleep 60` command and 1-second timeout
   - ClaudeSubagent rejection
   - Environment variable injection
   - Integration test: `echo` command through full T1 pipeline

## Notes

- T1 does NOT use tmux -- direct subprocess is simpler and more reliable for one-shot execution
- Deviates from product-strategy.md which specifies `std::process::Command`. `tokio::process::Command` is used instead because the orchestrator runs within an async Tokio runtime, and blocking `std::process` calls would require `spawn_blocking` wrappers. The functional behavior is identical -- direct subprocess, no tmux.
- The `#[async_trait]` crate is used for the trait definition since async fn in traits requires it
- `prompt_via_stdin` field in ExecutionOptions allows models that accept prompt via stdin (Codex) vs CLI argument (others)
- The timeout grace period (5s SIGTERM then SIGKILL) matches CodeFlow's existing process cleanup patterns
- `ModelSessionId` is generated even for T1 executions to provide a consistent tracking identifier for audit logs
