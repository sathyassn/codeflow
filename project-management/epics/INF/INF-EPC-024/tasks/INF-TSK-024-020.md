## Description

Create Rust CLI tooling that validates the JSONL-to-DB rebuild path. The three-tier data model guarantees that Tier 1 (SurrealDB via surrealkv:// embedded mode, per Decision D17) can be rebuilt from Tier 0 (JSONL), but currently there is no automated way to verify this guarantee. Schema-standardization.md Section 8 reveals that rebuild coverage ranges from 28% (tasks) to 71% (memory_events), with two tables having completely dead JSONL writers.

This tool reads JSONL ledger files, compares event field availability against DB schema expectations, and generates a per-table coverage report. It is the automated complement to the manual mapping document from INF-TSK-024-019.

In Rust, the validation errors use a `RebuildError` enum with thiserror for structured error reporting, and field mappings use a type-safe `FieldMapping` struct rather than runtime map lookups.

Uses shared types from INF-TSK-024-007: FieldName, EventType, SchemaError.

## Approach

1. Read the DB-to-JSONL rebuild mapping document (output of INF-TSK-024-019)
2. Read Rust ledger module at `codeflow-cli/core/src/ledger/` for event field definitions
3. Read Rust store module at `codeflow-cli/core/src/store/` for DB schema expectations
4. Create `codeflow-core/src/rebuild/` module with:
   - `FieldMapping` struct: `{ db_column: ColumnName, event_type: EventType, event_field: FieldName, field_type: FieldType }`
   - `RebuildValidator` struct with `validate()` method
   - `RebuildReport` struct: per-table coverage stats, missing fields, type mismatches
   - `RebuildError` enum with thiserror: `MissingField(FieldName, TableName)`, `TypeMismatch { field, expected, found }`, `DeadWriter(String)`, `ParseError(String)`
5. Implement `validate()` method that:
   - Reads JSONL files from `.state/ledger/`
   - Parses events and extracts field names per EventType variant
   - Compares against expected DB column mappings
   - Calculates coverage percentages
   - Detects dead writers (JSONL files with no recent entries)
6. Create `src/commands/rebuild.rs` with clap subcommand registration
7. Implement flags: --validate, --format json, --table
8. Write unit tests with tempdir for filesystem operations
9. Write insta snapshot tests for report output format
10. Run `cargo test`, `cargo clippy`, `cargo fmt --check`
