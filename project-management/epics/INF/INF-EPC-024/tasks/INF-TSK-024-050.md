# INF-TSK-024-050: Consolidate PID source for interactive_session.pid; eliminate dead lead_pid sources

> **MANDATORY VALIDATION:** Files created from this template MUST be validated against the task validation command before committing:
> `codeflow validate task <file-path>`

## Description

Fixes a structural source-of-truth bug where `codeflow interactive status` and `codeflow autorun status` display live sessions as "Stale". Root cause: `interactive_session.pid` DB column is populated from `std::process::id()` in the SessionStart hook subprocess (captures the hook subprocess PID — e.g. 12667, a dead shell), not the live Claude lead PID (e.g. 13015) which is already correctly held in `pathflow-session-status.json::lead_pid` via `parent_id()`.

PR #309 (INF-TSK-050-001) tightened liveness validation but did NOT fix the PID source. This task:

1. Fixes the DB column to use the correct PID source (`validate_claude_pid(parent_id())`)
2. Removes `session-pointer.json::lead_pid` — a dead duplicate field whose sole reader can be migrated to `pathflow-session-status.json::lead_pid`
3. Removes the redundant heartbeat write (lines 252–256 of session_start.rs) and the V5 `veto_heartbeat_fresh` liveness check — V4 (lead_pid file check) is sufficient
4. Populates `last_completed_phase` in `pathflow-session-status.json` from the checkpoint-complete handler (currently never set)
5. Adds cleanup retention logic to `codeflow interactive cleanup` (age-based row deletion)
6. Adds a regression-prevention lint guard to cf-rust-standards SKILL

> Populated by cf-development before STAGE-COMPLETE: WS-DEV

**Implementation Summary:**

Root cause fix for "live sessions display as Stale" in `codeflow interactive status` and `codeflow autorun status`. The DB column `interactive_session.pid` was populated from `i64::from(std::process::id())` in the SessionStart hook subprocess, capturing the short-lived hook PID rather than the live Claude lead PID. The TUI's `kill(0)` check then failed and tagged the row as Stale. PR #309 (INF-TSK-050-001) tightened the liveness check (`is_process_alive` -> `validate_claude_pid` with name verification) but did not change the PID source. This task fixes the source plus surrounding cleanup to keep the canonical chain `parent_id() -> validate_claude_pid -> pathflow-session-status.json::lead_pid -> liveness consumers` auditable.

Key design decisions:

1. **Single source of truth for lead PID**: All liveness consumers now read from `pathflow-session-status.json::lead_pid`. The duplicate `lead_pid` field in `session-pointer.json` was deleted from the struct, the writer signature, and downstream readers (`sync.rs::cleanup_dead_workers` was already migrated; this task migrates `interactive.rs::is_heartbeat_session_alive` and `session/mod.rs::is_live_worktree_session`).
2. **Liveness chain simplification**: V5 (`veto_heartbeat_fresh`) was removed from `is_session_alive`. V4 (lead_pid file check) is sufficient. The `.state/interactive/heartbeat-{SID}` file is still produced by the unmanaged-session SessionStart path (line 591) because `cli/src/cmd/interactive.rs` uses it as an FS-only discovery breadcrumb when the DB is unavailable; the liveness predicate no longer consults it.
3. **Per-row retention separated from autorun retention**: New `interactive.retention_days` config (default 30) so interactive rows can be pruned independently of autorun. `--prune-completed` ignores age and pruning tail.
4. **Lint guard**: New "Lint Guards" section in `cf-rust-standards/SKILL.md` enumerates the 6 allowed call sites for `validate_claude_pid` plus a grep one-liner so reviewers can mechanically detect new violations.
