# INF-TSK-024-024: Update cf-knowledge-layer agent definition with canonical schema reference

## Description

Update the cf-knowledge-layer agent definition (`.claude/agents/cf-knowledge-layer.md`) to reference the canonical event schema and enforce standardized field usage. The cf-knowledge-layer teammate is the primary agent that writes JSONL events (via the Rust `codeflow` CLI), manages the three-tier data model, and performs DB operations. After schema standardization, the agent definition must reflect the new canonical conventions to prevent regression through incorrect field usage in prompts and operations.

In the post-Epic 0 Rust codebase, many schema violations are caught at compile time (EventType enum exhaustive match, SessionId/WorktreeId newtypes). The agent definition update documents these type-level guarantees and references the Rust types that enforce them.

This is an additive update -- existing valid instructions are preserved, and new references to schema standardization deliverables are added.

## Approach

1. Read current `.claude/agents/cf-knowledge-layer.md` to understand existing structure and instructions
2. Read canonical event schema document (output of INF-TSK-024-007) for field specifications
3. Read DB rebuild mapping document (output of INF-TSK-024-019) for three-tier references
4. Identify sections that reference JSONL field names or event types
5. Add canonical schema reference in the References section
6. Update JSONL write operation instructions to mandate canonical field names, noting Rust type enforcement
7. Add deprecated field name mapping table
8. Update memory events section with canonical event types (MemoryEventType enum from task 009)
9. Update three-tier data model section with rebuild mapping reference and SurrealDB migration context (Decision D17)
10. Verify no existing valid instructions are removed
