# INF-TSK-024-043: Cross-worktree ledger aggregator

> **MANDATORY VALIDATION:** Files created from this template MUST be validated against the task validation command before committing:
> `codeflow validate task <file-path>`
> Fix all errors (exit code 1) before requesting a commit. Warnings are advisory.

## Description

Since PR #221, the JSONL ledger is LOCAL per-worktree (each worktree writes its events to `<worktree>/.state/ledger/`). This is correct for write-path isolation — it prevents concurrent writes between sessions — but it breaks the read path for any tool that expects a unified project-wide view: `codeflow report` queried from the main repo sees only main-repo events; worktree events are invisible until they are promoted via a future compaction cycle (INF-TSK-024-044).

This task introduces a streaming aggregator `aggregate_all_worktrees(project_dir, type_name)` that walks the main-repo ledger plus every active worktree's ledger (discovered via `.state/worktrees/worktrees.yaml`) and yields events in timestamp order via k-way merge. Deduplication handles the case where a future compaction-plus-promotion step (044) has already merged some events into the main ledger. The `codeflow report` command is updated to call the aggregator by default, with `--worktree <id>` and `--no-aggregate` flags for narrower scopes. Closes gap G4 from the 2026-04-22 chain audit.

**Deployment:** Compiled into the `codeflow` binary. No config changes.

## Approach

1. Create `codeflow-cli/core/src/ledger/aggregate.rs`.
2. Define types:
   - `pub enum AggregateError { RegistryRead(io::Error), SourceOpen { worktree_id: String, path: PathBuf, cause: io::Error }, ParseError { worktree_id: String, line: u64, cause: serde_json::Error }, TypeNotRegistered(String) }` with `thiserror::Error`.
3. Implementation of `aggregate_all_worktrees`:
   - Call `ledger::resolve_path(type_name, false)` for main-repo source (fails with `TypeNotRegistered` for unknown types).
   - Build the registry file path: `let registry_path = project_dir.join(".state/worktrees/worktrees.yaml");`. Call `worktree::registry::read_registry(&registry_path)` — the real signature at `worktree/registry.rs:107` is `pub fn read_registry(path: &Path) -> Result<WorktreeRegistry, WorktreeError>` and takes the registry FILE path, NOT the project_dir. On `Err`, emit WARN + continue with main-repo only; on `Ok(registry)`, iterate `registry.entries()` and filter by `status == Active` AND `entry.path.exists()`.
   - For each live source, open a `BufReader<File>` and wrap it in an iterator that yields `Result<Event, AggregateError>` line-by-line (parse JSON; on parse error, emit a `ParseError` item but continue the iterator).
   - Use `itertools::kmerge_by(iters, |a, b| timestamp_cmp(a, b))` to produce a merged stream.
   - Wrap the merged stream in a `dedup_by` adaptor that drops consecutive duplicates on `(timestamp, session_id, event_type)`.
   - Return as a `Box<dyn Iterator<Item = Result<Event, AggregateError>>>`.
4. Add `pub mod aggregate;` to `codeflow-cli/core/src/ledger/mod.rs`.
5. Refactor `codeflow-cli/cli/src/cmd/report.rs`:
   - Add clap flags: `#[arg(long)] worktree: Option<String>`, `#[arg(long)] no_aggregate: bool`.
   - If `no_aggregate`: read only main-repo via `resolve_path(type_name, false)`.
   - If `worktree=Some(id)`: read only that worktree's ledger; return error if unknown id.
   - Otherwise: call `aggregate_all_worktrees`.
6. Write unit tests in aggregate.rs using `tempfile::tempdir()` fixtures; mock `WorktreeEntry` via direct YAML writes or a test helper in `worktree::registry`.
7. Write the memory-profile test (criterion 12) with `RSS` bounded check — on platforms where RSS is unavailable, assert iterator advances without loading the whole stream.
8. Run the full test suite and lint passes.

## Concurrency Considerations

| Shared Resource | Access Pattern | Safety Mechanism |
|----------------|---------------|-----------------|
| `.state/worktrees/worktrees.yaml` | Read-only snapshot | One snapshot per aggregator call; no locking (worktree changes between snapshots are tolerated — next call picks up the update) |
| Per-worktree ledger base files | Read-only streaming | No locking required on readers; writers use advisory locks; aggregator is safe to run concurrently with ledger writes (will read whatever lines are flushed to disk) |
| Aggregator output iterator | Single consumer | Caller owns the iterator lifecycle; no internal sharing |

## Acceptance Criteria

1. New module codeflow-cli/core/src/ledger/aggregate.rs exposes pub fn aggregate_all_worktrees(project_dir: &Path, type_name: &str) -> Result<Box<dyn Iterator<Item = Result<Event, AggregateError>>>, AggregateError>
2. Aggregator enumerates event sources as: main-repo ledger dir + every WorktreeEntry with status=active from .state/worktrees/worktrees.yaml (read via worktree::registry::read_registry)
3. Events yielded in stable, non-decreasing timestamp order via merged k-way iteration (itertools::kmerge_by or equivalent) — no full-stream allocation; memory bounded regardless of total event count
4. Deduplication: the aggregator tracks the most recent (timestamp, session_id, event_type) triple seen on each yield; duplicates are dropped silently, but the count of drops is reported via a closure-accessible counter (for later observability)
5. Missing or unreadable registry is tolerated: aggregator falls back to main-repo-only with a stderr WARN naming the registry path
6. Pending-cleanup or stale worktrees (status != active, or worktree path no longer exists on disk) are skipped with a stderr WARN naming the worktree id
7. Empty worktree ledger (no base file for type_name) is a silent skip — not an error
8. AggregateError variants cover: RegistryRead(io::Error), SourceOpen { worktree_id, path, cause }, ParseError { worktree_id, line, cause }, TypeNotRegistered(String)
9. codeflow report CLI flag refactor: default behaviour calls aggregator across all worktrees; --worktree <id> scopes to one worktree; --no-aggregate (or --main-only) scopes to the main repo only
10. codeflow report --worktree <unknown-id> returns a user-friendly error naming the unknown worktree, not a silent empty result
11. Unit tests in aggregate.rs cover: (a) single-worktree sources emit all events in timestamp order; (b) two worktrees with unique events merge in timestamp order; (c) two worktrees with duplicate (ts, session, type) triples emit each unique triple exactly once; (d) missing registry falls back to main-repo-only with WARN; (e) worktree registry entry pointing to a non-existent directory is skipped with WARN; (f) empty ledger (type_name has no base file) returns empty iterator without error; (g) unknown type_name returns TypeNotRegistered; (h) events with equal timestamps are ordered deterministically by (session_id, event_type) as a tiebreaker
12. Integration test: create a tempdir with main-repo ledger and 2 worktree ledgers (registered in worktrees.yaml); run aggregator for pathflow-events; assert output contains all three sources' events in timestamp order
13. Memory profile test: aggregator operates in O(k) memory where k = number of sources (one BufReader per source), not O(n) in total events — verified via a large-ledger fixture (10k events per source) without RSS blowup
14. Per-file coverage >= 85% on codeflow-cli/core/src/ledger/aggregate.rs, codeflow-cli/core/src/worktree/registry.rs (only if registry read helpers are modified), and codeflow-cli/cli/src/cmd/report.rs

### Tests

- **Test files:**
  - Unit tests in `codeflow-cli/core/src/ledger/aggregate.rs` `#[cfg(test)] mod tests`
  - Integration tests in `codeflow-cli/core/tests/` or `codeflow-cli/cli/tests/`
  - Memory-profile test as a separate `#[test]` with a large fixture
- **Functional tests required:**
  1. Positive (single-worktree): fixture with main-repo events only → aggregator yields them in order.
  2. Positive (multi-worktree unique): main + 2 worktrees, each has distinct events → merged stream is timestamp-sorted and contains all events exactly once.
  3. Dedup: simulate post-promotion state where main-repo and worktree each contain the same `(ts, session, type)` triple → aggregator emits once.
  4. Negative (missing registry): no worktrees.yaml → aggregator falls back to main-only with a WARN.
  5. Negative (stale worktree path): registry entry points to a deleted directory → entry skipped with WARN, other entries included.
  6. Empty ledger: type_name has no base file in any source → returns an empty iterator, no error.
  7. Unknown type: call with `type_name="nonsense"` → returns `Err(TypeNotRegistered)`.
  8. Tiebreaker: two events with identical timestamps → output is stable across runs (pin ordering by `(session_id, event_type)` ascending).
  9. Memory: 10k events × 3 sources → iterator consumes O(k) memory, not O(30k); assert by running with a tight process RSS bound or by iterating halfway and confirming only the first half was buffered.
- **NOT acceptable:** Tests that allocate the full merged stream up front, mocks of `resolve_path`, or tests that skip the worktree registry read.

## Notes

- **Gap reference:** Closes G4 from `project-management/epics/INF/INF-EPC-024/audits/2026-04-22-chain-audit.md`.
- **Bounded memory is load-bearing:** Without streaming, aggregating a hot worktree with millions of events would OOM `codeflow report`. The k-way merge must hold only `k` readers (one per source) and one element per reader. This is the reason for the O(k) memory test.
- **Relationship to INF-TSK-024-044 (compaction):** Once 044 ships, the main-repo ledger will contain some events promoted from worktrees. The aggregator's dedup step handles this case; without dedup, a post-promotion reader would see each promoted event twice (once in main, once in the source worktree that hasn't yet cleaned up).
- **Tiebreaker determinism:** Criterion 11(h) requires stable ordering for equal timestamps. Without a tiebreaker, two consecutive runs of `codeflow report` could interleave events differently, which surprises users comparing output. Use `(session_id, event_type)` as ascending tiebreakers.
- **Observability counter:** Criterion 4 mentions a closure-accessible duplicate counter — this is for future `codeflow doctor --data-layer` (INF-TSK-024-021) which will want to report on post-promotion dedup activity. Exposing it now as part of an optional `&mut AggregateStats` parameter is acceptable; the minimum viable surface is the count.
- **CLI flag naming:** `--no-aggregate` is chosen over `--main-only` because it reads correctly alongside `--worktree <id>` as a mutual-exclusion set. clap `#[group]` can enforce the exclusion at parse time.
