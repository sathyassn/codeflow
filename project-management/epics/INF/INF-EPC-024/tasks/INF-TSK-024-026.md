# INF-TSK-024-026: Switch autorun orchestrator to read task metadata from DB

> **MANDATORY VALIDATION:** Files created from this template MUST be validated against the task validation command before committing:
> `codeflow validate task <file-path>`
> Fix all errors (exit code 1) before requesting a commit. Warnings are advisory.

## Description

Change the autorun orchestrator and batch modules to read task metadata (file_scope, scope_policy, dependencies, work_type, autorun_eligible) from the SurrealDB tasks table instead of parsing task markdown YAML frontmatter. This makes the DB the authoritative source for task metadata during autorun execution, aligning with the three-tier data model where Tier 1 (DB) is the query interface.

Currently, `dispatch_ready_tasks()` in `orchestrator.rs` and `read_task_scope()` in `batch.rs` parse markdown frontmatter to extract task fields. This is fragile (YAML parsing errors, file path resolution) and slow (filesystem reads per task). The DB already contains these fields from the cf-knowledge-layer sync pipeline.

Markdown parsing is retained as a fallback for tasks not yet synced to DB, with a warning log to surface the gap.
