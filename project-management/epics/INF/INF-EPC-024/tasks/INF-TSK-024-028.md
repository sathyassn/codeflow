# INF-TSK-024-028: Session ID consolidation: audit and fix UUID session ID usage in hook handlers

> **MANDATORY VALIDATION:** Files created from this template MUST be validated against the task validation command before committing:
> `codeflow validate task <file-path>`
> Fix all errors (exit code 1) before requesting a commit. Warnings are advisory.

## Description

Audit all Rust hook handlers to verify they use `codeflow-env.sh` CODEFLOW_SESSION_ID (via `session::current_session_id()`) rather than the Claude per-agent UUID from stdin for session identification. Fix any remaining instances.

The `current-session-id` file has already been eliminated as a write target. This task addresses the remaining UUID session ID bug where hook handlers may log or record the wrong session ID.

## Deliverables

| Deliverable | Type | Location | Integration Point |
|-------------|------|----------|-------------------|
| Session ID consolidation in hook handlers | refactor | `codeflow-cli/core/src/hooks/` (multiple files), `codeflow-cli/core/src/session/` | All hooks use consistent session ID; feeds downstream session isolation work (INF-TSK-024-037) |

**Expected Outcome:** All Rust hook handlers use `CODEFLOW_SESSION_ID` from `codeflow-env.sh` for session identification; `session::current_session_id()` is the single resolution function; no handlers use Claude per-agent UUID for session scoping.

**Deployment:** Rust crate change compiled into `codeflow` binary. No runtime migration required.

## Approach

1. Read `codeflow-cli/core/src/session/mod.rs` and `env.rs` to understand `current_session_id()` function
2. Audit each hook handler for session ID resolution:
   - `session_start.rs` -- how does it resolve session_id for logging and event recording?
   - `pre_tool_use.rs` -- team_guard uses session_id for what?
   - `post_tool_use.rs` -- logging uses session_id?
   - `session_end.rs` -- cleanup references session_id how?
   - `task_completed.rs` -- session_id for checkpoint operations?
   - `prompt_validate.rs` -- session_id for validation?
   - `logging/mod.rs` -- session_id in log entries?
3. For each handler, document: source of session_id (stdin, env, codeflow-env.sh), usage (logging, file ops, events), correctness
4. Fix any handlers using stdin UUID where they should use CODEFLOW_SESSION_ID
5. Ensure `session::current_session_id()` is the single resolution point
6. Write unit tests for session_id resolution

## Concurrency Considerations

- **Shared resource:** `codeflow-env.sh` at `.state/runtime/codeflow-env.sh` -- read by all hooks
- **Access pattern:** Read-only after SessionStart writes it. Session_id is immutable for the session lifetime.
- **Safety mechanism:** `codeflow-env.sh` is written once at SessionStart and read by all subsequent hooks. No concurrent write risk.
- **Worktree impact:** In worktree mode, `codeflow-env.sh` is per-worktree (`.state/runtime/` is local, not symlinked). Each worktree has its own session ID.
