# INF-TSK-024-007: Define canonical event schema: required fields, field naming conventions

## Description

Synthesize all six audit outputs (tasks 001-006) into a single normative canonical event schema document. This is the KEY DELIVERABLE of Phase D -- it defines the Rust types, field naming conventions, required fields, and deprecated field mappings that all enforcement tasks (008-015) implement against.

The schema defines shared Rust types: `CanonicalEvent` struct with universal fields, `EventType(String)` and `FieldName(String)` newtypes, `SchemaError` enum with thiserror, and `ValidationResult` struct. All downstream code tasks reference these types.

## Approach

1. Read all six audit documents (outputs of 001-006)
2. Read schema-standardization.md Section 6 (Canonical Event Schema) and Section 9 (Inconsistencies Summary)
3. Define universal required fields with Rust types: `timestamp: DateTime<Utc>`, `event: EventType`, `session_id: SessionId`, `worktree: WorktreeId`
4. Define per-event-type required fields for all canonical event types
5. Create deprecated field mapping table with `FieldMapping { deprecated: FieldName, canonical: FieldName, found_in: Vec<String> }`
6. Define `SchemaError` enum with thiserror derive
7. Define `CanonicalEvent` struct and `ValidationResult` struct
8. Specify the `details` object pattern for variable event-specific fields
9. Write the canonical schema document
