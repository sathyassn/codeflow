# INF-TSK-024-002: Ledger audit: work-graph.jsonl schema documentation and gap analysis

## Description

Document the current work-graph.jsonl schema across all event types, with special focus on the dual-ID coexistence bug where `id` sometimes holds a ULID and sometimes a format_id. The work-graph file is the most complex ledger file with 8+ event types covering epic lifecycle, task lifecycle, work sessions, and PR events.

Schema-standardization.md Section 8 reveals the `tasks` table has only 28% field coverage from JSONL -- 23 fields have no JSONL representation. This audit documents exactly which fields are present, which are missing, and how they should map to Rust types in `codeflow-core/src/ledger/work_graph.rs`.

## Approach

1. Read schema-standardization.md Section 1.2 (work-graph.jsonl audit) and Section 8.2 (tasks table mapping)
2. Read existing `.state/ledger/work-graph.jsonl` entries to verify field presence per event type
3. Document each event type with complete field inventory
4. Catalog the dual-ID bug: specific entries where `id` holds format_id vs ULID
5. Map current fields to Rust newtypes: `TaskId(Ulid)`, `EpicId(Ulid)`, `FormatId(String)`
6. Document the 23 missing fields for the tasks table rebuild gap
7. Write the audit document
