## Description

Document the current work-graph.jsonl schema across all event types, with special focus on the dual-ID coexistence bug where `id` sometimes holds a ULID and sometimes a format_id. The work-graph file is the most complex ledger file with 8+ event types covering epic lifecycle, task lifecycle, work sessions, and PR events.

The workgraph module at `codeflow-cli/core/src/workgraph/` provides the target data model. This audit documents exactly which fields are present in JSONL, which are missing, and how they map to Rust types.

## Approach

1. Read schema-standardization.md Section 1.2 (work-graph.jsonl audit) and Section 8.2 (tasks table mapping)
2. Read existing `.state/ledger/work-graph/work-graph.jsonl` (base) and session fragments to verify field presence per event type (note: subdirectory layout per PR #221; run `codeflow ledger migrate` if still flat)
3. Read `codeflow-cli/core/src/workgraph/task.rs` and `epic.rs` for current Rust field definitions
4. Read `codeflow-cli/core/src/types/ids.rs` for existing ID newtypes
5. Document each event type with complete field inventory
6. Catalog the dual-ID bug: specific entries where `id` holds format_id vs ULID
7. Map current fields to Rust types already defined in the workgraph module
8. Document fields present in `workgraph/task.rs` but missing from JSONL
9. Write the audit document
