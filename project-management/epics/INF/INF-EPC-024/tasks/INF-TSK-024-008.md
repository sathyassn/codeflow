## Description

Fix the dual-ID bug where the `id` field in work-graph.jsonl sometimes holds a ULID and sometimes a format_id. Enforce that `id` always contains a ULID and `format_id` always contains the human-readable format. This requires changes to the ledger writer and/or workgraph module where events are constructed.

## Approach

1. Read audit document from task 002 and canonical schema from task 007
2. Read `codeflow-cli/core/src/ledger/jsonl.rs` to understand LedgerWriter
3. Read `codeflow-cli/core/src/workgraph/task.rs` and `format_id.rs` to understand ID handling
4. Identify where work-graph events are constructed (likely in workgraph module)
5. Add validation to ensure id field contains ULID, not format_id
6. Add normalization for reading legacy entries with swapped fields
7. Add error types for dual-ID conflicts
8. Write unit tests

## Concurrency Considerations

- **Shared resource:** `.state/ledger/work-graph/work-graph.jsonl` (base) and session fragments -- written by LedgerWriter (subdirectory layout per PR #221)
- **Access pattern:** Append-only JSONL writes to session-scoped fragment files via file lock in `jsonl.rs`
- **Safety mechanism:** `LedgerWriter` uses file locking for concurrent append safety. The dual-ID fix adds validation before write, which runs within the same lock scope.
- **Worktree impact:** Ledger is LOCAL per-worktree (not symlinked). Each worktree has its own `.state/ledger/` directory. Cross-worktree isolation is achieved by separate file copies, not shared state. (Updated per PR #221 -- ledger moved from SHARED_STATE_DIRS to LOCAL_STATE_DIRS.)
