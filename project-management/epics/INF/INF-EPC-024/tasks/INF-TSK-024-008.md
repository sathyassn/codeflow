# INF-TSK-024-008: Fix dual-ID coexistence in work-graph.jsonl writer

> **MANDATORY VALIDATION:** Files created from this template MUST be validated against the task validation command before committing:
> `codeflow validate task <file-path>`
> Fix all errors (exit code 1) before requesting a commit. Warnings are advisory.

## Description

Fix the dual-ID bug where the `id` field in work-graph.jsonl sometimes holds a ULID and sometimes a format_id. Enforce that `id` always contains a ULID and `format_id` always contains the human-readable format. This requires changes to the ledger writer and/or workgraph module where events are constructed.

> **MANDATORY:** Every task must specify what is being delivered, where it integrates, and the expected outcome. Vague deliverables like "update code" are insufficient.

| Deliverable | Type | Location | Integration Point |
|-------------|------|----------|-------------------|
| Dual-ID enforcement in ledger writer | fix | `codeflow-cli/core/src/ledger/jsonl.rs` | LedgerWriter validates id=ULID before append |
| Legacy normalization for swapped IDs | fix | `codeflow-cli/core/src/workgraph/task.rs`, `epic.rs` | Read path normalizes old entries transparently |
| Unit tests for ID validation | test | `codeflow-cli/core/src/ledger/`, `workgraph/` | cargo test coverage enforcement |

**Expected Outcome:** All new work-graph.jsonl events have `id` containing a ULID and `format_id` containing the human-readable ID. Legacy entries with swapped fields are normalized on read. Schema validation rejects malformed events.
**Deployment:** PR merge; no migration script needed — normalization is read-time.
