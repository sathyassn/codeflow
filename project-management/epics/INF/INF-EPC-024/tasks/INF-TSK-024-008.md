# INF-TSK-024-008: Fix dual-ID coexistence in work-graph.jsonl writer

## Description

Fix the dual-ID coexistence bug in the work-graph.jsonl writer. Currently, the `id` field sometimes holds a ULID and sometimes a format_id (e.g., `INF-TSK-024-001`), and `task_id` is similarly inconsistent. After this fix, the Rust writer at `codeflow-core/src/ledger/writer.rs` enforces: `id` always contains a ULID (via `TaskId(Ulid)` or `EpicId(Ulid)` newtypes), and `format_id` always contains the human-readable format.

Uses shared types from INF-TSK-024-007: CanonicalEvent, SchemaError, FieldName, EventType.

## Approach

1. Read canonical event schema (output of INF-TSK-024-007) for field specifications
2. Read work-graph audit (output of INF-TSK-024-002) for dual-ID bug details
3. Update `schema.rs` validation to reject events where `id` matches format_id pattern
4. Update `writer.rs` to enforce `TaskId(Ulid)` and `EpicId(Ulid)` newtypes in serialization
5. Update `normalize.rs` to detect and swap legacy entries with incorrect field placement
6. Add backward-compatible deserialization via `serde(deserialize_with = ...)`
7. Write unit tests for valid, swapped, and missing ID scenarios
8. Write insta snapshot tests for JSON output verification
9. Run `cargo test`, `cargo clippy`, `cargo fmt --check`
