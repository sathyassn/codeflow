# INF-TSK-024-001: Ledger audit: sessions.jsonl schema documentation and gap analysis

## Description

Document the current sessions.jsonl schema across both shell-era and Go-era entries, identifying field naming inconsistencies (ts vs timestamp, event_type vs event), missing universal fields (session_id, worktree), and producing a gap analysis against the canonical schema that will be implemented in the post-Epic 0 Rust codebase at `codeflow-core/src/ledger/sessions.rs`.

This audit feeds into INF-TSK-024-007 (canonical event schema synthesis) and provides the field-level detail needed for Rust type definitions.

## Approach

1. Read schema-standardization.md Section 1.1 (sessions.jsonl audit) for the complete field inventory
2. Read existing `.state/ledger/sessions.jsonl` entries to verify documented fields against actual data
3. Document shell-era schema (pre-Go migration) with field names, types, and example values
4. Document Go-era schema with field names, types, and example values
5. Catalog all field naming inconsistencies with BEFORE (current) / AFTER (canonical) mapping
6. Document target Rust types referenced in the gap analysis (e.g., `EventType`, `SessionId`, `WorktreeId`) -- document what they are and which fields map to them, but do NOT define or implement the types (that is INF-TSK-024-007's scope)
7. Include BEFORE/AFTER JSON examples for each schema era showing field differences
8. Write the audit document
