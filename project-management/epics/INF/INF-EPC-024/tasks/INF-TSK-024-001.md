## Description

Document the current sessions.jsonl schema across both shell-era and Rust-era entries, identifying field naming inconsistencies (ts vs timestamp, event_type vs event), missing universal fields (session_id, worktree), and producing a gap analysis against the canonical schema. The Rust codebase writes events via `LedgerWriter` in `codeflow-cli/core/src/ledger/jsonl.rs` using typed events from `codeflow-cli/core/src/types/events.rs`.

This audit feeds into INF-TSK-024-007 (canonical event schema synthesis) and provides the field-level detail needed for Rust type definitions.

## Approach

1. Read schema-standardization.md Section 1.1 (sessions.jsonl audit) for the complete field inventory
2. Read existing `.state/ledger/sessions/sessions.jsonl` (base) and session fragments to verify documented fields against actual data (note: subdirectory layout per PR #221; run `codeflow ledger migrate` if still flat)
3. Read `codeflow-cli/core/src/ledger/jsonl.rs` to understand current Rust LedgerWriter output format
4. Read `codeflow-cli/core/src/types/events.rs` to understand typed event definitions
5. Document shell-era schema (pre-Rust migration) with field names, types, and example values
6. Document Rust-era schema with field names, types, and example values
7. Catalog all field naming inconsistencies with BEFORE (current) / AFTER (canonical) mapping
8. Document target Rust types referenced in the gap analysis (e.g., `EventType`, `SessionId`, `WorktreeId` from `codeflow-cli/core/src/types/ids.rs`) -- document what they are and which fields map to them, but do NOT define or implement new types (that is INF-TSK-024-007's scope)
9. Include BEFORE/AFTER JSON examples for each schema era showing field differences
10. Write the audit document
