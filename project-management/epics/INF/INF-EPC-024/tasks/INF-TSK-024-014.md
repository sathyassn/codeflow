## Description

Align the Rust event-type routing module with the canonical event types defined in INF-TSK-024-007. The routing module maps `EventType` enum variants to their target JSONL files. After this task, only canonical event types are routable -- non-canonical types (legacy aliases) are rejected at the type level via exhaustive match.

The Rust `EventType` enum (from INF-TSK-024-007) makes routing exhaustive at compile time: every variant must be handled in the match expression. This eliminates the class of bugs where a routing table entry exists without a schema entry (or vice versa).

Uses shared types from INF-TSK-024-007: EventType, MemoryEventType.

## Approach

1. Read canonical event schema (output of INF-TSK-024-007) for the complete list of canonical event types per file
2. Update `routing.rs` to use `EventType` enum variants in match expression
3. Remove non-canonical event type entries (handled by the enum -- they don't exist as variants)
4. Update memory events routing to use `MemoryEventType` enum from task 009
5. Verify `canonical_files()` returns correct file list
6. Write crosscheck test: exhaustive match on EventType ensures schema coverage
7. Write unit tests for each canonical type routing
8. Write insta snapshot test for routing table
9. Run `cargo test`, `cargo clippy`, `cargo fmt --check`
