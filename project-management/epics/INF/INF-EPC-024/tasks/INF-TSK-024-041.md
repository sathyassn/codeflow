# INF-TSK-024-041: One-time repair of mis-routed events in pathflow-events.jsonl

> **MANDATORY VALIDATION:** Files created from this template MUST be validated against the task validation command before committing:
> `codeflow validate task <file-path>`
> Fix all errors (exit code 1) before requesting a commit. Warnings are advisory.

## Description

Per the pathflow-events schema audit (INF-TSK-024-005), several event types (`begin_work`, `complete_work`, `progress`, `stale_work_cleanup`) are historical residue from the shell-era writer and belong in the work-graph or memory-events canonical streams, not in pathflow-events. The Rust writer's current `route_event_type()` function already sends new events of these types to the correct streams, but the historical file at `.state/ledger/pathflow-events/pathflow-events.jsonl` retains the legacy mis-routed entries.

This task adds an idempotent, streaming repair that (a) walks the existing base file line-by-line, (b) re-routes each event through the canonical `route_event_type()` helper, (c) appends mis-routed events to their correct destination streams, and (d) atomically rewrites the source file with only correctly-routed events. Corrupt JSON lines are preserved in place with a stderr warning so no data is silently discarded. A CLI subcommand `codeflow ledger repair` exposes the operation with a `--dry-run` mode for safe previewing. Closes gap G2 from the 2026-04-22 chain audit.

**Expected Outcome:** After running `codeflow ledger repair --type pathflow-events` once, the `.state/ledger/pathflow-events/pathflow-events.jsonl` file contains only events whose canonical target is pathflow-events; mis-routed `begin_work`/`complete_work`/`progress`/`stale_work_cleanup` events appear in their correct streams; a subsequent SurrealDB rebuild produces consistent state across all tables. Re-running repair is a no-op.
**Deployment:** Compiled into the `codeflow` binary. Operators run `codeflow ledger repair` manually (one-time) or as part of a follow-up maintenance task. Autorun workers SHOULD NOT invoke this command as a side effect.

## Approach

1. Create `codeflow-cli/core/src/ledger/repair.rs` with:
   - `pub struct RepairReport { events_scanned: u64, events_rerouted_by_target: BTreeMap<String, u64>, corrupt_lines: u64, would_rewrite: bool }`
   - `pub enum RepairError { SourceNotFound, RouteLookupFailed, AppendFailed, RewriteFailed, LockAcquireFailed }` with `thiserror::Error`
   - `pub fn repair_ledger_type(ledger_dir: &Path, type_name: &str, dry_run: bool) -> Result<RepairReport, RepairError>`
2. Implementation:
   - Open source file with `BufReader::new(File::open(...))`; return `SourceNotFound` if missing.
   - For each line: attempt `serde_json::from_str::<Event>`; on parse error, increment `corrupt_lines`, emit stderr warn with line number + first 80 chars, push to `kept_lines` Vec (preserved in-place).
   - On parse success, extract `event_type`, call `route_event_type(&event_type)?`; if target == type_name, push to `kept_lines`; else push to `reroute_map[target]`.
   - If `dry_run`: populate `events_rerouted_by_target` from sizes of `reroute_map`, set `would_rewrite=true`, return report.
   - If not dry-run: acquire per-type advisory lock on each destination via the same mechanism as `LedgerWriter` (timeout 5s, return `LockAcquireFailed`); for each (target, events) pair call `LedgerWriter::append_event(target, event)` under the lock. Then atomically rewrite the source file: write `kept_lines` to a temp file in the same directory and `fs::rename` over the original.
3. Add `pub mod repair;` re-export in `codeflow-cli/core/src/ledger/mod.rs`.
4. Add CLI subcommand in `codeflow-cli/cli/src/cmd/ledger.rs`:
   - `clap` derive: `Repair { #[arg(long)] type_: Option<String>, #[arg(long)] dry_run: bool }`
   - Implementation calls `repair_ledger_type` for each type (or just one if `--type` supplied), prints the report as a table, exits 0 on success.
5. Write unit tests using `tempfile::tempdir()` fixtures (no mocks).
6. Write integration tests using `assert_cmd` to invoke the binary against a tempdir.
7. Run `cargo test --workspace`, `cargo clippy --all-targets --all-features -- -D warnings`, `cargo fmt --check`, `codeflow test --mode full` twice.

## Concurrency Considerations

| Shared Resource | Access Pattern | Safety Mechanism |
|----------------|---------------|-----------------|
| `.state/ledger/<type>/<type>.jsonl` (source) | Read, then atomic rewrite | Acquire per-type advisory lock before read; hold through rewrite; release after `fs::rename`. Concurrent `LedgerWriter::append_event` on the same type is blocked during repair. |
| `.state/ledger/<target>/<target>.jsonl` (destination) | Append via `LedgerWriter::append_event` | Standard lock acquired by `append_event` itself (existing contract) |
| Cross-worktree ledger dirs | Repair runs against ONE ledger dir; caller chooses | Out of scope — aggregator (INF-TSK-024-043) is the cross-worktree tool |

## Acceptance Criteria

1. New module codeflow-cli/core/src/ledger/repair.rs exposes pub fn repair_ledger_type(ledger_dir: &Path, type_name: &str, dry_run: bool) -> Result<RepairReport, RepairError>
2. New CLI subcommand codeflow ledger repair [--type <T>] [--dry-run] wired in codeflow-cli/cli/src/cmd/ledger.rs; codeflow ledger repair --help lists the flags
3. When --type is omitted, repair iterates over every registered ledger type (files::CANONICAL + PATHFLOW_EVENTS)
4. Repair streams the base file line-by-line (bounded memory: no full-file read) and routes each event via the existing route_event_type() helper
5. Lines whose routed target equals the source type are preserved in-place (correctly routed — no-op for this stream)
6. Lines whose routed target differs are appended to the canonical destination stream via append_event() under the same lock discipline as the live writer
7. After rerouting, the source file is atomically rewritten (temp file + fs::rename) to contain only correctly-routed events
8. Dry-run mode reports intended moves via RepairReport (events_scanned, events_rerouted_by_target, corrupt_lines, would_rewrite: true) without touching any file
9. Idempotent: running repair twice against the same ledger dir produces events_rerouted_by_target counts of 0 on the second invocation
10. Corrupt JSON lines are preserved in-place (kept in the source stream as-is) with a stderr WARN including the line number and the first 80 chars of the line
11. RepairError variants cover: SourceNotFound(PathBuf), RouteLookupFailed { event_type, line }, AppendFailed { target, cause: Box<dyn Error> }, RewriteFailed { source: PathBuf, cause: Box<dyn Error> }, LockAcquireFailed(PathBuf)
12. Repair respects the existing per-type advisory lock (same mechanism used by LedgerWriter.append_event()); failure to acquire the lock within a configurable timeout (default 5s) returns LockAcquireFailed rather than blocking indefinitely
13. Unit tests in repair.rs cover: (a) fixture with mixed correctly-routed and mis-routed events produces the expected redistribution, (b) dry-run leaves the filesystem untouched and reports the intended moves, (c) re-run after a successful repair is a no-op (second-run rerouted count is 0), (d) corrupt JSON line survives in source with stderr warning, (e) empty source file is a no-op returning events_scanned=0, (f) source file absent returns Err(SourceNotFound)
14. Integration test: write a fixture pathflow-events.jsonl containing 3 begin_work events plus 2 phase_transition events; run repair; assert pathflow-events.jsonl contains only the 2 phase_transition events and work-graph/work-graph.jsonl now contains the 3 begin_work events
15. Integration test: invoke codeflow ledger repair --type pathflow-events --dry-run against a populated fixture; assert exit code 0, stdout contains the redistribution report, and no file on disk changes (compare SHA-256 before/after)
16. Post-repair SurrealDB rebuild (codeflow rebuild or sync_from_events) shows the relocated events present in their canonical streams (verified via codeflow db exec SELECT or equivalent inspection)
17. Per-file coverage >= 85% on codeflow-cli/core/src/ledger/repair.rs and codeflow-cli/cli/src/cmd/ledger.rs
18. cargo clippy --all-targets --all-features -- -D warnings passes; cargo fmt --check passes

## Notes

- **Gap reference:** Closes G2 from `project-management/epics/INF/INF-EPC-024/audits/2026-04-22-chain-audit.md`.
- **Generic by design:** Although the motivating mis-routing is pathflow-events → work-graph, the function is named and parameterised generically (`repair_ledger_type`) so the same helper handles any future mis-routing without new code.
- **Atomic rewrite invariant:** The source rewrite MUST be atomic (temp file + fs::rename) so that a crash partway through cannot leave the base file half-rewritten. A partial rewrite would cause data duplication on SurrealDB rebuild.
- **SurrealDB rebuild acceptance:** Criterion 16 requires a real `sync_from_events` execution, not a schema-only check. This catches silent routing errors that pass the unit tests but break the cross-tier rebuild contract.
- **Relationship to INF-TSK-024-020:** The rebuild cursor/incremental logic added by 020 must tolerate repair operations. After repair, a full `--full` rebuild may be required to rebuild SurrealDB from t=0 — document this in the repair subcommand's help text.
- **Not autorun-chained:** Because repair rewrites ledger files, it must NOT be invoked silently by autorun workers. The subcommand is operator-facing.
