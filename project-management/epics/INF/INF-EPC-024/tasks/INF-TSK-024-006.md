## Description

Document security, network, and conversation log schemas. These are secondary log files with varying levels of active writing. Some have dead writers (no active code produces events), some have been replaced by Rust hooks, and some are discontinued entirely.

## Approach

1. Read schema-standardization.md Sections 1.7, 1.8, 1.9 for security, network, conversation logs
2. Read actual log files to verify current state
3. Read `codeflow-cli/core/src/hooks/security/` for Rust security module
4. Read `codeflow-cli/core/src/hooks/logging/` for Rust logging module
5. Document each log schema with current writer status
6. Catalog discontinued logs and dead writers
7. Write all three audit documents

**Documentation Summary:**
Created two audit documents for the security and network log schema. Both documents follow
the established audit format from `sessions-jsonl-audit.md` with verified field schemas from
