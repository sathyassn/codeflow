## Description

Change worktree setup to COPY `.state/ledger/` contents instead of symlinking it. Each worktree gets its own ledger copy. This ensures JSONL writes from a worktree session appear in that worktree's git index, enabling proper git tracking on the feature branch.

Also evaluate whether `.state/db/` and `.state/registry/` symlinks cause `.gitkeep` phantom entries, and fix if needed.

## Approach

1. Read `codeflow-cli/core/src/worktree/setup.rs` to understand `setup_detached()` symlink logic
2. Read `codeflow-cli/core/src/worktree/paths.rs` to understand `WorktreePaths` resolution
3. Change `setup_detached()` to copy `.state/ledger/` contents instead of creating a symlink
4. Update `WorktreePaths` to resolve ledger as local directory (not following symlink)
5. Update `cleanup_worktree()` in `cleanup.rs` to handle local ledger directory
6. Evaluate `.gitkeep` files in db/ and registry/ -- if they cause phantom git entries, copy or create locally
7. Consider: should ledger events be merged back at PR merge time? Document the merge strategy in code comments.
8. Run existing worktree tests to verify no regressions
9. Add unit tests for the copy behavior

## Concurrency Considerations

- **Shared resource:** `.state/ledger/` -- currently symlinked (shared), will become local (copied)
- **Access pattern:** After this fix, each worktree has its own ledger copy. No cross-worktree writes to same files.
- **Safety mechanism:** File locking in `LedgerWriter` still applies for concurrent writes within a single worktree (multiple hooks writing simultaneously). Cross-worktree isolation is achieved by having separate file copies.
- **Merge strategy:** Ledger events from the worktree branch are committed to git and merged with the main branch at PR merge time. JSONL files are append-only, so merge conflicts are unlikely (both sides add lines). If conflicts occur, both sides' entries should be kept (union merge).
