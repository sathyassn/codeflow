# INF-TSK-024-037: Implement codeflow interactive command, worktree session isolation, and autorun field rename

> `codeflow validate task <file-path>`

## Description

This task implements three related changes to the CodeFlow session lifecycle:

**1. `codeflow interactive` CLI command (alias `codeflow -i`).** Creates a git worktree and generates a session ID (ses-{ulid}) BEFORE starting Claude Code, eliminating the shared `codeflow-env.sh` singleton race condition that causes parallel session corruption. The CLI always generates the session ID regardless of worktree mode, registers an InteractiveSession in SurrealDB, then passes `CODEFLOW_MANAGED=true` and `CODEFLOW_SESSION_ID` as env vars so the SessionStart hook knows to skip worktree creation and session ID generation.

**2. Interactive session management.** New DB model (`InteractiveSession`) tracking session_id, pid, status, worktree_path, branch, work_type, team_name, and timestamps. Three subcommands: `codeflow interactive status` (active sessions), `codeflow interactive list` (all sessions), `codeflow interactive cleanup` (stale PID removal). Liveness detection reuses the autorun PID + heartbeat pattern, with `.state/interactive/heartbeat-{SID}` written by the SessionStart hook.

**3. Autorun field rename.** Renames confusing batch file fields to be explicit about their purpose: `target` becomes `integration_branch`, `auto_merge` becomes `integration_auto_merge`, `final_pr_base` becomes `final_pr_target`, and `target_is_auto` becomes `integration_branch_is_auto`. Corresponding env var renames: `AUTORUN_TARGET` to `AUTORUN_INTEGRATION_BRANCH`, `AUTORUN_AUTO_MERGE` to `AUTORUN_INTEGRATION_AUTO_MERGE`.

**4. Hook simplification.** Removes PID-based env file functions from `session/env.rs`, simplifies `detect_project_dir()` to a 3-step resolution, and adds `update_branch_from_current()` at PF3 checkpoint completion.

## Approach

### Phase A: Interactive Command (Steps 1-9)

1. **Extract `setup_worktree()` from existing worktree/setup.rs functions** -- Create a shared `pub fn setup_worktree(project_dir, session_id, config) -> Result<WorktreePaths>` that encapsulates worktree creation, registry registration, and symlink setup. This function is currently spread across `WorktreeManager::setup_detached()` and autorun worker setup.

2. **Create `codeflow-cli/cli/src/cmd/interactive.rs`** -- New subcommand that:
   - Generates session_id (ses-{ulid}) ALWAYS, regardless of worktree mode
   - Reads worktree config from `parallel-work-config.json` (mode: always/disabled)
   - If mode=always: calls `setup_worktree()`, sets `CODEFLOW_MANAGED=true`, `CODEFLOW_SESSION_ID`, and `CODEFLOW_WORKTREE_PATH` env vars, then exec's `claude` in the worktree directory
   - If mode=disabled: sets `CODEFLOW_MANAGED=true` and `CODEFLOW_SESSION_ID`, passes through to `claude` without worktree setup
   - Registers InteractiveSession in SurrealDB before exec'ing claude
   - Registers the `-i` alias in the CLI parser

3. **Create InteractiveSession DB model and schema** -- New model in `codeflow-cli/core/src/models/interactive_session.rs` with fields: session_id, pid, status (active/complete/stale), worktree_path, branch, work_type, team_name, created_at, updated_at, completed_at. Add `DEFINE TABLE interactive_session` and fields to `schema.surql`.

4. **Add `codeflow interactive status/cleanup/list` subcommands** -- In `interactive.rs`:
   - `status`: query active InteractiveSessions, show PID liveness, worktree path, branch
   - `list`: show all sessions (active + complete + stale)
   - `cleanup`: detect dead PIDs via liveness check, mark stale, optionally remove worktrees
   - Liveness detection reuses autorun's PID + heartbeat pattern

5. **Add `CODEFLOW_MANAGED` detection to SessionStart** -- In `session_start.rs`, check for `CODEFLOW_MANAGED=true` env var. When set:
   - Read `CODEFLOW_SESSION_ID` from env (do NOT generate a new session ID)
   - Skip `WorktreeManager::setup_detached()` (worktree already exists)
   - Skip writing shared `codeflow-env.sh` (worktree has its own)
   - Skip teammate detection via `lead_pid` (env vars already propagated)
   - Write `.state/interactive/heartbeat-{SID}` for liveness detection
   - Still perform: pathflow initialization, sentinel directory setup

6. **Fix PID env file lifecycle in `session/env.rs`** -- Remove `clean_stale_pid_env_files()` only. Keep `write_pid_env_file()` and `read_pid_env_file()` — the per-PID file serves as `detect_project_dir()` step 4 fallback for tmux teammates in the unmanaged path. In `session_start.rs`, remove the early write call (before worktree creation — produces empty/incorrect path); keep the deferred write call that runs after `setup_worktree()` completes with the correct worktree path.

7. **Simplify `detect_project_dir()` in `helpers.rs`** -- Reduce to 4-step resolution by removing step 5 only (shared `codeflow-env.sh` fallback — the race condition source). Steps 1-4 are retained:
   1. Check `CODEFLOW_WORKTREE_PATH` env var (set by CLI or autorun)
   2. Check `CF_PROJECT_ROOT` env var (legacy/manual override)
   3. Walk CWD upward looking for `.codeflow/` directory
   4. Per-PID env file lookup via `read_worktree_path_from_pid_file()` (retained for tmux teammate fallback)

8. **Remove PID cleanup from `session_end.rs`** -- Remove calls to `clean_stale_pid_env_files()` in the SessionEnd handler since the function no longer exists.

9. **Add `update_branch_from_current()` at PF3 in `post_tool_use.rs` and `task_completed.rs`** -- When the PF3 checkpoint completes (all PF3 tasks done, pf-3 sentinel created), call `WorktreeRegistry::update_branch()` with the current branch name from `git rev-parse --abbrev-ref HEAD`. This ensures the worktree registry reflects the feature branch, not the detached HEAD.

## Concurrency Considerations

| Shared Resource | Access Pattern | Safety Mechanism |
|----------------|---------------|-----------------|
| WorktreeRegistry (worktrees.yaml) | read-modify-write during setup_worktree() and update_branch() | `locked_register_with_limit` (file_lock.rs) |
| state.loro (CRDT) | shared across worktrees via symlink | `locked_binary_rmw` (file_lock.rs) |
| SurrealDB (InteractiveSession table) | concurrent read/write from multiple CLI invocations | SurrealDB transactions with RetryConfig |
| codeflow-env.sh | per-worktree (NOT shared when worktree mode ON) | Isolation by design -- each worktree has its own copy |
| Heartbeat files (.state/interactive/) | per-session write, cross-session read | Session-scoped filenames prevent collision |
| Feature branch creation | concurrent worktrees may create branches | Git's own locking prevents corruption; branch names are session-scoped |

## Notes

- **Reference:** `.codeflow/docs/analysis/worktree-session-isolation.md` contains the comprehensive analysis that motivates this task, including the shared env file race condition, PID detection audit results, and the `codeflow interactive` solution design.
- **Session ID lifecycle (critical):** The CLI always generates the session ID, not the SessionStart hook. This is true even when `mode=disabled` (no worktree). The hook in MANAGED mode reads `CODEFLOW_SESSION_ID` from the environment and never calls its own ID generation.
- **Key insight:** The root cause of parallel session corruption is that `codeflow-env.sh` is a shared singleton. By creating the worktree and session ID BEFORE Claude starts (in the CLI command), each session is fully isolated from the start.
- **Backward compatibility:** Plain `claude` invocation (without `codeflow -i`) continues to work as before. The `CODEFLOW_MANAGED` env var is only set by the CLI command, so the SessionStart hook behavior is unchanged for non-managed sessions.
- **PID env files are dead code after this task:** The `write_pid_env_file` / `read_pid_env_file` / `clean_stale_pid_env_files` functions in `session/env.rs` were a workaround for the shared env file problem. With per-worktree env files, they serve no purpose.
- **Autorun rename rationale:** The current field names (`target`, `auto_merge`) are ambiguous -- they could refer to the final PR target or the integration branch. The new names (`integration_branch`, `integration_auto_merge`) make it explicit that these control the integration branch, not the final PR.
- **Parallelization:** Phase A (interactive command, steps 1-9), Phase B (autorun rename, steps 10-14), and Phase C (docs, steps 15-19) are largely independent and can be assigned to parallel teammates. Phase D (tests, step 20) depends on all three.
- **Standard requirements:** `cargo clippy --all-targets --all-features -- -D warnings`, `cargo fmt --check`, coverage >= 85% per file.
