# INF-TSK-024-037: Implement codeflow interactive command and worktree session isolation

> **MANDATORY VALIDATION:** Files created from this template MUST be validated before committing:
> `codeflow validate task <file-path>`
> Fix all errors (exit code 1) before requesting a commit. Warnings are advisory.

## Description

This task implements a `codeflow interactive` CLI command (alias `codeflow -i`) that creates a git worktree BEFORE starting Claude Code, eliminating the shared `codeflow-env.sh` singleton race condition that causes parallel session corruption. When two `codeflow -i` sessions run concurrently, each gets its own worktree with isolated `.state/` directories, preventing the PID-based env file conflicts and shared env writes that currently cause session ID confusion.

The task also simplifies the SessionStart hook chain by:
- Adding `CODEFLOW_MANAGED` env var detection so the hook skips worktree creation when the CLI already handled it
- Removing PID-based env file functions (`write_pid_env_file`, `read_pid_env_file`, `clean_stale_pid_env_files`) from `session/env.rs`
- Simplifying `detect_project_dir()` to a 3-step resolution: env var, CF_PROJECT_ROOT, CWD walk
- Adding `update_branch_from_current()` at PF3 checkpoint completion so the worktree registry reflects the actual feature branch

Additionally, the shared `setup_worktree()` function is extracted so both `codeflow interactive` and `autorun/worker.rs` use the same worktree creation path.

## Approach

1. **Extract `setup_worktree()` from existing worktree/setup.rs functions** -- Create a shared `pub fn setup_worktree(project_dir, session_id, config) -> Result<WorktreePaths>` that encapsulates worktree creation, registry registration, and symlink setup. This function is currently spread across `WorktreeManager::setup_detached()` and autorun worker setup.

2. **Create `codeflow-cli/cli/src/cmd/interactive.rs`** -- New subcommand that:
   - Reads worktree config from `parallel-work-config.json` (mode: always/disabled)
   - If mode=always: calls `setup_worktree()`, sets `CODEFLOW_MANAGED=true` and `CODEFLOW_WORKTREE_PATH` env vars, then exec's `claude` in the worktree directory
   - If mode=disabled: passes through to `claude` without worktree setup
   - Registers the `-i` alias in the CLI parser

3. **Add `CODEFLOW_MANAGED` detection to SessionStart** -- In `session_start.rs`, check for `CODEFLOW_MANAGED=true` env var. When set:
   - Skip `WorktreeManager::setup_detached()` (worktree already exists)
   - Skip writing shared `codeflow-env.sh` (worktree has its own)
   - Skip teammate detection via `lead_pid` (env vars already propagated)
   - Still perform: session record creation, pathflow initialization, sentinel directory setup

4. **Remove PID env file functions from `session/env.rs`** -- Delete `write_pid_env_file()`, `read_pid_env_file()`, and `clean_stale_pid_env_files()`. These are replaced by the worktree-scoped env file that `setup_worktree()` creates.

5. **Simplify `detect_project_dir()` in `helpers.rs`** -- Reduce to 3-step resolution:
   1. Check `CODEFLOW_WORKTREE_PATH` env var (set by CLI or autorun)
   2. Check `CF_PROJECT_ROOT` env var (legacy/manual override)
   3. Walk CWD upward looking for `.codeflow/` directory

6. **Remove PID cleanup from `session_end.rs`** -- Remove calls to `clean_stale_pid_env_files()` in the SessionEnd handler since the function no longer exists.

7. **Add `update_branch_from_current()` at PF3 in `post_tool_use.rs` and `task_completed.rs`** -- When the PF3 checkpoint completes (all PF3 tasks done, pf-3 sentinel created), call `WorktreeRegistry::update_branch()` with the current branch name from `git rev-parse --abbrev-ref HEAD`. This ensures the worktree registry reflects the feature branch, not the detached HEAD.

8. **Refactor `autorun/worker.rs` to use shared `setup_worktree()`** -- Replace the inline worktree setup code in the autorun worker with a call to the shared function from step 1.

9. **Update CLAUDE.md Section 4.2 Step 1** -- Remove "SessionStart creates worktree" language, add `codeflow -i` as the worktree entry point. Document that SessionStart now detects `CODEFLOW_MANAGED` and skips worktree creation when set.

10. **Update CLAUDE.md Section 8** -- Add `codeflow interactive` (alias `-i`) to the CLI commands list with description of worktree-isolated session startup.

11. **Update CLAUDE.md Section 10** -- Update `codeflow-env.sh` description to clarify it is written only in non-worktree mode. Document `CODEFLOW_MANAGED` env var in the session context files table.

12. **Update CLAUDE.md Section 11** -- Update recovery instructions to reference worktree-local env file instead of shared `codeflow-env.sh`. Update context overflow recovery to note that `CODEFLOW_WORKTREE_PATH` persists in the process environment.

13. **Update agent definitions** -- Update `cf-security.md` (CODEFLOW_WORKTREE_PATH sourcing references), `cf-documentation.md` (worktree path staging references), and `cf-development.md` (worktree path references) to reflect the new env var propagation model.

14. **Update `cf-doctor.md`** -- Add interactive command diagnostics: verify `codeflow interactive` is available, check worktree creation health, validate env var propagation.

15. **Write tests** -- Add tests for:
    - `setup_worktree()` shared function (creates worktree, registers, symlinks)
    - `interactive.rs` command (mode=always creates worktree, mode=disabled passes through)
    - SessionStart CODEFLOW_MANAGED detection (skips worktree, skips env write)
    - `detect_project_dir()` 3-step resolution (env var > CF_PROJECT_ROOT > CWD walk)
    - Parallel session isolation (two concurrent sessions don't corrupt each other)

## Concurrency Considerations

| Shared Resource | Access Pattern | Safety Mechanism |
|----------------|---------------|-----------------|
| WorktreeRegistry (worktrees.yaml) | read-modify-write during setup_worktree() and update_branch() | `locked_register_with_limit` (file_lock.rs) |
| state.loro (CRDT) | shared across worktrees via symlink | `locked_binary_rmw` (file_lock.rs) |
| codeflow-env.sh | per-worktree (NOT shared when worktree mode ON) | Isolation by design -- each worktree has its own copy |
| Feature branch creation | concurrent worktrees may create branches | Git's own locking prevents corruption; branch names are session-scoped |
