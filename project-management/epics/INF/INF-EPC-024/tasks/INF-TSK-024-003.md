# INF-TSK-024-003: Ledger audit: memory-events.jsonl schema documentation and gap analysis

## Description

Document the three coexisting schema patterns in memory-events.jsonl -- the most chaotic ledger file. Schema-standardization.md Section 1.3 reveals three distinct patterns: (1) nested data+event_type (~80%), (2) flat aliases (~10%), (3) non-canonical types (~10%). The `data` field has doubly-nested stringified JSON in some entries. The `event_type` and `memory_type` fields have overlapping semantics.

This audit maps all three patterns to the canonical 6 event types that will be enforced in the Rust writer at `codeflow-core/src/ledger/memory_events.rs`.

## Approach

1. Read schema-standardization.md Section 1.3 (memory-events.jsonl audit) and Section 7 (target schema)
2. Sample actual `.state/ledger/memory-events.jsonl` to verify pattern distribution
3. Document Pattern 1 (nested): field structure, data nesting depth, event_type values
4. Document Pattern 2 (flat): field aliases, memory_type usage, top-level fields
5. Document Pattern 3 (non-canonical): event types that don't map to canonical types
6. Map all patterns to the canonical 6 types as Rust enum variants
7. Document the consolidation path (BEFORE each pattern -> AFTER canonical)
8. Write the audit document
