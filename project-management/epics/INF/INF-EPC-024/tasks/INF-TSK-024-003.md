## Description

Document the three coexisting schema patterns in memory-events.jsonl -- the most chaotic ledger file. Schema-standardization.md Section 1.3 reveals three distinct patterns: (1) nested data+event_type (~80%), (2) flat aliases (~10%), (3) non-canonical types (~10%). The `data` field has doubly-nested stringified JSON in some entries. The `event_type` and `memory_type` fields have overlapping semantics.

This audit maps all three patterns to canonical event types and identifies the Rust type structure needed, referencing patterns from `codeflow-cli/core/src/types/events.rs`.

## Approach

1. Read schema-standardization.md Section 1.3 (memory-events.jsonl audit) and Section 7 (target schema)
2. Sample actual `.state/ledger/memory-events.jsonl` to verify pattern distribution
3. Read `codeflow-cli/core/src/types/events.rs` for existing event type enum patterns
4. Document Pattern 1 (nested): field structure, data nesting depth, event_type values
5. Document Pattern 2 (flat): field aliases, memory_type usage, top-level fields
6. Document Pattern 3 (non-canonical): event types that don't map to canonical types
7. Map all patterns to canonical types, proposing Rust enum variants following existing patterns in `types/events.rs`
8. Document the consolidation path (BEFORE each pattern -> AFTER canonical)
9. Write the audit document
