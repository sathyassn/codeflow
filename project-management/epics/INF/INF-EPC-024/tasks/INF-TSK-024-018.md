## Description

Create the `codeflow cleanup --retention` Rust CLI subcommand that applies retention policies from tasks 016 and 017. This is the operational implementation of the retention policy documents.

The subcommand must handle two distinct policy types: ledger files (NEVER delete, only archive+compress) and log files (rotate, compress, delete after retention period). It must support dry-run mode, type filtering, age overrides, and interactive confirmation.

In Rust, the `RetentionPolicy` enum enforces the NEVER-delete invariant at the type level: the `Ledger` variant only supports `archive()` and `compress()` operations, while the `Log` variant also supports `delete()`. This makes it impossible to accidentally call delete on a ledger file.

## Approach

1. Read retention policy documents (outputs of tasks 016 and 017)
2. Create `codeflow-core/src/cleanup/` module with:
   - `RetentionPolicy` enum: `Ledger { archive_after: Duration, compress: bool }` and `Log { delete_after: Duration, compress_after: Duration }`
   - `CleanupAction` enum: `Archive(PathBuf)`, `Compress(PathBuf)`, `Delete(PathBuf)`, `Skip(PathBuf, String)`
   - `apply()` method that returns `Vec<CleanupAction>` (plan) or executes (apply)
3. Implement policy application logic:
   - Ledger: archive to `.state/ledger/archive/`, compress with flate2 (gzip)
   - Logs: delete files older than retention period, compress recent files
   - Discontinued: delete sentinel, stop-events, git-operations directories
4. Create `src/commands/cleanup.rs` with clap subcommand registration
5. Implement flags: --retention, --dry-run, --type, --older-than, --compress, --archive, --yes
6. Add interactive confirmation via dialoguer crate for destructive operations
7. Use fs2 crate for advisory file locking (parallel session safety)
8. Write comprehensive unit tests with tempdir for filesystem operations
9. Write insta snapshot tests for dry-run output format
10. Run `cargo test`, `cargo clippy`, `cargo fmt --check`
