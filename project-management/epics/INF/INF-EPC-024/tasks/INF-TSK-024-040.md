# INF-TSK-024-040: Update pathflow-events/ledger consumers; introduce resolve_path helper

> **MANDATORY VALIDATION:** Files created from this template MUST be validated against the task validation command before committing:
> `codeflow validate task <file-path>`
> Fix all errors (exit code 1) before requesting a commit. Warnings are advisory.

## Description

INF-TSK-024-035 (PR #303) moved the pathflow-events.jsonl write target from `.state/logs/pathflow-events.jsonl` to `.state/ledger/pathflow-events/pathflow-events.jsonl` to match the subdirectory ledger layout established by PR #221. The writer side (routing.rs, jsonl.rs) was updated and a one-time migration was added, but downstream consumers were missed:

- `codeflow-cli/cli/src/cmd/report.rs:22` still joins `logs_dir.join("pathflow-events.jsonl")` for reading — `codeflow report` now silently returns zero pathflow events on post-migration installs.
- `codeflow-cli/core/src/doctor/mod.rs:682` still constructs `logs_dir.join("pathflow-events.jsonl")` inside `read_pathflow_events()`, called from `codeflow doctor` report paths.

This task fixes both consumers by (a) introducing a `pub fn resolve_path(type_name, worktree_aware) -> Result<PathBuf>` in `ledger/mod.rs` that returns the canonical subdirectory base file path for a given ledger type, and (b) refactoring `report.rs` and `doctor/mod.rs` to call the helper. A regression lint in tests fails CI if future consumers hardcode the old path. This closes gap G1 from the 2026-04-22 chain audit.

| Updated unit tests for report.rs and doctor/mod.rs fixtures | test | same files, `#[cfg(test)] mod tests` | Runs in `cargo test --workspace` |

**Expected Outcome:** After this task ships, `codeflow report` and `codeflow doctor` correctly read pathflow events from the ledger subdirectory on post-INF-TSK-024-035 installs; adding a new pathflow-events consumer without using `resolve_path` is caught by the regression test at CI time rather than by silent runtime zero-event output.
**Deployment:** Compiled into the `codeflow` binary; no config or migration steps required. Users receive the fix when they update the binary.

## Approach

1. Add `pub fn resolve_path(type_name: &str, worktree_aware: bool) -> Result<PathBuf, LedgerError>` to `codeflow-cli/core/src/ledger/mod.rs`.
   - Validate `type_name` against `files::CANONICAL` and any auxiliary stream constants (`PATHFLOW_EVENTS`, etc.); return `LedgerError::UnknownType(String)` on miss.
   - When `worktree_aware=true` AND `std::env::var("CODEFLOW_WORKTREE_PATH")` returns `Ok(root)`, resolve the state directory via `WorktreePaths::new(root).state_dir()` (see `codeflow-cli/core/src/worktree/paths.rs:23` — `pub fn new(root: impl Into<PathBuf>) -> Self`). Otherwise fall back to the project's main-repo `.state/`. Note: `WorktreePaths::from_env()` does NOT exist today — callers compose the env-var check with `WorktreePaths::new`. Optionally introduce a thin `WorktreePaths::from_env() -> Option<Self>` convenience; if so, add `codeflow-cli/core/src/worktree/paths.rs` to the task's `file_scope` and `To Modify` before implementation.
   - Return `<state_dir>/ledger/<type_name>/<type_name>.jsonl` (the base file path established by PR #221).
2. Refactor `cli/src/cmd/report.rs:22`: replace `logs_dir.join("pathflow-events.jsonl")` with `ledger::resolve_path("pathflow-events", true)?`. Adjust the surrounding `logs_dir` variable resolution (may become unused once the helper owns path construction).
3. Refactor `core/src/doctor/mod.rs:682`: same substitution inside `read_pathflow_events(state_dir)`. Preserve the function signature; internally use the helper.
4. Update the existing unit tests in `doctor/mod.rs` (approx lines 1711-2134) that write test fixtures to `logs_dir.join("pathflow-events.jsonl")` — rewrite to write to `<tempdir>/.state/ledger/pathflow-events/pathflow-events.jsonl` (create dir with `fs::create_dir_all`).
5. Add unit tests for `resolve_path`: known canonical type returns the expected path; unknown type returns `UnknownType`; worktree-aware path honours `CODEFLOW_WORKTREE_PATH` (use `temp_env` crate or a scoped env-var guard).
6. Add the regression lint test. Implementation options (pick the simpler one):
   - **Option A (recommended):** `#[test]` that reads the workspace's non-test Rust source files via `glob::glob` and asserts no line contains `.state/logs/pathflow-events` or `pathflow-events.jsonl` outside (i) `session_start.rs`'s migration function block, (ii) `ledger/mod.rs`'s `resolve_path`, (iii) lines carrying `// EXEMPT:`.
   - **Option B:** a shell-script test registered in `test-config.json` that invokes `rg` and asserts empty output.
   Choose A for workspace portability (no dependency on rg on CI).
7. Run `cargo test --workspace`, `cargo clippy --all-targets --all-features -- -D warnings`, `cargo fmt --check`, then `codeflow test --mode full` twice for stability.
