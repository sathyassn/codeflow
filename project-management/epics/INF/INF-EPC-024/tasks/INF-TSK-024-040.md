# INF-TSK-024-040: Update pathflow-events/ledger consumers; introduce resolve_path helper

> **MANDATORY VALIDATION:** Files created from this template MUST be validated against the task validation command before committing:
> `codeflow validate task <file-path>`
> Fix all errors (exit code 1) before requesting a commit. Warnings are advisory.

## Description

INF-TSK-024-035 (PR #303) moved the pathflow-events.jsonl write target from `.state/logs/pathflow-events.jsonl` to `.state/ledger/pathflow-events/pathflow-events.jsonl` to match the subdirectory ledger layout established by PR #221. The writer side (routing.rs, jsonl.rs) was updated and a one-time migration was added, but downstream consumers were missed:

- `codeflow-cli/cli/src/cmd/report.rs:22` still joins `logs_dir.join("pathflow-events.jsonl")` for reading — `codeflow report` now silently returns zero pathflow events on post-migration installs.
- `codeflow-cli/core/src/doctor/mod.rs:682` still constructs `logs_dir.join("pathflow-events.jsonl")` inside `read_pathflow_events()`, called from `codeflow doctor` report paths.

This task fixes both consumers by (a) introducing a `pub fn resolve_path(type_name, worktree_aware) -> Result<PathBuf>` in `ledger/mod.rs` that returns the canonical subdirectory base file path for a given ledger type, and (b) refactoring `report.rs` and `doctor/mod.rs` to call the helper. A regression lint in tests fails CI if future consumers hardcode the old path. This closes gap G1 from the 2026-04-22 chain audit.

### DEV Report

> Populated by cf-development before STAGE-COMPLETE: WS-DEV

**Implementation Summary:**
Introduced `ledger::resolve_path(type_name, worktree_aware)` and its explicit-state-dir companion `ledger::resolve_path_in(state_dir, type_name)` as the single authoritative resolver for ledger-file paths. Both call a shared `ledger_file_path(state_dir, type_name) -> PathBuf` that composes `<state_dir>/ledger/<type>/<type>.jsonl`, matching the PR #221 subdirectory layout and the PR #303 pathflow-events migration target. Unknown types return `LedgerError::UnknownType(String)` — a new typed variant added to `error.rs` — rather than panic. Env-var resolution goes through a new `WorktreePaths::from_env() -> Option<Self>` convenience in `worktree/paths.rs`, which treats empty strings as unset for consistency with existing downstream consumers.

Refactored the two silently-broken consumers: `codeflow-cli/cli/src/cmd/report.rs` now calls `resolve_path_in` with an explicit project-dir-derived `.state` (the CLI already resolves project_dir via `detect_project_dir`, which honours `CODEFLOW_WORKTREE_PATH`), and `codeflow-cli/core/src/doctor/mod.rs::read_pathflow_events(state_dir)` keeps its signature but replaces the hardcoded `state_dir.join("logs").join("pathflow-events.jsonl")` with `resolve_path_in(state_dir, files::PATHFLOW_EVENTS)?`. Report output added a zero-byte-file branch so users see "0 bytes (no pathflow events recorded)" rather than a bare "0 bytes" that could be mistaken for a missing-file condition — the absence branch still outputs "no pathflow events".

Added a workspace-portable regression lint (`ledger::tests::regression_lint::no_hardcoded_legacy_pathflow_events_literals`) that globs every `.rs` file under `codeflow-cli/core/src` and `codeflow-cli/cli/src`, parses `#[cfg(test)]` module blocks via brace-counting, exempts `ledger/mod.rs` (the helper itself) and `hooks/session_start.rs` (the one-shot migration), and asserts that no line contains `.state/logs/pathflow-events` or `pathflow-events.jsonl` outside test modules and `// EXEMPT:` markers. Four meta-tests verify the lint has teeth: the mask correctly detects `#[cfg(test)]` blocks, ignores `#[cfg(feature = ...)]`, recognises `// EXEMPT:` markers, and triggers on unmasked offending lines.

Updated 7 pre-existing doctor-test fixtures (and 1 pre-existing report.rs fixture) to write to `.state/ledger/pathflow-events/pathflow-events.jsonl`, preserving test intent rather than silently skipping coverage of the migrated path. Legitimate non-path mentions of the filename (doc comments, section dividers in routing.rs/events.rs, and user-facing `println!` output in report.rs) carry inline `// EXEMPT: <reason>` markers.
