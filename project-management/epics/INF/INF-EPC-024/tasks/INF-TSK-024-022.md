# INF-TSK-024-022: Design SurrealDB target schemas for all event types

## Description

Create a design document with SurrealDB-specific table and field definitions for all canonical event types. SurrealDB's multi-model capabilities (document, graph, relational) offer significant advantages over SQLite for the CodeFlow data model -- particularly for work graph traversal (graph queries), memory events (document flexibility), and session-work relationships (native RELATE).

This task is blocked by INF-EPC-022 (Epic 0: Rust CLI Foundation) which establishes the Rust CLI infrastructure including SurrealDB embedded mode (surrealkv://). The design document created here will guide the actual implementation of SurrealDB tables once the foundation is in place.

Decision D17 (SurrealDB-only, no SQLite extension) is the governing architectural decision. This design assumes SurrealDB replaces SQLite entirely as Tier 1. Decision D18 (Global DB) specifies the single-database-per-project architecture.

Uses shared types from INF-TSK-024-007: EventType, CanonicalEvent, FieldName -- the SurrealDB DEFINE FIELD statements map directly to Rust struct fields.

## Approach

1. Read canonical event schema (output of INF-TSK-024-007) for the authoritative field definitions
2. Read DB rebuild mapping document (output of INF-TSK-024-019) for current SQLite schema
3. Read schema-standardization.md Section 8 for coverage gaps to address in SurrealDB design
4. Read Decision D17, D18, D19 for architectural constraints
5. Study SurrealDB DEFINE TABLE/FIELD syntax and multi-model capabilities
6. Design table schemas using SurrealDB's type system (record links, arrays, objects, datetime)
7. Design graph relationships using SurrealDB RELATE for: task->epic, work->task, dependency->task
8. Design event ingestion pipeline: JSONL event -> SurrealDB upsert/relate (mapped from EventType variants)
9. Document migration path from SQLite
10. Document indexing strategy for common query patterns
11. Document Rust integration: surrealdb crate, surrealkv:// embedded, connection patterns
12. Write the design document

- Key SurrealDB advantages for CodeFlow:
  - Record links replace foreign keys (type safety for task->epic)
  - Native graph traversal replaces recursive SQL CTEs for dependency trees
  - Flexible document schema handles memory_events without rigid columns
  - Built-in datetime type replaces TEXT ISO 8601 parsing
  - surrealkv:// embedded mode: no external server needed (like SQLite)
- Rust crate: `surrealdb` (official Rust SDK), connection via `Surreal::new::<SpeeDb>("surrealkv://path/to/db")`
