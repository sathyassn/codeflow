# INF-TSK-024-044: Automated compaction lifecycle triggers

> **MANDATORY VALIDATION:** Files created from this template MUST be validated against the task validation command before committing:
> `codeflow validate task <file-path>`
> Fix all errors (exit code 1) before requesting a commit. Warnings are advisory.

## Description

`codeflow-cli/core/src/ledger/compact.rs` already contains `compact_ledger_type` and `compact_all` (verified at `compact.rs:33` and `:141`), but nothing ever calls them automatically. The original design intent — expressed in the cross-session merging comments and PR #221's worktree-isolation PR body — was that compaction runs at SessionEnd and worktree cleanup, promoting worktree-local base files into the main-repo ledger. Today that promotion is not implemented, so destroyed worktrees' historical events become invisible to main-repo tools unless the cross-worktree aggregator (INF-TSK-024-043) is running.

This task wires the compaction lifecycle: (a) SessionEnd invokes `compact_all` on the current worktree's ledger as a best-effort cleanup; (b) worktree cleanup invokes a new `compact_and_promote` that compacts plus merges into the main-repo ledger under an advisory promotion lock; (c) the rescue-bundle path still runs when promotion fails, preserving uncommitted data; (d) both paths honour a `CODEFLOW_NO_AUTO_COMPACT=true` env var for debugging and emergency opt-out. Closes gap G5 from the 2026-04-22 chain audit.

**Expected Outcome:** After this task ships, destroying a worktree promotes its ledger events into the main-repo ledger so they remain visible to tools running in the main repo even after the aggregator (INF-TSK-024-043) is no longer in play. SessionEnd also routinely compacts per-session fragments into base files, reducing file-count growth over time.
**Deployment:** Compiled into the `codeflow` binary; behaviour changes from the next binary upgrade onward. Users who want the pre-upgrade behaviour set `CODEFLOW_NO_AUTO_COMPACT=true` in their shell environment.

## Approach

1. **Shared opt-out helper.** Add `pub fn auto_compact_enabled() -> bool { std::env::var("CODEFLOW_NO_AUTO_COMPACT").map(|v| v != "true" && v != "1").unwrap_or(true) }` in `codeflow-cli/core/src/ledger/compact.rs`.
2. **`compact_and_promote` function.**
   ```rust
   pub fn compact_and_promote(worktree_ledger_dir: &Path, main_repo_ledger_dir: &Path)
       -> Result<PromotionReport, PromotionError>
   ```
   - Validate both dirs exist; return `WorktreeMissing` / `MainDirMissing` on absence.
   - For each type in `files::CANONICAL + [PATHFLOW_EVENTS]`:
     - Run `compact_ledger_type(worktree_ledger_dir, type_name, None)` → on Err, record in `report.errors` and continue (best-effort per type).
     - Acquire `.promotion.lock` at `main_repo_ledger_dir/<type>/.promotion.lock` with 5s timeout → on timeout, `LockAcquireFailed`.
     - Read compacted base file from worktree; append to main-repo base file under the lock (temp file + fs::rename pattern from `compact_ledger_type`).
     - On append failure, roll back: the worktree base file already holds the data (compaction moved it there), so rollback is "do nothing to worktree; skip this type" — record in `report.errors`.
     - Release lock.
   - Return report.
3. **SessionEnd integration** (`codeflow-cli/core/src/hooks/session_end.rs`):
   - After existing cleanup work (before the hook returns), call `if ledger::compact::auto_compact_enabled() { let _ = ledger::compact::compact_all(worktree_ledger_dir, None); }`
   - Log errors to stderr via `eprintln!("warn: session-end compaction: {e}")`. Never fail the hook.
4. **Worktree cleanup integration** (`codeflow-cli/core/src/worktree/cleanup.rs`):
   - Insert `compact_and_promote` call BEFORE directory removal, AFTER claim release.
   - If `compact_and_promote` returns Err: do NOT remove the worktree directory; still run rescue-bundle step if uncommitted changes exist; return the error up so the caller can retry.
   - If Ok: proceed with directory removal as today.
5. **CLI doc update** (`codeflow-cli/cli/src/cmd/ledger.rs`): add `--no-auto` to the `Compact` subcommand. Functionality is "this is a manual compaction invocation that does not trigger the auto lifecycle" — in practice, this is already how the manual command behaves; this AC makes the flag discoverable.
6. **Tests.** Use `tempfile::tempdir` for filesystem fixtures. For the crash-injection test, use a compile-time feature `#[cfg(feature = "crash_inject")]` or a thread-local atomic flag that the real code respects when `cfg!(test)`.
7. Run `cargo test --workspace`, `cargo clippy --all-targets --all-features -- -D warnings`, `cargo fmt --check`, and `codeflow test --mode full` twice.

## Concurrency Considerations

| Shared Resource | Access Pattern | Safety Mechanism |
|----------------|---------------|-----------------|
| Main-repo ledger `<type>/<type>.jsonl` | Concurrent promotion from multiple worktrees being torn down simultaneously | Per-type advisory lock at `main_repo_ledger_dir/<type>/.promotion.lock`; 5s timeout; `LockAcquireFailed` on timeout |
| Worktree ledger base files | Compaction rewrites them atomically | `fs::rename`-based atomic replacement in `compact_ledger_type`; no change required |
| `CODEFLOW_NO_AUTO_COMPACT` env var | Read-only | `std::env::var` is safe for reads |
| Rescue bundle directory (XDG cache) | Independent of compaction | Untouched by this task's code path |

## Notes

- **Gap reference:** Closes G5 from `project-management/epics/INF/INF-EPC-024/audits/2026-04-22-chain-audit.md`.
- **Opt-out is load-bearing:** Autorun workers running in tight loops should be able to disable auto-compaction via `CODEFLOW_NO_AUTO_COMPACT=true` to avoid disk churn during heavy batch execution. The env var MUST be checked at call time, not cached at process start.
- **Transactional discipline:** The "neither change observable" invariant (AC 4) is the single most important correctness property. A botched promotion that half-commits state will bite users later via rebuild drift. Test 3 (`main-repo append fails` → worktree preserved) is the canonical check.
- **Rescue bundle is orthogonal:** The rescue-bundle system handles uncommitted Git changes at worktree cleanup; promotion handles ledger events. Both must run; the ordering is: claim release → rescue bundle → compact-and-promote → directory removal. AC 6 verifies this ordering is preserved.
- **Future `codeflow worktree cleanup --dry-run`:** Not in scope here but likely useful. Leave the `PromotionReport` struct public so a future dry-run flag can surface the intended promotion plan without executing it.
