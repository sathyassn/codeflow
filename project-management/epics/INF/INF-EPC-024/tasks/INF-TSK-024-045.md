# INF-TSK-024-045: Backfill delivery evidence + orphan task reconciliation

> **MANDATORY VALIDATION:** Files created from this template MUST be validated against the task validation command before committing:
> `codeflow validate task <file-path>`
> Fix all errors (exit code 1) before requesting a commit. Warnings are advisory.

## Description

Fourteen completed INF-EPC-024 tasks have `status: complete` in their YAML frontmatter but empty `pr_number`, `branch`, `completed_at`, and `target_branch` fields. This missing bookkeeping data breaks downstream tooling: the three-tier consistency validator (INF-TSK-024-021) cannot trust task metadata, the rebuild-mapping tool (INF-TSK-024-019/020) cannot correlate tasks to PRs, and human auditors cannot trace work to merges without re-running grep across the git log every time.

This task performs an evidence-based backfill: for each of the 14 tasks (001–007, 016, 017, 028, 030, 031, 032, 037), scrape `git log --all --grep <task_id>` and `gh pr list --search <task_id> --state merged` to derive the missing fields and populate them verbatim. In addition, two orphan tasks (038 and 039) discovered during the 2026-04-22 format_id enumeration — one with a placeholder id, one with DB/disk status drift — are reconciled with the DB and added to the epic task table. No acceptance-criteria text or scope fields are modified; this is pure bookkeeping. Closes gap G8 and absorbs G12 (orphan reconciliation) from the 2026-04-22 chain audit.

## Approach

1. **Evidence gathering.** For each of the 14 tasks:
   - `gh pr list --search "<task_id>" --state merged --json number,headRefName,baseRefName,mergeCommit,mergedAt`
   - `git log --all --grep "<task_id>" --format='%H %ci %s'` — pick the merge commit on the target branch
   - Cross-check: the PR's `mergeCommit.oid` should match the git log merge commit.
2. **Frontmatter edit per task file.** For each:
   - Open the file; apply targeted frontmatter edits via Edit tool to ONLY these fields: `pr_number`, `branch`, `completed_at`, `target_branch`, `updated_at`. Do NOT touch `acceptance`, `file_scope`, `status`, or any other field.
   - Append one row to the Notes section:
     ```
     **Delivery Evidence:** PR #<n>, branch `<head>`, merged <ISO-8601> via <sha>, source: `gh pr view <n>`
     ```
3. **Orphan 038 reconciliation decision tree:**
   - Option A (register): generate a proper ULID, replace `task-pending-038` in the id field, send `PLANNER: create-task` message to cf-knowledge-layer with status=todo, verify DB insertion.
   - Option B (cancel): change frontmatter `status: todo` → `status: cancelled`, add a rationale comment in the task's Notes section, append `task_cancelled` event to work-graph-events via cf-knowledge-layer.
   - Decision made during implementation based on whether the template-to-DB alignment work is still relevant to INF-EPC-024. If unclear, default to Option A.
4. **Orphan 039 DB sync:**
   - Disk: status=complete, completed_at already populated.
   - DB: `codeflow db exec "UPDATE task SET status = 'complete', completed_at = '<iso>' WHERE id = 'task-01KPKR7C4CJMJXP6YMTW7YZ6VY'"` via cf-knowledge-layer.
   - Append `task_status_changed { from: "in_progress", to: "complete", timestamp, session_id }` to `.state/ledger/work-graph/work-graph.jsonl` via cf-knowledge-layer.
5. **Epic table update.** Use Edit tool on `INF-EPC-024.md` to append two rows to the task table for 038 and 039; also append a `Delivery Evidence Backfill (2026-04-22)` subsection under Notes summarizing what was changed.
6. **Validate.** Run `codeflow validate task` on every modified file and `codeflow validate epic` on the epic — all must exit 0.
7. **Diff discipline.** Run `git diff -- project-management/epics/INF/INF-EPC-024/tasks/` and confirm no `acceptance:` or `file_scope:` lines changed in the 14 completed tasks.
