# INF-TSK-024-013: Migrate ad-hoc flat fields to details object in work-graph.jsonl writer

## Description

Move ad-hoc flat fields from top level to a `details` object in the work-graph.jsonl Rust writer. Multiple event types have accumulated ad-hoc fields: `branch`, `summary`, `reason`, `note`, `completed_at`, `data` appear inconsistently across `task_status_changed`, `begin_work`, and `complete_work` events.

Per the canonical schema (INF-TSK-024-007), variable event-specific content goes in a `details` object. Core structural fields (`id`, `format_id`, `epic_id`, `new_status`, `old_status`) remain top-level, enforced by the Rust struct layout. Old entries remain immutable (append-only invariant) -- the reader handles both formats via serde untagged enum.

Uses shared types from INF-TSK-024-007: CanonicalEvent, details object pattern.

## Approach

1. Read work-graph audit (output of INF-TSK-024-002) for current field layout per event type
2. Read canonical event schema (output of INF-TSK-024-007) for details pattern
3. Define `WorkGraphDetails` enum with per-event-type variants:
   - `TaskStatusChanged { branch, summary, reason, note, completed_at, data }`
   - `BeginWork { branch, topic, domain }`
   - `CompleteWork { summary, branch, data }`
4. Update `work_graph.rs` writer to serialize ad-hoc fields into `details` via serde
5. Update `normalize.rs` to detect legacy flat entries and restructure into details format
6. Implement serde untagged enum for backward-compatible deserialization of both formats
7. Write unit tests for each event type in both formats
8. Write insta snapshot tests for canonical JSON output
9. Run `cargo test`, `cargo clippy`, `cargo fmt --check`
