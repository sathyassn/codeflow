# INF-TSK-024-021: Implement three-tier consistency validator (codeflow doctor --data-layer) in Rust CLI

## Description

Create a `codeflow doctor --data-layer` Rust CLI subcommand that performs end-to-end validation of the three-tier data model: Tier 0 (JSONL) -> Tier 1 (SurrealDB via surrealkv:// embedded mode, per Decision D17) -> Tier 2 (Markdown). This is the capstone tooling task for the data layer standardization epic.

The three-tier model guarantees directional consistency: JSONL is the rebuild authority for the DB, and the DB is the source for markdown. This validator checks that guarantee holds by comparing event counts, field values, and record existence across all three tiers. It integrates into the existing `codeflow doctor` infrastructure.

In Rust, the `ConsistencyError` enum (with thiserror) provides structured error reporting for each type of inconsistency: count mismatches, field drift, orphan records, and orphan markdown files.

## Approach

1. Read existing `codeflow-cli/src/commands/doctor.rs` for the doctor command structure
2. Read Rust store module at `codeflow-cli/codeflow-core/src/store/` for existing health check patterns
3. Read the rebuild mapping document (output of INF-TSK-024-019) for field mapping reference
4. Create `codeflow-core/src/datalayer/` module with:
   - `ConsistencyValidator` struct
   - `ConsistencyError` enum with thiserror: `CountMismatch { table, jsonl_count, db_count }`, `FieldDrift { table, field, jsonl_value, db_value }`, `OrphanRecord { table, id }`, `OrphanMarkdown { path }`, `RebuildFailed { table, reason }`
   - `ConsistencyReport` struct: per-tier results, error list, fix actions
5. Implement Tier 0->1 validation:
   - Count JSONL events per EventType variant
   - Count corresponding DB rows per table
   - Report mismatches via ConsistencyError::CountMismatch
6. Implement Tier 1->2 validation:
   - Scan `project-management/epics/` for markdown files
   - Parse YAML frontmatter using serde_yaml
   - Compare frontmatter fields against DB records
   - Report field-level drift via ConsistencyError::FieldDrift
7. Implement orphan detection:
   - DB records with no corresponding JSONL events
   - Markdown files with no corresponding DB records
8. Implement `--fix` flag for auto-repair (conservative: only unambiguous fixes)
9. Add `--data-layer` flag to existing doctor command in `src/commands/doctor.rs`
10. Write unit tests with tempdir for filesystem and mock DB
11. Write insta snapshot tests for report format
12. Run `cargo test`, `cargo clippy`, `cargo fmt --check`
