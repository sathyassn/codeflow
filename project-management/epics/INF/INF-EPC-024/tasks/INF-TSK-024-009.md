# INF-TSK-024-009: Standardize memory-events.jsonl: consolidate 3 schema patterns to 1

> **MANDATORY VALIDATION:** Files created from this template MUST be validated against the task validation command before committing:
> `codeflow validate task <file-path>`
> Fix all errors (exit code 1) before requesting a commit. Warnings are advisory.

## Description

Collapse three coexisting schema patterns in memory-events.jsonl to a single canonical format. This is the most complex schema standardization task in the epic due to the three distinct patterns: (1) nested data+event_type (~80%), (2) flat aliases (~10%), (3) non-canonical types (~10%).

## Deliverables

> **MANDATORY:** Every task must specify what is being delivered, where it integrates, and the expected outcome. Vague deliverables like "update code" are insufficient.

| Deliverable | Type | Location | Integration Point |
|-------------|------|----------|-------------------|
| Memory event type enum | feature | `codeflow-cli/core/src/types/events.rs` | LedgerWriter validates event type on write |
| Write-time validation for canonical types | fix | `codeflow-cli/core/src/ledger/jsonl.rs` | Rejects non-canonical memory event types |
| Read-time normalization for legacy patterns | fix | `codeflow-cli/core/src/ledger/jsonl.rs` | 3 legacy patterns normalized transparently on read |
| Unit tests | test | `codeflow-cli/core/src/ledger/`, `types/` | cargo test coverage enforcement |

**Expected Outcome:** Memory-events.jsonl writer produces only canonical event types. All 3 legacy schema patterns are normalized on read. Doubly-nested data.data is flattened. Non-canonical types are rejected at write time.
**Deployment:** PR merge; no migration script needed — normalization is read-time.
