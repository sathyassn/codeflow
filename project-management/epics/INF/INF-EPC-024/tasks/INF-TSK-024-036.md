## Description

This task implements the SurrealDB schema updates designed in INF-TSK-024-022 and builds the `codeflow rebuild --execute` command that replays cleaned JSONL data into SurrealDB using the new schema. It is the execution counterpart to the design task.

The rebuild command reads all 4 `files::CANONICAL` JSONL types (sessions, work-graph, memory-events, config), parses each line into typed events, maps them to SurrealDB records, and upserts into the database. The process must be idempotent and use the validation tooling from INF-TSK-024-020 to verify data integrity post-replay.

Schema evolution uses `DEFINE ... OVERWRITE` statements (already the pattern in schema.surql) to update table and field definitions without data loss.

## Approach

1. Read TSK-022 output: `.codeflow/docs/schemas/surrealdb-target-schemas.md` for target schema design

5. Update `schema.surql` with new/modified DEFINE TABLE and DEFINE FIELD statements from TSK-022
6. Implement `codeflow rebuild --execute` clap subcommand in `codeflow-cli/cli/src/`
7. Implement JSONL reader: iterate over 4 CANONICAL ledger files, parse typed events
8. Implement record mapper: EventType -> SurrealDB upsert per TSK-022 mapping
9. Implement integrity validation: call TSK-020 tooling after replay completes
10. Implement idempotency: running rebuild twice produces identical state
11. Document rollback procedure: how to restore from JSONL if rebuild fails
12. Write unit tests (min 4: add field, modify field type, add table, idempotent replay)
13. Write integration test: full JSONL->DB replay cycle on test fixtures
