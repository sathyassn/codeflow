## Description

Move variable event-specific fields from top-level to a `details` object in sessions.jsonl events. Universal fields (timestamp, event, session_id, worktree) remain top-level. Variable fields (source, interaction_mode, work_completed, summary) go into a nested details object. This standardizes the sessions.jsonl format to match the canonical schema pattern.

## Approach

1. Read audit from task 001 for field classification (universal vs variable)
2. Read canonical schema from task 007 for details object pattern
3. Read `codeflow-cli/core/src/hooks/session_start.rs` to find session event construction
4. Read `codeflow-cli/core/src/types/events.rs` for event type definitions
5. Modify event construction to nest variable fields in details object
6. Add read-time normalization: legacy flat entries converted to details format
7. Ensure serde deserialization handles both formats
8. Write unit tests

## Concurrency Considerations

- **Shared resource:** `.state/ledger/sessions/sessions.jsonl` (base) and session fragments -- written by LedgerWriter (subdirectory layout per PR #221)
- **Access pattern:** Append-only JSONL writes to session-scoped fragment files via file lock in `jsonl.rs`
- **Safety mechanism:** `LedgerWriter` uses file locking. The details object migration changes event structure but not the concurrency model.
- **Worktree impact:** Ledger is LOCAL per-worktree (not symlinked). The worktree field (from task 011) helps attribute events to their source worktree. (Updated per PR #221 -- ledger moved from SHARED_STATE_DIRS to LOCAL_STATE_DIRS.)
