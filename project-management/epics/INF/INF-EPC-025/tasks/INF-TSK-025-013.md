# INF-TSK-025-013: KG Ontology Schema & Entity Management

## Description

Implement the core KgStore module that provides CRUD operations for knowledge graph entities and relationships stored in SurrealDB. This is the foundational data access layer for the entire knowledge graph engine. The KgStore wraps a SurrealDB connection and provides typed methods for creating, reading, updating, and traversing entities and their relationships.

The ontology defines 16 entity types (Concept, Decision, Pattern, Component, Problem, Solution, Technology, Developer, Requirement, TestCase, Deployment, Incident, Convention, Lesson, API, Milestone) and 18 relationship types (relates_to, solved_by, caused_by, uses_pattern, decided_in, depends_on, expert_in, similar_to, implements, tested_by, deployed_to, owns, evolved_from, validates, learned_from, replaces, conflicts_with, references). All types are defined as SurrealDB SCHEMAFULL tables with proper field constraints and relation typing.

Graph traversal uses SurrealDB's native arrow syntax (`->`, `<-`, `<->`) for efficient multi-hop queries. A Direction enum controls traversal direction (Outgoing, Incoming, Both). Duplicate relations are prevented by checking existing edges before creation. A configurable confidence threshold (default 0.3) filters low-quality extracted relationships from query results.

## Approach

1. Define the `Direction` enum with variants `Outgoing`, `Incoming`, `Both` in `kg/mod.rs`
2. Define the `KgStore` struct holding a `Surreal<Any>` connection handle
3. Implement SurrealDB schema initialization: `DEFINE TABLE entity SCHEMAFULL` with fields for entity_type, name, description, hash, embedding, source_records, created_at, updated_at. Add `DEFINE INDEX entity_hash ON entity FIELDS hash UNIQUE` and `DEFINE INDEX entity_embedding ON entity FIELDS embedding HNSW DIMENSION 384`
4. Define all 18 relationship tables using `DEFINE TABLE TYPE RELATION IN entity OUT entity` with fields for relationship_type, confidence, source_record, extracted_at
5. Implement `create_entity()` -- insert entity record, return generated ID
6. Implement `get_entity()` -- SELECT by ID with all fields
7. Implement `update_entity()` -- merge strategy: higher confidence wins, union descriptions array, earliest created_at preserved
8. Implement `create_relation()` -- check for duplicate (same from/to/type) before RELATE; set confidence and source_record fields
9. Implement `get_relations()` -- query using Direction enum to select arrow syntax (`->` for Outgoing, `<-` for Incoming, `<->` for Both), filter by confidence >= threshold
10. Implement `traverse()` -- multi-hop graph traversal with configurable depth using SurrealDB recursive notation `@.{N}->`
11. Write unit tests covering all CRUD operations, direction filtering, duplicate detection, confidence threshold, and multi-hop traversal

## Notes

- The ontology is based on the extended analysis in knowledge-graph-engine.md Section 3.2 (16 entity types, 18 relationship types)
- Entity hash is SHA-256 of normalized(entity_type + ":" + name) for dedup
- SurrealDB symmetric dedup pattern for bidirectional relations (similar_to): `DEFINE FIELD key ON TABLE similar_to VALUE <string>array::sort([in, out]); DEFINE INDEX only_one_similarity ON similar_to FIELDS key UNIQUE;`
- Confidence threshold 0.3 is the default from knowledge-graph-engine.md pruning config
- The `traverse()` method should support both typed (specific relationship) and untyped (any relationship) traversal
