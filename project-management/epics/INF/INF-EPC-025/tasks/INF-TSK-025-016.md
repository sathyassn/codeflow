# INF-TSK-025-016: LLM Entity & Relationship Extraction (COGNIFY)

## Description

Implement the COGNIFY pipeline that extracts entities and relationships from text using LLM-based analysis. This is the core intelligence component that transforms raw text (task descriptions, session summaries, memory entries) into structured knowledge graph nodes and edges.

The design uses a trait-based abstraction (`LlmExtractor`) with two implementations: `MockExtractor` for deterministic testing without API calls, and `ClaudeExtractor` for production use via the Claude CLI (`claude -p "prompt"`). The extraction process is ontology-guided -- prompts include the full ontology (16 entity types, 18 relationship types) with descriptions and examples to constrain extraction quality.

The COGNIFY pipeline orchestrates the full extraction workflow: poll the extraction queue (from TSK-014), run entity extraction, run relationship extraction, deduplicate against existing entities (via TSK-017), store in the knowledge graph (via TSK-013), generate embeddings (via TSK-015), and mark the queue entry as processed. Rate limiting ensures LLM API calls don't exceed cost budgets.

## Approach

1. Define the `LlmExtractor` trait with two async methods: `extract_entities(text, ontology_prompt) -> Result<Vec<RawEntity>>` and `extract_relations(text, entities, ontology_prompt) -> Result<Vec<RawRelation>>`
2. Define `RawEntity` struct: entity_type (String), name (String), description (Option<String>), confidence (f32)
3. Define `RawRelation` struct: from_entity (String), to_entity (String), relationship_type (String), confidence (f32), evidence (Option<String>)
4. Implement `MockExtractor` -- returns hardcoded entities/relations based on keyword matching for deterministic test behavior
5. Implement `ClaudeExtractor`:
   a. Build ontology prompt from configured entity/relationship types with descriptions and examples
   b. Construct extraction prompt: system context + ontology + input text + JSON output format
   c. Invoke `claude -p "{prompt}" --output-format json` via tokio::process::Command
   d. Parse JSON response into Vec<RawEntity> / Vec<RawRelation>
   e. Apply rate limiting: track last call timestamp, sleep if interval < 2 seconds
6. Implement `CognifyPipeline` struct that orchestrates the full workflow:
   a. Poll IngestPipeline for pending queue entries (batch)
   b. For each entry: extract entities, extract relations
   c. Deduplicate entities via KgStore hash lookup
   d. Store new entities and relations via KgStore CRUD
   e. Generate embeddings for new entities via EmbeddingEngine
   f. Mark queue entry as processed (or failed with retry)
7. Add rate limiter: `RateLimiter` struct with configurable interval (default 2s), tracks last call time, async sleep before next call
8. Implement logging for timing, token counts, and extraction statistics
9. Write tests using MockExtractor for pipeline integration without API dependency

## Notes

- The hybrid approach (knowledge-graph-engine.md Section 9): ONNX for embeddings (free, always), Claude CLI for complex extraction (idle-time, paid)
- Claude CLI invocation: `claude -p "prompt" --output-format json` -- headless mode, no interactive UI
- Configuration-driven model selection via `codeflow-knowledge.toml`: extraction_model = "onnx" | "claude" | "codex" | "gemini" | "none"
- The ontology prompt should be constructed from the KG config, not hardcoded, to support custom_entity_types and custom_relationship_types extensions
- Rate limiting default (2s) is conservative; can be reduced to 1s for production Claude API with appropriate tier
- Cognee reference: 6-stage COGNIFY pipeline (knowledge-graph-engine.md Section 2.3) -- our implementation follows the same pattern but adapted for SurrealDB storage
- Research shows 89.7% precision, 92.3% recall for entity extraction with guided prompts (Nature Scientific Reports 2026)
