# INF-TSK-025-006: Global Configuration and Project Registry

## Description

Implement the configuration system for the Global Intelligence Layer. There are two config files:

1. **Global config** at `~/.codeflow/config.toml` -- daemon-wide settings (database paths, daemon behavior, embedding model, extraction settings)
2. **Per-project config** at `.codeflow/config/project.toml` -- project identity and sharing preferences

Both use TOML format parsed with the `toml` crate and deserialized via serde. All path fields support `~` expansion to the user's home directory. Missing config files are handled gracefully with sensible defaults -- a user should be able to start using the daemon without manually creating config files.

## Approach

1. Define `GlobalConfig` struct with 4 nested section structs:
   - `DatabaseConfig` -- daemon_socket, daemon_timeout_ms
   - `DaemonConfig` -- data_dir, log_file, pid_file, sync_interval_seconds
   - `EmbeddingConfig` -- model_name, model_path, dimensions
   - `ExtractionConfig` -- enabled, idle_threshold_seconds, max_queue_size
   - All fields have `#[serde(default)]` with sensible defaults
2. Define `ProjectConfig` struct with 2 nested sections:
   - `ProjectSection` -- name, area_prefixes, project_id (Option)
   - `SharingSection` -- visible_projects, visible_tags, visible_scopes, allow_sharing, shared_scopes
3. Implement path expansion utility:
   - `expand_tilde(path: &str) -> PathBuf` -- replaces leading `~` with `dirs::home_dir()`
   - Applied to all path-type fields during deserialization via custom serde deserializer or post-load transformation
4. Implement config loading:
   - `GlobalConfig::load() -> Result<Self, RegistryError>` -- reads `~/.codeflow/config.toml`, returns defaults if file missing
   - `GlobalConfig::load_from(path) -> Result<Self, RegistryError>` -- loads from specific path (for testing)
   - `ProjectConfig::load(project_root) -> Result<Self, RegistryError>` -- reads `{project_root}/.codeflow/config/project.toml`
5. Implement config validation:
   - `GlobalConfig::validate() -> Result<(), Vec<String>>` -- checks constraints
   - daemon_timeout_ms > 0
   - sync_interval_seconds >= 5
   - dimensions must be positive
   - All path directories must be writable (or creatable)
6. Implement config writing:
   - `GlobalConfig::save() -> Result<(), RegistryError>` -- writes to `~/.codeflow/config.toml`
   - `ProjectConfig::save(project_root) -> Result<(), RegistryError>` -- writes to `.codeflow/config/project.toml`
   - Used by `codeflow project register` to write initial project config
7. Write tests: default values, roundtrip (load -> save -> load), validation failures, missing file handling, tilde expansion

## Notes

- Source: global-intelligence.md Section 6 (Configuration) -- config file schemas
- Source: decisions.md D20 (Cross-Project Visibility) -- per-project sharing config
- The `toml` crate's serde integration allows `#[serde(default = "default_fn")]` for each field, avoiding a separate default initialization step
- Path expansion with `dirs::home_dir()` is cross-platform (macOS and Linux)
- The `[extraction]` section defaults to `enabled: false` -- knowledge graph extraction is opt-in, not automatic
- ProjectConfig is written by `codeflow project register` (INF-TSK-025-008) with auto-generated project_id
- Consider using `figment` crate instead of raw `toml` for layered config (env vars > file > defaults), but plain `toml` is simpler for initial implementation
