# INF-TSK-025-019: Hybrid Search -- GRAPH_COMPLETION

## Description

Implement the GRAPH_COMPLETION hybrid search mode that combines vector similarity search with knowledge graph traversal to provide contextually rich results. This is the primary retrieval mechanism for the knowledge engine, used by CLI commands (`codeflow context search`) and agent context retrieval.

The 4-stage pipeline works as follows:
1. **Vector search**: Embed the query text, find top-N semantically similar entities via HNSW cosine similarity
2. **Graph expansion**: From the vector hits, traverse 1-2 hops of graph relationships to discover related entities not captured by vector similarity alone
3. **Source retrieval**: For all entities in the result set, fetch the original source records (task descriptions, session summaries, etc.) to provide actionable context
4. **Combined ranking**: Score results using a weighted combination of vector similarity and graph proximity (alpha * vector + (1-alpha) * graph, default alpha=0.7)

Visibility enforcement ensures cross-project queries respect `can_access` graph relations. If the global daemon is unavailable, search gracefully degrades to project-local results only.

## Approach

1. Define `SearchScope` enum: `Project(ProjectId)`, `Visible(ProjectId)` (project + can_access), `Global` (admin/all)
2. Define `SearchRequest` struct: query (String), limit (usize, default 10), threshold (f32, default 0.7), scope (SearchScope), include_graph (bool, default true), include_sources (bool, default true), alpha (f32, default 0.7)
3. Define `SearchResult` struct: entities (Vec<ScoredEntity>), relationships (Vec<ScoredRelation>), source_records (Vec<SourceRecord>), timing (SearchTiming)
4. Define `ScoredEntity`: entity (Entity), vector_score (f32), graph_score (f32), combined_score (f32)
5. Implement Stage 1 -- Vector Search:
   a. Generate embedding for query text via EmbeddingEngine
   b. Query: `SELECT id, name, entity_type, vector::similarity::cosine(embedding, $vec) AS score FROM entity WHERE vector::similarity::cosine(embedding, $vec) > $threshold AND project IN $visible ORDER BY score DESC LIMIT $limit`
6. Implement Stage 2 -- Graph Expansion:
   a. For each vector hit, traverse: `SELECT ->knows->entity.* AS related, <-knows<-entity.* AS reverse FROM entity:$id`
   b. Compute graph_proximity as 1.0 for direct hits, 0.5 for 1-hop, 0.25 for 2-hop
7. Implement Stage 3 -- Source Retrieval:
   a. Collect all entity IDs from Stages 1+2
   b. Query source_records field from entities
   c. Fetch actual records from task/session/memory tables
8. Implement Stage 4 -- Combined Ranking:
   a. combined_score = alpha * vector_score + (1 - alpha) * graph_proximity
   b. Sort all results by combined_score descending
   c. Apply final limit
9. Implement visibility enforcement: build $visible project list from can_access traversal before Stage 1
10. Implement graceful degradation: try daemon connection first; on timeout/error, fall back to embedded DB with SearchScope::Project
11. Add timing instrumentation for each stage
12. Write tests covering all 4 stages, visibility filtering, alpha parameter effects, and degradation

## Notes

- GRAPH_COMPLETION is the default search mode, inspired by Cognee's retrieval mode (knowledge-graph-engine.md Section 2.3)
- The SurrealQL query pattern for combined graph+vector search is documented in knowledge-graph-engine.md Section 3.3 (SEARCH)
- Alpha=0.7 means vector similarity dominates by default; users who prefer graph-heavy results can lower alpha
- Graph proximity scoring: 1.0 (direct hit), 0.5 (1-hop neighbor), 0.25 (2-hop) -- exponential decay
- Performance targets from global-intelligence.md Section 10: vector search ~5-15ms, cross-project graph+vector ~10-30ms
- The search module lives at `daemon/search.rs` (not in kg/) because it's a cross-cutting concern that combines vector, graph, and source retrieval
