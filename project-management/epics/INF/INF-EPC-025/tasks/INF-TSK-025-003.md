# INF-TSK-025-003: Unix Domain Socket IPC Server + Protocol

## Description

Implement the IPC layer for communication between `codeflow` CLI clients and the global daemon. The server listens on a Unix domain socket at `~/.codeflow/db.sock` with restrictive permissions (0o600). Communication uses a length-prefixed JSON protocol: each message starts with a 4-byte big-endian length header followed by the JSON body.

The protocol defines typed Request and Response enums covering all daemon operations (register, search, sync, query, etc.) and an ErrorResponse type for structured error reporting. Concurrent connections are handled via `tokio::spawn` per accepted connection, enabling multiple `codeflow` processes to communicate with the daemon simultaneously.

This is the largest task in Phase C1 due to the protocol design, serialization layer, connection lifecycle management, and error handling complexity.

## Approach

1. Define the wire protocol in `protocol.rs`:
   - Message frame: `[4 bytes: u32 BE length][N bytes: UTF-8 JSON body]`
   - `Request` enum with 8 variants, each carrying its specific payload:
     - `Ping` -- no payload
     - `Register { project_id, name, repo_path, repo_url, area_prefixes }`
     - `Search { query, limit, scope, project_filter }`
     - `Sync { project_id, force }`
     - `Status` -- no payload
     - `Query { surql, params }`
     - `Rebuild { dry_run }`
     - `Shutdown` -- no payload
   - `Response` enum with 9 variants matching request types
   - `ErrorResponse { code: ErrorCode, message: String }`
   - Protocol version field (`version: u32 = 1`) in message envelope
2. Implement frame codec in `protocol.rs`:
   - `encode_message(msg: &impl Serialize) -> Result<Vec<u8>, IpcError>` -- serialize to JSON, prepend length
   - `decode_message<T: DeserializeOwned>(reader: &mut impl AsyncRead) -> Result<T, IpcError>` -- read length, read body, deserialize
   - Enforce 16MB maximum message size
3. Implement IPC server in `ipc.rs`:
   - `IpcServer::new(socket_path, handler)` -- creates server with request handler callback
   - `IpcServer::start()` -- binds socket, sets permissions, enters accept loop
   - `IpcServer::shutdown()` -- stops accepting, drains connections, removes socket file
   - Per-connection handler via `tokio::spawn`:
     - Read request frame
     - Dispatch to handler
     - Write response frame
     - Loop until connection closed or idle timeout (60s)
4. Set socket file permissions to 0o600 using `std::os::unix::fs::PermissionsExt`
5. Implement idle connection tracking: each connection tracks last activity timestamp, idle connections closed after 60 seconds
6. Implement graceful shutdown: on Shutdown request, stop accept loop, send ShutdownAcknowledged, wait for in-flight requests, remove socket file
7. Write tests:
   - Protocol tests: roundtrip encode/decode for all request/response variants
   - Server tests: connect, ping/pong, concurrent connections, idle timeout, max message size rejection

## Acceptance Criteria

1. IPC server listens on Unix domain socket at `~/.codeflow/db.sock`
2. Socket file created with 0o600 permissions (owner read/write only)
3. Length-prefixed JSON protocol: 4-byte big-endian header specifying JSON body length, followed by UTF-8 JSON body
4. Request enum with 8 variants: `Ping`, `Register`, `Search`, `Sync`, `Status`, `Query`, `Rebuild`, `Shutdown`
5. Response enum with 9 variants: `Pong`, `Registered`, `SearchResults`, `SyncComplete`, `StatusReport`, `QueryResult`, `RebuildStarted`, `ShutdownAcknowledged`, `Error`
6. `ErrorResponse` struct with `code` (`ErrorCode` enum) and `message` fields
7. `ErrorCode` enum with variants: `InvalidRequest`, `NotFound`, `Unauthorized`, `InternalError`, `Timeout`, `RateLimited`
8. Concurrent connections handled via `tokio::spawn` per accepted connection
9. Connection timeout: idle connections closed after 60 seconds of inactivity
10. Maximum message size: 16MB (reject larger messages with `ErrorCode::InvalidRequest`)
11. Server gracefully shuts down when receiving `Shutdown` request: drain connections, remove socket file
12. Protocol version field in every request/response for future compatibility (`version: 1`)

## Notes

- Source: global-intelligence.md Section 2 (Architecture) and Section 4 (Daemon Architecture)
- Unix domain socket chosen over TCP for security (local-only, no network exposure), latency (~1-2ms vs ~2-5ms TCP), and no port conflicts (decisions.md D18)
- The `tokio::net::UnixListener` provides async accept with automatic backpressure
- Protocol versioning enables future evolution without breaking existing clients. Version check: if client sends version > server supports, respond with Error(InvalidRequest, "unsupported protocol version")
- Consider using `tokio-util::codec` for the frame codec implementation -- LengthDelimitedCodec provides exactly the 4-byte BE length framing needed
- The `handler` callback in IpcServer is a trait object (`Box<dyn Fn(Request) -> Response + Send + Sync>`) for testability -- tests can inject mock handlers
