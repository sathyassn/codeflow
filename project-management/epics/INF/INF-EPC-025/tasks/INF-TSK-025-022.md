# INF-TSK-025-022: KG Configuration System

## Description

Implement the configuration system for the knowledge graph engine via `codeflow-knowledge.toml`. This file controls all aspects of KG behavior: which entity and relationship types are recognized (ontology), how extraction is performed (model selection, rate limits, source filters), embedding model settings, MEMIFY schedule and thresholds, search defaults, and trigger points.

The configuration supports extending the default ontology with custom entity and relationship types per project, enabling teams to define domain-specific concepts beyond the built-in 16 entity types and 18 relationship types. All configuration values are validated on load, with clear error messages for invalid values.

## Approach

1. Define `KgConfig` struct using serde with 5 nested sections:
   - `OntologyConfig`: default_entity_types (Vec<String>), custom_entity_types (Vec<EntityTypeDef>), default_relationship_types, custom_relationship_types
   - `ExtractionConfig`: enabled (bool), model (enum: Onnx/Claude/Codex/Gemini/None), model_paid (option), rate_limit_seconds (u64, default 2), sources (SourcesConfig with bools for ledger/tasks/sessions/code/docs), code_patterns (Vec<String>), code_exclude (Vec<String>)
   - `EmbeddingConfig`: model_path (PathBuf), dimensions (u32, default 384), download_url (String), checksum (String)
   - `MemifyConfig`: enabled (bool), schedule_hours (u32, default 24), pruning (PruningConfig: max_age_days, confidence_threshold, stale_check_interval), inference (InferenceConfig: enabled, min_confidence)
   - `SearchConfig`: default_alpha (f32, 0.7), default_limit (usize, 10), default_threshold (f32, 0.7), default_scope (String, "visible")
2. Define `TriggerConfig` section: on_task_complete (bool), on_session_end (bool), on_memory_event (bool), on_idle (bool), manual_only (bool)
3. Implement `KgConfig::load(path)` -- read TOML file, deserialize with serde, apply defaults for missing fields
4. Implement `KgConfig::validate()` -- check all constraints:
   - Thresholds between 0.0 and 1.0
   - Positive batch sizes and intervals
   - Valid model names
   - Non-empty names for custom types
   - Dimensions match model (384 for all-MiniLM-L6-v2)
5. Implement `KgConfig::default()` -- generate default configuration with all built-in types and sensible defaults
6. Implement `KgConfig::save(path)` -- write default config to TOML on first use
7. Implement `KgConfig::merged_entity_types()` and `merged_relationship_types()` -- combine default + custom types
8. Write tests for loading, validation, defaults, custom type extension, and invalid value rejection

## Notes

- Full config schema documented in knowledge-graph-engine.md Section 10 (Configuration)
- The toml crate handles deserialization; serde provides the derive macros
- Custom type extension (not replacement) is important: custom_entity_types ADDS to the default 16, it doesn't replace them
- Trigger points map to the COGNIFY/MEMIFY trigger matrix in knowledge-graph-engine.md Section 9
- The steering section (boost/suppress entity types) affects both extraction prompts and search ranking
- Config file location: project root `.codeflow/config/codeflow-knowledge.toml` (per-project) or `~/.codeflow/codeflow-knowledge.toml` (global default)
