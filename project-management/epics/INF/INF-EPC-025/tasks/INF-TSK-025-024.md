# INF-TSK-025-024: Platform Service Integration

## Description

Implement platform-specific service registration for the codeflow daemon so it starts automatically on user login and restarts on crash. This supports macOS (launchd) and Linux (systemd), the two primary platforms for CodeFlow. Service registration is performed via `codeflow db install-service` and removed via `codeflow db uninstall-service`.

On macOS, a launchd property list (plist) is installed at `~/Library/LaunchAgents/dev.codeflow.daemon.plist` with `RunAtLoad: true` (starts on login) and `KeepAlive: true` (auto-restarts on crash). On Linux, a systemd user unit is installed at `~/.config/systemd/user/codeflow-daemon.service` with `WantedBy=default.target` and `Restart=on-failure`.

Template files are shipped in the codeflow binary's resources directory and populated with the actual binary path at install time. Platform is auto-detected via `std::env::consts::OS`.

## Approach

1. Define `PlatformService` trait with methods: `install()`, `uninstall()`, `status()`, `is_installed() -> bool`
2. Define `MacOsService` struct implementing PlatformService:
   a. `install()`: write plist from template to `~/Library/LaunchAgents/dev.codeflow.daemon.plist`, substitute `{CODEFLOW_BIN}` with actual binary path, run `launchctl load -w {plist_path}`
   b. `uninstall()`: run `launchctl unload {plist_path}`, remove plist file
   c. `status()`: run `launchctl list | grep dev.codeflow.daemon`, parse output
   d. `is_installed()`: check if plist file exists
3. Define `LinuxService` struct implementing PlatformService:
   a. `install()`: write unit file from template to `~/.config/systemd/user/codeflow-daemon.service`, substitute `{CODEFLOW_BIN}`, run `systemctl --user daemon-reload && systemctl --user enable --now codeflow-daemon.service`
   b. `uninstall()`: run `systemctl --user disable --now codeflow-daemon.service`, remove unit file, run `systemctl --user daemon-reload`
   c. `status()`: run `systemctl --user status codeflow-daemon.service`, parse output
   d. `is_installed()`: check if unit file exists
4. Define `platform_service() -> Box<dyn PlatformService>` factory function using `std::env::consts::OS` to select implementation
5. Create macOS plist template in `codeflow-rs/resources/dev.codeflow.daemon.plist`:
   - Label: dev.codeflow.daemon
   - ProgramArguments: ["{CODEFLOW_BIN}", "db", "daemon", "start", "--foreground"]
   - RunAtLoad: true
   - KeepAlive: true
   - StandardOutPath/StandardErrorPath: ~/.codeflow/logs/daemon.log
6. Create Linux systemd template in `codeflow-rs/resources/codeflow-daemon.service`:
   - ExecStart={CODEFLOW_BIN} db daemon start --foreground
   - WantedBy=default.target
   - Restart=on-failure
   - RestartSec=5
7. Implement idempotency: check `is_installed()` before install (skip if already installed), check before uninstall (skip if not installed)
8. Handle unsupported platforms: return descriptive error "Platform {os} is not supported for service registration"
9. Write tests using mock filesystem and command execution for CI compatibility

## Acceptance Criteria

1. macOS: launchd plist generated at ~/Library/LaunchAgents/dev.codeflow.daemon.plist with RunAtLoad and KeepAlive
2. Linux: systemd unit generated at ~/.config/systemd/user/codeflow-daemon.service with WantedBy=default.target and Restart=on-failure
3. Platform auto-detection via std::env::consts::OS to select launchd (macOS) or systemd (Linux)
4. install_service() writes template file and runs platform-specific registration (launchctl load / systemctl --user enable)
5. uninstall_service() stops the service and removes the template file (launchctl unload / systemctl --user disable)
6. Install and uninstall are idempotent -- running twice produces no errors
7. Template files stored in codeflow-rs/resources/ and populated with the actual codeflow binary path at install time
8. Service status queryable via platform-specific commands (launchctl list / systemctl --user status)
9. Appropriate error messages for unsupported platforms (Windows, other Unix)

## Notes

- Service registration details from global-intelligence.md Section 4 (Daemon Architecture) and global-intelligence.md Section 11 (CLI Commands)
- macOS plist: Label=dev.codeflow.daemon, RunAtLoad=true, KeepAlive=true -- standard launchd conventions
- Linux systemd: user unit (not system), WantedBy=default.target, Restart=on-failure, RestartSec=5
- The `--foreground` flag on the daemon command is important -- launchd and systemd manage the process lifecycle, so the daemon should NOT daemonize itself
- Template substitution: only {CODEFLOW_BIN} needs to be replaced at install time; all other paths are derived from ~/.codeflow/
- CI tests must NOT actually install services; use mock filesystem and command execution assertions
