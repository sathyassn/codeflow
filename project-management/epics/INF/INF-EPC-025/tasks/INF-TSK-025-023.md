# INF-TSK-025-023: Context Search & KG Bootstrap CLI Commands

## Description

Implement the CLI command layer for knowledge graph operations. This adds two command groups to the `codeflow` binary: `context search` for semantic search across the knowledge graph, and `kg` for knowledge graph management (bootstrap, extract, stats, refine).

The `context search` command is the primary user-facing interface for the knowledge engine. It accepts a natural language query, generates an embedding, runs the GRAPH_COMPLETION hybrid search pipeline, and displays results with entity names, types, confidence scores, and source records. The `--json` flag enables machine-readable output for agent integration.

The `kg` subcommands provide manual control over KG operations: `bootstrap` for initial graph construction, `extract` for triggering COGNIFY, `stats` for graph health monitoring, and `refine` for triggering MEMIFY.

## Approach

1. Define `context search` Clap subcommand:
   - Positional arg: query (String, required)
   - `--limit N` (default 10)
   - `--scope project|visible|global` (default "visible")
   - `--project <name>` (filter to specific project)
   - `--include-graph` (include graph-expanded results, default true)
   - `--json` (JSON output instead of human-readable)
2. Implement search handler:
   a. Build SearchRequest from CLI args
   b. Call SearchEngine.search()
   c. Format results: human-readable table (default) or JSON (--json)
   d. Human-readable format: rank, entity name, type, score, snippet of description
3. Define `kg` Clap subcommand group with subcommands:
   - `kg bootstrap [--full] [--since "YYYY-MM-DD"] [--incremental]`
   - `kg extract [--batch-size N]`
   - `kg stats [--json]`
   - `kg refine [--dry-run]`
4. Implement `kg bootstrap`:
   a. If --full: scan all git history, process all markdown/code matching config patterns
   b. If --since: only process commits after the given date
   c. If --incremental (default): process only changes since last bootstrap
   d. Show progress: "Processing X of Y files...", "Extracting entities...", "Generating embeddings..."
   e. Run MEMIFY once after initial extraction
5. Implement `kg extract`:
   a. Poll extraction queue for pending entries
   b. Run CognifyPipeline on the batch
   c. Display results: entities extracted, relationships created
6. Implement `kg stats`:
   a. Query entity count grouped by entity_type
   b. Query relationship count grouped by relationship_type
   c. Query embedding count (entities with non-null embedding)
   d. Query extraction queue status (pending/processing/processed/failed counts)
   e. Show last MEMIFY run timestamp
7. Implement `kg refine`:
   a. If --dry-run: report what would be changed without modifying
   b. Otherwise: run MemifyPipeline.run() and display statistics
8. Add graceful error handling: if daemon unavailable, suggest `codeflow db daemon start`
9. Write CLI integration tests for each command
