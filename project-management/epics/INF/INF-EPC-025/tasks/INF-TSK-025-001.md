# INF-TSK-025-001: Core Domain Types and Error Enums

## Description

Define all foundational types for the Global Intelligence Layer daemon module. This is the type foundation that every other task in Epic C depends on. The types module provides newtype wrappers for type-safe identifiers, status enums for daemon/project/sync/extraction lifecycle tracking, the full knowledge graph ontology (16 entity types, 18 relationship types from the KG engine analysis), core data structures for entities, relations, projects, sync results, and search results, and trait definitions for embeddable and project-scoped behavior.

The error module defines 7 domain-specific error enums using `thiserror` derive macros, covering all error domains in the daemon subsystem: daemon lifecycle, IPC communication, sync engine, graph operations, embedding generation, knowledge extraction, and project registry.

These types are consumed by every subsequent task in the epic and establish the Rust idioms (newtype wrappers, thiserror enums, serde derives) used throughout the daemon module.

## Approach

1. Create the `daemon` module directory under `codeflow-rs/codeflow-core/src/` with `mod.rs` re-exporting public types
2. Implement newtype wrappers in `types.rs`:
   - `ProjectId(String)` -- wraps `proj_{hash}` format identifiers
   - `EntityId(ulid::Ulid)` -- wraps ULID for KG entities
   - `RelationId(ulid::Ulid)` -- wraps ULID for KG relations
   - `SyncCursor(String)` -- wraps file-offset-based cursor position
   - Derive: `Display`, `FromStr`, `Serialize`, `Deserialize`, `PartialEq`, `Eq`, `Hash`, `Clone`, `Debug`
3. Implement status enums: `DaemonStatus`, `ProjectStatus`, `SyncStatus`, `ExtractionStatus` with serde rename_all = "snake_case"
4. Implement KG ontology enums: `EntityType` (16 variants from KG engine analysis Section 3.2), `RelationType` (18 variants from Section 3.2)
5. Implement core data structures:
   - `Entity` -- id: EntityId, entity_type: EntityType, name: String, description: String, source_table: String, source_id: String, embedding: Option<Vec<f32>>, confidence: f32, created_at: DateTime, updated_at: DateTime, project: ProjectId
   - `Relation` -- id: RelationId, from_entity: EntityId, to_entity: EntityId, relation_type: RelationType, confidence: f32, source: RelationSource, metadata: serde_json::Value, created_at: DateTime
   - `RelationSource` -- enum with variants: Embedding, Manual, Sync, Extraction
   - `ProjectRecord` -- project_id, name, repo_path, repo_url (Option), area_prefixes, registered_at, last_synced (Option), sync_cursor (Option)
   - `SyncResult` -- accepted: u32, rejected: u32, new_cursor: SyncCursor, errors: Vec<SyncItemError>
   - `SearchResult` -- entity_id: EntityId, project_id: ProjectId, project_name: String, score: f32, title: String, summary: String, entity_type: EntityType
6. Define traits:
   - `Embeddable` -- `fn to_embedding_text(&self) -> String` for types that can be embedded
   - `ProjectScoped` -- `fn project_id(&self) -> &ProjectId` for project-scoped records
7. Implement error enums in `errors.rs` using `thiserror::Error` derive:
   - `DaemonError` -- variants: NotRunning, AlreadyRunning, Timeout(u64), Socket(io::Error), Shutdown, PidFile(io::Error), ProcessSpawn(io::Error)
   - `IpcError` -- variants: InvalidMessage(String), SerializationFailed(serde_json::Error), ConnectionReset, ProtocolViolation(String)
   - `SyncError` -- variants: ProjectNotFound(ProjectId), LedgerReadFailed(io::Error), CursorInvalid(SyncCursor), SchemaVersion(u32, u32)
   - `GraphError` -- variants: EntityNotFound(EntityId), RelationExists(RelationId), CycleDetected, DepthExceeded(u32)
   - `EmbeddingError` -- variants: ModelLoadFailed, InferenceFailed, DimensionMismatch, ModelNotFound
   - `ExtractionError` -- variants: QueueEmpty, LlmUnavailable, ParseFailed(String), DeduplicationConflict(EntityId)
   - `RegistryError` -- variants: ProjectNotFound(ProjectId), DuplicateProject(ProjectId), PathNotExists(PathBuf), InvalidProjectId(String)
8. Write proptest tests for newtype roundtrips (serialize -> deserialize identity)
9. Write insta snapshot tests for JSON serialization of all enum variants and key data structures
