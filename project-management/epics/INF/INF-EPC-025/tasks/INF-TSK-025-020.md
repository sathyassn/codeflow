# INF-TSK-025-020: MEMIFY Refinement Pipeline

## Description

Implement the MEMIFY refinement pipeline that continuously evolves the knowledge graph based on usage patterns, age, and structural analysis. Unlike COGNIFY (which builds the graph from text), MEMIFY improves the existing graph through five operations: edge reweighting (strengthen useful connections, decay unused ones), stale entity pruning (remove orphaned or untouched entities), near-duplicate merge (find and merge entities that slipped past initial dedup), transitive inference (derive new relationships from existing chains), and community detection (group related entities for higher-level navigation).

MEMIFY is inspired by Cognee's memify() pipeline (knowledge-graph-engine.md Section 2.3) and runs on a configurable schedule (default every 6-24 hours). All operations are idempotent -- running MEMIFY multiple times produces the same result, making it safe for scheduled execution.

## Approach

1. Define `MemifyPipeline` struct holding references to KgStore, EmbeddingEngine, and Deduplicator
2. Implement `run()` method that executes all 5 operations in sequence:

**Operation 1: Edge Reweighting**
3. Track search queries and traversed edges (log which edges appear in search results)
4. For frequently traversed edges: `UPDATE knows SET confidence = math::min(confidence * 1.1, 1.0) WHERE id IN $traversed_edges`
5. For edges not traversed in 30 days: `UPDATE knows SET confidence = confidence * 0.95 WHERE id NOT IN $recent_traversed AND updated_at < time::now() - 30d`

**Operation 2: Stale Entity Pruning**
6. Find orphaned entities: `SELECT id FROM entity WHERE count(->knows) = 0 AND count(<-knows) = 0`
7. Find untouched entities: `SELECT id FROM entity WHERE updated_at < time::now() - 90d` (configurable via pruning.max_age_days)
8. Delete orphaned + untouched entities; log deletions for audit

**Operation 3: Near-Duplicate Merge**
9. Find high-similarity pairs: for each entity, check if any other entity of the same type has embedding cosine similarity > 0.95
10. Merge using Deduplicator.merge_entities() (canonical = higher confidence, redirect edges)

**Operation 4: Transitive Inference**
11. Pattern: if entity A has relationship R to entity B, and entity B has relationship R to entity C, infer A->R->C
12. Inferred confidence = confidence(A->B) * confidence(B->C)
13. Only create inferred edge if confidence > threshold (0.3) and edge doesn't already exist
14. Mark inferred edges with source = "transitive_inference"

**Operation 5: Community Detection (Label Propagation v1)**
15. Initialize each entity with its own label
16. Iteratively: each entity adopts the most common label among its neighbors
17. Converge until labels stabilize (max 100 iterations)
18. Store community assignments as entity metadata: `UPDATE entity SET community = $label WHERE id = $id`

19. Add statistics collection and logging for each operation
20. Write tests for each operation independently and for the full pipeline

## Acceptance Criteria

1. Edge reweighting: boost confidence of edges that appear in search result traversals, decay confidence of edges never traversed
2. Stale entity pruning: remove entities with no relations AND no search hits in 90 days (configurable)
3. Near-duplicate merge: find entity pairs with embedding similarity > 0.95, merge within same project using Deduplicator
4. Transitive inference: if A->B and B->C exist with relationship type R, infer A->C with confidence = product of individual confidences
5. Community detection via label propagation (v1): group densely connected entities, assign community labels
6. All MEMIFY operations are idempotent -- running twice produces the same result
7. Configurable schedule: default every 6-24 hours via daemon timer or cron/launchd
8. MemifyPipeline struct with run() method that executes all 5 operations in sequence
9. Each operation logs statistics: entities pruned, edges reweighted, merges performed, inferences added, communities found

## Notes

- Cognee reference: knowledge-graph-engine.md Section 2.3 (MEMIFY: Prune stale nodes, Strengthen frequent connections, Reweight edges, Add derived facts)
- Community detection: label propagation is chosen as v1 because it's simple to implement without a graph algorithm library (Open Question #7 in knowledge-graph-engine.md). More sophisticated algorithms (Louvain, spectral) can be added later.
- Edge decay rate (0.95 per cycle) means edges not traversed in ~14 cycles (~84 days at daily schedule) drop below 0.5 confidence and ~28 cycles drop below 0.3 threshold
- Transitive inference only applies to same-type relationships (A->uses_pattern->B->uses_pattern->C) -- cross-type inference is deferred
- The 90-day stale threshold is configurable via codeflow-knowledge.toml [knowledge.pruning] section
- Open Question #7: without SurrealDB GDS equivalent, community detection uses label propagation. PageRank-style importance ranking is deferred.
