# INF-TSK-025-015: Local ONNX Embedding Engine

## Description

Implement the local embedding engine that generates 384-dimensional vector embeddings using the all-MiniLM-L6-v2 ONNX model via the `ort` crate (ONNX Runtime for Rust). This provides fully offline, zero-cost embedding generation for the knowledge graph -- no external API calls, no per-query charges, no internet dependency.

The engine wraps an `ort::Session` behind `Arc<Mutex<>>` for thread-safe concurrent access from the daemon's async runtime. Tokenization uses the `tokenizers` crate (pure Rust HuggingFace tokenizers) to convert text to token IDs before ONNX inference. The model is stored at `~/.codeflow/models/all-MiniLM-L6-v2.onnx` and downloaded from HuggingFace on first use with progress reporting and checksum verification.

Vector search leverages SurrealDB's native HNSW index defined on the entity embedding field. The `search()` method constructs a SurrealQL vector similarity query with cosine distance and configurable threshold/limit parameters.

## Approach

1. Add `ort` and `tokenizers` crate dependencies to `codeflow-core/Cargo.toml`
2. Define `EmbeddingEngine` struct with fields: `session: Option<Arc<Mutex<ort::Session>>>`, `tokenizer: Option<tokenizers::Tokenizer>`, `model_path: PathBuf`, `db: Surreal<Any>`
3. Implement `new(model_dir, db)` constructor -- sets model_path to `{model_dir}/all-MiniLM-L6-v2.onnx`, does NOT load model yet (lazy init)
4. Implement `ensure_model()` -- checks if model file exists at model_path; if missing, download from HuggingFace (`sentence-transformers/all-MiniLM-L6-v2`) with progress callback and SHA-256 checksum verification
5. Implement `init_session()` -- lazy initialization of ort::Session and tokenizer on first call; wrap Session in Arc<Mutex<>> for thread safety
6. Implement `embed(text)` -- tokenize text via tokenizers crate, run inference through ort::Session, extract 384-dim output vector, normalize to unit length
7. Implement `embed_batch(texts)` -- process multiple texts in a single session lock acquisition for efficiency; tokenize all, run batch inference
8. Implement `search(query_vec, limit, threshold)` -- construct SurrealQL query: `SELECT id, name, entity_type, vector::similarity::cosine(embedding, $query_vec) AS score FROM entity WHERE vector::similarity::cosine(embedding, $query_vec) > $threshold ORDER BY score DESC LIMIT $limit`
9. Implement HNSW index initialization: `DEFINE INDEX entity_embedding ON entity FIELDS embedding HNSW DIMENSION 384`
10. Add error types: `ModelNotFound`, `ModelCorrupt`, `InferenceError`, `DownloadFailed`
11. Write tests using a small test model or mock embeddings for CI compatibility

## Notes

- Model: all-MiniLM-L6-v2 (384 dimensions, ~50MB ONNX, Apache 2.0 license)
- The `ort` crate is production-ready and widely used for ONNX inference in Rust
- Embeddings are deterministic: same model + same text = identical vector (critical for Loro CRDT sync where embeddings are regenerated locally per machine)
- Decision #23 (Knowledge Graph Synchronization): embeddings are local-only, NOT synced via CRDT -- too large (1.5KB per entity) and deterministically reproducible
- Global-intelligence.md Section 7: all-MiniLM-L6-v2 selected for ~5-10ms inference, 384-dim, offline capability
- For CI tests, use a tiny test fixture or mock the ort::Session to avoid downloading the full 50MB model
- The `tokenizers` crate provides the same tokenization as Python HuggingFace tokenizers with zero Python dependency
