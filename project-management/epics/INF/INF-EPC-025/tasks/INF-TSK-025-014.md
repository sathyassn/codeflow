# INF-TSK-025-014: Extraction Queue & INGEST Pipeline

## Description

Implement the INGEST pipeline that captures record changes via SurrealDB DEFINE EVENT triggers and queues them for knowledge graph extraction. When a task, session, or memory record is created or updated, an event trigger automatically creates an entry in the `extraction_queue` table. The queue supports batch processing with priority ordering, hash-based deduplication to prevent redundant extraction, retry logic for transient failures, and automatic cleanup of processed entries.

The extraction queue is the entry point for the COGNIFY pipeline (TSK-016). Events flow: record write -> DEFINE EVENT fires -> extraction_queue entry created -> COGNIFY polls queue -> entities extracted. This decoupling ensures that record writes remain fast (no synchronous extraction) while extraction happens asynchronously during idle time.

## Approach

1. Define the `ExtractionStatus` enum: `Pending`, `Processing`, `Processed`, `Failed`
2. Define the `extraction_queue` SurrealDB table (SCHEMAFULL) with fields: source_table, source_id, text, text_hash (SHA-256), status, priority (high/normal/low), attempts, max_attempts (default 3), error_message, created_at, updated_at, processed_at
3. Add `DEFINE INDEX queue_text_hash ON extraction_queue FIELDS text_hash UNIQUE` for dedup
4. Create `DEFINE EVENT task_ingest ON TABLE task WHEN $event IN ["CREATE", "UPDATE"]` that inserts into extraction_queue with text = concat(title, " ", description)
5. Create `DEFINE EVENT session_ingest ON TABLE session WHEN $event = "UPDATE" AND $after.summary IS NOT NONE` that inserts with text = summary
6. Create `DEFINE EVENT memory_ingest ON TABLE memory WHEN $event = "CREATE"` that inserts with text = concat(key, ": ", value), priority = "high"
7. Implement `IngestPipeline` struct with methods: `poll_pending(batch_size)`, `mark_processing(ids)`, `mark_processed(id)`, `mark_failed(id, error)`, `retry_failed()`, `clear_completed(retention_days)`, `queue_status()`
8. Implement hash-based dedup: before INSERT, compute SHA-256 of text; use the UNIQUE index to silently skip duplicates
9. Implement idle trigger detection: expose a method that the daemon's event loop calls when no other work is pending
10. Add batch processing: poll up to N entries (configurable), mark as processing, return batch for COGNIFY consumption
11. Write tests covering event triggers, dedup, batch processing, retry exhaustion, and cleanup

## Acceptance Criteria

1. extraction_queue SurrealDB table defined with ExtractionStatus lifecycle (pending -> processing -> processed | failed)
2. DEFINE EVENT triggers on task, session, and memory tables queue extraction entries on CREATE and UPDATE
3. Hash-based deduplication (SHA-256 of source text) prevents duplicate queue entries for identical content
4. Batch processing function polls pending entries ordered by priority DESC, created_at ASC
5. Idle trigger mechanism detects daemon idle state and initiates queue processing
6. Retry logic with max 3 attempts per entry; failed entries logged with error details
7. clear_completed() removes processed entries older than 7 days (configurable retention)
8. Queue status query returns counts by status (pending, processing, processed, failed)
9. All queue operations are idempotent -- re-processing the same event produces no duplicates

## Notes

- SurrealDB DEFINE EVENT ASYNC (v3.0.0+) ensures events don't block the write path
- Hash-based dedup uses SHA-256 of the normalized text content, not the source record ID -- this ensures identical text from different sources doesn't get re-extracted
- Queue priority levels: high (memory entries -- immediately relevant), normal (new records), low (updates to existing records)
- The 7-day retention for clear_completed() is configurable via `codeflow-knowledge.toml` pruning settings
- Event triggers reference: knowledge-graph-engine.md Section 3.3 (INGEST) and Section 9 (Trigger Points)
