# INF-TSK-025-007: Daemon CLI Subcommands

## Description

Implement the user-facing CLI subcommands for daemon management and project registration. These are the primary interface through which users interact with the Global Intelligence Layer. All subcommands use `clap` derive macros consistent with the Epic 0 CLI framework.

The daemon subcommands (`codeflow daemon start/stop/restart/status/install-service/uninstall-service/rebuild`) manage the daemon lifecycle. The project subcommands (`codeflow project register/link/unlink/list`) manage project-to-daemon relationships.

All subcommands support a `--json` flag for machine-readable output (enabling integration with scripts and CI). Exit codes follow the convention: 0 for success, 1 for operational errors, 2 for usage errors (bad arguments).

## Approach

1. Define `DaemonCmd` clap subcommand enum in `daemon.rs`:
   - `Start` -- no required args, optional `--foreground` flag for debug
   - `Stop` -- no args
   - `Restart` -- no args
   - `Status` -- optional `--json` flag
   - `InstallService` -- no args
   - `UninstallService` -- no args
   - `Rebuild` -- optional `--dry-run` flag
   - Global `--json` flag at the daemon command level
2. Define `ProjectCmd` clap subcommand enum in `project.rs`:
   - `Register` -- optional `--name`, `--tags` args; auto-discovers project root
   - `Link { name: String }` -- positional arg for target project name
   - `Unlink { name: String }` -- positional arg for target project name
   - `List` -- optional `--json` flag
3. Implement each daemon subcommand handler:
   - `start` -- Load config, call `DaemonManager::start()`, print PID and socket path
   - `stop` -- Load config, call `DaemonManager::stop()`, print confirmation
   - `restart` -- stop then start with error recovery
   - `status` -- Call `DaemonManager::status()`, format as table or JSON
   - `install-service` -- Detect OS, write launchd plist or systemd unit (skeleton -- full impl in INF-TSK-025-023)
   - `uninstall-service` -- Remove service file
   - `rebuild` -- Connect to daemon via IPC, send Rebuild request, stream progress
4. Implement each project subcommand handler:
   - `register` -- Discover project root (find `.git`), generate project_id, write ProjectConfig, register with daemon via IPC
   - `link` -- Connect to daemon, send RELATE query for can_access, confirm
   - `unlink` -- Connect to daemon, DELETE can_access relation, confirm
   - `list` -- Connect to daemon, query all projects, format as table with columns: name, project_id, last_synced, sync_status
5. Implement output formatting:
   - Human-readable: colored table output using `comfy-table` or similar
   - JSON: serde_json::to_string_pretty when `--json` flag is set
6. Write tests: argument parsing, output format, exit codes

## Acceptance Criteria

1. `codeflow daemon start`: starts daemon in background, prints PID and socket path, exit code 0 on success
2. `codeflow daemon stop`: graceful shutdown, prints confirmation, exit code 0; exit code 1 if not running
3. `codeflow daemon restart`: stop then start, exit code 0 on success
4. `codeflow daemon status`: prints running/stopped, PID, uptime, connected clients, data size; exit code 0 if running, 1 if stopped
5. `codeflow daemon install-service`: installs launchd plist (macOS) or systemd unit (Linux), prints service file path
6. `codeflow daemon uninstall-service`: removes service registration, prints confirmation
7. `codeflow daemon rebuild`: delegates to rebuild command, prints progress
8. `codeflow project register`: registers current project with global daemon, auto-generates project_id, exit code 0
9. `codeflow project link <name>`: creates `can_access` relation to named project, exit code 0
10. `codeflow project unlink <name>`: removes `can_access` relation, exit code 0
11. `codeflow project list`: shows all registered projects with sync status, exit code 0
12. `--json` flag on all subcommands outputs structured JSON instead of human-readable text
13. Exit codes: 0 success, 1 operational error, 2 usage error (bad arguments)
