# INF-TSK-025-008: Project Registration and Discovery

## Description

Implement the project registration system that connects local project repositories to the global daemon. Each project is identified by a deterministic `project_id` computed as `proj_{SHA-256(canonical_root_path)[0..8]}` -- the first 8 characters of the SHA-256 hash of the resolved absolute path. This ensures the same project always gets the same ID regardless of when it registers, while avoiding collisions across different project directories.

The registration process auto-discovers project metadata (name, area prefixes, git remote URL) from the filesystem, writes a local `ProjectConfig` file, and creates a project record in the global SurrealDB daemon via IPC. Duplicate detection ensures re-registration updates rather than duplicates.

## Approach

1. Implement project_id generation in `ProjectRegistry`:
   - `generate_project_id(root_path: &Path) -> ProjectId`:
     - Canonicalize path via `fs::canonicalize()` (resolves symlinks)
     - Compute SHA-256 of canonical path string
     - Format as `proj_{hex[0..8]}`
2. Implement auto-discovery:
   - `discover_project_root() -> Result<PathBuf, RegistryError>`:
     - Walk up from `std::env::current_dir()` looking for `.git` directory
     - Return error if no `.git` found before filesystem root
   - `discover_project_name(root: &Path) -> String`:
     - Try: parse git remote URL for repo name (`git config --get remote.origin.url`)
     - Fallback: use directory name
   - `discover_area_prefixes(root: &Path) -> Vec<String>`:
     - Scan `{root}/project-management/epics/` for subdirectory names
     - Each subdirectory name is an area prefix (e.g., "INF", "PLN", "DEV")
3. Implement registration flow:
   - `ProjectRegistry::register(root: Option<PathBuf>) -> Result<ProjectRecord, RegistryError>`:
     - Discover project root (or use provided path)
     - Generate project_id
     - Auto-discover name, area_prefixes
     - Write ProjectConfig to `.codeflow/config/project.toml`
     - Send IPC Register request to daemon
     - Handle duplicate: if project_id exists, update metadata
     - Return ProjectRecord
4. Implement deregistration:
   - `ProjectRegistry::deregister(project_id, remove_local_config: bool)`:
     - Send IPC query to delete project record from daemon
     - Optionally remove local `.codeflow/config/project.toml`
5. Implement listing:
   - `ProjectRegistry::list() -> Result<Vec<ProjectRecord>, RegistryError>`:
     - Query daemon for all project records
     - Include sync status per project
6. Write tests:
   - project_id determinism: same path always produces same ID
   - project_id uniqueness: different paths produce different IDs
   - Auto-discovery with mock filesystem
   - Registration roundtrip

## Notes

- Source: decisions.md D19 (Project Identity and Scoping) -- project_id format and semantics
- Source: global-intelligence.md Section 12 (Migration Path) -- registration flow
- The `proj_{hash[0..8]}` format provides 4 billion unique IDs (32 bits of entropy) which is more than sufficient for developer workstations
- Canonical path resolution is critical: `/Users/alice/code/../code/project` and `/Users/alice/code/project` must produce the same project_id
- Area prefix auto-discovery by scanning `project-management/epics/` is a CodeFlow-specific convention; projects without this directory structure can manually set area_prefixes in ProjectConfig
- Git remote URL extraction: `git config --get remote.origin.url` may fail for local-only repos -- fallback to directory name is essential
