# INF-TSK-025-005: Global SurrealDB Instance + Schema

## Description

Initialize and manage the global SurrealDB daemon database. This task creates the complete database schema for the global intelligence layer including 9 SCHEMAFULL tables for data storage, 6 graph relation tables for cross-record relationships, HNSW vector indexes for semantic search, and DEFINE EVENT triggers for the extraction queue pipeline.

The database runs in SurrealDB server mode over the Unix socket (not embedded mode). The connection uses `ws+unix://~/.codeflow/db.sock` protocol. All access is through `Arc<Surreal<Client>>` for concurrent access from multiple tokio tasks handling IPC requests simultaneously.

Schema versioning via a `_meta` table enables incremental migrations as the schema evolves across future releases. The `GlobalDb::verify_schema()` method supports the `codeflow doctor` diagnostics for detecting schema drift.

## Approach

1. Create `GlobalDb` struct wrapping `Arc<Surreal<Client>>`:
   - `GlobalDb::connect(socket_path) -> Result<Self, DaemonError>` -- connect to daemon via ws+unix://
   - `GlobalDb::init() -> Result<(), DaemonError>` -- create all tables, indexes, events if not exist
   - Store connection as `Arc<Surreal<Client>>` for clone-and-share across handlers
2. Define all 9 SCHEMAFULL tables in SurrealQL:
   - `project` -- project_id, name, repo_path, repo_url, area_prefixes, registered_at, last_synced, sync_cursor
   - `task` -- id, project (record<project>), format_id, title, status, work_type, description, created_at, updated_at, embedding
   - `session` -- id, project (record<project>), session_id, status, summary, started_at, ended_at, embedding
   - `epic` -- id, project (record<project>), format_id, title, status, area_type, created_at, updated_at
   - `event` -- id, project (record<project>), event_type, payload, timestamp
   - `memory` -- id, project (record<project>), key, value, category, created_at, embedding
   - `entity` -- id, entity_type, name, description, hash, embedding, source_records, project (record<project>), created_at, updated_at
   - `extraction_queue` -- id, source_table, source_id, text, status, priority, created_at, processed_at
   - `_meta` -- schema_version, applied_at, migration_log
3. Define 6 graph relation tables:
   - `can_access TYPE RELATION IN project OUT project` -- with scopes array, granted_at
   - `belongs_to TYPE RELATION IN task OUT epic`
   - `depends_on TYPE RELATION IN task OUT task ENFORCED`
   - `produced_in TYPE RELATION IN session OUT task`
   - `knows TYPE RELATION IN entity OUT entity` -- with relationship_type, confidence, source_record, extracted_at
   - `references_source TYPE RELATION IN entity OUT record` -- links entities to source records
4. Define HNSW vector indexes (384 dimensions for all-MiniLM-L6-v2):
   - `entity_embedding ON entity FIELDS embedding HNSW DIMENSION 384`
   - `task_embedding ON task FIELDS embedding HNSW DIMENSION 384`
   - `session_embedding ON session FIELDS embedding HNSW DIMENSION 384`
   - `memory_embedding ON memory FIELDS embedding HNSW DIMENSION 384`
5. Define DEFINE EVENT triggers for extraction queue:
   - `task_ingest ON TABLE task WHEN $event IN ["CREATE", "UPDATE"]` -- queues extraction
   - `session_ingest ON TABLE session WHEN $event = "UPDATE" AND $after.summary IS NOT NONE`
   - `memory_ingest ON TABLE memory WHEN $event = "CREATE"`
6. Implement schema versioning:
   - `_meta` table stores current schema version (integer)
   - `GlobalDb::migrate(from, to)` applies ordered migration functions
   - Initial version: 1
7. Implement `GlobalDb::verify_schema()`:
   - Query `INFO FOR DB` to list all tables
   - Compare against expected table list
   - Return `Vec<SchemaDiscrepancy>` for missing/extra tables or indexes
8. Write tests using a test SurrealDB instance (embedded mode for test isolation)
