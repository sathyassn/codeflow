# INF-TSK-028-001: Cumulative sentinel enforcement — config-driven phase and stage checks

## Description

Fix the enforcement gap where the team lead can game the PathFlow checkpoint system by marking stage tasks complete without actually spawning the required teammates. The current gate-check hook only checks if a single sentinel exists, not whether all prerequisite sentinels for that phase exist cumulatively. This allows skipping stages by completing task tracker entries without executing them.

Implement:
1. Cumulative sentinel checks — all prior phase sentinels must exist before a new phase can proceed
2. Config-driven pipeline lookups — derive required stage sentinels from pathflow-config.json per work type
3. Dynamic task-to-stage mapping — match PF{N}-TSK-{NN} identifiers to their required stage sentinels

## Approach

1. Analyze current gate-check hook implementation to understand what is checked and what gaps exist
2. Review pathflow-config.json to understand pipeline/stage sentinel relationships
3. Implement cumulative phase sentinel checking in gate-check
4. Add config-driven stage sentinel lookup based on work type
5. Add dynamic task-to-stage mapping for PF4 task tracker entries
6. Write tests for all new enforcement paths

## Notes

The core issue is that the current gate-check only validates the presence of a specific sentinel for the operation being attempted. It does not verify the chain of prior sentinels that should exist if the session progressed correctly. A team lead could register PF4-TSK-06 (WS-REV) as complete in the task tracker without the ws-dev sentinel existing, which would then allow the pf-4 phase sentinel to be created via the checkpoint hook — bypassing the actual WS-DEV stage.
