# INF-TSK-022-030: Fix session startup stale cleanup and PID management

## Description

Fix three bugs discovered in the Go `SessionStart` hook (`codeflow-cli/internal/hooks/session/start.go`) and port the same fixes to Rust (`codeflow-rs/codeflow-core/src/hooks/session_start.rs`):

1. **detectStaleSessions** — currently only emits a warning log when a stale session is detected, but does not actually perform any cleanup. Stale sessions accumulate over time and can interfere with correct session management.

2. **sweepOrphanSentinels** — currently a no-op. Sentinel files left behind by dead sessions are never cleaned up, causing pathflow gate-check to potentially block future sessions incorrectly.

3. **updateLeadPID** — called on every `SessionStart` invocation including `source=compact` and `source=resume`. This creates a race condition: if two compaction events fire rapidly, the PID file may be overwritten with a stale PID. Should only update on `source=startup`.

## Approach

1. Fix `detectStaleSessions`: after detecting a stale session, remove `.state/runtime/active-task.json` if it references that session, and reset DB `active_work` records with `status='in_progress'` for that session to `status='stale'`
2. Fix `sweepOrphanSentinels`: enumerate sentinel files under `.state/sentinels/pathflow/`, check if each session directory corresponds to an active session in the DB, and remove directories where the session is no longer active
3. Fix `updateLeadPID`: add a source guard — only proceed if `input.Source == "startup"`
4. Write unit tests for all three fixes in `start_test.go`
5. Port all three fixes to `session_start.rs` in the Rust codebase

**Implementation Summary:**
Fixed three bugs in Go SessionStart hook and ported all fixes to Rust:
1. **Bug 1 (PID guard):** `handleStaleCleanup` now only calls `updateLeadPID` on `source=resume` (user relaunched claude). On `compact/clear`, the caller is a surviving tmux teammate whose lead died -- updating PID would incorrectly claim leadership.
2. **Bug 2 (stale sweep):** Replaced `detectStaleSessions` (warn-only) and `sweepOrphanSentinels` (orphan-only) with a single `sweepAllStaleSessions` that scans ALL ses-* dirs, checks lead_pid liveness via pathflow-team.json, and removes stale session dirs + sentinel dirs + team artifacts. Second pass sweeps orphan sentinel dirs with no matching session dir.
3. **Bug 3 (stale teams):** `detectStaleTeams` now checks ALL tmux pane members (not just leadPid) and removes team dir + task list when ALL members are dead. Preserves partially-alive teams.

**Deviations from Approach:**
- The original approach described updating PID only on `source=startup`. The actual fix is more nuanced: PID is updated on `source=resume` (user relaunched) but NOT on `compact/clear` (teammate whose lead died). This is because `resume` means the user relaunched claude (new PID is valid), while `compact/clear` means the same claude process compacted context (the old lead may be dead, and the caller is a surviving teammate).
- `detectStaleSessions` and `sweepOrphanSentinels` were replaced by a single consolidated function rather than fixing each independently, since they share the same scan pattern.
- `detectStaleTeams` was changed to check tmux pane member liveness (all-dead check) rather than just leadPid, matching the more robust Go implementation.
