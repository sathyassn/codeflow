# INF-TSK-022-001: Audit Go CLI for redesign opportunities

## Description

Analyze the existing Go CLI codebase (`codeflow-cli/`) to produce a comprehensive audit document that identifies redesign opportunities for the Rust implementation. This is a planning task that informs all subsequent implementation tasks. The audit must cover all 29 internal packages and the `cmd/codeflow/` command layer, identifying patterns that simplify under Rust idioms and areas where the Go implementation has accumulated technical debt.

The Go CLI currently has 29 packages under `internal/` (`autorun`, `benchmark`, `claim`, `claude`, `cliutil`, `config`, `db`, `doctor`, `githooks`, `hooks`, `idgen`, `initialize`, `integration`, `ledger`, `pathflow`, `preflight`, `report`, `sentinel`, `session`, `settings`, `shadowtest`, `testutil`, `update`, `validate`, `verification`, `welcome`, `workgraph`, `workstate`, `worktree`) plus the `cmd/codeflow/` dispatch layer with 30+ subcommand files.

## Approach

1. Read each of the 29 Go packages under `internal/` -- identify public API surface, dependencies, test coverage
2. Map inter-package imports to identify coupling patterns and potential circular dependencies
3. Identify DRY violations: logic duplicated across packages (error handling patterns, JSON marshaling, state checking)
4. Identify Go-specific workarounds: `interface{}` type assertions, string-typed enums, manual JSON marshal/unmarshal, `fmt.Errorf` wrapping chains
5. Identify patterns that Rust eliminates: stringly-typed states become enums, manual JSON becomes serde derives, error wrapping chains become `thiserror` enums
6. Map each Go package to its proposed Rust module, identifying consolidations (e.g., `session` + `workstate` merge) and splits
7. List all CLI subcommands with their Go handler functions for the Clap dispatch mapping
8. Produce the audit document with specific file:line references throughout
