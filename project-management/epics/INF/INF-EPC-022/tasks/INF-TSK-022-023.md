# INF-TSK-022-023: Coverage enforcement and lint pipeline

## Description

Configure granular coverage enforcement and lint rules for the Rust workspace with per-crate 85% coverage thresholds and strict lint enforcement.

The Rust workspace uses `cargo-llvm-cov` with per-crate or per-module coverage reporting. The coverage config lists which modules are "business logic" (enforced) vs "infrastructure" (excluded). The Go CLI's `test-config.json` is a reference for the principle of explicit module listing and threshold enforcement â not for format or tooling.

Clippy lints are configured at the crate level: `#![deny(clippy::all)]` catches common mistakes at build time, `#![warn(clippy::pedantic)]` catches style issues as warnings. Specific pedantic lints can be allowed with documented justification.

## Approach

1. Configure `cargo-llvm-cov` for per-file/per-module coverage reporting
2. Create coverage config listing business modules with 85% threshold
3. Document exclusions (test helpers, generated code, main.rs)
4. Set Clippy attributes in `lib.rs` and `main.rs`
5. Document pedantic lint exceptions with justification
6. Document cargo commands for CI: `cargo llvm-cov nextest` (coverage), `cargo clippy` (lint), `cargo fmt --check` (format)
7. Update CI job (from task 022) to use these targets
8. Generate coverage report as CI artifact
