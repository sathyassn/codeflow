# INF-TSK-022-020: Build contract conformance test suite

## Description

Build an automated test suite that runs both the Go and Rust binaries against the same inputs and verifies they produce identical outputs. This is the migration safety net -- any behavioral difference between the two binaries is caught here before cutover.

The test harness feeds the same stdin JSON to both `codeflow-cli/codeflow` (Go) and `codeflow-rs/target/debug/codeflow` (Rust), captures stdout/stderr/exit-code from each, and diffs the results. Any difference is a test failure.

Coverage must include all hook event types (SessionStart, PreToolUse, PostToolUse, TaskCompleted, Stop, SessionEnd, UserPromptSubmit), all CLI subcommands that produce output, and all exit code paths.

## Approach

1. Create test harness that builds both Go and Rust binaries
2. Create fixture files with representative stdin JSON for each hook event
3. For each hook event: run Go binary, capture output; run Rust binary, capture output; diff
4. For each CLI subcommand: run both binaries with same args, diff output
5. For exit code paths: test all three exit codes (0, 1, 2) per hook type
6. For file I/O: set up temp directory, run both binaries, diff generated files
7. Use `assert_cmd` crate for binary invocation and output capture
8. Generate test report showing coverage of each contract

## Notes

The conformance test suite is the primary safety net for the Go-to-Rust migration. It must be comprehensive enough that passing conformance guarantees the Rust binary is a drop-in replacement. The Go binary remains the reference implementation until Phase 0G cutover. After cutover, these tests become dead code (no Go binary to compare against) and can be removed or converted to standalone integration tests. Reference: `codeflow-cli/cmd/codeflow/hooks.go` for the complete list of hook subcommands.

- Requires CLI dispatch from task 018 (both Go and Rust binaries must be functional)

- Fixture JSON inputs should cover all `HookEvent` enum variants from `codeflow_core::types::enums` (task 006)
- Consumed by task 021 (shell test validation) and task 025 (cutover requires zero-diff)
- Removed or converted in task 027 (final cleanup) after Go binary no longer exists
