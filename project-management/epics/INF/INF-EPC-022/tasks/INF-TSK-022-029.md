# INF-TSK-022-029: Add pre-push test hook to enforce tests + coverage before PR

## Description

Add a `PreToolUse` hook that intercepts `git push` and `gh pr` commands and enforces that all tests pass and coverage meets the configured threshold before allowing the push to proceed. This closes the gap where code can be pushed without passing local quality gates — the current workflow relies on CI catching failures after the push, but a pre-push hook catches them earlier and faster.

The hook integrates with the existing `codeflow hooks pre-tool-use` dispatch system and uses `codeflow test` as its test runner, inheriting all existing test configuration.

## Approach

1. Add `pre-push` subcommand to `codeflow hooks pre-tool-use` dispatcher
2. Implement cache layer: hash current git tree (or staged files), store result in `.state/runtime/prepush-cache.json`; skip re-run if tree-hash matches last passing run
3. Run `codeflow test --mode {essential|full} --coverage` as subprocess, capture exit code and coverage output
4. Parse coverage output for threshold check (compare against value from `test-config.json`)
5. Emit structured result to stderr: test count, coverage %, verdict, elapsed time
6. Respect bypass: check `CODEFLOW_SKIP_PREPUSH` env var and `--no-verify` flag
7. Graceful degradation: if `codeflow` binary not found, emit warning and exit 0 (do not block)
8. Register hook in `.claude/settings.json` PreToolUse entries for `Bash(git push*)` and `Bash(gh pr*)`
9. Write unit tests covering all branches

## Design Questions (to resolve at implementation time)

- **Test mode:** `--mode essential` (fast, ~30s) vs `--mode full` (~2-5min)? Recommend `essential` for pre-push, `full` for CI — but user to confirm.
- **Cache granularity:** Per git tree-hash (whole repo) or per staged-files hash? Tree-hash is simpler; staged-files hash is more precise for partial commits.
- **Hotfix bypass:** `CODEFLOW_SKIP_PREPUSH=1` env var is sufficient, or should hotfix/* branches auto-bypass?

1. PreToolUse hook fires on git push and gh pr create/merge commands
2. Hook runs `codeflow test` with --coverage flag (mode TBD)
3. Hook blocks (exit non-zero) if any test fails
4. Hook blocks if coverage is below configured threshold (default 85%)
5. Hook result is cached per git tree-hash to avoid redundant re-runs on unchanged code
6. Hook is bypassable for hotfix branches via `CODEFLOW_SKIP_PREPUSH=1` or `--no-verify`
7. Hook emits structured output: test count, coverage %, pass/fail verdict, elapsed time
8. Hook gracefully degrades if codeflow binary not found (warn, do not block)
9. Unit tests cover: hook trigger conditions, cache hit/miss, bypass flag, coverage threshold check
10. All existing tests continue to pass
