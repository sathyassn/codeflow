# INF-TSK-022-015: Implement HookHandler trait and session hooks

## Description

Define the `HookHandler` trait and implement session lifecycle hooks (session-start, session-end). The `HookHandler` trait provides a unified interface for all hook implementations: parse stdin JSON into `HookInput`, process the event, and return `HookOutput` with the appropriate exit code.

The Go CLI has 21 hook entries mapped to Go handler functions. This task covers the session-related hooks (3 session-start + 2 session-end). Tool-use hooks are covered in task 016.

Hook handler implementations must preserve the exact exit code contract: 0 (allow/pass), 2 (block/deny), 1 (error/misconfiguration) -- matching Go constants ExitHookBlock=2 and ExitGeneralError=1.

## Approach

1. Define `HookHandler` trait in `traits/hook.rs`
2. Define `HookInput` and `HookOutput` structs with serde derives
3. Create `hooks/` module with session sub-module
4. Implement session-start handlers (init, instructions, logging)
5. Implement session-end handlers (cleanup, logging)
6. Write unit tests with mock stdin/stdout

## Notes

The session-start init hook is the most complex: it initializes checkpoint state, creates pathflow-active flag, sets up session directories, and writes codeflow-env.sh. Reference: `codeflow-cli/internal/hooks/session/start.go` (Go implementation).

**Session ID Consolidation (user directive):** The Go CLI has a bug where `current-session-id` is written on EVERY SessionStart regardless of source type (start.go:272, session.go:139). The Rust implementation MUST fix this by design: create/write session ID only when `source=startup`, not on compact/resume/clear. Eliminate `current-session-id` entirely -- use only `codeflow-env.sh` as the canonical session ID source. Ref: MEMORY.md "Session ID Consolidation".

**Standards references:** Follow cf-rust-standards (task 003) for trait design patterns, error handling (`HookError` with thiserror), and testing conventions.
