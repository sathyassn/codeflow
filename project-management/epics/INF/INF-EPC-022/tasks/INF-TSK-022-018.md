# INF-TSK-022-018: Implement CLI command dispatch

## Description

Port all Go CLI subcommands from `cmd/codeflow/` (30+ files) to Clap commands in the `codeflow-cli` binary crate. The CLI layer is a thin dispatch layer -- each subcommand parses arguments via Clap derive macros, calls the corresponding `codeflow-core` library function, and handles output formatting.

The Go CLI uses `cobra` for command registration; the Rust CLI uses `clap` derive macros for compile-time argument validation. Hook commands additionally read stdin JSON (matching the exact Go input contract) and write stdout JSON (matching the exact Go output contract).

This is the largest single CLI task, covering all 30+ Go command files. The key constraint: every subcommand must produce identical output (JSON format, exit codes, file I/O) to the Go binary.

## Approach

1. Create `main.rs` with Clap derive for top-level command enum
2. Create `commands/` directory with one module per command group
3. Port hook commands (highest priority -- these fire on every tool use)
4. Port db, session, workgraph, worktree commands
5. Port state, ledger, sentinel, pathflow commands
6. Port doctor, validate, test commands
7. Port config, settings, version, init, update, uninstall commands
8. Port report, normalize, coordination, githooks, shadowtest, internal commands
9. Write integration tests verifying command output matches Go output

## Notes

The Go CLI has 30+ command files in `cmd/codeflow/`. Some are trivial wrappers (version, uninstall) while others are complex (hooks.go, db.go, workgraph.go). The Clap derive macro approach eliminates much of the boilerplate that cobra requires. The `shadowtest` and `internal` commands may be omitted if they are development-only utilities that don't affect the frozen external interface. Reference: `codeflow-cli/cmd/codeflow/` (Go implementation).

**Standards references:** Follow cf-rust-standards (task 003) for CLI layer conventions: `anyhow` for error handling at the binary boundary (NOT `thiserror`), Clap derive macros for argument parsing. Business logic stays in `codeflow-core`; the CLI crate is thin dispatch only.

**Go source reference:** `codeflow-cli/cmd/codeflow/main.go` and `codeflow-cli/cmd/codeflow/init.go` (cobra command tree registration).

**Cross-task coherence:**
- Dispatches to ALL codeflow-core modules: hooks (tasks 015-017), DataStore (task 009), LedgerWriter (task 010), session (task 011), worktree (task 012), workgraph (task 013), utilities (task 014)
- Uses `anyhow::Result` at the CLI boundary; converts from domain errors (`SessionError`, `DbError`, etc.) via `From` impls from task 006
- Stdin/stdout JSON contracts must match Go output exactly -- this is verified by task 020 (contract conformance)
- Consumed by tasks 019 (unit test port), 020 (conformance tests), 021 (shell test validation)
