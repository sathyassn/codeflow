# INF-TSK-022-024: Cross-compile release builds

## Description

Configure the Rust workspace for cross-compilation across the three target platforms: darwin-arm64 (Apple Silicon), darwin-amd64 (Intel Mac), and linux-amd64 (CI/server environments). The Go CLI currently produces binaries for these targets via `GOOS/GOARCH` flags; the Rust equivalent uses `--target` flags and cross-compilation toolchains.

Key dependencies that require cross-compilation attention: `git2` (requires libgit2 -- use `vendored` feature to bundle), `surrealdb` (embedded mode must compile for all targets), and any native dependencies these pull in.

## Approach

1. Add target triples to `rust-toolchain.toml`
2. Configure `Cargo.toml` `[profile.release]` with LTO, strip, opt-level=3
3. Test native build: `cargo build --release` on macOS ARM64
4. Test cross-compile: darwin-amd64 via `--target x86_64-apple-darwin`
5. Test cross-compile: linux-amd64 via `cross` or `cargo-zigbuild`
6. Verify `git2` vendored feature compiles on all targets
7. Verify `surrealdb` embedded compiles on all targets
8. Add CI matrix job for all 3 targets
9. Configure CI to upload release artifacts

## Notes

The main cross-compilation challenge is native C dependencies pulled in by `git2` and `surrealdb`. The `git2 = { features = ["vendored"] }` approach bundles libgit2 C source and compiles it for the target platform. SurrealDB's embedded mode (`surrealkv://`) is pure Rust and should cross-compile without issues. If cross-compilation proves problematic for Linux targets, consider using GitHub Actions' Linux runner instead of cross-compiling from macOS. Reference: `codeflow-cli/Makefile` for Go cross-compilation targets.
