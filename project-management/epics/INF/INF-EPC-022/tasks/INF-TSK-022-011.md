# INF-TSK-022-011: Implement session and state management

## Description

Port the Go `internal/session/`, `internal/workstate/`, and `internal/config/` packages into a unified Rust session module. The key improvement: `SessionStatus` is an enum with a state machine that validates transitions at compile time. The session builder pattern replaces Go's multi-parameter constructor functions.

This task consolidates three Go packages (`session`, `workstate`, `config`) into one cohesive Rust module. The Go separation was an artifact of incremental development; the Rust redesign merges them because they share state and dependencies.

## Approach

1. Create `session/mod.rs` with sub-modules (state, builder, env, active_task)
2. Implement `SessionStatus` state machine with transition validation
3. Implement `SessionBuilder` using the builder pattern
4. Port session ID generation from `internal/session/session.go`
5. Port active-task.json management from `internal/workstate/`
6. Port codeflow-env.sh management from `internal/session/`
7. Port config loading from `internal/config/`
8. Write comprehensive unit tests

**Implementation Summary:**
Consolidated Go's `session`, `workstate`, and `config` packages into a unified Rust `session` module with four sub-modules (state, builder, env, active_task) plus a converted `config` directory module. Key design decisions: (1) `SessionStatus::can_transition_to()` uses `matches!` macro for exhaustive state machine validation, (2) `SessionBuilder` validates required fields at `build()` time returning `Result<Session, SessionError>`, (3) `resolve_session_id()` extracted as internal function accepting `Option<&str>` env var value to avoid `unsafe` env::remove_var in Rust 2024 edition, (4) `SessionError::Db` variant boxed to satisfy clippy::result_large_err (DbError contains surrealdb::Error at 144+ bytes), (5) atomic file writes via tmp+rename pattern for env.rs and active_task.rs.

**Deviations from Approach:**
- `resolve_session_id()` extracted as internal function instead of directly using env vars in `current_session_id()`, because Rust 2024 edition makes `std::env::remove_var` unsafe. This avoids `unsafe` blocks while maintaining full testability.
- `SessionError::Db` variant changed from `Db(#[from] DbError)` to `Db(Box<DbError>)` with manual `From<DbError>` impl to satisfy clippy::result_large_err (DbError contains surrealdb::Error at 144+ bytes).
