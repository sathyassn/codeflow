# INF-TSK-022-016: Implement tool-use hooks

## Description

Implement all PreToolUse, PostToolUse, and TaskCompleted hook handlers. These are the enforcement backbone of PathFlow -- they gate operations based on sentinel state, enforce scope restrictions, and manage checkpoint progression.

This is the largest hook implementation task, covering 7 PreToolUse handlers, 4 PostToolUse handlers, and 1 TaskCompleted handler. Each handler implements the `HookHandler` trait from task 015.

Key handlers:
- **gate-check**: The primary PathFlow enforcement gate. Blocks Edit/Write before pf-3 sentinel exists. Blocks git push/PR before pf-5 + ws-rev sentinels exist.
- **sentinel-write**: Creates stage sentinels by pattern-matching on "STAGE-COMPLETE: WS-{stage}" in messages.
- **checkpoint-register/complete**: The three-layer checkpoint system that creates phase sentinels.

## Approach

1. Implement PreToolUse handlers in `hooks/pre_tool_use.rs`
2. Implement PostToolUse handlers in `hooks/post_tool_use.rs`
3. Implement TaskCompleted handler in `hooks/task_completed.rs`
4. Port sentinel file I/O from `internal/sentinel/`
5. Port checkpoint state management from `internal/pathflow/`
6. Write unit tests with mock filesystem state

## Notes

**UUID Session ID Bug (INF-TSK-013-002):** 10 Go hook handlers use the Claude per-agent UUID from stdin instead of `CODEFLOW_SESSION_ID`. This causes sentinel lookups, logging directory creation, and guard checks to use wrong paths. The Rust implementation fixes this by design: all hook handlers MUST source `codeflow-env.sh` first and use `CODEFLOW_SESSION_ID` from environment, never the raw stdin `session_id`. Affected Go hooks: HIGH: session-start-logging.sh, team-guard.sh; MEDIUM: session-start-instructions.sh, session-end-logging.sh, stop-logging.sh, user-prompt-submit-logging.sh; LOW: protected-resource.sh, stop-pathflow-gate.sh, user-prompt-submit.sh, post-tool-use-logging.sh. Ref: MEMORY.md "UUID Session ID Bug".
