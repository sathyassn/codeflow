# INF-TSK-022-019: Port Go unit tests to Rust

## Description

Port all Go unit tests from `internal/*_test.go` and `cmd/codeflow/*_test.go` to Rust `#[test]` and `#[tokio::test]`. This is not a mechanical translation -- many Go test patterns (table-driven tests, interface mocking via test doubles) have idiomatic Rust equivalents (parameterized tests via macros, trait-based mocking).

The Rust trait-based architecture enables clean unit testing via mock implementations: `MockStore` for `DataStore`, `MockWriter` for `LedgerWriter`, `MockHandler` for `HookHandler`. Property-based testing with `proptest` covers serialization roundtrips, and snapshot testing with `insta` covers JSON output format stability.

## Approach

1. Inventory Go test files and categorize by module
2. Port `internal/` package tests to `codeflow-core` module tests
3. Port `cmd/codeflow/` command tests to `codeflow-cli` integration tests
4. Add `proptest` strategies for all serde-annotated types
5. Add `insta` snapshots for hook JSON input/output and CLI command output
6. Create mock implementations for trait-based testing
7. Run `cargo nextest run` for parallel execution
8. Verify coverage meets 85% threshold via `cargo-llvm-cov`

## Notes

The Go test suite has approximately 500+ unit tests across `internal/` and `cmd/codeflow/`. The Rust port should match or exceed this count. Many Go table-driven tests can be expressed more concisely using Rust `#[test]` with helper macros. The `proptest` and `insta` additions are NEW test types not present in Go, adding stronger coverage guarantees. Reference: `codeflow-cli/config/testing/test-config.json` for Go coverage configuration.

**Standards references:** Follow cf-rust-standards (task 003) for testing conventions (`#[test]`, `#[tokio::test]`, proptest, insta, cargo-nextest).
