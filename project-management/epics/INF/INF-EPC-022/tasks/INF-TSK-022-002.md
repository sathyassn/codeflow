# INF-TSK-022-002: Define trait hierarchy and module map

## Description

Design the core trait hierarchy and module dependency graph for the Rust CLI. This document is the architectural blueprint that all Phase 0C-0E implementation tasks follow. The trait hierarchy must match the architecture defined in `data-layer-protection.md` Section 6, while the module map translates Go packages to Rust modules with appropriate consolidation and separation.

Key traits to define:
- `DataStore` -- CRUD operations for sessions, tasks, epics, workgraph (sole impl: `SurrealStore`)
- `LedgerWriter` -- append-only event logging (sole impl: `JsonlWriter`)
- `HookHandler` -- hook event processing with typed input/output

Traits deferred to Epic A (NOT defined here, but placeholders documented):
- `Coordinator` -- CRDT claim/merge/sync (impl: `LoroCoordinator` in Epic A)
- `Transport` -- delta exchange mechanism (impls: `FileTransport`, `GitRefTransport` in Epic A)

## Stage Reports

### PLAN Report

> Populated by cf-planning before STAGE-COMPLETE: WS-PLAN

**Design Decisions:**

1. **DataStore: async trait with static dispatch** -- SurrealDB operations are inherently async. Trait uses `async fn` (stable Rust 1.75+) with `Send + Sync` bounds. All consumers use static dispatch (`impl DataStore` or `<S: DataStore>`), never `dyn DataStore`, because async fn in traits is not object-safe. Typed queries replace Go's `map[string]any` pattern.
2. **DataStore: transaction is impl-specific** -- Removed `transaction<F, R>` from the trait (generic methods break object safety, and transaction semantics are implementation-specific). `SurrealStore` provides its own `transaction()` method directly. This eliminates the `futures` crate dependency.
3. **LedgerWriter: sync trait** -- JSONL appends are local file I/O with flock. No async overhead needed. All JSONL writes go through the trait (eliminates Go's session/writeJSONLEvent bypass). `dir()` returns `&std::path::Path` for proper filesystem path handling.
4. **HookHandler: sync trait with enum output** -- Hook handlers perform local file checks only. `HookOutput` enum (Allow/Block/Warn) replaces Go's `Verdict` struct with `Allow bool`, making "forgot to check" bugs impossible via exhaustive pattern matching.
5. **Two-crate structure in `codeflow-rs/`** -- `codeflow-core` (lib) defines traits, types, models, errors. `codeflow-cli` (bin) provides implementations and Clap dispatch. Workspace root is `codeflow-rs/` (coexists with Go `codeflow-cli/` during migration). Matches data-layer-protection.md Section 6.
6. **7 consolidations** -- Merged: normalization, sentinel, session+workstate, verdict, hookInput, file constants, config loading. Each eliminates a documented DRY violation from go-audit.md.
7. **Coordinator and Transport deferred** -- Documented as commented-out placeholders per task description. Implemented in Epic A.
8. **User and ProjectConfig excluded from DataStore trait** -- Both models exist as structs in `codeflow-core::models` but have no trait-level CRUD. ProjectConfig is a singleton loaded via `config::load()`. User management is deferred to Epic C (daemon mode). Rationale in Section 4.1.1.

## Notes

The trait hierarchy is the architectural foundation. `DataStore` and `LedgerWriter` are implemented in Phase 0C. `HookHandler` is implemented in Phase 0D. `Coordinator` and `Transport` are placeholders here and implemented in Epic A. The key design principle: code depends on traits, not implementations. This enables mock-based unit testing and future implementation swaps.

**Standards references:** Follow cf-rust-standards for trait design patterns (trait objects vs generics decision tree), naming conventions, and module visibility rules. Refer to `data-layer-protection.md` Section 6 for the target architecture diagram.

**Go source references for trait mapping:**
- `DataStore` maps to: `codeflow-cli/internal/db/connection.go`, `codeflow-cli/internal/db/queries.go`, `codeflow-cli/internal/db/models.go`, `codeflow-cli/internal/db/transactions.go`
- `LedgerWriter` maps to: `codeflow-cli/internal/ledger/writer.go`, `codeflow-cli/internal/ledger/routing.go`
- `HookHandler` maps to: `codeflow-cli/cmd/codeflow/hooks.go` (dispatch), `codeflow-cli/internal/hooks/` (implementations per subdirectory: gate/, edit/, team/, sentinel/, session/, etc.)
