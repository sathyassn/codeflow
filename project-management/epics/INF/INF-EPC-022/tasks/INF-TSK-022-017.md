# INF-TSK-022-017: Implement logging and autorun modules

## Description

Port the Go `internal/hooks/logging/` package (7 files: config, writer, prompt, tooluse, session, stop, doc) and `internal/autorun/` package (5 files: batch, worker, worker_real, orchestrator, doc) to Rust.

The logging module provides structured event logging for all hook lifecycle events. In Go, this uses a custom `Writer` type with JSON marshaling; in Rust, it uses the `LedgerWriter` trait with serde serialization, giving compile-time schema enforcement via the `LedgerEvent` tagged union from task 006.

The autorun module manages autonomous multi-task execution. The Go implementation uses string-based task parsing and subprocess management via `exec.Command`; the Rust implementation uses typed batch configuration with serde and `tokio::process::Command` for async subprocess management.

## Approach

1. Implement logging handlers in `hooks/logging.rs` (or `hooks/logging/` sub-module)
2. Port `Writer` -> `ActivityWriter` using `LedgerWriter` trait
3. Implement prompt, tool-use, session, and stop logging as `HookHandler` impls
4. Create `autorun/mod.rs` with sub-modules (batch, worker, orchestrator)
5. Port batch parser with typed `BatchConfig` and `BatchTask` structs
6. Port worker with `tokio::process::Command` for Claude CLI subprocess execution
7. Port orchestrator with bounded concurrency via `tokio::sync::Semaphore`
8. Write unit tests for all handlers and autorun components

## Notes

The Go logging package has 7 files but consolidates well into a single Rust module since the `Writer` type is simple. The autorun package is more complex -- the orchestrator manages multiple concurrent Claude CLI sessions, which maps naturally to Tokio async tasks with semaphore-based concurrency control. Reference: `codeflow-cli/internal/hooks/logging/` and `codeflow-cli/internal/autorun/`.

**Standards references:** Follow cf-rust-standards (task 003) for async patterns (tokio runtime), error handling, and testing conventions.
