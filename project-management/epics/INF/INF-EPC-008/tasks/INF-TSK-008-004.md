# INF-TSK-008-004: Validation scripts: validate-task.sh + validate-epic.sh

## Description

Create two deterministic shell scripts that validate task and epic YAML frontmatter fields against schema rules. These scripts provide a non-LLM validation layer that can be called at multiple points in the PathFlow pipeline (PF4-TSK-02, WS-PLAN before commit, PF6-TSK-01).

## Approach

1. Create `.codeflow/scripts/validation/` directory
2. Write `validate-task.sh`:
   - Parse YAML frontmatter from markdown file (extract between `---` delimiters)
   - Use `grep`/`sed`/`awk` to extract field values (no external YAML parser dependency)
   - Validate each rule, collecting all errors before reporting
   - Exit 0 (valid) or 1 (invalid with all errors to stderr)
3. Write `validate-epic.sh`:
   - Same parsing approach as task validation
   - Apply epic-specific rules
4. Make both scripts executable
5. Follow cf-shell-standards skill conventions

## Files

### To Create

- `.codeflow/scripts/validation/validate-task.sh` -- Task field validation script
- `.codeflow/scripts/validation/validate-epic.sh` -- Epic field validation script

## Acceptance Criteria

1. `validate-task.sh` exists at `.codeflow/scripts/validation/` and is executable
2. `validate-task.sh` checks required fields: `id`, `format_id`, `epic_id`, `title`, `status`, `area_type`, `work_type`
3. `validate-task.sh` validates `format_id` matches `^[A-Z]{2,4}-TSK-[0-9]{3}-[0-9]{3}$`
4. `validate-task.sh` validates `status` is one of: `todo`, `blocked`, `in_progress`, `awaiting_review`, `complete`
5. `validate-task.sh` validates constraint: if `auto_merge=true`, `target_branch` must be non-null and not in protected_branches
6. `validate-task.sh` validates constraint: if `raise_pr=false`, `auto_merge` must be false
7. `validate-task.sh` exits 0 for valid files, exits 1 with error messages to stderr for invalid
8. `validate-epic.sh` exists at `.codeflow/scripts/validation/` and is executable
9. `validate-epic.sh` checks required fields: `id`, `format_id`, `title`, `status`, `area_type`
10. `validate-epic.sh` validates `format_id` matches `^[A-Z]{2,4}-EPC-[0-9]{3}$`
11. `validate-epic.sh` validates `status` is one of: `draft`, `planning`, `in_progress`, `blocked`, `complete`, `archived`
12. `validate-epic.sh` exits 0 for valid files, exits 1 with error messages to stderr for invalid

## Notes

- YAML frontmatter parsing: extract content between first `---` and second `---`, then use line-by-line field extraction. Handle multi-line values (arrays) by tracking indent level.
- Protected branches list for auto_merge validation: read from enforcement-policy.json `merge_protection.protected_branches` (created by INF-TSK-008-003). If file not found, default to `["main", "master"]`.
- Status transition validation is desirable but complex (requires knowing the previous status). Initial implementation validates status VALUES only. Transition validation can be added in a follow-up.
- The scripts should handle missing optional fields gracefully (only required fields cause failure).
- Edge case: empty YAML frontmatter (just `---\n---`) should fail with "no fields found" error.
