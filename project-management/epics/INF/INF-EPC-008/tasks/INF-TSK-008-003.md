# INF-TSK-008-003: Merge protection: enforcement-policy.json + hook extension

## Description

Add configurable merge protection to prevent agents from auto-merging PRs to protected branches. This involves two changes: (1) a new `merge_protection` section in enforcement-policy.json that defines which branches are protected from automated merging, and (2) extending the existing `cf-pre-tool-use-gh-pr.sh` hook to detect `gh pr merge` commands, resolve the PR's target branch, and block if it matches a protected pattern.

## Approach

1. Add `merge_protection` section to enforcement-policy.json:

   ```json
   "merge_protection": {
     "description": "Configurable merge protection for automated PR merging",
     "protected_branches": ["main", "master", "release/*", "production"],
     "policy": "hard_block",
     "message": "BLOCKED: Cannot auto-merge to protected branch '{branch}'. Human must merge via GitHub UI.",
     "applies_to": "gh pr merge"
   }
   ```

2. Extend cf-pre-tool-use-gh-pr.sh:
   - After existing PR creation checks, add a new detection block for `gh pr merge`
   - Extract PR number from the command
   - Resolve target branch via `gh pr view {number} --json baseRefName -q .baseRefName`
   - Load protected_branches from merge_protection config
   - Match target branch against patterns (support glob with fnmatch-style matching)
   - Exit 2 with descriptive message if blocked
3. Ensure existing `gh pr create` checks remain unchanged

## Files

## Acceptance Criteria

1. enforcement-policy.json has `merge_protection` section with `protected_branches` array containing `["main", "master", "release/*", "production"]`
2. enforcement-policy.json `merge_protection.policy` is `"hard_block"`
3. cf-pre-tool-use-gh-pr.sh detects `gh pr merge` commands (in addition to existing `gh pr create`)
4. Hook resolves PR target branch via `gh pr view {number} --json baseRefName` when merge detected
5. Hook exits 2 (BLOCK) when target branch matches any pattern in `merge_protection.protected_branches`
6. Hook exits 0 (ALLOW) when target branch does not match protected patterns
7. Hook supports glob patterns (e.g., `release/*`) for branch matching
8. Block message includes the branch name: `"BLOCKED: Cannot auto-merge to protected branch '{branch}'"`

## Notes

- The existing `protected_branches` array at the root level (line 411-416) covers git branch delete operations. The new `merge_protection.protected_branches` specifically covers `gh pr merge`. They may have the same values but serve different enforcement purposes.
- The hook must handle the case where `gh pr view` fails (e.g., PR doesn't exist) -- allow through and let gh report the error.
- Glob pattern matching: use bash `case` with glob patterns or `fnmatch`-style matching for `release/*`.
- The hook uses `gh pr view` to resolve the PR target branch. PreToolUse hooks run as shell scripts with direct system access, outside the agent sandbox. The gh pr view call works without sandbox considerations.
