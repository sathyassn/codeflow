# INF-TSK-008-005: PF3 reorder + PF4 validation gate in pathflow-config.json

## Description

Two changes to pathflow-config.json: (1) Reorder PF3-CLASSIFY tasks so branch creation happens before task registration, with task registration conditional on adhoc tasks only. (2) Insert a new PF4-TSK-02 validation gate that runs validate-task-fields before work execution begins.

## Approach

1. Reorder PF3 tasks:
   - PF3-TSK-01: Classify work type (team-lead, always) -- unchanged
   - PF3-TSK-02: Spawn cf-git-operations (team-lead, always) -- moved from TSK-03
   - PF3-TSK-03: Create feature branch (cf-git-operations, always) -- moved from TSK-04, triggers pf-3 sentinel
   - PF3-TSK-04: Register task in WorkGraph (cf-knowledge-layer, CONDITIONAL: adhoc only) -- moved from TSK-02, add condition field
   - PF3-TSK-05: Begin work (cf-knowledge-layer, always) -- unchanged
2. Add condition field to PF3-TSK-04: `"condition": "adhoc_only"`
3. Insert PF4-TSK-02:
   - id: "PF4-TSK-02"
   - task_order: 2
   - description: "Validate task and epic fields before work starts"
   - assigned_to: "cf-knowledge-layer"
   - operation: "validate-task-fields"
4. Renumber existing PF4 tasks: TSK-02 -> TSK-03, TSK-03 -> TSK-04, TSK-04 -> TSK-05
5. Update PF4 task_tracker comments to reflect 5 tasks

## Files

## Notes

- The `condition` field is a new concept in pathflow-config.json. It's advisory (interpreted by the team lead), not enforced by hooks. Value `adhoc_only` means: skip this task if the current work item has `origin: planned`.
- PF4-TSK-02 validation gate calls cf-knowledge-layer with operation `validate-task-fields`. cf-knowledge-layer will invoke the validation scripts from INF-TSK-008-004.
- The task_tracker comments in PF3 and PF4 sections should be updated to reflect the new task count and IDs.
