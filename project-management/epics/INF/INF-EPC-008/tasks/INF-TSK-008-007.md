# INF-TSK-008-007: Agent definition updates: cf-git-operations, cf-knowledge-layer, cf-planning, cf-security

## Description

Update four agent definitions to reflect the new capabilities and constraints introduced by this epic: verify-pr-and-sync SOP in cf-git-operations, merge protection rules, validation integration in cf-knowledge-layer and cf-planning, and security policy documentation in cf-security.

## Approach

### cf-git-operations.md

1. Add `verify-pr-and-sync` SOP section:
   - **Interactive mode**: `gh pr checks {number} --watch --fail-fast` -> notify user "PR #{number} is ready for review" -> wait for user confirmation of merge -> `git pull origin main`
   - **Autorun + auto_merge=true**: `gh pr checks {number} --watch --fail-fast` -> `gh pr merge {number} --delete-branch` to integration branch -> `git pull origin {target_branch}`
   - **Autorun + auto_merge=false**: `gh pr checks {number} --watch --fail-fast` -> update task status to `awaiting_review` via cf-knowledge-layer -> proceed
2. Add FORBIDDEN rule: "NEVER run `gh pr merge` targeting protected branches"
3. Add integration branch documentation: `autorun/{batch-name}` convention, regular merge (not squash)

### cf-knowledge-layer.md

1. Update `ensure-work-registered` SOP: clarify it runs after pf-3 sentinel for adhoc tasks (not before branch creation)
2. Add `validate-task-fields` operation: invoke `.codeflow/scripts/validation/validate-task.sh` on the task markdown, report errors
3. Update `complete-work` operation: add validation step before status transition
4. Remove references to `auto_commit` field in operational guidance

### cf-planning.md

1. Add validation step to Step 5 (Document Plan): run `validate-task.sh` and `validate-epic.sh` on created files before requesting commit
2. Update workflow diagram to include validation checkpoint

### cf-security.md

1. Add merge protection policy to security posture section: document that `gh pr merge` to protected branches is hard-blocked by PreToolUse hook
2. Reference `enforcement-policy.json merge_protection` section
