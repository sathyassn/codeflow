# INF-TSK-008-008: Command definition updates: cf-ship, cf-autorun

## Description

Update two slash command definitions: (1) Redefine `/cf-ship` as a preparation and notification command for protected branches -- it verifies CI and notifies the user, but does NOT execute `gh pr merge` on protected branches. (2) Update `/cf-autorun` to document the integration branch convention, merge protection rules, and auto_commit deprecation.

## Approach

### cf-ship.md

1. Update command description: "Prepare and verify PR for merging"
2. Update behavior:
   - Verify CI status on the PR via `gh pr checks`
   - If CI passes: notify user "PR #{number} is ready to merge via GitHub UI"
   - If CI fails: report failures and suggest fixes
   - DOES NOT call `gh pr merge` on protected branches
   - For non-protected branches: document as future consideration
3. Update routing table entry in CLAUDE.md Section 6 (handled by INF-TSK-008-009)

### cf-autorun.md

1. Add integration branch section:
   - Convention: `autorun/{batch-name}` created off `main`
   - Workers create feature branches off integration branch
   - Worker PRs merge to integration branch via `gh pr merge --delete-branch`
   - After all workers: human reviews summary PR integration->main
2. Add validation rules:
   - `auto_merge:true` requires `target_branch` to be non-null and non-protected
   - `auto_merge:true` + `target_branch:main` is FORBIDDEN
   - Validation runs at batch parsing time
3. Deprecate `auto_commit` in batch file format docs
4. Document `awaiting_review` as terminal state for autorun workers with `auto_merge:false`
