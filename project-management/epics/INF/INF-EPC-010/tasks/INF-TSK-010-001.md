# INF-TSK-010-001: Create checkpoint hooks and state helpers

## Description

Create the two new hooks that form Layers 1 and 2 of the checkpoint enforcement system, plus the state helper functions they rely on.

**Layer 1 -- PostToolUse on TaskCreate (registration tracking):**
Fires inside the agentic loop after TaskCreate executes. Parses `tool_input.subject` for the `PF{N}-TSK-{NN}` pattern and writes registration to the session-scoped checkpoint file.

**Layer 2 -- TaskCompleted lifecycle hook (completion tracking + sentinel creation):**
Fires as a CLI lifecycle event outside the agentic loop. Parses `task_subject` for the `PF{N}-TSK-{NN}` pattern, marks the task completed in the checkpoint file, and creates the phase sentinel when all required tasks are done.

## Approach

1. Add checkpoint read/write helper functions to `cf-pathflow-state.sh`:
   - `checkpoint_read()`: Read and parse checkpoint JSON
   - `checkpoint_write()`: Write checkpoint JSON atomically
   - `checkpoint_register_task()`: Add task to registered map
   - `checkpoint_complete_task()`: Add task to completed map, check phase completion
   - `checkpoint_is_phase_complete()`: Check if all required tasks are done/skipped
   - `checkpoint_create_sentinel()`: Create phase sentinel file
2. Create `cf-post-tool-use-phase-checkpoint.sh`:
   - Match on `tool_name == "TaskCreate"`
   - Read `tool_input.subject` from stdin JSON
   - Extract `PF{N}-TSK-{NN}` via regex
   - If match: call `checkpoint_register_task()`
   - If no match: exit 0
3. Create `cf-task-completed-phase-checkpoint.sh`:
   - Read `task_subject` from stdin JSON
   - Extract `PF{N}-TSK-{NN}` via regex
   - If match: call `checkpoint_complete_task()`
   - Check if phase is now complete, if so create sentinel
   - Check dependency constraints, return exit 2 if violated
   - If no match: exit 0
4. Follow shell standards from cf-shell-standards skill
