## Description

Create a new on-demand skill `cf-pathflow-protocol` that consolidates all PathFlow lifecycle procedures currently scattered across CLAUDE.md (Sections 4, 5, 6, 7, 11) and stage completion patterns duplicated in 5 role agent definitions. This is the largest new skill (~500-600 lines) and the highest-priority task because CLAUDE.md restructuring (INF-TSK-019-008) depends on it existing.

The skill serves both the team lead (phase execution, teammate management) and role agents (stage completion, criteria reporting). Function agents (cf-git-operations, cf-knowledge-layer, cf-security) do NOT use this skill because they don't participate in stage completion protocol.

## Approach

### Cross-Reference Requirement (Principle 0: No Blind Restore)

Before writing ANY operation, the implementer MUST:

1. Read the CURRENT CLAUDE.md sections being extracted (not just the analysis map)
2. Read the CURRENT agent definitions that will consume this skill
3. Read the CURRENT command files that reference PathFlow procedures
4. Reconcile: the skill must reflect the CURRENT state of all source artifacts

### Extraction Steps

1. Read source content from CLAUDE.md:
   - Section 4.2 Execution Steps (~240 lines of step-by-step PF1-PF7 procedures)
   - Section 5 (~180 lines of spawn patterns, parallel batch, deferred shutdown, stage reporting)
   - Section 6 (~60 lines of rework loop flow details)
   - Section 7 (~130 lines of sentinel system, checkpoint details, enforcement model, graceful degradation)
   - Section 11 (~100 lines of context overflow recovery, teammate verification protocol)
2. Read stage completion patterns from role agent defs (~15 lines x 5 agents = ~75 lines):
   - cf-development, cf-planning, cf-documentation, cf-review, cf-quality-assurance
3. Organize into 5 operations: execute-phase, complete-stage, handle-rework, recover-session, manage-teammates
4. Write SKILL.md with YAML frontmatter including "Used by:" scope in description
5. Use ASCII art for all workflow diagrams (no Mermaid)
