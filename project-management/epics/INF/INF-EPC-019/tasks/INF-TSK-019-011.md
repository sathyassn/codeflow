## Description

Slim 7 primary workflow commands (cf-develop, cf-plan, cf-review, cf-test, cf-document, cf-deploy, cf-ship) by:

1. Removing inline working protocol sections (~15-20 lines per command)

### Restructuring Steps Per Command

For each of the 7 commands, apply in this order:

1. **Remove `## Working Protocol` section** -- search for this heading near the top of the file. Replace entire section with: `Working protocol: Apply cf-working-protocol skill throughout execution.`
2. **Restructure `## 4. Workflow Definition` as SPINE** (per Design Principle 6):
   - Keep the workflow diagram in `### 4.1 Workflow Diagram`
   - Annotate each diagram node with: (a) which step below elaborates it, (b) which skill operation has the HOW
   - In `### 4.2 Execution Steps`, make each step reference a skill operation instead of embedding full procedure
3. **Remove `## 5. Skills Integration`** -- content moves into the workflow diagram annotations
4. **Trim `## 6. Hooks Integration`** -- remove rows that list generic hooks (pathflow-gate, edit-write, etc.) which are the same across all commands. Keep only command-specific hook behavior.
5. **Trim `## 7. Memory Integration`** -- remove the `### 7.2 Three-Tier Data Model` subsection (~8 lines, duplicated in every command). Keep the `### 7.1 Active Work Registration` or equivalent unique subsection.
6. **Remove `## 10. References`** -- merge into workflow diagram annotations
7. **Verify** `## 1. Purpose & Usage`, `## 2. Arguments & Flags`, `## 3. Prerequisites`, `## 8. Error Handling`, `## 9. Examples` are preserved intact

### SPINE Pattern for Commands (from Design Principle 6)

The workflow diagram becomes the structural backbone. Example target format:

```text
## 4. Workflow Definition

### 4.1 Workflow Diagram

    USER invokes /cf-develop
        |
        v
    CHECK prerequisites                        --> Section 3 below
        |
        v
    CLASSIFY work type + area                   --> Step 1 below
        |                                           cf-pathflow-protocol: classify-work
        v
    CREATE branch via cf-git-operations         --> Step 2 below
        |                                           cf-pathflow-protocol: execute-phase (PF3)
        v
    SPAWN cf-development teammate               --> Step 3 below
        |                                           cf-pathflow-protocol: manage-teammates
        v
    EXECUTE WS-DEV stage                        --> Step 4 below
        |                                           cf-pathflow-protocol: execute-stage
        v
    EXECUTE WS-REV stage                        --> Step 5 below
        |                                           cf-pathflow-protocol: execute-stage
        v
    EXECUTE WS-QA stage                         --> Step 6 below
        |                                           cf-pathflow-protocol: execute-stage
        v
    VERIFY + COMPLETE                           --> Step 7 below
        |                                           cf-pathflow-protocol: complete-session
        v
    DONE

### 4.2 Execution Steps

    ### Step 1: Classify work
        WHAT: Determine work_type (FEAT/FIX/RFCT/CICD) and area.
        HOW: cf-pathflow-protocol skill, classify-work operation.
    ...
```
