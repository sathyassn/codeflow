## Description

Restore the archived `cf-db-operations` skill (468 lines at `.codeflow/docs/archived/skills/cf-db-operations/`) and update it with improvements from the current `cf-knowledge-layer` agent definition. This is NOT a simple copy -- the archived skill content must be MERGED with the relevant Execution Steps from the agent def to produce an updated skill that reflects the latest operational procedures.

The cf-knowledge-layer agent def (570 lines) contains Execution Steps Parts 1-4 with operational improvements made since the skill was archived. The persistence-related operations (record-transitions, three-tier model) must incorporate these improvements, including the canonical ledger table that maps event types to JSONL files.

## Approach

### Cross-Reference Requirement (Principle 0: No Blind Restore)

Before writing ANY operation, the implementer MUST:

1. Read the archived skill (structural base)
2. Read the CURRENT cf-knowledge-layer agent def (improvements since archival)
3. Read the CURRENT CLAUDE.md Section 10 (Memory/three-tier model) to verify alignment
4. Reconcile: the final skill must reflect the CURRENT state, not the archived state

### Restoration Steps

1. Read archived skill at `.codeflow/docs/archived/skills/cf-db-operations/SKILL.md` (468 lines)
2. Read cf-knowledge-layer agent def at `.claude/agents/cf-knowledge-layer.md` (570 lines)
3. Identify persistence-related Execution Steps in agent def (Part 4 primarily: three-tier model, JSONL append, SurrealDB queries, markdown sync)
4. **MERGE** archived skill content with agent def improvements:
   - Use archived skill as the structural base
   - Update operation procedures with any enhanced logic from agent def Execution Steps
   - Incorporate canonical ledger table (event type to file routing) from agent def
   - Add any new operations or parameters introduced in agent def since archival
   - Remove V3 references, update to V4 patterns
5. Add V4 YAML frontmatter with "Used by: cf-knowledge-layer"
6. Ensure all workflow diagrams use ASCII art (no Mermaid)

### Merge Strategy

| Operation | Archived Source | Agent Def Source | Merge Action |
|-----------|----------------|------------------|--------------|
| record-transitions | cf-db-operations:record-transitions | Agent def Part 4: Event recording, JSONL append | Merge: use archived structure, update with agent def improvements |
| Three-tier model | cf-db-operations:three-tier model docs | Agent def: canonical ledger table, persistence guarantees | Merge: incorporate ledger table from agent def |
| Query interface | cf-db-operations:queries | Agent def: SurrealDB query patterns | Merge: same approach |
| Markdown sync | cf-db-operations:markdown-sync | Agent def: Tier 2 sync procedures | Merge: same approach |

### What "merge with agent def improvements" means

1. Start with the archived skill's operation structure and procedure steps
2. Compare each procedure step with the corresponding agent def Execution Step
3. If the agent def has additional checks, parameters, or edge case handling: ADD them to the skill
4. If the agent def has reworded or clarified a procedure: USE the clearer version
5. If the agent def references V4 concepts (sentinels, pathflow phases, checkpoint system) not in the archived skill: INCLUDE them
6. If the archived skill has content NOT in the agent def: KEEP it (the skill may have detail the agent def summarized)
7. The canonical ledger table in the agent def is CRITICAL -- it MUST be included in the restored skill
