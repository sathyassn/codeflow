# INF-TSK-019-017: Update pathflow-config.json with skill operation references

> **MANDATORY VALIDATION:** Files created from this template MUST be validated against the task validation script before committing:
> `bash .codeflow/scripts/validation/validate-task.sh <file-path>`
> Fix all errors (exit code 1) before requesting a commit. Warnings are advisory.

## Description

After all artifacts are restructured (skills created, agents slimmed, commands slimmed, CLAUDE.md restructured), update `pathflow-config.json` to add a `skill` field to each `PF{N}-TSK-{NN}` entry. The `skill` field names the skill whose procedures the executor should use. Combined with the existing `assigned_to` (who) and `operation` (what), the entry becomes:

```json
{
  "id": "PF3-TSK-03",
  "assigned_to": "cf-git-operations",
  "operation": "create-branch",
  "skill": "cf-git-workflow"
}
```

The `assigned_to` and `operation` fields stay as-is. For team-lead tasks that are pure orchestration (no skill procedure), omit the `skill` field.

## Approach

### Cross-Reference Requirement

Before adding any `skill` field, the implementer MUST:

1. Read pathflow-config.json to enumerate all `PF{N}-TSK-{NN}` entries and their `assigned_to` + `operation` values
2. Read each skill SKILL.md created/restored in Phase A (001-007, 015, 016) to inventory available skills and their operations
3. Map each PathFlow task to its correct skill based on the `assigned_to` teammate and the task's domain
4. Verify every `skill` value resolves to an actual SKILL.md at `.claude/skills/{skill}/SKILL.md`
5. Verify each task's `operation` exists as a named operation within the referenced skill

### Implementation Steps

1. Read `.codeflow/config/pathflow/pathflow-config.json` -- identify all `PF{N}-TSK-{NN}` entries across all 7 phases
2. For each entry, determine the appropriate `skill` value (skill name only):
   - Tasks assigned to `cf-git-operations` --> `"skill": "cf-git-workflow"`
   - Tasks assigned to `cf-knowledge-layer` --> `"skill": "cf-memory-management"`, `"cf-task-management"`, or `"cf-db-operations"` depending on the task's domain
   - Tasks assigned to `cf-security` --> `"skill": "cf-security-operations"`
   - Tasks assigned to `team-lead` with a skill procedure --> `"skill": "cf-pathflow-protocol"`
   - Tasks assigned to `team-lead` that are pure orchestration --> omit `skill` field
   - Tasks assigned to role teammates --> skill depends on the stage and domain
3. Add `"skill": "{skill-name}"` field to each applicable task entry in the JSON
4. Verify `assigned_to` and `operation` fields are unchanged: `git diff` should show only `skill` additions
5. Verify all references resolve: for each unique `skill` value, confirm `.claude/skills/{skill}/SKILL.md` exists and contains the task's `operation` as a named operation
6. Run full test suite

### Mapping Strategy

| assigned_to | skill value | Notes |
|-------------|------------|-------|
| team-lead | `cf-pathflow-protocol` or omit | Omit for pure orchestration tasks (e.g., TaskCreate, phase bookkeeping) |
| cf-security | `cf-security-operations` | All security tasks use this skill |
| cf-knowledge-layer | `cf-memory-management`, `cf-task-management`, or `cf-db-operations` | Depends on task domain: memory lifecycle vs work classification vs persistence |
| cf-git-operations | `cf-git-workflow` | All git tasks use this skill |
| cf-development | Omit or domain skill | Role agents use inline SOPs; may reference a shared skill if applicable |
| cf-planning | Omit or domain skill | Same as above |
| cf-review | Omit or domain skill | Same as above |
| cf-quality-assurance | Omit or domain skill | Same as above |

For tasks where the executor uses inline SOPs rather than a skill procedure, omit the `skill` field entirely.
