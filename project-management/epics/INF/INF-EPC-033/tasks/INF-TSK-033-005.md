# INF-TSK-033-005: Add proactive claim TTL eviction from Loro CRDT document

## Description

Claims in the Loro CRDT document have a TTL of 4200s, but this is only checked lazily at acquire time (in `loro.rs:290`). There is no proactive eviction of expired entries. Over time, expired claim entries pile up in `state.loro` binary, growing it unnecessarily. `cleanup_dead_workers()` only runs when the sync daemon is active (multi-worktree mode). Single-worktree interactive sessions — the most common case — never trigger cleanup, leaving expired claims indefinitely.

The fix is a `compact_expired_claims(coordinator)` function in `claims.rs` that proactively removes expired entries using the `locked_binary_rmw` pattern, called from both `release_all()` and `session_end.rs`.

## Approach

1. **Implement `compact_expired_claims(coordinator: &Coordinator)`** in `codeflow-cli/core/src/coordination/claims.rs`. The function iterates all claim entries in the Loro document, identifies those where `now - claim.acquired_at >= claim.ttl_secs`, and removes them. Wrap the entire read-modify-write in `locked_binary_rmw` — the same concurrency pattern used by existing claim operations. Return count of evicted entries.

2. **Call from `release_all()`** — append a `compact_expired_claims(coordinator)` call at the end of the `release_all()` function body (currently at `claims.rs:60-83`). This ensures every session end triggers eviction even in single-worktree mode.

3. **Call from `hooks/session_end.rs` cleanup path** — add a call to `compact_expired_claims` in the session end hook's cleanup section, after any claim release operations. Use the existing `coordinator` reference available in that scope.

4. **Write unit tests** in `claims.rs` `#[cfg(test)] mod tests`: create claims with past `acquired_at` timestamps (expired) and future timestamps (not yet expired), call `compact_expired_claims`, assert expired entries removed and valid entries retained.

## Concurrency Considerations

> The Loro CRDT document is shared state. All mutations require holding the sidecar lock.

| Shared Resource | Access Pattern | Safety Mechanism |
|----------------|---------------|-----------------|
| `state.loro` CRDT document | read-modify-write (iterate + delete expired entries) | `locked_binary_rmw` from `file_lock.rs` — same pattern as existing claim operations |
| Claim entries during eviction | Read all, delete expired subset | Single lock held for entire operation — atomic from other sessions' perspective |
| `session_end.rs` cleanup | Sequential (hook runs after work completes) | No concurrent session teardown; safe to call after claim release |
