# INF-TSK-033-004: Add autorun session/worker/task_run pruning and indexes

> **MANDATORY VALIDATION:** Files created from this template MUST be validated against the task validation command before committing:

## Description

Old completed autorun sessions accumulate forever in the DB. There are no DELETE statements for autorun records anywhere in the codebase, and no indexes on `created_at` (causing slow ORDER BY) or `session_id` (causing full table scans on worker/task_run queries). This becomes a performance problem as autorun usage grows.

The three tables involved: `autorun_session`, `autorun_worker`, `autorun_task_run`. All are defined in `schema.surql`. The store interface is in `mod.rs`, the implementation in `surreal.rs`, and the CLI subcommand routing in `cmd/autorun.rs`.

## Approach

1. **Add store trait method** in `codeflow-cli/core/src/store/mod.rs`: add `prune_autorun_sessions(before: DateTime<Utc>, keep_last: usize) -> Result<PruneResult, DbError>` to the `Store` trait and `NoopStore` mock. `PruneResult` is a new struct holding `sessions_deleted`, `workers_deleted`, `task_runs_deleted`, `failures: Vec<String>`.

2. **Implement in surreal.rs** at `codeflow-cli/core/src/store/surreal.rs`: execute three DELETE statements in FK-safe order within a single async function. Each DELETE uses SurrealQL: step 1 deletes task_runs by session_id IN (SELECT id WHERE completed_at < $before AND status IN terminal_statuses), step 2 deletes workers by same session_id subquery, step 3 deletes sessions by completed_at < $before AND status IN terminal_statuses. Capture deleted record counts. On any step failure, log warning, continue, add to failures vec.

3. **Add DEFINE INDEX statements** in `codeflow-cli/core/src/store/schema.surql` (use `DEFINE INDEX ... OVERWRITE` per project SurrealDB standards): `DEFINE INDEX OVERWRITE idx_session_created ON autorun_session FIELDS created_at`, `DEFINE INDEX OVERWRITE idx_worker_session ON autorun_worker FIELDS session_id`, `DEFINE INDEX OVERWRITE idx_taskrun_session ON autorun_task_run FIELDS session_id`.

4. **Add CLI subcommand** in `codeflow-cli/cli/src/cmd/autorun.rs`: parse `autorun prune --older-than <duration>` (e.g. `30d`, `7d`, `24h`). Parse duration string to `DateTime<Utc>`. Call store `prune_autorun_sessions`. Print summary table: sessions/workers/task_runs deleted count. Support `--dry-run` (runs SELECT-only COUNT queries, prints what would be deleted without executing DELETE). On partial failure, print per-failure errors after summary, exit code 1.

5. **Write unit tests** in `surreal.rs` and `mod.rs` test modules: insert sessions with various statuses (running, completed, failed, cancelled, timeout), call `prune_autorun_sessions(before=now, keep_last=0)`, verify only terminal-status sessions deleted, verify workers and task_runs of those sessions deleted, verify running session records untouched. Test `--dry-run` returns counts without deleting.

## Concurrency Considerations

> Pruning may run while an autorun orchestrator is active. The safety mechanism is status-based filtering.

| Shared Resource | Access Pattern | Safety Mechanism |
|----------------|---------------|-----------------|
| `autorun_session` table | DELETE WHERE status IN terminals | Only terminal-status rows deleted; running sessions untouched |
| `autorun_worker` table | DELETE WHERE session_id IN (terminal sessions) | Subquery ensures only orphaned workers deleted |
| `autorun_task_run` table | DELETE WHERE session_id IN (terminal sessions) | Same subquery pattern |
| SurrealDB embedded | Concurrent queries | SurrealDB transactions — use single transaction for all three DELETEs if possible |

## Acceptance Criteria

1. `prune_autorun_sessions(before, keep_last)` store method with cascade delete in FK-safe order: DELETE task_runs first (`DELETE FROM autorun_task_run WHERE session_id IN (SELECT id FROM autorun_session WHERE completed_at < $before AND status IN $terminal_statuses)`), then workers, then sessions
2. `DEFINE INDEX OVERWRITE` statements in `schema.surql`: `DEFINE INDEX OVERWRITE idx_session_created ON autorun_session FIELDS created_at`, `DEFINE INDEX OVERWRITE idx_worker_session ON autorun_worker FIELDS session_id`, `DEFINE INDEX OVERWRITE idx_taskrun_session ON autorun_task_run FIELDS session_id`
3. CLI: `codeflow autorun prune --older-than 30d` subcommand functional. Output shows count of pruned sessions/workers/task_runs. Supports `--dry-run` flag (shows counts without deleting). Handles partial prune failures gracefully (continue on error, report failures at end, exit code 1 if any failure)
4. Only sessions with terminal status (Completed/Failed/Cancelled/Timeout) are pruned — never prune Running/Pending sessions
5. Unit tests for pruning logic with 85%+ coverage per-file (in `#[cfg(test)] mod tests` within `surreal.rs` and `mod.rs`)
6. Store trait methods (`prune_autorun_sessions`, `PruneResult`) added to `mod.rs` interface and implemented in all Store impls
