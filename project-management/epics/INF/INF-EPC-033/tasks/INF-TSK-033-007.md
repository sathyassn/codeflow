# INF-TSK-033-007: Wire session-level Timeout status and remove/document Paused/Aborting

> **MANDATORY VALIDATION:** Files created from this template MUST be validated against the task validation command before committing:
> `codeflow validate task <file-path>`
> Fix all errors (exit code 1) before requesting a commit. Warnings are advisory.

## Description

Worker-level `Timeout` is wired correctly (worker status is set to Timeout when a stage times out), but `determine_final_status()` in `orchestrator.rs` always returns `Cancelled` for aborted/timed-out batches — the session-level `AutorunSessionStatus::Timeout` variant is never actually set. Timed-out batches appear as `Cancelled` in the DB, which is misleading for diagnostics.

`Paused` and `Aborting` are in a different situation:

- **`Paused`** appears only in `types/work.rs` tests (lines 763, 782, 821) and in the `FromStr`/`Display` impl — no caller ever sets a session to `Paused`. It is pure dead code at the session status level.
- **`Aborting`** has 8 call sites in `cli/src/cmd/autorun.rs` (lines 314, 846, 906, 965, 1442, 1483, 4260, 4646). It IS actively used as a transient state in the abort flow in `cmd/autorun.rs` — but only in the CLI display/filter layer, not set by the orchestrator itself. Need to determine if it should be wired as a proper orchestrator-level transient or kept as CLI-only.

**Known usages (from grep):**

- `Timeout`: `cmd/autorun.rs:1844` (filter), `types/work.rs:767,798,825` (tests + impl)
- `Paused`: `types/work.rs:763,782,821` (tests + impl only — no production caller)
- `Aborting`: `cmd/autorun.rs:314,846,906,965,1442,1483,4260,4646` (CLI abort flow — actively used)

## Approach

1. **Wire `Timeout` in `determine_final_status`**: update the function signature to `determine_final_status(aborted: bool, timed_out: bool, failed_count: usize) -> AutorunSessionStatus`. Return `Timeout` when `timed_out=true && !aborted` (a timed-out batch that was not explicitly aborted). Pass the `timed_out` flag from the orchestrator's run loop (find the variable tracking worker timeout completion and thread it to the call site at `orchestrator.rs:330`).

2. **Update call site at `orchestrator.rs:330`** to pass the new `timed_out` parameter. Find the existing variable that indicates whether any worker timed out in the current batch.

3. **Update existing `determine_final_status` tests** at `orchestrator.rs:1281-1300`: update test calls to pass the new third parameter. Add two new test cases: `(aborted=false, timed_out=true, failed=0) → Timeout` and `(aborted=true, timed_out=true, failed=0) → Cancelled` (abort takes precedence).

4. **For `Paused`**: verify via git log that it has no planned feature behind it. Add doc comment `// reserved — no callers; not yet implemented` to the variant in `types/work.rs`. Do NOT remove the variant — removing it would break serde deserialization of any existing DB records that contain `"paused"`.

5. **For `Aborting`**: it IS used in `cmd/autorun.rs` (8 call sites in the CLI abort flow). Preserve it. Add doc comment `// transient: set by CLI abort flow before orchestrator processes abort signal` to the variant to clarify its role and prevent confusion.
