# EPC-018: autonomy with judgment and a config-driven model catalog

## Summary

The operator asked for two things on 2026-09-23. First, CodeFlow should get
work done without being watched and stop only where a human really has to
decide, clarify or supply an input. Second, model routing should become
configuration: agents take the latest eligible version in a family, each
family says which models may be primary, and adding or removing a model
changes a catalog entry, never an instruction. Plan v2 lands both: one owned
autonomy reference with its decision record, the skill corrections that let a
task run to its finish line, a model catalog with a check and derived tests,
instruction surfaces that name only roles and workloads, and blind cases that
fail an agent in either direction.

| Gap | Where it shows today |
|---|---|
| Seven differing operator-owned lists, no single owner | `AGENTS.md` planning and blocker bullets, `workflow-lifecycle.md`, orchestrator preflight, `cf-plan` clarity gate, `quality-contract.md`, workspace `AGENTS.md` |
| No positive finish-line statement | only the pull request loop from EPC-017 covers one stage |
| Plan-then-stop is not forbidden | mode selection in the orchestrator and the lifecycle reference |
| A reversible seat disagreement stops for the human, and nothing records a settled dissent | orchestrator reconciliation, the plan and completion gates in `quality-contract.md` |
| A green pull request into an integration branch waits for a human | `cf-ship`, `pr-evidence.md` and the completion gate say no agent merges, for every target |
| "Hosted jobs never ran" reads as an operator choice | `cf-ship` step 8 and the billing-refused hosted runs on this program |
| The qualify harness waits for a human on its own sample's trust prompt | `tests/release-qualification/qualify.sh` on the EPC-014 and EPC-016 lines versus the workspace rule of 2026-09-22 |
| "Latest" is a label, not a resolution | `model_class` is never interpreted; `latest-sol` binds `gpt-5.6-sol` while `gpt-6-sol` exists |
| One binding per family, fallbacks in prose | `current-ensemble.json` rules text and `model_qualification.rs` one-binding-per-lineage check |
| A roster change edits tests, cases and records | literal selector pins in `orchestration_contract.rs`, the hand stale-pin list, eval kit markers |

Done is: the catalog resolves every workload to the latest eligible version,
no instruction surface names a model, a roster change is a data edit that the
check and the derived tests accept, the autonomy reference owns the one
operator-owned list, the skills continue where they used to stop without
weakening a gate, the evaluation kit fails a faulty control on each of
seventeen blind cases, and the combined body is reviewed and prepared for a
human to land on `main`.

## Model routing, as config

```text
catalog (managed, current-ensemble.json schema 5)
  family --> product lines --> ordered versions (lifecycle, assurance)
  family --> seats (primary-eligible lines, in order)
  workloads --> seats or lines, effort, minimum assurance, constraints
        |
        +-- personal overlay  ~/.codeflow/model-catalog.local.json
        +-- project overrides .codeflow/model-selection.json schema 2
        v
resolver: workload + host harness + author lineage + native exclusions
        --> latest eligible version, selector@effort, fallback chain
        v
skills, contracts, templates name only seats, roles and workloads
```

Figure: where a model name lives after this epic. Only the catalog and the
two override files carry versions or selectors.

Each piece, and why it earns its keep:

| Piece | Why it is needed now | Evidence |
|---|---|---|
| Product lines with ordered versions | "latest" must be computed; today it is a string no code reads | `model_qualification.rs:454`, `:529`; `latest-sol` bound to `gpt-5.6-sol` |
| Lifecycle per version (`active`, `fallback-only`, `known-unrouted`, `retired`) | GPT-5.6 Sol is a fallback only, `grok-4.7-build-fast` is known and unrouted, Terra and `grok-4.6` are retired; the retired set feeds the derived test | operator roster; hand pin list at `orchestration_contract.rs:352` already stale |
| Assurance per version (`candidate`, `operator-designated`, `scoped-qualified`, `qualified`) | the shipped roster has no qualification status in data, and the promotion question needs a level the schema can express | ADR-0039, ADR-0060; `capability-routing.md:142` |
| Seats with ordered eligible lines | "which models may be primary" per family, and fallbacks as data instead of a prose rule | `current-ensemble.json` rules text; one binding per lineage at `model_qualification.rs:463-468` |
| Workloads with effort and requirements | skills must name a task class, not a model; UX and UI, testing, review and computer use need one owner each | workload vocabulary lacks design, review, consultation, UI QA (`model_qualification.rs:149-156`) |
| Personal overlay | a new version ships before CodeFlow does; the operator adds one entry on their machine, as a candidate, without editing instructions | operator requirement |
| Project overrides (schema 2 of an existing file) | a project may prefer, exclude or pin a version; it may not add a selector or raise assurance | ADR-0041 already owns this file |

Not built, because nothing current needs it: runtime model discovery, live
availability probing beyond the existing doctor probes, cost accounting, a
scheduler, per-model routes, a policy language, and Hermes as a harness
(it still delegates to one native host). The resolver is a pure reading of
data plus recorded native evidence; it launches nothing, which keeps
ADR-0035's rejected "generic engine router" and ADR-0060's boundary intact.

Resolution for a workload: expand seats to their line order; drop lines the
constraints exclude; within a line take the newest version that is `active`
(or `fallback-only`, for a seat fallback), meets the workload's minimum
assurance, and has no fresh native exclusion (a harness or rate-limit error,
a failed canary, a stale login; an exhausted usage bucket excludes every line
in it; unknown usage excludes nothing). The first survivor runs at the
workload effort, raised on a catalog trigger and clamped to the version's
efforts. None left means reduced assurance under the existing solo rules;
a seat is never simulated. Every launch records requested versus observed
model and effort; an observed id that differs from the catalog is a drift
event, not a silent upgrade.

## Decisions settled here

- Design owner. Seat `claude-primary` owns design direction, real design and
  fidelity approval; with this roster it resolves to Opus 5.5 at high. Fable
  serves `reasoning-support`, `design-and-editorial-review` and
  `consultation` only, and its review of Claude work is a labeled
  same-lineage second opinion. The Fable authority exception of Plan v1 and
  the Opus design pilot route are removed. Fallbacks come from seat order:
  Opus unavailable after preflight, Fable at high carries the seat with
  reduced assurance; Fable unavailable, review falls to the cross-lineage
  reviewers with the second opinion recorded as missing.
- Qualification policy. `qualified` still means a full native suite plus an
  approved binding record (ADR-0039 unchanged). `operator-designated` means
  a dated human designation record; it permits seat use, is labeled
  "operator-designated, full suite not run" in every closeout, and the check
  warns until a full-suite record exists; it is never reported as
  qualified. A new version enters as `candidate` and serves only workloads
  whose minimum is `candidate`. Whether today's roster is designated is Q2.
- Guard on Q2. TSK-079 may be built and reviewed before the answer, but it
  does not land until Q2 is answered, and an unanswered Q2 is never read as
  yes. If the answer is to hold for full suites, Plan v3 adds a
  qualification task as a predecessor of TSK-079's landing. TSK-075 and its
  successors in the autonomy chain do not wait.
- The minimal contract cap. Charter section 4.4 makes the byte rule project
  policy: remove true duplication first, then move detail, then take a
  narrow recorded exception. The file repeats its tier sentence in the Git
  rules section (222 bytes, pinned by no test), which pays for the compact
  clause. No ratchet move is needed and none is an operator question.
- `cf-plan` keeps its clarity gate but its operator-owned list becomes the
  pointer alone; the per-file test asserts the pointer and the absence of a
  list, so the two cannot drift.
- Retired Terra and `grok-4.6`, and `grok-4.7-build-fast` known and unrouted,
  stay as catalog data so the derived test can read them. GPT-5.6 Luna is
  not added: nothing routes to it.
- The reviewer agents stay model-neutral. Project overrides may reorder,
  exclude or pin within the limits above. Hermes stays delegate-only.
