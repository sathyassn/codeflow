# EPC-019: delegate turn continuation and live transport proof

## Summary

CodeFlow 3.0.0 ships the typed directive after a pasted delegate prompt, but
three pieces of delegate work stayed off the release: the rule that lets a
backgrounded task's notice continue the turn that launched it, the
qualification harness fixes that stop it typing into a pane it cannot
identify, and a live run of the degraded tmux transport (only the Herdr path
ran live for the directive). This epic carries all three into the 3.0.1 patch
release, so a delegating host can rely on the lifecycle on both transports
and the release evidence comes from a harness that cannot submit blind.

Target release: 3.0.1. Done means the three tasks have landed on their
targets (see Plan graph), a qualification run on the final head of
`integration/EPC-019-delegate-turns` is green, and that body is prepared for
a human to land on `main` after the 3.0.0 release.

Evidence at plan time: the continuation fix is `a56551dad` and `aa74edd83`,
and the harness fixes end at `0e6715828`, all on `fix/delegate-paste-bytes`,
which branches from `integration/EPC-014-public-docs` at `4896ec72b`, not from
the 3.0.0 candidate `chore/release-assembly` (`e49726807`) this plan starts
from. The conforming pull request body fixture is `a0f859b48` on
`fix/qualify-pr-body`, which has the same base.

## Acceptance Criteria

- [ ] When a Workflow or background command launched inside a delegated
      Claude turn finishes after that turn's `Stop`, the delegate hook admits
      the resulting task notice as a continuation of that turn and rejects
      every near miss, on the 3.0.0 base; evidence: TSK-090.
- [ ] When the qualification harness cannot read the pane, or can see only
      history, a dialog or an ambiguous screen instead of the current editor,
      it sends no text and no keys and the verdict names that state; the
      conforming pull request body fixture passes `codeflow ci` with no
      warning; evidence: TSK-092.
- [ ] A live delegated turn over the degraded tmux transport delivers the
      pasted prompt, types the directive, and is accepted and completed by
      the lifecycle, with the run recorded as verification evidence; evidence:
      TSK-091.
- [ ] The integrated body passes the full local gate and a qualification run
      on its final head, has cross-lineage review of every task, and its pull
      request to `main` is prepared with release impact `patch` and a
      CHANGELOG entry; evidence: the TSK-091 closeout and the pull request.

## Out of scope

- New delegate transports, a change to the Herdr path beyond what the port
  needs, and Codex or Grok delegate seats.
- The model catalog and autonomy work of EPC-018, and the qualification CLI
  work of EPC-014 (TSK-044); this epic only ports the specific commits named
  above onto the 3.0.0 base.
- Publishing 3.0.1. Tagging and publication stay with the operator under
  `docs/releasing.md`.

## Affected surfaces and interfaces

- CAP-014 transport-neutral delegate lifecycle: `codeflow hook delegate-turn`
  admission rules and the on-disk run records
  (`turns/<turn>/continuations/<task-id>/`), in
  `crates/codeflow-core/src/delegate.rs` and `delegate/continuation.rs`.
- The delegate prompt boundary of ADR-0037: a task notice is admitted without
  an armed turn, so the boundary change is recorded as a dated note on that
  record.
- `cf-delegate` skill resources (`claude-turn-completion.md`) in
  `assets/base`, `.claude/skills` and `.codeflow/.baseline`, with manifest
  hashes.
- The release qualification harness under `tests/release-qualification/`.
- Consumers: every project that delegates Claude turns through `codeflow
  delegate`; the change is additive for them (a notice that was blocked is
  now admitted under narrow conditions).
