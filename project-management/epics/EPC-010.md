# EPC-010 — automated release candidates and governed publication

## Summary

Replace manual, drift-prone release bookkeeping with one continuously refreshed
release-candidate PR that a human reviews before publication. CodeFlow keeps
git-cliff as its sole version-bump authority and cargo-dist as its artifact
publisher, while consuming projects receive opt-in guidance that preserves
their own version, changelog, packaging and publication authority.

## Acceptance Criteria

- [x] Every CodeFlow PR carries checked release impact or a justified `none`,
      and target-relative CI rejects missing or mechanically contradictory
      intent without claiming to prove semantic compatibility.
- [x] A repeatable preparer maintains one release-candidate PR from an explicit
      published baseline and landed source, preserving curated notes and
      reconciling every deliberately coupled version/stamp through supported
      repository procedures.
- [x] Publication remains a separate human-authorized action against the exact
      reviewed candidate; stale source, tags, artifacts, approval or provenance
      fail closed without overwriting public history.
- [x] The historical v2.1 tag/release mismatch and staged unpublished v3 state
      receive explicit non-destructive baseline/provenance treatment.
- [x] Consumer guidance and model evaluations preserve independent project
      release systems and test evidence-linked impact reasoning rather than
      imposing CodeFlow's SemVer, Cargo, changelog or package topology.
- [x] Repository tests, disposable fixtures, mocked hosting failures, local
      release dry runs and independent cross-lineage reviews support only the
      scoped behaviors actually exercised.

## Out of scope

No tag move, public release, artifact upload, visibility/plan change, credential
provisioning, consumer deployment or global release engine. Do not replace
git-cliff/cargo-dist, migrate to release fragments, add general prerelease,
backport or multipackage orchestration, or treat CI as complete semantic proof.

## Affected surfaces and interfaces

CodeFlow PR checks, release preparation and publication workflows, git-cliff and
cargo-dist configuration, curated release history, version/scaffold stamp
agreement, release documentation and tests; CAP-012 plus shipped method/review
guidance, managed mirrors/manifests and model-evaluation cases. GitHub
credentials and human release authorization remain external trust boundaries.
