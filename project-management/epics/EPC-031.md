# EPC-031: Work records and landing correctness

## Summary

Several record and landing checks misjudge ranges that merge a base line, and a landed task needs a separate pull request to be marked done. This epic fixes those judgments. It is one of the feature epics the operator approved on 2026-11-03, when the 4.0.0 milestone epic (EPC-022) and the 4.1.0 epic (EPC-023) were regrouped by outcome. Planned version: 4.0.0. Why that version: Adopter workaround defects (2026-10-18 rule); operator 2026-11-01 14:22 (no PR only to mark done).

## Outcome

After this merges, a maintainer gets records, ranges and landings judged correctly: a base-line merge is never the branch's own change, and a landed task needs no pull request only to be marked done.

- the task records below: `project-management/tasks/`
- the code, docs and tests each task names, mostly under `crates/codeflow-core/src/workgraph/` and `crates/codeflow-cli/src/cmd/ci/`
