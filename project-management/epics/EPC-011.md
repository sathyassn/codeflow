# EPC-011 — repair instruction routing without dilution

## Summary

Make the existing method discoverable across complete task journeys without
weakening obligations added for safety, quality or independent judgment.
Repair conflicting transitions, excessive startup loading, context-policy
ambiguity and incomplete compositional evaluation; do not add another engine.

## Acceptance Criteria

- [x] Every moved duty retains an explicit required route and canonical owner;
      preserved semantic requirements and source/mirror tests remain intact.
- [x] Research, planning, implementation, review and documentation select
      applicable stages and repair failures at their owner; old/new native
      diagnostics retain evidence and limitations.
- [x] Typed guidance distinguishes compile-time contracts from runtime
      validation without forcing wrappers, dependencies or language migration.
- [x] Claude context settings respect effective windows and consumer overrides;
      distribution and bounded continuity checks support the exact claims.
- [x] Catalog and multi-concern tests cover discovery, authority, invalid input,
      recovery and review; keyword checks never substitute for native behavior.
- [x] Required integrated gates, Claude/Grok review, managed artifacts and
      same-PR release state agree before the final human main-merge decision.

## Out of scope

No publication, visibility or remote-permission change, global setting edit,
consumer deployment, unrelated cleanup or new workflow engine. Preserve dual
independent planning, Claude design ownership, author-relative review and
existing quality/safety floors. Public readiness is a separate evidence gate.

## Affected surfaces and interfaces

Managed entry/method/orchestrator/development/review/customize skills, Claude
settings, distribution/mirrors, evaluations and boundary/release documentation.
Agent OS has a separate minimal-tier integration under the same approved plan;
no CodeFlow tracking machinery is introduced there.
