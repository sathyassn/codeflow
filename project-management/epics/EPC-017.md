# EPC-017: operating doctrine follow-through

## Summary

Five behaviours recur in agent sessions on this repository and the doctrine
does not prevent any of them. Independent discovery by both families found
the same gap behind each, so every rule lands in the reference that already
owns its stage, with one policy sentence in the contract, one accepted
decision record, and a blind evaluation case with a faulty control per
behaviour. Existing bytes are grandfathered: accepted decision records are
append-only, and the contract's own dashes wait for its next managed edit.

| Behaviour | Gap found |
|---|---|
| After opening a pull request the agent does not watch its checks, repair red ones or report readiness unless asked | merge law exists but no post-open loop |
| Replies and written artifacts use mannered prose (dashes as drama, slogans, rhetorical framing, paragraph walls) where short plain prose with bullets and tables was wanted | the editorial skill governs substantial prose but excludes ordinary chat and protects the em dash as a false positive under ADR-0032 |
| A flow or relationship is explained in prose when a figure would carry it, and the review surface is neither offered nor opened for a substantial comparison | the figure duty exists but its case can pass on recognition without a figure |
| Pull requests, portals and pages are mentioned without the link the tool printed | no rule asks for a URL |
| Record identifiers or acronyms stand as titles | titles are governed against slogans but not against bare identifiers |

Enforcement has three planes and the decision record keeps them apart:

- two policy characters are checked mechanically on what a change adds
  (commit messages, pull request bodies, added lines);
- identifier-only titles are an editorial smell graded by evaluation;
- operator-facing replies are policy judged by evaluation, never by a hook.

Done is: the five behaviours are written rules in their owning references,
the mechanical check fails a new dash and passes the existing tree, the
evaluation kit fails a faulty control for each behaviour, every mirror and
hash is consistent, and the body is reviewed and prepared for a human to land.

## Acceptance Criteria

- [x] After `gh pr create`, the ship skill carries one step that polls the
      pull request's required checks with `gh pr checks` (or the equivalent
      the reference names) at most once a minute for at most thirty minutes,
      treats hosted checks that never start (for example unpaid Actions) as
      infrastructure-incomplete, honours a red check the agent cannot run
      locally by reporting it rather than shipping, classifies
      redness with the quality contract's existing taxonomy (assertion-red
      returns to the owning stage, infrastructure-incomplete is missing
      evidence), repairs assertion-red checks without asking, never merges,
      and reports readiness to the operator with the pull request URL and the
      green evidence without being asked; evidence: the step, its mechanics

      the operator to name the red job.

      editorial smell graded by evaluation (a title, heading, navigation

      acronym; a summary that is not two to four sentences of plain prose before any bullets; mannered

## Out of scope

- The figure grammar itself and the portal rebuild (EPC-016 owns them); this
  epic only states when a reply must carry a figure.
- Rewriting existing text: accepted decision records are append-only, the
  contract's existing dashes wait for its next managed edit, and no sweep of
  the tracked tree is part of this epic.
- A general prose linter, word list or AI-text detector; ADR-0032 keeps
  editorial judgment contextual and this epic narrows it only to policy
  characters and identifier-only titles.
- Retrofitting existing documents; the mechanical check judges what a change
  adds, so the tree as it stands passes without a sweep.
