# EPC-008 — resource-aware delegated execution

## Summary

Make CodeFlow's existing internal worker catalog runnable and honest enough for
primary-led, resource-aware delegation. Substantial bounded execution may use a
typed candidate route under primary review, while only outcome-qualified routes
carry scoped qualification and Claude retains design direction, design execution
authority and integrated judgment. Done means validation, doctor output,
guidance, evaluation, native proof and distribution agree without introducing a
second scheduler, worker registry or primary-binding promotion path.

## Acceptance Criteria

- [ ] When CodeFlow reads the managed ensemble, schema v4 provides exact native
  selectors, discrete efforts, workload scope, candidate/scoped-qualified
  status and evidence references for internal routes; QualifiedBinding v1 and
  ProjectSelection v1 remain compatible and unchanged.
- [ ] Validation and `doctor --check model-bindings` distinguish catalog shape,
  candidate usability, scoped qualification, harness availability and actually
  observed application without deriving promotion or making cost claims.
- [ ] Orchestration guidance makes bounded delegation accountable, preserves
  justified primary-direct exceptions, and restricts design implementation to
  the Claude design owner or its scoped-qualified Claude route unless Plan vN
  records an explicit operator override.
- [ ] Deterministic cases and focused native trials exercise actual route
  selection, accepted work products, primary integration, independent review,
  capacity uncertainty and design-authority failures; a small pilot never
  becomes a universal reliability, savings or default-promotion claim.
- [ ] Fresh scaffolds and brownfield updates receive one coherent contract while
  project-owned customization survives; the complete integration passes the
  repository's configured gates and exact native Claude source/evidence review.

## Out of scope

A generalized cost optimizer, token-billing service, runtime task scheduler,
phase-order/review-before-X engine, private worker-state ledger, duplicate worker
registry, blanket cheap-child default, full-suite campaign for every worker,
QualifiedBinding v2, ProjectSelection v2, automatic route promotion, product UI
changes, or unsupported cost/economy claims.

## Affected surfaces and interfaces

CAP-010 and CAP-013; the managed ensemble parser and validator, model-bindings
doctor report, orchestration/routing/quality guidance, evaluation corpus and
native evidence, scaffold assets and managed mirrors. Harnesses continue to own
native worker IDs, scheduling and session state.
