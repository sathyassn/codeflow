# PLN-TSK-001-006: Parallel Work Support Analysis

## Description

Analyze and design the parallel work support system for CodeFlow, covering:
- Worktrees: git worktree isolation for concurrent agent sessions
- State hardening: preventing data corruption under parallel writes
- CRDT (Conflict-free Replicated Data Types): merge strategies for shared state
- Data layer protection: SQLite and JSONL integrity under concurrent access

## Approach

1. Survey current state: how CodeFlow handles single-session state today
2. Identify gaps: what breaks when two sessions run concurrently
3. Design worktree isolation model: per-session worktrees, shared vs. isolated state
4. Design state hardening: WAL mode, file locking, append-only guarantees
5. Evaluate CRDT applicability: which data structures benefit from CRDT semantics
6. Design data layer protection: read/write coordination, conflict resolution
7. Produce design document / ADR deliverable

**Design Decisions:**
- Identified three CRITICAL singleton state files blocking parallelism: `codeflow-env.sh`, `/tmp/claude/{project}/`, and `active-task.json`

- Worktree creation at SessionStart hook (not PF1-INIT) so all PathFlow state is written inside the worktree from the start
- Designed `--detach` worktree pattern: `SetupDetached(name)` creates worktree at SessionStart, branch attached at PF3 via `git checkout -b`
- Worktree cleanup at SessionEnd hook (not PF7-END) to handle both normal and abnormal termination
- `.claude/` directory: git worktree handles tracked content; `memory/` uses git merge for reconciliation (no CRDT needed)
