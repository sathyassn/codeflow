**Design Decisions:**

1. **Domain-organized skills (separate per function):** Organized skills by function domain. 9 new/restored skills: cf-pathflow-protocol (lead + agents), cf-git-workflow (cf-git-operations only), cf-memory-management + cf-task-management + cf-db-operations (cf-knowledge-layer only, kept as 3 separate skills -- NOT consolidated), cf-security-operations (cf-security only), cf-team-communication (all agents), cf-code-exploration (cf-planning, cf-development, cf-review), cf-documentation-standards (cf-documentation). Each skill has "Used by:" scope enforcement in YAML description field.
2. **Function agents vs role agents distinction:** Function agents (cf-git-operations, cf-knowledge-layer, cf-security) extract entire Execution Steps to per-agent skills (57-68% reduction). Role agents (cf-development, cf-planning, cf-documentation, cf-review, cf-quality-assurance) only remove Working Protocol + trim Communication (4-9% reduction) because their SOPs are role-specific and must stay inline.
3. **5-phase bottom-up execution order (17 tasks):** Phase A creates/restores 9 skills (parallelizable). Phase B slims agent definitions (2 batches, depends on skills). Phase C slims commands (2 batches, depends on agents). Phase D restructures CLAUDE.md (depends on all above). Phase E finalizes (capabilities inventory, validation).
4. **ASCII art only mandate:** All workflow diagrams use ASCII art. No Mermaid anywhere, including commands.
5. **Skill scope enforcement via YAML description:** Each skill's YAML `description` field includes "Used by:" and optionally "Not used by:" -- agents check this at discovery time before loading.
