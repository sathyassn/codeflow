# TSK-188: agent sessions refuse the dangerous actions in every spelling

## Description

An adopter's agent session cannot escalate privilege, publish, release,
push a tag, change a repository or account, read a keychain, persist at
user level, discard local-only work or edit the enforcement files by any
spelling the guards can parse, and ADR-0075 says what is enforced and what
was dropped. TSK-171 shipped the deny rules for the listed spellings; the
3.0.0 notes disclose that wrapped and flag-led forms are not refused. This
task extends the two existing guards, adds one edit-guard hook for Codex
and Grok, and amends ADR-0075 to the guarded floor that ships: no state
store, no readiness receipts, no operator-actions queue, no Herdr grammar
enforcement. It replaces TSK-172's guard checks, TSK-174 and TSK-175, and
closes the autonomy reference rows TSK-164 AC-1, 4 and 7. Non-goals: the
policy source and fail-closed hooks (TSK-189); the Codex profile (TSK-190).

## Acceptance Criteria

- AC-1 When a command reaches any ADR-0075 decision-1 family (a privilege
  launcher; package or gist publishing; a release or tag push; a repository
  or account change such as `gh repo delete`, `gh secret set`, `gh auth
  login`, `git credential`; a keychain or secret-store read; user-level
  persistence such as `launchctl`, `crontab`, `defaults write`) through
  `env`, `command`, `nohup`, `timeout`, `xargs`, `find -exec`, `npx`, a
  shell `-c` string or a leading flag (`cargo +stable publish`, `gh -R o/r
  release create`, `git push origin v1.2.3`, `refs/tags/`, `--follow-tags`,
  `--mirror`), exec-guard or git-guard shall refuse it naming the family and
  the operator's route, and `bash -lc 'cargo test'`, `git push origin
  task/x`, `gh release view`, `cargo package` and `grep -rn sudo docs/`
  shall pass. Evidence: paired tests per wrapper and family, generated from
  the action table so no family is missed.
- AC-2 When a git command would discard work that exists only locally
  (`reset --hard` over tracked changes, `checkout` or `restore` of `.` or a
  directory, `stash drop` or `clear`, `clean` listing untracked non-ignored
  paths, `branch -D` of unreachable commits, `worktree remove --force` of a
  dirty tree), git-guard shall refuse it under `git.discard_uncommitted`
  naming the recoverable route, and `restore <file>`, `clean -fdX` over
  `target/` and `stash pop` shall pass. Evidence: dirty and clean fixture
  pairs.
- AC-3 When interpreter code (`python -c`, `node -e`, `perl -e`, `ruby -e`,
  a heredoc) names any AC-1 family, a headless peer, an enforcement path or
  a secret store from the sandbox deny list, exec-guard shall refuse it
  under the family's existing level (`security.headless_peer_runs` stays
  the one relief for headless runs; the unread `headless_opt_in` structure
  is dropped); `cat README.md`, `.env.example` and `rg 'claude -p' assets/`
  shall pass. Evidence: paired tests.
- AC-4 When a Codex `apply_patch` or Grok `write` or `search_replace` call
  targets an enforcement path, `codeflow hook edit-guard` shall refuse it
  and allow other paths; the scaffolded Codex and Grok hook files wire it.
  Evidence: payload tests captured from each harness; scaffold test.
- AC-5 ADR-0075 shall carry a dated note keeping decisions 1, 2, 3 and 7;
  amending decision 6 (the pinned retry allowlist is replaced by the
  seat-level native deny plus these guards judging the retried command,
  and the Herdr list stays unshipped workspace practice, which also amends
  operator decision D7's enforcement clause); and dropping decisions 4, 5
  and 8 with the reason (TSK-189 carries the policy source that replaces
  5, and the eval trials' containment replaces D10's fixture root). The
  3.0.1 CHANGELOG entry, `docs/adoption.md` relief text and the autonomy
  reference rows TSK-164 AC-1, 4 and 7 shall match; its AC-2, 3 and 6 are
  written from TSK-189's rules and close there. Evidence: review; the
  `delegate_doctrine_contract` test.
- AC-6 In a freshly scaffolded minimal-tier project driven by the installed
  CLI through the scaffolded Claude, Codex and Grok hooks, each refusal
  above names its rule and route and ordinary work (build, `git push origin
  task/x` to a local bare remote, `git restore <file>`) passes. Evidence:
  end-to-end test with the installed binary. (journey)

## Known limits

These accepted limits belong to literal inspection; the guards do not execute
commands or expand opaque inputs to discover their effects.

- Archive extraction through `tar -C` or `unzip -d`, and `xargs rm` fed by
  stdin, remain outside the inspected mutation list. Archive members and
  arguments supplied by stdin are not known from the command's literal text.
- Destructive `find` checks protect named traversal roots. The guard does not
  enumerate matches from a broader root, such as `find . -name policy.json
  -delete`.
- Interpreter `shutil.rmtree(".codeflow")` remains an ancestor-path limit:
  edit-guard has no ancestor rule. An explicit protected path such as
  `.codeflow/git-hooks` is still checked.
- For projects under `/tmp/claude*`, a typed absolute path using a different
  symlink spelling from the payload cwd (`/tmp` versus `/private/tmp`) can
  fall through to the existing absolute scratch-path exemption (Q5).
- The conservative refusal of a nested `vendor/.git` named directly remains.
  Removing an ordinary parent directory such as `vendor` remains allowed.
