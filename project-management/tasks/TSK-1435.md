# TSK-1435: A hand-resolved merge of main reopens review only for its difference

## Description

A merge of `main` into a line that differs from git's own merge (TSK-1434) needs review, but only of what a person changed. This task makes the refusal name each path whose content differs from the clean merge, and lets a delta review of exactly those paths, by another lineage at the merge commit, clear it. Proof is never kept across such a merge: the epic's journeys still run on the combined code. Non-goal: any change to how a clean merge is judged.

Landing on its target (`main`, alone, early):

- Reachable: the narrow review route for a hand-resolved merge.
- Inert: nothing else changes.
- Other lines: nothing.

## Outcome

After this merges, a maintainer who resolves a merge of `main` by hand sees which paths differ from git's own merge and needs a review of only those paths to keep the line's other reviews.

## Acceptance Criteria

- AC-1 When a merge of `main` into a line differs from git's own merge of its parents, `codeflow ci` shall refuse it naming each path whose content differs; evidence: a planted hand-edited merge (issue 770's done-when).
- AC-2 A delta review recorded at the merge commit, by another lineage, covering exactly those paths shall clear the refusal, and one that misses a path shall not; evidence: one fixture each.
- AC-3 No gate result shall be reused across such a merge, and the refusal's remedy text shall say that the epic's journeys run on the combined code; evidence: the remedy text and a test that no gate result is reused.
