# TSK-145: release lines judged where each change was introduced

## Description

The release catch-up merge that brings the EPC-020 line into the release
branch (the local `integration/release-3-0-0-rehearsal` at `cbc0b2ec8`)
was refused at pre-push with 15 `work.acceptance_binding` and 20
`work.criteria_frozen` findings, and `codeflow ci --base origin/main` on
it gives 18 `work.acceptance_binding` blocks (scratchpad
`models-stream/rehearsal/push-M3.txt`, `ci-M3-vsmain.txt`,
`ci-M3-vsL.txt`). In `cmd/ci/acceptance.rs` `criteria()`, a branch that
combines several lines is neither planning-only nor an epic line, so its
criteria are frozen and every completion is bound at the head, although
each change was already judged on the line it came from. This task judges
a release line, including its pull request into `main`, by SPC-013 R-120.
It is on the release's critical path.

R-120 in short. Scope by name under the default target's policy (planning
resolution 20, round 6). A release branch is one whose name matches
`git.release_branch_pattern` in the policy at the default target's remote
tip, or the built-in default `integration/release-*` when the key is
absent; a release range is a push to one, a pull request into one, or its
pull request into the default target. No merge-base selects this, so no
rewrite or records-only push changes it. The pattern may not match the
default target or an epic line, so epic lines, stacked lines, shared
history and line-to-line syncs keep R-52 and R-60. On a release range a
merge is an import only when each non-first parent lies on the
first-parent chain of a verified epic line (read from its authority ref)
or of the default target, never through the release branch's own refs,
however it arrived (a pull request into the branch is judged as the merge
it would create); otherwise the whole merge is direct work, which covers
octopus merges, lines rebased after the merge, side branches pushed only
to the release branch and the release task's own fix pull requests. Within
an import, a path is brought only when its full tree entry (existence,
object id, mode and type) equals the expected import's (the clean
three-way result, or the second parent's entry for a conflicted path); any
other path is a resolution judged against that import, never against the
first parent, so a resolution that restores an older record is caught with
no first-parent diff. Brought completions bind where they were introduced;
brought criteria changes are judged again at the merge that landed them on
their line. Direct changes: every direct change on a release range, of any
class and in any pushed slice, freezes criteria, so an amendment for any
task, the release-integration task included, lands on a line through a
planning PR and is brought; a direct records-only commit that changes no
criterion needs no release-integration completion, a merge resolution
never counts as one; anything else is integration work for the
release-integration task, completed inside the release pull request at the
head both primary seats reviewed; another task's direct completion is
judged as a task pull request.

Release-integration task: TSK-010 ("integrate and release the CodeFlow
system") owns release integration; TSK-109 AC-3 keeps TSK-010's release
ownership when it reconciles TSK-010, TSK-013 and EPC-005. `role:
release-integration` marks the one open task that owns direct release work
and closes in the release pull request; it does not select scope. The
planning PR that gives TSK-010 the role is still needed, but need not
reach the default target first; until it lands, direct code on a release
range is refused with "no release-integration task to own it", and the
release rules still apply. This task does not retarget TSK-010.

Trust boundary: a structural check can re-judge the merge that landed a
criteria change on its line by that merge's paths, so a loosening that
arrived with code is refused. It cannot see whether a planning-only
landing merge passed the line's pull request check; that stays with the
host's review and required checks on the line, which are not armed on
CodeFlow's own host.

The 3.0.0 rehearsal as built does not satisfy R-120. On `cbc0b2ec8`'s
first-parent path it carries direct code commits (`b1f52a820`,
`c455717bf`, `23979d7d8`, `580344e2b`, `f0f7e1a12` among them), TSK-049's
direct completion `1dc0033a2` followed by code, and the merge `b1923ac60`
of `integration/release-3-0-0-list`, which is no verified line.
