# TSK-145: release lines judged where each change was introduced

## Description

The release catch-up merge that brings the EPC-020 line into the release
branch (the local `integration/release-3-0-0-rehearsal` at `cbc0b2ec8`)
was refused at pre-push with 15 `work.acceptance_binding` and 20
`work.criteria_frozen` findings, and `codeflow ci --base origin/main` on
it gives 18 `work.acceptance_binding` blocks (scratchpad
`models-stream/rehearsal/push-M3.txt`, `ci-M3-vsmain.txt`,
`ci-M3-vsL.txt`). In `cmd/ci/acceptance.rs` `criteria()`, a branch that
combines several lines is neither planning-only nor an epic line, so its
criteria are frozen and every completion is bound at the head, although
each completion and criteria change was already judged on the line it
came from. This task judges a release line, including its pull request
into `main`, by introduction as an epic line is judged, and judges any
change made directly on the release line exactly as a task pull request
is judged today (SPC-013 R-120). It is on the release's critical path.

Recognition (decided here, recorded in planning resolution 20): a range
is a release-line range by structure and provenance, not by name or a
declaration. Only changes that a merge brings from a verified line are
judged by introduction: the merged commit must be reachable from the
authority's ref of an epic line that passes the epic-line check, or from
the default target. Every other change on the release line's
first-parent path, a direct commit or a merge resolution, is judged as a
task pull request. A policy declaration was weighed and not chosen: the
target of the release pull request is `main`, whose policy predates any
new key, so a target-side declaration cannot recognize the first release,
and a head-side declaration could be granted by the pull request it
judges. Claiming a range as a release line gains nothing for a change
that did not come from a verified line.

## Acceptance Criteria

- AC-1 When a range merges verified lines into a release line, each
  completion those merges bring shall be bound at the commit that
  introduced its block on its own line, under rules 1 and 2 of R-60, and
  each criteria change they bring shall be judged at its introducing
  commit under its own line's rules; evidence: `ci_cli` fixtures with two
  epic lines merged into a release branch, one completion and one
  planning amendment on each.
- AC-2 When a completion is added directly on the release line (a
  first-parent commit or a merge resolution) with a reviewed commit that
  is not the head or an ancestor whose later diff touches only that
  record's status and Closeout, CI, pre-push and `task status` shall
  refuse it as `work.acceptance_binding`; evidence: fixtures for a direct
  commit and for a merge resolution, each refused.
- AC-3 When a criterion is changed directly on the release line,
  including a loosening made in a merge resolution, CI and pre-push shall
  refuse it as `work.criteria_frozen`; evidence: fixtures for both
  shapes, each refused.
- AC-4 When a merge's second parent is not reachable from a verified
  line's ref on the authority (a branch that fails the epic-line check,
  an unpushed branch, or a forged merge message naming a real line), its
  changes shall be judged as direct changes on the release line;
  evidence: fixtures for each case, judged as AC-2 and AC-3.
- AC-5 Pre-push, CI and `task status` shall return the same verdict for
  the same range; evidence: each AC-1 to AC-4 fixture run through all
  three with matching verdicts.
- AC-6 (journey) When the EPC-020 line and one other line are merged
  into a release branch in a freshly scaffolded full-tier project driven
  by the installed CLI, the push shall pass pre-push and `codeflow ci
  --base` the default target shall be clean; and the 3.0.0 rehearsal
  replayed (the `cbc0b2ec8` merge, pushed, then `codeflow ci --base
  origin/main`) shall report no `work.acceptance_binding` or
  `work.criteria_frozen` finding; evidence: an `acceptance_journey` case
  and the replay logs beside the three refusal logs above.
