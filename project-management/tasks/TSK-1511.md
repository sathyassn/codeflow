# TSK-1511: CodeFlow's docs portal gate target runs as a heavy target with a measured bound

## Description

The `docs-portal` target in this repository's `.codeflow/test-config.json` (lines 489 to 506 at the EPC-022 line tip 5405cdb1b) has `timeout_seconds` 300 and is not marked heavy, so it does not get TSK-1278's heavy-target handling: a heavy target keeps running while it shows activity, up to 4 times its base timeout. Under host load the target runs past 300 s: on 2026-11-15 the 300 s bound cut three runs with no failing check, at 300121 to 300237 ms (TSK-1299's Findings). TSK-1497's final-head docs-portal gate took 811 s as a whole invocation, of which the `docs-portal` target itself took 285 s and its prerequisites `rust-build` and `codeflow-bin` the rest, so an unloaded run already sits close to the bound. A correct change then fails the gate. This task marks the target heavy, so its bound follows measured activity instead of a flat wall clock. The shipped default test config declares no `docs-portal` target at 5405cdb1b (no match under `assets/`), so the change is to this repository's config only, unless that has changed at claim. Non-goal: making the portal build faster. How a timeout reports under heavy load in general stays with EPC-047's open question, owned by coord/ci.

## Outcome

After this merges, a CodeFlow maintainer running the gate on a loaded host gets the docs-portal target's real verdict, with no false timeout while the target is still progressing.

## Deliverables

- the `docs-portal` target entry: `.codeflow/test-config.json`
- the shipped default test config, only if it declares the target at claim: under `assets/`
- a runner test for the heavy docs-portal bound: `crates/codeflow-cli/tests/` (provisional; the builder places it beside TSK-1278's heavy-target tests)

## Acceptance Criteria

- AC-1 The `docs-portal` target shall be marked heavy in this repository's `.codeflow/test-config.json`, and in the shipped default test config if that config declares the target. A raised `timeout_seconds` is a fallback only, used when marking the target heavy cannot hold, and the pull request states which one was used and why. Evidence: the file:line of the target entry at the final head, and one real `codeflow test --only docs-portal` run on a loaded host that passes (owed after the 2026-11-15 disk hold lifts).
- AC-2 When a heavy docs-portal run is still showing activity at its base timeout, the runner shall keep it running, and shall stop it once it stops showing activity or reaches the 4 times ceiling. Evidence: one test with a fake runner and no real portal build, covering all three cases, with its name and result line in the pull request.
