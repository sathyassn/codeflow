# TSK-1449: The dependency audit and the full-range secret scan run in every local gate

## Description

The operator relaxed hosted CI on 2026-11-11: line pushes start no hosted run, line pull requests run short checks only, and `main`'s heavy checks are relaxed on local evidence. The pinned osv-scanner dependency audit and the full-range gitleaks scan therefore have to run locally. The operator ruled at about 20:35 EST that both run locally always, not only in hosted CI. TSK-1176 (PR 690) builds the `codeflow scan` command with both pinned runners and base-commit reads; this task makes that command run in every local gate by default, so a vulnerable dependency or a committed secret is found on the builder's machine before it reaches a line.

Owner search (coord/records, 2026-11-11 20:30, corrected 21:0x), open records on `main` that name osv or gitleaks:

- TSK-1176 (EPC-027, todo, PR 690): its AC-6 to AC-10, moved from TSK-430 on 2026-11-04, give the command, the runners, the policy levels, a pre-push opt-in (AC-8), the research note and the journey.
- TSK-430: cancelled on `main` (merged into TSK-1176). The EPC-024 line's older `todo` copy is stale and takes `main`'s copy at that line's next sync.
- TSK-412 (complete): the commit-time gitleaks engine and pin check.
- TSK-1366 (EPC-027, todo): the trusted hosted canary job, which stays hosted; this task adds the local run of the same canary set.
- TSK-294, TSK-424, TSK-1026: audit exceptions, the exemption register, CI reuse; edges only.

This task reuses TSK-1176's command and engine. Its own scope is the always-on placement in every gate, the local canary, the missing-objects refusal and the shipped default.

## Outcome

After this merges, every pre-push and every `codeflow test` gate run (quick and full) runs the pinned osv-scanner over every lockfile and the pinned gitleaks over the full range from the base, with the ignore and configuration files read from the base commit and the allowlist canary checked; a missing tool or an unreachable advisory source refuses with the install or network line; docs and doctor say so.

## Deliverables

- the gate and hook placements of TSK-1176's `codeflow scan` engine (pre-push, quick, full), the local canary, the missing-objects check and the shipped default (provisional homes; the builder confirms them)
- tests per placement, level and refusal state, and the planted negatives
- `docs/cli.md`, `docs/policy-reference.md`, the gate docs and doctor's report

## Acceptance Criteria

- AC-1 Placement (Director, 2026-11-11: "run always" means every gate): the secret scan, the allowlist canary and the dependency audit each run at pre-push, in the quick gate and in the full gate. Each shall run the pinned osv-scanner over every lockfile with `osv-scanner.toml` read from the base commit, and the pinned gitleaks over `base..HEAD` with `.gitleaksignore`, `.gitleaks.toml` and `.gitattributes` read from the base commit, and shall give the verdict the managed `security review` and `secret scan` jobs give for the same base and head, through TSK-1176's `codeflow scan` engine. Evidence: a gate and hook test per placement, and a fixture whose working-tree ignore file differs from the base's, with the matching verdict. This replaces TSK-1176 AC-8's opt-in; TSK-1176's own pull request records that amendment.
- AC-2 The local run shall check the allowlist canary: when the configuration in force stops reporting any planted canary credential, the gate shall fail and name the credential class it missed. Evidence: a planted configuration that drops one rule.
- AC-3 A missing or checksum-mismatched binary, an advisory query that cannot reach its source (osv-scanner queries osv.dev on every run; there is no cached database, so an offline run refuses), or a range with missing objects shall refuse the run, never pass, with a message that names the cause and gives the exact install, network or fetch line. The missing-objects check runs `git rev-list --objects --missing=print <base> <head>` before the scan: a partial clone with 0 missing objects scans, git's lazy-fetch warning is accepted, and any missing object refuses and names the fetch command. The AC-5 policy level is the project's way to lower a refusal; there is no per-run skip. Evidence: one test per state. The missing-binary state extends TSK-1176 AC-7 to each gate placement.
- AC-4 Planted negatives: a lockfile with a known vulnerable dependency, and a secret committed in the range, each fail the gate and name the finding. Evidence: both fixtures.
- AC-5 The levels `git.secret_scan`, `git.security_review` and `git.dep_audit` govern the local run as they govern the hosted jobs, for block, warn and off. The shipped default for the local run is block; lowering it is a recorded policy choice that `codeflow doctor` reports; CodeFlow's own repository stays at block (operator: "run always"). Evidence: tests per level at each placement, the shipped default, a doctor test for a lowered level, and this repository's policy at block. TSK-1176 AC-7 gives the levels for the command; this gives them for the gate placements.
- AC-6 `docs/cli.md`, `docs/policy-reference.md` and the gate docs say both scans run in every local gate, with the install lines; `codeflow doctor` reports each binary's lookup and pin, says that the dependency audit queries its advisory source online on every run, and refuses a missing binary with the install line. Evidence: the docs diff and doctor tests. Corrected 2026-11-12 from draft 29, which also asked doctor to report the advisory database's age: the audit keeps no local database (AC-3), so there is no age to report, and doctor states the online query instead.
- AC-7 The time each scan adds is measured on this repository and stated in the pull request. The interim measurement with the workspace script `coordination/scripts/local-security-scans.sh` (workspace 1a098a29) gave gitleaks about 2 s, the canary under 1 s and osv-scanner about 2 s online once folders holding no tracked file (`target/`, `node_modules/`) are skipped. Evidence: the measured run with the shipped command at each placement.
- AC-8 The behaviour of every other gate step, hook and guard is unchanged. Evidence: the existing gate and hook tests, `codeflow test --mode quick`, clippy `-D warnings`, `cargo fmt --check`.
- AC-9 Until this ships, the workspace script `coordination/scripts/local-security-scans.sh` covers the relaxed hosted `secret scan` and `security review` jobs; once this task is on `main` and released, that script retires. Evidence: the relaxation file's cover column and its removal note.
