# TSK-1389: A project can protect its own files, such as AGENTS.md and CLAUDE.md, from agent writes

## Description

Issue 635 asks that a project can protect its own instruction files, such as `AGENTS.md` and `CLAUDE.md`, under `git.hook_integrity`. Today the guards protect only the built-in enforcement paths, so an agent session can rewrite a project's instructions. This task adds an additive policy key, `git.hook_integrity_paths`, that lists extra repository paths. Edit-guard, git-guard and exec-guard then refuse writes to them as they refuse writes to the built-in enforcement paths. The guards read the key only from the landed policy, and it is empty by default, so an adopter that does not set it sees no change.

It reuses the routes TSK-325 extends for the built-in paths and needs neither TSK-283 nor TSK-284 (coord/ci's assessment, `coordination/coordinators/parallel/notes/tsk325-633-assessment.md`, outside the repository, section B). The Git commands that write work-tree files without moving HEAD are judged by the issue 633 task; this task applies that judgment to the listed paths.

Non-goals: whether CodeFlow's own policy sets the key for its instruction files, which is the operator's choice; the harness edit-deny presets, which come from the shipped list.

## Outcome

After this merges, a project maintainer can list files such as `AGENTS.md` and `CLAUDE.md` in the landed policy, and agent sessions are then refused every write to them, while a person's edit outside the session still commits.

## Deliverables

- the key and its schema: `git.hook_integrity_paths` in `crates/codeflow-core/src/hooks/policy.rs`
- the guards: edit-guard (`crates/codeflow-core/src/hooks/edit_guard.rs`), git-guard (`crates/codeflow-core/src/hooks/git_guard.rs`) and exec-guard's interpreter route (`crates/codeflow-core/src/security/`)
- tests: `crates/codeflow-cli/tests/hooks_cli.rs` and guard unit tests, and the journey
- docs: `docs/policy-reference.md` and `docs/adoption.md`
- release note: `changelog.d/TSK-1389.md`

## Acceptance Criteria

- AC-1 A project shall be able to list extra protected files under a new policy key, `git.hook_integrity_paths` (for example `["AGENTS.md", "CLAUDE.md"]`). Each entry is a repository-relative path or a `dir/**` prefix; an absolute path, a `..` component or any other pattern refuses at policy load. The key is additive and cannot remove a built-in enforcement path. The guards read it only from the landed policy (the authority ref), never from the working copy. Its default is empty, and its name stays distinct from the commit-time `path_policy` `protected_paths` key (`crates/codeflow-core/src/hooks/policy.rs:534`). Evidence: schema tests (each invalid entry refuses at load), and a test that a working-copy-only edit of the key changes no verdict.
- AC-2 Each listed path shall be refused at `git.hook_integrity` as a built-in enforcement path is: by edit-guard for a native Write or Edit; by git-guard for a redirect, `tee`, `cp`, `mv`, `install`, `sed -i`, `rm` and each Git command that writes work-tree files without moving HEAD; by exec-guard for an interpreter argument or code naming it. Evidence: one test per route with `AGENTS.md` and `CLAUDE.md` listed, each failing before the change.
- AC-3 With the key absent, `AGENTS.md` and `CLAUDE.md` shall stay ordinary files that an agent can edit, and reads of a listed path shall pass. Evidence: controls in the AC-2 tests, with the key absent and with it set.
- AC-4 The docs shall describe the key, state that a listed file then changes only by a person's edit outside the session or a reviewed merge, and state that the harness edit-deny presets come from the shipped list, so a project-listed path is enforced by the guards and not by the presets. Evidence: the text in `docs/policy-reference.md` and `docs/adoption.md`.
- AC-5 (journey) With the installed build and the key set in a scratch project's landed policy, a session's Edit and shell write to `AGENTS.md` shall be refused, `git checkout <older revision> -- AGENTS.md` shall be refused, and a person's edit made outside the session shall commit. Evidence: the journey output.
- AC-6 A cross-family security review shall pass on the whole unit, checking that the key cannot relax a built-in path, that a working-copy policy is never read, and that no ordinary write is falsely refused while the key is absent. Evidence: the review file named in the pull request.
