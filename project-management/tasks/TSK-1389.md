# TSK-1389: A project can protect its own files, such as AGENTS.md and CLAUDE.md, from agent writes

## Description

Issue 635 asks that a project can protect its own instruction files, such as `AGENTS.md` and `CLAUDE.md`, under `git.hook_integrity`. Today the guards protect only the built-in enforcement paths, so an agent session can rewrite a project's instructions. This task adds an additive policy key, `git.hook_integrity_paths`, that lists extra repository paths. Edit-guard, git-guard and exec-guard then refuse writes to them as they refuse writes to the built-in enforcement paths. The guards read the key only from the landed policy, and it is empty by default, so an adopter that does not set it sees no change.

It reuses the routes TSK-325 extends for the built-in paths and needs neither TSK-283 nor TSK-284 (coord/ci's assessment, `coordination/coordinators/parallel/notes/tsk325-633-assessment.md`, outside the repository, section B). The Git commands that write work-tree files without moving HEAD (for example `git checkout <older revision> -- AGENTS.md`) are judged by TSK-1390 (issue 633), and are out of this task's acceptance until that task is an edge here.

Non-goals: whether CodeFlow's own policy sets the key for its instruction files, which is the operator's choice; the harness edit-deny presets, which come from the shipped list.

## Outcome

After this merges, a project maintainer can list files such as `AGENTS.md` and `CLAUDE.md` in the landed policy, and agent sessions are then refused a native Write or Edit, a shell write and an interpreter write to them, while a person's edit outside the session still commits. A Git command that writes the work tree without moving HEAD stays outside this task until TSK-1390 is added as its edge (Execution contract, Edges).

## Deliverables

- the key and its schema: `git.hook_integrity_paths` in `crates/codeflow-core/src/hooks/policy.rs`
- the guards: edit-guard (`crates/codeflow-core/src/hooks/edit_guard.rs`), git-guard (`crates/codeflow-core/src/hooks/git_guard.rs`) and exec-guard's interpreter route (`crates/codeflow-core/src/security/`)
- tests: `crates/codeflow-cli/tests/hooks_cli.rs` and guard unit tests, and the journey
- docs: `docs/policy-reference.md` and `docs/adoption.md`
- release note: `changelog.d/TSK-1389.md`

## Acceptance Criteria

- AC-1 A project shall be able to list extra protected files under a new policy key, `git.hook_integrity_paths` (for example `["AGENTS.md", "CLAUDE.md"]`). Each entry is a repository-relative path or a `dir/**` prefix; an absolute path, a `..` component or any other pattern refuses at policy load. The key is additive and cannot remove a built-in enforcement path. The guards read it only from the landed policy (the authority ref), never from the working copy. Its default is empty, and its name stays distinct from the commit-time `path_policy` `protected_paths` key (`crates/codeflow-core/src/hooks/policy.rs:534`). Evidence: schema tests (each invalid entry refuses at load), and a test that a working-copy-only edit of the key changes no verdict.
- AC-2 Each listed path shall be refused at `git.hook_integrity` as a built-in enforcement path is: by edit-guard for a native Write or Edit; by git-guard for a redirect, every entry of the shared writer table (`WRITERS`, `crates/codeflow-core/src/security/unresolved.rs:39`, judged through `judge_writer`, for example `tee`, `cp`, `mv`, `install`, `ln`, `dd`, `truncate`, `curl -o`, `tar` and `patch`), `rm`, `sed -i` and sed's `w` and `W` commands; by exec-guard for an interpreter argument or code naming it. The refusal holds for every spelling that lands on a listed file: a different-case name on a volume that folds case, a symlink whose target is the listed file, and a write path with `.` or `..` components. Evidence: one test per route with `AGENTS.md` and `CLAUDE.md` listed, each failing before the change, including a writer outside today's sample (`curl -o AGENTS.md`) and `sed -n wAGENTS.md`; a test that fails when a `WRITERS` entry has no listed-path case; and tests for a different-case name on a folding volume, a symlink to the listed file and a `..` path.
- AC-3 With the key absent, `AGENTS.md` and `CLAUDE.md` shall stay ordinary files that an agent can edit, and reads of a listed path shall pass. Evidence: controls in the AC-2 tests, with the key absent and with it set.
- AC-4 The docs shall describe the key, state which agent writes it refuses (the routes in AC-2), state that a Git command which writes the work tree without moving HEAD is not yet refused for a listed file until TSK-1390's judgment covers it, and state that the harness edit-deny presets come from the shipped list, so a project-listed path is enforced by the guards and not by the presets. Evidence: the text in `docs/policy-reference.md` and `docs/adoption.md`.
- AC-5 (journey) With the installed build and the key set in a scratch project's landed policy, a session's Edit and shell write to `AGENTS.md` shall be refused, and a person's edit made outside the session shall commit. Evidence: the journey output.
- AC-6 A cross-family security review shall pass on the whole unit, checking that the key cannot relax a built-in path, that a working-copy policy is never read, and that no ordinary write is falsely refused while the key is absent. Evidence: the review file named in the pull request.
