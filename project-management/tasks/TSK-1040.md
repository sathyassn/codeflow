# TSK-1040: A pull request body edit never cancels the required policy check

## Description

Issue #373 (CodeFlow 3.1.1, opened 2026-10-28 01:17Z). The generated
`.github/workflows/codeflow-policy.yml` runs on `pull_request_target`
with types `opened, synchronize, reopened, edited, ready_for_review`, in
one concurrency group per pull request with `cancel-in-progress` true for
those runs (`assets/base/ci/codeflow-policy.yml:40-53`). When the body is
edited seconds after a push, the `edited` run cancels the push's run; the
required "commit standards" check on that head then shows once cancelled
and once passed, and the adopter's PR stayed blocked until someone re-ran
it (runs 40613620628 and 40613623003, 2026-10-28; five more cancelled
runs on three branches on 2026-10-26 and 2026-10-27). Turning
`cancel-in-progress` off alone does not fix it: with the default
single-slot queue GitHub keeps one pending run per group and cancels it
when a newer one arrives. The shipped comment (`:29-36`) states the
cancellation as intended, reasoning that the surviving run reads the
current body from the API; the required check on the pushed head is what
it loses. This repository's own `.github/workflows/codeflow-policy.yml`
carries the same block.

Outcome: **no pull request event cancels or replaces the run that judges
a pushed head's required "commit standards" check; every queued run
completes; a run that judged a body, head or base that changed while it
ran fails with its own message so the run queued by that change decides;
and the body is logged by digest, never as text.**

Rules (the issue's proposal, to be confirmed by AC-1):

- Concurrency keeps the per-PR group and the per-run group for push,
  schedule and dispatch, with `cancel-in-progress: false` and the queue
  mode that keeps every pending run (`queue: max`, GitHub changelog of
  2026-05-07), if AC-1 confirms the key and its limits.
- A last step reads the pull request again and fails if the head SHA,
  the base branch or the body changed while the run judged them, and
  fails closed when the read fails. The base commit is not compared,
  since a push to the base fires no pull request event.
- The body is logged as a sha256 digest.
- Limits are documented: the queue's 100-run cap (past it a newest push
  fails closed), the window after a run's last read, two API calls per
  run on the shared token's rate limit, and linter support for the new
  key.

Non-goals: `codeflow-ci.yml`'s cancellation of superseded runs
(TSK-1026, which builds on this task's rule).
