# TSK-231: Evaluation trials launch Codex without remote plugins and Grok 1.0.46

## Description

TSK-194's model qualification could not launch Codex or Grok trials on
2026-10-04. Codex 0.159.1 synced nine account-managed remote plugins into the
dedicated evaluator home's plugin cache at every start, and one of them
(`defense-factory`) holds a React `src/hooks` folder, which the runner's plugin
check refuses, so every hook-trust bypass launch refused, Codex peers in Claude
trials included. Grok Build 1.0.46 is installed, but the runner recognised
only the 1.0.44 trust dialog and reported any startup refusal as "evaluator
home not signed in".

The kit now keeps account-managed plugins out of the dedicated Codex home:
`prepare-eval-homes` writes `plugins = false` and `remote_plugin = false`
under `[features]` and moves a stale remote plugin cache out of the home with
the reason printed; every Codex start the kit builds passes the same settings
on its command line; and the runner refuses a launch whose home lacks the
settings or holds that cache. `remote_plugin` (Codex's documented catalog
switch, listed by `codex features list`) alone did not stop the sync in a
live launch; Codex runs the sync whenever its `plugins` feature is on and the
home is signed in, so both are turned off. The runner
learns Grok 1.0.46's screens from a real launch, keeps 1.0.44, and fails
closed on any other version or screen with a message naming both.

Non-goals: the plugin check's refusal of any folder named `hooks` stays as it
is; no hook trust or folder trust is accepted beyond what the kit already
accepts; only `~/.codeflow-eval/codex` is touched, never the operator's own
`~/.codex`.

## Deliverables

- Kit setup and launch arguments: `assets/base/agents/skills/cf-evaluate-model/scripts/eval_kit.py` and its four mirrors
- Runner checks and Grok screens: `evals/qualification/runner.py`
- Tests: `evals/model-artifacts/test_eval_kit.py`
- Runner documentation: `evals/qualification/README.md`
- Release note: `CHANGELOG.md` (3.1.0, Fixed)

## Acceptance Criteria

- AC-1 When `prepare-eval-homes` runs, the dedicated Codex home's `config.toml` carries `plugins = false` and `remote_plugin = false` under `[features]`: seeded in a new file, and otherwise only the missing settings added, as a new table or under the one existing `[features]` header, with the rest of the file verified to parse unchanged; another value (including a number) or a features form the kit cannot extend is refused and the file left as it was; a stale account-managed remote plugin cache is moved into a real kit-owned folder beside the home (a linked destination is refused before anything moves) and each move and its reason are printed; the operator's `~/.codex` is never read or written; evidence: new `test_eval_kit` tests, which fail on the unfixed kit and pass after.
- AC-2 When a trial launches, every Codex start the kit builds (the trial seat, a peer's answer, the printed hook-review command and the setup helper) carries `-c features.plugins=false -c features.remote_plugin=false`, and the runner refuses before any seat starts, naming `prepare-eval-homes`, when the dedicated home lacks either setting or holds a remote plugin cache; the same state is checked again after readiness and at finish; the plugin check still refuses any folder named `hooks`; evidence: new `test_eval_kit` tests, which fail on the unfixed runner and pass after, and the existing plugin-hook tests unchanged.
- AC-3 When Grok Build 1.0.44 or 1.0.46 shows its trust dialog naming the exact trial path, the runner accepts it as before, and on any other version or a changed trust, welcome or unknown screen it sends no key and refuses with a message that names the Grok version and the screen; "evaluator home not signed in" is reserved for a visible sign-in screen; evidence: new `test_eval_kit` tests built from the captured 1.0.46 screens, which fail on the unfixed runner and pass after.
- AC-4 When a real Codex 0.159.1 trial with `--codex-hook-trust=bypass` and a real Grok 1.0.46 trial are launched through `runner.py launch` in Herdr against the dedicated homes, both reach readiness and the Codex home holds no remote plugin cache after startup; evidence: both `launch.json` records and screens, pasted in the pull request (journey).
- AC-5 The runner README and the 3.1.0 CHANGELOG describe the plugin settings, the cache move and the Grok versions; evidence: the diff, `manifest_consistency` and `codeflow validate --docs`.
