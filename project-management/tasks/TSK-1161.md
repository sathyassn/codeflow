# TSK-1161: A push is judged by the line, policy, base and class it targets

## Description

Judge a task branch's push against the line its record targets when the destination advertises that line, and treat an empty range whose head the line already contains as no change. Today the hook takes its policy and commit-history authority from the destination's default branch tip (`judged_by`, `crates/codeflow-cli/src/cmd/push_set.rs:1016`; `--policy-from` and `--commits-from` at `:334`), and that stays. The target it hands `codeflow ci` is the branch's declared line only when `declared_bounds` allows it (`ci_target`, `:366-383`; `declared_bounds`, `:1475-1485`, which sets aside a protected line whose advertised tip differs from the default branch's); `--into` is omitted when the range is empty (`base == r.local_sha`, `:346-349`); and `target_base` uses the declared line's advertised tip only on some paths (`:1544-1559`). `codeflow ci --branch` takes the work target from the head's task record (`work_target_at`, `crates/codeflow-cli/src/cmd/ci.rs:1822-1830`) and checks work admission against it (`work.stable_planning_anchor`, `ci.rs:1840-1870`). The two therefore diverge on some heads: a push can be refused, or judged against the wrong base, though ci on the same head passes. Found in TSK-1124's work; the issue 454 family, whose criteria half is TSK-350 AC-13. Non-goal: the default branch stays the policy and commit-history authority (TSK-350 requires it); this task changes only the target line and range base the push is judged against, not `--policy-from`. Planned grade: Medium, 2 to 4 hours (2026-11-01). It follows TSK-350 because both edit the pre-push call in `push_set.rs` (one writer at a time).

## Outcome

After this merges, an adopter whose task branch passes `codeflow ci --branch` is no longer refused by pre-push, or judged against the wrong base, because of a target-line mismatch; a push to a destination that does not advertise the line is still refused.
