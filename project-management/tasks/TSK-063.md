# TSK-063: agent-os guide rebuilt on the doctrine

## Description

Rebuild the Agent OS repository guide to the design and the doctrine, inside
this epic, on the starter as it stands on `integration/EPC-016-visual-guide`,
dogfooding the integration starter rather than a published release. The
guide already exists: Agent OS PR #54 landed it on Agent OS `main` on
2026-09-20 (read at `origin/main` `3c6568b` on 2026-09-23). It is the
managed docs-portal starter 2.0.0 under `guide/`, six layers over `system/`
and `docs/`, theme `folio`, and ADR-0041 there makes it a derived output with
no content of its own that does not restructure deployed doctrine; only one
page (`docs/architecture/repository-surfaces.md`) has a figure, a
`cf-stage`. Start from a fresh branch off that `main`. Re-adopt the
integration starter through `portal setup` from a CodeFlow binary built at
the integration head, so the guide carries the kit's chrome, the three
skins, the Display panel, search and the panels.

Figures go only on pages operators read, which the Agent OS alignment audit
of 2026-09-23 names as `system/getting-started.md`, `system/operations/`,
`system/core/architecture/` and `docs/architecture/`; confirm the list
against the bundle manifest before composing. No figure, declaration or
rewritten doctrine enters a source the agent loads into its context:
`system/skills/**` (the operating rules are
`system/skills/operating-rules/SKILL.md`), `system/core/identity/SOUL.md`
(8192-byte deployed budget, constitution block byte identical across homes)
and `system/core/identity/AGENTS.md`. Accepted Agent OS ADRs under
`docs/decisions/` are append-only and are not rewritten either. The guide
renders every source today, and the gate would otherwise treat each as
explanatory, so declare these sources pass-through in
`guide/portal.config.json` with the class TSK-059 adds: agent-loaded
source for the skills and identity files, accepted record for the ADRs.
They stay visible in the guide with their bytes unchanged. Every other page
that is neither composed nor pass-through is named in the closeout with the
reason; none is dropped from the guide. Placing a figure in an agent-loaded
source needs an Agent OS ADR amending ADR-0041, which is the operator's
decision and is not assumed here. Compose
each operator-read explanatory page with the explanation method (TSK-072): a
figure per altitude and a figure in each how-to section under the grammar,
the design primary authoring the declarations; rewrite the prose on those
pages to the rules (short, plain, bullets where they help, no em or en
dash). Any `system/` byte that changes changes the bundle, so the Agent OS
release impact note and `scripts/release_bundle.py sync` follow its rules.

Settle three things early: the theme value (the starter maps `folio` onto
the retired skins; after TSK-060 set a kit skin, or rely on the `folio`
alias and record it); the page-class and composition gate run over the
current Agent OS pages, with the pass-through declarations in place, before
any date is promised; and the tier question
(Agent OS is minimal and the portal workflow ships at standard and full:
move to standard, or record a minimal-tier exception in an Agent OS ADR; the
Agent OS audit recommends minimal with an exception, and the operator
decides). Run its own `validate --portal` and browser verification. The
design primary reviews every route rendered. Non-goal: the public showcase
in the sibling `agent-os-portal` repository (ADR-0012 there), which is not a
CodeFlow portal. Landing the Agent OS PR on Agent OS `main` waits for the
CodeFlow release that publishes the starter the guide pins; the rebuild,
verification and review are complete inside this task.

## Affected surfaces and interfaces

The Agent OS repository only: `guide/**`, `.codeflow/docs-portal.json`,
`guide/portal.config.json` theme and pass-through declarations,
`.codeflow/project.toml` if the tier changes, the operator-read sources
that gain figure declarations and rewritten prose
(`system/getting-started.md`, `system/operations/`,
`system/core/architecture/`, `docs/architecture/`), one new ADR for the
tier decision. Never `system/skills/**`, `SOUL.md`,
`core/identity/AGENTS.md` or an accepted ADR. The CodeFlow side ships
nothing new for this task; the pass-through class is TSK-059's.
