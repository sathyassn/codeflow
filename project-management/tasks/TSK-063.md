# TSK-063: agent-os guide rebuilt on the doctrine

## Description

Rebuild the Agent OS repository guide to the design and the doctrine, inside
this epic, on the starter as it stands on `integration/EPC-016-visual-guide`,
dogfooding the integration starter rather than a published release. The
guide already exists: Agent OS PR #54 landed it on Agent OS `main` on
2026-09-20 (read at `origin/main` `3c6568b` on 2026-09-23). It is the
managed docs-portal starter 2.0.0 under `guide/`, six layers over `system/`
and `docs/`, theme `folio`, and ADR-0041 there makes it a derived output with
no content of its own that does not restructure deployed doctrine; only one
page (`docs/architecture/repository-surfaces.md`) has a figure, a
`cf-stage`. Start from a fresh branch off that `main`. Re-adopt the
integration starter through `portal setup` from a CodeFlow binary built at
the integration head, so the guide carries the kit's chrome, the three
skins, the Display panel, search and the panels.

### The rule for Agent OS sources

This task changes no byte under Agent OS `system/` and no byte of an
existing file under `docs/`, accepted ADRs included; `release-checklist-v2.md`
stays frozen as the Agent OS contract says. It restructures no page into
the Concept, Architecture, Technical trio, and it rewrites no prose. Prose
changes to Agent OS doctrine are Agent OS product work under its own
contract. Because no `system/` byte changes, the deployed bundle does not
change and this task has no bundle duty. Outside `system/` and `docs/`,
the root `AGENTS.md`, `CHANGELOG.md` and `README.md` change only as the
successor ADR requires.

### Companion figures

Every figure this task adds is a companion declaration owned by the guide,
under `guide/figures/`, for example `guide/figures/<route>.yaml`. Each one:

- is bound in `guide/portal.config.json` to a route and, optionally, a
  section anchor, with the page class TSK-059 adds (illustrated source);
- names in its `facts[]` the source path and anchor of every fact it
  draws, so the fidelity rule re-derives each one from the unchanged source;
- is rendered by the adapter above the source, or at the head of its
  anchored section, and passes all twelve figure rules;
- never overrides, restates or adds to a source instruction; it draws a
  relationship the source already states.

Add companion figures across the guide, `getting-started.md`, the
`operations/` pages and the architecture pages included: one per route for
the relationship its subject is about (this is the page-head figure the
illustrated source gate requires), and one per how-to section that is
a sequence, the design primary choosing the family and the facts. A route
with no relationship to draw, and every accepted ADR, is declared
pass-through with its reason. `repository-surfaces.md` already carries the
trio and stays explanatory; its figures are companion declarations bound
to its three panels.

Agent OS ADR-0041 makes the guide a derived view with no content of its
own. Write a narrow successor ADR in Agent OS that authorizes guide-owned
companion figure declarations with recorded provenance (the source path
and anchor of each fact), rules out any declaration that overrides or
restates a source instruction, and names the fidelity check that binds
them. ADR-0041 stays as it is. Follow the partial supersession shape Agent
OS already uses: ADR-0033 carries `supersedes: ADR-0004` and a
`supersedes_scope` line in its frontmatter and leaves the older ADR
unedited. The successor ADR also updates the two root contract clauses it
makes untrue, read at Agent OS `3c6568b`: `AGENTS.md:271-273` (the guide
is configured only through `guide/portal.config.json`) and
`AGENTS.md:340-343` (edit the sources and `guide/portal.config.json`),
which gain the guide-owned figure declarations. As the ADR-0041 commit
did, it adds the guide entry to the pending section of `CHANGELOG.md` and
updates the guide paragraph of `README.md` where it needs a word. This is
a design choice settled by the primary inside the operator's request for
an illustrated guide; it is reviewed with this task.

The verification record for this task lives in Agent OS at
`docs/verification/guide-companion-figures-<date>.md`, following the
Agent OS convention for dated evidence; it is the one added file under
`docs/` beside the two ADRs.

ADR) and this task's acceptance. An unanswered D5 authorizes neither the
upgrade nor the exception.
