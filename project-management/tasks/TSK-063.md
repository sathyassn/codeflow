# TSK-063: agent-os guide rebuilt on the doctrine

## Description

Rebuild the Agent OS repository guide on the starter as it stands on
`integration/EPC-016-visual-guide` and the figure grammar, dogfooding the
integration starter rather than a published release. The guide exists on Agent OS's `docs/repository-guide` branch (six
layers over `system/` and `docs/`, `guide/portal.config.json`, ADR-0041
declaring the guide a derived, never-committed output); it renders the
sources as text. Adopt the integration starter through `portal setup` from a CodeFlow binary
built at the integration head on that branch,
compose a figure per altitude on each explanatory page under the grammar
(the design primary authors the declarations), settle and record the tier
question (Agent OS is minimal tier and the portal workflow ships at standard
and full: either move to standard, or record a minimal-tier exception in an
Agent OS ADR), and run its own `validate --portal` and browser verification.
Non-goal: the public showcase in the sibling `agent-os-portal` repository
(ADR-0012 there), which is not a CodeFlow portal; landing the Agent OS PR,
which waits for the CodeFlow release that publishes the starter and is the
operator's follow-on after this epic closes.

## Affected surfaces and interfaces

The Agent OS repository only: `guide/**`, `.codeflow/docs-portal.json`,
`.codeflow/project.toml` if the tier changes, the `system/` and `docs/`
sources that gain figure declarations, one new ADR for the tier decision. The
CodeFlow side ships nothing new for this task.

## Acceptance Criteria

- [ ] The Agent OS guide builds from the starter at the integration head,
      its `.codeflow/docs-portal.json` pins that starter's hashes, and
      `validate --portal guide` is clean with the binary built at that head;
      evidence: the Agent OS branch and the recorded output with both SHAs.
- [ ] Every explanatory page of the Agent OS guide carries a figure per
      altitude in a named family and passes the figure gate; evidence:
      `browser:verify` on the Agent OS branch.
- [ ] The tier decision is recorded in an Agent OS ADR and the scaffold state
      agrees with it; evidence: the ADR and `codeflow doctor`.
- [ ] The design primary reviews every Agent OS route rendered in three skins,
      two modes and two widths; Grok adversarial review of the combined Agent
      OS diff; evidence: the review records.
- [ ] The Agent OS branch is pushed with a draft PR body that names Agent
      OS PR #54 and the CodeFlow release as its preconditions; re-pinning to
      the released starter and landing are the operator's follow-on, not a
      predecessor of TSK-064; evidence: the branch and the draft body.

## Execution contract

Plan v2, EPC-016. Responsible primary: claude-primary (Fable) at high effort,
primary-retained for every figure's composition; an Opus worker adopts the
starter and drafts page markup. Cross-lineage reviewer: Grok at high effort.
Integration target for the CodeFlow record: `integration/EPC-016-visual-guide`;
the Agent OS PR targets Agent OS `main` after the operator's merge order.
Recovery: git reversal on the Agent OS branch; the guide is a derived output.
