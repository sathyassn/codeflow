# TSK-063: agent-os guide rebuilt on the doctrine

## Description

Rebuild the Agent OS repository guide to the design and the doctrine, inside
this epic, on the starter as it stands on `integration/EPC-016-visual-guide`,
dogfooding the integration starter rather than a published release. The
guide already exists: Agent OS PR #54 landed it on Agent OS `main` on
2026-09-20 (read at `origin/main` `3c6568b` on 2026-09-23). It is the
managed docs-portal starter 2.0.0 under `guide/`, six layers over `system/`
and `docs/`, theme `folio`, and ADR-0041 there makes it a derived output with
no content of its own that does not restructure deployed doctrine; only one
page (`docs/architecture/repository-surfaces.md`) has a figure, a
`cf-stage`. Start from a fresh branch off that `main`. Re-adopt the
integration starter through `portal setup` from a CodeFlow binary built at
the integration head, so the guide carries the kit's chrome, the three
skins, the Display panel, search and the panels.

### Route inventory

Every route the guide builds is classified before any page is composed,
from what the runtime makes an agent read, never from a directory name or
the bundle manifest (which proves shipment, not reading). A page an
operator reads can also be one an agent reads; being operator-read never
exempts it. A source is agent-loaded when any of these holds, with the
citing line recorded:

1. It is loaded as instructions: a skill, an identity file, or a file whose
   filled copy becomes one.
2. A loaded source names it as a required read, an executable dependency
   before the affected work proceeds.
3. A loaded source directs the agent to it for a binding or a rule it must
   apply.
4. The setup assistant is told to read or follow it, or copies it into a
   file the deployed agent loads.

This moves `getting-started.md`, `daily-operation.md`,
`deployment-topologies.md` and most of `system/core/architecture/` out of
the figure set that the Agent OS audit proposed. `presentation-binding.md`
has no citation at `3c6568b`, so it is confirmed at the start scan before
composing. The executor reruns the same scan at the task's start base and
again after any rebase. A new citation moves a page into pass-through; a
page leaves pass-through only with evidence that the citation is gone. No
route is dropped, and none is left unclassified: an undeclared route stays
explanatory under TSK-059, so it must carry figures.

Declare every pass-through route in `guide/portal.config.json` with the
class TSK-059 adds, reason agent-loaded source or accepted record. Those
routes stay visible in the guide with their source bytes unchanged. Placing
a figure in an agent-loaded source needs an Agent OS ADR amending
ADR-0041, which is the operator's decision and is not assumed here.

### Composing the operator-only set

Compose each page in the operator-only set with the explanation method
(TSK-072): a figure per altitude and a figure in each how-to section under
the grammar, the design primary authoring the declarations; rewrite the
prose on those pages to the rules (short, plain, bullets where they help,
no em or en dash on the lines this task adds or rewrites). A page named as
a source by a qualification requirement keeps the statement that
requirement cites (`maintenance.md` for AO-SHIP-001 in
`qualify-model-binding/resources/requirements.v1.json`). Any `system/` byte
that changes changes the bundle, so the Agent OS release impact note and
`scripts/release_bundle.py sync` follow its rules.

### Early settlements and the operator decision

Settle two things early: the theme value (the starter maps `folio` onto the
retired skins; after TSK-060 set a kit skin, or rely on the `folio` alias
and record it); and the page-class and composition gate run over the
current Agent OS pages with the pass-through declarations in place, before
any date is promised.

The tier is the operator's decision D5 (Agent OS is minimal and the portal
workflow ships at standard and full: move to standard, or record a
minimal-tier exception in an Agent OS ADR; recommended: standard). D5 does
not block this task's preparation: the inventory, the declarations, the
starter adoption on a branch, the figures and the verification can all
proceed. It blocks the tier-dependent change (`.codeflow/project.toml` and
the tier ADR) and this task's acceptance. An unanswered D5 authorizes
neither the upgrade nor the exception.

### Handoff with EPC-018

EPC-018's TSK-082 also changes Agent OS: it rewrites agent-loaded sources
(`operating-rules`, the SOUL condensed block, `model-strategy.md` and any
text naming a model) and the qualification cases. This task writes none of
those. The epic's Agent OS handoff decides the order: TSK-082 lands first;
this task then rebases its Agent OS branch onto the new `main`, reruns
`release_bundle.py sync` and `verify-state`, the route inventory scan, the
pass-through byte check against the new base, `validate --portal guide`,
the browser verification and the Agent OS tests. If this task is ready
first, the order flips and those duties fall on TSK-082's owner.

Run its own `validate --portal` and browser verification. The design
primary reviews every route rendered. Non-goal: the public showcase in the
sibling `agent-os-portal` repository (ADR-0012 there), which is not a
CodeFlow portal. Landing the Agent OS PR on Agent OS `main` waits for the
CodeFlow release that publishes the starter the guide pins; the rebuild,
verification and review are complete inside this task.
