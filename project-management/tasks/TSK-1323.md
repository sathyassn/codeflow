# TSK-1323: A stacked claim finds its predecessor on an integration line from any checkout

## Description

coord/catalog reported on 2026-11-04 (11:58) that `codeflow work claim --on TSK-1185@<sha>`, run from the project root, refused with "TSK-1185 pin is not the unique predecessor branch tip" (`crates/codeflow-core/src/workgraph/work_start.rs:1742-1749`), while the same claim from a worktree at the line tip found the predecessor. The branch-to-task match reads task ids from the record files visible in the current checkout (`visible_task_ids`, `work_start.rs:1604`). The root checkout is on `main`, which holds neither task, so a predecessor that lives only on an integration line is never found. Every stacked claim on a line task hits this; the workaround is a detached worktree at the line tip.

This task reads the predecessor's identity from history the claim is judged against, never from whatever the current checkout happens to hold, and keeps refusing every pin that is not a reviewed predecessor's exact tip. Non-goals: which pins count as reviewed (TSK-1271 and the review lookup), and the claim's push handling (TSK-1322).

## Outcome

After this merges, a builder can stack a claim on a reviewed line task from any checkout, including the root on `main`, and gets the same result as from a worktree at the line tip.

## Deliverables

- the lookup change and its tests: `crates/codeflow-core/src/workgraph/work_start.rs` and its tests
- the changelog entry: `changelog.d/TSK-1323.md`

## Acceptance Criteria

- AC-1 A stacked claim's predecessor lookup shall read task ids from the tree of the claim's target tip, and from the pinned commit's tree only for a record the target tip does not hold, never from the current checkout's files; evidence: a test that runs the claim from a checkout on `main` holding neither task and finds a predecessor that exists only on the line, refused before the change and accepted after.
- AC-2 The pin checks shall stay as strict: a pin that is not the unique predecessor branch tip, a pin at a commit other than the reviewed head, two branches carrying the same task, and a task id that no tree read holds still refuse; evidence: a test per case.
- AC-3 The lookup shall depend only on commits and their trees, never on which branch is checked out or on files outside version control; evidence: a test that varies the checkout and adds an untracked record file, with the same result.
- AC-4 (journey) With the change built, the same stacked claim run from the root checkout on `main` and from a worktree at the line tip gives the same result; evidence: both commands and their exit codes.
