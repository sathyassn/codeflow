# TSK-132: a pre-push gate under a minute that blocks

## Description

The pre-push quick gate runs the whole test suite in 5.5 to 7.6 minutes,
only warns, was pushed through while failing, and competes with full gates
for CPU. This task makes pre-push a set that finishes in under a minute and
blocks, for CodeFlow and, as the operator settled, as the shipped default
for adopters: format, lint, `validate --docs` and `codeflow ci` on the
pushed range, with the test suite left to the full gate. Changing the
adopter default from warn to block is public behaviour and is marked so in
the changelog. Source: guardrails strand row 9 and top five item 2.

## Affected surfaces and interfaces

- `crates/codeflow-cli/src/cmd/git_hook.rs` (pre-push), the push set in
  `.codeflow/test-config.json` and the scaffolded test config.
- `test_gate_on_push` default in `assets/base/policy.json` and
  `.codeflow/policy.json`; `codeflow update` policy migration.
- `CHANGELOG.md` with a release-impact marker.

## Acceptance Criteria

- [x] AC-1 Pre-push shall run only the push set and block on its failure; on
      CodeFlow's own repository the set shall finish in under 60 seconds on
      a warm target; evidence: a hook test for the block path and a timed
      push log.
- [x] AC-2 When the push set's measured time exceeds 60 seconds, the hook
      shall name the slowest target and the config key that moves it out of
      the push set; evidence: a hook test with a slow fixture target.
- [x] AC-3 In a freshly scaffolded project at every tier (minimal, standard,
      full) `test_gate_on_push` shall default to block with the fast set;
      evidence: `init_e2e` and `tier_floor_e2e`.
- [x] AC-4 `codeflow update` shall keep an existing `test_gate_on_push`
      value and print one line recommending `block` and how to set it
      (amended in review round 1: equality with the old baseline cannot show
      the adopter did not choose `warn`); evidence: update tests for the
      default-equal `warn`, other explicit values and an existing `block`.
- [x] AC-5 The changelog shall state the new default as a public behaviour
      change with the way to restore warn; evidence: the `CHANGELOG.md`
      entry and its release-impact marker.

## Closeout

The push set is `codeflow ci` on each pushed branch's range (from the
destination's own tracking refs, else the first protected branch that
resolves, else a note that CI runs it), plus the tree checks
`codeflow validate --docs` and the test-config targets that define `quick`
(no alias to `essential`). The tree checks run only when a pushed sha is the
checked-out commit with no tracked changes; any other pushed branch gets a
note that they did not run. `test_gate_on_push` defaults to `block` in code,
in `assets/base/policy.json` and in this repository's policy.
