# TSK-1382: The whole core test run passes with the build output folder set and unset

## Description

Filed on 2026-11-07 for two core tests that failed whenever `CARGO_TARGET_DIR` was set (`testing::gate::evidence_root_link_tests::a_link_at_the_build_output_folder_is_refused_before_any_write` and `testing::runner::tests::timeout_cause_survives_dependent_skips_and_saved_report`), with a sweep of sibling tests. TSK-1369, complete on the EPC-022 line through PR 688, delivered both: the two tests pass under both settings and its sweep covers the core and CLI tests (TSK-1369 Findings and acceptance block).

What TSK-1369 did not establish is a green run of the whole `codeflow-core` test suite with the variable set and unset. Its acceptance block records that the core library's set run still failed `testing::runner::tests::a_heavy_target_keeps_progressing_past_the_base_timeout` at its 4 s wall-clock ceiling under load. That test's wait is TSK-1413 AC-3 (filed in PR 756), so this task runs after TSK-1413 lands.

This task, narrowed on 2026-11-10, is that remaining proof, and the fix of anything the proof turns up that only fails with the variable set.

Non-goals: changing how the gate resolves the build output folder (TSK-1044's rule, unchanged by TSK-1369), and the CLI integration tests that set `CARGO_TARGET_DIR` on purpose (`test_gate_cli.rs`, `test_setup_cli.rs`, `hooks_cli.rs`).

## Outcome

After this merges, a maintainer or a builder can run the whole core test suite with `CARGO_TARGET_DIR` set, as in a worktree, and get the same result as with it unset, with no gate evidence written outside the tests' temporary projects.

## Deliverables

- the two run logs and the probe output, named in the pull request body
- a fix and its release note (`changelog.d/TSK-1382.md`, internal) only if AC-2 finds a failure this task owns

## Estimate

- Grade: Easy; band: Easy (1 to 2 h); moved: none
- Split: not needed
- Basis: two full runs of one crate's tests and one probe; a fix only if a new set-only failure appears. Planner judgment from the criteria.

## Acceptance Criteria

- AC-1 `cargo test -p codeflow-core` shall pass with `CARGO_TARGET_DIR` set to a per-worktree folder outside the test projects and again with it unset, at a line tip that contains TSK-1413; evidence: both logs saved with the commit they ran on, and a listing of the set folder after the set run showing no gate evidence written there (the check TSK-1369 AC-4 used).
- AC-2 A test that fails only with the variable set shall be fixed in this task, or recorded in `## Findings` with file:line and the task that owns it; evidence: the Findings table, and for a fix, the test failing before and passing after with the variable set.

Criteria changed on 2026-11-10: the former AC-1 (the two named tests pass under both settings) and the sweep part of the former AC-2 were delivered by TSK-1369 AC-2 and AC-3; the former AC-3 (no non-test code changes) no longer applies, since the delivered fix is TSK-1369's.
