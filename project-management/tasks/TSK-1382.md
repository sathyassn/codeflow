# TSK-1382: Core tests locate the build output folder the way the gate does

## Description

Two core tests fail whenever `CARGO_TARGET_DIR` is set and pass when it is unset, observed on `main` at `acf0be5b6`: `testing::gate::evidence_root_link_tests::a_link_at_the_build_output_folder_is_refused_before_any_write` (fails at `crates/codeflow-core/src/testing/gate.rs:1756`) and `testing::runner::tests::timeout_cause_survives_dependent_skips_and_saved_report` (fails at `crates/codeflow-core/src/testing/runner/mod.rs:1927`). The code under test finds the build output folder through `target_dir` and `target_anchor` in `crates/codeflow-core/src/testing/delivery.rs`, which read `CARGO_TARGET_DIR` and fall back to `target`. Both tests build their fixture at `<project>/target` and assume that is where the code looks, so they break in a session or on a host that sets the variable, which is the normal case for a worktree builder.

This task makes the two tests resolve the build output folder through the same function the code uses, so they pass with and without the variable. It also sweeps the other tests that join `target` onto a project path (for example `runner/mod.rs:3142`, `gate_guard.rs:2589` and `:4425`, and `delivery.rs:799`) and fixes each one that fails with the variable set. It changes no product behaviour: `delivery.rs` is read, not edited, unless the sweep shows a helper is needed for tests, in which case it is a test-only helper.

Non-goals: changing how the gate resolves the folder, and the CLI integration tests that set `CARGO_TARGET_DIR` on purpose (`test_gate_cli.rs`, `test_setup_cli.rs`, `hooks_cli.rs`).

Evidence at filing: `/private/tmp/claude/post562/624-main-probe-two-tests.txt` and `624-branch-two-tests.txt` (workspace scratch, not committed).

## Outcome

After this merges, a maintainer or a builder can run the core tests with `CARGO_TARGET_DIR` set, as in a worktree, and get the same result as with it unset.
