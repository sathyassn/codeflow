# TSK-1446: CodeFlow's own CI placement and reuse are proven on main

## Description

TSK-1445 changes workflows that enforce themselves from the default branch, so its proof exists only after it lands. This task reads the first runs after TSK-1445 lands and shows the placement working, or lands the prepared revert first. While `main`'s heavy checks are relaxed (TSK-1452's temporary items), no pull request into `main` runs the heavy jobs, so there is no full run to reuse: the temporary placement is proved right after TSK-1445 lands (AC-2, AC-4 and AC-5), and the reuse proof (AC-1) is read on the first pull request into `main` and its push after TSK-1452's restore. The task stays open until then. Non-goal: any workflow change of its own.

Landing on its target (`main`, right after TSK-1445):

- Reachable: nothing new.
- Inert: not applicable; it reads runs.
- Other lines: nothing.

## Outcome

After this merges, a CodeFlow maintainer has run links showing that a line push starts no hosted run, that the temporary placement on `main` runs as TSK-1451 sets it, and, after TSK-1452's restore, that a push to `main` reuses its pull request's full run; or the revert is on `main`.

## Deliverables

- the run links and the result: this record's Closeout
- the revert, if a run is red: the revert branch TSK-1445 prepared

- AC-1 After TSK-1452's restore, a push to `main` whose tree equals its pull request's full run shall reuse that run and name it, and a push on a differing tree shall run in full; a skipped heavy job is never reuse evidence; evidence: the run links.
