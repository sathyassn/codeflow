# TSK-1553: The guard names the real cause when a sibling worktree registration vanishes during a read

## Description

Source: the Director's sweep of 2026-11-19 (13:2x), relayed to coord/records. Filed by coord/records.

As reported by the Director, not checked here: while a night-loop runner removed worktrees (12:22 to 12:45), the codeflow guard in other live worktrees refused every command with `cannot read project root: cannot read worktree registration: No such file or directory (os error 2) ... the operator runs git worktree repair`. Both registrations of the affected worktrees were intact afterwards. Two builders were stopped for about an hour. Evidence named: Codex panes `term_f7e21afb` (12:29) and `term_7636b5b0` (12:26), and `coordination/coordinators/capabilities/notes/tsk1476-round-zd-report.md:7` and `:156` (line 156 holds the refusal text).

Checked here (coord/records, 13:3x): the text comes from `crates/codeflow-core/src/hooks/repo.rs:1091` (`registered_marker`), which reads `<admin>/gitdir` with one bounded read and maps any error to `cannot read worktree registration: <error>`. `registrations` (`repo.rs:1071-1082`) lists every registration folder with `repo.worktrees()` first, so the guard reads the registrations of sibling worktrees as well as its own; a sibling folder removed between the listing and the read gives the same `No such file or directory`. That cause fits the report but is not shown by a run here. The existing task TSK-379 (complete; discovery cannot unprotect enforcement files) built this reader; it records no case where a registration disappears while the guard reads. `git grep` of the task records for `worktree registration` finds only TSK-379.

Premise: read `repo.rs:1060-1120` and every caller of `registered_marker` and `registrations`, TSK-379's criteria, and `tsk1476-round-zd-report.md:7` and `:156`; reproduce the refusal with a stub that removes a sibling registration folder between the listing and the read (the single reproducible check); then decide the design.

Non-goals:

- Weakening the guard: it must keep refusing when a registration cannot be read.
- Telling the operator to repair when no repair is needed, or any change to `git worktree repair` itself.

## Outcome

After this merges, a guard run that cannot read a worktree registration because the registration disappeared during the read refuses, as now, but the message names the cause (a registration was removed while the guard read it) and tells the agent to retry once the removal has finished. A registration that is present and unreadable, or malformed, still refuses with the operator repair advice.

## Deliverables

- the registration reader's error separation: a vanished sibling registration (not found at read time) is told apart from an unreadable or malformed present one, both fail closed
- the message for the vanished case: names the cause and says to retry after the removal ends; the repair advice stays only for the other case
- tests for each case, with the vanished case failing before the change
- the release note: `changelog.d/TSK-1553.md`

## Acceptance Criteria

- AC-1 When a worktree registration listed during discovery is not found at read time, the guard shall refuse and name that cause, and shall tell the agent to retry after the removal ends, without the `git worktree repair` advice; evidence: a test with a stub that removes a sibling registration between the listing and the read, failing before the change and passing after.
- AC-2 When a present registration cannot be read or is malformed, the guard shall refuse as it does now, with the operator repair advice unchanged; evidence: tests for an unreadable file and a malformed file, with the current text asserted.
- AC-3 The guard shall still fail closed in the vanished case, with the same refusal exit and no command run; evidence: the test of AC-1 asserts the exit status and that nothing ran.
- AC-4 When the change is made, it shall touch only the registration reader and its message, its tests, the release note and any documentation of the message; evidence: the diff paths.
