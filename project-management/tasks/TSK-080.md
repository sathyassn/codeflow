# TSK-080: model bindings check and catalog derived tests

## Description

Make the catalog checkable by the operator and make the tests read the
catalog instead of naming models, so the next roster change edits data only.

Extend the existing `codeflow doctor --check model-bindings`
(`doctor/mod.rs`, today it reports route selectors and probe presence). It
runs the TSK-079 validator on the managed catalog, the personal overlay and
the project file, and prints one resolved row per supported host harness and
workload: the chosen line and version, selector, effort and fallback chain,
for example `claude-code / design -> claude-primary: opus 5.5 @high,
fallback fable 5.1`. It warns, without failing, on: a newer version pending
in a line, an `operator-designated` version with no full-suite record, and an
observed id that differs from a recorded canary. It still never launches a
model, and says so in its output.

Tests whose data comes from the catalog, each with a failing fixture:

- no selector, alias or full id of any catalog version appears in a
  `SKILL.md`, a skill resource other than the catalog, a template, a reviewer
  agent, `grok-host.md`, `cf-herdr`, `cf-delegate` or a workflow example;
- no `retired` selector appears outside `docs/decisions/`,
  `docs/verification/`, `project-management/`, `CHANGELOG.md` and
  `docs/plan/`.

Remove the literal selector and class pins in `orchestration_contract.rs`
(today near lines 263-273 and 736-738) and the hand stale-pin list (near
line 352) in favour of structural checks read from the catalog: every seat
line has an eligible version, every workload resolves on some supported
host, `engineering-review` includes the Codex seat, the design owner seat is
Claude. After this task no test file names a current model.

Why it earns its keep: the doctor row is the one place an operator sees what
"latest eligible" resolved to on their machine; the derived tests replace
three hand lists that already went stale.

Non-goal: launching models, availability discovery, prose migration
(TSK-081).

## Affected surfaces and interfaces

`crates/codeflow-core/src/doctor/mod.rs` and its tests;
`crates/codeflow-cli/tests/orchestration_contract.rs`; a new test module for
the derived checks where the crate layout calls for one. CAP-013.

## Acceptance Criteria

- [ ] When `codeflow doctor --check model-bindings` runs on a scaffolded sample, it shall print a resolved row per host harness and workload and the warnings above, and shall fail on any catalog, overlay or project violation; evidence: doctor tests and one sample run pasted in the closeout.
- [ ] When a fixture places a catalog selector in a skill, the derived test shall fail; when it places a retired selector outside the historical paths, the second test shall fail; evidence: both failing fixtures and the passing run.
- [ ] No test file names a current model, and the structural checks replace the removed pins; evidence: a search of the test tree in the closeout and the targeted test output.
- [ ] Editing only the catalog (a fixture that adds a newer candidate Sol version) changes the doctor row and passes every test without an instruction or test edit; evidence: the fixture test.
