# TSK-193: present conversation: replies, reopen, revision diff, check

## Description

A reviewer in present sees the agent's reply, can reopen a resolved
thread, sees what changed between two revisions, and an agent can validate
a page without a browser. This is the rest of the present parity package
the operator approved on 2026-09-26; nothing on the line covers it
(`delivery.rs` and `responses.rs` reserve replies, reopens and
tombstones). It replaces TSK-121 (with two narrowings: the digest of
uncommitted changes becomes a dirty flag beside the commit, and revision
labels and the code-block content digest are dropped as polish), the rest
of TSK-122 (`present check`, engine and width qualification; the blind
evaluation cases are dropped as evidence with no consumer), and TSK-179's
documentation line (the Codex wake itself waits on Codex CLI and needs no
task until it ships).

## Affected surfaces and interfaces

- `crates/codeflow-present/` (state store, rail, delivery, responses, the
  `present diff` and `present check` commands), `crates/codeflow-cli/src/cmd/present.rs`,
  the present web package and its distribution, the cf-present
  `references/feedback-loop.md` and mirrors, the 3.0.1 CHANGELOG.

## Acceptance Criteria

- AC-1 An agent reply shall appear in the thread's rail entry; a resolved
  thread can be reopened; a deleted thread leaves a visible tombstone; the
  session store records each transition against its revision; `present
  list` shows a one-line summary per session (TSK-121's revision labels
  are dropped as polish). Evidence: state tests; browser cases; CLI test.
- AC-2 `present diff <id> --from N --to M` shall print a block-level diff
  with notes and answers carried to the target revision and each carried
  note marked as such. Evidence: a golden test over a fixture with added,
  removed and edited blocks.
- AC-3 Each revision shall record the repository commit and whether the
  tree was dirty (TSK-121's digest of uncommitted changes narrowed to that
  flag); a captured code or diff block shall record its path and commit
  (the content digest is dropped); export shall omit notes, answers and replies unless
  `--with-notes`; no service route serves repository files. Evidence:
  tests; a route probe.
- AC-4 `present check <id>` shall validate framing, anchors and forms
  without a browser and name each fault; a faulty fixture fails, a clean
  one passes. Evidence: CLI tests.
- AC-5 The review round trip (open, comment, answer, reply, reopen, diff)
  shall run in Chrome, Firefox and Safari and at 375 px on the built
  package. Evidence: the browser suite per engine, recorded once. (journey)
- AC-6 The feedback-loop reference and the CHANGELOG shall state the
  shipped conversation, the Codex wake limitation and its route. Evidence:
  review; `validate --docs`.

Criteria note (AC-6): the entry belongs in pending 3.0.0 because present first
ships there and no 3.0.1 section exists; this corrects the affected-surface label.
