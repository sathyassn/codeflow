# TSK-1563: The acceptance binding accepts a revert that re-creates an earlier completion

## Description

Source: the Director's ruling on PR 857 (TSK-408), 20 Nov 00:1x, after `codeflow ci` blocked work.acceptance_binding on that branch. Filed by coord/records.

What happened: the branch range holds a reopen of a completed task (`c7be4d9c93`) and, later, a plain `git revert` of that reopen (`0f533680d3`). The revert restores the completed record, so the completion reviewed at `5ab950c967` is live again. The next reopen then archives it a second time. `codeflow ci` expects the archive to hold every completion the range made, in order, and counts the revert as a completion. No sanctioned verb can write that block at that position: `task status complete` appends at the end, a record-only redaction keeps results and reviewed commits, and a waiver changes a criterion result. The message names those three exits, and none of them fixes the archive.

Any adopter can hit this, since a revert of a reopen is an ordinary git action. The PR 857 work-around was to recut the branch without the pair (approved by the Director); that rewrites history and changes every head, so it should not be the answer for the next adopter.

Premise: before any change, reproduce it as an inert fixture: a record completed on the target, a branch that reopens it, reverts the reopen, reopens it again and completes it. Run `codeflow ci` on it and say what it blocks and which count it uses. Decide from the reader which of these is right, with a reason: the revert is not a completion (the check derives completions from verb-written transitions only), or the revert's restored block is accepted as the archive's matching entry, or the check names a verb that does write it. Do not weaken the check for any history that really made a completion without a block.

Non-goals: allowing a hand-written archive block; changing waivers or redactions; the PR 857 recut itself.

## Outcome

After this merges, a branch that reopens a task, reverts that reopen and reopens it again passes the acceptance binding when its archive is true to the verbs that wrote it, and a branch whose archive really lacks a completion still fails.

## Deliverables
