# TSK-1413: Three tests with fixed waits tolerate a loaded host

## Description

Three tests fail on a host under heavy load (load average about 200) and pass when run alone. Each waits on a fixed wall-clock bound rather than on the event it needs. TSK-1253 (complete) fixed this class for tests that wait on a fake remote or a child process, but its sweep does not name these three.

| Test | Failure under load | Alone |
|---|---|---|
| `codeflow-core` `hooks::git_guard::tests::kept_line_readings_match_fresh_readings_and_verdicts` (`git_guard.rs:15615`) | "cannot verify Git configuration: child exceeded 3 seconds", the guard's fail-closed bound on a Git child (`security/git_config.rs:456`, `:497`); PR 718's merge `dd3914477` | passed in 0.97 s at load about 29 |
| `codeflow-core` `testing::runner::tests::a_heavy_target_keeps_progressing_past_the_base_timeout` (`runner/mod.rs:1680`) | "timed out at the ceiling after 4 s" after all six steps had printed; PR 695's merge `ed19b5676` | passed in 3.97 s, 30 ms under its own 4 s ceiling even on an idle host |
| `codeflow-cli` `hooks_cli` `exec_guard_judges_the_paths_an_interpreter_is_given` (`hooks_cli.rs:8659`) | "the guard reached no decision within 20 seconds" (`GUARD_DEADLINE_SECS`, `cmd/hook.rs:161`) during a 1141 s suite; PR 695's merge | passed in 98.96 s, far above one 20 s decision, so the test may hold a single decision near the bound |

Scope: the test side only. The guard's 3 s Git child bound, its 20 s decision deadline and their fail-closed refusals are security bounds and stay unchanged in this task; a builder finding that adopters hit one of them is recorded for separately authorized work, never acted on here. Overlaps:

- TSK-1318 AC-9 makes `target_repository::earlier_writes_make_the_next_runner_state_unknown` accept the same 3 s refusal while keeping the 3 s limit, and records that 55 sibling assertions in `target_repository.rs` can meet it. This task follows the same rule for `git_guard.rs`'s own tests and leaves `target_repository.rs` to TSK-1318.
- TSK-1406 covers the `hooks_cli` glob deadline only.

## Outcome

After this merges, these three tests pass under the synthetic load that AC-5 records, so that load alone no longer reddens a gate run.

- the sibling sweep table and the load reproductions: the pull request body

## Acceptance Criteria

- AC-1 For each of the three tests, the wait that expired shall be named (file:line) and classed as a test bound or a product bound. The product bounds (the guard's 3 s Git child bound in `security/git_config.rs`, the 20 s decision deadline `GUARD_DEADLINE_SECS`) and their fail-closed refusals shall stay unchanged; if the builder finds that adopters hit one of them on an ordinary loaded host, the finding is recorded with its evidence and a tracked item for separately authorized work, and nothing in the product changes here; evidence: a `## Findings` section in the pull request body and the diff, which touches no product bound.
- AC-2 `kept_line_readings_match_fresh_readings_and_verdicts` shall keep every pure reading comparison it makes now and shall compare cached and fresh verdicts deterministically across its whole corpus, with no comparison dropped or skipped because the host is slow. Tolerance of the guard's fail-closed "child exceeded 3 seconds" refusal shall be tested separately: a deterministic case with a slow `git` on `PATH` shall show that this refusal, and only this refusal, is accepted where a verdict depends on a Git child, and that every other error still fails the test, as TSK-1318 AC-9 does for `target_repository`; evidence: the comparison count before and after, the deterministic case, and a fail-before under induced load.
- AC-3 `a_heavy_target_keeps_progressing_past_the_base_timeout` shall prove its point by an event: the target shall show that it is still active after its base timeout has passed (for example a marker it writes only after that time) before it is allowed to finish, with a generous safety bound for the whole run, so the test no longer passes or fails by milliseconds against its ceiling (4 x `timeout_seconds`, which is 4 s today and 30 ms above the idle run time). `an_active_heavy_target_still_reaches_its_ceiling` shall stay as the separate proof that the ceiling holds; evidence: the event in the test, and idle and loaded run times before and after.
- AC-4 `exec_guard_judges_the_paths_an_interpreter_is_given` shall pass under load with every payload and refusal assertion it has now. The builder shall time each guard decision in it, alone and under load, and find which one nears the 20 s deadline and why (the 99 s aggregate spans many decisions and does not by itself show one near the bound). The fix makes that decision's test setup cheaper, for example a smaller fixture or fewer files to read, without changing what is judged; if the slow decision is slow in the product itself, the finding says so under AC-1's rule and names the task that owns it; evidence: per-decision timings before and after.
- AC-5 (journey) Each of the three tests shall fail before and pass after under the same synthetic load (for example a CPU burner sized to the host's cores), with host, revision, load average and the command recorded; evidence: the runs.
- AC-6 A sibling sweep shall list every remaining fixed child or decision bound that tests in `git_guard.rs`, `testing/runner/mod.rs` and `hooks_cli.rs` depend on, apart from `target_repository.rs` (TSK-1318 AC-9) and the glob deadline (TSK-1406), and fix each or record why it is safe under load; evidence: the sweep table in the pull request body.
