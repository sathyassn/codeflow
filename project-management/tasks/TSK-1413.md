# TSK-1413: Three tests with fixed waits tolerate a loaded host

## Description

Three tests fail on a host under heavy load (load average about 200) and pass when run alone. Each waits on a fixed wall-clock bound rather than on the event it needs. TSK-1253 (complete) fixed this class for tests that wait on a fake remote or a child process, but its sweep does not name these three.

| Test | Failure under load | Alone |
|---|---|---|
| `codeflow-core` `hooks::git_guard::tests::kept_line_readings_match_fresh_readings_and_verdicts` (`git_guard.rs:15615`) | "cannot verify Git configuration: child exceeded 3 seconds", the guard's fail-closed bound on a Git child (`security/git_config.rs:456`, `:497`); PR 718's merge `dd3914477` | passed in 0.97 s at load about 29 |
| `codeflow-core` `testing::runner::tests::a_heavy_target_keeps_progressing_past_the_base_timeout` (`runner/mod.rs:1680`) | "timed out at the ceiling after 4 s" after all six steps had printed; PR 695's merge `ed19b5676` | passed in 3.97 s, 30 ms under its own 4 s ceiling even on an idle host |
| `codeflow-cli` `hooks_cli` `exec_guard_judges_the_paths_an_interpreter_is_given` (`hooks_cli.rs:8659`) | "the guard reached no decision within 20 seconds" (`GUARD_DEADLINE_SECS`, `cmd/hook.rs:161`) during a 1141 s suite; PR 695's merge | passed in 98.96 s, far above one 20 s decision, so the test may hold a single decision near the bound |

Scope: the test side. The product bounds stay unless the builder shows that adopters hit them on an ordinary loaded host; the guard's 3 s Git child bound and its 20 s decision deadline fail closed, and that refusal is kept. Overlaps:

- TSK-1318 AC-9 makes `target_repository::earlier_writes_make_the_next_runner_state_unknown` accept the same 3 s refusal while keeping the 3 s limit, and records that 55 sibling assertions in `target_repository.rs` can meet it. This task follows the same rule for `git_guard.rs`'s own tests and leaves `target_repository.rs` to TSK-1318.
- TSK-1406 covers the `hooks_cli` glob deadline only.

## Outcome

After this merges, these three tests pass on a heavily loaded host, so a gate run is not reddened by host load alone.

## Deliverables

- the repaired tests: `crates/codeflow-core/src/hooks/git_guard.rs`, `crates/codeflow-core/src/testing/runner/mod.rs`, `crates/codeflow-cli/tests/hooks_cli.rs`, or their helpers
- the sibling sweep table and the load reproductions: the pull request body

## Acceptance Criteria

- AC-1 For each of the three tests, the wait that expired shall be named (file:line) and classed as a test bound or a product bound; a product bound that fails closed (the 3 s Git child bound, the 20 s guard decision deadline) shall stay unchanged unless the builder shows adopters hit it on an ordinary loaded host, and then the finding says so; evidence: a `## Findings` section in the pull request body.
- AC-2 `kept_line_readings_match_fresh_readings_and_verdicts` shall not depend on host speed: it waits on the event it needs, or accepts the guard's fail-closed "child exceeded 3 seconds" refusal, and only that refusal, in place of an expected reading, while at least one reading in the test is still compared; a deterministic case with a slow `git` on `PATH` shall show that the refusal is accepted and any other refusal still fails, as TSK-1318 AC-9 does for `target_repository`; evidence: the deterministic case and a fail-before under induced load.
- AC-3 `a_heavy_target_keeps_progressing_past_the_base_timeout` shall have margin: the work it runs shall fit well inside its ceiling on an idle host (not 30 ms under it), while it still proves that an active target outlives its base timeout and `an_active_heavy_target_still_reaches_its_ceiling` still proves the ceiling holds; evidence: the idle and loaded run times before and after.
- AC-4 `exec_guard_judges_the_paths_an_interpreter_is_given` shall pass under load: the builder shall find which guard call in it comes near the 20 s decision deadline and why the test takes 98.96 s alone, then either make that call cheaper in the test or split the test so no single decision depends on host speed; if one decision itself is slow in the product, the finding says so and names the task that owns it; evidence: per-decision timing alone and under load, before and after.
- AC-5 (journey) Each of the three tests shall fail before and pass after under the same synthetic load (for example a CPU burner sized to the host's cores), with host, revision, load average and the command recorded; evidence: the runs.
- AC-6 A sibling sweep shall list every remaining fixed child or decision bound that tests in `git_guard.rs`, `testing/runner/mod.rs` and `hooks_cli.rs` depend on, apart from `target_repository.rs` (TSK-1318 AC-9) and the glob deadline (TSK-1406), and fix each or record why it is safe under load; evidence: the sweep table in the pull request body.
