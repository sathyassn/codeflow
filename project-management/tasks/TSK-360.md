# TSK-360: The repository contract states builder evidence and the hosted green landing rule

## Description

Source: the operator's request of 2026-10-17 to make the gates fast while
the right checks run locally and in hosted CI, the primary's decisions on
it the same day, and the hosted-red diagnosis of 2026-10-17.

Two rules this repository works by are not written where builders and the
primary read them:

- **Builder evidence.** Builders no longer run `codeflow test --mode
  essential`. Their evidence is targeted tests plus the quick gate (the
  pre-push quick run counts for the same tree), which the managed block of
  `AGENTS.md` already states in its "build" row; one full gate runs on each
  landing candidate. The project section of `AGENTS.md` still says the
  opposite: its "Rust gates" bullet asks for `codeflow test --mode
  essential` on every `crates/**` change. This repository's own pipeline
  copy (`.claude/workflows/pipeline.workflow.js`, user-owned, never touched
  by `codeflow update`) runs essential in its final verification stage.
- **Hosted green before the next landing.** The line was red on hosted
  Linux and Windows from 2026-10-12 while later pull requests landed. The
  rule: a red hosted run on an integration line blocks the next landing on
  that line until the red is diagnosed, meaning its cause is named and its
  repair is a tracked task; the repair itself may land. Once TSK-358 lands,
  a pull request into an integration line lands only with its own hosted
  `codeflow gates` and `windows` verdicts green; TSK-358 updates that
  sentence when it lands.

The managed block between the codeflow markers is maintained by
`codeflow update`, and the files under `.codeflow/rules/` are managed
scaffold destinations, so both rules go in the project section of
`AGENTS.md`, below the markers.

Process note: the second rule adds a check before every landing on a line.
The operator asked for this gap to be closed on 2026-10-17 (relayed by the
primary). Protection: no landing on top of an unexplained hosted failure,
so platform failures cannot pile up as they did from 2026-10-12. Cost: a
look at the line's latest hosted run before each landing, and a wait of
about 31 minutes when a run is in progress. The planning pull request
states this for the operator's confirmation.

Non-goals: the managed block, shipped rules and the shipped pipeline
default for adopters (an adopter-facing decision this plan does not make).
Product surface: this repository's contract and its own pipeline copy only.
