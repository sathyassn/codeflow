# TSK-142: local full gate parity on one machine

## Description

On 2026-09-27 the local full gate on the EPC-020 line could not go green
in one run on one machine. `docs-portal` needs Node 24.18.0 (its
`.node-version`) and `cf-present-qualification` needs the official Node
26.4.0 (its `package.json` engines; Homebrew's 26 fails on zlib), and CI
pins each per job while the local gate runs both under one PATH. The
present real-browser check uses `target/debug/codeflow` and ignores
`CARGO_TARGET_DIR`, although `real-browser-check.mjs` honours
`CF_PRESENT_CODEFLOW`, which the gate command does not pass. On Windows,
a killed gate leaves its target processes running and frees the machine
lock, because only Unix tracks the target's process group. Two tests
fail at random: the readiness test
`a_pin_is_an_object_id_never_a_ref_name` writes an 8-character commit
prefix unquoted in YAML, which parses as a number when it is all digits
or reads as one (such as `12e45678`); and the present test
`process_group_cleanup_requires_and_terminates_the_exact_owned_identity`
failed once under a loaded full gate and passed on rerun (workspace
`RELEASE-PLAN.md`, deferred there to 3.1, which "nothing parked"
overrides). This task makes one `codeflow test --mode full` invocation
reproduce CI on one machine.

Cross-line dependency: the figure-gate test that runs over 900 seconds
belongs to TSK-118 on `integration/EPC-016-visual-guide`, whose AC-8
names that test and whose closer makes its duration bound explicit. The
one-machine gate of AC-1 is green on the combined release candidate only
once that bound holds. This is a cross-line reference, not a
`depends_on` edge, because `validate --docs` refuses a task id that does
not exist on this line. Non-goal: the 120-second present handoff expiry
is by design (ADR-0049, planning resolution 20).

## Acceptance Criteria

- AC-1 When the local full gate runs `docs-portal` and
  `cf-present-qualification` in one invocation, each target shall run on
  the Node version its CI job pins, read from a version file per target,
  and a missing version shall fail that target with a message naming the
  version; evidence: `gate-parity` asserting that the local and CI pins
  agree, and a full gate log on one machine with both targets green, on
  this line and on the combined release candidate after TSK-118
  (EPC-016 line) bounds the figure-gate test's duration.
- AC-2 When the gate runs the present real-browser check, it shall use
  the `codeflow` binary the gate built, wherever `CARGO_TARGET_DIR`
  points; evidence: a gate run with `CARGO_TARGET_DIR` outside the
  worktree in which the check passes, and a `gate-parity` check on the
  target command.
- AC-3 When a full gate is killed on Windows, its running targets shall
  end with it, so the machine lock never frees while a target of the
  killed gate runs; evidence: a runner test on the Windows CI job that
  kills the gate process and finds the target tree gone.
- AC-4 When `workgraph::readiness::tests::a_pin_is_an_object_id_never_a_ref_name`
  runs, it shall pass whatever commit id the run produces, with the pin
  written as a typed string instead of an unquoted YAML scalar; and when a
  record's `depends_on` pin is an unquoted commit prefix that YAML reads
  as a number, the dependency parser shall read the commit id as written
  or refuse it saying the pin must be quoted, never report that it is
  not a commit id (today it reports `pin must be a commit id`); evidence:
  the test with fixed all-digit and exponent-form prefixes, and
  `deps.rs` tests for both unquoted forms.
- AC-5 (journey) In a freshly scaffolded project driven by the installed
  CLI, when a `codeflow test --mode full` is killed during a long target,
  no second full gate shall run beside that target: on Windows the target
  ends with the gate, on Unix the lock stays held until the target's
  process group exits (TSK-134), and the next full gate then takes the
  lock; evidence: a `test_gate_cli` case run on the Windows and Linux CI
  jobs.
- AC-6 When `process_group_cleanup_requires_and_terminates_the_exact_owned_identity`
  runs under a loaded full gate, it shall pass, with the cause of its
  failure under load found and fixed rather than retried; evidence: the
  cause in the Closeout and a stress loop under parallel load with the
  pass count before and after the fix.

## Closeout

Implemented; completion waits for the review round and the primary's
full gate.

- AC-1: `scripts/with-node.py` runs each Node target on the version its
  version file pins (`docs-portal/.node-version` 24.18.0,
  `crates/codeflow-present/web/.node-version` 26.4.0) and fails naming
  the version when it is not installed. `gate-parity` holds each version
  file to the `package.json` engines and to every `actions/setup-node`
  pin, including the job that runs the full gate.
- AC-2: the present target passes `CF_PRESENT_CODEFLOW` resolved from
  `CARGO_TARGET_DIR`; `gate-parity` refuses a real-browser check without
  it. The check passed with the target directory in the scratchpad.
- AC-3 and AC-5: each Windows target starts suspended in a kill-on-close
  job object (`testing/runner/target_job.rs`). The Windows runner test and
  the `test_gate_cli` journey run only on the Windows CI job.
- AC-4: the readiness test writes the pin as a typed string, and an
  unquoted pin YAML reads as a number is refused with the quoting remedy.
- AC-6 cause: two faults, each seen under load. On macOS, `ps` can list
  another process caught mid-exec with bytes that are not UTF-8, and the
  inventory refused the whole listing; it now decodes lossily, and a
  stray byte can neither hide nor forge an owned line. The fixture's
  `trap 'exit 0' TERM` could miss the signal on macOS `/bin/sh` (bash
  3.2), which defers a trapped TERM that lands as `read` starts, so the
  cleanup escalated to SIGKILL; the fixture now takes the default action,
  and the test asserts SIGTERM. A trap probe hung 4 of 3,750 runs with
  the trap and 0 of 3,750 without it.
- AC-6 stress loop (12 loaders spawning shells and holding a CPU each):
  before the fix 398 of 400 and 798 of 800 passed; after it 800 of 800,
  twice.
