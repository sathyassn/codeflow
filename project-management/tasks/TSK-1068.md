# TSK-1068: The release benchmark and release qualification state an Outcome on the records they create

## Description

On the checkpoint pull request from the 3.2.0 line into `main` (PR 396),
run 40866564188 at `35672e8bd` failed its required "codeflow gates" check
because the release benchmark failed: `validate --docs` exited 1 on the
benchmark's 10,000-record inventory (job 123424842821). TSK-435 made
`validate --docs` refuse a task or epic created after the project adopted
`## Outcome` when that section is empty, and a fresh `init` adopts it with
`outcome_present_uids = []`. TSK-435 filled the Outcome in the record
fixtures of the tests that run on every pull request, but the read
benchmark is an ignored test that runs only in the release gate (ready pull
requests into `main`, pushes to `main`, the schedule and manual runs), so
its generator kept writing records with no Outcome. The release
qualification script (`tests/release-qualification/qualify.sh`) has the
same gap: it runs `epic new` and `task new`, then expects
`validate --docs` to report a clean graph, and no hosted job runs it.

The validation rule is correct and stays as it is. The fix fills the
Outcome in both generators, as a record's author does. A fast, non-ignored
test validates records built from the benchmark's own templates, so a rule
the generator misses fails in the ordinary Unix workspace test runs. The
qualification's record rows (`qualify_records`) move into
`tests/release-qualification/lib.sh`, which `qualify.sh` already sources, so
a test runs those exact rows against the built binary. The benchmark, its
inventory size and its budgets are unchanged.

This task proves the benchmark passes on its own branch, in a hosted manual
run of the full workflow. Whether PR 396's required check then passes is
known only when that pull request reruns after this lands on the line; that
rerun is evidence for the checkpoint, not for this task.

At an earlier head, `30e233602`, all executed jobs of manual codeflow-ci run
40934916460 passed (the verdict-reuse job was skipped): the release
benchmark (job 123668126058, `completed target 'read-benchmark': passed`),
release prose and present, the build, both coverage shards and the report
(92.96 percent against a 90 percent floor), security review, "codeflow
gates", the Windows partitions, "windows journeys" and "windows". This
record is final before the run at the PR head that lands, so that run covers
it; the PR body names that run, its head SHA and its job conclusions.

## Outcome

after this merges, the 3.2.0 line's release benchmark and the release qualification's record rows can run on records that `validate --docs` accepts

## Deliverables

- the benchmark generator, its fast validation test and its failure message: `crates/codeflow-cli/tests/read_benchmark.rs`
- the qualification record rows and their Outcome step: `tests/release-qualification/lib.sh` (`qualify_records`, `state_sample_outcomes`), called from `tests/release-qualification/qualify.sh`
- the qualification rows test: `crates/codeflow-cli/tests/release_qualification_records.rs`
