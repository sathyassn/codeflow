# TSK-453: The several-suppliers test counts line reads instead of timing them

## Description

The unit test `security::interpreter::tests::several_suppliers_read_the_line_once` protects the TSK-302 review F4 fix: on a line with several `xargs` or `find -exec` suppliers, the exec guard reads what the whole line names once per directory (`Facts::line_enforcement` and `Facts::line_authority` in `crates/codeflow-core/src/security/arguments.rs`), not once per call. The test checks this with a 5-second wall-clock budget. Three reviews on 2026-10-24 measured the same binary at 0.75 to 17 seconds at host load 15 to 34, and it failed on the integration line's own code, so local full gates fail on host load alone.

Outcome: **the test proves the line is read once across suppliers by counting the reads, so its result no longer depends on host load.**

Scope: a test-only counter on the two line readings and the test that reads it. Non-goal: changing the guard's behaviour or the hook's time budget.

## Deliverables

- the test-only read counter: `crates/codeflow-core/src/security/arguments.rs`
- the rewritten test: `crates/codeflow-core/src/security/interpreter.rs`

## Acceptance Criteria

- AC-1 When five `xargs` interpreter calls run from one directory on one line, the test shall assert that all five calls ask for both readings and that the line's enforcement reading and its authority reading each run exactly once, with no wall-clock assertion. Evidence: the diff and a passing `cargo test -p codeflow-core --lib security::interpreter::tests::several_suppliers_read_the_line_once`.
- AC-2 When the per-directory cache is removed from either reading, or only the first call on the line is judged (mutations), the test shall fail. Evidence: the mutated run's failure output for each mutation, recorded in the PR.
- AC-3 The test shall pass on repeated runs under concurrent host load. Evidence: a run log of at least 20 runs with the load average at each run, recorded in the PR.

## Execution contract

- Affected surface: this repository's tests only; the counter is compiled only under `cfg(test)`, so no shipped behaviour changes and no release note is needed.
