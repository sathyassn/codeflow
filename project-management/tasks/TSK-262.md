# TSK-262: Present show waits out a dying browser group on Linux

## Description

Hosted Linux CI (the coverage job on PR 124, run 37814253287) failed
`present_cli show_after_the_browser_exited_ignores_unreadable_command_lines`
with "browser process group exists without its verifiable leader". The
stand-in browser is a shell with a `sleep` child in its own process group.
The test kills the group and reaps the shell, then runs `present show`. On
Linux `/proc/<leader>/cmdline` is then gone, but `kill(-pgid, 0)` still
succeeds while the killed `sleep` is exiting or waits, as a zombie, for its
new parent to reap it. `process_identity_from_proc` treats any surviving
group member as a live process it cannot prove and refuses. A real user hits
the same window after quitting the browser: its helper processes exit after
the main process, and in a container whose first process never reaps, the
zombies stay for good.

The fix: when the recorded leader is gone and its group still answers, the
identity check waits a bounded 2 seconds for the group to empty, and on Linux
it counts a group whose every visible member is an exited, unreaped process
(state `Z` or `X` in `/proc/<pid>/stat`) as exited. A group with a live
member, or a member it cannot read, still fails closed with the same
message after the wait. The cleanup path after SIGTERM and SIGKILL uses the
same test of an exited group. A `/proc` read that fails with `ENOENT` or
`ESRCH` because the process was reaped between two reads now counts as gone,
in the identity check and in the owned-process scan; any other read error,
such as a permission error, stays an error. Nothing new is ever signalled: the exited
outcome is `Absent`, which signals nothing, and the existing owned-process
inventory and profile checks still run after it.

Scope: the Unix identity check and cleanup waits in
`crates/codeflow-present/src/browser.rs`. macOS gets the bounded wait; its
zombie handling is unchanged. Non-goals: Windows, what counts as owned, and
the refusal to signal an unproven process.
