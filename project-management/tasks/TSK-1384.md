# TSK-1384: Tests that run git use the test build of codeflow, never an installed one

## Description

On PR 700 a CLI test ran `codeflow init`, which installs the git hooks, and then ran git through a helper that does not put the test build of codeflow first on `PATH`. On hosted CI the installed hook found no `codeflow` and failed. Locally an installed `codeflow` answered the hook instead, so the test passed while exercising a different binary from the one under test. Any test that spawns git in a repository with codeflow hooks has the same exposure.

This task makes the shared test helpers that spawn git in `crates/codeflow-cli/tests/support/` and `crates/codeflow-core/tests/support/` build `PATH` from the test binary's own folder (`CARGO_BIN_EXE_codeflow`), drop every other folder that holds a `codeflow`, and remove any inherited `CODEFLOW_HOOK_BINARY` without ever setting it. It adds a check that fails a test spawning git outside those helpers, with a reasoned allowlist, moves the current tests onto the helpers, and proves the targeted suites pass with no `codeflow` on `PATH`.

Sibling note: PR 700 fixes only its own helper. This task owns the class. Nearest open tasks, checked 2026-11-07, do not cover it: TSK-1280 (tests run offline, no network host), TSK-364 (a substituted hook binary cannot pass a hook silently, which concerns the shipped shim, not the test helpers) and TSK-1285 (a hook binary older than the repository says so).

Non-goals: product hook or shim behaviour (TSK-364, TSK-1285), and tests that set `PATH` or `CODEFLOW_HOOK_BINARY` on purpose to test that behaviour; those take an allowlist row with the reason.

## Outcome

After this merges, a maintainer can trust that a test which runs git through codeflow hooks exercised the test build, on any host, with or without an installed `codeflow`.

## Deliverables

- the git-spawning helpers: `crates/codeflow-cli/tests/support/`, `crates/codeflow-core/tests/support/`
- the check, its allowlist and its fixture test: provisional home under `crates/*/tests/` or `scripts/`, decided by the builder and named in the PR
- the moved tests: `crates/codeflow-cli/tests/`, `crates/codeflow-core/tests/`
- the no-codeflow `PATH` run: a CI step in `.github/workflows/` or a quick target in `.codeflow/test-config.json`
- release note: `changelog.d/TSK-1384.md` (internal)

## Acceptance Criteria

- AC-1 The shared test helpers in codeflow-cli and codeflow-core that spawn git shall build `PATH` from the test binary's own folder (`CARGO_BIN_EXE_codeflow`), shall drop any other folder that holds a `codeflow`, shall never set `CODEFLOW_HOOK_BINARY` and shall remove an inherited one; evidence: helper tests that pass with a stand-in `codeflow` first on the caller's `PATH` and show the stand-in never runs.
- AC-2 A check shall fail any test that spawns git outside those helpers, with an allowlist that gives a reason per entry; evidence: the check, plus a fixture test that fails before and passes after.
- AC-3 Every current test that spawns git shall move to the helpers or get a reasoned allowlist row; evidence: the check passes on the tree.
- AC-4 The targeted suites shall pass with no `codeflow` on `PATH`; evidence: a CI step or quick target that runs them with `PATH` stripped of every folder holding a `codeflow`, failing before (PR 700's pre-fix test, or an equivalent fixture) and passing after. (journey)
