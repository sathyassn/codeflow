# TSK-369: Each landing candidate's full gate records its own coverage

## Description

Source: both test integrity audits of 2026-10-17 at
`eaf2ed04e932186cdd26dc4a7e5740cc553acee3` (Fable finding F4; Codex
coverage section).

The gate already records coverage in each full run's `run.json`
(`crates/codeflow-core/src/testing/gate.rs`, `coverage`), with the 90
percent line floor from `.codeflow/test-config.json` (`rust-coverage`).
What is missing is a green, complete full run on the tree that lands. Of
21 complete local full runs in the archive, 6 were green and the last 8
were red: `present-browser` fails under the agent sandbox (Firefox cannot
start), and `release-automation` usually hits its 600 second timeout. The
candidate behind this line head (`a1bb1ff30`) timed out on `rust-coverage`
at 1800 seconds; its 92.74 percent line figure came from a run whose gate
did not pass. No coverage figure exists for the audited tree.

Outcome: each landing candidate on this line has a complete full gate whose
`run.json` carries the coverage totals (lines, functions, regions) and the
floor for that exact tree, and its pull request cites them. A target that
cannot run in the local sandbox either runs, or is recorded as owed to a
named hosted job with that job's run id, and such a run is never shown as
complete local evidence without it.

Coordinated, not duplicated: TSK-331 (machine lock and worker budget)
removes overlap timeouts; PR 224's restored test-time task owns the
`rust-coverage` time limit and the guard fuzz tests; PR 226's fixture task
shortens the serial path, and its selection task adds the Git tree id this
task cites. Any timeout change is gate configuration and needs a stated
reason and the operator's approval, as PR 224's task already requires.

Product surface: this repository's gate configuration and landing
evidence; engine only if recording a hosted-owed target needs a run record
field (CAP-004), stated in the pull request.

## Deliverables

- `release-automation`: the cause of its timeouts found and fixed, or its timeout changed with reason and approval (`scripts/test_release.py`, `.codeflow/test-config.json`)
- `present-browser`: run where it can run (outside the sandbox through the sanctioned route, or the hosted present part), with the local record naming the hosted job when it did not run locally
- landing evidence: the PR evidence reference for this repository (provisional: `AGENTS.md` project section, coordinated with PR 226's contract task) stating that a landing candidate's pull request cites its full run id, tree, coverage totals and floor
- the proof: one landing candidate's full gate, cited in this task's pull request

## Acceptance Criteria

- AC-1 On the reference host, `release-automation` shall finish inside its
  configured timeout in three consecutive full gates, or its timeout shall
  change with a recorded reason and the operator's approval; evidence: the
  three run ids and durations. (serves EPC-022 AC-67)
- AC-2 `present-browser` shall either pass in the local full gate or be
  recorded in the run as not run locally, naming the hosted job and run id
  that passed it on the same tree; evidence: the run record and the hosted
  run link.
- AC-3 A landing candidate's full gate shall be complete and passed, and its
  `run.json` shall carry line, function and region coverage with the floor
  for the candidate's tree; evidence: the run id, revision and tree, and
  the coverage block. (serves EPC-022 AC-67)
- AC-4 (journey) The next landing on this line after this task shall cite,
  in its pull request, the candidate's full run id, tree and coverage
  totals; evidence: that pull request's Testing section.
