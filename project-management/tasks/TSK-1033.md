# TSK-1033: The shipped instructions declare each value once and reviews ask about copies

## Description

Issue #274 and the operator's quality asks of 2026-10-27, declare once
(D4). Two adopting repositories held hundreds of hand copies of names,
ids, team slugs, paths, settings and closed sets of strings, most
bypassing a home that already existed (an exported constant nothing
imports, a declared tuple compared against raw literals, a required-check
guard covering two of six names), and 12 copied helper families (21 git
wrappers, 59 JSON loaders, 82 repository-root lookups); a team rename
needed 122 lines in 50 files edited by hand, and both reviews checked
only that the edit was complete. The shipped instructions say "keep
business rules single-sourced" and "stay DRY with judgment", but say
nothing about declaring each value once as an enum, constant or type,
and the reviewer is not asked about copies.

TSK-425 (EPC-024) is the define-once gate; it needs TSK-424's register
and baseline. This task is the instruction-level part, small on its own.

Outcome: **the shipped instructions require each value with meaning
(names, ids, paths, settings, closed sets of strings, limits) to be
declared once as a constant, enum or type that every use reads,
generates from or checks; shared shapes and helpers to have one home
that callers import; and code to be DRY and modular in that sense; and
`cf-reviewer` asks whether a change copies a value or code that already
has a home, a new unchecked copy being a material finding.**

Rules:

- The rule covers values across languages and file types (code,
  workflows, policy, infrastructure, config); where one language cannot
  import another's value, the copy is generated from or checked against
  the home.
- A copy kept on purpose (a test's independent oracle, a stable
  protocol constant, documentation) is allowed with a stated reason; the
  instructions say which cases count.
- This task delivers the review question that TSK-424 AC-5 first named
  ("whether a change copies a value that has a home"); TSK-424 AC-5
  keeps only the exemption question.

Non-goals: the gate, adapters, the known-values file and exemptions
(TSK-425, TSK-424); rewriting copies that adopters already hold.

### Research findings (AC-1, 2026-10-30, line tip `461827479`)

Recorded before any instruction change, as AC-1 requires.

**Declaring a value once, by language.** Every stack CodeFlow serves
has a native home for a value with meaning and for a closed set of
strings, so the instruction can name the home in general terms and
leave the construct to the stack:

| Stack | Constant | Closed set of strings | Source |
|---|---|---|---|
| TypeScript | exported `const` | string `enum`, or a literal union from an `as const` array | [enums](https://www.typescriptlang.org/docs/handbook/enums.html), [literal types](https://www.typescriptlang.org/docs/handbook/2/everyday-types.html) |
| Python | module constant | `enum.StrEnum` (3.11), or `typing.Literal` checked by mypy | [enum](https://docs.python.org/3/library/enum.html), [mypy literal types](https://mypy.readthedocs.io/en/stable/literal_types.html) |
| Go | `const` block | typed constants with `iota`; `stringer` generates the names | [spec](https://go.dev/ref/spec), [stringer](https://pkg.go.dev/golang.org/x/tools/cmd/stringer) |
| Rust | `const` item | `enum` with serde `rename_all` or `strum` for the string form | [constant items](https://doc.rust-lang.org/reference/items/constant-items.html), [serde](https://serde.rs/container-attrs.html), [strum](https://docs.rs/strum/latest/strum/) |

**Values shared across file types.** Workflows, policy, infrastructure
and config cannot import a TypeScript or Rust constant. Current practice
gives them their own single home and then either generates the copy or
checks it:

- OpenTofu `locals` and variables hold a value once per module
  ([locals](https://opentofu.org/docs/language/values/locals/)).
- Rego reads shared values as data documents instead of restating them
  in each rule ([external data](https://www.openpolicyagent.org/docs/latest/external-data/)).
- JSON Schema `enum` makes a config file's closed set checkable
  ([enum](https://json-schema.org/understanding-json-schema/reference/enum)).
- GitHub Actions reusable workflows hold a shared job once
  ([reusing workflows](https://docs.github.com/en/actions/sharing-automations/reusing-workflows)).
- Code generation from one source: Protocol Buffers enums
  ([proto3](https://protobuf.dev/programming-guides/proto3/)),
  Rust to TypeScript types with typeshare
  ([typeshare](https://github.com/1Password/typeshare)) or ts-rs
  ([ts-rs](https://github.com/Aleph-Alpha/ts-rs)), and JSON to types with
  quicktype ([quicktype](https://quicktype.io/)).
- CodeFlow does the same with its own copies: managed skills are mirrored
  under `.claude/skills`, `.agents/skills` and the baseline, and the
  `manifest_consistency` test checks each mirror against the source.

**Tools that find copies.** These are TSK-425's adapters; this task only
cites them so the instruction names a class of check, not a tool:

- magic values: Ruff `PLR2004`
  ([magic-value-comparison](https://docs.astral.sh/ruff/rules/magic-value-comparison/)),
  ESLint `no-magic-numbers`
  ([rule](https://eslint.org/docs/latest/rules/no-magic-numbers)),
  Biome `noMagicNumbers`
  ([rule](https://biomejs.dev/linter/rules/no-magic-numbers/));
- duplicate strings: `sonarjs/no-duplicate-string`, Sonar rule S1192
  ([eslint-plugin-sonarjs](https://github.com/SonarSource/eslint-plugin-sonarjs)),
  Go `goconst` ([goconst](https://github.com/jgautheron/goconst));
- an enum compared with a raw literal: typescript-eslint
  `no-unsafe-enum-comparison`
  ([rule](https://typescript-eslint.io/rules/no-unsafe-enum-comparison/)),
  which catches the issue's "declared tuple compared against raw
  literals" in TypeScript;
- copied blocks: jscpd ([jscpd](https://github.com/kucherenko/jscpd)),
  PMD CPD ([CPD](https://pmd.github.io/pmd/pmd_userdocs_cpd.html)),
  Pylint `duplicate-code`
  ([duplicate-code](https://pylint.readthedocs.io/en/stable/user_guide/messages/refactor/duplicate-code.html)).
- No linter sees a value copied across languages (a team slug in a
  workflow, a policy file and TypeScript). That needs issue #274's
  known-values file, which TSK-425 builds; until then the review question
  is the only check.

**Where DRY goes too far.**

- DRY is about knowledge, not text: each piece of knowledge has one
  authoritative representation
  ([DRY](https://en.wikipedia.org/wiki/Don%27t_repeat_yourself)). Two
  blocks that look alike but change for different reasons are not a copy.
- A wrong shared abstraction costs more than duplication, and the remedy
  is to inline it again
  ([The Wrong Abstraction](https://sandimetz.com/blog/2016/1/20/the-wrong-abstraction),
  [Goodbye, Clean Code](https://overreacted.io/goodbye-clean-code/)).
  The rule of three waits for a third use before extracting shared code
  ([rule of three](https://en.wikipedia.org/wiki/Rule_of_three_(computer_programming))).
  This bounds the helper half of the rule; a value with meaning has one
  home from its first use, because its copies drift silently.
- Tests: expected values written out in the test keep it an independent
  oracle; a test that reads the constant under test cannot catch a wrong
  constant
  ([Tests too DRY](https://testing.googleblog.com/2019/12/testing-on-toilet-tests-too-dry-make.html)).
  `cf-reviewer` already rejects "implementation-copied expectations"
  (`assets/base/claude/agents/cf-reviewer.md:79-81`), so the exemption
  agrees with existing doctrine.
- Coupling: importing a value across a module or service boundary that
  should stay independent is worse than a checked copy. A stable protocol
  or format constant fixed outside the project (an HTTP status, a file
  signature) needs no project home.

**CodeFlow guidance today** (the survey above, rechecked at this tip):
the discipline rules say "stay DRY with judgment" without saying what
DRY means for values; `design-implementation.md:15-22` says "keep
business rules single-sourced"; `cf-reviewer` flags "duplicated business
knowledge or existing abstractions" (`cf-reviewer.md:30-32`) but never
asks about a copied value; `cf-develop` applies the neighbour rule
(`cf-develop/SKILL.md:34-35`) to helpers only. The neighbour rule in the
discipline rules ("find the neighbour that already does the job") is the
closest existing hook, so the new text sits beside it.

**Adjacent concerns.** Issue #274 asks for a gate (known-values file,
adapters, exemption register, ratcheting baseline) and a review
question. The amendment tables (EPC-022 D4, EPC-024 "Declare once") place
the gate in TSK-425 and the exemption question in TSK-424 AC-5; the
review question and the instruction ship here. A rename across languages
is the cost the issue measured (122 lines in 50 files); the instruction
addresses it by giving each value one home with generated or checked
copies.

**Chosen scope.**

- The discipline rules gain one paragraph, "Declare each value once", in
  "Write only what earns its keep": values with meaning and closed sets
  have one home (constant, enum or type) that every use reads, generates
  from or checks; shared shapes and helpers have one home callers import;
  DRY means knowledge, with the wrong-abstraction limit; the allowed
  deliberate copies, each with its reason at the site: a test's
  independent expected value, a stable external protocol or format
  constant, documentation and examples, and a generated or checked
  mirror; a new unchecked copy is under-design.
- `design-implementation.md` and `cf-develop` point at that paragraph
  instead of restating it.
- `cf-reviewer` asks the copy question and grades a new unchecked copy
  major (material), naming the copy and the home at file:line.
- Qualification: requirement CF-QA-017 with markers in each home, and
  three cases in the quality-core pack: a builder reads an existing
  constant, a builder adds an enum for a closed set, and a reviewer
  refuses a new unchecked copy.
- Not in scope: any lint, gate, known-values file or exemption register
  (TSK-425, TSK-424); `cf-stack` lint setup (TSK-425 AC-5); rewriting
  existing copies in adopter projects.
