# TSK-315: Misplaced records and outside waits get a report and guidance

## Description

Task and epic records drift from the truth in ways no check reports
(https://github.com/sathyassn/codeflow/issues/167, parts A to D): a record
lives on a line other than the one it targets, a status is written on a
line that is not the record's home, a closed pull request leaves a
completed record on no line, and a wait for another epic is written in
prose so `work next` calls the task ready. Part E, the binding defect, is
TSK-308 in EPC-022. This task adds four checks on TSK-311's facts, with
policy keys under `git.` and rule ids under `work.`:

| Check | Where | Default |
|---|---|---|
| `work.record_off_target`: a task whose target's fetched tip holds no copy; an epic whose line exists and holds no copy. Exempt: an epic and its breakdown's task records whose only copies are on the default branch (ADR-0078) | `validate --docs`, `report program` | warn (`git.record_hygiene`) |
| `work.off_home_status`: the range changes a task's status and its target is not the task's home line | `ci`, pre-push | warn |
| `work.orphaned_record`: a `complete` or `cancelled` record on a task branch and on no line; a registry id with no record on any ref; worded "on a branch, on no line" | `ids check`, `report program` | report |
| `work.prose_wait`: an open `todo` task whose Description holds "starts only after", "waits for" or "after ... merges" and has no Blocker | `validate --docs` | off (`git.prose_wait`), never above warn |

A copy that is `behind` or `same` never warns. At `block`, unknown
evidence refuses. Both keys are schema and defaults only (TSK-280): no file
carries them until a project writes them after raising its pin.

Guidance is written once in `project-organization.md` "The work lifecycle"
and pointed to from `cf-plan` and `cf-ship`: the home-line rule; planning
lands on the line its records target, or on the default branch for a new
epic; closing a PR unmerged is a record act only when the work is abandoned
or moved (cancel with `- scope:`), and closing a duplicate PR or changing
how the same work lands cancels nothing; an outside wait is a Blocker; a
shared-file change after a landing lands as a merge of its own reviewed
branch, else as a recorded line adoption in the same step. Deferred by
operator decision 9: the typed `landed` dependency and
`work.partial_at_ready`.

## Acceptance Criteria

- AC-1 `work.record_off_target` shall report each case of issue 167 part A
  and stay silent for a default-branch breakdown and for a record whose
  target's tip holds a copy; evidence: one fixture per case.
  (serves EPC-023 AC-3)
- AC-2 `work.off_home_status` shall warn in `ci` and pre-push when a range
  changes a task's status off its home line, as in issue 167 part B, and
  shall not warn on the home line; evidence: CLI tests.
  (serves EPC-023 AC-3)
- AC-3 `work.orphaned_record` shall list part C's records in `ids check`
  and `report program` with the wording "on a branch, on no line";
  evidence: a fixture of closed-unmerged task branches and a registry id
  with no record.
- AC-4 `work.prose_wait` shall be off by default, shall flag part D's
  phrases on an open `todo` task without a Blocker when turned on, and
  shall refuse any level above warn in policy validation; evidence: tests.
- AC-5 A `behind` or `same` copy shall never warn, and at `block` an
  unknown fact shall refuse; evidence: tests over TSK-311's fixtures.
- AC-6 `git.record_hygiene` and `git.prose_wait` shall exist in the schema
  and defaults only: `policy show` marks them `default (binary)`, `update`
  inserts neither, and TSK-280's placement check passes; evidence: tests.
- AC-7 The guidance shall be written once with pointers from `cf-plan` and
  `cf-ship`, every copy byte-identical; evidence: the text and
  `manifest_consistency`.
- AC-8 When the installed build runs in a scratch repository holding each
  of issue 167's examples A to D, each shall be reported once under its
  rule, and a copy that only lags its home shall not be (journey);
  evidence: the journey output.
