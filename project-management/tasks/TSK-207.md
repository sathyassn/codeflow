# TSK-207: the human override covers commits and pushes

## Description

A consuming project reported (sathyassn/codeflow#12) that the README's
promise, "A human can override the git-hook plane locally with
`CODEFLOW_HUMAN_OVERRIDE=1`", fails for the first push of `main` to an
empty remote after `codeflow init`: the pre-push hook refuses it under
`git.push_to_protected`, and the only way through is `--no-verify`. ADR-0007
gives humans this override for protected branches, but only the
pre-merge-commit and reference-transaction hooks read it; pre-push and
pre-commit honour only the integrate token. This task makes a human's
override pass the protected-branch commit and push rules too, keeps
force-push, deletion and history rewrites of a protected branch refused
(they are destructive, not landing), and corrects the README and the
enforcement docs to name exactly what the override covers and how a human
makes the bootstrap push. The git-guard keeps refusing an agent that sets
the override, and the remote's branch protection stays the authoritative
boundary. Non-goal: any agent path past the protected-branch rules.

## Acceptance Criteria

- AC-1 When a human runs `CODEFLOW_HUMAN_OVERRIDE=1 git push` of a
  protected branch, the pre-push hook does not refuse it under
  `git.push_to_protected`, and the same push without the override is still
  refused; evidence: a hooks CLI test with the installed hook, both ways.
  (journey)
- AC-2 When a human runs `CODEFLOW_HUMAN_OVERRIDE=1 git commit` on a
  protected branch, the pre-commit hook does not refuse it under
  `git.commit_to_protected`, and without the override it is still refused;
  evidence: a hooks CLI test, both ways.
- AC-3 With the override set, a force push and a deletion of a protected
  branch are still refused; evidence: hooks CLI tests.
- AC-4 The git-guard still refuses an in-session command that sets
  `CODEFLOW_HUMAN_OVERRIDE`; evidence: the existing guard tests, passing.
- AC-5 The README and the enforcement-planes doc name the rules the
  override covers (commit, merge and push to a protected branch) and those
  it never covers, and the adoption guide gives the human bootstrap push;
  evidence: the doc diff.
