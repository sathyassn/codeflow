# TSK-226: Records match what landed on main

## Description

CodeFlow 3.0.0 is published, and the records on `main` still describe the
time before it. Seven merged tasks (TSK-198 to TSK-202, TSK-090, TSK-187) are
`todo` or carry template closeouts; several tasks name integration lines that
exist only in the archive, so `codeflow work next` shows cancelled tasks as
waiting and finished work as ready. This task makes each record say what
happened, from the merged pull requests and the release evidence, and records
the decision on the release baselines. The test that keeps the baseline ids
honest is TSK-227's: a completion after a landing may change planning
records only, so `codeflow ci` refuses a range that completes landed tasks
and also adds code, and the two changes cannot share a pull request. This
task also replaces the plan's reuse of TSK-195: that record targets a retired
release branch, and a pull request that names it is refused by
`work.stable_planning_anchor` until a planning change retargets it, so the
reconciliation runs here and TSK-195 is only retargeted and noted (it
completes after this pull request's review).

Nothing is invented. Where evidence was never recorded or is not in this
repository (the archive review files), the acceptance block says so.
Non-goals: moving the release baseline tables (decided below), closing the
epics, changing what any task delivered, and TSK-091's and TSK-099's open
criteria, which need a release qualification run and a download that this
task does not run.

Decision on the release baselines: `release_records_baseline` and
`release_rule_baseline` keep their archive ids, for four reasons. SPC-013
R-120 makes them a write-once bridge, so any later edit makes every release
check refuse and name the editing commit. They carry only imports from the
five retired epic lines, and the public repository has no `integration/EPC-*`
branch (`git ls-remote --heads origin`, 2026-10-03), so no public release
range brings anything they would judge; a cutoff that is not on a line's
chain covers nothing, and a public-only clone reads the ids as absent with a
warning, as TSK-198 recorded. And `.codeflow/project.toml` is an enforcement
path that agents cannot edit, so a move is the operator's. TSK-227's test
lists the ten entries, so a rewritten id anywhere else fails and a release
table id missing from that list fails too. If public epic lines ever need
cutoffs, that is a specification change to the one-time bridge, not a
records fix.
