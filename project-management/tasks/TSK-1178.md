# TSK-1178: Candidate gates and the security review cannot certify themselves

## Description

Issue #279, widened 2026-10-30 after the Grok whole-diff review of PR 396 (CWE-345) and 2026-11-01 after Grok's CI scope check of PR 485. Split from TSK-336 on 2026-11-01. The whole-PR review of PR 479 graded TSK-336 Very Hard (9: S2 2, S6 1, S7 1, C 2, X 1, R 2), and a Very Hard task is split before claim. TSK-336 keeps the foundation (the default branch's code judges every pull request); this task takes one outcome with the criteria that prove it, moved and not copied, each marked with its old number. The five pieces are TSK-336, TSK-1175, TSK-1176, TSK-1177 and TSK-1178.

Merge admission, `ci-reuse.py admit` (`scripts/ci-reuse.py:182-207`), accepts the newest `codeflow-ci` `pull_request` run at the head by event, head SHA, pull request number and workflow path, and by the conclusions of the jobs named `codeflow gates` and `windows`; it never checks what those jobs ran, and a head that replaces its own `codeflow-ci.yml` with trivially green jobs of those names is admitted. The required `security review` check has the same flaw. The tracked nit (the adopter workflow chooses essential or full on a pull request from the head's own `.codeflow/test-config.json`, `assets/base/ci/codeflow-ci.yml:175-178`, so a head can lighten its own gate) travels with AC-1, revisit event unchanged.

Files shared by the five pieces (`codeflow-ci.yml`, `codeflow-policy.yml`, their installed copies and baselines, `ci.rs`): one writer at a time, as TSK-336's contract says; the Coordinator orders the writers. File sharing adds no scheduling dependency.

Outcome: **merge admission and every verdict built on it accept only a gates verdict produced by the default branch's workflow at the authority SHA, running the head's code as the candidate under a read-only token; the required `security review` check is produced the same way; and the resulting workflow set passes a fresh and an updated adopter on hosted CI.**

Journey placement (decided by the Director, 2026-11-01): the final hosted journey stays here because it proves the outcome of the whole split, not TSK-303's separate scope. This task waits on TSK-1175, TSK-1176 and TSK-1177 for that journey only; those three have no edge between them and build in parallel.

## Outcome

after this merges, no pull request can certify its own gates or security review, and the whole resulting workflow set passes a fresh and an updated adopter on hosted CI.
