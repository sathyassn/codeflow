# TSK-1307: Global installers are refused and an unknown writer cannot write a protected name

## Description

The operator decided on 2026-10-17 that refusing global installers would follow TSK-284 as its own task (TSK-284 decision D3; RELEASE-PLAN.md), and on 2026-10-07 that registry installers are refused unless the install provably lands inside the repository, with read-only forms allowed. This task checks what the guards refuse today against that rule, closes what is left, and closes TSK-284's remaining residual: an unrecognised writer program can write a protected name into the command directory. Local npm installs stay a stated residual, as the operator decided. The dot-directory glob over the entry limit is fixed in TSK-284 itself and is out of scope.

## Outcome

After this merges, an agent command that would install a tool globally is refused with the sanctioned path named, and a program the guard does not recognise cannot write a protected name into the command directory.

## Deliverables

- The guard change: provisional home in the security guards under `crates/codeflow-core/src/hooks/`; AC-1 decides.
- Refusal fixtures and the documented residuals: beside the existing guard tests and in the guard documentation.

## Acceptance Criteria

- AC-1 Before any change, the builder shall list the installer forms of the operator's 2026-10-07 decision (`cargo install`, global `npm`, `pnpm` and `yarn`, `pipx install`, `pip install --user`, `go install`, `gem install`, `brew install`, `brew tap`) with today's verdict for each, and shall reuse what already refuses; evidence: the table in the PR body with file:line.
- AC-2 Each listed form shall be refused unless the install provably lands inside the repository, failing closed when that cannot be proved, naming the rule and the sanctioned path, and read-only forms (list, help, search) shall stay allowed; evidence: one refusal and one allowed fixture per form, failing before the change where it was not refused.
- AC-3 This rule shall have no relief key and no form shall have a hardcoded exception, by the operator's decision of 2026-10-07 (`RELEASE-PLAN.md`: "refused with no relief key"); evidence: a test that no policy setting turns the refusal off.
- AC-4 A program the guard does not recognise that writes a protected name into the command directory shall be refused, and one that only reads or runs that name (`command -v git`, `xargs git grep`) shall stay allowed. Where the guard cannot tell which it is, the task states how it decides, without refusing ordinary commands under an empty `PATH` entry; evidence: fixtures for each, the first failing before the change.
  - Amended 2026-11-03 by the planning pull request after PR 578; earlier text: "A program the guard does not recognise that names a protected path in the command directory shall be refused, and an ordinary unrecognised command that names no protected path shall stay allowed"; reason: read literally, it brings back false refusals the design ruling removed.
- AC-5 The guard documentation shall state the remaining residuals, local npm installs included; evidence: the text diff.
  - Stated limits that TSK-284 leaves and no task covers, added 2026-11-03: a recognised writer putting a file into a directory the line never runs in, which follows the design ruling's direct-child rule; a local installer creating an executable under `node_modules/.bin/`, which stays open and uncontained; a program that writes a protected name without naming it on the command line, which stays open because a command-line guard cannot see a name the program computes.
- AC-6 (journey) With the built binary in a sample repository, a global install shall be refused by the Bash guard, and an install into the repository shall pass; evidence: the session output. Cross-lineage security review, as this is a guard change.
