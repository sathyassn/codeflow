# TSK-1496: Every spelling that reads one tree from history gets one verdict

## Description

Split from TSK-1053 on 2026-11-13 (coord/catalog's plan `tsk-1053-plan.md`, decision D1, with the Director's placement on the EPC-022 line). TSK-1053 tracked this as its AC-16, added 2026-10-29 from Fable review 08 of PR 346 (TSK-1002). The work is separate code and separate proof from TSK-1053's runner grammars, so it is its own task.

Git can read the same tree's content from history by several spellings. Fable review 08 found that the guard does not give them all the same verdict. This task makes every spelling get the verdict TSK-1002's rule gives a history read of that path. The spellings and the review's findings are kept in a restricted specification, `coordination/coordinators/planning/staging-epc022-guard-records/history-read-spellings-spec.md` (workspace repository; the reviewed version has SHA-256 `20d352b3b28643fb760f6668f57b725c6a30f96213ed2cc883cb248cab7eb319`), until the fix is on `main`.

Non-goals: TSK-1053's runner grammars; any change to TSK-1002's rule for which history reads refuse.

## Outcome

After this merges, every spelling that reads the same tree from history gets one verdict: each refuses when the tree can hold a protected path and allows when it cannot.

## Deliverables

- the fix: git-guard's and exec-guard's history-read judgment in `crates/codeflow-core/src/hooks/git_guard.rs` and the shared security modules it calls
- tests: one guard test table over every spelling for a protected and a public directory
- release note: `changelog.d/TSK-1496.md`

## Acceptance Criteria

- AC-1 Every spelling that reads the same tree's content from history, starting from the spellings the restricted specification lists, shall get one verdict, decided by the rule TSK-1002 applies to history reads of that path: each refuses when the tree can hold a protected path and allows when it cannot, and this record states which and why; evidence: one guard test table over every spelling for a protected and a public directory, the review's inconsistent rows failing before the change and every row agreeing after.
- AC-2 A further spelling the builder finds that reads a tree from history (another verb, revision syntax or pathspec form) shall be added to AC-1's table and get the same verdict; evidence: the table rows and the list in the pull request body.
- AC-3 Judged by the base and head binaries over TSK-1002's refusal tests, the reviews' payloads TSK-1053 AC-8 names and this task's fixtures: every row the base refuses shall stay refused except rows in one reasoned list of one class: history reads whose only refusal at the base came from the spelling, of a tree that cannot hold a protected path; a row refused for any other reason stays refused, including the protected-directory rows of AC-1, rows where TSK-397's strict branch or TSK-1052's rule applies (TSK-1053's Description states their precedence) and every `cargo run` or `direnv exec` row; every newly refused row shall be listed with its reason; if TSK-397's replay harness has landed it is the tool, run in both of its outcomes; evidence: the replay output with both revisions named and both lists. This carries TSK-1053 AC-8's replay obligations for this class through the split of 2026-11-13, so the split keeps that proof (Codex review of the split, 2026-11-13).
- AC-4 `docs/policy-reference.md` shall state that every spelling of a history read gets the verdict of the path it reads; evidence: the doc diff and `codeflow test --only docs-portal`.
- AC-5 Security review: a cross-family reviewer applies the `cf-security-reviewer` checklist (the change both lifts and adds refusals) and confirms no refusal a test or criterion requires was lost; evidence: the verdict file named in the pull request body.
