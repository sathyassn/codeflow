# TSK-1056: Qualification requires an administrator policy on every escape control

## Description

This is a planning draft accepted from the TSK-397 design note, revision 4.1, Part C (pull request 331), where it is unit U3 (invisible-policy rule). The note called the unit 3.3.0; the release is 4.1.0. Part C is accepted as planning drafts only: the criteria below are drafts, and this unit takes its own whole-unit review when it is built. Part C decisions (i) to (v) apply: (i) explicit non-secret enforcement-file arguments are allowed on a qualified host under attested `W-enforcement`, and the secret-read classes override, never a file name; (ii) a patch update invalidates a record, because exact executable digests bind it and a changed binary is `Unknown` until the operator re-runs the ceremony; (iii) managed settings are a design requirement for qualification, not a vendor fact; (iv) no exclusion matcher ever, so a non-empty `excludedCommands` disqualifies and route A+ is dropped; (v) the ceremony runs through the Bash tool, never the `!` prompt, and its evidence is receipts, not operator attention.

Qualification requires an administrative policy, enforced independently of the session, that constrains every relevant escape control. The sandbox settings the guard cannot see from inside a session are pinned by the managed-settings file, and doctor refuses the ceremony (TSK-1054) without it.

Edges: none. TSK-1054 (U1) depends on this unit, because qualification is sound only under the independently enforced managed policy pinned here; the doctor check in AC-2 is the one that refuses the ceremony TSK-1054 builds, so it ships first. This unit also introduces route A: pinning `allowUnsandboxedCommands: false` (AC-1) refuses every unsandboxed retry, and AC-6 makes it report which host-state workflows that makes unavailable. TSK-1059 (U6) depends on this unit and withdraws that report per tool.

Non-goal: any exclusion list or exclusion matcher; none is compatible with qualification.

## Outcome

after this merges, an administrator can see which managed-settings entries a host must pin before it can qualify, and doctor refuses to qualify a host that lacks them.

## Acceptance Criteria

- AC-1 The managed-settings file shall pin `enabled`, `failIfUnavailable`, `allowUnsandboxedCommands: false`, `filesystem.disabled: false`, `allowNestedUserNamespaces: false`, `enableWeakerNestedSandbox: false`, `allowAllUnixSockets: false` and `allowAppleEvents: false`, and the sandbox shall be admin-required; evidence: a fixture managed file and a test that each missing or changed pin is named.
- AC-2 Doctor shall read the managed file and refuse the ceremony without it; evidence: a doctor journey on a host with and without the file.
- AC-3 The argv walk shall be recorded as fail-closed evidence, not proof, and shall be named so in the output and the docs; evidence: the doctor output and the doc text.
- AC-4 No exclusion list shall be compatible with qualification: a non-empty `excludedCommands` shall disqualify; evidence: a test.
- AC-5 A receipt shall count as "observed active" only under route A (retries refused) and otherwise shall be diagnostic; evidence: a test of both routes.
- AC-6 Under route A (retries refused, `allowUnsandboxedCommands: false` pinned), doctor and orient shall report that the `gh`, `herdr` and `codex` host-state workflows are unavailable and why, until TSK-1059 lands a supported route for a tool; evidence: a doctor and an orient test on a host with the pin and one without.
