# TSK-1045: An away session's charter, decisions and owed actions survive compaction and render as one report

## Description

The operator asked on 2026-10-28 for a standard command or skill a user
sets when away, so work keeps going without stalling, is tracked, and
ends in one consolidated report with action items (things to run,
review or approve, and anything else). The operator widened it the same
day: the capability is generic, never tied to a time of day; it adapts
to how and when the user engages and to what the user uses it for; and
it covers keeping the work going, doing it right, following the `cf-*`
procedures and rules, tracking, and the report. This task is the engine
half: the durable state and the report. TSK-1046 is the skill that runs
the session on it; the design, field trial and harness research are
recorded there.

Why CodeFlow code is needed: a session's working memory does not survive
compaction, a restart or a usage-limit stop, and nothing CodeFlow prints
at session start says the session was left to run, for what, or what it
owes the user. `codeflow orient` on the line tip `654935d52` prints no
ledger or away line (checked 2026-10-28). In the maintainer's own
coordination workspace, which ran this behaviour by hand from
2026-10-23 to 2026-10-28, the state lived in a hand-kept board and
handoff file, and stale facts, an unread listener and parked items
followed.

Outcome: **`codeflow away` records an away activation (what the user
left the session to do, its scope and target line, how the user will
engage, an optional end, the coordinator and its trigger), the
reversible choices the session made, and the items it owes the user, in
the clone's coordination home; the session-start digest names an
active activation at start, resume and compaction; and `codeflow report
away` renders one outcomes-first report whose user actions are typed
Run, Review, Approve, Decide or Provide, each bound to its subject,
evidence, preconditions and the time it was last checked, from the
activation, the coordination ledger and local git, with every fact and
source it could not read marked unverified.**

Rules:

- No authority. The activation has no field that grants an action, and
  nothing in it widens `cf-method/references/autonomy.md`; an unknown
  field is refused. Who started it is recorded, never trusted as the
  operator; the ledger's actor binding is cooperative and an "approved"
  event grants nothing.
- No time of day. Start, end and cadence are absolute times or
  durations; an open-ended activation is the normal case.
- One activation per coordinator. A repeated `away start` reconciles the
  active one (it reports or updates it) and never yields a second
  trigger.
- Owed actions reuse the ledger. An item the user must act on is a
  follow-up (`codeflow follow add --awaiting-operator`, TSK-422) with
  new optional, versioned fields: the type (`run | review | approve |
  decide | provide`), the authority reason, the preconditions (repository,
  branch, head or base SHA) and the instruction (an exact command,
  destination or options). The ledger refuses unknown fields
  (`docs/coordination-ledger.md:72-73`) and an unknown newer schema
  version makes it read-only (`:405-407`), so this is a schema version
  change. A `fulfils` link closes the item when
  the fact changes (a pull request merged), so the report never lists an
  action already done. A Note (a disclosed limitation or choice) is
  shown but is not an action.
- Decisions are indexed, not copied. Each reversible choice stays in its
  home as `autonomy.md` "While a question is open" says (task record,
  epic notes or PR body); the activation's log holds one line per choice
  with that pointer, its status (working default, fail closed, settled)
  and what reverses it.
- Live or marked. The report observes the forge through the ledger's
  bounded observer (`coord/observe.rs`) unless `--offline`, prints each
  forge fact with its observation time, and lists every source it could
  not read. Exit 0 means the command ran; completeness is reported
  separately in text and JSON.
- Stages are named apart: implemented, reviewed, landed on a line,
  merged to `main`, released.
- The cadence default is 30 minutes, the operator's sweep interval of
  2026-10-27, read from `[sweep] interval_minutes` in
  `.codeflow/project.toml`, which this task defines as the one interval
  key for scheduled sweeps, attended (TSK-1037) or away.
- CodeFlow schedules nothing and runs no agent (`docs/product.md:70-71`).
  The activation records which trigger the session armed and when it
  last saw it fire; it never claims a trigger can wake a sleeping host
  or restore quota.
- The saved report and its JSON never use the NEED YOUR ATTENTION
  heading (`.codeflow/rules/writing.md:141-143` keeps it for replies);
  they label the section "Your actions". Ledger display ids (FU, LN, WS)
  stay out of tracked records and PR bodies.

Non-goals: a scheduler or daemon; sending the report outside the
machine (a hard gate, `autonomy.md:79`; the operator's answer is asked);
streams and lanes (TSK-439), which the activation links to when present;
the sweep checklist (TSK-1037); an open-PR classifier (TSK-1041).

### Planning survey (line tip `654935d52`, 2026-10-28)

- Ledger: `codeflow follow` records holder, `done_when`,
  `--awaiting-operator`, `--next-check` and typed links (`docs/cli.md`
  "Remember"); only a `fulfils` link closes an item
  (`crates/codeflow-core/src/coord/due.rs:10`, `:503-519`); its home is
  the clone's common git directory (ADR-0086); `follow snapshot
  --output` refuses to overwrite (`crates/codeflow-cli/src/cmd/follow.rs:232`).
  It has no action type.
- Session start: `session-orient` runs at
  `startup|resume|clear|compact|fork` in Claude
  (`assets/base/settings/default.json:544-553`) and at
  `startup|resume|clear|compact` in Codex
  (`assets/base/codex/hooks.json:18-20`), so a digest line survives
  compaction on both.
- TSK-440 (EPC-025, 3.2.0) adds the ledger to the start digest, a
  turn-end overdue check and observations only through
  `coord/observe.rs`, never unattended (its AC-4, AC-8). This task does
  not wait for it: its digest line reads the activation only, offline.
  Whichever of the two lands second folds the away line into the
  stream section, so the digest shows owed operator items once.
- `codeflow report ceremony` (`crates/codeflow-cli/src/cmd/report.rs:18`)
  is the existing report namespace, so the report is `codeflow report
  away`, adopted from the Codex discovery.
- Shared files: `hooks/orient.rs` with TSK-423, TSK-440 and TSK-1037;
  the ledger schema and `follow.rs` with TSK-439. One writer at a time.

## Acceptance Criteria

- AC-1 Before any change, the builder shall investigate broadly and record the findings with sources in this record: the ledger's store, event schema, versioning, observer and permission matrix (TSK-422, ADR-0086, `docs/coordination-ledger.md`) and whether the activation and decision index fit as ledger events or need a sidecar in the coordination home; how `orient` and `session-orient` reach compaction and resume on each harness; what TSK-439 (streams), TSK-440 (digest, turn-end check), TSK-1037 (sweep), TSK-1041 (PR status) and TSK-311 (program report) will change or offer; how the report's facts stay live within the observer's budget; the Codex discovery's failure table (TSK-1046); and the chosen storage and default report path (inside the coordination home, outside any worktree, unless the user names one), with the ADR note or new ADR it needs; evidence: the record section and the ADR text, committed before the first code change in the PR.
- AC-2 `codeflow away start` shall record an activation with purpose, scope links, target line, engagement (not reachable, checking in, or reachable), an optional end as a duration or absolute time, the interval, an optional report path, an optional operator-set resource limit, the coordinator's actor and native session id, the trigger it armed and the observed permission mode; `away update` shall change the user-set fields and record each trigger fire; `away status` shall print it read-only with `--json`; a repeated `start` shall reconcile the active activation and report that no second trigger is needed; and a field outside that list shall be refused; evidence: CLI tests for each, including an open-ended activation, an end given as a duration, an end given as a time, a repeated start and an extra field. (serves EPC-022 AC-149)
- AC-3 `codeflow away note` shall record a decision (subject, its home, status working default, fail closed or settled, and what reverses it), an operator engagement (when the user last answered) or a progress line, each bounded and scanned like the ledger's free text; `codeflow follow add` and `update` shall accept the action fields (type `run|review|approve|decide|provide`, authority reason, preconditions, instruction) only with `--awaiting-operator`, under a new ledger schema version that an older build reads as read-only, never as empty; and an exact duplicate action (same source identity or idempotency key) shall be recorded once; evidence: CLI tests, including an action type without an operator condition (refused), an oversized or secret-shaped note (refused), a duplicate add, and an older-schema reader fixture.
- AC-4 While an activation is active, the session-start digest shall print one line naming its purpose, end or open end, the count of owed actions by type, the report path and when the last trigger fired, at start, resume and compaction, and shall print nothing about away state when none is active; it shall stay read-only and offline; evidence: hook tests for each event with and without an activation, and a test that the digest makes no network call.
- AC-5 `codeflow report away` shall print, in this order: an opening with what the session was set to do and where it stands (implemented, reviewed, landed on a line, merged to `main`, released kept apart); what changes that position and who clears it; "Your actions" grouped by type, each starting with its verb, naming its subject in words with its evidence link, preconditions, instruction and last check time, ordered by what it unblocks; progress since the activation started or the previous report; the decisions with their homes and reversals; continuing work with owner and next event; and evidence and limits (sources not read, facts not verified with their last check time, the trigger's armed state); an empty group is omitted and no action section appears when nothing is owed; `--json` carries the same content; evidence: report tests over fixtures with one item per type, a closed item (absent), a Note (shown, not counted), a decision, a blocker, nothing owed, and the rendered Markdown checked against `.codeflow/rules/writing.md` "Replies and status". (serves EPC-022 AC-149)
- AC-6 The report shall observe the forge through the ledger's bounded observer unless `--offline`; a fact older than its own observation, or one the observer could not reach, shall be printed as unverified with its last check time; an action whose `fulfils` link is met shall be closed by that observation and not listed; an action whose preconditions no longer hold (the head or base moved) shall be shown as stale, never as ready; and a partial read shall name the unread sources while the command exits 0; evidence: tests with the network unreachable (every forge fact unverified), a hung observer (finishes within the bound), a merged pull request closing its Approve item, a head moved after the item was recorded (stale), and the first of these failing before the change against a report built from `follow list` alone. (serves EPC-022 AC-149)
- AC-7 `report away --output <path>` shall write the report atomically, privately, to a path the activation names, replacing only a file this activation wrote; `away end` shall record the end, render the final report and leave every open follow-up open; evidence: CLI tests for a replaced own file, a refused foreign file and an end with open items.
- AC-8 `[sweep] interval_minutes` in `.codeflow/project.toml` shall set the default interval, falling back to 30, and `away start --interval` shall override it for one activation; evidence: a CLI test reading a project value and the fallback.
- AC-9 State shall stay consistent under failure: a kill between the event append and the report export, a duplicated trigger fire, two coordinators starting at once, and a returning older coordinator shall leave one activation, one entry per action and a report that can be re-rendered; events shall order by ledger sequence, never by wall clock; evidence: tests with a fake clock and recorded observations, labelled as deterministic replays.
- AC-10 (journey) With the built binary in a scratch adopter project with a pull request fixture, a stalled task and a pending decision, a real harness session shall start an activation, record a decision and three owed actions, survive a compaction and a restart with the digest naming the activation, render the report after the fixture pull request merges (its Approve item gone) and after another fixture's head moves (its item stale), and end with a final report; evidence: the journey transcript and the reports.
