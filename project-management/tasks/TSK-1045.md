# TSK-1045: An away session's charter, decisions and owed actions survive compaction and render as one report

## Description

The operator asked on 2026-10-28 for a standard command or skill a user
sets when away, so work keeps going without stalling, is tracked, and
ends in one consolidated report with action items (things to run,
review or approve, and anything else). The operator widened it the same
day: the capability is generic, never tied to a time of day; it adapts
to how and when the user engages and to what the user uses it for; and
it covers keeping the work going, doing it right, following the `cf-*`
procedures and rules, tracking, and the report. This task is the engine
half: the durable state, the admission of every effect, the effects'
commands and the report. TSK-1046 is the skill that runs the session on
it; the field trial and harness research are recorded there.

Why CodeFlow code is needed: a session's working memory does not survive
compaction, a restart or a usage-limit stop, and nothing CodeFlow prints
at session start says the session was left to run, for what, or what it
owes the user. `codeflow orient` on the line tip `654935d52` prints no
ledger or away line (checked 2026-10-28). In the maintainer's own
coordination workspace, which ran this behaviour by hand from
2026-10-23 to 2026-10-28, the state lived in a hand-kept board and
handoff file, and stale facts, an unread listener and parked items
followed.

Outcome: **one away activation per clone records the charter (purpose,
scope, target line, engagement, an optional end, the interval and the
limits), its owner, what it has consumed, the reversible choices the
session made and the items it owes the user; it admits every consuming
effect (a tick, a claim, a seat, a replacement, a landing, a job
renewal) before the effect happens and never refunds it; it gives the
session one command for each effect, each reconciled against the world
after a crash; the session-start digest names an active activation at
start, resume and compaction; and `codeflow report away` renders one
outcomes-first report whose user actions are typed Run, Review,
Approve, Decide or Provide, each bound to its subject, evidence,
preconditions and the time it was last checked, with every fact and
source it could not read marked unverified.**

### Session design, revision 12.3 (amended 2026-10-29)

Source: the session system design, revision 12.3 of 2026-10-29, the last
design revision. It amends the final design of the same day through
revisions 8 to 12.3; Codex (GPT-6 Astra at high) reviewed revisions 8 to
11 (r11-04: SOUND) and, under the corrected threat model, 12.1 and 12.2
(r12-05 and r12-06, both NOT SOUND). Revision 12.3 answers r12-06: its
blocking finding became the named landing residual the operator
accepted, and its races became the fault tests of AC-26. No Codex
review covers 12.3 itself; the build's fault tests are its proof. The documents are listed in the planning pull request's
references. This section and the criteria carry the decided specifics,
so a builder needs no other source.

Threat model: the session's own tool results (`git push --porcelain`,
`git ls-remote`, `gh`, `herdr`, `CronCreate`, `CronList`, `CronDelete`)
are trusted as evidence of the world at that moment and read
defensively: a lost reply or a timeout is unknown, success is never
inferred from silence, and every record precedes its effect. Content
other actors write (repository files, PR and issue text, other people's
refs and jobs) is evidence, never authority. Our own primary and the
operator are cooperative. A hostile model or a stolen session is out of
scope here, as everywhere in CodeFlow.

```text
  harness fires the scheduled prompt: activation id + watcher nonce
        |
        v
  codeflow away tick --activation <id> --watcher <nonce>   (or --hand)
   lock | id? owner? stop? end? clock ok? same boot?
        | nonce current? gap elapsed? fires < limit? -> fires += 1
   unlock
   observe (no lock): refs, PRs, checks, runs and rulesets at exact
            shas, herdr lists and pane processes, ledger follow-ups,
            units and landings in a non-final phase, the job listing
   print:   snapshot (units, seats, landings, watcher, owed items,
            limits, purpose, stop, quarantine cost, unconfirmed cleanups)
        |
        v   the skill acts within purpose; each effect admitted first
  every effect: read outside the lock; reserve under it; release;
                call; record and reconcile under it
  claim   : work claim --away      (one push, then ls-remote; contract)
  seat    : away admit seat ; --dispatch ; herdr agent start ;
            --snapshot ; the seat's --check
  replace : away seat --evidence ; away admit seat --replaces
            (fresh branch and worktree; the old ones quarantined)
  land    : away admit landing ; pre-merge read ; reserve ;
            gh pr merge --merge --match-head-commit ; verify ; cleanup
  watcher : renew --begin ; CronCreate ; renew --sent ; renew --created ;
            observe --listing (resolve pending, adopt, then delete)
  record  : away note | owe --key | answer --expect <item-rev>
  report  : report away --output
  attended: landing into main; clearing a landing mismatch; releasing
            a quarantine; start and first arming; a second activation;
            rebinding after /branch; after a reboot: status, report, end
  waits   : a security-path unit until another lineage approves its head
```

Figure: one tick. A missed or doubled tick costs latency, never
correctness; nothing is recorded as done before it is done, and nothing
consumed is refunded.

Rules:

- No authority. The activation has no field that grants an action, and
  nothing in it widens `cf-method/references/autonomy.md`; an unknown
  field is refused. Who started it is recorded, never trusted as the
  operator.
- No time of day. Start, end and cadence are absolute times or
  durations; an open-ended activation is the normal case.
- One activation per clone. The store is `codeflow/coord/away.json` in
  the clone's coordination home (`format: 1`), beside `away.lock`
  (`fs2` exclusive, bounded wait) and `away.cache.json`. `away start`
  takes the lock and refuses while a live, `.prev`, damaged or temp
  file exists. Writes go to a temp file in the same directory with
  `fsync`, then `rename(live, .prev)`, `rename(temp, live)` and a
  directory `fsync`, each result checked; `.prev` is never restored
  into the live file.
- The lock contract, for every effect: read the world outside the lock;
  under the lock re-check the local record against the read and persist
  the reservation (an attempt, a phase, a pending); release; make the
  external call; under the lock again record the result and reconcile.
  The lock is never held across a network or tool call, so a stop from
  another shell always persists, and a crash between the reservation
  and the record is reconciled by the next tick from the world, with
  nothing refunded or reserved twice.
- Ownership. The owner is one Claude Code session on one machine and
  boot: `session_id`, `pid`, `pid_start`, `machine_id`, `boot_id`,
  harness and version, and a `generation` that `start`, `--take-over`
  and `resume --rebind` increment. Claude Code 2.1.312 on macOS is
  qualified first, Linux after its canaries, Windows refused until a
  boot id source is named; Codex and Grok are refused as owner and run
  as seats. An owner-only command is accepted only when the caller's
  environment names the owner session id and pid, the pid's start time
  equals the recorded one, and the caller descends from that pid by the
  owner identity walk below. `/fork`, `--fork-session` and `/branch`
  give a new session id and are refused as owner; after `/branch`,
  `away resume --rebind` is attended. After a changed boot id only
  `away status`, `report away` and `away end` are accepted.
- Ticks. A fire carries the watcher nonce in its prompt; a retired,
  unknown or missing nonce consumes nothing. Admitted ticks are at least
  half the recorded interval apart. The nonce only refuses: a
  caller-supplied value never grants more than a hand tick would.
- Claims follow the cooperative claim contract: a claim branch is
  created once at a claim commit, an object only this activation
  produces, and no CodeFlow clone writes to a branch it did not create.
  Under it, `ls-remote` settles an unclear push: our claim commit at the
  tip is ours; an absent branch is retried, three pushes in all; any
  other value is `lost` and the unit is skipped. Someone who recreates
  the branch at our exact commit reads as us, a boundary the contract
  accepts.
- Seats are admitted, dispatched once by the owner and acknowledged once
  by the seat. A lost seat is replaced only on recorded evidence, on a
  fresh branch and worktree; the old branch, worktree and pull request
  are quarantined and never reused, so two seats never share a target.
  4.0.0 has no qualified process-containment guarantee, so a quarantine
  is released only by the attended `away seat --terminated`, and its
  cost is reported every tick.
- Landing into an integration line is unattended under its admission
  checks; landing into `main` or any protected branch is refused by name
  and stays the operator's. GitHub's merge API pins the head, not the
  destination, so a retarget between the pre-merge read and the merge
  lands elsewhere and is caught by verification after, which blocks
  every further landing on the clone until the attended unblock (the
  named residual for C4, E1 and E2).
- The scheduled job is created by the user at start and renewed and
  cleaned by the activation: one pending renewal at a time, resolved by
  one atomic promotion or abandoned before anything is deleted, and only
  jobs this activation owns are deleted. The exact-copy watcher
  contract: a job whose prompt carries a nonce this activation issued is
  reconciled as this activation's job, whoever created it, because the
  nonce is random and appears only in prompts the activation wrote.
- Security paths. A unit whose diff touches an entry of the governing
  `security_paths` list (AC-25) lands only on a full-assurance approval
  from another lineage at its exact head; until one answers it waits,
  unattended, and each tick re-probes.
- Time. Every activation with an end has `deadline_mono` on the
  suspend-inclusive counter (Linux `CLOCK_BOOTTIME`, macOS
  `mach_continuous_time`, Windows `QueryInterruptTime`), never
  extended.
- Owed items and decisions live in the activation (design decision 5):
  id-scoped keys and per-item revisions; the ledger's follow-ups
  (TSK-422) are read with a budget and listed beside, never written. A
  `fulfils` link closes an item when the fact changes, so the report
  never lists an action already done. A Note is shown but is not an
  action. Each reversible choice stays in its home as `autonomy.md`
  "While a question is open" says; the activation holds one entry per
  choice with that pointer, its status and what reverses it.
- Limits are the ones CodeFlow counts: an end time or duration, units
  claimed, seats admitted (a total-attempt budget: every admitted seat,
  replacements included, counts for the rest of the activation) and
  admitted ticks. Usage, tokens and spend are advisory telemetry where a
  harness reports them; a configured usage, token or spend limit is
  refused at `away start` (design decision 3).
- Live or marked. The report observes the forge through the ledger's
  bounded observer (`coord/observe.rs`) unless `--offline`, prints each
  forge fact with its observation time, and lists every source it could
  not read. Exit 0 means the command ran; completeness is reported
  separately in text and JSON.
- Stages are named apart: implemented, reviewed, landed on a line,
  merged to `main`, released.
- The cadence default is 120 minutes (amended 2026-11-07, see AC-8;
  it was 30), read from `[sweep]
  interval_minutes` in `.codeflow/project.toml`, which this task or
  TSK-1037, whichever lands first, defines as the one interval key for
  scheduled sweeps, attended or away.
- CodeFlow schedules nothing and runs no agent (`docs/product.md:70-71`).
  The harness fires the ticks; the activation records the jobs it owns
  and never claims a trigger can wake a sleeping host or restore quota.
- The saved report and its JSON never use the NEED YOUR ATTENTION
  heading (`.codeflow/rules/writing.md:141-143` keeps it for replies);
  they label the section "Your actions". Ledger display ids (FU, LN, WS)
  stay out of tracked records and PR bodies.

Non-goals: a scheduler or daemon; sending the report outside the
machine (a hard gate, `autonomy.md:79`); the sweep checklist (TSK-1037);
an open-PR classifier (TSK-1041); and, each tracked once in EPC-023 with
its revisit event, away mode on another harness's route (Codex-owned
activations and job kinds with no list surface, TSK-1074), cross-clone
claim arbitration for the title-slug case (TSK-1075) and usage as a stop
trigger (TSK-1076). The delegate heartbeat and Stop lifecycle stay with
TSK-440 (EPC-025).

### Owner identity walk

```text
expected := read(self)                 # (pid, ppid, start) of the caller
for hop in 0..32:
    current := read(expected.pid)
    refuse unless current == expected  # all three fields
    succeed if current.pid == owner.pid and current.start == owner.start
    refuse if current.ppid in {0, 1}
    parent := read(current.ppid)       # sample the parent tuple
    again  := read(current.pid)
    refuse unless again == current     # the hop did not change while sampled
    refuse unless parent.start <= current.start
    expected := parent                 # carry the sampled parent, whole
refuse                                 # 32 hops
```

Figure: the walk carries each hop's whole tuple, so a process that
exits and whose pid is reused between iterations fails on its ppid or
start time. Two reader limits stay: an intermediate hop is
indistinguishable only when pid, ppid and start all repeat within the
reader's resolution, and the owner, identified by pid and start time
alone, when both repeat. Descendants of the owner are the owner's
processes by design, a cooperative boundary.
