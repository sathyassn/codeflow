Historical evidence from the source plan, not a measurement of this candidate:

Measurements taken on 2026-10-12 on the operator's macOS arm64 host at a load of about 25 to 45:

- **Fuzz test, side by side.** The bash test, both builds under the same
  load: 258 seconds at `main` 7542e5a4a (before PR 158) and 521 seconds at
  42344d989 (after).
- **Local full gate with coverage.** The bash test took 688 seconds, the
  zsh test 1022 seconds, and `codeflow-cli::refusal_journey`
  `startup::installed_hooks_refuse_unresolved_forms_beside_a_named_target`
  1390 seconds. In the 3.1.0 gate on the same host they took 7 to 45
  seconds for the first two and 97 to 132 seconds for the journey.
- **Hosted Linux at that revision.** The journey test ran in 29 to 53
  seconds and the fuzz tests in under a second; the hosted coverage shards
  passed.
- **Ordinary commands at that revision.** Twelve typical commands, five
  rounds: median hook time 112.9 ms before and 111.9 ms after.

The local coverage target then had an 1800-second limit and timed out twice. Host load affects these figures, so the same-load side-by-side run is the performance comparison. Changing refusals or the hosted CI shards is outside this task.

## Acceptance Criteria

- AC-1 When the bash and zsh random-words fuzz tests run on the reference
  macOS host, they shall take no longer than at `7542e5a4a` under the same
  load, or the cost TSK-290 added to judging those words shall be found
  and removed; evidence: a side-by-side timing of both tests at
  `7542e5a4a` and at the fix, both builds run back to back under the same
  load, and the profile that names the guard path and its cost.
- AC-2 When the local full gate runs on the reference macOS host, its
  `rust-coverage` target shall complete inside its configured limit and
  `codeflow-cli::refusal_journey`
  `startup::installed_hooks_refuse_unresolved_forms_beside_a_named_target`
  shall run in a time of the same order as in the 3.1.0 gate; evidence: one
  full gate run with the target's duration and the three test durations.
  Changing `timeout_seconds` is allowed only with a stated reason and the
  operator's approval, since it is gate configuration, and it never
  replaces AC-1. (journey)
- AC-3 When the guard judges the twelve ordinary commands of the baseline
  set, its per-command hook time shall stay within 5 percent of the 3.1.1
  baseline; evidence: the same twelve-command timing, five rounds, median
  per command and overall, against the 3.1.1 figure of 111.9 ms.
- AC-4 When the fix changes how a word or script is judged, every refusal
  and allow test that passes at the 3.1.1 candidate shall still pass and the
  fuzz tests shall still find the planted enforcement-file writes; evidence:
  `cargo test -p codeflow-core` on the guard tests and the fuzz tests with
  their seeds unchanged.
