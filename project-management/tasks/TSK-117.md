# TSK-117: present review contract v2 and its decision record

## Description

Node A of the present review parity package (Plan v5). The operator found
three failures in a real cf-present review: a comment cannot target a node
or arrow inside a figure, figures carry no visible title or explanation, and
there is no form whose answers reach the agent. The approved proposal
(workspace `design/present-parity/proposal-present-parity-v2.md`, v2.1 at
workspace commit `b823cbe`, sections 1 to 3) settles the design; this task
turns it into the contract that TSK-118 to TSK-122 build against. It writes
SPC-014 (allocated for this output and consumed by TSK-118 to TSK-122), a
new ADR for the decisions, the v1 and v2 compatibility table with its named
consumers, the draft, retention and answer-authority rules, and the fixtures
the later tasks must pass, before any of them starts. Non-goals: runtime or
schema code (TSK-118 onward), and every offering the operator ruled out in
decision 1a (shared database, rooms, page-side model calls, connectors,
hosted identity, permission grants; proposal section 2).

## Affected surfaces and interfaces

- `project-management/specs/SPC-014.md` (written here; linked from TSK-118
  to TSK-122 and set `approved` here).
- `docs/decisions/` one new ADR. No ADR file is allocated at planning time:
  CodeFlow has no ADR allocator, and the validator needs none yet. On
  2026-09-26 the next free number across every ref and all history was
  ADR-0073; the task takes the next free number at its start after the same
  check.
- A fixture set for the review contract under `crates/codeflow-present`
  (path chosen in the spec), used by TSK-118 to TSK-122.
- ADR-0049 (a dated update) and `docs/architecture/present.md`, for the
  `html` stage sandbox drift.
- CAP-016. No runtime, schema, CLI or skill file changes here.
