# TSK-1003: The Codex builder permission profile opens on Codex 0.164

## Description

On Codex CLI 0.164.0 a builder seat launched as documented
(`--ask-for-approval never -c default_permissions="cf-builder"` from the main
checkout root) fails before the seat opens with `failed to load workspace
requirements: invalid input parameter`, while the default `cf-guard` profile
works. This task finds what 0.164 rejects in the `cf-builder` profile in
`.codex/config.toml`, rewrites it in the current schema with the same intent
(cf-guard plus Git metadata writes except hooks and config), adds write access
to the CodeFlow lock directory `~/.codeflow/locks` only so a builder can run
`codeflow reserve`, and adds a preflight check that reports when the installed
Codex rejects the configured builder profile. Non-goal: changing the reviewer
(`cf-guard`) posture or granting any other home path.

## Deliverables

- Fixed builder profile and qualification notes: `.codex/config.toml`
- Matching scaffold template, if shipped: `assets/`
- Preflight check and its test: `crates/codeflow-core/`, `crates/codeflow-cli/`
- Launch-line docs, if the launch changes: cf-model-orchestrator `resources/routing/transport.md` and `cf-delegate`, mirrored
