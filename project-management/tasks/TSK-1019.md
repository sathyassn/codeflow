# TSK-1019: A link retargeted earlier on a line is judged after the retarget

## Description

Source: TSK-397 security review SF-4 (PR 331), 2026-10-26. The exec guard resolves a symbolic link in an interpreter argument at guard time, before the line runs. A link the same line retargets first is judged by its old target: `ln -sfn .claude L && python3 x.py L/settings.json` passes, and the interpreter then reads `.claude/settings.json`. Outcome: **a line that creates, retargets or removes a link before an interpreter call is judged as if any path through that link could be protected.** The fix belongs in `crates/codeflow-core/src/security/arguments.rs` and `outward.rs`, near the TSK-397 directory set. Non-goal: links changed by another process between the guard and the shell, which remain the OS sandbox's concern.

## Deliverables

- the guard change: `crates/codeflow-core/src/security/arguments.rs`, `crates/codeflow-core/src/security/outward.rs`
- tests: refusal tests in `crates/codeflow-core/src/security/interpreter.rs`
- release note: `changelog.d/TSK-1019.md`

## Acceptance Criteria

- AC-1 When a line runs `ln`, `mv`, `rm`, `cp` or any unmodeled command before an interpreter call, the guard shall judge an interpreter argument that passes through a link by its trailing components, so `ln -sfn .claude L && python3 x.py L/settings.json` refuses; evidence: a refusal test that fails before the change.
- AC-2 A line with no such command before the interpreter shall keep today's judgement, so `python3 x.py L/notes.txt` with `L` a link to `src` still passes; evidence: a test.
