# TSK-051: render the guide shape in the adapter and the starter

## Description

The adapter renders every source under the same page shape and lists record
sources as portal pages. Under Plan v7 the adapter renders the guide shape:
the home page shows the reading path through the configured layers as one
figure with one sentence per step; a layer landing shows the layer's pages in
configured reading order; the capabilities registry renders its YAML fences as
a generated table and per-capability detail, never as raw code; and records
are pointed to through a generated pointer page that lists each configured
folder with its purpose, its count and its repository link. The records layer
and per-decision pages become a configuration switch, off in codeflow's own
portal and docs-only in the starter. The five rendered defects found during
the theme review are fixed here. Non-goals: no composed epic, task or decision
views; no timeline; SPC-010 is cancelled.

## Affected surfaces and interfaces

`docs-portal/scripts/adapter.mjs` and `lib.mjs` with their starter mirrors;
`docs-portal/src/styles/portal.css` and mirror; `docs-portal/portal.config.json`
and the starter config; `docs-portal/tests/adapter.test.mjs` (new cases only)
and mirror; the portal validator only if the pointer page needs a route rule;
`.codeflow/docs-portal.json` pristine hashes; manifest and baseline. CAP-015.

## Acceptance Criteria

- [ ] Home shall render the reading path from the layer configuration as one
      figure with one sentence per layer; evidence: a fixture with four layers
      renders four steps in configured order, and the rendered review.
- [ ] A layer landing shall render its pages in configured reading order with
      the layer description and a reading-order figure; evidence: a fixture
      whose configured first page sorts last renders first.
- [ ] The capabilities registry shall render its YAML fences as a generated
      table with id, name, status and job, and per-capability detail rows,
      never as a raw code block; evidence: a fixture with two fences renders
      two rows and no `<pre>` for the fence, and the rendered review.
- [ ] A record pointer page shall be generated from configuration listing
      folder, purpose, count and repository link for decisions, epics, tasks
      and specs; evidence: a fixture with the four folders renders four rows
      with correct counts and links, and a missing folder renders "none yet".
- [ ] The records layer and per-decision pages shall be a configuration
      switch, off in `docs-portal/portal.config.json` and docs-only in the
      starter; evidence: codeflow's build emits no `/records/` or ADR page
      routes and `llms.txt` lists none; the starter fixture default is docs
      only; `validate --portal` passes.
- [ ] Record ids in page text shall link to the pointer page or the repository
      file when the record is not a portal source; evidence: a fixture page
      citing an ADR id renders a link to the repository file and the evidence
      manifest records no missing relationship.
- [ ] The five rendered defects shall be fixed with tests: stage node width
      and word wrapping, heading ids excluding the provenance line, capability
      table width, landing order, provenance short hash on one row; evidence:
      the tests named in the TSK-046 record, carried over.
- [ ] Mobile: a stage with more than three nodes in a row shall stack
      vertically at 390 pixels with no horizontal overflow; evidence: a style
      assertion and the rendered review at 390.
- [ ] Starter mirrors byte-identical, hashes refreshed; evidence: mirror
      equality check, manifest consistency test, managed-drift clean.
