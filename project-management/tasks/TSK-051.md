# TSK-051: render the guide shape in the adapter and the starter

## Description

The adapter renders every source under the same page shape and lists record
sources as portal pages. Under Plan v7 the adapter renders the guide shape:
the home page shows the reading path through the configured layers as one
figure with one sentence per step; a layer landing shows the layer's pages in
configured reading order; the capabilities registry renders its YAML fences as
a generated table and per-capability detail, never as raw code; and records
are pointed to through a generated pointer page that lists each configured
folder with its purpose, its count and its repository link. The records layer
and per-decision pages become a configuration switch, off in codeflow's own
portal and docs-only in the starter. The five rendered defects found during
the theme review are fixed here. Non-goals: no composed epic, task or decision
views; no timeline; SPC-010 is cancelled.

## Affected surfaces and interfaces

`docs-portal/scripts/adapter.mjs` and `lib.mjs` with their starter mirrors;
`docs-portal/src/styles/portal.css` and mirror; `docs-portal/portal.config.json`
and the starter config; `docs-portal/tests/adapter.test.mjs` (new cases only)
and mirror; the portal validator only if the pointer page needs a route rule;
`.codeflow/docs-portal.json` pristine hashes; manifest and baseline. CAP-015.

      the layer description and a reading-order figure; evidence: a fixture

Configuration shape chosen for the switch, which the brief left open:

```json
"records": { "enabled": false, "layer": "system",
  "pointers": [{ "folder": "docs/decisions", "id_prefix": "ADR",
                 "purpose": "..." }] }
```

`id_prefix` drives both the folder count and the closing sentence, so the
pointer page names no id the configuration does not declare. Pointers are
refused while `enabled` is true, a layer that publishes only pointer folders
while records are off is refused, and the pointer page is generated at
`<records.layer>/records`, a reserved route. The capability fence carries no
`job` field, so the generated table uses the `area` field it does carry.
