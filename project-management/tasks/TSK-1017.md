# TSK-1017: Drop the include-flate-compress git pin once upstream releases zstd 0.14

## Description

TSK-1016 pins `include-flate-compress` to the upstream commit
`bfe8fcd57aed281988f1ee86edbc35fd5905239a` through `[patch.crates-io]` in the
root `Cargo.toml`, because no published release takes `zstd` 0.14. A git
source carries no registry checksum and makes builds fetch from github.com.
Once upstream publishes an `include-flate-compress` release newer than 0.3.4
that requires `zstd` 0.14 or later, this task removes the patch so the
dependency comes from crates.io again, with the fixed `zstd` versions kept.
Trigger: that upstream release. Non-goal: other dependency upgrades.

## Deliverables

- the dependency change: `Cargo.toml` (the `[patch.crates-io]` entry and its comment removed), `Cargo.lock`
- the release note: `changelog.d/TSK-1017.md`

## Acceptance Criteria

- AC-1 When `Cargo.lock` is read, `include-flate-compress` shall come from the crates.io registry at a release newer than 0.3.4, the root `Cargo.toml` shall carry no `[patch.crates-io]` entry for it, and `zstd`, `zstd-safe` and `zstd-sys` shall stay at or above 0.14.3, 8.2.0 and 2.1.2. Evidence: `git diff Cargo.toml Cargo.lock` and `cargo tree -i zstd`.
- AC-2 When osv-scanner runs on the tree, it shall report no advisory against those packages, and the release binary shall still read its embedded assets. Evidence: osv-scanner before and after, `cargo test --release -p codeflow-present --lib`, and the hosted security review. (journey)

## Blocker

- reason: No include-flate-compress release takes zstd 0.14 yet; 0.3.4 requires zstd ^0.13.3
- owner: upstream SOF3/include-flate
- revisit: an include-flate-compress release newer than 0.3.4 on crates.io
