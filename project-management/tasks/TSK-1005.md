# TSK-1005: A target's test report decides its result, and every skip or disabled target is recorded

## Description

Issue #303, filed against CodeFlow 3.1.1 (`48104f48b`). The test engine
decides a target's result from the command's exit code alone
(`crates/codeflow-core/src/testing/gate.rs`, `gate_verdict`). A missing,
stale or malformed report, skipped tests, tests the report marks flaky,
and targets switched off in config (`enabled: false`, `ci_skip` without a
reason) all pass with no recorded reason. The issue states this is a
deliberate tightening of designed behaviour, not a defect, so it is a
feature here, beside the other quality defaults of this epic.

Outcome: **in `essential` and `full` mode a test-executing target passes
only when its own report, produced or cache-restored for this run, shows
tests executed and every skipped, flaky or switched-off item has a
recorded entry; the gate evidence names those items.**

Rules:

- A target that executes tests declares a `report`. A target that does
  not (lint or format) declares `kinds: ["lint"]` and is exempt from the
  report checks. This task adds the `kinds` field; TSK-1009 adds the
  evidence kinds to it.
- Each allowance (a skipped id, a quarantined flaky id, a disabled target,
  a CI-skipped target) is an entry in TSK-424's exemption register, of its
  own kind, with reason, owner and expiry. The issue's per-target
  `skip_allow` and `quarantine` lists become register entries so the
  epic keeps one register (EPC-024 AC-1); the PR states this choice.
- No entry makes an absent, unparseable or leftover report pass: the
  only route to a passing report is one this run wrote or a valid
  cache restoration. Register entries cover skipped, flaky, disabled
  and CI-skipped items only.
- Existing projects get the checks report-only first; `block` comes
  through a reviewed policy change, and new scaffolds write it on.

Non-goals: `quick` mode (format and lint by design, so the pre-push notes
stay as they are); CodeFlow's own early-returning tests (TSK-361 in
EPC-023); the coverage floor (TSK-1006).

- the typed report result, artifact clearing for every runner, the executed count and the kept skipped and flaky ids: `crates/codeflow-core/src/testing/gate.rs`, `crates/codeflow-core/src/testing/validation.rs`, `crates/codeflow-core/src/testing/runner/mod.rs`, `crates/codeflow-core/src/testing/report/`
- the `kinds` field and config validation of `ci_skip_reason` and disabled targets: `crates/codeflow-core/src/testing/config/mod.rs`, `assets/base/testing/test-config.schema.json`
- the activation key (provisional `testing.report_integrity`) and the register kinds: `crates/codeflow-core/src/hooks/policy_schema.rs` and TSK-424's register module
- attempts per tree in the gate-runs record and the summary line: `crates/codeflow-core/src/testing/delivery.rs`, `crates/codeflow-cli/src/cmd/test.rs`
- the report-only listing on update: `crates/codeflow-core/src/scaffold/update.rs`
- tests: unit tests beside the changed code and `crates/codeflow-cli/tests/`
- docs: `docs/test-gate.md`, `docs/policy-reference.md`
- release note: `changelog.d/TSK-1005.md`

## Acceptance Criteria

- AC-1 In `essential` and `full` mode, a target that executes tests shall fail when its report is absent, unparseable, or a leftover from an earlier run, and shall pass when the report was written by this run or restored by the target's build cache for the same inputs; evidence: four gate tests (a fresh run, a cache restoration with an old timestamp, a missing artifact, an unrelated leftover). (serves EPC-024 AC-12)
- AC-2 A report that executed no tests (passed plus failed is zero), or whose summary total disagrees with its test list, shall fail the target whatever any allowance says; evidence: report tests, one per case. (serves EPC-024 AC-12)
- AC-3 A skipped test id with no matching register entry, and a test the report marks flaky with no quarantine entry, shall fail the target; a quarantined test shall still run and its result shall be printed; the gate summary and the gate-runs record shall keep the skipped and flaky ids; evidence: gate tests and the record's contents. (serves EPC-024 AC-12)
- AC-4 Config validation shall refuse `ci_skip: true` without `ci_skip_reason`, and `enabled: false` without a register entry; a target declaring `kinds: ["lint"]` shall be exempt from AC-1 to AC-3; evidence: validation tests.
- AC-5 The gate-runs record shall store each attempt on the same tree, and the summary line shall print the attempt count; evidence: a test with two runs on one tree.
- AC-6 With the activation key unset, an existing project shall see the findings reported and its verdict unchanged, `codeflow update` shall list per target what would fail, and at `block` the findings shall fail the gate; evidence: tests at each level and the update listing.
- AC-7 (journey) With the installed build in a scratch adopter at `block`, a planted skipped test, a disabled target with no reason and a leftover report shall each fail `codeflow test --mode full --strict`; the skipped test and the disabled target shall pass after their register entries are added, with each entry printed, and the leftover report shall pass only after the target runs again and writes a fresh report; evidence: the journey output. (serves EPC-024 AC-12)
- AC-8 A register entry of any kind that names a target or its report shall not make an absent, unparseable or leftover report pass; evidence: a gate test with a leftover report and a matching entry, which fails. (serves EPC-024 AC-12)
