# TSK-313: Tasks carry a class and a lane from the project vocabulary

## Description

A project cannot say what kind of work a task is in its own terms, or which
lane of people or agents carries it; task frontmatter has a fixed key set
(`assets/base/pm/task.md.tmpl:1-14`) and `work_type` is a fixed list
(https://github.com/sathyassn/codeflow/issues/164, the lane from
https://github.com/sathyassn/codeflow/issues/166). This task adds design
foundation F3: a project vocabulary file and two optional task fields.

- Vocabulary: `project-management/vocabulary.json`, schema-versioned,
  user-owned, a planning path and not an integrity path:
  `{"schema_version": 1, "classes": [{"id": "design", "name": "Design", "retired": false}], "lanes": [{"id": "lane-a", "name": "Coordinator"}]}`.
- Fields: `class: <id>` and `lane: <id>`, both optional. The class is set
  by `codeflow task new --class <id>`, `codeflow task class <id> <value>`
  or a hand edit in a reviewed PR; the lane by a hand edit in a reviewed
  PR. Setting a lane at claim time is deferred (operator decision 9).
- Validation: no catalog and a present value gives one warning per record
  naming the file to create; a catalog and an undeclared value is an error;
  a retired value warns on an open task and is silent on a closed one; a
  missing value is never a finding. The error is data integrity in
  `validate --docs` and the gates that run it, not a new authority.
- Views: `status` per class with `unclassed`; one optional `orient` line
  with its size reported against the advisory budget (ADR-0083);
  `work next --class` and `--lane`, and their JSON; a `ci` report line that
  is never a verdict; `estimate --by class` with `unclassed`. Grouping by
  `work_type` is unchanged and never mixed with class.

A class never changes a `ci` class, waives a review trigger, implies a
Deliverables home, changes readiness, or gates `work start`, `ci` or a
landing. Non-goal: the program report's class and lane rollups (TSK-314).

## Deliverables

- the vocabulary reader and validation: `crates/codeflow-core/src/validate/mod.rs` and a reader beside `crates/codeflow-core/src/models/task.rs`
- the fields and verbs: `crates/codeflow-core/src/models/task.rs`, `crates/codeflow-core/src/workgraph/status_verb.rs`, `crates/codeflow-cli/src/cmd/new.rs`, the `task` and `work` commands
- the views: `crates/codeflow-cli/src/cmd/status.rs`, `crates/codeflow-cli/src/cmd/work.rs`, the orient digest, `crates/codeflow-core/src/estimate/`
- the template: `assets/base/pm/task.md.tmpl` (comment lines for the optional fields)
- docs: `docs/cli.md`, the record fields in `docs/adoption.md` or the reference the PR names
- release note: `changelog.d/TSK-313.md`

## Acceptance Criteria

- AC-1 `validate --docs` shall read `project-management/vocabulary.json`
  at `schema_version` 1 and refuse a malformed file by name; evidence:
  tests for a valid file, malformed JSON and an unknown schema version.
  (serves EPC-023 AC-2)
- AC-2 The three validation states and the missing-value case shall give
  exactly the findings above; evidence: one test per state.
  (serves EPC-023 AC-2)
- AC-3 `task new --class` and `task class <id> <value>` shall set the
  class, refusing an undeclared value when a catalog exists; evidence: CLI
  tests.
- AC-4 Every record writer shall keep both fields byte for byte; evidence:
  one test per writer (`task new`, `task status`, `task class`, the
  amendment and acceptance writers).
- AC-5 The views shall show class and lane as stated, with `unclassed` and
  the `orient` line's size reported against the advisory budget;
  `work_type` grouping shall be unchanged; evidence: CLI tests per view and
  the existing estimate tests unchanged.
- AC-6 With and without a class or lane, `ci` classification, review
  triggers, readiness, `work start` and landing checks shall give the same
  verdict; evidence: paired tests.
- AC-7 When the installed build runs in a scratch project with a
  vocabulary file and classed tasks, `status`, `work next --class` and
  `estimate --by class` shall show the groups, and an undeclared value
  shall fail `validate --docs` (journey); evidence: the journey output.
