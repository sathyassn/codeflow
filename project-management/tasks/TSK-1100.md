# TSK-1100: Figures draw expected windows on a time axis with now, dependencies and the path to main

## Description

The operator's feedback of 2026-10-30 (20:40, relayed by the coordinator)
on the hand-built status presentation: the lane figure "still doesn't seem
to convey certain things like the timing aspects clearly"; timing must
read at a glance, on a real time axis with now, the expected windows and
the dependencies; and the report must make clear what is on `main`, what
is not, and when it gets there. The figure grammar has nine families and
none draws time: the method says a series over time is "a table and one
sentence naming that boundary" (`explanation-method.md` stage 3), the
extent family draws reach from a baseline on one scale, and the layering
family draws planes over one shared axis of moments with no durations
(`figure-grammar.md` section 1). The hand-built report drew expected
completion as extent bars from zero, so a reader could not see when an
item starts, how windows overlap, or which dependency sets the end.

Outcome: **a tenth family, `schedule`, drawn by the grammar module both
runtimes load, places items as windows on one time axis (a band from the
earliest to the latest end with a soft fill and a dashed outline, no
solid part, the planning value a thin tick inside), marks the as-of
moment as a vertical rule labelled `as of`, draws a completed event as a
filled disc at its time, draws dependencies as connectors from a
predecessor's latest end to a successor's start, groups rows by lane or
by location (`main`, integration line, pull request, branch), draws an
agent-owned milestone such as the line's gate as a diamond at the end of
its window, draws an operator-owned step as a readiness window ending in
the human ring with the done event undated and written in words (`your
decision`, `no date`) off the axis, hatches a stopped item's band with
its condition (`after the issue clears`), writes `not yet estimable` with
the reason for an item with no window instead of drawing it, and keeps
the twelve rules (two non-hue channels per state, a legend, a
one-sentence caption, a table twin with the exact windows and bases, a
narrow recomposition that stacks rows and keeps the axis).**

```text
  as of 21:00
    |
  task A  (o)  ..[- - -|- - ]                    lane 1   on line
  task B      [- - -|- - - -]                    lane 2   pull request
  task C               \-->[///|///]  waits on B lane 2   branch
  line gate                        <>            milestone
  PR to main                         [- -](O)  ready for the operator
  merge to main      no date: operator's call    (off the axis)
  |----|----|----|----|----|----|----|----|----> 21:00  23:00  01:00 EDT
```

Figure: rows are items grouped by lane or location, bands run from the
earliest to the latest end with the planning tick inside, a disc is a
completed event, hatching is a stopped item with its condition,
connectors show dependencies, the diamond is an agent milestone, the ring
is the operator's decision, and the undated merge is written off the
axis.

Decisions, each reversible and disclosed here:

- The axis reads as a clock when the declaration's `now` carries a
  timestamp with its zone: major ticks show the clock time with the zone
  named once in the axis title and the offset from now (`+2 h`) beneath;
  without a timestamp the axis is hours from now, then days when a window
  passes 48 hours. The renderer prints the basis of the windows beside
  the legend. A second panel with a days scale may follow the same label
  column when a milestone lies beyond the hours span.
- Location gets a shared chip vocabulary in `figure-grammar.md` section
  4, drawn by the module wherever an item appears (schedule rows, encoded
  table cells, flow stations): `main` (the `layer-remote` square in the
  cat2 tone), `line` (the same square in the cat1 tone), `pull request`
  (the `node` ring with the number), `branch` (the `optional` dashed
  outline), each with its word, so no page defines location by tone
  alone (the design brief revision 2, gap 4).
- Marks reuse the vocabulary: `optional` (soft fill, dashed outline) for
  a window band, `done` for a completed event disc, `blocked` hatching
  for a stopped band, `trans` for a dependency connector, `merge` for an
  agent milestone diamond, `human` for the operator ring, `limit` for the
  as-of rule, with the `accent` tone on the critical path and `cat1` and
  `cat2` as lane companions; a new mark is added only if the builder
  shows the vocabulary cannot carry a state.
- The declaration takes `axis` (unit and span), `as_of`, `rows` (item,
  group, state, a window with earliest, planning and latest, completed
  events with times, dependencies, kind item or milestone, owner agent or
  human, a condition for a stopped or conditional band, a reason for an
  item with no window). The field names follow the window shape TSK-1095's
  record specifies (earliest, planning and latest end as durations from
  the as-of moment, a start, a condition, a basis), so TSK-1098 can bind
  the facts without a translation layer; the derived binding itself
  (`source` into a `codeflow status --json` file) is TSK-1098's, since it
  needs the landed facts.
- The chat form is the fenced ASCII above, under 78 columns.

Non-goals: a daemon or scheduler; computing the windows (TSK-1095);
the progress document (TSK-1098); a Gantt editor; a calendar.

## Outcome

After this merges, a present document or a portal page can show when
each item starts and is expected to end, what each waits on, where it is
on the way to `main` and when it is expected there, on one time axis a
reader grasps in a few seconds, with the exact windows and bases in the
twin.
