# TSK-1107: codeflow ci notes a change to the project audit exception check

## Description

`codeflow ci` prints a note when a range edits `.codeflow/ci-setup.sh`
(`ci.rs:2124-2153`) because the managed CI sources that file. TSK-294 (PR
446) adds a second project-owned file the managed CI reads, the dependency
audit exception check, and the Codex review of that PR found that `codeflow
ci` does not note a change to it (queue item 37, 2026-10-31 11:54). Codex
judged it non-material, since the check cannot change its own pull request's
verdict (it is read from the trusted commit), and the coordinator tracked it
as a small task. The fix gives the audit exception check the same note with
its own engine remedy code, and the sibling sweep covers every project-owned
file the managed CI reads so the next one (TSK-1103's declared checks) gets
the note in its own task. Non-goal: no verdict changes.

## Outcome

After this merges, a reviewer sees a `codeflow ci` note whenever a pull request edits the project's dependency-audit exception check, as they already do for the CI setup hook.

## Deliverables

- the note and its remedy code: `crates/codeflow-cli/src/cmd/ci.rs`, `crates/codeflow-core/src/remedy.rs`
- tests: `crates/codeflow-cli/tests/ci_cli/` (the note, the unchanged verdict) and the `remedy_clearing` entry
- docs: `docs/policy-reference.md` (the list of project-owned CI inputs that `codeflow ci` notes)
