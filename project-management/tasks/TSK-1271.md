# TSK-1271: A pinned claim's review lookup survives a slow provider and still refuses a dead one

## Description

The pinned claim/start review lookup in `crates/codeflow-cli/src/cmd/work.rs`
uses a fixed five-second deadline for `gh pr view`. The coordination brief
reports 4.09 to 5.07 seconds under nice10 on a busy host, compared with
1.4 seconds at normal priority. Valid pins therefore fail with
"cannot verify review for this pin: provider unavailable, too large or timed out".
Slow adopter networks can reach the same deadline.

The line at `d2752c69d` and 35 open PR branches into the EPC-022 line were
searched for "verify review for this pin", "pinned claim" and "timed out".
No open task owns this lookup. TSK-1253 covers a different doctor timeout.

## Outcome

After this merges, people claiming or starting reviewed pinned work can
complete a slow provider lookup while an unavailable or unsafe provider
still refuses the pin within a bounded wait.

## Deliverables

- Bounded review lookup: `crates/codeflow-cli/src/cmd/work.rs`.
- Slow, hanging, failed and oversized fake-provider evidence: existing CLI
  work tests under `crates/codeflow-cli/` (exact test home confirmed at build).
- Sibling timeout inventory and dispositions: this record or the PR body.
- Release note and any limit documentation: `CHANGELOG.md` and affected docs.

## Acceptance Criteria

- AC-1 A timeout, provider failure or oversized response refuses the pin with a named reason; no unverified pin is accepted. Evidence: fake-provider refusal tests.
- AC-2 A provider taking about 5 to 10 seconds succeeds. Use a longer default deadline of 15 seconds, retaining one attempt and a bounded wait; this avoids retrying successful slow calls and adds no configuration surface. The lookup deadline is 15 seconds, plus process cleanup and scheduling overhead. Evidence: a slow fake-provider journey.
- AC-3 A slow fake provider passes within the bound, and a dead or hanging provider refuses within the bound. The slow-provider regression fails before the fix and passes after. Evidence: targeted tests with elapsed-time assertions. (journey)
- AC-4 Every other fixed timeout on a gh or network call under `crates/` receives the same treatment or a recorded reason to retain its bound. Evidence: a sibling inventory with dispositions.
- AC-5 The changelog and any help or docs naming the limit reflect the change. Evidence: text search and documentation validation.
