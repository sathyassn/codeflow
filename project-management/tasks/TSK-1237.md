# TSK-1237: The gitleaks-ordering warning names the risk it found

## Description

Source: the CI throughput study of 2026-11-02 (`coordination/coordinators/parallel/throughput/`: RECOMMENDATIONS.md, FINDINGS.md, CHECK-codex.md, CHECK-fable.md), cross-checked by Codex GPT-6 Astra and Claude Fable 5.1, and the operator's priority on CI throughput.

Issue [#516](https://github.com/sathyassn/codeflow/issues/516) (CodeFlow 3.1.1): `codeflow update` warns about any step before the gitleaks step in the secret-scan job, with one text, even a step that runs before `actions/checkout`, reads one value from `env:` and only exits. That step writes neither `GITHUB_ENV` nor `GITHUB_PATH` and runs no pull request code, so the advice to move it is wrong, and the reader cannot tell a real finding from this one.

The warning should fire only for a step before gitleaks that could change the scan: one that runs after a checkout, runs a `uses:` action, or writes `GITHUB_ENV` or `GITHUB_PATH`. It should name which of those it found, and a guard that only exits early is not reported.

## Outcome

After this merges, `codeflow update` warns about a step before gitleaks only when the step can change the scan, says which risk it found, and leaves a guard that only exits alone.

## Deliverables

- the warning logic and text: `crates/codeflow-core/src/` (the update check for the secret-scan job)
- tests: the issue's guard step (no warning) and one case for each named risk
- docs: the text in `docs/` that describes the warning, if any

## Acceptance Criteria

- AC-1 Before any change, the builder shall record in the Findings where the warning is produced, the conditions it uses today, and every other place that repeats its text; evidence: a `## Findings` section, committed before the first code change.
- AC-2 A step before the gitleaks step that runs after a checkout, runs a `uses:` action, or writes `GITHUB_ENV` or `GITHUB_PATH` shall produce a warning that names which of the three it found; evidence: one test per risk. (serves EPC-022 AC-235)
- AC-3 A step before the gitleaks step that does none of the three, such as the issue's `Require a supported pull request base` guard that reads `BASE_REF` before the checkout and exits, shall produce no warning; evidence: a test with the issue's step verbatim.
- AC-4 The warning text and its remedy shall stay in the existing remedy-code scheme and shall not tell a reader to move a step that was not found to be a risk; evidence: the remedy test and the text diff.
- AC-5 `codeflow update` run with the installed build over a scratch project whose workflow holds the issue's guard step shall print no gitleaks-ordering warning, and over one with a risky step shall print the warning that names the risk; evidence: the journey output. (journey)
