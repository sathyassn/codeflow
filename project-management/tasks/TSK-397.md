# TSK-397: The exec guard adds a strict rule where the sandbox is absent or loosened

## Description

Source: PR 239 (TSK-373) final confirm, 2026-10-18. `cd src && python3 tool.py ..` from the checkout root is refused, because the guard's directory set keeps the starting directory after a `cd` (`crates/codeflow-core/src/security/outward.rs`, `DirSet::change`).

History of the outcome:

- 2026-10-25 (operator): narrowing after `cd` cannot be made sound against shell state the guard cannot see, so `cd src && python3 tool.py ..` stays refused. The PR 331 reviews found 14 text-bypass classes.
- 2026-10-27 (operator, option D): every stop in launcher traversal keeps its words judged, with a non-executing allowlist.
- 2026-10-28 (operator, narrowed option (c)): the allowlist and its shadowing analysis are removed. The text guard has two outcomes, selected from the harness configuration the host can read. The specification is design note D revision 4.1, Part A (`target/tsk-397-design-D.md` in the TSK-397 worktree; checks: Codex 01 to 03, Fable 01 to 04).
- 2026-10-29 (operator, option 2): selecting the outcome from the harness configuration is removed. A trigger list (rounds 15 to 16) and then an attestation (rounds 17 to 18) each missed a layer or key that let a weaker configuration select the relaxed rule, so the feature could not be made sound. The strict rule is the default; the relaxed rule is the operator's choice in landed policy.

The two outcomes:

- **Strict**, the default, adds the strict branch, PR 331's rule with every name-based exemption removed. It applies to every call unless the operator chose relaxed.
- **Relaxed** is the line's rule. It applies when `security.text_guard` is `relaxed` in every policy the hook reads at the remote-tracking refs as last fetched: the call's repository (its remote's default branch, the one policy authority since TSK-1077) and, for a Claude Code call, the session's project. A working copy, a local branch or tag, a remote `HEAD` outside the remote, a ref file that is a symbolic link and a repository without a remote stay strict. The guard verifies no sandbox under relaxed. A recognized marked retry (`dangerouslyDisableSandbox`), and every call on native Windows, stay strict under relaxed.
- The strict rule's own refusals always block, under `security.text_guard`; `git.hook_integrity` sets the level of the line's findings only (security review round 1, SEC01-1).

Doctor and the hook decide through the same function (`sandbox_state::reasons`). Doctor prints `text rule: strict` with its reason, or `text rule: relaxed by operator choice, not verified` with the ref it was read from. `codeflow init` and `codeflow update` never write the key.

The strict outcome keeps every relaxed finding. Neither outcome allows what the line refuses, except the H-3 class below, which relaxed allows and strict refuses. A replay of the historical corpus is the test.

Hardening in both outcomes:

- a NUL byte refuses (H-1);
- the headless `xargs` reader no longer guesses a bare optional-value option or a BSD option (H-2);
- a line made only of bare `cd`, `pushd` and `popd` builtins no longer takes the startup write judgement (H-3, issue 342);
- the enforcement paths are explicit `sandbox.filesystem.denyWrite` entries in the presets (H-4);
- `~/.codeflow/authority/` is a protected directory, reserved for the 4.1.0 qualification records (H-5).

`codeflow doctor --check sandbox` names the rule in force and why (H-6). Non-goals for 4.0.0: qualification, receipts, capability relaxation and the other Part C units, which are planned for 4.1.0.

Limits, each as it is on the line today unless noted:

- An unread program (a script file, code the guard does not read) can write an enforcement file or read a secret wherever no kernel deny holds. The strict branch narrows the text-visible paths and contains nothing.
- Under relaxed, the guard trusts the OS sandbox the project configures and does not check it. An unsandboxed retry the harness does not mark (a Codex seat has no field) follows the relaxed rule; TSK-1052 fails closed there for a command that runs code after a same-line write (EPC-022, filed by PR 390).
- Doctor's state-root check reads Claude write grants only; Codex and Grok grants are not computed, and doctor does not claim the state root is unwritable.
- An `awk` inline program that writes an enforcement path passes the exec guard (git-guard refuses it); it is the unread-program residual above, to be tracked once.
- Debug builds honour `CODEFLOW_TEST_CLAUDE_MANAGED_DIR`, which moves the managed settings layer doctor reads; release builds ignore it.
- The `Monitor` tool is outside the hook matcher (4.1.0, TSK-1058).
- Policy authority under `refs/remotes/origin/*` and `packed-refs` is writable by a direct file write (4.1.0, TSK-1057). A relaxed value written there by a session, or a stale relaxed ref before the next fetch, would be read as landed; the same gap applies to every policy key. Security review round 1 (SEC01-2) narrowed the read to plain refs inside the remote's namespace with no symbolic-link ref files; it does not authenticate them.
- A file a repository configuration `include` names is read by libgit2 with a blocking read and is not checked. A fifo named only by an include stalls that read until the guard's own deadline (TSK-1082, merged from the line on 2026-10-30) refuses with exit 2 after 20 seconds; the stall never allows the command (`docs/policy-reference.md`, repository discovery). The repository's own `config` and `config.worktree` files, the policy and the project settings are checked first (SEC01-3).
- Neither rule sees the environment a command inherits (`PATH`, `HOME`, Codex's `shell_environment_policy`, secret-bearing variables); Fable F3-1's attestation finding is moot, this residual is not.
- In a linked worktree, protection of the shared `.git`'s `hooks`, `config` and `config.worktree` is unverified (4.1.0, TSK-1054).
- Codex nested secret files and `.envrc`, and Grok's launch-time globs, are recorded gaps of those profiles.

Follow-ups (for the closeout `follow_ups`): the Part C units of design D, planned for 4.1.0 in EPC-023 by PR 391. They are TSK-1054 (qualification record), TSK-1055 (capability relaxation), TSK-1056 (administrator policy), TSK-1057 (authenticated policy authority), TSK-1058 (`Monitor` matcher), TSK-1059 (trusted host-state operations) and TSK-1060 (Codex managed requirements). A relaxed rule tied to verified containment, in place of the operator's unverified choice, belongs to TSK-1054. Failing closed in the unknown-containment cases is tracked as TSK-1052 (EPC-022). Deferred: setting `security.text_guard: relaxed` in CodeFlow's own `.codeflow/policy.json` (the operator's choice of 2026-10-29) waits until 4.0.0 publishes. Reason: a new key enters the installed policy only after the release that introduced it has published (`docs/policy-reference.md`, "Where a new key goes", held by `policy_key_placement`), and the hosted policy check judges the head with the base's binary, which does not know the key; the coordinator tracks it.

## Outcome

After this merges, the strict text rule applies in every session by default, and an operator can choose the line's rule for a project by landing `security.text_guard: relaxed` on its protected refs. No command the line refuses is allowed, except a line made only of bare `cd`, `pushd` and `popd` builtins under relaxed, which writes nothing. The change is breaking (4.0.0): `codeflow doctor --check sandbox` shows the rule in force.

## Acceptance Criteria

- AC-1 `cd src && python3 tool.py ..` and `cd src && python3 tool.py ../.claude/settings.json` from the checkout root shall refuse in both outcomes; the origin case stays refused until the 4.1.0 qualification design; evidence: guard tests under both outcomes. (serves EPC-022 AC-86)
- AC-2 (journey) No row of the historical corpus that the line binary built from the integration line this branch last merged (recorded in `line-binary.txt`) refuses shall be allowed in either outcome. The corpus is the Codex and security round probes as the round 15 replay assembled them, the 49-line everyday sample and the two shell review fixtures. A row may become stricter. Each row keeps its original operation. Every judgement shall exit 0 or 2. The one reasoned exception is the H-3 class: a line made only of bare `cd`, `pushd` and `popd` builtins with literal or plain `"$NAME"` arguments, joined by `&&`, `;` or newlines, may be allowed under relaxed and shall be refused under strict; evidence: `text_guard_invariant.rs` at the head, which states the class as its own predicate and drives the built binary through `codeflow hook exec-guard` in a fixture checkout whose origin's landed policy is relaxed, with the line column and the line binary's version and digest beside the corpus.
- AC-3 A payload with `dangerouslyDisableSandbox: true` shall be judged under the strict branch, also under relaxed (the recorded Claude Code 2.1.312 payload as fixture). A payload without the field shall be judged by the rule the landed policy selects. The release note shall state that an unmarked retry follows the rule in force; evidence: state tests, the replay's strict column. The installed-build journey runs at epic close.
- AC-4 With no `security.text_guard` in any policy source, every call shall take the strict rule. `relaxed` shall be honoured only when read from the remote's default branch as last fetched, the one policy authority TSK-1077 established, of the call's repository and, for a Claude Code call, of the session's project, with no loose ref file on the way that is a symbolic link; a `relaxed` in the working copy, in a local commit or branch the remote does not hold, or in a repository without a remote shall keep the strict rule. Under relaxed, native Windows shall keep the strict rule; evidence: `sandbox_state` tests and the hook journey tests.
- AC-5 Doctor shall print the text rule through the function the hook uses: `text rule: strict` with each reason, or `text rule: relaxed by operator choice, not verified` with the ref it was read from. It shall fail on an unreadable policy and when the project, the temporary directory or a Claude write grant of any layer reaches the CodeFlow state root, and shall not claim the state root is unwritable. `codeflow update` shall deliver H-4 and H-5 to the presets and profiles. The commands H-5 names shall run unchanged; evidence: doctor and preset tests, the existing CLI tests of those commands.
- AC-6 The 49-line everyday sample shall be judged by the built binary in both outcomes, with the per-line results recorded in the replay file at the head; no count is a criterion; evidence: the replay file.
- AC-7 `security.text_guard` shall accept `strict`, the default and the meaning of an absent key, and `relaxed`. Where policy sources disagree, `strict` shall win. `codeflow init` and `codeflow update` shall not write the key; evidence: policy schema, landed-policy merge and state tests.
- AC-8 The hardening items shall hold in both outcomes: a command holding a NUL byte refuses (H-1); a bare GNU optional-value `xargs` option or an unmodelled one never hides a headless peer run (H-2); and `cd ~ && cd "$p"` and `cd / && pushd "$p"` pass the startup check in both outcomes and the guard under relaxed, while every other line keeps the write judgement (H-3); evidence: guard, headless and startup tests.
