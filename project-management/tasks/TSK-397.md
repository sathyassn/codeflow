# TSK-397: A cd before an interpreter narrows the directory set correctly

## Description

Source: PR 239 (TSK-373) final confirm, 2026-10-18. `cd src && python3 tool.py ..` from the checkout root is refused, because the guard's directory set keeps the starting directory after a `cd` (`crates/codeflow-core/src/security/outward.rs`, `DirSet::change`), and from the root `..` is above the checkout. It passes when the hook cwd is `src`. Usability, info; it refuses a legitimate command.

Outcome: **after `cd <dir> &&`, the guard judges later operands from `<dir>` alone, so a legitimate relative path is not refused.**

The narrowing applies only to `&&` joins, resolves `..` physically after a `cd` through a symlink, and accounts for `CDPATH`. Any other join keeps today's set.

Added to EPC-023 (4.1.0) by the amendment of 2026-10-18: the operator's release decision of that day puts lower-severity review follow-ups in 4.1.0 (workspace `RELEASE-PLAN.md`, 2026-10-18 operator decision).

## Deliverables

- tests: guard tests for each join and for symlinked and `CDPATH` cases
- release note: `changelog.d/TSK-397.md`

## Acceptance Criteria

- AC-1 `cd src && python3 tool.py ..` from the checkout root shall pass, and `cd src && python3 tool.py ../.claude/settings.json` shall still refuse; evidence: guard tests, the first failing before the change. (serves EPC-023 AC-29)
- AC-2 `cd src; ...`, `cd src || ...` and a `cd` inside a subshell shall keep today's set; a `cd` through a symlink shall resolve `..` physically; `CDPATH` shall be honoured or the line judged with both sets; evidence: tests per case.
