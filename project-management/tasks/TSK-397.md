# TSK-397: A cd before an interpreter keeps the starting directory

## Description

Source: PR 239 (TSK-373) final confirm, 2026-10-18. `cd src && python3 tool.py ..` from the checkout root is refused, because the guard's directory set keeps the starting directory after a `cd` (`crates/codeflow-core/src/security/outward.rs`, `DirSet::change`), and from the root `..` is above the checkout. It passes when the hook cwd is `src`. Usability; it refuses a legitimate command, and the workaround is to change the hook cwd.

Outcome (amended 2026-10-25 by operator decision): **after `cd <dir>`, the guard keeps judging interpreter operands from the starting directory as well, and every way the reviews found for a `cd` to land somewhere the guard does not follow makes the directory unknown.**

Amendment reason: narrowing cannot be made sound against shell state the guard cannot see (aliases, functions, `chpwd` hooks, `PATH` wrappers, the shell's own `PWD` and `CDPATH`, zsh options). The security, Grok and Codex reviews of PR 331 found 14 bypass classes, and the operator directed the secure choice. `cd src && python3 tool.py ..` from the checkout root therefore stays refused; the workaround stays a hook cwd of `src`.

First added to EPC-023 (4.1.0) on 2026-10-18; moved to EPC-022 (3.2.0) the same day after the Codex review of PR 249, under the operator's rule that every security gap and every defect that forces an adopter workaround or blocks work belongs in 3.2.0.

## Deliverables

- the directory set: `crates/codeflow-core/src/security/outward.rs` and `ruby -C` in `arguments.rs`
- tests: a refusal test per review bypass line, and the pinned starting-directory behaviour
- release note: `changelog.d/TSK-397.md`

## Acceptance Criteria

- AC-1 After `cd <dir>`, the guard shall keep the starting directory in the set it judges interpreter operands from, for every join: `cd src && python3 tool.py ..` and `cd src && python3 tool.py ../.claude/settings.json` from the checkout root shall both refuse; evidence: guard tests pinning both. (serves EPC-022 AC-86)
- AC-2 Every bypass line from the PR 331 reviews (security-01, grok-01, codex-02) shall refuse: a `..` in a `cd` target, a `cd` operand that reaches no existing directory (`cdable_vars`), zsh's two-operand `cd`, any `CDPATH` or `cdpath` mention however quoted or encoded, any `cd` that a `CDPATH` (on the line or held only by the shell) could redirect, a `CDPATH` entry read physically, and `ruby -C` through a link; evidence: a refusal test per line, each failing before its fix.
- AC-3 (journey) With the installed build, an agent session running `cd src && python3 tool.py ../.claude/settings.json` from the checkout root shall be refused; evidence: the journey output. Hook payloads against the built binary prove the guard decision; the live-session run on an installed build is deferred to the epic close.
