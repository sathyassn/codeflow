# TSK-013 — prepare the v3 release candidate

## Description

Prepare the integrated tree as a truthful v3.0.0 release candidate without
approving or publishing it: reconcile versioned scaffold state, release docs,
current product claims, public-history recurrence prevention, and repeatable
local/cross-target canaries so TSK-010 can focus on the still-blocking native,
cross-lineage, public-history, human-merge, tag, artifact, and downstream gates.

## Affected surfaces and interfaces

- Workspace/scaffold version markers and baselines, changelog, adoption and
  release documentation, CodeFlow's portal release provenance, repository-only
  local-state ignores, current CLI/role claims, distribution plan, and
  greenfield/brownfield release canaries.

- [ ] The workspace, lockfile, installed root scaffold state, managed markers,
      and CodeFlow portal provenance agree on v3.0.0; the portal starter keeps
      its independent 1.0.0 format/tool version.
- [ ] The curated changelog has an empty Unreleased section, a dated v3.0.0
      section with every breaking migration, and correct comparison links;
      current adoption/contribution/release docs contain no stale platform,
      role, command, or version claim while historical evidence stays intact.
- [ ] Root-only ignore rules prevent new CodeFlow `.state/`, Claude memory, and
      coverage-profile artifacts without imposing those project-specific names
      on consuming scaffolds. The release record truthfully carries the
      historical-publication blocker; this task does not rewrite history or
      change remote visibility.
- [ ] A clean v3 binary performs idempotent greenfield and representative
      brownfield init/update/validate/doctor canaries while preserving
      project-owned content, reporting conflicts, and keeping both optional
      utilities opt-in.
- [ ] The complete local gate, current secret/dependency/supply-chain checks,
      cargo-dist plan/generation check, macOS release build, and Windows/Linux
      cross-check/build pass on the exact candidate. Every missing native,
      installer, public-network, or model result remains explicit.
- [ ] Independent review and an exact-patch Fable review find no unresolved
      material release-preparation defect; every blocking finding is resolved
      and re-reviewed. A verified service-boundary failure may permit bounded
      candidate preparation and landing into the declared integration target
      with the missing assurance recorded, but this task remains `in_progress`
      and cannot satisfy its edge into TSK-010 until that review approves.
