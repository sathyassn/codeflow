# TSK-304: Pre-push checks every pushed tree or refuses the push

## Description

With `git.test_gate_on_push` at `block`, a commit that fails the push set
can still be pushed: edit a tracked file without committing and push again,
and the pre-push hook skips the tree checks with a note
(https://github.com/sathyassn/codeflow/issues/156, reproduced 2026-10-12).
`crates/codeflow-cli/src/cmd/push_set.rs` runs `validate --docs` and the
quick targets only when the checkout is clean, complete and at the pushed
commit (`push_set.rs:184`, `tracked_tree_clean` at `:1725`); every other
ref gets the `PUSH_TREE_UNCHECKED` note, never a violation, whatever the
level. The range checks still run first, so not every pre-push check is
skipped. The existing CLI tests in `crates/codeflow-cli/tests/hooks_cli.rs`
expect success on the unchecked dirty-tree and other-ref paths.

This task makes the gate fail closed for the whole class, not only the
dirty-file spelling: at `block`, a pushed ref whose tree the hook cannot
check (dirty tracked files, a ref other than `HEAD`, several refs in one
push, a sparse or incomplete checkout, a submodule whose checkout differs
from the pushed gitlink) is either checked on the pushed commit in a
temporary checkout or refused with the clean-checkout remedy. The builder
chooses between the two and records the choice and its cost in the PR; the
Codex triage of 2026-10-13 (`triage-codex-02.md`, "Patch contents and
release order") names both. Lower levels keep the note, honestly worded.
The documented caveat that untracked files can influence a working-tree
test (`push_set.rs:11`) stays and is tested.

The destination-held exception is limited to advertised branch history: tag
pushes run no push set and cannot establish this exemption. A clean, complete
checkout at the pushed commit still runs the tree checks first (AC-4).

Operator record: kept first in 3.2.0 rather than in a 3.1.2 patch
(SETTLED_DISSENT of 2026-10-13 in the workspace `RELEASE-PLAN.md`), because
hosted CI reruns the same checks on every pull request and they are
required on protected branches. Non-goal: changing which checks the push
set holds.

## Deliverables

- the fail-closed push set: `crates/codeflow-cli/src/cmd/push_set.rs`
- the remedy text: `crates/codeflow-core/src/remedy.rs` (`PUSH_TREE_UNCHECKED` and any new refusal)
- tests: `crates/codeflow-cli/tests/hooks_cli.rs` (the two success expectations replaced)
- docs: the `git.test_gate_on_push` entry of `docs/policy-reference.md`
- release note: `changelog.d/TSK-304.md`

## Acceptance Criteria

- AC-1 When `git.test_gate_on_push` is `block` and a commit that fails a
  quick target is pushed from a checkout whose tracked files differ from
  that commit, the push shall be refused, or the failing target shall run
  on the pushed commit and refuse it; evidence: the issue 156 reproduction
  as a CLI test (a failing commit, then a fixed but uncommitted working
  tree, then the push), failing before the fix and passing after.
  (serves EPC-022 AC-14)
- AC-2 At `block`, a push of a ref other than `HEAD` whose commit no branch the
  destination advertises already holds, a push of several refs at once, a
  push from a sparse or incomplete checkout and a push whose submodule checkout differs from
  the pushed gitlink shall each be
  checked on the pushed commit or refused, never passed with a note;
  evidence: one CLI test per shape. (serves EPC-022 AC-14)
- AC-3 At `warn` and `off`, the same shapes shall keep the note, and the
  note shall say that the tree checks did not run and what to run;
  evidence: a CLI test per level.
- AC-4 A clean, complete checkout at the pushed commit shall still take
  the existing blocking path, and the hook shall make no more `ls-remote`
  calls than today; evidence: the existing control test and a count of
  advertisement calls in the test.
- AC-5 When an untracked file changes a quick target's result, the output
  shall name the documented caveat; evidence: a CLI test with an untracked
  file.
- AC-6 (journey) When the installed hooks run a push of the issue's shape in a
  scratch adopter project, the push shall be stopped and nothing shall
  reach the remote; evidence: the journey output with
  `git ls-remote` showing the remote unchanged.

## Follow-ups

- Destination advertisement can be redirected by on-disk `url.<x>.insteadOf`
  configuration. This predates TSK-304 and affects the branch-history
  exemption, range base and destination policy authority. The range-base
  commands (`push_set.rs`'s `merge-base` and `rev-list --boundary`) also still
  read commit-graph, grafts and replace refs. Track these pre-existing inputs
  separately; owner: EPC-022 primary; revisit: before 3.2.0 ships.
