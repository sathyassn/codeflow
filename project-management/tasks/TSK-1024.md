# TSK-1024: git-guard allows read-only git commands it cannot place

## Description

Issue #357 and its comment (CodeFlow 3.1.1). git-guard refuses read-only
git commands in common shapes, so agents split or rewrite harmless
inspection lines, and the guard's own advice (`cd /path/to/repo && git …`)
is a form it then refuses.

Rechecked on 2026-10-27 through `codeflow hook git-guard --contract 3`
with the 3.2.0 binary built at TSK-397's head `caf728c70`, payload cwd a
worktree of this repository:

| Issue case | Result on 3.2.0 |
|---|---|
| 1: `git -C <repo> branch --list 'task/TSK-643-*'` | still refused, `git.discard_uncommitted`, "the pattern in `task/TSK-643-*`" |
| 2 and 2b: `cd <repo> && git remote -v \| head -2`, the same with `git worktree list` | still refused, `git.policy_authority`, "a directory change on a line the guard does not model", after a note advising `cd /path/to/repo && git …` |
| comment: `cd $S; git remote show origin` | still refused, `git.policy_authority`, "`$S`" |
| 2c: `cd <repo> && git status -sb \| head -2` | allowed with the "judged it as a protected branch" note |
| 3: `git -C <repo> worktree add <new> task/x && git -C <new> status -sb` | allowed with a note: no longer reproduces |
| comment: `cd $TMPDIR && rm -rf cfsrc && …` | allowed: no longer reproduces |
| comment: `gh issue comment … --body "… git remote show …"` | allowed: no longer reproduces |

Causes, read on the line tip `7172229aa`:

- Case 1: `discard_intent` (`crates/codeflow-core/src/hooks/git_guard.rs:20146`)
  expands every operand with `expand_word` before it parses options; a
  glob fails there (`crates/codeflow-core/src/hooks/git_target.rs:244`),
  although the `branch` arm (`git_guard.rs:20268`) treats only a forced
  delete as a discard.
- Cases 2 and the comment: on a line `flat_top_level` does not model (a
  pipe, `||`, a group), `moves_for` (`git_guard.rs:8561-8569`) makes every
  git command's directory unknown when the line changes directory, and an
  unknown target is allowed only for the subcommands of
  `discard_readonly_git` (`git_guard.rs:20466`): `status`, `diff`, `log`,
  `show`, `rev-parse`, `ls-files`, `ls-tree`, `merge-base`,
  `for-each-ref`, `show-ref`, `cat-file`, `check-ignore`, `help` and
  `version`.

Outcome: **a git command that cannot change refs, the index, the work
tree, configuration, hooks or a remote is allowed with a note wherever
git-guard cannot place it, and a refusal's advice names a form the guard
accepts.**

Design, fixed here:

- The guard does not start modeling `cd`. The operator decided on
  2026-10-25 (TSK-397's amendment) that narrowing directories cannot be
  made sound against shell state the guard cannot see; the issue's
  suggestions 3 and 4 (model a leading `cd`, model paths created earlier
  on the line) are therefore not taken. An unknown directory stays
  unknown; what changes is which commands are safe there.
- One read-only classifier replaces `discard_readonly_git`. It decides
  from the subcommand and its parsed options, not from the subcommand
  name alone, and serves the unresolved-target block in `check_git`,
  `may_change_discard_state`, an early exit in `discard_intent` and
  `check_discard`, so discard intent is decided before any operand is
  expanded, and `check_authority` (`git_guard.rs:8635`, run first for
  every git command from `check_git` at `:8722`). There, a command whose
  `-C` target is a worktree created earlier on the same line takes its
  source's authority only for `status` (`:8674`), so `git -C <new> log -1`
  still loads policy from a directory that does not exist yet and is
  refused (`:8679-8685`). The classifier replaces that `status`-only
  test; a mutation still needs a readable target and every branch
  check.
- Read-only forms it accepts: the current list; `branch` with only
  listing options (`--list`/`-l` with patterns, `--show-current`, `-a`,
  `-r`, `-v`/`-vv`, `--contains`, `--no-contains`, `--merged`,
  `--no-merged`, `--points-at`, `--format`, `--sort`); `worktree list`;
  `remote` with no subcommand, `-v`, `show`, `get-url`; `config` read
  forms (reusing `config_only_reads`, `git_guard.rs:10716`); `stash list`
  and `stash show`; `tag` with `--list`/`-l` only; `describe`, `name-rev`,
  `rev-list`, `shortlog`, `blame`, `count-objects`, `var`, and
  `symbolic-ref` with no new value.
- Never read-only: any form that creates, renames, deletes or sets
  something (`branch <name>`, `-m`, `-c`, `-d`, `-u`, `tag <name>`,
  `remote add`, `config` without a read flag), and any option that runs a
  program or writes a file: a `git -c` setting, `--exec-path`,
  `--output`, `grep -O`/`--open-files-in-pager`, `--upload-pack` and
  `--receive-pack`. `grep` joins the list only without those options.
- The advice printed with an unresolved target says why the guard could
  not place the command (a pipe or `||` on the line, an unresolved `cd`)
  and suggests `git -C <literal path> …`, never `cd /path && git …`.

Severity: medium. No refusal of a write is removed; the cost is agent
turns and confusing advice on every read-only inspection line with a pipe
after `cd`.
