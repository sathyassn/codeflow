# TSK-180: Retract a removed trap or hook in the deletion reader

## Description

The TSK-141 deletion reader stores each `trap` action and zsh hook function
it meets and joins that action into the state at every later command
boundary, but never retracts one. A trap reset (`trap - DEBUG`,
`trap '' DEBUG`, `trap - EXIT`) or a removed hook (`unfunction chpwd`,
`unfunction TRAPDEBUG`) leaves the stored action live, so a later safe
cleanup is refused. Codex found this in its round 4 review of TSK-141
(`ed06b48a6`): `trap 'D=/' DEBUG; trap - DEBUG; D=build; rm -rf "$D"` is
refused as a protected deletion, while Bash print-only oracles with the
same setup print `build`, and the EXIT reset and zsh hook removal oracles
agree. This is a false refusal, not a false allow. The fix keys each
stored action by its signal or hook name, retracts it on a reset or an
undefinition the reader can prove, and keeps the conservative join
wherever the registration or its removal is uncertain.

Non-goal: modelling signal delivery itself. A trap that is set stays
feasible at every later boundary, as TSK-141 reads it.

## Affected surfaces and interfaces

- exec-guard's composed deletion reader, `security/deletion.rs` in
  `codeflow-core` (CAP-001), and its probe tables in
  `security/guard_forms.rs`. No policy key, message or CLI surface
  changes.
- Shared file: `security/deletion.rs` after TSK-141.

## Acceptance Criteria

- AC-1 When a line resets a trap the reader stored (`trap - SIG`,
  `trap '' SIG`, or `trap -- - SIG`, for `DEBUG`, `EXIT`, `ERR`,
  `RETURN` or a signal) before a deletion, exec-guard shall judge the
  deletion without that trap's action from the reset on, so
  `trap 'D=/' DEBUG; trap - DEBUG; D=build; rm -rf "$D"`,
  `trap 'D=/' DEBUG; trap '' DEBUG; D=build; rm -rf "$D"` and
  `trap 'D=/' EXIT; trap - EXIT; D=build; rm -rf "$D"` run; evidence: rows in
  a round 4 probe table in `guard_forms.rs`, each red at `ed06b48a6`,
  replayed through the built hook.
- AC-2 When a line removes a zsh hook function the reader stored
  (`unfunction chpwd`, `unfunction TRAPDEBUG`, `unset -f precmd`), or
  redefines it with a body that changes nothing the reader follows,
  exec-guard shall judge a later deletion without the removed action, so
  `chpwd() { D=/; }; unfunction chpwd; D=build; cd empty; rm -rf "$D"`,
  `TRAPDEBUG() { D=/; }; unfunction TRAPDEBUG; D=build; rm -rf "$D"` and
  `precmd() { D=/; }; unset -f precmd; D=build; rm -rf "$D"` run;
  evidence: rows in the same table, each red at `ed06b48a6`.
- AC-3 When the reset or removal may not run, or names a signal or hook
  the reader cannot resolve (inside an `if` branch, after `||`, in a
  subshell, in a function never called, `trap - "$SIG"`), exec-guard
  shall keep the stored action feasible, so
  `trap 'D=/' DEBUG; if test -f x; then trap - DEBUG; fi; D=build; rm -rf "$D"`,
  `trap 'D=/' DEBUG; (trap - DEBUG); D=build; rm -rf "$D"` and
  `trap 'D=/' DEBUG; trap - "$SIG"; D=build; rm -rf "$D"` stay refused;
  evidence: rows in the same table, refused at `ed06b48a6` and after.
- AC-4 When a reset or removal targets a different signal or hook, or a
  trap is set again after its reset, exec-guard shall keep the refusal
  TSK-141 gives, so `trap 'D=/' DEBUG; trap - EXIT; D=build; rm -rf "$D"`
  and `trap 'D=/' DEBUG; trap - DEBUG; trap 'D=/' DEBUG; D=build; rm -rf "$D"`
  stay refused, and every row of `REVIEW_ROUND_TWO_PROBES` and
  `REVIEW_ROUND_THREE_PROBES` keeps its verdict; evidence: the same
  table and the existing round tables.
