# TSK-1235: Target commands receive the comparison base, the head and the changed paths

## Description

Source: the CI throughput study of 2026-11-02 (`coordination/coordinators/parallel/throughput/`: RECOMMENDATIONS.md, FINDINGS.md, CHECK-codex.md, CHECK-fable.md), cross-checked by Codex GPT-6 Astra and Claude Fable 5.1, and the operator's priority on CI throughput.

Issue [#514](https://github.com/sathyassn/codeflow/issues/514) (CodeFlow 3.1.1): `codeflow test` runs each target's command with no information about what the push changes, so a target cannot narrow itself to the touched suites. In a second adopting repository (29 October to 2 November, 65 pre-push logs), each push ran every suite: median 3.3 minutes, p90 5.7, maximum 10.1.

The ask is to pass the comparison base, the head and a file that lists the changed paths to each target command in quick and full mode, to say so in the same variables when no base could be proven so that the target runs everything, and to record the base the run used in `run.json`.

These inputs serve only the target's own narrowing. They never count toward CodeFlow's own selection credit: a local run earns none (ADR-0089, TSK-1044), and this task does not change that. Non-goals: #371 (CodeFlow's selection of targets) and #476 (the landing gate by change class).

## Outcome

After this merges, a project's own test command can read the base, the head and the changed paths of the push it runs for, and can fall back to running everything when no base was proven.

## Deliverables

- the environment and the changed-paths file passed to each target command: `crates/codeflow-core/src/testing/`
- the base recorded in `run.json` and its schema: the same module and `.codeflow/schemas/` where the schema lives
- tests: a target command that prints its inputs, in quick and full mode, with and without a proven base
- docs: `docs/cli.md` and `docs/policy-reference.md` where target commands are described

## Acceptance Criteria

- AC-1 Before any change, the builder shall record in the Findings how a target command is started in quick and full mode, where the comparison base is already computed (the push set and the delivery base), and what a project's runner would need (variable names, the changed-paths file format, path quoting and size limits); evidence: a `## Findings` section, committed before the first code change.
- AC-2 Each target command shall receive the comparison base (`CODEFLOW_BASE`), the head (`CODEFLOW_HEAD`) and a file listing the changed paths (named by a variable), in quick and full mode; evidence: a test whose target prints its inputs, for each mode. (serves EPC-022 AC-234)
- AC-3 When no base could be proven, the same variables shall say so, and the changed-paths file shall not be offered as if it were complete; evidence: a test with no provable base.
- AC-4 `run.json` shall record the base the run used, or that none was proven, and its schema version rules shall hold; evidence: the schema test and a run.json fixture.
- AC-5 These inputs shall never change which targets CodeFlow selects, skips or credits: a run with the inputs present shall select and credit exactly as a run without them; evidence: the existing selection tests passing unchanged, and one test that compares the two.
- AC-6 In a scratch project with the installed build, a target command that reads the variables shall run only the suites for the changed paths on a push with a proven base, and shall run everything on a push without one; evidence: the journey output. (journey)
