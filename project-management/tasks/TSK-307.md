# TSK-307: A misshapen acceptance file is refused by name

## Description

`codeflow task status <id> complete --acceptance <file>` refuses a file
whose YAML has no top-level `acceptance:` key with "a complete record needs
an acceptance block in its Closeout", which names the task record and reads
as a problem with it (https://github.com/sathyassn/codeflow/issues/175). The
command reads the file verbatim and inserts it
(`crates/codeflow-cli/src/cmd/new.rs:733`), and the lifecycle check then
finds no block (`NO_BLOCK`, `crates/codeflow-core/src/workgraph/lifecycle.rs:894`).
The option's help (`new.rs:96`) says "the YAML between the fences", which
starts with `acceptance:`, but the template comment lists the fields, not
the key. This task parses the file before inserting it and refuses a file
without the top-level key with a message that names the file and the key.
It does not wrap the fields silently: the refusal is explicit, so a lane
learns the shape once. Non-goal: changing the acceptance block's fields.

## Deliverables

- the parse and refusal: `crates/codeflow-cli/src/cmd/new.rs`
- the help text: the `--acceptance` option in `new.rs`, and `docs/cli.md`
- tests: `crates/codeflow-cli/tests/` beside the existing `task status` tests
- release note: `changelog.d/TSK-307.md`

## Acceptance Criteria

- AC-1 When the `--acceptance` file has no top-level `acceptance:` key,
  `codeflow task status <id> complete` shall refuse before it writes the
  record, and the message shall name the file and the missing key, and
  shall not name the task record as the cause; evidence: the issue 175
  reproduction as a CLI test, failing before the fix and passing after.
  (serves EPC-022 AC-18)
- AC-2 When the file is not valid YAML, the refusal shall name the file
  and the parse error; evidence: a CLI test.
- AC-3 A file with the top-level key shall behave as today, including the
  later field checks that report the real field problems; evidence: the
  existing tests unchanged.
- AC-4 The `--acceptance` help and `docs/cli.md` shall say that the file
  holds a top-level `acceptance:` key and list its fields; evidence: a help
  text test.
