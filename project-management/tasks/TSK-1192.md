# TSK-1192: Keep hosted coverage shards from running out of disk during the instrumented build

## Description

Hosted coverage shards run out of disk during the instrumented build. PR 485 (TSK-1153, four coverage shards) does not cover this: it changes the matrix to `[1, 2, 3, 4]` and the shard bookkeeping, but every shard still compiles the whole instrumented workspace (`cargo llvm-cov nextest --workspace ... -E <filter>`; the comment says "All four shards build the same thing") and adds no step that frees disk. The only disk measure today is the profraw merge pool (`codeflow-ci.yml:446-449`, the EPC-022 tip).

Evidence: job 125339596386 (run 41463848238, PR 511): "No space left on device", then `ld terminated with signal 7 [Bus error]`, about 90 s into the build, while compiling `wp7_contract` and the cli bin (log lines 443, 448, 452 and 464). Job 125110168429 (run 41393619630, line tip `6c04fc591`, attempt 1) failed on the same shard and attempt 2 passed; its error text is not read yet.

Order: after TSK-1153 (PR 485), because it edits the same coverage job in `.github/workflows/codeflow-ci.yml` and builds on the four-shard matrix. The TSK-1153 record is not on the line while PR 485 is open, so `depends_on` cannot name it yet; the edge is added when it lands.

## Outcome

after this merges, a person's hosted coverage shards finish the instrumented build with a stated free-disk margin and the coverage totals unchanged.

## Deliverables

- the disk measure and the freeing or shrinking steps: `.github/workflows/codeflow-ci.yml` (coverage job)
- the recorded margin: the hosted run link and the `df` output in the PR
- release note: not needed if only this repository's CI changes (the builder confirms)

## Acceptance Criteria

- AC-1 A `df -h` before and after the build on each coverage shard, plus the size of `target/llvm-cov-target`, shall be recorded from a hosted run, showing the margin the heaviest shard has before the change; evidence: the run link and the output.
- AC-2 The coverage shards shall free disk before the build, by removing preinstalled runner toolchains the job does not use, or shrink the instrumented build (for example with no debug info for coverage), or both; each step shall be pinned and its effect measured; evidence: the workflow diff and the measured `df` figures.
- AC-3 On a hosted run of the line, every coverage shard shall finish with at least a stated free-disk margin recorded from the same `df` step, and the coverage totals shall be unchanged against the previous run; evidence: the run link and the two totals.
- AC-4 (journey) (added 2026-11-02, final review round 1, finding 1: the task had no journey criterion; this one drives its own change with the built binary) On a scratch pull request into the line, the coverage workflow shall complete on every shard with the recorded free-disk margin and the aggregate verdict job shall pass; evidence: the hosted run link and the verdict job result.
