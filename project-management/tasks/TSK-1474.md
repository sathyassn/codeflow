# TSK-1474: Managed-instruction follow-ups: Codex home on Windows, doctor advice and a refusal's link

## Description

Three small gaps left by TSK-1302, found in its review and tracked there until filed:

- On Windows, CodeFlow finds the Codex home by taking `HOME` before `USERPROFILE` (`crates/codeflow-core/src/scaffold/rule_map.rs` `codex_home`, `crates/codeflow-core/src/portable_path.rs` `user_home`). Under Git Bash `HOME` can name a different folder from the one Codex reads, so the override budget can read a different `.codex/config.toml` from Codex. The only effect is that a user-lowered `project_doc_max_bytes` can be missed.
- TSK-1302's override budget treats Codex's instruction limit as 32 KiB, lowered by a smaller `project_doc_max_bytes` and never raised by one. Doctor's `instructions` check still reads a raised value as the limit, and `docs/troubleshooting.md` advises raising it as a fix, so the two checks disagree.
- When `codeflow update` refuses an override whose code fence label is not an accepted language, the message names `docs/model-upgrades.md` (`crates/codeflow-core/src/scaffold/overrides/sections.rs:536` at PR 767's head), a path in the CodeFlow repository that an adopter's project does not have.

The three are one task by the Director's ruling of 2026-11-12 07:25: small review items in one area, carried by one pull request. If one grows when built, most likely the Windows lookup order, its builder says so and it is split then.

Source: TSK-1302's acceptance `follow_ups` at its PR head fc2a75fe0 (PR 767), items (1) and (2), and coord/catalog's round 5 Fable review of TSK-1302 (track once), also in PR 767's Risk list. Search by coord/catalog on 2026-11-12: main's task records for `USERPROFILE` and `project_doc_max_bytes` find only TSK-352 and TSK-267, both complete, neither covering these.

## Outcome

After this merges, an adopter on any OS gets one Codex instruction limit from CodeFlow's update and doctor alike, read from the folder Codex reads, and every override refusal points to documentation they can open.

## Deliverables

- one shared Codex home lookup and one shared limit rule: `crates/codeflow-core`
- the doctor advice in `docs/troubleshooting.md` and any other doc that advises raising `project_doc_max_bytes`
- the refusal messages and the shared fence language list

## Acceptance Criteria

- AC-1 On Windows, every CodeFlow reader of the Codex home (the override budget's `codex_home` and the doctor's, `crates/codeflow-core/src/doctor/mod.rs`) shall find it in the same order Codex does, through one shared lookup, with Codex's documentation or source for that order cited in the pull request; behaviour on macOS and Linux is unchanged. Evidence: a test that sets `HOME` and `USERPROFILE` to different folders and reads the limit from the one Codex reads, the readers listed with file:line in the pull request, and the landing candidate's hosted Windows run.
- AC-2 Doctor's `instructions` check shall use the override budget's limit rule (32 KiB, lowered and never raised by `project_doc_max_bytes`) from one shared definition, and `docs/troubleshooting.md` and every other doc that advises raising `project_doc_max_bytes` shall instead advise moving project detail out of `AGENTS.md`. Evidence: a fail-before test with a raised `project_doc_max_bytes` and a chain over 32 KiB, which warns after the change; the existing lowered-limit tests still passing; the doc diff and `codeflow validate --docs`.
- AC-3 Every override refusal that points to documentation shall name a place an adopter can reach (the published docs page or `codeflow help` text), never a CodeFlow repository path, and the accepted fence languages shall stay listed in one place the refusal, the docs and the code share. Evidence: a test over the refusal messages, a list with file:line in the pull request of each message checked, and the existing test that reads the language list from `docs/model-upgrades.md` (`sections.rs:1106`) still passing, or its replacement.
