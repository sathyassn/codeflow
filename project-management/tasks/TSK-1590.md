# TSK-1590: The identity reader holds the contributor's git, account and home values in memory only

## Description

Owner: to be assigned by the Director. Staged 2026-11-23 for coord/records.

SPC-018 R-19 (the sources common to Linux and macOS), R-22 and R-23. The
reader is the one place layer 3 learns the contributor's identity: git
`user.name` and `user.email` as git resolves them for the repository, the
login name, the full name from the password entry, the home directory's
user segment and `gethostname`. It returns values in a type that cannot
be formatted, serialised or logged, and it classifies each source as
read, absent or unreadable.

Security reading:

- Every git process goes through `codeflow_core::git`; the git spawn
  contract test enforces it (GATE-RULES.md, workspace, "Hosted failures").
- No credential helper, SSH configuration or secret store is read; the
  password entry is read through the C library, not by opening files.
- The value type implements no `Debug`, `Display` or `Serialize`; its
  only operation is a match against a byte slice.

Non-goals: platform host names (TSK-1591), Tailscale (TSK-1592),
matching rules (TSK-1593).

## Outcome

After this merges, the hooks can obtain the contributor's git, account,
full-name, home and host values for one run, held so that no code path can
print, store or pass them on, with each source reported as read, absent
or unreadable.

## Deliverables

- `crates/codeflow-core/src/privacy/identity/` (new): the reader and the opaque value type
- tests, including a compile-fail test that the type cannot be formatted
- docs: the sources table in `docs/policy-reference.md`; `changelog.d/TSK-1590.md`

## Acceptance Criteria

- AC-1 Before any change, the builder shall record in a `## Findings` section, with sources, how git resolves `user.name` and `user.email` (local, global, system, include files, environment), what `getpwuid` returns on Linux and macOS for the login and full name, and which of these the Claude, Codex and Grok sandboxes shipped by CodeFlow allow; evidence: the Findings section before the first code change.
- AC-2 With placeholder values set through a test seam (a git configuration and environment in a temporary home), the reader shall return each common source on Linux and macOS; evidence: unit tests on both platforms (macOS locally, Linux in the hosted run or a container).
- AC-3 The value type shall not compile under `format!`, `{:?}` or `serde_json::to_string`; evidence: compile-fail tests.
- AC-4 A source that errors or times out (200 ms, SPC-018 R-23) shall be unreadable and one the platform lacks shall be absent, and neither shall carry a value; evidence: tests with a failing and a missing stand-in.
- AC-5 The git reads shall go through `codeflow_core::git` with a cleared environment apart from the variables git needs; evidence: the git spawn contract test passing and a test of the child's environment.
