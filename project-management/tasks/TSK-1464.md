# TSK-1464: A file a verb cannot read is reported as unreadable, never as an uncommitted change

## Description

The task and epic completion verbs refuse a worktree with changes outside the record: "uncommitted changes outside the record were never reviewed (...); commit, remove or ignore them, then review the result again" (`crates/codeflow-core/src/workgraph/acceptance.rs:1391-1402` at `main` 63061d210). Under an agent sandbox that denies reading secret-named paths, a clean worktree is reported this way. In a clean worktree at 63061d210, `git status --short` prints `crates/codeflow-cli/tests/ci_cli/secret_scan_exemption.rs: Operation not permitted` and the same for two more test files, and the EPC-020 completion was refused naming those three paths as uncommitted changes. The message tells the user to commit, remove or ignore files that have no change, and a user who follows it may delete tracked tests.

TSK-1405 (EPC-022) renames those three files so the sandbox can read them. That removes today's trigger but leaves the verb's behaviour, which any unreadable path still triggers. TSK-105 (complete) added the check. TSK-1315 (complete) fixed the same kind of misreport for generated branch names.

Non-goal: no read access is widened and no deny is relaxed; the verb reports what it cannot read and still refuses.

## Outcome

After this merges, someone completing a task or epic in a worktree with a path the verb cannot read gets a refusal that names the path as unreadable, with the reason and how to clear it, and is never told to commit, remove or ignore a file that has no change. A worktree with real changes is still refused as today.

## Acceptance Criteria

- AC-1 When a path's status cannot be read, the completion verbs shall refuse with a message that names the path as unreadable, gives the operating system's reason and says how to clear it (read the path from a session that can, or run the verb outside the deny list), distinct from the uncommitted-change refusal; evidence: a test that denies read access to one tracked file in a clean fixture worktree, failing before and passing after.
- AC-2 A real staged, unstaged or untracked change outside the record shall still be refused with today's message, alone and alongside an unreadable path, and the mixed case shall name both; evidence: the existing TSK-105 tests stay green, plus one mixed case.
- AC-3 Every verb that runs this check, task and epic completion and any other caller of the same changed-path list, shall behave the same; evidence: the caller list with file:line, and one test per caller or a shared test of the list.
- AC-4 No path shall be treated as clean because it could not be read (fail closed); evidence: AC-1's test asserts a refusal, never a pass.
- AC-5 A changelog entry shall describe the change; evidence: `changelog.d/TSK-1464.md`.
