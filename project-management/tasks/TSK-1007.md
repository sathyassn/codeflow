# TSK-1007: codeflow ci checks the lines a code pull request's Testing section must hold

## Description

Issue #300, filed against CodeFlow 3.1.1 (`48104f48b`). The PR evidence
reference requires a code range's Testing section to hold the tested
revision, the command, a `Coverage:` line, a `New tests:` line and a
`Not tested:` line (`cf-ship/references/pr-evidence.md`). `codeflow ci`
checks only that the Testing heading exists and is not empty
(`crates/codeflow-cli/src/cmd/ci.rs`, `pr_code_sections`), and raises a
missing `Not tested:` line at warn whatever `git.pr_sections` says
(`crates/codeflow-cli/src/cmd/ci/pr_body.rs`). The issue proposes a
deliberate tightening, so it is a feature of this epic.

Outcome: **on a code range, `codeflow ci` checks that the Testing
section's visible text holds the `Coverage:`, `New tests:`, `Not tested:`
and tested-revision lines, at the `git.pr_sections` level, with a
project able to turn off a named line only through a recorded entry.**

Rules:

- The lines are read from the section's visible text with fenced blocks
  excluded, so a pasted log cannot supply one (the existing `visible_text`
  helper).
- `Coverage:` holds a percentage with metric and scope, or `N/A:` with a
  reason; `New tests:` may be `none:` with a reason; the revision line
  names a commit sha.
- The line list lives in policy (provisional `git.pr_testing_lines`); a
  line a project keeps off is an entry in TSK-424's register and is
  printed on every run.
- Existing projects see the findings reported first; `block` comes
  through a reviewed policy change, and new scaffolds and the PR template
  carry the lines.
- Gate-run id resolution is out of scope (hosted CI reruns the gate).

Non-goals: path-triggered evidence such as Whole-flow and `UI:` lines
(TSK-1009); re-judging merged pull requests.

## Deliverables

- the line check: `crates/codeflow-cli/src/cmd/ci/pr_body.rs` (`testing_lines` beside `presentation`) and its call in `crates/codeflow-cli/src/cmd/ci.rs`
- the policy key and its default list: `crates/codeflow-core/src/hooks/policy_schema.rs`, `crates/codeflow-core/src/hooks/policy.rs`
- the PR template placeholders: `crates/codeflow-core/src/scaffold/pr_template.rs`
- tests: `pr_body.rs` unit tests and `crates/codeflow-cli/tests/ci_cli/`
- docs: `cf-ship/references/pr-evidence.md` (mirrored skills and `assets/base/`), `docs/policy-reference.md`
- release note: `changelog.d/TSK-1007.md`

## Acceptance Criteria

- AC-1 On a code range, a Testing section whose visible text lacks a `Coverage:`, `New tests:` or `Not tested:` line, or a line naming the tested revision as a commit sha, shall get one finding per missing line at the `git.pr_sections` level; evidence: unit tests, one per line. (serves EPC-024 AC-14)
- AC-2 A line present only inside a fenced block shall not count, and `Coverage: N/A: <reason>` and `New tests: none: <reason>` shall count; evidence: unit tests.
- AC-3 A line named in a register entry shall not be required, and the entry shall be printed on every run; an entry with no reason or expiry shall be refused by the register; evidence: a `ci_cli` test.
- AC-4 With the policy key unset, an existing project shall see the findings reported with its verdict unchanged; at `block` they shall refuse; a docs-only or planning range shall not be checked; evidence: `ci_cli` tests at each level and per range class.
- AC-5 The scaffolded PR template shall carry the four lines as placeholders, which the remnant check flags when left unfilled; evidence: a template test.
- AC-6 (journey) With the installed build in a scratch adopter at `block`, `codeflow ci` on a code PR body missing `Coverage:` shall refuse naming the line and pass once the line is filled; evidence: the journey output. (serves EPC-024 AC-14)
