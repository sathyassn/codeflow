# TSK-079: model catalog with latest eligible resolution

## Description

Turn the managed ensemble into a catalog so a roster change is a data edit,
and seed it with the operator's 2026-09-23 roster. Shape, seed data, workload
table and resolution rules are the ones in EPC-018 "Model routing, as
config"; the routing audit (`routing-audit/routing-framework.md` sections 3.2
to 3.6) is the detailed input, with the design owner changed to seat
`claude-primary`.

`current-ensemble.json` moves to schema 5, keeping its name and five managed
copies so no pointer changes:

- families (`claude`, `codex`, `grok`) with provider, harness ids, probe ids
  and usage bucket; harness and probe ids must already exist in
  `harnesses.json` and the code allowlist, so the catalog cannot introduce an
  executable (ADR-0054 item 8);
- product lines with ordered versions; a version carries its selector per
  harness (Claude also its alias and full id), supported efforts, lifecycle
  and assurance, and for `operator-designated` a designation record;
- seats: one primary seat per family, mapped to its standing or catalog role,
  with ordered eligible lines; seat `claude-primary` is the design owner;
- workloads with the seats or lines that serve them, effort default and
  escalation, minimum assurance and constraints (lineage opposite the
  author, a required harness capability, Codex in engineering review);
- the existing high and xhigh triggers; `rules` keep duty text only, with no
  model name. The prose fallback rule becomes seat line order.

`model_qualification.rs` gains the catalog structs and validator (unknown
field, duplicate key, unsupported harness or probe, two standing families of
different lineage, a Claude design owner seat, one primary seat per family,
a seat line with no eligible version, an effort no version supports, an
assurance claim without its record) and one pure resolver
`resolve(workload, host harness, author lineage, exclusions)` that applies
EPC-018's resolution rules and returns the chosen version, selector, effort
and fallback chain, or none with the reason. The existing
`EnsembleBinding` view is derived from the primary seats so
`resolve_project_selection` and the doctor keep working.

Overrides, each failing the whole file on any violation:

- personal `~/.codeflow/model-catalog.local.json` (optional, outside any
  repository): add a version to an existing line as `candidate`, exclude a
  version on this machine, record a designation for this machine; never add
  a family, harness or probe, never claim `scoped-qualified` or `qualified`;
- project `.codeflow/model-selection.json` schema 2, read beside schema 1:
  the existing binding references (ADR-0041), plus reorder lines within a
  seat or workload, exclude a version, pin a line to a version, lower a
  workload's default effort within the version's efforts; never add a
  selector, raise assurance, change a lineage invariant or remove Codex from
  engineering review.

`harnesses.json` gains an optional computer-use evidence field per harness
so `computer-use-qa` can require it; no harness id is added.

Seed data: the EPC-018 roster table. Assurance of the roster versions follows
the operator's answer to Q2: yes records `operator-designated` with ADR-0069
as the designation; this task does not land until Q2 is answered, and no
answer is never read as yes. The Opus design pilot route is removed.

Keep the gate green: adapt every existing pin, fixture and requirement marker
the schema change breaks (the `model_class` markers in `requirements.json`,
the ensemble parsing in `orchestration_contract.rs`, the doctor and
qualification fixtures that stand for a current binding), without adding a
literal pin for a current model; name each adapted pin in the closeout.
Format-only fixtures such as `claude-fable-high` stay and are named.

ADR-0069, "model catalog with product lines, seats and workloads", records
the catalog model, the assurance ladder and what each level permits, the
adoption policy (Q1), the design owner seat, fallbacks as line order, the
same-lineage review label, the Claude selector choice (Q3), the Codex
transport (plugin when its login is current, otherwise the Codex CLI in
Herdr; it cites ADR-0059, which already superseded ADR-0055 item 4, and adds
only the stale-login detail) and the roster with its date. Dated Notes point
at it from ADR-0024, ADR-0028, ADR-0035, ADR-0039 (layer 4), ADR-0041,
ADR-0054 (item 2), ADR-0055 (item 2) and ADR-0060 (design owner paragraph).
ADR-0056 and ADR-0059 are not amended.

Why this is not over-built: every field maps to a row in EPC-018's "why it
earns its keep" table; the resolver launches nothing, discovers nothing and
schedules nothing.

Non-goal: the check output and derived tests (TSK-080), prose migration and
case re-scoping (TSK-081), a full native qualification suite, Agent OS.
