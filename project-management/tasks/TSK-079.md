# TSK-079: model catalog with latest eligible resolution

## Description

Build the catalog engine: the schema 5 types, the validator, the
eligibility predicate and the duty resolver described in EPC-018 "Model
routing, as config". This task changes no managed file: every test runs on
fictional catalogs (fictional families, lines, versions and ids), so it runs
beside the autonomy chain and does not wait on Q2. TSK-085 later switches
the managed catalog to the roster.

Schema 5, keeping the file name `current-ensemble.json`:

- families (`claude`, `codex`, `grok`) with provider, harness ids, probe ids
  and usage bucket; harness and probe ids must already exist in
  `harnesses.json` and the code allowlist (ADR-0054 item 8);
- product lines with ordered versions; a version carries alias, expected
  full id, selector per harness, supported efforts, lifecycle (`active`,
  `fallback-only`, `retired`), seat designations (seat, date, record) and
  scoped evidence entries (exact harness, selector, effort, duty, evidence
  paths);
- one primary seat per family, mapped to its standing or catalog role, with
  ordered eligible lines; the Claude seat is the design owner;
- duties with required participants, triggered participants (trigger ids
  from `routing-policy.json` or a named policy), each participant an ordered
  list of alternatives (seat or line) with a lineage relation to the author,
  and an effort floor and escalation obligation;
- the existing high and xhigh triggers; rules text names no model; an
  adoption policy per line (`manual` or `workers`) for Q1.

The validator rejects: an unknown field, a duplicate key, an unsupported
harness or probe, standing families that are not two distinct lineages, a
non-Claude design owner, more than one primary seat per family, a seat line
with no version that could be eligible for it, a duty default below its
floor, and a designation or evidence entry without its record.

The eligibility predicate and the resolver follow EPC-018 "Eligibility and
resolution" exactly. `resolve(duty, host harness, author lineage,
exclusions, observed ids, trigger facts)` returns every owed participant with
the chosen version, selector, effort and remaining alternatives, or names
the participant it cannot fill and why. It is a pure function: no launch, no
probe, no clock.

Overrides: the personal overlay `~/.codeflow/model-catalog.local.json` may
add a version to an existing line (always a candidate, no designation) or
exclude a version; anything else fails the whole overlay. The project file
`.codeflow/model-selection.json` stays at schema 1 (ADR-0041): a binding
reference still applies only to its exact role and harness, and is tested
against schema 5.

Until TSK-085 lands, the engine also accepts the schema 4 managed file so
the current tree stays green; TSK-085 removes that path.

Rename this module's own fixture ids that use a current model name (for
example `claude-fable-high` near `model_qualification.rs:1214`) to fictional
ids.

Write ADR-0069, "model catalog with product lines, seats and duties", as
`proposed`: the catalog model, eligibility (designation apart from scoped
evidence), duties as participant sets, effort floors (ADR-0056 unchanged),
the identity drift rule, the Q3 decision, the design owner seat, the
overlay limits, deferred project schema 2 with its "may" and "never" lists,
and one sentence naming `grok-4.7-build-fast` as known and not routed.
TSK-085 accepts it with the roster.

Non-goal: the command and doctor output (TSK-080), any managed file, prose,
Agent OS.

## Acceptance Criteria

- [ ] When a fictional schema 5 catalog is loaded, the validator shall accept a valid one and reject each invalid shape named above; evidence: unit tests with one failing fixture per rule.
- [ ] When `unit-review` is resolved, a Claude-authored unit shall owe the Codex seat, a Codex-authored unit the Claude seat, and a Grok-authored unit the Codex seat, else the Claude seat; the Grok seat shall be added only when its trigger fires and Grok is not the author; a missing required reviewer shall leave the duty open, never substituted by a same-lineage model; evidence: unit tests for all three authors and the missing-reviewer case.
- [ ] When `independent-plan` or `body-review` is resolved, both standing seats shall be returned; with one seat excluded the duty shall be open; evidence: unit tests.
- [ ] Eligibility negatives: a version with scoped test-authoring evidence offered a primary seat is ineligible; a scoped tuple reused at another effort or harness is ineligible; a design-implementation worker offered direction or fidelity approval is refused; a candidate added by the overlay never fills a seat; evidence: unit tests.
- [ ] Effort: a catalog with a seat duty default of medium is rejected; an xhigh trigger on a version without xhigh excludes that version rather than clamping; a medium default for `bounded-execution` is valid; evidence: unit tests.
- [ ] Drift: an observed id that differs from the expected id inherits no designation or evidence; a seat falls to the same version's pinned id, then its next alternative, and a candidate-eligible worker duty may use the drifted model only as a candidate; with no alternative the duty is open; evidence: unit tests including an alias-drift control where design work must not proceed.
- [ ] Latest eligible: a newer active version is chosen for a worker duty when adoption is `workers` and ignored under `manual`; a usage-bucket exclusion removes every line in it; `fallback-only` serves only as a listed seat fallback; evidence: unit tests.
- [ ] A schema 1 project binding reference resolves only for its exact role and harness under schema 5, and a reference for another harness or effort fails; evidence: tests.
- [ ] The targeted crate tests pass and no fixture in this module uses a current model name; evidence: test output and a search in the closeout.
