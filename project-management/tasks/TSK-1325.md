# TSK-1325: The group watcher closes descriptors in batches, not one call per descriptor

## Description

Source: the review of TSK-1278 at 2ba3ad4e6, nit 1 (`coordination/coordinators/parallel/reviews/tsk1278-head-2ba3ad4e6.md`), and coord/ci, 2026-11-04 12:3x. After the fork, the group watcher closes every descriptor up to the process limit one syscall at a time (`crates/codeflow-core/src/testing/runner/group_watch.rs:70-74` on PR 557's head 9e6c135de), up to about 1,048,576 calls. On a loaded host that loop outlasts the five-second cleanup grace, so a heavy target that exited 0 reported "process-tree termination unconfirmed". TSK-1278 answered with a configurable grace and a half-grace group kill, which leaves the root cause in place.

This task closes descriptors in batches: `close_range(2)` on Linux 5.9 and later, and on macOS one call that lists the open descriptors, then a close of each listed one. Before the multithreaded fork, the watcher sizes a buffer for one `proc_fdinfo` per descriptor up to the same limit the current loop walks, and binds the symbol of the call it makes after fork. After fork it makes the raw `proc_info` syscall with `PROC_PIDLISTFDS`, not libc's `proc_pidinfo` wrapper, so nothing allocates, takes a lock or resolves a symbol there. A return that fills the buffer, or a 0 or failed return, is a failure: the watcher never treats it as the full set and falls back to the existing per-descriptor loop. Windows has no such loop and is unaffected.

## Outcome

After this merges, a heavy target that exits 0 on a loaded host reports a clean cleanup, because the watcher no longer spends seconds closing descriptors that were never open.
