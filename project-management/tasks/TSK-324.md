# TSK-324: A fresh clone installs the pinned binary and wires the hooks

## Description

A fresh clone carries the hook shims and policy but not the binary, git
wires nothing on clone, and the shims' repair line points at the
`releases/latest` installer, which can install a version newer than the
project pins (https://github.com/sathyassn/codeflow/issues/170). This task
ships one managed setup step under decisions 13, 14, 16 and 17:

- Managed files `.codeflow/bootstrap.sh` and `.codeflow/bootstrap.ps1` at
  every tier, integrity paths through TSK-325.
- Inputs: only `scaffold_version` and `[scaffold_sha256]` from the
  committed `.codeflow/project.toml`, by a strict line pattern, checked by
  `is_version` and `is_digest` before any URL, path or shell word; the TOML
  is never sourced. Origin: the `https` GitHub releases host compiled in, no
  environment override, `file://` refused, redirects only to `https`.
- Verification: the archive must match the table's digest and the
  release's `sha256.sum`; a missing table, entry or match installs nothing,
  so a maintainer with a binary lands `codeflow update --pin <version>`
  first (decision 13).
- Install: download and extract privately with a lock; refuse traversing,
  absolute, link or unexpected entries; keep the verified binary in
  `~/.codeflow/versions/<version>-<archive digest>/codeflow` with its own
  SHA-256 recorded beside it; place it in the installer directory the
  `releases/latest` installer uses, named in the output, when no `codeflow`
  is there, when the one there is older, or when it has this pin's version
  with a different hash. A newer one stays (`ahead of pin`); the shared
  binary is never downgraded by any flag (decision 16).
- Under `CI`: the script exits early, before any download, install or
  wiring, printing "skipped: nothing installed or verified; the managed CI
  installer owns installation", exit 0. It runs neither `codeflow setup`
  nor a doctor check.
- Completion outside `CI`: exactly one of `verified` (the `codeflow` on the
  launching `PATH` hashes to the recorded digest; exit 0), `installed`
  (exit 0), `ahead of pin` (exit 0), or a refusal (non-zero). After
  `verified`, `installed` or `ahead of pin` only, it runs `codeflow setup`,
  `codeflow doctor --check hooks` and `codeflow doctor --check
  policy-source`; after a refusal it wires nothing.
- `codeflow setup`: sets `core.hooksPath` to the shim path only when
  unset, as `init` does; leaves a detected hook manager alone and prints its
  integration; records `git_hooks`; writes nothing else; arms, never
  disarms; no download, no `update`.
- In-session selection of the hook binary is a fixed refusal
  (`Violation::always_blocking`, decision 17): an assignment of
  `CODEFLOW_HOOK_BINARY` (leading, `export`, `env`, `declare`); a git
  command whose process would run with a `PATH` under which `codeflow`
  resolves to a different file than under the launching `PATH`, judged
  from a leading assignment, an earlier `export`, `declare -x` or
  assignment-only segment, a plain `declare`, `typeset` or `readonly` of an
  already-exported `PATH`, and a prefix on a wrapper (`sh -c`, `bash -c`,
  the other shells git-guard unwraps, `env`, `xargs`, `command`) whose body
  expands to git, taking reassignments in order and each wrapper's and
  sourced file's scope; the same words in a direct script operand of `sh`,
  `bash`, `zsh`, `dash`, `ksh`, `ash` or `pwsh` or a file read by `source`,
  `.` or pwsh dot-source, tokenized one level; an unreadable or non-UTF-8
  operand refuses. A `PATH` value the guard cannot resolve (an unresolved
  expansion) is never treated as an unchanged resolution: it refuses, or is
  recorded as a stated parser limit. An assignment that leaves the
  resolution unchanged is allowed; the binary's own export to its git
  children is untouched. The development route is the environment that
  launches the session.
- `ci` compares `.codeflow/bootstrap.sh`, `.codeflow/bootstrap.ps1` and
  `.codeflow/git-hooks/*` with the judging binary's embedded copies, or the
  target's bytes when unchanged; equal to neither blocks whatever the level
  (decision 14).
- Never: the script runs `update` or `init`; a hook or guard runs the
  script; a missing binary admits anything while the hooks are loaded.

The sample adopter repository of TSK-303 (EPC-023, 4.1.0) can serve this task's
fresh-clone journey.

## Acceptance Criteria

- AC-1 The script shall read only the two pinned inputs by the strict
  pattern, use only the compiled `https` origin, refuse `file://` and a
  non-`https` redirect, and install nothing on a missing table, entry or
  digest match; evidence: script tests with a local stub server.
  (serves EPC-022 AC-70)
- AC-2 Extraction shall refuse traversing, absolute, link and unexpected
  entries; the cache and the recorded binary digest shall be written as
  stated; the copy rule shall replace an absent, older or same-version
  different-hash binary and keep a newer one; no flag shall downgrade;
  evidence: script tests per case.
- AC-3 Under `CI`, the script shall exit 0 early with the skipped line,
  having downloaded, installed and wired nothing and run neither `setup`
  nor `doctor`; outside `CI` it shall end in exactly one of `verified`,
  `installed`, `ahead of pin` or a refusal with its exit code, name the
  installer directory, and run `setup` and the doctor checks only after a
  non-refusal; evidence: script tests per status, the `CI` test asserting
  an unchanged `core.hooksPath` and no files written.
- AC-4 `codeflow setup` shall set `core.hooksPath` only when unset, leave
  a detected manager alone and print its integration, record `git_hooks`
  and write nothing else; `doctor --check hooks` shall report `verified`,
  `compatible`, `behind pin`, `ahead of pin`, shadowing, an unwired manager
  and an unsupported platform; evidence: CLI tests.
- AC-5 git-guard shall refuse at the floor `CODEFLOW_HOOK_BINARY=/tmp/stub git commit`,
  `export CODEFLOW_HOOK_BINARY=/tmp/stub`, `PATH=/tmp/stub:$PATH git commit`,
  `export PATH=/tmp/stub:$PATH; git commit`, `PATH=/tmp/stub:$PATH; git commit`,
  `PATH=/tmp/stub:$PATH sh -c 'git commit'`, the same through one
  non-bash wrapper (`zsh -c` or `dash -c`), plain `declare`, `typeset` and
  `readonly` of the already-exported `PATH` followed by `git commit`, the
  same words in a direct script operand, a sourced file that exports the
  `PATH` followed by `git commit` in the sourcing shell, an unreadable
  operand and a non-UTF-8 operand; it shall take ordered reassignments
  (a stub `PATH` set and then restored before git is allowed; restored and
  then set again is refused), keep a wrapper's or sourced file's
  assignment to its own scope, and refuse or record as a parser limit an
  unresolved `PATH` expansion, never reading it as unchanged; and it shall
  allow a `PATH` assignment that leaves the `codeflow` resolution
  unchanged; evidence: guard tests, one per form. (serves EPC-022 AC-72)
- AC-6 `ci` shall block, whatever the level, a head whose bootstrap
  scripts or shims equal neither the judging binary's embedded copies nor
  the target's unchanged bytes; `bootstrap.ps1` shall install nothing
  until a digest for the exact published Windows asset is pinned;
  evidence: CLI tests and a script test.
- AC-7 The shims' repair line and the three harness wrappers shall print
  "codeflow is missing, older than the hooks, or failed; in your own
  terminal run `sh .codeflow/bootstrap.sh` from this checkout, then
  restart the session" on stderr, non-zero, with the trailing blocking
  line and no `$`, and the `releases/latest` pipe shall be gone;
  `docs/adoption.md` shall state what is automatic, lifecycle scripts,
  unloaded hooks, the counterfeit and execution-identity residuals with the
  hosted-CI statement, the ahead-of-pin limit and the maintainer pin step;
  evidence: tests of the messages and the doc text.
- AC-8 Journeys with the installed build: a fresh clone with no binary; an
  older binary replaced; a same-version different-hash binary replaced; a
  newer binary kept with `ahead of pin`; an existing hook manager; a bad
  digest; a traversing archive; an agent session refusing until setup ran;
  an agent setting the variable by command, by script and by a sourced
  file refused (journey); evidence: the journey output.
