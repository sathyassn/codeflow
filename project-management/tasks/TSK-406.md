# TSK-406: Shell expansions cannot hide a checkout from the guards

## Description

Sources: the security reviews of PR 246 (TSK-377) on 2026-10-18, findings SEC-377-14, SEC-377-15 and SEC-377-16, and Grok 4.7's rounds 4 and 5 of the same PR, finding R4-1 and the round 5 `git worktree move` case. TSK-377's Closeout names this task as their owner before it had an ID. All are pre-existing: the released 3.1.0 binary also allows R4-1 and SEC-377-16, judged with the commands never executed.

Reproduced on the line at `236e9d08b` with that tree's built hooks, from the main checkout, the commands judged and never run: exec-guard allows `python3 tool.py $PWD/.worktrees/w`, `W=.worktrees/w; python3 tool.py $W` and `python3 tool.py "$(printf %s .worktrees/w)"` while it refuses `python3 tool.py .worktrees/w`; git-guard allows `rm -rf $PWD/.worktrees/w` when the hook process's `PWD` is another directory, while it refuses `rm -rf .worktrees/w`; both guards allow `git worktree add -b t .worktrees/n && printf x > .worktrees/n/.claude/settings.json`.

The guards judge literal words for checkout reach, so a shell expansion that names the same path passes:

- **Interpreter arguments and code (SEC-377-14).** The interpreter checks in `crates/codeflow-core/src/security/outward.rs` and `security/interpreter.rs` do not resolve shell variables. `python3 tool.py $PWD/.claude/settings.json`, `${PWD}`, `$(pwd)`, `$HOME/<path to the checkout>`, a variable assigned earlier on the line (`D=.claude; python3 tool.py $D/settings.json`), and the same words inside double-quoted interpreter code or an unquoted heredoc pass, while the literal path refuses.
- **Static command substitution (Grok R4-1).** `node -e "$(printf %s '<code naming .claude/settings.json>')"` hides the code body from the checkout check. Any command substitution whose output is fixed by its literal text is the same class.
- **git-guard's `$PWD` (SEC-377-15).** `environment_value` (`crates/codeflow-core/src/hooks/git_guard.rs:4030-4047`) reads `PWD` from the hook's own process environment, not from the payload's working directory, so `$PWD` in a target word resolves against the wrong directory.
- **A worktree made earlier on the line (SEC-377-16, Grok round 5).** A path created by `git worktree add <path>` earlier in a command is not protected later in it: `git worktree add -b t .worktrees/n && printf x > .worktrees/n/.claude/settings.json` passes. So does `git worktree move .worktrees/w <outside> && rm -rf <outside>`.

Outcome: **a path the shell would expand to a checkout root or an enforcement file gets the verdict of the literal path, an expansion the guard cannot resolve is refused where a registered checkout or enforcement file is reachable, and a checkout created or moved earlier on a line is protected for the rest of it.**

Scope: assignments earlier on the line (plain and `export`), `$PWD`, `${PWD}`, `$(pwd)`, `` `pwd` ``, `$HOME` and `${HOME}`, and static command substitutions such as `$(printf %s '<literal>')`, in interpreter argv, in double-quoted interpreter code and in unquoted heredoc bodies, on both guards' routes. git-guard expands `$PWD` as the payload cwd. A path named by `git worktree add <path>` (with or without `-b`, `-B` or `--detach`), and both the source and the destination of `git worktree move <src> <dst>`, are treated as registered checkouts for the rest of the command.

Residual, kept by the operator's decision of 2026-10-15 (workspace `RELEASE-PLAN.md`, the TSK-302 scope decision): a path built by interpreter code at run time (adjacent literals, `+`, `chr()`, formatting, encoding) stays a stated residual; the OS sandbox and the permission preset are the backstop. Quoted heredocs (`<<'EOF'`) and single-quoted code are literal and keep their current verdict.

Non-goal: a full shell evaluator. A command substitution whose output depends on anything other than its literal text (a file read, another program's environment, a network call) is unresolved and is judged under the unresolved rule above.

Added by the second EPC-022 amendment of 2026-10-18, under the operator's release rule of that day that every security gap belongs in 3.2.0 (workspace `RELEASE-PLAN.md`, 2026-10-18 operator decision).

## Acceptance Criteria

- AC-1 When an interpreter argument names a checkout root or an enforcement path through `$PWD`, `${PWD}`, `$(pwd)`, `` `pwd` ``, `$HOME` or `${HOME}` (where the home directory encloses the checkout), a variable assigned or exported earlier on the line, or a static command substitution such as `$(printf %s '.claude/settings.json')`, exec-guard and git-guard shall refuse it as they refuse the literal path; evidence: one guard test per form, each failing before the change. (serves EPC-022 AC-96)
- AC-2 The same expansions inside double-quoted interpreter code (`python3 -c "open('$PWD/.claude/settings.json','w')"`) and inside an unquoted heredoc body, and the R4-1 form `node -e "$(printf %s '<code naming .claude/settings.json>')"`, shall be refused; a single-quoted body and a quoted heredoc (`<<'EOF'`) shall keep their current literal verdict; evidence: guard tests per form, the R4-1 test failing before the change. (serves EPC-022 AC-96)
- AC-3 When an expansion in an interpreter argument or code cannot be resolved (an unset or externally set variable, a command substitution whose output is not fixed by its text) and a registered checkout or enforcement path is reachable from the directory set, the guards shall refuse it as cannot-verify with a message that names the word; evidence: guard tests for an unresolved variable and a non-static substitution. (serves EPC-022 AC-96)
- AC-4 Resolved ordinary values shall keep passing: `D=src; python3 tool.py $D/app.py`, `python3 tool.py $PWD/src/app.py`, `python3 tool.py $HOME/notes.txt` with the home outside the checkout, and `node -e "$(printf %s 'console.log(1)')"`; evidence: guard tests.
- AC-5 git-guard shall expand `$PWD` and `${PWD}` as the payload's working directory: with the hook process's `PWD` set elsewhere, `rm -rf $PWD/.worktrees/w` and `rm -rf ${PWD}/.worktrees/w` from the main checkout shall refuse, `printf x > $PWD/.claude/settings.json` shall keep refusing, and `printf x > $PWD/src/a.txt` shall pass; evidence: `hooks_cli.rs` tests that run the built hook with a differing process `PWD`, the `rm -rf` refusals failing before the change. (serves EPC-022 AC-96)
- AC-6 A path named by `git worktree add` (plain, `-b`, `-B` or `--detach`) earlier in a command, and both the source and the destination of `git worktree move`, shall be protected as a registered checkout for the rest of that command: `git worktree add -b t .worktrees/n && printf x > .worktrees/n/.claude/settings.json` and `git worktree move .worktrees/w <outside> && rm -rf <outside>` shall refuse, while `git worktree add -b t .worktrees/n && git -C .worktrees/n status` shall pass; evidence: `hooks_cli.rs` tests per form, the refusals failing before the change. (serves EPC-022 AC-96)
- AC-7 `docs/policy-reference.md` shall list the expansions the guards resolve, the cannot-verify rule, the same-line worktree protection, and the runtime-built interpreter path residual with its sandbox backstop; `changelog.d/TSK-406.md` shall say that 3.1.0 also allowed R4-1 and SEC-377-16; evidence: the doc and note text.
- AC-8 (journey) With the installed build, an agent session in a scratch adopter project with a linked worktree shall be refused each planted case above (argv, code, heredoc, R4-1, git-guard `$PWD`, same-line `worktree add` and `worktree move`) and shall run the ordinary forms of AC-4 and AC-6; evidence: the journey output.
