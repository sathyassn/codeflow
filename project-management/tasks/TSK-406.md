# TSK-406: Shell expansions cannot hide a checkout from the guards

## Description

Sources: the security reviews of PR 246 (TSK-377) on 2026-10-18, findings SEC-377-14, SEC-377-15 and SEC-377-16, and Grok 4.7's rounds 4 and 5 of the same PR, finding R4-1 and the round 5 `git worktree move` case. TSK-377's Closeout names this task as their owner before it had an ID. All are pre-existing: the released 3.1.0 binary also allows R4-1 and SEC-377-16, judged with the commands never executed. The Codex review of PR 255 (round 1) added the `cd` case and corrected the fail-before cases below.

Reproduced on the line at `236e9d08b` with that tree's built hooks, payload cwd the main checkout and `<w>` a registered worktree under `.worktrees/`, the commands judged and never run. Each case names the guard that owns its route:

| Route and owning guard | Allowed today (fail-before case) | Refused today (literal or preservation case) |
|---|---|---|
| interpreter argument, exec-guard | `python3 tool.py $PWD/.worktrees/<w>`, `W=.worktrees/<w>; python3 tool.py $W`, `python3 tool.py "$(printf %s .worktrees/<w>)"` | `python3 tool.py .worktrees/<w>`; `python3 tool.py $PWD/.claude/settings.json` |
| interpreter code, exec-guard | `python3 -c "import shutil; shutil.rmtree('$PWD/.worktrees/<w>')"`; the same `shutil.rmtree("$PWD/.worktrees/<w>")` in an unquoted heredoc | `python3 -c "open('$PWD/.claude/settings.json','w')"`, the same `open` in an unquoted heredoc |
| static substitution, exec-guard (R4-1) | `node -e "$(printf %s 'require("fs").rmSync(".worktrees/<w>",{recursive:true,force:true})')"` | the same form naming `.worktrees/<w>/.claude/settings.json` |
| shell writer, git-guard (SEC-377-15) | `rm -rf $PWD/.worktrees/<w>` with the hook process's `PWD` elsewhere; `cd docs && rm -rf $PWD/../.worktrees/<w>` | `rm -rf .worktrees/<w>`; `cd docs && rm -rf ../.worktrees/<w>` |
| same-line worktree, git-guard (SEC-377-16) | `git worktree add -b t .worktrees/n && printf x > .worktrees/n/.claude/settings.json` | none |

The refused enforcement-file forms already refuse because exec-guard judges opaque and composed text against enforcement-path tails (`crates/codeflow-core/src/security/arguments.rs:130-157`); they stay as preservation tests. The checkout-root forms have no such fallback, which is the defect. git-guard has no interpreter route: exec-guard owns every interpreter refusal, and this task does not add one to git-guard.

The defects:

- **Interpreter arguments and code (SEC-377-14).** The interpreter checks in `crates/codeflow-core/src/security/outward.rs` and `security/interpreter.rs` do not resolve shell variables for checkout reach: `$PWD`, `${PWD}`, `$(pwd)`, `$HOME`, an assignment earlier on the line, and the same words inside double-quoted interpreter code or an unquoted heredoc.
- **Static command substitution (Grok R4-1).** A command substitution whose output is fixed by its literal text, such as `$(printf %s '<code>')`, hides the code body from the checkout check.
- **git-guard's `$PWD` (SEC-377-15).** `environment_value` (`crates/codeflow-core/src/hooks/git_guard.rs:4030-4047`) reads `PWD` from the hook's own process environment. Replacing it with the payload cwd alone is not enough: after `cd docs`, the shell's `$PWD` is `<checkout>/docs`, so `cd docs && rm -rf $PWD/../.worktrees/<w>` reaches the worktree while the literal `cd docs && rm -rf ../.worktrees/<w>` already refuses.
- **A worktree made earlier on the line (SEC-377-16, Grok round 5).** A path created by `git worktree add <path>` earlier in a command is not protected later in it, and `git worktree move .worktrees/<w> <outside> && rm -rf <outside>` also passes. Today `git worktree add -b t .worktrees/n && git -C .worktrees/n status` is refused by git-guard under `git.policy_authority`, because the new path does not exist when the line is judged; after this task it passes.

Outcome: **a path the shell would expand to a checkout root or an enforcement file gets the verdict of the literal path, an expansion the guard cannot resolve is refused where a registered checkout or enforcement file is reachable, and a checkout created or moved earlier on a line is protected for the rest of it.**

Two pieces of shell state are tracked at every command position and kept apart. The working directory starts at the payload cwd and changes only through `cd`, `pushd` and `popd`; every relative filesystem operand (a writer target, an interpreter argument, a link name or target) resolves from it. The `PWD` parameter starts equal to it and follows each successful `cd`, but it can also be assigned (`PWD=/private/tmp`), which changes what `$PWD` expands to and not where commands act. `$PWD` expands from the parameter; a relative path never resolves from an assigned `PWD`. Scope follows the shell: a brace group `{ ...; }` runs in the current shell, so its `cd` and assignments reach the commands after it; a subshell `( ... )`, a command substitution and a background job (`&`) keep their changes to themselves; a pipeline element runs in a subshell, except the last element where the shell runs it in the current shell (zsh, or Bash with `lastpipe`), and when the shell or that option is unknown the guard keeps both states. `&&`, `||`, `;` and newlines carry the state to the next command. Where the guard cannot know which state holds (a `cd` that may fail on an `||` branch, a `cd` to an unresolved word, `CDPATH`), it keeps every reachable state and judges the command against each. `$HOME` comes from the payload environment the guards already read. The directory set TSK-397 narrows after `cd` is the same working-directory state; whichever task lands second reuses the other's model.

Scope: assignments earlier on the line (plain and `export`), `$PWD`, `${PWD}`, `$(pwd)`, `` `pwd` ``, `$HOME` and `${HOME}`, and static command substitutions such as `$(printf %s '<literal>')`, in interpreter argv, in double-quoted interpreter code and in unquoted heredoc bodies (exec-guard), and in shell writer targets (git-guard). A path named by `git worktree add <path>` (with or without `-b`, `-B` or `--detach`), and both the source and the destination of `git worktree move <src> <dst>`, are treated as registered checkouts for the rest of the command.

Interface with TSK-407: this task provides the expansion resolver (assignments, static substitutions, `PWD` and `HOME` as command-position state). TSK-407 depends on this task and reuses that resolver for link names and link targets; neither task carries a second resolver.

Residual, kept by the operator's decision of 2026-10-15 (workspace `RELEASE-PLAN.md`, the TSK-302 scope decision): a path built by interpreter code at run time (adjacent literals, `+`, `chr()`, formatting, encoding) stays a stated residual; the OS sandbox and the permission preset are the backstop. Quoted heredocs (`<<'EOF'`) and single-quoted code are literal and keep their current verdict.

Non-goal: a full shell evaluator. A command substitution whose output depends on anything other than its literal text (a file read, another program's environment, a network call) is unresolved and is judged under the unresolved rule above.

Added by the second EPC-022 amendment of 2026-10-18, under the operator's release rule of that day that every security gap belongs in 3.2.0 (workspace `RELEASE-PLAN.md`, 2026-10-18 operator decision).

## Acceptance Criteria

- AC-1 When an interpreter argument names a checkout root through `$PWD`, `${PWD}`, `$(pwd)`, `` `pwd` ``, `$HOME` or `${HOME}` (where the home directory encloses the checkout), a variable assigned or exported earlier on the line, or a static command substitution, exec-guard shall refuse it as it refuses the literal `python3 tool.py .worktrees/<w>`; evidence: one exec-guard test per form, the allowed forms of the table above failing before the change. (serves EPC-022 AC-96)
- AC-2 exec-guard shall refuse `python3 -c "import shutil; shutil.rmtree('$PWD/.worktrees/<w>')"`, the same call in an unquoted heredoc, and the R4-1 form `node -e "$(printf %s 'require("fs").rmSync(".worktrees/<w>",{recursive:true,force:true})')"`; the already-refused enforcement-file forms of the table shall keep refusing; a single-quoted body and a quoted heredoc (`<<'EOF'`) shall keep their current literal verdict; evidence: exec-guard tests per form, the three checkout-root forms failing before the change. (serves EPC-022 AC-96)
- AC-3 When an expansion in an interpreter argument or code cannot be resolved (an unset or externally set variable, a command substitution whose output is not fixed by its text) and a registered checkout or enforcement path is reachable from the directory set, exec-guard shall refuse it as cannot-verify with a message that names the word; evidence: tests for an unresolved variable and a non-static substitution. (serves EPC-022 AC-96)
- AC-4 Resolved ordinary values shall keep passing: `D=src; python3 tool.py $D/app.py`, `python3 tool.py $PWD/src/app.py`, `python3 tool.py $HOME/notes.txt` with the home outside the checkout, and `node -e "$(printf %s 'console.log(1)')"`; evidence: guard tests.
- AC-5 git-guard shall expand `$PWD` and `${PWD}` from the `PWD` parameter at the consuming command and resolve relative operands from the working directory: with the hook process's `PWD` set elsewhere, `rm -rf $PWD/.worktrees/<w>` and `rm -rf ${PWD}/.worktrees/<w>` from the main checkout shall refuse; `cd docs && rm -rf $PWD/../.worktrees/<w>` shall refuse like its literal pair `cd docs && rm -rf ../.worktrees/<w>`; `{ cd docs; } && rm -rf $PWD/../.worktrees/<w>` (a brace group changes the caller's state) shall refuse, while its literal pair `{ cd docs; } && rm -rf ../.worktrees/<w>` keeps refusing; `(cd docs) && rm -rf $PWD/.worktrees/<w>` and `cd docs || true; rm -rf $PWD/../.worktrees/<w>` shall refuse; `PWD=/private/tmp; rm -rf .worktrees/<w>` keeps refusing, because the assignment does not move the working directory; `printf x > $PWD/.claude/settings.json` shall keep refusing; and `printf x > $PWD/src/a.txt`, `cd docs && printf x > $PWD/notes.txt`, `{ cd docs; } && printf x > $PWD/notes.txt` and `(cd docs && printf x > $PWD/notes.txt)` shall pass; evidence: `hooks_cli.rs` tests that run the built hook with a differing process `PWD`, the `rm -rf` refusals that pass today failing before the change. (serves EPC-022 AC-96)
- AC-6 A path named by `git worktree add` (plain, `-b`, `-B` or `--detach`) earlier in a command, and both the source and the destination of `git worktree move`, shall be protected as a registered checkout for the rest of that command: `git worktree add -b t .worktrees/n && printf x > .worktrees/n/.claude/settings.json` and `git worktree move .worktrees/<w> <outside> && rm -rf <outside>` shall be refused by git-guard; `git worktree add -b t .worktrees/n && git -C .worktrees/n status`, refused today under `git.policy_authority`, shall pass; evidence: `hooks_cli.rs` tests per form, the refusals and the add-then-status pass each failing before the change. (serves EPC-022 AC-96)
- AC-7 `docs/policy-reference.md` shall list the expansions the guards resolve, `PWD` as command-position state, the cannot-verify rule, the same-line worktree protection, which guard owns each route, and the runtime-built interpreter path residual with its sandbox backstop; `changelog.d/TSK-406.md` shall say that 3.1.0 also allowed R4-1 and SEC-377-16; evidence: the doc and note text.
- AC-8 (journey) With the installed build, an agent session in a scratch adopter project with a linked worktree shall be refused each planted case above (argv, code, heredoc, R4-1, `$PWD` after `cd`, process-`PWD` mismatch, same-line `worktree add` and `worktree move`) and shall run the ordinary forms of AC-4, AC-5 and AC-6; evidence: the journey output.
