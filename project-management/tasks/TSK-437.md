# TSK-437: Each seat reaches only its own lane's sockets and never the container runtime

## Description

Issue #286, item 1. Parallel lanes each run local helper services (a
browser automation server, a dev database, a preview server), and
anything that can connect to a lane's service can act through it; a
browser server can read files the browser reaches and take raw
DevTools commands. Every seat, hook and tool runs as one OS user who
also owns the container runtime socket, so a project cannot keep one
lane away from another's service by changing the service alone. The
shipped postures set `dangerously_allow_all_unix_sockets = false` for
`cf-guard` and `cf-builder` (`assets/base/codex/config.toml:205`,
`:242`) with no per-seat allowance, and the Claude presets carry no
`allowUnixSockets` list; the container runtime socket is not denied by
name on any plane. Two research passes agreed the criterion "no other
process under the same host user may connect" cannot be met on a
single-user host; this task delivers what the seat postures can.

Outcome: **a seat's sandbox can be given access to its own lane's unix
sockets only, through a documented and tested per-seat launch override
(Codex `unix_sockets` rules, Claude `allowUnixSockets`), and every
seat denies the container runtime socket by default, with unsandboxed
retries off for a seat that holds a socket allowance.**

Criteria to establish first, recorded in the task's pull request (the
issue's "not verified" items): whether a per-lane Codex `unix_sockets`
rule works as a launch override on the supported release, and Claude's
`allowUnixSockets` default and merge behaviour on macOS. Each AC
below states what the answer changes.

Non-goals: the optional supervisor and the separate-account guidance
(TSK-438 in EPC-024); the services themselves, which stay the
project's (unix socket, peer credentials, per-run secret).

Added by the EPC-022 amendment of 2026-10-22 under the operator's
rule of 2026-10-18 (a security gap in the seat postures CodeFlow owns).

## Deliverables

- the per-seat allowance: `assets/base/codex/config.toml` (a `unix_sockets` list per profile with a launch override), the Claude presets under `assets/base/settings/` (`allowUnixSockets`) and the Herdr launch in `cf-herdr` and `cf-model-orchestrator/resources/routing/transport.md` in `assets/base/`, `.claude/skills` and `.agents/skills`
- the runtime-socket deny: the same postures (Docker, Podman, containerd, colima and lima socket paths on macOS and Linux) and the `doctor --check permissions` report in `crates/codeflow-cli/src/cmd/doctor.rs`
- the research answers: `docs/research/` note with the native probes
- tests: scaffold tests over the rendered postures and native permission canaries under `evals/qualification/`
- docs: `docs/policy-reference.md` (the lane socket rule) and `.codeflow/rules/worktrees.md` (one lane, one socket directory)
- release note: `changelog.d/TSK-437.md`
- managed wiring, mirrors and baseline: `assets/base/scaffold-manifest.toml`, installed managed files and `.codeflow/` baseline, synchronized when changed

## Acceptance Criteria

- AC-1 Whether a per-lane Codex `unix_sockets` rule works as a launch override, and what Claude's `allowUnixSockets` default and merge behaviour are on macOS, shall be established by native probes on the supported releases and recorded with the exact commands and results; evidence: the research note. (serves EPC-022 AC-119)
- AC-2 A seat launched with a lane's socket allowance shall connect to that lane's socket and be refused another lane's socket and the container runtime socket, on the Codex and Claude planes, by the route AC-1 establishes (a launch override, or a per-lane rendered profile where no override exists); evidence: native canaries with two sockets and a fake runtime socket. (serves EPC-022 AC-119)
- AC-3 Every shipped seat posture shall deny the container runtime socket by default, and a seat holding a socket allowance shall have the unsandboxed retry off; evidence: scaffold tests over the rendered postures and the canary. (serves EPC-022 AC-119)
- AC-4 `codeflow doctor --check permissions` shall report each seat posture's socket allowance and the runtime-socket deny; evidence: the doctor output.
- AC-5 The docs shall state the rule, what it does and does not cover (same-account processes outside every seat sandbox), and point at TSK-438 for the rest; evidence: the doc text.
- AC-6 (journey) With the installed build, two Herdr lanes in a scratch adopter project shall each reach only their own browser-server socket, and neither shall reach the runtime socket; evidence: the journey output.
