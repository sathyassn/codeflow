# TSK-440: The ledger hooks run on every harness through one implementation

## Description

ADR-0086, the enforcement part. The operator decided on 2026-10-22
that surfacing the ledger must not depend on a session timer, which is
session-scoped and vendor-specific: one implementation in the binary
(`codeflow hook session-orient`, a Stop-time check, and any `codeflow`
command) with per-harness adapters. Claude wires `.claude/settings.json`
(SessionStart already runs `session-orient`), Grok wires
`.grok/hooks/codeflow.json`, and Codex has no session hook wired today,
so this task establishes what Codex supports and wires it or states
the gap.

Outcome: **at every session start on every harness, `session-orient`
claims or reports the session's role and prints the items owed, overdue,
orphaned and waiting on the operator plus lanes with stale seats; at
every turn end, `codeflow hook follow-check` reports items past their
next check, items with no next check and a turn that answered an
operator ask without an item, advisory by default and blocking under a
policy key; any `codeflow` command can print the overdue count; status
and `orient` are built from `follow list`;
the same binary code serves all three harnesses through their
adapters; and the Codex route is established and wired, or its gap is
stated with the sanctioned substitute.**

Rules:

- The three surfaces are one module (`crates/codeflow-core/src/follow/surface.rs`,
  provisional) that the SessionStart and Stop hooks and the CLI's
  shared output call; a harness adapter only wires the hook. The start
  surface reads the logs in the order `roles.jsonl`, `items.jsonl`,
  `lanes.jsonl`, then `status/`. A missing or damaged ledger only
  warns; no surface blocks.
- Claude: SessionStart (existing) and Stop in the managed settings
  presets. Grok: the same events in `.grok/hooks/codeflow.json`. Codex:
  the task probes the supported release for a session-start and
  turn-end hook (`hooks.json`, the app-server notifications, or the
  `notify` setting); where one exists it is wired in the managed
  `.codex/` files; where none exists, the gap is stated in the docs and
  the orchestrator's launch prompt runs `codeflow orient` as the
  substitute.
- A session claims its role (`coordinator` or a lane id, TSK-439) at start so
  the surfaces know whose items to show; every hook firing and every
  `codeflow` command refreshes the caller's heartbeat; the coordinator surfaces
  due items every `check interval` through these surfaces, and an
  orchestrator timer is an optional aid, never the mechanism. The start
  hook reports a stale coordinator or seat and never adopts it.
- The turn-end check warns by default; blocking is a project opt-in
  through a policy key (provisional `work.follow_check`, levels warn
  and block, placed by TSK-280's rule); its strength in this
  repository is open for the operator.
- These are layers 2, 4 and 5 of ADR-0086's five enforcement layers;
  layer 1 is TSK-423's rule and skill, layer 3 the bookkeeping commands
  of TSK-422 and TSK-439.

Non-goals: the store and items (TSK-422), lanes (TSK-439), the rules
(TSK-423).

## Deliverables

- the adapters: the Claude presets under `assets/base/settings/` (Stop), `assets/base/grok/hooks/codeflow.json`, and the Codex wiring in `assets/base/codex/` or the documented gap

- docs: `docs/policy-reference.md` (the hooks) and the per-harness notes (`CLAUDE.md`, the Codex and Grok notes in `assets/base/`)
- release note: `changelog.d/TSK-440.md`
- managed wiring, mirrors and baseline: `assets/base/scaffold-manifest.toml`, installed managed files and `.codeflow/` baseline, synchronized when changed

## Acceptance Criteria

- AC-1 `codeflow hook session-orient` shall claim or report the session's role, refresh its heartbeat, print the items owed, overdue, orphaned and waiting on the operator for that role and the lanes and coordinator with stale heartbeats (reporting, never adopting), from any worktree, and print nothing when no ledger exists; evidence: hook tests from two worktrees with a stale lease. (serves EPC-025 AC-3)
- AC-2 `codeflow hook follow-check` at turn end shall report items past their next check, items with no next check and a turn that answered an operator ask without an item, advisory by default and blocking when the policy key says so, any `codeflow` command shall be able to print the overdue count, and `orient` and the status digest shall be built from `follow list`; evidence: hook and CLI tests with a fixture transcript at both levels. (serves EPC-025 AC-3)
- AC-3 The Claude and Grok adapters shall wire both hooks in the managed files and the rendered files shall run the same binary code; evidence: scaffold tests and one native canary per harness. (serves EPC-025 AC-3)
- AC-4 The Codex route shall be established on the supported release and recorded with the probe commands and results; where a hook exists it shall be wired and proven by a native canary, and where none exists the gap and the substitute shall be stated in the docs and the launch prompt; evidence: the research note and the canary or the doc text. (serves EPC-025 AC-3)
- AC-5 No surface shall depend on a session timer, and the docs shall say an orchestrator timer is an optional aid; evidence: the code search and the doc text.
- AC-6 (journey) With the installed build, a Claude session, a Grok seat and a Codex seat in a scratch adopter project shall each see the same overdue row at start, and the Claude session's stop shall flag an unlogged operator ask; evidence: the journey output per harness.
