# TSK-084: operating doctrine merged in from main

## Description

Bring the operating doctrine body (EPC-017) onto
`integration/EPC-016-visual-guide` from `main`, after the EPC-017 pull
request has landed there, and reconcile the one paragraph the two epics
edit differently. This was step M in Plan v4; it is a task so that
`codeflow work start TSK-073` can see it: work start checks that every
dependency is complete at the merge base, and a prose step is invisible to
it.

The only source is `origin/main` at a commit that contains the EPC-017
landing. `main` lands pull requests with merge commits, so the EPC-017
commits arrive as the same objects that `main` holds, and the EPC-016 pull
request diff then shows only this epic. Merging the EPC-017 integration
branch before it lands is not allowed here; if EPC-017 has not landed when
the rest of the epic is ready, TSK-073 waits.

On a task branch cut from the integration head, merge `origin/main` with a
no fast forward merge and resolve the conflicts:

- The `Shape deliverables` paragraph of
  `cf-method/references/workflow-lifecycle.md`: this branch names the nine
  families in chat (TSK-058); EPC-017 adds the reply rule, the short-answer
  rule and the link rule and drops the family sentence. The merged text
  carries the family sentence, the reply rule with its short-answer
  exception, and the link rule.
- Shared test files and hashes (`manifest_consistency.rs`,
  `artifact_budget_contract.rs`, the manifest hashes, `CHANGELOG.md`,
  `docs/capabilities.md`, the `cf-docs-portal/references/operations.md`
  lines EPC-017 touched): keep both sides' pins, entries and lines, then
  regenerate mirrors and hashes.
- The evaluation kit resources, if TSK-062 has landed first: keep both
  sides' requirements, cases, fixtures and packs.

Task branches in flight when this lands rebase onto it. Non-goal: any new
wording beyond the reconciliation; the pointer to the method and the copy
guide is TSK-073's.
