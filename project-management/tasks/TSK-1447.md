# TSK-1447: Tests give the same results when cargo runs from outside the repository

## Description

The repository's `.cargo/config.toml` `[env]` table blanks the agent-session markers and turns off automatic Git maintenance for every test process. Cargo reads that file from the directory it runs in, so a run started from outside the repository with `--manifest-path` skips the whole table, while cargo still sets `CARGO_MANIFEST_DIR`.

`root_checkout::tests::the_test_environment_blanks_every_harness_marker` (`crates/codeflow-core/src/root_checkout_tests.rs:230`) takes `CARGO_MANIFEST_DIR` as proof that the table was applied. From outside the repository in an agent session, it fails on the inherited marker. From inside the worktree, it passes.

The fixture helpers clear the markers themselves (TSK-1397), so the marker assertion is the visible failure. Other values in the same table, such as the Git maintenance settings that TSK-245 relies on, are also missing in such a run.

Search (coord/records, 2026-11-11 16:2x, task records on `main` and the EPC-022, 024, 025 and 026 lines, for the harness markers, `.cargo/config.toml`, `--manifest-path` and the test name): TSK-201, TSK-245, TSK-1084, TSK-1369 and TSK-1397 shaped the test environment and are complete; no open record owns it.

Source: coord/ci, 2026-11-11 16:2x, a defect the PR 706 round 10 Worker reproduced; the Director asked for one tracked home.

## Outcome

After this merges, a test run started from outside the repository either gives the same results as one started inside it, or stops at once with a message that names the cause and the command that fixes it. No test passes or fails because of where cargo was started.
