# TSK-1365: The present browser check waits for stage measuring and rewrites the revision atomically

## Description

The present real-browser check races the page it tests, and that race failed checkpoint 607's "codeflow gates (release present)" job (run 42146553626, job 127663216279). `crates/codeflow-present/web/scripts/real-browser-check.mjs` loads the revised page (about :329-330), which starts POSTs to `/app/api/stages/measure` (`web/src/stage-measuring.ts:14-67`). Without waiting for `data-cf-stages-measured`, the check then rewrites the stored revision file with a plain `writeFile` (about :364). The rewrite happens outside the store lock that the measure endpoint takes, and there are two ways it fails. A POST that reads the file mid-write sees a torn file in `read_revision_record` (`crates/codeflow-present/src/state.rs:4106`, reached from `record_stage_measurement` at :1175), and the service answers 500 (`src/service.rs:751`). A POST that reads the complete retired revision answers 400 ("this revision cannot be measured"). `web/scripts/csp-violations.mjs:15-20` keeps either error across the reload, so the retired-page check (about :367) fails. An atomic write closes only the first, so the wait for stage measuring is the fix and the atomic write hardens it. The race came in with TSK-1101 (548d79925, 2fe20ada5). The fix is in the test harness only: the check waits for stage measuring to finish, asserts that no measure request is pending or failed at the rewrite, and writes the revision atomically, and every present browser check is swept for the same pattern. Non-goal: changing the server's handling of a torn read, which is product behaviour and needs its own task if wanted. Diagnosis by coord/ci, filed at the Director's priority on 2026-11-06 because it is on checkpoint 607's path.

## Outcome

After this merges, the present release job no longer fails at random on the retired-page check, so a checkpoint's hosted run gives a true verdict for the present app.

## Deliverables

- the wait, the pending-request assertion and the atomic rewrite: `crates/codeflow-present/web/scripts/real-browser-check.mjs`
- an atomic write helper with a small unit test, if it is extracted: `crates/codeflow-present/web/scripts/`
- the sweep result over every `*browser-check*.mjs` and `transport-check.mjs`, and the same fix in any check it finds
