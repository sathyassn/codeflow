# TSK-1108: Seat trust prompts follow a recorded delegation, else the operator

## Description

On 2026-10-30 at 20:00 the operator gave a standing rule directly in the
coordinator's session (queue item 28): in this repository, agents answer
Herdr seat hook-trust and folder-trust prompts themselves after reading each
prompt in full, and approve once only CodeFlow's own hooks that match
`origin/main`, never trust-all unread and never always-approve. That rule is
this repository's delegation, and its home is one line in the project
section of this repository's `AGENTS.md` (the AGENTS.md row "receive a
standing operator rule"; `cf-method/references/autonomy.md` "Recorded rules
and delegations"; no config key holds seat prompts).

It is not a default for adopters. The shipped texts say hook trust is the
operator's: `cf-herdr/SKILL.md:128` and `:181`, `transport.md` "First-run
prompts" (ADR-0075, amendment of 2026-10-03), and `autonomy.md` "Trust
prompts" (near `:133`) and its hook example (near `:230`), which say an
agent never answers a hook-trust prompt. An adopter whose operator gave no
delegation keeps that route. This task makes the shipped rule conditional:
a hook-trust prompt goes to the operator unless the consuming project's own
`AGENTS.md` project section records a delegation that meets "Recorded rules
and delegations" (the authenticated operator's approval, landed by a human
merge on the protected target branch, naming the actions, the trusted ref
and the revocation event). Under such a delegation the agent approves once,
after reading the whole prompt, only when every hook file the prompt names
is byte-identical to the trusted ref's copy, and refuses and reports
everything else. The folder-trust text matches the workspace rule of
2026-09-22 already in `autonomy.md` "Trust prompts".

This changes an authority boundary in shipped instructions although no hook
byte changes, so the one whole-unit review carries the security checklist.
Non-goals: no change to the hooks, the guards or what a seat may run; the
qualification runner's hook-review decision in TSK-1032 (PR 447) is not
settled by this text.

## Outcome

After this merges, an agent running a Herdr seat in any project knows from the shipped instructions that a hook-trust prompt goes to the operator unless that project records a delegation, what a recorded delegation lets it approve and how it checks the hooks, and what it must refuse; in this repository the recorded delegation lets it answer the prompt itself.

## Deliverables

- this repository's delegation: `AGENTS.md`, project section (outside the managed block), one line
- the shipped texts: `assets/base/agents/skills/cf-herdr/SKILL.md` (`:124`, `:128`, `:181`), `assets/base/agents/skills/cf-model-orchestrator/resources/routing/transport.md` ("First-run prompts"), `assets/base/agents/skills/cf-method/references/autonomy.md` ("Trust prompts" near `:133`, the hook example near `:230`), with the `.claude/skills` and `.agents/skills` mirrors byte-identical per `assets/base/scaffold-manifest.toml` and the managed baseline resynced
- the comparison procedure, in `transport.md` "First-run prompts": fetch the trusted ref (the default branch at the fetched remote, TSK-1077's authority), compare each installed hook file the prompt names with `git show <trusted ref>:<path>` by digest, and treat an absent or differing file as a refusal; the approval report to the primary (prompt text, files, digests, trusted ref SHA)
- the qualification case: `evals/qualification/` (a prompt read in full and answered under a recorded delegation; the same prompt with no delegation handed to the operator; a hook set differing from the trusted ref refused; a prompt that bundles hooks with another permission refused)
