# TSK-1108: Agents answer seat trust prompts themselves and the skills say so

## Description

On 2026-10-30 at 20:00 the operator gave a standing rule directly in the
coordinator's session (queue item 28): agents answer Herdr seat hook-trust
and folder-trust prompts themselves after reading each prompt in full, and
approve once only CodeFlow's own hooks that match `origin/main`, never
trust-all unread and never always-approve. `cf-herdr/SKILL.md:128` and
`transport.md` "First-run prompts" still say hook trust is the operator's,
and the workspace contract already records the folder-trust part (workspace
`AGENTS.md`, authorized 2026-09-22). The AGENTS.md row "receive a standing
operator rule" names the rule's home: an existing config key where one fits,
else one project-owned AGENTS.md line. No config key holds seat prompts, so
the home is one line in the project section of this repository's AGENTS.md,
and the two instruction texts change to match. The rule relaxes nothing: an
unread prompt, a trust-all and an always-approve stay refused, and a prompt
for hooks that do not match `origin/main` is refused and reported.
Non-goal: no change to the hooks, the guards or what a seat may run.

## Outcome

After this merges, an agent running a Herdr seat knows from the repository's own instructions that it answers the seat's trust prompts itself, under which conditions, and what it must refuse.
