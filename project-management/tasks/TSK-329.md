# TSK-329: The model evaluation gate target waits for the release binary

## Description

The `model-eval-kit` gate target can start before the release binary exists,
and its result then depends on scheduling. In the full gate on candidate
dd1188c5e (batch 2, gate run 7ba19750-cf8d-4043-a25e-a89ff2299411 under
`/Users/sathya/.codeflow/gate-runs/7a134ea9c2ea8c39/`), `model-eval-kit`
failed with a `FileNotFoundError` for `target/release/codeflow` in
`test_closeout_inventory_matches_real_local_worktrees`
(`evals/model-artifacts/test_eval_kit.py:8513`, calling
`eval_kit.configure_closeout_inventory`, which runs the binary at
`assets/base/agents/skills/cf-evaluate-model/scripts/eval_kit.py:3043`).
`release-automation` passed in the same run. The test builds the path from
`CARGO_TARGET_DIR` or `target`, plus `release/codeflow`
(`test_eval_kit.py:8509`). `.codeflow/test-config.json` declares
`model-eval-kit` with no `requires`, so nothing orders it after whichever
target produces that binary; it passed in batch 1 and in a targeted rerun
only because the binary was already there. Which target builds
`target/release/codeflow` in a gate run is part of this task's diagnosis;
the planning evidence shows only that it existed when `release-automation`
ran.

The outcome is that the target never depends on scheduling order: it
declares and enforces its dependency on the binary it runs (a `requires`
entry on the target that builds it), or builds or locates the binary itself
and fails with a message naming the missing prerequisite. The builder picks
the smaller of these and records the choice. Non-goals: changing what the
evaluation kit tests, or switching the gate to serial execution.

## Deliverables

- the dependency or build step: `.codeflow/test-config.json` (the `model-eval-kit` target), and `evals/model-artifacts/test_eval_kit.py` or `assets/base/agents/skills/cf-evaluate-model/scripts/eval_kit.py` if the test locates or builds the binary itself
- the check: a deterministic test or a gate-config check (provisional home: `scripts/test_gate_contracts.py` or `scripts/gate-parity.py`; the builder confirms)
- release note: `changelog.d/TSK-329.md`, only if shipped scaffold content changes

## Acceptance Criteria

- AC-1 The `model-eval-kit` target shall not run before the binary its
  tests execute exists: its configuration shall require the target that
  produces it, or its tests shall build or locate the binary and fail with
  a message that names the missing prerequisite; evidence: the diff and a
  statement of which target builds `target/release/codeflow` in a gate run.
  (serves EPC-022 AC-26)
- AC-2 A deterministic check shall fail when a gate target runs a binary
  under `target/` without requiring its producer, and shall fail on the
  3.1.0-line configuration of `model-eval-kit`; evidence: the check run
  against the old and the new configuration, failing before the change and
  passing after. A test of the missing-binary message replaces this check
  if the target builds or locates the binary itself. (serves EPC-022 AC-26)
- AC-3 With the binary absent from `target/release/` at the start, the
  `model-eval-kit` target alone shall pass, or fail naming the missing
  prerequisite and not a `FileNotFoundError`; evidence: a run from a clean
  `target/` directory. (serves EPC-022 AC-26)
- AC-4 When a full gate run is forced to start `model-eval-kit` first
  (reordered or with the producer's start delayed), the run shall pass, and
  the same run shall pass in the default order (journey); evidence: both
  gate runs with the forcing method stated, run one at a time. (serves
  EPC-022 AC-26)
