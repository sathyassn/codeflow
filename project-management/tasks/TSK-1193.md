# TSK-1193: The git tree reader batches blob size lookups

## Description

A TSK-1132 review nit. The git tree reader spawns one `git cat-file -s` per blob. This task resolves blob sizes for a whole tree with one batched git process (`git cat-file --batch-check`). Revisit when a catalog is large enough to measure. Status todo, with an edge from TSK-1132 and none into the catalog chain, so it blocks nothing (Director, 2026-11-02).

## Outcome

after this merges, a person reading a catalog from a git tree pays one git process for all blob sizes instead of one per blob, or the task closes as not needed with the measured numbers.

## Deliverables

- the batched size lookup: the git tree reader in `crates/codeflow-core/` (the builder finds it from the TSK-1132 loader)
- tests: the process-count test and the missing-blob case
- the measurement recorded in this record's Closeout

## Acceptance Criteria

- AC-1 The reader shall resolve blob sizes for a whole tree with one batched git process (`git cat-file --batch-check`), not one process per blob; evidence: a test counting spawned git processes for a tree of N blobs, which reports N before the change and 1 after.
- AC-2 Sizes and errors shall be unchanged: a missing blob shall still fail closed, naming the path; evidence: the existing reader tests pass, plus one missing-blob case.
- AC-3 A measurement of time and process count on the largest catalog available at build time shall be recorded in the task; if it shows no gain, the task closes as not needed, with the numbers; evidence: the recorded figures.
- AC-4 (journey) (added 2026-11-02, final review round 1, finding 1: the task had no journey criterion; this one drives its own change with the built binary) With the built binary, the command that reads a catalog from a git tree (the caller of the TSK-1132 loader, which the builder names) over a fixture tree shall give the same output as before the change and spawn one git process for the sizes; evidence: both outputs and the process count.
