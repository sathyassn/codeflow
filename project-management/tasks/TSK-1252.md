# TSK-1252: codeflow ci resolves the destination's default branch from trusted CI context, without a credential

## Description

Source: issue #527 (untrusted text, read only as a problem description) and the Director's direction of 2026-11-02.

`codeflow ci` runs `git ls-remote --symref <url> HEAD refs/heads/* refs/tags/*` to learn the destination's default branch (`crates/codeflow-core/src/workgraph/release_line.rs:194-201`, called from `crates/codeflow-cli/src/cmd/ci/acceptance.rs:235`). On a private repository that needs a credential, which is undocumented. A hardened checkout (`persist-credentials: false`) fails every pull request policy check, because the lookup fails closed and is reported as unscoped (`acceptance.rs:289`, `release_line.rs:313-318`). TSK-1175 makes every shipped checkout set `persist-credentials: false`, so without this fix the shipped `ci` step fails the same way.

Trust: the default branch selects the policy source and the release-branch pattern (`release_line.rs:324-360`, `:130-141`). The name therefore comes only from trusted CI context: the base repository's event payload (`GITHUB_EVENT_PATH`, `repository.default_branch`), bound to the default-branch SHA that TSK-336 resolves, and it fails closed on a mismatch with the local tracking ref. A flag typed on a developer machine is advisory and never selects the policy source. Non-goals: TSK-291's push credential helper and TSK-304.

## Outcome

After this merges, `codeflow ci` in a hardened hosted checkout learns the default branch from the trusted event without a credential, and a forged name is refused.

## Deliverables

- the event-based lookup: `crates/codeflow-core/src/workgraph/release_line.rs` and `crates/codeflow-cli/src/cmd/ci/acceptance.rs`
- fixtures: no network, forged event, mismatched tip, disagreeing local flag
- docs for the lookup, its inputs and the hardened-checkout route

## Acceptance Criteria

- AC-1 With no credential and `persist-credentials: false`, `codeflow ci` in the hosted policy workflow shall resolve the default branch from the event and pass; evidence: a fixture repository without network that fails before and passes after.
- AC-2 A forged or mismatched name shall be refused and the check shall fail closed: an event naming a branch whose tip differs from the trusted SHA, and a local flag that disagrees; evidence: one fixture per case.
- AC-3 The objects `ci` needs (the default tip) shall come from the checkout or the event's SHA, with no credentialed fetch; where they are missing the refusal shall name the missing input and the sanctioned fix; evidence: a fixture with the object missing.
- AC-4 The docs shall name the lookup, its inputs and the hardened-checkout route, and the help for `--destination` and `--advertisement-stdin` shall either document them or they stay hidden, with the reason recorded; evidence: the docs diff and the help output.
- AC-5 A cross-lineage security review shall cover the change, with the seat checked live, and the pull request shall state the threat it closes and why the trusted-event binding is the standard design; evidence: the review verdict and the pull request body.
- AC-6 A scaffolded adopter workflow with `persist-credentials: false` shall pass its pull request policy check on a private-style remote with no credential; evidence: the run output. (journey)
