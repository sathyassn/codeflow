# TSK-1470: A range that changes the decision map is told when a portal figure goes stale

## Description

TSK-1465 keeps the decision-map figure true as the decision count grows. A decision that starts or extends a supersession chain also changes what the architecture figure draws, and that figure's chain facts check substrings and the chain count, so some such changes pass them while the drawing goes stale. Planning and records-only ranges do not run the portal check, so the author is not told in the same pull request and the stale figure reaches `main` unseen, as it did with pull request 772.

TSK-1465's review narrowed this case out of that task. This task builds after TSK-1465 lands on `main`; it is not yet listed in `depends_on` because TSK-1465's record reaches `main` with its own pull request.

## Outcome

After this merges, an author whose range adds or changes a decision is told in the same pull request when a portal figure that reads the decision pages goes stale.

## Deliverables

- the figure check for planning and records-only ranges in `codeflow ci`: `crates/codeflow-core`
- the architecture figure's chain facts, or a chain declaration, that see a chain extended at its end
- fixtures for a planning range that adds a decision and for a chain extended at its end

## Estimate

- Grade: Medium; band: Medium (2 to 4 h); moved: none
- Split: not needed; one outcome (a decision change is checked against the figures in its own pull request)
- Basis: one admission change in `codeflow ci`, one figure-fact change, two fixtures and a cross-family security review of the admission change; graded by coord/records under issue 334's bands.

## Acceptance Criteria

- AC-1 For any range that changes `docs/decision-map.md` or `docs/decisions/`, planning and records-only ranges included, `codeflow ci` shall run the figure fidelity check, or name each figure that reads the changed page, so the author is told in the same pull request. Evidence: a fixture of a planning range that adds a decision, refused or named.
- AC-2 The architecture figure's chain facts shall detect a chain extended at its end, or the figure shall declare its chains so that any chain change is a refusal. Evidence: a fixture appending a decision to an existing chain.
- AC-3 The change to records-only admission shall get a cross-family review with the `cf-security-reviewer` checklist, since it changes what `codeflow ci` admits. Evidence: the review row.

## Execution contract

- Builder: assigned by the Director.
- Reviewer: a family that did not build it, checked live at dispatch.
- Landing: standalone into `main`; the operator merges.
- Edges: builds after TSK-1465 lands on `main`.
