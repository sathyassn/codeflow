# TSK-1014: Coverage defaults apply to targets that set no rules of their own

## Description

Issue #299, its defect half. The shipped test-config schema says
`defaults.coverage` holds "Default coverage rules applied when targets
omit them" (`assets/base/testing/test-config.schema.json`, `defaults`),
but the engine never applies them: `crates/codeflow-core/src/testing/config/mod.rs`
reads `defaults.coverage` only for its glob check, and
`collect_coverage_reports` in `crates/codeflow-core/src/testing/gate.rs`
skips a target with no coverage configuration and judges a target's own
rules only. A project that writes its floor once in `defaults.coverage`,
as the schema invites, gets no floor at all and must copy the rules into
every target, a workaround the release rule of 2026-10-18 places in
3.2.0. Codex's review of PR 343 separated this from the issue's feature
half (a mandatory 80 floor with recorded exemptions), which stays
TSK-1006 in EPC-024.

Outcome: **the rules a project writes in `defaults.coverage` are applied
to every target that collects coverage and sets no rules of its own, and
a test target that cannot be covered by them (no coverage producer) is
named in the gate output rather than passing silently.**

Rules:

- Defaults carry rules only, not a producer (format, artifact, the mode
  command that writes it). A target with a `coverage` block and no rules
  inherits the default rules; a target's own non-empty rules replace
  them, as "applied when targets omit them" says.
- A target with no `coverage` block while `defaults.coverage` is
  non-empty gets a warning naming the target and the missing producer;
  it is not failed, since no floor applied to it before and the
  mandatory floor is TSK-1006's decision.
- The inherited rules are enforcing exactly as a target's own rules are:
  a missing artifact fails the gate.
- No minimum is imposed and no default value changes; the schema text
  is kept and now true.

Non-goals: the mandatory 80 floor, exemption records and `essential`
evaluation (TSK-1006, EPC-024); changed-files scope.

## Acceptance Criteria

- AC-1 With `defaults.coverage` holding a `global` rule at 90 and a target whose `coverage` block names a producer and no rules, a full gate whose measured coverage is below 90 shall fail naming the default rule; evidence: a `codeflow test` fixture with explicitly configured defaults, failing before the change (it passes today). (serves EPC-022 AC-130)
- AC-2 A target with its own non-empty rules shall be judged by them alone, and with the default rule inherited a missing coverage artifact shall fail the gate as a target's own enforcing rule does; evidence: gate tests for both. (serves EPC-022 AC-130)
- AC-3 With `defaults.coverage` non-empty, a test target with no `coverage` block shall get one warning naming it and the missing producer, and its verdict shall be unchanged; with empty defaults nothing changes; evidence: gate tests.
- AC-4 (journey) With the installed build in a scratch adopter whose floor is written only in `defaults.coverage`, a full gate below that floor shall fail, and pass once tests raise coverage; evidence: the journey output.
