# TSK-155: criterion tags read with sentence punctuation

## Description

The acceptance checker reads a criterion tag (`(journey)`, `(after
release)`) only when the criterion text starts or ends with it exactly, so
ordinary sentence punctuation after a closing tag hides it. TSK-152 AC-4 on
the EPC-016 line ends `... that renders them (journey).`: `codeflow ci`
over its adopter-facing range reports `work.journey_criterion` (no journey
criterion), and the whole-tree `validate` skips the journey result check
that a journey criterion requires. TSK-152 is complete and its acceptance
is bound to its reviewed head, so the checker changes, not the record.
This task makes a tag read the same with trailing `.`, `,`, `;` or `:`,
still only as the first or last token, and makes SPC-013 R-50 say so.
Non-goal: repairing TSK-152's own acceptance block. Once the tag reads,
`validate` reports that block's `journey: AC-4 | ...`, which R-54 requires
as `verified | <path exercised>`; that repair belongs to the EPC-016 line
and the operator.

## Affected surfaces and interfaces

- `crates/codeflow-core/src/workgraph/record_text.rs` (`Criterion::has_tag`,
  the one reader behind `is_journey` and `is_after_release`) and its unit
  tests; `(serves ...)` is read anywhere in the text and is unchanged.
- `crates/codeflow-cli/tests/acceptance_journey.rs`.
- `CHANGELOG.md` (the pending acceptance entry) and `docs/capabilities.md`.
- SPC-013 R-50, amended by this planning pull request.

## Acceptance Criteria

- AC-1 When a criterion closes with a tag followed by `.`, `,`, `;` or
  `:`, the system shall read the tag as present; evidence: a unit test in
  `record_text.rs`.
- AC-2 When `codeflow ci`, `task status complete` or `validate` asks
  whether a criterion is a journey or an after-release criterion, the
  system shall answer by one rule; evidence: `has_tag` is the only tag
  reader and every `is_journey` and `is_after_release` caller goes through
  it (a grep in the pull request body).
- AC-3 When SPC-013 R-50 describes a tag's position, the system shall
  accept exactly what it describes; evidence: the amended R-50 text and
  AC-1's test.
- AC-4 When a criterion ends with `(journey).` or `(journey),`, the system
  shall read a journey, and when `(journey)` sits inside the text, the
  system shall refuse it as a tag; evidence: unit fixtures for all three
  and AC-5's journey.
- AC-5 (journey) On a fresh `init --full` project, through the built
  binary, a task whose journey criterion is TSK-152's real AC-4 text shall
  complete and pass `codeflow ci` on an adopter-facing range, and a task
  whose tag sits inside the text shall fail it with
  `work.journey_criterion`; evidence: `acceptance_journey.rs`.
