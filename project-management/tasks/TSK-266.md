# TSK-266: Guidance checks what content could be taken to mean

## Description

CodeFlow's writing guidance asks for plain, short, outcome-first prose and
names mannered patterns, and its figure and design references guard against
decoration and hue-only states. None of it asks the agent to consider what a
reader could take a word, name, image, colour or example to mean beyond what
was meant, to look for a second reading, or to treat a wrong, unsafe,
alarming or offensive reading as a material defect; names and messages in
code are not covered at all. This task adds that check once, in
`writing.md` "Meaning the reader takes" (what to check, how to check, code,
visuals, severity), raises the plain-writing rule at every tier to "clear
and unambiguous" with "check what a reader could take it to mean", and adds
short pointers and concrete checks where an agent writes or reviews: the
copy guide ("Names and code strings"), the editorial smells ("Meaning
taken"), `cf-editorial-review`, `cf-reviewer` and "Review verdicts",
`cf-develop`, `cf-design` and its design-choice audit, the explanation
method's check table, the UI verification section and the release policy.
The evaluation kit gains requirement CF-OUT-008 and the `meaning-taken`
pack so the change can be qualified natively; the native run itself needs
seats and is not part of this task. Non-goals: no hook, linter, word list or
policy character is added (ADR-0067's stance holds); no size budget is cut
to make room, and any guideline overrun is reported for the budget task to
decide; `cf-security-reviewer` is unchanged, since its charge is security
defects, not wording.

## Acceptance Criteria

- AC-1 When an agent at any tier reads the managed `AGENTS.md` block, the "Write plainly" rule reads "simple, straightforward, clear and unambiguous" and ends "State the fact directly, and check what a reader could take it to mean" (`rule_map_contract`, `artifact_budget_contract`).
- AC-2 When an agent at any tier opens `.codeflow/rules/writing.md`, it finds "Meaning the reader takes" with what to check (connotation, ambiguity, unintended readings, audience and context), the three-step check (a reader who does not know the intent, a hostile or careless reader, name by name and claim by claim), the rules for code (a name says what the thing does; a message names cause and fix without alarm or blame; a loaded term gives way to the plain technical word in a new name; example data is invented and neutral) and for figures and images (only what the facts carry; colour and icon conventions; no state by hue alone; no association the subject lacks), and the severity rule (`artifact_budget_contract`, `model_eval_contract` markers).
- AC-3 When an agent at the standard or full tier writes or reviews, the copy guide carries "Names and code strings", the editorial smells carry "Meaning taken" with the material-finding rule, `cf-editorial-review` diagnoses and verifies a second reading, `cf-develop` names each identifier, flag, message, log line, comment, test and example value for what it does, `cf-design` and the design-choice audit check implied meaning in names, images, colour and icons with a "Reading" lens, the explanation method's check table has a "Reading" row in both skills, the UI verification section and the release policy point at the home (`model_eval_contract` markers, `manifest_consistency`, `skill_mirrors`).
- AC-4 When a reviewer applies `cf-reviewer` or "Review verdicts", a name, message, figure or example that a plausible reader takes as wrong, unsafe, alarming, offensive or a false promise is a material finding, and naming and wording are nits only with no such reading (`artifact_budget_contract`, `model_eval_contract` markers).
- AC-5 When `codeflow update` built from this branch runs on the repository, every managed copy equals its source and the second run changes nothing; `codeflow doctor --check reading` reports each size, and any guideline overrun is stated with its bytes in the PR for the budget task to decide (`manifest_consistency`, `repository_update_noop`, `skill_mirrors`, the doctor output).
- AC-6 When the evaluation suite is validated, requirement CF-OUT-008 has its source markers in every named home, the `meaning-taken` pack composes the `release-strings-say-what-they-do` case with its faulty controls and a blind prompt, and the fixture states the frozen behaviour the subject must keep (`eval_kit.py validate-suite`, `model_eval_contract`).
- AC-7 When the guidance itself is read for what it could be taken to mean, it carries no mannered prose, no em or en dash, and no loaded example beyond the pairs it names as replaced (independent review; `codeflow ci` policy characters).
