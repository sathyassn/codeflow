# TSK-1039: A quick gate with no comparison base explains its full run

## Description

Issue #371 (CodeFlow 3.1.1, `48104f48b`, opened 2026-10-28 01:16Z). With
targets that declare `narrow` paths and a complete green full run
recorded at the merge base, the 3.1.1 pre-push hook runs every quick
target on every push with the reason "no proven comparison base", about
550 to 580 seconds a push in the reporting repository, and the adopter
is building its own selection map as a workaround. At 3.1.1 the hook
reaches `run_gate_exact(root, "quick")` with default options (the issue
cites `git_hook.rs:1278` and `gate.rs:152-153`), and the selector has
no base when `--since` is absent.

That path no longer exists on the 4.0.0 line. TSK-449 (complete, PR 325,
2026-10-24) removed test-config targets from the push on purpose: the
push set is `codeflow ci` over each pushed range and runs no target
(`crates/codeflow-cli/src/cmd/push_set.rs:5`,
`docs/policy-reference.md:75`, the test at
`crates/codeflow-cli/tests/hooks_cli.rs:5537`, EPC-022 AC-125). The
adopter runs 3.1.1, before TSK-449, so 4.0.0 removes the reported cost,
and nothing in this task returns a test target to the push.

Issue #494 (filed 2026-11-01, also 3.1.1, `48104f48b`, tag v3.1.1, merged
2026-10-12) is the same mechanism on two more pushes: the 3.1.1 push ran the
quick gate (`push_set.rs` at that commit, lines 6 and 195), so one
intermittent test at the tip refused a records-only push and the push made
by `codeflow work claim`, and the task that fixes the flaky test could not be
claimed. PR 325 (TSK-449, 2026-10-24) is after that release, so neither push
can fail on a test on this line. This task owns the regression test for both
shapes (AC-2). The issue's third ask, a recorded pre-existing failure, has no
push to attach to here; a failure of the cited quick gate stays the builder's
to report at ready.

What remains is the quick gate that a pull request cites when it is made
ready. TSK-352 (complete) gave `codeflow test` a default base:
`comparison_base` in `crates/codeflow-core/src/testing/delivery.rs:388`
takes an explicit `--since`, else the merge base of `HEAD` with the
declared target of the task the branch carries. With no task on the
branch (`plan/`, `chore/`), a detached head, or a task with no declared
target (`:405`, `:413`, `:416`), it runs every target and prints only
"no comparison base: ..." (`:465-467`), without saying that `--since
<commit>` narrows, the route the issue itself found working.

Outcome: **issue #371's push cost is confirmed gone on the 4.0.0 line
and stays gone (a push runs no test-config target), and a quick or
essential gate with no comparison base runs every target and states its
reason; it names `--since <commit>` as the way to narrow only where
`--since` can narrow (row A below), and otherwise says that local
narrowing is unavailable (row B).**

Credit rows (TSK-1044 settles which one holds; every criterion below
that narrows, skips, reuses or recommends `--since` is checked against
both):

| Row | When | Required behavior |
|---|---|---|
| A | the operator adopted a protected recorder in TSK-1044 | the positive journeys: selection narrows, skips and reuse happen only from attested executions |
| B | no protected recorder | every requested target runs and the reason is reported; no output recommends `--since` where it cannot narrow; positive narrowing, skip and reuse journeys are marked deferred in the epic's planning notes |

Rules:

- TSK-449's push contract holds: a push neither runs nor waits for a
  test-config target.
- The base stays TSK-352's rule: an exact commit from `--since` or the
  carried task's line, never a mutable branch name and never the push's
  old tip; an unproven base runs everything and names why.
- A default base for a branch with no task is out of scope: `--since`
  is a working manual route, and an automatic one would be a feature
  (4.1.0) with its own planning.

Non-goals: result reuse (TSK-355); the push budget itself.

  row B no output recommends `--since`; the message states why local
  narrowing is unavailable.

- AC-2 gains a third push shape, from issue 515 (pre-push should run the cheap commit and record checks before the test gate; its 185 s and 218 s waits were on 3.1.1). On this line the push set runs no test target (TSK-449, `push_set.rs:5-8`, `git_hook.rs` test `pre_push_ref_checks_never_run_targets`), so the shape is a regression test only: `push_refused_for_a_commit_or_record_reason_runs_no_target` pushes to a seeded destination, is refused for a commit reason (`git.commit_format`) and for a record reason (`work.id_registry`), starts no target (`ran.marker` absent) and leaves the remote unchanged. Current-line evidence: the hook tests `records_only_push_runs_no_failing_target`
and `task_branch_creation_runs_no_failing_target` (`hooks_cli.rs`) push to a
destination that already holds `main`, so ordinary admission runs; they assert

refused on the same fixture. `claim_push_runs_no_failing_target_at_the_tip`

negative control, that a non-conventional commit is refused. The shallow clone case
is `a_shallow_clone_runs_every_target_and_recommends_no_since`.
