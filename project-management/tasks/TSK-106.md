# TSK-106: release notes, entry identity, local preflight and typed repair

## Description

Main was left with invalid release state twice, the release notes leak
staging text, and a broken base blocks its own repair. This task delivers
the 3.0.0 part of design v4 section 6, keeping the model of ADR-0062 (one
calculator, same-PR release state, frozen published sections, human
publication): a multi-line staging strip and merged repeated headings;
entries reconciled for the actual 3.0.0 content under decision 3a; one
identity per pending entry; a cheap local release preflight in pre-push;
release-state checks on integration lines; a typed repair for a stale base;
errata outside frozen bytes; CodeFlow's release jobs moved out of the
managed CI file adopters receive; one fixture set for both parsers of the
Release impact block; `watched_contract_paths` extended. Non-goal: change
fragments (EPC-021, decision 4a) and EPC-018's entries (its own 4.0.0
release).

## Affected surfaces and interfaces

- `scripts/release.py`, the Rust PR-body check, `CHANGELOG.md`,
  `CONTRIBUTING.md`, `docs/releasing.md` (CAP-003).
- Pre-push; `codeflow integrate`'s test stage; the scaffolded and
  CodeFlow-only CI workflows; `.codeflow/policy.json`.
- Shared files this task edits: the CI workflow, the hooks and the policy
  schema, and `CHANGELOG.md`. Ownership follows SPC-013
  R-118.

## Acceptance Criteria

- [ ] AC-1 When the notes are rendered, a staging strip wrapped over several
      lines (`release.py:900` matches one; the candidate wraps it at
      `CHANGELOG.md:14-15`) shall be removed and repeated subsection headings
      merged; the notes shall be rendered on the final assembled source and
      reviewed as a new user and as an upgrading user before the tag;
      evidence: renderer tests and the recorded review.
      Spec: R-91.
- [ ] AC-2 The 3.0.0 entries shall match the release content under decision
      3a: every breaking change has a migration (including `00739affd` and
      `83903695d`), each included line's consumer outcomes are covered, and
      the delegate "pasted prompt" entry is settled once; evidence:
      `release.py check-pr` and a reviewed entry list.
      Spec: R-90.
- [ ] AC-3 A pending entry shall be identified by a bold label unique among
      pending entries, with an explicit identity for the legacy group; a
      changed body or impact under an existing label shall be treated as an
      edit whose net change is assessed; evidence: entry-identity tests.
      Spec: R-92.
- [ ] AC-4 Pre-push shall check the release tree against the recorded
      baseline, saying "not checked against the host", and warn when a range
      touches behaviour paths without a pending entry or a
      `Release impact: none` intent; a work-in-progress push is never blocked
      by a missing entry; the PR job keeps the full `check-pr` and blocks;
      evidence: pre-push tests.
      Spec: R-93.
- [ ] AC-5 CI shall run release-state on pushes to `integration/*`, and
      `codeflow integrate` shall run the structural check in its test stage;
      evidence: workflow and integrate tests.
      Spec: R-94.
- [ ] AC-6 When the base fails `validate_release_tree` and the proposed merge
      passes, `check-pr` shall accept a repair that changes only the
      changelog and the parsed stamp fields of the coupled files, read
      release configuration from the base, and name the invariant repaired;
      frozen sections, version non-reuse and impact floors stay enforced, and
      a repair that changes the baseline configuration is refused; evidence:
      typed repair fixtures.
      Spec: R-95.
- [ ] AC-7 Errata shall be a dated note outside frozen bytes, and
      CONTRIBUTING's git-cliff line corrected; evidence: the files and the
      frozen-section check.
      Spec: R-96.
- [ ] AC-8 CodeFlow's release jobs shall leave the managed CI file adopters
      receive, and `release.py` and the Rust check shall pass one shared
      fixture set for the Release impact block; evidence: the fixture suite
      run by both parsers.
      Spec: R-96.
- [ ] AC-9 (journey) On an adopter project updated with the installed CLI,
      the managed CI file shall carry no CodeFlow release job, and on this
      repository a behaviour change with no entry shall warn locally and
      block in the PR job; evidence: update journey and PR fixture.
      Spec: R-93, R-96.
- [ ] AC-10 This task shall extend the adopter-facing path set that TSK-104
      creates with the release contract paths (`watched_contract_paths`
      extended to the record schema, the CLI flag surface and policy keys),
      within TSK-104's structure, and shall own and ship the behaviour-path
      set for the local preflight (every path outside `docs/`,
      `project-management/`, `docs/verification/` and the record templates,
      with the skill trees counted as behaviour); both ship as fixtures the
      journeys use; evidence: the fixtures and a watch test that flags each
      added member.
      Spec: R-114, R-53, R-71, R-93.
- [ ] AC-11 (amended 2026-09-27, moved from TSK-150 AC-5) Audit row Q52 of
      `docs/verification/tsk-150-byte-cut-audit.md`, the nonbreaking
      migration exception dropped from the always-read release rule, shall
      be restored by meaning in the `cf-ship` release guidance this task
      rewrites; evidence: a restoration row in the pull request (audit row,
      restored text, file and trigger).
      Spec: R-118.
