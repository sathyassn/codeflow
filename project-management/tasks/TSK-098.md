# TSK-098: resync CodeFlow's own policy baseline with shipped defaults

## Description

CodeFlow is its own first consumer, so `codeflow update` on this repository
should be a no-op after a release. At `e49726807` it is not. Run in a
disposable clone with the branch binary on 2026-09-26, it skipped the live
`.codeflow/policy.json` (user-owned, "no new default keys") but rewrote the
committed baseline `.codeflow/.baseline/.codeflow/policy.json` to the shipped
`assets/base/policy.json`: it added `policy_characters: "warn"`,
`pr_release_impact: "warn"` and `pr_breaking_level: "major"`, changed
`pr_required_sections` from Summary and Changes to Summary, Changes, Reviews
and Release impact, and updated the file's hash in `.codeflow/manifest.json`.
So the release commits that changed shipped defaults did not resync this
repository's baseline, and nothing failed. This task resyncs the baseline and
adds the missing check, so the next default change cannot drift silently.

The live policy is not changed by this task: it already carries the PR keys,
and it keeps `policy_characters: "block"` for this repository by operator
decision (2026-09-26).

Target release: 3.0.0 (delivery plan of 2026-09-26 evening). Non-goal: changing any shipped default or any value
in the live policy.

## Affected surfaces and interfaces

- `.codeflow/.baseline/.codeflow/policy.json` and `.codeflow/manifest.json`
