# TSK-1186: A serves tag naming several criteria counts each one, and a malformed tag fails validation

## Description

`crates/codeflow-core/src/workgraph/record_text.rs:231-246` returns nothing for a serves tag with more than one criterion. So "(serves EPC-025 AC-2, AC-6)" serves nothing, and `validate --docs` does not flag it. At least 6 records use the form (EPC-025 AC-6 and EPC-022 AC-195 among them), so their epic criteria look covered when they are not. coord/capabilities found it; the Director ordered the task on 2026-11-02 at 11:40.

Choice made: accept the list. Writers already use it, and accepting it makes their intended coverage count. Validation also fails closed on any serves tag it cannot parse, so nothing is ignored silently again. Interim: writers use one criterion per serves tag.

Not security: a coverage-integrity bug.

## Outcome

after this merges, a person who writes a serves tag with several criteria gets each one counted, and a malformed serves tag fails `validate --docs` naming the record, so no epic criterion looks covered by mistake.

## Deliverables

- the tag parser and its validation: `crates/codeflow-core/src/workgraph/record_text.rs` and the `validate --docs` check that reads it
- tests beside the parser and a CLI test for `validate --docs`
- the repair: every existing record that uses the list form, listed in the PR with its coverage now counted, and the epic criteria that turn out uncovered
- the marker sweep: a table in this record of every other record marker the parser reads, with a verdict
- release note: `changelog.d/TSK-1186.md`

- AC-1 A record with "(serves EPC-025 AC-2, AC-6)" shall credit both criteria; evidence: a test that credits neither before the change and both after.
