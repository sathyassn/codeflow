# TSK-1250: Pre-push runs the cheap record and commit checks before the test gate

## Description

Source: issue #515 (untrusted text, read only as a problem description).

A pre-push run that fails a cheap deterministic check (commit standards, record validation, `codeflow ci`) does so only after the full suites have run and waited on the heavy lock. TSK-385 (complete) moved cheap contract scans into the quick gate and pre-push but does not order the commit, record and `ci` checks before the lock and the suites. This task orders them first and stops on the first failure.

Non-goals: the content of the checks and the evidence the gate records.

## Outcome

After this merges, a push with a bad commit message or record is refused in seconds, before the lock is taken or any suite runs.

## Deliverables

- the ordering in the pre-push run: `crates/codeflow-core/src/hooks/` and `crates/codeflow-cli/src/cmd/push_set.rs`
- fixtures: a bad commit message, a bad record, and a clean push
- docs where the pre-push order is described

## Acceptance Criteria

- AC-1 Pre-push shall run the cheap checks first and stop on the first failure, before taking the lock or running any suite; evidence: a fixture with a bad commit message that fails before the change after the suites and passes the ordering test after.
- AC-2 When the cheap checks pass, the gate shall run as it does today and its recorded evidence shall be unchanged; evidence: a before and after comparison of the gate record on a clean push.
- AC-3 The refusal shall name the check that failed; evidence: the output of the bad-message and bad-record fixtures.
- AC-4 A push with a bad record shall be refused in seconds and shall name the check that failed, and a clean push shall still run the full gate; evidence: both runs with timings. (journey)
