# TSK-267: Reading budgets are evidence-based, advisory and configurable

## Description

An agent that edits a shipped skill, agent or rule should see a size number
only when a tool would cut the file or refuse it, and otherwise a note with
the convention behind it, never a warning that reads as a defect and forces
a trim. Today the sixteen per-skill byte numbers in
`crates/codeflow-core/src/reading.rs` sit one percent above the measured
sizes, the per-task chain number has trailed the measurement three times,
and the written convention that "a change that moves a shipped file past
its number sets the new number in the same change" turned advisory numbers
into caps: `75c8972bc` trimmed `cf-reviewer.md` for 86 bytes. The research
behind this task (the 2026-10-11 report, `target/tsk-267-research-notes.md`
in the build worktree) found one real tool limit, Codex's
`project_doc_max_bytes` (32 KiB by default), one hard API limit, a skill
or agent description of at most 1,024 characters, and two vendor
conventions in lines: a skill or rule body under 500 lines (Anthropic's
skill authoring guide, Cursor's rules guide) and the always-loaded
CLAUDE.md set under 200 lines (Claude Code's memory guide).

This task keeps the two real limits hard: the Codex limit stays a failing
test on the generated `AGENTS.md` and a doctor warning for adopters, and
now reads `project_doc_max_bytes` from the project's `.codex/config.toml`
when it is set; a description over 1,024 characters is a doctor warning.
Every other number becomes an advisory doctor note that states its basis:
skill and agent bodies in lines against 500, the always-loaded set in lines
against 200, the per-task chain against 160 KiB (about one fifth of a 200k
window at four bytes per token), and the kernel against a number derived
from the Codex limit less a 16 KiB project section and the header (15 KiB).
The per-skill byte table, the class fallbacks, the rule count, the rule
line bytes, the agent and CLAUDE byte numbers and the guidance block number
are removed; the structure test and review control proliferation. A
project tunes the advisory numbers in a user-owned `[reading]` section of
`.codeflow/project.toml`, and the PR body word warning gets
`git.pr_body_max_words` (default 1000, 0 off). The doctor reading report
states the binary and skill-tree versions and reports the chain as
information when the installed read edges differ from the shipped map.
ADR-0083 records the policy and supersedes the charter's section 4.4
table. Decisions of 2026-10-11 from the operator: advisory guidelines are
notes, never warnings; the shipped word default stays 1000; no per-skill
byte number survives anywhere, this repository included.

Non-goals: measuring an adopter's own skills; a change to the commit
length limits in `policy.json`, which follow git's 50/72 convention and are
already configurable; a change to the present or portal product limits; an
edit to this repository's `.codeflow/policy.json`, which the operator owns.

## Acceptance Criteria

- AC-1 When the generated `AGENTS.md` with a 16 KiB project section passes Codex's instruction limit, `rule_map_contract` and `init_e2e` shall still fail, and when a project's `AGENTS.md` chain passes the limit, `codeflow doctor --check instructions` shall still warn; the limit is `project_doc_max_bytes` from the project's `.codex/config.toml` when that key is set, else 32,768 bytes. Evidence: the unchanged failing tests green at the PR head; the doctor unit test that sets the key and sees the limit move; the fresh-project demonstration.
- AC-2 When a shipped skill or agent description is over 1,024 characters, `codeflow doctor --check reading` shall warn with a catalogued remedy, and `artifact_budget_contract` shall fail on a shipped file; at or under it the check does not mention it. Evidence: the doctor unit test, the `remedy_clearing` proof `clears_doctor_description`, the contract assertion.
- AC-3 When a skill or agent body is over 500 lines, the always-loaded instruction set (CLAUDE.md and the files it imports, or AGENTS.md alone) is over 200 lines, the per-task chain is over 160 KiB or the kernel is over the derived 15 KiB, `codeflow doctor --check reading` shall report a note (exit 0, printed as `note` with `confirm:`) that states the measure, the number and its basis, never a warning; within every number it passes and states the numbers. Evidence: the doctor unit tests for each measure; `codeflow doctor --check reading` on this repository and on a fresh project.
- AC-4 When `.codeflow/project.toml` carries `[reading]` with `skill_max_lines`, `instructions_max_lines`, `chain_max_bytes` or `kernel_max_bytes`, doctor shall measure against those values, an absent key shall keep its default, a value of the wrong type shall be refused with its key named, and `ProjectState::store` shall round-trip the section verbatim. Evidence: the state unit tests, the doctor unit test with an override, the fresh-project demonstration.
- AC-5 When `codeflow ci` reads a PR body, it shall warn over `git.pr_body_max_words` words (default 1000; 0 turns the warning off), with the key documented in `docs/policy-reference.md` and absent from the shipped `policy.json` so an older binary never meets it. Evidence: the `pr_body` unit tests at the default, at a project value and at 0; the policy default test.
- AC-6 When the tree is searched for "sets the new number in the same change", "fresh install reports clean" as a rule and the per-skill byte table, none shall remain in `crates/`, `docs/` outside history records or `assets/`; the charter's section 4.4 table carries a dated note naming ADR-0083 as its successor. Evidence: `grep` output over the tree at the PR head; the ADR file.
- AC-7 (journey) When `codeflow init --standard` runs in a fresh repository with the worktree binary, `codeflow doctor --check reading` and `--check instructions` shall both report `ok`, naming the measures and their numbers. Evidence: the pasted output.
- AC-8 When the full workspace builds at the PR head, no public contract shall change incompatibly: `codeflow update` on this repository changes nothing, `repository_update_noop`, `manifest_consistency` and `skill_mirrors` pass, and the `pr_body_max_words` field carries a serde default so an older policy file parses. Evidence: the test summaries; `codeflow update` run twice; the Release impact section of the PR.
- AC-9 When the installed skill tree's read edges differ from the map the running binary ships, the reading report shall state the binary version and the installed scaffold version and report the chain as information, not a note or warning. Evidence: the doctor unit test that installs an older-shaped tree.
- AC-10 When `codeflow validate --docs`, `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `RUSTDOCFLAGS="-D warnings" cargo doc --workspace --no-deps` and `codeflow test --mode essential` run at the PR head, they shall pass. Evidence: the pasted summaries with the revision.
