# TSK-316: A pull request's scope drift and authority paths are reported

## Description

The assignment rule asks for a task before research, planning or review
that writes nothing (`assets/base/rules/workflow-discipline.md:365-371`,
repeated in `assets/base/claude/skills/cf-method/references/delivery-process.md:13-18`
and its figure), and nothing reports when a task's changes leave its
Deliverables (https://github.com/sathyassn/codeflow/issues/168, parts A and
B). The operator approved the rule wording on 2026-10-13 (decision 1). This
task edits the Planning paragraph of `workflow-discipline.md` and the
matching sentence and figure of `delivery-process.md` to this text, leaving
`assets/base/rule-map.toml` untouched:

> Before writing a repository deliverable, attach the work to its task and
> use that task's branch. A standalone task may be created on that branch
> and land with its deliverable in the same PR. An epic breakdown or
> amendment uses the epic's planning PR and needs no separate task.
> Discovery that writes nothing to the repository needs no task. Review,
> confirmation and repairs reuse the open task; a finding, a reviewer turn
> or a status reply creates none. A changed outcome follows the applicable
> standalone or epic planning route. At the standard and minimal tiers the
> task is the harness's tracked unit.

The change gets a qualification case covering a standalone task created on
its branch, an epic breakdown, a research artifact, and review or repair of
existing work.

Amended 2026-11-05 by the value audit planning pull request (PR 638), from
the planning-rules review of the Director (2026-11-05): AC-1 (the rule text)
and AC-2 (its qualification case) are removed because the rule they ask for
is on the line in other words. The Planning paragraph
(`assets/base/rules/workflow-discipline.md:443-449`) and the four rules of
`delivery-process.md` (`:11-17`) say that work which changes the repository
has a task before substantive work, that research, review and consult work
with no durable artifact needs none, and that review, confirmation and
repairs reuse the current task; the managed map's "shape a brief" row says
one planning PR creates the epic and its tasks
(`assets/base/AGENTS.full.md.tmpl:51`). The quoted text above is
history; this task now owns only the scope drift and authority path report.

It also adds `work.scope_drift` in `ci` and pre-push, warn by default
(`git.scope_drift`, block allowed): changed paths grouped by the covering
Deliverables line, uncovered paths with a count, the own record's
Deliverables delta, and the implicitly covered paths and evidence folders
printed beside the result. Implicitly covered: the task's own record and
`git.evidence_paths` (shipped default `["changelog.d/"]`, which a project
may empty). The Deliverables parser reads `- <output>: <path>` lines; the
path is the text after the last `: `, normalized; a backslash or escape
makes the entry unparsed; matching is a prefix match on path components; a
provisional entry matches nothing and is listed; a root entry is
unconstrained and covers nothing; an unparsed entry never becomes coverage.
For a planning class, `ci` prints each `docs/` file that no record in the
range mentions, as information only. Both keys are schema and defaults only
(TSK-280).
