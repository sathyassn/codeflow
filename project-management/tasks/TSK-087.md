# TSK-087: retire Mermaid and the present diagram block

## Description

Remove Mermaid from cf-present and remove the `diagram` block that is its
only consumer. The operator decided on 2026-09-24 that replies and documents
use HTML figures (the figure block drawn from the figure grammar, or a
justified `html` stage), ASCII on plain-text surfaces, and never Mermaid,
provided the removal causes no issue. The impact assessment of the same day,
on `integration/EPC-016-visual-guide` at `c5a86cf5d` and
`task/TSK-059-figure-runtime` at `11cd61e51`, found no issue that argues
against it. The portal never supported Mermaid (a fence renders as plain
code), so the change is confined to present, its skills, its records and
its supply chain.

Present has never shipped. The last tag is v2.1.0, and `codeflow present`
first appears under the unreleased 3.0.0 `### Added` entry
(`CHANGELOG.md:787-799`). No released consumer holds a document or a
session with a `diagram` block, so this is not a public break: the Added
entry is amended, and no Removed section or migration line is written.
Stored sessions with a diagram block exist only from pre-release builds,
and the task keeps them loadable so no maintainer session fails.

Stored revision mechanism. The stored record reader in `src/state.rs` gains
a legacy branch used only for records on disk: when a v1 `RevisionRecord`
fails typed parsing because its document holds a `diagram` block, the
reader loads it as a read-only revision content kind (`RevisionContent`
gains a `retired` kind carrying the raw document and the ids of its diagram
blocks). The new-input refusal is never called on this path, and no record
on disk is rewritten. The service and `present export` render that kind
through the existing unsupported page route (`src/render.rs:125-133`), with
a notice naming the conversion and each diagram block's escaped Mermaid
source beside it, so the author has the text to convert. The notice carries
no `data-cf-diagram` hook. `session-history-v1.schema.json` gains the kind,
so `history` output stays valid. Feedback: `content_block`
(`src/state.rs:2299-2302`) finds no block in the retired kind, so a new
note on it is refused with a named reason; notes already recorded stay in
`history` and `resolve` still closes them; on `update` with a converted
document, notes anchored on a removed diagram id orphan with a reason that
names the removed block.

Schema. The v1 document schema narrows: the `diagram` definition and its
`oneOf` entry go. That is acceptable because present has never shipped, so
no released consumer's editor or CI holds a v1 file the narrowed schema
would newly refuse; `schema_version` stays 1.

Conversion, stated once in the conversion section of `document-authoring.md`
and named by the refusal: `flowchart` becomes a flow figure; `sequence` a
sequence figure; `state` a state figure; `class` and `entity_relationship` a
structure figure, or a table where no relationship must be seen; `mindmap` a
`tree` block; `timeline` a table, or a sequence figure when participants
exchange messages. The `cf-stage` interim applies to the portal only; in
present an `html` stage stays limited to the two uses
`document-authoring.md` sanctions. The section points at the figure block
JSON example that replaces the diagram example and at the family specimens
in `figure-grammar-specimens.md`, since a figure declaration is larger than
a Mermaid line and the author needs one to copy.

The review page CSP is out of scope. Its inline style allowance is shared:
besides Mermaid, the interactive `html` block is inlined with scoped style
elements and validated style attributes (`src/render.rs:415-428`,
`src/safe_html.rs:75-95,160-163`), and the utility tokens are an inline
style element (`src/render.rs:59-64`). Tightening it is recorded as a
deferred item in EPC-016. The figure block needs no allowance: the grammar
module writes no inline style (`web/src/figure-grammar.mjs:10-12` on
`task/TSK-059-figure-runtime` at `2d53f70f0`), and its render check flags a
style attribute carrying a literal colour (`:1056-1057`). The removal still
retires the Mermaid SVG sanitizer (`hardenSvg`), about a hundred
third-party packages, and the accepted residual in `present.md` that
Mermaid renders synchronously within one diagram.

Order inside the task: the refusal and the stored revision branch land
first, so no intermediate head accepts a block the runtime can no longer
draw or fails to load a stored one. Non-goals: the figure runtime
(TSK-059), the chrome and the token values (TSK-060), the annotation matrix
(TSK-071), the review page CSP (the EPC-016 deferred item), the Agent OS
repository, and Mermaid in the portal, which has none to remove.
