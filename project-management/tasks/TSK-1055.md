# TSK-1055: Text rules relax only where each protected effect is attested

## Description

This is a planning draft accepted from the TSK-397 design note, revision 4.1, Part C (pull request 331), where it is unit U2 (capability matrix and relaxation). The note called the unit 3.3.0; the release is 4.1.0. Part C is accepted as planning drafts only: the criteria below are drafts, and this unit takes its own whole-unit review when it is built. Part C decisions (i) to (v) apply: (i) explicit non-secret enforcement-file arguments are allowed on a qualified host under attested `W-enforcement`, and the secret-read classes override, never a file name; (ii) a patch update invalidates a record, because exact executable digests bind it and a changed binary is `Unknown` until the operator re-runs the ceremony; (iii) managed settings are a design requirement for qualification, not a vendor fact; (iv) no exclusion matcher ever, so a non-empty `excludedCommands` disqualifies and route A+ is dropped; (v) the ceremony runs through the Bash tool, never the `!` prompt, and its evidence is receipts, not operator attention.

Each text rule relaxes only where every protected effect it prevented is attested. A matrix lists, for each rule, the capabilities it rests on, and a rule stops firing only on a host whose qualification record (TSK-1054) attests all of them.

Edges: this unit depends on TSK-1057 (U4), because the general run-time-word rule relaxes only after the authenticated policy authority has landed and is attested (`W-authority`), and on TSK-1054 (U1), because capabilities are attested by its record.

Non-goal: relaxing any rule on a host with no attested record; behaviour there is unchanged.

## Outcome

after this merges, an operator on a qualified host can run an interpreter on a non-secret enforcement file without a refusal, while a host that is not qualified sees no change.

## Acceptance Criteria

- AC-1 The matrix shall list per rule the capabilities it rests on; the general run-time-word rule shall rest on `W-enforcement`, `W-common-git` (when the common dir is not the project's `.git`), `W-startup` (startup containment: `security/startup.rs:12-23` names run-time paths as outside its text backstop), `W-authority` (TSK-1057 landed and attested) and all three `R-secret-*`; evidence: the matrix and a test that each missing capability keeps the rule firing.
- AC-2 With the matrix satisfied, the run-time rules shall not fire and an interpreter argument naming a non-secret enforcement file shall be allowed, with the secret classes overriding; evidence: a journey on a qualified host and the same command refused on an unqualified one.
- AC-3 A scope reduction shall change the stated guarantee and the tests, and shall never pass a test by weakening it; evidence: the PR body names each reduction and its changed guarantee.
- AC-4 Codex shall be unqualifiable for the run-time rules until its profile closes nested secrets (TSK-1060 AC-3); evidence: a test that a Codex record never relaxes them.
