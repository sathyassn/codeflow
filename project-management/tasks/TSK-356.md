# TSK-356: Slow test fixtures run once and exhaustive matrices run in the full gate

## Description

Source: the gate speed discovery of 2026-10-17, ranked change 4 and its
table of the 30 slowest tests (JUnit of run
`8b201fe4-2175-47a7-b3b8-1ac6961dfc71`, 5,278 cases, 11,040 seconds of
summed test time, 1,144 seconds elapsed).

The full gate's elapsed time has a floor set by the nextest serial group
(`.config/nextest.toml`): 319 cases and 737.27 seconds, of which
`init_e2e` is 585.76 seconds. The slowest case,
`fresh_scaffolds_install_the_confirmed_herdr_delivery_and_update_brings_it`
(`crates/codeflow-cli/tests/init_e2e.rs`), takes 242.02 seconds because it
runs the Herdr stub suite six times: four fresh installs and two updates.
Two remedy tests in `crates/codeflow-cli/tests/remedy_clearing/push.rs`
each sleep 61 seconds to cross a time budget. Other slow cases rebuild the
same planned-project fixtures many times (`readiness_journey.rs`,
`read_commands_offline.rs`, `release_line_cli.rs`, `ci_cli.rs`) or run
exhaustive tier, harness and crash matrices on every run.

Outcome: the full gate keeps every distinct boundary it proves while
repeated identical work runs once, and exhaustive matrices are placed
explicitly: the full gate runs them all; routine runs keep representative
and security counterexample cases.

Overlap settled here, folded rather than duplicated: the restored
test-time task of PR 224 (it replaces TSK-301) owns the guard random-words
fuzz tests and
`startup::installed_hooks_refuse_unresolved_forms_beside_a_named_target`,
including their timing and the `rust-coverage` time limit. This task does
not change those tests. TSK-351 (the hosted repair) owns the fixture fixes
it lists; this task starts from its landed fixtures.

Non-goals: removing a test, a security counterexample or a distinct
installation, recovery or shell boundary; adding any environment variable
or production knob that shortens a security timeout; the coverage floor.
Product surface: this repository's tests and gate config. A testability
seam in production timing code, if needed, is product code and states so.

## Deliverables

- Herdr corpus once: `crates/codeflow-cli/tests/init_e2e.rs`
- budget tests without real 61-second waits: `crates/codeflow-cli/tests/remedy_clearing/push.rs`, and an internal clock or budget seam in the code under test only if needed (named in the pull request)
- shared isolated fixture seeds: `crates/codeflow-cli/tests/` support modules for the slow fixtures in the discovery table
- matrix placement: `.config/nextest.toml` (the full-only matrix filter for the essential profile TSK-354 adds) and `.codeflow/test-config.json` if a target changes
- the measurement: serial-group time, fixture spawn counts and the case list before and after, in the pull request body
