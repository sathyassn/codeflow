# TSK-1012: Estimate outcomes find a deleted line's landing and report open-task age with idle claims

## Description

Consolidated 2026-11-04 (second consolidation amendment, coord/catalog): absorbed by TSK-1171. Its live criteria AC-1, AC-2, AC-4, AC-9 and AC-8 are now TSK-1171 AC-9 to AC-13, word for word with `Moved` notes; old AC-7 was already TSK-1171 AC-7 by the 2026-11-01 cut. Both tasks read the blocked spans in `history.rs` and prove one category per task, and the joined task grades Hard 7. Its edge to TSK-1173 is carried by TSK-1171.

Issue #334 items D and B and its comment of 2026-10-25. Two measurements are
lost today:

- **D, deleted lines.** A task's landing is found through its integration
  ref; when that ref is deleted after the epic merges, the run says the
  target "does not resolve in this clone" (`history.rs:472-477`) and the
  task's start is lost. In the adopter's run, 39 of 41 completed tasks
  without a start had a deleted line whose tip survives on `main` as a
  merge's second parent.
- **B, open-task age.** No report shows an open task's start, blocked spans,
  current age and idle claims.

The claim record (item F) is TSK-1173's; this task reads it. The profile, bands
and the clock's end are TSK-1013 to TSK-1172. Each of D and B has a manual route
(record outcomes before deleting a line), so this is a 4.1.0-grade feature
carried in EPC-022 so the method runs on the work now in flight.

Outcome: **after this merges, `estimate outcomes` times a task whose
integration ref was deleted after its line merged, measures a line before
deletion with `--ref`, and lists each open task's start, blocked spans,
current age less blocked time and idle claims, in the `ongoing` category
beside TSK-1171's.**

Rules:

- Landing from HEAD keeps the first-parent base the current reader uses; a
  deleted line is found through the merge on the target that brought it,
  never by a branch name.
- Every started task stays in the report in its own category (completed,
  ongoing, cancelled, reopened, superseded, unknown start). An unknown start
  is never filled.
- An idle claim (a claim with no later commit) is flagged with its age and
  handed over, never released automatically, never deleted. No idle
  threshold is set here; any threshold is set later from the measured
  claim-to-first-commit gaps and needs the operator's approval (D3).

Non-goals: bands, hit rates and the profile (TSK-1013, TSK-1171); the claim record
(TSK-1173); grouping by class (TSK-313).

Criteria removed from this record by the 2026-11-01 cut, each moved and not copied (`AC-n removed: <reason>`):

- AC-3 removed: the recorded claim time and the idle claim are TSK-1173 AC-2 and AC-4
- AC-5 removed: the one-step claim and the adopted-branch start (D4, D1) are TSK-1173 AC-1 and AC-2
- AC-6 removed: the idle flag with its age is this task's AC-9; the handover text and the no-release rule are TSK-1173 AC-7
- AC-7 removed: clocked and elapsed time (D3b) print for every started task in TSK-1171 AC-7 and for open tasks in this task's AC-4

## Acceptance Criteria

- AC-1 With a task's integration ref deleted after its line merged to the target, `estimate outcomes` shall find its landing and start from commits reachable from HEAD and report its duration; evidence: a CLI fixture, failing before the change with "does not resolve". (old TSK-1012 AC-1) (serves EPC-022 AC-200)
- AC-2 `estimate outcomes --ref <line>` shall measure a line before it is deleted, and the result shall equal the post-deletion result of AC-1 for the same tasks; evidence: a CLI fixture comparing both. (old AC-2)
- AC-4 The open-task view shall list each open task's start, blocked spans from `task status blocked`, current age less blocked time (its clocked time) and elapsed time with blocked included (D3b), and idle claims, and every started task shall appear in exactly one category; evidence: a fixture with one task per category. (old AC-4, with AC-7's open-task half)
- AC-9 An idle claim shall be flagged with its age and shall carry the task's original start unchanged; the report shall set no release, no deletion and no threshold, and shall name the handover route (the Coordinator takes the claim over, or the lane records `blocked`); evidence: a fixture showing the flag, the preserved start and the absence of any release or threshold. (old AC-6, reading half; the handover text is TSK-1173's)
- AC-8 (journey) With the installed build in a scratch adopter, claiming a task, completing it on a line, merging the line and deleting its ref shall leave the task timed in `estimate outcomes`; evidence: the journey output. (old AC-8; this journey is this task's only)
