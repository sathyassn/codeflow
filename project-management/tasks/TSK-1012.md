# TSK-1012: Estimate outcomes measure claim starts, open-task age and deleted lines

## Description

Issue #334, items B, D and F, and its comment of 2026-10-25. `codeflow
estimate outcomes` loses three measurements an adopter needs:

- **D, deleted lines.** A task's landing is found through its
  integration ref; when that ref is deleted after the epic merges, the
  run says the target "does not resolve in this clone"
  (`crates/codeflow-core/src/estimate/outcomes/history.rs`) and the
  task's start is lost. In the adopter's run, 39 of 41 completed tasks
  without a start had a deleted line whose tip survives on `main` as a
  merge's second parent.
- **F, claim time.** The start is the first commit after the target tip.
  `work claim` makes no commit, so the time from claim to first commit is
  not measured and an idle claim looks like work.
- **B, open-task age.** No report shows an open task's start, blocked
  spans, current age and idle claims.

Each has a manual route (record outcomes before deleting a line; commit
at claim), so these are 4.1.0 features, not 4.0.0 defects. The rest of
the issue (the opt-in time-box profile) is TSK-1013.

Outcome: **`estimate outcomes` finds a task's landing from commits
reachable from HEAD when its integration ref is gone, measures a line
before deletion with `--ref`, takes a recorded claim time as the start
when present, and reports open tasks' age with blocked spans and idle
claims.**

Rules:

- Landing from HEAD keeps the first-parent base the current reader uses;
  a deleted line is found through the merge on the target that brought
  it, never by a branch name.
- The claim time is recorded by `work claim` (a claim event in the
  ledger, or a start commit; the PR settles which, with the reason) and
  is used as the start only when it is the task's own claim.
- Every started task stays in the report in its own category
  (completed, ongoing, cancelled, reopened, superseded, unknown start),
  as `cf-estimate` `operating-model.md` requires.

Non-goals: bands, hit rates and the profile (TSK-1013); grouping by class
(TSK-1013, after TSK-313).

## Deliverables

- landing from HEAD and `--ref`: `crates/codeflow-core/src/estimate/outcomes/history.rs`, `crates/codeflow-cli/src/cmd/` (the estimate command)
- the claim record: `crates/codeflow-core/src/workgraph/` (`work claim`) and its reader in `crates/codeflow-core/src/estimate/outcomes/`
- the open-task view: `crates/codeflow-core/src/estimate/outcomes/mod.rs`, `render.rs`
- tests: `crates/codeflow-cli/tests/estimate_outcomes_cli.rs` and unit tests
- docs: `cf-estimate` `references/records.md` (mirrored), `docs/cli.md`
- release note: `changelog.d/TSK-1012.md`

## Acceptance Criteria

- AC-1 With a task's integration ref deleted after its line merged to the target, `estimate outcomes` shall find its landing and start from commits reachable from HEAD and report its duration; evidence: a CLI fixture, failing before the change with "does not resolve". (serves EPC-023 AC-32)
- AC-2 `estimate outcomes --ref <line>` shall measure a line before it is deleted, and the result shall equal the post-deletion result of AC-1 for the same tasks; evidence: a CLI fixture comparing both.
- AC-3 After `work claim`, the recorded claim time shall be the task's start when present, and a claim with no later commit shall be reported as an idle claim with its age; evidence: a CLI fixture. (serves EPC-023 AC-32)
- AC-4 The open-task view shall list each open task's start, blocked spans from `task status blocked`, current age less blocked time, and idle claims, and every started task shall appear in exactly one category; evidence: a fixture with one task per category.
- AC-5 (journey) With the installed build in a scratch adopter, claiming a task, completing it on a line, merging the line and deleting its ref shall leave the task timed in `estimate outcomes`; evidence: the journey output.
