# TSK-325: Edit denies cover every workflow file, the CI hook, scanners and bootstrap

## Description

Several files that decide enforcement are not in the in-session edit
denies (`crates/codeflow-core/src/security/actions.json:670-689`): the
policy workflow, the CI setup hook (`docs/adoption.md:396`), the scanner
configuration (`docs/adoption.md:397-398`), and the bootstrap scripts
TSK-324 adds (adopter design section 9). This task adds exactly eight paths
to `claude_edit_denies` (decision 8):
`.github/workflows/codeflow-policy.yml`, `.codeflow/ci-setup.sh`,
`.gitleaksignore`, `.gitleaks.toml`, `.gitleaks.json`, `osv-scanner.toml`,
`.codeflow/bootstrap.sh` and `.codeflow/bootstrap.ps1`. The Codex
read-only list and the presets are regenerated, and git-guard refuses the
known writers to each. `.gitignore` is deliberately not added. The writer
lock path and the publication directory are TSK-321's additions, not this
task's. Changing these files becomes a human-only act in agent sessions;
the writer boundary (what the guards can and cannot see) is stated in the
docs. Non-goal: `.codeflow/manifest.json` and `.codeflow/.baseline/`
(tracked once as a candidate, EPC-023 planning notes).

Widened on 2026-10-18 (EPC-022 amendment, PR 255) by the primary under the
operator's rule that every security gap belongs in 3.2.0: every file under
`.github/workflows/` is refused, not only the policy workflow. Today only
`.github/workflows/codeflow-ci.yml` is protected (`git_guard.rs:3706`,
and the `Edit(/.github/workflows/codeflow-ci.yml)` deny). Reproduced on the
line at `236e9d08b` with that tree's built hooks, the payloads judged and
never run: a native Write to `codeflow-policy.yml`, `release.yml` or a new
`other.yml` passes edit-guard; `printf x > .github/workflows/release.yml`,
`tee`, and `mv x.yml .github/workflows/new.yml` or
`mv .github/workflows/release.yml /tmp/r.yml` pass git-guard and
exec-guard; `python3 tool.py .github/workflows/release.yml` and
`python3 -c "open('.github/workflows/release.yml','w')"` pass exec-guard,
which refuses the same argument naming `codeflow-ci.yml`. So the
`.github/workflows/codeflow-policy.yml` entry becomes
`.github/workflows/**`, which also covers the existing `codeflow-ci.yml`
entry. Git commands that check out, switch to, merge, rebase onto or pull a
branch carrying workflow changes keep their current verdict: the workflow
change was made and reviewed elsewhere, and a person's edit outside the
session still commits. Adopter effect: agents in an adopter's session can
no longer write any workflow file; workflow changes become a person's act,
as they already are for `codeflow-ci.yml`.

  other, with `.github/workflows/**` in place of

  the list. (serves EPC-022 AC-71)

  test.
- AC-3 git-guard shall refuse the known writers (redirection, `tee`,
  `cp`, `mv`, `sed -i`, interpreter writes it already models) to each of
  the eight paths at the `git.hook_integrity` level; evidence: one guard
  test per path. (serves EPC-022 AC-71)
- AC-4 The docs shall list the eight paths and state the writer boundary

  doc text.
- AC-5 (journey) When an agent session with the installed build tries to edit each
  path by the Edit tool and by a shell write, each shall be refused, and a
  person's edit outside the session shall commit; the same holds for an
  existing workflow other than `codeflow-ci.yml`, a new workflow file, and
  a rename into or out of `.github/workflows/`, and a `git merge` of a
  branch carrying a workflow change shall run; evidence: the
  journey output.

  refused at the `git.hook_integrity` level by its owning guard for each

  `mv` or `install` into it, a `mv` or `rm` of a file in it, and `sed -i`
  by git-guard; an interpreter argument or code naming it by exec-guard;
  evidence: one test per route with `codeflow-policy.yml`, `release.yml`

  change. (serves EPC-022 AC-71)
