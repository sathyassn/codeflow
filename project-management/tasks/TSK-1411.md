# TSK-1411: The derived review row names the approving reviewer

## Description

When a task is complete, `codeflow ci` derives the pull request's Reviews row from the task's acceptance block and prints it (TSK-451). It takes the reviewer cell from the block's `review` text up to the first comma or semicolon (`crates/codeflow-cli/src/cmd/ci.rs`, `review_row_check`), and it keeps a YAML quote that opens a quoted value. When the review text lists several rounds, the row names whoever comes first, which need not be the reviewer whose verdict approved the reviewed commit. PR 718's ready policy run (codeflow-policy run 42617937210, head 1aa836448) printed `| "Grok 4.7 | whole unit at 7ea033ffb... | approved |` for TSK-326, whose review text lists Grok's rounds and then the Codex confirmation of the bound head. PR 752 printed `| "Codex GPT-6.1 Sol cross-lineage dependency review | whole unit at 09fdd1835... | approved |`, where the text's first round was a changes-requested verdict on an earlier commit. The row is review provenance, so a wrong name misstates who approved the landed code. coord/ci called it material. TSK-1291 AC-17 covers a row that names the wrong commit, not the reviewer.

## Outcome

After this merges, the Reviews row `codeflow ci` derives from an acceptance block names the reviewer or reviewers whose verdict approved the reviewed commit, with no stray quoting. When the review text does not say which verdict approved that commit, `codeflow ci` says so and names no reviewer.

## Deliverables

- the fix: the derived row in `crates/codeflow-cli/src/cmd/ci.rs` and, where the reader lives, the acceptance block reader in `crates/codeflow-core/src/workgraph/`
- tests: `ci_cli` cases beside the existing derived-row tests
- docs: the Reviews rows guidance in `cf-ship` `references/pr-evidence.md` (both skill mirrors), if the review text needs a form the reader can rely on, and a changelog fragment `changelog.d/TSK-1411.md`

## Acceptance Criteria

- AC-1 When an acceptance block's `review` text names more than one review or round, the derived row shall name the reviewer or reviewers whose verdict approved the block's `reviewed` commit, not the first name in the text; evidence: a `ci_cli` test with TSK-326's shape (rounds by one reviewer, then the approving confirmation by another) and one with PR 752's shape (a changes-requested round on an earlier commit, then approval of the reviewed commit), each failing before the change and passing after.
- AC-2 A `review` value written as a quoted YAML string shall be read without its quotes, so no cell of the derived row starts or ends with a stray quote; evidence: a test with a quoted value, failing before and passing after, and a check that every other reader of the block's `review` field gets the same unquoted text.
- AC-3 When the reviewer of the approving verdict cannot be read reliably from the text, `codeflow ci` shall say that it cannot name the reviewer and how to write the review text so it can, and shall not print a guessed name; it shall not refuse a pull request whose body carries its own approving Reviews row; evidence: a test per case.
- AC-4 A single-review text, as most records hold, shall derive the same row as now apart from removed quoting; evidence: the existing derived-row tests pass unchanged, plus one for an unquoted single review.
- AC-5 If the fix relies on a form of the review text, the Reviews rows guidance in `pr-evidence.md` shall state it, both mirrors byte-identical, and the changelog fragment shall describe the fix; evidence: the doc diff and `codeflow validate --docs`.
