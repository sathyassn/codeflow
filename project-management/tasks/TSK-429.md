# TSK-429: Managed skills ship once, or each copy is justified

## Description

Issue #279, item 4. In both adopting repositories about two thirds of
the tree is CodeFlow's own managed copies: `.claude/skills`,
`.agents/skills`, and two more copies under `.codeflow/.baseline`.
The mirror exists because Claude Code and Codex read different
folders; the baseline exists for the three-way merge of
`codeflow update`. The 4.0.0 baseline replacement (TSK-247, the
read-only update plan of issue #74) changes how the baseline is kept,
so this task is decided against that design and not before it.

Outcome: **an adopter's tree holds each managed skill once, or the
documentation names each extra copy and the reason it must exist, with
the measured footprint of each; and `codeflow doctor` reports the
managed footprint.**

Rules: a copy that a harness must read in place stays; a baseline copy
is replaced by the 4.0.0 baseline design where that design keeps
digests or a compressed baseline instead of full trees; a copy that
cannot go is documented with its reason in `docs/architecture.md`.

Non-goals: changing which harnesses CodeFlow supports; the update
algorithm itself (4.0.0).

## Deliverables

- the footprint decision: `docs/architecture.md` (the managed-copy section) and an ADR if the baseline shape changes
- the scaffold change where a copy goes: `crates/codeflow-core/src/scaffold/` (`update.rs`, the baseline writer) and `assets/base/scaffold-manifest.toml`
- doctor: the footprint report in `crates/codeflow-cli/src/cmd/doctor.rs`
- tests: scaffold tests and the `manifest_consistency` test
- release note: `changelog.d/TSK-429.md`

## Acceptance Criteria

- AC-1 After `codeflow init --standard` and after `codeflow update`, each managed skill shall be present once, or each additional copy shall be named in `docs/architecture.md` with its reason and measured size; evidence: a scaffold test counting copies and the doc. (serves EPC-024 AC-6)
- AC-2 `codeflow doctor` shall report the managed footprint (files and bytes per copy); evidence: the doctor output. (serves EPC-024 AC-6)
- AC-3 `codeflow update` on a project from the previous release shall still resolve a person's edits and conflicts as it did (TSK-405's cases); evidence: the existing update tests passing.
- AC-4 (journey) A project updated from the previous release shall show the reduced footprint and pass its quick gate; evidence: the journey output with `du` before and after.

## Execution contract

- Source: issue #279 item 4.
- Likely release impact: minor, or major if the baseline shape changes on update; decided with the 4.0.0 baseline design.
- Builder: Claude Sonnet 5.5 at high, a native subagent of the primary's session.
- Reviewer: Codex GPT-6 Astra at high, interactive Herdr seat, one independent whole-unit pass; the primary routes Grok 4.7 at high as the cross-family reviewer when both Claude and Codex authored the unit.
- Seats are the plan's; they are confirmed at dispatch, and a change of builder or reviewer lineage is a reassignment in the batched epic amendment.
- Security review: no (scaffold layout; `cf-security-reviewer` if the baseline integrity check changes).
- Affected surface: adopter-facing scaffold layout and doctor.
- Edges: a root of EPC-024, dispatched after the 4.0.0 baseline replacement (TSK-247) lands, which it is decided against (prose; TSK-247 is standalone and not on this epic's graph). Shares `update.rs` with TSK-247 and TSK-405; one writer at a time.
