# TSK-1241: Coverage measurement splits from Linux test execution on integration pull requests

## Description

Source: the CI throughput study of 2026-11-02 (`coordination/coordinators/parallel/throughput/`: RECOMMENDATIONS.md, FINDINGS.md, CHECK-codex.md, CHECK-fable.md), cross-checked by Codex GPT-6 Astra and Claude Fable 5.1, and the operator's priority on CI throughput.

The Linux coverage shards run the whole Linux Rust suite as `cargo llvm-cov nextest --workspace` (`.github/workflows/codeflow-ci.yml:455`), and their report also supplies the journey evidence and the check that every test ran exactly once (`:520`, `:528`). Moving the shards off integration pull requests would therefore remove the Linux tests there, not only the coverage measurement (Codex check, finding 2).

The recommendation is to keep an uninstrumented `cargo nextest --workspace` run, with its journey evidence and the once-each check, on integration pull requests, and to move llvm-cov instrumentation and aggregation to pull requests into `main` plus a scheduled run. The replacement job is measured before anything switches. The verdict jobs keep their names; what "codeflow gates" contains on an integration line changes.

Blocked on operator decision 2 of the study (keep Linux tests on integration pull requests and move only the coverage measurement). Non-goals: Windows (TSK-1242) and the reuse design (TSK-359).

## Outcome

After this merges and the operator's decision is recorded, an integration pull request runs the full Linux suite without instrumentation, and the coverage measurement runs on pull requests into main and on a schedule.

## Deliverables

- the Linux test job, the coverage shards and the aggregation: `.github/workflows/codeflow-ci.yml`
- tests for the report and the once-each check: the scripts the workflow calls
- the contract text that lists what "codeflow gates" contains per tier

## Acceptance Criteria

- AC-1 Before any switch, the builder shall measure the replacement job (the uninstrumented `cargo nextest --workspace` run with the journey evidence and the once-each check) against the instrumented shards on the same commit, and record the minutes of each, with run links; evidence: the measurement in the pull request body and the Findings.
- AC-2 On a pull request into an integration line, the Linux Rust suite shall run uninstrumented with its journey evidence and the once-each check, and llvm-cov instrumentation and aggregation shall not run; on a pull request into `main` and on a schedule they shall run; evidence: the workflow diff and one hosted run of each tier. (serves EPC-022 AC-232)
- AC-3 The verdict job names shall stay the same, the integration tier's skips shall be declared in one place, and the contract text shall say what "codeflow gates" contains on an integration line; evidence: the workflow diff and the contract text diff.
- AC-4 A candidate for `main` shall still get the coverage report and the once-each check on instrumented runs; evidence: a hosted run for a pull request into `main`, or the scheduled run.
- AC-5 A pull request into an integration line shall show the Linux tests passing without a coverage run, and a pull request into `main` shall show the coverage report; evidence: the links of both hosted runs. (journey)
