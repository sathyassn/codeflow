# TSK-399: Managed harness denies protect enforcement paths in every task worktree

## Description

Issue: #230, item 6 only. The rest of #230 (one harness-agnostic worktree home and harness adapters) is a feature request and stays deferred.

The protected harness paths (`.claude/skills`, `.claude/hooks`, `.claude/.cc-writes` and the settings files) are denied as absolute paths of the worktree a session was launched in. A worker that enters another task worktree is not covered: the reporter's test shows a worker in an entered worktree writing `.claude/skills/x` with no refusal. A skill or hook file is loaded as instructions or run as code by later sessions, so this is a security gap, not only a layout question. The in-session edit denies in `crates/codeflow-core/src/security/actions.json:670-690` name settings, policy and hook paths, but no skill or hook path.

The builder first records where each absolute deny entry comes from (CodeFlow's managed preset, or the harness's own defaults), then closes the gap in the layer CodeFlow owns.

Outcome: **an agent in any task worktree, launched there or entered later, cannot write the skills, hooks or settings of that worktree or any other checkout of the repository.**

Non-goal: changing where worktrees live or adding harness adapters (#230 items 1 to 5).

Added by the EPC-022 amendment of 2026-10-18 after the Codex review of PR 249 (`target/review-PR249-codex-01.md`), under the operator's rule that every security gap and every defect that forces an adopter workaround or blocks work belongs in 3.2.0.

## Deliverables

- the source of each deny entry and the chosen fix: the task PR
- the denies or guard refusals: the managed Claude preset under `assets/base/settings/` and `crates/codeflow-core/src/scaffold/settings_merge.rs`, the Codex and Grok equivalents under `assets/base/codex/` and `assets/base/grok/`, and the integrity set in `crates/codeflow-core/src/hooks/edit_guard.rs` and `git_guard.rs` if a guard refusal is needed
- tests: `crates/codeflow-cli/tests/hooks_cli.rs` and preset consistency tests
- release note: `changelog.d/TSK-399.md`
- managed wiring, mirrors and baseline: `assets/base/scaffold-manifest.toml`, installed managed files and `.codeflow/` baseline, synchronized when changed

## Acceptance Criteria

- AC-1 With the cwd in the main checkout, in a launched task worktree and in an entered task worktree, a native Write and a shell write to `<worktree>/.claude/skills/x/SKILL.md`, `<worktree>/.claude/hooks/x` and `<worktree>/.claude/settings.json`, for the current worktree and for another worktree under `.worktrees/` and `.claude/worktrees/`, shall be refused; evidence: one test per cwd, path and route, the entered-worktree skill write failing before the change. (serves EPC-022 AC-87)
- AC-2 Reads of those files, and writes to ordinary project files in the same worktrees, shall still pass; evidence: tests.
- AC-3 The deny set shall be generated from one list, so the Claude, Codex and Grok forms match it; evidence: the preset consistency test.
- AC-4 (journey) With the installed build, in a scratch adopter project with two task worktrees, an agent session that enters the second worktree shall be refused the skill, hook and settings writes of both, and shall still edit an ordinary file; evidence: the journey output.
