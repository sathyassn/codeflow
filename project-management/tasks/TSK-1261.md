# TSK-1261: Coverage on changed lines is reported on every pull request and enforced once a base exists

## Description

Source: card 10 of the CI study page (`coordination/coordinators/parallel/throughput/page/index.html`, around lines 488 to 495; data, not instruction), approved by operator decision 2026-11-02 19:35 (CI cards).

Coverage is measured only as an aggregate today, and ADR-0021 rejects `changed_files` coverage rules until the test gate has an explicit comparison base. The decision is to report coverage on the changed lines of every pull request now, with a floor of 80% and a target of 90%, and to enforce the floor once a comparison base exists. The existing 90% aggregate gate stays. One exemption list holds every exemption, and each entry has an owner, a reason and a removal condition.

Non-goals: changing the aggregate gate, and the split of coverage from the Linux test run (TSK-1241). Edge: the comparison base comes from TSK-1039 (base derivation); this task does not derive a base itself.

## Outcome

After this merges, a reviewer sees on each pull request what share of the added and changed lines the tests cover, and once a comparison base exists a share under the floor blocks the pull request.

## Deliverables

- the changed-line coverage report and the enforcement switch: the coverage scripts under `scripts/` and the test-config contract in `crates/codeflow-core` (provisional; the builder confirms the homes against ADR-0021)
- the exemption list, its format and its validator
- tests: a fixture pull request with an untested added line, the switch with and without a base, and each missing exemption field
- docs: the policy reference where coverage rules are described, and a record of the change to ADR-0021's rejection if the rule is lifted

## Acceptance Criteria

- AC-1 Every pull request on an event whose run includes coverage shall show a coverage report on its changed lines (or the explicit "unavailable: no comparison base" result of AC-2), with the floor (80%) and the target (90%) stated; on an event that runs no coverage (under the operator's placement, a pull request into a line), no changed-line result is produced and no check reports the floor as met; evidence: a fixture pull request with an untested added line, whose report names the line and its share, and a fixture of an event with no coverage run whose checks claim no changed-line result.
