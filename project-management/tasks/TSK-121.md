# TSK-121: present revision diff, replies and reopen

## Description

Node E of the present review parity package (Plan v5). Present shows only the
current revision, and notes end at addressed or dismissed; until this task
lands the reviewer sees "acknowledged", not a reply (proposal section 2). This
task adds, to SPC-014: a block-level diff between any two revisions with notes
and answers carried across and their changes disclosed; each revision bound to
the git commit and a digest of uncommitted changes as captured context; each
code and diff snapshot carrying its repository path, commit and a content
digest of the captured bytes, with the browser never reading files (section 2,
read project files row); and threads with the agent's reply text, reopen, and
delete as a visible tombstone (proposal sections 2 and 3.5). It also owns
three section 2 rows (settled 2026-09-26): optional revision labels, a summary
line for session listings, and a share-safe export that omits notes and
answers unless the operator opts in (decision 3a). Sessions stay private local
state; accepted decisions are promoted to records through the normal workflow.

## Affected surfaces and interfaces

- `crates/codeflow-cli/src/cmd/present.rs` (`present diff <id> --from N
  --to M`, the reply and reopen commands SPC-014 names);
  `crates/codeflow-present/src/state.rs` (revision context, thread records,
  tombstones), `service.rs`, `render.rs` for the diff view.
- `crates/codeflow-present/web/src/` and `chrome.tsx` for replies, reopen,
  tombstones and change disclosure in the rail.
- The `cf-present` skill's reply instructions, with mirrors and hashes; the
  present rebuild, manifest and checksum; `present_cli.rs`, the browser
  suites. CAP-016.

## Acceptance Criteria

- AC-1 `present diff <id> --from N --to M` shows block-level changes
      (added, removed, changed, unchanged) readably, and the notes and
      answers on each block are carried to the target revision with their
      change disclosed; evidence: `present_cli` golden output on a fixture
      with every change kind (4.2 row E, 3.5).
- AC-2 Each new revision records the git commit and a digest of uncommitted
      changes as captured context, shown in history and diff; evidence:
      state tests in a repository with and without uncommitted changes (3.5).
- AC-3 A code or diff block captured from the repository records its repository
      path, the commit, and a content digest of the captured bytes; a file
      with uncommitted changes records the digest of the bytes shown and marks
      them uncommitted; the browser never reads a file; evidence: state tests
      capturing a clean file and a dirty file and asserting each field, and a
      check that no service route serves repository files (section 2; Codex
      R5, plan review round 1).
- AC-4 The agent's reply text on a note or answer is visible to the reviewer
      in the rail; the reviewer can reopen a resolved thread; a posted note
      is kept, and delete leaves a visible tombstone; evidence: browser cases
      and state tests (section 2, threads row).
- AC-5 A revision can carry an optional label, shown in `history`, `diff`
      and the page; a session carries a summary line shown by
      `present list`; evidence: `present_cli` tests and a browser case
      (section 2, publish and title rows).
- AC-6 `present export` by default omits notes, answers and replies, and
      includes them only with an explicit opt-in flag named in SPC-014;
      evidence: export tests that inspect both outputs (section 2,
      private by default row).
- AC-7 Answers and replies stay in the private local session store; nothing
      is written into the repository; evidence: a test that the working tree
      is unchanged after a reply (decision 4a).
- AC-8 `npm run check`, the browser checks, `cargo test -p codeflow-present`
      and `cargo test -p codeflow-cli --test present_cli` are green and the
      present checksum matches a clean rebuild; evidence: recorded output
      with the head SHA.
