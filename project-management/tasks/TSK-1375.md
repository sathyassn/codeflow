# TSK-1375: The guards judge every reading of ambiguous text

## Description

Some shell text can be read in more than one way, and which reading a shell takes depends on details the guards do not see. The deletion reader (`crates/codeflow-core/src/security/deletion.rs`) picks one reading for such text. When the reading it picks holds no command, a deletion carried by another reading is never judged by exec-guard or git-guard. This task makes the reader take every reading the text allows, judge each one, and refuse the command when any reading is refused.

Scope: the deletion reader as it stands, and the guards that report its result. Non-goal: deciding which reading a given shell takes. The reader judges all of them, so it does not need to know.

Boundary with other work:

- TSK-1073 covers the future shell parser in `hooks/git_guard.rs`. When it replaces this reading, it must keep the result that every reading is judged.
- TSK-1374 makes the same reader fail closed at its bounds. A reading this task adds counts against those bounds like any other.
- TSK-286's proof table should cover this class of text later. This record notes that; it does not change TSK-286.

## Outcome

After this merges, an agent session on any adopter's machine gets a refusal when a deletion sits inside text a shell could read in more than one way, whichever reading the shell takes.

## Deliverables

- the reader change: `crates/codeflow-core/src/security/deletion.rs`
- tests: the test modules of that file, and `crates/codeflow-cli/tests/` for the built-binary path
- the changelog entry: `changelog.d/TSK-1375.md`
- the threat statement: the PR body

## Acceptance Criteria

- AC-1 When text can be read by a shell in more than one way, the reader shall read it each way, judge every reading, and refuse the command if any reading is refused; evidence: tests over each such form the reader handles, with the deletion placed in each reading in turn.
- AC-2 A test shall fail on `main` and pass after the change; evidence: the fail-before and pass-after output in the PR.
- AC-3 The real `codeflow hook exec-guard` and `codeflow hook git-guard` shall refuse the same text the tests judge, on default policy; evidence: a built-binary test or run that pipes the text to each hook and never executes it. (journey)
- AC-4 Real commands shall not gain false refusals, since ordinary scripts use these forms often; evidence: a run over the real-command corpus TSK-1374 uses, with every change from allowed to refused listed with its reason.
- AC-5 Statements about how a shell reads a form shall be given as expected behaviour, not as fact, unless a later step is authorized to check them against a real shell; evidence: the record, code comments and PR text.
- AC-6 The PR shall state the threat in class terms and why judging every reading is the standard design; evidence: the PR body.
