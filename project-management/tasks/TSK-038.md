# TSK-038 — retune the ink skin

## Description

The ink skin's light mode reads as grey rather than paper: the canvas and
surface tokens sit too far from white and the accent is oversaturated, which
also makes the embedded present distribution and the starter look unlike the
live portal. This task retunes ink light — canvas and surface toward white,
accent desaturated with its hue kept — propagates the identical values to the
present stylesheet, the starter and the live portal, and adds a starter↔live
equality assertion so the three cannot drift again. Non-goal: the dark mode
palette, the other skins and the token schema are not changed; this is a value
retune inside the existing system, not a new theme.

## Affected surfaces and interfaces

`docs-portal/src/styles/utility-tokens.css`,
`assets/docs-portal/starter/src/styles/utility-tokens.css`,
`crates/codeflow-present/web/src/styles.css` and the rebuilt embedded present
distribution, and the token test in
`crates/codeflow-core/tests/manifest_consistency.rs`. CAP-015 and CAP-016
presentation surfaces.

## Acceptance Criteria

- [ ] Ink light canvas and surface move toward white and the accent is
      desaturated with its hue preserved; evidence: the recorded before/after
      token values and the hue component unchanged.
- [ ] The same ink values appear in the live portal, the starter mirror and the
      present stylesheet; evidence: `portal_utility_tokens_match_present_skins`
      passes with its new starter↔live equality assertion, and that assertion
      fails when one file is perturbed.
- [ ] The embedded present distribution is rebuilt from the changed source and
      integrity-checked; evidence: the rebuilt artifact's checksum is recorded
      and the full `codeflow test` passes.
- [ ] Text and UI contrast meet the floors recorded in the TSK-037 doctrine in
      both light and dark; evidence: measured contrast ratios per token pair.
- [ ] Focus rings remain visible against the new canvas and surface in light,
      dark and the narrow layout; evidence: rendered inspection in all three.

## Execution contract

Plan v2, EPC-014. Responsible primary: claude-primary at high effort, who owns
the design judgement on the retuned values. Execution: a same-family opus
worker at high effort performs the CSS and test mechanics — token edits, mirror
propagation, the equality assertion and the distribution rebuild — under the
primary's authored values; the primary remains accountable for acceptance.
Cross-lineage reviewer: codex-primary at high effort. Integration target
`integration/EPC-014-public-docs`. Risk: the embedded present distribution is a
generated artifact, so a hand edit to it instead of a rebuild is a defect.
Recovery is git reversal plus a clean rebuild.
