# TSK-1293: A project adds model lines and routes duties to them in its model selection file, with one adopter page

## Description

Models change faster than CodeFlow releases. The operator ruled on 2026-11-03 that a consuming project can add a model line or version CodeFlow does not ship yet, without waiting for a release, and can override every catalog field. Today `.codeflow/model-selection.json` schema 1 and 2 accept only qualified-binding ids, design authority within a family and standing reviews (`references/model-overrides.md:3-28`, `crates/codeflow-core/src/model_catalog/selection.rs:18-29`); the personal overlay (`overlay.rs:4-20`) is per user and carries no routes.

This task adds the schema 3 `models` block. A project entry gives family and lineage, a selector per harness, allowed efforts, lifecycle and launch mode, and may mark a shipped version retired or excluded. A family the catalog does not know must declare its lineage, so the review-independence check can still tell lineages apart. Project entries carry no designations or qualification evidence; those stay managed.

The only refusals are the floors: no headless seats, launching the pinned id that resolve returns, and failing closed with the key named when the file is invalid. Security relevant: the file decides which model reviews whose work.

## Outcome

After this merges, a project maintainer can register a new model line or version in `.codeflow/model-selection.json` and have `codeflow models resolve` launch its pinned id.
