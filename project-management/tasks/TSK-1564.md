# TSK-1564: The guard reads a loader setting given behind a launcher on a script run

## Description

Owner: to be assigned by the Director. Priority: low. Staged by coord/records on coord/catalog's request of 2026-11-20 as one bare key, "track once", for the next filing batch. No pull request is needed before then.

The guard reads a loader setting given to an interpreter on an inline run and on a settled-stdin run, and refuses the shapes it cannot read. On a script run that sits behind a privilege launcher, one spelling of that loader setting is still accepted: TSK-1476's round zt does not touch it. The launcher's own manual leaves environment passing to the host's sudoers policy, so whether the setting reaches the interpreter depends on that policy. The gap is the script-run file-loader case behind that launcher only.

The exact spelling is kept in a coordination note that does not reach GitHub (the same standing rule as for the held records of 2026-11-20): `coordination/coordinators/planning/notes/held-record-concrete-rows-2026-11-20.md`, section "Key sudo-env-assignment-script-runs". The builder gets it from the brief.

Source: Grok's delta read of TSK-1476 round zt (`reviews/tsk1476-zt-grok.md`, nit 3) and the Director's ruling of 2026-11-20, relayed by coord/catalog. coord/records did not read that verdict.

Related: TSK-1476 (the unit that left it), TSK-1536 (the launcher reader).

Revisit event: when the next allowlist round touches launchers, for example TSK-1561 or a change to the launcher list.

Non-goals:

- Changing the sudoers model.
- The other residuals the TSK-1476 pull request names: the dynamic-linker variables, binder values on a script run, and a loader setting the guard's own environment already carries.

Not verified: that the spelling is accepted at the line tip (not reproduced here); the premise step does that as an inert string, and no payload is run.
