# TSK-048: close the validator and cleanliness holes under the portal gate

## Description

Two holes that the per-source composition gate rests on do not depend on the
composed views and were waiting behind them for no reason: the portal
validator accepts an empty or malformed Pagefind entry file, and the adapter's
HEAD-cleanliness check refuses harness litter such as `.claude/.cc-writes` and
`__pycache__` while it must never excuse a tracked or source-file change. This
task closes both now so the composition gate task carries only the page-class
rules. Non-goals: no page-class rule, no browser-verify change, no page content.

## Affected surfaces and interfaces

The portal validator under `crates/codeflow-core/src/validate/` and its tests;
the dirty-check in `docs-portal/scripts/lib.mjs` and `git-snapshot.mjs` with
their starter mirrors under `assets/docs-portal/starter`; the adapter test
fixtures in `docs-portal/tests/adapter.test.mjs` and its mirror, only for the
three cleanliness cases. Does not touch `adapter.mjs`, `portal.css`,
`browser-verify.mjs` or `composed-views.test.mjs`. CAP-015.

## Acceptance Criteria

- [ ] `codeflow validate --portal` shall reject an empty or malformed
      `dist/pagefind/pagefind-entry.json`; evidence: three validator tests
      where a valid entry passes, an empty entry fails and a malformed entry
      fails, each naming the file in the failure.
- [ ] The adapter's HEAD-cleanliness check shall exempt a file only when it is
      untracked AND matched by the repository's `.gitignore` AND outside the
      configured source and runtime inputs; evidence: three fixture cases,
      tracked-but-ignored modification reads dirty, ignored untracked litter
      reads clean, non-ignored untracked source reads dirty.
- [ ] The starter mirrors of every touched portal script and test shall be
      byte-identical to the live copies; evidence: the mirror equality check
      passes, and the manifest and baseline hashes are refreshed at the head.
- [ ] The adapter shall run clean on this repository with `.claude/.cc-writes`
      present; evidence: `npm run build` in `docs-portal` succeeds with that
      directory present and fails when an untracked non-ignored source file is
      added, both recorded in the closeout.
