# TSK-1037: A waiting session gets a managed sweep of its rules, skills and open work

## Description

Issue #366 and its amendment of 2026-10-28 00:37Z. CodeFlow reminds a
session of its rules only when something happens: the SessionStart
digest, the per-prompt reminder from `session-orient` and the guards on
each command. A session that is waiting on review seats, background
workers or hosted checks gets no reminder, and in one adopting
repository on 2026-10-27 finished verdicts and worker reports sat
unread, agreed steps went idle and the coordinator lost track of which
`cf-*` skill fits each step after compaction. Each host can schedule a
prompt (Claude Code `CronCreate` and `/loop`, other hosts' timers, a
Herdr keeper), so every session writes its own sweep prompt, about 30
lines that restate parts of the managed block and the skill list.

Outcome: **a read-only `codeflow sweep` prints a short, project-derived
checklist for the current session (pointers to the managed rules with a
hash of the instruction files, the `cf-*` skills that fit the session's
state, open work for its role, and project-owned additions), with
`--json`; managed guidance says how to schedule it on each host with a
30-minute default interval set per project; the sweep is on by default
for a session with a coordinator role or one that opens review seats or
background workers, and off for other sessions, so `session-orient`
reminds such a session when it has no sweep scheduled; onboarding says
so and how to turn it off; a project or a person can turn it off; and
nothing fails when a session never schedules it.**

Rules:

- Pointers and counts, never copies of the rules (as `orient` does),
  and exit 0. A sweep with nothing new prints one line.
- State comes from what CodeFlow can read: claimed or started tasks
  with no recent commit, open PRs whose checks are red or have not run,
  draft PRs with an approving review, integration lines behind the
  default branch, and the coordination ledger's follow-ups and lanes
  where the ledger is present (EPC-025: TSK-422 landed; TSK-439 adds
  lanes and seats). Forge state is read where the forge is reachable
  and reported as unread otherwise. The sweep reads open-PR state from
  `codeflow pr status` (TSK-1041) and task drift from `codeflow work
  audit` (TSK-1042) instead of reimplementing them.
- The interval defaults to 30 minutes (the operator's decision of
  2026-10-27, replacing the issue's 15), set per project with
  `[sweep] interval_minutes` in `.codeflow/project.toml`, which TSK-1045
  (EPC-022, 3.2.0) defines as the one interval key for scheduled sweeps,
  attended or away; this task reads it and adds no second key, and it
  is overridable by the project and the operator (amended 2026-10-28). A shorter interval
  while seats or checks run stays an option a project or operator may
  set; it is never the default.
- Project additions live in a project-owned file or table
  (provisional `.codeflow/sweep.md` or `[sweep]` in
  `.codeflow/project.toml`); AC-1 settles the home.
- No gate: no required step, no record, and no refusal for a session
  that never schedules it.
- Default (the operator's decision of 2026-10-27, made under "Only the
  operator adds process"): on for a session with a coordinator role or
  one that opens review seats or background workers, off for every other
  session. A project turns it off with `[sweep] enabled = false` and a
  person with a personal switch (for example `CODEFLOW_SWEEP=off`).
  Onboarding (`codeflow init` output and the SessionStart digest) states
  the default and both switches.
- What a scheduled sweep may do unattended stays inside
  `cf-method/references/autonomy.md`; the sweep never widens it.

Non-goals: the ledger itself (EPC-025); a scheduler inside CodeFlow;
any change to the per-command guards.

## Acceptance Criteria

- AC-1 Before any change, the builder shall research session sweeps broadly: how each host CodeFlow serves schedules a recurring prompt (Claude Code `CronCreate` and `/loop`, Codex, Grok, Herdr keepers) and whether those schedules survive a restart; how comparable tools build a periodic status digest; which state CodeFlow can read cheaply and offline; the existing guidance and readers in the survey above; and adjacent concerns (token cost of a frequent sweep, compaction, several coordinators at once, sessions with no forge access, the ledger's lanes from TSK-439); and shall record the findings with sources, the chosen scope and the project-additions home before any change; evidence: the note or record section, committed before the first code change in the PR.
- AC-2 `codeflow sweep` shall print pointers to the managed rules and the instruction files' hash; the `cf-*` skills that fit the session's state (for example `cf-reviewer` when a verdict is pending, `cf-ship` when a reviewed unit can land, `cf-herdr` when this run has seats open, `cf-plan` when a record change is pending, `cf-estimate` before a date is given); counts with pointers for claimed or started tasks with no recent commit, open PRs whose checks are red or have not run, draft PRs with an approving review, integration lines behind the default branch, and the ledger's open follow-ups when the ledger is present; and the project's additions; and shall exit 0 without changing any file, ref or record, with `--json` carrying the same content; evidence: CLI tests over fixtures with a stale claimed task, a PR with no check run, a PR with a red check, an approved draft PR, a line behind the default branch, a ledger follow-up and a project addition, one with none of them, and a test that the tree, refs and records are unchanged after a run. Amended 2026-10-27 to name each item of issue #366. (serves EPC-023 AC-34)
- AC-3 A sweep with nothing new since the session's last sweep shall print one line, and a changed instruction hash shall be reported as changed; evidence: CLI tests.
- AC-4 The managed guidance shall give, per host, how to schedule the sweep with a short prompt; the 30-minute default interval, set per project with `[sweep] interval_minutes` and overridable by the project and the operator; that a shorter interval while seats or checks run is an option, never the default; how a project and a person change or turn it off; and what a scheduled sweep may and may not do, bounded by `autonomy.md`; and `codeflow sweep` shall read the configured interval; evidence: the text diff, a `cf-editorial-review` pass and a CLI test that reads a project's interval and falls back to 30. Amended 2026-10-27 to the operator's 30-minute default. (serves EPC-023 AC-34)
- AC-5 By default, `session-orient` shall remind a session with no sweep scheduled, at start and at resume, when it has a coordinator role or when it opens review seats or background workers, and shall not remind any other session; the project and personal switches shall silence it; and `codeflow init` output and the SessionStart digest shall state the default and how to turn it off; evidence: hook tests for a coordinator session, a non-coordinator session that opens a worker, one that opens a review seat, a session that does neither (no reminder), and each switch, and the onboarding text. Amended 2026-10-27 to the operator's default: on for those sessions, off for others.
- AC-6 A session that never schedules a sweep, or turns it off, shall be refused nothing and shall leave every check's verdict unchanged; evidence: a gate and CI run with the sweep off.
- AC-7 (journey) With the installed build in a scratch adopter project with a stale claimed task, a red PR fixture, an approved draft PR fixture and a project addition, `codeflow sweep` shall list each, a coordinator session shall be reminded with the 30-minute default, a quiet sweep shall print one line, and a scheduled run in one host shall reprint after the configured interval; evidence: the journey output.
