# TSK-1037: A waiting session gets a managed sweep of its rules, skills and open work

## Description

Issue #366 and its amendment of 2026-10-28 00:37Z. CodeFlow reminds a
session of its rules only when something happens: the SessionStart
digest, the per-prompt reminder from `session-orient` and the guards on
each command. A session that is waiting on review seats, background
workers or hosted checks gets no reminder, and in one adopting
repository on 2026-10-27 finished verdicts and worker reports sat
unread, agreed steps went idle and the coordinator lost track of which
`cf-*` skill fits each step after compaction. Each host can schedule a
prompt (Claude Code `CronCreate` and `/loop`, other hosts' timers, a
Herdr keeper), so every session writes its own sweep prompt, about 30
lines that restate parts of the managed block and the skill list.

Outcome: **a read-only `codeflow sweep` prints a short, project-derived
checklist for the current session (pointers to the managed rules with a
hash of the instruction files, the `cf-*` skills that fit the session's
state, open work for its role, and project-owned additions), with
`--json`; managed guidance says how to schedule it on each host with a
30-minute default interval set per project; only the coordinator of a stream with
no parent (the Director, or a lone Coordinator) schedules the sweep, and
it notifies each child stream's Coordinator to run its own part, so
`session-orient` reminds only that root coordinator when it has no sweep
scheduled (amended 2026-11-03, see the re-scope note below); onboarding says
so and how to turn it off; a project or a person can turn it off; and
nothing fails when a session never schedules it.**

Rules:

- Pointers and counts, never copies of the rules (as `orient` does),
  and exit 0. A sweep with nothing new prints one line.
- State comes from what CodeFlow can read: claimed or started tasks
  with no recent commit, open PRs whose checks are red or have not run,
  draft PRs with an approving review, integration lines behind the
  default branch, and the coordination ledger's follow-ups and lanes
  where the ledger is present (EPC-025: TSK-422 landed; TSK-439 adds
  lanes and seats). Forge state is read where the forge is reachable
  and reported as unread otherwise. The sweep reads open-PR state from
  `codeflow pr status` (TSK-1041) and task drift from `codeflow work
  audit` (TSK-1042) instead of reimplementing them.
- The interval defaults to 30 minutes (the operator's decision of
  2026-10-27, replacing the issue's 15), set per project with
  `[sweep] interval_minutes` in `.codeflow/project.toml`, the one
  interval key for scheduled sweeps, attended or away, overridable by
  the project and the operator (amended 2026-10-28). Whichever of
  TSK-1045 and this task lands first defines the key, and whichever of
  TSK-1046 and this task lands first writes the per-harness route
  reference; the later one reads them and adds no second key or
  reference (amended 2026-10-28). The key sets the base interval. An
  active away activation may shorten its own tick while a result is due
  (TSK-1046 AC-9(f)), and the sweep guidance says so; otherwise a
  shorter interval while seats or checks run stays an option a project
  or operator may set, never the default.
- Where "scheduled" and "last sweep" live (amended 2026-10-28). CodeFlow
  cannot see a harness's schedules (`docs/product.md:70-71`), so an
  active away activation's armed trigger and last fire (TSK-1045) are
  the one home for whether a sweep is scheduled. A session counts as
  scheduled only while its activation records an armed trigger that
  fired, or was armed, within one interval; an activation with no
  trigger armed, or whose continuation stopped on a limit, does not
  silence the reminder. `codeflow sweep` stays read-only and keeps no
  marker: it prints a digest of what it read, and a later sweep given
  that digest (`--since <digest>`) prints one line when nothing changed.
  Amended 2026-10-29 after Codex review 01 of PR 393, as the smallest
  consistent fix; the session design in progress keeps the attended
  sweep read-only, and its planning pull request settles this home.
- Project additions live in a project-owned file or table
  (provisional `.codeflow/sweep.md` or `[sweep]` in
  `.codeflow/project.toml`); AC-1 settles the home.
- No gate: no required step, no record, and no refusal for a session
  that never schedules it.
- Default (the operator's rule of 2026-11-03, which supersedes the
  decision of 2026-10-27): only the coordinator of a stream with no parent
  (the Director, or a lone Coordinator) runs a scheduled sweep. On each
  sweep it notifies every child stream's Coordinator, which runs its own
  part and reports up; Coordinators and Workers keep no sweep schedule of
  their own. The earlier default (on for every session with a coordinator
  role or one that opens review seats or background workers) is withdrawn. A project turns it off with `[sweep] enabled = false` and a
  person with a personal switch (for example `CODEFLOW_SWEEP=off`).
  Onboarding (`codeflow init` output and the SessionStart digest) states
  the default and both switches.
- What a scheduled sweep may do unattended stays inside
  `cf-method/references/autonomy.md`; the sweep never widens it.

Non-goals: the ledger itself (EPC-025); a scheduler inside CodeFlow;
any change to the per-command guards.
