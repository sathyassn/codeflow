# TSK-235: Guidance for working while something is uncertain

## Description

CodeFlow says what an agent settles itself and what it asks, and that a stop
holds only the one action. It says little about how dependent work keeps
moving while an operator question is open, a fact cannot be verified yet, or
operator feedback has arrived mid-run. Issue 70 proposes five pieces plus two
small ones from an adopter project; this task judges each against the
existing doctrine, keeps what adds protection or removes friction, merges the
overlaps, and writes the text where it loads: the full interim-state rule in
the autonomy reference (a conditional read), its every-tier summary in
`workflow-discipline.md` "Navigate blockers", the reach-claim and
encoded-guidance rules in "Claims need evidence", the operator-feedback rule
in "Planning", the qualified-term rule in `writing.md`, the record home in
`project-organization.md`, and one reviewer check in `cf-reviewer.md`. The
per-task reading chain does not grow. Non-goals: the per-epic plan document
(issue piece 7) adds a record to every epic and is listed for the operator
in the pull request, not written; the numbered decision log is a project
convention, not a managed one. No enforcement path (policy, hooks, CI)
changes.
