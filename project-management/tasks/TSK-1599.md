# TSK-1599: An adopter can install the pinned name engine and doctor checks it

## Description

Owner: to be assigned by the Director. Staged 2026-11-23 for coord/records.

SPC-018 R-26b. The operator decided on 2026-11-23 that layer 4 is local,
optional and warn only; how the engine is installed follows from that and
is settled here: the adopter installs it, CodeFlow pins its versions and
hashes and documents the install, `codeflow doctor --check privacy`
reports what it found, and no hook or command downloads anything, as the
gitleaks engine already works (`policy-reference.md` main `:1093` to
`:1130`: "The hook never downloads anything"). Bundling Python and a model
in the binary was not chosen: the engine is optional and local, and
bundling would add its size to every install. A Tier-3 dependency, so the
ADR TSK-1583 writes records it.

## Outcome

After this merges, an adopter can follow one documented step to install
the pinned engine on Linux or macOS, and doctor says whether it is there,
pinned and runnable.

## Deliverables

- the pin file (versions and hashes) as a managed asset; the documented install step in `docs/policy-reference.md`
- `codeflow doctor --check privacy` engine rows; `changelog.d/TSK-1599.md`

## Acceptance Criteria

- AC-1 The documented install on Linux and macOS shall install exactly the pinned versions with hash checking, and doctor shall then report the engine as pinned and runnable; evidence: the install transcript per platform in a scratch environment.
- AC-2 Doctor shall report a missing engine, another version and a failing self-test separately, each with the install step; evidence: doctor tests.
- AC-3 No hook, `codeflow ci` run or `codeflow update` shall download the engine or the model; evidence: a test with network blocked showing each path warns and does not fetch.
