# TSK-1263: The line keeps the Playwright apt cache that the verdict reuse check looks for

## Description

Source: TSK-1246's check of the first line pushes after PR 482 (TSK-359), and coord/planning's decision of 2026-11-02 that two pushes without reuse is a defect.

Both line pushes after PR 482 fell back to running every job:

| Push | Commit | Run | Reuse job |
|---|---|---|---|
| first | c1481a51a (PR 483 merge) | codeflow-ci 41538428643 | job 125596165346 |
| second | 349d0f176 (PR 532 merge) | codeflow-ci 41550583650 | job 125637639779 |

Each reuse job logged: `ci-reuse: every job runs: neither refs/heads/integration/EPC-022-the-3-2-0-milestone-fixes nor refs/heads/main holds apt cache 'playwright-apt-ubuntu24-20261026.354.1-1.62.1'; every job runs so the present part saves it`. `gh api repos/sathyassn/codeflow/actions/caches?key=playwright-apt` returned no cache at all on 2026-11-03.

Cause found by reading, not yet proven by a fix:

- The lookup is `scripts/ci-reuse.py:388-394`. It asks for the exact key built at `scripts/ci-reuse.py:156-159` on the pushed ref and on main, and runs every job when neither holds it.
- The only step that saves that key is the `actions/cache` step at `.github/workflows/codeflow-ci.yml:444-448`, in the `present` part of the `gates-release` job (line 354). That job's `if` (line 355) runs it only for pull requests into main or master, pushes to main or master, schedule and workflow_dispatch. It was skipped on both line pushes (job 125597502500 in run 41538428643).
- The `present` part of the `gates` job (line 263) has no apt cache step, so a line push never saves the key. The message "every job runs so the present part saves it" (`scripts/ci-reuse.py:394`, and the matching text at `scripts/ci-reuse.py:33-36`) is wrong for a line push.
- A cache saved by a pull request into main is scoped to that pull request's ref, so the lookup on `refs/heads/main` finds one only after a push to main or a scheduled run saves it. No such cache exists now.

Likely causes to confirm: the key spelling matches (it does, from the log and the two files), so the ref scope and the save step's condition are the live suspects; the lookup's ref list is correct for a line push.

Scope: make the line hold the key, or make the lookup name where the key is saved, and correct the message. Non-goals: the reuse design of TSK-359, and any weakening of the fallback. Related to TSK-1248 (the hosted cache proof); no edge is added because neither needs the other to start. The `codeflow-ci.yml` change goes to the operator as a patch, as for TSK-1241 and TSK-1242, because that file is under the operator's edit deny. The `scripts/ci-reuse.py` change is an ordinary edit. This task is not a security task: a missing cache runs every job, which is the safe direction (AC-3 shows it).

Links: TSK-359 and TSK-1246 (its Findings).
