# TSK-413: An inline interpreter program's git calls are read by the language's grammar

## Description

Issue #253. exec-guard reads the source text of an inline
`python3 -c '...'` program as if it were shell git arguments. In
`subprocess.run(["git", "-C", str(source), "status"])` the guard takes
the literal `str` as the `-C` repository path, fails to discover a
repository at `<cwd>/str`, and refuses the whole command under
`git.policy_authority` with the remedy "restore the command repository
and its readable policy authority", which names no route that fits. The
`-C` value is a Python expression evaluated at run time to a throwaway
clone path. The adopter's workaround is to move the snippet into a file
and run `python3 -I -B <file>`, which the guard does not read at all, so
the current parse is both over-strict and easy to step around. Seen
2026-10-18 on CodeFlow 3.1.1 (`48104f48b`) in a Codex builder seat. The
reader is the interpreter judge TSK-302 added
(`crates/codeflow-core/src/security/interpreter.rs`); TSK-378 widens it
to more interpreters and TSK-406 gives it the shell-expansion resolver.

Outcome: **a git call inside an inline interpreter program is read by
that language's grammar: a string literal operand gets the literal's
verdict, any other expression is unresolved and is refused only where a
checkout or enforcement file is reachable, and the refusal names the
expression and the sanctioned route (a literal path, or a reviewed
script file).**

Rule: a `-C`, `--git-dir`, `--work-tree` or path operand of a git call
in interpreter code is judged as a literal only when the language's
grammar makes it one (a plain string literal, or a concatenation of
literals); a name, call, f-string with a placeholder, or other expression
is an unresolved word, judged by the same rule TSK-406 gives an
unresolved shell expansion: refused where a checkout or enforcement file
is reachable from the working directory, with the expression quoted in
the message, and allowed otherwise. The refusal names
`git.policy_authority` only when a literal path names a repository the
guard cannot read.

Non-goals: reading a script file the interpreter is given (a stated
residual of TSK-302, unchanged here); executing or evaluating interpreter
code.

Added by the EPC-022 amendment of 2026-10-22 under the operator's release
rule of 2026-10-18 (a defect that blocks work belongs in 3.2.0).

## Acceptance Criteria

- AC-1 The issue's command, `python3 -I -B -c 'import subprocess; source="/tmp/x"; subprocess.run(["git", "-C", str(source), "status"])'`, shall pass exec-guard from a checkout, and the same with `str(source)` replaced by a literal path to another repository's enforcement file or `.git` shall get that literal's verdict; evidence: hook tests, the first failing before the change. (serves EPC-022 AC-102)
- AC-2 A git operand that is a name, a call, an f-string with a placeholder, a concatenation with a non-literal part or any other expression shall be unresolved: refused naming the expression where a checkout or enforcement file is reachable from the working directory, allowed where none is, with the same reachability rule TSK-406 uses for an unresolved shell expansion; evidence: one test per expression kind and per reachability case, on each interpreter the guard reads. (serves EPC-022 AC-102)
- AC-3 A refusal for an unresolved operand shall name the sanctioned route (a literal path, or a reviewed script file run from the checkout) and shall never say `cannot discover existing repository` for a word that is not a literal path; evidence: the message in the tests of AC-2.
- AC-4 Every refusal the interpreter judge gives today for a literal git operand (a literal `-C` into another checkout, a literal enforcement path as a git operand, the TSK-302 and TSK-378 cases) shall stay refused; evidence: the existing interpreter tests passing.
- AC-5 `docs/policy-reference.md` shall state what the guard reads inside an inline program, how a non-literal operand is judged, and that a script file stays a stated residual; evidence: the doc text.
- AC-6 (journey) With the installed build, an agent session in a scratch adopter project shall run the issue's command and shall be refused the same command with a literal `-C ../other-checkout` where `other-checkout` holds enforcement files; evidence: the journey output.
