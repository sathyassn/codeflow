# TSK-1400: The 3.2.0 line passes its Windows tests after the remote identity change

## Description

The EPC-022 line has failed its hosted Windows run on every push since TSK-1184 landed (PR 698). This task returns the line to green by fixing each cause where it lies.

- The edit guard judged the operator-authority directory (`~/.codeflow/authority`) in a different path spelling from the one it gives the targets it compares with it. The directory is now spelled through the same normalization as the targets, lexically and resolved, with ASCII case folded as before. This is a guard change and takes a security review.
- The policy authority's refusal shows each URL through `display_text`, which escapes every backslash on purpose (TSK-388). The TSK-1184 tests compared the refusal with the raw path, which differs on Windows only. They now compare with the shown form, and on other hosts their remotes sit under a directory whose name holds a backslash, so every host runs that comparison.
- One TSK-1184 test wrote a git configuration file with a raw path in it, which git reads as escape sequences when the path holds a backslash. It now writes the path as an escaped configuration string.

Non-goals: the Windows fence timing failure in `test_gate_cli` (`a_killed_gates_target_tree_ends_before_older_binaries_get_in`), which predates TSK-1184 and belongs to TSK-1318; changing how messages escape backslashes.

## Outcome

After this merges, the EPC-022 line's Windows run passes the TSK-1184 tests, and the edit guard covers the operator-authority directory whichever spelling of the home it is given.

## Deliverables

- Guard change and its unit tests: `crates/codeflow-core/src/hooks/edit_guard.rs`
- Policy authority test fixes: `crates/codeflow-core/tests/policy_authority.rs`, `crates/codeflow-cli/tests/policy_authority_journey.rs`
- End-to-end guard test: `crates/codeflow-cli/tests/hooks_cli.rs`
- This record: `project-management/tasks/TSK-1400.md`

## Acceptance Criteria

- AC-1 When the guard's home is given in a spelling that normalizes to another path, the edit guard shall refuse a write to the operator-authority directory in any ASCII case under either spelling, and allow an ordinary file beside it; evidence: `the_authority_directory_is_covered_whatever_the_homes_spelling` and `agents_cannot_write_the_ssh_configuration_allow` (through the built binary) fail before and pass after on macOS.
- AC-2 On Windows, the edit guard and its tests for the Windows spellings of the home shall compile, and on macOS the tests that do not need Windows shall pass; evidence: `cargo cross-check-windows` compiles `the_authority_directory_is_covered_under_windows_spellings_of_the_home`, `the_authority_directory_is_covered_in_any_case_and_under_the_account_home` and `agents_cannot_write_the_ssh_configuration_allow`, and the last two pass on macOS at the head.
- AC-3 When a rewrite makes git use a remote other than the configured one, the TSK-1184 refusal tests shall find both URLs in the refusal as messages show them; evidence: `an_insteadof_rewrite_to_a_populated_remote_refuses_naming_both`, `a_push_rewrite_or_push_url_refuses_naming_both`, `a_rewrite_to_another_empty_repository_refuses` and `a_rewritten_empty_remote_refuses_and_a_matching_fresh_remote_pushes` pass on macOS at the head with a backslash in the path, and fail before the fix at the assertion that names both URLs (`policy_authority.rs:599`, `:624` and `:666`, `policy_authority_journey.rs:941` in the fail-before tree). (journey)
- AC-4 When a test writes a git configuration file that names a path, it shall write the path as an escaped configuration string; evidence: `a_rewrite_from_an_included_file_refuses` passes on macOS at the head with a backslash in the path, and fails before the fix with "invalid escape" (`policy_authority.rs:645` in the fail-before tree).
- AC-5 No check is weakened: no assertion is removed or loosened, and the gates named in the PR body pass at the head.
