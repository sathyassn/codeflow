# TSK-286: The deletion guard is proven against the native tools

## Description

The deletion guard judges a command by its own model of each tool's input
grammar, and where that model differs from the native tool it can allow a
command that deletes something it would refuse if typed directly
(https://github.com/sathyassn/codeflow/issues/102). PR 84 fixed the `-0`, `-d`, quoting and parallel newline cases
and judges every unmodelled xargs or parallel option as unproven; the rest
of the grammar has no native proof. The issue's comments add two
findings: `crates/codeflow-core/src/root_checkout.rs:918` maps a literal
Unix backslash in a `.gitmodules` path to `/`, and
`crates/codeflow-core/src/ids/inventory.rs:32-41` splits a remote ref at its
first slash. This task proves the guard against the native tools. Its sed
row builds on TSK-290 (lands on main in 3.1.1; the line takes it when it
merges main): TSK-290 gives git-guard one sed script reader for issue 147,
and this task's sed row proves the guards against native sed through it.
TSK-290 is not on this line, so it is not in `depends_on`.

Amended 2026-10-13 after re-reading the issue's comments. Both findings
above are this task's AC-4, and each still needs the native fixture the
comments say was not run (`root_checkout.rs:918` and `inventory.rs:37-40`
are unchanged at `main` 4226a9408). The comment from the PR 84 review says
which xargs and parallel options are to be modelled: the ones PR 84 round
19 judges unproven. The line takes 3.1.1, and with it TSK-290's sed reader
(`crates/codeflow-core/src/security/sed_script.rs`), by the merge of `main`
that this amendment's pull request names, so once that merge is on the
line the sed rows start with the other grammars. TSK-299 (planned in draft
pull request 162) changes how a nested quoted sed script is judged; the
sed rows here prove whatever reader the line holds when they run.
`ids/inventory.rs` is also read by the adopter feature epic's program
report, which builds on the corrected remote boundary.

## Acceptance Criteria

- AC-1 A differential fixture shall run each native tool on disposable
  inputs for each grammar the issue names (xargs `-L`, `-n`, `-E`, `-a`;
  parallel's option grammar; `find -print0` and `-exec`; sed scripts and
  `w`; Windows separators) and compare what it touched with the guard's
  judgment; evidence: the fixture, run on macOS and Linux. The sed rows are
  part of this task only once this line contains TSK-290, which reaches it
  from 3.1.1 through `main`; until then they are outside this task's diff,
  and the other grammars can start now. (serves EPC-022 AC-5)
- AC-2 When a command uses a grammar the guard does not model, the guard
  shall judge it unproven and refuse it; evidence: one test per unmodelled
  form. Each xargs and parallel option that PR 84 judges unproven shall
  either gain a fixture row and become modelled or stay listed as unproven
  in AC-3's table; evidence: the table rows for those options.
- AC-3 A table shall list each grammar as modelled, unproven or untested,
  and a test shall fail when a listed grammar has no fixture row;
  evidence: the table and the test.
- AC-4 `root_checkout.rs` shall keep a literal Unix backslash distinct from
  `/`, and `ids/inventory.rs` shall split a remote-tracking ref at a
  configured remote name, a name holding a slash included; evidence: a
  native submodule fixture and a native remote fixture.
- AC-5 (journey) When the installed hooks judge each bypass form from the PR 84 review
  and this issue, each shall be refused, and each allowed form shall delete
  exactly what the native tool deletes; evidence: the
  differential fixture driven through the installed hooks.
  - Amended 2026-11-02: the journey tag moved to open the criterion, where the check counts it; the wording and the serves tag are unchanged.
- AC-6 (moved from TSK-1022 AC-1) When a command deletes a configured secret store or a file inside one, the guards shall refuse it across a command-family matrix built on the existing deletion mechanisms (`security/deletion.rs`, `dangerous.rs`, `git_guard.rs`): plain `rm FILE` and `rm -f`; every recursive flag spelling (`-r`, `-R`, `-rf`, `--recursive`, split and reordered flags); `rmdir`; `unlink`; `shred` and `srm`; `find -delete` and `find -exec rm`; `xargs rm`; `parallel`; destructive `rsync` (`--delete`, `--remove-source-files`); and each launcher carrying any of these (`env`, `sh -c`, `bash -c`, `eval`, `command`, `nohup`, `exec`, `xargs`); for every store in the configured list; evidence: a matrix test of family by launcher by store through the real hook, each refusal failing before the change (`rm -rf ~/.ssh`, `echo ~/.ssh | xargs rm -rf` and `unlink ~/.ssh/id_rsa` among them).
- AC-7 (moved from TSK-1022 AC-2) When a command moves a configured secret store away (`mv ~/.ssh x`), truncates a file in one (`: > ~/.ssh/id_rsa`, `truncate -s 0`), or runs `git clean` over one, the guards shall refuse it, or the record shall state per form why it is excluded, with the reason in the PR body; evidence: a test per form, or the stated exclusion reviewed.
- AC-8 (moved from TSK-1022 AC-3) When the target is spelled by any equivalent path, the guards shall give the same verdict: `~`, `$HOME`, `${HOME}`, an absolute path, a relative path after `cd`, a variable the line assigned, a symbolic link to the store, a glob that can match it, and deleting a parent directory of the store; a target the guards cannot resolve shall refuse (fail closed); evidence: a test per spelling, each failing before the change, and an unresolved-target case that refuses.
- AC-9 (moved from TSK-1022 AC-4) When the guards refuse such a deletion, the message shall name the store and the remedy (the sanctioned way for the operator to delete it); evidence: a test asserting the rule name, the store and the remedy text.
- AC-10 (moved from TSK-1022 AC-5) When a command deletes an ordinary path, the guards shall keep allowing it in both outcomes where it is written without a run-time word: project temp files (`rm -rf ./target`) and harmless globs (`rm ./*.log`); the controls written with a leading `~`, a project temp file (`rm -rf ~/scratch/x`), a near-name (`rm ~/.sshx-notes`) and unprotected siblings of protected entries (`rm ~/.cargo/config.toml` next to the protected `~/.cargo/credentials*`; the builder picks each sibling control from `crates/codeflow-core/src/security/actions.json` and checks it is not listed), shall be allowed by git-guard and by exec-guard under `security.text_guard: relaxed`, and under the strict default exec-guard shall refuse them under `security.text_guard`; the SSH entries `~/.ssh/id_rsa.pub` and `~/.ssh/known_hosts` are protected (`actions.json:636`, `:638`) and stay in the AC-1 refusal matrix, never in the controls; evidence: allowed-control tests beside the refusals, the `~` controls under both outcomes.

Reason: TSK-397 option 2 (PR 331) makes the strict text rule the default, and PR 331's binary at `c53591264` refuses `rm -rf ~/scratch/x`, `rm ~/.sshx-notes` and `rm ~/.cargo/config.toml` in exec-guard under `security.text_guard`; `rm -rf ./target` and `rm ./*.log` pass in both outcomes.
- AC-11 (moved from TSK-1022 AC-6) Boundary with TSK-395: TSK-395 AC-1 and AC-2 own writes, copies, moves and recursive deletes of the harness settings folders (`~/.claude`, `~/.codex`, `~/.grok`); this task owns the home credential and secret stores in the configured list and adds no rule for those three folders; evidence: the builder reads both lists, records any store named in both, and the matrix test names which task owns each store.
- AC-12 (moved from TSK-1022 AC-7) (journey) The installed Claude, Codex and Grok hook commands shall refuse the planted deletions without running them; evidence: a refusal journey replaying each installed hook.
- AC-13 (moved from TSK-1022 AC-8) When a deletion form could reach a configured secret store but the guard does not model it (an unsupported option, an unknown launcher, or an input transformation it cannot read, as at `security/deletion.rs:4464`), the guards shall refuse it as cannot-verify and say so; this is separate from the opaque program-internals residual (a program that deletes on its own), which stays a named residual; evidence: tests per unmodeled option, launcher and input transformation, each refusing, and a positive control with a modeled equivalent (plain `rm -rf ./target`) that still passes; a deletion is allowed only when the guard can prove every effective target is ordinary, so a form with an input it does not model (`xargs --arg-file=paths rm -rf ./target` also takes targets from `paths`) refuses even when its visible operand looks ordinary.
