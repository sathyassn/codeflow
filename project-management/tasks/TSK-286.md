# TSK-286: The deletion guard is proven against the native tools

## Description

The deletion guard judges a command by its own model of each tool's input
grammar, and where that model differs from the native tool it can allow a
command that deletes something it would refuse if typed directly
(https://github.com/sathyassn/codeflow/issues/102). PR 84 fixed the `-0`, `-d`, quoting and parallel newline cases
and judges every unmodelled xargs or parallel option as unproven; the rest
of the grammar has no native proof. The issue's comments add two
findings: `crates/codeflow-core/src/root_checkout.rs:918` maps a literal
Unix backslash in a `.gitmodules` path to `/`, and
`crates/codeflow-core/src/ids/inventory.rs:32-41` splits a remote ref at its
first slash. This task proves the guard against the native tools. Its sed
row builds on TSK-290 (lands on main in 3.1.1; the line takes it when it
merges main): TSK-290 gives git-guard one sed script reader for issue 147,
and this task's sed row proves the guards against native sed through it.
TSK-290 is not on this line, so it is not in `depends_on`.

Amended 2026-10-13 after re-reading the issue's comments. Both findings
above are this task's AC-4, and each still needs the native fixture the
comments say was not run (`root_checkout.rs:918` and `inventory.rs:37-40`
are unchanged at `main` 4226a9408). The comment from the PR 84 review says
which xargs and parallel options are to be modelled: the ones PR 84 round
19 judges unproven. The line takes 3.1.1, and with it TSK-290's sed reader
(`crates/codeflow-core/src/security/sed_script.rs`), by the merge of `main`
that this amendment's pull request names, so once that merge is on the
line the sed rows start with the other grammars. TSK-299 (planned in draft
pull request 162) changes how a nested quoted sed script is judged; the
sed rows here prove whatever reader the line holds when they run.
`ids/inventory.rs` is also read by the adopter feature epic's program
report, which builds on the corrected remote boundary.

## Acceptance Criteria

- AC-1 A differential fixture shall run each native tool on disposable
  inputs for each grammar the issue names (xargs `-L`, `-n`, `-E`, `-a`;
  parallel's option grammar; `find -print0` and `-exec`; sed scripts and
  `w`; Windows separators) and compare what it touched with the guard's
  judgment; evidence: the fixture, run on macOS and Linux. The sed rows are
  part of this task only once this line contains TSK-290, which reaches it
  from 3.1.1 through `main`; until then they are outside this task's diff,
  and the other grammars can start now. (serves EPC-022 AC-5)
- AC-2 When a command uses a grammar the guard does not model, the guard
  shall judge it unproven and refuse it; evidence: one test per unmodelled
  form. Each xargs and parallel option that PR 84 judges unproven shall
  either gain a fixture row and become modelled or stay listed as unproven
  in AC-3's table; evidence: the table rows for those options.
- AC-3 A table shall list each grammar as modelled, unproven or untested,
  and a test shall fail when a listed grammar has no fixture row;
  evidence: the table and the test.
- AC-4 `root_checkout.rs` shall keep a literal Unix backslash distinct from
  `/`, and `ids/inventory.rs` shall split a remote-tracking ref at a
  configured remote name, a name holding a slash included; evidence: a
  native submodule fixture and a native remote fixture.
- AC-5 When the installed hooks judge each bypass form from the PR 84 review
  and this issue, each shall be refused, and each allowed form shall delete
  exactly what the native tool deletes (journey); evidence: the
  differential fixture driven through the installed hooks.
