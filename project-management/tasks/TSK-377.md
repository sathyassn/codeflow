## Review repair decisions

The primary settled the following behavior under the operator's direction to
decide from evidence. The fourth and fifth repair batches refine the same contract:

- A proven-absent registered checkout is prunable. Protect its administrative
  namespace and registered path by spelling, exclude it from live roots, and
  allow ordinary work in the remaining checkouts. Existing conflicting targets
  still refuse before policy loading. A missing commondir target with an
  existing checkout remains fail-closed, as the primary decided.
- A single literal `git worktree list` or `git worktree prune` remains available
  when discovery fails. Force removal is available for a proven-absent
  registered checkout, with both the registration and the command target
  proven absent. Compound commands do not inherit this recovery. Quoted and
  escaped recovery words require a shell whose grammar the guard recognizes.
- Shell writers, interpreter code and native edits cannot create or write under
  the common `worktrees/` namespace, including new administrative names, or
  overwrite common and linked HEAD files. Git's ordinary worktree lifecycle
  and HEAD-moving commands retain their existing responsibilities and checks.
- Complete absolute and parent-relative code literals reaching a checkout root
  refuse, including registered roots such as `.worktrees/w`. Exact `.` and `./`
  code strings stay literal fragments, so directory reads, string operations
  and heredocs remain usable. `rmtree(".")` and its node, perl and ruby
  equivalents are accepted residuals, as in 3.1.0; reconsideration belongs to
  TSK-378. Absolute own-root reads such as `os.chdir("/abs/repo")` still refuse
  as the stated cost of judging paths without interpreting calls. Ordinary
  interpreter project argv operands, bare `~` and accepted runtime
  concatenations stay unchanged.
- Interpreter bodies are judged after shell quote removal. An escaped quote
  inside double-quoted code cannot split the body into separate commands.
- A prunable registration must be a regular gitdir file, not a symlink, naming
  a path with the trailing `/.git` marker. Normalize that path before every
  absence proof. Force-removal recovery requires an absolute target without
  dot components or doubled separators and the same normalized recorded path.
  The discovery-failure exception runs only after discovery fails; healthy
  commands load policy and use the normal checks, including discard inspection.
- SEC-377-13 is accepted: an existing folder without its `.git` marker remains
  prunable and protected until prune. The primary explicitly preserved this
  case when clarifying the absent-root requirement.
- A well-formed relative registration resolving to an absent path while its
  live checkout still exists is the hidden-checkout case in TSK-379 AC-3.
  Its out-of-band discovery repair stays outside this PR.
- Grok F2, F3, F6 and SEC-377-5, plus SEC-377-10 with F2, are tracked in
  TSK-379 (EPC-022 amendment, pending). They are outside this repair.

- Validate each registration once within a hook invocation, sharing the result
  across discovery and protected-path readers by common directory. Keep all
  sibling checks and discard the snapshot when the invocation ends. Reuse the
  protected set for recursive targets and find candidates.
- Relative force removal of a proven-absent registered checkout stays refused.
  Its remedy names `git worktree prune` and the exact absolute removal form.
  Keep the bounded literal re-read in discard inspection unchanged.
- Grok R4-1 and SEC-377-14/15 are tracked for a new 3.2.0 shell-expansion task
  to be allocated in the next EPC-022 planning amendment after PR 249 lands.
  The installed 3.1.0 binary also allows R4-1 from main
  and linked cwd; the commands were judged, never executed. This batch does
  not change shell expansion.
