# TSK-314: The program report groups by class and lane

## Description

TSK-311's `codeflow report program` rolls up by epic and line, and TSK-313
gives tasks a class and a lane. This task joins them: the report gains
`--class` and `--lane` filters and rollups by class and lane, with
`unclassed` for a task without a value, and an `undeclared` bucket, naming
the ref, for a value a fetched copy carries that the home's vocabulary does
not declare (https://github.com/sathyassn/codeflow/issues/164, issue 166).
Filters filter output only, as in TSK-311. Non-goal: any check on the
values; `validate --docs` owns that (TSK-313).

## Deliverables

- the rollups and filters: the report module and `crates/codeflow-cli/src/cmd/report.rs` from TSK-311
- tests: the report CLI tests from TSK-311
- docs: `docs/cli.md`
- release note: `changelog.d/TSK-314.md`

## Acceptance Criteria

- AC-1 The report and its JSON shall roll up by class and by lane, with
  `unclassed` counted apart; evidence: a fixture with classed, unclassed
  and laned tasks and its expected rollups. (serves EPC-023 AC-2)
- AC-2 A class or lane on a fetched copy that the home vocabulary does not
  declare shall appear in an `undeclared` bucket with its ref, and never in
  a declared group; evidence: a fixture with a fork copy carrying an
  unknown class.
- AC-3 `--class` and `--lane` shall filter the output and never the
  totals; evidence: CLI tests.
- AC-4 The JSON shall keep TSK-311's `schema_version` rules: a new field
  is added under the versioning rule TSK-311 writes, and the schema test
  covers it; evidence: the schema test.
