# TSK-1394: Guard tests accept only the slow Git child refusal

## Description

The git guard runs Git children to read repository state and refuses, failing closed, when one outlives its 3 s bound. On a busy hosted runner that refusal reaches tests that expect the guard to allow a command. TSK-1318 AC-9 made one test tolerate it (`allowed_or_slow_child` in `crates/codeflow-cli/tests/hooks_cli/target_repository.rs`) and tracked the siblings once, to revisit when the other exact-pass assertions move to that helper.

The class has now failed outside that file. EPC-022 line push run 42496435944 at b85d30681, job 128781513925 (windows tests 4 of 12): `hooks_cli checkout_identity::checkout_identity_administrative_writes_refuse_before_registration` failed at `checkout_identity.rs:560`, where `git switch task/next` expected exit 0 and got 2, a git-guard refusal under rule `git.hook_integrity` reading "cannot read Git runner: cannot verify Git configuration: child exceeded 3 seconds". The tip before, ae4a89312, was green, and no member of candidate 1108a changed the test. The same job logged an install-action "bash startup failure" runner warning. So runner speed hit the guard's bound (coord/ci, 2026-11-08).

This task makes every hooks_cli test that expects an allow from a guard that may run a Git child tolerate that one refusal and nothing else, and folds in TSK-1318's nits 1 and 2. Non-goals: the guard's 3 s bound and its fail-closed refusal, which stay as they are for users; TSK-1318 nit 3 (refused commands checked by exit code only), which predates TSK-1318 and stays tracked there.

## Outcome

After this merges, a maintainer reading a red hosted Windows hooks_cli job can rely on it meaning a wrong guard answer, because a slow runner's time-bound refusal no longer fails a test that expects an allow, while any other refusal still does.

## Acceptance Criteria

- AC-1 Before any change, the builder shall list in `## Findings` every assertion in `crates/codeflow-cli/tests/hooks_cli/` that expects a guard to allow a command while the guard may run a Git child, with file:line and the assertion form it uses today; evidence: the Findings list.
- AC-2 Each assertion in that list shall use one shared helper that accepts exit 0, or a refusal whose message contains the time-bound text "cannot verify Git configuration: child exceeded 3 seconds" (`crates/codeflow-core/src/security/git_config.rs:456` and `:497` on main 7b76f5c4e), and treats every other result as a failure, including the read-or-size refusal "read failed or exceeded 3 seconds / 4 MiB" (`git_config.rs:483`) (TSK-1318 nit 2); evidence: helper tests for an allow, the time-bound refusal, the read-or-size refusal and an unrelated refusal.
- AC-3 Each test that uses the helper shall still require at least one real allow in every hook and configuration combination it runs, so a combination refused for time on every command fails the test (TSK-1318 nit 1); evidence: a deterministic test with a `git` on `PATH` that sleeps past the bound for one combination, failing on that combination.
- AC-4 The guard's 3 s bound, its fail-closed refusal and its messages shall stay unchanged; evidence: a diff that touches only test code.
- AC-5 (journey) The hooks_cli tests shall pass on the hosted Windows partitions at the task's head, and the PR body shall report per partition how many time-bound refusals the helper tolerated; evidence: the hosted job logs.
