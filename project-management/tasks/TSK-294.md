# TSK-294: A project can route dependency-audit exceptions through its own reviewed check

## Description

When the managed dependency audit fails, its advice tells the reader to
record a suppression in an `osv-scanner.toml` beside the lockfile
(`assets/base/ci/codeflow-ci.yml:920`, with the route described at
`:822-829` at v3.1.0). A project that records audit exceptions elsewhere,
such as a reviewed dependency register with an owner, an expiry and a
reason per row, must edit the managed step and reconcile that edit on every
update (https://github.com/sathyassn/codeflow/issues/149). This task adds a project exception hook, on the pattern of
the project setup hook `.codeflow/ci-setup.sh` that issue 46 added: an
optional script, read from the trusted commit, that runs after the managed
audit and may accept findings that a trusted project file records. When the
hook exists, the failure advice names it. The hook is chosen over an advice
text key because it serves both halves of the issue without a new policy
key. The 3.1.0 hardening that replaces every `osv-scanner.toml` with the
trusted commit's copy stays.

## Deliverables

- the hook and the advice: `assets/base/ci/codeflow-ci.yml`, its installed copy `.github/workflows/codeflow-ci.yml` and baseline
- tests: the managed workflow tests in `crates/codeflow-core/tests/`
- docs: `assets/base/ci/README.md`, `docs/adoption.md`
- release note: `changelog.d/TSK-294.md`

## Acceptance Criteria

- AC-1 When the trusted commit holds the project exception hook and the
  audit fails only on findings the hook accepts, the audit step shall pass
  and list each accepted finding; evidence: workflow tests with an
  accepting and a rejecting hook. (serves EPC-022 AC-10)
- AC-2 The hook and the file it reads shall come from the trusted commit,
  so a pull request that adds or changes them does not accept its own
  findings; evidence: a test with the hook changed only on the head.
- AC-3 When the hook exists, the failure advice shall name it instead of
  `osv-scanner.toml`; without it, the advice and the `osv-scanner.toml`
  route shall be as at v3.1.0; evidence: tests of both messages.
- AC-4 The CI README and `docs/adoption.md` shall document the hook, its
  inputs and its exit contract; evidence: the doc diff.
- AC-5 (journey) When a fresh project updated with the installed build adds
  the hook and a register row for one advisory, a pull request that hits that
  advisory shall pass the audit with no local edit to the managed workflow;
  evidence: a run of the managed step on a scratch repository.
