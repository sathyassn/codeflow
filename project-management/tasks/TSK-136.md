# TSK-136: headless peer runs and delegation provenance in the tools

## Description

The rule that peer seats run interactively, never headless, is prose in five
files and exec-guard does not see it; and delegation provenance (the thread
id and model of each exchange) is recorded by hand, so none of the Codex
review files holds a thread id. This task adds a headless-run rule to exec-
guard for `claude -p`, `codex exec` and `grok -p`, warn first, and makes the
delegate path record provenance itself. Scripting outside a delegation stays
allowed at the warn level. Source: guidelines strand top five item 4; Fable
challenge F10.

## Affected surfaces and interfaces

- `crates/codeflow-core/src/hooks/exec_guard.rs`; policy schema (one
  level key, default warn); `crates/codeflow-cli/src/cmd/delegate.rs` and
  `hooks/delegate_turn.rs`; the cf-delegate provenance duty text.

## Acceptance Criteria

- [ ] AC-1 When a Bash command runs `claude -p`, `codex exec` or `grok -p`,
      exec-guard shall warn with the rule and the sanctioned interactive
      path; at the block level it shall refuse; other commands are
      unaffected; evidence: `hooks_cli` tests per command, per level, and
      negatives such as `codex --version`.
- [ ] AC-2 Each delegated exchange shall record its thread id, model and
      effort in the delegation record without manual steps, and an
      unavailable value shall be recorded as unknown, never guessed;
      evidence: `delegate_cli` tests for present and missing values.
- [ ] AC-3 cf-delegate shall point to the recorded provenance instead of
      asking for manual recording; evidence: the skill diff, mirrors and
      `manifest_consistency`.
- [ ] AC-4 (journey) In a freshly scaffolded project at every tier (minimal,
      standard, full) the guard shall run in the Claude, Codex and Grok hook
      wiring at the warn default, and `codeflow update` shall keep an
      adopter's explicit level; evidence: `init_e2e`, `codex_hooks` and an
      update test.
