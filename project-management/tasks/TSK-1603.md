# TSK-1603: Every managed check has a policy level with a documented default, and the non-relaxable operations are named once

## Description

Owner: to be assigned by the Director. Staged 2026-11-23 for coord/records.

The operator's cross-cutting rule of 2026-11-23 asks that every CodeFlow
check be configurable in `.codeflow/policy.json` with sensible defaults
(block, warn or off). Most are: the key table in `docs/policy-reference.md`
(main `:60` to `:110`) gives each a level.

A safety floor is a non-relaxable operation and the decision that made it
so, not a rule id that nothing may name. Configurable activation and the
occurrence exceptions the project already authorizes stay valid. At
`origin/main` d2307063f2:

| Check | Configurable today (keep) | Non-relaxable operation (the floor) | Source |
|---|---|---|---|
| `git.path_policy` | its level (`off` removes only this gate); `git.blocked_names` `except_under` and `git.protected_paths` `allow` from the default branch | an exception from a head, a line or a working copy; a working copy adds denials only | `policy-reference.md` main `:75` to `:77` |
| `git.ignored_files`, `git.max_file_bytes` | their levels and `allow` or `except_under` from the authority | the same: no head-held exception | main `:78`, `:79` |
| `git.secret_scan` | its level at the authority (off or allow disables the scan); `.gitleaksignore` fingerprints from the trusted commit | a head lowering the level or adding its own exemption; suspension by bootstrap grace | main `:80`; "Secret-scan exemption pull requests", main `:1036` |
| `git.work_records`, `git.work_planning` | `block` or `warn` | `off`; the transition rules (Blocker, Closeout, acceptance block) always block | main `:65`, `:66` |
| `security.dangerous_commands` | nothing | any level below `block` or any approval of the destructive command class | main `:94`; the workspace contract: approval never unlocks the non-relaxable command class |
| push to a protected branch | nothing | admitting the push by any level or exemption | the protected-branch rules, recorded with their source at Findings |

The floor list is one code constant, each entry naming the operation, the
decision and its source. TSK-424 (as amended, AC-20) reads this constant
to refuse a register entry or level that would perform a floor
operation; it never refuses an entry merely for naming the check's rule.
A contract test keeps new checks from shipping without a key or a floor
entry.

The hooks' unit-test loop that asserts some rules keep `block`
(`hooks/mod.rs` main `:439` to `:452`) is a test of finding severity,
not the production rule table, and is not a source for any floor.

## Outcome

After this merges, every rule a managed check can emit maps to a policy
level key with a documented default or to a floor entry naming its
non-relaxable operation and decision; existing authorized exception
routes and activation keys work as before; and a test fails when a new
rule has neither.

## Deliverables

- the floor list as one code constant beside the policy schema (the interface TSK-424 AC-20 consumes), and its generated table in `docs/policy-reference.md`
- a contract test that collects every rule id the hooks, guards and `codeflow ci` can emit and checks each against the key table and the floor list
- level keys for any rule the inventory finds without one, at a default equal to today's behaviour
- `changelog.d/TSK-1603.md`

## Acceptance Criteria

- AC-1 Before any change, the builder shall record in `## Findings`, with file:line at the base, every rule id a managed check can emit, its level key or its reason for having none, every authorized exception route and activation key for it, and, for each floor, the non-relaxable operation and the decision that set it, cited from production code, policy reference or a decision record (never from a unit test); evidence: the Findings section, committed first.
- AC-2 Fail before: the contract test run at the base shall list each rule with neither a key nor a floor entry (or none, quoted); evidence: the base run in the PR.
- AC-3 Pass after: every rule shall map to a key or a floor entry; each new key shall default to today's behaviour so no verdict changes; evidence: the contract test and the existing tests passing unchanged.
- AC-4 The floor list shall hold each non-relaxable operation of the table above with its decision and source; an attempt to perform one (a head-held `protected_paths` exception, a head lowering `git.secret_scan`, `security.dangerous_commands` below `block`, `git.work_records: off`) shall be refused; and, with the floor check active, a legitimate authorized exception on its route as it exists at this task's base (a default-branch `blocked_names` `except_under` entry, a trusted-commit `.gitleaksignore` fingerprint) shall still apply. This task proves its floor decisions against today's authorized routes and direct floor inputs only; the comparison after migration into the register is TSK-1602 AC-5's, run once the migrator exists; evidence: one refusal test per floor operation, the two preserved-route tests on today's routes, and the generated doc table.
