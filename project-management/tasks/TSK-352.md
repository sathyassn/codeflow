# TSK-352: Gate selection uses proven candidate evidence against the task's line

## Description

Source: the gate speed discovery of 2026-10-17 (Codex peer report, ranked
change 1, at line head `eaf2ed04e932186cdd26dc4a7e5740cc553acee3`) and the
operator's request of the same day to make the verification gates fast
without losing assurance. Amended after the Codex review of PR 226
(finding F1).

Today a run with no `--since` selects every eligible target
(`crates/codeflow-core/src/testing/delivery.rs`, `select`, the "no proven
comparison base" branch). Of 239 retained run records, 139 gave that reason
and 100 were `--only` runs, so no unrestricted run has used change-based
selection. Two further gaps stop it working even with `--since`:
`green_base` needs a passed, clean, complete run at the exact base revision
with the exact config digest, and only an unrestricted full run is ever
recorded complete (`testing/gate.rs`, the `complete` computation). So a
landed merge whose tree equals the gated candidate's tree never counts,
because its revision differs. The run record's `tree` field is a digest of
the tracked snapshot, not a Git tree id, so it cannot be compared with
`git rev-parse <base>^{tree}`. A matching tree and config digest also say
nothing about the tools, platform, environment, test membership or
producer outputs a check depended on.

Outcome: quick and essential `codeflow test` runs, and the pre-push quick run,
select against the task's declared line by default and skip a target only when
recorded evidence covers the exact check that would run now. Full mode compares
only with explicit `--since`; without it every target runs for non-selective
landing evidence (security F1). Every unproven case runs and names its reason.

This task owns the evidence foundation that TSK-355 (result reuse) builds
on.

Decisions recorded here:

- **Default base.** The merge base of `HEAD` with the declared integration
  target of the task being worked on, read from the task record's
  `integration_target` (or the branch's work metadata). It is never guessed
  as `main`, never the previous commit, and never a mutable branch name
  used as evidence identity. An explicit `--since` stays authoritative and
  `--all` stays available.
- **Input classes.** Each target declares an input class in the test
  config: `content` (it reads only declared files), or `history`, `remote`,
  `time` or `external` (it reads Git history, a remote, the clock, a
  vulnerability database or another outside source). A target with no
  declared class is unclassified. Only a `content` target can ever be
  skipped; every other class, and every unclassified target, runs.
- **Per-target evidence.** The run record stores, for each executed target:
  its mode and exact command, the Git tree id, the digests of its declared
  inputs before and after it ran, the identities of the tools it declares
  (for example the rustc, cargo, nextest, node and python versions), the
  platform and architecture, evidence for the environment variables it
  declares as relevant (below), its test membership digest where it has
  one, and its producers' output digests. Missing evidence of any kind
  means the target runs.
- **Environment evidence never stores raw values.** Amended after the
  Codex confirmation review of PR 226 (finding F6). Equality evidence is
  kept apart from displayable data. Only metadata the config marks as
  audited non-secret (for example a platform or locale name) may be stored
  as a value. Every other declared environment input is stored as an
  opaque keyed fingerprint (a keyed hash under a key held outside the
  repository and the run record, so the record cannot be used to test a
  guessed value), never as its value. An environment dependency marked
  sensitive with no safe fingerprint available, or one that is undeclared
  or unclassified, makes the target ineligible for selection and reuse:
  it runs. Sensitive and fingerprint values are redacted from gate-owned
  output and reports. Audited non-secret and unclassified values remain
  unchanged in output; equality evidence never stores raw values.
- **Coverage of the check.** A target is skipped only when the qualifying
  run executed the same command in the same mode with matching evidence,
  or when the config declares a coverage relation between two commands
  (for example that full's `rust-coverage` runs the membership of
  essential's `rust-workspace`) and a test proves that relation. A full run
  is not assumed to cover quick-only or essential-only commands.
- **Qualifying run.** A passed, clean, complete full run whose recorded Git
  tree equals the base's tree and whose config digest is current, and in
  which each credited target's inputs were unchanged during its own run.
- **The landing candidate.** Selection never applies to a landing
  candidate's gate: the primary runs it with `--all`, and a run with any
  skipped or reused target is never recorded complete, so the candidate
  always executes every target.
- **Pre-push.** The pre-push quick gate uses the same selection. Its ref,
  range, authority, release preflight and checked-out-tree protections
  (`crates/codeflow-cli/src/cmd/push_set.rs`, and `run_push_targets` in
  `crates/codeflow-core/src/hooks/git_hook.rs`) are unchanged and always run.

Non-goals: declaring this repository's target inputs and classes
(TSK-353), reusing a prior target result (TSK-355), and any change to what
a complete full gate runs. Product surface: adopter-facing engine (CAP-004
test gate, the test config schema) and the pre-push hook path.

## Acceptance Criteria

- AC-1 Quick and essential `codeflow test` runs on a task branch with no
  `--since`, `--all` or `--only` shall compare against the merge base of `HEAD`
  with the task's declared integration target and print that base and its source.
  Explicit `--since` overrides that comparison and enables comparison for full
  mode. Full mode without `--since` runs every target to provide non-selective
  landing evidence (security F1). Evidence: CLI tests for quick and essential
  defaults, explicit full comparison, and full without `--since`.
  (serves EPC-022 AC-48)
- AC-2 A target shall be skipped only when it is `content` class, the
  qualifying run executed the same mode and command (or a declared and
  tested coverage relation), and its recorded tools, platform, relevant
  environment, membership, producer outputs and inputs match; a `history`,
  `remote`, `time`, `external` or unclassified target shall always run;
  evidence: a fixture with two commits of one tree (the clean merge of a
  gated candidate), one test per class, and a test that a full run does not
  cover a quick-only command without a declared relation. (serves EPC-022 AC-48)
- AC-3 Each of these shall make the target run and name the reason: a
  changed tool version, a different platform or architecture, a changed
  declared environment value, changed test membership, a changed or
  missing producer output, a mode-specific command that differs from the
  recorded one, inputs that changed during the qualifying run, missing
  evidence of any kind, an unknown declared target, unproven ancestry, no
  qualifying run, a changed config, a failed, partial, dirty, corrupt or
  legacy (no `git_tree`) qualifying record, and untracked, renamed,
  deleted, unmatched or submodule inputs; evidence: one test per case.
- AC-8 With synthetic secret markers set in declared environment inputs,
  no marker shall appear in the run record, the gate log, stdout, stderr
  or any report the gate writes, while changing such an input still makes
  the target run; an input with no safe fingerprint, or an undeclared or
  unclassified environment dependency, shall make the target run with the
  reason named; evidence: a test that greps every artifact the run writes
  for the markers, a changed-value test, and a fail-closed test.
- AC-4 A completion commit that changes only a task record shall not be an
  exact-tree hit against its parent, and it shall select every target whose
  declared inputs include that record; evidence: a fixture commit that
  changes one record.
- AC-5 A target skipped by selection shall be recorded as skipped with its
  reason and never as executed or passed, a run with any skipped target
  shall never be recorded complete, and `--all` shall execute every target;
  evidence: run record assertions, and a test that the landing command
  executes every target with a proven base present.
- AC-6 The pre-push quick gate shall use the same default selection while
  its ref, range, authority, release preflight and checked-out-tree checks
  still run on every push, including a push of several refs and a push
  whose tree it cannot check (TSK-304's cases); evidence: the existing
  pre-push tests passing unchanged, plus a test that a records-only push
  runs only the quick targets whose inputs changed.
- AC-7 (journey) With the installed build, a task branch cut from a line
  whose tip carries a passed full candidate run of the same tree shall, for
  a records-only change, run only the targets whose inputs changed, and for
  a change under `crates/` run every eligible target; after a toolchain
  version change with no file change, the Rust targets shall run; evidence:
  the three runs' output with the selection reason, the selected targets
  and elapsed time.

## Review repair decisions

The primary settled these decisions under the operator's direction after the
whole-unit and security reviews of `40a9bbf12`:

- Landing gates are non-selective. Both integration modes request all targets
  and refuse incomplete or empty gates. Default full runs execute every target.
- Skip credit is local convenience, never landing evidence. Records must be
  owned by the effective user and not group- or world-writable. An overridden
  `CODEFLOW_HOME` receives no credit. A MAC under a sandbox `denyRead` key was
  considered and deferred; the owner's mutable record is not authenticated.
- Every summary names executed and skipped counts. Any skip says "not complete".
  Strict runs fail when no target executed or candidate evidence skipped a
  requested target. The operator clarified that explicit `--only` and mode
  exclusions are not skips: `--strict --all --only X` passes when its requested
  checks execute successfully, while its full-gate evidence stays incomplete.
  CI workflow files are operator-applied and unchanged by this repair.
- Only declared `fingerprint` and `sensitive` values suppress progress and are
  redacted, including classified configured environment values. Literal, XML-,
  JSON- and URL-escaped forms are covered. Tool source reports stay untouched;
  the producing tool owns their protection. Non-secret and unclassified values
  stay intact. This clarifies AC-8's scope to reports written by the gate.
- Selection reasons omit empty separators, prefer "no qualifying run for the
  base tree" when no record matches, and name repository-local key storage as
  a cause of unavailable fingerprints. The capability rule and ADR date are
  corrected. Both managed landing skills and their mirrors name the full gate.

The primary authorized a summary-only edit to `hooks/git_hook.rs` for the
pre-push counts. Hook behavior, installed hooks, policy and project settings
remain outside this repair. The primary owns review and the landing candidate;
this repair does not complete the task.

The primary settled the second repair batch on `985d33cf8`:
