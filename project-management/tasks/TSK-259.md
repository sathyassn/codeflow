# TSK-259: A reviewer can comment on a named part of every stage the cf-present skill writes

## Description

The operator asked on 2026-09-26 that a reviewer can comment on one element
inside an agent's figure and that the comment survives a regenerated figure.
The entity model that does this is on `main` (TSK-117 to TSK-120, TSK-192,
TSK-193), but the cf-present skill still steers agents to schema 1, `present
check` is silent on a v1 stage with no caption and no named parts, and a
click on an unnamed shape shows the wrapper's `aria-label` sentence or the
stage title, then re-anchors onto the title as "Moved" after a revision.

This task makes the skill write schema 2 with named parts; adds advisory
`framing`, `entities` and `version` warnings to `present check`, `open` and
`update`, never a refusal; labels an unnamed part `Unnamed part of <title>`
with no quote, so it falls back to the block after a change; keeps a stored
shape note whose quote is the stage title off the title; gives stage
entities accessible names; and brings the architecture doc up to date,
which becomes the home of the SPC-014 rules this changes, because an
implemented spec is frozen. Design: revision 3 of the present parity design (2026-10-08, after two
cross-lineage challenges). No stored format, schema, route or ledger change.
A missing description is never a rule or a warning (operator decision
2026-10-08).

Non-goals: accessible names for grammar figures, because
`figure-grammar.mjs` is hash-pinned with the portal and the starter (a
follow-up after this lands); per-mark entities on derived figures.

## Deliverables

- skill: `assets/base/agents/skills/cf-present/` (`SKILL.md`, `references/document-authoring.md`, both example documents), its four mirrors, `.codeflow/manifest.json`
- check warnings: `crates/codeflow-present/src/document.rs`, `crates/codeflow-cli/src/cmd/present.rs`
- re-anchoring rules: `crates/codeflow-present/src/state.rs`
- accessible names: `crates/codeflow-present/src/entity.rs`
- page label rule: `crates/codeflow-present/web/src/selection.ts` and the rebuilt `crates/codeflow-present/assets/`
- fixtures and tests: `crates/codeflow-present/tests/fixtures/contract-v2/`, `crates/codeflow-cli/tests/present_cli.rs`, `crates/codeflow-present/web/scripts/`
- docs: `docs/architecture/present.md` (the changed SPC-014 rules), `CHANGELOG.md`

## Acceptance Criteria

- AC-1 When `present check --file` runs on either rewritten skill example, the system shall print no fault and no warning; each example stage shall have a title, a caption, a named node and arrow, and arrowheads in a `marker`; `SKILL.md` shall stay under 8448 bytes, and its five copies and the manifest shall agree. Evidence: a `present_cli` test, the `codeflow doctor` reading guideline, the `manifest_consistency` and `repository_update_noop` tests, `codeflow validate --docs`.
- AC-2 When `present check` runs on the operator's delivery document (schema 1, six stages), the system shall print six `framing` lines, six `entities` lines and one `version` line, each with `severity: "warning"`, a summary of `faults: 0, valid: true, warnings: 13`, and exit 0; when `open` or `update` runs on it, the system shall print the same lines to stderr and proceed; a prose v1 document shall print nothing; a v2 stage with one named box, three unnamed arrows and a marker path shall warn with the count 3; an element with `role="img"` that contains an entity shall print a second `entities` line. Evidence: `present_cli` and `document.rs` tests on fixtures under `tests/fixtures/contract-v2/check/`.
- AC-3 When a reviewer clicks a shape with no label of its own under a `figure` or `svg` that carries `aria-label`, the system shall store `element_selector.label` as the full `Unnamed part of <block label>` with no excerpt text, keep a labelled `g` ancestor's label and a `text` node's own words, and after an update that changes the stage `feedback` shall report `block_fallback`. Evidence: the `selection-browser-check.mjs` wrapper case and the updated `aria-rect` assertion; the `entity-browser-check.mjs` v1 case through `update`.
- AC-4 When a stored element note has no excerpt text and its stage changed, the system shall report `block_fallback`; when a stored shape note (`path`, `line`, `rect`, `circle`, `ellipse`, `polyline`, `polygon`, `svg`, `g`) carries an excerpt equal to the current or source block's review label, the system shall report `block_fallback`; a `text` node or the v1 frame-title `p` with the title as excerpt, and a text note quoting the title, shall still re-anchor on the quote; an entity note whose entity is gone and whose quote equals the title shall fall back to the block. Evidence: re-anchor tests in `contract_tests.rs` over `tests/fixtures/contract-v2/reanchor/`, each failing before the change.
- AC-5 While the keyboard walk is on a v2 stage, each entity that sets no `aria-label` of its own shall have a computed accessible name equal to its label, an author `aria-label` or `role` shall be left in place, and a `g` entity shall carry `role="group"`. Evidence: `entity-browser-check.mjs` reading the accessibility tree; an `entity.rs` test on `annotate_stage`; the security review verdict.
- AC-6 When the docs are validated, `docs/architecture/present.md` shall state the shipped anchor order, the server's entity checks, the responses ledger and the check severities, and shall be the current home of the SPC-014 B1 step 2, B3 step 4, B11 and I5 rules this task changes, since SPC-014 is implemented and frozen; the changelog entry shall say stored bytes are unchanged and that the displayed anchor of a title-quote shape note changes. Evidence: `codeflow validate --docs`; `codeflow ci` accepting the range with SPC-014 untouched; the review diff.
- AC-7 (journey) When the delivery document written per the v2 skill is opened with the built binary, a node and an arrow pinned by pointer and keyboard shall show `entity_anchored` and `entity_reanchored` across an `update`, and an unnamed part pinned on a v1 copy shall show the block fallback. Evidence: `npm run check:entities` extended, with the browser and width recorded.
- AC-8 When the present suites run, `npm run check`, `check:browser`, `check:entities`, `check:matrix`, `check:forms`, `cargo test -p codeflow-present`, `cargo test -p codeflow-cli --test present_cli`, the manifest and scaffold tests and `codeflow test --mode quick` shall pass, and the present distribution shall be rebuilt with its checksum. Evidence: the PR's Testing section.
