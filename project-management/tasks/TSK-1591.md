# TSK-1591: The identity reader reads the host names macOS and Linux keep

## Description

Owner: to be assigned by the Director. Staged 2026-11-23 for coord/records.

SPC-018 R-19, host row. A machine has more names than `gethostname`
returns. On macOS: `ComputerName` (often "<Name>'s MacBook Pro"),
`LocalHostName` (the Bonjour name) and `HostName`, held by the system
configuration. On Linux: the static, pretty and transient names
`hostnamectl` reports where systemd runs, else `/etc/hostname` and
`PRETTY_HOSTNAME` in `/etc/machine-info`.

Risk to settle in Findings: the system configuration on macOS is served
by `configd`; a sandbox that denies that service makes the source
unreadable, which at `block` refuses every commit in that session
(SPC-018 R-23). AC-1 measures it under each sandbox CodeFlow ships; if a
shipped sandbox denies it, the builder stops and reports to the owning
coordinator before choosing a route.

## Outcome

After this merges, the reader returns every host name SPC-018 R-19 names
on macOS and Linux, through the same opaque type and read, absent or
unreadable classification as TSK-1590.

## Deliverables

- `crates/codeflow-core/src/privacy/identity/host_macos.rs` and `host_linux.rs` (new), behind `cfg(target_os)`
- docs: the per-platform rows; `changelog.d/TSK-1591.md`

## Acceptance Criteria

- AC-1 Before any change, the builder shall record in `## Findings`, with sources, how each name is read on each platform without a shell (the SystemConfiguration API or `scutil --get` as a fallback; the systemd hostname D-Bus interface or `hostnamectl`), and whether each read succeeds under the Claude sandbox preset and the Codex profile CodeFlow ships, and the wall-clock cost of each read (median of five cold and five warm runs) on Linux and on Apple silicon macOS, for TSK-1595's final speed run (SPC-018 R-9a); evidence: the Findings section with the probe and timing output.
- AC-2 On macOS, `ComputerName`, `LocalHostName` and `HostName` shall be read, an unset `HostName` shall be absent, and a denied service shall be unreadable; evidence: tests on macOS with a stand-in for the denied case.
- AC-3 On Linux, the static, pretty and transient names shall be read with systemd, and `/etc/hostname` and `/etc/machine-info` without it; evidence: tests in a container with and without systemd, or stand-ins named under not_verified.
- AC-4 Every `cfg(unix)`-only or platform-only item shall carry its `cfg`, and the Windows build shall compile with the source absent; evidence: the dead-code read GATE-RULES.md describes, and the hosted Windows build.
