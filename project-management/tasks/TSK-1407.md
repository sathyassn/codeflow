# TSK-1407: The SQLite dependency carries no known advisory

## Description

The hosted dependency audit (osv-scanner, the "security review" check) now fails on RUSTSEC-2026-0459, an advisory against `libsqlite3-sys` 0.35.0 (CVSS 6.8, fixed in 0.39.0), first seen on PR 735 in run 42599893446 on 2026-11-09. `libsqlite3-sys` comes in only through `rusqlite` 0.37 (`Cargo.toml:33`, bundled feature), used by `codeflow-core`. The policy sets the audit to block, so every pull request into the EPC-022 line and into `main` fails until the lock carries a patched version. This task upgrades `rusqlite` to a release whose `libsqlite3-sys` is 0.39.0 or later and makes the API changes that upgrade needs. Non-goal: an ignore entry or advisory exemption; suppressing the advisory would weaken the check. It is a standalone task: its record rides in its own build pull request, because a records-only filing fails the same audit and cannot land first.

## Outcome

After this merges, the dependency audit passes on the EPC-022 line with no suppression of this advisory, so pull requests into the line are no longer blocked by it; `main` is repaired when the twin pull request lands there.

## Deliverables

- the upgrade: `Cargo.toml`, `Cargo.lock`, and any `codeflow-core` source the `rusqlite` API change touches
- evidence: the audit run and the changelog review in the pull request body

## Estimate

- Grade: Medium; band: Medium (2 to 4 h); moved: none
- Split: not needed; one outcome
- Basis: one dependency bump across two `rusqlite` minor versions with a bundled SQLite, possible API changes in the store code, and the audit and test proof; graded by coord/records under issue 334's bands. The builder re-scores at claim.

## Acceptance Criteria

- AC-1 `Cargo.lock` shall carry `libsqlite3-sys` 0.39.0 or later, reached by upgrading its parent `rusqlite` in the workspace `Cargo.toml`, with every API change that upgrade needs made in the source; evidence: `cargo tree -i libsqlite3-sys` before and after, and the diff.
- AC-2 The dependency audit shall pass with no new ignore entry, filter or advisory exemption for this advisory in any `osv-scanner.toml`, in `.codeflow/audit-exceptions.sh` or any register it reads (the exemption route `.github/workflows/codeflow-ci.yml` supports), or in other audit configuration, and the audit's enforcement levels (`git.security_review`, `git.dep_audit`) shall stay as they are; existing unrelated suppressions are unchanged; evidence: a local osv-scanner run over `Cargo.lock` (or `cargo audit`) reporting no advisory, and the hosted "security review" check green on the pull request.
- AC-3 The behaviour that uses SQLite shall be unchanged; evidence: the targeted tests of every module that uses `rusqlite` passing, `codeflow test --mode quick`, clippy with `-D warnings`, `cargo fmt --check`, `RUSTDOCFLAGS="-D warnings" cargo doc`, and the Windows cross-check.
- AC-4 The pull request body shall summarise the `rusqlite` and `libsqlite3-sys` changelogs between the old and new versions (breaking changes, the bundled SQLite version, any change to defaults such as feature flags) and say how each relevant change was handled; evidence: the body section, checked by the reviewer against the published changelogs.
