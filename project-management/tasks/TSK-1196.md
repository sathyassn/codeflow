# TSK-1196: A project supplies its own brand design through the one token source

## Description

Operator decision d8 (2026-11-02): a project can supply its own brand design. CodeFlow's design is the default. A project supplies brand tokens (palette, type, logo) through TSK-1162's one token source, and the colour floors of TSK-1162 AC-4 warn on a weak brand palette. It is shown with one sample brand on both surfaces. `TSK-1096:136` puts brand design out of scope, which is why this is its own task.

TSK-1162 already warns, never refuses, at project-token import when a pair of ink roles falls under its colour-deficiency floor (`crates/codeflow-present/src/config.rs`); this task adds the brand input to that import and the generator, and uses the same warning for a weak brand palette. The floors it applies are those TSK-1162 records in its AC-5 findings.

Non-goals: changing CodeFlow's default design, and the site mode (TSK-1194).

## Outcome

after this merges, a project can supply its own palette, type and logo through the one token source and see them on `cf-present` and the docs portal, while a project that supplies none keeps CodeFlow's design.

## Deliverables

- the brand input and its schema: the token source and generator of TSK-1162, and `crates/codeflow-present/src/config.rs` (project-token import)
- the brand warning wired to the TSK-1162 colour floors
- one sample brand and its captures on both surfaces
- docs: the skills' description of brand input
- release note: `changelog.d/TSK-1196.md`
