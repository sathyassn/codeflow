# TSK-449: Push and CI gates stop rerunning unchanged work

## Description

The push and hosted CI rerun checks on unchanged work. Pre-push runs
`codeflow validate --docs` and every quick target at HEAD on each push
(`crates/codeflow-cli/src/cmd/push_set.rs:235-237`), the git rules ask for a
durability push after every unit, and no target declares `input_class`, so the
skip in `crates/codeflow-core/src/testing/delivery.rs:559-566` never fires;
`run_everything` includes `*.md`. Hosted CI builds the release binary in six
jobs, reruns fmt, clippy, rustdoc and doctests on Windows, and fails the
verdict jobs on purpose for a draft to `integration/**`
(`.github/workflows/codeflow-ci.yml:109, 445, 727`). Source: the operator
approved process audit of 2026-10-23 (line numbers at `c9993bcf3`).

Scope: (1) pre-push keeps `codeflow ci`, the conflict check and the secret
scan; `validate --docs` (already run by `codeflow ci` as `work.valid_graph`)
and the quick targets leave it, and the quick gate is cited in the PR Testing
section when the PR is made ready. (2) The input
declarations (`input_class`, narrower `run_everything`, per-target inputs)
belong to open TSK-353, not this task: reuse stays conditional on complete
matching check identity from a qualifying run, and documentation-reading
targets such as `docs-validation` keep running on docs edits. This task adds
only the pre-push and tier changes. (3)
`prose-exhaustive`, `read-benchmark`, `present-browser` and
`present-binary-delta` move from the landing-candidate full gate to the weekly
schedule and the release candidate. (4) The release binary is built once per
workflow. (5) Windows drops fmt only. (6) Draft PRs get a neutral verdict and
`ready_for_review` runs the exact head. (7) The shipped template runs
essential on PRs and full on the protected branch and schedule.

Dispatch contract: TSK-449 depends on TSK-331 (it removes the quick targets
from pre-push after TSK-331's heavy-work admission and pre-push wait criteria
have landed, and amends those pre-push criteria as moot in its PR). The
Testing-citation check at ready is TSK-451's (AC-8). The shipped template's
dependency-audit step is TSK-450's; this task owns the rest of
`assets/base/ci/**`. `push_set.rs` is this task's alone; the release-impact
preflight call there stays unchanged because the evaluator interface does not
change (TSK-451).

Non-goals: the full gate on the landing candidate, its lock, the coverage
floor, the secret scan, gitleaks, the trusted `codeflow ci` job and the human
merge are unchanged. Risk: a neutral or skipped check passes a required-check
rule, so a ready PR needs its run at the exact head (AC-6). This task owns the
`test_gate_on_push` entry (its meaning changes with (1)) in both policy files
and its row in `docs/policy-reference.md`; TSK-450 owns every other line.

Effect on adopting projects: shipped hooks stop running the test gate on push
(a push is backup, not a gate); the shipped workflow runs essential on PRs and
full on the protected branch and schedule; a project that relied on the
pre-push gate runs `codeflow test --mode quick` itself.

Owned files: `push_set.rs`, the pre-push stage of
`crates/codeflow-cli/src/cmd/git_hook.rs` and
`crates/codeflow-core/src/hooks/git_hook.rs`, `testing/delivery.rs`,
`.codeflow/test-config.json`, `assets/base/testing/**`,
`.github/workflows/codeflow-ci.yml` (all but the dependency-audit step of the
security review job, which TSK-450 owns), `.github/workflows/codeflow-policy.yml`,
`assets/base/ci/**` (except the dependency-audit step, TSK-450), `scripts/gate-parity.py`, `scripts/ci-reuse.py`. Guidance
that tells builders to cite the quick gate is TSK-452.
