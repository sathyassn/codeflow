# TSK-449: Push and CI gates stop rerunning unchanged work

## Description

The push and hosted CI rerun checks on unchanged work. Pre-push runs
`codeflow validate --docs` and every quick target at HEAD on each push
(`crates/codeflow-cli/src/cmd/push_set.rs:235-237`), the git rules ask for a
durability push after every unit, and no target declares `input_class`, so the
skip in `crates/codeflow-core/src/testing/delivery.rs:559-566` never fires;
`run_everything` includes `*.md`. Hosted CI builds the release binary in six
jobs, reruns fmt, clippy, rustdoc and doctests on Windows, and fails the
verdict jobs on purpose for a draft to `integration/**`
(`.github/workflows/codeflow-ci.yml:109, 445, 727`). Source: the operator
approved process audit of 2026-10-23 (line numbers at `c9993bcf3`).

Scope: (1) pre-push keeps `codeflow ci`, the conflict check and the secret
scan; `validate --docs` (already run by `codeflow ci` as `work.valid_graph`)
and the quick targets leave it, and the quick gate is cited in the PR Testing
section when the PR is made ready. (2) Deterministic targets declare
`input_class = content` and `run_everything` narrows to build inputs. (3)
`prose-exhaustive`, `read-benchmark`, `present-browser` and
`present-binary-delta` move from the landing-candidate full gate to the weekly
schedule and the release candidate. (4) The release binary is built once per
workflow. (5) Windows drops fmt only. (6) Draft PRs get a neutral verdict and
`ready_for_review` runs the exact head. (7) The shipped template runs
essential on PRs and full on the protected branch and schedule.

Non-goals: the full gate on the landing candidate, its lock, the coverage
floor, the secret scan, gitleaks, the trusted `codeflow ci` job and the human
merge are unchanged. Risk: a neutral or skipped check passes a required-check
rule, so a ready PR needs its run at the exact head (AC-6). This task owns the
`test_gate_on_push` entry (its meaning changes with (1)) in both policy files
and its row in `docs/policy-reference.md`; TSK-450 owns every other line.

Effect on adopting projects: shipped hooks stop running the test gate on push
(a push is backup, not a gate); the shipped workflow runs essential on PRs and
full on the protected branch and schedule; a project that relied on the
pre-push gate runs `codeflow test --mode quick` itself.

Owned files: `push_set.rs`, the pre-push stage of
`crates/codeflow-cli/src/cmd/git_hook.rs` and
`crates/codeflow-core/src/hooks/git_hook.rs`, `testing/delivery.rs`,
`.codeflow/test-config.json`, `assets/base/testing/**`,
`.github/workflows/codeflow-ci.yml` (all but the dependency-audit step of the
security review job, which TSK-450 owns), `.github/workflows/codeflow-policy.yml`,
`assets/base/ci/**`, `scripts/gate-parity.py`, `scripts/ci-reuse.py`. Guidance
that tells builders to cite the quick gate is TSK-452.

## Acceptance Criteria

- AC-1 When a push is made, the pre-push hook shall run `codeflow ci` over the range, the conflict-marker check and the secret scan, and no `validate --docs` step or test-config target, and shall still refuse a staged-secret shape and a protected-branch push. Evidence: tests in `crates/codeflow-cli/tests/hooks_cli.rs` that fail before and pass after, and a durability push timed without the quick gate (command and wall time in the PR Testing section). (serves EPC-022 AC-125)
- AC-2 When a code PR is made ready, its Testing section shall cite `codeflow test --mode quick` for the head tree, `codeflow ci` shall report a missing citation at the level of the existing Testing check, and a draft shall owe none. Evidence: a `codeflow ci` classification test with a draft case and a ready case without the citation. (serves EPC-022 AC-125)
- AC-3 When `codeflow test` selects targets, deterministic targets shall declare `input_class = content`, `run_everything` shall list build inputs only, an unchanged tree shall skip the declared targets, a docs-only edit shall select none of them and a changed input shall run them. Evidence: `delivery.rs` unit tests for the three cases, the test-config schema check, and `codeflow test --mode quick` run twice with the second run's skip output in the PR. (serves EPC-022 AC-125)
- AC-4 When the landing candidate runs the full gate, `prose-exhaustive`, `read-benchmark`, `present-browser` and `present-binary-delta` shall not run there, shall run on the weekly schedule and the release candidate, and `scripts/gate-parity.py` shall refuse a target in neither place. Evidence: test-config mode-membership tests and `scripts/test_gate_parity.py`. (serves EPC-022 AC-125)
- AC-5 When the CI workflow runs, it shall build the release binary once and share it, and the Windows job shall run clippy, doctests and the test partitions but not fmt. Evidence: `scripts/test_gate_contracts.py` counts the build steps (one) and lists the Windows steps (no fmt); the hosted run shows one build job. (serves EPC-022 AC-125)
- AC-6 When a PR is a draft, the verdict jobs shall end neutral, `ready_for_review` shall start a run at the exact head, and a ready PR shall never satisfy its required checks with a neutral or skipped verdict for its head. Evidence: a workflow contract test of the draft and ready conditions, and this task's own PR showing the neutral draft verdict and the green ready run at its head. (serves EPC-022 AC-125)
- AC-7 When an adopter takes the shipped CI template, it shall run essential on PRs and full on the protected branch and schedule, and an existing adopter test-config shall keep working. Evidence: the template contract test and `crates/codeflow-cli/tests/adopter_fit.rs`. (serves EPC-022 AC-125)
- AC-8 When a builder pushes a durability commit, makes the PR ready and lands it (journey), the push shall complete with `codeflow ci` only, the quick gate shall be cited at ready, the hosted run at the head shall pass, and the candidate full gate shall keep its other targets. Evidence: this task's own branch, PR and the full-gate output on the candidate. (journey) (serves EPC-022 AC-125)
