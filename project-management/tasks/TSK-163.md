# TSK-163: the delegated Claude turn rules read once, in the adapter

## Description

TSK-138 found that the delegated Claude lifecycle is stated twice on the
Codex host lane: the Lifecycle section of cf-delegate's
`resources/lane-lifecycle.md` restates the launch sequence, turn detection
and the sibling Stop-hook preflight that `claude-turn-completion.md` (the
turn adapter) owns, and the copies have drifted. The lane runs the
preflight "Before delivery", the adapter "Before launching"; launch is the
moment that matters, because a session loads its hooks when it starts.
Both readers are the same agent on a non-Claude host at successive
moments of one task, so one home serves them. This task states each of
those rules once, in the adapter, and leaves the lane its pointer to the
adapter, the Herdr variant and its evidence section. It does not change
the lifecycle's behaviour, the Claude host path (which loads neither
file), or the `codeflow delegate` commands.

## Affected surfaces and interfaces

  `resources/claude-turn-completion.md` (SPC-013 R-118 cf-delegate row,

- `crates/codeflow-core/tests/delegate_doctrine_contract.rs` (the two
