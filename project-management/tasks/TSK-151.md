# TSK-151: pipeline example names a resolved selector

## Description

The shipped pipeline workflow's per-stage model example still names a model
(`{ build: 'sonnet' }` on this line; `opus` after TSK-041 on EPC-014). Under
the model catalog (TSK-085, ADR-0069) an instruction names no selector, and
the catalog scan fails as soon as the example names a catalog selector, which
is what happened when the two lines met in the release rehearsal. This task
makes the example the placeholder `<selector>` and says the selector comes
from `codeflow models resolve`. It is the pipeline part of the cancelled
TSK-081, whose scope left this line; TSK-041's criterion was amended to the
model-neutral form on EPC-014. Non-goal: the rest of TSK-081's instruction
rewrite, and TSK-041's own test, which the release branch adapts as
release-integration work (TSK-010).

## Affected surfaces and interfaces

`assets/base/claude/workflows/pipeline.workflow.js`, its dogfood copy
`.claude/workflows/pipeline.workflow.js` and the pristine baseline; the
user-owned manifest record for the dogfood copy; a pin in
`crates/codeflow-cli/tests/orchestration_contract.rs`. The file is
user-owned in adopter projects, so `codeflow update` never rewrites an
adopter's copy; only new installs and the pristine baseline change. CAP-010.

## Acceptance Criteria

- AC-1 When the scaffold ships `pipeline.workflow.js`, the per-stage model example shall name the placeholder `<selector>` and say the selector comes from `codeflow models resolve`, in the shipped asset, the dogfood copy and the pristine baseline; evidence: an `orchestration_contract` test that pins the placeholder and the command in all three copies.
- AC-2 The pipeline example shall name no model: no catalog selector and not the stale `sonnet`; evidence: the new test fails on `sonnet`, and `real_tree_scans_find_no_catalog_selector_or_stray_retired_selector` passes over the changed files.
- AC-3 (journey) On a project scaffolded at the full tier by this line's binary, the installed `.claude/workflows/pipeline.workflow.js` shall show the placeholder and the command; evidence: `codeflow init` into a temporary project and the installed file's example line.
