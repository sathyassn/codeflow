# TSK-382: An amendment note under a criterion keeps its closing journey tag

## Description

Issue: #199. R-50 counts a `(journey)` tag only where it opens or closes a criterion. CodeFlow's own amendment practice adds an indented sub-bullet under a criterion ("- Amended <date> ..."). The checker reads the sub-bullet as part of the criterion, so a criterion whose head line ends with `(journey)` stops counting once amended (`crates/codeflow-core/src/workgraph/acceptance.rs:2190-2210`). The effect spreads: `work.journey_criterion` then blocks every adopter-facing task, including one that serves the epic's journey criterion. The workaround is to move the tag to the start. This repository deferred the issue on 2026-10-17; the operator's release rule of 2026-10-18 brings it into 3.2.0 because it blocks work.

Outcome: **an amendment note (a dash sub-bullet whose first word is exactly `Amended` or `Moved` and whose next word is a `YYYY-MM-DD` date) and its wrapped continuation are left out of tag reading, while every other sub-bullet stays criterion text, so a closing tag on the head line counts, and a refusal names the hiding sub-bullet or note when a tag is still unreadable.**

The rule must keep substantive continuation lines of a criterion (wrapped text) part of the criterion, and keep direct and served journey semantics unchanged. The `serves` and `(after release)` tags follow the same rule.

Added by the EPC-022 amendment of 2026-10-18 under the operator's release decision of that day (workspace `RELEASE-PLAN.md`, 2026-10-18 operator decision).

## Acceptance Criteria

- AC-1 When a task or epic criterion's head line ends with `(journey)`, `(serves EPC-NNN AC-n)` or `(after release)` and an amendment note follows (an indented dash sub-bullet whose first word is exactly `Amended` or `Moved` and whose next word is a `YYYY-MM-DD` date), the tag shall count, the note and its wrapped continuation shall be left out of tag reading, and every other sub-bullet shall stay criterion text; evidence: unit tests for task and epic criteria, failing before the change, and the two review inputs: the undated `- Moved files shall stay listed in the report.` hides the head tag and the refusal names that sub-bullet, and a dated note followed by `- The command shall pass the suite before release (journey).` counts that later tag and does not keep the head `(after release)`. (serves EPC-022 AC-78)
- AC-2 A criterion wrapped over several lines with no sub-bullet shall keep its whole text, and a tag in the middle of the text shall still not count; evidence: tests.
- AC-3 When a tag is still hidden, the R-50 refusal shall name the criterion and the note that hides it, and say to move the tag to the start; evidence: a test of the message.
- AC-4 (journey) With the installed build, `codeflow ci` over a scratch project whose epic journey criterion carries an amendment sub-bullet shall accept a task that serves it; evidence: the journey output.
