# TSK-447: Cargo takes the fixed tokio release

## Description

Advisory RUSTSEC-2026-0386 affects `tokio` 1.53.1, which `Cargo.lock`
resolves; the fix is in 1.53.3. The dependency audit in the security review
job (osv-scanner, policy `git.dep_audit=block`) now fails on every pull
request on the EPC-022 line. This task moves `tokio` to 1.53.3 with
`cargo update -p tokio --precise 1.53.3` and nothing else, so the lockfile
change stays minimal. It adds no audit suppression, because a fixed release
exists. Effect on adopting projects: none, since the lockfile is not shipped.
Non-goal: other dependency upgrades.

## Deliverables

- the lockfile fix: `Cargo.lock`
- the release note: `changelog.d/TSK-447.md`
- any SBOM or pin file the lockfile change touches, if a check requires one

## Acceptance Criteria

- AC-1 When `Cargo.lock` is read, it shall resolve `tokio` at 1.53.3, the diff shall change only the `tokio` entry and any entry the precise update itself requires, and osv-scanner shall report no RUSTSEC-2026-0386 and no suppression shall be added. Evidence: `git diff Cargo.lock`, and osv-scanner on `Cargo.lock` before and after.
- AC-2 When the workspace is built and checked from the committed tree, it shall build and the targeted tests shall pass. Evidence: `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings`, rustdoc with `-D warnings`, and `codeflow test --mode quick`.
