# TSK-1370: Any other model family counts as a cross-family review

## Description

CodeFlow's shipped instructions disagree about who may give a cross-family review. Many places say a Codex review is required, call the Claude and Codex primaries "the standing pair", require "both seats approve", or record reduced assurance whenever Codex is missing, even when Grok reviewed.

The operator decided on 2026-11-06 (11:5x, relayed by the Director): "on this yes review and resolve conflicting docs/skills and such". The decision: a review or plan challenge by any model family other than the author's counts as cross-family; Codex is the preferred cross-family seat, not a required one; reduced assurance means no other family was available, so only the same-family fallback ran. The workspace contract already states it in "Seats and models".

This task makes the skills, agents, rules, managed `AGENTS.md` and docs say the same thing, and changes the shipped routing policy's `default_review` from `standing-pair` to `cross-family`, with its Rust check and tests. Unchanged: Grok's limits and ADR-0075 D3 (a Grok seat never builds), the ban on headless seats, same-family review never counting as cross-family, and the security attacker lens, now "another family's attacker lens, Codex preferred". ADRs, changelog history, verification records, and evaluation fixtures and cases kept as history stay as written. The Director added the catalog routing to this task on 2026-11-06: in `current-ensemble.json`, the cross-family participants of `independent-plan`, `unit-review`, `body-review` and `design-and-editorial-review` are relative to the author and list the eligible seats outside the author's family in preference order, Codex first, then Grok. `codeflow models resolve` prints that order, the host takes the first seat a live probe finds available, an absent author gets a reason that the author lineage is required, and resolve reports reduced assurance only when no other-family seat has an eligible version. `computer-use-qa` keeps Codex and Claude, because Grok has no harness in this catalog that can run it; `resources/routing/design.md` states that exception. A review seat is not a builder, so ADR-0075 D3 holds: Grok fills no build or design duty.

## Outcome

After this merges, an agent or adopter reading any CodeFlow skill, agent, rule or doc gets one rule: any other model family satisfies cross-family review and the plan challenge, Codex is preferred, and reduced assurance is recorded only when no other family was available.
