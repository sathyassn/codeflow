# TSK-1057: The policy authority cannot be weakened by a direct ref write

## Description

This is a planning draft accepted from the TSK-397 design note, revision 4.1, Part C (pull request 331), where it is unit U4 (authenticated policy authority). The note called the unit 3.3.0; the release is 4.1.0. Part C is accepted as planning drafts only: the criteria below are drafts, and this unit takes its own whole-unit review when it is built. Part C decisions (i) to (v) apply: (i) explicit non-secret enforcement-file arguments are allowed on a qualified host under attested `W-enforcement`, and the secret-read classes override, never a file name; (ii) a patch update invalidates a record, because exact executable digests bind it and a changed binary is `Unknown` until the operator re-runs the ceremony; (iii) managed settings are a design requirement for qualification, not a vendor fact; (iv) no exclusion matcher ever, so a non-empty `excludedCommands` disqualifies and route A+ is dropped; (v) the ceremony runs through the Bash tool, never the `!` prompt, and its evidence is receipts, not operator attention.

`landed_policy` reads the landed policy from a remote-tracking ref, and a direct write to `refs/remotes/*` or `packed-refs` can weaken it. This unit keeps a baseline copy of the landed policy and enforces the stricter of the two. A copy is only as sound as its source, so the baseline is bound to an independently authorized repository, authority and exact commit, and only a command behind an enforced boundary, not a name or a flag, creates or replaces it.

Edges: depends on TSK-397, whose H-5 change denies `~/.codeflow/authority/` in 3.2.0 and so protects the baseline written there, as it protects TSK-1054's receipts. TSK-1055 (U2) depends on this unit, because the general run-time rule relaxes only after it has landed.

Non-goal: a sandbox deny on `refs/remotes` (AC-4).

## Outcome

after this merges, an operator can rely on the landed policy even if an agent rewrites a remote-tracking ref to a weaker one.

## Acceptance Criteria

- AC-1 A baseline of the landed policy shall be kept under `~/.codeflow/authority/`, bound to the repository (canonical common git dir and remote identity), the authority (the protected branch and the host it is read from) and the exact commit id and policy digest, and `landed_policy` shall enforce the stricter of the ref's policy and the baseline. Only a `codeflow` command behind an enforced boundary shall create or replace it: the design shall name the mechanism (for example, refusal when any ancestor process is a harness session, together with the directory deny from TSK-397) and state what it cannot stop; a command name or flag is not a boundary. Initialization shall read the policy by a fresh fetch of the authority's protected branch, never from the local tracking ref, and show the operator the commit and digest to confirm. Replacement shall accept only a descendant commit of the bound one on the same repository and authority, or an explicit operator reset that is recorded; evidence: unit tests of the comparison and the binding, and a test that an agent-side write to the directory or a run of the command from inside a session is refused.
- AC-2 A test shall rewrite `refs/remotes/origin/main` to a weaker policy and show that the stricter policy is still enforced; fail-before and pass-after.
- AC-3 The audit of `landed_policy.rs:67-81` (the fallback to `HEAD` or the working copy when no tracking ref is populated) shall state whether an agent can reach that state, and shall close it if so; evidence: the audit record and, when closed, a test.
- AC-4 No sandbox deny on `refs/remotes` shall be added, because the baseline replaces it; evidence: the settings diff in the PR.
- AC-5 The baseline states shall behave as follows: missing for a repository that was never initialized, behaviour unchanged with a doctor note; missing for one that was initialized, malformed, or mismatched (another repository or authority), the policy check blocks; stale (the ref's policy is a descendant of the baseline's commit), the stricter of the two is enforced and doctor names the refresh; a ref whose commit is not a descendant of the baseline's, the baseline is enforced; evidence: one test per state.
- AC-6 The following attacks shall each fail: poisoned initialization (the tracking ref is weakened before the first run, so initialization yields the authority's stronger policy or refuses), an unauthorized refresh (from inside a session, to a non-descendant commit, or to a weaker policy at a descendant), and replay of a baseline from another repository or authority; evidence: one test per attack, alongside the post-initialization ref-rewrite test of AC-2.
