# TSK-1057: The policy authority cannot be weakened by a direct ref write

## Description

This is a planning draft accepted from the TSK-397 design note, revision 4.1, Part C (pull request 331), where it is unit U4 (authenticated policy authority). The note called the unit 3.3.0; the release is 4.1.0. Part C is accepted as planning drafts only: the criteria below are drafts, and this unit takes its own whole-unit review when it is built. Part C decisions (i) to (v) apply: (i) explicit non-secret enforcement-file arguments are allowed on a qualified host under attested `W-enforcement`, and the secret-read classes override, never a file name; (ii) a patch update invalidates a record, because exact executable digests bind it and a changed binary is `Unknown` until the operator re-runs the ceremony; (iii) managed settings are a design requirement for qualification, not a vendor fact; (iv) no exclusion matcher ever, so a non-empty `excludedCommands` disqualifies and route A+ is dropped; (v) the ceremony runs through the Bash tool, never the `!` prompt, and its evidence is receipts, not operator attention.

`landed_policy` reads the landed policy from a remote-tracking ref, and a direct write to `refs/remotes/*` or `packed-refs` can weaken it. This unit keeps a baseline copy of the landed policy that only an operator-run command writes, and enforces the stricter of the two.

Edges: none. TSK-1055 (U2) depends on this unit, because the general run-time rule relaxes only after it has landed.

Non-goal: a sandbox deny on `refs/remotes` (AC-4).

## Outcome

after this merges, an operator can rely on the landed policy even if an agent rewrites a remote-tracking ref to a weaker one.

## Acceptance Criteria

- AC-1 A baseline copy of the landed policy shall be kept under `~/.codeflow/authority/`, written only by an operator-run `codeflow` command, and `landed_policy` shall enforce the stricter of the ref's policy and the baseline; evidence: unit tests of the comparison and a test that an agent-side write to the directory is refused.
- AC-2 A test shall rewrite `refs/remotes/origin/main` to a weaker policy and show that the stricter policy is still enforced; fail-before and pass-after.
- AC-3 The audit of `landed_policy.rs:67-81` (the fallback to `HEAD` or the working copy when no tracking ref is populated) shall state whether an agent can reach that state, and shall close it if so; evidence: the audit record and, when closed, a test.
- AC-4 No sandbox deny on `refs/remotes` shall be added, because the baseline replaces it; evidence: the settings diff in the PR.
