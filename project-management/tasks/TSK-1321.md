# TSK-1321: The Windows test plan needs no measurements to stay runnable

## Description

The Windows test partitions and the Linux coverage shards placed tests by measured times in `scripts/windows-test-times.json` and `scripts/coverage-test-times.json`. Those files go stale as tests are added: on coord/ci's estimate at PR 587's head 425795db8, the Windows filterset limit is reached at about 440 new `codeflow-core` tests, and the 10 percent unmeasured-share check fails at about 595 unmeasured tests, about six days at the recent rate.

This task removes the measurements. nextest's `hash:M/N` partitioning places a test by the hash of its name, so there is nothing to refresh. The same change computes the `windows` verdict from the jobs' results, keeps the reduced Windows tier on the event and base alone, and bounds a hung test on the hosted Windows partitions.

## Outcome

After this merges, the Windows partitions run nextest `hash:M/16` from the one archive and the Linux coverage shards run `hash:M/2`, both with no measured data, so a new or renamed test never makes either plan stale, and the `windows` verdict is computed from the jobs' own results.

## Deliverables

- the workflow change, as an operator script: `coordination/scripts/operator/apply-tsk1321-workflows.sh` (workspace repository)
- the check that every listed test ran once: `scripts/partition-check.py`, `scripts/test_partition_check.py`
- the pins and controls: `scripts/gate-parity.py`, `scripts/test_gate_parity.py`, `scripts/test_windows_tier.py`
- the hosted Windows profile: `.config/nextest.toml`
- the description of the plan: `docs/architecture.md`, `docs/releasing.md` ("Where CI suites run")

- the daily Linux coverage and its reader: `scripts/windows-daily.py`, `scripts/coverage-merge.py --total-file`, `scripts/test_windows_daily.py`
