# TSK-1321: The Windows test plan needs no measurements to stay runnable

## Description

The Windows test partitions and the Linux coverage shards placed tests by measured times in `scripts/windows-test-times.json` and `scripts/coverage-test-times.json`. Those files go stale as tests are added: on coord/ci's estimate at PR 587's head 425795db8, the Windows filterset limit is reached at about 440 new `codeflow-core` tests, and the 10 percent unmeasured-share check fails at about 595 unmeasured tests, about six days at the recent rate.

This task removes the measurements. nextest's `hash:M/N` partitioning places a test by the hash of its name, so there is nothing to refresh. The same change computes the `windows` verdict from the jobs' results, places the CI suites by event and base as the operator decided on 2026-11-05 (ADR-0097), and bounds a hung test on the hosted Windows partitions.

## Outcome

After this merges, the Windows partitions run nextest `hash:M/16` from the one archive and the Linux coverage shards run `hash:M/3`, both with no measured data, so a new or renamed test never makes either plan stale, and the `windows` verdict is computed from the jobs' own results. Each suite runs where the operator placed it (2026-11-05, ADR-0097): a pull request into an integration line runs only the short checks; line pushes, pull requests into main and the weekly run keep the full Linux and Windows suites; and the daily run runs them on main and each active line. A parity check holds the maintainer page's placement table, the ADR's and the workflows to each other.
