# TSK-1321: The Windows test plan's measurements are refreshed before they go stale

## Description

The Windows test plan places tests by the measured times in `scripts/windows-test-times.json`, written by `scripts/windows-partitions.py measure` from the JUnit reports of named green runs. TSK-1319 (PR 587) fixes the filterset overrun that stopped PR 552's Windows proof and refreshes the data once (its AC-6). The data goes stale again as tests are added. On coord/ci's estimate at PR 587's head 425795db8, the filterset limit is reached at about 440 new `codeflow-core` tests, and the 10 percent unmeasured-share check fails at about 595 unmeasured tests, about six days at the recent rate. No open task refreshes the data.

This task makes the refresh routine. A scheduled or triggered job measures from named green runs and reports how close the plan is to each limit, and the refreshed file lands through a normal reviewed pull request before either limit is reached. It builds after TSK-1319 lands, on its script and data; TSK-1319's record is not on the line yet, so its `depends_on` edge is added when it lands. The daily exact-SHA Windows run (TSK-1242) is a natural source of green runs once it exists, but this task does not wait for it. Non-goals: the limit values (TSK-1319 AC-4 keeps them) and the placement rules.

## Outcome

After this merges, the Windows plan's measurements are refreshed before an author on the line meets either limit, and the line's maintainers see the remaining headroom without running the script by hand.

## Deliverables

- the refresh job or trigger: `.github/workflows/` and `scripts/windows-partitions.py`
- the tests: `scripts/test_windows_partitions.py`
- the description of the refresh and the headroom report: the script's help and `docs/`, where the Windows plan is described

## Acceptance Criteria

- AC-1 A report shall state the plan's headroom against each limit (filterset characters against FILTERSET_LIMIT, unmeasured share against UNMEASURED_SHARE) on the current listing, and shall flag when either falls inside a margin the builder records with its reason; evidence: unit tests and the report on the real listing.
- AC-2 On a schedule or trigger, a job shall produce refreshed measurements from named green runs of the target line and offer them as a pull request or a downloadable file, never a direct write to the line; the job holds only the permissions that needs, the PR it opens is never auto-merged, and it lands through the line's normal review; evidence: the workflow and one real run, named by run id.
- AC-3 The refresh shall refuse input it cannot trust: a run that is not green, is cancelled or is from another repository or line, a missing or unreadable report, and a run not named by id; evidence: a test per refusal.
- AC-4 A refresh shall not change what runs: across all partitions every listed test is selected exactly once before and after, and `drift` passes on the refreshed data; evidence: a test that compares the selected sets, and `drift` output before and after on the real listing.
- AC-5 (journey) A refresh from real green runs on the line, landed through a reviewed pull request, shall leave the next Windows run of the line inside every limit; evidence: the refresh run id, the PR, and the next Windows run's partition summary.
