# TSK-1027: A review seat on macOS has a sanctioned route to drive a browser

## Description

Issue #355 (CodeFlow 3.1.1, macOS, a Codex review seat in Herdr). Under
the managed `cf-guard` profile, Chromium does not start: both the system
Chrome and Playwright's headless shell exit with
`bootstrap_check_in org.chromium.Chromium.MachPortRendezvousServer:
Permission denied (1100)`. A UI review that needs the reviewer to drive a
browser then falls back to a capture the author's host runs, which the
reviewer can only recheck by hash, so the live checks are not independent.

Read on the line tip `7172229aa`: the limitation is known and stated in
the shipped config (`assets/base/codex/config.toml:13-18`: Playwright's
Chromium did not start under `cf-guard`, `cf-builder` or `:workspace`
because the sandbox denies its Mach port rendezvous; it starts
unsandboxed). No managed guidance gives a review seat a sanctioned route
to run browser checks. The issue's observation was not re-run here.

Outcome: **a review seat on macOS can drive a browser against the
reviewed head itself, through one documented route that does not widen
the seat's file or network access, and a review that cannot use it says
so as reduced assurance.**

Options and the choice:

- Allow the Mach registration in `cf-guard`. Not chosen as the default:
  whether a Codex permission profile can express a Mach allowance is not
  established, and a Mach service allowance in a read-only reviewer
  sandbox is an IPC surface outside the file and network rules the
  profile states. AC-1 establishes the facts; if a narrow, named
  allowance exists and the security review accepts it, it may be the
  route.
- Run the browser outside the seat's sandbox as a lane-owned browser
  server started for the reviewed head, which the review seat drives
  over its own lane socket. This reuses TSK-437's per-seat socket
  allowance, and the reviewer issues every interaction itself. Chosen
  unless AC-1 finds a sound profile allowance. A lane socket controls who
  connects, not what the connected browser can do (TSK-437 states that a
  browser server can read files the browser reaches and take raw DevTools
  commands), so this route needs its own boundary: the browser process
  runs in its own sandbox, or behind a broker that passes only the
  automation commands the review needs, with file reads limited to the
  served reviewed head and a scratch profile, network limited to the
  local server under review, and downloads and file writes refused. The
  seat's own denies being unchanged does not prove that boundary; AC-2's
  negative canaries do.
- A host-executed capture with a hashed report stays the documented
  fallback and is recorded as reduced assurance, never as an independent
  live check.

## Acceptance Criteria

- AC-1 Whether a Codex permission profile on the supported release can allow Chromium's Mach rendezvous without other access, and whether a lane browser server reached over a lane socket works from a `cf-guard` seat, shall be established by native probes on macOS and recorded with exact commands and results; evidence: the research note. (serves EPC-022 AC-135)
- AC-2 By the route AC-1 settles, a `cf-guard` review seat on macOS shall load a page served from the reviewed head, run a keyboard walk and take a screenshot; the route shall define the browser's own filesystem and network boundary in the transport guidance; and through that route, negative canaries shall fail: a `file://` read of a synthetic denied file outside the served tree, raw DevTools `Page`, `Runtime` and `Network` commands that read such a file or reach a forbidden destination, a navigation or fetch to a destination outside the local server, and a download or file write; the seat's direct denies (a write to the worktree, a read of `~/.ssh`) shall also still fail, but they do not satisfy this criterion alone; evidence: the native canary output per case. (serves EPC-022 AC-135)
- AC-3 The transport guidance shall state the route, its setup per lane, and the reduced-assurance wording for a review that used a host capture instead; evidence: the doc diff.
- AC-4 (journey) In a scratch adopter project on macOS, a Codex review seat shall review a UI change using the route and cite its own browser evidence in the verdict; evidence: the journey output.
