# TSK-1020: codeflow test reads a named test config

## Description

`codeflow test` reads its targets only from `<repository>/.codeflow/test-config.json`
(`crates/codeflow-core/src/testing/gate.rs`). PR 337 (TSK-1001) needs the
gate's targets and commands to come from the base revision: a codeflow built
from the base, in a job that runs no pull request code, reads the base's test
config from a side directory while the pull request's checkout stays the code
under test. Overwriting the checkout's config in place would make the pull
request's own tests read the base config. This task adds
`codeflow test --config <path>`: the run reads that file and only that file,
with no fallback to the repository's config or to stack detection, and binds
its evidence to that file's bytes. A path that is missing, unreadable, a
symbolic link or not a regular file is refused before any target starts.
Non-goals: changing the default config location, `codeflow test setup`, or
any workflow (PR 337 wires the gate).

## Deliverables

- the option and its read: `crates/codeflow-cli/src/cmd/test.rs`, `crates/codeflow-core/src/testing/{gate,delivery}.rs`, `crates/codeflow-core/src/testing/config/mod.rs`
- tests: `crates/codeflow-cli/tests/test_gate_cli.rs`
- docs and release note: `docs/test-gate.md`, `changelog.d/TSK-1020.md`

## Acceptance Criteria

- AC-1 When `codeflow test --config <path>` runs, it shall take its targets and execution settings from that file only, whatever the repository's `.codeflow/test-config.json` holds or whether it exists, and shall not fall back to stack detection. Evidence: `test_gate_cli` tests where the repository config's target fails or is absent and the named config's target runs. (journey)
- AC-2 When the named path is missing, a directory, a symbolic link (to a valid config included) or unreadable, `codeflow test` shall refuse with a non-zero exit before any target starts. Evidence: `test_gate_cli` tests for each case, each also proving no target ran.
- AC-3 When `--config` is not given, `codeflow test` shall behave as before. Evidence: the existing `test_gate_cli` suite passes unchanged.
