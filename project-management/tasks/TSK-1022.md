# TSK-1022: Deleting a configured secret store is refused

## Description

Source: the Claude security review of PR 346 (TSK-1002), finding S10, saved as `target/review-TSK-1002-security-02.md` in the `guard-bypass-classes` worktree. Severity medium, CWE-284, OWASP A01, confirmed by the reviewer. The gap predates PR 346: the line base allows the same commands.

Evidence: the guards allow `rm -rf ~/.ssh`, `echo ~/.ssh | xargs rm -rf` and `unlink ~/.ssh/id_rsa`. Home secret stores are protected from reads and writes but not from deletion, so an agent session can destroy keys and credentials the operator cannot recreate.

Outcome: **a command that deletes a configured secret store, or a file inside one, gets a refusal that names the store and its remedy, in every deleting spelling the guards read, while ordinary deletions stay allowed.**

Order: build this on top of TSK-1002 (PR 346), which reshapes the same guard code. TSK-1002 is not on the line yet, so `depends_on` cannot name it; add `depends_on: [TSK-1002]` once PR 346 lands.

Remedy direction from the review: a deletion rule for the configured secret stores under `security.dangerous_commands` or an operator-owned level. The builder settles which of the two with evidence and records the choice.

Non-goal: a deletion built at run time that no guard can read stays a named residual, as the other guard rules state.

## Deliverables

- Deletion rule for configured secret stores: `crates/codeflow-core/src/security/`
- Guard tests per spelling, each failing before the change: `crates/codeflow-cli/tests/`
- Documentation of the rule and its remedy: `docs/`

## Acceptance Criteria

- AC-1 When a command deletes a configured secret store or a file inside one, the guards shall refuse it for each of `rm -r`, `rm -rf`, `rmdir`, `unlink`, `find -delete`, `xargs rm` and a launcher-wrapped `rm`, for every store in the configured list; evidence: guard tests per spelling and per store through the real hook, each failing before the change (`rm -rf ~/.ssh`, `echo ~/.ssh | xargs rm -rf` and `unlink ~/.ssh/id_rsa` among them).
- AC-2 When the guards refuse such a deletion, the message shall name the store and the remedy (the sanctioned way for the operator to delete it); evidence: a test asserting the rule name, the store and the remedy text.
- AC-3 When a command deletes an ordinary path (`rm -rf ./target`, `rm -rf ~/scratch/x`, `rm ~/.sshx-notes`), the guards shall keep allowing it; evidence: allowed-control tests beside the refusals.
- AC-4 (journey) The installed Claude, Codex and Grok hook commands shall refuse the planted deletions without running them; evidence: a refusal journey replaying each installed hook.
