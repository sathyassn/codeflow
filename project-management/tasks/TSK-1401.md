# TSK-1401: The clone creation check judges only the paths clone writes

## Description

TSK-379 (complete, PR 260) made the guards refuse Git-native creation in
enforcement directories under `git.hook_integrity`; its record says both
hooks must "continue to refuse protected clone destinations". The
creation check that carries that rule judges every operand of
`git clone`, the source included
(`crates/codeflow-core/src/hooks/git_guard.rs:6379-6413` at the line's
d8274e43e: `:6396` checks every word and option value, `:6407-6408`
resolves each non-option operand as a path). It resolves those operands
with no URL handling (`integrity_shell_path`, `git_guard.rs:3977`).

Effect, from a read-only diagnosis by a coord/ci Worker on 2026-11-09:
the same local source gets different verdicts depending on how it is
spelled.

- A plain-path spelling of a local bare repository is refused under
  `git.hook_integrity`. The source's own folder is read as a repository
  that owns enforcement files (its HEAD, config and hooks), through
  `repo.rs:568`, `edit_guard.rs:972-986` and `edit_guard.rs:1270`, and
  the refusal reaches the user through `git_guard.rs:2543-2546`. A clone
  only reads its source, so this refusal protects nothing.
- The `file://` and `file://localhost` spellings of the same source
  resolve to a path that names nothing, and are allowed.
- The installed 3.1.0 build has none of this code and allows both.

The task narrows the TSK-379 creation check for `git clone` to the
paths clone writes, and reads the source and `--reference` values with
Git's own URL rules, so every spelling of one local repository gets one
verdict. `git init` and `git worktree add` keep their current check.

```text
git [-C dir] clone [options] <source> [<destination>]
        |
        +-- source, --reference, --reference-if-able
        |     read with Git's URL rules (plain path, file://,
        |     file://localhost -> one path); read, never a creation target
        |
        +-- written: destination (given, or the directory Git
        |   derives, placed in the starting directory -C selects),
        |   --separate-git-dir, and the template copy, which lands
        |   in the new git directory
        |     -> creation check (git.hook_integrity), unchanged
        |
        +-- cannot tell which operand is the destination -> refuse
```

Non-goals:

- The repository discovery refusal for a bare repository whose folder is
  named `.git` (`repo.rs:249-256`, "reports no work tree; its checkout
  enforcement cannot be verified") is not changed. It is a fail-closed
  read of a repository the guard cannot place, and it still applies
  wherever the guard discovers the repository a command runs in or
  writes to. A clone source reaches it today only because the source is
  judged as a creation target; after this task the source is read, not
  judged, so a source in that shape follows the new rule. Its verdict
  before and after is one of AC-1's fixtures, so the change is visible.
- The program-running clone options (`--upload-pack`, `--config` and the
  others `runners/catalog.rs` lists for clone) keep their checks.
- Git-guard allowing `git clone <url> ~` while exec-guard refuses it
  stays the division of duties TSK-379 disclosed.

The derived destination is the directory Git creates: exactly the name
`git_url_basename` returns (Git 2.54.0 `dir.c:3272-3383`, the whole
function), placed in the starting directory `-C` selects. With no
destination operand, `builtin/clone.c:1069` calls it with the bundle
flag (`:100`, `:132-136`) and the bare flag, which `--mirror` also sets
(`:1034-1036`). The function does more than take the last component.
In order, it:

- skips the scheme, then drops userinfo through the last `@` before the
  first separator (`dir.c:3281-3295`);
- strips trailing separators and whitespace, then a trailing `/.git`
  (`:3300-3307`);
- drops a trailing numeric port when what is left has a `:` and no `/`
  (`:3326-3333`);
- takes the last component, splitting on separators and `:`
  (`:3341-3344`);
- strips `.bundle` for a bundle and `.git` otherwise, then appends `.git`
  for `--bare` and `--mirror` (`:3349-3359`);
- turns each control character into a space, collapses each run of
  whitespace into one space, and removes leading and trailing spaces
  (`:3360-3381`).

Separators and character classes are Git's own: `/`, plus `\` on
Windows (`compat/win32/path-utils.h:9`); whitespace is tab, line feed,
carriage return and space (`ctype.c:21-23`). A raw last component can
therefore be an ordinary name while the directory Git creates is an
enforcement directory.

Chosen rule: the builder ports `git_url_basename` whole and the check
judges its result. The guard does not instead refuse every source that
carries userinfo or a port with no destination operand, because the
ordinary `git@host:org/repo.git` form carries userinfo and refusing it
would block the most common clone. It fails closed: when the port cannot
produce Git's name, because Git would stop with "No directory name could
be guessed" (`dir.c:3314-3316`, `:3352-3354`) or the guard cannot read
the source, the guard refuses (AC-4).

`humanish` (`hooks/git_guard/runners.rs:1536-1541`) covers only part of
this rule, so it is not reused as it is; `starting_directory`
(`runners.rs:995-1002`) already folds every `-C`.
`git/remote_identity.rs:33-55` already reads a plain path and a
`file://` URL as the same local transport and can be reused for the
source.

### Threat and why the narrowed check keeps it

The threat is a clone that writes into an enforcement directory: a
destination, a separate git directory or a template copy that lands in
an enforcement directory the creation check refuses (`.git`, `.claude`,
`.codeflow`, `.codex`, `.grok`, `.agents` and `.github`,
`git_guard.rs:6546-6555`) or in an existing repository's hooks directory
(`edit_guard.rs:972-986`), which would let a session plant hooks,
settings, agent instructions or workflows. Only those written paths
can carry that threat. A clone reads its source and its reference
repositories and writes nothing there, so judging them as creation
targets adds no protection, and it splits the verdict by spelling.
Judging every written path, including the directory Git derives from
the source and places in the starting directory, and refusing whenever
the destination cannot be placed, keeps the protection whole.

## Outcome

After this merges, an agent session can clone a local repository by any
spelling Git accepts and gets one verdict for all of them, and a clone
whose destination, separate git directory or template copy would land in
an enforcement directory is still refused.

## Acceptance Criteria

- AC-1 Every spelling of one local source repository shall get the same verdict as its `file://` twin: an absolute path, a relative path, `./`, `~/`, a trailing `/`, a relative path under `git -C <dir>`, `<checkout>/.git`, and `--reference` and `--reference-if-able` given as a plain path; a bare repository whose folder is named `.git` is a fixture too, with its verdict before and after stated. Evidence: guard tests, one per spelling, each paired with its `file://` and `file://localhost` twin, the path forms refused before at d8274e43e and allowed after, the twins allowed in both.
- AC-2 A clone whose written destination lands in an enforcement directory the creation check refuses at d8274e43e (`.git`, `.claude`, `.codeflow`, `.codex`, `.grok`, `.agents` and `.github`, `git_guard.rs:6546-6555`) or in an existing repository's hooks directory shall stay refused under `git.hook_integrity`, whatever the source's spelling. The destination judged is the directory Git creates: a given destination, or exactly the name `git_url_basename` returns (Git 2.54.0 `dir.c:3272-3383`, every step listed in the Description), placed in the starting directory `-C` selects. Evidence: guard tests per directory, each with a given and a derived destination and each with a plain-path and a `file://` source; `--bare` and `--mirror` fixtures judged on the directory Git creates; a bundle source whose Git-derived directory is an enforcement directory while its name with the suffix is not (refused); a clone whose starting directory is an enforcement directory and whose derived name is ordinary (refused); one fixture per reduction, each with no destination operand, a raw last component that is an ordinary name and a Git-derived directory that is an enforcement directory, all refused: userinfo (`ssh://me@.claude`, raw `me@.claude`, Git creates `.claude`), a port (`ssh://.github:2222`, raw `2222`, Git creates `.github`), a control character or whitespace (a last component of a tab followed by `.agents`, Git creates `.agents`; and `.grok` followed by a trailing space, Git creates `.grok`), and a trailing `/.git` (`/srv/mirror/.codex/.git`, raw `.git`, Git creates `.codex`); and a control, `git@github.com:org/repo.git` with no destination operand, which carries userinfo and derives the ordinary `repo` (allowed).
- AC-3 A clone with `--separate-git-dir` or a template copy that lands in a protected path shall stay refused under `git.hook_integrity`. Evidence: guard tests for `--separate-git-dir` into each protected directory, and for a template given by `--template` whose copy lands in the new repository's git directory inside a protected path.
- AC-4 When the guard cannot tell which operand of a clone is the destination (an option it cannot classify as taking a value or not, more operands than clone takes, or an operand it cannot read), or when there is no destination operand and its port of `git_url_basename` cannot produce Git's name (Git would stop with "No directory name could be guessed"), it shall refuse under `git.hook_integrity`, naming the literal destination form it accepts. Evidence: guard tests per case, each refused, including a source that reduces to no name (`ssh://me@`), with a plain two-operand clone as the control.
- AC-5 The pull request and `## Findings` shall record the baseline: each fixture of AC-1 to AC-4 judged by the installed 3.1.0 build and by the line's binary at d8274e43e, beside its verdict after the change. Evidence: the table, with each binary's version line.
- AC-6 (journey) In a scratch adopter project with the installed build, an agent session shall clone a local bare repository by plain path and by `file://` with one verdict for both, and shall be refused a clone into `.github` given directly and through a derived name; evidence: the journey output in the pull request body.
- AC-7 The pull request shall state, in class words, the threat the narrowed check keeps (a clone that writes into an enforcement directory) and why judging only the written paths keeps it, and shall name this as a narrowing of the TSK-379 creation rule; evidence: the pull request body.
