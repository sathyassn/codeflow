# TSK-1363: An open task's dependency missing from the declared task graph fails validation

## Description

Record `depends_on` edges can be missing from every epic graph, and `codeflow
validate --docs` does not flag it (the graph-gap finding of 2026-11-05,
`coordination/coordinators/capabilities/reviews/pr596-610-opus-criteria.md:480-490`).
This task adds that check: where a task's epic, or the epic holding its
line's graph, declares a fenced `TASK_GRAPH vN` block, an open task's edge
that no such block holds is refused. The criterion was added to TSK-1186 on
2026-11-05; the records follow-up after PR 638 (Director ruling, relayed by
coord/records) moves it here, because it reads the task graph rather than
record markers and has its own parser and fixtures.

Non-goals: the serves-tag parser and the record-marker sweep (TSK-1186), and
the `areas` field (TSK-1362). Edges of closed tasks are not checked.

## Outcome

After this merges, a person who adds a `depends_on` edge to an open task gets a `validate --docs` refusal naming the edge and the graph to add it to, whenever the task's epic or its line declares a task graph.

## Deliverables

- the graph coverage check, beside the existing `validate --docs` graph checks in `crates/codeflow-core/src/validate/`, with its fixtures
- the list of what `validate --docs` checks in `task-graph.md` (`cf-model-orchestrator/resources/task-graph.md:101-104`), which AC-1 makes stale
- release note: `changelog.d/TSK-1363.md`

## Acceptance Criteria

- AC-1 When a task's epic, or the epic holding its line's graph, declares a graph (a fenced block headed `TASK_GRAPH vN`; a mention in prose or `TASK_GRAPH: N/A` is not one), `codeflow validate --docs` shall refuse an open task's `depends_on` edge found in no fenced block of either graph, naming the edge and the graph to add it to: the line's graph when the epic declares `parent_line`, else the task's epic. A task with no epic and an epic with no declared graph shall not be refused; evidence: a fixture that fails before and passes after for each refusal, a regression fixture for each case not refused, and `validate --docs` green on this repository.
  - Moved 2026-11-05 from TSK-1186 AC-9, text unchanged, by the records follow-up after PR 638 (Director ruling, 2026-11-05: the graph check is its own outcome). TSK-1186 AC-9 had it from the graph-gap finding of that day (`coordination/coordinators/capabilities/reviews/pr596-610-opus-criteria.md:480-490`).
