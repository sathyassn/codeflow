# TSK-328: The present close test is reliable under host load

## Description

`present_cli::close_ignores_other_processes_with_unreadable_command_lines`
(`crates/codeflow-cli/tests/present_cli.rs`) failed once in the TSK-283
essential run 6558afd8 (`target/s2-essential-9f-present-failed.log` in the
TSK-283 worktree) and passed alone and in its suite. The failure was
`present close` refusing with "browser process group exists without its
verifiable leader" (`crates/codeflow-present/src/browser.rs`, the macOS
`process_identity` path). The test registers a stand-in browser (`sh -c
'sleep 120 & wait'` in its own process group), drops it, which kills the
group and waits only for the leader, and then runs `present close`. The
close treats a missing leader as gone only when the rest of the group is
also gone within `LEADERLESS_GROUP_EXIT_WAIT`, two seconds. On macOS a
group member that has exited but is not yet reaped still answers the signal
probe (`process_group_holds_only_exited_members` can tell only on Linux), so
the killed `sleep` member can outlast the wait while the host is busy.

That cause is a hypothesis: the failure was seen once, in a full gate run
beside other work. The task confirms or refutes it, then makes the test
reliable. The sibling test
`show_after_the_browser_exited_ignores_unreadable_command_lines` builds the
same fixture and gets the same check. Non-goal: lengthening a product
timeout only to hide the race. If the cause is a product race (a leaderless
group that is gone a moment later), the fix may be in `browser.rs`; if it is
the fixture, the fix is the test.

## Deliverables

- the diagnosis: the cause and its evidence in the pull request (the reproduction under load and the measured group lifetime)
- the fix: `crates/codeflow-cli/tests/present_cli.rs`, and `crates/codeflow-present/src/browser.rs` only if the cause is a product race
- release note: `changelog.d/TSK-328.md`, only if the product changes

## Acceptance Criteria

- AC-1 The cause of the failure shall be found and stated with evidence,
  and a repeatable reproducer shall exist whichever way it is found: a
  command that fails the test with the logged message under CPU and process
  load at a stated rate; or, when the diagnosis is a trace of the group's
  members showing the unreaped member that outlasts the wait, a fixture
  that reproduces that state on demand (for example a group member held
  unreaped past the wait) and fails the test every time it is applied;
  evidence: the reproducer, the failure rate or the every-time result
  before the change, and the trace, in the pull request. (serves EPC-022
  AC-25)
- AC-2 After the fix, `close_ignores_other_processes_with_unreadable_command_lines`
  and `show_after_the_browser_exited_ignores_unreadable_command_lines` shall
  pass in every run of the AC-1 reproducer: for a load reproducer, a number
  of runs the pull request states and justifies against the observed
  failure rate; for a fixture, every application of the fixture, plus a
  stated number of unloaded runs; evidence: the run counts and the output.
  (serves EPC-022 AC-25)
- AC-3 The fix shall not remove what the tests pin: a non-UTF-8 or
  over-64 KiB command line of another process shall still be ignored by the
  scan, and a real browser group without its leader shall still be
  refused; evidence: the other `present_cli` and `browser.rs` tests pass
  unchanged, and removing the unreadable-process stand-ins from the test
  is shown to change what it checks. (serves EPC-022 AC-25)
- AC-4 When the full `present_cli` suite runs under the same load as AC-1,
  it shall pass (journey); evidence: the suite output under load, and a
  clean `codeflow test --mode quick`. (serves EPC-022 AC-25)
