# TSK-398: Binding anchors resolve only remote-tracking refs

## Description

Source: PR 243 (TSK-375) security review, 2026-10-18, finding F3 (low, pre-existing). `crates/codeflow-cli/src/cmd/ci.rs:2350-2359` tries `origin/<b>` then `<b>` with rev-parse. A local branch named `origin/main` (`refs/heads/origin/main`) shadows `refs/remotes/origin/main`, so bare `codeflow ci` and pre-push can take an author-made local commit as the protected binding anchor, against TSK-275's rule that a local-only branch never counts. PR CI is unaffected, because target metadata decides there.

Outcome: **binding anchors resolve only fully qualified remote-tracking refs, so a local branch can never stand in for the protected branch.**

First added to EPC-023 (4.1.0) on 2026-10-18; moved to EPC-022 (3.2.0) the same day after the Codex review of PR 249, under the operator's rule that every security gap and every defect that forces an adopter workaround or blocks work belongs in 3.2.0.

## Deliverables

## Acceptance Criteria

- AC-2 Every anchor lookup shall use `refs/remotes/<remote>/<branch>` spelled in full; evidence: a search recorded in the PR and tests for each caller.

## Closeout

Binding anchors read exact refs: a local branch or tag named `origin/main`,
or one whose full name is `refs/remotes/origin/main`, never stands in for the
remote-tracking ref in `codeflow ci`, the pre-push hook, the status verbs or
`epic new --integration`. Codex approved at
9aac8fab8fc0fa0faab6cb70d88ffc034dd40872 and Grok 4.7 approved the same
product code except the final `is_branch_name` fix, which Codex confirmed.

The task was reopened after the first completion because the Codex review at
6fdf8a3295454e33cd5bdc6c2a6569570221193a found three majors that the Grok
rounds missed: the pre-push protected fallback still guessed a missing full
ref, valid CI branch names such as `release@2026` were discarded, and a full
`refs/remotes/upstream/main` was rewritten to origin. That acceptance is kept
below as superseded.

Review decisions (primary): the CI base variables are author-controlled, since
the author can pass any `--base`, pre-push ignores them and hosted CI passes an
exact commit id. Their protection is exact lookup and Git's branch-name rules,
not rewriting names, so the round 2 to 4 normalization was replaced. A value
starting with `refs/` is read exactly as written, `origin/<b>` reads
`refs/remotes/origin/<b>`, and any other name reads `refs/remotes/origin/<b>`
then `refs/heads/<b>`, each exactly. `@{-N}`, which Git expands to an earlier
checkout's branch, is refused. The local protected branch stays the fallback
when the remote-tracking ref is absent. Landing, its candidate gate and the
merge remain with the primary.
