# TSK-398: Binding anchors resolve only remote-tracking refs

## Description

Source: PR 243 (TSK-375) security review, 2026-10-18, finding F3 (low, pre-existing). `crates/codeflow-cli/src/cmd/ci.rs:2350-2359` tries `origin/<b>` then `<b>` with rev-parse. A local branch named `origin/main` (`refs/heads/origin/main`) shadows `refs/remotes/origin/main`, so bare `codeflow ci` and pre-push can take an author-made local commit as the protected binding anchor, against TSK-275's rule that a local-only branch never counts. PR CI is unaffected, because target metadata decides there.

Outcome: **binding anchors resolve only fully qualified remote-tracking refs, so a local branch can never stand in for the protected branch.**

Added to EPC-023 (4.1.0) by the amendment of 2026-10-18: the operator's release decision of that day puts lower-severity review follow-ups in 4.1.0 (workspace `RELEASE-PLAN.md`, 2026-10-18 operator decision).

## Deliverables

- fully qualified anchor resolution: `crates/codeflow-cli/src/cmd/ci.rs` and any other anchor lookup found by a search
- tests: CLI tests with a local `origin/main` branch
- release note: `changelog.d/TSK-398.md`

## Acceptance Criteria

- AC-1 With a local branch `refs/heads/origin/main` pointing at an author commit, bare `codeflow ci` and pre-push shall anchor on `refs/remotes/origin/main`; evidence: tests, failing before the change. (serves EPC-023 AC-28)
- AC-2 Every anchor lookup shall use `refs/remotes/<remote>/<branch>` spelled in full; evidence: a search recorded in the PR and tests for each caller.
- AC-3 (journey) With the installed build, a scratch adopter clone holding the shadowing branch shall get the same verdict as a clean clone; evidence: the journey output.
