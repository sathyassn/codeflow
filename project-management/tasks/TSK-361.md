# TSK-361: A test reports skipped or incomplete when its scenario did not run

## Description

Source: the two test integrity audits of 2026-10-17 (Codex and Claude Fable
5.1, both read-only at line head `eaf2ed04e932186cdd26dc4a7e5740cc553acee3`).
Both found no faking or sabotage. Both found tests that report a pass when
the scenario they name did not run.

Sites that return early and pass when a prerequisite is missing, merged
from both audits:

- `crates/codeflow-cli/tests/live_eval_pack.rs:22`: `CODEFLOW_EVAL_HOLDOUT`
  unset, which is always the case in CI; CAP-013 cites this test.
- `crates/codeflow-cli/tests/hooks_cli.rs:4847` and `:4918`: the
  permission probe still reads the file (for example as root), so the
  unreadable-state and unreadable-task-home refusals are never proven.
- `crates/codeflow-cli/tests/hooks_cli.rs:3792`: installed git lacks
  reftable.
- `crates/codeflow-cli/tests/release_journey.rs:402`,
  `crates/codeflow-core/src/release_local.rs:203` and
  `crates/codeflow-core/src/integrate.rs:1097`: `python3` missing.
- `crates/codeflow-core/src/hooks/git_guard.rs:14741`, `:14845`, `:15077`
  and `:15162`: bash or zsh missing.
- `crates/codeflow-core/tests/project_baselines_resolve.rs:218` to `:230`:
  no repository or a shallow clone.
- `crates/codeflow-core/src/git/mod.rs:426`,
  `crates/codeflow-core/src/testing/structural/mod.rs:553`,
  `crates/codeflow-core/src/workgraph/light_paths.rs:491` and
  `crates/codeflow-core/src/workgraph/layout.rs:472`: the filesystem
  refuses a non-UTF-8 name (the first also hides any other setup error).
- `crates/codeflow-core/src/fixture_tests.rs:93` and
  `crates/codeflow-core/src/hooks/session_summary.rs:387`: `TMPDIR` lies
  inside a repository.

`crates/codeflow-cli/tests/delegate_pty_stress.rs:578` is a self-spawned
child entry point by design and stays as it is.

Five tests are `#[ignore]`. `read_benchmark.rs:419` has its own gate
target. The other four have none: `policy_last_release_journey.rs:92`
(released-binary compatibility, CAP-002), `hooks_cli.rs:1142` (baseline
guard comparison), `present_cli.rs:315` and `:862`. The `herdr-delivery`
target passes with its live cases skipped. One archived run's nextest
stderr reported 5 skipped while its recorded summary said 0.

Two assertions are weaker than they read.
`crates/codeflow-core/src/security/deletion.rs:8239` asserts
`fields[0].contains("")`. The audits disagree on whether that can fail
(`Values` is a set, so it tests membership of the empty value). Either way
it does not state the intended leading field, so it becomes an exact
assertion. At `crates/codeflow-cli/tests/models_cli.rs:110`, `assert!(!participants.is_empty() || required_open)`
skips the participants check when a required role is open.

Outcome: a result counts as passed only when its scenario ran. A missing
prerequisite either fails on a lane that must have it or is reported as
skipped and counted, and every ignored test has a lane that runs it or a
recorded reason.

Overlaps: TSK-351 (hosted repair) owns the fixture repairs it lists, and
the fixture work of PR 226 (repeated fixtures) and the restored test-time
task of PR 224 (guard fuzz timing) stay with those tasks. The macOS-only
tests belong to the native platform task of PR 224; this task lists them in
the inventory. Product surface: this repository's tests, plus the gate's
skipped count in the run record (CAP-004 engine) if the reconciliation
needs it.

## Deliverables

- the skip inventory: every early return, `#[ignore]`, platform gate and optional live case, with its lane or reason (provisional home `docs/verification/test-skip-inventory.md`; the builder confirms against the docs structure)
- the test changes at each site above under `crates/codeflow-cli/tests/` and `crates/codeflow-core/`
- skipped-count reconciliation: `crates/codeflow-core/src/testing/gate.rs` or the target's reporting, whichever owns the summary
- lanes for the four ignored tests: `.codeflow/test-config.json` targets or CI steps, or a recorded reason per test
- `herdr-delivery` skip reporting: `evals/herdr-delivery/test_delivery.py` and its target

## Acceptance Criteria

- AC-1 For each early-return site listed above, the test shall either
  assert its prerequisite (on a lane where it must hold, so a missing
  prerequisite fails) or report skipped through the runner so the run's
  skipped count includes it; no listed site shall exit as passed without
  running its scenario; evidence: per site, a run with the prerequisite
  removed showing failed or skipped, never passed. (serves EPC-022 AC-59)
- AC-2 The two permission refusals (`hooks_cli.rs:4847`, `:4918`) shall run
  on a lane where the permission denial is real (an unprivileged user or an
  equivalent deterministic denial), asserting the exact rule and an
  unchanged protected state; evidence: that lane's output naming both tests
  as executed.
- AC-3 `live_eval_pack.rs` shall report skipped, not passed, without its
  holdout, and CAP-013's registry entry shall not cite it as evidence that
  runs in CI; evidence: a run without the variable, and the registry diff.
- AC-4 Each of the four `#[ignore]` tests without a target shall have a
  named lane that runs it (with its required input, such as the last
  release binary verified by digest) or a recorded reason in the
  inventory; evidence: the lane's run or the inventory row.
- AC-5 A gate run's recorded skipped count shall equal the runner's skipped
  count, and the `herdr-delivery` target shall report its skipped live
  cases in the run record; evidence: one run whose JUnit, stderr and
  `run.json` agree, including the ignored tests.
- AC-6 `deletion.rs:8239` shall assert the exact leading field value and
  `models_cli.rs:110` shall assert participants for each duty kind
  separately; evidence: each assertion failing when the behaviour it states
  is changed, run through `codeflow test`. (journey)
