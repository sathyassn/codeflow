# TSK-158: present note markers on adjacent lines stay apart

## Description

In the present review surface, the note markers of two notes whose anchors
are closer than a marker's height sit on top of each other. Fable found it in
the TSK-071 round 4 design review (P3-10): on the annotation fixture, the
markers of element notes on two adjacent diff lines overlap in the gutter,
badge 2 covering most of badge 1 (36 px lines, 36 px markers; evidence
`t071-fable/r4/renders/slate-dark-rail.png` in the EPC-016 lead's
scratchpad). `markerPlacement` in `web/src/chrome.tsx` places each marker
from its own anchor only, so the same happens for any notes whose anchors
are close: adjacent code or prose lines, or two notes on one line. Make each
marker readable and clickable on its own while it still points at its
anchor. Non-goal: changing what a marker looks like or how notes anchor.

## Affected surfaces and interfaces

`crates/codeflow-present/web/src/chrome.tsx` marker placement and, if
needed, `styles.css`; `web/scripts/browser-check.mjs` or
`matrix-browser-check.mjs`; the present rebuild and its checksum. No server,
envelope or CLI change.

## Acceptance Criteria

- AC-1 When two or more notes anchor within one marker height of each other,
      their markers do not overlap, and each stays beside the gutter or
      anchor it points at; evidence: a browser check that saves notes on two
      adjacent diff lines, two adjacent code lines and twice on one prose
      line, and asserts that the marker boxes are disjoint and each marker's
      vertical range meets its anchor's line or an offset stated in the
      check.
- AC-2 Each marker still opens its own note from a click at its centre, at
      desktop width and at 375 px; evidence: the same check clicks every
      marker and asserts the note it opens.
- AC-3 The annotation matrix, `npm run check`, the browser checks,
      `cargo test -p codeflow-present` and `cargo test -p codeflow-cli --test
      present_cli` stay green and the present checksum matches a clean
      rebuild; evidence: the recorded output with the head SHA.
- AC-4 The design primary reviews the marker layout on the fixture in the
      three skins and two modes; evidence: the review record.
