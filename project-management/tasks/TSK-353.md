# TSK-353: Repository gate targets declare the inputs they read

## Description

Source: the gate speed discovery of 2026-10-17, ranked change 1 and its
section "Input declarations still select most work".

Once TSK-352 gives selection a proven base, this repository's own config
still selects almost everything. In `.codeflow/test-config.json`,
`execution.run_everything` lists `crates/**`, `assets/**`, `.codeflow/**`
and `.github/**`, so any Rust or scaffold edit selects every eligible
target. Of the targets, 5 of 7 quick, 10 of 16 essential and 20 of 26 full
have an empty `narrow`, which `select` always keeps
(`crates/codeflow-core/src/testing/delivery.rs`). A records or docs change
therefore still runs the workspace suite, clippy and the build targets.
In recent passing essential runs the workspace target alone took 28.89 and
31.02 target minutes of 49.19 and 54.00.

Outcome: each target in this repository declares the inputs it really
reads, so a records-only or docs-only change runs only the checks that read
those paths, while docs, release fragments, managed instructions and Rust
changes still run every relevant check. The landing candidate's full gate
stays complete and unchanged. Under row A below this narrowing takes
effect; under row B the declarations are written and tested against a
trusted base in unit tests, every requested target still runs with the
reason, and the narrowed runs are deferred.

Credit rows (TSK-1044 settles which one holds; every criterion below
that narrows, skips, reuses or recommends `--since` is checked against
both):

| Row | When | Required behavior |
|---|---|---|
| A | the operator adopted a protected recorder in TSK-1044 | the positive journeys: selection narrows, skips and reuse happen only from attested executions |
| B | no protected recorder | every requested target runs and the reason is reported; no output recommends `--since` where it cannot narrow; positive narrowing, skip and reuse journeys are marked deferred in the epic's planning notes |

Rules for the declarations (each target also gets the input class that
TSK-352 defines; a target whose reads cannot be audited stays unclassified
and always runs):

- A declaration is justified by what the target actually reads. Input
  ownership cannot be inferred from file extensions: the update no-op test
  reads `.codeflow/`, every manifest destination and the shipped assets
  (`crates/codeflow-core/tests/repository_update_noop.rs`), and Rust tests
  that read real repository docs or records need their own mapped inputs.
- A managed-instruction or scaffold edit is product input, not prose.
- Unknown, deleted and renamed paths keep the conservative fallback.
- The guard, hook and policy suites are never narrowed away from a change to
  hooks, guards, policy, security tables or the files they protect.
- Docs keep the portal check AGENTS.md requires, not an assumed equivalent.

Plan amendment of 2026-10-23 (process cuts, TSK-449 to TSK-452): this task is
the one owner of input declarations for this repository. That includes
`input_class = content` on targets whose reads are fully audited, a
`run_everything` narrowed to build inputs, and the skip of those targets on an
unchanged tree. A skip is granted only from complete matching check identity
(command, tools, environment, membership and producer outputs) recorded by a
qualifying execution; unproven cases run. Targets that read docs or records
(for example `docs-validation`) keep running when those paths change.
TSK-449 declares no inputs.

Non-goals: engine changes (TSK-352 owns selection), result reuse (TSK-355)
and the full gate's membership. Product surface: this repository's gate
config only; no shipped default changes.

## Deliverables

- input declarations: `.codeflow/test-config.json` (`narrow` per target and a smaller `run_everything`)
- the path-to-target matrix and its check: a table-driven test of representative paths against the selected targets (provisional home `scripts/test_gate_contracts.py`; the builder confirms)
- the before and after measurement: selected targets and elapsed time for a records-only, a docs-only, a managed-instruction and a Rust change, in the pull request body

## Acceptance Criteria

- AC-7 Before any change, the builder shall investigate broadly: TSK-1044's landed trust contract for local gate records and what selection and skip credit it leaves, the targets this repository would declare and what each reads, the readers of those declarations (`delivery.rs` selection, TSK-355's reuse), and adjacent concerns (records-only and docs-only changes, unknown paths, Windows); and shall record the findings and the chosen scope before any change; evidence: the record section, committed before the first change in the PR. Added 2026-10-28 with the edge to TSK-1044, by the operator's rule of 2026-10-27 that an amended task starts with an investigation.
- AC-1 A path-to-target matrix shall cover at least a task record, an epic
  record, a `docs/` page, a `changelog.d/` fragment, a managed instruction
  under `assets/`, a hook source, a guard security table, a Rust source in
  each crate, a workflow file, a deleted path, a renamed path and an
  unknown top-level path, and shall state for each the targets selected
  with their prerequisite closure; evidence: the matrix test passing, run in
  the quick gate. (serves EPC-022 AC-49)
- AC-2 Each narrowed declaration shall be justified by the files the target
  reads, and for each mapped target a planted fault in one declared input
  shall be caught by that target when selected from that input's change;
  evidence: the file reads or test sources cited per target in the pull
  request, and the planted-fault runs.
- AC-3 A records-only change shall not select `rust-workspace`,
  `rust-build`, `rust-clippy` or `rustdoc` unless the input audit shows one
  of them reads records, and shall select `docs-validation` and every
  target that reads records; the CLI binary's provenance rebuild
  (`crates/codeflow-cli/build.rs` watches records and Git metadata) is kept
  as a mapped narrow producer where a consumer needs it, never suppressed
  to satisfy a target-name rule; a docs-only change
  shall select the full `docs-portal` command AGENTS.md requires; a change
  to hooks, guards, policy or `assets/` shall select the guard, no-op and
  scaffold contract suites, as the selector computes from a trusted base;
  evidence: the matrix rows as selector tests with a trusted base, and
  under row A one real run per case with its selection output, or under
  row B one real run per case showing every target run with the reason
  and the narrowed run marked deferred. Amended 2026-10-28 after the PR 378 review, round 2: both credit rows. (serves EPC-022 AC-49)
- AC-4 An unknown, deleted or renamed path shall select every eligible
  target, as today; evidence: matrix rows.
- AC-5 (journey) On a branch from a line with a proven base, a records-only
  commit and a docs-only commit shall each run only their selected targets
  under row A, and every target with the reason under row B, and a Rust
  change shall run every eligible target in both rows, with selected
  targets and elapsed time reported before and after this change;
  evidence: the three runs' output in the pull request for the row
  TSK-1044 landed, with the other row's narrowing marked deferred.
  Amended 2026-10-28 after the PR 378 review: selection follows TSK-1044; round 2: both credit rows.
- AC-6 When a target is a candidate to skip, it shall skip only through credit TSK-1044's trust contract grants and only if its recorded check identity from a qualifying run matches completely (if TSK-1044 withdrew local credit, no target skips and the run names why), and a changed tool, environment, producer output or membership, or missing evidence, shall run it; a docs or record change shall still run every target that reads those paths. Evidence: invalidation cases in the `delivery.rs` tests (changed tool, changed environment, changed producer, missing evidence, docs-reading target), each running the target in both rows; and `codeflow test --mode quick` run after a qualifying full run, pasted in the PR, showing the repeat-run skip under row A, or under row B every target run with the reason and the skip marked deferred. Amended 2026-10-28 after the PR 378 review: skips follow TSK-1044; round 2: both credit rows. (serves EPC-022 AC-125)
