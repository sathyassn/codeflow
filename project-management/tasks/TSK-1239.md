# TSK-1239: Commit standards admits a pull request when its CI run completes, with no polling

## Description

Source: the CI throughput study of 2026-11-02 (`coordination/coordinators/parallel/throughput/`: RECOMMENDATIONS.md, FINDINGS.md, CHECK-codex.md, CHECK-fable.md), cross-checked by Codex GPT-6 Astra and Claude Fable 5.1, and the operator's priority on CI throughput.

The hosted "commit standards" job waits for the pull request's codeflow-ci run by polling, for up to 35 minutes, while it holds a runner slot (`.github/workflows/codeflow-policy.yml:160-185`, and the admit step of `scripts/ci-reuse.py`). TSK-449's closeout names the runner-slot cost and its revisit trigger (`TSK-449.md:134`). The study recommends replacing the poll with trusted admission that starts when the run completes.

Recurrence 2026-11-05: commit standards refused PR 596 (head bb2ad6ca2, run 41988427754 attempt 1, while gates run 41988427189 was queued) and PR 610 (head 072ac5934, run 41987831703 attempt 1, while gates run 41987831075 was queued; earlier also at draft head bcd0168e7, run 41984732559). Each refusal read "run <gates run> for head <sha> is queued; re-run this check once that run completes", and a manual rerun after the gates run completed was needed. Runs: https://github.com/sathyassn/codeflow/actions/runs/41988427754, https://github.com/sathyassn/codeflow/actions/runs/41988427189, https://github.com/sathyassn/codeflow/actions/runs/41987831703, https://github.com/sathyassn/codeflow/actions/runs/41987831075, https://github.com/sathyassn/codeflow/actions/runs/41984732559.

The existing predicate stays: the newest codeflow-ci run at the exact head, pull request and workflow, with the named verdict jobs succeeded (`scripts/ci-reuse.py:182`). The scaffold shipped to consumers has no such poll; it shares only the cancellation behaviour (`assets/base/ci/codeflow-policy.yml:51`, and it ends at :241), so this task adds no admission mechanism to the scaffold. Non-goals: reuse of hosted verdicts at landing (TSK-359), the cache of the target build (TSK-1240) and any change to the verdict jobs' names.

## Outcome

After this merges, a pull request is admitted by the hosted policy check as soon as its CI run completes, with no runner held while waiting, and a missing, cancelled, failed or wrongly skipped run is still refused.

## Deliverables

- the admission trigger and step: `.github/workflows/codeflow-policy.yml`
- the admit logic and its tests: `scripts/ci-reuse.py`, `scripts/test_ci_reuse.py`
- a note in the workflow's comment block that states the new trigger and what it rechecks

## Acceptance Criteria

- AC-1 Before any change, the builder shall record in the Findings, with run links: how the poll and the admit step work today (`codeflow-policy.yml:160-185`, `ci-reuse.py:182`); the longest wait and the runner-slot cost seen (`TSK-449.md:134`); each event that can start a trusted admission when a run completes, with what it carries and what a pull request can influence; and what a body edit, a rerun and a retarget do to the run that admission must read; evidence: a `## Findings` section, committed before the first code change.
- AC-2 Admission shall start when the pull request's codeflow-ci run completes, shall hold no runner while it waits for anything, and shall keep the existing predicate: the newest codeflow-ci run at the exact head, pull request and workflow, with every named verdict job succeeded; evidence: `scripts/test_ci_reuse.py` cases and the workflow diff showing the polling step gone. (serves EPC-022 AC-230)
- AC-3 At admission time the job shall recheck the pull request's current identity, head, target and readiness, and shall handle a body edit (which never cancels the check; TSK-1040) and a rerun (the newer attempt replaces the older); evidence: one test per case.
- AC-4 Admission shall refuse a missing run, a cancelled run, a failed run, a wrongly skipped verdict job, a completion for a head that has moved, a retargeted pull request and any API error, shall execute no code the pull request supplies, and shall not trust an artifact merely because it names a successful run; evidence: one test per refusal and a read of the job's checkout and environment handling in the review.
- AC-5 The consumer scaffold (`assets/base/ci/codeflow-policy.yml`) shall gain no admission mechanism; evidence: the scaffold diff, which shows only a cancellation fix where one applies, and a scaffold test that the template holds no admission step.
- AC-6 On this repository, a ready pull request whose codeflow-ci run completes shall be admitted without a polling step in its commit standards job and with less runner time than the polling job used, and a pull request whose run failed, was cancelled or was wrongly skipped shall be refused; evidence: the links and durations of both hosted runs. (journey)
- AC-7 A pull request whose codeflow-ci run has not completed when admission is evaluated, or whose wait hits any limit, shall never get a failed admission verdict: the admission check stays pending, with no conclusion, until the run completes, and never concludes while the run is unfinished (fail closed: an unfinished run is never admitted). An unfinished run counts only when bound as AC-4 binds a run: the same head SHA and the trusted workflow. A queued or in-progress run is not a missing run, so AC-4's refusal of a missing run does not apply to it. Evidence: PR 625's commit standards job 127516935556 as the before case (red after 37m56s when its wait for run 42104746040, then in progress and later failed, timed out, with a clean records verdict), and a test or hosted case where an unfinished run leaves the check with no conclusion, then admitted when the run completes green.
  - Amended 2026-11-05: added by Director ruling after PR 625's commit standards went red on a ci-reuse wait timeout while its records verdict was clean.
  - Amended 2026-11-05: from the PR 634 review (F8 and N5): the check now has one allowed state while the run is unfinished, no conclusion; an unfinished run is bound as AC-4 binds a run; and run 42104746040 was in progress, not queued; was: A pull request whose codeflow-ci run has not completed when admission is evaluated, or whose wait hits any limit, shall never get a failed admission verdict: the check stays pending, or ends with a message that says "not finished, rerun" and is distinct from a refusal, and it never ends success, neutral or skipped for an unfinished run (fail closed: an unfinished run is never admitted). A queued or in-progress run is not a missing run, so AC-4's refusal of a missing run does not apply to it. Evidence: PR 625's commit standards job 127516935556 as the before case (red after 37m56s when the wait for queued run 42104746040 timed out, with a clean records verdict), and a test or hosted case where a queued run leaves the check unconcluded or marked "not finished", then admitted when the run completes green.
