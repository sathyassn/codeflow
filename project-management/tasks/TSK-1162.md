# TSK-1162: One token source gives both surfaces their themes, modes, accents and colour floors

## Description

Split from TSK-1097 on 2026-11-01 (planning amendment of the same day). After
the navigation component left TSK-1097 for TSK-1160, the task still held the
token system beside the bar, the figure guidance and ten check families, and
graded Very Hard. This task takes the token source: one modular source for
colour, type, space, radius, elevation and motion that a generator turns into
CSS custom properties and a typed module, with the themes, modes, curated
accents, the stage colours and their contrast, CIEDE2000 and colour-deficiency
floors, the minimum segment width and ring arc, the colour-deficiency
separation test, and the portal starter's display control on the same tokens.
The criteria are the former TSK-1097 AC-9, AC-10, AC-12 and AC-4, unchanged
in meaning (the originals stay in TSK-1097 as moved notes). The source of
each is recorded in its text: the operator's design decisions of 2026-10-31.

TSK-1097 (the bar, the figure guidance, the check warnings and the text
rule) and TSK-1160 (the navigation component) depend on this task for the
token source, the line limits and the motion tokens. Other records that say
"TSK-1097's token system" mean this task. The operator's design direction of
2026-11-01 (`coordination/coordinators/visual-docs/DESIGN-DIRECTION.md`)
rejects a generic blue accent, so AC-2 no longer names clear blue as the default
(see its Amended note).

Non-goals: the bar, warnings and text checks (TSK-1097); the navigation
component (TSK-1160); the dashboard shell and its display popover (TSK-1120);
the portal frame (TSK-1114).

## Outcome

After this merges, `cf-present` and `cf-docs-portal` draw every colour, size
and radius from one typed token source, and a theme, accent or stage colour
that misses a contrast or colour-safety floor fails the build.

## Deliverables

- the design system: one modular token source (colour, type, space, radius, elevation, motion; themes, modes, curated accent options, stage colours, the floors and the minimum segment width and ring arc, each declared once) and its generator writing the CSS custom properties and a typed module, consumed by both skill kits, the present runtime, `assets/docs-portal/starter/src/styles/` and this repository's portal; the portal starter's display control (Mode, Theme, Accent, Size behind one gear) on the same tokens
- the checks: the token build floors and the style-literal lint, and the simulated-deficiency separation measure in the kit palette test (`crates/codeflow-core/tests/`, beside the drift test) and at project-token import in `crates/codeflow-present/src/config.rs`
- findings: the AC-5 section of this record
- release note: `changelog.d/TSK-1162.md`
- managed wiring, mirrors and baseline: `assets/base/scaffold-manifest.toml`, installed managed files and `.codeflow/` baseline, synchronized when changed

## AC-5 findings before implementation

DESIGN_INTENT: conform to the accepted utility design in the coordinator's
`design/after/cf.css` and `DESIGN-DIRECTION.md`. The coordinator relayed the
operator's page 5 choices on 2026-11-02 at 12:08: one design for every page
and docs site; deep green remains the main accent (#12766e light, #63cbbf
 dark); Graphite and Sage use plum as their second accent, Slate uses violet.
Measure these choices against the floors; report conflicts without substituting
colours. The initial findings below precede implementation and measurements.

The lightness and distance thresholds are project design choices. WCAG supplies
the contrast thresholds, and the cited papers supply measurement methods, not
universal colour-discrimination guarantees. Labels and shape/pattern channels
remain necessary.

| Property | Proposed value and measurement | Basis |
|---|---|---|
| Graphite canvas lightness | CIELAB D65 L* 94 through 99.5 light; 5 through 12 dark, inclusive | Prototype cf.css lines 25 and 34/46: #f4f4f4 ground and #171717 dark ground; light paper #fdfdfd also fits. DESIGN-DIRECTION.md Required calls for soft off-white and near-black. These bands are project choices containing the reference values and excluding extremes. |
| Graphite neutral roles | Exact R=G=B for canvas, paper, chrome, panel and neutral text/border roles; forbid #ffffff and #000000 canvas separately | AC-2 and design direction. Accent/status roles are intentionally coloured. |
| Text contrast | At least 4.5:1 against each actual supported background, including on-accent and accent-wash text | AC-2; WCAG 2.2 SC 1.4.3; preserve existing companion ink 4.5:1 checks. |
| UI/focus and stage contrast | At least 3:1 against each adjacent surface used by the role | AC-2/3; WCAG 2.2 SC 1.4.11. |
| Stage pair separation | CIEDE2000 >=10 normally; >=5 after EACH full-severity protan, deutan and tritan simulation | Proposed project discrimination floors, not accessibility standards. Existing kit uses dE 10 and 20 for companion comparisons. Stronger than mere nonidentity; rendered and two-channel evidence remains necessary. |
| Figure ink simulated separation | CIEDE2000 >=5 after EACH simulation, all distinct semantic figure ink roles in each of six theme/mode combinations | Proposed project floor; extend existing companion palette checks. Do not confuse six theme/mode combinations with six pairwise comparisons. Enumerate every unordered role pair and print role names. |
| Existing ordinary companion distances | Retain current named 20/10 floors | design_kit.rs lines 898-918; do not lower existing protection to satisfy the new palette. |
| Accent/status hue gap | >=24 degrees, shortest circular distance in CIELCh D65 hue, for each mode against ok/warn/danger | AC-2 supplies 24 degrees; CIELCh is the proposed explicit hue space. Flag any design conflict before changing a required default. |
| Positive bar/ring minima | 3 CSS px per positive segment; 3 degrees per positive ring arc | Proposed project visibility choices under AC-3; not WCAG requirements. Zero remains absent; labels retain actual counts. Allocate residual geometry proportionately and test impossible allocations explicitly rather than overlapping marks. |

Measurement sources:
- WCAG 2.2: https://www.w3.org/TR/WCAG22/#contrast-minimum and https://www.w3.org/TR/WCAG22/#non-text-contrast
- Machado, Oliveira and Fernandes (2009), full-severity simulation: https://profs.ic.uff.br/~laffernandes/content/publications/journal/2009_tvcg_15%286%29/machado_oliveira_fernandes-tvcg-15%286%29-2009-corrected.pdf
- Sharma, Wu and Dalal CIEDE2000 implementation notes/test data: https://www.ece.rochester.edu/~gsharma/ciede2000/ciede2000noteCRNA.pdf
- Local prototype: /Volumes/DATA/Local/software-workspace/projects/agentic-systems/coordination/coordinators/visual-docs/design/after/cf.css, lines 22-86; sibling coordinator DESIGN-DIRECTION.md, Required.
- Existing extension point: crates/codeflow-core/tests/design_kit.rs, contrast helpers lines 153-196, CIEDE2000 lines 211-255, palette checks lines 844-918, drift checks lines 460-550 and 754 onward (line numbers at inspected integration SHA).

Simulation pipeline: decode sRGB to linear RGB, multiply published severity-1 matrices, clamp to display gamut, convert to D65 Lab, then CIEDE2000. Validate math against published reference vectors, including hue wrap and zero chroma. Source matrices and their provenance once. Never tune floors downward to make a fixture pass.
