# TSK-1065: A program-valued Git setting cannot read a protected path through the program it runs

## Description

Source: Fable review 10 of TSK-1002 (PR 346), a nit tracked once. It is
the residual that the option D scope leaves for later: what a program
does once it runs.

Several Git settings name a program that Git runs, and the words of
that program are a command of their own:
`git -c core.pager='cat copies/id_r*' log`, `git -c core.editor=...`,
`git -c diff.external=...`, `git submodule foreach 'cat ...'`. Where
those words are text on the line, TSK-1002 now judges them (see the
amendment below). Where they are not, the program Git starts can read a
protected checkout or secret path, and the guard's verdict on the `git`
line says nothing about what that program reads.

Some program values are plain text the guard can read as a command.
Others are a script file, or a value Git takes from the environment or
a configuration file; their effect cannot be read from the line. Even a
readable value does not prove which executable runs: a writable `PATH`
entry can put a program named `difft` or `less` there that reads a
secret, and a public working directory proves nothing about it. So the
rule fails closed: a program-valued setting whose executable cannot be
resolved to a trusted path refuses, separately from TSK-397's
text-rule selection, which says nothing about which executable runs.
Relaxing where a host's containment is attested is TSK-1055's rule.

The line reads these settings and their command bodies through
`configured_commands` (`crates/codeflow-core/src/hooks/git_guard/runners.rs:597`,
from TSK-379, called by TSK-1002's runner reader at `:2250`); this task
reuses that reader instead of writing a second one, and composes with
TSK-1052 (a written file then run) and TSK-1053 (execution identity under
runners). Amended 2026-10-29 after Codex review 02 of PR 393.

Non-goals: changing what TSK-1002 already refuses; credential helpers
are not run or queried by any test (agents never run `git credential`).

Amended 2026-10-30, after TSK-1002 landed (PR 346, merge `6a05e1c00`).
TSK-1002 now judges every command a Git call runs as the same command
run directly: a `-c` or `--config-env` setting the subcommand uses, the
`GIT_CONFIG_COUNT` environment, `submodule foreach` and the other
operand commands (`docs/policy-reference.md:524-544`). The line binary
at `6a05e1c00`, with the text on stdin and never run, refuses under
`security.secret_reads` the `core.editor`, `diff.external`,
`submodule foreach`, `diff.<driver>.textconv`, `filter.<name>.clean`,
`core.sshCommand`, `gpg.program`, `pager.<command>`,
`sequence.editor`, `merge.<driver>.driver`, `--config-env` and
`GIT_CONFIG_COUNT` forms of `cat copies/id_rsa`, and `core.pager` with
the literal path; `core.pager='cat copies/id_r*'` gets the verdict of
`cat copies/id_r*` run directly, which depends on what the glob matches.
The runner reader reads configured commands through `configured_commands`
(`crates/codeflow-core/src/hooks/git_guard/runners.rs:2250`). What
remains is the part TSK-1002 did not take: a program the guard cannot
read from the line, and an executable it cannot trust. The same binary
allows `git -c core.pager=./pager.sh log` (a script it does not read)
and `PATH=/private/tmp/evil:$PATH git -c core.pager=less log` (a
substituted executable). A value set only in a configuration file was
not probed. So this task stays, narrowed to AC-1's inventory, AC-3,
AC-4 and AC-5, with AC-2 and AC-6 kept as regressions. Earlier text of
this description said TSK-1002 judged only the alias-free `!` helpers,
that the other program-valued settings reached a program unread, and
that `configured_commands` sat at `runners.rs:465`; the paragraphs above
now state the landed position.

## Outcome

After this merges, an agent cannot read a protected checkout or secret path through a program-valued Git setting whose program the guard cannot read from the line or whose executable it cannot trust, such as a script path, a configuration-file value or a substituted `PATH` entry.

## Acceptance Criteria

- AC-1 Before any change, the builder shall list every Git setting and command form that runs a program the requester names (at least `core.pager`, `pager.<command>`, `core.editor`, `sequence.editor`, `diff.external`, `diff.<driver>.textconv`, `diff.<driver>.command`, `merge.<driver>.driver`, `filter.<name>.clean`, `smudge` and `process`, `core.sshCommand`, `core.fsmonitor`, `gpg.program`, `submodule foreach` and `-c alias.<name>=!...`), each spelled with `-c`, `--config-env`, the `GIT_CONFIG_COUNT` environment and a configuration file, and shall record which of them TSK-1002 already refuses at its landed head and which reach a program unread; evidence: the Findings section, committed before the first code change.
- AC-2 Where the program value is text the guard can read, the guard shall keep judging it as the same command run directly: in a fixture holding `copies/id_rsa`, `git -c core.pager='cat copies/id_r*' log`, `git -c core.editor='cat copies/id_rsa' commit`, `git -c diff.external='cat copies/id_rsa' diff` and `git submodule foreach 'cat copies/id_rsa'` shall refuse; evidence: regression tests for each form (TSK-1002 refuses them at `6a05e1c00`, so they owe no fail-before).
  - Amended 2026-10-30: earlier text "each allowed at TSK-1002's landed head (failing before) and refused after". Reason: TSK-1002 landed (merge `6a05e1c00`) and its line binary refuses these forms under `security.secret_reads`, so the criterion is now a regression guard.
- AC-3 A program-valued setting whose executable cannot be resolved to a trusted path, or whose words cannot be read from the line (a script path, a value from the environment or a configuration file, a quoting form the guard does not model), shall refuse; a host where TSK-1055 attests the protected effect may relax this only by TSK-1055's rule, never by a public working directory alone; evidence: guard tests for each unreadable form, a substituted-executable test for each setting AC-1 lists (a writable `PATH` entry ahead of the trusted one holding a `less`, `vim` or `difft` that reads a protected file), each refused, and the same lines under a TSK-1055 attestation fixture judged by that rule.
- AC-4 Ordinary program values that name no protected path shall allow only where the executable resolves to a trusted path: `git -c core.pager=less log`, `git -c core.editor=vim commit` and `git -c diff.external=difft diff` in a public tree, with a clean `PATH`, allow; the same lines with a substituted executable refuse (AC-3); evidence: control tests passing before and after for the trusted case, and the substituted case refused after.
- AC-6 The settings and their command bodies shall be read through `configured_commands` (`git_guard/runners.rs:597`, called by the runner reader at `:2250`), with no second reader of Git's program-valued configuration; evidence: the code and a test that one setting reaches both the write check and this read check through that reader. Amended 2026-10-29 after Codex review 02 of PR 393, with AC-3 and AC-4.
  - Amended 2026-10-30: the line reference moves from `:465` to `:597` after TSK-1002 landed; TSK-1002's runner reader already calls this reader, so the reads this task adds go through it too.
- AC-5 `docs/policy-reference.md` shall list the program-valued settings the guard reads and the rule for those it cannot read; evidence: the text diff and `codeflow validate --docs`.
