# TSK-135: PR body and spec checks scaled to the change class

## Description

A two-line records pull request is blocked for missing Reviews and Release
impact sections, and SPC-013's approval had to reword "None." because the
open-questions check matches words such as "pending" in free text. This task
scales the pull request body and spec checks to the change class that
TSK-104 introduces: docs-only and planning-only ranges need Summary and
Changes, with Release impact defaulting to none; spec open questions become
a structured field. Source: guardrails strand rows 23 and 30.

## Affected surfaces and interfaces

- `crates/codeflow-cli/src/cmd/ci/pr_body.rs` and `cmd/ci.rs`
  (`pr_sections`); the PR template in `.github/` and `assets/base`.
- `crates/codeflow-core/src/validate/mod.rs` (spec check); the spec
  template in `project-management/templates/` and its scaffold copy.

## Acceptance Criteria

- [ ] AC-1 For a docs-only or planning-only range, the PR body check shall
      require only Summary and Changes and treat an absent Release impact as
      none; code ranges keep today's sections; evidence: `ci_cli` tests per
      change class.
- [ ] AC-2 The PR template shall say which sections apply to which class;
      evidence: the template diff.
- [ ] AC-3 A spec's open questions shall be read from a structured field,
      keyword matching shall be removed, and every existing spec on this
      line shall validate unchanged or through a documented one-time
      migration; evidence: validator tests and a clean `validate --docs`.
- [ ] AC-4 (journey) In a freshly scaffolded project at the full tier the
      templates and checks shall match, and `codeflow update` shall migrate
      the spec template and keep the adopter's kept PR template mapping;
      evidence: `init_e2e` and an update test.
