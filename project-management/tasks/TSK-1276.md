# TSK-1276: Id sync names a broken worktree and how to repair it, and still refuses

## Description

`codeflow task new` id sync failed with "bad remote object refs/heads/task/TSK-1176-secret-scan-from-authority" while filing TSK-1275 at 00:4x on 2026-11-03, and `git worktree list` showed `.worktrees/tsk-1176` at "000000000 (error)". The worktree is healthy: unsandboxed, the ref resolves at `3201e60c4`, and fsck and all 89 worktree entries are clean (coord/parallel, 00:4x). The Claude sandbox's read deny list blocks file names containing "secret", so the loose ref `.git/refs/heads/task/TSK-1176-secret-scan-from-authority` cannot be read inside a sandboxed command. The refusal names a ref but not the likely cause or the way out, and the branch slug derived from a task title can itself contain a denied word.

Id sync stays fail closed: skipping a worktree could miss an id allocated there and hand out a duplicate (Director, 00:4x). This task makes the refusal say what is wrong and what to do, and keeps new branch names from tripping the sandbox. Owner: coord/planning (builder to be staffed). Non-goal: existing branches are not renamed.

## Outcome

After this merges, an adopter whose id sync is refused can read from the message which ref or worktree is unreadable or only partly created and how to clear it, and new task branch names do not collide with the sandbox's denied file names.

## Deliverables

- the refusal message and the worktree skip rule: the id sync code and its tests (the builder confirms the files)
- the slug rule or the preset change, the builder's pick stated with its reason: `codeflow work start` slug code, or the shipped Claude and Codex presets under `assets/`
- the release note: `changelog.d/TSK-1276.md`

## Acceptance Criteria

- AC-1 When a worktree ref or HEAD cannot be read, whether broken or denied by a sandbox, id sync shall refuse and issue no id. The message shall name the ref, the worktree path and the likely causes: if permission is denied it shall say a sandbox may deny that name and the command should be rerun outside the sandbox; if the ref is broken it shall give `git worktree repair <path>`, or removal of the worktree if it is abandoned. Evidence: a test with an unreadable ref and one with a broken HEAD, each failing before the change and passing after, and the original error text (`bad remote object refs/heads/task/TSK-1176-secret-scan-from-authority`) with the `git worktree list` line `.worktrees/tsk-1176 ... 000000000 (error)`. (journey)
- AC-2 A worktree shall be skipped only when it provably holds no task records: no `project-management/tasks` file differs from the target and no task branch is checked out there. The skip shall be printed. Evidence: a test covering a skipped case and a refused case.
- AC-3 The same naming shall apply wherever else codeflow walks worktrees for records or claims (the sibling sweep), or each place shall be recorded with its reason. Evidence: the list of places searched and each one's disposition.
- AC-4 A changelog entry shall describe the change. Evidence: `changelog.d/TSK-1276.md`.
- AC-5 The branch slugs `codeflow work start` derives shall avoid words the shipped sandbox preset denies in file names (secret, credential and credentials, `.env`, key, pem, token and the like, taken from the shipped Claude and Codex presets), OR the shipped preset's deny patterns shall stop matching git ref paths. The builder picks one and states why. Evidence: a test covers the chosen fix; existing branches are not renamed.
- AC-6 Where CodeFlow walks or reports worktrees (id sync, `codeflow doctor` and the places AC-3 lists), a folder under the project's worktree folder that git does not register as a worktree, and whose `.git` file names worktree metadata that does not exist, shall be listed as a partial worktree: its path, the likely cause (a `git worktree add` that stopped partway, for example when a sandbox denied a tracked file during checkout) and the removal step (check that it holds no work you need, then delete the folder). Such a folder shall never be treated as a worktree, skipped silently or counted as clean; id sync judges it under AC-1 and AC-2, so it refuses unless the folder provably holds no task records. Evidence: a fixture with one partial worktree, misreported before and listed after, in id sync and in `codeflow doctor`. Added 2026-11-12 (reason in the Execution contract).
