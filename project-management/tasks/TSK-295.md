# TSK-295: A task on a diverged integration line can complete before main holds it

## Description

In 3.1.0 the pre-push check judges a task's criteria at two points: the
range base, which is the integration line tip, and the default branch tip,
which is the candidate authority. When the line has diverged from the
default branch and the default branch does not hold the task's record,
`judge()` counted the missing record as a version that disagrees with the
line's record. The criteria became unknown, so every push that changes the
task's own record was refused and a task on such a line could not be
completed (sathyassn/codeflow#153). This task makes a judged point that
holds no record of the task count as no version, so the points that do
hold it decide. A doubt, two held versions that disagree, and an absent
point whose history holds a different version still refuse. Non-goal:
changing which points the pre-push judges against.

## Deliverables

- The judgement fix and its unit tests: `crates/codeflow-core/src/workgraph/landing.rs`
- The regression fixture: `crates/codeflow-cli/tests/acceptance_cli.rs`
- The 3.1.1 release notes and version stamps: `changelog.d/TSK-295.md` and the coupled stamp files `scripts/release.py sync` writes

## Acceptance Criteria

- AC-1 When the judged points are not ordered by ancestry and every point but one holds no record of the task, carries no doubt and has no other version in its history, the judgement shall take the held point's version as the criteria authority. Evidence: a unit test of `judge` in `landing.rs`.
- AC-2 When two judged points that are not ordered by ancestry hold versions with different criteria, when a judged point carries a doubt, or when an absent point's history holds a version with other criteria, the judgement shall leave the criteria unknown, so a criteria change is refused. Evidence: unit tests of `judge` in `landing.rs`.
- AC-3 (journey) On an `integration/EPC-x` line that has diverged from `main` and holds a task `main` does not hold, when a task branch completes that task with an acceptance block, `codeflow ci` run as the pre-push runs it, with `--policy-from` and `--commits-from` at the `main` tip, shall pass without a `work.criteria_frozen` refusal. Evidence: the regression fixture in `acceptance_cli.rs`, failing before the fix and passing after.
- AC-4 The release fragment `changelog.d/TSK-295.md` shall carry one patch entry that says what an adopter sees and an entry on replacing the binary on macOS, the version stamps shall be synced to 3.1.1, and `scripts/release.py check-state` shall accept the tree at 3.1.1. Evidence: the check's output.
