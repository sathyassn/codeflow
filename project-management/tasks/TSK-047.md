# TSK-047: ship the no attribution setting in every Claude settings preset

## Description

The Claude Code host injects a request for a `Co-Authored-By` trailer on
commits and a "Generated with Claude Code" line on pull request bodies. The
project policy forbids both and the commit-msg hook and git-guard block them,
so today an agent learns the rule only by being blocked. Claude Code honours
two settings that turn the injection off at the source: `includeCoAuthoredBy`
set to false and an `attribution` object with empty `commit` and `pr` strings.
This task ships both keys in the three managed settings presets so every
consuming project gets them at init and, through the settings merge that adds
absent top-level keys, at the next `codeflow update`. Codeflow's own
`.claude/settings.json` and its managed baseline carry the same keys. The
agent-os repository receives the same two keys by a separate change in that
repository. Non-goals: no change to the hooks, the policy or the guard, which
remain the enforcement floor.

## Affected surfaces and interfaces

`assets/base/settings/default.json`, `assets/base/settings/acceptEdits.json`,
`assets/base/settings/bypass-sandboxed.json`; the top-level key list in
`crates/codeflow-cli/tests/settings_presets.rs`; codeflow's own
`.claude/settings.json`, `.codeflow/.baseline/.claude/settings.json` and the
`.claude/settings.json` entry in `.codeflow/manifest.json`; one sentence in
`assets/base/CLAUDE.md.tmpl` and the root `CLAUDE.md` managed block; the
enforcement matrix row in `docs/adoption.md`. CAP-015 is unaffected.

## Acceptance Criteria

- [ ] When any of the three presets is read, it shall carry
      `includeCoAuthoredBy: false` and `attribution: {commit: "", pr: ""}`;
      evidence: the settings preset test asserts both keys and values in all
      three presets and lists them in the top-level key set.
- [ ] Codeflow's own `.claude/settings.json`, the managed baseline copy and the
      manifest hash shall agree with the shipped preset; evidence:
      `codeflow doctor --check managed-drift` reports clean at the closeout
      head and the manifest consistency test passes.
- [ ] A consuming project on an earlier scaffold shall receive both keys on
      `codeflow update` without losing its own settings; evidence: a merge test
      feeding a current settings file without the keys reports both as added
      and preserves the existing keys.
- [ ] The Claude notes in the managed block shall name the setting and the
      reason in one sentence; evidence: the sentence is present in the template
      and in the root file and the two managed blocks stay byte-identical.
