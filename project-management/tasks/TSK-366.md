# TSK-366: Expectation regeneration never counts as verification

## Description

Source: both test integrity audits of 2026-10-17 at
`eaf2ed04e932186cdd26dc4a7e5740cc553acee3` (Codex low finding; Fable
section 4 and minor M8).

Some tests rewrite their own expected output when an environment variable
is present, then pass:

- `CODEFLOW_BLESS` in `crates/codeflow-cli/tests/settings_presets.rs:955`
  (returns after rewriting a mismatch at `:968`) and
  `crates/codeflow-core/tests/rule_map_contract.rs:172` (skips comparisons
  after writing at `:177`). Presence is enough, even `0`.
- `CODEFLOW_REGENERATE_LOOKUPS` in
  `crates/codeflow-cli/src/command_reference.rs:318` and
  `crates/codeflow-cli/src/cmd/validate.rs:368`.
- `CODEFLOW_UPDATE_FIGURE_FIXTURES` in the portal's
  `figure-grammar.test.mjs:120`.

No gate sets them, and the gate's tracked-tree check
(`crates/codeflow-core/src/testing/gate.rs`, `generation_unchanged`) stops
a gate that changed tracked files from qualifying a candidate. A direct
test run can still regenerate and report success. Separately, the shipped
portal script `assets/docs-portal/starter/scripts/publication.mjs:503`
takes `simulateCrash` and `testHooks` parameters that only its tests use.

Outcome: generating expectations is an explicit maintenance action, a
verifying run refuses or records it as non-verifying, and shipped code
carries no test-only switch.

Product surface: this repository's tests and gate; the portal starter
script is shipped scaffold (CAP-015).

## Deliverables

- regeneration as maintenance: each site above, either moved to an explicit maintenance command or test (provisional: a `--bless` style script under `scripts/`; the builder names it) or made to fail the test when set
- the gate: `codeflow test` strips or refuses these variables for its targets, as it strips `CODEFLOW_HOOK_BINARY` (`crates/codeflow-core/src/testing/`)
- the portal script: test injection moved out of the shipped function signature in `assets/docs-portal/starter/scripts/publication.mjs` and `docs-portal/scripts/publication.mjs`, with `docs-portal/tests/adapter.test.mjs` updated
- release note: `changelog.d/TSK-366.md`, for the portal starter change

## Acceptance Criteria

- AC-1 With each regeneration variable set, running the affected test
  directly shall either fail with a message naming the maintenance command
  or leave every expected file unchanged and end in a non-verifying result
  state (not a pass with printed text), never rewrite and pass; evidence: one run per variable with `git status`
  before and after. (serves EPC-023 AC-23)
- AC-2 A `codeflow test` run started with any of these variables in its
  environment shall not pass them to targets, or shall refuse to start;
  evidence: a CLI test per variable.
- AC-3 The maintenance command shall regenerate each expectation and its
  output shall be reviewed as an ordinary diff; evidence: one regeneration
  run with no diff on the current tree.
- AC-4 The shipped portal publication function shall have no test-only
  parameter, and its crash and hook tests shall still pass through a
  test-only seam; evidence: the diff and `docs-portal` tests. (journey)
