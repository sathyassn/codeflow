# TSK-007 — verify and qualify the presentation utility

## Description

Stress and qualify the complete presentation utility against its functional,
security, accessibility, editorial, cross-platform, harness, and lifecycle
claims. Correct material findings in the owning implementation rather than
lowering the contract or approving it because narrow tests pass.

## Affected surfaces and interfaces

- Rust/unit/integration/browser suites, model-evaluation fixtures and graders,
  live native-interactive evidence, install/update canaries, release evidence.

- [ ] Tests cover schema skew, malformed/oversized/untrusted content,
      authentication, DNS rebinding, token/session isolation, path confinement,
      concurrent history, duplicate feedback, crash/retention cleanup, and
      export fidelity across supported operating-system path semantics. Every
      presentation-owned external child also proves that its restricted
      environment excludes provider-secret canaries.
- [ ] Native macOS, Linux, native Windows, and WSL2 runs qualify their own
      state, permission, process, browser-launch, export, and cleanup adapters.
      WSL2 is recorded as Linux, never as native-Windows evidence; cross-builds
      remain compile/link evidence only; an unqualified adapter fails closed.
- [ ] Headless browser runs use a task-owned profile, service port, test-data
      namespace, output/trace directory, and isolated application endpoint to
      verify interaction, accessibility, responsive behavior, layout,
      themes/modes, visual blocks, console/network state, export, and close /
      crash / retention cleanup. Any necessary headed run uses a task-owned
      browser and never the operator's profile, browser window, or desktop;
      teardown proves that owned processes, listeners, profiles, and temporary
      artifacts are removed or explicitly retained with a reason.
- [ ] The renderer rebuilds byte-identically from its exact lockfile and
      toolchain; integrity hashes, Brotli/export and release-binary size
      budgets, license inventory, CycloneDX SBOM, and package/dependency audits
      pass. Installing and using the presentation utility requires no Node
      toolchain in a consuming repository.
- [ ] Fresh greenfield init and representative brownfield update canaries
      install byte-identical `cf-present` skill artifacts for Claude and Codex,
      and native sessions discover and route to the skill from task semantics.
      Repeated update is idempotent and preserves project-owned configuration,
      intentional sidecars, and unrelated files.
- [ ] Semantic cases prove proportional invocation/composition, session-aware
      language, durable-decision promotion, simple-answer restraint, and
      graceful degradation across native Claude and Codex hosts; paired cases
      reject text-card grids as fake visuals while also rejecting a forced
      diagram when clear prose or bullets are the better form.
- [ ] Fresh native-interactive Fable 5/high and GPT-5.6 Sol/high trials satisfy
      exact envelopes and cross-grade one another. Both lineages independently
      review the same exact implementation SHA and its claim-matched evidence;
      retained provenance distinguishes deterministic, rendered,
      platform-native, and model-reasoned claims.
- [ ] Full local gates and independent integrated review find no unresolved
      material issue. An uninstall-style disposable canary removes only its
      task-marked CodeFlow-managed scaffold artifacts and task-owned
      presentation runtime/profile/data/output roots, preserves every
      user-owned or unrelated file, and makes no claim that CodeFlow exposes a
      public uninstall command.

## Execution contract

Plan v5 is EPC-005, approved SPC-004, ADR-0049, ADR-0050, ADR-0052, and the
exact TSK-006 design settlement. This readiness correction decomposes those
already accepted requirements into claim-matched evidence; it changes no
outcome, graph edge, interface, owner, integration target, or safety boundary.

Verification ownership is independent from each claim's producer where
practical. Codex producer first-verification and cross-lineage challenge cover
code, security, concurrency, platform behavior, supply chain, and evidence;
the qualified Claude judgment primary owns final UX, accessibility, editorial,
design-fidelity, and integrated code judgment. Both reviews bind the exact
integration-ready SHA; an approval of an earlier SHA is not transferable.

TSK-007 qualifies the presentation-specific inputs to release. TSK-010 owns the
combined CodeFlow release review, final release archives/installers/checksums,
version/tag workflow, and public-network install canaries. Integration target:
`integration/EPC-005-presentation-system`. Failed cases change the owning
implementation or require a dual-approved plan amendment; they never lower the
contract, relabel cross-build evidence as native execution, or change an
expected result merely to produce green output.

## Qualification evidence boundaries

| Claim | Required evidence | Not a substitute |
|---|---|---|
| Platform support | Native runtime journey on each claimed platform; WSL2 recorded separately as Linux | Cross-compilation, static review, or a different OS |
| Browser behavior | Isolated real-browser journey plus teardown evidence; headed only in a task-owned session | Unit tests, screenshots alone, or the operator's browser |
| Renderer supply chain | Exact locked rebuild, reproducibility, audit, license, SBOM, integrity, and size evidence | A successful Rust compile or unchecked generated files |
| Skill availability | Greenfield and brownfield scaffold parity plus native Claude/Codex discovery and invocation | Byte equality alone or an explicitly named skill prompt only |
| Integrated quality | Independent exact-SHA Claude and Codex verdicts over claim-matched evidence | Self-review, stale-SHA approval, model agreement, or tests alone |
