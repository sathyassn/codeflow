# TSK-007 — verify and qualify the presentation utility

## Description

Stress and qualify the complete presentation utility against its functional,
security, accessibility, editorial, cross-platform, harness, and lifecycle
claims. Correct material findings in the owning implementation rather than
lowering the contract or approving it because narrow tests pass.

## Affected surfaces and interfaces

- Rust/unit/integration/browser suites, model-evaluation fixtures and graders,
  live native-interactive evidence, install/update canaries, release evidence.

## Acceptance Criteria

- [ ] Tests cover schema skew, malformed/oversized/untrusted content,
      authentication, DNS rebinding, token/session isolation, path confinement,
      concurrent history, duplicate feedback, crash/retention cleanup, and
      export fidelity across supported operating-system path semantics.
- [ ] Headless browser runs verify interaction, accessibility, responsive
      behavior, layout, themes/modes, visual blocks, console/network state, and
      resource teardown without taking over the operator's view.
- [ ] Semantic cases prove proportional invocation/composition, session-aware
      language, durable-decision promotion, simple-answer restraint, and
      graceful degradation across native Claude and Codex hosts; paired cases
      reject text-card grids as fake visuals while also rejecting a forced
      diagram when clear prose or bullets are the better form.
- [ ] Fresh Fable 5/high and GPT-5.6 Sol/high trials satisfy exact envelopes and
      cross-grade one another; retained evidence distinguishes deterministic,
      rendered, and model-reasoned claims.
- [ ] Full local gates, clean init/update/uninstall-style cleanup canaries, and
      independent integrated review find no unresolved material issue.

## Execution contract

Plan v2 is EPC-005/SPC-004. Verification ownership must be independent from each
claim's producer where practical; Claude owns final UX/editorial judgment and
Codex owns producer first-verification plus cross-lineage challenge. Integration
target: `integration/EPC-005-presentation-system`. Failed cases change the
implementation or plan, never the expected answer merely to produce green
output.
