# TSK-072: explanation method for docs, portal and present

## Description

Give every CodeFlow explanation one staged way to think before it is drawn
or written. Present has a real method today (`how-presentation-works.md`
steps A to F); the portal has a gate checklist; neither names the reader at
each altitude, and chat, README and ADR authors load neither. Write
`resources/explanation-method.md`, byte identical in `cf-docs-portal` and
`cf-present`, first in both load orders:

| Stage | Question | Output |
|---|---|---|
| 1. Reader and question | who reads this, and what one question must they answer afterwards | one line per altitude: reader, question |
| 2. Altitude | which altitudes this deliverable carries, in what order | the altitudes |
| 3. Carrier | what relationship the reader must see first, and in which medium | a family and a medium, or none |
| 4. Draft | declaration, lead, figure, caption, acting text, twin | the draft |
| 5. Check | masked title, removal, two channels, sources, policy characters, copy | pass, or back to stage 3 |

The stage outputs are the author's working notes; only the draft and its
declaration are artifacts, and nothing asks a page to record the stages.
The method never rewrites a source it must leave alone (an accepted
record, a source an agent loads into its context, governance text): such a
source renders as it is, and the method illustrates it only through a
companion figure bound in configuration. The method says so in one
sentence and names the illustrated source and pass-through classes TSK-059
defines.

Stage 1 names the reader per altitude: Concept is read by someone deciding
whether the subject is for them; Architecture by an engineer who will change
or integrate it; Technical by an operator or reviewer; a how-to section by
someone doing it now; a reply by the operator who asked. A PR body takes
the reply row's reader, and an ADR the Architecture row's. Stage 3 carries
the carrier table by subject and medium: the nine families (with their chat and
README form and their portal and present form), a screenshot for a surface
as it is, a table for a lookup, and a named boundary for distribution or a
series over time, which no family draws today. A README figure is the fenced
ASCII chat form; an SVG file and a Mermaid fence are not README figures,
because the portal rejects SVG media and GitHub shows a `cf-stage` fence as
code. The smallest carrier that keeps the depth wins; facts with no
relationship take bullets or a table and no figure. Three worked decisions,
one per altitude, on this repository's facts, each in about six lines: the
portal itself (Concept, structure), the four enforcement planes
(Architecture, layering), a gate's coverage of surfaces (Technical,
coverage).

Around the method:

- Give each presentation skill one load list, in `SKILL.md`, with the
  method as item 1. The "Required load order" preambles of both
  `visual-craft.md` files, the "Required first" preamble of
  `document-authoring.md` and the head of `how-presentation-works.md` each
  become one line pointing at that list.
- Add a chat form under each of the nine families in
  `figure-grammar-specimens.md`, on the same facts as the SVG specimen, and
  point `figure-grammar.md` section 7 at them.
- Add screenshot and raster image rules to the shared doctrine beside the
  media carrier: a screenshot shows a surface as it is and never a
  relationship; capture Graphite light at 2x unless the subject is a skin or
  a mode; crop to the surface plus one margin unit; annotate only with
  numbered markers keyed in the caption, never drawn arrows; alt text names
  the surface and its state; PNG for chrome, WebP for photographs, inside
  the portal byte budget; committed beside the source in a folder named for
  the page; refreshed when the surface changes. An imported raster
  diagram is never a carrier; it is redrawn in a family. The media rule of
  `cf-docs-portal/references/content-contract.md`, which fails an SVG file
  closed, gains one author-facing line: on the portal and in present a
  figure is inline SVG through the figure block, and in chat and a README
  it is the ASCII chat form.
- State the altitude contract table once (`figure-grammar.md` section 3) and
  the rule not to clone the evidence board once (the doctrine, section 0),
  with the board path in the doctrine and the grammar only; the other files
  point.
- Trim `cf-present/resources/how-presentation-works.md` to present content:
  what the human sees, block order as attention order, the worked contrast;
  its general steps become one pointer to the method.
- Add a "How a portal page thinks" walk to
  `cf-docs-portal/references/visual-craft.md`: one page taken through the
  method at Concept, Architecture, Technical and one how-to section, naming
  reader, question and family per panel; it replaces section 1's bullets.
- Add one pointer sentence to `cf-design/SKILL.md` section 1: a CodeFlow
  utility surface (portal, present) loads `cf-docs-portal` or `cf-present`
  and the method, not this skill.
