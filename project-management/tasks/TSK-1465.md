# TSK-1465: The decision-map figure counts the decisions the map lists

## Description

`codeflow test --only docs-portal` fails on `main` 63061d210 and on 4cc6de60a: "docs-portal/figures/decision-map/technical.json: rule 6 (fidelity): fact "70 decisions, 3 superseded" draws true but docs/decision-map.md#technical gives false". PR 772 brought `docs/decision-map.md`'s count sentence to its table's 75 rows; the figure's fact still checks for the text "70 decisions, 3 with `status: superseded`." (`kind: contains`, `technical.json:29-38` at 4cc6de60a). The check is `crates/codeflow-core/src/validate/portal/figures.rs:844`.

The defect has a cause beyond this one number. Every pull request that adds a decision updates the map's count sentence, and the figure repeats that sentence as fixed text, so each new ADR breaks the portal build until someone edits the figure by hand. A planning pull request cannot carry the figure edit, because a planning amendment admits only records and `docs/` paths (`work.classification`), and records-only evidence does not run the portal check, so the break reaches `main` unseen. That is what happened with PR 772.

Non-goal: no other figure's design changes beyond what AC-3 finds.

## Outcome

After this merges, `main`'s docs portal check passes, and adding a decision to `docs/decision-map.md` no longer breaks the decision-map figure without the author being told in the same pull request.

## Deliverables

- the figure: `docs-portal/figures/decision-map/technical.json`
- the durable fix, the builder's pick stated with its reason: the figure fact grammar and its checker (`crates/codeflow-core/src/validate/portal/figures.rs`, `crates/codeflow-present/web/src/figure-grammar.mjs`), or the path rule that makes `codeflow ci` run the figure check (provisional; the builder confirms the files)
- tests for the chosen fix
- the release note: `changelog.d/TSK-1465.md`

## Acceptance Criteria

- AC-1 The decision-map figure's count fact shall agree with `docs/decision-map.md` at the head; evidence: `codeflow test --only docs-portal` failing with figure rule 6 on `main`'s tree (4cc6de60a) and passing at the head, both outputs kept.
- AC-2 Adding a decision to `docs/decision-map.md` shall no longer leave the figure silently stale. Either the figure's count is derived from the map's table, so a new row needs no figure edit, or `codeflow ci` runs the figure fidelity check, or names the stale figure, for any range that changes `docs/decision-map.md` or `docs/decisions/`, records-only and planning ranges included. The builder shows which is the smaller durable change and states why. It fails closed: a count that cannot be derived is a refusal, never a pass. Evidence: a fixture that adds one decision row, stale before the change and derived or refused after.
- AC-3 Every other portal figure fact that repeats a count or number from a `docs/` page as fixed text shall be listed with its disposition (moved to the AC-2 mechanism, or kept with a reason); evidence: the list with file:line.
