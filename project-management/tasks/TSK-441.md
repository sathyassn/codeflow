# TSK-441: cf-present is the default surface and explains visually, with colour chosen by judgment

## Description

Operator decision of 2026-10-22, two parts in one adopter-facing
change. First, the default surface: in a project that uses CodeFlow,
explaining something visually defaults to `cf-present`; the harness's
own artifact (a Claude Artifact page, an inline widget) is used only
when the operator asks for it or the content must be shared, since
`cf-present` is local and cannot be shared. Today the managed instructions say
the opposite: the "show something complex" row of the Claude harness
table (`assets/base/CLAUDE.md.tmpl:44`, installed as `CLAUDE.md:45`),
the managed-block row of the same name (`assets/base/AGENTS.md.tmpl:75`)
and `.codeflow/rules/writing.md` "Figures by surface"
(`assets/base/rules/writing.md:147`) send a page people will comment on
or share to the harness's page publisher, and the `cf-present` skill
trigger describes it as a review surface for when one materially helps.

Second, figure authoring: the operator reports that `cf-present`
figures look monochrome. The figure guidance in `cf-present` and
`cf-docs-portal` (`figure-grammar.md` and the visual-craft references)
maps most marks to the grey ink roles and does not say that a figure's
governing path or governing actors take the accent-bearing marks
(`done`, `agent`, `act`, `used`, `return`), which `present.reference.html`
and `portal.reference.html` already do. The operator's direction of
2026-10-22: figures may use the existing colours or added ones that
harmonise with them; there is no hard restriction, but the result must
show strong aesthetic judgment, elegant and coherent across Graphite,
Slate and Sage in light and dark, and taste is the operator's. So this
part is a design pass with `cf-design`, led by the Claude design primary
(Fable 5.1), that decides whether figures gain a small set of harmonious
category hues per skin and mode beside the one accent and how the
grammar uses accent against category colour; a change of tokens follows
only from that decision.

Third, the skill itself. The operator's words of 2026-10-22: "make
sure the cf-present skill is properly updated as part of the task to
ensure it presents things visually rich, explaining things visually in
a nicer way, with supporting text and preferably short prose and bullet
points and not walls of text; any concept or such should be explained
with diagrams and flows, not text." The failure shown: one paragraph
defining follow-up, lane and work stream, where a figure belongs. The
worked example is the coordination ledger presentation, revision 5 of
session `dac94188` (five figures, one line of prose, tables in a
disclosure), generated by `scratchpad/coord-present/build3.py` in that
session's scratchpad. Also seen: `codeflow present check` passed a
document whose sequence figure failed to draw at render time (its
JSON-sourced facts used the contains check) and showed "The figure was
not drawn".

Outcome: **in a CodeFlow project, a figure or explanation that needs
more than an inline reply goes to `cf-present` by default, with the
harness's artifact or widget the stated exception for the operator's
ask or content that must be shared; and, after a design pass the operator
signs off on, the figure guidance says that a figure draws its
governing path or governing actors with the accent-bearing marks while
grey stays for context, and, where the design pass adds them, a small
set of harmonious category hues per skin and mode with the grammar
saying when a figure uses accent and when category colour; rule 3
(never hue alone) and the contrast floors hold; every home changes
together; and the operator sees the reference figures redrawn in each
skin and mode in `cf-present` before the task lands; and the
`cf-present` skill and its resources require a visually rich document:
every concept, mechanism, lifecycle, ownership model or comparison
carried by a figure in the right grammar family, text limited to a
one-line lead, the caption and short bullets, tables in a disclosure,
the governing path in accent-bearing marks, a pre-handoff check of
figures against narrative and table blocks, and a rendered look before
handoff.**

Rules the text states: an inline figure in the reply stays the default
where the surface renders one and the answer is short; beyond that,
`cf-present`; the harness page or widget only on the operator's ask or
for sharing; fenced ASCII in Markdown files, records, PR bodies and
terminals; never Mermaid. The exception is stated in each home in one
sentence so a reader cannot take the harness page as an equal option.

Non-goals: new figure families; changing the skins themselves; a
change that is not shown to the operator before landing.

Added by the EPC-022 amendment of 2026-10-22 at the operator's
direction; adopter-facing, since it changes managed instructions.
