# TSK-1283: Hosted CI runs only the record checks for a records-only pull request

## Description

Source: the Director's request via coord/planning on 2026-11-03. PR 544 changes only four Markdown records, but it runs 43 hosted checks (full gates, coverage, 12 Windows partitions, release targets) and holds about 30 hosted jobs while the runners are saturated. TSK-1151 (PR 486) gives local records-only candidates a lighter path, but it does not change hosted job selection.

This task makes hosted job selection depend on a records-only verdict that trusted code computes. The threat is a pull request that edits the workflow, the classifier, the policy or the declared record paths in order to skip jobs, so the classification runs from the base branch's contents at an exact base SHA, or from a digest-pinned decider like TSK-1239's `DECIDER_SHA256`, and never from the head. It waits for TSK-1151 for its records-only classifier (see Blocker). Related: TSK-1239 (the decider pin) and ADR-0091.

Owner: coord/planning (builder to be staffed). Adopter-facing and security-relevant: the shipped workflow and the required check change.

## Outcome

After this merges, a pull request that changes only declared records runs only the record checks on hosted CI, and the required check still cannot be passed by a pull request that edits what decides the selection.

## Deliverables

- the Findings (how `codeflow-ci.yml` selects jobs today, the trusted-classification options, the threat): this record
- the trusted job selection and the shared records-only definition, with tests: the workflow, the classifier and the files the builder confirms
- the operator patch: `operator-patches/` in the task worktree, with a branch and digest check like `apply-TSK-1239.sh`
- the release note: `changelog.d/TSK-1283.md`

## Acceptance Criteria

- AC-1 Before any change, the builder shall record how `codeflow-ci.yml` selects jobs today, how a classification can run from trusted code (base-branch contents at an exact base SHA, or a digest-pinned decider like TSK-1239's `DECIDER_SHA256`), and the threat: a pull request that edits the workflow, the classifier, the policy or the declared record paths to skip jobs; evidence: a `## Findings` section committed before the first code change.
- AC-2 The job selection shall classify the diff from the merge base to the exact head SHA using the base branch's classifier and the base branch's declared record paths, never the head's. A diff that touches the workflow, the classifier or decider, the policy, the test config, or any path outside the declared records shall get the full job set; evidence: tests, including a pull request that adds its own path to the record declaration.
- AC-3 A records-only verdict shall run record validation, the policy checks, commit standards and the secret scan, and skip build, test, coverage, Windows and release-target jobs; evidence: a fixture run that names the jobs selected for a records-only diff and for a code diff.
- AC-4 The required "codeflow gates" check shall report success only when the trusted classifier returned records-only and the selected jobs passed, or when the full job set passed. It shall fail closed when the classifier errors, times out or cannot read the base; evidence: tests for each case.
- AC-5 The hosted classification and TSK-1151's `classify_landing_into` shall share one definition of a records-only diff; evidence: one shared function or data source, and a test that the two agree on the TSK-1151 fixtures.
- AC-6 With the patched workflow in a local fixture repository, a records-only pull request shall run only the AC-3 jobs and the required check shall pass, while a pull request that also edits the workflow shall run the full set; hosted fixture pull requests on `sathyassn/codeflow` follow only after the patch reaches main, under TSK-1270's rules (no scratch GitHub repository, per the operator's ruling); evidence: the local run output and, later, the run links. (journey)
- AC-7 The workflow change shall come as an operator patch (`operator-patches/` in the task worktree, with a branch and digest check like `apply-TSK-1239.sh`), and the task shall get a cross-lineage security review with the `cf-security-reviewer` checklist; evidence: the patch file and the review record.
- AC-8 A changelog entry shall describe the change; evidence: `changelog.d/TSK-1283.md`.
