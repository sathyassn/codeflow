# TSK-179: Codex is woken by each present answer

## Description

TSK-120's qualification showed that Claude Code and Grok Build run the
cf-present wait as a background task that wakes the model once per event,
while Codex CLI cannot: it runs the wait inside its turn and polls it with a
model step every 10 to 20 s, and nothing wakes it when an answer arrives.
With Codex an answer, a correction or a review is stored at once and
delivered on the agent's next turn, and the page shows "Stored, waiting for
agent" until then; cf-present's loop reference and the 3.0.0 changelog say
so. This task qualifies Codex on the same path once Codex CLI can run a
command in the background and wake the model when it exits, and updates the
skill to use that mechanism. It waits on that external capability.

## Affected surfaces and interfaces

- `cf-present` `references/feedback-loop.md` and its mirrors, the changelog,
  and the qualification record; no runtime change is expected.

## Acceptance Criteria

- AC-1 When Codex CLI offers a background command that wakes the model on
      exit, the cf-present loop reference teaches it for Codex; evidence:
      the reference text with mirrors and the manifest test.
- AC-2 Codex is qualified on the TSK-120 path: each answer wakes the live
      session once, it acknowledges each, and a wait outlives ten minutes by
      re-arming without a model turn; evidence: the recorded session log,
      the driver log and the ledger, as TSK-120 recorded them.
- AC-3 The Codex limit is removed from the loop reference and the changelog
      states the change; evidence: the diff.

## Execution contract

interactive Codex seat through Herdr, never headless. Integration target

- owner: EPC-016 line lead
