# TSK-1281: Local checks name the cargo tests that guard the paths a change touches

## Description

Source: coord/visual-docs at 08:3x on 2026-11-03, at the Director's request. PR 525 (TSK-1162) at `52ed290e1` changed 52 files under `assets/base/agents/skills/cf-present/` and added a record link (`TSK-1162.md:128` to `../../docs/verification/evidence/tsk-1162/ink-swatches.html`). Local `codeflow test --mode quick` passed all 7 quick targets, and none of them included the `init_e2e` or `release_contract` suites. Hosted codeflow-ci run 41637830020 then failed two tests the change touches:

- `init_e2e.rs:437`, `init_full_tier_renders_the_real_asset_tree_end_to_end`: the cf-present managed count was 136 against an expected 50, because `PRESENT_SKILL_FILES` is stale
- `release_contract.rs:481`, `kept_markdown_does_not_link_into_the_evidence_the_archive_leaves_out`

Quick selected what it defines. The gap is that nothing maps touched paths to the cargo tests that guard them, so the builder picks targeted tests by hand and missed both. Duplicate check (coord/planning): no existing task covers it; TSK-1039 covers explaining a quick gate with no base, and TSK-352 covers candidate evidence. Related: TSK-1039 and ADR-0085. No structural predecessor was found, so `depends_on` is empty.

Owner: coord/planning (builder to be staffed). Adopter-facing: the mapping lives in the test config and the shipped build guidance.

## Outcome

After this merges, a builder who changes paths gets the names of the cargo tests that guard them, and any touched path without a guarding test is printed as unguarded.

## Deliverables

- the Findings (both misses reproduced, the path-class sweep, the design choice and its reason): this record
- the mapping as test config data, its reader and tests: the test config and the files under `crates/codeflow-core/` and `crates/codeflow-cli/` that the builder confirms
- the shipped build guidance and the CLI reference: `docs/cli.md` and the guidance under `assets/`
- the release note: `changelog.d/TSK-1281.md`

## Acceptance Criteria

- AC-1 Before any change, the builder shall investigate: reproduce both misses from PR 525's range, sweep which path classes are guarded by which cargo tests (managed assets and skill trees, records and Markdown links, policy and hooks, workflows, test config), and choose where the mapping lives (a quick target, essential's selection, or a printed list for the build loop), with the reason; evidence: a `## Findings` section committed before the first code change.
- AC-2 For a change against its base, codeflow shall name the cargo tests that guard each touched path class, and run them where the chosen design runs them. On PR 525's range it names `init_e2e` and `release_contract`; evidence: a test on that fixture, failing before the change and passing after. (journey)
- AC-3 The mapping shall be data in the test config, not code. A touched path with no mapping shall be printed as unguarded and never passed over in silence; evidence: tests for a mapped and an unmapped path.
- AC-4 The shipped build guidance and `docs/cli.md` shall describe the step; evidence: the diff.
- AC-5 A changelog entry shall describe the change; evidence: `changelog.d/TSK-1281.md`.
