# TSK-233: exec-guard stops refusing certified prose that quotes a launcher word

## Description

Issue 66: exec-guard refuses prose such as "; supersedes", "; su" or "such
as" inside a heredoc, an `echo` or a grep pattern, because its privilege,
headless and dangerous checks match a privileged word as a substring of the
raw line, not as a token. Root cause: a substring matched instead of a token.

A word-boundary edit to those checks cannot be made safely. Review showed that
a shell can reach a launcher without its name appearing as a word (`s???` with
a file named `sudo`, extglob and zsh qualifiers, a `declare -n` nameref that
rewrites `PATH`), so the 3.0.0 raw matching stays as the floor on every line,
and `privilege.rs`, `headless.rs` and `dangerous.rs` are unchanged.

Relief comes only from a positive proof. A new strict tokenizer,
`crates/codeflow-core/src/security/prose.rs`, certifies a line only when the
whole line parses in a closed grammar: `echo`, `printf` (a `%s` and `%%` only
format), `grep` and `cat`, bare or single-quoted or double-quoted words (no
backslash, `$` or backtick), the separators `;`, `&&`, `||`, `|` and newline,
redirects to a document file (md, markdown, txt, rst, log) plus `2>&1` and
`>&2` whose target is, when the call is judged, a new file or an existing
plain non-executable file with one hard link (never a symbolic link,
hard-linked file, pipe, device or executable, or a path under `/dev`, `/proc`
or `/sys`), and one
quoted heredoc for `cat`. Anything else, including a glob, an
expansion, `#`, a path program, a control character or non-ASCII space, is not
certified and falls to the 3.0.0 floor. A certified line skips only the
privilege, headless and dangerous checks (the deletion check composed in the
dangerous module included; none of the four programs deletes); every other
module still runs. Only
the Bash and `run_terminal_command` payloads are certified, never PowerShell.

Class and siblings (operator direction: treat the issue as a defect class).
Searched `security/privilege.rs`, `dangerous.rs`, `outward.rs`, `headless.rs`,
`interpreter.rs`, `deletion.rs`, `actions.rs`, `pattern.rs`, `git.rs`,
`hooks/git_guard.rs` and `hooks/edit_guard.rs`, the Claude, Codex and Grok hook
entries and the scaffolded deny rules. Raw-substring members of the class: the
privilege chaining and wrapper checks, the `PATH=` and `LD_PRELOAD=` patterns,
the headless raw run and the dangerous-command regexes; one prose shape covers
all three modules together. Siblings that differ and are unchanged: outward,
deletion, interpreter and git-guard work on parsed tokens and only route lines;
edit-guard and protected-branch matching are anchored whole-path globs.
Boundary edits to the `PATH=`, `LD_PRELOAD=`, `bash -c`, `dd`, `mkfs`, `chmod`
and `chown` patterns were tried and dropped, because a name boundary cannot be
proved safe against shell indirection. Effect on adopting projects: a binary
change only, with no policy default, scaffolded hook, managed doc or upgrade
step behind it; it allows certified prose the guard refused and refuses
nothing it allowed before.

Residuals, both with the operator: (1) shell startup state that changes how a
certified line runs, an alias or function shadowing `echo`, `printf`, `grep` or
`cat`, or a zsh global alias that expands an argument (review 07: `alias -g`
makes `echo ARG` run a second command); outside the model, as `ls='sudo ls'`
already is for 3.0.0. (2) A certified line can create a document that a later
call runs as a script (`bash a.md`); 3.0.0 already allows a plain `printf`
redirected into a `.sh` file. Overwriting an existing executable, or writing
through a symbolic link, a hard link, a named pipe or a device by way of a
document name (reviews 07 and 08), is closed by the on-disk target check, not
left as a residual. Two given-up classes stay refused
and need the file route: a double-quoted pattern holding a backslash, and
`git commit -m` or `gh pr create --body` text.

Non-goals: parsing arbitrary shell, changing any raw rule, adding programs to
the closed list, and certifying PowerShell.

## Acceptance Criteria

- AC-1 On every line the tokenizer does not certify, the privilege, headless and dangerous verdicts equal 3.0.0's, and `privilege.rs`, `headless.rs` and `dangerous.rs` are byte-identical to `origin/main`; a differential over a corpus of more than 10,000 launcher, prose, mutated and spliced lines shows every changed verdict is a certified line that only loses a raw finding (`only_certified_lines_change_and_they_only_lose_the_three_raw_findings`, and the blocked table in `exec_guard_keeps_the_3_0_0_floor_on_every_line_it_cannot_certify`).
- AC-2 A line the tokenizer certifies runs, in bash with extglob and aliases and in zsh with extendedglob, exactly the listed programs and nothing else: no stub of any launcher, peer, destructive command, shell or interpreter is called and no file other than a document redirect target is created, over a mutated and spliced corpus (`certified_lines_run_only_the_four_programs_in_bash_and_zsh`).
- AC-3 A wildcard, glob, expansion or quoting form inside any launcher, peer or dangerous name, in any command position, is never certified (`a_wildcard_inside_a_dangerous_name_is_never_certified`), and only a document-extension redirect target is certified (`only_document_files_may_be_written_by_a_certified_line`).
- AC-4 A redirect target that is a symbolic link, a hard-linked file, a named pipe, a directory, an executable file, in a directory that does not exist, or a path that resolves under `/dev`, `/proc` or `/sys` (including `/./dev` and a symlinked parent) is not certified (`exec_guard_does_not_certify_a_write_that_reaches_a_link_pipe_or_executable`, `a_write_must_reach_a_new_or_plain_non_executable_file`).
- AC-5 Issue 66's heredoc, `printf`, `grep '; su'` and `echo "(...; supersedes ...)"` lines are allowed, and a refusal names the prose shape and the file route in its message (`exec_guard_allows_certified_prose_and_keeps_the_3_0_0_floor_elsewhere`).
- AC-6 Every bypass form the design reviews found (a quote character before a chained launcher, `awk` with `system`, `s???`, `su[d]o`, extglob and zsh qualifiers, `printf -v`, `printf '%n'`, `rg`, a written shell script, `LD_PRELOAD=`, `export PATH=...:/tmp`, `env -S`, `runas.exe`, `cmd /c format`) is refused through the real hook with 3.0.0's rule, and PowerShell is never certified (same test as AC-5).
- AC-7 On the real `codeflow hook exec-guard`, the issue's heredoc is allowed and `true; su -` is still refused with `security.privilege_escalation` (`installed_minimal_hooks_refuse_each_family_and_allow_real_ordinary_work`) (journey).
- AC-8 The exemption lives in `security/prose.rs` and the exec-guard dispatch only. A certified line skips the privilege, headless and dangerous modules (the deletion check composed in the dangerous module included, since no listed program deletes); the outward, interpreter, edit and git checks run on it as before (`only_certified_lines_change_and_they_only_lose_the_three_raw_findings`).
- AC-9 `docs/policy-reference.md` and the refusal text state the prose shape and the file route, and the CHANGELOG 3.1.0 entry is a patch that names both residuals.
