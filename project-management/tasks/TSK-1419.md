# TSK-1419: The hosted policy check fetches the shared registry before codeflow ci judges a pull request

## Description

TSK-1135's capability impact rule joins legacy catalog entries through the shared id registry's bindings, so the hosted `commit standards` job must fetch `codeflow/registry` before it runs `codeflow ci`. The EPC-026 line made that reorder (commit `aab917de6`, "fetch registry before hosted judging"). The EPC-026 main sync (TSK-1371) takes main's three `codeflow-policy.yml` copies whole, by the Director's ruling of 2026-11-10, because main rewrote the verdict job under the default-branch authority model. That drops the reorder from the line. Main still runs "Fetch the shared registry" after `codeflow ci`.

On `pull_request_target`, main's job builds codeflow from the default branch's own commit. Once EPC-026 lands on main, the capability rule runs there, and without the earlier fetch it would judge against missing bindings. This task moves main's fetch step (with the "Assert the authority checkout" step after it) to just before "codeflow ci (commit + branch + PR-body standards)" in all three copies. It goes through the operator patch path because the workflow files are operator-owned. Source: `coordination/coordinators/capabilities/builders/epc026-main-sync-analysis.md` section 3.1.

Non-goals: the line's dropped `EXPECTED_*` pre-check and post-run snapshot, which main's own head, base-ref and body-digest checks cover (same section).

## Outcome

After this lands on main, the hosted `commit standards` job fetches the shared registry before `codeflow ci` in the live workflow, the managed asset and the baseline, so the capability impact rule never judges without the registry's bindings.

## Deliverables

- `.github/workflows/codeflow-policy.yml`, its managed asset and its baseline copy (provisional paths; the builder confirms them at claim)
- a release note: `changelog.d/TSK-1419.md`

## Acceptance Criteria

- AC-1 In all three `codeflow-policy.yml` copies on main, the "Fetch the shared registry" step and its "Assert the authority checkout" step shall run before the `codeflow ci` step, the registry shall be fetched once per job, and the three copies shall stay byte-identical where they are today; evidence: the diff and the existing workflow consistency tests passing.
- AC-2 This shall be on main before EPC-026 lands there; evidence: the merge order recorded in the EPC-026 checkpoint pull request body.
- AC-3 A hosted `pull_request_target` run on main after this lands shall show the registry fetch step finishing before `codeflow ci` starts; evidence: the run's step times.
