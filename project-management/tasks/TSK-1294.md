# TSK-1294: A project routes duties and roles to models and sets their effort

## Description

The operator ruled on 2026-11-03 that a consuming project chooses which model does which duty or role, and at what effort, and that every catalog field can be overridden. This task adds the schema 3 `routes` and `effort` blocks: per duty, and per coordination role (director, coordinator, worker, lone session), each maps to any shipped or project line (TSK-1293) with an effort from that line's allowed list. A project can also override the usage fields TSK-1292 adds, for example `launch` to use Fable as a seat.

Cross-lineage independent review, security review included, stays the default. A project with one model family, or one that chooses otherwise, can relax it; the relaxation is recorded as reduced assurance in the review evidence, never silently. The only refusals are the floors: no headless seats, the pinned id resolve returns, and failing closed with the key named on an invalid file. Security relevant: this decides who reviews whose work.

## Outcome

After this merges, a project maintainer can route each duty and role to any shipped or project model at a chosen effort, and see each effective route and its source.

## Deliverables

- the schema 3 `routes` and `effort` blocks and field overrides: `crates/codeflow-core/src/model_catalog/`
- the reduced-assurance record: the review evidence `codeflow ci` and `models resolve` read
- doctor: `codeflow doctor --check model-bindings`
- tests and docs: unit and CLI tests, `references/model-overrides.md` (mirrored)
- release note: `changelog.d/TSK-1294.md`

## Acceptance Criteria

- AC-1 When the project file routes a duty or a coordination role (director, coordinator, worker, lone session) to a shipped or project line with an effort from that line's allowed list, `codeflow models resolve` shall return the project value; when the block is absent, the defaults shall be unchanged; evidence: CLI tests for each role and for an absent block.
- AC-2 The project file may override any catalog field TSK-1292 adds, such as `launch: seat` for Fable; evidence: a test that resolves Fable as a seat after the override.
- AC-3 When a route or override turns off cross-lineage review, security review included, resolve shall still return it, and the review evidence for work under it shall record reduced assurance naming the key; evidence: a test that reads the recorded reduced assurance.
- AC-4 The floors shall refuse with the floor named: a headless route, a launch of an id other than the pinned one resolve returned, and an invalid file (an effort outside the line's list, an unknown line or role); evidence: one test per case.
- AC-5 `codeflow doctor --check model-bindings` shall show each effective route and effort with its source: default, project or task override; evidence: a doctor output test.
- AC-6 (journey) In a scratch project with the installed build, a maintainer routes builds to a project line, sets Coordinator effort to high and turns off cross-lineage review; resolve shows all three, and a review's evidence records the reduced assurance; evidence: the journey output.
- AC-7 A changelog entry shall describe the blocks; evidence: `changelog.d/TSK-1294.md`.
