# TSK-1372: Projects can check commit author and committer identity, off by default

## Description

A commit's identity shows who wrote it and what tool committed it, and a personal name or email in a public history cannot be taken back. CodeFlow checks commit messages but not commit identity. The operator decided on 2026-11-06 that the user is the author and the agent acts as committer: TSK-1348's `setup-apps` prints the App's committer name and email once, and checked-in project settings hold them for agent sessions. Those checked-in values need no key and are not secrets. `agent-token --committer` needs the key, so it is only one way the person running setup can get the values, never an input to these checks. The committer field is a provenance record, not proof, because git lets anyone set it; proof of who pushed is the token. TSK-1348 keeps enforcement out of its own scope, so this task carries it, and a project can also require a no-reply author address.

The operator approved this on 2026-11-06, relayed by the Director, with two conditions: "make sure we don't end up doing things that may make it harder for consuming projects - so any such stricter stuff should ahve optionality that's configurable" and "should we also check to make sure no names or personal emails are used and only no-reply or such ones should be used".

So every check is a separate policy setting, off by default for adopters, and this repository turns them on in its own policy. The operator approved the levels on 2026-11-06, relayed by the Director: the level is always set explicitly in project policy and never switches on repository visibility; `codeflow init` only suggests values from visibility, and `codeflow doctor` warns when a public repository has the email check off. The agent App stays optional, so nothing here may require it. Bounded scope: the checks judge only the commits in a change and never rewrite existing history. Non-goals: detecting a real name in general, which cannot be done reliably; any rule in CI that the committer must be a bot, because humans commit too; and treating the committer field as a security control. It touches guards and CI admission, so it takes a cross-family review.

## Outcome

After this merges, a project owner can turn on each commit identity check as off, warn or block, and a project that sets nothing sees no change.

## Deliverables

- The policy settings and their schema: `crates/codeflow-core/src/hooks/policy_schema.rs`, `docs/policy-reference.md`
- The in-session guard check: `crates/codeflow-core/src/hooks/git_guard.rs`, with session detection from `crates/codeflow-core/src/root_checkout.rs`
- The author checks in the git hook and in the existing commit standards job: `crates/codeflow-core/src/hooks/git_hook.rs`, `crates/codeflow-cli/src/cmd/ci.rs`, `.github/workflows/codeflow-policy.yml` and `assets/base/ci/codeflow-policy.yml`

- The release note: `changelog.d/TSK-1372.md`

## Acceptance Criteria

- AC-1 Each identity check shall have its own policy setting taking `off`, `warn` or `block`, the author email check with separate levels for the local hook and for CI, and each shall default to `off`, so a project that sets nothing behaves exactly as before; any other value, the shared level `allow` included, shall be refused when the policy is read; evidence: schema tests for each value, for `allow` and for an unknown value, and a fresh `codeflow init` project, with the AC-9 suggestion declined, whose commit, push and `codeflow ci` results are unchanged with a personal author address. (journey)
- AC-2 When the in-session committer check is on, in a session the hook identifies as an agent (`AGENT_MARKERS`), the guard shall judge by the setting a commit whose committer name or email differs from the expected values checked in to the project's policy, or whose author equals those values or has a name ending `[bot]`; a check set to `warn` or `block` with either value missing shall be refused when the policy is read; the guard shall read only those checked-in values, never `agent-token --committer` or any store or network source, so the check needs no key or token and works at TSK-1348's committer-values level, and a project with no agent App leaves it `off`; a refusal shall name the rule and the sanctioned path; a commit made with no agent marker is not judged by this check and is never counted as proof of a human; the docs shall say the committer field is a provenance record, not proof, that an agent can leave a session the hook can detect, and so this check catches a misconfigured session and is not a security control; evidence: guard tests for a matching session, a wrong committer, a bot author, a missing value and a shell with no marker, and the docs sentences.
- AC-3 When the author email check is on, the git hook and CI shall both judge each commit's author email against a glob list the project sets, because a human's commit counts too; the check shall run on merge commits as well, ahead of the merge return in `commit_msg`; the documented suggested value is `*@users.noreply.github.com` and company domains may be listed; a check set to `warn` or `block` with an empty or missing list shall be refused when the policy is read, never passed silently, and `off` with no list shall load; evidence: tests for a match, a miss, a company domain, a local merge and an empty list, in the hook and in `codeflow ci`.
- AC-4 When the optional author name check is on, the author name shall match the login in the no-reply address of the same commit, in either GitHub form, `login@users.noreply.github.com` or `<id>+login@users.noreply.github.com`, where the login is the part after `+` when one is present; a commit whose address has no login shall be judged by the setting; the docs shall say this compares a name with a login and cannot detect a real name in general; evidence: tests for a match in both forms, a mismatch and a non-noreply address, and the docs sentence.
- AC-5 The CI checks shall run inside the existing commit standards job, adding no job and no required check name, and CI shall have no rule that the committer is a bot; a commit shall be excepted only when GitHub's record of that commit shows `verification.verified` and either a merge GitHub made (committer login `web-flow` and more than one parent) or an author and a committer that are the same account, which GitHub lists as a Bot, so the signature is that bot's own; a signature by any other account never excepts a commit; when that record cannot be read the commit shall be judged; a bot that does not meet this is judged like anyone else, and a project may list its address in the AC-3 glob list; a name, an email, a subject, a parent count alone, a `web-flow` signature alone and the pull request's opener shall never except a commit; evidence: a workflow test showing the job list unchanged, and tests that each of these is still judged: a forged dependency-bot author string, an unsigned two-parent commit, a single-parent web-edited commit, a human commit on a bot's pull request, a commit whose author is a Bot and whose committer is a user with a verified signature, and a commit whose record cannot be read.
- AC-6 The checks shall judge only the commits in the change, and nothing shall rewrite or ask to rewrite existing history; evidence: a test on a repository whose earlier history holds a personal address, where a clean change passes.
- AC-7 This repository shall set the author email check to `block` at both the hook and CI levels and the author name check to `warn` in its own `.codeflow/policy.json`, and the policy reference shall describe each setting and how to adopt it; evidence: the policy diff, a `codeflow ci` run on this repository with the checks on, and `codeflow validate --docs`.
- AC-8 No commit rule shall relax for a bot-committed commit: it shall pass every commit standard, and no policy, hook or check shall be loosened or special-cased for it; evidence: tests that a bot-committed commit with an AI trailer and one with a non-conventional message are both refused.
- AC-9 `codeflow init` shall suggest levels from the repository's visibility and write a level only as an explicit value in project policy that the person accepts: for a public repository, author email `block` in the local hook, `warn` or `block` in CI, and author name `warn`; for a private repository, author email `warn` or `off` at both levels and author name `off`; when visibility cannot be read it shall suggest nothing and leave every check `off`; no check shall read visibility at run time, so a change of visibility never changes a level; evidence: init tests for a public, a private and an unreadable repository, a declined suggestion leaving the policy unchanged, and a test that changing visibility changes no judgment.
- AC-10 `codeflow doctor` shall warn when a public repository has the author email check `off` at either level, the warning shall change no level and block nothing, and when visibility cannot be read doctor shall say it could not check; evidence: doctor tests for a public repository with the check off and on, a private repository and an unreadable repository.
