# TSK-1372: Projects can check commit author and committer identity, off by default

## Description

A commit's identity shows who wrote it and what tool committed it, and a personal name or email in a public history cannot be taken back. CodeFlow checks commit messages but not commit identity. Once TSK-1348's agent App exists, an agent session can commit as the bot while the author stays the human, and a project can require a no-reply author address.

The operator approved this on 2026-11-06, relayed by the Director, with two conditions: "make sure we don't end up doing things that may make it harder for consuming projects - so any such stricter stuff should ahve optionality that's configurable" and "should we also check to make sure no names or personal emails are used and only no-reply or such ones should be used".

So every check is a separate policy setting, off by default for adopters, and this repository turns them on in its own policy. Bounded scope: the checks judge only the commits in a change and never rewrite existing history. Non-goals: detecting a real name in general, which cannot be done reliably, and any rule in CI that the committer must be a bot, because humans commit too. It touches guards and CI admission, so it takes a cross-family review.

## Outcome

After this merges, a project owner can turn on each commit identity check as off, warn or block, and a project that sets nothing sees no change.

## Deliverables

- The policy settings and their schema: `crates/codeflow-core/src/hooks/policy_schema.rs`, `docs/policy-reference.md`
- The in-session guard check: the git-guard sources under `crates/codeflow-core/src/hooks/`
- The author checks in the git hook and in the existing commit standards job: the hook sources, `.github/workflows/codeflow-policy.yml` and `assets/base/ci/codeflow-policy.yml`
- This repository's settings: `.codeflow/policy.json`
- The release note: `changelog.d/TSK-1372.md`

## Acceptance Criteria

- AC-1 Each identity check shall have its own policy setting taking `off`, `warn` or `block`, and each shall default to `off`, so a project that sets nothing behaves exactly as before; an unknown value shall be refused when the policy is read; evidence: schema tests for each value and for an unknown value, and a fresh `codeflow init` project whose commit, push and `codeflow ci` results are unchanged with a personal author address. (journey)
- AC-2 When the in-session committer check is on, in an agent session on a project with the agent App set up, the guard shall judge a commit whose committer is not the bot, or whose author is a bot, by the setting; on a project with no agent App the check shall do nothing; a refusal shall name the rule and the sanctioned path; evidence: guard tests for a session with the App, a session without it and a human shell outside a session.
- AC-3 When the author email check is on, the git hook and CI shall both judge each commit's author email against a pattern list the project sets, because a human's commit counts too; the documented suggested value is `*@users.noreply.github.com` and company domains may be listed; a check set to `warn` or `block` with an empty or missing list shall be refused when the policy is read, never passed silently; evidence: tests for a match, a miss, a company domain and an empty list, in the hook and in `codeflow ci`.
- AC-4 When the optional author name check is on, the author name shall match the login in the no-reply address of the same commit, and a commit whose address has no login shall be judged by the setting; the docs shall say this compares a name with a login and cannot detect a real name in general; evidence: tests for a match, a mismatch and a non-noreply address, and the docs sentence.
- AC-5 The CI checks shall run inside the existing commit standards job, adding no job and no required check name, and CI shall have no rule that the committer is a bot; GitHub merge commits and dependency bots shall be excepted by an identity a requester cannot forge, such as GitHub's verified signature or the pull request's verified author, never by a name or email string alone; evidence: a workflow test showing the job list unchanged, and tests that a forged dependency-bot author string is still judged.
- AC-6 The checks shall judge only the commits in the change, and nothing shall rewrite or ask to rewrite existing history; evidence: a test on a repository whose earlier history holds a personal address, where a clean change passes.
- AC-7 This repository shall turn the checks on in its own `.codeflow/policy.json`, and the policy reference shall describe each setting and how to adopt it; evidence: the policy diff, a `codeflow ci` run on this repository with the checks on, and `codeflow validate --docs`.
