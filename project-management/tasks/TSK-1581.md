# TSK-1581: The guards match a heredoc's closing delimiter after joining backslash-newline continuations

## Description

Source: S1 in `coordination/coordinators/capabilities/reviews/tsk1344-p16-opus.md:78-85` (severity high if confirmed) and nit N5 at `:92`, with both comparison sites confirmed by Codex in `coordination/coordinators/capabilities/reviews/tsk1344-p14-p16-codex.md:56` (`crates/codeflow-core/src/security/composed.rs:698` and `crates/codeflow-core/src/hooks/git_guard.rs:9415` at `2ddc3313d4`). Both predate PR 706 (TSK-1344), which does not change those sites; TSK-1344 lists this task under `follow_ups` beside TSK-1570. Inert example strings only; none is ever run.

Defect (S1): both heredoc readers compare each physical line against the closing delimiter before joining backslash-newline continuations. In bash (`make_here_document`), when the heredoc delimiter is unquoted, body lines are read with backslash-newline removed and the joined line is compared to the delimiter. As a result, an inert input such as `cat <<EOF` followed by `EO\` and `F` on the next line, then a guarded command, then `EOF`, ends the heredoc at the joined `EOF` in bash and executes the guarded command, whereas the guards keep reading the command as heredoc data (which `git-guard` does not judge for `HEREDOC_DATA_READERS`). The reverse direction (a body line ending in `\`) causes bash to swallow the following delimiter line.

Related nit (N5): the zsh flag arm at `crates/codeflow-core/src/security/composed.rs:1057-1073` has no dialect gate, so in bash mode `$#a` is read as `${#a}` rather than `$#` followed by `a`. Fix this arm in the same task so it does not apply bash-only forms, with a regression row.

Premise: before changing code, verify bash and zsh behavior for quoted vs unquoted heredoc delimiters with backslash-newline continuations (manual references and inert test strings), check TSK-1570 for any overlap at claim, and complete the sibling sweep of every place in `codeflow-core` that treats a physical line as the unit for heredoc bodies, comments, or here-strings. Do not run a payload; guard tests feed inert strings only.

Non-goals: changing unrelated heredoc data-reader rules, or altering quoted-delimiter heredoc body semantics where the shell does not join continuations.

## Outcome

After this merges to `main`, `git-guard` and `exec-guard` share one heredoc delimiter matching routine that handles backslash-newline continuations as bash does, every sibling physical-line reader is accounted for, and the zsh flag arm no longer misreads bash `$#a`.

- AC-2 The two comparison sites (`composed.rs` and `git_guard.rs`) shall share one routine so they cannot drift apart, and a sibling sweep shall list every other place in the codebase that treats a physical line as the unit for heredoc bodies, comments, or here-strings with `file:line`, fixing each defect or stating why it is sound; evidence: the diff and the sibling sweep table in the pull request.
