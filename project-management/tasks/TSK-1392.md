# TSK-1392: Shell word reader keeps a dollar inside ANSI-C quoting as text

## Description

The git-guard shell word reader (`shell_words` in
`crates/codeflow-core/src/hooks/git_guard.rs`) marks a word as expanding
when it sees an unquoted `$`. For ANSI-C quoting, `$'...'`, the `$` opens
the quote, and the reader's ANSI-C arm removes that `$` from the word but
leaves the word's `expands` flag set. Bash keeps a `$` inside `$'...'`
literal, so `git branch -D $'feat/a$b'` deletes the branch named `feat/a$b`,
while the guard reads it as holding a variable and refuses. This is an
over-refusal, on the safe side, found in the TSK-326 cross-lineage review
(PR 718, Grok, nit N2). The same flag feeds `command_argv_live`, which both
guards' data-operand reader reads, so the fix reaches both. Scope is the
`expands` flag for the ANSI-C and `$"..."` arms; the decoding itself is
unchanged. Non-goal: reading any other quoting form.

Revisit event: when TSK-326 lands on the line.

## Outcome

After this merges, an agent can delete or name a branch spelled with
ANSI-C quoting that holds a `$` without the guard refusing it as a variable.

## Acceptance Criteria

- AC-1 When a word's only `$` opens ANSI-C or locale quoting (`$'feat/a$b'`, `$"feat/x"`), the shell word reader shall not mark the word as expanding; evidence: a unit test on `command_argv_live` that fails before the change and passes after. (serves EPC-022 AC-23)
- AC-2 When `git branch -D $'feat/a$b'` is judged, git-guard's discard check shall ask about the branch named `feat/a$b`, and a `$` outside the quote (`$'feat/a'$b`) shall still read as a variable; evidence: a discard unit test with a probe that is clean only for the literal name. (serves EPC-022 AC-23)
- AC-3 A `$` anywhere else in the same word, before or after the quoted part, shall still mark the word as expanding: when exec-guard reads `V=$(cat refs); git push origin $'x'"$V"`, `git push origin "$V"$'x'` or `git push origin "$V"$"x"`, it shall still refuse the push as unresolved, and git-guard shall not read a `sed` script word that holds an expanding `$` as literal; evidence: outward unit tests for each quote order and a `sed` script unit test. (serves EPC-022 AC-23)
