# TSK-206: fresh scaffolds pass the secret scan

## Description

A consuming project reported (sathyassn/codeflow#13) that the scaffold
commit fails Gitleaks in every adopting repository: rule `generic-api-key`
matches line 209 of `.claude/workflows/pipeline.workflow.js` and its
baseline copy, where the security stage's prose names
"vulnerable/malicious deps". It is prose, not a credential. CodeFlow's own
repository allows that exact match in its `.gitleaks.toml`, but the
allowance never shipped, and the adopter CI template scans the full
history, so the finding stays even after the line is edited. Reproduced
with Gitleaks 8.30.1 (the template's pin) on a fresh `codeflow init
--full` from the 3.0.0 binary: those two findings and no others. This
task rewords the line so new scaffolds are clean, and gives repositories
already scaffolded by 3.0.0 a managed, narrowly scoped allowance that
`codeflow update` brings, so their secret scan passes without a hand
edit. Non-goal: changing which rules the adopter scan runs.

## Acceptance Criteria

- AC-1 When `codeflow init` runs at the minimal, standard and full tiers in
  an empty repository, Gitleaks 8.30.1 with its default rules finds
  nothing in the scaffolded files; evidence: a test or gate target that
  scans fresh scaffolds of every tier with the pinned Gitleaks, failing on
  the 3.0.0 scaffold and passing after the fix.
- AC-2 When a repository whose history holds the 3.0.0 scaffold commit runs
  `codeflow update` and then the adopter CI template's secret-scan command,
  the scan passes, and the allowance it uses covers only the exact flagged
  prose in the managed workflow paths, so the same text in any other file,
  or any other value on that line, is still reported; evidence: a fixture
  repository scanned before and after update, with a control secret
  planted beside the allowed prose. (journey)
- AC-3 A repository with its own `.gitleaks.toml` keeps it: the update does
  not overwrite it, and the docs state how to extend it with CodeFlow's
  allowance; evidence: the fixture with an adopter config, and the doc
  diff.
- AC-4 The pipeline's security stage still names the dependency attack
  classes it hunts; evidence: the reworded line in the diff.
