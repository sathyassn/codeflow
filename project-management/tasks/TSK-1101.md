# TSK-1101: The present export sizes each stage frame from its content and waits for stages to paint

## Description

Four reviewers of the status report design brief (Fable, Codex GPT-6
Astra, Grok 4.7 and a fresh Claude Opus reader, consolidated on
2026-10-30 21:42 EDT) read the exported page and all saw the same defect:
the live session hosts each `html` stage inline
(`crates/codeflow-present/src/render.rs:591`, `.cf-stage-host`), but the
export puts each stage in a sandboxed frame with a fixed height
(`crates/codeflow-present/web/src/styles.css:651-654`, `.block--html
iframe { block-size: 28rem }`), so a stage taller than the frame is
clipped (a nine-row lane board showed seven rows) and a shorter one
leaves a blank gap, and at phone width the frame clips again. A static
capture of the export taken before the stages' script has painted shows
them blank. The reviewers ruled the export a review capture only and the
live session the handover surface until this is fixed, and named the
fix: size the frame from the stage's rendered height, or inline the
stage in the export as the live page does.

Outcome: **an exported present page shows every measured `html` stage
whole, at the height the live session measured for the export's own
geometry, in light and dark and at phone width, with no clipping and no
blank gap, declares any unmeasured stage instead of clipping it, and a
capture of the export taken after the page reports ready shows every
frame loaded.**

```text
  live session            export today                 export after
  stage inline            frame 28rem fixed            frame sized to content
  [ 9 rows shown ]        [ 7 rows ]..clipped          [ 9 rows shown ]
                          [ 2 rows ]  blank gap        [ 2 rows ]
```

Figure: the live page and the export today, and the export after the
fix, for a tall stage and a short one.

Decisions, each reversible and disclosed here:

- The runtime boundary of ADR-0049 is unchanged: the export keeps the
  sandboxed `iframe` with `srcdoc`, `sandbox=""`, no `allow-scripts` and
  no `allow-same-origin` (`crates/codeflow-present/src/export.rs`, the
  `export_html_stage_keeps_content_and_sandbox` test), no script runs
  inside a frame, and the stage is never inlined in an export. The
  height comes from the live session instead, measured in the export's
  own geometry: the live page renders each stage a second time in a
  hidden measuring host that reproduces the export frame's layout (the
  export's content width in CSS pixels, its padding, no review rail), at
  each content width the export produces (its wide and narrow columns),
  and reports the rendered height (stage id, revision, export content
  width, height in CSS pixels) to the session store over the existing
  session channel; the live page's own inline host, whose width changes
  with the review rail, is never the source. The export writes a stored
  height as the frame's block size only when the stored revision and
  content width equal the ones it renders at, with a floor of one row
  and no ceiling. A stage with no matching measurement (a document never
  opened live at that revision, or an export at another width) is
  `not measured`: it keeps the present fixed height and shows a visible
  notice, "height not measured at this width; open the session", never
  a silent clip. The outcome is therefore: every measured stage whole,
  every unmeasured stage declared.
- The reported height is validated input: numeric, bounded, bound to a
  stage id, a revision and a content width the store knows the export
  produces; a report for another revision, an unknown stage or an
  unlisted width is dropped; a later report for the same stage, revision
  and content width replaces the earlier one.
- The export marks the document ready (`data-cf-ready` on the root)
  only after every frame has fired `load` or failed within a bounded
  wait, from the host page's own script, with a visible notice on a
  frame that did not load, so a capture tool can wait on one signal.
- The export's chrome says what it is: a review capture of the session
  at a time, with the session the handover surface.

Non-goals: a change to the ADR-0049 boundary (no script in a frame, no
inline stage in an export); the figure grammar; a new block or a schema
field for height.

## Outcome

After this merges, an exported present page can be read and captured
whole, so a review of a document with `html` stages reads what the live
page shows.

## Deliverables

- the fix: the live page's measuring host in `crates/codeflow-present/web/src/` (renders each stage in the export's geometry at each export content width and reports the height), the session store and its channel in `crates/codeflow-present/src/` (the validated height record per stage, revision and export content width), `crates/codeflow-present/src/export.rs` (the frame's block size from the stored height, the notice when none, the capture chrome, the host-side ready marker), `crates/codeflow-present/web/src/styles.css` (the frame rule reads the written height)
- tests: an export render test with a tall stage (more rows than the old frame held) and a short stage, measured at 1200 and 400 px in light and dark with no clipping and no gap beyond the stage padding; a wrapping stage measured with the review rail open and with it closed at one viewport giving one height, since the measuring host ignores the rail; an export at another content width than any measured one showing the notice; the sandbox test unchanged (`sandbox=""`, no `allow-scripts`, no `allow-same-origin`, no script element in any frame); height reports refused when non-numeric, out of bounds, for an unknown stage, for another revision or for an unlisted width, and replaced by a later report; a not-measured stage showing the notice at the present height; a readiness test that a capture after `data-cf-ready` shows every frame loaded; a failed-frame test showing the notice
- docs: `docs/present-guide.md` (exports are captures of a session; the ready signal for capture tools)
- release note: `changelog.d/TSK-1101.md`

## Acceptance Criteria

- AC-1 Before any change, the builder shall investigate broadly and record the findings with sources in this record: (a) how the export builds and sandboxes a stage frame today (ADR-0049, `export.rs`, the sandbox test) and why no script may run in it; (b) the export frame's exact geometry (content widths, padding) and how the live host's inline geometry differs from it (`styles.css`, the review rail), so the measuring host reproduces the export and not the live page; (c) what the session channel already carries from the page and how a session store record is scoped to a revision; (d) what capture tools the project uses (the qualification runner, the portal gate) wait on; evidence: the record section, committed before the first code change in the PR.
- AC-2 An exported page shall size every `html` stage frame from the height the live page measured for that stage, revision and export content width in a measuring host that reproduces the export's geometry and ignores the review rail, with no clipping and no blank gap beyond the stage padding, at 1200 and 400 px in light and dark, and a stage with no measurement at the export's revision and content width shall keep the present height and show the "height not measured at this width" notice, never a silent clip; evidence: the render test with a tall and a short stage, failing before the change; the wrapping stage measured with the rail open and closed giving one height; an export at an unmeasured width showing the notice; the never-opened document showing the notice. (serves EPC-022 AC-179)
- AC-3 The ADR-0049 boundary shall be unchanged: every frame keeps `sandbox=""` with no `allow-scripts` and no `allow-same-origin`, no script element appears in any frame, no stage is inlined in an export, and a height report shall be refused when non-numeric, out of bounds, for an unknown stage, for another revision or for a width the export does not produce, and replaced by a later report for the same stage, revision and content width; evidence: the sandbox test unchanged and the report validation tests. (serves EPC-022 AC-179)
- AC-5 The exported page shall mark itself ready only after every frame has loaded or failed within a bounded wait, show a visible notice on a frame that did not load, and say in its chrome that it is a review capture of the session at a time; evidence: the readiness and failed-frame tests and the rendered chrome. (serves EPC-022 AC-179)
- AC-4 (journey) The status report document of the design brief (its revision 1 export, `shots-lead/r1-full-light.png` showed the clipped lane board), opened live once with the installed build and then exported, shall show all nine lane rows at 1200 and 400 px, and the same document exported without being opened live shall show the notice on every stage; evidence: the captures. (journey)
