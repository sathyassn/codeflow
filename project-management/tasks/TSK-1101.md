# TSK-1101: The present export sizes each stage frame from its content and waits for stages to paint

## Description

Four reviewers of the status report design brief (Fable, Codex GPT-6
Astra, Grok 4.7 and a fresh Claude Opus reader, consolidated on
2026-10-30 21:42 EDT) read the exported page and all saw the same defect:
the live session hosts each `html` stage inline
(`crates/codeflow-present/src/render.rs:591`, `.cf-stage-host`), but the
export puts each stage in a sandboxed frame with a fixed height
(`crates/codeflow-present/web/src/styles.css:651-654`, `.block--html
iframe { block-size: 28rem }`), so a stage taller than the frame is
clipped (a nine-row lane board showed seven rows) and a shorter one
leaves a blank gap, and at phone width the frame clips again. A static
capture of the export taken before the stages' script has painted shows
them blank. The reviewers ruled the export a review capture only and the
live session the handover surface until this is fixed, and named the
fix: size the frame from the stage's rendered height, or inline the
stage in the export as the live page does.

Outcome: **an exported present page shows every `html` stage whole, at
the height its content renders, in light and dark and at phone width,
with no clipping and no blank gap, and a capture of the export taken
after the page reports ready shows every stage painted.**

```text
  live session            export today                 export after
  stage inline            frame 28rem fixed            frame sized to content
  [ 9 rows shown ]        [ 7 rows ]..clipped          [ 9 rows shown ]
                          [ 2 rows ]  blank gap        [ 2 rows ]
```

Figure: the live page and the export today, and the export after the
fix, for a tall stage and a short one.

Decisions, each reversible and disclosed here:

- Keep the sandboxed frame (it isolates stage markup in a file opened
  from disk) and size it from the content: the stage script posts its
  rendered height to the host on load and on resize, and the host sets
  the frame's block size, with a floor of one row and no ceiling; where
  the builder shows the message path cannot be made sound in a
  `file://` export, inline the stage as the live page does and record
  why.
- The export marks the document ready (`data-cf-ready` on the root)
  only after every stage has painted or failed, with a bounded wait and
  a visible notice on a stage that did not paint, so a capture tool can
  wait on one signal.
- The export's chrome says what it is: a review capture of the session
  at a time, with the session the handover surface.

Non-goals: the live renderer's stage host (unchanged); the figure
grammar; a new block.

## Outcome

After this merges, an exported present page can be read and captured
whole, so a review of a document with `html` stages reads what the live
page shows.
