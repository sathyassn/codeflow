# TSK-1101: The present export sizes each stage frame from its content and waits for stages to paint

## Description

Four reviewers of the status report design brief (Fable, Codex GPT-6
Astra, Grok 4.7 and a fresh Claude Opus reader, consolidated on
2026-10-30 21:42 EDT) read the exported page and all saw the same defect:
the live session hosts each `html` stage inline
(`crates/codeflow-present/src/render.rs:591`, `.cf-stage-host`), but the
export puts each stage in a sandboxed frame with a fixed height
(`crates/codeflow-present/web/src/styles.css:651-654`, `.block--html
iframe { block-size: 28rem }`), so a stage taller than the frame is
clipped (a nine-row lane board showed seven rows) and a shorter one
leaves a blank gap, and at phone width the frame clips again. A static
capture of the export taken before the stages' script has painted shows
them blank. The reviewers ruled the export a review capture only and the
live session the handover surface until this is fixed, and named the
fix: size the frame from the stage's rendered height. Inlining the stage,
their other option, is ruled out by the ADR-0049 boundary, so the height
is measured on the live page in the export's geometry; an unmeasured
stage keeps the fixed height with a notice, never a silent clip.

Outcome: **an exported present page shows every measured `html` stage
whole, at the height the live session measured for the export's own
geometry, in light and dark and at phone width, with no clipping inside the
measured frame (unused column space may remain beside it), declares any unmeasured stage instead of clipping it, and a
capture of the export taken after the page reports ready shows every
frame loaded.**

```text
  live session            export today                 export after
  stage inline            frame 28rem fixed            frame sized to content
  [ 9 rows shown ]        [ 7 rows ]..clipped          [ 9 rows shown ]
                          [ 2 rows ]  blank gap        [ 2 rows ]
```

Figure: the live page and the export today, and the export after the
fix, for a tall stage and a short one.

Decisions, each reversible and disclosed here:

- The runtime boundary of ADR-0049 is unchanged: the export keeps the
  sandboxed `iframe` with `srcdoc`, `sandbox=""`, no `allow-scripts` and
  no `allow-same-origin` (`crates/codeflow-present/src/export.rs`, the
  `export_html_stage_keeps_content_and_sandbox` test), no script runs
  inside a frame, and the stage is never inlined in an export. The
  height comes from the live session instead, measured in the export's
  own geometry: the live page renders each stage a second time in a
  hidden measuring host that reproduces the export frame's layout (the
  export's content width in CSS pixels, its padding, no review rail), at
  seven bounded content widths (360, 372.8, 480, 640, 768, 832 and 900px),
  and reports the rendered height (stage id, revision, export content
  width, the export rendering contract it measured under, height in CSS
  pixels) to the session store over the existing session channel; the
  live page's own inline host, whose width changes with the review rail,
  is never the source. The export rendering contract is a digest the
  binary computes over the inputs that decide a stage's rendered height
  in an export: the export stylesheets it embeds (`export.rs:186`,
  `styles.css`, `figure.css`, `export-fallback.css`), the root font size
  and type scale, the bundled fonts and the frame geometry; the live page
  reports the contract its measuring host ran under, and the export
  writes a stored height as the frame's block size only when the stored
  revision and rendering contract match. It selects the nearest stored width
  at or below the available column and keeps that measured iframe width,
  with a floor of one row and a bounded height (Codex round 8,
  F5: TSK-1109 of PR 449 changes the root scale and stage typography, so
  a height measured before it is wrong after it at the same revision and
  width). A stage with no matching measurement (a document never opened
  live at that revision, a column below the smallest stored width, or a measurement
  under another rendering contract) is `not measured`: it keeps the
  present fixed height and shows a visible notice, "height not measured
  at this width; open the session", never a silent clip; opening the
  session re-measures under the current contract. The outcome is
  therefore: every measured stage whole, every unmeasured stage declared.
- The reported height is validated input: numeric, bounded, bound to a
  stage id, a revision, a finite content width in 320 to 1920 CSS pixels,
  and the rendering contract digest the binary knows. At most 42 entries
  per stage/revision cover seven widths across three themes and two modes.
  Width keys within 1/64px replace the same rung across browser layout grids.
  Invalid reports, including zero or future revisions, a stage absent from
  the measured revision, out-of-range geometry, an unknown contract or an
  extra entry beyond that cap, are refused with HTTP 400. A valid report
  for an older revision receives HTTP 200 `{"status":"ignored_stale_revision"}`
  and stores nothing: a report already in flight can arrive after a CLI
  update advances the revision, as `.state/stage-measure-probe.json` showed.
  A later report for the same current stage, revision, content width,
  contract, theme and mode replaces the earlier one.
- The export marks the document ready (`data-cf-ready` on the root)
  only after every frame has fired `load` or failed within a bounded
  wait, from the host page's own script, with a visible notice on a
  frame that did not load, so a capture tool can wait on one signal.
- The export's chrome says what it is: a review capture of the session
  at a time, with the session the handover surface.

Non-goals: a change to the ADR-0049 boundary (no script in a frame, no
inline stage in an export); the figure grammar; a new block or a schema
field for height.

## Outcome

After this merges, an exported present page shows every stage the live
session measured whole and declares every unmeasured stage with a notice
at the fixed height, never a silent clip, so a review of a document with
`html` stages reads what the live page shows or says where it cannot.

  session CSP, so frame scripts and same-origin privileges remain forbidden.
- Geometry: `web/src/styles.css:580-588` makes the document at most 96rem,
  with right padding clamp(1.75rem, 5vw, 4rem) and left padding adding the
  200px route plus 3rem gap above 70rem (`:74`, `:341`, `:1504`). At 1200px

- Channel and state: `src/service.rs:361-367` exposes authenticated POST

- Design intent: conform to the existing present surface and ADR-0049.
  Scope is measurement, validated storage, export sizing and readiness,

## Round 2 width decision

- AC-2 changed: Fable M1: real readers at other widths got only the fallback.
- AC-3 changed: Fable M1: real readers at other widths got only the fallback.
- The ladder replaces the original two reference widths. Selection never takes

  The iframe retains the selected width, since arbitrary authored CSS can
