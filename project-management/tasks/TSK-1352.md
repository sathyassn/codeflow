# TSK-1352: The shipped workflows run once per epic and never on a line push by default

## Description

Re-scoped 2026-11-11 at the planning landing that files EPC-057, for the operator's ruling of 2026-11-11 about 20:05 recorded in ADR-0102: no hosted run on any line push, CodeFlow included; a pull request into a line runs only the short checks; the Linux gates and every Windows job run only on the pull request into the default branch. This task makes that the default of every shipped CI template, with one declared setting a project can change, read from the base side. Before the re-scope it carried CodeFlow's ADR-0097 placement to adopters, with the full gate on line pushes; the criteria notes below record each change.

The shipped templates today (`assets/base/ci/` on `main` at `f8aabc62c`):

- The GitHub gate template (`codeflow-ci.yml:26-35`) runs on every pull request, whatever its base, and on pushes to `main` and `master` only; it already runs no gate on a line push.
- The GitHub registry workflow (`codeflow-registry.yml:20-25`) runs on pushes to `integration/**`.
- The gate template chooses the gate mode by event alone (`:45-47`, `:171-178`), so a pull request into `main` can run the same reduced gate as one into a line.
- It has no draft handling and no `concurrency` block, and no `merge_group` trigger.
- No adopter doc says which event runs which gate, or how a project changes it.
- The other shipped templates are the GitLab template (`.gitlab-ci.yml`, merge requests and the default branch only, `:53-55`), the Bitbucket template (`bitbucket-pipelines.yml`) and `ci-generic.sh` (`README.md:28-30`). AC-8 inventories them. Each criterion applies to every shipped template where its host exposes the event and the target branch; where a host does not, that template runs the full gate and the guide says so for that host.

The short checks are commit standards (`codeflow-policy.yml`, job `commit standards`), the secret scan and the security review (`codeflow-ci.yml`, jobs `secret-scan` and `security-review`).

This task owns the gate mode: it chooses each event's gate mode by placement, read from the pull request's base (AC-6). It absorbs issue [#676](https://github.com/sathyassn/codeflow/issues/676) ("Managed gate mode ignores base kind and landing candidates"). TSK-384 consumes the mode this task sets and does not choose it. Added 2026-11-06 from the CI/CD coherence result of 2026-11-06 (workspace `coordination/briefs/cicd-coherence-result-2026-11-06.md`, "Where the reviews differed", rows on the gate mode and #676).

Landing on its target (`main`, alone, early):

- Reachable: the shipped files only.
- Inert: adopters get them through `codeflow update` after the release; a hand-patched copy is merged, never overwritten.
- Other lines: nothing.

Waits for TSK-1396 on `main`: TSK-1396 (the `merge_group` trigger and the up-to-date choice) is on the EPC-022 line only, so it is not in `depends_on`; the record is blocked until it is on `main` (its Blocker).

Non-goals: CodeFlow's own workflows (TSK-1445); reuse on the push to the default branch (TSK-1444); any change that drops the secret scan or the policy check from an event that runs them today.

Note of 2026-11-12 (home on `main`): this task's home is `main`. Pull request 772, the epic delivery plan, merged into `main` at 63061d210 on 2026-11-11, moved it from the EPC-022 line and marked it blocked, because it lands on `main` alone and early, as "Landing on its target" above states, and waits for TSK-1396 on `main`. The EPC-022 line has no copy of this record. A sync of `main` into that line refuses a home move made on `main` (`work.import_authority`); this reviewed change on `main`, the task's home, is the repair that refusal names.

## Outcome

After this merges, a project that adopts CodeFlow's CI templates gets, by default, no hosted run on a line push, only the short checks on a pull request into a line or a draft, and the full gate once on the pull request into the default branch, sees it documented and in the release note, and can change it in one declared place.
