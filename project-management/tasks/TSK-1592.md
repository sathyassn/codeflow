# TSK-1592: The identity reader reads this machine's Tailscale names and nothing else of the tailnet

## Description

Owner: to be assigned by the Director. Staged 2026-11-23 for coord/records.

SPC-018 R-19, Tailscale row, and R-22. A tailnet gives the machine a host
name and a MagicDNS name under a tailnet-specific `*.ts.net` domain; both
identify the person. Layer 2 already flags any `*.ts.net` name
(TSK-1585); this task adds this machine's exact names, including the
tailnet label, so a bare node name is caught too.

Security reading: only the CLI's status output is read, and only its
self entry. Peer entries are never parsed or retained. The daemon's state
files, which hold node keys, are never opened. The CLI runs with a
cleared environment, no prompt and a 200 ms limit (SPC-018 R-23). The macOS app's
bundled CLI path and the `tailscale` on `PATH` are the two locations;
neither present means absent.

## Outcome

After this merges, on a machine with Tailscale, the reader returns its
node host name, its MagicDNS name and the tailnet label in the opaque
type; without Tailscale the source is absent; a failing CLI is
unreadable.

## Deliverables

## Acceptance Criteria

- AC-1 Before any change, the builder shall record in `## Findings`, with sources, the CLI's status JSON fields for the self node, the flag that omits peers where the CLI has one, the CLI locations on Linux and macOS, the state file paths that must never be read, and the wall-clock cost of the status call (median of five cold and five warm runs, with Tailscale running and stopped) on Linux and on Apple silicon macOS, for TSK-1595's final speed run (SPC-018 R-9a); evidence: the Findings section with the timing output.
- AC-2 Given a stand-in CLI whose JSON holds a self node and two peers with placeholder names, the reader shall return the self names only, and a test shall show no peer name in memory after parsing (the parser keeps only the self entry); evidence: unit tests.
- AC-3 A missing CLI shall be absent; a non-zero exit, malformed JSON or a timeout shall be unreadable; evidence: tests per case.
- AC-4 A test shall fail if the module opens any path under the daemon's state folders; evidence: a test with an instrumented file opener, or a source-level test of the module's file reads.
