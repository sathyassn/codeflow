# TSK-1145: Heavy test runs share the host by capacity instead of one lock

## Description

Every heavy test run on a machine takes one exclusive lock today: a full or
essential gate in another worktree or project is refused, quick runs wait
for the lock or record their heavy targets as "not run", and `codeflow
reserve` queues behind it. The operator directed on 2026-11-01 that CodeFlow
must not limit parallel work except for correctness. This task replaces the
one lock with admission by host capacity: each heavy run (full, essential,
heavy quick targets, `codeflow reserve`) takes any free slot among slot
locks in the lock folders and holds a shared host lock. Runs never queue
behind each other; when more runs are active than the host's job budget
allows, a new run starts with a smaller job count. Only a target that
declares `host_exclusive: true` runs alone: it takes the host lock
exclusively. Per-run caps (`max_parallel`, `worker_budget`) stay. The
lock-folder hardening of TSK-1003 and TSK-1044, the killed-gate group check
and the TSK-1128 nested hand-over carry over to slot files. Non-goals:
the guidance sweep (TSK-1147) and the pre-push line-sync rule (TSK-1149);
landing order on a line is unchanged.

This task supersedes three parts of TSK-1128, whose record stays as its
history: AC-5 (no two heavy gates at once), AC-7 (waiters served in arrival
order through queue tickets) and the `execution.heavy_wait_seconds`
setting. The tickets and the setting are removed; `--wait-seconds` remains
only as the bound for a host-exclusive target.

Grade: Hard, band 4 to 6 h of active life (operator clock, codeflow issue
334), after the split into TSK-1145, TSK-1147 and TSK-1149.

## Outcome

After this merges, builders and adopters can run full gates, quick runs and
reserved commands in several worktrees and projects at once, each sized to
the host's cores and memory, and only a target that declares itself
host-exclusive runs alone.

## Deliverables

- Slot admission, shared and exclusive host lock: `crates/codeflow-core/src/testing/gate_guard.rs`
- Host job budget from cores and available memory: `crates/codeflow-core/src/testing/capacity.rs`
- Config keys `execution.host_jobs` and target `host_exclusive`: `crates/codeflow-core/src/testing/config/mod.rs`
- Runner and CLI admission: `crates/codeflow-core/src/testing/runner/mod.rs`, `crates/codeflow-cli/src/cmd/test.rs`, `crates/codeflow-cli/src/cmd/reserve.rs`
- Tests: `crates/codeflow-cli/tests/test_gate_cli.rs`, `crates/codeflow-cli/tests/test_gate_cli/`, unit tests in `gate_guard.rs` and `capacity.rs`
- Docs and changelog: `docs/cli.md`, `docs/troubleshooting.md`, `changelog.d/TSK-1145.md`

## Acceptance Criteria

- AC-1 When two full or essential gates start in two worktrees of one repository, both run at once; a CLI test fails before the change and passes after. (journey)
- AC-2 When a quick run reaches its heavy targets while a full gate runs, they run at once, without waiting and without a "not run" result; a CLI test fails before and passes after. (journey)
- AC-3 When more heavy runs are active than the host's capacity, a new run starts at once with a smaller job count (the host job budget divided by the active runs, at least one) instead of waiting; the budget comes from cores and available memory by default and from `execution.host_jobs` when set; unit tests cover the computation and a CLI test shows a run lowering its count, failing before and passing after.
- AC-4 When a target declares `host_exclusive: true`, it starts only when no other heavy run holds the host, and no heavy run starts while it runs; a waiting target is bounded by the run's wait and otherwise reported not run; targets without the declaration never run alone; a test shows both directions.
- AC-5 `codeflow reserve -- <command>` is admitted the same way and never waits for another run; on Unix a `codeflow` command nested under a reserve uses the reserve's slot, and the TSK-1128 hand-over checks (forged value, other binary, surviving target) still hold.
- AC-6 Lock state that cannot be read or written refuses (fail closed): an unreadable slot record, an unopenable lock folder, a planted link or swapped file; the TSK-1003 and TSK-1044 lock-folder tests pass against slot files, and a free slot whose record names a live target group counts as busy.
- AC-7 The admission builds and runs on Windows with shared and exclusive byte-range locks; the hosted windows job is green.
- AC-8 `docs/cli.md`, `docs/troubleshooting.md` and the test config reference describe capacity admission, `execution.host_jobs` and `host_exclusive`, and no message or doc in the code says only one heavy gate runs at a time; the `execution.heavy_wait_seconds` setting and the arrival-order tickets are gone from code, schema, this repository's config and docs.
