# TSK-1608: Two codeflow-core tests build and pass on Windows

## Description

Source: Director rulings 2026-11-25 (`msg_4bda0ffa4329`, `msg_0349c5796a6e`, `msg_d2e0d3f3216d`), from Chief's read of `codeflow-ci` run 45613906814 on `dbd5f64efc`.

Pull request 939 (TSK-1516, commit `7522f3cd0b`) added two pieces of test code that fail on Windows:

- Clippy, `crates/codeflow-core/src/ids/order.rs:286`: the helper `awkward_paths()` has `let mut paths` that is changed only inside a `#[cfg(unix)]` block. On Windows the `mut` is unused and `-D warnings` fails the job "windows checks (doc, clippy, Node)". Reproduced without a Windows host: the repository's cross-check form of `cargo xwin clippy` for `x86_64-pc-windows-msvc`, on `codeflow-core` at `a9c056a16a`, exits 101 with that one error (`coordination/coordinators/planning/notes/tsk1352-complete/win-clippy-a9c056a16a-rerun.log`).
- Test, `crates/codeflow-core/src/validate/docs.rs:1506` (`folded_ledger_findings_equal_the_separate_pass`): the test turns each finding's path into text with `display_path`, which keeps the native separators, and compares the text with literals that use `/`. On Windows the text has backslashes, so it fails in "windows tests 1 of 12". The findings themselves, their order and their lines are equal. This cannot be shown without a Windows host; the fail-before is the hosted log as Chief read it.

These keep the windows jobs red on every run of `main` and of each pull request that holds main's tip, and a red job can hide its other findings. This fix prevents both.

Non-goals: any product change; what paths look like in shipped output; any other Windows test.

## Outcome

After this merges, the windows clippy job passes for `codeflow-core` and the named test passes on Windows, and the tests check the same paths and findings on Unix as before.

## Deliverables

- `crates/codeflow-core/src/ids/order.rs`, test module only: the Unix byte rows come from their own helper, with an empty one elsewhere, and no `mut` is left
- `crates/codeflow-core/src/validate/docs.rs`, test module only: the finding's path is compared in its `/` form
- release note: none, test-only
