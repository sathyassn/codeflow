# TSK-1312: A sync of main into a line has its own admitted route

## Description

A merge of `main` into an integration line whose net diff includes a changelog entry has no admitting task: `Task: <epic>` is refused by `work.classification` because a planning-only pull request cannot touch `changelog.d/`, and `Task: <the landed task>` is refused by `work.stable_planning_anchor` because that task is complete. Seen on PR 563 at 304b68aee on 2026-11-03. TSK-1311 carries that one sync; this task makes the next one need no task of its own invented for it. It changes what `codeflow ci` admits, so it binds to exact commits and fails closed.

## Outcome

After this merges, a maintainer can land a sync of `main` into a line through `codeflow ci` without filing a task to carry it, and nothing else gains admission.

## Deliverables

- the admission rule: provisional home in the classification and acceptance code of `codeflow ci`; AC-1 decides
- the tests: `crates/codeflow-cli/tests/ci_cli/`
- docs: `docs/delivery.md`
- release note: `changelog.d/TSK-1312.md`

## Acceptance Criteria

- AC-1 Before any change, the builder shall reproduce both refusals on a fixture and name the code that raises each; evidence: the output and file:line.
- AC-2 A merge into a line shall be admitted as a sync when its second parent is on the trusted default branch and its result equals the clean merge of its parents, and every other `codeflow ci` refusal (the criteria freeze, epic criteria, record checks) shall still apply to it; a sync of main into a line shall take main's version only for records whose home is main, and shall never change a record whose home is the line; evidence: a positive fixture with a changelog entry in the net diff, failing before the change, a fixture admitting main's change to a main-homed task of the line's epic, failing before the amendment, and fixtures refusing a change to each kind of line-homed record.

A bare `AC-n` inside a moved criterion means TSK-1272's own criterion, kept in its cancelled record.
- Amended 2026-11-05: AC-2 read "every other `codeflow ci` refusal (the criteria freeze, epic criteria, record checks) shall still apply to it, so a sync cannot change line records", and the docs added "even when main holds the change". That collides with the operator's landing rule of 2026-11-05 17:24 (`RELEASE-PLAN.md`): "each task or epic record changes only on its own epic's line or on main". The Director accepted the replacement wording now in AC-2: a sync of main into a line takes main's version only for records whose home is main, and never changes a record whose home is the line. Under the one-home rule, main never holds a newer change to a line-homed record. ADR-0098 (the landing-rule pull request, not yet open) records the rule. A task's home is its declared `integration_target`; an epic's home is its own line or its `parent_line`; a task with no declared target is judged by its epic. A record whose home is another line reaches main only through that line's checkpoint, and a sync takes main's version of it as it does for a main-homed record. Effect on the code: a task of the line's epic that targets main is now main-homed, so a sync takes main's change to it; before, any task of the line's epic was frozen.
