# TSK-1505: Reopen and archive checks agree on a completion edited in place

## Description

When a task's completion block was edited in place after it was made, two checks disagree on which completion is "the previous completion". The reopen check takes one version of the block and the history (archive) check takes another. A reopened task whose completion had been edited in place can then never be completed again, because whichever block it archives, one of the two checks refuses it. TSK-416's re-completion on the EPC-022 line hit this.

Limits of the fix, which an adopter must know:

- The reopen verb archives only the active block, which is the edited one (`crates/codeflow-core/src/workgraph/status_verb.rs:1007-1030`). The adopter inserts the block as made by hand, ahead of the edited block, before completing again (`lifecycle.rs:1245-1254`).
- When a redaction changes the active block, the history no longer matches it, and the plain archive rule applies, as before this fix (`acceptance.rs:983-984`, `redaction.rs:259`). A redaction combined with an in-place edit is not covered.
- One commit that both reopens and archives the two blocks is refused. The reopen and the added as-made block go in separate commits, as TSK-416 did (`lifecycle.rs:1122-1123`, `:1185-1186`).

Overlap: TSK-1185 (import authority ordering record versions) and TSK-1316 (folded into TSK-1185) judge record versions across landings; neither covers which completion a reopen archives. No open record holds this.

Source: the Director, 2026-11-15 04:00, from coord/ci's TSK-416 re-completion report; the fix was built by a Claude Worker of coord/ci in `acceptance-history-fix` on `main` at d59f1688d before this record existed.

## Outcome

After this merges, the reopen check and the history check name the same previous completion for a completion that was edited in place. Once the archive holds that completion as made and then as edited, a task reopened after the edit can be completed again through `codeflow task status`, and `codeflow ci` passes the range. A completion never edited in place is judged as before. The three limits above still apply.

## Deliverables

- one reading of "the previous completion" shared by the reopen check and the history check
- tests with fail-before evidence
- `## Findings`: each reader of the previous completion, swept, with its disposition
