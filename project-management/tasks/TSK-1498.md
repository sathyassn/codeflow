# TSK-1498: Projects can accept named runners in a writable project as a stated residual

## Description

TSK-1053 establishes no runner launch (the Director's ruling R, 2026-11-14, after Grok's reviews of TSK-1053 showed that no closed model of a runner's lookup is sound). Under `uv run`, `npm exec`, `npx`, `poetry run`, `pnpm exec`, `yarn exec` and `bundle exec`, inline code and operands that could name a secret are judged as after an unknown directory change and refuse, and the only setting that lifts them, `security.secret_reads: warn`, relaxes every secret read, not only runners.

The operator's standing rule for adopter-facing limits is a configurable option unless the limit is a safety floor (the operator, 2026-11-13, about 14:35). The Director ruled on 2026-11-13 (23:4x, relayed by coord/catalog) that this residual gets such an option, on the same pattern as TSK-1487. A project that turns it on accepts, in committed policy, that a runner in a project the session can write runs a program the session can change, so a planted program runs. The default stays closed. This task is the only route by which a runner launch is accepted: TSK-1053 establishes no runner (Director ruling R, 2026-11-14).

Non-goals: any change to TSK-1053's default verdicts; runners TSK-1053 does not model (`cargo run`, `direnv exec`, `pipx run`, `uvx`, `bunx`, `pnpm dlx`, `yarn dlx`); any relaxation of the floors AC-4 lists.

## Outcome

After this merges, an adopter whose agents use `uv run`, `npm exec`/`npx`, `poetry run`, `pnpm exec`, `yarn exec` or `bundle exec` in their own project can choose, in committed policy, to treat those launches as established, accepting in writing that a program the session can change may run; every project that does not set the option keeps TSK-1053's rule.

## Acceptance Criteria

- AC-1 A policy key, off by default, shall name the runners an adopter accepts, as a closed list of the runners TSK-1053 models (`uv run`, `npm exec`, `npx`, `poetry run`, `pnpm exec`, `yarn exec`, `bundle exec`); any other value shall refuse to load, naming the key and its accepted values. The schema note and the generated policy reference shall state the residual in plain words: a runner in a project the session can write runs a program the session can change, so a planted program runs. Evidence: schema tests for the default, each accepted value and an unknown value; the generated reference diff.
- AC-2 The key shall be read only from landed policy, by the same authority rule as TSK-1487: a session or working-tree edit to the key changes nothing until the operator lands it. Evidence: tests proving that an uncommitted value is ignored, that a value committed on the task branch but not landed is ignored, and that a landed value takes effect.
- AC-3 With the key set for a runner, a launch under that runner in a writable project shall be judged as a direct command in the runner's directory: reads and inline code are judged there, as the same command run directly in that directory. Naming a runner never resolves its directory: an option, variable or workspace selector the grammar does not model, or a directory it cannot resolve, keeps TSK-1053's unknown-directory refusal with the key set. Runners not named keep TSK-1053's rule. Evidence: paired git-guard and exec-guard rows for each runner, with the key set and unset, including a moving-directory row and an unknown-directory row per runner.
- AC-4 The key shall never lift the floors: secret-store reads, protected paths, the install verbs and the hook-integrity checks still refuse under a named runner. Evidence: paired guard rows proving each, with the key set.
- AC-5 `codeflow doctor` or the orient digest shall name an active key and the runners it accepts, so the residual is visible. Evidence: the command's output with the key set and unset.
- AC-6 A changelog entry shall name the key, the default, the residual and how to turn it on. No bypass form is named before it is fixed on `main`. Evidence: the changelog fragment and `codeflow validate --docs`.
- AC-7 The change shall get one cross-family security review with the `cf-security-reviewer` checklist (it adds a way to relax refusals), and the pull request shall state the residual, why the default is closed and why the floors stay outside the key. Evidence: the verdict file named in the pull request body.
