# TSK-1506: Present's process inventory works on a busy host

## Description

`codeflow present show` and `present close` list the host's processes to find
the session's browser. On macOS the list came from one `ps` run whose whole
output was refused above 4 MiB. A busy Mac exceeds that (measured
2026-11-15: 963 processes, 8,179,629 bytes), so show and close refused, and
three `present_cli` tests failed on that host, which blocked a main landing.

The listing is now read line by line with no total bound. Each line keeps at
most 64 KiB; a longer line is read to its end in bounded memory and skipped
unless it holds the session's instance argument, in which case the inventory
refuses (fail closed). A `ps` that cannot start or exits non-zero still
refuses.

Siblings: the Windows inventory had the same fixed 4 MiB total over every
browser process, and is now filtered in `PowerShell` to the processes that
can be ours. The Linux `/proc` scans already read each process in bounded
memory; their fixed 65,536-entry count is raised to the kernel's own process
id limit. Non-goal: how identity is proven for a listed process does not
change.

## Outcome

After this merges, a user on a busy host can run `codeflow present show` and
`present close`, and they find or clear the session's browser instead of
refusing because the process listing is large.

## Acceptance Criteria

- AC-1 When the macOS process listing is larger than 4 MiB, the inventory
  still reads it and finds the owned browser line wherever it falls
  (`an_inventory_over_four_mib_still_finds_the_owned_process` in
  `browser.rs`), and `present show` and `present close` succeed with a
  planted listing over 4 MiB
  (`show_and_close_work_when_the_process_listing_is_over_four_mib` in
  `present_cli.rs`). (journey)
- AC-2 When a listing line is longer than the 64 KiB line bound, the
  inventory keeps no more than the bound of it in memory, skips it when it
  does not hold the session's instance argument, and refuses the inventory
  when it does, at any read boundary
  (`an_overlong_line_holding_the_instance_argument_is_refused`,
  `the_inventory_line_reader_bounds_each_line` in `browser.rs`).
- AC-3 When `ps` cannot start or exits non-zero, the inventory refuses as
  before (code review of the macOS `owned_process_candidates`; no test can
  make `/bin/ps` fail).
- AC-4 The three `present_cli` tests that failed on the busy host
  (`close_ignores_other_processes_with_unreadable_command_lines`,
  `show_after_the_browser_exited_ignores_unreadable_command_lines`,
  `show_no_launch_prints_the_address_while_the_browser_runs`) fail before
  the change and pass after it on that host (fail-before and pass-after
  logs in the PR evidence).
- AC-5 The Windows inventory lists only qualified browser processes that
  hold the instance argument or whose command line cannot be read, so other
  browser processes never fill its size bound
  (`the_windows_inventory_lists_only_processes_that_can_be_ours` in
  `browser.rs`; Windows runtime evidence from the hosted windows job).
- AC-6 The Linux `/proc` scans stop only past the kernel's process id limit
  (4,194,304 entries), with each entry still read in bounded memory (code
  review; the existing `linux_proc_inventory_*` tests stay green on the
  hosted Linux job).
