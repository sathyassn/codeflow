# TSK-1483: The shipped presets keep every session program inside the sandbox, using the named routes

## Description

Once TSK-1482's routes and TSK-1484's broker are in place, every shipped Claude preset changes one sandbox setting, `allowUnsandboxedCommands`, from `true` to `false`. This is the operator's decision of 2026-11-12 (RELEASE-PLAN.md). This task makes that change, carries it to adopters through `codeflow update`, reports it in doctor and orient, documents how an operator turns it back on, records it in an ADR that succeeds ADR-0029, and lists it in the release note as a new restriction.

This task does not start building until the operator has answered the pending choices for this body: the interim least-privilege token, the GitHub fallback if the masked-token probe fails, whether TSK-1484 ships to adopters, and the floors F1 to F3.

The setting is a default an adopter can edit. A person can turn it back on in one of four places, all outside any agent session:

| Place | Scope |
|---|---|
| the shared `.claude/settings.json`, edited by a person through review | the team; update keeps it and reports it |
| `.claude/settings.local.json` | one person on one project |
| managed settings | the organization |
| `--settings` | one launch |

None of the four works against a `false` in user or managed settings, which is the harness's own precedence rule.

If TSK-1484 does not ship to adopters, the TSK-1484 edge is dropped by amendment, and doctor reports seat control unavailable as TSK-1482's AC-3 states.

Non-goals: the routes (TSK-1482); the broker (TSK-1484); host qualification (EPC-037); Codex and Grok presets, which have no such retry.

## Outcome

after this merges, every shipped Claude preset keeps the programs a session runs inside the sandbox, and an adopter's regular host-state work keeps working through the named routes.

## Acceptance Criteria

- AC-1 Every shipped Claude preset shall set `allowUnsandboxedCommands: false`. On `codeflow update`, a value equal to the recorded shipped value shall move to `false`, a different value shall be kept and reported, and a missing key shall be added as `false`. Evidence: the preset diff and an update test for each of the three cases.
- AC-2 With the setting off, doctor and orient shall report as TSK-1482's AC-6 states, doctor shall say when a `false` in user settings makes a project's `true` ineffective, and orient shall print only the unavailable workflows. Evidence: a doctor and an orient test for each case.
- AC-3 `docs/harness-posture.md` shall state what the OS sandbox bounds and what it does not (command hooks, local MCP servers, the status line command and any CodeFlow broker or hook run with full access; a localhost service acts for its caller; an injected credential carries its authority), the cost to adopters, and the four places in the description where a person turns the setting back on. Evidence: the doc text and `codeflow validate --docs`.
- AC-4 An ADR shall succeed ADR-0029, record the change and the operator's decision of 2026-11-12, and name everything AC-3 says the sandbox does not bound; under AC-7 it states no further reason for the change. Evidence: the ADR text.
- AC-5 The release note shall list the change as a new restriction: what stops working inside the sandbox, the doctor line, the way back, and the per-host GitHub setup (the masked credential in user settings and a least-privilege token). Evidence: the changelog fragment.
- AC-6 The whole unit shall have a cross-family security review with the `cf-security-reviewer` checklist, its seat checked live at dispatch. The threat the change closes and why its design is the standard one shall be stated in the private review evidence, kept in the coordination workspace, and the pull request shall say only that the security review is recorded. Evidence: the review record and the pull request body.
- AC-7 No public text (commit subjects, test names, docs, the ADR, the changelog fragment and pull request text, for this task and for TSK-1482 and TSK-1484) shall say why the setting changes, or why a floor exists, until this task is on `main`. The reason first appears publicly in the release notes of the release that ships this body, written after it is on `main`. Evidence: the pull request as opened and its docs, checked by the reviewer.
- AC-8 If the operator accepts floor F2, no agent session, CodeFlow verb, skill, script or team bootstrap shall write the setting back on, and tests shall show the local settings file cannot be written from a session at the start folder, at the main checkout root, and in a nested checkout. If the operator rejects it, this criterion is cancelled with that ruling. Evidence: the tests.
- AC-9 (journey) In a scratch project with the installed build, `codeflow update` from the previous release shall move the setting as AC-1 states, and a session there shall run TSK-1482's routes and see doctor's report. Evidence: the journey output.
- AC-10 Every shipped Claude preset shall deny sandboxed reads of the runtime state file of each seat app the broker drives, Orca's included (`~/Library/Application Support/orca/orca-runtime.json` on macOS), and a sandboxed read of it shall be refused. Evidence: the preset diff, a preset test row per file, and one sandboxed read refused.
