# TSK-365: The CI pin attack drives the installed candidate binary

## Description

Source: the Codex test integrity audit of 2026-10-17 at
`eaf2ed04e932186cdd26dc4a7e5740cc553acee3`, medium finding and mutation
probe 1.

The journey "a PR lowers the enforcing binary"
(`crates/codeflow-cli/tests/journey_gate.toml:265`) claims the managed CI
installs the pinned binary and that this binary enforces policy. The test
publishes a fixture executable that only prints a version
(`crates/codeflow-cli/tests/ci_pin.rs:97`), checks that the installer put
`codeflow 1.2.3` in place, and then takes the enforcement verdict from
`CARGO_BIN_EXE_codeflow` (`ci_pin.rs` near `:1301` and `:1308`), not from
the installed file. An installer or `PATH` regression that installs an
executable which prints the right version and enforces nothing would still
pass.

Outcome: the journey installs a release-like artifact that contains the
actual candidate binary, through the managed workflow's own install script,
and dispatches the installed file against valid and hostile pull request
data. No publication is needed: the artifact is local.

Product surface: this repository's tests of the shipped CI workflow; the
shipped installer changes only if the test exposes a defect.

## Deliverables

- the release-like fixture: a local archive with the candidate binary, its `sha256.sum` and the layout the managed installer reads, built inside the test
- the journey: `crates/codeflow-cli/tests/ci_pin.rs` and its `journey_gate.toml` entry, dispatching the installed binary
- a fix in `assets/base/ci/` only if the journey exposes one, with its release note in `changelog.d/TSK-365.md`

## Acceptance Criteria

- AC-1 The journey shall install the candidate binary from a local
  release-like archive through the managed workflow's install script and
  run the CI judgement with the installed file, never
  `CARGO_BIN_EXE_codeflow`; evidence: the test source and a log line
  naming the installed path and its digest. (serves EPC-023 AC-22)
- AC-2 With the installed binary, a valid pull request shall pass, and a
  lowered pin, a changed workflow, a relaxed head policy and a substituted
  executable shall each fail for its stated reason; evidence: one case
  each.
- AC-3 An executable that prints the expected version and approves
  everything shall not satisfy the journey; evidence: that impostor
  passing the old version-only check and failing the strengthened
  installed-enforcement journey, beside the genuine installed binary
  passing it. (journey)
