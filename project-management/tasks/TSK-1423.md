# TSK-1423: codeflow ci judges a line-merge range inside the push budget, with the same verdicts

## Description

`codeflow ci` checks that every record's status changes in a pushed range are legal steps. It does this one record at a time: `status_steps::judge` (`crates/codeflow-core/src/workgraph/status_steps.rs:143`) builds a new `Walker` for each record, and each walker walks the whole range and indexes and parses the record at every commit (`:559-575`, `locate` at `:474`, `RecordView::parse` beneath it). The per-commit cache lives inside one walker, so with hundreds of records the same commits are indexed and the same record blobs parsed hundreds of times.

Measured on 2026-11-10 and 2026-11-06:
- a push of PR 707's head 9b0d36237 over a03706f29, whose range carries the EPC-022 line merge: the pre-push push set took 217.8 s, 204.8 s of it `codeflow ci`, against the 60 s push budget (TSK-1306's `git.push_budget_seconds`);
- the hosted `commit standards` job on the 4.0.0 checkpoint range 879a7a7f..2630d4854 (1380 commits, 383 merges): the `codeflow ci` step ran 8.5 minutes (job 127659313186, 01:57:25 to 02:05:55 UTC on 2026-11-06);
- the same range in a debug build used more than 45 CPU minutes (TSK-416 AC-20 fixture, stack samples in `status_steps::judge`, `Walker::range`, `RecordView::parse`).

TSK-1306 made the budget a setting and made an overrun a report, not a refusal; it is complete. This task makes the judgment itself fast enough that a push carrying a line merge fits the budget, without changing any verdict.

Non-goals: changing which steps are legal, the push budget's default, or what `codeflow ci` judges.

## Outcome

After this merges, a push or a pull request run whose range carries a line merge gets its `codeflow ci` verdict inside the push budget on this host, and every verdict and finding is the same as before.

- AC-2 One `codeflow ci` run shall walk a range once for all records it judges, and shall index a commit and parse a given record blob at most once per run, whatever the number of records; evidence: a test that counts walks and parses on a fixture with many records and many commits, failing before and passing after.
