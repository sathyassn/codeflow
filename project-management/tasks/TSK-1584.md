# TSK-1584: Email addresses and phone numbers in added content are privacy findings

## Description

Owner: to be assigned by the Director. Staged 2026-11-23 for coord/records.

SPC-018 R-13: the contact kinds of layer 2. Email addresses and phone
numbers are the most common personal values an agent copies from a
terminal, a config or a conversation into a repository. The secret scan
does not look for them (`hooks/scan.rs:23` `secret_res`, both revisions).
Accepted forms are the reserved domains of RFC 2606 and RFC 6761 and the
fictional number ranges in the placeholder table (TSK-1583).

Non-goals: a project-maintained list of addresses; commit author headers
(TSK-1372).

## Outcome

After this merges, an email address or phone number added in a change is
a `privacy.patterns.email` or `privacy.patterns.phone` finding at the
`privacy.patterns` level, and placeholder forms pass.

## Deliverables

- `crates/codeflow-core/src/privacy/patterns/contact.rs` (new) with unit tests
- placeholder rows for these kinds in the TSK-1583 table
- docs: the kinds in `docs/policy-reference.md`
- release note: `changelog.d/TSK-1584.md`

## Acceptance Criteria

- AC-1 Fail before: at the base, a commit adding an email address at a non-reserved domain and an E.164 phone number outside the reserved fictional ranges (both assembled at run time from parts, so the repository holds no literal) is accepted with no finding; evidence: the base output in the PR.
- AC-2 Pass after: each shall be refused at `block` and warned at `warn`, naming the kind, path, line and columns and not the value; evidence: detector tests and one hook test per kind.
- AC-3 `user@example.com`, an address at any `.example`, `.test`, `.invalid` or `.localhost` domain and each reserved fictional number shall pass; evidence: tests per form.
- AC-4 Version strings (`1.2.3.4`), dates, IPv4 addresses, hex ids, UUIDs and long decimal constants in code shall not match as phones; evidence: a negative corpus test of at least 50 such values drawn from this repository's own sources at the base.
- AC-5 A GitHub no-reply address in content shall be a finding, and the docs shall say why (it names a login); evidence: a test and the doc sentence.
