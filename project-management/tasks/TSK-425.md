# TSK-425: A define-once gate refuses hand-copied values and code

## Description

Issue #274, item 1 and the audit behind it. Two adopting repositories
held hundreds of hand copies of names, ids, team slugs, paths and
settings, most bypassing a home that already existed (an exported
constant nothing imports, a required-check guard covering two of six
names, workflow branch filters drifted from the policy); a team rename
needed 122 lines in 50 files edited by hand, and both reviews checked
only that the edit was complete. CodeFlow has no duplication or
known-values check, and the project runs its own as a `runner: custom`
target.

Outcome: **a `define-once` gate target type runs the configured
language adapters for copied literals and blocks, a stack-neutral
known-values check from a project file where each value names its one
home and its generated or checked mirrors, and an advisory discovery
mode that lists literals appearing in several files; every refusal
cites the home and the register route of TSK-424.**

Rules:

- Adapters are configured per stack in `.codeflow/test-config.json`
  (for example Biome `style/noMagicNumbers`, ESLint
  `sonarjs/no-duplicate-string`, Ruff `PLR2004` and `RUF100`, jscpd,
  Regal, tflint); the gate runs the ones the project's stack and
  installed tools support and reports the rest as not run.
- Known values are `known-value` records in TSK-424's register (the
  provisional register file; TSK-424 AC-16 defines the kinds). A record
  lists value, home and mirrors; any other occurrence fails, and a
  mirror is checked for equality with its home. A value is a plain
  literal, a regex or a template body (for example
  `format!("{root}/state/{id}.json")`). A record lists its variant
  bodies by hand (for example a task-id regex written in several files
  with two different quantifiers); every listed body is searched for. A
  template is compared by its shape with placeholder names and format
  specifiers ignored, and a pattern by its source text without its
  language's delimiters and flags. Every duplicate is reported against
  the one record. Where a home lives is the project's choice, named in
  the record (for example a JSON policy file the project already keeps).
- Discovery mode is advisory by default and never changes the result;
  a project may set it to blocking.
- The `define-once` target type is one gate target that also runs the
  strict adapters of TSK-426 together with the define-once checks, in one
  verdict. A drift-test template ships with it: a home file, its mirrors
  and a generated check that fails when a mirror differs from its home.
- The project configures, per language, which tools run and their
  thresholds (jscpd `min-tokens`, the duplicate-string count, the
  magic-number allowances), the file globs, path dispositions and the
  sources of generated mirrors, the longest exception expiry
  (`max_exemption_days`, default 90) and whether discovery is advisory
  or blocking.
- An exemption or baseline entry from TSK-424 clears an occurrence; an
  inline suppression must cite a register id.

Non-goals: adding adapters for languages the project does not use;
rewriting the copies the check finds.

comments of 2026-11-05 and 2026-11-07). An adopter review of 2026-11-04
found about 70 storage-path literals in one task: six key shapes, a stack
pattern and a stamp pattern, across 11 modules. No gate saw them. The
comment of 2026-11-07 adds what two adopting repositories now run and
what each project must be able to configure. Earlier text: the
known-values rule and AC-1 covered identifiers and plain literals only,
from a separate `.codeflow/known-values.json`, with one pattern per

only. Reasons: templates and patterns are the adopter's actual case; the
comment puts known values in the one register, with per-value variant
lists; and it asks for blocking discovery as a project choice, one gate
target with the strict checks, a drift-test template and per-project
configuration. The comment wins where it differs from the earlier text.
Changes: Rules (known values, discovery, one target, configuration),
AC-1, AC-4, AC-8, and new AC-11 to AC-15. Discovery mode comes back as
AC-13 (it was removed with AC-3 on 2026-11-04). The Director decided on
2026-11-07, at the request of the issue #274 comment of 2026-11-07 (18:48Z),
to keep it, advisory by default and blocking when a project sets it, under
the operator's rule that anything stricter is optional and configurable.

## Deliverables

- the target type and adapters: `crates/codeflow-core/src/testing/` (a `define-once` runner beside the existing runners) and the config schema under `crates/codeflow-core/src/testing/config/`
- the known-values check and discovery: the same runner, reading the register's `known-value` records (schema in `docs/policy-reference.md`)
- the drift-test template: `assets/base/testing/templates/` (a home file, its mirrors and a generated check)
- `cf-stack`: the adapter setup per language in `assets/base/`, `.claude/skills` and `.agents/skills`
- tests: runner unit tests over fixture trees per adapter and `crates/codeflow-cli/tests/test_gate_cli.rs`
- docs: `docs/cli.md` and the test-config reference
- release note: `changelog.d/TSK-425.md`
