# TSK-1073: The guards read command lines through a qualified shell parser

## Description

Source: issue #404 (CodeFlow 3.1.1). git-guard and exec-guard read a
Bash call as text and with their own word readers, so quoted data can
be read as code or as a path. The issue asks for a real shell parser
whose tree the existing rules judge.

What the line already does, rechecked on 2026-10-29 with the line's
binary at `bd721f39b` through `codeflow hook git-guard` and `exec-guard`
(the issue gives descriptions, not exact lines, so each row was rebuilt
from its description):

- A literal assignment earlier on the same line resolves (TSK-406): the
  issue's `git -C "$W" show`, `git -C "$R" ...`, `sed -i` under `$D` and
  `tar -xf $D/... -C $D/...` all pass when the line assigns the
  variable, in `;`, `&&`, newline, `export` and pipe shapes. A variable
  the line does not assign, or one filled by a substitution
  (`D=$(mktemp -d)`), stays refused, as the issue's own proposal keeps.
- Quoted patterns and prose given to `grep`, `rg`, `echo`, `printf`
  and `cat` pass, as do `cat` heredocs that name a peer's headless form.
- Still refused: a quoted launcher word or peer name given to any other
  program (`gh pr comment --body "... ; su ..."`, a `tee` heredoc of
  prose), and the cases TSK-415, TSK-417, TSK-1024 and TSK-1072 own.

Outcome: **an agent can pass quoted data to a program whose identity
and argument grammar the guard establishes, without a false refusal,
while every line the guards refuse without the parser, where its text
can run, stays refused.**

The base reader below means the guards' reading without the parser, as
the line has it when this task starts; its verdict is the base verdict.

Rules this task follows:

- Fail closed. The parser reading may only relieve the classes AC-5
  lists. A parse error, an unsupported construct, a dialect difference
  between the shells the harnesses run, or any disagreement between the
  parser and TSK-397's lexer (`security/shell_lex.rs`, from PR 331) on
  command or word boundaries leaves the line with the base verdict.
- Build on TSK-397's lexer, never replace it here. The lexer stays the
  strict branch's reader and becomes the divergence check. Retiring
  either reader is a later decision that needs this task's
  qualification evidence.
- Execution identity (EPC-022, Guard scope follow-ups amendment): no
  allowance rests on a command name alone. Data relief needs the
  program to resolve to an executable the requester cannot substitute,
  through the resolution TSK-1053 builds.
- Directories: the operator decided on 2026-10-25 that narrowing after
  `cd` cannot be made sound, so the parser does not narrow a directory.
  The issue's request to track `cd`, `pushd` and `popd` is not taken
  unless the operator revisits that decision.
- Option D (TSK-1002, PR 346): committed history, a file run after a
  same-line write and an unmodelled runner's child directory are
  outside the text guard's promise; TSK-1052, TSK-1053 and TSK-1065
  own them, and this task does not re-enter them.

Deliberate text scans that stay (the issue's trade-offs):

- content written to an executable file, a `.sh` path, a startup file
  or an enforcement path, and a file run later on the line or in a
  later call (TSK-1052's class);
- interpreter code: a heredoc or `-c` text given to a shell or an
  interpreter is code, so a launcher word or a peer's headless form in
  it stays refused (the issue's session rows 5 and 8). Relieving a
  string literal there needs a language reader, as TSK-413 does for
  git calls; that is not planned here;
- shell `-c` strings, `eval`, `trap`, `ssh` remote commands, and the
  templates of `xargs`, `find -exec` and `parallel` are code.

Placement: EPC-022, 4.0.0 by the operator's decision of 2026-10-29.
The planning pull request for issue #404 first recommended 4.1.0
(EPC-023), because the task needs a new parser dependency, execution
identity and a qualification corpus run under real shells; the
operator chose the current release. Its qualification (AC-3) is part
of this task and ships with it.

## Outcome

After this merges, an agent can pass quoted prose, patterns and message text to an identified program without a guard refusal, and every line the guards refuse without the parser, where its text can run, is still refused.

## Deliverables

- findings and the parser decision: a `## Findings` section in this record and an ADR in `docs/decisions/` (the parser, its fail-closed composition with TSK-397's lexer and the relief classes)
- the parser reading: a new module under `crates/codeflow-core/src/security/` (provisional; the ADR names it), with any crate dependency in the workspace `Cargo.toml` and its audit and license entries
- the composition with the guards: `crates/codeflow-core/src/hooks/exec_guard.rs`, `crates/codeflow-core/src/hooks/git_guard.rs` and the raw-text checks in `security/privilege.rs` and `security/headless.rs`
- the qualification harness: a differential test under `crates/codeflow-cli/tests/` with its corpus as fixtures, extending TSK-397's `text_guard_invariant.rs` corpus
- docs: `docs/policy-reference.md` (what the guards read as data), `docs/architecture.md`
- release note: `changelog.d/TSK-1073.md`

## Acceptance Criteria

- AC-1 Before any change, the builder shall record in the Findings: each parser option the issue names (`tree-sitter-bash`, `brush-parser`, a `shfmt` subprocess, `yash-syntax`, `conch-parser`) and TSK-397's lexer, with grammar coverage against the bash and zsh versions the supported harnesses run, error reporting, maintenance, license, supply-chain status, binary size and per-call latency; which shell each harness runs a Bash call in (Claude Code, Codex and Grok Build, on macOS, Linux and native Windows); every issue row rechecked on the line tip with its owner; and the chosen design. A choice that adds a second executable to the product, such as the `shfmt` subprocess, shall be recorded as an operator decision before code; evidence: the Findings section and the ADR draft, committed before the first code change.
- AC-2 When the parser reports an error, meets a construct it does not support, reads a construct the dialect table marks as differing between the harness shells, exceeds its size or nesting bound, or disagrees with TSK-397's lexer on command or word boundaries, both guards shall give the line the base verdict; evidence: fault-injection tests (malformed and truncated input, deep nesting, oversized lines, each dialect row), each asserting a verdict no weaker than the base binary's. (serves EPC-022 AC-164)
- AC-3 The parser shall be qualified by a differential corpus that runs each body under the real bash and zsh versions AC-1 names, records which words each shell runs as commands, passes as arguments, reads as here-document bodies and expands (by traced execution with stub programs in a scratch directory), and compares that with the parser's reading; the corpus shall hold the issue's rows, the infra spike forms the issue names (backticks in `${x:-...}`, `$()` in a `<<-` body, `coproc`), TSK-397's historical corpus and everyday sample, the TSK-415, TSK-417, TSK-1024 and TSK-1072 fixtures, PR 346's bypass probes, and a fuzz set; each disagreement shall be fixed or listed as a fail-closed construct under AC-2; evidence: the harness run on macOS and Linux with shell versions recorded. (serves EPC-022 AC-164)
- AC-4 Once AC-3 holds, a quoted argument or here-document body shall be read as data only when it is given to a program whose identity is established under the execution-identity rule and whose argument grammar is modelled as non-executing for that argument, and when the line does not run it later; each such program and argument shall be listed in one table with its grammar source; evidence: one test per table row on both guards, and one per refused neighbour (an alias, a function, a `PATH` override, a relative program path, an unlisted option). (serves EPC-022 AC-164)
- AC-5 The relief shall cover only these classes: a launcher word or a peer's headless form in data under AC-4, and a pattern or path-shaped word in data under AC-4 that no write or run reaches; the issue rows each class relieves shall be listed; evidence: the list in the Findings and the tests of AC-4. (serves EPC-022 AC-164)
- AC-6 The deliberate scans in the Description shall keep their verdicts: content written to an executable, `.sh`, startup or enforcement path, a file run later on the line, interpreter code including heredocs and `-c` text given to a shell or interpreter, shell `-c` strings, `eval`, `trap`, `ssh` remote commands and `xargs`, `find -exec` and `parallel` templates; evidence: one test per scan on both guards, passing before and after. (serves EPC-022 AC-164)
- AC-7 A literal assignment earlier on the line shall resolve with the shell's scoping (subshell, pipeline element, function body, `export`, `local`) and never more widely than TSK-406's resolver does today; a word filled by the environment, a substitution or a computation shall stay unresolved; and every directory change shall stay an unknown directory as TSK-397 decides; evidence: tests per scope, with TSK-406's tests passing unchanged.
- AC-8 No row of the replay corpus that the line binary at the task's base refuses shall be allowed, except rows in AC-5's classes, each named with its class; evidence: the replay file at the head with the base binary's column, version and digest beside the head's. (serves EPC-022 AC-164)
- AC-9 Per-call latency of both guards on TSK-397's everyday sample, binary size and the dependency added shall be measured before and after and recorded in the pull request; evidence: the measurement table.
- AC-10 The task shall have a cross-lineage security review with the `cf-security-reviewer` checklist, with the reviewer seat's availability checked live, covering the parser dependency, every AC-4 table row and AC-2's fail-closed paths; the pull request shall state the threat each relief could open and why its design is the standard one; evidence: the review verdict and the pull request body. (serves EPC-022 AC-164)
- AC-11 (journey) With the installed build in a scratch adopter project, an agent session shall run the rows AC-5 relieves through both guards and the Codex hook, and shall be refused `true; su -`, a `tee` of prose into `.claude/settings.json`, a heredoc written to a script and run on the same line, and a Python heredoc that names `sudo`; evidence: the journey output.
