# TSK-400: An opt-in infrastructure preset refuses commands that change live cloud state

## Description

Issue: #171, its defect portion. exec-guard has no way to refuse commands that change live cloud state: `terraform apply`, `tofu apply`, mutating `gcloud` verbs, `kubectl` writes and `flux` pass at `security.outward_actions: block`, because `crates/codeflow-core/src/security/outward.rs` knows only the shipped families. The adopter's workaround is its own deny rules in the Claude permission preset and Codex command rules, to be removed once a release refuses these commands.

This task ships the opt-in infrastructure preset that TSK-320 first planned (operator decision 5 of 2026-10-13): `security.project_action_presets: ["infrastructure"]`, off by default. When on, it refuses exactly decision 5's forms, as recorded in TSK-320's description: `tofu` and `terraform` `apply`, `destroy`, `import`, `state rm`, `state mv`, `force-unlock`, `taint`, `untaint`; `gcloud` verbs `create`, `delete`, `update`, `deploy`, `set-iam-policy`, `add-iam-policy-binding`, `remove-iam-policy-binding`, `enable`, `disable`; `kubectl` `apply`, `create`, `delete`, `patch`, `replace`, `scale`, `edit`, `rollout`, `drain`, `cordon`, `taint`; `flux` as a whole program; `helm` `install`, `upgrade`, `uninstall`, `rollback`; `pulumi` `up`, `destroy`, `import`, `refresh`. They are refused at the `outward_actions` level, through the shipped unwrapping, and `update` reports a changed preset.

The preset is a list-valued security key, so it must survive policy composition. Today `crates/codeflow-core/src/hooks/landed_policy.rs` starts from the default branch's policy (`:77`) and folds in each declared integration target through `stricter` (`:108`), which composes levels and level-like enums (`:342`) and unions only `git.protected_branches` (`:360`). A main policy with the preset off would erase an integration target's opt-in. This task adds a bounded union for `security.project_action_presets` in that function, across every default-branch candidate and declared target, so any applicable landed authority that turns the preset on keeps it on. It does not wait for TSK-322's typed composition API; whichever of the two lands second moves this union onto that API.

Project-declared commands (`project_actions`) remain TSK-320 in EPC-023 (4.1.0), which now depends on this task and adds its declarations beside the preset.

Outcome: **an adopter that turns on the infrastructure preset has these commands refused by CodeFlow and can drop its own deny rules.**

Added by the EPC-022 amendment of 2026-10-18 after the Codex review of PR 249 (`target/review-PR249-codex-01.md`), under the operator's rule that every security gap and every defect that forces an adopter workaround or blocks work belongs in 3.2.0.

## Deliverables

- the preset and its key: `crates/codeflow-core/src/security/outward.rs` beside the shipped families, `crates/codeflow-core/src/hooks/policy_schema.rs`, `docs/policy-reference.md`
- the authoritative read and union: `crates/codeflow-core/src/hooks/landed_policy.rs` (`stricter`), and the target-policy read in `codeflow ci`
- tests: guard unit tests and `crates/codeflow-cli/tests/hooks_cli.rs`
- release note naming the preset and the adopter's reversal: `changelog.d/TSK-400.md`

## Acceptance Criteria

- AC-1 With the preset on, each listed command shall be refused at the `outward_actions` level, directly and through `env`, `command`, the shells exec-guard unwraps and `xargs`; with it off, nothing changes; evidence: guard tests per command and wrapper, failing before the change. (serves EPC-022 AC-88)
- AC-2 Read-only forms (`terraform plan`, `kubectl get`, `gcloud ... list`, `--help` and `-help`) shall pass with the preset on; evidence: tests.
- AC-3 The key shall be schema and defaults only, placed by TSK-280's rule, `codeflow policy explain` shall list it, the preset shall hold exactly decision 5's forms, and `update` shall report a changed preset; evidence: the key placement test, a test of the preset list and CLI output.
- AC-4 (journey) With the installed build, a scratch infrastructure project that turns the preset on and removes its own Claude and Codex deny rules shall have an agent session refused `tofu apply` and `kubectl apply -f x.yaml` and allowed `terraform plan`; evidence: the journey output.
- AC-5 When `main`'s landed policy has the preset off and the declared integration target's has it on, the guards on a task branch of that line shall still refuse `tofu apply`; when a branch's own policy removes a preset the target holds, the guards and `codeflow ci` shall still refuse; with every applicable authority off, `tofu apply` shall pass; evidence: `landed_policy.rs` unit tests and CLI tests for the three cases, the first two failing before the change. (serves EPC-022 AC-88)
