# TSK-1607: Eliminate timing race in remote_query policy timeout test under host load

## Description

Source: Director ruling 2026-11-24 (`msg_9abc2e11bd28`, `msg_6c68fc420eee`) and `coord/ci` filing request (`msg_06c2e0bc7608`).

On `origin/main` (`d2307063f2`), `crates/codeflow-core/src/git/remote_query.rs:1149` (`a_slow_destination_answers_within_the_policy_timeout`, from `TSK-1301`) scales the 10-second timeout by 50 to 200 ms against a 226 ms fake `git` sleep (only a 26 ms margin). Under `nice 10` and macOS host load, the child process finishes before the timeout poll fires and `unwrap_err()` panics on `Ok`. Evidence: `coordination/coordinators/capabilities/notes/tsk1568/diag-4tests-96303443f2.log` (`RC3=101`, 0.87s isolated rerun on `96303443f2`, which touches zero Rust files).

Non-goals: changing the production policy timeout semantics in `remote_query.rs`.

## Outcome

After this merges, `a_slow_destination_answers_within_the_policy_timeout` reliably tests the timeout boundary without a 26 ms scheduling race under `nice 10` or loaded macOS/CI hosts.
