# TSK-128: rules re-injected after compaction and on prompt triggers

## Description

After compaction or resume the skill listing and the always rules are gone,
and nothing reminds the agent of a rule at the moment it applies. This task
makes the session-start digest source-aware: on compact and resume it adds a
guidance block of about 1.5 KB (the always rules, the moment table and the
skill names available at that tier), generated from TSK-127's kernel. A
UserPromptSubmit hook adds the one relevant rule, about 300 bytes, when a
prompt asks for a duration, a status or a complex explanation. The sizes are
guideline numbers, not caps. It is
advisory (warn) first and never blocks. Source: research map Part 3, "What
to re-inject".

## Affected surfaces and interfaces

- `crates/codeflow-core/src/hooks/orient.rs`; a new prompt-reminder hook
  command; policy schema (one level key, default warn).
- Scaffolded settings: Claude presets in `assets/base/settings/`, Codex
  `assets/base/codex/hooks.json`, Grok `assets/base/grok/hooks.json`.
- Tests: `hooks_cli.rs`, `settings_presets.rs`, `codex_hooks.rs`.

## Closeout

Status stays `todo`: completion needs the review round and an acceptance
block (TSK-102). AC-1 to AC-5 have their evidence below.

- Generator: `crates/codeflow-core/src/hooks/guidance.rs` reads the shipped
  kernel (`assets/base/rule-map.toml`) and the tier in
  `.codeflow/project.toml`. The compaction block holds the always rules by
  title, each moment with its first pointer and the skills the tier's map
  points at: 1,422 to 1,455 bytes on fresh scaffolds, cap 1,536. The prompt
  line is the always rule's title plus the moment's action and pointers,
  122 to 152 bytes, cap 300.
- Triggers are word sequences, first match by priority duration, status,
  explanation; hyphenated names stay whole (`cf-estimate`), and `git
  status`, `status code`, `status bar` and `progress bar` do not count.
- Policy (R-118, schema owned by TSK-102): one additive key,
  `guidance.prompt_reminders`, default `warn`; `off` and `allow` silence
  it, and `block` is refused by validation and still only advises. The
  key is in the schema (`policy explain`, `policy show`) but not written
  into the shipped or this repository's `policy.json`: `codeflow ci`
  validates the head's policy with the target's binary, which refuses an
  unknown key (probed with the line binary), and an older binary's hooks
  would block every commit. The default applies when the key is absent,
  as for `git.policy_characters`.
- `update`: the settings merge now moves a CodeFlow hook whose shipped
  matcher changed instead of leaving a second copy in the old group, so
  `session-orient` runs once under the explicit matcher. A mutation probe
  (move disabled) fails both the unit test and the update test.
- Reading budget: no skill file changed, so the per-task reading chain is
  unchanged (`artifact_budget_contract`, 15 passed). The block and the line
  are hook output, not files on the chain: the block replaces context a
  compaction removed, once per compaction or resume, and the line appears
  only on a matching prompt.
- Live smoke (one Claude Code 2.1.283 run, Haiku, session
  `441595c2-58e5-4b57-a9ce-cb35f91ab5f4`, fresh standard scaffold from this
  build): asked for a duration, the model quoted the injected reminder line
  and the orient heading from its context and deferred to `/cf-estimate`.
  Codex and Grok were not run live.
- Version skew (open for review): the hook never blocks, but an older
  `codeflow` exits 2 on the unknown `hook prompt-reminder` (probed with
  the line binary), and exit 2 on `UserPromptSubmit` refuses the prompt in
  Claude Code and Codex. A machine with an older binary in an updated
  project has every prompt refused until it upgrades. A `|| true` wrapper
  is not portable to Codex on native Windows, so the CHANGELOG states the
  upgrade order instead.

the Codex hooks reference (learn.chatgpt.com/docs/hooks), the Grok Build

parent's context, digest included, and no longer runs the hook.
