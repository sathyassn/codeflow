# TSK-128: rules re-injected after compaction and on prompt triggers

## Description

After compaction or resume the skill listing and the always rules are gone,
and nothing reminds the agent of a rule at the moment it applies. This task
makes the session-start digest source-aware: on compact and resume it adds a
guidance block of about 1.5 KB (the always rules, the moment table and the
skill names available at that tier), generated from TSK-127's kernel. A
UserPromptSubmit hook adds the one relevant rule, about 300 bytes, when a
prompt asks for a duration, a status or a complex explanation. The sizes are
guideline numbers, not caps. It is
advisory (warn) first and never blocks. Source: research map Part 3, "What
to re-inject".

## Affected surfaces and interfaces

- `crates/codeflow-core/src/hooks/orient.rs`; a new prompt-reminder hook
  command; policy schema (one level key, default warn).
- Scaffolded settings: Claude presets in `assets/base/settings/`, Codex
  `assets/base/codex/hooks.json`, Grok `assets/base/grok/hooks.json`.
- Tests: `hooks_cli.rs`, `settings_presets.rs`, `codex_hooks.rs`.

## Closeout

Complete. Codex approved `a81fa7926` in round 2, and the one later commit,
`b528c6f9e`, only adds the guideline to a test's size print. AC-1 to AC-5
have their evidence below. The first Codex review (`changes_requested` on
`313fdb8cd`) found version skew, the missing `fork` source and a
pointer-derived skill list; all three are fixed here.

- One advisory entry: `codeflow hook session-orient` is wired on
  `SessionStart` and on `UserPromptSubmit` in Claude and Codex, with no
  extra argument, and dispatches on the payload's `hook_event_name`.
  `SessionStart` prints the digest, plus the guidance block when the source
  is `compact`, `resume` or `fork`. `UserPromptSubmit` prints one reminder
  line or nothing. Any other event is a silent no-op; a malformed payload
  gives no reminder. Every path exits 0. `hook prompt-reminder` stays as a
  manual command and is never wired. The guards do not pass through this
  router, and no exit code is remapped.
- Version skew: an older binary (public 2.1.0, or 3.0.0 before this change)
  exits 2 on the unknown `hook prompt-reminder` but exits 0 on
  `hook session-orient` with a prompt payload, printing its digest. With
  one wired command, a machine that has not upgraded sees its digest on
  each prompt and the prompt goes through; the CHANGELOG says so.
- Generator: `crates/codeflow-core/src/hooks/guidance.rs` reads the shipped
  kernel (`assets/base/rule-map.toml`), the tier in `.codeflow/project.toml`
  and the tier's installed inventory from the scaffold manifest (every
  `.agents/skills/<name>/SKILL.md` and `.claude/agents/<name>.md` entry). The
  block holds the always rules by title, each moment with its first pointer,
  every installed skill and, on its own line, the reviewer agent. The prompt
  line is the always rule's title plus the moment's action and pointers.
- Sizes are guidance numbers, per operator direction of 2026-09-27, not
  asserted caps; tests assert structure and print the sizes. Measured on
  fresh scaffolds: block 1,433 bytes (minimal), 1,492 (standard), 1,525
  (full), against a 1,536 guideline; reminder lines 122 to 152 bytes,
  against a 300 guideline. A separate task is turning the reading budget
  into progressive loading.
- Triggers are word sequences, first match by priority duration, status,
  explanation; hyphenated names stay whole (`cf-estimate`), and `git
  status`, `status code`, `status bar` and `progress bar` do not count.
- Policy (R-118, schema owned by TSK-102): one additive key,
  `guidance.prompt_reminders`, default `warn`; `off` and `allow` silence
  it, and `block` is refused by validation and still only advises. The
  key is in the schema (`policy explain`, `policy show`) but not written
  into the shipped or this repository's `policy.json`: `codeflow ci`
  validates the head's policy with the target's binary, which refuses an
  unknown key (probed with the line binary). The default applies when the
  key is absent, as for `git.policy_characters`.
- `update`: the settings merge moves a CodeFlow hook whose shipped matcher
  changed instead of leaving a second copy in the old group, and it removes
  the Grok `session-orient` registrations while keeping the adopter's own
  hooks and the guards. A mutation probe (move disabled) fails both the
  unit test and the update test.
- Reading budget: the one file on the reading chain that changed is the
  Grok host resource, which got shorter (`artifact_budget_contract`). The
  block and the line are hook output, not files on the chain.
- Live smoke (one Claude Code 2.1.283 run, Haiku, session
  `441595c2-58e5-4b57-a9ce-cb35f91ab5f4`, fresh standard scaffold, before
  the review fixes): asked for a duration, the model quoted the injected
  reminder line and the orient heading from its context and deferred to
  `/cf-estimate`. Codex and Grok were not run live.
- Criteria amendments: AC-1, AC-2 and AC-3 were amended by planning pull
  request #648 on the line (merge `07f106541`), since criteria are frozen
  in a task pull request (R-52). AC-2 lists each host's sources, with
  `fork` for Claude treated as resume, after the review found that a fork
  runs `SessionStart` with source `fork`. AC-1 and AC-3 make the sizes
  guideline numbers, per the operator's direction. This branch is rebased
  onto that merge.
