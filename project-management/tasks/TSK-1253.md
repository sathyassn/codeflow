# TSK-1253: Tests that wait on a fake remote or child process tolerate a loaded runner

## Description

Source: hosted run 41523922494, attempt 1, partition 4, on PR 526.

On hosted Windows, `codeflow-cli::policy_authority_journey` test `asking_the_remote_sends_no_stored_http_credentials` (`crates/codeflow-cli/tests/policy_authority_journey.rs:369`) timed out at a 10 second fake-remote wait. It passed on rerun. The red shard also failed commit standards, which reuses the run, and it stalled a records-only pull request's landing chain. The cause class is a fixed wall-clock wait on a loaded runner. The test file has no 10 second constant: it calls `challenging_server()` (`:324`) and `Adopter::doctor()` (`:112`), so the wait sits either in the product's remote query timeout that `doctor` uses or in a shared helper. Find it first.

No open task owns this test. TSK-1077 introduced the journey (its AC-8) and is complete. TSK-1005's flaky-test register is related: a quarantine entry used meanwhile follows its register rules.

Narrowed 2026-11-02 (the Director, 18:3x; source `coordination/coordinators/planning/cut/held-batch/task-G-remote-wait-flake.md`, "Narrowed"): a second slow test, `security::interpreter::tests::interpreter_large_glob_requires_a_safe_prefix` (`interpreter.rs:4643`), ran for more than 53 minutes inside the glob matcher in a full lib run, and 6.5 s alone. TSK-1258 owns its reproduction, the cause and the matcher bound, as a security task. This task keeps only making that test hermetic, so it no longer depends on the shared state TSK-1258 shows (not a working-directory race, which TSK-1258 found false). It depends on TSK-1258's finding, and one builder takes both, TSK-1258 first.

## Outcome

After this merges, the fake-remote tests wait on events, not on a fixed wall-clock bound, and a loaded runner no longer reddens them.

## Deliverables

- the event-based wait in the failing test or its helper: `crates/codeflow-cli/tests/`
- the sibling sweep of fixed short waits, each fixed or recorded with a reason

## Acceptance Criteria

- AC-1 The exact wait that expired shall be named (file:line) and classed as test code or a product timeout; if it is a product timeout that adopters hit on slow remotes the finding shall say so and keep the product limit unless there is evidence to change it; the test shall wait on the event (a request seen, or a child exit); evidence: a `## Findings` section.
- AC-2 The failing test shall no longer depend on a fixed wall-clock bound under load; evidence: a run under induced load that fails before and passes after, or a deterministic event-based wait whose generous bound is documented.

## Findings

Read at `d9bf657be` on the line. The record's line numbers came from an
older revision; each site below is named at its current line.

AC-1, the wait that expired:

- It is a product limit: the guard's remote lookup wait,
  `GUARD_REMOTE_QUERY_WAIT` (`crates/codeflow-core/src/hooks/limits.rs:108`),
  10 s fixed, Security class, with no policy key. `doctor --check
  policy-source` reaches it through `landed_policy::advertises_refs`
  (`hooks/landed_policy.rs:174-177`, `QueryLimits::guard()`).
- Adopters do hit it: on a remote that does not answer within 10 s while the
  tracking refs are missing. The refusal then names `git fetch`, which
  removes the need to ask. It is kept: it sits under the 20 s guard
  deadline, and there is no evidence to change it (coord/ci agreed,
  2026-11-05).
- The test now waits on an answered question.
  `doctor_until_answered` (`crates/codeflow-cli/tests/policy_authority_journey.rs`)
  runs `doctor` to its exit and asks again only when the text names the
  expired guard wait, up to 6 times. Requests from every attempt stay in the
  server log, and all of them are checked for credentials.
- Two TSK-1301 journey tests proved "the guard asked the remote nothing"
  with a 5 s clock. They now read a log that the fake git appends to on each
  `ls-remote`. The asking case asserts one call, so the log is shown to work.

AC-5, the large-glob test: the shared state TSK-1258 names is the
process-wide glob cache (`security/pattern.rs`). The test now runs inside
`pattern::with_private_glob_cache` (test builds only), which gives that one
test a fresh cache instance it owns. Every other test, and the product, keep
the shared cache unchanged. Glob matching runs on the caller's thread, so
the walk uses the test's own cache.
