# TSK-1009: Changed paths that owe end-to-end, UI or mutation evidence are checked

## Description

Issue #302, filed against CodeFlow 3.1.1 (`48104f48b`). The method
requires end-to-end runs for changed journeys, a Whole-flow evidence
section when a CLI, install, hook, handoff or rendered UI changes, real
UI driving with keyboard, contrast and WCAG 2.2 AA checks for user-facing
changes, and property or mutation testing on named triggers. Only a
reviewer enforces any of it: the test-config schema has no evidence kind,
no `codeflow ci` source reads a Whole-flow section, and the journey rule
(`crates/codeflow-cli/src/cmd/ci/classification.rs`) checks free text
only. The issue proposes a deliberate tightening, so it is a feature of
this epic.

Outcome: **a project declares once which changed paths owe which
evidence kinds; `codeflow test --mode full --strict` fails when an owed
kind had no completed target in the run, and `codeflow ci` requires the
Whole-flow section and the `UI:` line when a triggering path changed,
with each opt-out a recorded entry.**

Rules:

- One trigger definition in policy (provisional
  `testing.evidence_triggers`: `paths`, `requires`, `cadence`), read by
  both `codeflow test` and `codeflow ci`. The adopter-facing path set the
  journey rule uses is one built-in trigger owing `e2e` and Whole-flow
  evidence.
- Targets declare `kinds` (the field TSK-1005 adds) with values such as
  `unit`, `integration`, `e2e`, `ui`, `a11y`, `mutation`, `property` and
  `lint`; one target may declare several, and one completed run
  satisfies each.
- Only `cadence: change` triggers block; `cadence: scheduled` triggers
  report from a scheduled job, and a survived non-equivalent mutant
  becomes a tracked item. No repository-wide mutation score is a gate.
- An opt-out is an entry in TSK-424's register with paths, reason, owner
  and expiry, printed on every run.
- Existing projects get the starter triggers report-only; `block` comes
  through a reviewed policy change, and new scaffolds write it on for
  `cadence: change` triggers.

Non-goals: the fixed Testing lines (TSK-1007); writing the end-to-end or
mutation suites of any adopter.

## Acceptance Criteria

- AC-1 When the paths changed since the base select a `cadence: change` trigger and no enabled target declaring an owed kind completed in the run, `codeflow test --mode full --strict` shall fail naming the kind and the paths; a target declaring several kinds shall satisfy each with one run; evidence: gate tests. (serves EPC-024 AC-16)
- AC-2 When a triggering path changed, `codeflow ci` shall refuse at the `git.pr_sections` level a PR body with no Whole-flow evidence section (one bullet per journey) and, for a UI kind, no `UI:` line; evidence: `ci_cli` tests. (serves EPC-024 AC-16)
- AC-3 `codeflow test` and `codeflow ci` shall read the same trigger definition, and the adopter-facing path set shall be one built-in trigger, not a second list; evidence: a test that changes one definition and sees both verdicts change.
- AC-4 A `cadence: scheduled` trigger shall never block a PR, and the scheduled example shall report its results; evidence: a gate test and the workflow example's contract test.
- AC-5 A register entry for a trigger shall clear its paths and be printed on every run; with the policy key unset, an existing project shall see the owed kinds reported and its verdict unchanged, and `codeflow update` shall print what open branches would owe; evidence: tests at each level.
- AC-6 (journey) With the installed build in a scratch web adopter at `block`, changing a UI path without an `e2e` and `a11y` target run shall fail the full gate and `codeflow ci`, and pass after the example Playwright target runs and the PR body carries the Whole-flow section and the `UI:` line; evidence: the journey output. (serves EPC-024 AC-16)
