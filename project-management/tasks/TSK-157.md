# TSK-157: portal relationships read every depends_on form

## Description

The docs portal starter reads a record's dependencies with
`extractRelationships` (`assets/docs-portal/starter/scripts/lib.mjs`), which
accepts only a bare task id per `depends_on` entry. Reproduced 2026-09-28
with a real run: on a fresh `init --full` project with the portal set up and
`project-management` added to its sources (as this repository's own portal
has it), a task with `depends_on: [{id: TSK-001, kind: research, pin:
"0123abcd"}]`, which `validate --docs` accepts (SPC-013 R-112), builds as a
"Source unavailable" stub whose diagnostic reads `declared depends_on
relationship is invalid`, and its content is not shown. In the same run a
task with the legacy spelling `dependencies: [TSK-001]`, which `validate`
and the task model still accept and which EPC-014's TSK-002-001 to
TSK-002-005 use, builds with no dependency shown at all. This task makes
the portal read every `depends_on` form `validate` accepts, as a depends-on
relationship to the entry's `id`. Non-goal: showing a dependency's kind or
pin on the page, or changing what `validate` accepts.

## Affected surfaces and interfaces

- `assets/docs-portal/starter/scripts/lib.mjs` (`relationshipFields`,
  `extractRelationships`) and `assets/docs-portal/starter/tests/adapter.test.mjs`.
- This repository's installed portal (`docs-portal/scripts/lib.mjs` and any
  other changed managed file) with its hashes in `.codeflow/docs-portal.json`,
  reconciled by `codeflow portal setup`; adopters receive the change on
  their next portal setup.
- A CLI journey test; `CHANGELOG.md`.

## Acceptance Criteria

- AC-1 When a record's `depends_on` entry is a bare task id, a research
  object with a pin, or a decision object not yet pinned, and when a record
  uses the legacy `dependencies` spelling, the portal starter's
  `extractRelationships` shall read each as a depends-on relationship to the
  entry's task id, and shall still refuse an entry with no valid id;
  evidence: AC-2's tests.
- AC-2 A starter test shall cover each form in AC-1 and the refused entry;
  evidence: `adapter.test.mjs` run with `node --test`.
- AC-3 (journey) On a fresh `init --full` project with the portal set up
  and `project-management` among its sources, through the built binary and
  the starter's page generator, a task using the research object form shall
  build as a normal page showing its dependency, not a stale stub, and a
  task using the legacy spelling shall show its dependency; evidence: the
  generated pages compared before and after the fix.
