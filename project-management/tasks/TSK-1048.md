# TSK-1048: Cargo takes the fixed pulldown-cmark release

## Description

Advisory RUSTSEC-2026-0414 (CVSS 7.5, High) affects `pulldown-cmark` 0.13.4,
which `Cargo.lock` resolves; the fix is in 0.13.5. The dependency audit in the
security review job (osv-scanner, policy `git.dep_audit=block`) now fails
every pull request on the EPC-022 line. The flaw is exponential event growth
when `Options::ENABLE_WIKILINKS` is on and a wikilink such as `[[a|]]` has an
empty display text. The option is off by default and no CodeFlow code sets it
(the options in use are tables, footnotes, strikethrough, task lists and GFM),
so the vulnerable path is not reached; the audit still blocks on the version.
The workspace pins the crate exactly (`=0.13.4` in the root `Cargo.toml`), so
`cargo update --precise` alone cannot move it: this task raises the pin to
`=0.13.5` and updates the lock, with no other dependency change. It adds no
audit suppression, because a fixed patch release exists. Effect on adopting
projects: none, since the lockfile is not shipped. Non-goal: other dependency
upgrades.

## Deliverables

- the pin and lockfile fix: `Cargo.toml`, `Cargo.lock`
- the release note: `changelog.d/TSK-1048.md`
- any SBOM or pin file the change touches, if a check requires one

## Acceptance Criteria

- AC-1 Before the fix is made, the advisory and its use in CodeFlow shall be investigated and recorded: the affected range, the fixed version, which crates depend on `pulldown-cmark`, whether any code sets `ENABLE_WIKILINKS`, and whether another lockfile or SBOM pins the crate. Evidence: the PR body's investigation section, `cargo tree --locked -i pulldown-cmark`, a search of the sources for the option, and a search of the other lockfiles and supply-chain files.
- AC-2 When `Cargo.lock` is read, it shall resolve `pulldown-cmark` at 0.13.5, the diff shall change only the `pulldown-cmark` entry and any entry the update itself requires, osv-scanner shall report no RUSTSEC-2026-0414, and no suppression shall be added. Evidence: `git diff Cargo.lock`, and osv-scanner on `Cargo.lock` before and after.
- AC-3 When the workspace is built and the Markdown paths run, it shall build and the tests that parse or render Markdown shall pass. Evidence: `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings`, targeted tests of `codeflow-core`, `codeflow-cli` and `codeflow-present`, and `codeflow test --mode quick`.
- AC-4 When the change is released, the changelog shall carry a patch-impact entry that says the build takes the fixed release and that no command or output changes. Evidence: `changelog.d/TSK-1048.md`.
