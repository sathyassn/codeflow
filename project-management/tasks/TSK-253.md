# TSK-253: A completed standalone task's criteria text can be corrected

## Description

A completed standalone task's criteria cannot be corrected today: `work.criteria_frozen` refuses a wording fix on the task branch, on a `plan/` branch and on a reopen, and the only sanctioned route, a planning amendment that names its epic (ADR-0078), does not exist without an epic (sathyassn/codeflow#103). An adopter had to keep a person's name in a criterion and record it as a workaround. This task adds one correction route: a range that changes planning records only may change the text of a completed standalone task's existing criteria when its `Task:` line names that task, or a follow-up task whose `follow_up_of` is that task. The criteria set stays frozen: an added, removed, renumbered or reordered criterion, or a changed `(journey)`, `(after release)` or `(serves ...)` tag or checkbox form, or an added list item that is no criterion, is refused as before. `codeflow ci` prints the delta as a note for the human reviewer, who judges that the substance is unchanged; the task stays `complete` and its acceptance block stays bound to its reviewed commit.

Non-goals: no change to the epic route (ADR-0078), the reopen rule (SPC-013 R-119), the own-task route of an unfinished task, or the release-range rules; the corrected task's own `task/` branch keeps today's behaviour.

## Deliverables

- The correction route: `crates/codeflow-core/src/workgraph/acceptance.rs`, `crates/codeflow-core/src/workgraph/lifecycle.rs` (`follow_up_of`), `crates/codeflow-cli/src/cmd/ci/acceptance.rs`, `crates/codeflow-cli/src/cmd/ci/classification.rs` (no anchored preflight for a records correction), `crates/codeflow-core/src/remedy.rs` (`CRITERIA_CORRECTION`)
- Tests: `crates/codeflow-cli/tests/criteria_correction.rs` and unit tests in `acceptance.rs`
- Decision: `docs/decisions/ADR-0080-a-completed-standalone-task-s-criteria-text-is-c.md`
- Requirement: SPC-013 R-52 and its table row in `project-management/specs/SPC-013.md`
- Doctrine and docs: cf-method `project-organization.md` and cf-model-orchestrator `task-graph.md` (assets and managed copies), `docs/delivery.md`, CAP-010, `CHANGELOG.md` 3.1.0

## Acceptance Criteria

- AC-1 (journey) When a `plan/` pull request whose `Task:` line names a completed standalone task replaces a person's name with a role in one of its criteria, in a range of planning records only, `codeflow ci` shall pass and print a `work.criteria_frozen` note with the criteria delta; evidence: the issue 103 reproduction driven with the built binary in a temporary repository, and `criteria_correction a_named_task_corrects_its_criteria_text`, which fails before the fix.
- AC-2 When the `Task:` line names a follow-up task whose `follow_up_of` is the completed standalone task, `codeflow ci` shall pass the same correction and print the same note; evidence: `criteria_correction a_follow_up_corrects_the_task_it_follows`.
- AC-3 When the correction adds, removes, renumbers or reorders a criterion, changes a criterion's `(journey)`, `(after release)` or `(serves ...)` tag or its checkbox form, or adds a list item that is no criterion, `codeflow ci` shall refuse it as `work.criteria_frozen`, also when every criterion's text is unchanged; evidence: `criteria_correction the_criteria_set_stays_frozen`, `criteria_correction a_checkbox_form_change_is_refused` and the unit test of the structure check.
- AC-4 When the range also changes a path outside the planning records, the `Task:` line names an unrelated task, or the corrected task belongs to an epic, `codeflow ci` shall refuse the change as `work.criteria_frozen` as before; evidence: `criteria_correction the_route_needs_records_only_a_named_task_and_no_epic`.
- AC-5 When the change runs on the corrected task's own `task/` branch or reopens the task, `codeflow ci` shall refuse it as before; evidence: `criteria_correction the_own_branch_and_a_reopen_stay_frozen`.
- AC-6 When a correction passes, the task shall stay `complete` with no `work.acceptance_binding` finding, and the existing `acceptance_cli`, `planning_amendment`, `acceptance_journey` and `ci_cli` suites shall pass unchanged; evidence: the AC-1 test and those suites.
- AC-7 ADR-0080, SPC-013 R-52, the cf-method and cf-model-orchestrator text (byte-identical mirrors, resynced baseline and manifest), `docs/delivery.md`, CAP-010 and the CHANGELOG 3.1.0 entry shall describe the route and its limits; evidence: `codeflow validate --docs` and the `manifest_consistency` test.
