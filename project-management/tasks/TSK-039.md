# TSK-039 — compose the orient layer sources

## Description

The orient layer is the public reader's entry path and currently fails its own
page class: `product.md` narrates v1/v2 history instead of stating a governing
claim, `adoption.md` carries three unrelated subjects in one file, and
`capabilities.md` and `architecture.md` state facts the code contradicts —
wrong Node pins, a Codex effort of medium, a subcommand count that omits
`estimate`. This task rewrites the orient and architecture sources to the
page-class rule settled in TSK-037: one governing claim with a lead carrier per
page, the adoption file split into adoption, harness posture and model
upgrades, capabilities graduated to per-capability sources behind an authored
registry table, and the architecture scaffold block turned into an
area/ADR/consequence table. Non-goal: no product intent is changed and no ADR
is rewritten — the ADR map is authored as a source view, and the ADR-0012 chain
note in `releasing.md` belongs to TSK-040.

## Affected surfaces and interfaces

`docs/product.md`, `docs/adoption.md`, new `docs/harness-posture.md` and
`docs/model-upgrades.md`, `docs/capabilities.md` with new
`docs/capabilities/CAP-*.md` for CAP-010, CAP-013, CAP-015 and CAP-016,
`docs/architecture.md`, `docs/architecture/present.md`, and
`docs-portal/portal.config.json` for the resulting navigation. CAP-015.

## Acceptance Criteria

- [ ] `product.md` opens with a governing claim and the six-layer stage, with
      v1/v2 history removed; evidence: rendered review against the TSK-037
      orient page class.
- [ ] `adoption.md` is split into adoption (install, tiers, daily loop),
      `harness-posture.md` and `model-upgrades.md`, each with one lead carrier;
      evidence: rendered review of all three and no duplicated section.
- [ ] Codex effort reads high, verification stamps are labelled historical, the
      `gh` download tag is a placeholder rather than a stale tag, and charter,
      Herdr, Astra and Hermes are glossed on first use; evidence: `validate
      --docs` plus a term-by-term check of the five items.
- [ ] `capabilities.md` presents an authored registry table and CAP-010,
      CAP-013, CAP-015 and CAP-016 are graduated to `docs/capabilities/`, in the
      corrected order; evidence: every registry row resolves to its source.
- [ ] Node pins read portal 24.18.0 and present 26.4.0 wherever they appear in
      these files; evidence: a repository-wide grep shows no other value in the
      task's owned files.
- [ ] `architecture.md` states 22 subcommands including `estimate`, and the
      scaffold block is an area/ADR/consequence table; evidence: the count
      matches the CLI's registered subcommands at the task head.
- [ ] `architecture/present.md` no longer duplicates `architecture.md`, and the
      System index ADR map is authored by area as a source; evidence: rendered
      review confirms one home per statement.
- [ ] `portal.config.json` navigation resolves every new and moved source with
      no dead entry; evidence: `codeflow validate --portal` passes.
