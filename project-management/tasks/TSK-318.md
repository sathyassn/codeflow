# TSK-318: A carry is a named, checked landing on another line

## Description

A task landed on one line can reach another line today only by an
unchecked merge or a hand port; `ci` requires the task anchored at the
merge-base (`crates/codeflow-cli/src/cmd/ci.rs:1497-1530`)
(https://github.com/sathyassn/codeflow/issues/169, part 1). This task adds
the `Carry` class, a dated note on ADR-0076 (decision 4), with the
exact-preimage, one-commit restriction (decision 11):

- Opt-in: `carry/` in `git.branch_prefixes`; the shipped default gains it,
  and `update` reports a project list that lacks it, inserting nothing.
- Branch and trailer: `carry/TSK-NNN-to-<destination slug>`;
  `Carries: TSK-NNN@<full sha>` is always allowed; `Task:` names the source
  task; the slug is a label; the destination is the PR base or `--into`.
- Class: exact `carry/` prefix and a range `base..head` that introduces
  exactly one non-merge commit carrying the trailer with one task id and
  one sha; any other range is malformed.
- Source proof: `bind_completion` on the home line's fetched tip (TSK-287's
  guarded reader, TSK-308's structured result) returns the reviewed commit,
  landing merge, span head and completion tail; the trailer's sha equals the
  reviewed commit; doubt refuses.
- Reviewed delta: the home line's tree diff from the landing merge's first
  parent to the merge, every planning-record path removed.
- Delta proof: C is the tree diff from the destination merge-base to the
  carry head, `--no-renames`; the path sets are equal; per path, pre-image
  blob and mode at the destination base equal the pre-image at the merge's
  first parent, and post-image blob and mode at the carry head equal the
  post-image at the merge; deletions likewise; no planning path; a symlink
  or gitlink in either image refuses; an empty or already-applied C refuses
  as no delivery; an equal mode change carries, a mismatch refuses.
- The proofs admit the PR and say nothing about the destination having
  received it. They replace the anchor for this class only. Source review
  is reused for content; destination tests, CI and a destination-fit review
  still run. A carry branch is a carry, not an open claim.

Non-goal: carrying a change that needs adaptation, links or merges; that is
a port task.

## Acceptance Criteria

- AC-1 A `carry/` range of exactly one non-merge commit with one valid
  trailer shall be classed `Carry`; two commits, a merge, a missing or
  repeated trailer, two task ids, a short sha and a prefix mismatch shall
  each be malformed; evidence: one test per case. (serves EPC-023 AC-5)
- AC-2 The source proof shall read `bind_completion` on the home line's
  fetched tip, and a forged sha, a task with no landing, a doubt and an
  overlaid history shall each refuse; evidence: tests.
  (serves EPC-023 AC-5)
- AC-3 The delta proof shall pass fixtures for: an extra file, a deleted
  file, an equal mode change (accepted), a mode or type mismatch, a
  symlink, a gitlink, a pre-image mismatch, a touched record, an empty
  delta and an already applied delta, each with its expected result;
  evidence: the fixtures. (serves EPC-023 AC-5)
- AC-4 An admitted carry's output shall say that admission is not landing,
  and the anchor rule shall stay unchanged for every other class; evidence:
  CLI tests and the existing classification tests unchanged.
- AC-5 A carry branch shall not count as an open claim in `work next` or
  readiness; evidence: a readiness test.
- AC-6 The shipped `git.branch_prefixes` default shall include `carry/`,
  `update` shall report a project list without it and insert nothing, and
  commit-msg shall allow the `Carries:` trailer; evidence: tests.
- AC-7 ADR-0076 shall carry a dated note for the `Carry` class; evidence:
  the note.
- AC-8 When the installed hooks and `codeflow ci` carry a task landed on
  one line to another line at checkpoint S3, with TSK-293's merge mode on
  the line, the carry PR shall be admitted and the destination gates shall
  run (journey); evidence: the journey output.
