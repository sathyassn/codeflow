# TSK-1393: Guards judge every git subcommand that writes refs

## Description

git-guard judges the operands of the subcommands in `JUDGED_SUBCOMMANDS`
(`crates/codeflow-core/src/hooks/git_guard.rs`), and exec-guard reads
`push`, `tag`, `config`, `update-ref`, `remote` and `credential`
(`Reader::judges` in `crates/codeflow-core/src/hooks/git_guard/data_operands.rs`).
Git subcommands that can write a ref or a remote are outside both lists:
among them `tag`, `fetch` and `pull` (a refspec can name a local branch),
`notes`, `replace`, `reflog`, `bisect`, `revert`, `am`, `send-pack`,
`fetch-pack`, `submodule` and `filter-branch`. A protected ref or a
data-supplied operand in one of them reaches git without a session
judgment; the reference-transaction hook is the local-ref floor, and
pre-push and remote branch protection are the push floors. Found in the
TSK-326 cross-lineage review (PR 718, Grok, nit N4); it is a subcommand
coverage gap, a different class from TSK-326's data operands.

The task sweeps git's ref and remote writers, decides for each whether a
session judgment adds protection over the floors, and adds the ones that do
to the judged lists of both guards, with the rules they can break. Non-goal:
changing the floors.

Revisit event: when TSK-326 lands on the line.

## Outcome

After this merges, an agent session is refused in session, not only at the
hook floor, when a git subcommand that writes refs names a protected ref or
takes a ref from data.

## Deliverables

- the sweep table, with a decision per subcommand: this record's `## Findings`
- the judged lists and their rules: `crates/codeflow-core/src/hooks/git_guard.rs`, `crates/codeflow-core/src/hooks/git_guard/data_operands.rs`
- docs: the guard residual list in `docs/policy-reference.md`
- release note: `changelog.d/TSK-1393.md`

## Acceptance Criteria

- AC-1 The record shall list each git subcommand that can write a ref or a remote, with whether a session guard judges it after this task and why; evidence: the `## Findings` table, checked against git's documentation for the pinned git version.
- AC-2 When a subcommand the table marks as judged names a protected ref, or takes a ref from data, git-guard shall refuse it under the rule it can break; evidence: unit tests for at least `git fetch origin feat/x:main` and `V=$(cat refs); git fetch origin "$V"`, each failing before and passing after, plus one per other added subcommand. (serves EPC-022 AC-23)
- AC-3 When exec-guard reads a subcommand the table marks as judged by exec-guard, its data-operand reader shall refuse a data-supplied operand as unresolved; evidence: an outward unit test per added subcommand. (serves EPC-022 AC-23)
- AC-4 Read-only uses of the added subcommands (`git fetch origin`, `git tag -l`, `git notes show`) shall still pass in both guards; evidence: an allow-control list in the tests.
- AC-5 The policy reference shall list the judged subcommands of each guard; evidence: the `docs/policy-reference.md` diff.
