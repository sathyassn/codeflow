# TSK-1393: Guards judge every git subcommand that writes refs

## Description

git-guard judges protected-ref rules only for the subcommands in
`JUDGED_SUBCOMMANDS` (`crates/codeflow-core/src/hooks/git_guard.rs`), and
judges a third-party git program only as a command of its own, never
against the protected-ref rules. exec-guard applies no protected-ref rule
on the line; TSK-326's data-operand reader adds its git reading. Git
subcommands that can write a ref or a remote ref are outside git-guard's
list, in these classes:

- a remote-writing plumbing class;
- a local history-rewrite class;
- a commit-creating patch and importer class;
- a protected-branch rename class;
- reflog writes that move a ref, and a command that runs git subcommands in
  other repositories;
- ref names that can be confused with a protected branch;
- third-party git programs.

Found in the TSK-326 cross-lineage review (PR 718, nit N4) and widened by
the Director to every ref writer in git's own command list. It is a
subcommand coverage gap, a different class from TSK-326's data operands.

The task classifies every subcommand in git's command list, judges each
writer against the protected-ref rules it can break, and refuses, fail
closed, a writer whose target ref is protected or cannot be resolved. A
subcommand the guard has not classified is refused where policy protects
refs, unless the project's committed base-branch policy lists it in
`git.trusted_subcommands` (empty by default). Non-goal: changing the hook
floors.

Revisit event: when TSK-326 lands on the line.

## Outcome

After this merges, an agent session is refused in session, not only at a
hook floor, when any git subcommand would write a protected ref locally or
on a remote, would write a ref the guard cannot resolve, or is a program
the guard has not classified and the project has not trusted.

## Deliverables

- the classification by class, with a decision per class: this record's `## Findings`
- the judged writers, the classification and their rules: `crates/codeflow-core/src/hooks/git_guard.rs` and `crates/codeflow-core/src/hooks/git_guard/ref_writers.rs`
- the trusted-subcommand key: `crates/codeflow-core/src/hooks/policy.rs`, `policy_schema.rs`, `landed_policy.rs`, `crates/codeflow-cli/src/cmd/hook.rs`
- docs: the judged classes, the key with a project example and the residuals in `docs/policy-reference.md`
- release note: `changelog.d/TSK-1393.md`

## Acceptance Criteria

- AC-1 The record shall classify each git subcommand in git's command list for the pinned git version that can write a ref or a remote ref, by class, with whether a session guard judges the class before and after this task; evidence: the `## Findings` table, from the guards run on a disposable scratch project.
- AC-2 When a command of the remote-writing plumbing class would update a protected remote branch, update in bulk, or names targets the guard cannot resolve, git-guard shall refuse it under the push rule it can break; evidence: unit tests failing before and passing after. (serves EPC-022 AC-23)
- AC-3 When a command of the local history-rewrite class that git-guard does not already judge could rewrite a protected ref, including through an all-refs option or a ref argument the guard cannot resolve, git-guard shall refuse it under `git.local_ref_protection`; evidence: unit tests failing before and passing after.
- AC-4 When a command of the patch and importer class would write a protected branch, a branch rename or copy names a protected branch in a form git-guard does not already refuse, a reflog write would move a protected ref, a remote read into a named local ref or a remote configuration change would write a protected ref, or a command runs git writers in other repositories, git-guard shall refuse it under the rule it can break; evidence: unit tests failing before and passing after.
- AC-5 Ordinary read-only and unprotected uses of the judged subcommands shall still pass; evidence: an allow-control list in the tests.
- AC-6 The policy reference shall list the judged classes, the trusted-subcommand key with a project example, and the residuals; evidence: the `docs/policy-reference.md` diff.
- AC-7 When `git.local_ref_protection` is active and a git subcommand is neither in the guard's classification of git's command list nor listed in `git.trusted_subcommands` of the project's committed base-branch policy, git-guard shall refuse it; the key shall ship empty, be read only from committed base-branch policy (never the working tree or the environment), and an entry naming a git-shipped command shall not lift that command's judgment; evidence: unit tests for an unclassified program refused before trust, passed after a base-branch entry, still refused with only a working-tree entry or only an environment entry, and a git-shipped writer still judged when listed.

## Findings

AC-1 run on the line's built binary (source b85d30681, git 2.53.0) in a
disposable scratch project with a protected branch and a local bare remote.
The per-command table lands in the task's own pull request together with
the fix (Director ruling, 2026-11-08).

| Class | git-guard before | exec-guard before | After this task (git-guard) |
|---|---|---|---|
| ordinary push (control) | refuses | no ref rule | unchanged |
| remote-writing plumbing | allows | no ref rule | judged as a push; bulk or unresolved targets refuse |
| local history rewrites git-guard already judges | refuses (`git.hard_reset_protected`) | no ref rule | unchanged |
| local history rewrites outside the judged list | allows | no ref rule | refuses when a protected ref may be rewritten or a ref cannot be resolved |
| patch and importer commands on or naming a protected branch | allows | no ref rule | refuses under the commit or ref rule |
| a forced rename onto a protected branch | refuses (`git.local_ref_protection`) | no ref rule | unchanged |
| other branch renames or copies naming a protected branch | allows | no ref rule | refuses under the rule it can break |
| reflog writes that move a protected ref | allows | no ref rule | refuses |
| commands that run git writers in other repositories | allows | no ref rule | refuses unless the embedded command is maintenance |
| ref names that can be confused with a protected branch | allows | no ref rule | refuses |
| push settings given outside the push arguments | allows | no ref rule | judged as a bulk push |
| ref plumbing (control) | refuses | no ref rule | unchanged |
| remote reads into named local refs, and remote configuration changes | refused only when the transport configuration cannot be verified; not judged against the ref rules | no ref rule | judged against the ref rules; a protected ref write refuses |
| writers confined to their own namespaces | allows | no ref rule | unchanged: cannot write a protected ref |
| third-party git programs | allows (judged only as a command) | no ref rule | refused unless trusted in base-branch policy |
