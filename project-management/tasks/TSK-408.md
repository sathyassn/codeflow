# TSK-408: A recursive copy or sync is judged by the enforcement files it creates, replaces or deletes

## Description

Source: finding F6 of the `cf-security-reviewer` round 1 review of PR 260
(TSK-379) at `7156ae3ec`, severity high, confirmed, predating that PR and
outside its diff (`.worktrees/tsk-379/target/review-TSK-379-security-01.md`).
It is a 3.2.0 security gap under the operator's release rule of 2026-10-18.

git-guard's copy judge reads a copy or sync by its destination path: the
`copies` check (`crates/codeflow-core/src/hooks/git_guard.rs:5296-5309`)
hands `copy_destinations` (`:5388-5417`) the destination, the sources as
spelled and, for a copy into a directory, each source's base name inside
it, and refuses when one of those words is an enforcement path. It never
reads what the source tree holds, so a recursive copy whose source
contains `.claude/settings.json` or a hook lands it on the checkout
unjudged, and it never reads what a sync would delete under its
destination. Allowed today by both hooks and by the base binary, the
commands judged and never run except where the reviewer says so:

| Spelling | Effect in the reviewer's scratch run |
|---|---|
| `cp -R /src/.claude .` | overwrote `.claude/settings.json` |
| `cp -R /src/ .worktrees/w` | lands `/src`'s `.claude` and `.git` content in a checkout |
| `rsync -a /src/ ./` | the same onto the current checkout |
| `ditto /src .` | the same |
| `rsync -a --delete /empty/ .worktrees/w/` | deleted the worktree's settings and its `.git` pointer |
| `rsync -a --remove-source-files .claude/ /dst/` | removes every file under `.claude` after copying it out |
| `rsync -a --remove-source-files .git/hooks/ /dst/` | removes the hooks |

F5 of the same review, the `--remove-sent-files` and `--remove-source`
spellings of the last two, is repaired inside PR 260 and is not this task.

Outcome: **a recursive copy or sync is refused when any file it would
create, replace or delete under its destination is an enforcement file
or a checkout's git pointer, and a copy or sync that touches none of them
passes as it does today.**

Rule: the guard judges the content a recursive copy or sync moves, not
only the destination word.

- **Commands read:** `cp` with `-R`, `-r` or `-a`, `rsync` (its archive
  and recursive forms, every `--delete*` option, `--remove-source-files`
  and its aliases), `ditto`, and `install` with a directory source, in
  every launcher and separator form the guards already read for `cp`.
- **What is judged:** for each source, every path the command would write
  under the destination, mapped by the command's own rules (cp's copy
  into an existing directory under the source's base name, rsync's and
  ditto's trailing-slash rules); for a deleting sync, every path under
  the destination that the source lacks; for a source-removing sync,
  every source file. A path in that set that is an enforcement file, a
  `.git` file or directory of a registered checkout, or a checkout root
  refuses with the rule that file gets, and the message names the file
  and the source it comes from.
- **Reading the source:** the guard reads the source tree on disk at
  judgment time, bounded by the same walk limit the repository reader
  uses (`crates/codeflow-core/src/hooks/repo.rs`). A source it cannot
  read (missing, unreadable, an unresolved expansion or glob, a remote
  `host:` or `rsync://` spelling) or a walk past the bound refuses as
  cannot-verify, naming the source, when the destination is inside a
  checkout or the guard cannot tell. A destination outside every checkout
  and enforcement set keeps its ordinary verdict without reading the
  source.
- **Plain copies unchanged:** a non-recursive `cp` of a single file keeps
  the destination-path verdict it has today. A copy whose destination
  is outside every checkout (`cp -R .claude /scratch/backup`) stays
  allowed; it writes nothing the guards protect, and TSK-407's hard-link
  rule covers the one case where a copy shares an inode with the
  original.

Non-goal: archive extraction (`tar -x`, `unzip`, `git archive`) whose
member names are inside the archive and not on disk; it keeps the
destination-path check and the OS sandbox as its backstop, and the builder
records it as the residual in the policy reference. Modelling what a copied
script does when run later is TSK-378's and TSK-406's ground, not this
task's.

Added by the EPC-022 amendment of 2026-10-20 under the operator's release
rule of 2026-10-18 that every security gap belongs in 3.2.0.

## Acceptance Criteria

- AC-1 When a recursive copy or sync would create or replace an enforcement file or a checkout's `.git` under its destination, git-guard shall refuse it naming that file and its source: `cp -R /src/.claude .`, `cp -R /src/ .worktrees/w`, `rsync -a /src/ ./`, `ditto /src .`, and each of them with `.git/hooks/` in place of `.claude`; evidence: one guard test per spelling over a fixture source tree, each failing before the change. (serves EPC-022 AC-99)
- AC-2 When a sync would delete an enforcement file or a checkout's `.git` under its destination (`rsync -a --delete /empty/ .worktrees/w/`, and the `--delete-before`, `--delete-during`, `--delete-after`, `--delete-excluded` and `--del` spellings), or remove one as a copied source (`rsync -a --remove-source-files .claude/ /dst/`, the same with `.git/hooks/`), git-guard shall refuse it naming the file; evidence: one guard test per option, each failing before the change. (serves EPC-022 AC-99)
- AC-3 A source the guard cannot read (missing, unreadable, an unresolved expansion or glob, a remote spelling), or a walk past the bound, shall be refused as cannot-verify naming the source when the destination is inside a checkout or the guard cannot tell; evidence: guard tests per case.
- AC-4 Ordinary forms shall keep passing: `cp -R src/ build/`, `rsync -a docs/ site/`, `ditto src build`, `rsync -a --delete out/ dist/` where neither side holds an enforcement file or a checkout, `cp -R .claude /scratch/backup` and `rsync -a .claude/ /scratch/backup/` with the destination outside every checkout, a single-file `cp` unchanged, and `rsync -n` or `--dry-run` of any refused line; evidence: guard tests.
- AC-5 `docs/policy-reference.md` shall state the content rule, the commands it reads, the cannot-verify cases and the archive-extraction residual; evidence: the doc text.
- AC-6 (journey) With the installed build, an agent session in a scratch adopter project holding a planted source tree shall be refused each line of AC-1 and AC-2 and shall run the ordinary forms of AC-4; evidence: the journey output. (serves EPC-022 AC-99)
