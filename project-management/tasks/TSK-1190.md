# TSK-1190: Each target command receives the comparison base and the changed paths

## Description

Issue 514. A target command receives the comparison base and the changed paths, so a project script can narrow its own work without CodeFlow trusting it. Code: `crates/codeflow-core/src/testing/runner/mod.rs:956-959` and `:1239-1244`. The hint stays informational and never becomes selection credit (ADR-0089), and a run is complete only when every target ran. TSK-1039 supplies the base derivation.

Security: a light touch, so no separate cross-lineage security pass is required; the Codex whole-unit review is told to check the ADR-0089 boundary.

## Outcome

after this merges, a project's target command can read the comparison base, the head and the list of changed paths from its environment, in quick and full mode.

## Deliverables

- the environment variables and the per-worktree path file: `crates/codeflow-core/src/testing/runner/mod.rs`
- the base recorded in `run.json`
- docs: the target-command contract where it is described
- release note: `changelog.d/TSK-1190.md`
- the exit-code contract in `crates/codeflow-core` test running, with output and `run.json` states (from TSK-1260)
- docs of the reserved code where target commands are described (from TSK-1260)
- tests per case below (from TSK-1260)

## Acceptance Criteria

- AC-1 A target command shall receive `CODEFLOW_BASE`, `CODEFLOW_HEAD` and the changed-paths file path in quick and full mode; evidence: a fixture target that prints them, failing before the change.
- AC-2 With no provable base, the variables shall say "unknown" and nothing shall narrow; evidence: a fixture with no base, and a test that the run still runs every target.
- AC-3 `run.json` shall record the base, and the path file shall be per worktree and never shared; evidence: a two-worktree fixture.
- AC-4 (journey) (added 2026-11-02, final review round 1, finding 1: the task had no journey criterion; this one drives its own change with the built binary) With the built binary, `codeflow test` over a fixture target that prints its inputs shall show the base, the head and the changed-paths file in a repository with a provable base, and "unknown" with every target still run where none is provable; evidence: both outputs.
- AC-5 (added 2026-11-02, source: `for-TSK-1190-from-T8.md` (study item T8, issue 514); reason: the landed record states the ADR-0089 boundary only in its Description) These inputs shall never change which targets CodeFlow selects, skips or credits: a run with the inputs present shall select and credit exactly as a run without them (ADR-0089, TSK-1044); evidence: the existing selection tests passing unchanged, and one test that compares the two runs.
- AC-6 (added 2026-11-02, source: `for-TSK-1190-from-T8.md`; reason: AC-2 and AC-3 do not say what the changed-paths file and `run.json` show when no base was proven) When no base could be proven, the changed-paths file shall not be offered as if it were complete, and `run.json` shall record that no base was proven; the schema version rules of `run.json` shall hold; evidence: a test with no provable base, the schema test and a `run.json` fixture.
- AC-7 (added 2026-11-02, source: `for-TSK-1190-from-T8.md`; reason: the landed record has no step that fixes the variable names and the path-file format before code) Before any change, the builder shall record in a `## Findings` section how a target command is started in quick and full mode, where the comparison base is already computed, and the variable names, the changed-paths file format, path quoting and size limits a project's runner needs; evidence: the Findings, committed before the first code change.
- AC-8 Each target command shall also receive the landing target line, including on a detached candidate checkout; evidence: a runner test on a detached head (issue 545).
  - Added 2026-11-03 by the regroup planning pull request (planning amendment, batch 3); reason: issue 545 asks for the landing line in the same environment passing this task adds (`crates/codeflow-core/src/testing/runner/mod.rs`); issue fold of 2026-11-03.
- AC-9 (was TSK-1260 AC-1) Exit 0 shall be a pass, one documented reserved code shall be "skipped, not selected", and any other code shall fail; evidence: a test per exit code.
- AC-10 (was TSK-1260 AC-2) A skip shall be reported as not selected in the output and in `run.json`, and the run shall be incomplete and not evidence; evidence: a test over both. (serves EPC-022 AC-238)
- AC-11 (was TSK-1260 AC-3) In a complete-gate mode (full, strict or a protected target) a skip shall fail the run or leave the gate incomplete; evidence: a test per mode.
- AC-12 (was TSK-1260 AC-4) A skip shall grant no reuse, no evidence and no pass count, including for a reporting job that aggregates shards; evidence: tests for reuse and the aggregate with a skipped target offered.
- AC-13 (was TSK-1260 AC-5) (journey) In a scratch repository with a target that exits the reserved code, a quick run shall report it skipped and incomplete, and a strict run shall not pass; evidence: the journey output.
