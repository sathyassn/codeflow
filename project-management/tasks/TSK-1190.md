# TSK-1190: Each target command receives the comparison base and the changed paths

## Description

Issue 514. A target command receives the comparison base and the changed paths, so a project script can narrow its own work without CodeFlow trusting it. Code: `crates/codeflow-core/src/testing/runner/mod.rs:956-959` and `:1239-1244`. The hint stays informational and never becomes selection credit (ADR-0089), and a run is complete only when every target ran. TSK-1039 supplies the base derivation.

Security: a light touch, so no separate cross-lineage security pass is required; the Codex whole-unit review is told to check the ADR-0089 boundary.

## Outcome

after this merges, a project's target command can read the comparison base, the head and the list of changed paths from its environment, in quick and full mode.

## Deliverables

- the environment variables and the per-worktree path file: `crates/codeflow-core/src/testing/runner/mod.rs`
- the base recorded in `run.json`
- docs: the target-command contract where it is described
- release note: `changelog.d/TSK-1190.md`
- the exit-code contract in `crates/codeflow-core` test running, with output and `run.json` states (from TSK-1260)
- docs of the reserved code where target commands are described (from TSK-1260)
- tests per case below (from TSK-1260)

## Findings

- Target launch: quick and full both use `gate::run_configured`, then
  `configure_run_targets`, then the dependency scheduler and
  `runner::run_target_with_workers`. The latter chooses `target.modes[mode]`
  and calls `spawn_command`; `configure_environment` copies `target.env`
  into the child. Worker grants are added by the scheduler before launch.
- There is no comparison-base derivation on this line. `delivery::select`
  runs every eligible target. The new hint resolves `--since` once to an
  exact commit, otherwise uses the merge base of HEAD with the carried
  task's committed `integration_target`. A shallow repository, missing
  revision, detached head without `--since`, absent task or target, or an
  unreadable diff yields unknown. No fallback to HEAD~1 or a push's old tip.
- The variables are `CODEFLOW_BASE`, `CODEFLOW_HEAD`,
  `CODEFLOW_CHANGED_PATHS_FILE` and `CODEFLOW_LANDING_LINE`. Without a
  provable comparison, the first three say `unknown`; the landing line is
  independently available from the task record. A detached candidate may
  carry `CODEFLOW_LANDING_LINE` explicitly, as an informational caller hint.
  It never grants selection, reuse or completion credit.
- The path file contains NUL-separated, repository-relative raw Git path
  bytes, including tracked edits and untracked, nonignored files. No shell
  quoting or escaping is applied. Readers split on NUL and never evaluate
  names. This preserves newlines and non-UTF-8 names. Environment values
  require exact UTF-8; an unrepresentable path value stays unset rather
  than naming a lossy lookalike (issue 79). The list is bounded at 16 MiB;
  an incomplete or unavailable list offers no path file and says unknown.
  `validation::detect_changed_files` cannot be reused: its error returns an
  empty list and its strings encode non-UTF-8 names as storage keys.
- The file lives inside the run's unique, exclusively created directory
  under the worktree's target directory. Writes use the existing anchored
  containment API. It is a snapshot before targets start, never authority.
  `run.json` gains additive comparison fields under schema version 2;
  unknown is recorded explicitly, with a reason, never an empty complete
  list. Existing schema-2 fields keep their meanings.
- Reserve exit 77 for `skipped, not selected`. Its serialized status is
  `not_selected`, distinct from selection's `skipped`; this is also the
  state to use in main's newer `outcomes` list when the lines join. A skip
  makes the gate fail and incomplete in every mode, earns no target
  evidence or pass count, and blocks dependent targets. This conservative
  behavior also prevents a hosted success or reuse of a skipped shard.
- Scope: target inputs and outcome reporting, their tests and public
  contract. No target-selection changes. Builder: this Codex session;
  independent whole-unit security review is arranged by coord/ci under the
  operator's build brief. Interface design conforms to the existing CLI.

- Review repair (2026-11-14, Grok findings at `e2c94d82ab`): F1 allowed a
  task to name itself as its landing line and claim an empty comparison.
  Declared lines now require `is_stable_work_target`, resolve only through
  `target_reference_names`, and leave the comparison unknown when they name
  the current logical branch or resolve to HEAD. F2 exported unchecked
  candidate and parent strings as `CODEFLOW_LANDING_LINE`. Both sources now
  require a stable name using only ASCII letters, digits, `/`, `-`, `_` and
  `.`, without `..`; invalid values become `unknown` before export, even
  when the ref cannot be resolved. Regression fixtures cover the self-target,
  HEAD alias and literal payload strings. N1 adds a path-list fixture over
  16 MiB; N2 adds a two-merge-base fixture. N3 and N4 remain dropped.
