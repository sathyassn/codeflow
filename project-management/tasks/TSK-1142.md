# TSK-1142: The journey map refuses a stale pending entry and a shared control and fault

## Description

Follow-up of TSK-362, which moved to EPC-026 (the capabilities catalog) and kept only the typing of `verified_by`. This task carries the journey map rules from its original criteria, unchanged in intent. The journey map (`crates/codeflow-cli/tests/journey_gate.toml`, 42 entries) refuses a pending entry only when its task is `complete` (`crates/codeflow-cli/tests/journey_gate.rs`, the pending check near line 196), so "the live pack graded with zero, one and two available primaries" stays pending on TSK-116, which is cancelled and superseded by TSK-194. And 13 of 42 entries name one test as both control and fault; the map check does not require them to differ. Basis for the grade: one gate file, one map and fixtures, about 300 lines. Source: the two test integrity audits of 2026-10-17 at `eaf2ed04e932186cdd26dc4a7e5740cc553acee3`.

## Outcome

After this merges, a green journey gate cannot be read as "every journey proven" when a pending entry sits on a cancelled or superseded task or when one test stands as both control and fault without proving both.

## Deliverables

- the journey rules: `crates/codeflow-cli/tests/journey_gate.rs` and `journey_gate.toml` (pending on a terminal or superseded task refused; control and fault distinct or explicitly annotated)
- the live pack journey: remapped to its successor's tests or removed by a spec amendment of SPC-013 R-104 in the same pull request, with CAP-013's status reconciled
- release note: `changelog.d/TSK-1142.md`

## Acceptance Criteria

- AC-1 The journey check shall refuse a pending entry whose task is complete, cancelled or superseded, naming the successor where one is recorded; evidence: fixture maps for each status, failing before the change for `cancelled`. (serves EPC-023 AC-21)
- AC-2 An entry whose control and fault are the same test shall be accepted only when that test is proven to drive both states: a passing control and the intended fault verdict, the entry naming the fault's expected rule or message and the check verifying that the test asserts both; an annotation alone grants nothing. Otherwise the entry is split. The 13 entries with identical control and fault lists (21 entries share at least one identity) shall each be proven or split; evidence: the check's test, a negative fixture in which an annotated shared test omits the fault or its oracle and is rejected, and the map diff. (serves EPC-023 AC-21)
- AC-3 (journey) With the installed build, removing a mapped test or leaving the live pack entry pending on a cancelled task shall make the gate fail, and restoring it shall pass; evidence: both runs' output. (serves EPC-023 AC-21)
