# TSK-211: new Claude settings compact at half the window

## Description

CodeFlow's own `.claude/settings.json` has carried a compaction policy
since 2026-09-14 (commit `888c06708`):
`CLAUDE_CODE_AUTO_COMPACT_WINDOW=1000000` and
`CLAUDE_AUTOCOMPACT_PCT_OVERRIDE=50`, so a session on a native 1M-window
model compacts at about 500K tokens instead of Claude Code's default of
about 967K. That change kept the policy out of the Claude settings presets
that `codeflow init` and `codeflow update` write, as opt-in through
cf-customize. The operator decided on 2026-10-03 to ship it in those
presets. Per the Claude Code docs (code.claude.com/docs/en/env-vars and
/model-config), the percentage can only lower the threshold, the window is
capped at the model's real window, and a session limited to 200K
compacts at about 100K with these values. Non-goal: the immutable
delegated-run settings, which stay unchanged.

## Acceptance Criteria

- AC-1 When `codeflow init` writes Claude settings at any tier and
  permission preset, `.claude/settings.json` carries a top-level `env`
  with `CLAUDE_CODE_AUTO_COMPACT_WINDOW` = `"1000000"` and
  `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` = `"50"`, as strings; evidence:
  settings preset and init tests over every preset. (journey)
- AC-2 When `codeflow update` runs in a project whose settings have no
  `env`, it adds the two keys; when the project has its own `env`, it
  keeps every entry and value the project set, adds a missing one of the
  two keys only when the project has not removed or changed it since
  CodeFlow last wrote it (the managed baseline), and a second update is a
  no-op; a malformed `env` is reported and left as is; evidence:
  settings merge unit tests and an update journey in a fixture project.
- AC-3 The cf-customize context-policy reference describes the default,
  its effect on 1M and 200K windows and the status-line caveat from the
  docs, and how a project opts out or changes the values so that update
  keeps its choice; every mirror and baseline copy matches; evidence: the
  diff and `manifest_consistency`.
- AC-4 The pending 3.1.0 CHANGELOG entry, under its release-impact marker,
  states the new default, who it affects and how to opt out; evidence: the
  diff and the release-impact check.
