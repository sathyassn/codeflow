# TSK-082: Agent OS mirror of the catalog and autonomy rules

## Description

Bring Agent OS to the same rules as the EPC-018 line. The work lands in
the agent-os repository in two halves, each through its own reviewed agent-os
pull request; this record tracks both, following the EPC-015 TSK-056
precedent. Split on 2026-09-28: the settings v8 permission work changes the
autonomy reference (TSK-164), so the autonomy half waits for it while the
routing half does not.

- Routing half (starts now: ADR-0069 is accepted and `codeflow models
  resolve` exists on this line from TSK-080): any Agent OS text that names a
  model or a CodeFlow binding points at the CodeFlow catalog by seat and duty
  instead, and resolves through `codeflow models resolve`; this includes
  `system/core/architecture/model-strategy.md`. Hermes stays a
  delegate-only host; no Agent OS catalog copy is made.
- Autonomy half (starts after TSK-164 is complete, so Agent OS mirrors the
  reference as the permission work leaves it; ADR-0070 is accepted):
  `system/skills/operating-rules/SKILL.md` section 2 opens with the same
  short statement and keeps its tiers; the SOUL condensed block gains one
  line; the `qualify-model-binding` cases gain the over-asking set in their
  own schema (`tier`, `action`, `needs_approval`), and
  `test_doctrine_contract.py` asserts the clauses. Where Agent OS already
  states a rule, cite it instead of adding a copy.

Agent OS handoff with EPC-016 TSK-063, as EPC-016 Plan v4.3
(`plan/visual-guide-v4` at `eb2a17219`, `EPC-016.md` near lines 447-468 and
`TSK-063.md` near lines 92-103) states it. TSK-063 writes nothing under
Agent OS `system/`: its figures are guide-owned companion declarations bound
in `portal.config.json`, so no bundle duty falls on EPC-016. The shared part
is meaning: a companion figure whose `facts[]` point into a page this task
changes must be rechecked.

Each half's pull request follows the same order rule against TSK-063.

- Default order: this task lands on Agent OS `main` first. It regenerates
  and verifies the bundle itself (`scripts/release_bundle.py sync`,
  `verify-state`). EPC-016 then owns the guide recheck (TSK-063, then
  TSK-064, then the conditional steps in its draft Agent OS pull request).
- Reverse order: if TSK-063's pull request lands on Agent OS `main` first,
  this task is the second lander and owns the same guide recheck. Rebase
  onto the new Agent OS `main`; recheck every companion figure whose
  `facts[]` point into a page this task changed, against the changed page;
  run `validate --portal guide`, the browser verification and the source
  byte check against the new base; then regenerate and verify the bundle
  and rerun this task's own tests.

Non-goal: CodeFlow files, the workspace contract.

## Affected surfaces and interfaces

agent-os `system/skills/operating-rules/SKILL.md`, the SOUL condensed block,
its `qualify-model-binding` cases and `test_doctrine_contract.py`,
`system/core/architecture/model-strategy.md`, the bundle artifacts that
`release_bundle.py sync` regenerates, and any
agent-os text a search finds naming a model. No CodeFlow source.

## Acceptance Criteria

- AC-1 (autonomy half) The operating rules open with the same statement as
  `autonomy.md` after TSK-164, the over-asking cases exist with faulty
  controls, and the doctrine test asserts the clauses; evidence: agent-os
  test output and the pull request URL.
- AC-2 (routing half) A search of agent-os finds no model name outside
  historical records and fictional fixtures, and the routing texts point at
  the catalog by seat and duty; evidence: the search output and the pull
  request URL.
- AC-3 The EPC-016 handoff holds on the default order for each half: the
  half that lands before TSK-063 regenerates and verifies the bundle itself
  and leaves no bundle duty to EPC-016; evidence: the Agent OS merge order,
  the `release_bundle.py sync` and `verify-state` output.
- AC-4 On the reverse order (TSK-063 landed first), each half that lands
  after it, as second lander, rebased onto the new Agent OS `main`,
  rechecked every companion figure whose `facts[]` point into a page it
  changed, and passed `validate --portal guide`, the browser verification
  and the source byte check against the new base before landing; evidence:
  the list of rechecked figures with their pages, the validator output, the
  browser verification record and the byte check output.
- AC-5 Grok and Codex review each agent-os pull request, or reduced
  assurance is recorded for a missing seat; evidence: the review records.
