# TSK-1131: Default reasoning effort follows each vendor's recommendation

## Description

Operator direction (2026-11-01): models improved and tokens should be used
efficiently, so every session and worker CodeFlow starts or recommends runs
at its model's vendor-recommended default effort, and raises it only when a
specific task needs it ("make sure the sessions are running in medium effort
by default unless really needed in high"; "it would depend on the model and
what's recommended"). Claude Code's model configuration docs say effort
defaults to high except on Opus 5.5, Sonnet 5.5 and Haiku 5.5, which default
to medium, and Anthropic's effort guidance recommends starting at medium. So
Opus 5.5 and Sonnet 5.5 default to medium, Fable 5.1 keeps its own default
(high), the Codex lines GPT-6 Astra, GPT-6.1 Sol and GPT-6 Luna default to
medium, and Grok 4.7 stays at high. High (xhigh on Codex) is used only for a
named reason: a trigger, a hard build, a security review or a stuck
diagnosis. Director and coordinator sessions stay at the default.

The shipped catalog (`current-ensemble.json`) bound the host, both planning
primaries, the executor and the reviewers at high by role, and its validator
forced a high floor on every seat-targeted duty. This task fixes the records
by model: seat-targeted routes carry medium, design included; the floor is
high only for the reasoning-support duty; the high triggers are exactly the
named needs (hard build, security review, stuck diagnosis) and raise only
the lane they are applied to, never the orchestrating session; a project
binding accepts the medium default and keeps a higher bound effort; and a
seat at medium resolves only to a line that offers medium (so the Claude
seat resolves to Opus). Review round 01 (Grok, 2026-11-01) found the design
floor, the category triggers and the binding check; they are fixed here.

Scope addition (operator, 2026-11-01 14:00): Fable 5.1 uses tokens and limits
much faster, so the guidance says the highest-cost reasoning model (Fable in
the current ensemble) serves only key review, analysis and direction (design,
architecture and planning decisions), never execution; each run names its
deliverable and an end and is closed when done; execution goes to Opus or
Sonnet. A test holds that no execution route binds Fable.

The change is generic for adopters: shipped catalog, orchestration and seat
launch guidance, the scaffold mirrors and baseline, and the decision record
(ADR-0095, superseding ADR-0056's high default). Non-goals: per-person effort
settings (ADR-0087 stands), the model roster, and evaluation fixtures that
use fictional models at high.

## Outcome

After this merges, an adopter or operator who starts or routes a session
through CodeFlow gets each model's vendor-recommended effort by default, sees
high used only for a named reason, and never has an execution route bound to
the highest-cost reasoning model.
