# TSK-216: CodeFlow guards and gate work inside its own Claude sandbox

## Description

Three defects make CodeFlow fight its own Claude sandbox or let a
protected branch move. Issue 23: on macOS the git guard refuses
`sed -i '' ...`, and an empty `rm ''` operand, as an edit of the
enforcement files whenever the cwd is a worktree under
`<root>/.claude/worktrees/`. Issue 24: the full gate refuses with
`gate lock unavailable` inside the sandbox the shipped presets install,
because they do not allow writes to `~/.codeflow/locks` or
`~/.codeflow/gate-runs`; `codeflow doctor` misses that and, in the
sandbox, reports offline and signed out of Codex when neither is true. A
gap found on 2026-10-03: the guard allows `git branch -f main HEAD~3`, a
local rewind of a protected branch.

Scope: the guards' reading of these commands, the presets' sandbox write
roots, the gate's refusal text and the doctor checks. Two full gates must
still never run at once on one machine. Non-goal: the Claude and Grok hook
command strings in the presets, which another task changes (issue 29).

## Acceptance Criteria

- AC-1 When git-guard judges, with the cwd in a linked worktree under
  `<root>/.claude/worktrees/<name>`, `sed -i '' 's/a/b/'` on a scratch
  file or `README.md`, `rm -f ''`, `rm -f .`, `sed -i` and `sed -i.bak`,
  it allows them, and it still refuses `sed -i ''` on the worktree's
  policy file, `sed -i '' -e` on its Claude settings and `rm -rf` of its
  `.claude` or `.codeflow` directory; evidence: `hooks_cli`
  `git_guard_allows_empty_operands_in_a_claude_worktree` fails before the
  change and passes after, and the `git_guard` unit tests for BSD `sed`
  forms. (journey)
- AC-2 When a full gate runs in a session using a shipped Claude preset,
  the sandbox lets it write `~/.codeflow/locks` and `~/.codeflow/gate-runs`,
  the presets add no other write root under the CodeFlow home, `codeflow
  update` carries the roots into this repository's settings, an unopenable
  lock still refuses, and the refusal names `codeflow doctor --check
  permissions`; evidence: `settings_presets`
  `sandbox_allows_writes_only_to_present_state_and_the_gate_directories`,
  the gate lock unit tests, `test_gate_cli`
  `unavailable_gate_lock_refuses_before_start`, and
  `repository_update_noop`.
- AC-3 When `codeflow doctor` runs, the permissions check names each gate
  lock or evidence directory this process cannot write, with the remedy to
  allow it, and with `SANDBOX_RUNTIME` set doctor says it runs in the
  sandbox, probes the network over HTTPS, and reports a failed `codex
  login status` as unreadable in the sandbox, not as signed out; evidence:
  the doctor unit tests for permissions, network and delegates, and a
  doctor run in a sandboxed session.
- AC-4 When git-guard judges `git branch -f main HEAD~3`, `git branch -M`
  or `-C` onto a protected branch, `git checkout -B main` or `git switch -C
  main`, it refuses under `git.local_ref_protection`, and the same moves of
  a feature branch stay allowed; evidence: `hooks_cli`
  `git_guard_refuses_a_forced_move_of_a_protected_branch` fails before the
  change and passes after, and the `git_guard` unit test
  `test_forced_branch_move_of_protected_blocked`.
- AC-5 The pending 3.1.0 CHANGELOG entries, under their release-impact
  markers, state each fix and who it affects; evidence: the diff and the
  release-impact check.
