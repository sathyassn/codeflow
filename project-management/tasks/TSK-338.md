# TSK-338: A first adoption can push and complete without weakening an established policy

## Description

Issue: #182, including its comment. `crates/codeflow-core/src/workgraph/release_line.rs:428` deliberately treats every existing default target without `.codeflow/policy.json` as an error; `:440` reads only its tree. It does not distinguish never adopted from a policy deleted later. Pre-push calls that scope decision at `crates/codeflow-cli/src/cmd/push_set.rs:1240`; completion also depends on the release-branch determination described in the issue.

TSK-330's recovery starts only on unmerged local index entries and explicitly preserves authority selection. It does not cover a remote default branch that never had a policy. TSK-305's destination failure also has a different cause.

Outcome: **A full-tier adoption task can be pushed and completed in its own PR when the existing default branch has never held CodeFlow policy, while deleted or unreadable prior policy still refuses.**

Source inspection is from the accepted triage at `c5c6f6f671d2bf67a77113c656b3be446fb0bea1`; runtime reproductions remain implementation evidence.

## Deliverables

- history authority and lifecycle callers: `crates/codeflow-core/src/workgraph/release_line.rs`, guarded history reader and `crates/codeflow-cli/src/cmd/push_set.rs`
- adoption and negative-control journeys: `crates/codeflow-cli/tests/`
- initial-adoption guidance: `docs/` (provisional page selected from existing adoption guidance)
- release note: `changelog.d/TSK-338.md`

## Acceptance Criteria

- AC-1 Through the guarded history reader, distinguish never-present policy from removed policy, unreadable ancestry, shallow/overlaid history and an invalid policy. Only the proven initial-adoption case receives the defined bootstrap rule.
- AC-2 `work claim`, ordinary pre-push, `task status complete` and local/hosted `ci` agree on that bootstrap authority. Preserve the existing no-default-target case.
- AC-3 A protected main with no bypass can receive the adoption through a normal PR; no hook skip, direct main push or acceptance-file hand edit is required.
- AC-4 (journey) Run initial commit -> full init -> task -> reviewed completion -> pushed PR on a disposable destination, plus removed-policy and unreadable-history negative controls.
