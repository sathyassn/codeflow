# TSK-418: A records-only editorial change lands wording changes to many closed records

## Description

Issue #277. A full-tier project adopted a rule that tracked content must
not name internal sessions or local paths, and must rewrite that wording
across closed task and epic records while keeping every criterion id,
tag, status, criterion outcome and reviewed commit. `codeflow ci` 3.1.1
refuses the edit in every pull request shape: a records-only PR naming
the cleanup task (37 `work.acceptance_binding`, 24 `work.criteria_frozen`,
7 `work.records`), a `plan/` branch naming the open epics (binding,
amendment and records refusals remain), one PR per completed standalone
task under ADR-0080 (criteria text only, 64 PRs), and a cancelled epic,
which `Task:` cannot name. The issue cites each rule's source lines at
`48104f48b` and shows that the binding refusal depends on unrelated
history after the landing, not on the edit. ADR-0084 on this line
(TSK-278) covers one task record per PR and only its criteria and
acceptance blocks, with the `review` field frozen. The project leaves
closed records unchanged and registers the workaround.

Outcome: **one reviewed pull request can change only the wording of any
number of closed task and epic records, across epics, standalone tasks
and cancelled epics, while `codeflow ci` proves that every status,
criterion id, tag, criterion outcome, reviewed commit, waiver commit and
superseded-block count is unchanged and prints a per-record wording
delta for the reviewer; such a record is not rebound, not read as
reopened and not judged as a criteria change.**

Decisions recorded here, from the issue's suggested fix:

- **Class.** A planning-records-only range on a `plan/` branch whose body
  declares the class with one `Records: editorial` line beside
  `Task: TSK-NNN`, the cleanup task, so the `Task:` line keeps one
  meaning. The cleanup task is an ordinary task (standalone or in an
  epic) whose own record may be in the range.
- **What CI proves per changed record,** against the merge-base copy:
  same path, kind and status; frontmatter identical except the
  annotation ADR-0084 defines; same criteria ids, order and tags; same
  number of active and superseded acceptance blocks; in each block the
  same `reviewed`, every criterion outcome, every waiver sha, the journey
  outcome and the verdict. Prose sections, criteria text, block evidence
  and notes text, a superseded block's `reason` and `- reopened:` lines
  may change. A `review` field may change only when the pull request
  records the original as ADR-0084's digest does.
- **Exemptions.** A record that passes these checks is not rebound, not
  read as reopened and not judged under `work.criteria_frozen`; each
  prints a wording delta as a note. A record that fails any check gets
  today's refusal, naming the field that changed.
- **Remedy text.** The waiver clause leaves the binding remedy unless
  the refused block holds a `waived` result, and a wording edit is
  pointed at this class.
- The decision extends ADR-0084 and is recorded as a new ADR drafted in
  this task's PR (Tier-3: a CI class that exempts closed records from
  three checks).

Non-goals: changing any result or outcome through this class; the
single-record redaction of ADR-0084 (unchanged); cancelling or
reopening a task.

Added by the EPC-022 amendment of 2026-10-22 under the operator's
decisions of 2026-10-18 and 2026-10-22 (an adopter workaround, and a
project-management change, belong in 3.2.0).

## Acceptance Criteria

- AC-1 The issue's minimal reproduction (a landed standalone task, a later direct commit on the target, then a `plan/` branch that rewords a Description sentence and an acceptance evidence phrase) shall pass `codeflow ci` with `Records: editorial` and `Task: <cleanup task>`, with a wording delta note for the record and no binding, reopen or criteria refusal; evidence: a CLI fixture, failing before the change. (serves EPC-022 AC-107)
- AC-2 Each variation in the issue shall pass under the class: criteria text of an epic task, a superseded block's `reason`, a `- reopened:` line, records of two epics in one range, and a cancelled epic's records; evidence: one fixture per variation. (serves EPC-022 AC-107)
- AC-3 A range under the class that changes a status, a criterion id or tag, a criterion outcome, a `reviewed` sha, a waiver sha, the journey outcome, the verdict, the block count, or a path outside planning records shall be refused naming the field; evidence: one negative fixture per field. (serves EPC-022 AC-107)
- AC-4 A `review` field change shall be accepted only with the original recorded as ADR-0084 records it; without the class line a wording range shall get today's verdict unchanged; evidence: fixtures for both.
- AC-5 The binding remedy shall mention a waiver only when the refused block holds a `waived` result, and a refused wording edit shall be pointed at the editorial class; evidence: the remedy tests.
- AC-6 The ADR shall state the class, what is proved, what is exempted and why the binding is not rejudged; `codeflow validate --docs` shall pass; evidence: the ADR and the validate output.
- AC-7 (journey) With the installed build in a scratch adopter project with closed records of three kinds (epic task, standalone task, task of a cancelled epic), one `plan/` pull request rewording all three shall pass `codeflow ci` and pre-push, and the same range with one criterion outcome changed shall be refused; evidence: the journey output.
