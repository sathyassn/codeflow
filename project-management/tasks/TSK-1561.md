# TSK-1561: The guard reads inline code for Perl, Ruby, PowerShell and awk by an allowlist

## Description

Source: coord/catalog's request to coord/records on 2026-11-19 (21:3x), on the Director's ruling of 21:31. Filed by coord/records. The review named below was not read by coord/records; its findings are as coord/catalog reported them.

TSK-1476 ships allowlist inline-code scanners for Python and Node only. Inline code for Perl, Ruby, PowerShell and awk stays on main's inert-only subset, so those four interpreters get no allowlist reading. The input for this task is the Codex read of the earlier denylist scanners for them: `coordination/coordinators/capabilities/reviews/tsk1476-zl-codex.md`, findings F1 to F5.

Premise: before any change, read TSK-1476's Python and Node scanners as they landed (their shape, tests and limits), read findings F1 to F5, and list for each of the four interpreters which inline-code forms the guard reads today and which it refuses. Do not run a payload; tests give strings only.

Non-goals: Python and Node (TSK-1476); a denylist scanner for any interpreter (F1 to F5 are why).

## Outcome

After this merges, the guard reads inline code for Perl, Ruby, PowerShell and awk by an allowlist of forms it can show are inert, in the same way it does for Python and Node, and refuses the rest.

## Deliverables

- the premise answers per interpreter, and a line saying how each of F1 to F5 is closed or why it does not apply to an allowlist
- one allowlist scanner per interpreter, following TSK-1476's shape
- guarded tests: each allowed form as an inert string, and refused forms still refused, fail-before at a tests-only commit
- the changelog fragment `changelog.d/TSK-1561.md`
