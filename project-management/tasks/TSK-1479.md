# TSK-1479: Agents fetch and push their own task branches; main, lines, tags and releases stay with the operator

## Description

Agents cannot fetch from or push to the project's remote today. The exec guard judges each program a Git transport call starts as a command of its own, and the configured GitHub CLI credential helper, `gh auth git-credential`, matches the account rule. That rule exists to stop an agent reading the GitHub token itself. In a fetch or push, Git starts the helper and reads the token over a pipe, so the rule's subject does not fit this case. This task admits two closed command forms: a fetch from `origin`, and a fast-forward push of one work branch to `origin`. On an admitted line only, the account finding is skipped for that exact helper body. Every other check on that body, and every other line, stays as today.

Decision: D1, by the operator on 2026-11-12 at about 10:36. Agents may fetch, and push unprotected task branches; `main`, integration lines, tags and releases stay operator-only.

Identity: agents act on GitHub through the agent GitHub App that TSK-1348 creates, by the operator's decision of 2026-11-05. The configured GitHub CLI helper serves the token a session mints. This task adds no identity of its own, and its admission is the same whichever token the helper serves. Until agent sessions use the App's token, tag and line creation rest on this guard alone.

No policy value changes. `security.outward_actions` is one level for publishing, releases, tag pushes and account changes, so lowering it would stop refusing all of them. The admission is a guard change, and the operator's step is installing the fixed binary.

The forms:

- Fetch: `git [-C <plain path>] fetch [-q|--quiet|-p|--prune] [origin [<branch>...]]`.
- Push: `git [-C <plain path>] push [-u|--set-upstream] [-q] origin <src>:refs/heads/<name>`, where `<src>` is a hex id, `HEAD` or a plain branch name. `git push [-u] origin HEAD` and `git push origin <name>` are admitted only when `remote.origin.push` is unset, the current branch is that admitted name, and no local tag has the name.
- With `-C`, the target repository's configuration and landed policy are the ones read.
- The line holds only plain word characters, blanks and, for the push refspec, `:`. It is one command, with no assignment, launcher, quote or redirection.

Admitted branch names are those under a work-branch prefix in the landed policy's `git.branch_prefixes`, read at the default branch and never from the pushed branch or the working tree. Refused even under a listed prefix: a name matching `git.protected_branches`, `integration/**`, `main`, `master`, a release or tag pattern, and `codeflow/registry`. Protection is proven by name, without the network; a branch the forge protects still rejects the push on the forge side.

Non-goals:

- `git pull`, which stays refused.
- Rewriting a pushed branch. `--force-with-lease` stays refused for agents; `.codeflow/rules/git-rules.md` line 83 is not changed, and agents keep using the operator's path after a rewrite.
- Pushing `main`, integration lines, tags or releases, or using any remote other than `origin`.
- The forge's own rules, which TSK-1480 changes.

The operator has not yet chosen how agents authenticate to the forge. The criteria marked "(identity)" are written for the current setup, in which Git gets its GitHub credential from the GitHub CLI credential helper over HTTPS. That choice may change those criteria and no others.

Boundary with other work:

- TSK-1456 changes how the guards find the program word of a line. Until it lands, AC-7 uses the reading on `main`, and the builder says so; whichever of the two lands second aligns them.
- The pre-push and reference-transaction hooks are unchanged, so an admitted push still runs pre-push and `codeflow ci`.

## Outcome

After this merges and the operator installs the new binary, an agent can fetch from `origin` and push a fast-forward update of its own work branch to `origin`, while `main`, integration lines, tags, releases and other remotes stay refused.

## Findings

- exec-guard does not refuse a push of a line whose program word it cannot fill, such as a word that comes from a variable or a command substitution. That is the class of TSK-1404 ("Both guards refuse a program word they cannot fill"), which closes it for both guards; this task does not.
- AC-5's "landed or first-seen" URL has no source yet. No landed policy or project file holds a remote URL, and no first-seen store exists, so the admission compares `origin`'s one URL only with Git's own resolution of it. Replacing that URL with another repository on the same host keeps the admission. Binding it needs a new policy key or a new trust store, which waits for coord/catalog's decision.
