# TSK-1092: A refused interpreter that names an enforcement path says what it found and names the read route

## Description

Source: issue #431 (CodeFlow 3.1.1, filed 2026-10-30 by an adopter),
triaged the same day. A reviewer computing the digest of a managed
workflow with `python3 -I -c "...open('.github/workflows/codeflow-ci.yml','rb')..."`
was refused under `git.hook_integrity` with the remedy "the enforcement
hooks and their policy are not agent-editable", which speaks of an edit
the reviewer never tried. A read of `.codeflow/policy.json` the same way
got the same text.

The verdicts stay: an inline program cannot be shown to be read-only,
so the guard keeps failing closed. What changes is what the refusal says.
Read on the line tip `b7ae7c6a6`:

- a path literal in interpreter code is refused in
  `crates/codeflow-core/src/security/interpreter.rs:94-110`, with the
  edit-only `HOOK_INTEGRITY` remedy (`crates/codeflow-core/src/remedy.rs:457`);
- an interpreter argument naming an enforcement path is refused with
  TSK-302's `INTERPRETER_ARGUMENT` remedy (`remedy.rs:461`), which names
  read routes but speaks only of arguments.

So the same kind of read gets two remedies, one of which names no read
route. With TSK-302 landed, a path given as a script argument is refused
too, so the read routes left are a plain reader (`cat`, `jq`, `grep`,
`shasum`, `git show <ref>:<path>`) and a redirect into the program's
stdin, where the shell opens the file read-only.

Non-goals: judging an obvious read in code as a read (the issue's second
option, which a later reopen of the path defeats); any verdict change.

## Outcome

After this merges, an agent refused for naming an enforcement path in an interpreter is told whether the code or an argument named it and how to read the file instead.

## Deliverables

- the refusal texts: `crates/codeflow-core/src/security/interpreter.rs`
- the remedies: `crates/codeflow-core/src/remedy.rs`
- tests: unit tests beside the changed code, guard tests in `crates/codeflow-cli/tests/hooks_cli/`, and a `remedy_clearing` entry in `crates/codeflow-cli/tests/remedy_clearing/`
- docs: the read route in `docs/troubleshooting.md`
- release note: `changelog.d/TSK-1092.md`

## Acceptance Criteria

- AC-1 Every `git.hook_integrity` refusal of an interpreter shall say whether its code or an argument named the enforcement path, and its remedy shall name the read routes (`cat`, `jq`, `grep`, `shasum`, `git show <ref>:<path>`, a redirect into the program's stdin) and shall not describe the line as an edit; evidence: guard tests for a path in `-c` code and for a path as an argument, whose remedy text names no read route before the change for the code case and names them after. (serves EPC-022 AC-173)
- AC-2 The verdicts shall be unchanged: the issue's inline read and `pathlib` forms, a script argument and a `node -e` form naming an enforcement path refuse; a stdin redirect, a `cat` pipe into the program, `shasum` and the same programs naming `README.md` allow; evidence: a table test over these lines, passing before and after, and a `remedy_clearing` entry that follows the printed read route and sees the refusal clear. (serves EPC-022 AC-173)
- AC-3 `docs/troubleshooting.md` shall give the read route for an enforcement file; evidence: the doc diff and `codeflow validate --docs`.
