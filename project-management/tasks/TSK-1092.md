# TSK-1092: A refused interpreter that names an enforcement path says what it found and names the read route

## Description

Source: issue #431 (CodeFlow 3.1.1, filed 2026-10-30 by an adopter),
triaged the same day. A reviewer computing the digest of a managed
workflow with `python3 -I -c "...open('.github/workflows/codeflow-ci.yml','rb')..."`
was refused under `git.hook_integrity` with the remedy "the enforcement
hooks and their policy are not agent-editable", which speaks of an edit
the reviewer never tried. A read of `.codeflow/policy.json` the same way
got the same text.

The verdicts stay: an inline program cannot be shown to be read-only,
so the guard keeps failing closed. What changes is what the refusal says.
Read on the line tip `b7ae7c6a6`, whose binary already differs from
3.1.1 here (TSK-302 landed):

- `interpreter.rs` runs TSK-302's argument reader first
  (`crates/codeflow-core/src/security/interpreter.rs:38`,
  `arguments::evaluate`), which reports every word after the interpreter,
  a `-c` code string included, as "an interpreter argument `<path>` may
  reach `repository enforcement files`" with the `INTERPRETER_ARGUMENT`
  remedy (`crates/codeflow-core/src/security/arguments.rs:197`,
  `crates/codeflow-core/src/remedy.rs:461`), which names `cat`, `jq`,
  `grep` and a stdin redirect.
- The broader literal scan that follows
  (`interpreter.rs:94-110`) reports "interpreter code names the
  enforcement path" with the edit-only `HOOK_INTEGRITY` remedy
  (`remedy.rs:457`), but exec-guard keeps the first finding of equal
  strength for one rule (`crates/codeflow-core/src/hooks/exec_guard.rs:322`,
  `merge_strongest`), so on the line the argument finding is the one
  printed. The issue's digest command, fed to the line binary on stdin
  and never run, prints the argument text and the read routes.
- 3.1.1, which the issue ran, has no argument reader for this case and
  prints the code finding with the edit-only remedy.

So the line's defect is attribution: a path inside `-c` code is called
an argument, and the edit-only text is still reachable wherever the
argument reader does not fire first. The read routes are a plain reader
(`cat`, `jq`, `grep`, `shasum`, `git show <ref>:<path>`) and a redirect
into the program's stdin, where the shell opens the file read-only.

Non-goals: judging an obvious read in code as a read (the issue's second
option, which a later reopen of the path defeats); any verdict change.

## Outcome

After this merges, an agent refused for naming an enforcement path in an interpreter is told whether the code or an argument named it and how to read the file instead.

## Deliverables

- the refusal texts and their attribution: `crates/codeflow-core/src/security/arguments.rs` and `crates/codeflow-core/src/security/interpreter.rs`, and the finding merge in `crates/codeflow-core/src/hooks/exec_guard.rs` if attribution needs it
- the remedies: `crates/codeflow-core/src/remedy.rs`
- tests: unit tests beside the changed code, guard tests in `crates/codeflow-cli/tests/hooks_cli/`, and a `remedy_clearing` entry in `crates/codeflow-cli/tests/remedy_clearing/`
- docs: the read route in `docs/troubleshooting.md`
- release note: `changelog.d/TSK-1092.md`

## Acceptance Criteria

- AC-1 Every `git.hook_integrity` refusal of an interpreter shall say whether its code or an argument named the enforcement path, and its remedy shall name the read routes (`cat`, `jq`, `grep`, `shasum`, `git show <ref>:<path>`, a redirect into the program's stdin) and shall not describe the line as an edit; evidence: guard tests for a path in `-c` or `-e` code, which the line binary reports as "an interpreter argument" before the change and as code after, for a path given as a script argument, reported as an argument before and after, and for a case where only the literal scan fires, whose edit-only remedy is replaced; the existing read routes stay in every case. (serves EPC-022 AC-173)
- AC-2 The verdicts shall be unchanged: the issue's inline read and `pathlib` forms, a script argument and a `node -e` form naming an enforcement path refuse; a stdin redirect, a `cat` pipe into the program, `shasum` and the same programs naming `README.md` allow; evidence: a table test over these lines, passing before and after, and a `remedy_clearing` entry that follows the printed read route and sees the refusal clear. (serves EPC-022 AC-173)
- AC-3 `docs/troubleshooting.md` shall give the read route for an enforcement file; evidence: the doc diff and `codeflow validate --docs`.
