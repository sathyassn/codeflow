# TSK-221: Task and epic records name their deliverables and where they go

## Description

A task or epic record can pass `codeflow validate --docs` and review without
saying what the work produces or where it goes, because the templates have no
place for it (sathyassn/codeflow#40). In an adopting monorepo a 53-task
breakdown passed two reviews with 16 tasks naming no output or home and four
homes the agreed target tree had removed. This task gives the task template a
`## Deliverables` section after Description, asks the epic template's
"Affected surfaces and interfaces" for the repository homes its tasks write,
adds a deliverables and homes check to the cf-method clarity checklist that
`cf-plan` applies, and adds one `validate --docs` warning for an open task
that names neither a deliverable nor a path. The warning never blocks and
never reads complete or cancelled records. Non-goal: requiring the section,
or checking that a named home exists.

- AC-1 When an adopter allocates a task with `codeflow task new`, the record
  shall carry a `## Deliverables` section after Description that asks for
  each output and its home as a path in the project's structure, and for a
  home not known yet to be marked provisional with what decides it; evidence:
  the template contract test and a `task new` record in the remedy test.
- AC-2 When an epic is allocated, its "Affected surfaces and interfaces"
  guidance shall ask for the repository homes the epic's tasks write, or a
  pointer to the project's structure authority; evidence: the template
  contract test.
- AC-3 When `cf-plan` materializes records, the cf-method clarity checklist it
  applies shall require every task to name its deliverables and homes,
  checked against the project's structure authority where one exists;
  evidence: the contract test, and `manifest_consistency` for the mirrors.
- AC-4 (journey) When `codeflow validate --docs` runs on a project with an
  open task (todo, blocked or in progress) that has no filled
  `## Deliverables` section and no path in its Description, it shall print a
  warning that names the record and the edit that clears it, and still exit
  0; it shall print none for a task with a filled section, for one with a
  path in its Description, and for a complete or cancelled task; evidence:
  unit tests in `validate/mod.rs` and `clears_task_deliverables` in
  `remedy_clearing`.
- AC-5 When `codeflow validate --docs` runs on this repository, it shall exit
  0 and print no new warning for a complete or cancelled record, and the
  installed copies, the baseline and the manifest shall match the assets;
  evidence: `validate --docs` before and after, `manifest_consistency` and
  `repository_update_noop`.
