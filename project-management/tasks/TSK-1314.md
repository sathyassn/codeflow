# TSK-1314: Each line's daily Windows run executes under that line's own ref

## Description

TSK-1242's daily run makes each line's code run with `github.ref` set to main. Its patch stops the cache actions saving there, but line code might still take the job's cache token from the runner and write under main, so a line could write what main's runs later restore. The token technique is unproved here and rests on public research.

Threat closed: restores in the verdict jobs trust main's cache scope, and TSK-1242's daily run opens that window once the line reaches main. Two restores are exposed. Dependency restore through `Swatinem/rust-cache` is one. The other is the binary restore in PR 528: `actions/cache` extracts with `tar -P` before verification runs, so a crafted entry can write files before any check. PR 528 therefore depends on this task. Because the token technique is unproved, that ordering is a precaution against a write nobody has shown, and it is required all the same.

Source: the Director's rulings of 2026-11-03, including the one at 21:34 that this task is required before the EPC-022 line goes to main; findings F1 and F2 of `coordination/coordinators/parallel/reviews/tsk1240-design-fable.md`. Non-goal: changing what the daily run covers, which is TSK-1242.

## Outcome

After this merges, each line's daily Windows run executes under the line's own ref, so a maintainer can trust that nothing a line runs there writes to main's cache.

## Deliverables

- the workflow change: `windows-daily-run.yml`, by operator script
- the design choice and the statement that the token technique is unproved: this record's `## Findings` section

## Findings

- The token technique is unproved. A Worker's response was stopped by a safety classifier during read-only inspection, trigger unknown, and nothing was built or run. The Director withdrew the hosted proof of the token technique on 2026-11-03. Nobody retries, rewords or re-delegates that probe.
- AC-1 holds without that proof by design: the scheduled job under main only dispatches one run per line at that line's ref, so no line code runs under main's ref, whether or not the token technique works.
- PR 528 depends on this task: its binary restore extracts before verification, so it relies on no line being able to write main's cache scope. Whether a line can is unproved, so the ordering is a precaution, and it holds.
- Design: the scheduled job under main resolves the sources and starts one run per line at that line's ref. A reader on main credits a run only from GitHub's record: workflow path, event, branch, exact head SHA, conclusion and every job, at a commit whose `windows-daily-run.yml` has the hash of main's copy recorded at the request. Scripts: `coordination/scripts/operator/apply-tsk1314-daily-dispatch.sh`.
- A line's own scripts can still make its steps pass, as in every push run. A daily result is never merge evidence.
- A line left out is not green: it has its own row in the verdict's `lines` with `result: no-evidence` and `left_out: true`, the overall result is computed over the lines started or skipped, both summaries say "left out, no daily evidence", and nothing reads that overall pass as a daily verdict for the line, including TSK-1242's reduced tier, which reads nothing from the daily run.
- Known limit: the reader's expected job names come from main's script at verdict time, so a change on main that renames the runner's jobs between 06:23 and 12:23 gives one red day, which clears the next day.
- Cost: one full run measures a median 168.9 Windows job minutes over 24 green line push runs (150.3 to 180.0). Before: 5 refs daily, 845 minutes per day, calculated. After: 2.0 runs per day, 338 minutes per day, from a replay of 10-28 to 11-03 assuming every run passes; it cannot be measured until main. The route itself adds one short Ubuntu job a day and is not materially costlier. This replaces the estimate of about 1100 weighted partition minutes.
- A line must carry main's runner to get a daily run, so other lines get none until they merge main in, and each is named as left out until then. Line pushes still run every partition.
