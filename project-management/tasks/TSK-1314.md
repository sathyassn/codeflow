# TSK-1314: Each line's daily Windows run executes under that line's own ref

## Description

TSK-1242's daily run makes each line's code run with `github.ref` set to main. Its patch stops the cache actions saving there, but line code might still take the job's cache token from the runner and write under main, so a line could write what main's runs later restore. The token technique comes only from a Worker's memory and is untested here. Threat closed: dependency restore in the verdict jobs trusts main's cache scope, so a line's daily run under main could write what those jobs restore. PR 528 does not rely on this task for soundness, because any binary restore there is verified against provenance or dropped; this task stands on the dependency-restore residual and still reaches main in 4.0.0. Source: the Director's rulings of 2026-11-03, relayed by coord/ci, separate from TSK-1242's landing and required for 4.0.0. Non-goal: changing what the daily run covers, which is TSK-1242.

## Outcome

After this merges, each line's daily Windows run executes under the line's own ref, so a maintainer can trust that nothing a line runs there writes to main's cache.

## Deliverables

- the workflow change: `windows-daily-run.yml`, by operator script
- the proof and the design choice: this record's `## Findings` section

## Acceptance Criteria

- AC-1 Each line's daily run shall execute under that line's ref, with no write path to main's cache scope; evidence: the workflow diff, a workflow test that fails if a line's job runs under main's ref, and one hosted daily run per ref kind whose log shows the ref.
- AC-2 The builder shall prove the token technique on a scratch path, or the record shall state it as unproved and why AC-1 holds without that proof; evidence: the scratch run and its output in the Findings, or the statement.
- AC-3 The builder shall check whether a dispatch at the line's ref does this cheaply and record the result, with the job-minutes of that route against the current one; evidence: the Findings.
- AC-4 Any workflow change shall land through an operator script, and the record shall name it; evidence: the script path and the PR. Cross-lineage security review, as this is a trust boundary in CI.
