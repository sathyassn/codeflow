# TSK-1314: Each line's daily Windows run executes under that line's own ref

## Description

TSK-1242's daily run makes each line's code run with `github.ref` set to main. Its patch stops the cache actions saving there, but line code might still take the job's cache token from the runner and write under main, so a line could write what main's runs later restore. The token technique is unproved here and rests on public research. Threat closed: restores in the verdict jobs trust main's cache scope, so a line's daily run under main could write what those jobs restore, and TSK-1242's daily run opens that window once the line reaches main. Two restores are exposed. Dependency restore through `Swatinem/rust-cache` is one. The other is the binary restore in PR 528: `actions/cache` extracts with `tar -P` before verification runs, so a crafted entry can write files before any check, and PR 528 therefore lands after this task. Source: the Director's ruling of 2026-11-03, relayed by coord/ci, separate from TSK-1242's landing, and the Director's ruling of 21:34 that this task is required before the EPC-022 line goes to main; findings F1 and F2 of `coordination/coordinators/parallel/reviews/tsk1240-design-fable.md`. Non-goal: changing what the daily run covers, which is TSK-1242.

## Outcome

After this merges, each line's daily Windows run executes under the line's own ref, so a maintainer can trust that nothing a line runs there writes to main's cache.

## Deliverables

- the workflow change: `windows-daily-run.yml`, by operator script
- the proof and the design choice: this record's `## Findings` section

## Acceptance Criteria

- AC-1 Each line's daily run shall execute under that line's ref, with no write path to main's cache scope; evidence: the workflow diff, a workflow test that fails if any run under main's ref executes code from another ref, and one hosted daily run per ref kind whose log shows the ref.
- AC-2 The builder shall prove or disprove the token write with a hosted run on a scratch path; evidence: the run link and its output in the Findings, whichever way it comes out.
- AC-3 The builder shall check whether a dispatch at the line's ref does this cheaply and record the result, with the job-minutes of that route against the current one; evidence: the Findings.
- AC-4 Any workflow change shall land through an operator script, and the record shall name it; evidence: the script path and the PR. Cross-lineage security review, as this is a trust boundary in CI.
