# TSK-1062: The Windows killed-gate test waits on a signal, not a fixed deadline

## Description

Source: the line's own push run at `dc9ec266d` (run 40750765706, job
"windows tests (12 of 12)", job id 123053893714). The test
`codeflow-core testing::runner::tests::a_killed_gate_ends_its_target_tree_on_windows`
failed as `FAIL + LEAK [61.585s]`, panicking at
`crates/codeflow-core/src/testing/runner/mod.rs:1960` with "the target
recorded its pid". The same test passed on the line's earlier run at
`e937da4ee`. Nine other tests in the same shard were reported slow
(over 60 seconds), so the runner was loaded.

The test (TSK-142 AC-3) spawns its own test binary as a gate
(`windows_gate_helper`, `:1905`), whose target runs `cmd.exe`, then
`powershell`, which writes its pid to `pid.txt`. The test polls for that
file 1,200 times at 50 ms (`:1950-1960`), a fixed 60-second deadline,
then kills the gate and checks the tree ended. Three things are not
known from the log, and each could produce the same panic:

- the helper's start, the gate's start and PowerShell's start were
  slower than 60 seconds on a loaded runner;
- the helper or its target failed early, which the test cannot see: the
  helper's stdout and stderr go to null and `run_target`'s result is
  discarded (`let _ =`, `:1913`);
- the pid file was written in a form the parse rejects.

The `LEAK` verdict also shows a second defect: when the wait panics,
the spawned gate and its target tree are left running, because the kill
happens only after the wait succeeds.

The fix: the test passes or fails for a stated cause on a slow runner,
never on an arbitrary deadline alone, and it never leaves its gate
running. Raising the deadline alone is not a fix.

Non-goals: changing what TSK-142 AC-3 proves (a killed gate ends its
target tree); the Windows partition balance (shard 5 of 12 hit the
30-minute limit on the first attempt of PR 392's run 40775926015), which is a separate
outcome.

## Outcome

After this merges, a maintainer reading a Windows run can trust that a failure of the killed-gate test names its cause, and that the test leaves no process behind.
