# TSK-1006: Every test-running target meets the coverage floor or records why not

## Description

Issue #299, filed against CodeFlow 3.1.1 (`48104f48b`). The quality
contract states an 80% aggregate production line floor wherever the stack
supports it, with exclusions only with an owner, reason and removal
condition (`cf-model-orchestrator` `resources/quality/coverage.md`). The
test engine enforces a floor only when a target carries its own
`coverage` block with at least one rule, accepts any minimum, evaluates
it only in `full` mode, and never applies `defaults.coverage`
(`crates/codeflow-core/src/testing/config/mod.rs`, parsed but read only
by the glob check), although the shipped schema says the defaults are
"applied when targets omit them". The changed-files scope is implemented
but refused on every target. The issue proposes strict defaults with
recorded exceptions; that changes designed behaviour, so it is a feature
of this epic.

Outcome: **every enabled test-executing target resolves an aggregate
coverage floor of at least 80, from its own rules or the defaults, or
carries a recorded exemption; `essential` runs evaluate it, a changed-files
floor works against the gate's base, and every exclusion names its
reason, owner and removal condition.**

Rules:

- `defaults.coverage` is merged into each target before collection and
  validation. The scaffolded default is one `global` rule at 80.
- An aggregate minimum below 80, and every exemption, exclusion and
  per-file exception, is an entry in TSK-424's register with reason,
  owner and expiry; plain `exclude` strings are read with a warning for
  one release.
- `essential` evaluates the floors for the targets it runs; `quick` stays
  format and lint. If `essential` cost is rejected in review, the PR
  instead names one supported builder route and the skills cite it, as
  the issue allows.
- The `changed_files` scope works against `--since <ref>` or the landing
  candidate's merge base and is documented as whole-file; changed-line
  coverage is a later step, not this task.
- Existing projects get the checks report-only first; `block` comes
  through a reviewed policy change, and new scaffolds write it on.

Non-goals: changed-line coverage; CodeFlow's own coverage evidence per
landing candidate (TSK-369 in EPC-023).

## Deliverables

- defaults resolution, the floor check and the `essential` evaluation: `crates/codeflow-core/src/testing/config/mod.rs`, `crates/codeflow-core/src/testing/gate.rs`, `crates/codeflow-core/src/testing/validation.rs`, `crates/codeflow-core/src/testing/threshold/mod.rs`
- the `changed_files` scope with a base: `crates/codeflow-core/src/testing/gate.rs`, `crates/codeflow-cli/src/cmd/test.rs`
- schema and templates: `assets/base/testing/test-config.schema.json`, `assets/base/testing/templates/`, and `codeflow init` stack detection
- the doctor finding: `crates/codeflow-core/src/doctor/` (`--check test-config`)
- the activation key (provisional `testing.coverage_floor`): `crates/codeflow-core/src/hooks/policy_schema.rs`
- tests: unit tests beside the changed code and `crates/codeflow-cli/tests/`
- docs: `docs/test-gate.md`, `docs/policy-reference.md`, and the builder route in `cf-develop` if AC-4's alternative is taken (mirrored skills)
- release note: `changelog.d/TSK-1006.md`

## Acceptance Criteria

- AC-1 When a target omits its own `coverage` block, the gate shall apply `defaults.coverage`, and a project with an empty default and a test-executing target with no block and no exemption shall be refused before any target runs; evidence: config tests for both cases. (serves EPC-024 AC-13)
- AC-2 A rule set whose aggregate minimum is below 80 without a register entry shall be refused; per-file exceptions beneath an aggregate floor that holds shall keep working; evidence: validation tests. (serves EPC-024 AC-13)
- AC-3 Every `exclude` glob, per-file exception and target exemption shall carry reason, owner and expiry through the register; a plain `exclude` string shall be read with a warning for one release; evidence: validation tests.
- AC-4 An `essential` run shall evaluate the coverage floor of every target it runs and fail on a shortfall, or the PR shall name the one supported builder route and `cf-develop` shall cite it; evidence: a gate test, or the skill diff and its test.
- AC-5 A `changed_files` rule shall evaluate the whole-file coverage of each file changed since `--since <ref>` or the landing candidate's merge base, and the docs shall say it is whole-file; evidence: a gate test with a base.
- AC-6 With the activation key unset, an existing project shall see the findings reported with its verdict unchanged, `codeflow update` and `codeflow doctor --check test-config` shall list them with the exemption syntax, and at `block` they shall fail; evidence: tests at each level.
- AC-7 (journey) With the installed build, a fresh `codeflow init --standard` project shall carry the 80 `global` default, fail its full gate on a planted untested module, and pass after a test is added or a register entry is recorded; evidence: the journey output. (serves EPC-024 AC-13)
