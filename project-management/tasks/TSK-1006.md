# TSK-1006: Every test-running target meets the coverage floor or records why not

## Description

Issue #299, filed against CodeFlow 3.1.1 (`48104f48b`). The quality
contract states an 80% aggregate production line floor wherever the stack
supports it, with exclusions only with an owner, reason and removal
condition (`cf-model-orchestrator` `resources/quality/coverage.md`). The
test engine enforces a floor only when a target carries its own
`coverage` block with at least one rule, accepts any minimum, evaluates
it only in `full` mode, and never applies `defaults.coverage`
(`crates/codeflow-core/src/testing/config/mod.rs`, parsed but read only
by the glob check), although the shipped schema says the defaults are
"applied when targets omit them". The changed-files scope is implemented
but refused on every target. The issue's defect half, defaults the
schema promises and the engine ignores, is TSK-1014 in EPC-022 (4.0.0),
placed there by the Codex review of PR 343. This task is the feature
half: strict defaults with recorded exceptions, which change designed
behaviour.

Outcome: **every enabled test-executing target resolves an aggregate
coverage floor of at least 80, from its own rules or the defaults, or
carries a recorded exemption; `essential` runs evaluate it, a changed-files
floor works against the gate's base, and every exclusion names its
reason, owner and removal condition.**

Rules:

- TSK-1014 makes `defaults.coverage` apply to targets that set no rules;
  this task makes a floor mandatory. The scaffolded default is one
  `global` rule at 80.
- An aggregate minimum below 80, and every exemption, exclusion and
  per-file exception, is an entry in TSK-424's register with reason,
  owner and expiry; plain `exclude` strings are read with a warning for
  one release.
- `essential` evaluates the floors for the targets it runs; `quick` stays
  format and lint. If `essential` cost is rejected in review, the PR
  instead names one supported builder route and the skills cite it, as
  the issue allows.
- The `changed_files` scope works against `--since <ref>` or the landing
  candidate's merge base and is documented as whole-file; changed-line
  coverage is a later step, not this task.
- Existing projects get the checks report-only first; `block` comes
  through a reviewed policy change, and new scaffolds write it on.

Non-goals: changed-line coverage; CodeFlow's own coverage evidence per
landing candidate (TSK-369 in EPC-023).

Amended 2026-10-27 by the quality asks amendment (the operator's D2
ask): "every test-running target" explicitly includes project tooling,
meaning the scripts, build helpers, code generators, release and CI
helpers and hook scripts a repository runs to build, check or release
itself. Tooling code is held to the floor like product code; only
generated, vendored, fixture and test code may be excluded, through the
register. TSK-1031 (EPC-022, 4.0.0) states this in the shipped
instructions and has `cf-stack` wire a tooling test target; this task
enforces it, because the default floor and its exemptions need TSK-424.
First-pass survey (planning, 2026-10-27, line tip `5f2fe3827`): the
nine test-config templates under `assets/base/testing/templates/` have
no tooling target; `codeflow doctor --check test-config` does not look
for code no target covers; this repository runs eight `scripts/test_*.py`
files with no coverage (`.codeflow/test-config.json:299`), and three
scripts have no test file.
