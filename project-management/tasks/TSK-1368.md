# TSK-1368: The policy verdict job keeps the required name commit standards

## Description

TSK-336 (commit 677c13037, which reached `main` through PR 607 on 2026-11-05) renamed the policy verdict job from `commit standards` to `trusted: commit standards`. Both live rulesets, "Integration hosted gates" and the one on `main`, still require `commit standards`, so since that merge no pull request can satisfy them and every line landing is blocked; PR 667's merge was refused for it.

The operator asked on 2026-11-06 (10:5x, relayed by the Director): "can we keep the old name without affecting the consuming projects?" The answer was yes, since the rename was never released. Decision: keep the check name `commit standards`; the rulesets do not change. Recorded in the workspace repository's `RELEASE-PLAN.md` and `coordination/HANDOFF-2026-10-27.md` section 5 (commit 9ce5d1ed).

This task restores the job name and every place that names it. Out of scope: the job's `pull_request_target` trigger, its default-branch checkout and its other behaviour from TSK-336 stay as they are, and no ruleset changes. The `trusted: release impact` job keeps its name: the rulesets' `release impact` check is posted by `codeflow-release.yml` (`:33`), which the rename did not touch.

## Outcome

After this merges, pull requests into `main` and the integration lines get the required `commit standards` verdict again, so the operator's rulesets admit them unchanged.
