# TSK-1029: The Claude compaction point is a documented project choice

## Description

Issue #358 (CodeFlow 3.1.1). Every scaffolded `.claude/settings.json` sets
`CLAUDE_CODE_AUTO_COMPACT_WINDOW=1000000` and
`CLAUDE_AUTOCOMPACT_PCT_OVERRIDE=50`, so sessions compact at about 500K
tokens, and the shared value sits above each contributor's own settings.
The adopter reports long orchestrator sessions running near that point,
and is measuring 50, 40, 35 and 30 percent on cost per session and on
whether a session still knows its task, branch and next step after
compaction.

Read on the line tip `7172229aa`:

- the presets set both keys (`assets/base/settings/default.json:3-6`,
  `acceptEdits.json:3-6`, `bypass-sandboxed.json:3-6`), shipped by
  `3adda9b44` (2026-10-03);
- the issue's "undocumented" claim holds only in part.
  `cf-customize/references/claude-context-policy.md` states the values,
  the thresholds (about 500K against Claude Code's default of about 967K
  on a 1M-window model; about 100K on a session limited to 200K), how to
  change or opt out, and the per-person override in
  `.claude/settings.local.json` (`:47-49`). It does not say why 50 percent
  was chosen or what it costs, and it is reachable only through
  `cf-customize`;
- unlike #351's keys, `env` has a baseline-guarded merge
  (`crates/codeflow-core/src/scaffold/settings_merge.rs:227-290`): a
  project's changed or deleted value survives `codeflow update`;
- the qualification kit depends on the local file outranking the shared
  one: it pins the percentage at 100 in `.claude/settings.local.json` for
  its compaction fixtures
  (`cf-evaluate-model/scripts/eval_kit.py:396-403`).

Token-cost tradeoff, stated for the record:

- every turn sends the whole context as input; with prompt caching most of
  it is billed as cache reads, but per-turn input still grows with the
  context, so a turn near 500K carries about 3.3 times the input of a turn
  near 150K;
- without these keys a 1M-window session compacts near 967K, so the
  shipped pin roughly halves the peak against the harness default; it is
  cheaper than shipping nothing, and dropping it would raise cost for
  everyone who sets no value of their own;
- a lower point (30 to 40 percent, about 300K to 400K) cuts per-turn input
  further but compacts more often; each compaction reads the full context
  once and writes a summary, and detail the summary drops is lost. The
  orient digest that SessionStart prints after a compaction (ADR-0013)
  restores task, branch and next step from their durable homes, which
  limits that loss;
- some models price input above a size threshold at a higher rate; the
  current rate for the model in use is checked, not assumed (not verified
  here).

Outcome: **the compaction point is a project choice the docs explain, with
its cost and context tradeoff and the personal route, and the shipped
default is set from measured sessions.**

Proposed change:

- Keep the keys in the shared file. Unlike status line and effort, the
  compaction point is a team cost policy, it also applies to subagents,
  and the qualification kit relies on a known shared value.
- Move the explanation to where adopters see the keys: the posture docs
  and `cf-customize`, which asks the project for its compaction point
  with the tradeoff above and records the answer.
- Document the personal route (`.claude/settings.local.json`, and its
  per-checkout limit from TSK-1028's section).
- Set the default from evidence: the adopter's measurements on #358 and
  one measurement in this repository (tokens per session and post-compaction
  task recall at 50 and 35 percent). Changing the shipped default is the
  operator's decision; until it is made the default stays 50.

## Acceptance Criteria

- AC-1 The docs shall state why the shipped point was chosen, the per-turn cost and compaction-frequency tradeoff above, how the point interacts with a fresh session per phase and the post-compaction orient digest, and how a project and a person each change it; evidence: the doc diff. (serves EPC-022 AC-137)
- AC-2 `cf-customize` shall ask the project for its compaction point with that tradeoff, write the chosen values to the shared `env`, and leave them unchanged when the project keeps the default; evidence: a skill test or eval case and the rendered skill text.
- AC-3 The pull request shall carry a measurement in this repository of tokens per session and post-compaction recall of task, branch and next step at 50 and 35 percent, and the adopter's figures if posted on #358; evidence: the evidence note.
- AC-4 The shipped default shall be the value the operator chooses from AC-3's evidence, recorded with that evidence; a changed default shall reach installed projects only through update's existing `env` rule, which keeps a project's own values; evidence: the decision in the pull request and the preset diff, or a recorded no-change.
- AC-5 (journey) In a scratch adopter project, `cf-customize` shall set a chosen compaction point and a later `codeflow update` shall keep it; evidence: the journey output.
