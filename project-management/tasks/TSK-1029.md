# TSK-1029: The Claude compaction point is a documented project choice

## Description

Issue #358 (CodeFlow 3.1.1). Every scaffolded `.claude/settings.json` sets
`CLAUDE_CODE_AUTO_COMPACT_WINDOW=1000000` and
`CLAUDE_AUTOCOMPACT_PCT_OVERRIDE=50`, so sessions compact at about 500K
tokens, and the shared value sits above each contributor's own settings.
The adopter reports long orchestrator sessions running near that point,
and is measuring 50, 40, 35 and 30 percent on cost per session and on
whether a session still knows its task, branch and next step after
compaction.

Operator decision of 2026-10-27: 35 percent of the 1M window (compaction
at about 350K), replacing 50; the operator proposed it ("how about 35%
(350k)"). The value is revisited once the adopter's measurement lands.

Read on the line tip `7172229aa`:

- the presets set both keys (`assets/base/settings/default.json:3-6`,
  `acceptEdits.json:3-6`, `bypass-sandboxed.json:3-6`), shipped by
  `3adda9b44` (2026-10-03);
- the issue's "undocumented" claim holds only in part.
  `cf-customize/references/claude-context-policy.md` states the values,
  the thresholds (about 500K against Claude Code's default of about 967K
  on a 1M-window model; about 100K on a session limited to 200K), how to
  change or opt out, and the per-person override in
  `.claude/settings.local.json` (`:47-49`). It does not say why the value
  was chosen or what it costs, and it is reachable only through
  `cf-customize`;
- `codeflow update` keeps every `env` value a project has
  (`crates/codeflow-core/src/scaffold/settings_merge.rs:227-290`), so a
  changed shipped default reaches only fresh installs unless update learns
  to move a value that is exactly the old shipped one;
- the qualification kit pins the percentage at 100 in
  `.claude/settings.local.json` for its compaction fixtures
  (`cf-evaluate-model/scripts/eval_kit.py:396-403`), so it does not depend
  on the shared value.

Token-cost tradeoff, stated for the record:

- every turn sends the whole context as input; with prompt caching most of
  it is billed as cache reads, but per-turn input still grows with the
  context: a turn near 350K carries about 0.7 times the input of a turn
  near 500K, and about 2.3 times one near 150K;
- without these keys a 1M-window session compacts near 967K, so any pin
  lowers the peak against the harness default;
- a lower point compacts more often; each compaction reads the full
  context once and writes a summary, and detail the summary drops is
  lost. The orient digest that SessionStart prints after a compaction
  (ADR-0013) gives context and pointers to the durable records, and
  rereading those records recovers task, branch and next step, which
  limits that loss;
- the percentage also applies to sessions limited to 200K, which compact
  at about 70K with 35 percent;
- some models price input above a size threshold at a higher rate; the
  current rate for the model in use is checked, not assumed (not verified
  here).

Outcome: **scaffolded sessions compact at 35 percent of the 1M window, the
docs explain the cost and context tradeoff and where a project and a
person change it, and the value is revisited from the adopter's
measurement.**

The keys stay in the shared file: the compaction point is a team cost
policy and also applies to subagents.

Corrected during the build: AC-3 first gave the personal file a
per-checkout limit. Since Claude Code v2.1.211 a worktree session uses the
file at the main checkout's root, except outside git, with the repository
root at the home folder, on Windows, or under another owner (TSK-1028
corrected its AC-6 the same way), so AC-3 now asks where the file lives
for a worktree. The AC-4 revisit is TSK-1049 (EPC-023).

## Acceptance Criteria

- AC-1 A fresh `codeflow init` with each preset shall write `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` as `35` with the 1M window, and `codeflow update` shall move a project whose value is exactly the previously shipped `50`, proved by the recorded baseline, to `35`, while keeping any value the project chose; evidence: preset and settings-merge tests, failing before the change. (serves EPC-022 AC-137)
- AC-2 The docs shall state the tradeoff: per-turn cost grows with the context carried, compactions get more frequent as the threshold drops, the effect on sessions limited to 200K, how the point interacts with starting a fresh session per phase (a session that ends at a phase boundary may never reach the threshold, so the point matters most for long orchestrator sessions), and how the post-compaction orient digest limits lost state; evidence: the doc diff. (serves EPC-022 AC-137)
- AC-3 The docs shall say where a project changes the value (the shared `env`) and where a person overrides it (`.claude/settings.local.json`, and where that file lives for a worktree), and that update keeps both; evidence: the doc diff.
- AC-4 When the adopter's measurement of 50, 40, 35 and 30 percent is posted on #358, the value shall be revisited and the operator's decision recorded, as a change to the presets or a recorded no-change; until then 35 stands. This criterion is met in this task if the measurement lands before it closes, and otherwise by a follow-up named in its acceptance; evidence: the decision and its link.
- AC-5 (journey) In a scratch adopter project upgraded from 3.1.1 with the shipped `50`, `codeflow update` shall set `35`, and a project-chosen value and a personal `.claude/settings.local.json` value shall each survive a later update; evidence: the journey output.
