# TSK-1390: Git commands that write working-tree files cannot put other content on an enforcement path

## Description

Issue 633: git-guard let `git checkout <rev> -- <policy file>` overwrite a
worktree's enforcement file with an older copy. Since TSK-1002, main refuses
that spelling when the file is named, but the same overwrite still passes
through a whole-tree selection (`-- .`, `checkout-index -a`), Git pathspec
wildcards, an abbreviated `--worktree`, a two-step index plant, and the path
writers `stash apply`, `stash pop`, `read-tree -u`, `cherry-pick -n`,
`revert -n` and `git apply`. These commands leave HEAD in place, so the
planted file sits as an uncommitted change and rides into the next commit.
This task judges each such writer by the content it would put on an
enforcement path. git-guard reads the source (a revision, the index, a stash
or the picked commits) from the object store, compares it with HEAD's entry
for every enforcement path the selection can reach, and refuses when they
differ. It also judges `git am` by its patch paths, and `git reset --hard`,
`--keep` and `--merge` to a revision by that revision's content. Non-goal:
branch switches, `merge` (with `--squash` and `--no-commit`), `rebase`,
`pull` and committing `cherry-pick` and `revert` keep their verdict under
TSK-325 AC-7. The change narrows TSK-1002 AC-3, which allowed the `.`-rooted
forms; that record gets a dated note through planning PR 719.

## Outcome

After this merges, an agent session can no longer use a Git path writer to
put content other than HEAD's on an enforcement path in its own or another
worktree, and restoring HEAD's content or an ordinary file from any revision
still works.

- AC-1 When a Git command writes work-tree files without moving HEAD (`checkout` or `restore` of paths, `checkout-index`, `read-tree -u`, `stash apply`, `stash pop`, `stash branch`, `apply` without `--cached`, `cherry-pick -n`, `revert -n`), git-guard shall refuse it under `git.hook_integrity` when the content it could write on an enforcement path differs from HEAD's entry for that path (blob and mode, presence included). The source is read from the object store, read only: the named revision, the index, the stash commits, or the picked or reverted commits. A selection is read as Git reads it: `.`, a directory, a `*` that crosses `/` and matches leading dots, and the `-C` target. Evidence: path_writers unit tests and hooks_cli path_writers tests, one per verb, each failing at `7b76f5c4e`.
- AC-2 When every enforcement path the selection can reach would receive HEAD's content, the same commands shall pass: `git restore .` and `git checkout -- .` with a clean index, `git checkout main -- .` when main's enforcement files equal HEAD's, a restore of an ordinary file from any revision, and a stash that changes no enforcement path. Evidence: allowed controls in the same tests.
- AC-3 The guard shall fail closed. A selection it cannot read (pathspec magic, `--pathspec-from-file`, `--stdin`, a wildcard with an escape) is judged as the whole tree. A source it cannot establish refuses: an unknown option, a revision, stash or object it cannot read, a patch on stdin or one it cannot read, an unmerged index entry on an enforcement path, and `--git-dir`, `--work-tree`, a `-c` whose key is not one that only changes a program run for a person or how output looks (an include or a filter always counts), or a `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`, `GIT_OBJECT_DIRECTORY` or `GIT_ALTERNATE_OBJECT_DIRECTORIES` setting on the line, for a form that writes work-tree files; a form that writes none, such as `reset --soft`, keeps its verdict. Option abbreviations Git accepts (`--work`, `--sour=`) are read as Git reads them. Evidence: unit tests per form, failing before the change where the form passed.
- AC-4 `-p` and `--patch`, and pathspec magic, shall be judged by AC-1 whatever `git.discard_uncommitted` and `security.secret_reads` say. Evidence: hooks_cli tests with `discard_uncommitted: off` and `secret_reads: off`.
- AC-5 The two-step plant shall be refused at its work-tree step: an index-only write of an enforcement path (`restore --staged --source`, `reset <rev> -- <path>`, `update-index --cacheinfo`, `read-tree` without `-u`, `apply --cached`) followed by `checkout -- .`, `restore .` or `checkout-index -a -f`. Evidence: a test of each pair in a temporary repository, the second command failing before the change.
- AC-6 `git am` shall be refused when a patch it applies (from its mailbox files, or the session in progress for `--continue`, `--skip` and `--resolved`) touches an enforcement path, and when its mailbox comes from stdin; `git reset --hard`, `--keep` and `--merge` to a revision shall be refused when that revision's enforcement content differs from HEAD's. Evidence: unit tests with refused and allowed cases.
- AC-7 Branch switches (`switch`, `checkout <branch>`, `checkout -b`), `merge` (with `--squash` and `--no-commit`), `rebase`, `pull`, and committing `cherry-pick` and `revert` shall keep their current verdict, and docs/policy-reference.md shall state that limit with its reason: HEAD moves with the files, so any change is a commit in the pull request diff. Evidence: allowed controls and the doc diff.
- AC-8 The narrowing of TSK-1002 AC-3's `.`-rooted exemption shall live in this task's AC-1 and AC-2; TSK-1002 AC-3 keeps its text and gets a dated note pointing to them through planning PR 719, which lands with or before this task's pull request, and this pull request leaves TSK-1002's record unchanged. Reason (2026-11-08, `codeflow ci` lifecycle invariant `work.criteria_frozen`, ADR-0078): a task pull request amends only its own record. Evidence: the PR body naming PR 719, and no TSK-1002 change in the PR diff.
- AC-9 With the built binary, in a scratch repository with two worktrees, a session in one worktree shall be refused issue 633's reported command and each AC-1 form aimed at the other worktree through `git -C`, and shall still restore an ordinary file from an older revision there. Evidence: the hooks_cli two-worktree journey test and a manual run with the worktree's `target/debug/codeflow`. (journey)
