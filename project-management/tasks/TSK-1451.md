# TSK-1451: CodeFlow's own line pushes start no hosted run, and line PRs run short checks only

## Description

The operator ruled on 2026-11-11, about 20:05 EST, that no push to a line starts a hosted run, and the Director ruled that a pull request into a line runs the short checks only (ADR-0102). CodeFlow's own workflows still run on `integration/**` pushes, and the Linux gates and the reduced Windows tier still run on pull requests into lines. This task changes the push triggers of `codeflow-ci.yml`, `codeflow-registry.yml` and `codeflow-release.yml` and moves the Linux gates and Windows to the pull request into `main`. TSK-1445 (unit U13) cannot carry it: its outcome includes a push to `main` reusing its pull request's run under TSK-1444's conditions, and it builds on PR 620 (TSK-1321). TSK-1444 waits for TSK-1352, which waits for TSK-1396 on `main`. This change needs no other wait, so it lands first and alone, and TSK-1445 starts from what it leaves on `main`. Non-goal: the reuse of a pull request's run on a push to `main`, which TSK-1445 and TSK-1444 own.

This is in the named class of changes that prove themselves only on the default branch: it lands alone, with a revert branch prepared and reviewed first, and its proof (AC-5) is read on `main` after it lands.

Landing on its target (`main`, alone):

- Reachable: the new triggers for CodeFlow's own events.
- Inert: nothing.
- Other lines: not nothing: a line takes the change only when it merges `main`. A pre-rule line that takes it without TSK-1450's rule on `main` waits for tip verdicts that no longer come, so TSK-1450 goes first or in the same batch.

## Outcome

After this merges, a CodeFlow maintainer sees no hosted run on a push to any `integration/**` line, only commit standards, the secret scan and the security review on a pull request into a line, and the Linux gates and every Windows job only on the pull request into `main`.

## Deliverables

- the workflow triggers and line pull request jobs: `.github/workflows/codeflow-ci.yml`, `.github/workflows/codeflow-registry.yml`, `.github/workflows/codeflow-release.yml`
- the gate contract scripts that pin the trigger: `scripts/`, with the placement check `scripts/test_ci_placement.py`
- the revert branch: its SHA in the pull request body
- the first-run proof on `main`: this record's Closeout

## Acceptance Criteria

- AC-1 The `push` branches of `.github/workflows/codeflow-ci.yml` shall become `[main, master]`; the integration branches shall leave its concurrency expression and that expression's comment; the Linux gates and the reduced Windows tier shall no longer run on pull requests into lines; and the gate contract scripts that pin the trigger shall follow; evidence: the diff and `scripts/test_ci_placement.py`.
- AC-2 The `push` branches of `codeflow-registry.yml` shall become `[main, master]` and those of `codeflow-release.yml` shall become `[main]`, and no skipped `release impact` check run shall be left on a line commit; evidence: the diff.
- AC-3 No required check on `main` or a line shall be one that can pass by being skipped; evidence: the required sets read live at landing against the jobs each event now runs (TSK-1452 owns the ruleset writes).
- AC-4 A revert branch shall be prepared and reviewed before landing; evidence: its SHA in the pull request body.
- AC-5 On `main`, the first line push after landing shall show no hosted run, and the first line pull request shall show only the short checks; evidence: the run lists.
- AC-6 Return condition: CodeFlow's own triggers move to the epic placement when TSK-1445 lands, which starts from this task's change, and `codeflow update` reconciles the managed copies once TSK-1352 ships; until then no line push run returns without an operator ruling; evidence: TSK-1445's `depends_on` and Edges name this task, and this task's follow-up entry.
- AC-7 The change shall have a cross-lineage review with the `cf-security-reviewer` checklist, since it changes which events run trusted checks; evidence: the review row and its findings.
