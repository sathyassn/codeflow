# TSK-1451: CodeFlow's own line pushes start no hosted run, and line PRs run short checks only

## Description

The operator ruled on 2026-11-11, about 20:05 EST, that no push to a line starts a hosted run, and the Director ruled that a pull request into a line runs the short checks only until EPC-055's line gate ships (both recorded in ADR-0102, which is proposed). CodeFlow's own workflows still run on `integration/**` pushes, and the Linux gates and the reduced Windows tier still run on pull requests into lines. This task changes the push triggers of `codeflow-ci.yml`, `codeflow-registry.yml` and `codeflow-release.yml` and moves the Linux gates and Windows to the pull request into `main`. The operator also ruled that `main`'s heavy checks are relaxed for now (TSK-1452's temporary items), so the same workflow change runs the Linux gates, the Windows jobs and both verdicts only on a daily schedule on `main`'s tip and on a manual dispatch until TSK-1452's restore brings them back on the pull request into `main`. The change is coord/ci's reviewed workflow patch, which carries both parts. TSK-1445 (unit U13) cannot carry it: its outcome includes a push to `main` reusing its pull request's run under strict equality, and it builds on PR 620 (TSK-1321), which is not on `main`. This change needs no other wait, so it lands first and alone, and TSK-1445 starts from what it leaves on `main`. Non-goal: the reuse of a pull request's run on a push to `main`, which TSK-1445 and TSK-1444 own.

This is in the named class of changes that prove themselves only on the default branch: it lands alone, with a revert branch prepared and reviewed first, and its proof (AC-6) is read on `main` after it lands.

Landing on its target (`main`, alone):

- Reachable: the new triggers for CodeFlow's own events.
- Inert: nothing.
- Other lines: not nothing: a line takes the change only when it merges `main`. A pre-rule line that takes it without TSK-1450's rule on `main` waits for tip verdicts that no longer come, so no pre-rule line merges `main` between this landing and TSK-1450's, which follows right after (TSK-1450 depends on this task).

## Outcome

After this merges, a CodeFlow maintainer sees no hosted run on a push to any `integration/**` line, only the short checks on a pull request into a line (commit standards, the secret scan and the security review, with `release impact` and the trusted policy checks still reporting), and, while `main`'s checks are relaxed, the Linux gates and every Windows job only on the daily run on `main`'s tip and on a manual dispatch; after TSK-1452's restore they run on the pull request into `main`, and never again on a line.

## Deliverables

- the workflow triggers, the line pull request jobs and the temporary gate conditions: `.github/workflows/codeflow-ci.yml`, `.github/workflows/codeflow-registry.yml`, `.github/workflows/codeflow-release.yml`, and the admission list in `.github/workflows/codeflow-policy.yml`
- the gate contract scripts and tests that pin them: `scripts/gate-parity.py`, `scripts/test_gate_parity.py`, `scripts/test_gate_contracts.py`, and `crates/codeflow-cli/tests/journey_gate.rs` and `release_journey.rs`

- the first-run proof on `main`: this record's Closeout

## Acceptance Criteria

- AC-1 The `push` branches of `.github/workflows/codeflow-ci.yml` shall become `[main, master]`; the integration branches shall leave its concurrency expression and that expression's comment; the Linux gates and the reduced Windows tier shall no longer run on pull requests into lines; and the gate contract scripts that pin the trigger shall follow; evidence: the diff, `scripts/test_gate_parity.py` and `scripts/test_gate_contracts.py`, which pin the triggers and the concurrency on `main`, and the `journey_gate` and `release_journey` tests. The placement check `scripts/test_ci_placement.py` arrives with PR 620 (TSK-1321) after this lands, and TSK-1445 brings it to this placement.
- AC-2 The `push` branches of `codeflow-registry.yml` shall become `[main, master]` and those of `codeflow-release.yml` shall become `[main]`, and no skipped `release impact` check run shall be left on a line commit; evidence: the diff.
- AC-3 While `main`'s checks are relaxed, the Linux gates, the Windows jobs and both verdicts shall run only on the daily schedule on `main`'s tip and on a manual dispatch; every pull request, into `main` or a line, shall run the secret scan, the gitleaks canary, the security review and provenance, and its admission in `codeflow-policy.yml` shall require the secret scan and the security review; the workflow's header comment shall name what the restore puts back, which is only the pull request into `main` and the push to `main` clauses, never a line push or a line pull request clause; evidence: the diff, `scripts/test_gate_parity.py`, `scripts/test_gate_contracts.py`, and the `journey_gate` and `release_journey` tests.
- AC-4 No required check on `main` or a line shall be one that can pass by being skipped; evidence: the required sets read live at landing against the jobs each event now runs (TSK-1452 owns the ruleset writes).
- AC-5 A revert branch shall be prepared and reviewed before landing; evidence: its SHA in the pull request body.
- AC-6 On `main`, the first line push after landing shall show no hosted run; on the first line pull request and the first pull request into `main`, codeflow-ci shall run only the secret scan, the gitleaks canary, the security review and provenance, while the checks of codeflow-policy and codeflow-release (`commit standards`, `release impact` and the trusted checks) still run and report, so every required check is present; and the first daily run shall show the Linux gates, the Windows jobs and both verdicts on `main`'s tip; evidence: the run lists.
- AC-7 No hosted run on a push to a line is permanent placement, by the operator's ruling of 2026-11-11. Line pull requests run only the short checks, by the Director's ruling, until EPC-055's line gate ships; what follows it is the placement ADR-0102 proposes. No restore of `main`'s relaxed checks (TSK-1452) puts a line push run or a heavy line pull request job back, and none returns without an operator ruling. TSK-1445 later brings the rest of CodeFlow's own CI to the epic placement, starting from this change, and `codeflow update` reconciles the managed copies once TSK-1352 ships; evidence: TSK-1445's `depends_on` and Edges name this task, TSK-1452's list keeps items 1 to 3 out of its restore, and this task's follow-up entry.
- AC-8 The change shall have a cross-lineage review with the `cf-security-reviewer` checklist, since it changes which events run trusted checks; evidence: the review row and its findings.
