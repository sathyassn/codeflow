# TSK-246: The docs portal takes fixed dependency releases

## Description

New npm advisories against `postcss-selector-parser` (through
`postcss-nested`), `smol-toml`, `source-map-js` and `http-cache-semantics`
fail the dependency audit, so the security review is red on `main` and on
every open pull request. This task takes the fixed releases in the docs
portal lockfile and the shipped starter lockfile, re-pins the portal state
and the runtime script list to the new lockfile, and removes the starter's
`osv-scanner.toml` ignore that existed only because `http-cache-semantics`
had no fixed release, rewording the unreleased 3.1.0 changelog entry that
added it. The work was built and reviewed inside TSK-245 and is split out so
it lands first; TSK-245 keeps the test fixture race. Effect on adopting
projects: `codeflow update` installs the starter's new `package.json` and
lockfile, and the portal's recorded runtime scripts are unchanged. No
released version shipped the starter's `osv-scanner.toml` ignore (it was
added after 3.0.0), so no released portal carries it.

## Deliverables

- the dependency fix: `docs-portal/package.json`, `docs-portal/package-lock.json`, `assets/docs-portal/starter/package.json`, `assets/docs-portal/starter/package-lock.json`
- the stale ignore removed: `docs-portal/osv-scanner.toml`, `assets/docs-portal/starter/osv-scanner.toml`
- the portal pins: `.codeflow/docs-portal.json`, `docs-portal/scripts/runtime-scripts.json`, `assets/docs-portal/starter/scripts/runtime-scripts.json`
- the release note: `CHANGELOG.md`

## Acceptance Criteria

- AC-1 When `npm audit` and osv-scanner run on the docs portal and the shipped starter lockfiles, they shall report no advisory. Evidence: `npm audit --package-lock-only` and osv-scanner 2.4.0 on both, and the hosted security review job.
- AC-2 When the docs portal is built and checked from a committed tree, the portal state and runtime script list shall match the new lockfile. Evidence: `codeflow test --mode full --only docs-portal-deps,docs-portal` and `manifest_consistency`.
- AC-3 (journey) When an adopter sets up the portal with this build, or updates a portal set up with CodeFlow 3.0.0, the project's portal lockfile shall carry the fixed releases and its dependency audit shall report no advisory. Evidence: a fresh `codeflow portal setup` and a 3.0.0 setup followed by `codeflow update`, both through the built binary, with osv-scanner on each resulting lockfile; the 3.0.0 lockfile reports the four advisories before the update.
