# TSK-1113: Stat tiles, titled callouts, labelled code and disclosure chips are catalog blocks

## Description

the design audit of 2026-10-31 (Fable 5.1, design seat; the artifact "Present and Portal Redesign" and its scratch notes `present-redesign/` and `portal-audit/`) found that the block model lacks the vocabulary report pages need
(`document.rs:44-161`: 17 kinds, no stat, progress, titled callout,
labelled code or chip), so authors fall back to html stages, which get the
worst treatment. PR 438 plans encoded table cells (TSK-1096) and the clock
axis (TSK-1100). This task adds the rest the audit proposes: a `stats`
block (label, value, unit, delta, spark, meter), `callout` gains `title`,
`code` gains `label` and `highlight` with a copy button, and the disclosure
summary gains `chips`. Each block is drawn once by the grammar module so
present and the portal share it, with a specimen page. The sanitiser
boundary is unchanged. Non-goal: table cells and the timeline (PR 438).

## Outcome

After this merges, an author can write a stat tile, a titled callout, a labelled code block with copy and a disclosure with chips as catalog blocks, and present and the portal draw them the same way.

## Deliverables

- the schema: `crates/codeflow-present/src/document.rs` (`stats`; `callout.title`; `code.label`, `code.highlight`; `disclosure.summary.chips`) and the JSON schema under `.codeflow/schemas/`
- the drawing: `figure-grammar.mjs` (shared), `crates/codeflow-present/src/render.rs`, `crates/codeflow-present/web/src/styles.css`, the portal components that render the same blocks
- the specimen page: `assets/base/skills/cf-present/resources/specimen.json` (every block kind once), both mirrors byte-identical; `document-authoring.md` updated
- tests: schema and render tests per block, the portal parity test, the specimen render in both modes

## Acceptance Criteria

- AC-1 Before any change, the builder shall research report-page block vocabulary broadly: how report and dashboard systems define stat tiles, callouts, code blocks and chips (the dataviz skill's stat tile and meter rules, artifact-design on cards by role), the current 17 kinds and their sanitiser paths, TSK-1096's cell grammar and TSK-1100's timeline on PR 438 so nothing is drawn twice, and adjacent concerns (copy buttons inside an inert page, chips as comment anchors, a stat with no unit, long labels at 400 px); and shall record the findings with sources and the chosen scope before anything else changes; evidence: the Findings section, committed before the first code change in the PR. Listed first because it runs first (the operator's rule of 2026-10-27).
- AC-2 A `stats` block shall render label, value, unit, delta, an optional spark and an optional meter per tile, three tiles across at 1200 px and one at 400 px, with the dataviz stat-tile rules (tabular numerals, delta tone from the semantic palette); evidence: schema and render tests and the specimen screenshots. (serves EPC-022 AC-187)
- AC-3 `callout` shall accept `title`, `code` shall accept `label` and `highlight` and render a copy button that copies the code text only, and a disclosure summary shall accept `chips` drawn from the semantic palette; evidence: render tests and a browser test for the copy button. (serves EPC-022 AC-187)
- AC-4 Each new block shall be drawn once in the grammar module and rendered identically in present and the portal, proven by the parity test on the specimen; evidence: the test.
- AC-5 The sanitiser shall admit no new raw HTML: every new field is text, a number or an enum, and planted markup in a title, label or chip renders as text; evidence: sanitiser tests.
- AC-6 (journey) With the installed build, the specimen page shall open in cf-present and build in the portal, in light and dark at 1200 and 400 px, read by the design seat against the audit's component mockups; evidence: the renders and the written verdict in the PR.
