# TSK-261: Required checks run on the current target tip before a merge

## Description

On 2026-10-08 main went red because PRs 97, 109 and 112 merged on checks that ran before PR 93 landed: the `main` ruleset requires six checks but not that a branch be up to date (`strict_required_status_checks_policy: false`), so the host accepted a green about an older main. `codeflow remote protect` intends strict checks on the classic path only; its ruleset body carries no required checks, it always adds a new ruleset, and its classic PUT drops `required_conversation_resolution`. No command reads the live rules back. This task makes `remote protect` require up-to-date branches on both host paths from one list of check names, makes it update a ruleset that already targets the branch instead of adding another, adds a warn-only `doctor` check that reads the default branch's live rules, runs the source-scan contracts in the quick gate, and states the mechanism in the docs and an ADR. The list is a new optional `git.required_checks` key that lives in the schema and the code default only (the `git.pr_summary` pattern, issue 118); it is never written into `assets/base/policy.json` or this repository's `.codeflow/policy.json`. Non-goals: changing this repository's rules (the operator turns on strict on ruleset 24379074; nobody runs `remote protect` here), the CI workflows, merge queue, and the three refused sites (PR 123, TSK-257). Design: the merge race design with Grok 4.7's challenge folded in.

## Deliverables

- strict checks on both paths, live-rule reading and in-place ruleset update: `crates/codeflow-core/src/remote.rs`
- the `git.required_checks` key, schema and default only: `crates/codeflow-core/src/hooks/policy.rs`, `crates/codeflow-core/src/hooks/policy_schema.rs`
- the remote-perimeter doctor check and its remedies: `crates/codeflow-core/src/doctor/`, `crates/codeflow-core/src/remedy.rs`
- the contract-scans quick target and its pins: `.codeflow/test-config.json`, `scripts/test_gate_contracts.py`, `crates/codeflow-cli/tests/journey_gate.rs`
- the decision: a new ADR under `docs/decisions/`
- the docs: `docs/releasing.md`, `docs/adoption.md`, `docs/delivery.md`, `docs/policy-reference.md`, `docs/cli.md`, `README.md`, `assets/base/ci/README.md`, the git rules and the portal resources that say this repository has no remote protection
- the changelog entry: `CHANGELOG.md`

## Acceptance Criteria

- AC-1 When `codeflow remote protect` applies a rule that requires status checks, it shall require the branch to be up to date on both host paths: the classic body sets `strict: true` with the check names, and the ruleset body carries a `required_status_checks` rule whose checks are objects `{context, integration_id: 15368}` with `strict_required_status_checks_policy: true`; a rule with an empty list is never emitted. Evidence: unit tests in `crates/codeflow-core/src/remote.rs`, failing before the change.
- AC-2 When a repository ruleset already targets the branch, `remote protect` shall update that ruleset in place, keeping its other rules, checks and bypass list, and shall create no second ruleset and no classic protection; on the classic path the PUT shall carry the live `required_conversation_resolution`. Evidence: `remote.rs` tests against a `gh` shim that serves the live shapes of this repository's rules and logs each request, failing before the change.
- AC-3 When the policy has no `git.required_checks`, it shall validate and `remote protect --dry-run` and the doctor check shall use the four scaffold job names; a set list replaces them; a non-string or empty entry is refused; neither `assets/base/policy.json` nor `.codeflow/policy.json` names the key. Evidence: policy schema tests, the dry-run CLI test in `crates/codeflow-cli/tests/recall_remote_cli.rs`, and `codeflow test --mode quick` passing `repository-update-noop`.
- AC-4 When `codeflow doctor --check remote-perimeter` runs with `gh` and a GitHub `origin`, it shall warn when the default branch requires no checks, when no rule that requires checks requires up-to-date branches, when a listed check is not required, or when the protection that carries the checks can be bypassed; it shall pass when the live rules match the policy; and it shall report a note, never a warning or failure, when `gh` is missing, the remote is not GitHub or the rules cannot be read. Evidence: doctor unit tests through the `exec_command` seam, and the real command run read-only against `sathyassn/codeflow`, which reports ok since the operator turned strict on for ruleset 24379074 on 2026-10-08. (journey)
- AC-5 When the quick gate runs, it shall run `git_spawn_contract` and `artifact_budget_contract`, so a tree with a refused git spawn or a stale instruction artifact reference fails before push and names the file. Evidence: the quick gate failing on `git_spawn_contract` at `origin/main` 97ede7aa1, which holds the three raced sites, and passing on a tree with TSK-257's reviewed repair; `scripts/test_gate_contracts.py` and `journey_gate.rs` pin the quick set.
- AC-6 The docs shall state the mechanism: an ADR records that `main` requires up-to-date branches and supersedes ADR-0006's revisit line, the rules and release docs name the setting instead of the merger's memory, `codeflow validate --docs` passes, and `git grep` finds no remaining claim, outside the historical v2 plan, that this repository's remote protection is unavailable; a historical sentence that a dated note corrects is not a remaining claim. Evidence: the diff, `codeflow validate --docs`, and the `git grep` output.
- AC-7 When the operator has turned on strict on ruleset 24379074, a pull request that is behind `main` shall not merge until it is updated and its required checks pass again. Evidence: the host's merge state for a named pull request before and after the update. This depends on the operator's setting. (journey)
