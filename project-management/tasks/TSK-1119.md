# TSK-1119: Every script CodeFlow ships or runs has tests and counts toward the coverage floor

## Description

CodeFlow holds its adopters to the rule that tooling is tested code
(TSK-1031) and plans an 80 coverage floor for every test-running target
(TSK-1006), while its own scripts are not all held to either. TSK-1031's
first-pass survey (TSK-1031.md, "First-pass survey") found that
`.codeflow/test-config.json` runs the `scripts/test_*.py` files with no
coverage, that `scripts/changelog_split.py`, `scripts/gate-binary.py` and
`scripts/coverage-shards.py` have no test file, and that the Python files
shipped under `assets/` (the `cf-evaluate-model` and `cf-herdr` scripts)
are under no coverage target; TSK-1031's non-goals leave this repository's
own untested scripts to be recorded and routed, and the operator asked on
2026-10-31 who owns them. This task owns them: every script this repository ships
in `assets/` or runs from `scripts/` has tests in a test-executing target,
those targets report coverage per target, and the result counts toward the
floor TSK-1006 enforces, so TSK-1006's whole-of-`main` evaluation (its
AC-10) finds the tooling covered or admitted with a fix task rather than
unmeasured. Non-goals: the floor's enforcement and exemption semantics
(TSK-1006), the instruction text (TSK-1031), the assurance record per
shipped executable (TSK-1043, which reads the coverage this task produces).

## Outcome

After this merges, a maintainer can see, per target, the test coverage of every script CodeFlow ships or runs, and no shipped or run script is outside a test target.

## Deliverables

- the inventory and the gaps: the Findings section of this record (every `scripts/*` and shipped `assets/**` script, its target, its test file, its coverage)
- tests for the untested scripts: new `scripts/test_changelog_split.py`, `scripts/test_gate_binary.py` and `scripts/test_coverage_shards.py`, and a test file per shipped script that has none under `assets/base/agents/skills/cf-evaluate-model/scripts/` (`eval_kit.py`, `fake_client.py` today) and `assets/base/agents/skills/cf-herdr/scripts/deliver.py`, beside its script, with `scaffold-manifest.toml` entries for both harness destinations like the scripts they test
- the targets: `.codeflow/test-config.json` (a `tooling-python` and a `shipped-scripts` test-executing target with per-target coverage rules, or the existing targets given coverage), `scripts/coverage-merge.py` if the merge needs a new source
- the per-target coverage report line in the gate output and the CI summary: `crates/codeflow-core/src/testing/` (`threshold/mod.rs` and `gate.rs`, where the coverage summary is composed)
- docs: `docs/test-gate.md` (this repository's tooling targets), `AGENTS.md` project section if the builder evidence row needs the new target names

- AC-1 Before any change, the builder shall research tooling test coverage broadly: every script this repository runs (`scripts/`, the hook and CI helpers) and ships (`assets/**` Python, shell and JavaScript), which target runs each today and with what coverage (`.codeflow/test-config.json`, `coverage-merge.py`), how Python, shell and Node coverage is measured and merged per target (coverage.py, bashcov or kcov, c8), what TSK-1006 and TSK-1031 require and what TSK-1043 will read, and adjacent concerns (a shipped script's tests shipping with it and their footprint under TSK-429, scripts that need a browser or a binary, Windows runners); and shall record the inventory and the chosen targets before any change; evidence: the Findings section, committed before the first code change in the PR. - AC-2 Every script in `scripts/` and every shipped script under `assets/` shall belong to a test-executing target that runs its tests, and a script with no test shall be a gate failure naming it; evidence: the inventory in AC-1 with zero uncovered rows, and a test that adds an untested script to a fixture config and sees the target fail. - AC-3 Each tooling target shall report coverage per target in the gate output and the CI summary, merged by `coverage-merge.py` where a target has several languages; evidence: the gate run output on this repository with one line per target. (serves EPC-022 AC-189)
- AC-4 `scripts/changelog_split.py`, `scripts/gate-binary.py` and `scripts/coverage-shards.py` and every shipped Python script AC-1 lists shall have tests that fail on a planted defect in each; evidence: the test files and one mutation run per script. (serves EPC-022 AC-189)
