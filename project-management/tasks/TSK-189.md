# TSK-189: guards judge by the landed policy and never go missing

## Description

An agent session cannot relax the policy it is judged by, and a missing or
older binary blocks the call loudly instead of silently proceeding. The
guards read policy from the landed target branch's remote-tracking ref,
never from `HEAD`, the index or the working copy, so no local checkout,
commit, rebase, reset or stash changes what the guard applies; only a
reviewed landing on the target does, and the operator lands enforcement
changes. What remains is keeping the tracking ref honest and failing
closed. This replaces TSK-172's enforcement baseline and TSK-173's
fail-closed hooks and readiness receipts, and closes the autonomy
reference rows TSK-164 AC-2, 3 and 6. It builds on TSK-188's reviewed head
(`--on`), since both change the guard files. Residuals stated in the
record: a repository with no remote is judged by its own `HEAD`, which the
session can commit, and only `security.dangerous_commands` is clamped by
the binary today (`policy_schema.rs`), so that path has no privilege or
publish floor and `doctor` says so; a retarget to a different repository
is judged by that repository's landed policy, as today; the git hooks' own
plane (`core.hooksPath`) stays with the shims and the existing override
refusal; an agent that lands an enforcement change through a reviewed PR
on the target has done what the process allows, and the review is the
control.

## Affected surfaces and interfaces

- `crates/codeflow-core/src/hooks/policy.rs` (the policy source),
  `git_guard.rs` (ref and remote protections, the integrity list),
  `assets/base/git-hooks/*` (the shims), the hook commands in
  `assets/base/settings/*.json`, `assets/base/codex/hooks.json`,
  `assets/base/grok/hooks.json`; `codeflow doctor` and the orient digest.

## Acceptance Criteria

- AC-1 In an agent session the guards shall read `.codeflow/policy.json`
  and `project.toml` from the remote-tracking ref of the landed target: the
  stricter, key by key in the policy level order, of the configured
  remote's default branch (`refs/remotes/<remote>/HEAD`) and the declared
  target (`git.root_branch` in workspace mode, else the task record's
  `integration_target` at that remote), so a declared target can only add
  strictness; never `HEAD`, the index or the working copy, in the
  repository the command mutates after `-C`, `--git-dir` and `GIT_DIR`.
  With no remote, or before the first fetch, they shall read `HEAD` (the
  working copy on an unborn `HEAD`) and say which source they used in
  every refusal and in `doctor`. A weaker policy in the working copy, the
  index, `HEAD` or any local branch changes no verdict. Evidence: tests
  with a weaker local policy on each of those four sources and a stricter
  line policy applied over the default branch's.
- AC-2 In an agent session git-guard shall refuse what could fake the
  tracking ref: `update-ref` and `symbolic-ref` on `refs/remotes/`, a
  `fetch` whose destination is not the configured remote's own mapping (an
  explicit `<src>:refs/remotes/...`, `--refmap`, or a source that is not
  that remote's URL), a `push` to `.` or a local path, `remote` add,
  set-url, set-head, rename and remove for the configured remote, `branch
  -d -r` and `-D -r`, and `config` writes at any scope of `remote.*`,
  `url.*.insteadOf`, `url.*.pushInsteadOf`, `include.*` and `includeIf.*`;
  the guard shall also refuse a fetch whose effective URL for the
  configured remote (after `insteadOf` from every config scope, read with
  `git config --show-origin`) differs from `remote.<name>.url`. Shell
  writes to `refs/remotes`, `packed-refs` and `config` under the common git
  dir (resolved through a linked worktree's `.git` file, with `..` and
  symlinks resolved) join the integrity list beside `.git/hooks`. When a
  remote is configured and the tracking ref AC-1 reads is missing, the
  guard shall refuse the call naming `git fetch <remote>`. Plain `fetch`,
  `fetch <remote>`, `push <remote> task/x`, `status`, `log` and `config
  user.name` shall pass. Evidence: paired tests per form, including an
  `insteadOf` in the user config and a deleted tracking ref.
- AC-3 When `codeflow` is missing from `PATH` or older than the hook, every
  git hook shim shall exit 1 and every harness hook command shall exit 2,
  each printing the install command and `codeflow update`; `codeflow hook
  <name> --contract 3` shall be the wired form and an older binary shall
  reject it. Evidence: shim shell tests over exit 0, 2, 1, 127 and an older
  binary; scaffold and settings-preset tests; the Windows shells recorded
  as supported or unsupported.
- AC-4 `codeflow doctor` and the session-orient digest shall report a
  missing or older binary, the policy source in use, and a local policy
  that differs from the landed one, each naming the command. Evidence:
  tests.
- AC-5 In a fresh project with the installed binary and a local bare
  remote: the agent checks out a branch with a weaker policy and commits on
  it, and a guarded command is still judged by the landed policy; the
  agent's `git fetch <path-to-weaker-repo> main:refs/remotes/origin/main`
  is refused; the operator lands a stricter policy on the target and the
  agent's next fetch applies it; with the binary removed from `PATH`, a
  Bash tool call and a commit through the shim are refused with the
  install message. Evidence: end-to-end test. (journey)
