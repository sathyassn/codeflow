## Closeout

The investigation found a product security defect, also reproduced on macOS.
Glob expansion reaches the linked checkout's `.git` and `.claude`, but
interpreter arguments took file-edit checks that did not protect directory
ancestors or checkout roots. The repair applies the shell writer's checks to
each resolved candidate path. This code was unchanged at 02530462e, before
TSK-372. Unquoted and prefix-quoted patterns still refuse.

The originally reported fully quoted Windows payload is a literal under the
accepted shell-grammar contract. `"<linked>/.*"` and `"<linked>/.cla*"` now
allow, whereas `"<linked>/".*` and unquoted patterns refuse. Fully quoted
patterns refused at 9eca03960. The primary accepts this correction under the
operator's 2026-10-15 decision to model shell grammar exactly. TSK-372's
Windows matrix now quotes only the prefix so the wildcard remains active.

The same inspection found two Windows spelling hazards: mixed separators in
a verbatim glob were read as part of a name, and slash conversion could turn
a verbatim drive marker into a UNC prefix. These now keep the intended path
reading. Every case in the native Windows matrix is collected before its
assertion. The portable fixture proves expansion and refusal independently.

An unreadable final component previously disappeared from the glob results.
It now fails closed. At the unchanged 4096-entry limit, an enclosing directory
can stand for the expansion only when it holds no enforcement paths or
registered checkouts and the pattern cannot escape it through parent
components or symbolic links. Other incomplete expansions refuse.
These shell-guard defects came from 3ed842d75, an ancestor of both v3.1.0
and v3.1.1. The interpreter repairs concern unreleased 3.2.0 work. The release
impact remains patch because the changes restore the existing guard contract.

Claude Fable 5.1 and cf-security-reviewer requested changes at 683c58721.
The repair removes raw-value re-expansion, preserves quoted literal arguments,
and checks literal, brace and glob results through one shared writer path.
A candidate filter limits repository reads to protected names, directories
and registered checkout roots, cached for both the payload repository and
each resolved run directory. A portable case and the CLI journey cover a
launcher changing into another repository before naming its linked checkout.
Shell, env and Ruby directory operands with
globs or braces become unknown; incomplete expansion reports its reason.
Portable unit and built-hook tests cover the reported bypasses and ordinary
arguments. The host owns independent confirmation and native Windows results.
No workflow change, essential gate or full gate is included.

At 9eca03960, both reviewers closed the preceding findings and requested
changes for new findings. The next repair carries quote provenance from the
shell parser into interpreter argument expansion, preserves the current
checkout as an ordinary project location, and protects a
linked checkout's `.git` file through external symbolic links. The shared
resolving inventory omitted that pointer in 3.1.0 and 3.1.1. Checkout facts
are cached per directory; authority candidates are checked first, then the
enforcement scan stops at its first hit. The release impact remains patch.

Both reviewers approved 666afaf7c and closed the earlier findings. The final
M1 repair limits the project-location exemption to the canonical current
checkout root. From a linked checkout, ancestors that contain other checkouts
refuse, including external aliases. `.` within an ordinary project directory
and `..` from `src` resolving to that checkout root remain allowed. The new
unit refusal matrix and built-hook journey fail when equality is replaced
with the previous ancestor check. The host owns confirmation of this batch.

The landing candidate exposed two regressions at 630ce7cd9, and the primary
dropped this PR from that landing. Ordinary build globs above 4096 entries
must retain the safe-prefix fallback described above. A code string such as
`"/."` in a runtime concatenation must also remain a fragment. Code strings
retain enforcement-file checks and exempt only the filesystem root and the
current checkout root from the registered-checkout check. Every other
ancestor that holds a registered checkout refuses, as it does in shell argv.
The startup reader also needs the contained-prefix fallback for a large
single-component glob. It checks startup class locations and names while
retaining its existing recursive-glob refusals. Integration at 790bbfac4
was merged cleanly before these repairs. The 2026-10-15 runtime-path residual
remains unchanged. Verification requires
the complete core library and CLI guard, refusal-journey and remedy
suites, the repository contracts, strict lints, docs and queued quick gate.

At 011b9b04f, Fable approved with a wording nit and Grok found that the code
literal exemption wrongly covered every ancestor of the current checkout.
The repair narrows it to the normalized filesystem root, preserving `"/."`,
`"/.."` and Windows drive roots as fragments. Unit and built-hook matrices
cover Python, Node, Perl and Ruby ancestor literals from the linked checkout,
main checkout and `src`. Restoring the ancestor predicate must fail both
matrices. Ordinary contained single-level globs remain allowed above the
entry limit; recursive deletion and startup glob refusals stay intact.
Hard links retain the existing path-based protection limit. Grok measured a
flat directory of 100000 files below three seconds; no new performance change
is included. Publication waits for the primary's release after TSK-375 lands.
