## Closeout

The reported failure is a product security defect, also reproduced on macOS.
Glob expansion reaches the linked checkout's `.git` and `.claude`, but
interpreter arguments took file-edit checks that did not protect directory
ancestors or checkout roots. The repair applies the shell writer's checks to
each resolved candidate path. This code was unchanged at 02530462e, before
TSK-372. The expectation remains a refusal.

The same inspection found two Windows spelling hazards: mixed separators in
a verbatim glob were read as part of a name, and slash conversion could turn
a verbatim drive marker into a UNC prefix. These now keep the intended path
reading. Every case in the native Windows matrix is collected before its
assertion. The portable fixture proves expansion and refusal independently.

An unreadable final component previously disappeared from the glob results.
It now fails closed, as does expansion past the unchanged 4096-entry limit.
These shell-guard defects came from 3ed842d75, an ancestor of both v3.1.0
and v3.1.1. The interpreter repairs concern unreleased 3.2.0 work. The release
impact remains patch because the changes restore the existing guard contract.

Claude Fable 5.1 and cf-security-reviewer requested changes at 683c58721.
The repair removes raw-value re-expansion, preserves quoted literal arguments,
and checks literal, brace and glob results through one shared writer path.
A candidate filter limits repository reads to protected names, directories
and registered checkout roots. Shell, env and Ruby directory operands with
globs or braces become unknown; incomplete expansion reports its reason.
Portable unit and built-hook tests cover the reported bypasses and ordinary
arguments. The host owns independent confirmation and native Windows results.
No workflow change, essential gate or full gate is included.
