# TSK-384: A project can run a gate target in its own split job without weakening the gate

## Description

Issue: #203. The managed gates job in `assets/base/ci/codeflow-ci.yml` runs `codeflow test --strict` over every target in `.codeflow/test-config.json`. A project cannot keep a target out of that job, so a target that needs its own runner shape (the reporter's browser target, sharded in its own workflow with `codeflow test --only`) makes the managed job fail or time out. The only route inside the project is to edit the managed workflow, which `codeflow update` overwrites. Deferred on 2026-10-17; the operator's rule of 2026-10-18 brings it into 3.2.0 because it forces an adopter workaround.

Outcome: **a project can declare that a target runs in its own CI job; the managed job leaves it out, and the gate counts as complete only when a green, current run of that target from the split jobs is present.**

Constraints carried from the 2026-10-17 deferral: every shard binds to the same revision and configuration; missing, failed or stale evidence is refused; required checks are kept; globally disabling the target is not a green result. `ci_skip` keeps its current meaning.

The edge to TSK-355 is real: split-job evidence is recorded target execution evidence, which TSK-355 defines and reuses.

Added by the EPC-022 amendment of 2026-10-18 under the operator's release decision of that day (workspace `RELEASE-PLAN.md`, 2026-10-18 operator decision).

Widened 2026-10-27 for issue #352, item 3 (CodeFlow 3.1.1). An adopter's
managed gate job ran five targets in series on the 2-vCPU
`ubuntu-24.04` runner in 23 min 54 s; running two targets at once in
one job starved the CPU and one hit its 900 s limit. The adopter split
the gate into a matrix of shards, each `codeflow test --strict --only
<targets>` on its own runner, with one aggregate job keeping the
required `codeflow gates` name and a unit test against shard drift, and
measured 10 min 26 s. This task's outcome (a target runs in its own job
and the gate is complete only with every split result green and
current) already covers it; AC-5 and AC-6 ask the managed workflow to
generate the shards from the test config, so the list cannot drift. The
issue's items 1 and 2 (cancel superseded runs, skip a proven repeat)
are TSK-1026.

## Acceptance Criteria

- AC-1 A target marked to run in its own job shall be left out of the managed gates job, and `codeflow test --strict` there shall report it as owed by the split job, not as passed; evidence: schema and CLI tests. (serves EPC-022 AC-80)
- AC-2 The gate shall count as complete only when every shard of the split target reports green on the same revision and configuration; a missing, failed, stale or mismatched shard shall leave it incomplete; evidence: tests per case.
- AC-3 A project that marks a target this way shall keep the required check names, and a configuration that disables the target everywhere shall not report a complete gate; evidence: tests.
- AC-4 (journey) A fresh and an updated adopter with a split browser-like target shall run the managed workflow and a project matrix job, the managed job shall pass without the target, and the gate shall be complete only after the shards report; evidence: the journey output and hosted run URLs in the PR.
- AC-5 The managed workflow shall be able to run the gate as a matrix of shards generated from `.codeflow/test-config.json` (a per-target shard setting), each running `codeflow test --strict --only <targets>` on its own runner, with one aggregate job that keeps the required `codeflow gates` name, passes only when every shard passed on the same revision and configuration, and fails on a failed, cancelled or missing shard; evidence: scaffold tests over the rendered matrix and aggregate job, and a hosted run on a scratch adopter with #352's five-target shape. Added 2026-10-27 for issue #352 item 3: the generated form of this task's split job. (serves EPC-022 AC-80)
- AC-6 A shard list that differs from the enabled targets in `.codeflow/test-config.json`, or an enabled target in no shard, shall leave the gate incomplete with a message naming the target; evidence: tests per case. Added 2026-10-27 for issue #352 item 3: the adopter's drift test, made a gate rule.
