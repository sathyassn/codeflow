# TSK-438: A supervisor and a separate agent account isolate lanes beyond the sandbox

## Description

Issue #286, items 2 and 3. The per-lane socket allowance (TSK-437,
4.0.0) separates lanes whose seats run inside sandboxes; it does not
cover agent processes that run as the same account outside every seat
sandbox, such as hooks or unsandboxed retries. The issue asks for two
more layers: an administrator-owned supervisor that enrols each lane's
client with its own identity, specified until a project asks for it;
and guidance for a dedicated non-admin agent account with the service
runtime under a separate service account, since several adopters will
want the same setup.

Outcome: **an adopter can read one specification of the optional
supervisor layer (identities, enrolment, what it refuses, what it
costs) and one guide to a separate agent account (what moves: logins,
clone, Herdr, App key custody; what it buys; what it does not), each
with its evidence, and decide which to adopt.**

Rules: the supervisor is specified as an SPC record with its open
questions closed, not built, until a project asks; the account guide
is a doc under `docs/` with a tested setup on macOS and Linux. The
issue's "not verified" items are TSK-437's; this task cites its answers.

Non-goals: building the supervisor; changing the seat postures
(TSK-437).
