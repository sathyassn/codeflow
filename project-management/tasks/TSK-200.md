# TSK-200: Release 3.0.0 without Windows

## Description

By operator decision on 2026-10-01, CodeFlow 3.0.0 ships without native
Windows: the hosted Windows job fails real tests, including a git guard
that strips backslashes from Windows paths and refuses ordinary work.
This task makes the release path neither build nor require Windows and
makes every release-facing statement accurate. It removes the
`x86_64-pc-windows-msvc` target and the PowerShell installer from
`dist-workspace.toml` (the generated `release.yml` is unchanged at
cargo-dist 0.32.0), drops the Windows job from
`required_publication_checks`, keeps that job running as an advisory
check with `continue-on-error` so Windows evidence keeps accumulating,
and corrects the README, adoption, product, contributing, harness
posture, releasing, release checklist, 3.0.0 verification records and the
pending CHANGELOG. 2.1.0 published no Windows asset, so no published
asset is removed. Non-goals: fixing the Windows defects and restoring the
Windows target, which TSK-197 owns for 3.0.1; the published CHANGELOG
sections and the digest-pinned pre-policy group, which stay unchanged.

## Acceptance Criteria

- AC-1 When `dist plan --output-format=json` runs with the pinned
  cargo-dist 0.32.0, the 3.0.0 plan lists the macOS arm64 and x86-64 and
  Linux x86-64 archives, the shell installer and the source archive on the
  macos-14, macos-15-intel and ubuntu-22.04 runners, with no Windows
  archive, PowerShell installer or Windows runner; evidence: the plan
  output and the command envelope's `jq` check in
  `docs/verification/releases/v3.0.0-command-envelope.md`, which an
  adopter's installer path depends on. (journey)
- AC-2 `dist generate --mode ci` with cargo-dist 0.32.0 leaves
  `.github/workflows/release.yml` unchanged, and the
  `distribution_config_keeps_supported_targets_and_installers` test pins
  exactly the three targets and the shell installer; evidence: an empty
  regeneration diff and `cargo test -p codeflow-cli --test
  release_contract` output.
- AC-3 The publication authority requires `release state`,
  `codeflow gates`, `secret scan` and `security review` and no Windows
  check, and a failed check outside that set does not block publication
  while every other required check still does; evidence:
  `python3 -B scripts/test_release.py` and
  `python3 -B scripts/test_gate_contracts.py` output.
- AC-4 The `windows` CI job still runs the same raw Rust floors as the
  local gate, carries `continue-on-error: true`, and is named as advisory
  with TSK-197; evidence: `python3 -B scripts/gate-parity.py`,
  `python3 -B scripts/test_gate_parity.py` and the
  `test_windows_job_is_advisory_until_tsk_197` test.
- AC-5 No release-facing document claims that 3.0.0 publishes a Windows
  archive, a PowerShell installer or `codeflow.exe`; the pending CHANGELOG
  states the omission in a `release-impact none` entry and in its known
  limits, and the published sections and the pre-policy group are
  byte-unchanged; evidence: a `git grep` over the changed documents,
  `python3 -B scripts/release.py check-state --structural` output and
  `codeflow validate --docs`.
