# TSK-209: Unblock CI from an unreachable docs portal advisory

## Description

On 2026-10-02 osv.dev updated GHSA-ch52-4w7c-c8xp (High): `http-cache-semantics`
through 4.2.0 can hand one user's cached response to another when a shared
cache honours a client's large `max-stale`. No fixed version exists. Astro
depends on it, so both docs portal lockfiles (CodeFlow's own `docs-portal/`
and the shipped `assets/docs-portal/starter/`) carry 4.2.0, and the
`security review` job, which blocks under CodeFlow's policy, now fails on
every pull request. Astro uses the package only in
`dist/assets/build/remote.js`, to compute how long a remote image fetched
during the build stays cached; a static docs build serves no shared cache
and takes no client request, so the flaw is not reachable. This task adds a
dated, reasoned suppression in an `osv-scanner.toml` beside both portal
lockfiles, and
corrects the CI text that tells adopters to use `.osv-scanner.toml`, a name
osv-scanner never reads: its configuration is `osv-scanner.toml` in the
scanned lockfile's own directory. The starter's copy is user-owned: a fresh portal gets it
as a starting point, and the adopter may edit or delete it without a portal
conflict, since accepting an advisory is each project's call (review of PR
17 found a managed copy could be neither). Existing portals do not receive
it; the changelog tells them how to add their own. Non-goal:
replacing Astro or patching the package.

## Acceptance Criteria

- AC-1 When osv-scanner 2.4.0 scans the repository, GHSA-ch52-4w7c-c8xp is
  reported as ignored with its reason for both docs portal lockfiles and no
  other advisory is hidden; evidence: the scan output before and after.
- AC-2 The suppression names the advisory id alone, carries the
  reachability reason and expires on 2026-11-30, so the advisory blocks
  again unless someone triages it anew; evidence: the file and the scan
  with the date moved past expiry.
- AC-3 The starter's `osv-scanner.toml` is user-owned: `codeflow portal
  setup` writes it to a fresh portal, keeps an adopter's edit, does not
  recreate it after deletion, leaves an adopter's existing file alone, and
  adds nothing to an existing portal, all without a conflict; CodeFlow's own
  copy is byte-identical; evidence: `manifest_consistency` and those five
  setup runs. (journey)
- AC-4 The managed CI template, CodeFlow's own CI and the baseline copy name
  `osv-scanner.toml` beside the lockfile; evidence: the diff and
  `gate-parity.py`.
- AC-5 The `security review` job passes on this PR. (journey)
