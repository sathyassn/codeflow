# TSK-218: PR summaries open with a prose lead then bullets

## Description

The operator decided on 2026-10-03 that a pull request Summary opens with a
short prose lead followed by bullets, and that this holds mechanically. This
task adds that check to `codeflow ci` under a new policy key,
`git.pr_summary`, blocking by default and adjustable by adopters, records the
decision as a dated note on ADR-0071 (whose rule 7 keeps "no count"), and
teaches the shape where PR bodies are taught: `writing.md` "Summaries", the
PR template, cf-ship's PR evidence reference and the copy guide. On the
coordinator's request it also adds one rule to cf-ship: a PR already reported
ready goes back to draft before any further change to its branch. Non-goal:
judging whether the lead anchors the reader, which stays with review.

- The check reads the visible top-level blocks of the one Summary section
  under its mapped heading. HTML comments, blocks with no visible text and a
  paragraph that is only the `Task:` line are skipped.
- Pass: one paragraph, then a list or table, then only lists, tables and at
  most one closing paragraph, which comes last.
- A missing, empty or repeated Summary stays with `git.pr_sections`.
- While a kept PR template is diagnosed the check runs at warn at most; a
  trusted automation profile skips it, because a bot writes its body to its
  own format.

## Acceptance Criteria

- AC-1 When `codeflow ci` reads a PR body whose Summary is one prose paragraph followed by a list or table, with at most one closing paragraph, it reports no `git.pr_summary` finding (unit tests in `crates/codeflow-cli/src/cmd/ci/pr_body.rs`).
- AC-2 When the Summary is prose only, has two paragraphs before its first list, opens with a list, table, quote or code block, carries more than one paragraph after the list, or holds a heading, code block or HTML block, `codeflow ci` reports a `git.pr_summary` finding at block by default that names the shape found, the shape expected and a remedy naming `writing.md` "Summaries" (unit tests and a `ci_cli` test of the binary with fail-before).
- AC-3 Text hidden in an HTML comment or a code fence never supplies the lead or the list (unit tests).
- AC-4 An adopter can set `git.pr_summary` to warn, allow or off; the key is in the policy schema, the shipped policy, the level keys and the generated policy reference, and `codeflow ci` prints its level and origin; it runs at warn at most while a kept template is diagnosed, and a trusted automation profile skips it (unit tests, `policy_schema` drift test, `derived_lookup_pages_match_the_binary`).
- AC-5 ADR-0071 carries a dated note naming the operator decision of 2026-10-03, and `writing.md` "Summaries", the PR template, cf-ship's `pr-evidence.md`, the copy guide, the CI README, `docs/adoption.md`, `docs/capabilities.md` and the CHANGELOG state the shape, with managed copies, baseline and manifest in sync (`manifest_consistency`, `repository_update_noop`, `codeflow validate --docs`).
- AC-6 cf-ship's `pr-evidence.md` says that a PR already reported ready goes back to draft before any further change to its branch and is reported ready again only after the new head has its review and checks (review).
- AC-7 The current Summaries of open PRs 26, 34 and 35 pass the new check, and this PR's own body passes `codeflow ci --pr-body-file` (journey).
