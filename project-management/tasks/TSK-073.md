# TSK-073: positive copy guide

## Description

Say how to write each string, not only what to avoid. The system today has a
smell list (`cf-editorial-review/references/editorial-smells.md`, from
EPC-017) and six writing bullets restated in about seven files with drifting
wording; voice is stated three ways. Write
`cf-editorial-review/references/copy-guide.md`, one section per string type,
each with its rules and one good example that exists verbatim in a named
source (the kit reference pages, the figure specimens, an accepted ADR, the
PR template or a skill), with the source named beside it:

| Section | What it settles |
|---|---|
| Voice | one statement: plain and calm; third person in documentation, second person in how-to steps and replies |
| Sentences | one idea, active, present tense, a named subject, about 25 words or fewer; colon and semicolon use |
| Words | exact identifiers and commands, acronyms expanded once, one term per thing, digits with units |
| Titles and headings | a noun phrase in words; a how-to heading names the outcome; sentence case; identifiers in the body |
| Leads | what the reader is looking at; never the caption again |
| Captions | one sentence, the takeaway |
| Legend keys and descriptions | a key is a noun phrase naming the state; the description names every state and drawn fact |
| Summaries | a substantive summary (a closeout, a PR, an ADR context, a reply that leads into a list or table) is two to four plain sentences before the list or table; a short answer is its own summary and takes no lead |
| Bullets and tables | one fact per bullet, parallel form; a table when three or more items share fields; noun headers |
| Microcopy | verb-first labels, adjective states, empty states that say what to do, errors with cause and fix, digits, one-clause tooltips, no exclamation marks |
| Replies | a simple answer stays simple: no figure, no headings, no recap, and a one-line answer stays one line; otherwise the summary rule, a fenced figure when a relationship carries the point, a table for tabular facts, the exact link a tool printed; never a sentence about the reply's own format |
| Skill prose | the same sentence and word rules in the imperative register; no slogans |
| ADR and PR shapes | ADR context in two to five sentences, one decision paragraph stated as fact, consequences with a cost; PR summary two to four sentences, then bullets or a table, with test evidence |

The guide adds no ceremony: every rule removes words or moves a fact to its
best carrier, and none asks for a lead, heading or explanation that a short
answer does not need. It cites ADR-0067 in one sentence as the policy and
points at the editorial smells for diagnosis; it does not copy the
mannered prose table. The kit README keeps its six writing bullets, because
a product reads the kit on its own, names the guide as the full text, and
the guide carries the six bullets verbatim. Every other restatement becomes
a pointer: the writing sentences in `explanation-method.md` stage 4,
`utility-presentation-system.md` section 3, `figure-grammar.md` section 3
(keeping its ADR-0067 citation), the language lines of both presentation
`SKILL.md` files and the language section of `document-authoring.md`.

Pointers also go into:

- `workflow-lifecycle.md` "Shape deliverables": one sentence naming the
  method and the guide, and the reply rule's figure wording aligned to the
  figure block, on the text TSK-084 reconciled;
- `cf-editorial-review/SKILL.md`: load the guide when writing, the smells
  when reviewing; its line on using an ASCII diagram when relationships are
  clearer points at the nine families in the explanation method;
- `cf-ship/SKILL.md` step 5;
- the Summary comment of the PR template, in all three copies, changed
  identically; the rest of each copy is untouched, so the live template
  keeps CodeFlow's changelog impact lines and its Release impact section,
  and the managed copy and the baseline stay equal to each other;
- the summary comments of the ADR template
  (`assets/base/docs/decisions/template.md`, Context) and the epic
  template (`assets/base/pm/epic.md.tmpl`, Summary), with this
  repository's managed copies and baselines. The ADR template ships at
  standard and full, the epic template at full, and `cf-editorial-review`
  at standard and full, so no pointer dangles in a consumer.

Grade the guide in the evaluation kit, beside the method cases TSK-062
adds, with requirements whose markers resolve verbatim in `copy-guide.md`.
The prompt never names the rule; the faulty control is a plausible draft a
careful reader would accept:

| Case | Prompt (fixture) | Faulty control | Graded signal |
|---|---|---|---|
| Lead and caption | write the text around a fixture figure | the lead restates the caption; the caption repeats the title; a sentence explains the legend | the lead says what the reader looks at; the caption is the takeaway; legend keys are noun phrases |
| Microcopy | name the controls, the empty state and the no-results message of a search dialog | "Nothing here yet!", Title Case labels, "Oops, no matches" | verb-first labels, sentence case, an empty state that says what to type, no exclamation mark, digits |
| Summary before a table | write a task closeout from fixture evidence with test output and a coverage number | bullets only, or one paragraph of nine sentences | two to four sentences, then a table for the evidence, what was not tested named; positive control, on its own prompt (a simple yes or no question): a one-line answer with no lead passes |
| Skill prose | write the first section of a new skill | a draft with a slogan, a contrast turn and an em dash | imperative plain sentences, no policy character, no slogan |
| ADR shape | record a decision to pin a sheet byte for byte | context as four paragraphs of history; the decision spread over three | context in two to five sentences naming the constraint; one decision paragraph; consequences with a cost |
