# TSK-1427: The event policy is proved in the 2026-11-16 brownout and then narrowed to main's events

## Description

GitHub blocks `pull_request_target` by default from 2026-12-02 and runs brownouts before then. TSK-1347 applied repository policy 11322 to allow the event for `.github/workflows/codeflow-policy.yml` only, and shipped the doctor, protect and docs work. Two of its criteria can only be shown after it lands:

- TSK-1347 AC-6: a hosted run of the policy check inside a brownout window runs with the setting applied. GitHub runs `pull_request_target` from the default branch's file whatever the pull request targets (TSK-1347 Findings, run 42255054674), so a same-repository pull request whose policy run is created by an event inside the window is the proof: the run's `created_at` and its triggering event's time both fall inside it (AC-1).
- TSK-1347 AC-3: policy 11322 is narrowed to the events `main`'s file declares, with `coordination/scripts/operator/tsk1347-event-policy.sh`, and a live read shows only those. The Director ruled on 2026-11-06 that narrowing waits until after the brownout proof, so one change does not muddy that test.

This task runs the proof in the 2026-11-16 window, 16:00 to 18:00 UTC, or after enforcement starts on 2026-12-02 if that window gives no proof. Only after a passing proof does the operator narrow the policy. The task records both.
