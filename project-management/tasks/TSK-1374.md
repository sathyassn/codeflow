# TSK-1374: The deletion guard fails closed at its bounds

## Description

The deletion reader (`crates/codeflow-core/src/security/deletion.rs`) reads a shell line as a small program, within fixed bounds on nesting, values, argument combinations, loop passes and launch wrappers. A guard that stops at a bound has not read the rest of the line, so it cannot show the line is safe. This task makes the reader treat every such stop as a refusal or as an unknown value, never as "nothing found".

Scope: the guards fail closed at their reading bounds. That covers the deletion reader as it stands, the floor check that reports its result, and the shell startup guard's reading of symbolic links (`crates/codeflow-core/src/security/startup.rs`), which is the same class. The bounds keep their values and their declarations: TSK-1299 moves them to the limits registry.

Boundary with other work:

- TSK-1073 AC-2 covers the future shell parser in `hooks/git_guard.rs`. This task covers the current reader. When TSK-1073 replaces this reading, it must keep the same fail-closed result.
- TSK-286's proof table may list this result later.
- TSK-1258 is the precedent: the glob matcher refuses when it cannot finish.

Non-goal: reading a program the line does not contain, such as a sourced file or a script on disk. The module documents that limit.

## Outcome

After this merges, an agent session on any adopter's machine gets a refusal that names the cause when the deletion guard cannot finish reading a command, whatever the project's policy says.

## Deliverables

- the fail-closed result and its refusal message: `crates/codeflow-core/src/security/deletion.rs`, `crates/codeflow-core/src/security/dangerous.rs`, `crates/codeflow-core/src/security/startup.rs`
- tests for each bound, and for ordinary nested commands staying allowed: the test modules of those files, and `crates/codeflow-cli/tests/` for the built-binary path
- the changelog entry: `changelog.d/TSK-1374.md`
- the threat statement: the PR body

## Acceptance Criteria

- AC-1 When the reader reaches its nesting bound on a nested shell script, an `eval`, a function call or a command substitution, the guard shall refuse the command and shall never read the stop as "nothing found"; evidence: a test that fails before the change and passes after it, covering each of those forms at every level up to past the bound. (serves EPC-022 AC-164)
- AC-2 When the reader reaches any other bound it has, on brace alternatives, input lines, argument combinations, loop passes, launch wrappers, compound structure or parameter expansions, it shall keep the fact that it stopped: as an unknown value, so a later deletion through it refuses, or as a refusal where the unread part may be a command; evidence: one test per bound that reproduces, each failing before the change and passing after it.
- AC-3 Every refusal from a stop in structure shall come from one shared result with a named message that gives the cause and says what to do; evidence: the code path and a test that asserts the message.
- AC-4 The refusal shall not depend on a setting a project can lower; evidence: the floor check runs it with no policy input, and a built-binary run with `git.hook_integrity` at warn still refuses.
- AC-5 The real `codeflow hook exec-guard` shall refuse the same text the tests judge; evidence: a built-binary test or run that pipes the text to the hook and never executes it. (journey)
- AC-6 Ordinary nested commands shall stay allowed: `sh -c`, `bash -lc`, `xargs`, `find -exec`, `make` style lines and CodeFlow's own gate commands; evidence: a test over those forms and a built-binary run, with any new refusal listed for the owner before a bound moves. A command nested past what the reader can follow is refused, whatever it does; the PR states this as a behaviour change.
- AC-7 The bounds shall keep their values and declarations; evidence: the diff.
- AC-8 The PR shall state the threat in class terms and why refusing at a bound is the standard design; evidence: the PR body.
- AC-9 When the shell startup guard stops following symbolic links at its bound, it shall refuse the path, whether the links sit in one path or add up across directory changes; evidence: a test that fails before the change and passes after it.
- AC-10 Text the reader cannot parse within its bounds shall give a refusal, never a crash of the guard; evidence: tests over deep structure and deep expansions.
