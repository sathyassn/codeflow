# TSK-203: Fast CI gates and a clean release build

## Description

CodeFlow's own CI took about an hour to judge a main push (run
37026679259): the Linux full gate ran every target on one runner for
26 minutes, and the advisory Windows job ran the whole nextest suite on
one runner for 54 minutes, while the release authority waits for the
whole workflow run. This task splits the Linux full gate into parallel
jobs that together run exactly the same targets with the same
strictness, behind one aggregate check still named `codeflow gates`;
splits the Windows suite into nextest partitions that cover it once,
with the journey gate reading all of their results; and adds the
selector that makes the split honest, `codeflow test --only`, which runs
the named targets with their prerequisites and never records complete
evidence. It also fixes the published binary reporting `dirty=true`:
the release job redirects cargo-dist's manifest to `dist-manifest.json`
at the checkout root before building, and the build script counts that
untracked file as a dirty tree. Non-goals: fixing the Windows test
failures and making Windows a gate again (TSK-197); changing the
adopter CI template, which installs a pinned released binary and knows
no project's targets.

Review fixes (Codex GPT-6 Astra at d7e20c1b5): `scripts/gate-parity.py`
now accepts only the exact verdict job and refuses a gate step that can
be skipped or forgiven, where a substring check let four unsafe forms
through; one `docs-portal-deps` target runs the portal's `npm ci` and
both portal targets require it, so a local full gate can no longer run
two installs at once (gate-parity refuses a second installer); and an
`--only` run is never recorded complete, even when its names cover every
target.

## Acceptance Criteria

- AC-1 When a pull request into `main` or a push to a protected or
  integration line runs codeflow-ci, the Linux full gate runs as
  parallel jobs whose `--only` groups together name every enabled
  full-mode target of `.codeflow/test-config.json`, each with
  `--mode full --strict --all`, and the aggregate check `codeflow gates`
  passes only when every part passed; evidence:
  `scripts/gate-parity.py` refusing a missing or unknown group target
  (`scripts/test_gate_parity.py`) and the PR's codeflow-ci run. (journey)
- AC-2 The advisory Windows nextest suite runs as partitions numbered 1
  to N of N, which together run the whole suite once; the journey gate
  reads every partition's results; the jobs stay advisory and outside
  the publication checks; evidence: `scripts/gate-parity.py` refusing an
  incomplete partition set, `scripts/test_gate_contracts.py`, and the
  PR's run.
- AC-3 The PR's own codeflow-ci run reaches its verdict in about 10 to
  15 minutes instead of about an hour; evidence: the run's job timings
  against run 37026679259.
- AC-4 When `codeflow test --only <targets>` runs, the system runs the
  named targets and their prerequisites, skips the rest, records the
  run as not complete, and refuses a name that is not an enabled target
  of the mode before any target starts; evidence:
  `crates/codeflow-cli/tests/test_gate_cli.rs`.
- AC-5 Every path the release job writes into its checkout before
  `dist build` is ignored, so the release binary reports `dirty=false`;
  evidence: `the_release_build_writes_only_ignored_paths_so_its_binary_is_clean`
  in `crates/codeflow-cli/tests/release_contract.rs`, failing before the
  `.gitignore` fix and passing after.
