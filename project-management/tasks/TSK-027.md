# TSK-027 — keep release metadata in the work PR

## Description

Replace the rejected automatic candidate-PR path inside the existing main PR.
The working agent records reviewed impact with curated changelog entries and
updates the cumulative pending version/stamps before opening or updating that
same PR. CI verifies state without writing it. Publication is an explicit
owner action through supported cargo-dist main-snapshot dispatch. Preserve
historical provenance without moving tags or publishing anything in this task.

## Affected surfaces and interfaces

Repository PR template/checks; `.github/workflows/` release automation;
git-cliff/cargo-dist configuration and supported generated extensions; a small
locally testable preparer/verifier; workspace, lockfile and managed scaffold
stamp agreement; `CHANGELOG.md`, `docs/releasing.md`, the next available release
ADR, release verification/history, and focused release-contract tests. Shipped
consumer skills/assets and their mirrors/manifests belong to TSK-028.
