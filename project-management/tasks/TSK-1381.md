# TSK-1381: Guards judge commands run through other terminal launchers the same as bare commands

## Description

TSK-1344's sibling sweep found that commands carried by other terminal and job launchers still pass exec-guard and git-guard unread. This task extends TSK-1344's carrier reader to these launcher families:

- terminal multiplexers: tmux, screen, zellij, dtach, abduco
- terminal emulators' remote control: wezterm, kitty, and iTerm's scripted `write text`
- remote shells: ssh, mosh, autossh
- containers: docker exec and run, podman exec and run, nerdctl exec and run, kubectl exec, lxc exec
- schedulers and service launchers: at, batch, crontab with the job body on the line, launchctl, systemd-run, schtasks
- application openers: open -a
- scripted terminals: expect
- programs that run a command in another tree or as another user without being terminal launchers: chroot, unshare, nsenter, su; these fall under the unknown-directory rule in AC-3

The reader rule is one contract. A carried command whose directory is a known directory on this machine is judged as if typed bare in that directory. A command that runs where the guard cannot establish the directory (another host, a container, another pane or session) refuses. A form the reader cannot read with certainty refuses. Text typed into a running session stays on TSK-1344's floor.

Overlap, kept where it is. This task's reader shall not weaken any of these:
- the closed prefix-launcher list (nohup, setsid, timeout, sudo, doas, env, nice, time, stdbuf, unbuffer and the GNU `g` names) in `crates/codeflow-core/src/security/launchers.rs`
- flock, script and watch, read on the startup-file walk that `docs/policy-reference.md` describes beside them
- the osascript and make inline-code readers in `security/outward.rs`
- `scp -S` and `rsync -e` as unknown writer options in `security/unresolved.rs`
- ssh heredoc bodies and TSK-1073's deliberate scans; TSK-1073 already covers how an ssh command line is parsed, so this task covers what the launchers carry, not ssh parsing
- launchctl load and bootstrap, and crontab as user-level persistence, under TSK-188 AC-1
- tmux and screen beside a named startup file or a user git config write, which refuse as unread programs today

Non-goals: launchers TSK-1344 already reads (hc and herdr); text typed into a running session (AC-5); recipe files and editor task files, which are unseen files and outside this reader.

## Outcome

After this merges, an agent that runs a command through tmux, ssh, a container, a scheduler or another listed launcher meets the same guard refusals as when it types the command bare. A command whose directory the guard cannot establish refuses.

## Acceptance Criteria

- AC-1 Before any product change, the builder shall judge, on the line's built binary, one named form per listed launcher and per chroot, unshare, nsenter and su, crossed with the headless-peer, Git, destructive, privileged and outward classes, plus each launcher's directory forms (a spelled directory, another host or container, a new pane, window or session with its own directory or environment), and record in `## Findings` which forms are weaker than bare. The table uses class-only wording, and each row names the test that AC-2, AC-3 or AC-4 adds for it; evidence: the Findings table.
- AC-2 When a listed launcher carries a command in a form the reader knows and the command runs in a directory on this machine that the reader can resolve, exec-guard and git-guard shall judge the carried command as they judge it typed bare in that directory; evidence: one test per launcher and class, each with its named form. Where AC-1 records the form as weaker than bare, the test fails before the change and passes after it; where the line binary already refuses, the test passes before and after, and shows the new reader does not allow the form.
- AC-3 When a listed launcher, or chroot, unshare, nsenter or su, runs a command in a directory the guard cannot establish as a directory on this machine, the guards shall refuse the form and name it. Such directories are:
  - a remote host
  - a container or other mount
  - a pane or session whose directory is not this one
  - a spelled directory on another machine
  - a split, new window or new session with its own directory or environment
  - a chroot, unshare or nsenter target, or su's login directory

  A path that exists on this machine is still refused when the command runs somewhere else. A relative destructive command and a relative secret read shall refuse in each of those forms, including where the same relative words are allowed in the session directory. An unknown option, a template, a word the guard cannot fill in, or a job body that is not a literal on the line shall refuse and name the form. Marking a form fully read shall not skip the existing unknown-directory reading of a quoted script string (`outward.rs` `unmodeled_launch`). Evidence: one test per launcher and directory form, and one each for chroot, unshare, nsenter and su, with a relative destructive command and a relative secret read; and one test per launcher for each of an unknown option, a template, an unfilled word and a non-literal job body, where the launcher has that form. Where AC-1 records the form as weaker than bare, the test fails before the change and passes after it; where the line binary already refuses (for example a quoted script string under `unmodeled_launch`), the test passes before and after, and shows the new reader does not allow the form.
- AC-4 Forms that carry no command and change no directory or environment (listing sessions, attaching, read-only queries) shall pass. A split, new window or new session that sets only a directory or environment is not a no-command form; AC-3 governs it. Evidence: one test per launcher with its named form, which passes before and after the change.
- AC-5 Text typed into a running session stays unjudged, on TSK-1344's decision for `hc send` and `hc keys`.
  - The forms are `tmux send-keys`, `tmux load-buffer` with `paste-buffer`, `screen -X stuff`, zellij write-chars, `kitty @ send-text`, `wezterm cli send-text` and `expect send`. They pass when their options parse.
  - A partial filter shall not be presented as protection.
  - The docs and the rule text shall name the floor. The program that receives the text runs its own guards before it runs a command, and a plain shell has none. After that come the Git hooks in each repository, CI and the remote branch protection.
  - A decision that would refuse these forms goes to the Director for the operator before it is built, because the tmux transport types into a session this way.

  Evidence: one passing test per form, the decision in `## Findings`, and the doc sentence.
- AC-6 The reader shall not weaken the readers and rules listed under Overlap in the Description; evidence: the existing tests for each stay green unchanged, and one test per listed reader shows its refusal still fires when the command is carried by a listed launcher.
- AC-7 The docs shall list each launcher the guards read, the unknown-directory rule and the typed-text floor; evidence: `docs/policy-reference.md`, and a test that the list matches the reader's table.
- AC-8 The installed guards shall refuse a carried destructive command in an unknown directory, and judge a carried Git command in a known one as bare, in a fresh `codeflow init` repository on the installed CLI (serves EPC-029 AC-2); evidence: a CLI test against the built binary in a scratch repository.
- AC-9 The change shall have a cross-lineage security review with the `cf-security-reviewer` checklist: Grok or Codex when a live probe at dispatch shows usage, else a fresh Claude Opus medium subagent with reduced assurance recorded; evidence: the review row and its findings record.
- AC-10 A changelog entry shall name the launchers and the unknown-directory refusal; evidence: `changelog.d/TSK-1381.md`.
- AC-11 A multi-call binary that runs a shell or another tool through an applet argument shall be read the way the guards read busybox today, by both exec-guard and git-guard, on the bare form and on the form where a supplier (a launcher, `xargs` or a wrapper the guards already unwrap) carries it: the carried command is judged as if typed bare, and an applet the reader cannot identify refuses on each guard. The builder shall first inventory this class on the line's built binary: the multi-call binaries in common distributions, including a multi-call name that is not a shell, each judged bare and supplier-carried on both guards. Evidence: that inventory; one test per inventoried binary, form and guard, where each supplier-carried test uses a carrier that hands the multi-call name to the guard's own walk as the program word (for exec-guard, the supplier path at `crates/codeflow-core/src/security/outward.rs:1846-1851` at b85d30681), failing before only where the inventory records the form as weaker than bare and passing after; and a test per guard that an unidentified applet refuses.
