# TSK-1004: Import authority tells shared planning merges apart from unpublished imports

## Description

`work.import_authority` can refuse a valid first push of an integration line
as an unpublished import. When two lines branch from one commit and both
merge the same planning branch, they share planning provenance: a record
introduced by that planning merge is on both lines. While checking line A,
`refuse_unpublished` (`crates/codeflow-core/src/workgraph/acceptance/imports.rs:286`)
walks the other line's local first-parent history through
`matching_landing` (`:341`), which accepts any matching version that is an
ancestor of the head (`:366`) as a landing. A shared ancestor that line A
reached through its own history is then treated as an import from line B,
and because line B is not yet published the push is refused. Hosted run
40158545922 hit this through identical same-second merges (TSK-455 made its
test merges distinct); Codex's TSK-455 review (round 3, thread
01a17228-3903-7d03-be64-a17947d3d9e2) found it reachable by ordinary
branching too.

Scope: the import check tells shared planning provenance (a record version
both lines reached through common ancestry, or through the same planning
source) apart from a genuine foreign import (a version that exists in the
range only because the other line's history was merged in). Non-goal: no
change to what counts as published authority or to the refusals for real
unpublished imports.

## Deliverables

- The distinction in the import check: `crates/codeflow-core/src/workgraph/acceptance/imports.rs`
- Regression and refusal tests: `crates/codeflow-core` acceptance tests and `crates/codeflow-cli/tests/acceptance_journey.rs`

## Acceptance Criteria

- AC-1 When two lines share a planning merge or other common ancestry that introduced a record, a first push of either line shall not be refused by `work.import_authority` for that record, including when both lines hold the identical planning merge commit. Evidence: a test that builds both shapes (distinct merges of one planning branch, and one shared merge commit) and pushes each line first; it fails before the fix.
- AC-2 When a line's range really imports a record version from another line whose history is unpublished, the existing refusal shall still fire with its current message. Evidence: the existing import-authority refusal tests stay green unchanged, plus one test where the imported version exists only on the other line's unpublished history.
- AC-3 (journey) When an adopter runs `a_release_branch_from_two_lines_passes_on_a_fresh_project` with author and committer dates pinned to one second and the original single planning-merge message, both lines shall push. Evidence: `GIT_AUTHOR_DATE=GIT_COMMITTER_DATE=<fixed> cargo test -p codeflow-cli --test acceptance_journey` with the message variant restored in a test, output in the PR.
