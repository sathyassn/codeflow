# TSK-1355: A managed workflow judges a pull request by the base authority: the base tip resolved once, test config and policy read from it

## Description

Split 2026-11-05 from TSK-1103 by the CI records planning pull request, before claim, by outcome (Director ruling, 15:5x). Issue #602 (an adopter): a run after the base moved judged the old base's policy and passed, because the managed workflows read `pull_request.base.sha`, which is fixed when the event fires. This task resolves the base ref's tip once at job start and uses that SHA everywhere, and the gates job reads `.codeflow/test-config.json` and `.codeflow/policy.json` from that base authority instead of the pull request's head, failing closed when the base copy cannot be read. TSK-1356 was merged in on 2026-11-05 (its AC-1 is AC-2 here); TSK-384 AC-9 (`codeflow test --mode pr`) uses the read, so TSK-384 depends on this task. Non-goal: the race after the verdict, which only strict up-to-date checks or a merge queue close; the guidance states it.

## Outcome

After this merges, an adopter's managed CI judges a pull request against the base tip as it is when the run starts, under that base's test config and policy, and the report names that SHA.

## Deliverables

- the managed workflows: `assets/base/ci/codeflow-ci.yml` and `assets/base/ci/codeflow-policy.yml`, with installed copies and the baseline synchronized
- the guidance: `assets/base/ci/README.md`
- tests: the scaffold template tests, a moved-base fixture, and fixtures for a dropped target, a lowered floor, a policy edit and an unreadable base copy
- docs: `docs/policy-reference.md`

## Acceptance Criteria
