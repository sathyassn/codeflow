# TSK-337: The prescribed Codex lane starts with its intended permissions

## Description

Issue: #213. `assets/base/agents/skills/cf-model-orchestrator/resources/routing/transport.md:57` selects `cf-builder` through `-c default_permissions`, while the profile is defined in project config (`assets/base/codex/config.toml:72`, `:228`). The issue reports that Codex 0.163.0 performs an earlier global-only configuration load. The integration line contains no accommodation for that load order.

The current consult row already omits the override and relies on the project's default. The verified repository claim is therefore narrower than “all managed launches pass the bad flag”: the builder row does, and explicitly selecting either project profile has the reported failure. The upstream regression and native startup results were not independently reproduced here.

Outcome: **Each prescribed Codex launch reaches an authenticated prompt with the intended effective guard or builder permissions on the supported CLI release.**

Source inspection is from the accepted triage at `c5c6f6f671d2bf67a77113c656b3be446fb0bea1`; runtime reproductions remain implementation evidence.
