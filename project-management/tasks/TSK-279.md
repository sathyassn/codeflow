# TSK-279: One local command gives the hosted release-impact verdict

## Description

Pre-push runs `scripts/release.py preflight`, which never applies the
marker floor or the equality rule that hosted `release impact` applies
through `check-pr`, and `release_local::preflight`
(`crates/codeflow-core/src/release_local.rs`) never passes the PR body. On
2026-10-08 PRs 99, 111 and 97 passed pre-push and failed hosted CI
(https://github.com/sathyassn/codeflow/issues/117). This task gives one local command that returns the hosted
verdict for a base, head and PR body, and makes the preflight report the
same mismatches when a body is available. Pre-push keeps reporting them as
warnings, as it reports a missing entry today (`docs/releasing.md:355`), and
no policy key is added. Non-goal: making pre-push block on them.

## Deliverables

- the command and the preflight: `scripts/release.py`, `crates/codeflow-core/src/release_local.rs`
- tests: `scripts/test_release.py`, the pre-push preflight tests
- docs: `docs/releasing.md`
- release note: `changelog.d/TSK-279.md`

## Acceptance Criteria

- AC-1 When an author runs the documented local command with a base, head
  and PR body, it shall give the verdict hosted `release impact` gives,
  the marker floor and the equality rule included; evidence:
  `scripts/test_release.py` replays of PRs 99, 111 and 97 reaching their
  hosted results. (serves EPC-022 AC-3)
- AC-2 When pre-push runs with a PR draft available, the preflight shall
  report floor and equality mismatches as warnings that name the rule, and
  without a body it shall say these rules were not checked; evidence:
  preflight tests.
- AC-3 `docs/releasing.md` shall document the command beside `check-pr` and
  say what pre-push judges and what it does not; evidence: the doc diff.
- AC-4 (journey) When a branch on this repository declares `patch` under a `minor`
  marker, the local command run with the installed build shall give the
  hosted error before any push; evidence: a scripted run on a
  scratch branch.
