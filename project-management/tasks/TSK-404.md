# TSK-404: The browser escalation test reaches its escalation path under parallel scheduling

## Description

Issue: #232. The macOS browser unit test `browser::tests::process_group_cleanup_reverifies_before_forced_escalation` failed once in `cargo test -p codeflow-present --lib browser::tests` on `79a6491cc`: it ran out of its one-second identity-startup deadline before exercising termination (`crates/codeflow-present/src/browser.rs:2686-2693`). It passed alone and in a serial run. TSK-328 left this file unchanged and tracked this failure as the issue; its completion is not amended.

A flaky gate test blocks landing candidates, so it is 3.2.0 work.

Outcome: **the escalation test reliably reaches and proves its escalation path under normal parallel suite scheduling.**

A serial-only pass is not the repair, and the escalation assertions keep their meaning.

Added by the EPC-022 amendment of 2026-10-18 after the Codex review of PR 249 (`target/review-PR249-codex-01.md`), under the operator's rule that every security gap and every defect that forces an adopter workaround or blocks work belongs in 3.2.0.
