# TSK-185: Pre-push checks a landing against the line it lands on

## Description

The pre-push push set picks a single `--base` for `codeflow ci` from the
first boundary of `rev-list --boundary` against every tip the destination
advertises. When the pushed history has several boundaries, as a batch
landing on the line or a task branch that merged the line has, that
boundary is an arbitrary branch tip (`89f6c41` on 2026-09-29), and the
range then re-checks history the destination already holds and refuses
it. Batch 1 of EPC-020 cannot land for this reason alone: the same range
checked from the line's own tip is clean. The change makes the push set
choose the base CI uses when it judges the same change as a pull request,
and never a base that checks fewer commits than the destination lacks.

Non-goal: changing which checks run on the range, or any level.

## Affected surfaces and interfaces

- `crates/codeflow-cli/src/cmd/push_set.rs` (range base selection) and its
  tests; the pre-push hook behaviour adopters see.

## Acceptance Criteria

- AC-1 When a push extends an existing protected or `integration/` branch,
  the push set shall run `codeflow ci` from that branch's advertised tip,
  even when other destination branches hold part of the pushed history;
  evidence: a push-set test with a merge of several remote task branches
  onto the line, red before the change and green after.
- AC-2 When a push creates or updates any other branch whose integration
  target resolves at the destination, the push set shall run `codeflow ci`
  from the merge base of the pushed commit and that target's advertised
  tip, the base CI uses for the branch's pull request, and shall name the
  target in its output; evidence: push-set tests for a task branch that
  merged the line after its first push and for a new branch with several
  boundaries, red before and green after.
- AC-3 When the push set chooses a base by AC-1 or AC-2, that base shall
  be an advertised destination commit or an ancestor of one, so the range
  contains every commit the destination lacks; evidence: a test whose
  pushed history holds a commit the destination lacks that a base cut
  below an advertised tip would leave out.
- AC-4 When a push rewrites a protected or `integration/` branch, the
  target cannot be resolved, or the destination cannot be asked, the push
  set shall behave as it does today; evidence: the existing push-set tests
  green, including the one-boundary new branch and the stale tracking ref
  cases.
- AC-5 When batch 1 is pushed to the EPC-020 line with the fixed binary,
  the pre-push range shall start at the line's old tip and pass; evidence:
  the push output. (journey)
