# TSK-1242: A daily exact-SHA Windows run covers each active integration line

## Description

Source: the CI throughput study of 2026-11-02 (`coordination/coordinators/parallel/throughput/`: RECOMMENDATIONS.md, FINDINGS.md, CHECK-codex.md, CHECK-fable.md), cross-checked by Codex GPT-6 Astra and Claude Fable 5.1, and the operator's priority on CI throughput.

The Windows schedule runs weekly and covers `main` only (`.github/workflows/codeflow-ci.yml:22`). The twelve Windows test partitions run on every pull request (`:717`) and cost about 2 x 330 weighted minutes per pull request. They can move to pull requests into `main` only once a scheduled run covers the integration lines daily and reports the exact SHA it tested, because a daily result cannot prove that a newer tip passed (Codex check, finding 2).

Integration pull requests keep Windows clippy, doc and Node (`:744`, `:751`, `:760`, `:770`), the Python release journey (`:777`) and a chosen set of runtime journeys. The verdict job (`:849-870`) must accept that tier's skips.

Blocked on operator decision 3 of the study, choice (b): move the partitions to pull requests into main plus a daily line run, accepting that Windows runtime breaks surface later on integration lines. Non-goals: the Linux split (TSK-1241).

## Outcome

After this merges and the operator's decision is recorded, each active integration line gets a daily Windows run that names the SHA it tested, and integration pull requests no longer run the twelve Windows test partitions.

## Deliverables

- the schedule, the line dispatch and the SHA report: `.github/workflows/codeflow-ci.yml`
- the verdict job's tier skip set: the same workflow
- tests for the line selection and the report: the scripts the workflow calls

## What the daily run covers and skips

Controls: `ActiveLineTests`, `DiscoverJourneyTests` and `DailyCoverageTests` in `scripts/test_windows_daily.py`. The same statement is in the docstring of `scripts/windows-daily.py`.

- Lines covered (Director's ruling, 2026-11-03, superseding the Findings' "every existing ref"): `main` and each active integration line. A line is active when its own tree at discovery has what the runner calls: every script named in `windows-daily-run.yml`, each with the subcommands and flags the runner passes it, such as `drift` and `reports`, and the partition measurements. The test reads files and runs nothing from the line. There is no named list. Task branches, tags and pull request refs are not covered.
- A line that lacks any of these is not proven active: it stays out, and the run's summary names it, its commit and what is missing. Nothing is deleted. `main` is always selected. A selected line that fails fails visibly.
- How the list stays current: `discover` runs `git ls-remote` and reads the trees on every run, and nothing stores the result. The needs come from the runner workflow itself, so a new runner command applies to the next run. If the listing or a read fails, the run fails and offers no lines.
- What a run skips: no Windows job, and no selected line for its age or an unchanged tip. An unchanged tip runs again every day until TSK-1314 replaces this. TSK-1314 (filed, record lands in the next planning PR) owns a skip for a tip with a passing daily run recorded, unless that run is older than a configurable age (default 7 days), and it measures the real minutes. It is required before the line goes to `main`, and the schedule does not run until then (Director's ruling, 2026-11-03). The rerun has two reasons meanwhile. The tested tree is not the whole input: the Windows runner image changes under an unchanged commit, which is why `scripts/ci-reuse.py` already compares images before reusing a verdict. And TSK-1273 AC-4 asks for a daily run of each line that reports the commit it tested; a skip would add a way for a day's result to pass on an earlier run's proof. Cost, an estimate: about 1100 weighted partition minutes per day, unchanged tips included. Basis: four selected sources times the 272.73 to 282.40 per run under "Findings", extrapolated from two runs; no daily run has been observed. The verdict refuses any skipped job.
- What it does not do: it runs Windows only, so Linux gates and coverage are outside it. A commit that was never a tip at discovery is not tested, and a later tip gets no credit.
- Limit: discovery's shallow fetch took 11 to 15 seconds per ref from this host, inside the `sources` job's 5 minutes at today's five lines. About 20 lines would reach that limit and fail the run visibly. The fetch has not run on a hosted runner.

- Artifact key, low consequence, recorded once: `inputs.artifact-key` is a SHA-256 digest of the ref and commit, and artifacts belong to their own run. No follow-up.
