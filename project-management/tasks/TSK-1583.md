# TSK-1583: The privacy check has policy levels, findings that never show the value, and fails closed

## Description

Owner: to be assigned by the Director. Staged by a planning Worker for
coord/records on 2026-11-23 from the operator's privacy request.

This task builds the frame every privacy layer plugs into (SPC-018 R-1 to
R-9, R-2a, R-5a, R-7a and R-35): the `privacy` policy section with its
first key, `privacy.patterns`, and the per-layer level reader the later
layers' keys use; the placement in `pre-commit`, `commit-msg`, `pre-push`
and `codeflow ci`; the finding format that names kind and place and never
the value, with paths that hold a value redacted; binary classification
from blob bytes alone; the privacy relaxation line; the shared placeholder
table; and the fail-closed rule. It ships no detector of its own beyond
one stub kind used by its tests. By SPC-018 R-2b it adds no
`privacy.identity`, `privacy.names` or `privacy.terms` key: each comes
with its layer (TSK-1594, c3, c5).

Read at `origin/main` d2307063f2 and the EPC-022 line tip 960eb7dbf4:

- The secret scan runs in `git_hook.rs` `secret_scan` (main `:195`, tip
  `:217`) and `commit_msg_secret_scan` (main `:824`, tip `:896`) over the
  staged diff (`hooks/scan.rs:152` `scan_diff`, both); the privacy hooks
  sit beside it on the same inputs.
- `git.secret_scan` is never suspended by bootstrap grace, while its own
  key can still turn it off (`policy-reference.md` main `:80`, tip
  `:85`); privacy levels follow the same grace rule.
- In hosted CI, `codeflow ci` judges in the verdict job of the trusted
  admission workflow, which fetches base and head as git data only
  (`codeflow-policy.yml` main `:12` to `:13`); the privacy pass runs there,
  never in `codeflow-ci.yml`, which runs head code.
- The managed CI annotation carries file and line, never line text
  (`codeflow-ci.yml` main `:914`, tip `:892`).
- Levels come from the default branch at one commit (ADR-0091 `:44`);
  TSK-1078 moves the commit hooks there.

Non-goals: any detector kind (TSK-1584 to a5, EPC-060, EPC-061);
exemptions (TSK-1588); installing defaults in new or updated projects
(TSK-1589).

## Outcome

After this merges, a project can set `privacy.patterns` in its policy,
read from the default branch; every privacy finding in any hook or
`codeflow ci` names its rule, path (with any value in it redacted), line
and columns and never the value; a lowered level prints a relaxation line
on every run; a binary blob is decided from its bytes, never from head
attributes; and a detector that cannot run refuses at `block`.

## Acceptance Criteria

- AC-1 Before any change, the builder shall record in a `## Findings` section, with file:line at the base, every place the secret scan reads staged content, a message file and a pushed or CI range, how each reads its level, how each reads blobs (and whether any applies `.gitattributes`, a diff driver or textconv), and where the privacy runner attaches beside each; evidence: the Findings section, committed before the first code change.
- AC-2 `privacy.patterns` shall load with `off`, `warn` or `block`, `allow` and any other value shall be refused when the policy is read, its schema default shall be `block` (the operator's decision of 2026-11-23), and a project value below it shall load; no `privacy.identity`, `privacy.names` or `privacy.terms` key shall exist yet (SPC-018 R-2b); evidence: schema tests per value, and a test that the three later keys are unknown.
- AC-3 Levels shall be read from the default-branch authority as TSK-1078 does for the commit hooks, a working copy may only raise them, and bootstrap grace shall not suspend them; evidence: hook tests with the authority at `block` and a working copy at `off`, failing before the change only in the sense that no privacy key exists, and a grace test.
- AC-4 Fail before: on a scratch project at the base, a commit adding the stub kind's value is accepted with no message; evidence: the base output, quoted in the PR.
- AC-5 Pass after: the stub kind shall refuse at `block`, warn at `warn` and not run at `off`, at the two blocking points the operator decided on 2026-11-23, `pre-push` over each commit of the range and `codeflow ci` over each introduced commit, and also in `pre-commit` and `commit-msg` (a plain message and a merge Git concludes itself) for early feedback; a value added and deleted inside the range shall still be a finding; evidence: one test per placement and level.
- AC-6 No privacy output shall contain the matched value: a test seeds a unique placeholder value, runs every placement, captures stdout, stderr, the CI annotation lines, `codeflow doctor --check privacy`, any temporary file and the arguments and environment of every child process, and finds the value nowhere; it runs twice, once with the value in file content and once with the value only in an added file name and only in an added folder name; evidence: the content and path canary tests.
- AC-7 When the diff, the message file, the range or the authority cannot be read, the run shall report a finding naming what could not be read and refuse at `block`; evidence: a test per input.
- AC-8 `codeflow doctor --check privacy` shall print each layer's effective level and the commit it was read from; evidence: a doctor test.
- AC-9 The placeholder table shall have one home (the code constant), and the policy reference section shall be generated from it; evidence: a test that the doc table equals the constant.
- AC-10 Speed, component bound (SPC-018 R-9a): the suite shall hold the typical-change fixture (one commit adding 2,000 lines across 20 text files, about 200 KB, Rust, Markdown, JSON and YAML, with 20 placeholder values and 5 findings), and a component benchmark in the optimised test profile shall run the privacy pass on it five times and fail when the median exceeds 500 ms; pre-push shall print the layer time in one line; TSK-1584 to a5 each keep this component benchmark green; the bound itself is proven by the final runs in TSK-1589 (layer 2) and TSK-1595 (layers 2 and 3) after the real hook is wired; evidence: the benchmark on the hosted Linux runner and on an Apple silicon macOS machine, with both medians in the PR.
- AC-11 Binary classification (SPC-018 R-5a): a blob shall be binary only when its first 8000 bytes hold a NUL byte, read from the git object with no `.gitattributes`, diff driver or textconv applied; a head whose `.gitattributes` marks a prose file `binary`, or `-diff`, or names a textconv driver, shall still have that file's added lines scanned and the stub value found; a real binary blob shall be reported by one line naming its (redacted) path; evidence: the regression test with the hostile `.gitattributes`, failing before at any call site Findings shows using git's attribute-driven diff, and a binary test.
- AC-12 Path redaction (SPC-018 R-7a): a finding or skip line whose path holds the stub value shall print the path with that segment replaced by the kind's placeholder, in every hook, the CI annotation and doctor; evidence: output tests per surface.
- AC-13 Relaxation line (SPC-018 R-2a): with `privacy.patterns` at `warn` or `off` at the authority, every placement and doctor shall print one relaxation line, with TSK-424's activation key unset and with it set; evidence: tests per placement for both key states.
