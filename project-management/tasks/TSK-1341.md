# TSK-1341: A standalone task PR may add its own estimate records

## Description

Found on 2026-11-05 while building TSK-1013, and filed by the second consolidation amendment (planning pull request 596). `codeflow ci`'s work-classification rule refuses a task pull request that adds any Markdown under `project-management/` other than its own record (`crates/codeflow-cli/src/cmd/ci/classification.rs`, `is_added_work_record`, applied to `Class::Tracked`). Two shipped steps write estimate records in a standalone task pull request, so an adopter who follows them is refused: `cf-plan` step 5 writes the version 1 profile at the project's first breakdown, which may be a standalone task, and `cf-estimate` step 6 writes the outcome record of a standalone task. This task admits added Markdown under the adopted estimate root in a task pull request and keeps every other added work record refused. Forecasts are JSON and an epic's outcome record rides a line records pull request, so neither needs a change.

Non-goals: any other change to the classification rule; where estimate records live (`cf-estimate` `references/records.md` sets it); the estimate checker and `codeflow estimate outcomes` (TSK-1171, TSK-1172).

Edges: this changes a `codeflow ci` admission rule, so it gets a cross-lineage security review. The exemption is read from the base branch's `.codeflow/estimate.json`, which the requester cannot change in the pull request, and anything the check cannot be sure of exempts nothing.

## Outcome

After this merges, in a project that has adopted estimation, a standalone task pull request that writes the project's first profile or its own outcome record passes `codeflow ci`, and every other added work record is still refused.

## Deliverables

- the admission rule and its tests: `crates/codeflow-cli/src/cmd/ci/classification.rs`, `crates/codeflow-cli/tests/ci_cli/`
- the records paragraph on where estimate records land: `assets/base/agents/skills/cf-estimate/references/records.md` and its mirrors

## Acceptance Criteria

- AC-1 When a tracked task pull request adds Markdown under the estimate root that the base branch's `.codeflow/estimate.json` names with status `adopted`, `codeflow ci` shall admit those files; evidence: a `ci_cli` test with a profile and an outcome record, failing before the change with the work-classification refusal.
- AC-2 The admission shall fail closed: the root shall be read from the base branch, never the head; a missing, unreadable or non-adopted base record shall exempt nothing; and a file under the root that parses as a task, epic or other work record shall still be refused; evidence: one `ci_cli` test for each case.
- AC-3 (journey) With the installed build in a scratch adopter, a first breakdown run as a standalone task that carries the version 1 profile shall leave the task branch's local `codeflow ci` clean; evidence: the journey output.
- AC-4 The `cf-estimate` `references/records.md` paragraph TSK-1013 writes on where estimate records land shall say that a task pull request may add its own estimate records under an adopted root; evidence: the diff, with its mirrors in step.
