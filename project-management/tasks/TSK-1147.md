# TSK-1147: Guidance and seat config describe capacity admission, not one gate at a time

## Description

CodeFlow must not limit parallel work except where correctness needs it. This task removes every instruction that serializes work without protecting correctness, in CodeFlow's own rules and in what `codeflow update` ships to adopters, and describes capacity admission instead: every heavy run (full, essential, quick heavy targets, reserve) takes one free slot of N, N is computed from cores and free memory and can be set in `.codeflow/test-config.json`, a run with no free slot uses a smaller job count and never waits or skips, and a target declared `host_exclusive: true` runs alone on the host. Landing one candidate at a time on a line tip, and waiting for hosted verdicts before the next landing, stay. The code change is the sibling task TSK-1145; this task is guidance only. Non-goals: it documents no config key beyond those above and does not hand-edit the generated command tables in `docs/cli.md`, which follow the code.

## Outcome

After this merges, an agent or adopter reading CodeFlow's rules, skills, seat config and docs is told to run builds and gates in parallel within host capacity, and is told to order only landing.

## Deliverables

- Discipline rules: `assets/base/rules/workflow-discipline.md` ("Lanes and capacity") and its installed copy
- Skills and references: `assets/base/agents/skills/`, `assets/base/claude/skills/` and their installed mirrors
- Seat config and routing transport: `assets/base/codex/config.toml`, `assets/base/agents/skills/cf-model-orchestrator/resources/routing/transport.md`
- Project section and docs: `AGENTS.md`, `docs/`
- Release note: `changelog.d/TSK-1147.md`

## Acceptance Criteria

- AC-1 No shipped rule, skill, template, seat config or doc says that heavy work takes a gate lock, that only the primary runs gates, that a landing has priority over new builds, that lanes defer heavy runs or that a queue orders them. Evidence: `grep` of `assets/`, `docs/` and `AGENTS.md` for those phrases returns only landing-order text.
- AC-2 The discipline rules, the orchestrator transport and the seat config describe capacity admission: one free slot of N per heavy run, a smaller job count when none is free, and `host_exclusive: true` running alone. Evidence: review of those files at their file:line.
- AC-3 Landing one candidate at a time on a line tip and waiting for hosted verdicts stay, and the text says neither stops building or testing. Evidence: `.codeflow/rules/workflow-discipline.md` and `worktrees.md` at their file:line.
- AC-4 Adopters receive the change through `codeflow update`: installed copies, baselines and manifest digests match `assets/base`. Evidence: `manifest_consistency` and the instruction contract tests pass.
- AC-5 Docs and records stay valid. Evidence: `codeflow validate --docs` and the docs-portal check pass.
