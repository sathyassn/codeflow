# TSK-1508: A selective run never counts as split gate evidence, and update keeps a hand-patched workflow

## Description

Split from TSK-384 on 2026-11-15 by the Director's approval (16:44). TSK-384 keeps the shard plan and its check (its AC-1 to AC-6). This task takes two outcomes that sit on top of that check. First, a partitioned gate binds every shard to the same tree, configuration digest and mode, a selective run (one that picked a subset of targets by what changed) never counts as shard evidence, and the landing record says whether the aggregate was hosted or local. Second, `codeflow update` has a stated path for a repository that already hand-patched its managed `codeflow-ci.yml` into shards, and the builder first records how update treats such a workflow today. These were TSK-384's AC-7 and AC-8. The workflow change itself (TSK-384's AC-9) is TSK-1509. Non-goal: this task does not change the shipped workflow or the managed baseline.

## Outcome

After this merges, a project that splits its gate into shards can rely on only a complete, same-revision shard set counting as gate evidence, and an adopter who hand-patched the managed workflow into shards can run `codeflow update` without losing the patch silently.

- selective-run refusal and same-binding check for shard evidence: `crates/codeflow-core/src/testing/shards.rs` and the run record
- landing record wording ("hosted aggregate" or "local"): the landing record writer under `crates/codeflow-core/src/` (provisional; decided by where TSK-384's shard check records its result)
- update path for a hand-patched sharded workflow: `crates/codeflow-core/src/scaffold/update.rs` and `crates/codeflow-core/src/scaffold/report.rs`
- the record of how `codeflow update` treats a hand-patched managed workflow today: this task's Findings section
