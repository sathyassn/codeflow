# TSK-050: make the doctrine describe a guide to the project as it stands

## Description

The shared doctrine and the portal skill still describe the portal as a view
over every source in the repository, with records and accepted decisions as
page classes of their own and an instruction to add a records layer whenever
work records exist. Plan v7 settles the portal as a guide to the project as it
stands: what it is, what it does, how to adopt it, how it is built and how it
is operated, each page layered Concept, Architecture and Technical with a
figure that carries the meaning and prose that frames it. Decisions, epics,
tasks and specs stay in the repository and are pointed to as folders. This
task rewrites the page classes, the layer ladder, the information architecture
rule and the content contract's treatment of record ids accordingly, in both
skill copies and their mirrors, and records the decision in one short ADR.
Non-goals: no token or carrier change; no adapter change.

## Affected surfaces and interfaces

`assets/base/agents/skills/{cf-docs-portal,cf-present}/resources/utility-presentation-system.md`
(byte-identical), `cf-docs-portal/SKILL.md` section 3,
`cf-docs-portal/references/{visual-craft,information-architecture,content-contract,operations}.md`,

`docs/decisions/ADR-0064`. CAP-015, CAP-016.

## Acceptance Criteria

- [x] The doctrine page classes shall be Orient, Architecture, Reference and
      Record pointer, with the altitude trio the standard form of every
      explanatory page and the record pointer a table of folders that never
      expands into per-record pages; evidence: the rewritten section 2 table
      in both skill copies, byte-identical, and the parity test passing.
- [x] The portal skill and its references shall describe the layer ladder as
      purpose, capabilities and journeys, architecture in effect, reference
      and pointers, and shall no longer instruct adopters to add a records
      layer; evidence: SKILL.md section 3, visual-craft.md section 3 and
      information-architecture.md carry the new text and a grep for "Records
      layer" in the skill returns only the pointer rule.
- [x] Record ids that target sources outside the portal shall resolve to the
      pointer page or the repository folder link; evidence: content-contract.md
      states the rule and names the fallback.
- [x] Stale wording shall be gone: "two utility themes" and the old accent
      hexes in operations.md, "plex" where the skin is ink; evidence: grep.
- [x] ADR-0064 shall record the change in one page with Context, Decision and
      Consequences and name ADR-0048, ADR-0058 and ADR-0063 as unchanged;
      evidence: `codeflow validate --docs` passes with the new record.
- [x] Every mirror and hash shall agree; evidence: `codeflow doctor --check
      managed-drift` clean and the manifest consistency test passing.
