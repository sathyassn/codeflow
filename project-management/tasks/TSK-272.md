# TSK-272: the extended CodeQL triage is reviewed and its false positives are settled

## Description

The first CodeQL scans of `sathyassn/codeflow` left alerts that need a
settled state. Alerts 1 to 103 (run 38158838901, default suite) were triaged
and approved by an independent Grok 4.7 review. Alerts 104 to 126 (setup run
38182246438, extended suite) were triaged by a Claude Opus worker with no
cross-lineage review yet; the five unpinned-action alerts among them are
fixed in the 3.1.0 release pull request. Both triages are in
`docs/verification/releases/v3.1.0-codeql-triage.md`. This task gets the
cross-lineage review of the extended-suite triage, dismisses the false
positives with their recorded reasons once the operator approves (dismissal
changes the repository's security state), and, after five healthy pull
request runs, brings the operator the decision on whether branch protection
requires CodeQL. The design-kit escaping that alerts 1 and 2 call for is
owned by TSK-269 (on its own branch, not on `main` yet) and is not repeated
here. Non-goal: code changes; a review finding that needs one is filed
against its owner.

## Deliverables

- the cross-lineage review of the extended-suite triage and its verdict: `docs/verification/releases/v3.1.0-codeql-triage.md`
- the dismissal record (alert numbers, reasons, the operator's approval): provisional, a section of the same record
- the branch protection decision and the five runs it rests on: provisional, the same record and the workspace `RELEASE-PLAN.md`

## Acceptance Criteria

- AC-1 A review by another lineage than the triage's author reads alerts 104 to 126 against the code at the reviewed commit and returns a verdict with file:line evidence; any disagreement is resolved before a dismissal. Evidence: the review file, named with its seat, model and head.
- AC-2 With the operator's recorded approval, every alert classed false positive or test-only is dismissed with its recorded reason, and no other alert is dismissed. Evidence: the code-scanning API listing of dismissed alerts compared with the record.
- AC-3 After five healthy CodeQL runs on pull requests, the operator's decision on requiring CodeQL in branch protection is recorded with the five run ids. Evidence: the record and a live read of the branch protection.
- AC-4 After the dismissals, every open CodeQL alert on the repository has a recorded owner. Evidence: the open-alert listing compared with the record (journey)
