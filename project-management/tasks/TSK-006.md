# TSK-006 — research and prototype the presentation experience

## Description

Independently research, design, render, and compare materially different
`cf-present` experiences before the reusable renderer, block catalog, default
theme, or interaction model is implemented. Use representative CodeFlow work
and real review decisions; do not select a generic dashboard or attractive
text-card grid from prose alone.

## Affected surfaces and interfaces

- Disposable prototype worktrees/artifacts, information-shape/block studies,
  feedback interaction and annotation studies, theme/mode prototypes, rendered
  browser evidence, and the durable utility `DESIGN_INTENT` consumed by TSK-011.
- No production runtime, scaffold, or managed artifact lands from this task.

- [ ] Fable independently researches and proposes the utility experience;
      Codex performs an independent research/proposal pass before either sees
      the other's conclusion.
- [ ] At least three materially different, sufficiently complete prototypes use
      representative explanation, comparison, plan, code/diff, diagram,
      evidence, and feedback content rather than palette-only variations.
- [ ] The selected default is modern, elegant, aesthetically coherent,
      pleasing, and functional; comparison against representative real content
      rejects generic dashboard composition, repeated pretty text boxes, prose
      walls, and decorative visuals that carry no information.
- [ ] Every viable prototype is rendered in light/dark modes and evaluated for
      hierarchy, information-bearing visuals, interaction/annotation clarity,
      language, responsive behavior, accessibility, reduced motion, code and
      diagram fidelity, and implementation maintainability.
- [ ] Claude leads the design recommendation; Codex reviews feasibility,
      durability, implementation size, and testability. Unresolved
      operator-owned direction is presented to the user with the real
      alternatives and consequences before settlement.
- [ ] The selected exact `cf-present` `DESIGN_INTENT`, representative cases,
      rejected-direction rationale, and fidelity evidence plan are durable,
      dual-approved inputs to TSK-011; prototypes remain isolated and
      disposable rather than production authority.

## Execution contract

Plan v2 is EPC-005 plus approved SPC-004 and the design/eval findings from
TSK-005. The directly invoked Claude judgment primary leads design research and
prototype critique; Codex independently researches and challenges feasibility,
durability, and verification. Integration target:
`integration/EPC-005-presentation-system`. A material direction
choice unresolved by evidence remains operator-owned; prototype code cannot
enter the production scaffold by convenience.
