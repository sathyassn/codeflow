# TSK-1069: Cargo takes the fixed libz-sys release

## Description

Advisory RUSTSEC-2026-0418 (GHSA-8p3x-q3q3-q3v5, no CVSS score) affects
`libz-sys` from 1.0.21 up to 1.1.31, and `Cargo.lock` resolves 1.1.29. The
dependency audit in the security review job (osv-scanner, policy
`git.dep_audit=block`) now fails every pull request on the EPC-022 line and
the checkpoint pull request into `main`. The flaw is in the build script: it
logs its zlib probe command with `{:?}`, and from `cc` 1.6.0 that command
carries the whole build environment, so secrets in it are written to the build
script output under `target/`, where CI caches can keep them. CodeFlow reaches
`libz-sys` only through `git2` 0.21 and `libgit2-sys` 0.18.7, with no `static`
feature, so the probe runs. The checked workspace lock resolves `cc` 1.4.0,
which puts only `LC_ALL` on the command and does not trigger the leak. Other
or historical resolutions are not verified: the documented source install,
`cargo install --path crates/codeflow-cli` without `--locked` in `README.md`
and `docs/adoption.md`, recomputes dependency versions and may have taken `cc`
1.6.0 or later, which crates.io records as published on 2026-10-03. The audit
blocks on the version, and a later `cc` update would arm the leak. This task
moves the lock to `libz-sys` 1.1.31, which stops logging the probe command,
with no other dependency change and no audit suppression, and adds `--locked`
to every documented source-install command so a source build uses the checked
lock. Effect on adopting projects: the lockfile is not shipped, and a build
from the checked lock does not trigger the leak. Anyone who built CodeFlow
from source without `--locked` on or after 2026-10-03 should treat that build
output as possibly holding environment values; the release note says so. Dated
historical records, released changelog entries and test fixtures that quote
the old command stay as written. Non-goal: other dependency upgrades.

## Outcome

After this merges, contributors can open pull requests into the EPC-022 line
and the checkpoint pull request into `main` without the dependency audit
failing on RUSTSEC-2026-0418.

## Deliverables

- the lockfile fix: `Cargo.lock`
- the release note: `changelog.d/TSK-1069.md`
- the locked source-install commands: `README.md`, `docs/adoption.md`, `docs-portal/figures/adoption/howto-install.json`
