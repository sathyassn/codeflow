# TSK-290: The git guard reads a sed script by sed's grammar

## Description

git-guard refuses read-only `sed` commands when a letter `w` appears
anywhere in the script (https://github.com/sathyassn/codeflow/issues/147). `sed_script_writes`
(`crates/codeflow-core/src/hooks/git_guard.rs:9446` at v3.1.0) treats every
`w` or `W` in the script as sed's write command, and `sed_unknown_dir_use`
(`:1175`) reads script words as paths, so both commands in the issue were
refused on 2026-10-12 under `git.hook_integrity`. This task reads a sed
script by sed's grammar: a command only in command position (after an
address, `;`, a newline or `{`) and the `w` flag of an `s` command, never a
letter inside an address regex, an `s` pattern or replacement, a `y`
operand or the text of `a`, `i` or `c`. It is its own task, not part of
TSK-286: it is a false positive in git-guard that blocks agents now and can
ship alone, while TSK-286 proves the deletion guard. It is a standalone
task on `main` and ships in CodeFlow 3.1.1; TSK-286 may reuse the reader
once it lands.

## Deliverables

- the sed script reader: a module under `crates/codeflow-core/src/security/` or in `crates/codeflow-core/src/hooks/git_guard.rs` (provisional)
- its users: git-guard's integrity and unknown-directory checks, and any other guard that reads sed scripts (`crates/codeflow-core/src/security/startup.rs`)
- tests: guard unit tests and a native sed differential test
- release note: `changelog.d/TSK-290.md`

## Acceptance Criteria

- AC-1 When a sed script has a `w` only inside an address regex, an `s`
  pattern or replacement, a `y` operand or `a`, `i` or `c` text, git-guard
  shall allow the command; evidence: both commands of issue 147 and one
  test per position.
- AC-2 A real write shall stay refused when it reaches an integrity path: a
  `w` or `W` command after an address or `;`, the `w` flag of `s`, a `-f`
  script file holding one, and `sed -i` on an enforcement file; evidence:
  a refusal test per form.
- AC-3 For each script in the fixture set, the files native GNU and BSD sed
  write shall equal the paths the reader reports; evidence: a differential
  test run on macOS and Linux.
- AC-4 A sed script argument shall not be read as a path in the
  unknown-directory check; evidence: the first command of issue 147 run
  from a folder the guard cannot read.
- AC-5 A script form the reader does not model shall be judged unproven and
  refused where its writes could reach an integrity path; evidence: a test
  for an unmodelled form.
- AC-6 When the installed build's git-guard judges the two commands of
  issue 147, it shall allow them, and it shall refuse `sed -n '1w
  .codeflow/policy.json' README.md` (journey); evidence: a CLI journey
  through `codeflow hook git-guard` in a fresh project.
