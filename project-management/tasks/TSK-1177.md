# TSK-1177: The App authority names the verdict identity and Mode B fails closed

## Description

Issue #279. Split from TSK-336 on 2026-11-01. The whole-PR review of PR 479 graded TSK-336 Very Hard (9: S2 2, S6 1, S7 1, C 2, X 1, R 2), and a Very Hard task is split before claim. TSK-336 keeps the foundation (the default branch's code judges every pull request); this task takes one outcome with the criteria that prove it, moved and not copied, each marked with its old number. The five pieces are TSK-336, TSK-1175, TSK-1176, TSK-1177 and TSK-1178.

A check bound to a job name under the Actions app id (15368) can be produced by any workflow in the repository. One authority job, only for `pull_request_target` into the default branch, is the only job that references `environment: codeflow-authority`; it mints a dedicated GitHub App's installation token inside the one step that creates the `authority:` check runs on the head SHA, and ruleset B (TSK-1080) pins those names to the App's id. Without the App (Mode B, the floor), the final step lists check runs and statuses of the trusted names and fails closed. The hosted report prints the content verdict and the authority line separately. AC-12 (the report line) is here and not with TSK-336 as the review proposed: it names "check identity: App `<id>` or Actions" and the host rules, which this task establishes, so TSK-336 would otherwise print an identity it does not yet produce.

Files shared by the five pieces (`codeflow-ci.yml`, `codeflow-policy.yml`, their installed copies and baselines, `ci.rs`): one writer at a time, as TSK-336's contract says; the Coordinator orders the writers. File sharing adds no scheduling dependency.

Outcome: **only the default branch's authority job, holding an App token confined to one step, creates the `authority:` check runs on the head SHA; without the App the final step fails closed on any other producer of a trusted name; and the hosted report prints the content verdict and the authority line separately.**

Non-goals: the verdict jobs themselves (TSK-336); ruleset writing (TSK-1080, complete).

## Outcome

after this merges, a verdict check on a pull request can be produced only by an identity the agent cannot hold, and without the App the check fails closed.
