# TSK-1093: Work claim adopts the agent's own checked-out task branch and publishes it

## Description

Source: issue #433 (CodeFlow 3.1.1, filed 2026-10-30 by an adopter),
triaged the same day. An agent built an epic task ahead of its claim on
the local branch `task/TSK-150-<slug>`, never pushed. Run from that
worktree, `codeflow work claim TSK-150` refused: "TSK-150 is already
claimed by a visible branch: task/TSK-150-...", naming the branch the
agent was on. No remote branch carried the task, the name was the one
the claim would create, and the branch contained the target's tip. The
refusal names no route, so an agent either stops or works around the
claim's create-only push.

Read on the line tip `b7ae7c6a6`, in
`crates/codeflow-core/src/workgraph/readiness.rs`:

- `visible_work_branches` (`:350`) counts local branches as claims, as
  `.codeflow/rules/worktrees.md:66` documents.
- `claim_on` (`:1743`) drops the current branch from the carriers only
  on the standalone route (`standalone_claim_base`, `:1709`; the
  `retain` at `:1787`), which renames a branch holding a new standalone
  record. An epic task, or a record already on the target, never takes
  it.
- Every other carrier that has not landed refuses (`:1793`).
- `work start` already reports other carriers as information, not a
  refusal (`crates/codeflow-cli/src/cmd/work.rs:408`).

Rule: `work claim` adopts the current branch only when all of these
hold, and refuses otherwise with the reason and a route:

- the branch is checked out in the worktree the command runs in;
- it is the only carrier of the id among local branches and every
  remote the claim reads; any remote carrier refuses;
- its name is the name the claim would create;
- it is not a protected branch;
- it contains the target's tip, or the `--on` pins;
- readiness is judged on the target's record, as for a new claim.

It then publishes the branch with the existing create-only push
(`--force-with-lease=<destination>:`, `readiness.rs:1815`) and prints
"adopted" instead of "created". A lost push race refuses and leaves
local and remote refs unchanged.

The claim is the mark other agents trust to see who holds a task, so the
review carries the `cf-security-reviewer` checklist. Today's refusal
stays when another clone has pushed a branch for the id or a second
local branch carries it.

## Outcome

After this merges, an agent that built a task on its own unpushed task branch ahead of the claim can claim the task from that branch and publish it as the claim, while every other carrier still refuses.

## Deliverables

- the adoption rule: `claim_on` and its helpers in `crates/codeflow-core/src/workgraph/readiness.rs`, and the claim output in `crates/codeflow-cli/src/cmd/work.rs`
- tests: unit tests beside `claim_on` and CLI fixtures in `crates/codeflow-cli/tests/`
- docs: `docs/cli.md` (`work claim`) and `.codeflow/rules/worktrees.md` with its managed source and baseline copies
- release note: `changelog.d/TSK-1093.md`

## Acceptance Criteria

- AC-1 When the only carrier of a task's id is the branch checked out in the current worktree, with the name the claim would create, not protected and containing the target's tip, `codeflow work claim` shall adopt it, publish it create-only and print "adopted"; evidence: CLI fixtures for an epic task and for a record already on the target, each with and without an `origin` remote, refused before the change with "already claimed by a visible branch" and adopted after. (serves EPC-022 AC-174)
- AC-2 `codeflow work claim` shall still refuse, naming the reason and a route, when another local branch carries the id, any remote branch carries it, the carrying branch is checked out in another worktree, its name differs from the claim's, it is protected, or it does not contain the target's tip; evidence: one negative fixture per case. (serves EPC-022 AC-174)
- AC-3 When the create-only push loses a race to another claim, `codeflow work claim` shall refuse and leave the local branch and the remote unchanged; evidence: a fixture that creates the remote branch between the check and the push. (serves EPC-022 AC-174)
- AC-4 `docs/cli.md` and `.codeflow/rules/worktrees.md` (near `:66`) shall state the adoption rule and its refusals; evidence: the doc diff and `codeflow validate --docs`.
