# TSK-268: macOS temporary paths match the OS-resolved working directory

## Description

The test suite passes on macOS for CodeFlow 3.1.0. On main 09f52c88f the one
failing test is `push::clears_registry_root_unreadable` in
`crates/codeflow-cli/tests/remedy_clearing/push.rs`. The product names the
file it could not inspect from `std::env::current_dir()`
(`touch_registry_best_effort`, `crates/codeflow-cli/src/cmd/mod.rs`), and on
macOS the OS reports the resolved `/private/var/...` path for a temporary
folder. The test built the expected path from the unresolved `/var/...`
tempfile path and compared without resolving it, so it passed on Linux and
Windows and failed on macOS. Hosted CI runs only Linux and Windows, so only a
local macOS gate sees it. The product behaviour is right and stays: the
registry already stores canonical roots, and the warning names the path the
product actually inspected. The fix is to the test expectation, plus a sweep
of the other tests that compare a tempdir path with a path the product
derives from the working directory or from `canonicalize`.

Non-goal: no product change, no change to the registry or the warning text.
Release impact is none (test only).

## Deliverables

- the corrected test expectation: `crates/codeflow-cli/tests/remedy_clearing/push.rs`
- any other macOS-only path comparison the sweep finds: the same PR, in its test file
- this record with the sweep result: `project-management/tasks/TSK-268.md`
