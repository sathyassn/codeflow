# TSK-1035: A doubled slash in a path is judged like its plain spelling, and the essential gate passes

## Description

Found by TSK-435 (PR 364), diagnosed by its Codex review
(`.worktrees/tsk-435/target/review-TSK-435-codex-01.md`, GPT-6 Astra,
session `01a17fcb-712f-7450-901f-d6a412fbb4bc`, "TMPDIR assessment") and
reproduced for this record. This repository's essential gate target
creates its run directory with `mktemp -d "${TMPDIR:-/tmp}/cf.XXXXXX"`
and exports it as `TMPDIR` (`.codeflow/test-config.json:151`). On macOS
the default `TMPDIR` ends in `/`, so the exported path holds `//`
(`.../T//cf.ab12cd`). Under such a `TMPDIR`, 12 essential tests fail;
with a plain path they pass. Every local essential run on a macOS host
is red, and the failures hide real regressions in the same suites.

One of the 12 is a real protection miss, not a spelling difference:
`security/outward.rs:549` normalizes the candidate path, while
`security/interpreter.rs:152` (`secret_path_spelling`) strips an
unnormalized `HOME` prefix, so a `HOME` spelled with a doubled slash can
let a secret path read through the guard (`refusal_journey/secret_paths.rs:67`).
Paths the guards compare reach adopters from their own environment, so
this is a security defect wherever a root is spelled with `//`.

Codex's split of the 12, confirmed by the reproduction below:

| Group | Tests | Cause named by the review |
|---|---|---|
| Absent-worktree handling (5) | 4 `checkout_identity`, `remedy_clearing` `guards::clears_absent_worktree` | `crates/codeflow-core/src/hooks/repo.rs:993` rejects repeated separators, then canonicalization fails at `hooks/git_discard.rs:224`; git-guard refuses `git worktree prune` under `git.discard_uncommitted` instead of printing the absent-worktree remedy |
| Path-spelling assertions (6) | 3 `target_repository`, 3 `test_gate_cli` | tests compare the original spelling with normalized diagnostics: `hooks_cli/target_repository.rs:682`, `:771`, `test_gate_cli.rs:1276`, `:1602`, `:1658` |
| Secret path (1) | `refusal_journey` `secret_paths` | the unnormalized `HOME` prefix above |

Reproduction (2026-10-27, line tip `5f2fe3827`, test binaries built in
the planning worktree, run outside the sandbox because one test file's
name holds `secret`):

```text

  refusal_journey secret_paths (1): installed_hooks_refuse_secret_path_spellings_without_execution

    lock_status_reads_both_holder_records_without_running_or_changing_them,
    quick_default_class_controls_undeclared_targets_and_keeps_explicit_light_work
```

Outcome: **a guard judges a path with a doubled slash, in the candidate
or in the root it compares against (`HOME`, a checkout, a worktree, a
configured store), exactly as its plain spelling, failing closed when it
cannot; absent-worktree handling accepts a repeated separator; the
tests compare normalized paths; and the essential gate's run directory
holds no `//`, so the essential suite passes on macOS.**

Rules:

- Both sides of every prefix or containment comparison are normalized
  the same way before comparing; a path that cannot be normalized
  refuses.
- The sibling sweep covers every comparison against `HOME` or another
  root in `crates/codeflow-core/src/security/` and `src/hooks/`, not
  only the sites above.
- The test-config fix (no `//` in the run directory) does not replace
  the product fix; a regression test sets a `//` root directly.

Order: build after TSK-1002 (PR 346), which has uncommitted edits in
`security/interpreter.rs` and reshapes the same guard code. TSK-1002 is
standalone and its record is not on this line, so `depends_on` cannot
name it yet; add `depends_on: [TSK-1002]` and unblock this task in the
EPC-022 amendment that does the same for TSK-1022 once PR 346 lands.

Non-goals: other spellings the guard tasks already own (symbolic links,
case, `~` forms).
