# TSK-1402: Every protected path set in the edit guard keeps its resolved spelling or refuses

## Description

The edit guard compares a target with several sets of protected paths, each
held in two spellings: the path as written and its resolved form. In some of
these sets, when the resolved form of a protected entry cannot be made, the
entry keeps only its written spelling and the guard does not refuse. The
TSK-1400 sibling sweep found this class in two sets that are not covered by
TSK-1400's own fix, and one more set where it is deliberate, behind a
reduced-coverage warning and a test that pins it. This task makes every
protected set either keep a resolved spelling or refuse the edit when it
cannot make one, and records a decision for the deliberate case. The same
trace found that the guard's shared cache of resolved paths can make
resolution succeed or fail depending on what was resolved earlier in the
same invocation, so whether the guard fails closed can depend on call order;
this task makes that result independent of order. It is a
security change and needs a cross-lineage review with the security checklist.
Non-goal: the site TSK-1400 fixes, which lands on its own.

## Outcome

After this merges, an operator can rely on the edit guard refusing an edit to
a protected path whatever spelling reaches it and in whatever order paths
are checked, or saying why one protected
set accepts reduced coverage.

## Deliverables

- the guard change and its tests: `crates/codeflow-core/src/hooks/` (the edit guard)
- the decision for the deliberate case, with its reason: this record's Closeout and the guard's comment at that site

- AC-1 When the edit guard builds a set of protected paths and cannot make the resolved form of an entry, it shall either keep a resolved spelling for that entry or refuse the edit, naming the entry and the reason; it shall never keep only the written spelling and allow the edit. The one exception is the set AC-2 decides on, and only on the terms AC-2 records. Evidence: one fail-before and pass-after test for each of the two sets the TSK-1400 sweep found, and for each further set AC-3 finds with the same gap, each showing an edit through the other spelling refused after the change.
- AC-2 The set where this reduced coverage is deliberate shall either be brought under AC-1 or keep its behaviour with a recorded reason, a warning that names the reduced coverage, and its pinning test; evidence: the decision and its reason in this record's Closeout, and the test that pins the chosen behaviour.
- AC-3 Every other place the edit guard builds a protected set from resolved paths shall be swept for the same class and listed, each with the test that covers it or the reason none is needed; evidence: the list in the pull request body.
- AC-4 Within one guard invocation, resolving a path shall give the same result, the same resolved path or the same refusal, whatever paths were resolved before it; a result cached for one kind of lookup shall never answer another kind; evidence: a test that resolves the same path cold and after an earlier resolution that previously changed its outcome, failing before the change (a cold refusal, a warm success) and passing after.
