# TSK-1106: The shipped presets deny secret-bearing files by kind and keep source readable

## Description

The shipped Claude presets (`assets/base/settings/default.json`,
`acceptEdits.json`, `bypass-sandboxed.json`, mirrored in
`crates/codeflow-core/src/security/actions.json`) deny `Read(**/*secret*)`
and `Read(**/*credentials*)` and try to exempt source code with negated
entries such as `Read(!**/*secret*.rs)`. On 2026-10-31 the TSK-397 builder
found that the Read tool still denied
`crates/codeflow-cli/tests/refusal_journey/secret_paths.rs`: the negated
entries do not take effect as permission rules, while the sandbox read list
does honour them (queue item 34). An adopter whose source names contain
`secret` or `credentials` (a secrets module, a credentials parser, their
tests) cannot read those files through the editor tools; two TSK-397 test
edits waited on the operator for this reason. The fix replaces the broad
name deny with patterns that name secret-bearing file kinds, after the
Claude Code permission-rule semantics are verified against the current
documentation and a live probe. Non-goal: the sandbox read list and the
hooks' secret-path rules (TSK-335, TSK-1002) are unchanged; only the editor
permission rules change, and no deny that covers a real secret file is
dropped.

## Outcome

After this merges, an agent under the shipped presets can read a source file whose name contains secret or credentials, and still cannot read a secret-bearing file such as `.env`, a key or a credentials JSON.

## Deliverables

- the preset rules: `assets/base/settings/default.json`, `assets/base/settings/acceptEdits.json`, `assets/base/settings/bypass-sandboxed.json`, `crates/codeflow-core/src/security/actions.json`
- tests: the preset agreement test and a new permission-rule fixture under `crates/codeflow-core/tests/` that lists each kind as readable or denied
- docs: `docs/harness-posture.md` and `docs/policy-reference.md` (the secret-bearing kinds the presets deny), `docs/troubleshooting.md`

## Acceptance Criteria

- AC-1 Before any change, the builder shall research editor permission rules for secret-bearing files broadly: the Claude Code permission-rule documentation for `Read` deny patterns and whether negation exists (fetched, with the date), a live probe of a `!` entry in a scratch project, the sandbox read list's own semantics and why it differs, the full list of secret-bearing kinds the hooks already refuse (TSK-335, TSK-1002 and `docs/policy-reference.md:215-225`), what other harnesses' presets (Codex, Grok) do with the same names, and adjacent concerns (backup copies, archives, a secret-bearing file inside `tests/fixtures/`); and shall record the findings with sources and the chosen scope before anything else changes; evidence: the Findings section, committed before the first code change in the PR. Listed first because it runs first (the operator's rule of 2026-10-27).
- AC-2 The presets and `actions.json` shall deny `Read` on secret-bearing kinds by name and extension (`.env` and `.env.*`, `*.pem`, `*.key`, `*.p12`, `*.pfx`, `*.jks`, `*.keystore`, `*credentials*.json`, `*secret*.json`, `*secret*.yaml`, `*secret*.yml`, `*secret*.toml`, `*.netrc`, the SSH and cloud credential paths the presets name today, and every kind AC-1's research adds) and shall no longer deny a source file by the words `secret` or `credentials` alone; evidence: a fixture that reads `*secret*.rs`, `*credentials*.py` and `*secret*.md` (allowed) and `.env`, `x.pem` and `*secret*.json` (denied) under each preset. (serves EPC-022 AC-184)
- AC-3 The three presets and `actions.json` shall agree on the deny set, checked by the existing agreement test extended to the new kinds; evidence: the test. (serves EPC-022 AC-184)
- AC-4 The TSK-397 edits to `secret_paths.rs` shall no longer need an operator step: the file shall be readable through the editor tools under the shipped preset in this repository; evidence: a read of that path recorded in the PR body with the preset in force.
- AC-5 `docs/harness-posture.md` and `docs/policy-reference.md` shall list the kinds and say that a source file named for secrets is readable and that the hooks' secret rules are unchanged; evidence: the doc diff and `codeflow validate --docs`.
- AC-6 (journey) With the installed build, a fresh `codeflow init --standard` project with a `src/secrets.rs`, a `tests/credentials_test.py`, a `.env` and a `config/credentials.json` shall let the agent read the first two and refuse the last two through the Read tool; evidence: the journey output.
