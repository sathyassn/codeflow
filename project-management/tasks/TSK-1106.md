# TSK-1106: The shipped presets deny secret-bearing files by kind and keep source readable

## Description

The shipped Claude presets (`assets/base/settings/default.json`,
`acceptEdits.json`, `bypass-sandboxed.json`, mirrored in
`crates/codeflow-core/src/security/actions.json`) deny `Read(**/*secret*)`
and `Read(**/*credentials*)` and try to exempt source code with negated
entries such as `Read(!**/*secret*.rs)`. On 2026-10-31 the TSK-397 builder
found that the Read tool still denied
`crates/codeflow-cli/tests/refusal_journey/secret_paths.rs`: the negated
entries do not take effect as permission rules, while the sandbox read list
does honour them (queue item 34). An adopter whose source names contain
`secret` or `credentials` (a secrets module, a credentials parser, their
tests) cannot read those files through the editor tools; two TSK-397 test
edits waited on the operator for this reason. The fix replaces the broad
name deny with patterns that name secret-bearing file kinds, after the
Claude Code permission-rule semantics are verified against the current
documentation and a live probe. Non-goal: the sandbox read list and the
hooks' secret-path rules (TSK-335, TSK-1002) are unchanged; only the editor
permission rules change, and no deny that covers a real secret file is
dropped.

## Outcome

After this merges, an agent under the shipped presets can read a source file whose name contains secret or credentials, and still cannot read a secret-bearing file such as `.env`, a key or a credentials JSON.

- the preset rules: `assets/base/settings/default.json`, `assets/base/settings/acceptEdits.json`, `assets/base/settings/bypass-sandboxed.json`, `crates/codeflow-core/src/security/actions.json`
- tests: the preset agreement test and a new permission-rule fixture under `crates/codeflow-core/tests/` that lists each kind as readable or denied
- docs: `docs/harness-posture.md` and `docs/policy-reference.md` (the secret-bearing kinds the presets deny), `docs/troubleshooting.md`
