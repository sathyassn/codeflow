# TSK-1495: The guard's ** expansion follows symbolic links as the shells do

## Description

Split from TSK-1053 on 2026-11-13 (coord/catalog's plan `tsk-1053-plan.md`, decision D1, with the Director's placement on the EPC-022 line). TSK-1053 tracked this as its AC-15, added 2026-10-29 from Fable review 08 of PR 346 (TSK-1002). The work is separate code and separate proof from TSK-1053's runner grammars, so it is its own task.

The guard expands `**` in a word to decide which files a command reads. Its walk (`crates/codeflow-core/src/hooks/git_guard.rs:3376-3410` at PR 346's head `a2e3efd57`, `expand_components` today) passes a linked directory on to the next component. zsh and Bash with `globstar` do not descend through a symbolic link to a directory during `**` matching, so the guard expands files the shells would not, and refuses lines the shells would run safely. This task makes the guard's `**` expansion match the shells' rule for links.

Non-goals: TSK-1053's runner grammars; any change to what counts as a protected file.

## Outcome

After this merges, a `**` word that the shells expand to no protected file is allowed even when the tree holds a symbolic link to a directory inside a protected store, and a `**` word the shells would expand to a protected file still refuses.

## Deliverables

- the fix: the guard's `**` expansion in `crates/codeflow-core/src/hooks/git_guard.rs`
- tests: guard tests per link case beside the existing expansion tests
- findings: a `## Findings` section in this record with each shell's recorded behaviour
