# TSK-1452: The rulesets follow the transition, and main's relaxed checks return on their conditions

## Description

Under ADR-0102 a task of a marked epic is merged onto its line and pushed with no pull request, and a line push starts no hosted run (TSK-1451). Ruleset 25435656 requires, on every `integration/**` commit, checks that only pull request runs produce, so the server refuses that push. The operator also ruled on 2026-11-11 that `main`'s CI checks are relaxed for now, "as long as they're locally run and successful", and put back afterwards. This task covers the two ruleset changes and the relaxation of `main`'s checks together: all are repository settings the operator applies with one coord/ci script that has a read-only check mode and a restore mode, and each needs its return condition in the same record. The relaxation replaces the transition plan's earlier line that `main` stays fully gated. Non-goal: the workflow trigger changes, which TSK-1451 owns.

coord/ci keeps the list of relaxed items. Its eight items, each with the cover while it is off and its return condition:

| # | Switched off | Cover while off | Comes back when |
|---|---|---|---|
| 1 | codeflow-ci runs on a push to a line | the local evidence run on each landing candidate before its merge; the task landing check at the merge | EPC-055 ships its line gate |
| 2 | codeflow-registry and codeflow-release runs on a push to a line | `commit standards` runs `codeflow ids check` on every pull request; `codeflow ci` runs in the local evidence; release state still runs on `main`'s push | as item 1 |
| 3 | the Linux gates and the reduced Windows tier on pull requests into a line | the builder's local gate and the local evidence on the landing candidate; the independent review; the short checks | EPC-055 ships its line gate, and the guard fixes are on `main` |
| 4 | the Linux gates and Windows on pull requests into `main` | the local evidence on the pull request head, with its block in the body; the task landing check before the operator is asked to merge; a manual dispatch runs the full set on demand | the open backlog into `main` is merged, and EPC-057's CI templates and the guard fixes are on `main`; the operator decides |
| 5 | Windows on any pull request, and the daily Windows workflows for `main` and every line | not coverable locally, since the host is macOS; codeflow-ci runs once a day on `main`, not blocking, with every Windows job, and on manual dispatch; a Windows failure there is triaged the same day | with item 4 |
| 6 | `codeflow gates` and `windows` leave the required list of the five pre-rule lines (ruleset 25435656); `release impact` stays only if it runs and reports on every line pull request (AC-1) | those jobs no longer run on line pull requests (items 3 and 5) | with the jobs, at item 3's condition |
| 7 | `codeflow gates` and `windows` leave `main`'s required list (ruleset 24379074) | as item 4 | with item 4 |
| 8 | lines cut under the new rule carry history protection only (ruleset "Integration line history": no force push, no deletion) | the task landing check and the local candidate gate; the epic's one pull request into `main` re-gates the whole line | EPC-055 ships its line gate |

## Outcome

After the operator applies it, new lines carry history protection only, pre-rule lines keep only required checks that always run on a line pull request, `main` accepts merge commits only if the operator approves that change, and `main`'s relaxed checks no longer block a merge that carries passing local evidence; each change is put back by the same script when its return condition is met.

## Deliverables

- the ruleset and relaxation changes: repository settings, applied by the operator with coord/ci's script (kept in the CodeFlow workspace, outside this repository)
- the list of relaxed items with their cover and return conditions: this record's Description, from coord/ci's list
- the live values read before and after each write, and the restore read-back: this record's Closeout
- the dated restore entry: the workspace release plan

## Acceptance Criteria

- AC-1 The line rulesets shall change in this order: (a) a ruleset "Integration line history" on `refs/heads/integration/**` with `non_fast_forward` and `deletion` only; (b) ruleset 25435656 narrowed by exact ref to the five pre-rule lines, its required set limited to checks that always run and report on every line pull request, else history-only. Hard preconditions: the guard fixes TSK-1455, TSK-1456, TSK-1457, TSK-1458, TSK-1460, TSK-1461, TSK-1463 and TSK-1344 on `main`, and the interim task landing check committed; evidence: script output with the live values before and after.
- AC-2 If the operator approves it, ruleset 24379074 `allowed_merge_methods` shall become `[merge]`; evidence: script output.
- AC-3 Each relaxed item shall name the hosted check, how it is relaxed (removed from the required set or bypassable), the local check that covers it (the local full gate and TSK-1449's scans, and until TSK-1449 ships, the workspace's local security scan script), and its return condition. A pull request into `main` during the relaxation shall cite that local evidence in its body; evidence: the list in the Description and the pull request bodies.
- AC-4 The script shall have `--check`, which reads live values and writes nothing, and `--restore`, which writes back the values recorded before the change, and it shall refuse on any live value that differs from the recorded one; evidence: dry runs of both modes, and a cross-lineage review of the script.
- AC-5 Return conditions: AC-1 (a) is permanent; AC-1 (b) ends when the last pre-rule epic closes, and ruleset 25435656 is then deleted; each relaxed `main` check returns when its condition in the list is met, and in any case at the operator's word ("put things back after"). The restore shall be run, read back live, and recorded with a dated entry in the release plan; evidence: the restore output and the dated entry. Until then this task stays open, with the restore as its remaining criterion.
- AC-6 No required check on `main` or a line shall be one that can pass by being skipped; evidence: the live read after each write.
