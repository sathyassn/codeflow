# TSK-1452: The rulesets follow the transition, and main's relaxed checks return on their conditions

## Description

Under ADR-0102, proposed, a task of a marked epic is merged onto its line and pushed with no pull request, and a line push starts no hosted run (TSK-1451). Ruleset 25435656 requires, on every `integration/**` commit, checks that only pull request runs produce, so the server refuses that push. The operator also ruled on 2026-11-11 that `main`'s CI checks are relaxed for now, "as long as they're locally run and successful", and put back afterwards. This task covers the two ruleset changes and the relaxation of `main`'s checks together: all are repository settings the operator applies with one coord/ci script that has a read-only check mode and a restore mode, and each needs its return condition in the same record. The relaxation replaces the transition plan's earlier line that `main` stays fully gated. Non-goal: the workflow changes, which TSK-1451 owns, including the temporary gate conditions that switch off items 4 and 5; this task's restore puts those conditions back.

coord/ci keeps the list of changed items; the numbers below follow it. The items fall in two groups, and the restore puts back only the second.

The line placement, which this task's restore never puts back. Items 1 and 2 are permanent, by the operator's ruling of 2026-11-11. Items 3, 6 and 8 hold by the Director's ruling until EPC-055's line gate ships; what follows it is the placement ADR-0102 proposes:

| # | Change | Cover |
|---|---|---|
| 1 | codeflow-ci starts no run on a push to a line (TSK-1451) | the local evidence run on each landing candidate before its merge; the task landing check at the merge; EPC-055's line gate once it ships |
| 2 | codeflow-registry and codeflow-release start no run on a push to a line (TSK-1451) | `commit standards` runs `codeflow ids check` on every pull request; `codeflow ci` runs in the local evidence; release state still runs on `main`'s push |
| 3 | the Linux gates and the reduced Windows tier no longer run on pull requests into a line, and the daily Windows workflow no longer runs for any line (TSK-1451) | the builder's local gate and the local evidence on the landing candidate; the independent review; the short checks; every Windows job on the pull request into `main`. A daily run on a line comes back only on an operator ruling |
| 6 | ruleset 25435656, on the five pre-rule lines: `codeflow gates` and `windows` leave the required list, and `secret scan` and `security review` join `commit standards` and `release impact` on it | every check left on it runs and reports on every line pull request; the ruleset is deleted when the last pre-rule epic closes (AC-5) |
| 8 | lines cut under the new rule carry history protection only (ruleset "Integration line history": no force push, no deletion) | the task landing check and the local candidate gate; the epic's one pull request into `main` re-gates the whole line |

Temporary, under the operator's ruling on `main`'s checks. Each returns on its condition, and in any case at the operator's word:

| 5 | the separate daily Windows workflow for `main` | not coverable locally, since the host is macOS; codeflow-ci runs once a day on `main`, not blocking, with every Windows job, and on manual dispatch; a Windows failure there is triaged the same day | with item 4 |
| 7 | `codeflow gates` and `windows` leave `main`'s required list (ruleset 24379074) | as item 4 | with item 4 |

## Outcome

After the operator applies it, new lines carry history protection only, pre-rule lines keep only required checks that always run on a line pull request, `main` accepts merge commits only if the operator approves that change, and `main`'s relaxed checks no longer block a merge that carries passing local evidence; each temporary relaxation is put back by the same script when its return condition is met, and that restore leaves the line placement in place.

## Deliverables

- the list of relaxed items with their cover and return conditions: this record's Description, from coord/ci's list
- the live values read before and after each write, and the restore read-back: this record's Closeout
- the dated restore entry: the workspace release plan

## Acceptance Criteria

- AC-1 The line rulesets shall change in this order: (a) a ruleset "Integration line history" on `refs/heads/integration/**` with `non_fast_forward` and `deletion` only; (b) ruleset 25435656 narrowed by exact ref to the five pre-rule lines, its required set limited to checks that always run and report on every line pull request (`commit standards`, `release impact`, `secret scan` and `security review`), else history-only. Preconditions: the local evidence command and the interim task landing check are committed in the workspace (the delivery order's step 2), and the required sets are cut before TSK-1451's workflow change merges, so no required check ever reports as skipped; evidence: script output with the live values before and after.
- AC-2 If the operator approves it, ruleset 24379074 `allowed_merge_methods` shall become `[merge]`; evidence: script output.
- AC-3 Each relaxed item shall name the hosted check, how it is relaxed (removed from the required set or bypassable), the local check that covers it (the local full gate and the local security scans, both inside the local evidence run), and its return condition. A pull request into `main` during the relaxation shall cite that local evidence in its body; evidence: the list in the Description and the pull request bodies.
- AC-4 The script shall have `--check`, which reads live values and writes nothing, and `--restore`, which writes back the values recorded before the change for the temporary items only (4, 5, 7 and 9) and never touches the line items (1, 2, 3, 6 and 8), and it shall refuse on any live value that differs from the recorded one; evidence: dry runs of both modes, a `--check` read after the restore dry run showing, for each event in ADR-0102's table, the jobs it runs and the required set on `main`, the pre-rule lines and new lines, and a cross-lineage review of the script.
- AC-5 Return conditions: items 1 and 2 and AC-1 (a), the history rules, are permanent; items 3 and 8 are never put back by this task and hold until EPC-055's line gate ships; AC-1 (b), item 6, ends when the last pre-rule epic closes, and ruleset 25435656 is then deleted; each temporary item returns when its condition in the list is met, and in any case at the operator's word ("put things back after"). The restore shall be run, read back live, show the line items unchanged and every temporary item back, and be recorded with a dated entry in the release plan; evidence: the restore output, the live read and the dated entry. Until then this task stays open, with the restore as its remaining criterion.
- AC-6 No required check on `main` or a line shall be one that can pass by being skipped; evidence: the live read after each write.
