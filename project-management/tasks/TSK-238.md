# TSK-238: Text that is not UTF-8 no longer stops present or the test gate

## Description

Issue 79: text from the operating system or git that is not valid UTF-8 still
stops CodeFlow in four places, the browser identity reads of `present` on
macOS, Linux and Windows and the tracked-file snapshot of the test gate. This
task settles one rule for OS-supplied text and applies it to every site: decode
lossily or compare bytes where the value is only compared or displayed, and
fail only where a wrong value would change a security or identity decision,
with the reason in a comment at that site. A decode of file content (JSON,
TOML, Markdown, blobs) is a format contract and is not in scope. Effect on
adopting projects: a repository with a non-UTF-8 file name can run
`codeflow test`, and a guard sees a non-UTF-8 name as the work it is.
Non-goal: the pre-push and reference-transaction stdin reads, which stay
strict by a recorded, test-pinned decision.

## Acceptance Criteria

- AC-1 When the browser identity of one recorded process is read on macOS, Linux or Windows and its text is not valid UTF-8, the read judges identity from the exact bytes of its arguments (Linux, macOS) and fails only for a bound, never for the encoding; on Windows the decoded text is refused only when the profile path holds U+FFFD too (`non_utf8_identity_*` tests in `browser.rs`).
- AC-2 When the Windows process inventory carries text that is not valid UTF-8, the inventory is still parsed and each process is judged on its arguments (`non_utf8_windows_inventory_*` tests in `browser.rs`).
- AC-3 When the git index of a project holds a path that is not valid UTF-8, the test gate snapshot of tracked files includes it and `codeflow test` runs (`tracked_snapshots_a_path_that_is_not_utf8` in `delivery.rs`; journey `a_tracked_path_that_is_not_utf8_does_not_stop_the_gate` in `test_gate_cli.rs`) (journey).
- AC-4 When git output the gate selects from is not valid UTF-8, selection stays strict and runs every target, never fewer, and says why in a comment (`git_output_that_is_not_utf8_selects_every_target`).
- AC-5 When a dirty, untracked or ref name is not valid UTF-8, the discard guard counts it instead of failing with uncertainty and still refuses a discard that would lose it; a worktree name it cannot read still refuses (`git_discard.rs` tests).
- AC-6 When the effective git configuration holds a value that is not valid UTF-8, the remote update check reads the remotes it needs; a config key that is not valid UTF-8 never sets another remote's option, and a remote name that is not valid UTF-8 refuses the command and the policy read instead of being skipped (`ref_authority.rs`, `landed_policy.rs` tests).
- AC-7 Each site that stays strict states why in a comment and has a test with non-UTF-8 input, and the rule is written down once (`docs/architecture.md`, the comments listed in the PR). A worktree whose folder name is not valid UTF-8 keeps its `config.worktree` and its checkout protected (`edit_guard.rs` tests).
