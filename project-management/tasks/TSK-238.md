# TSK-238: Text that is not UTF-8 no longer stops present or the test gate

## Description

Issue 79: text from the operating system or git that is not valid UTF-8 still
stops CodeFlow in four places, the browser identity reads of `present` on
macOS, Linux and Windows and the tracked-file snapshot of the test gate. This
task settles one rule for OS-supplied text and applies it to every site: a
name is read once as exact bytes (`GitName`), shown with an escape for each
invalid byte, compared and matched as bytes, and refused where a rule needs
text, so a lossy spelling never decides anything. A site that stays strict
says why in a comment, and a source scan lists each remaining lossy decode
with its reason. A decode of file content (JSON,
TOML, Markdown, blobs) is a format contract and is not in scope. Effect on
adopting projects: a repository with a non-UTF-8 file name can run
`codeflow test`, and a guard sees a non-UTF-8 name as the work it is.
Non-goal: the pre-push and reference-transaction stdin reads, which stay
strict by a recorded, test-pinned decision.

## Acceptance Criteria

- AC-1 When the browser identity of one recorded process is read on macOS, Linux or Windows and its text is not valid UTF-8, the read judges identity from the exact bytes of its arguments (Linux, macOS) and fails only for a bound, never for the encoding; on Windows the decoded text is refused only when the profile path holds U+FFFD too (`non_utf8_identity_*` tests in `browser.rs`).
- AC-2 When the Windows process inventory carries text that is not valid UTF-8, the inventory is still parsed and each process is judged on its arguments (`non_utf8_windows_inventory_*` tests in `browser.rs`).
- AC-3 When the git index of a project holds a path that is not valid UTF-8, the test gate snapshot of tracked files includes it and `codeflow test` runs (`tracked_snapshots_a_path_that_is_not_utf8` in `delivery.rs`; journey `a_tracked_path_that_is_not_utf8_does_not_stop_the_gate` in `test_gate_cli.rs`) (journey).
- AC-4 When git output the gate selects from is not valid UTF-8, selection stays strict and runs every target, never fewer, and says why in a comment (`git_output_that_is_not_utf8_selects_every_target`).
- AC-5 When a dirty, untracked or ref name is not valid UTF-8, the discard guard counts it instead of failing with uncertainty and still refuses a discard that would lose it; a worktree name it cannot read still refuses (`git_discard.rs` tests).
- AC-6 When the effective git configuration holds a value that is not valid UTF-8, the remote update check reads the remotes it needs; a config key that is not valid UTF-8 never sets another remote's option, and a remote name that is not valid UTF-8 refuses the command and the policy read instead of being skipped (`ref_authority.rs`, `landed_policy.rs` tests).
- AC-7 Each site that stays strict states why in a comment and has a test with non-UTF-8 input, and the rule is written down once (`docs/architecture.md`, the comments listed in the PR). A worktree whose folder name is not valid UTF-8 keeps its `config.worktree` and its checkout protected (`edit_guard.rs` tests).
- AC-8 When a checked-out branch, a linked worktree or a task branch has a name that is not valid UTF-8, it is read as exact bytes and never dropped: a protected branch does not read as detached, a worktree keeps its checkout, a task branch is still seen as work, two names that differ only in an invalid byte never read as one (`GitName`), `codeflow integrate` refuses a checkout it cannot restore, a target worktree is found from git's files at its exact path, release-check paths are keyed by their exact bytes, advertised remote names stay distinct and an SSH command that is not UTF-8 refuses the query, and a symlink target or repository folder in the gate snapshot is hashed by its exact bytes (`repo.rs`, `git/mod.rs`, `root_checkout_tests.rs`, `readiness.rs`, `work_start.rs`, `integrate.rs`, `release_line_tests.rs`, `remote_query.rs`, `acceptance_cli.rs`, `delivery.rs` tests).
- AC-9 When a name from git or the operating system feeds a decision, it is read as exact bytes through one layer (`GitName` in `git/name.rs`), and a lossy decode is used only to show it: decisions compare bytes, use `rule_text()` or refuse. This covers the hook plane, root checkout, claims and readiness (remote names), lifecycle and work-start tree walks (a directory that is not UTF-8 no longer stops them), the `git log -z` parser, release-check paths, the CI inventory and name-status parsers, and a source scan fails on a new lossy decode that is not listed with its reason (`name.rs`, `name_decode_scan.rs`, and the tests beside each site).

- AC-10 When an existing input (policy, project settings, repository metadata, environment value, script, remote answer) cannot be read, decoded or parsed, or the process that reads it cannot run or fails, the hook plane and the guards refuse or report unproven and never select a default; absence is proven through every ancestor, so a dangling link at the file or an ancestor refuses (`proven_absent` tests, `policy.rs`, `repo.rs`, `git_guard.rs`, `remote.rs`; the scan's scoped absence check; `r19_test_config_*` loader, gate and push-target regressions; `r20_unlaunchable_git_*`, `r20_*include_refuses_hook_queries`, `r20_registry_*` and CI acquisition regressions).
- AC-11 When a delimiter frames an input, it is removed once by the reader FRAMING_OWNERS names, and the deletion guard splits `xargs` and `parallel` input by the delimiter the command selects (`-0`, `-d`, quoted blanks, newline for `parallel`), so a path holding a blank is judged whole (`guard_forms.rs`, `name_decode_scan.rs`; `r19_xargs_*` clustered-option, replacement and unproven-option regressions).
