# TSK-392: The macOS case lookup stays fast in a crowded directory

## Description

Source: found while landing PR 235 (2026-10-17). The macOS case normalizer (`edit_guard::normalize_case`) reads the parent directory listing for every path component, so a crowded temp directory made the interpreter suite take 2025 seconds. TSK-386 removes the leak that crowded it; a guard that slows with directory size remains a cost for adopters with large directories.

Outcome: **a case-insensitive path lookup on macOS costs about the same in a directory of 50,000 entries as in one of 50.**

Measurement basis, fixed before implementation: the reference host is a macOS arm64 workstation of this repository's workspace; the workload is 1,000 lookups of a three-component path whose last parent holds 50 entries, then 50,000 entries; the threshold is a median 50,000-entry lookup no more than twice the 50-entry median. TSK-386 removes the leak that crowded the temp directory; this task first measures the residual after TSK-386 on that workload, and the result decides whether code changes.

First added to EPC-023 (4.1.0) on 2026-10-18; moved to EPC-022 (3.2.0) the same day after the Codex review of PR 249, under the operator's rule that every security gap and every defect that forces an adopter workaround or blocks work belongs in 3.2.0.

## Deliverables

## Acceptance Criteria

- AC-1 The lookup shall return the same result as today for every existing test case, including case variants and missing components; evidence: the existing tests. (serves EPC-022 AC-86)
- AC-2 On the reference workload, the median 50,000-entry lookup shall be no more than twice the 50-entry median; evidence: the measurement before and after, on the same host, with the residual measured after TSK-386 recorded first.
- AC-3 (journey) The interpreter guard suite run with 50,000 extra entries in its temp directory shall finish within 10 percent of its time with an empty temp directory on the reference host; evidence: both timed runs.
