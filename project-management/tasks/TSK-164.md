# TSK-164: autonomy reference follows the permission presets

## Description

The harness permission work (settings v8, filed on
`integration/EPC-020-delivery-system` as five units and an ADR that
supersedes ADR-0066) changes what several statements in the autonomy
reference assume. Today the reference tells a session to take "the one
classified unsandboxed retry" for any trusted installed tool, says that a
bypass launch "is not a sandbox", cites ADR-0066 for the unrestorable-delete
gate, lets the primary merge any green integration pull request, lets an
approved hard-gate action be performed by the agent unless it is in the
non-relaxable class, and has a trust prompt rule that does not separate
hook-definition trust from folder trust. After the settings units land, each
of those reads wrong. This task brings `cf-method/references/autonomy.md`,
its contract pins and evaluation markers, and two ADR notes in line with the
landed ADR, by meaning. The wording follows what the units actually landed
(spike 0 decides whether the retry allowlist is empty; D7 decides whether a
sandboxed primary may drive Herdr).

Non-goals: changing the settings, guards, presets or ladder; adding a gate;
rewriting accepted ADR text, which gains dated Notes only.
