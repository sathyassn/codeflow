# TSK-1189: A gate that waited records its wait and the holder in run.json

## Description

Issue 513. Depends on TSK-1145, which is not a record on the line while PR 483 is open, so `depends_on` cannot name it yet; the edge `TSK-1145 -> TSK-1189` is added when PR 483 lands, and this task is not claimed before that. TSK-1145 (PR 483) is complete and reviewed, and the PR is open. Amending it would reopen its whole-unit review for a small addition, so this is a follow-up task. A gate that waits for a `host_exclusive` target, an output lease or `codeflow reserve` records the wait and the holder in `run.json`, so a person can see who held the gate.

Not security. Out of scope: a "list holders" command (a TSK-1010 follow-up, if wanted).

## Outcome

after this merges, a person whose gate run waited can read in `run.json` and in the not-run message how long it waited and who held the gate.

## Deliverables

- the wait block in `run.json` and the not-run message: the gate runner under `crates/codeflow-core/src/testing/`
- tests: a waiting run, a run that did not wait, and an unreadable holder record
- release note: `changelog.d/TSK-1189.md`

## Acceptance Criteria

- AC-1 A run that waits for a `host_exclusive` target, an output lease or `codeflow reserve` shall record `{wait_started, acquired, seconds_waited, holder: {pid, worktree, mode}}` in `run.json` and name the holder in its not-run message; evidence: a fixture failing before the change.
- AC-2 A run that did not wait shall record no wait block; evidence: a fixture.
- AC-3 An unreadable holder record shall be reported as "holder unknown" and never omitted; evidence: a fixture.
- AC-4 (journey) (added 2026-11-02, final review round 1, finding 1: the task had no journey criterion; this one drives its own change with the built binary) With the built binary, two `codeflow test` runs that contend for one `host_exclusive` target shall leave the second run's `run.json` with the wait block and the holder and shall name the holder in its not-run message, and an uncontended run shall record no wait block; evidence: both `run.json` files and the message.
