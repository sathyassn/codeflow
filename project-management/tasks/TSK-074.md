# TSK-074: current model roster in the ensemble and its decision record

## Description

Bind the managed ensemble to the roster the operator set on 2026-09-23 and
record it in ADR-0069.

The Claude judgment primary binding moves to the Opus class (`opus`,
observed id `claude-opus-5-5`) at high with xhigh on trigger. It keeps
independent planning, plan approval, orchestration and integrated code
judgment. The Fable class (`fable`, observed id `claude-fable-5-1`) becomes
one route inside that role, the design and review route, at high with xhigh
on trigger. It carries three duties: design direction, real design
implementation and fidelity approval; key reviews (the plan of a
consequential epic, the integrated design, editorial judgment, the combined
diff before `main`); and consultations. The existing Opus worker routes stay
for routine building and evidence, and the Opus design pilot stays a
candidate limited to disposable fixtures.

The design owner rule. `design_execution_owner` stays the
`claude-judgment-primary` role: the validator requires a Claude standing
role, and the duty stays in Claude lineage. The role's design authority is
carried by the Fable route by recorded operator designation. This is the
same mechanism by which the recorded same-Claude fallback already carries
Claude authority. Candidate status keeps limiting every other design route.
The Opus primary briefs design work, integrates it and accepts the rest of
the unit, but does not override Fable's direction or fidelity call without
a recorded reason. When Fable is unavailable after preflight, the Opus
primary carries design authority with reduced assurance recorded, and a
Fable design review is taken when the seat returns, never claimed before.
When Opus is unavailable, Fable at high is the recorded degraded primary.
A schema field for a second Claude binding was considered and rejected: it
adds a schema version and parser change for one designation the existing
fallback precedent already expresses.

Codex routes: Astra (`gpt-6-astra`) stays the engineering primary at high;
`sol-bounded-execution` moves to `gpt-6-sol` (medium or high); a new
`luna-light-execution` route binds `gpt-6-luna` under a `latest-luna`
class; `terra-simple-execution` and `latest-terra` are removed;
`gpt-5.6-sol` stays only as the recorded fallback in the rules text. Grok
binds `grok-4.7` on the primary and all three internal routes;
`grok-4.7-build-fast` is recorded in ADR-0069 as known and not routed.
Codex from a Claude Code host runs through the official plugin when its
login is current, otherwise the interactive Codex CLI in Herdr over the
local app-server; ADR-0069 amends ADR-0055 item 4, which said a missing
plugin degrades to solo.

Update every live pin the inventory in EPC-018 names: `orchestration_contract.rs`
(selectors, classes, the stale pin list gains the retired and current
concrete names), the evaluation kit routing case at `cases.json` line 2786
(signals for an Opus primary at high and the Fable design and review route;
`opus_as_fable_high_substitute` becomes a must_not against design authored
on the unqualified Opus pilot), the Terra case at line 5068 re-pointed at
Luna, the `latest-terra` marker in `requirements.json`, the Sol route
fixture in `fixtures.json`, and the qualification and doctor fixtures that
stand for a current binding. Add one test that fails if `gpt-5.6-terra` or
`grok-4.6` appears outside `docs/decisions/`, `docs/verification/`,
`project-management/`, `CHANGELOG.md` and `docs/plan/`, and one that
asserts no SKILL.md, contract, `grok-host.md`, `cf-herdr` or `cf-delegate`
text carries a concrete selector. Switch the `pipeline.workflow.js` comment
example from `sonnet` to `opus`.

Run one native identity canary per binding (Opus primary, Fable route,
Astra, 6 Sol, Luna, 5.6 Sol, `grok-4.7`) and record requested versus
observed model and effort; an unobserved binding stays unknown and is
named. Append a dated Note pointing at ADR-0069 to ADR-0024, ADR-0028,
ADR-0035, ADR-0041, ADR-0054 and ADR-0055, and verify the other eight
records that name a model are historical or still consistent.

Non-goal: the full native qualification suite for the new bindings (named
as a gap unless the operator asks for it), Agent OS, and the workspace
contract.
