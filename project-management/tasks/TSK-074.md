# TSK-074: current model roster in the ensemble and its decision record

## Description

Plan v1 of EPC-018 planned a data rebinding of the schema 4 ensemble to the
2026-09-23 roster, with a Fable design authority exception, per-model routes
and literal selector pins in tests and cases.

## Acceptance Criteria

Not pursued; kept as planned under Plan v1 for the record.

- [ ] The schema 4 ensemble binds the 2026-09-23 roster and the qualification validator accepts it.
- [ ] ADR-0069 records the roster, the design owner rule and the Codex transport.

## Closeout

- Cancelled before implementation under EPC-018 Plan v2. No source changed.
- Reason: the operator directed on 2026-09-23 that model routing become a
  config-driven catalog (latest eligible version per family, primary-eligible
  lines per family, instructions naming roles and workloads only), and that
  Opus, not Fable, owns design. Fable, Grok and Codex reviews of Plan v1 each
  found this task hard-codes the roster and places design authority on a
  route that cannot hold it.
- Replaced by TSK-079 (catalog engine), TSK-080 (the resolution command,
  the model-bindings check and the scan functions), TSK-085 (the managed
  catalog switched to the roster, from Plan v3) and TSK-081 (instruction
  surfaces that name roles and duties only). This id is not reused.
