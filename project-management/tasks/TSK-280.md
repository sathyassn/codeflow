# TSK-280: Policy keys have one placement rule and a check

## Description

No written rule or check says where a new policy key goes, so agents ship
keys in the policy template, where an adopter's older pinned binary can
meet them and fail closed (https://github.com/sathyassn/codeflow/issues/118). Since 3.0.0, `git.pr_summary` lives
only in the schema and the code default, with a per-key note
(`crates/codeflow-core/src/hooks/policy_schema.rs:392-393`); `git.claim_remotes`
was first added to the template and then removed; two replays on 2026-10-08
put a key in the template again. This task writes one rule where a
contributor adding a key reads, ties it to the two-step upgrade in
`docs/adoption.md`, and adds a check that holds it. TSK-276 adds a key and
follows this rule, so it lands after this task.

## Deliverables

- the rule: the module documentation of `crates/codeflow-core/src/hooks/policy_schema.rs`, `docs/policy-reference.md`
- the check and the last release's schema it reads: `crates/codeflow-core/tests/policy_key_placement.rs` and `crates/codeflow-core/tests/fixtures/policy-schema-last-release.tsv`
- release note: none. The change touches only tests, fixtures and documentation, so its impact is `none`, and `scripts/release.py` refuses a changelog fragment that carries only `none` entries. The PR declares `Impact: none` instead of adding `changelog.d/TSK-280.md`

## Acceptance Criteria

- AC-1 The policy schema module and `docs/policy-reference.md` shall state
  one rule for when a new key ships in the template and the installed
  policy and when it lives only in the schema and the code default, tied
  to the two-step upgrade in `docs/adoption.md`; evidence: the doc diff,
  checked by the reviewer against `git.pr_summary` and `git.claim_remotes`.
  (serves EPC-022 AC-3)
- AC-2 A test shall fail when `assets/base/policy.json` or
  `.codeflow/policy.json` names a key that the last released binary's
  schema does not know; evidence: the test fails on a planted key and
  passes on this branch's files. (serves EPC-022 AC-3)
- AC-3 The per-key test
  `no_shipped_or_installed_policy_file_names_required_checks` shall be
  folded into the general check or kept with a stated reason; evidence:
  the test diff.
- AC-4 (journey) When a project at the last released version runs
  `codeflow update` with this build's template, its policy file shall still
  load in that released binary; evidence: a journey that updates a fixture
  with the installed build and loads the result with the last release's
  schema.
