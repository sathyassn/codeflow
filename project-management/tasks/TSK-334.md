# TSK-334: Cloud and registry credentials remain outside agent sessions

## Description

Issues: #183 and #192. Both omissions come from the shipped secret-store inventory and its rendered harness presets. The Docker helper and environment channels must be included in the same outcome.

Evidence:

- `crates/codeflow-core/src/security/actions.json:629` lists the hard secret stores; `:699` lists supplemental sandbox read denies. Neither lists the reported cloud/Docker stores. The environment-mask list ends at `:697` without the reported additions.
- `assets/base/codex/config.toml:75` explicitly exempts GitHub CLI and Docker configuration. The hard-deny list starts at `:79`; `:69` enables Codex's generic environment scrub but supplies no explicit exclusions for all the reported names. Generic masking may already remove names containing TOKEN or SECRET; it does not prove coverage of every credential variable in these issues.
- `assets/base/grok/sandbox.toml:57` and the corresponding Claude presets omit the reported provider stores. The search covered all three shipped Claude presets, Codex, Grok and the action table.
- TSK-325 AC-1 requires exactly its eight repository paths (`project-management/tasks/TSK-325.md:47`). TSK-322's blocked-name list (`TSK-322.md:69`) is a commit-time control. Neither protects host credentials from session reads.

Outcome: **A session cannot read the supported cloud and Docker credential stores, retrieve registry secrets through helpers, or inherit their raw credential variables. Ordinary credentialless tool use still works.**

Source inspection is from the accepted triage at `c5c6f6f671d2bf67a77113c656b3be446fb0bea1`; runtime reproductions remain implementation evidence.

## Acceptance Criteria

- AC-1 Add the known Google Cloud, Azure, Terraform/OpenTofu and Docker credential stores to the common inventory and every applicable native preset; regenerate and verify mirrors. State alternate-location/environment-selected path coverage and residual limits explicitly.
- AC-2 Refuse `docker-credential-* get` through direct, absolute-path and `env` forms, and explicitly mask/exclude the credential variables each supported harness can filter. Verify effective configuration rather than presence of text alone.
- AC-3 Use synthetic, known-existing credential fixtures plus a readable control. Report absent, denied and unexpectedly readable distinctly. Never print credential contents, including synthetic values, as the proof of denial.
- AC-4 Prove local Docker operation with an empty private `DOCKER_CONFIG`, preserving contexts/socket/plugin use where supported; document brokered authentication and any necessary operator configuration.
- AC-5 (journey) A fresh and an updated adopter receive the protections, and native sessions refuse the planted file, helper and environment cases on their supported platforms.
