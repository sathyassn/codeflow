# TSK-379: Repository and worktree discovery cannot unprotect enforcement files

## Description

Sources: SEC-377-5 from the security confirm of PR 246 (TSK-377) on 2026-10-18, and Grok's review of PR 246 at `a3de25c80`, findings F2, F3 and F6 (`.worktrees/fix-hosted-red-5/target/review-TSK-377-grok-01.md` in the codeflow checkout, outside the repository). Severity high. All are pre-existing on 3.1.x. PR 246 cites this task as their owner.

Protection follows the repository the guards discover from the working directory, not the repository that holds the target. Four ways to move or hide that discovery make another checkout's enforcement files writable:

- **Nested repository or non-repository cwd (SEC-377-5, F6).** After `git init sub`, with the cwd in `sub`, `printf x > ../.claude/settings.json` passes git-guard, and native writes of `<repo>/.claude/settings.json` and `<repo>/.git/hooks/pre-commit` pass edit-guard (`crates/codeflow-core/src/hooks/edit_guard.rs:241-290`). A submodule gitfile cwd does the same. From a directory outside any repository the Write and the interpreter argument also pass.
- **`core.worktree` (F2).** `git config core.worktree <decoy>`, or the same through `--file .git/config`, is allowed by both guards. `core.worktree` is not in `SAFE_CONFIG` (`crates/codeflow-core/src/security/git.rs:46-101`), and a local write with no file resolver drops the finding (`crates/codeflow-core/src/hooks/git_guard.rs:8516-8532`, `:9060-9092`). Afterwards both checkouts' enforcement files are writable.
- **`mv` then `git worktree prune` (F3).** A plain `mv` of a registered worktree directory followed by `git worktree prune` unregisters a live checkout, and its `.claude/settings.json` becomes writable from the main checkout.
- **Registration that disagrees with its checkout.** When a worktree is moved by hand, every guard fails closed and `git worktree repair` is refused under hook integrity. The remedy text does not name the person's route (`git worktree repair` run outside the harness). Folded here from the Fable confirm of PR 246, because this task changes the same messages.

Outcome: **an enforcement file of any repository that encloses the target, or of the session's project, is refused whatever directory the command starts in, and no git or shell command can move, hide or unregister a checkout to drop that protection.**

Reach, defined once here: a target is judged against every repository that encloses it (its work tree; for a linked worktree, also its common directory and main checkout) and against the session's project repository with its registered worktrees. So an absolute-path write into another repository's enforcement files, from inside this repository or from outside any, is refused the same way as a write into this one. Refuse writes of `core.worktree` (and the other keys that move a work tree) under `git.hook_integrity`. Refuse a shell move of a registered worktree directory. Protect every directory under the configured worktree locations whose `.git` gitfile names this repository's git directory, registered or not, so a checkout hidden by a move and a prune is still protected when it returns. The guard decides from on-disk state only, never from a memory of earlier commands.

Non-goal: a path that no repository encloses, other than the session project's files; the harness settings folders in the home directory are TSK-395. TSK-396 was cancelled on 2026-10-18 because this definition covers its case.

Added by the EPC-022 amendment of 2026-10-18 under the operator's release decision of that day (workspace `RELEASE-PLAN.md`, 2026-10-18 operator decision). The coordinator widened SEC-377-5 into this task on 2026-10-18.

## Acceptance Criteria

- AC-1 With the cwd in a nested repository, in a submodule whose `.git` is a gitfile, or in a directory outside any repository, a shell redirect, an interpreter argument and a native Write to the enclosing checkout's `.claude/settings.json`, `.codeflow/policy.json` and `.git/hooks/pre-commit`, and to a linked worktree's `.claude/settings.json`, shall each be refused by its owning built hook; so shall the same writes, and `rm -rf <other>/.worktrees/w`, aimed by absolute path at an unrelated repository `<other>` from inside the session's project; evidence: one `hooks_cli.rs` test per route and cwd, including the unrelated-repository case, each failing before the change. (serves EPC-022 AC-75)
- AC-2 `git config core.worktree <path>`, `git config --local`, `--file .git/config` and `--worktree` forms of it, and `git -C <checkout> config core.worktree <path>`, shall be refused under `git.hook_integrity` by git-guard and exec-guard; `git -c core.worktree=<path> status`, which persists nothing, keeps its current verdict; evidence: guard tests per form. (serves EPC-022 AC-75)
- AC-3 A shell `mv`, `cp` then `rm`, or `rsync --remove-source-files` of a registered worktree directory shall be refused. End to end: after a checkout is moved away outside the session, `git worktree prune` runs, and the checkout is moved back, its `.claude/settings.json` and the main checkout's enforcement files shall still be refused from the main checkout and from inside the returned checkout. The evidence that separates the cases is on disk: a hidden checkout still holds a `.git` gitfile under a configured worktree location naming this repository's git directory, and stays protected; an honestly deleted worktree has no such directory, so prune passes and nothing is left to protect. Evidence: `hooks_cli.rs` fixtures for the refused moves, the move-prune-return sequence and an honest deletion, each judged from on-disk state with no record of earlier commands.
- AC-4 Legitimate commands shall still pass through the built hooks: `git worktree add`, `git worktree move`, `git worktree remove`, `git worktree list`, `git worktree prune` of a truly removed worktree, and `git init` of a scratch repository outside the checkout; evidence: `hooks_cli.rs` tests per command.
- AC-5 When a worktree registration disagrees with its checkout, the refusal shall name the person's route, `git worktree repair` run in their own terminal outside the harness; evidence: a test of the message.
- AC-6 (journey) With the installed build, in a scratch adopter project with a linked worktree, an agent session shall be refused each attack above (nested `git init` then a write from inside it, a submodule cwd write, a write from outside any repository, an absolute-path write into an unrelated repository, the `core.worktree` write, the move-prune-return sequence), and shall run the legitimate worktree commands; evidence: the journey output.
