# TSK-237: codeflow init no longer hangs on a git pipe deadlock

## Description

`codeflow init` could hang forever (GitHub issue 71). `git_stdin` in `crates/codeflow-core/src/root_checkout.rs` wrote all of a child's stdin before it read stdout. With `git check-ignore -v -n --no-index --stdin -z`, git answers each path it reads, so once the stdout pipe filled, git blocked on its write while codeflow blocked on the rest of stdin. The fix is one shared helper, `codeflow_core::git::output_with_input`, that writes stdin from its own thread while stdout and stderr are drained, closes stdin when the input is written, and joins the writer with its error. The same write-all-then-read pattern is fixed in every production place found by a search for piped stdin: `git_stdin`, `doctor::Options::do_exec_stdin`, `doctor::run_captured` (whose timeout never started while the write was blocked) and `GithubProvider::run_gh` (a request body to `gh api --input`). Call sites that already use a writer thread (`ids/git.rs`, `ci.rs`, `push_set.rs`, `hooks/conflict_markers.rs`, `validate/portal.rs`) and test fixtures are unchanged. Non-goal: no new timeout on the git call; the exchange now cannot block on pipe size.

## Deliverables

- Shared helper `output_with_input` and its tests: `crates/codeflow-core/src/git/mod.rs`
- The fixed call sites: `crates/codeflow-core/src/root_checkout.rs`, `crates/codeflow-core/src/doctor/mod.rs`, `crates/codeflow-core/src/remote.rs`
- Tests that fail before the fix: `crates/codeflow-core/src/root_checkout_tests.rs`, `crates/codeflow-core/src/doctor/mod.rs`, `crates/codeflow-core/src/remote.rs`, `crates/codeflow-cli/tests/init_e2e.rs`
- Release note: `CHANGELOG.md` 3.1.0 Fixed, annotated patch

## Acceptance Criteria

- AC-1 When `nested_repositories` scans a repository with 12,000 folders whose names are long enough that git's `check-ignore -v -n --stdin -z` input and answer each exceed a pipe, the scan finishes and returns the nested repository, with the wait bounded so a regression fails instead of hanging; the test hangs on main and passes after (unit test over real git in `crates/codeflow-core/src/root_checkout_tests.rs`, fail-before shown).
- AC-2 When a child process answers while it reads, `git::output_with_input` returns all of its output for an input of 4 MiB, closes stdin when the input is written, and judges a child that stops reading early by its exit status, while any other write error and a writer panic are returned (unit tests in `crates/codeflow-core/src/git/mod.rs`).
- AC-3 When `doctor`'s `run_captured` and `do_exec_stdin`, and `GithubProvider::run_gh`, pass a multi-megabyte input to a child that echoes it, each completes within a bound and returns the output; each test hangs on main and passes after (unit tests in `doctor/mod.rs` and `remote.rs`, fail-before shown).
- AC-4 Every production call site that writes a child's stdin and then reads its output either writes on its own thread or goes through the helper, and the fixed sites are listed in the PR (search of `crates` for piped stdin, recorded in the acceptance block).
- AC-5 The pending 3.1.0 CHANGELOG has a Fixed entry annotated patch, and `codeflow validate --docs` passes.
- AC-6 When `codeflow init --standard --yes` runs in a repository with 12,000 long-named folders and one nested repository, it completes with exit 0 and writes the policy, with the wait bounded; the test hangs on main and passes after (journey, `init_standard_completes_in_a_repository_with_many_folders` in `crates/codeflow-cli/tests/init_e2e.rs`).
