# TSK-237: codeflow init no longer hangs on a git pipe deadlock

## Description

`codeflow init` could hang forever (GitHub issue 71). `git_stdin` in `crates/codeflow-core/src/root_checkout.rs` wrote all of a child's stdin before it read stdout. With `git check-ignore -v -n --no-index --stdin -z`, git answers each path it reads, so once the stdout pipe filled, git blocked on its write while codeflow blocked on the rest of stdin. The fix covers the whole class. One module, `crates/codeflow-core/src/git/stdin.rs`, is the only place codeflow pipes a child's stdin: `output_with_input` writes stdin from its own thread while stdout and stderr are drained, and `spawn_with_input` does the same for callers that own their wait loop (a deadline, a byte bound). Every production site now goes through it: `root_checkout::git_stdin`, `doctor::do_exec_stdin`, `doctor::run_captured`, `GithubProvider::run_gh`, `ids/git.rs` (`run_input`, and `blobs`, which piped stderr and never drained it), `cmd/ci.rs`, `cmd/push_set.rs` (two sites), `hooks/conflict_markers.rs` and `validate/portal.rs`. A source scan test over the Rust sources fails when production code sets a child's stdin to anything but null or inherit, or names a stdin handle, outside the module (macro-generated code and raw file descriptors are not covered). Non-goal: no new timeout on the git call, because the exchange now cannot block on pipe size.

## Deliverables

- Shared stdin module `crates/codeflow-core/src/git/stdin.rs` (`output_with_input`, `spawn_with_input`, `InputWriter`) and its tests in `crates/codeflow-core/src/git/mod.rs`
- The routed call sites: `root_checkout.rs`, `doctor/mod.rs`, `remote.rs`, `ids/git.rs`, `hooks/conflict_markers.rs`, `validate/portal.rs` under `crates/codeflow-core/src`, and `cmd/ci.rs`, `cmd/push_set.rs` under `crates/codeflow-cli/src`
- The rule as a test: `crates/codeflow-core/tests/stdin_pipe_rule.rs`
- Tests that fail before the fix: `crates/codeflow-core/src/root_checkout_tests.rs`, `crates/codeflow-core/src/doctor/mod.rs`, `crates/codeflow-core/src/remote.rs`, `crates/codeflow-cli/tests/init_e2e.rs`
- Release note: `CHANGELOG.md` 3.1.0 Fixed, annotated patch

## Acceptance Criteria

- AC-1 When `nested_repositories` scans a repository with 12,000 folders whose names are long enough that git's `check-ignore -v -n --stdin -z` input and answer each exceed a pipe, the scan finishes and returns the nested repository, with the wait bounded so a regression fails instead of hanging; the test hangs on main and passes after (unit test over real git in `crates/codeflow-core/src/root_checkout_tests.rs`, fail-before shown).
- AC-2 When a child process answers while it reads, `git::output_with_input` returns all of its output for an input of 4 MiB, closes stdin when the input is written, and judges a child that stops reading early by its exit status, while any other write error and a writer panic are returned (unit tests in `crates/codeflow-core/src/git/mod.rs`).
- AC-3 When `doctor`'s `run_captured` and `do_exec_stdin`, and `GithubProvider::run_gh`, pass a multi-megabyte input to a child that echoes it, each completes within a bound and returns the output; each test hangs on main and passes after (unit tests in `doctor/mod.rs` and `remote.rs`, fail-before shown).
- AC-4 Every production site that pipes a child's stdin goes through `git::output_with_input` or `git::spawn_with_input`, and no production piped stdout or stderr is left undrained: `ids/git.rs`, `cmd/ci.rs`, `cmd/push_set.rs`, `hooks/conflict_markers.rs` and `validate/portal.rs` no longer hand-roll a writer, and `ids::blobs` no longer leaves a piped stderr unread (the call sites are listed in the PR, and the suites that exercise them pass: `ids`, `hooks`, `validate`, `ci_cli`, `id_registry_journey`, `hooks_cli`).
- AC-7 When production Rust code under `crates/` outside `crates/codeflow-core/src/git/stdin.rs` sets a child's stdin to anything but null or inherit (a piped call, a variable, a conditional, a `Command::stdin` path call, or a raw identifier spelling of them), or names a child's `stdin` handle, `ChildStdin` or a `Child { stdin, .. }` pattern, `cargo test` fails and names the file and line; the scan reads code tokens, skips comments, literals and `#[cfg(test)]` items one by one, is shown failing on each spelling in its fixtures, and states its limits: code a macro generates and raw file descriptors are not covered, and scripts and assets are outside it and were searched by hand (`crates/codeflow-core/tests/stdin_pipe_rule.rs`).
- AC-5 The pending 3.1.0 CHANGELOG has a Fixed entry annotated patch, and `codeflow validate --docs` passes.
- AC-6 When `codeflow init --standard --yes` runs in a repository with 12,000 long-named folders and one nested repository, it completes with exit 0 and writes the policy, with the wait bounded; the test hangs on main and passes after (`init_standard_completes_in_a_repository_with_many_folders` in `crates/codeflow-cli/tests/init_e2e.rs`). (journey)
