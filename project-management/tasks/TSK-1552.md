# TSK-1552: The present-browser test times out in Firefox after launch under the software compositor

## Description

Source: the Director's message to coord/records on 2026-11-19 (17:4x), from the candidate 1119j journey-gate probe. Filed by coord/records.

As reported by the Director, not re-run here: the `present-browser` target fails with a Firefox `TimeoutError` after the browser has launched. This happens on `main` at `17510e9bd4` and on landing candidate 1119j alike, so it is not caused by the candidate. The browser prints `GraphicsCriticalError RenderCompositorSWGL failed mapping default framebuffer`, the same line that appears in the failing test logs. Probe: `coordination/coordinators/parallel/notes/candidate-main-1119j-firefox-probe/01-probe.log` (sha256 `0e1c95c89bfb440e51d3a350eac88aa26f81d7ae2b49e5e3c7a66d29ad97b1f3`, checked by coord/records at filing). Playwright build `firefox-1538`.

The likely area is the page or context step under the software GL compositor. That is a lead, not a finding.

Premise: before any change, read the probe log and reproduce the timeout on `main` at `17510e9bd4`, and say where it stops (browser launch, context, page creation or first navigation). Also say whether the same target passes with another Playwright browser or with the compositor setting changed.

Non-goals: changing what the present runtime renders; skipping or weakening the browser test to make a gate green.

## Outcome

After this merges, the `present-browser` target runs to completion in Firefox on the machines that gate CodeFlow, or, if the fault is in the host rather than the code, the target reports that cause plainly instead of a bare timeout.

## Deliverables
