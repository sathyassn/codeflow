# TSK-1148: CodeFlow's initial catalog is inventoried, classified, evidenced and reviewed, and the check blocks

## Description

The last two bootstrap stages for CodeFlow itself. Evidence is resolved for each record (typed `test:`, `journey:`, `record:` or a declared `gap:`, with `stage` set honestly), an independent review of the whole catalog is recorded, `inventory: complete` is set, and CodeFlow's policy sets the capability check to `block` (the severity the operator approved on 2026-11-01). The pull request carries a matching `## Capability impact` section in the new format. Basis: evidence resolution for 20 to 60 records through TSK-362's resolver, one review, one policy edit.

Design: `coordination/coordinators/capabilities/design-note.md` revision 5 and the operator's comments of 2026-11-01 (about 12:47 EST) in the same folder's `DIRECTION.md`.

Consolidated 2026-11-04 (second consolidation amendment, from the operator's sizing direction of 2026-11-04 21:5x, ruled by coord/catalog): this task absorbs TSK-1146 (Easy 0 to 1), the first two bootstrap stages for CodeFlow (inventory and classification), because both run the same records under EPC-026 AC-12 with one reviewer pass; one task can run all four stages in order. TSK-1146's criteria follow this task's own as AC-6 to AC-10, word for word, each with a `Moved` note; its deliverables are listed with `(from TSK-1146)`. If the inventory finds over 40 new records, the builder splits by area at claim, as TSK-1146's record said.

## Outcome

After this merges, CodeFlow's catalog lists every user-facing, internal and technical capability, functional and non-functional, classified by facet, evidenced, reviewed and marked complete, and every product pull request to CodeFlow must declare its capability impact or be refused.
