# TSK-319: Pushed branches are inventoried and deleted on a recorded-tip proof

## Description

Cleanup of pushed branches requires a merged PR and a matching SHA
(`assets/base/rules/worktrees.md:93-110`), `status` inventories local
cleanup only, and git-guard reads every `--force-with-lease` as a force push
(`crates/codeflow-core/src/hooks/git_guard.rs:10663`), so pushed task, plan
and carry branches pile up (https://github.com/sathyassn/codeflow/issues/169,
part 2). This task adds the inventory and a compare-and-swap delete under
the approved cleanup rule (decision 3):

- Inventory: `status` lists remote task, plan and carry branches with the
  tip SHA it read and independent facts: ancestor of the destination line's
  fetched tip (destination from the record's target or the PR base); PR
  merged with that SHA (`--host`); patch-equivalent lead; live claim;
  admitted-but-unlanded carry; owner active; worktree dirty. `status` never
  deletes.
- Rule: delete only with an inactive owner and a clean worktree (as today),
  the recorded tip SHA still shown by `ls-remote`, and that SHA an ancestor
  of the destination line or the PR `MERGED` with it, by
  `git push origin --force-with-lease=refs/heads/<b>:<sha> :refs/heads/<b>`.
  A patch-equivalent lead never proves.
- Guard: git-guard admits that form for exactly one delete refspec with an
  explicit expected value, no wildcard or mirror, on a non-protected
  branch, and nothing wider. No delete command ships.

## Deliverables

- the inventory: `crates/codeflow-cli/src/cmd/status.rs` and TSK-311's facts

- docs: `docs/cli.md`

## Acceptance Criteria

- AC-1 `status` shall list remote task, plan and carry branches with the
  recorded tip SHA and each independent fact, the destination taken from
  the record's target or the PR base; evidence: a fixture with landed,
  unlanded, carried and claimed branches. (serves EPC-023 AC-5)
- AC-2 A branch whose owner is active or whose worktree is dirty shall be
  listed as not deletable whatever its other facts, and a patch-equivalent
  lead shall never make one deletable; evidence: negative tests.
- AC-3 git-guard shall admit `git push origin --force-with-lease=refs/heads/<b>:<sha> :refs/heads/<b>`
  for one non-protected branch, and refuse the same delete without an
  expected value, with a wildcard, with `--mirror`, with two refspecs, and
  on a protected branch; evidence: guard tests. (serves EPC-023 AC-5)
- AC-4 When the remote tip moved after the inventory read it, the lease
  delete shall fail and the branch shall remain; evidence: a native test
  against a bare remote.
- AC-5 The approved rule text shall be in `worktrees.md` "Cleanup", and no
  command that deletes a remote branch shall ship; `status` shall never
  delete; evidence: the text and a test that `status` leaves refs intact.
- AC-6 When the installed build inventories a scratch remote and an agent
  session deletes one landed branch by the admitted form, the guard shall
  allow it, and a second branch whose tip moved shall survive (journey);
  evidence: the journey output.
