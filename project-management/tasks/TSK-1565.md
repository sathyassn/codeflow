# TSK-1565: A later value on a line clears an earlier loader setting for a script run

## Description

Owner: to be assigned by the Director. Priority: low. Staged by coord/records on coord/catalog's request of 2026-11-20 as a follow-up record of TSK-1476, for the next filing batch. No pull request is needed before then.

On a script run, a loader setting that an earlier part of the same line exports or declares is never cleared by a later harmless value or by an unset. So the guard keeps refusing a loader file that the line no longer sets. This is an over-refusal: the command is refused although nothing it runs can load the file. It is not a bypass.

Class words only, by the same rule as the other 2026-11-20 guard records: no concrete spelling of an accepted form is in this record.

Source: Grok's zt delta read of TSK-1476 (`reviews/tsk1476-zt-grok.md`, nit 1), relayed by coord/catalog. coord/records did not read that verdict or reproduce the claim.

Related: TSK-1476 (the unit that left it), TSK-1536 (the launcher reader).

Revisit event: when the next allowlist round touches the loader-setting reader.

Non-goals: accepting any form that is refused today for another reason; the residuals the TSK-1476 pull request names.

Not verified: that the over-refusal happens at the line tip; the premise step reproduces it as inert strings, and no payload is run.

## Outcome

After this merges, a script run is refused for a loader setting only while the line still sets it, and a later clearing value or unset on the same line lifts the refusal.

## Deliverables

- the loader-setting reader's handling of a later clearing value or unset
- tests with inert strings for both directions
