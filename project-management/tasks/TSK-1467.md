# TSK-1467: A line can take main's move of a task's home when the line never changed that task

## Description

`codeflow ci` refuses a range that imports a task record whose declared home changed at its landing on `main`, unless that landing is a planning merge on the checked head's own first-parent history (`verify_record_home`, `crates/codeflow-core/src/workgraph/acceptance/imports.rs:763-797` at `main` 4cc6de60a; tests `a_clean_sync_cannot_re_home_a_line_task`, `crates/codeflow-cli/tests/ci_cli/main_sync.rs:405-425`, and `a_home_move_off_the_checked_line_stays_refused`, `crates/codeflow-cli/tests/acceptance_cli/imports.rs`). A line's sync of `main` never has `main`'s landings on its first-parent history. So any home move made on `main` blocks every later sync of `main` into that line, until the record changes again on `main` or the line's copy becomes byte-identical.

On 2026-11-12 this blocked the EPC-022 sync on four records: TSK-1177 and TSK-1357 (moved by pull request 666) and TSK-341 and TSK-1352 (moved by pull request 772). The refusal named only the first, because the check stops at the first record it refuses (`imports.rs:180-181`). It names a repair ("fetch the home and repair or reopen the work there through its task pull request") that a planning move on `main` cannot meet for a todo task, since `main` is not the line task's home. The rule that each record changes only at its home stays; this task adds the one safe case and makes the refusal complete.

Relation to TSK-1123: its AC-24 to AC-26 cover the same family (sync false positives on records `main` changed: `work.criteria_frozen` and `work.acceptance_binding`). This task takes only the `work.import_authority` home-move case, so it does not wait for the EPC-022 checkpoint. TSK-1123 keeps AC-24 to AC-26.

Non-goals: no change to how a record's home is chosen or moved; no change to `work.criteria_frozen` or `work.acceptance_binding`.

## Outcome

After this merges, a maintainer whose line syncs `main` after `main` moved an untouched todo task's home sees the sync admitted, and sees every refused record named with its own repair when it is not.

## Acceptance Criteria

- AC-1 Given a range that imports from `main` a task record whose declared home moved at its landing on `main`, `codeflow ci` shall accept the move when all hold: the landing is an admissible planning landing on `main`'s first-parent history at the commit `--policy-from` names (a clean merge whose change from its first parent touches only records and plans); the task was `todo` or `blocked` with no acceptance block at the landing and at its first parent; and the line's copy of the record is unchanged since the merge base of the line and that landing. Evidence: a fixture of the 2026-11-12 shape (a todo line task moved to `main` by a planning merge on `main`, the line then syncing `main`), refused before and passing after.
- AC-2 It shall fail closed, refusing with today's message and the cause, when any condition cannot be proven: the landing is not on `main`'s trusted first-parent history (a second-parent or replayed commit), the landing is not a clean planning merge, the task was complete, superseded or malformed at either side, or the line changed its copy since the merge base. Evidence: one negative fixture per condition, reusing the cases of `a_home_move_outside_a_permitted_state_stays_refused` and `a_home_move_through_no_planning_landing_stays_refused`.
- AC-3 The refusal shall name every refused record in the range, not only the first, each with its own cause and repair. Evidence: a fixture with two refused records (the TSK-1177 and TSK-1357 shape) naming both.
- AC-4 The refusal for a task that was complete when its home moved (TSK-1177's shape) shall name the routes that clear it as they stand after AC-7's decision; it shall name a later reviewed change to the record on `main` as a route only if AC-7 decides that route is intended. Evidence: the message in AC-3's fixture.
- AC-5 The sync class's own rule is unchanged: a sync never changes a record whose home is the line through `main`'s version, apart from AC-1's case. Evidence: the existing `main_sync.rs` tests stay green.
- AC-6 `docs/delivery.md` ("A sync of main into a line") shall state the accepted case and its conditions, and a changelog entry shall describe it. Evidence: the docs diff and `changelog.d/TSK-1467.md`.
- AC-7 Today any later reviewed change to a record on `main` clears an earlier home move made on `main`, because `verify_record_home` compares only the record's last landing with that landing's first parent (`imports.rs:784-796`). TSK-1312, TSK-1318 and TSK-1239 passed the EPC-022 sync this way. This task's cross-lineage design review shall decide whether that is intended. If it is not, this task closes it in the same change as AC-1, and a line's sync accepts a home move only under AC-1's conditions. If it is, `docs/delivery.md` shall say so. Evidence: the review's decision, and either a fixture showing a later change on `main` no longer clears a refused move, or the docs sentence.
