# TSK-1559: A test target can be marked release-only, so the local full gate skips it and the release tier runs it

## Description

Source: the operator's choice "a" on PR 589 (TSK-1279, heavy runs keep the caller's job cap and wait for a host-exclusive target), relayed by the Director on 2026-11-19 (16:4x): file a task, adopter-facing, targeting the EPC-022 line. Filed by coord/records. The decision came from the open question on 589 of how a very heavy target such as `read-benchmark` should behave in the local full gate. Correction by the Director (2026-11-19 16:5x): PR 589 lands without this step and does not wait for this task; this task depends on nothing in 589, and 589 does not depend on it. When this task lands, it moves `read-benchmark` to release-only itself.

As reported in the 589 thread, not re-checked here: some targets in the project's test configuration are too heavy for the local full gate and already run only in the hosted release tier (`.github/workflows/codeflow-ci.yml` job `gates-release`; the contract in `scripts/test_gate_contracts.py`, around `test_release_tier_targets_leave_the_hosted_landing_gate`, names `prose-exhaustive`, `read-benchmark`, `present-browser` and `present-binary-delta`, and a further test asserts the modes of `read-benchmark` and `prose-exhaustive` are `full`). Today nothing in the test configuration says that a target is release-only: the local full gate still runs them, and the release tier's list lives in a workflow and a Python contract.

Change: a new optional setting in the test configuration marks a target release-only. The local full gate skips a target so marked; the release tier runs it. Existing configurations are left unchanged and behave exactly as before. `scripts/test_gate_contracts.py` changes with it so the contract reads the setting and keeps asserting that the release-only targets leave the hosted landing gate and are run by `gates-release`.

Premise: before any change, open the test configuration schema and the code that selects targets for the local full gate and for the release tier (find them from `.codeflow/test-config.json`, the `codeflow test` code, and `scripts/test_gate_contracts.py`), and read the 589 thread only for the `read-benchmark` context (589 does not wait on this task). Establish how the four named targets are marked as release-only today (job `only:` lists), and what a configuration without the setting does.

Non-goals:

- Changing the targets' contents, modes or budgets.
- PR 589 (TSK-1279) and its heavy-run wait and job-cap behaviour: 589 lands without this task and does not depend on it, and this task depends on nothing in 589.
- Moving any other target into or out of the release tier: the task adds the setting and moves `read-benchmark` only (AC-5).
- The heavy-run wait and job-cap behaviour of TSK-1279 itself.

## Outcome

After this merges, a project marks a target release-only in its test configuration; `codeflow test` full-mode skips it locally and the release tier runs it; an existing configuration without the setting behaves as before; and the gate contract reads the setting.

## Deliverables

- the optional setting in the test-configuration schema, with its default (not release-only), documented in the configuration reference
- the target selection: the local full gate skips a release-only target, the release tier includes it
- `scripts/test_gate_contracts.py` changed to read the setting and keep its release-tier assertions
- tests: setting present, absent, and malformed; local full gate skips; release tier runs; an unchanged configuration selects the same targets as before
- the release note: `changelog.d/TSK-1559.md` (adopter-facing)

## Acceptance Criteria

- AC-1 The test configuration shall accept an optional setting that marks a target release-only, and a configuration without the setting shall select exactly the targets it selected before; evidence: a test that loads a pre-change configuration and compares the selected targets for the local full gate and the release tier before and after.
- AC-2 The local full gate shall skip a target marked release-only; evidence: a test with one marked and one unmarked target, the gate's selection and its output naming the skip with the reason.
- AC-3 The release tier shall run a target marked release-only; evidence: a test of the release-tier selection that includes the marked target.
- AC-4 A malformed value of the setting shall be refused with a message that names the setting; evidence: a test asserting the refusal and its text.
- AC-5 `scripts/test_gate_contracts.py` shall read the setting and keep asserting that the release-only targets are absent from the hosted landing gate parts and present in `gates-release`; evidence: the changed contract and its passing run, and the project's own configuration marking `read-benchmark` release-only, so the local full gate skips it and the release tier runs it; no other target changes tier.
- AC-6 The setting shall be documented where the test configuration is documented, and the change shall alter no existing configuration file's behaviour; evidence: the changed documentation lines with file:line and a diff showing no existing configuration changed other than the `read-benchmark` mark of AC-5.
- AC-7 The change shall carry an adopter-facing changelog entry; evidence: `changelog.d/TSK-1559.md`.
