# TSK-283: Guards read the git configuration a command will use

## Description

Exec-guard's outward-release check reads a git alias from configuration
files and `-c` and refuses `--config-env`, but it ignores configuration
given through `GIT_CONFIG_COUNT`, `GIT_CONFIG_KEY_n`, `GIT_CONFIG_VALUE_n`,
`GIT_CONFIG_PARAMETERS` and `GIT_CONFIG_GLOBAL`, `GIT_CONFIG_SYSTEM` or
`GIT_CONFIG_NOSYSTEM` (https://github.com/sathyassn/codeflow/issues/98; `crates/codeflow-core/src/security/outward.rs:725-790`
at v3.1.0). Only git-guard covers that case today. Files that an existing
`include.path` or `includeIf.*.path` names are not protected, so a planted
alias or pager there runs under a later git command (https://github.com/sathyassn/codeflow/issues/88; an open residual
in `docs/policy-reference.md:476-477`). Both need the configuration git will
actually use, and one shared reader serves both, so they are one task.

## Deliverables

- the shared reader: a module under `crates/codeflow-core/src/security/` (provisional name)
- its users: `crates/codeflow-core/src/security/outward.rs`, `crates/codeflow-core/src/security/git.rs`, `crates/codeflow-core/src/hooks/git_guard.rs`, `crates/codeflow-core/src/hooks/edit_guard.rs`, and the doctor report in `crates/codeflow-core/src/doctor/`
- tests: guard unit tests and an exec-guard CLI test
- docs: `docs/policy-reference.md` residual list
- release note: `changelog.d/TSK-283.md`

## Acceptance Criteria

- AC-1 One shared reader shall build a command's effective git
  configuration from its files, includes and conditional includes
  (bounded, with no loops), `-c`, `--config-env` and the `GIT_CONFIG_*`
  variables above, and report "cannot verify" when it cannot reproduce
  them; evidence: reader tests, an include loop and a missing include
  among them. (serves EPC-022 AC-5)
- AC-2 When exec-guard runs alone, `GIT_CONFIG_COUNT=1
  GIT_CONFIG_KEY_0=alias.ship GIT_CONFIG_VALUE_0='push origin v9.9.9' git
  ship` shall be refused as an outward release, as shall the same alias
  through `GIT_CONFIG_PARAMETERS` and through a `GIT_CONFIG_GLOBAL` file;
  evidence: exec-guard tests with git-guard not wired. (serves EPC-022 AC-5)
- AC-3 Every other guard that decides from `alias.*`, `core.*`, `push.*`,
  `remote.*` or `branch.*` shall use the reader or refuse when the
  command's environment names one of these variables; evidence: a sweep
  table in the pull request with file:line per reader.
- AC-4 A native edit or shell write to a file that the global, system or
  repository configuration includes shall be refused, naming the rule and
  the sanctioned path, or `codeflow doctor` shall report includes that
  point at writable files; the policy reference shall update its residual
  list; evidence: planted include tests and the doc diff.
- AC-5 When a fresh project with the installed build wires only exec-guard,
  the AC-2 command shall be refused, and a session edit to a file named by
  `include.path` shall be refused or reported by doctor (journey);
  evidence: a CLI journey.
