# TSK-1327: Every start path bases new work on the tip it judged, freshly fetched

## Description

Source: the review of PR 586 (TSK-1047) at its head, findings 1 and 3 (`coordination/coordinators/planning/reviews/pr586-head-review-fable.md`). Both are start paths that pick a base from a tip other than the one the work needs; they share that cause, so they are one task by the operator's sizing rule of 2026-11-04.

- `claim_on` reads the records tree at `target_tip` from `resolve_target` (`crates/codeflow-core/src/workgraph/readiness.rs:1976-1984`), which keeps a local target that is ahead of its upstream (`work_start.rs:447-449`), while `select` takes the remote-tracking tip (`claim_base.rs:116`) and the branch is created and recorded there (`readiness.rs:2048-2051`). A claim can be admitted on planning records the base does not hold; `work start` then refuses it as not anchored.
- `codeflow new epic --integration` cuts `integration/<epic>` from `refs/remotes/origin/main` as last fetched, with no fetch (`crates/codeflow-cli/src/cmd/new.rs:281`, `crates/codeflow-core/src/workgraph/light_paths.rs:252-258`, `work_start.rs:303-312`), so a line can start from a stale copy of `main`.

Both fail safe today in the sense that no local-only base is used; the fix makes each path judge and base on the same, current tip. Line numbers are at PR 586's head 4b9baecf0.

## Outcome

After this merges, a builder's claim is judged on the same tip its branch starts from, and a maintainer's new epic line starts from a freshly fetched `main`.

## Deliverables

- the claim and epic-line changes and their tests: `crates/codeflow-core/src/workgraph/readiness.rs`, `claim_base.rs`, `light_paths.rs`, `crates/codeflow-cli/src/cmd/new.rs`, and the `work_cli` tests
- release note: `changelog.d/TSK-1327.md`

## Acceptance Criteria

- AC-1 When the local target is ahead of its upstream, `work claim` shall either read the records it judges from the tip it bases the branch on, or refuse naming both tips and the push or reset that clears it; evidence: a test with unpushed planning commits on a local line, failing before the change.
- AC-2 `codeflow new epic --integration` shall fetch the remote's `main` before it cuts the line, refuse naming the remote when the fetch fails, and record the commit it cut from; evidence: a test whose remote `main` advanced after the last fetch, failing before the change, and one with an unreachable remote.
- AC-3 (journey) With the built binary in a scratch clone, a claim on a line with unpushed planning commits and a new epic after the remote `main` moved each behave as AC-1 and AC-2 state; evidence: the command output with exit codes captured directly.
