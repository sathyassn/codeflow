# TSK-1512: The GitLab, Bitbucket and generic pinned runs judge a change by the target's test config

## Description

TSK-1355 makes GitHub's managed gates job read `.codeflow/test-config.json` from the base authority, so a pull request is judged by the coverage floor and targets its base approved. The other three shipped CI templates do not do the same. At TSK-1355's reviewed head ad379b9a69, `assets/base/ci/.gitlab-ci.yml:333`, `assets/base/ci/bitbucket-pipelines.yml:328` and `assets/base/ci/ci-generic.sh:293` run `codeflow test --strict` in the change's own tree, with no copy of the test config from the target commit (lines 330, 325 and 290 at the EPC-022 line tip 5405cdb1b). The change's own test config therefore sets the coverage floor and targets on those hosts. Their policy levels already come from the target worktree (`ci-generic.sh:253-259` at ad379b9a69), and the GitHub gates job takes the target's copy (`codeflow-ci.yml:285-303` at ad379b9a69). This task gives the three templates the same read of the test config. Non-goal: the head repository reaching `codeflow ci` (TSK-1343 AC-7).

## Outcome

After this merges, an adopter on GitLab, Bitbucket or the generic pinned run has each change judged under the coverage floor and targets of the target commit, as on GitHub, and a change to the test config takes effect only after it merges.

## Deliverables

- the shipped templates: `assets/base/ci/.gitlab-ci.yml`, `assets/base/ci/bitbucket-pipelines.yml`, `assets/base/ci/ci-generic.sh`, with the managed baseline and manifest synchronized
- the guidance: `assets/base/ci/README.md`
- tests: one fixture per template, beside TSK-1355's template tests in `crates/codeflow-cli/tests/`

## Estimate

- Grade: Medium; band: Medium (2 to 4 h); moved: none
- Split: not needed; one outcome (every shipped template judges by the target's test config)
- Basis: one read of the test config from the target commit in each of three templates, following TSK-1355's GitHub read, a lowered-floor fixture and an unreadable-copy fixture per template, and guidance; graded by coord/records under issue 334's bands. The builder re-checks the grade at claim.

## Acceptance Criteria

- AC-1 When the GitLab, Bitbucket or generic pinned run judges a change, it shall read `.codeflow/test-config.json` from the target commit, never from the change's tree, and shall fail closed when the target's copy cannot be read. Evidence: for each of the three templates, a fixture where the change lowers the coverage floor and is still judged at the target's floor, and a fixture where the target's copy cannot be read and the run fails.
- AC-2 The guidance shall state, for each of the four shipped templates, that the test config judging a change comes from the target commit. Evidence: the `assets/base/ci/README.md` diff.
