# TSK-1195: Product docs carry product screenshots and every page has a Markdown twin

## Description

Operator decision d8 (2026-11-02), scope as the Director corrected it at 12:14: product docs mode puts product screenshots in the docs pages and writes a Markdown twin of every page plus `llms.txt` and `llms-full.txt`, all from the same sources, and a check fails when a page lacks its twin. The `llms` files already exist, so this task extends them to the product docs and does not rebuild them; the builder finds the existing generator at claim and records where it is.

It depends on TSK-1162 and TSK-1160 as the decision states: the pages that carry the screenshots are drawn from the token source and the navigation component. The features home and feature captures are TSK-1194; brand tokens are TSK-1196. A text alternative on each screenshot is the plan's elaboration, so that the twin can carry it.

Non-goals: the site mode itself (TSK-1194), and rebuilding the existing `llms` generation.

## Outcome

after this merges, an agent or a person can read every page of a project's product docs as Markdown from the `llms` files, and the docs pages show the product, with a build that refuses a page that has no twin.

## Deliverables

- the twin generation, the `llms.txt` and `llms-full.txt` extension and the missing-twin check: the portal starter and the existing `llms` generator under `assets/docs-portal/`
- the screenshots in the sample project's docs pages
- tests: the missing-twin fixture, the count check and the drift test
- docs: the skill's agent-readable output description
- release note: `changelog.d/TSK-1195.md`

## Acceptance Criteria

- AC-1 A check shall fail the build when a product docs page lacks its Markdown twin, naming the page; evidence: a fixture site with one page missing its twin, which the check passes before the change and refuses after it. (serves EPC-022 AC-203)
- AC-2 Every page of the sample product docs shall have a Markdown twin generated from the same source, and `llms.txt` and `llms-full.txt` shall list and contain every page; evidence: a build over the sample where the page count equals the twin count and the entry count in both files, and a diff showing the existing `llms` generation extended and not rebuilt. (serves EPC-022 AC-203)
- AC-3 Product docs pages that describe a product surface shall carry a product screenshot with a text alternative, and the alternative shall also appear in the page's twin; evidence: the sample build and a planted screenshot without a text alternative that fails. (serves EPC-022 AC-203)
- AC-4 A twin shall match its page's source: a drift test shall fail when a twin differs from the page it was generated with; evidence: a planted edit to one twin that fails the test, with a clean control. (serves EPC-022 AC-203)
- AC-5 (journey) On a built sample site, fetching `llms.txt` shall give a link to every page's twin, and each twin shall open and match its page's title and headings; evidence: the fetch transcript over all pages. (serves EPC-022 AC-203)
- AC-6 (added 2026-11-02, operator requirement: samples, examples and templates steer the skills as real worked examples shipped in the kit, relayed by the Director at 12:3x on 2026-11-02; criteria-changes-2026-11-02.md at workspace commit 6976f9d) The product docs example, with its screenshots, Markdown twins and `llms` files, shall ship as a worked example on real CodeFlow content, read live from records and the line with its as-of time, in the `cf-docs-portal` kit as the template its skill names for it; it shall pass the bar of TSK-1097 and the portal gate; and it shall have an other-lineage review and the Coordinator's browser look at 1280 and 390 px in light and dark, recorded beside it; evidence: the committed example, the skill text naming it, the gate output, the review and the recorded look.
