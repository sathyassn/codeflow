# TSK-1013: The estimation method is in the shipped references, templates and plan flow, and CodeFlow's profile is on

## Description

Issue #334 items G (templates, `cf-ship` step, plan convention) and H, plus
the method ADR and CodeFlow's own adoption. This is the first of five tasks
that replace the old TSK-1013 and TSK-1012 (see EPC-022 for the cut). The
other four read what this one writes: the block shapes, the profile file
and the ADR. Nothing here is code.

Outcome: **after this merges, a planner in any adopted full-tier project can
write a Delivery size block, an epic Estimate section and a task Estimate
block from the shipped templates and `cf-plan`; the references explain the
bands and the clock; the pace rule is gone from every managed site; and
CodeFlow's `.codeflow/estimate.json` and `profile-v1.md` exist, so every
task created on or after the profile's effective date carries a band.**

Rules:

- The profile is optional. A project that leaves the blocks out validates as
  before; a missing block is a warning under the profile, never a failure.
- No band is written before the profile's effective date; ranges stay
  orientation. The Estimate block is frozen at breakdown with the profile
  revision.
- The clock is defined once in the references: it starts at the claim commit
  (or, for an adopted branch, the earlier first task commit) and ends at the
  later of the bound approval and the verification point, with the landing
  standing in when the completion was written later (operator decisions D1
  and D2, 2026-11-01). Until TSK-1173 and TSK-1172 land, the references say what the
  reader does today.

Non-goals: any code; banding CodeFlow's open tasks (decision P2.6); class
grouping and class validation (TSK-313, EPC-023, 4.1.0).

Criteria removed from this record by the 2026-11-01 cut, each moved and not copied (`AC-n removed: <reason>`):
