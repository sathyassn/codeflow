# TSK-1431: The release-route guard and its tests hold on Windows

## Description

TSK-1346 (complete, PR 716) added `security.outward_actions` refusals for release dispatch routes, with their tests. Its first Windows run, the EPC-022 line push after candidate 1111a (codeflow-ci 43020402245 on 79595078b, jobs 130528587069 and 130528586789), failed 13 tests. Log: `coordination/coordinators/parallel/logs/716-windows-43020402245.txt` (workspace a4d41082). Nothing below was run on Windows; the diagnosis is from reading the code and the log.

**Test defects (the 13 failures).**

- curl without `-q` (nine release-route tests and `hooks_cli` case F14, `guard_review_cases.rs:58-62`): on Windows the guard refuses curl without `-q` first, because curl there also reads a config file the guard does not check (recorded at `TSK-1346.md:247`). The refusal is intended and stays (Director 08:05). The tests expect the Unix outcomes.
- gh and HTTPie configs (four tests: `release_routes_tests.rs:1192`, `:1215`, `:1252-1262`, `:1295`, `:1402`): the fixtures write paths into shell lines in a form that shell parsing changes, so the config is not found and the call passes. The cause is the fixtures, not the guard's existence checks, which go through the filesystem (`absence.rs:55`).
- `review3_an_empty_config_variable_is_the_current_directory` (`:1555`): a separator mismatch in the test's expected path; the product refused correctly.

**Gaps in landed code that fail open on Windows.** No failing test reached them and no test covers them. They are in three classes, each about config a line sets for a client program on Windows that the guard does not yet judge as the client reads it. The cases stay in the workspace diagnosis until the fix is on `main`:

1. Config-variable names: the guard does not yet judge every config variable a client program reads on Windows. Item 1 of the workspace diagnosis gives the cases.
2. Config paths: the guard does not yet judge every config path at the folder the client reads on Windows. Item 2 of the workspace diagnosis gives the cases.
3. Config paths the guard cannot place: the guard does not yet refuse every config value it cannot place on Windows. Item 3 of the workspace diagnosis gives the cases.

The workspace diagnosis is coord/catalog's read-only diagnosis on TSK-1346's tree at 421154431, `coordination/coordinators/capabilities/builders/716-windows-diagnosis.md` (workspace 2d8d65c9), whose scope the Director approved at 08:1x.

Search (coord/records, 08:10): no open criterion covers this. TSK-391 (todo, EPC-050) covers how the shell guards resolve command operands on Windows (its AC-13) and planning paths (AC-3); it does not cover config-variable values or names in the release-route reader. TSK-1426 (standalone, coord/ci) fixes the edit guard's Windows test.

Source: coord/ci's report of the line push above (tree 9302443df); the Director's ruling of 2026-11-11 08:02 EST (a new fix-forward task, not a reopen of TSK-1346; coord/catalog builds it); coord/catalog's diagnosis above. Sites checked by coord/records at 08:20 EST against the candidate commit 6a543e376 (same tree as the line tip) and `main` f8aabc62c.

## Outcome

After this merges, the release-route tests pass on Windows with Windows expectations, and on Windows the guard reads each config variable a line assigns the way the client reads it, reads each config path where the client reads it, and refuses a config path it cannot place. On every OS, a line that sets a config variable the guard reads, in a form the guard cannot resolve, is refused. The line push is no longer red on these tests.

- AC-5 On Windows, the release-route tests and `hooks_cli` case F14 shall expect curl's refusal without `-q` (the Windows message), and the same call with `-q` first shall meet the Unix expectation, through one shared helper; the Unix assertions shall stay unchanged. - AC-6 The gh and HTTPie tests shall write fixture paths with `portable_path::slashed` and build expected paths with `Path::join(..).display()`, and `review3_an_empty_config_variable_is_the_current_directory` shall compare paths in the system's own separator.
