# TSK-1345: Seats run on the new Herdr app through hc, and CodeFlow drops the old Herdr host

## Description

Operator decision of 2026-11-05, relayed by the Director: "new only - codex and Grok will work - if we really want we can still open the sessions and check - only that we wont have them working right now".

CodeFlow 4.0.0 supports only the new Herdr app, reached with `hc`. `cf-herdr` is rewritten for `hc` and keeps its name. Old `herdr` steps leave skills, shipped templates, doctor and tests. `codeflow doctor` tells anyone on the old host that only the new app is supported and how to install it. The no-host fallback stays. A lost behaviour or platform with no host is recorded here and told to the Director, and does not reopen the decision unless it is a safety failure.

Research at `a5cd83c69`: `coordination/coordinators/planning/reviews/cf-herdr-hc-research.md` in the workspace repository. A live trial opened Codex and Grok on `hc` with the planned flags and closed them with no leftover processes. No prompt was sent, so real work, follow-up and resume are unproven; AC-12 covers them.

Issue [#618](https://github.com/sathyassn/codeflow/issues/618) reports the same gap from an adopter: `cf-herdr` and `deliver.py` do not work on a machine that runs Herdr on herdr-core. This task closes it; linked 2026-11-05 by the records follow-up after PR 617.

Findings this task closes:

- The cleanup rule at `cf-herdr/SKILL.md:195` reads only `herdr agent list`, which showed 0 agents with two `hc` seats live. An adopter following it could remove a worktree under a live seat.
- A kept terminal that loses its program returns as a plain shell at the same address, and `hc send` would run the prompt as a command. Not exercised.
- `transport.md:23` routes Codex through the app-server daemon, and the `hc` manual requires `--no-daemon`, or its commands run outside `hc`.
- `hc server status` tried to start a core on macOS, so detection must use a path lookup. A sandboxed `hc ls` fails with `cannot start core: Operation not permitted`, which must not read as no host.

What leaving old Herdr loses (recorded, not safety items):

| Lost | Replacement |
|---|---|
| Intel Mac host: CodeFlow ships `x86_64-apple-darwin`, the app lists no such build, so seats fall to tmux, degraded | None |
| Session reference in listings | Recorded ids and `argv` |
| Automatic resume after a server restart | Resume by hand from the recorded id |
| Paste without Enter | Short prompts, or a pointer to a brief file |
| `state_change_seq`, `completion_seq` | `hc send --wait`, `not_started`, `first_message`; not exercised |
| `agent start` readiness | `hc wait <t>` |
| Tabs that do not take focus | Labels, `hc attach`, `hc read` |
| Named test sessions | `HC_SESSION` with scratch XDG paths |

Non-goals: role and session management outside `hc` seats, rewriting history records, and the guards' reading of `hc` commands (TSK-1344).

## Outcome

After this merges, an adopter on the new app can start, message, read, resume and close Codex, Grok and tracked Claude seats through `hc` by following `cf-herdr`. An adopter on the old host, or with no host, is told plainly what to do.

## Acceptance Criteria

- AC-1 `cf-herdr` and its references shall cover discovery, naming, launch, first-run prompts, delivery, harvest, blocked seats, resume and cleanup with `hc` commands and no `herdr <subcommand>` step; evidence: the updated `herdr_host_contract` test and `git grep` output.
- AC-2 The worktree cleanup rule shall read `hc`, including `foreground.cwd`, and shall fail closed when `hc` cannot be read; evidence: a test with a live terminal in a scratch core.
- AC-3 The delivery script shall refuse a terminal whose status is not `idle`, including one with no status, one that is `blocked`, a terminal whose folder is gone, and an oversize prompt; evidence: `evals` delivery tests, including a recovered shell at a kept address.
- AC-4 Delivery to a tracked Claude seat shall handle a long prompt without paste-then-sentence, by a pointer to a brief file or another proven form; evidence: a lifecycle `accepted` result on a long brief in a live canary.
- AC-5 Codex shall launch with `--no-daemon` in both posture rows, with `transport.md` as the one home of that fact; evidence: `codeflow doctor --preflight` passes with the flag, and a canary shows a seat command running inside the `hc` terminal.
- AC-6 Seats that outlive their caller shall use `--outlive-parent` with an owner label, and cleanup shall list children before a kill; evidence: a canary in a scratch core showing a default child ends with its parent and an `--outlive-parent` child does not.
- AC-7 `cf-herdr` shall state that a resume moves a seat and never copies it, and give a check that works on a seat started with a resume id, with its limit for sessions started new; evidence: a canary refusing a second resume of a live id.
- AC-8 `codeflow doctor` shall report no gap with `hc` found; with `herdr` only, shall state that only the new app is supported and give that platform's install line; on an Intel Mac, shall name tmux and offer no app install; with neither host and tmux present on a platform the app supports, shall state that seats use tmux until the app is installed, with the install line; with neither host nor tmux, shall say there is no seat host; and shall start no core; evidence: doctor tests per case, and a test that the check never runs `hc server status`.
- AC-9 The transport rule and `cf-customize` shall use the trigger "`hc` is not installed or its core cannot run", and a sandbox refusal shall not read as no host; evidence: a contract test and the skill text.
- AC-10 The sandbox retry guidance and allow-list evidence shall name `hc` and no longer `herdr`; evidence: `settings_presets.rs` and the preset evidence file.
- AC-11 `evals/qualification`, `tests/release-qualification`, `evals/herdr-delivery`, `docs/delegation.md`, portal figures, `remedy.rs:831` and `skill-triggers` shall use `hc`, with tests on `HC_SESSION` and scratch XDG paths, never the user's core; evidence: the full gate on the landing candidate.
- AC-12 (journey) On the installed build, from a fresh trust state, one Codex seat and one Grok seat shall each take a read-only prompt, a follow-up and a resume on `hc`, with usage probed live at dispatch; evidence: a verification record with resume ids.
- AC-13 The change shall carry a successor ADR to ADR-0077, a CHANGELOG entry and a `type!:` commit with a `BREAKING CHANGE:` footer; evidence: the files and `codeflow ci`.
- AC-14 The cf-herdr hc guide states that a seat started through `hc run` inherits hc's terminal PATH, and that the seat's codeflow hooks need the `codeflow` binary on it. It gives the sanctioned launch form, which puts the directory of the installed codeflow binary (the one `codeflow doctor` reports) on the seat's PATH. It never names a worktree build or uses CODEFLOW_HOOK_BINARY. `codeflow doctor`, run in a seat with codeflow off PATH, reports that the hooks will fail and names the fix. Evidence: the guide text, plus a doctor test with codeflow off PATH.
  - Amended 2026-11-05: added by the Director's ruling, from coord/catalog's finding of 17:23: a seat started through `hc run` gets a terminal PATH without `~/.cargo/bin`, so its prompt hook fails with "codeflow: command not found". Added by the value audit planning pull request (PR 638) after PR 629 landed.
