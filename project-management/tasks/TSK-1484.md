# TSK-1484: Sandboxed sessions drive seats through a fixed broker that signs the model it observed

## Description

An agent session that runs inside the sandbox cannot reach the hc socket. This task builds a broker that runs outside the sandbox, as CodeFlow's hooks do, with a small grammar: start a seat, read it, send it one line, wait for it, and close it. That grammar and a sandbox profile for each seat it starts are shipped, and the operator's acceptance of floors F1 and F3 on 2026-11-13 fixes the parts those floors name, below.

The first step is C0, a short spike: hc's transport and its current verbs (create, read, send, wait, close), how a launch command is passed, and whether the CLI can be driven by a fixed argument list. The task is graded again after C0.

The operator decided on 2026-11-13 that this broker ships to adopters in this body. The Orca adapter uses the same grammar and is workspace code, outside this task.

The operator accepted floors F1 (TSK-1482 AC-9) and F3 on 2026-11-13. F1 fixes the grammar. F3 fixes all of these: the grammar cannot be extended; every launch form carries an enforced sandbox profile for its family and `nice -n 10`; the route table is read from a place no session can write; text that starts with `!` or `/` is refused, except `/compact`, `/clear` and `/new`; panes started by hand are not adopted.

The broker also records which model built a task (Director's ruling, 2026-11-14, which carries the outcome of the cancelled TSK-1469). When it starts a seat for a task, the broker reads the model that seat actually runs from a native source no session can write, ties that reading to the seat it started, and only then signs a record of the observed model and its lineage. The record is bound to the repository and the task, and signed with a key no session can read. It never signs the model its route table or the request names. The signing stays within the five verbs that F1 fixes.

A project turns the check on with the policy key `git.whole_epic_builder_record` (Director's ruling, 2026-11-14, under the operator's rule of 2026-11-12 that adopter-facing behaviour is configurable unless it is a safety floor; disclosed to the operator, who may overturn it). The key is `off` by default, and then whole-epic lines are judged exactly as today. At `block`, `codeflow ci` on the line of an epic marked `main_landing: whole-epic` verifies each task's record and refuses a task whose record is missing or whose lineage disagrees with `built_by`. A task built by a session the broker did not start, such as a native subagent of a session, has no record, so a line with the key at `block` refuses it. This task adds no broker route for native subagents.

What stays unproven until the broker exists:

- Today `built_by` is self-reported. The agent that completes a task writes it, and `codeflow ci` checks only its form and that the reviewer is of another lineage, or that a same-lineage review carries the reduced-assurance statement (TSK-1433). A false claim is not detected.
- So, on a whole-epic line today, nothing proves which model family built a task, and nothing proves that another family reviewed it.
- Once this task lands, with the key at `block`, the broker's record proves which model ran in the seat the broker started for the task. It still does not prove that this model wrote every change in the task's commits, or that the review was independent.
- With the key `off`, the default, builder lineage on a whole-epic line stays unproven after this task lands, as it is today.

Non-goals: the Orca adapter; the routes for other tools (TSK-1482); the preset change (TSK-1483); key rotation beyond replacing the public half on the default branch; a broker route for native subagents.

## Outcome

after this merges, a sandboxed agent session can start, read, prompt, wait for and close hc seats through the broker's grammar, and a project that sets `git.whole_epic_builder_record` to `block` has its whole-epic lines land a task only when the broker's signed record of the model observed in the seat it started for that task, in that repository, agrees with `built_by`.
