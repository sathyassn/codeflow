# TSK-1484: Sandboxed sessions drive seats through a fixed broker

## Description

An agent session that runs inside the sandbox cannot reach the hc socket, and a sandbox exemption for hc would let any program drive any terminal, the session's own included. This task builds a broker that runs outside the sandbox, as CodeFlow's hooks do, with a small grammar: start a seat, read it, send it one line, wait for it, and close it. That grammar and a sandbox profile for each seat it starts are the shipped defaults. Whether any of them becomes a restriction an adopter cannot edit is the operator's ruling on floors F1 and F3, below.

The first step is C0, a short spike: hc's transport and its current verbs (create, read, send, wait, close), how a launch command is passed, and whether the CLI can be driven by a fixed argument list. The task is graded again after C0.

Whether this broker ships to adopters in this body is the operator's choice, pending. If it does not ship, doctor reports seat control as unavailable for adopters, and the broker stays this workspace's. The Orca adapter uses the same grammar and is workspace code, outside this task.

Fixed floors apply only where the operator accepts them. Accepting proposed floor F1 (TSK-1482, pending) is enough to fix the grammar. Proposed floor F3 (pending) fixes all of these: the grammar cannot be extended; every launch form carries an enforced sandbox profile for its family and `nice -n 10`; the route table is read from a place no session can write; text that starts with `!` or `/` is refused, except `/compact`, `/clear` and `/new`; panes started by hand are not adopted. The operator's ruling on F3 is recorded in this task before the broker is built. Until then these are proposals, and the builder builds nothing that only the floor requires.

Non-goals: the Orca adapter; the routes for other tools (TSK-1482); the preset change (TSK-1483).

## Outcome

after this merges, a sandboxed agent session can start, read, prompt, wait for and close hc seats through the broker's grammar.

## Acceptance Criteria

- AC-1 The C0 spike shall record hc's transport and authentication, the verbs a seat needs, how a launch command is passed, and whether the CLI can be driven by a fixed argument list, before the broker is built. Evidence: the spike record, with its sources and any probe.
- AC-2 The broker shall accept the requests its grammar defines, shipped as five verbs (start, read, send one line, wait, close), and refuse every other request with a refusal that names the grammar. Evidence: tests for each verb and for refused requests.
- AC-3 (journey) For each seat kind the broker supports, a sandboxed session shall start a seat, send it one line, read its reply and close it, through the broker only. Evidence: one journey per seat kind with the installed build.
- AC-4 `codeflow init`, `codeflow update` and `codeflow doctor` shall install, update and report the broker, or report seat control as unavailable where it is not installed. Evidence: tests for each verb.
- AC-5 Each part of the broker an adopter can change (which seat kinds, which models and efforts, the launch profiles, and the grammar and its refusals unless an accepted F1 (TSK-1482 AC-9) or F3 (AC-6) fixes them) shall be a documented default, and an edited value shall survive `codeflow update`. Evidence: the docs text and an update test. (serves EPC-058 AC-3)
- AC-6 If the operator accepts floor F3: the grammar shall not be extensible; every launch form shall carry `nice -n 10` and an enforced sandbox profile for its family, namely Codex under `cf-guard` or `cf-builder`, Grok under an explicit sandbox profile, and Claude with the sandbox on, `failIfUnavailable: true` and `allowUnsandboxedCommands: false`, with no unsandboxed launch form; the route table shall be read from `~/.codeflow/authority`, which sessions are denied; text starting with `!` or `/` shall be refused except `/compact`, `/clear` and `/new`; and panes started by hand shall not be adopted. The floor shall be listed in the pull request and the docs, with its reason under the public-text rule of TSK-1483 AC-7. If the operator rejects F3 or changes it, this criterion is cancelled or amended with that ruling before the broker is built, and the other criteria stand with the shipped defaults, subject to any other floor the operator accepts: with F1 accepted, the grammar stays fixed under TSK-1482 AC-9. Evidence: a test per rule, including one per seat family showing each required profile value in the launch form and a refused launch form without it.
- AC-7 The whole unit shall have a cross-family security review with the `cf-security-reviewer` checklist, its seat checked live at dispatch. Evidence: the review record.
