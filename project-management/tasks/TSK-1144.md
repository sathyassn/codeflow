# TSK-1144: The bootstrap guide and adopter docs walk each stage step by step

## Description

The step-by-step bootstrap guide and the adopter docs. They cover each stage (inventory, classification, evidence, review) and what a comprehensive catalog is: user-facing, internal and technical capabilities, functional and non-functional, each classified by the generic facets and by project facets the project derives from itself. They say how an agent decides what counts as one capability, how to resolve evidence (test, journey, record, or a declared gap), what the review checks, and when the project moves the check from `warn` to `block` (once `inventory: complete` and `codeflow ci` is a required check). The guide is harness-neutral. Basis: `.codeflow/rules/capabilities.md` (created by TSK-1136 for declarations; this task adds the bootstrap part), one adopter doc page and a worked example from CodeFlow's real capabilities.

Design: `coordination/coordinators/capabilities/design-note.md` revision 5 and the operator's comments of 2026-11-01 (about 12:47 EST) in the same folder's `DIRECTION.md`.

## Outcome

After this merges, an agent or person in a newly adopting project can follow written steps from an empty catalog to a comprehensive, reviewed one and know when to turn the check to `block`.

## Deliverables

- the bootstrap part of the guide: `assets/base/rules/capabilities.md` (mirrored to `.codeflow/rules/capabilities.md`)
- the adopter docs page: `docs/` (path chosen with the docs structure; the adopter docs index links it)
- a worked example using three real CodeFlow capabilities

## Acceptance Criteria

- AC-1 The guide shall give each of the four stages its inputs, steps, output and exit check, and shall define "comprehensive" over user-facing, internal and technical capabilities and functional and non-functional ones, including the surface and quality sweep checklist (each CLI command, hook, guard, policy key, scaffolded asset, skill, agent, CI template, doc and harness adapter; each quality attribute such as security, performance, reliability, compatibility, portability and observability) that every entry or exclusion is decided against; evidence: review against the operator's words in DIRECTION.md. (serves EPC-026 AC-11)
- AC-2 The guide shall state when and how a project moves the check to `block`, and shall name no one harness; evidence: a grep for harness names and review. (serves EPC-026 AC-11)
- AC-3 A reader with no CodeFlow background shall be able to run the stages on a sample project from the guide alone; evidence: one fresh-context walk-through on a non-Rust sample, with its notes. (journey) (serves EPC-026 AC-11)
