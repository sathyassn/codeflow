# TSK-1326: The Monitor guard's recognised payload shape is confirmed on each new Claude Code release

## Description

Source: coord/ci, 2026-11-04 12:47, and TSK-1058's completion on PR 577 (head 7180bea7b). TSK-1058 confirms the `Monitor` tool's command payload only on Claude Code 2.1.318 (a native hook capture) and 2.1.317 (the tool schema); the `ws.url` socket form comes from the 2.1.317 schema alone, never from a native payload. A later Claude Code release can change the payload, and a guard that no longer recognises a field must still refuse.

This task confirms the recognised shape on each new Claude Code release from a native capture and keeps the guard fail closed. Recognised fields widen only from a native capture.

## Outcome

After this merges, an operator can see, for each Claude Code release since 2.1.318, whether the Monitor payload the guards recognise was confirmed by a native capture, and a payload they do not recognise is refused.

## Deliverables

- the shape record per release: `docs/verification/evidence/tsk-1058/` (TSK-1058's home), extended
- any widened matcher and its tests: the guard's Monitor field reader and `crates/codeflow-cli/tests/hooks_cli/monitor_fields.rs`

## Acceptance Criteria

- AC-1 For each Claude Code release after 2.1.318 that the project supports, a native hook capture of a `Monitor` call shall be recorded with the release number, for the command form and the `ws.url` socket form; evidence: the capture files.
- AC-2 A recognised field shall be added only when a native capture shows it, and a payload with an unknown or missing field shall still be refused; evidence: a policy test per added field and one for an unknown field.
- AC-3 (journey) With the installed build under the newest supported Claude Code, a refused command given to `Monitor` shall be refused as it is under `Bash`; evidence: the session output.
