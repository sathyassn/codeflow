# TSK-354: Essential Rust tests run under nextest with doctests and the same membership

## Description

Source: the gate speed discovery of 2026-10-17, ranked change 2 and its
section "Rust execution and the slow tests".

Before this task, the essential `rust-workspace` target ran `cargo test
--workspace --quiet` (`.codeflow/test-config.json`). Cargo ran test binaries
one after another, so the slowest binary of each crate sets the pace: in run
`f5c9303a-23be-48b4-9908-8b9be010d034` the target spent 1,689.67 of
1,733.18 seconds inside 99 libtest result blocks. The full gate already
runs the suite under nextest (`rust-coverage`, `cargo llvm-cov nextest
--profile codeflow`) with a separate `rust-doctest` target; nextest
schedules single tests across binaries. A simple longest-first model of
the retained JUnit gives an upper planning clue of about half the elapsed
time at 10 workers; it is not a measurement.

Under the 2026-10-17 decision builders no longer run essential, so this
target now runs only when the primary, a reviewer or a pipeline asks for
essential. Such a run uses the same runner, isolation and serial groups
as the full gate, so the two modes cannot disagree about a test because
of the runner. The speed comparison is deferred under AC-4's amendment.

Outcome: essential Rust verification runs under nextest with an explicit
doctest step, with exactly the same test membership as today.

Non-goals: filtering or moving slow tests (TSK-356), the coverage
threshold, and any change to shipped Rust defaults for adopters. Product
surface: this repository's gate config and nextest profile only.

## Deliverables

- the essential target: `.codeflow/test-config.json` (`rust-workspace` under nextest, and an essential doctest target or step)
- the profile: `.config/nextest.toml` (an essential profile with JUnit output; serial group kept)
- the evidence: completed end-to-end run, membership diff and existing measurements in the pull request body, with reproduction commands; the deferred speed comparison is tracked once in EPC-022
