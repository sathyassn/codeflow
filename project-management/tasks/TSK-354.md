# TSK-354: Essential Rust tests run under nextest with doctests and the same membership

## Description

Source: the gate speed discovery of 2026-10-17, ranked change 2 and its
section "Rust execution and the slow tests".

The essential `rust-workspace` target runs `cargo test --workspace
--quiet` (`.codeflow/test-config.json`). Cargo runs test binaries one after
another, so the slowest binary of each crate sets the pace: in run
`f5c9303a-23be-48b4-9908-8b9be010d034` the target spent 1,689.67 of
1,733.18 seconds inside 99 libtest result blocks. The full gate already
runs the suite under nextest (`rust-coverage`, `cargo llvm-cov nextest
--profile codeflow`) with a separate `rust-doctest` target; nextest
schedules single tests across binaries. A simple longest-first model of
the retained JUnit gives an upper planning clue of about half the elapsed
time at 10 workers; it is not a measurement.

Under the 2026-10-17 decision builders no longer run essential, so this
target now runs only when the primary, a reviewer or a pipeline asks for
essential. The value is that such a run finishes sooner and uses the same
runner, isolation and serial groups as the full gate, so the two modes
cannot disagree about a test because of the runner.

Outcome: essential Rust verification runs under nextest with an explicit
doctest step, with exactly the same test membership as today.

Non-goals: filtering or moving slow tests (TSK-356), the coverage
threshold, and any change to shipped Rust defaults for adopters. Product
surface: this repository's gate config and nextest profile only.

## Deliverables

- the essential target: `.codeflow/test-config.json` (`rust-workspace` under nextest, and an essential doctest target or step)
- the profile: `.config/nextest.toml` (an essential profile with JUnit output; serial group kept)
- the comparison: same-revision timings, membership diff and worker comparison in the pull request body, with the commands that reproduce them

## Acceptance Criteria

- AC-1 The set of non-ignored tests the essential Rust target runs shall
  equal the set `cargo test --workspace` runs at the same revision, apart
  from doctests, which a separate essential step runs; evidence: the two
  sorted test lists and their diff (empty), and the doctest step's output.
  (serves EPC-022 AC-50)
- AC-2 Intentional exclusions shall be unchanged: ignored tests, the
  release benchmark and the exhaustive oracle stay full-only; evidence: the
  ignored list before and after.
- AC-3 The serial group, environment isolation and process cleanup shall
  still hold: no test in the serial group overlaps another, and the essential
  runner leaves no temporary folder or process that the previous cargo runner
  did not already leave; existing fixture residue is listed by path and test
  and assigned to TSK-386; evidence: a run's JUnit timestamps for the serial
  group and a process and temp-folder check after the run.
- AC-4 On one unloaded host at one revision, `codeflow test --mode
  essential --only rust-workspace` shall run the new step end to end, and its
  elapsed time shall be reported for the old command and the new one, at
  four and eight nextest workers, with fixture construction counts for the
  slowest binaries; the change is adopted only if it is not slower;
  evidence: the timing table and commands in the pull request. (journey)
- AC-5 The full gate's `rust-coverage` and `rust-doctest` targets, the
  coverage floor of 90 and their membership shall be unchanged; evidence:
  the config diff touches neither target.

AC-3 amendment, 2026-10-19: the primary assigned existing static fixture
residue to TSK-386 so this runner change proves it adds no leakage.
