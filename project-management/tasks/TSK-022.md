# TSK-022 — apply and verify accountable worker delegation

## Description

Apply SPC-009's accountable delegation and Claude design-execution policy across
CodeFlow guidance, evaluation and distribution, then run focused native proof
against real bounded work. Any scoped qualification must be supported by the
pre-registered workload's outcome evidence in the same reviewed PR; this task
also removes the implication that a Codex-hosted production unit must execute in
the primary's current session. It does not promise savings, promote a primary
binding or redesign product UI.

## Affected surfaces and interfaces

AGENTS/CLAUDE, CAP-010/CAP-013, architecture and a newly allocated ADR; canonical
orchestrator, capability-routing, quality, delegate, customize and develop
guidance plus applicable design wording and all managed mirrors; existing
`cf-evaluate-model` requirements/cases/fixtures and a focused pack only if
needed; `model_eval_contract`, orchestration, scaffold/update, manifest and
distribution tests; one durable native verification report. No product UI or
separate runtime routing surface.

## Acceptance Criteria

- [ ] Root and skill guidance separates accountable primary responsibility from
  execution; expects suitable delegation for substantial bounded routine work,
  permits concrete primary-direct exceptions, records actual execution/provenance
  and never creates a scheduler, task-ledger policy engine or blanket child default.
- [ ] Design direction, authorship, implementation/execution and fidelity remain
  owned by the Claude design seat. A candidate design route must be under that
  binding and is usable only in controlled disposable qualification fixtures;
  only scoped-qualified may execute real settled `design-implementation`. Other
  families review, challenge and QA unless Plan vN records an explicit
  task-specific operator override; Claude absence alone is not an override.
- [ ] Hard deterministic requirements and cases cover candidate versus
  scoped-qualified, actual selector/effort provenance, same-selector validity,
  primary-retained exceptions, capacity unknown/shared-bucket handling,
  unqualified/wrong-lineage design execution, mixed/stale authorship, unavailable
  tools, preserved security boundaries, primary accountability and independent
  review. Cases accept an explicit user override naming another design family,
  and treat unknown quota as advisory unless a hard limit depends on it. They do
  not turn these exceptions into unconditional bans or equate policy-text success
  with native proof.
- [ ] Pre-register a narrow pilot for routine backend implementation and evidence
  collection, comparing primary-retained and same-family candidate execution
  under the same acceptance/review gates, with three fresh trials per case/arm.
  Retain every attempt, real work products, observed exact route/selector/effort,
  primary integration behavior, cross-family review, rework, all-attempt
  coordination overhead, elapsed/resource evidence and limitations; never
  fabricate unavailable telemetry.
- [ ] A route changes to scoped-qualified only when every pre-registered trial
  meets its task-class quality floor with complete trace, primary integration and
  cross-family review; evidence and status land atomically. Any failed acceptance,
  missing applied identity/trace or unresolved validity threat leaves it
  candidate. A successful small cohort supports only its narrow workload claim;
  it does not establish universal reliability. Scoped status covers only the
  harness/selector/effort/workload tuples evidenced: narrow the route or evidence
  every tuple before flipping it. Design-policy tests are not design-route
  fidelity qualification.
- [ ] An economical-default or savings recommendation requires a separate
  measured all-in capacity, time or cost benefit, including every attempt,
  coordination and rework. Scoped workload quality alone never supplies that
  recommendation or a default-promotion claim.
- [ ] Fresh and brownfield scaffold/update tests prove all canonical assets,
  mirrors, manifests and consumer customizations remain coherent, then the full
  configured gate suite and exact native Claude source/evidence review pass on
  the integrated result.

## Execution contract

EPC-008 Plan v1 and SPC-009, after guarded TSK-021 integration. The Codex
engineering primary is accountable. It may dispatch bounded prose/eval/
distribution units through a same-family Sol/high candidate route, records
requested and observed values honestly, and inspects/accepts the result; the
reason is to preserve primary capacity for integration and review without
claiming lower cost. The settled native-Fable wording owns policy and design
direction; Codex/Sol implements it without reauthoring that judgment. Native
Claude independently reviews the exact unit and final integrated evidence before
`integration/resource-aware-routing`. If current native preflight confirms Grok
Build availability, run one bounded interactive Grok adversarial pass over the
integrated contract and evidence; retain an evidenced limitation otherwise. This
adds challenge evidence only—it is not a standing-primary replacement, a silent
vote, a headless launch or authority for third-party authentication. Use one task
writer, at most two active coding workers overall and one heavyweight build.
Stop for a new dual-approved plan if the pilot, schemas, ownership or graph must
materially change.
