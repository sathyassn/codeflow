# TSK-355: Unchanged deterministic gate results are reused while push protections stay live

## Description

Source: the gate speed discovery of 2026-10-17, ranked change 3 and its
section "Exact reuse and changed-input selection are different".

The same checks run again on inputs already proven. In the retained
records, sixteen groups of clean passing runs repeated the same snapshot,
config, mode and selection, fifteen of them quick runs. Two quick runs at
`dec65cb133e4` and `d37e55ed86be` share Git tree
`14956b9f5b20400ff7d1f802db432877ca1efb38` and cost 2.18 and 1.72 target
minutes; quick repeats usually cost 1 to 3 target minutes and one cost
10.53 with build waits. The pre-push hook calls `run_gate_exact(root,
"quick")` with no reuse (`crates/codeflow-core/src/hooks/git_hook.rs`,
`run_push_targets`).

Outcome: a target whose inputs, command and environment are unchanged
since a recorded pass reuses that result and names the run it came from,
while every push protection still runs live.

Decisions recorded here:

- The reuse key binds the target's command and config, the digests of its
  declared transitive inputs, its producers' output digests, its test
  membership, the platform and architecture, the actual compiler and test
  runner versions, relevant flags and environment, and evidence that the
  inputs did not change during the recorded run. A tree digest alone is not
  a key.
- Only deterministic, content-input targets qualify. A target that reads
  history, remotes, time, a vulnerability database or scanner rules never
  reuses. The repository's config decides which targets qualify; unknown
  means no.
- Reuse is per target. A reused result never makes a partial run complete
  and never certifies a full gate. A full gate on a landing candidate
  executes every target.
- The pre-push ref, range, authority, release preflight and checked-out-tree
  checks are never reused.

Non-goals: hosted CI reuse (TSK-359), a shared compiler cache (TSK-357).
Product surface: adopter-facing engine (CAP-004 run records and the gate
runner) and the pre-push hook path.

## Acceptance Criteria

- AC-1 When a qualifying target's key matches a recorded clean pass, the
  run shall report it as reused with the source run id, and otherwise it
  shall execute; evidence: a test with two commits of one tree (the
  recorded `dec65cb133e4` and `d37e55ed86be` pair reproduced in a fixture).
  (serves EPC-022 AC-51)
- AC-2 A changed input, command, producer output, toolchain or runner
  version, platform, relevant environment value or test membership shall
  each cause a miss, as shall a missing, corrupt, failed, partial or legacy
  record; evidence: one test per case.
- AC-3 Two commits with the same tree but different history shall still
  run every history-dependent target, and a records-only commit shall
  re-run the targets that read records; evidence: fixture tests.
- AC-4 A run that reuses any target shall never be recorded complete, and
  a full gate shall execute every target; evidence: run record assertions.
- AC-5 Different modes shall not share a key when their commands differ;
  evidence: a quick and an essential target with the same name and
  different commands.
- AC-6 The pre-push hook shall reuse only qualifying quick target results,
  and its ref, range, authority, release preflight and checked-out-tree
  checks shall run on every push, including a push of several refs; a
  history-dependent or secret-range check shall never be reused; evidence:
  the existing pre-push tests unchanged plus a test that a second push of
  the same tree reuses the qualifying targets and runs the rest.
- AC-7 (journey) With the installed build, two pushes of the same tree from
  two commits shall show the second push's qualifying quick targets as
  reused with the first run's id, and a third push with one changed source
  file shall execute the targets that read it; evidence: the three pushes'
  output with elapsed time.
