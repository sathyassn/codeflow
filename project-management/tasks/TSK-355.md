# TSK-355: Unchanged deterministic gate results are reused while push protections stay live

## Description

Source: the gate speed discovery of 2026-10-17, ranked change 3 and its
section "Exact reuse and changed-input selection are different". Amended
after the Codex review of PR 226 (finding F3 and a minor on producer
outputs).

The same checks run again on inputs already proven. In the retained
records, sixteen groups of clean passing runs repeated the same snapshot,
config, mode and selection, fifteen of them quick runs. Two quick runs at
`dec65cb133e4` and `d37e55ed86be` share Git tree
`14956b9f5b20400ff7d1f802db432877ca1efb38` and cost 2.18 and 1.72 target
minutes; quick repeats usually cost 1 to 3 target minutes and one cost
10.53 with build waits. The pre-push hook calls `run_gate_exact(root,
"quick")` with no reuse (`crates/codeflow-core/src/hooks/git_hook.rs`,
`run_push_targets`).

Outcome: in an explicit gate run, a target whose evidence matches an
execution attested through TSK-1044's trust mechanism reuses that result
and names the run that executed it, while a push still runs no
test-config target (TSK-449), every push protection still runs live and
a landing candidate's gate still executes everything. If TSK-1044 lands
with no protected recorder, reuse from local records is not enabled: every
requested target executes with the reason, and the reuse scope returns to
the epic's planning notes as deferred, never to credit from writable
records. (Amended 2026-10-28 after the PR 378 review: since TSK-449 the push runs no test-config
target, and reuse depends on TSK-1044.)

Credit rows (TSK-1044 settles which one holds; every criterion below
that narrows, skips, reuses or recommends `--since` is checked against
both):

| Row | When | Required behavior |
|---|---|---|
| A | the operator adopted a protected recorder in TSK-1044 | the positive journeys: selection narrows, skips and reuse happen only from attested executions |
| B | no protected recorder | every requested target runs and the reason is reported; no output recommends `--since` where it cannot narrow; positive narrowing, skip and reuse journeys are marked deferred in the epic's planning notes |

This task builds on the input classes and per-target evidence TSK-352
adds; it does not define a second key.

Decisions recorded here:

- **Two kinds of completeness.** A *completed target execution* is one
  target that ran to its end in some run: its exit status was recorded, it
  was not interrupted, cancelled or timed out, it passed, its declared
  inputs were unchanged from its start to its end, and every output it
  declares exists with a recorded digest. A *complete gate* is today's
  run-level `complete`: an unrestricted full run with no skipped target.
  Reuse needs the first and never produces the second.
- **What may be reused.** A completed target execution from any run
  (quick, essential, full or `--only`), whether or not that run was a
  complete gate, may be reused when its `content` class and its evidence
  (TSK-352: mode and command, tools, platform, relevant environment,
  membership, producer outputs and inputs) match the current check. A
  target of any other class or with any missing evidence executes.
  Environment equality uses TSK-352's one contract (audited non-secret
  metadata as values, opaque keyed fingerprints otherwise, fail closed when
  neither is safe); this task adds no other encoding and never stores or
  prints a raw environment value.
- **Producer outputs.** A consumer is reused only when each producer's
  output exists now and matches its recorded digest; a missing or corrupt
  output makes the producer execute and the consumer re-evaluate.
- **Provenance.** A reused result names the run that executed it; a result
  reused again keeps naming that original run, never an intermediate one.
- **Never certification.** A run that reuses any target is never recorded
  complete. A landing candidate's gate runs with `--all` and executes every
  target (TSK-352).
- **Push protections.** The pre-push ref, range, authority, release
  preflight and checked-out-tree checks are never reused. The repository's
  config decides which targets qualify; unknown means no.

Non-goals: hosted CI reuse (TSK-359), and any compiler cache (not adopted; TSK-357 records the verdict).
Product surface: adopter-facing engine (CAP-004 run records and the gate
runner) and the pre-push hook path.

## Investigation (AC-9)

Recorded 2026-11-01 at line tip `bee344658`, before any code change.

### Which credit row holds

Row B. TSK-1044 is complete and the operator decided on 2026-10-30 to
adopt no local recorder and to drop the Claude presets'
`~/.codeflow/gate-runs` grant (TSK-1044 "Operator decision (AC-4)").
ADR-0089 withdrew all selection credit from local run records on every
platform: "a key any of them can read authenticates nothing". Credit can
return only from a recorder no agent session and no candidate test can
use, such as hosted CI attestation, and that is a new decision. So no
local result may be reused here, and this task delivers row B only.

### Readers and writers of the records reuse would consume

| Site | Role today | Reuse use under row B |
|---|---|---|
| `crates/codeflow-core/src/testing/gate.rs:339-520` | writes `run.json` under `<target>/codeflow-gate/<run-id>/` and copies a full run to `~/.codeflow/gate-runs/<repo>/<run-id>/` through the contained tree | report only; no reader |
| `crates/codeflow-core/src/testing/delivery.rs:400-432` `select` | selects every eligible target unless `--only`; reads no record; `--since` narrows nothing and the reason says so | unchanged: every requested target runs with the reason |
| `crates/codeflow-core/src/hooks/git_hook.rs` pre-push | runs no test-config target since TSK-449; ref, range, authority, release preflight and checked-out-tree checks run live | unchanged |
| `codeflow integrate` | runs its own full gate and writes a durable record | unchanged; never reads an earlier record |

No production code reads a stored `run.json` to decide what runs; the
only readers are tests (for example `gate.rs:1423`).

### Who can write them

Every record is written by a process of the user: the operator's shell,
an agent session (Codex profiles and, until the operator's 2026-10-30
decision, the Claude presets could write `~/.codeflow/gate-runs`), and
the candidate's own tests, which run inside the gate as the same user.
The build-output copy under `<target>/codeflow-gate/` is writable by any
session working in the worktree. A forged, replayed or planted record,
or one reached through a link, cannot be told apart from a real one by
owner, mode or content, so none can earn reuse.

### Adjacent concerns

- Links in the evidence directory: TSK-1044 contained every evidence
  write and the durable copy refuses links on both sides; reuse adds no
  new reader, so no new link-following surface.
- Hosted CI reuse of a named green run is TSK-359, the only sound route
  to credit named so far (GitHub artifact attestations with the workflow
  identity, per TSK-1044's comparison table).
- Speed: under row B this task removes no local work. The CI and local
  gate time the operator asked to cut on 2026-11-01 must come from
  TSK-359 (hosted reuse) and the later chain (TSK-384, TSK-1026), not
  from local reuse.
