# TSK-355: Unchanged deterministic gate results are reused while push protections stay live

## Description

Source: the gate speed discovery of 2026-10-17, ranked change 3 and its
section "Exact reuse and changed-input selection are different". Amended
after the Codex review of PR 226 (finding F3 and a minor on producer
outputs).

The same checks run again on inputs already proven. In the retained
records, sixteen groups of clean passing runs repeated the same snapshot,
config, mode and selection, fifteen of them quick runs. Two quick runs at
`dec65cb133e4` and `d37e55ed86be` share Git tree
`14956b9f5b20400ff7d1f802db432877ca1efb38` and cost 2.18 and 1.72 target
minutes; quick repeats usually cost 1 to 3 target minutes and one cost
10.53 with build waits. The pre-push hook calls `run_gate_exact(root,
"quick")` with no reuse (`crates/codeflow-core/src/hooks/git_hook.rs`,
`run_push_targets`).

Outcome: a target whose evidence matches a recorded execution reuses that
result and names the run that executed it, while every push protection
still runs live and a landing candidate's gate still executes everything.

This task builds on the input classes and per-target evidence TSK-352
adds; it does not define a second key.

Decisions recorded here:

- **Two kinds of completeness.** A *completed target execution* is one
  target that ran to its end in some run: its exit status was recorded, it
  was not interrupted, cancelled or timed out, it passed, its declared
  inputs were unchanged from its start to its end, and every output it
  declares exists with a recorded digest. A *complete gate* is today's
  run-level `complete`: an unrestricted full run with no skipped target.
  Reuse needs the first and never produces the second.
- **What may be reused.** A completed target execution from any run
  (quick, essential, full or `--only`), whether or not that run was a
  complete gate, may be reused when its `content` class and its evidence
  (TSK-352: mode and command, tools, platform, relevant environment,
  membership, producer outputs and inputs) match the current check. A
  target of any other class or with any missing evidence executes.
  Environment equality uses TSK-352's one contract (audited non-secret
  metadata as values, opaque keyed fingerprints otherwise, fail closed when
  neither is safe); this task adds no other encoding and never stores or
  prints a raw environment value.
- **Producer outputs.** A consumer is reused only when each producer's
  output exists now and matches its recorded digest; a missing or corrupt
  output makes the producer execute and the consumer re-evaluate.
- **Provenance.** A reused result names the run that executed it; a result
  reused again keeps naming that original run, never an intermediate one.
- **Never certification.** A run that reuses any target is never recorded
  complete. A landing candidate's gate runs with `--all` and executes every
  target (TSK-352).
- **Push protections.** The pre-push ref, range, authority, release
  preflight and checked-out-tree checks are never reused. The repository's
  config decides which targets qualify; unknown means no.

Non-goals: hosted CI reuse (TSK-359), and any compiler cache (not adopted; TSK-357 records the verdict).
Product surface: adopter-facing engine (CAP-004 run records and the gate
runner) and the pre-push hook path.

## Acceptance Criteria

- AC-9 Before any change, the builder shall investigate broadly: TSK-1044's landed trust rule for local gate records and what it leaves a reuse decision able to trust, every reader and writer of the records reuse would consume, which sessions and tests can write them, and adjacent concerns (forged, replayed and planted records, links in the evidence directory); and shall record how reuse earns credit only from evidence those processes cannot write, with the chosen scope, before any change; evidence: the record section, committed before the first code change in the PR. Added 2026-10-28 with the edge to TSK-1044, by the operator's rule of 2026-10-27 that an amended task starts with an investigation.
- AC-1 When a qualifying target's evidence matches a completed target
  execution, the run shall report it as reused with the original executing
  run's id, and otherwise it shall execute; a result reused twice shall
  still name the original run; evidence: a quick-to-quick test with two
  commits of one tree (the recorded `dec65cb133e4` and `d37e55ed86be` pair
  reproduced in a fixture) and a chained reuse test. (serves EPC-022 AC-51)
- AC-2 A target execution that was interrupted, cancelled, timed out or
  failed, whose inputs changed during it, whose declared outputs are
  missing or corrupt, or whose record is missing, corrupt or legacy shall
  never be reused; a changed input, command, producer output, toolchain or
  runner version, platform, relevant environment value or test membership
  shall each cause a miss; evidence: one test per case.
- AC-3 A consumer whose producer's output is missing or does not match its
  recorded digest shall not be reused; the producer shall execute first;
  evidence: tests that delete and that corrupt a producer output.
- AC-4 Two commits with the same tree but different history shall still
  run every non-`content` target, and a records-only commit shall re-run
  the targets that read records; evidence: fixture tests.
- AC-5 A run that reuses any target shall never be recorded complete, and a
  landing candidate's `--all` full gate shall execute every target even
  when every target has a matching execution; evidence: run record
  assertions.
- AC-6 Different modes shall not share a result when their commands
  differ; evidence: a quick and an essential target with the same name and
  different commands.
- AC-7 The pre-push hook shall reuse only qualifying quick target results,
  and its ref, range, authority, release preflight and checked-out-tree
  checks shall run on every push, including a push of several refs; a
  history-dependent or secret-range check shall never be reused; evidence:
  the existing pre-push tests unchanged plus a test that a second push of
  the same tree reuses the qualifying targets and runs the rest.
- AC-8 (journey) With the installed build, two pushes of the same tree from
  two commits shall show the second push's qualifying quick targets as
  reused with the first run's id, and a third push with one changed source
  file shall execute the targets that read it; evidence: the three pushes'
  output with elapsed time.
