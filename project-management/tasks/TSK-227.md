# TSK-227: Baseline commit ids must resolve

## Description

The first public history rewrote commit ids, and the baselines in
`.codeflow/project.toml` kept the archive ids until every pull request failed
the record checks (TSK-198). Nothing noticed that the ids had stopped
resolving. This task adds one test that reads the real project file, collects
every full commit id under a key with `baseline` in its name
(`work_records_baseline`, `release_records_baseline`, `release_rule_baseline`
and any later one), and fails naming the key and the id when the repository
cannot resolve one.

The two release tables are the one stated exception. They are a write-once
bridge (SPC-013 R-120) and keep five archive-line cutoff ids that a
public-only clone does not hold, so the test lists those ten entries and
checks the list in both directions: an entry that leaves the tables fails, a
release table id that is not listed fails, and an archive id under the work
records baseline fails. Each entry is pinned by table, line and id, so an
entry removed, moved to another line or added fails. Resolution needs the
history the baselines name, which a shallow clone does not hold, so in a
shallow clone the resolution test says so and skips (the hosted Windows test
partitions check out shallow); the hosted Linux gates and any full clone run
it. The decision to leave the release tables on archive
ids is recorded in TSK-226. Non-goals: moving any baseline, and changing the
release judge.

## Deliverables

- the baseline resolution test: crates/codeflow-core/tests/project_baselines_resolve.rs

## Acceptance Criteria

- AC-1 When a baseline commit id in `.codeflow/project.toml` does not resolve
  in the repository, the test shall fail naming the key and the id, except
  the release tables' listed archive ids, and shall pass on this tree.
  Evidence: `cargo test -p codeflow-core --test project_baselines_resolve`,
  including a control that builds a throwaway repository and reports a
  rewritten id, an archive id under the work records baseline, a listed
  archive id at the wrong line and an unlisted release id while a held id
  and a listed release archive entry pass, and a control that reports a
  removed, moved or extra release table entry. (journey)
- AC-2 The test shall pass in a public-only clone of this branch, where the
  archive objects are absent, and shall skip with a stated reason, never fail
  falsely, in a shallow clone. Evidence: the same command in a fresh full
  clone of the public repository with this branch checked out, and in a
  `--depth 1` clone of it.
