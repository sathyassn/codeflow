# TSK-1588: A privacy finding is exempted only by an authority-held register entry bound to one path and value

## Description

Owner: to be assigned by the Director. Staged 2026-11-23 for coord/records.

SPC-018 R-31 to R-34. Some identifying values belong in a repository: a
copyright holder in `LICENSE`, a maintainer contact in `SECURITY.md`. The
request asks that such exemptions be tracked records with an exact path
and value or pattern, a reason, an approver and an expiry, changed only
through a reviewed pull request and always shown. TSK-424 (EPC-024, as
amended by this plan) is the one register; this task makes privacy
findings its consumer.

Settled constraints:

- ADR-0091 (`:44`, both revisions): only the default branch at one commit
  supplies an exception; a head-introduced entry for a blocking class
  never applies (TSK-424 AC-4, main `:152`, tip `:170`).
- TSK-428 AC-8 (main `:142`, tip `:140`) is the model consumer: a path or
  pattern, reason and expiry, no whole-directory entry.
- A value is bound by fingerprint, never plain text (SPC-018 R-32), so the
  register does not leak what it exempts. A path that itself holds a
  privacy value is bound by `path_fingerprint` too, and reports print the
  entry id in its place (R-7a, R-32). A layer 2 pattern holds no literal
  identifying value; it uses only the non-literal forms the placeholder
  table lists.
- The approver is two fields: `approver`, a role, and `approved_in`, the
  approving pull request number (SPC-018 I3; TSK-424 AC-18 as amended).
- TSK-424 already refuses an exception past its expiry (AC-1, AC-6; tip
  `:163`, `:174`). That refusal stays; the expired entry also stops
  applying, so the finding it covered shows again (R-34).

## Outcome

After this merges, a privacy finding is cleared only by a register
`exception` held at the default branch that names its rule, one exact
path and the value's fingerprint or a narrow pattern, with reason, task,
approver and expiry; every applied entry is printed in that run's
output, and any widening shows in the pull request evidence.

## Deliverables

- the privacy consumer of the register: `crates/codeflow-core/src/privacy/exemptions.rs` (new)
- `codeflow privacy fingerprint <rule> [<path>]`: reads the value, or with no path argument the path, on standard input and prints only the fingerprint
- docs: the privacy exemption route in `docs/policy-reference.md`; `changelog.d/TSK-1588.md`

## Acceptance Criteria

- AC-1 Fail before: at the base, no route exists to exempt a privacy finding; at the head with this task's tests but without its consumer, an authority-held entry does not clear the finding; evidence: the failing test run, quoted in the PR.
- AC-2 An authority-held entry with every field, the exact path and the value's fingerprint shall clear that one occurrence, and the same value at another path, or another value at that path, shall still be a finding; evidence: consumer tests.
- AC-3 An entry introduced, widened (another path, a broader pattern, a later expiry) or re-dated at the head shall not apply in that run, at any level, and shall be listed in the pull request evidence as added or widened; evidence: tests for each change.
- AC-4 An entry with a plain value field, a directory or glob path, a pattern for a layer 3 kind, a pattern that matches outside its path, a pattern holding a literal identifying value (a literal email such as an address at a non-reserved domain, assembled at run time), a plain-text path that holds a privacy value, a missing `approver`, or a missing or non-numeric `approved_in` shall be refused naming the entry and field, without printing the value; evidence: one test per refusal.
- AC-5 Every applied entry shall be printed (id, rule, path redacted by SPC-018 R-7a or the entry id for a fingerprinted path, approver, `approved_in`, expiry) in `pre-commit`, `commit-msg`, `pre-push` and `codeflow ci`; an expired entry shall keep TSK-424's refusal, shall not apply, and the run shall print both the entry as expired and the finding it covered at its level; the fingerprint command shall never echo its input; evidence: output tests per placement, an expiry test asserting both lines, and a canary test on the command.
- AC-6 An entry for a path that holds the contributor's home segment in a folder name, bound by `path_fingerprint`, shall clear that occurrence, and the register file, every report and the CI annotation shall hold neither the segment nor the plain path; evidence: the consumer test, using the real home-path detector of TSK-1586 (a predecessor), and the path canary of TSK-1583 AC-6 run over the register file and the reports.
