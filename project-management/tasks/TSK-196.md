# TSK-196: task branches push their own criteria changes

## Description

TSK-184 lets a task change its own acceptance criteria in its own pull
request, and `codeflow ci` prints the change for the reviewer. The pre-push
check runs `codeflow ci` without a pull request body, so it has no class
and refused any task branch that carries such a change, which blocked the
pushes of TSK-190 and TSK-191. With no body, a task branch's only valid
class is its own task, so the check now reads that task's criteria rule
from the branch. Non-goal: no change to how a pull request body is judged;
CI with the body stays the gate.

## Acceptance Criteria

- AC-1 (journey) When a task branch that changes its own task's criteria is checked
  without a pull request body (the pre-push path), `codeflow ci` shall
  accept the change as it does for that task's pull request, and still
  refuse a change to another task's criteria and a completed task's
  frozen criteria. Evidence: an `acceptance_cli` test that fails before
  the change and passes after, beside the existing freeze tests.
