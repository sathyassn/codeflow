# TSK-1489: The guards judge the transport program a remote URL selects

## Description

To reach a remote, git can start a helper program. It chooses that program from the remote's address, or from the remote's configuration even when the address has an ordinary form or there is no address at all. The guards do not judge that program for every way git can select it, so a command that contacts such a remote can start a program that no guard has judged. Both guards judge the program word of every command they see, so this is a gap in that rule, not a separate one.

TSK-1479 admits agent fetches and pushes for one remote shape only, so it closes the gap for that admission and not for other commands that contact a remote. The gap is already on `main`. It was found by the second sweep of TSK-1479's review (coord/catalog, 2026-11-12), and no open record holds it. Three other items from that sweep are already in TSK-1057 AC-6.

## Outcome

After this merges, every git command that contacts a remote, explicitly or implicitly, has the transport git will select resolved first. When that transport starts a helper program, both guards refuse the command or judge the program by the same rules as any other program word. Commands that reach a remote over an ordinary transport, with no configured program selection, keep today's verdict.

## Deliverables

- one shared transport resolution, used by both guards, that finds what git will use for each remote a command contacts: every effective destination (a push can have several, a fetch uses the first), after the address rewrites git applies in each direction, and any program the remote's configuration selects, in git's order of precedence
- refusal of every resolved transport that starts a helper program, unless the program is judged as a program word, with the rule and the way through named
- tests fed as hook payload strings and scratch configurations, following the private matrix; nothing under test is executed and no remote is contacted
- the refusal in the guard documentation in class words, and in the release notes' list of new refusals

## Acceptance Criteria

- AC-1 When a git command contacts a remote whose resolved transport starts a helper program, whether git selects it from the address or from the remote's configuration, and whether the command names the remote, names an address or contacts it implicitly, git-guard and exec-guard shall refuse it, or judge that program by the program-word rules; the refusal shall name the rule and the way through. Evidence: one test row per selection form in the private matrix and per guard, each failing before the change and passing after, each asserting the finding comes from this rule.
- AC-2 Commands that reach a remote over https, ssh (the URL and the short host form) or a local path or file address, with no configured program selection and no rewrite to such a selection, shall keep today's verdict, and so shall the fetches and pushes TSK-1479 admits. Evidence: control rows passing before and after.
- AC-3 The transport shall be resolved for every effective destination of the command, after the rewrites git would apply for that direction, in git's order of precedence. When the guard cannot read the configuration it shall refuse, naming what it could not read; when it reads the configuration but cannot resolve the transport git would select, it shall refuse, naming the remote. Evidence: test rows for a fetch rewrite and a push rewrite, for a remote with several push destinations of which one starts a helper program, for an unreadable configuration and for an unresolved selection, each a separate row.
- AC-4 The guard documentation shall describe the refusal in class words, and the release notes shall list it among the new refusals (operator decision D5, 2026-11-12). Evidence: the doc diff, the changelog fragment and `codeflow validate --docs`.
- AC-5 The change shall get one cross-family security review with the `cf-security-reviewer` checklist. The pull request shall state the threat it closes and why resolving the transport in one shared check, and refusing what it cannot resolve, is the fail-closed design. No address form, configuration key or payload shall appear in the pull request title, its body summary, any commit subject, the changelog fragment or a test name until the fix is on `main`. Evidence: the review row, and the pull request as opened, checked by the reviewer.
- AC-6 (journey) With the built binary, a scratch project shall refuse, through the hook entry, a fetch payload whose remote resolves to a transport that starts a helper program, and shall pass the same fetch to an https remote. The output of each guard that judges the payload shall be captured, and the refusal shall be this task's rule, not an unrelated finding. Evidence: both outputs.
- AC-7 A project shall admit named helper programs through one list in its policy: a remote helper the transport resolution selects, and a credential helper Git starts while it contacts a remote, which the account rule refuses today. The guards shall read the list only from the policy landed at the remote's default branch; it shall be empty by default, and no value set by the command line, the session's own configuration or an unlanded policy shall add to it. With the list empty, the refusals of AC-1 and the account refusal of a credential helper on a command that contacts a remote stay as they are. With a helper named, a remote helper is judged as a program word, and a credential helper's account finding is skipped on a command that contacts a remote, never on a command that reads a credential directly, and every other finding on that helper stands. This list is the only list of admitted helpers: TSK-1479's admission names remote URLs and adds no helper list of its own. Evidence: rows for an empty list, a named remote helper, a named credential helper on a fetch and on a push, the same helper on a direct credential read (refused), and a list set only in the working copy or by a command-line setting (refused); the policy schema and reference entries; and the pull request stating the threat and why a list read only from landed policy is the standard design (Director ruling, 2026-11-14).
