# TSK-1489: Tighten how the guards judge remote operations

## Description

The guards judge some git commands that contact a remote less strictly than their existing rules require. Both guards apply those rules to every command they see, so this is a gap in an existing rule, not a separate one. The detail stays in the private matrix and the review evidence until the fix is on `main`.

TSK-1479 admits agent fetches and pushes for one remote shape only, so it closes the gap for that admission and not for other commands that contact a remote. The gap is already on `main`. It was found by the second sweep of TSK-1479's review (coord/catalog, 2026-11-12), and no open record holds it. Three other items from that sweep are already in TSK-1057 AC-6.

## Outcome

After this merges, both guards judge every git command that contacts a remote, explicitly or implicitly, by their existing rules, and refuse a remote operation they cannot judge, naming the rule and the way through. Commands that reach an ordinary remote keep today's verdict.

## Deliverables

- one shared check, used by both guards, that works out what git will do for each remote a command contacts: every effective destination (a push can have several, a fetch uses the first), after the changes to a remote's location that git applies in each direction, and any choice the remote's configuration makes, in git's order of precedence
- refusal of every remote operation the check finds outside the guards' rules or cannot work out, with the rule and the way through named
- tests fed as hook payload strings and scratch configurations, following the private matrix; nothing under test is executed and no remote is contacted
- the refusal in the guard documentation in class words, and in the release notes' list of new refusals

## Acceptance Criteria

- AC-1 When a git command contacts a remote, whether the command names the remote, names its location or contacts it implicitly, git-guard and exec-guard shall judge what git will do for that remote by their existing rules, and refuse it when those rules do not admit it; the refusal shall name the rule and the way through. Evidence: one test row per form in the private matrix and per guard, each failing before the change and passing after, each asserting the finding comes from this rule.
- AC-2 Commands that reach a remote over https, ssh (both forms), a local path or a file location, with an ordinary configuration, shall keep today's verdict, and so shall the fetches and pushes TSK-1479 admits. Evidence: control rows passing before and after.
- AC-3 The check shall cover every effective destination of the command, after the changes to a remote's location that git would apply for that direction, in git's order of precedence. When the guard cannot read the configuration it shall refuse, naming what it could not read; when it reads the configuration but cannot work out what git would do, it shall refuse, naming the remote. Evidence: a fetch row and a push row for the two direction-specific location changes in the fourth case group of the private matrix for AC-1 and AC-3 (a change git applies to fetch and push, and a change it applies to push only), each judged after the change git applies for its direction, in git's order; these are the first two unit rows that the AC-3 evidence of the first archived acceptance block under Closeout names. Also a row for a remote with several push destinations of which only a later one is refused (the matrix's third case group), a row for an unreadable configuration and a row for a configuration the guard cannot resolve, each a separate row.
- AC-4 The guard documentation shall describe the refusal in class words, and the release notes shall list it among the new refusals (operator decision D5, 2026-11-12). Evidence: the doc diff, the changelog fragment and `codeflow validate --docs`.

- AC-6 (journey) With the built binary, a scratch project shall refuse, through the hook entry, a fetch payload whose remote is set up as a case of the first, second or fourth case group of the private matrix for AC-1 and AC-3, and shall pass the same fetch to an https remote. The output of each guard that judges the payload shall be captured, and the refusal shall be this task's rule, not an unrelated finding. Evidence: both outputs.
- AC-7 A project shall admit, through one list in its policy, named entries of two kinds: the first kind, an entry that a remote is set up to use as in the first, second or fourth case group of the private matrix for AC-1 and AC-3, which this task's check refuses; the second kind, an entry git uses while it contacts a remote, which the account rule refuses today. The guards shall read the list only from the policy landed at the remote's default branch; it shall be empty by default, and no value set by the command line, the session's own configuration or an unlanded policy shall add to it. With the list empty, the refusals of AC-1 and the account rule's refusal of an entry of the second kind on a command that contacts a remote stay as they are. With an entry of the first kind named, it is judged by the guards' existing rules, and every finding on it stands. With an entry of the second kind named, its account-rule finding is skipped on a command that contacts a remote, never on a command that reads the entry's stored value directly, and every other finding on it stands; the skip applies to the second kind only. This list is the only such list: TSK-1479's admission names remotes and adds no list of its own. Evidence: rows for an empty list, a named entry of the first kind, a named entry of the second kind on a fetch and on a push, the same entry of the second kind on a direct read (refused; the direct-read case of the row that the AC-7 evidence of the first archived acceptance block under Closeout names last), and a list set only in the working copy or by a command-line setting (refused); the policy schema and reference entries; and, once the fix is on `main`, the threat and why a list read only from landed policy is the standard design, stated as AC-5 provides (Director ruling, 2026-11-14; amended 2026-11-16 with AC-5, the wording made general the same day, and the two kinds kept distinct as before).
