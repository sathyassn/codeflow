# TSK-1489: Tighten how the guards judge remote operations

## Description

The guards judge some git commands that contact a remote less strictly than their existing rules require. Both guards apply those rules to every command they see, so this is a gap in an existing rule, not a separate one. The detail stays in the private matrix and the review evidence until the fix is on `main`.

TSK-1479 admits agent fetches and pushes for one remote shape only, so it closes the gap for that admission and not for other commands that contact a remote. The gap is already on `main`. It was found by the second sweep of TSK-1479's review (coord/catalog, 2026-11-12), and no open record holds it. Three other items from that sweep are already in TSK-1057 AC-6.

## Outcome

After this merges, both guards judge every git command that contacts a remote, explicitly or implicitly, by their existing rules, and refuse a remote operation they cannot judge, naming the rule and the way through. Commands that reach an ordinary remote keep today's verdict.

## Deliverables

- one shared check, used by both guards, that works out what git will do for each remote a command contacts: every effective destination (a push can have several, a fetch uses the first), after the changes to a remote's location that git applies in each direction, and any choice the remote's configuration makes, in git's order of precedence
- refusal of every remote operation the check finds outside the guards' rules or cannot work out, with the rule and the way through named
- tests fed as hook payload strings and scratch configurations, following the private matrix; nothing under test is executed and no remote is contacted
- the refusal in the guard documentation in class words, and in the release notes' list of new refusals
