# TSK-1593: Added content that holds the contributor's own identity is a privacy finding

## Description

Owner: to be assigned by the Director. Staged 2026-11-23 for coord/records.

SPC-018 R-20 and R-21. The matcher compares added content (lines, added
paths, messages) with the identity values of one run: case folded, NFC,
on token boundaries, with the whole value and its separator variants
(`<first> <last>`, `<first>.<last>`, `<first>-<last>`,
`<first>_<last>`, `<first><last>`). Values under 4 characters and the
generic set in the placeholder table are skipped, and the skip is counted
without the value.

Overlap with TSK-1372 (EPC-027, todo, `origin/main` only): TSK-1372
judges a commit's header fields: the author email against a project glob
list in the hooks and CI (AC-3, `TSK-1372.md:44`), the author name
against the no-reply login (AC-4, `:45`), and, in an agent session only,
the committer against the project's checked-in expected values (AC-2,
`:43`). This task never judges headers, so a
commit authored under the contributor's own name is not a layer 3
finding. TSK-1372's criteria stay unchanged.

This task proves the matcher alone, as a library over the frame's input
types. No hook calls it yet: the wiring, the hook tests and the speed run
are TSK-1594's and TSK-1595's.

## Outcome

After this merges, the matcher reports, for added content lines, added
paths and messages holding the contributor's git name or email, login,
full name, home user segment, any host name or Tailscale name, a
`privacy.identity.<kind>` finding with its place and never the value,
ready for TSK-1594 to wire into the hooks.

## Deliverables

- `crates/codeflow-core/src/privacy/identity/matcher.rs` (new) with tests
- docs: matching rules; `changelog.d/TSK-1593.md`

## Acceptance Criteria

- AC-1 Fail before: at the base, the matcher test suite, with placeholder identity values given through the test seam, fails because no matcher exists (a full name in a comment line, a host name in a log line and a login in a path are not reported); evidence: the failing test run in the PR.
- AC-2 Pass after: each kind shall be a matcher finding in a content line, in an added path and in a commit message, in each separator variant and case; evidence: matcher tests per kind.
- AC-3 A value inside a longer word with no token boundary, a value under 4 characters and a value in the generic set shall not be findings, and the matcher's skip count shall count them without naming them; evidence: tests.
- AC-4 Given a commit's author and committer header values equal to the identity values, and content that holds neither, the matcher shall report nothing: it reads content, never headers; evidence: a test.
- AC-5 A finding on an added path shall carry the redacted path of SPC-018 R-7a, and the canary seam of TSK-1583 AC-6 shall find no identity value in any matcher output, in content and path cases; evidence: the canary tests extended to the matcher.
- AC-6 The matcher's own cost on the typical-change fixture, with every identity kind present, shall be measured (median of five runs, Linux and Apple silicon macOS) and recorded for TSK-1595's final speed run; evidence: the micro-benchmark and its medians in the PR.
