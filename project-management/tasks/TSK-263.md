# TSK-263: Shipped guidance makes engineering rigour a habit at every tier

## Description

A builder, reviewer or tester who follows the shipped guidance should reason
through the scenario cases, the long-term shape, the fit with the
repository and the checks that read what they changed, without a new form
to fill. Two hosted CI breaks showed the gap: PR 84 changed the guard's
absence walk and nobody ran `rust-workspace`, the essential-only target that
holds `name_decode_scan`; PR 126 reworded CAP-010 and nobody ran the
full-only `docs-portal` target whose figure fidelity check reads it.

This task adds a sentence or a clause to thirteen managed instruction files,
so the every-tier rule file carries the lifetime question, the neighbour and
boundary sentence, the shortcut rule, the scenario classes and the
consumer-check definition, and the standard and full skills add the
derivation method with the one-failure probe advice, the performance
trigger, `TEST_PLAN` content and source-to-sink on the security trigger. It
raises two reading guidelines the wording needs, adds three eval
requirements and cases, moves the shipped pipeline's verify stage to
`codeflow test --mode essential --strict` where the config defines
`essential` (review stays on `codeflow validate` plus quick), and gives this
repository's `docs-portal` target and its `docs-portal-deps` prerequisite an
`essential` mode, so an essential run checks figure fidelity. Design:
`target/rigour-plan.md` revision 2 with the operator's section 5 decisions
of 2026-10-08: (a) the `Not tested:` clause for code PRs, (b) no departure
bullet, only the reviewer fit clause, (c) the probe as advice in
`coverage.md`, no record, (d) verify on essential, (e) the docs-portal
essential mode in this task.

Non-goals: a command that lists the test targets reading a changed path (a
standalone follow-up); a gated `Not tested:` content check; a departure
bullet; a recorded probe; a change to `cf-stack` or to the coverage floor
phrase pinned by TSK-184.
