# TSK-1044: Gate evidence cannot be redirected or forged by an agent session

## Description

Source: the Codex security review of TSK-337 (PR 375) on 2026-10-27,
findings 1 and 2 (`.worktrees/tsk-337/target/review-TSK-337-codex-01.md`,
session `01a18068-1704-7682-a9e8-322c84d7164f`). Both concern the durable
gate evidence under `~/.codeflow/gate-runs/<repo>/<run-id>/`, which any
process running as the user can write, an agent session included.

- **Writes follow planted links (CWE-59).** A full gate copies its run
  directory into the durable root with `copy_evidence`
  (`crates/codeflow-core/src/testing/gate.rs:513`, `:629`), which uses
  `create_dir_all` and `fs::copy` and rejects no link at a destination
  ancestor, directory or final file. The run directory is visible before
  the targets finish (`:345`). A process that can write `gate-runs` can
  plant a link there, and a later gate, possibly run with wider file
  access, writes through it outside the evidence directory. The reviewer
  reproduced the link following with a scratch harness of this copier;
  no end-to-end privileged attack was run. The run directory itself is
  already created through the anchored helper `crate::contained::Tree`
  (`gate.rs:533`).
- **Skip credit from records anyone can write (CWE-345).** `green_base`
  (`crates/codeflow-core/src/testing/delivery.rs:330`) accepts a
  `run.json` by Git tree, config digest and claimed successful, clean and
  complete execution; `target_covered` (`:617`) checks consistency of
  the record's own claims, and a match removes an opted-in content
  target from a quick or essential run (`:557`). Records are not
  authenticated or bound to a commit SHA, and the ownership and
  permission check (`read_owned_record`, `:236`) cannot tell an agent
  from the real recorder, since both run as the same user. A writer of
  `gate-runs` can forge local skip credit in an adopter project that opts
  into reusable content targets.

Scope of each finding:

- Link-following writes affect every gate that writes evidence, default
  full runs included: a full run with a revision writes its durable copy
  (`gate.rs:506`, `copy_evidence` at `:629`), and the copier has no
  platform exclusion, so containment is needed on macOS, Linux and
  Windows (where the threat is junctions and other reparse points).
- Forged selection credit does not reach hosted CI (`--all`,
  `.github/workflows/codeflow-ci.yml`), a default full run (all targets
  forced when `--since` is absent, `gate.rs:186`), integration
  (`integrate.rs:585`) or Windows (no local selection credit). It does
  reach every selection-capable run: quick and essential runs and a full
  run with `--since`, which reaches the same record-based selection
  (`delivery.rs:557`). This repository declares no reusable content
  target today.

Who can write `gate-runs` today: Claude sessions, through the shipped
presets' sandbox write grant (`assets/base/settings/default.json:368`,
`acceptEdits.json:369`, `bypass-sandboxed.json:447`, and this
repository's `.claude/settings.json:488`), which full gates in a sandboxed
session need for the evidence preflight (`gate_guard.rs:241`) and the
durable copy (`gate.rs:513`). Codex builders would have had the same
access; TSK-337 (PR 375) drops that grant from `cf-builder` and amends its
AC-5.

Outcome: **no gate writes outside the durable evidence directory whatever
links or special files are planted in it, and no record a session or a
candidate's tests can write removes a requested target from any gate
run; the shipped Claude presets keep, narrow or drop the `gate-runs`
grant by the operator's recorded decision, which states what it means
for running full gates in an agent session.**

Rules:

- Secure by default (the operator's rule of 2026-10-24): fail closed
  when a check cannot be sure; bind trust to identities a requester
  cannot forge, never to file contents, names or ownership the requester
  controls; and remove a feature that cannot be made sound rather than
  patching its bypasses.
- Evidence writes use anchored traversal (the existing
  `crate::contained::Tree`, or its equivalent for the home directory):
  every component is opened without following links, links and special
  files are refused at ancestors, directories and final files, and
  files are created without following an existing name.
- Skip credit comes only from a recorder whose authority the agent
  session and the candidate's tests cannot exercise. A key or token they
  can read does not count. If no such recorder is sound on a platform,
  local selection credit from these records is withdrawn there and every
  requested target runs.
- Ordinary run reports stay writable and readable; cited run ids for
  landing evidence keep working. Readable is not trusted: a record
  written before this change, or by any process the session can run,
  stays report-only and is never promoted to credit.
- Any uncertain case (an unreadable, unauthenticated, pre-upgrade or
  replayed record, or authentication that is unavailable) runs the
  requested target or refuses; it never grants credit.
- Decision owner (`cf-method/references/autonomy.md`: a material
  security boundary the brief does not fix is the operator's): the
  operator decides whether the shipped Claude presets keep, narrow or
  drop the `~/.codeflow/gate-runs` grant, and whether a protected
  recorder is adopted. The builder investigates and brings the options
  with the full-gate route for each. Until the operator decides, the
  interim state holds: writable reports earn no credit; an unresolved
  grant or recorder authority authorizes nothing that depends on it
  (TSK-353's skips, TSK-355's reuse, TSK-1039's `--since` narrowing);
  and the containment repairs of AC-2 proceed, since they do not wait
  on the decision. The decision clears when the operator's choice is
  recorded in this task's Closeout and in the epic's planning notes.

Non-goals: result reuse itself (TSK-355, which follows this task's
trust rule); the Codex profile's grant (TSK-337); hosted CI.

### Link classes and races

- A symbolic link or Windows junction at any destination component, the
  run's own destination folder included, is refused by the walk; an
  ancestor swapped after the walk cannot redirect it, since each step is
  relative to a held handle (`contained.rs:12-16`).
- In the durable copy, the local `run.json` and the probe, a link or hard
  link raced in at a final file after its folder was made is refused by the
  exclusive create (`Tree::create_new`: `O_EXCL|O_NOFOLLOW` on Unix,
  `FILE_CREATE` relative to the held parent on Windows). Each target's logs
  and report copies use `Tree::write`, an atomic replace: a link raced in at
  that name is replaced by the rename, never written through
  (`contained.rs:16-18`).
- A special file (pipe, socket, device) is refused by type before it is
  opened; the old copier would block on a pipe.
- The trusted roots are the project folder, the parent of an absolute
  `CARGO_TARGET_DIR`, and the parent of the CodeFlow home. The build-output
  folder and the home folder themselves are entered without following, so
  a link at either is refused. A held directory moved during a write
  carries the file with it (an object anchor, `contained.rs:13-16`);
  nothing is written through it.

### Selection credit

Selection-capable runs were quick, essential and full with `--since`
(`delivery.rs:557` through `select`; `gate.rs:186` forces every target
only for a full run without `--since`). Every run with a revision writes
durable evidence: a default full run, a full run with `--since`, and
`codeflow integrate` (`gate.rs:506`).

No sound recorder exists on any platform today. Every record is written by
a process the session or the candidate's tests can run as the same user,
so a claim of success in a record proves nothing, and a key either of them
can read is no proof either. Comparable tools reach soundness only through
an identity the builder cannot use:

| Tool | How local results are trusted | Sound for agent sessions? |
|---|---|---|
| Nix multi-user mode (Nix manual, "Multi-User Mode") | the store is owned by root and written only by the daemon, which builds as separate `nixbld` users | yes, through a separate OS principal; a large install and operating change |
| Bazel disk cache and remote cache (Bazel docs, "Remote Caching") | the local disk cache is trusted as written; the docs advise letting only CI write the remote cache | only the CI-written remote cache |
| Gradle build cache (Gradle docs, "Build Cache") | the local cache is the user's; the docs recommend CI as the only remote-cache writer | only the CI-written remote cache |
| Turborepo remote cache signing (Turborepo docs, "Remote Caching") | an HMAC key from the environment | no: the session can read the key |
| sccache and ccache | same-user local caches, unauthenticated | no |
| GitHub artifact attestations (GitHub docs, "Using artifact attestations") | signed with the workflow's OIDC identity in hosted CI | yes, for hosted runs |

Adopters affected by withdrawal: none in this workspace. `codeflow`,
`agent-os` and the shipped templates declare no `input_class: content`
target (checked 2026-10-30 in each `.codeflow/test-config.json` and under
`assets/base`). An adopter that opted in loses local skips: quick,
essential and full runs with `--since` execute those targets again. Before
this change Windows already granted no credit.

### Chosen design

- Containment: every evidence write, the lock files and the report read
  go through `crate::contained::Tree` from a held root above the build
  output and home folders, with exclusive creates in the durable copy; a
  refusal names the full path and fails the gate.
- Credit: withdrawn on every platform (ADR-0089). `select` runs every
  eligible target unless `--only` limits it; `--since` is accepted and
  narrows nothing. Records stay as reports and run ids stay citable.
  Withdrawing is required whatever the preset decision, since the
  candidate's tests can write the store in any case.

### Options for the operator (AC-4)

For the Claude presets' `~/.codeflow/gate-runs` grant, with credit
withdrawn and writes contained:

| Option | What a session can then do | Full-gate route in an agent session |
|---|---|---|
| Keep (the interim state) | edit or delete reports; nothing it writes earns credit or redirects a gate's writes | unchanged: the probe (`gate_guard.rs:241`) and the durable copy (`gate.rs:513`) succeed in the sandbox |
| Narrow to the repository's own folder (`~/.codeflow/gate-runs/<digest>`) | the same, for one repository | the digest is per repository, so `codeflow update` would write a per-repository entry; same route as keep |
| Drop | nothing under `gate-runs` | a sandboxed full gate fails the evidence preflight and the copy; the full gate runs outside the sandbox (the operator's terminal or an approved unsandboxed run) |

For a protected recorder, which would allow credit again:

| Option | Soundness | Cost |
|---|---|---|
| None (recommended now) | credit stays withdrawn | none beyond lost local skips |
| Credit from hosted CI runs (attested by the workflow identity, as TSK-359's reuse of a named green run) | sound: no local process holds the identity | needs hosted runs on the exact tree; a later task |
| A separate OS user or daemon that runs the targets and owns the store | sound only if the targets run under yet another identity, since they run inside the recorder | installation, privileges and per-platform service code |

The builder's recommendation: keep the grant (nothing in it earns trust
now), adopt no local recorder, and route any future reuse through hosted
CI attestation. The cross-lineage security review (round 1) recommends
drop instead, if in-sandbox full gates are not required: with the grant
kept, a session can still edit or delete the reports a pull request cites
as landing evidence; it rejects narrow, since the per-repository folder
leaves the same tamper. Either way the containment holds, since an
unsandboxed gate would otherwise follow a link planted in the worktree.
