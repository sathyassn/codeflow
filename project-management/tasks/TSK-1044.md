# TSK-1044: Gate evidence cannot be redirected or forged by an agent session

## Description

Source: the Codex security review of TSK-337 (PR 375) on 2026-10-27,
findings 1 and 2 (`.worktrees/tsk-337/target/review-TSK-337-codex-01.md`,
session `01a18068-1704-7682-a9e8-322c84d7164f`). Both concern the durable
gate evidence under `~/.codeflow/gate-runs/<repo>/<run-id>/`, which any
process running as the user can write, an agent session included.

- **Writes follow planted links (CWE-59).** A full gate copies its run
  directory into the durable root with `copy_evidence`
  (`crates/codeflow-core/src/testing/gate.rs:513`, `:629`), which uses
  `create_dir_all` and `fs::copy` and rejects no link at a destination
  ancestor, directory or final file. The run directory is visible before
  the targets finish (`:345`). A process that can write `gate-runs` can
  plant a link there, and a later gate, possibly run with wider file
  access, writes through it outside the evidence directory. The reviewer
  reproduced the link following with a scratch harness of this copier;
  no end-to-end privileged attack was run. The run directory itself is
  already created through the anchored helper `crate::contained::Tree`
  (`gate.rs:533`).
- **Skip credit from records anyone can write (CWE-345).** `green_base`
  (`crates/codeflow-core/src/testing/delivery.rs:330`) accepts a
  `run.json` by Git tree, config digest and claimed successful, clean and
  complete execution; `target_covered` (`:617`) checks consistency of
  the record's own claims, and a match removes an opted-in content
  target from a quick or essential run (`:557`). Records are not
  authenticated or bound to a commit SHA, and the ownership and
  permission check (`read_owned_record`, `:236`) cannot tell an agent
  from the real recorder, since both run as the same user. A writer of
  `gate-runs` can forge local skip credit in an adopter project that opts
  into reusable content targets.

Not affected: hosted CI (`--all`, `.github/workflows/codeflow-ci.yml`),
default full runs (all targets forced, `gate.rs:185`), integration
(`integrate.rs:585`) and Windows (no local selection credit). This
repository declares no reusable content target today.

Who can write `gate-runs` today: Claude sessions, through the shipped
presets' sandbox write grant (`assets/base/settings/default.json:368`,
`acceptEdits.json:369`, `bypass-sandboxed.json:447`, and this
repository's `.claude/settings.json:488`), which full gates in a sandboxed
session need for the evidence preflight (`gate_guard.rs:241`) and the
durable copy (`gate.rs:513`). Codex builders would have had the same
access; TSK-337 (PR 375) drops that grant from `cf-builder` and amends its
AC-5.

Outcome: **no gate writes outside the durable evidence directory whatever
links or special files are planted in it, and no record a session or a
candidate's tests can write removes a requested target from any gate
run; the shipped Claude presets keep, narrow or drop the `gate-runs`
grant by a recorded decision that states what it means for running full
gates in an agent session.**

Rules:

- Secure by default (the operator's rule of 2026-10-24): fail closed
  when a check cannot be sure; bind trust to identities a requester
  cannot forge, never to file contents, names or ownership the requester
  controls; and remove a feature that cannot be made sound rather than
  patching its bypasses.
- Evidence writes use anchored traversal (the existing
  `crate::contained::Tree`, or its equivalent for the home directory):
  every component is opened without following links, links and special
  files are refused at ancestors, directories and final files, and
  files are created without following an existing name.
- Skip credit comes only from a recorder whose authority the agent
  session and the candidate's tests cannot exercise. A key or token they
  can read does not count. If no such recorder is sound on a platform,
  local selection credit from these records is withdrawn there and every
  requested target runs.
- Ordinary run reports stay writable and readable; cited run ids for
  landing evidence keep working.

Non-goals: result reuse itself (TSK-355, which follows this task's
trust rule); the Codex profile's grant (TSK-337); hosted CI.

## Acceptance Criteria

- AC-1 Before any change, the builder shall investigate broadly: every writer and reader of `~/.codeflow/gate-runs` and the run directory listed in the survey, with which sessions, harnesses and tests can write each path on macOS, Linux and Windows; how link, junction and special-file attacks reach each write (ancestors, the run directory, final files, replacement races between check and use); what `crate::contained::Tree` already covers and what a home-directory anchor needs; how comparable tools protect local build caches and attest local results (a separate OS user or service, a keychain-held key the session cannot use, content-addressed outputs), and whether any is sound for CodeFlow's agent sessions; the adopters who opt into reusable content targets and what withdrawing credit costs them; the Claude preset grant and the full-gate preflight that needs it; and shall record the findings with sources, the chosen design and the preset decision before any change; evidence: the record section, committed before the first code change in the PR.
- AC-2 A full gate shall write its durable evidence without following any link: with a link planted at a destination ancestor, at the run's destination directory, at a final file such as `run.json`, or swapped in between check and use, and with a link or special file inside the source run directory, the gate shall refuse with a message naming the path, write nothing outside the evidence directory, and leave the target of the link unchanged; evidence: one test per case with a victim file outside the directory, each failing before the change (the fail-before reproduction of finding 1). (serves EPC-022 AC-148)
- AC-3 No record that an agent session or a candidate's tests can write shall remove a requested target from a quick or essential run: a forged same-user `run.json` matching the base tree and config digest shall run the target, either because local credit from such records is withdrawn or because credit needs a protected recorder those processes cannot reach; evidence: a test with a forged record that skips an opted-in content target before the change (the fail-before reproduction of finding 2) and runs it after, and, if a recorder is introduced, tests that a record the session writes or a key it can read earns no credit. (serves EPC-022 AC-148)
- AC-4 The shipped Claude presets shall keep, narrow or drop the `~/.codeflow/gate-runs` write grant for agent sessions by the decision AC-1 records, and `docs/harness-posture.md` shall state the decision and its consequence for running full gates in an agent session (the evidence preflight at `gate_guard.rs:241` and the durable copy at `gate.rs:513`), with the route a session uses when the grant is gone; evidence: preset tests per file, the installed and baseline copies matching, and the doc diff. (serves EPC-022 AC-148)
- AC-5 Ordinary run reports and cited run ids shall keep working for landing evidence, and hosted CI, default full runs and integration shall run every target as today; evidence: the existing gate, integrate and citation tests passing, and a full-run test that writes and cites a durable record.
- AC-6 (journey) With the installed build in a scratch adopter with one reusable content target, a link planted in its `gate-runs` directory and a forged green record: a full gate shall refuse the link and leave the victim unchanged, and a quick run shall run the target; evidence: the journey output.
