# TSK-1594: The identity layer is installed at block, blocks at pre-push, behaves in CI as the operator chose, and fails closed

## Description

Owner: to be assigned by the Director. Staged 2026-11-23 for coord/records.

SPC-018 R-2b, R-4 (layer 3), R-22, R-23 and R-23a. By the operator's
decision of 2026-11-23, layer 3 blocks at pre-push and fails closed when
an identity read cannot run; it also runs in `pre-commit` and
`commit-msg` at the same level for early feedback (SPC-018 "Disclosed
choices"). This task wires TSK-1593's matcher into the hooks, and, by
SPC-018 R-2b, is the task that installs the identity layer's key and
shipped default (`privacy.identity: block`, `identity_sources` all): the
policy schema, `assets/base/policy.json`, the init suggestion and
`codeflow update`. Before this task, no released CodeFlow has an
identity key or default.

What layer 3 does in `codeflow ci` is open question Q3: CI has no
contributor machine. This record assumes the recommendation, option B:
`codeflow ci` reads no identity source and reports layer 3 as "judged at
pre-push only". Under B, the CI backstops are conditional, not coverage
every adopter gets: layer 2 runs in CI at its level for every adopter;
TSK-1372's author header checks, which run in the hooks and CI (AC-3,
AC-4), exist only once TSK-1372 lands (it is `todo`) and are off by
default for adopters (TSK-1372 AC-1), while its committer check runs
only in the agent-session guard (AC-2) and is no CI backstop; layer 5 ships off
and needs a project's own terms and key. If the operator decides
otherwise, AC-2 changes before claim.

This task also wires `privacy.identity_sources` (a subset of sources,
default all; a narrowed set is a relaxation) and the per-source rows of
`codeflow doctor --check privacy`.

## Outcome

After this merges, a new project at every tier and an updated project get
`privacy.identity: block`; pre-push refuses a range that adds the
contributor's own identity at `block`, the commit hooks report it
earlier, `codeflow ci` behaves as Q3 decides and says so in its output,
an unreadable source refuses at `block` naming its kind, a lowered level
or narrowed sources print the privacy relaxation line on every run, and
no identity value is left in any output, file or child process.

## Deliverables

- hook wiring in `crates/codeflow-core/src/hooks/git_hook.rs` and `crates/codeflow-cli/src/cmd/push_set.rs`; the CI report line in `crates/codeflow-cli/src/cmd/ci.rs`
- `privacy.identity` and `privacy.identity_sources` in `policy_schema.rs`; the default in `assets/base/policy.json` and the init suggestion under `crates/codeflow-core/src/scaffold/`; the `codeflow update` addition; the doctor rows
- docs; `changelog.d/TSK-1594.md`

## Acceptance Criteria

- AC-1 Fail before: at the base with the earlier tasks of this epic, no hook calls the matcher, so a push whose range adds the contributor's host name (a placeholder value through the test seam) passes `pre-push`; evidence: the failing hook test run.
- AC-2 Pass after: `pre-push` shall refuse that range at `block` and warn at `warn`, and `pre-commit` and `commit-msg` shall report it at the same level, for each identity kind in content, in an added path and in a commit message; under option B, `codeflow ci` shall read no identity source and shall print one line that layer 3 was judged at pre-push only; evidence: hook tests per kind and placement (moved here from TSK-1593), and a `codeflow ci` test with a reader stand-in that fails the test if called.
- AC-3 Fail closed: an unreadable source shall refuse the push at `block` and warn at `warn`, naming its kind and the doctor check; an absent source shall not; evidence: hook tests.
- AC-4 `privacy.identity_sources` shall narrow the sources and refuse an unknown name; a narrowed set, or `privacy.identity` at `warn` or `off`, shall print the privacy relaxation line (SPC-018 R-2a) in every hook, `codeflow ci` and `codeflow doctor --check privacy`, with TSK-424's activation key unset and with it set; evidence: schema tests and output tests per placement for both key states.
- AC-5 Canary: with unique placeholder identity values, a full run of the three hooks, `codeflow ci` and `codeflow doctor --check privacy` shall leave none of them in stdout, stderr, any file the run writes (including `.git` and temporary folders), any child's arguments or environment, or the coordination ledger, both with the values in file content and with them only in added file and folder names; evidence: the content and path canary tests.
- AC-6 Install (SPC-018 R-2b): a fresh `codeflow init` at minimal, standard and full shall write `privacy.identity: block` and `identity_sources` all beside the pattern section; `codeflow update` over a project with only the pattern section shall add them and report it, and over a project that set its own identity level shall change nothing; evidence: scaffold tests per tier and two update tests.
