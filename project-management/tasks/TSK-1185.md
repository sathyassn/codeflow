# TSK-1185: import_authority orders a superseding record version whose branch forked before the old version

## Description

Confirmed by a binary run on 2026-11-02 11:20 (`.worktrees/tsk-1132` binary, 4.0.0 at `e7a3422f7`). PR 507 synced EPC-022 at `c0a4c9f33` into EPC-026 at 05:14Z. PR 497 then landed on EPC-022 at 05:22Z and rewrote TSK-1097, TSK-1120 and TSK-1127, and EPC-026 keeps the older versions. `work.import_authority` (`crates/codeflow-core/src/workgraph/landing.rs`) cannot order the two versions. The probe was an EPC-026-based branch with `6c04fc591` merged in (local `94b8ba7e3`), checked with `codeflow ci --into integration/EPC-026-the-capabilities-catalog`. It printed the TSK-1097 `import_authority` block verbatim and nothing else blocked; TSK-1120 and TSK-1127 showed only planning amendment notes.

Cause: in `landing.rs`, `yields` calls a version older only if every introduction of it is an ancestor of every introduction of the newer one. The old version has merge-resolution introductions on other lines: `d5811acc3` (main into EPC-022, 18:49) and `6130a4d49` (EPC-022 into the catalog plan, 15:32). PR 497's branch-only introduction `8092c073a` forked from `a66ab01e2`, before both merges. So the ordering fails in both directions and the sync is refused.

Security task (admission security lens): the ordering decides which record version a landing may supersede, so it must never trust a name or a date the requester controls. The Director decided on 2026-11-02 at 11:18 that this is its own task and that TSK-421 depends on it.

Evidence the builder owns: the local branch `plan/probe-import-authority` at probe merge `94b8ba7e3` (EPC-026 with `6c04fc591` merged in, never pushed). The guard refuses `-D` on it because no other ref keeps its commit. The builder deletes it once the fixture reproduces the refusal (Director, 2026-11-02 11:24).

Second fail-before fixture (added 2026-11-02, the Director): TSK-1062 on the EPC-024 sync. EPC-024 holds version `8dff14606` from before the cut and EPC-022 holds `f99ba81a7`, and the old blob was re-introduced by merges `997c60b0f` (PR 396) and `8bc7ddce7`, so the ordering fails the same way. Evidence the builder owns: the local branch `plan/probe-epc024-sync` at `64b3a079b`, which the builder deletes once the fixture reproduces the refusal. This task blocks the EPC-024 sync for TSK-431 and TSK-421 and any future EPC-026 syncs, and it builds alongside TSK-1184.

## Outcome

after this merges, a person can sync one integration line into another and have a superseding record version ordered by its landing on the source line, even when the newer version's branch forked before the old version was introduced, while a real two-sided divergence still refuses.
