# TSK-1187: A git-guard refusal of a copy names the operand it rests on and its role

## Description

Issue 509. A git-guard refusal of a copy of `.github/workflows/codeflow-ci.yml` to a scratch destination names the wrong path, so the person cannot tell which operand the guard rests on. In `crates/codeflow-core/src/hooks/git_guard.rs`: `GitWriter::copies` at :6892, `copy_destinations` at :7090, `GitWriter::integrity` at :6876 and the message at :6944. `unresolved_names_enforcement` at :4794 returns any integrity path named on a line that has an unresolved operand. The likely cause, not yet reproduced, is that the adopter's destination was run-time, such as `$TMPDIR/...`, so the guard reported the source path. The builder first records whether the verdict or only the message is wrong. A run-time destination stays refused, so the fix there is the message.

Security task: it changes a guard and keeps failing closed for an unresolved destination.

Related, not covering it: TSK-1167 (issue 500, `mv` and `rm` on a fixture `.git`), TSK-1092 (interpreter-refusal text), TSK-417 (quoting; EPC-022 AC-106 scopes "a refusal names the operand it rests on" to TSK-417's cases).

Landing order, not an edge: this task shares `git_guard.rs` with TSK-1167, TSK-342, TSK-1024 and TSK-407, so one writer at a time.

## Outcome

after this merges, a person whose copy is refused by git-guard is told which operand the refusal rests on and whether it is the source or the destination.

## Deliverables

- the message and operand selection: `crates/codeflow-core/src/hooks/git_guard.rs` (`GitWriter::copies`, `copy_destinations`, `GitWriter::integrity`, the message)
- tests: the issue's repro and the per-verb cases in `crates/codeflow-core/tests/` or beside the guard
- release note: `changelog.d/TSK-1187.md`

## Acceptance Criteria

- AC-1 The issue's repro (copying `.github/workflows/codeflow-ci.yml` to a scratch destination) shall be the fail-before test, asserting the decided verdict and a message that names the matched operand and its role, source or destination; the builder first records whether the verdict or only the message is wrong, and a run-time destination stays refused, so the fix there is the message; evidence: the test, failing before the change.
- AC-2 A `cp` whose literal destination is an integrity path shall stay refused, and a run-time destination next to an integrity-path source shall stay refused with a message that names the unresolved destination, not the source; evidence: one test per case.
