# TSK-201: Keep tests independent of the CI event environment

## Description

The first hosted gate on a pull request (PR 5, TSK-199) failed 34 Rust
tests that pass on a push run and on a laptop. The pull request job's
variables (`GITHUB_EVENT_NAME=pull_request`, `GITHUB_EVENT_PATH`,
`GITHUB_BASE_REF`, `GITHUB_HEAD_REF`, `GITHUB_ACTOR`, `GITHUB_ACTIONS`,
`CI`) reached every `codeflow` and git process the tests start, so
`codeflow ci` read the real event: it demanded a PR body, took its range
from the real base and judged the real head branch. This task blanks every
CI platform variable the product reads in the test environment, in
`.cargo/config.toml` `[env]` beside the harness markers, and adds a test
that fails when a newly read variable is not blanked. An empty value counts
as unset everywhere the product reads one, and a test that needs a variable
sets it on its own command. Non-goal: product behaviour; `codeflow test`
and `codeflow ci` in an adopter's CI still read their real variables.
