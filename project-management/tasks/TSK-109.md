# TSK-109: retroactive cleanup of ids, statuses and closeouts

## Description

Bring every existing record on every line to the new rules from evidence,
without renumbering anything (Plan v4 section 9). A scan of every ref found
no canonical id naming two different landed records; the deviations are of
format and status. This task normalises the eleven legacy `TSK-002-*`,
`TSK-003-*` and `TSK-004-*` records where the mapping is one to one, seeds
the registry once with a `uid` for every record, lands each line's `uid`
backfill in that line's cleanup pull request (main first, then each
integration line when it is next touched), and reconciles statuses and
Closeouts one pull request per line after the status verbs and acceptance
rules exist. Where evidence is gone, the record says "historical evidence
unavailable" and names the merge that landed the work. Nothing is invented.

## Affected surfaces and interfaces

- `project-management/` on `main`, the EPC-016 line, the EPC-018 line and
  the backlog branch; the `codeflow/registry` seed.
- No product code.
