# TSK-1358: One landing rule for every project

## Description

The operator decided on 2026-11-05 at 17:24 ("general run is fine", recorded in the workspace release plan) that one landing rule holds for every project, CodeFlow and adopters alike. The shipped guidance said instead that a multi-task epic reaches `main` once, when it is finished, through one final pull request, and CodeFlow's own `AGENTS.md` said a candidate lands on its own hosted verdicts, which the CI placement decision of 15:57 ended. This task writes ADR-0098 and changes every shipped surface to state the rule: a task pull request targets `main` when a human can merge it as it becomes ready; otherwise it targets its epic's line, where agents merge, and a checkpoint pull request from the line to `main` is opened or refreshed at every green line tip; each task or epic record changes only in its one home, its epic's line or `main`; a line takes `main` only through the admitted sync route (TSK-1312), which never changes a record homed on the line. It also carries the CI/CD consistency fixes the coordinator approved for this pull request: CodeFlow's `AGENTS.md` landing section, the TSK-358 sentence and `cf-ship` step 9. Non-goals: the sync route itself (TSK-1312 builds it), the one push per batch (TSK-1351) and CI job placement (ADR-0097, TSK-1321).

The checkpoint wording in `cf-method` "Managing a body of work" has its home here; TSK-419 keeps epic sizing and one epic at a time per stream.

Search for an existing owner, on the line tip `447d3ffd7` on 2026-11-05: open tasks and epics mentioning checkpoint, one home, landing rule, epic line or a human merging as ready, and open tasks whose deliverables name `docs/delivery.md`, `cf-method` "Managing a body of work", the git rules "Bodies of work" or `rule-map.toml`. None owns the rule:

- TSK-1312: builds the admitted sync route in `codeflow ci`; this task cites it for the fourth point.
- TSK-421: commands to sync, carry and close a line, not where tasks land.
- TSK-318: a carry between lines.
- TSK-316: the planning rule's wording and scope-drift reports.
- TSK-1152: a status change riding a landing pull request.
- TSK-1154: a candidate accepting a task's own criteria change.
- TSK-419: epic sizing and one epic per stream; planning PR 638 is amending its criteria.

## Outcome

After this merges, an adopter's maintainer knows one rule for how work reaches `main`: a task pull request goes to `main` when a human can merge it as it becomes ready, and otherwise to an epic line with a checkpoint pull request at every green tip, one home per record, and lines taking `main` through the admitted route.
