# TSK-156: commit pins read as ids even when all digits

## Description

A research or decision dependency pins a commit (`depends_on: [{id:
TSK-NNN, kind: research, pin: <sha>}]`, SPC-013 R-112). Written unquoted, a
short id made only of digits (`70283613`) or shaped like an exponent
(`949894e0`) reads in YAML as a number, and the parser refuses it with a
bare "pin must be a commit id", which gives the planner no way to see the
fault. About 2 to 3% of 8-character prefixes are affected. The same fault
makes `readiness::a_pin_is_an_object_id_never_a_ref_name` flaky: it writes a
random commit prefix unquoted and failed 3 of 40 runs, on `70283613`,
`32746128` and `949894e0` (found 2026-09-27 while rerunning TSK-155's
tests). This task refuses such a pin with a remedy that says to quote it,
shows the pin quoted wherever CodeFlow shows its form, and makes the test
deterministic. Refusing is chosen over reading the number back because
YAML may have lost the text: `949894e0` becomes 949894.0, a 40-digit id a
rounded float and `+1234567` loses its sign, so a read-back could name a
different commit or accept text that is not one. (Corrected at build: a
leading zero, as in `07028361`, stays text in this parser and reads.)
Non-goal: changing what a quoted pin means or how it is resolved.

## Affected surfaces and interfaces

- `crates/codeflow-core/src/workgraph/deps.rs` (`parse_dependency`) and its
  unit tests; the missing-pin message in `workgraph/work_start.rs`.
- `crates/codeflow-core/src/workgraph/readiness.rs` tests.
- `assets/base/pm/task.md.tmpl` (`depends_on` guidance comment), with any
  manifest hash or rendered fixture that pins it; adopters see it on the
  next `task new` and `codeflow update`.
- A CLI journey test; `CHANGELOG.md`; SPC-013 R-112 and its Interfaces
  line, amended by this planning pull request.
- No CLI verb or scaffold file writes a pin today; nothing to migrate: no
  record on any line carries one.

## Acceptance Criteria

- AC-1 When a `depends_on` pin is an unquoted short id that YAML reads as
  a number, all digits (`70283613`) or exponent-shaped (`949894e0`), the
  system shall refuse it with a message that names the dependency and says
  to quote the pin, and the same text quoted shall read as a commit id;
  evidence: `deps.rs` unit tests for both values, quoted and unquoted, and
  a letter-bearing pin both ways.
- AC-2 When CodeFlow shows the pin form, in the task template's
  `depends_on` guidance, the refusal and missing-pin messages and SPC-013
  R-112 and Interfaces, the system shall show it quoted; evidence: a grep
  in the pull request body, and that no verb or scaffold file writes a pin.
- AC-3 When the readiness pin test runs, the system shall give the same
  result every time: its pin is written quoted, and fixed digit, exponent
  and letter cases replace any dependence on a random commit prefix;
  evidence: the test and 40 repeated runs with no failure.
- AC-4 (journey) On a fresh `init --full` project, through the built
  binary, a task whose `depends_on` pin is an unquoted `70283613` shall be
  refused by `validate --docs` with the quote remedy, the same pin quoted
  shall pass, and `task new` shall write the quoted guidance; evidence: a
  CLI test.
