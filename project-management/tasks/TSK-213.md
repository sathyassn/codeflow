# TSK-213: one rule for how one model family calls another

## Description

CodeFlow's skills and managed instructions gave hosts different answers to
"how does one model family call another": the orchestrator's preflight
preferred the Codex app-server, while its seat table, cf-delegate, cf-consult,
cf-herdr, the CLAUDE.md row and the exec-guard refusal preferred the official
Codex plugin, and cf-herdr refused to drive Herdr outside a Herdr pane
(issues 30 and 31). The operator decided on 2026-10-03 to adopt issue 31's
rule: another family is reached through an interactive seat (Codex through
the app-server, else its CLI, in a Herdr tab; Claude and Grok through their
CLIs in Herdr tabs), the same family through native subagents, never a print
or exec mode, the Codex plugin an optional fallback, tmux the last fallback
when no Herdr server is reachable, and cf-herdr may drive any reachable Herdr
server with its anti-hijack rules. This task states that rule once, in the
orchestrator's `resources/routing/transport.md`, makes every other passage
cite it, records the decision in an ADR, and documents the first-run prompts
of a new seat and the Codex session-record harvest in cf-herdr. Non-goals:
the Grok hook fix (issue 29, another task), hook assets and settings presets,
and any change to the Codex builder posture that ADR-0075 D1 fixes.

## Acceptance Criteria

- AC-1 When an agent reads any shipped skill, resource or managed
  instruction about calling another model family, it finds the rule in one
  file, `cf-model-orchestrator/resources/routing/transport.md`, and every
  other passage cites that file instead of restating a route; evidence: a
  contract test that pins the rule's home and fails on a stale preference
  (plugin preferred, Herdr only when `HERDR_ENV=1`, tmux ahead of Herdr) in
  the issue 31 inventory files, and the inventory table in the PR.
- AC-2 When a host with no `HERDR_ENV` reaches a running Herdr server,
  cf-herdr lets it create and drive its own `cf-` tabs under the existing
  anti-hijack rules; evidence: the cf-herdr text and the Herdr contract test.
- AC-3 The launch posture of every cross-family seat (Claude, Codex, Grok;
  production and consult) is stated once, agrees with ADR-0055 and ADR-0075,
  and the delegate lanes cite it, so an edit handoff no longer prescribes
  auto mode; evidence: the contract test and the diff.
- AC-4 cf-herdr names the first-run prompts of a new seat (folder trust,
  project hook trust, a self-update offer) with who answers each, hook
  trust by the caller only for hooks byte-identical to the target tip
  (operator decision of 2026-10-03, ADR-0075 amendment), and the
  Codex session record as the harvest and observed model and effort source,
  never a completion signal; the delivery script's oversize message no
  longer sends the caller to tmux; evidence: the text, the delivery eval and
  the contract test.
- AC-5 The regression case `cross-harness-dispatch-declares-bounded-role`
  asks for the interactive seat route, and the bad-dispatch fixture is kept;
  the exec-guard refusal names the same route; evidence: the diff, the eval
  kit tests and the remedy unit test.
- AC-6 An ADR records the operator decision and the ADRs it narrows carry a
  dated Note; the source, both mirrors and the managed baseline match; the
  pending 3.1.0 CHANGELOG entry carries its release-impact marker; evidence:
  `manifest_consistency`, `repository_update_noop`, the reading structure
  tests and `codeflow test --mode quick`.
