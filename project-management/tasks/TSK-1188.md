# TSK-1188: A green hosted run of the exact candidate can stand in for the landing's full gate

## Description

Issue 512. A green hosted run of the exact candidate can stand in for the landing's full gate. Why this is not a fold-in: TSK-359 AC-2 reuses hosted verdicts for pushes in this repository's CI only, and its non-goals exclude adopter routes; `TSK-1044:308` records hosted-run credit as "a later task".

Security task. Threat: the requester controls the PR, the run id it cites, and the head's workflow and test config, and integration lines are unprotected. Reuse is sound only if CodeFlow finds the run itself through the API. A cited id is never trusted. The binding covers:

- the exact candidate SHA, the PR number and its base, and the recorded merge tree, which must equal the tree being landed;
- the workflow blob at the run, which must equal the base line's blob;
- the required jobs, read from the base's workflow, all successful, in full mode with every shard;
- no partial rerun;
- an unchanged line tip (push with a lease);
- a run produced by trusted authority.

Any error falls back to the local full gate (fail closed). Follow-up, a separate Easy task: the optional "open, wait, push with lease" command.

## Outcome

after this merges, a person landing a candidate can use a green hosted run of the exact candidate in place of the local full gate, and every landing record says which one was used.

## Deliverables

- the run lookup and binding: `crates/codeflow-core/` and `crates/codeflow-cli/src/cmd/ci.rs` (provisional; the builder confirms the homes against TSK-359 and TSK-1044)
- the landing record and the `codeflow ci` and pre-push lines that name "hosted run <id>" or "local"
- tests: fixtures for each binding input and each fallback
- docs: where the full gate is described, and `docs/cli.md` if a verb gains an option
- release note: `changelog.d/TSK-1188.md`
