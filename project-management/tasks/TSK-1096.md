# TSK-1096: Present and portal tables encode state, extent and emphasis from one grammar module

## Description

The operator's clarification of 2026-10-30 (20:15, relayed by the
coordinator): avoiding text tables does not mean banning tables; it means
that when a table is the better shape, it is presented visually, with
colour encodings, inline bars, status marks, grouping and emphasis, never
as plain text. The feedback of the same day (20:40) added that a table
must be easy to consume and look good, elegant and restrained, never
cheesy or overdone, and that a disclosure must open to content presented
as well as the first reading path, since layering information is not
sweeping text into a box the reader fears to open. Neither surface can do
this today:

- the present `table` block holds string cells rendered as Markdown in
  plain `<td>` elements (`crates/codeflow-present/src/render.rs:406-425`;
  schema `.codeflow/schemas/present/document-v2.schema.json`, `table`),
  with no state, bar, tone or group a cell can carry;
- the present `status` block draws pass and fail with the same filled
  mark and pending and not-run with the same outlined mark, told apart by
  colour alone, and hides the mark from assistive technology without
  emitting the state as text (`crates/codeflow-present/src/render.rs:425-440`,
  `crates/codeflow-present/web/src/styles.css`, the `.state-mark` rules),
  against the two-channel rule the figure grammar sets for every pair of
  states (`figure-grammar.md` section 2, rule 3);
- the portal renders Markdown tables as Starlight tables and its generated
  capability table prints status as plain text
  (`assets/docs-portal/starter/scripts/adapter.mjs:422`,
  `scripts/lib.mjs:1150`); the lookup wrappers in `portal.css:688-762`
  change layout at phone width only;
- the figure twin is an exact textual fallback, which must stay as it is
  (`crates/codeflow-present/web/src/figure-grammar.mjs`, the twin
  renderer).

Outcome: **one encoded-table vocabulary, drawn by the grammar module both
runtimes load, lets an author or a generator give a table cell a state
mark from the mark vocabulary, an inline extent bar against a declared
maximum, a tone (accent, cat1, cat2) or an emphasis, and a row a group,
so the present `table` block and a declared portal table read as visuals
with their exact values kept as text; the present `status` block meets the
two-channel rule with an accessible state name; and the figure twin stays
the plain fallback.**

```text
  author or generator
        |
        v
  encoded table (cells: text, state, bar, tone, group)
        |
        +--> present `table` block v2 (typed cells)  --> runtime draws
        |
        `--> portal declared table (bound like a figure) --> adapter draws
                                     \
                                      `-- one grammar module: marks, tokens, legend, text twin
```

Figure: one vocabulary and one module serve both surfaces; each surface
keeps its own carrier and shell.

Decisions, each reversible and disclosed here:

- A cell is a string (as today) or an object with `text` and any of
  `state` (a mark from `figure-grammar.md` section 4, drawn with its two
  non-hue channels and its name as accessible text), `bar` (`value`,
  `max`, optional `unit` and `label` naming what is measured, such as
  `criteria`; drawn to length on the table's one declared scale per
  column, the value kept as text beside it; a `value` of null draws no
  bar and the text `not recorded`, never zero), `tone` (`accent`,
  `cat1`, `cat2`; hue only, never the only carrier) and `strong`; a row
  may carry `group`, drawn as a group heading. A legend lists every state
  and tone used, as figures do. The present `table` block gains these
  fields under `schema_version: 2` without breaking a string-only table.
- The portal carrier is a declared table bound in `portal.config.json`
  like a figure (`tables`, with `route` and `panel` or `anchor`), drawn
  by the adapter from a declaration file; a Markdown table in a source
  stays a Markdown table. The builder confirms in AC-1 that a declaration
  beats a `cf-table` fence in sources under the content contract, and
  records the choice; the vocabulary is the same either way.
- An encoded table is a primary carrier when a comparison or lookup is its
  better shape; the method text that puts tables in disclosures (TSK-445
  AC-3) applies to reference detail, and TSK-1097 restates the rule.
- No new colours: the `--cf-fig-*` roles and the mark vocabulary draw
  everything; a status cell is the `cov`, `part`, `notrun`, `na`, `nc`,
  `done`, `todo`, `blocked` or `stop` mark, and the `status` block's four
  states map to `done` (pass), `stop` (fail), `todo` (pending) and
  `notrun` (not run), each with the state name in the accessible tree.
- Restraint is part of the vocabulary: a column carries one encoding (a
  mark, a bar or a tone), a table uses at most two tones beside the
  accent, bars share one scale per column, row striping and borders come
  from the kit's `chrome.css` table rules and never from the declaration,
  and the legend lists only what is used; the renderer refuses a cell
  with two encodings and a table with more than three tones. The kit's
  table rule in `chrome.css` sets the quiet surface (hairline rules,
  tabular numerals, a group heading one step heavier), so an encoded
  table looks the same on both surfaces.
- An encoded table and the figure families are the carriers inside a
  disclosure too: the present `disclosure` block and the portal's details
  panels accept the same blocks as the first reading path, and the twin
  of a figure stays the exact accessible fallback and writes every mark
  as its human word (`checked`, `partial`, `not run`, `not applicable`,
  `not claimed`, `unknown`), never its identifier. The runtime's own
  figure Details panel, which today opens to the description paragraph
  and the plain twin (`crates/codeflow-present/web/src/figure-grammar.mjs`,
  the `Details` renderer near line 722, and the portal's copy), is the
  disclosure the operator met: it opens instead to a one-line lead and
  the twin drawn as an encoded table (states as marks, values with bars
  where the figure drew extent), with the plain twin kept beneath for
  assistive readers and copy, on both surfaces. A disclosure's closed
  summary line may carry a `state` mark and a `count` chip, so a closed
  disclosure says what is inside and how much (the design brief revision
  2, gap 8).
- The vocabulary gains an `unknown` mark (a hatched ring with the word),
  distinct from `na` (faint, not applicable) and `notrun` (hatch), so a
  generator can draw a value it could not establish without calling it
  inapplicable or zero.

Non-goals: new figure families; a table that replaces a figure where a
relationship carries the point (the altitude contract stands); the portal
page rewrites (TSK-446); the method text beyond the block selection table
(TSK-1097); product or brand design.

## Outcome

After this merges, an author or a generator can show state, magnitude,
grouping and emphasis inside a table on the present surface and the docs
portal, readable at a glance and without colour, with every exact value
still present as text.
