# TSK-1468: The EPC-022 checkpoint brings the line's work to 75f7a135c into main

## Description

The EPC-022 line has to carry everything on `main` before its checkpoint pull request can take the line's work to `main` without breaking `main`. This task merges `main` into the line through a reviewed task pull request. A sync would normally land as an admitted sync, but the first merge (87315ddc9, `main` 63061d210) resolves record and code conflicts by hand, so `codeflow ci` judges the range as ordinary work, and it needs its own task.

Three things blocked the merge on 2026-11-12:

- `work.import_authority` refused four records whose home moved to `main` on `main`: TSK-1177 and TSK-1357 (pull request 666) and TSK-341 and TSK-1352 (pull request 772). The check stops at the first record it refuses (`crates/codeflow-core/src/workgraph/acceptance/imports.rs:180-181` on `main` at 4cc6de60a). A dated home note on each record on `main` was proposed to clear them, and its cross-lineage review judged that it would defeat the check (Codex, 2026-11-12, workspace `coordination/coordinators/planning/reviews/main-records-2026-11-12-codex-0f4c23301.md`). The refusal clears only when TSK-1378's fix of the home check is on `main`; this task merges `main` at or after that landing.
- `every_publishing_job_refuses_a_rerun_first` (`crates/codeflow-core/tests/release_rerun_contract.rs:232`) fails on the merged tree for the `authority` job. The Director approved one pinned exemption for that job (2026-11-12). coord/ci wrote it as a patch to that test file only, with no workflow, baseline or manifest change (`coordination/coordinators/parallel/patches/`, applied in rounds up to round 6, `epc022-rerun-exemption-r6-on-0d974027b.patch`, sha256 3a6c8985…aca55bc, each approved by Codex; the pull request section names every round). It pins the SHA-256 of each copy's `authority` job text, refuses that job inheriting workflow-level `env` or `defaults` or anchors from elsewhere in the file, and matches the secret in any case. It takes an other-family security review. This narrows a security contract by one pinned case; the pull request states the threat the contract closes and why it does not apply to this job.
- `work.classification` named `.codeflow/.baseline/.github/workflows/codeflow-policy.yml`, because the trial body said `Task: EPC-022`. A body naming an epic off its line is judged as a planning amendment or a clean sync (`planning_or_sync`, `crates/codeflow-cli/src/cmd/ci/classification.rs:316-330` at 8fec66535); this range is neither, and the baseline is just the first path outside the planning set. The file itself is right: its blob at 8fec66535 is be4e4c088a, the same as `main`'s at 4cc6de60a and the template's. A body naming this task is judged as tracked work (`:236-249`), so no hunk is needed (coord/ci's reading, 2026-11-12; AC-2's run confirms it).
