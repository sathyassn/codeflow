# TSK-1523: Release-automation test timeout under load

## Description

Source: the Director's ruling of 17:3x on 2026-11-16, relayed by coord/ci through coord/records. The local full gate on `main` candidates times out the `release-automation` target under host load, which keeps `main` red.

Evidence: run alone on candidate `candidate-main-1116a` (HEAD `47088e152c`), `python3 -B scripts/test_release.py` took 1945 s and exited 0, with the load average falling from 311 to 208 (`coordination/coordinators/parallel/notes/candidate-main-1116b-release-automation-rerun.log` in the agentic-systems workspace: "end 17:06:47 elapsed 1945 s"). The target sets no `timeout_seconds` in `.codeflow/test-config.json` on `main` at `ec8d5c1ab3` (the `release-automation` entry at `:272-297`), so the runner applies its 600 s default (`DEFAULT_TIMEOUT_SECONDS`, `crates/codeflow-core/src/testing/runner/mod.rs:69`). Other heavy targets in the same file already set their own limits (for example 3600 s and 4500 s).

Change: add `"timeout_seconds": 3000` to the `release-automation` target. 3000 s is the Director's value; it is about 1.5 times the measured 1945 s.

Related record: TSK-369 (EPC-038, on the EPC-022 line) AC-1 asks for `release-automation` and three other targets to pass inside their configured timeouts in three consecutive reference-host full gates, by a stated limit change with recorded approval where needed. This task is the narrow `main` fix that unblocks the current `main` candidates; it does not meet or replace TSK-369 AC-1, which still owns the three-run proof on the reference host.

Placement: EPC-047 ("The gate gives its real verdict on any host"), whose outcome is a gate with no false timeout on a loaded host and whose deliverables include `.codeflow/test-config.json`. Target `main`, as TSK-1299 in the same epic; it lands in main candidate D.

Non-goals: changing the runner's default; the timeouts of other targets; speeding up `scripts/test_release.py`; the heavy or exclusive route TSK-369 AC-1 names.

## Outcome

After this merges, a maintainer running the local full gate on a loaded host gets `release-automation`'s real result instead of a timeout at 600 s.
