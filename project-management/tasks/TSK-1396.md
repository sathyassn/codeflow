# TSK-1396: Projects choose whether branches must be up to date, or use a merge queue

## Description

ADR-0081 made "require branches to be up to date before merging" part of the
protection CodeFlow ships. At the line's b85d30681, `codeflow remote protect`
always writes strict required checks (`crates/codeflow-core/src/remote.rs:358`,
`:369`), and `codeflow doctor --check remote-perimeter` warns whenever the
live rules are not strict (`crates/codeflow-core/src/doctor/remote_perimeter.rs:599`,
`:641`, `:871`). No policy key lets a project choose otherwise
(`crates/codeflow-core/src/hooks/policy_schema.rs` has none), so a project
that turns the setting off on its host gets a doctor warning that never
clears. No shipped workflow triggers on `merge_group`, and ADR-0091 says merge
queues are not covered until it is wired (`ADR-0091` line 224).

The operator's direction (relayed by the Director, 2026-11-08): the strict
rule stays on by default, projects can opt out, and a merge queue is the
alternative where the host offers one. This task adds the policy key, makes
`remote protect` and doctor honour it, wires `merge_group` into the shipped
CI and policy workflows, and records the decision in an ADR that amends
ADR-0081. Non-goals: changing this repository's own `main` rules, which stay
the operator's, and merge queues on hosts other than GitHub beyond a refusal
with the reason.

## Outcome

After this merges, a project can keep the strict up-to-date rule, turn it
off with a stated reason and no standing doctor warning, or use a merge
queue where its host supports one, with CodeFlow's checks reporting for
queue entries.

## Acceptance Criteria

- AC-1 A policy key (for example `git.require_up_to_date`) shall take `true` (the default, also when absent), `false` or `merge_queue`; `codeflow remote protect` and `codeflow doctor --check remote-perimeter` shall honour it, and with `false` or `merge_queue` doctor shall not warn that the rules are not strict and shall say why. Only the committed value relaxes the rule: a working-tree value that differs from HEAD, and any environment value, shall be ignored or refused, never used to relax it; evidence: schema and policy unit tests, remote protect tests for each value, doctor tests for each value with strict and non-strict live rules, and a test with the working tree set to `false` while HEAD has the key absent or `true`, in which remote protect still writes strict checks and doctor still warns.
- AC-2 The shipped CI and policy workflows, and this repository's copies, shall run every required job for a merge-queue entry, never skipped: the policy job still judges only from the default-branch authority with the queue commit treated as data, the installed release stays the base pin and never comes from the queue commit, and each workflow's concurrency key tells queue entries apart; evidence: workflow template tests for each of those properties on a `merge_group` event, and a hosted queue run where the host supports one, else that run named as not verified.
- AC-3 With `merge_queue`, `codeflow remote protect` shall add the host's merge-queue rule where the host and plan support it, and otherwise refuse with the reason (for example a user-owned GitHub repository); evidence: remote protect tests for a supported host and for each refusal.
- AC-4 The docs shall state the cost of each setting and that a merge queue on GitHub needs an organization-owned repository; evidence: the `docs/policy-reference.md` and adopter docs diff.
- AC-5 An ADR shall amend ADR-0081 with the opt-out and the merge-queue route; evidence: the new ADR and ADR-0081's amended status line.
- AC-6 An adopter whose default branch commits `git.require_up_to_date: true` and who sets `false` in the working copy and in the environment shall get a strict plan from the installed `codeflow remote protect --dry-run`, which names the committed value; evidence: the remote protect CLI journey test run against the built binary. (journey)
