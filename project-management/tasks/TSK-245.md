# TSK-245: Keep CI green after a test fixture clone race

## Description

Test fixtures that clone a local repository race on hardlinks, which fails
CI on `main` and on open PRs for a cause outside their code. A local-path
clone hardlinks object files, newer Git checks each link against its source,
and the scaffold commit in a fresh `codeflow init` starts
`git maintenance run --auto --detach`, which can write the source
repository's objects while the clone runs (hosted failures on 2026-10-05 and
2026-10-06 in `readiness_journey` and `read_commands_offline`). This task
disables Git's automatic maintenance in every process the test suite starts,
across Rust, Node and Python fixtures and their shell harnesses, including
Git descendants of CodeFlow, and keeps `--no-local` on fixture clones as a
second guard. The npm advisory half of the original scope moved to TSK-246
so it could land first. Behavioural tests verify inheritance; static scans
refuse unreviewed environment tokens and clone forms outside their subset.
Effect on adopting projects: none; only test fixtures change. Non-goals:
changing how `codeflow init` runs Git for adopters, and any CI workflow edit.
The detached maintenance after `codeflow init` is Git's default after any
commit, and is not a product concern.

## Deliverables

- the fixture clone fix: the clone sites under `crates/*/tests/`, test code in `crates/*/src/`, and `crates/*/examples/`
- the shared fixture environment: `.cargo/config.toml`
- the maintenance inheritance tests: `crates/codeflow-cli/tests/git_maintenance_contract.rs`
- the Node fixture helper and trace test: `docs-portal/tests/portal-fixture.mjs`, `docs-portal/tests/git-maintenance.test.mjs`; other portal and binary-delta fixtures use the same environment
- the Python release fixture and trace test: `scripts/test_release.py`
- the shell fixture environment: `scripts/fixture-git-env.sh`, consumed by the qualification and gitleaks harnesses
- the exact environment allowances: `crates/codeflow-core/tests/fixtures/git_environment_allowlist.tsv`
- the durable scan: `crates/codeflow-core/tests/git_spawn_contract.rs`

## Acceptance Criteria

- AC-3 Automatic Git maintenance shall be off in every process a test starts, directly or through `codeflow`, across Rust, Node and Python fixtures and their shell harnesses. This removes automatic maintenance as a concurrent object-store writer; deliberate concurrent writers remain outside this guarantee, including `concurrent_issuers_in_two_clones_and_two_worktrees_never_share_a_number` in `crates/codeflow-core/tests/id_registry.rs`. The `--no-local` flags remain a second guard. Evidence: real fixture init and commit traces in each runtime, configuration origin, and affected suites.
- AC-4 A token scan across Rust sources, tests and examples, and Node, Python and shell fixture sources, shall refuse unreviewed environment replacement or Git configuration injection tokens and unsupported clone forms. Environment allowances bind the file, line number and exact trimmed line text with a reason; a new occurrence, moved line or changed value fails with its site. Evidence: reviewer probes, changed-value controls and behavioral restoration tests. Dynamic key construction from fragments and environment changes made by external programs remain outside the token scan.
