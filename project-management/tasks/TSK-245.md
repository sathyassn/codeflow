# TSK-245: Keep CI green after new dependency advisories and a test clone race

## Description

CI fails on `main` and on every open PR for two causes outside their code.
First, new npm advisories (postcss-nested's selector parser, smol-toml,
source-map-js, http-cache-semantics) fail the security review against the docs portal lockfile and
the shipped starter lockfile. Second, test fixtures that clone a local
repository race on hardlinks: a local-path clone hardlinks object files, newer
Git checks each link against its source, and the scaffold commit in a fresh
`codeflow init` starts `git maintenance run --auto --detach`, which can write
the source repository's objects while the clone runs (hosted failures on
2026-10-05 and 2026-10-06 in `readiness_journey` and `read_commands_offline`).
This task takes fixed releases of the flagged packages in both lockfiles,
keeps the portal state and runtime script list pinned to the new lockfile,
makes every fixture clone of a local path copy instead of hardlink (or use the
transport where it already uses `file://`), stops automatic maintenance in
fixture repositories where it is the concurrent writer, and adds a scan so a
new local clone without the flag fails a test. Effect on adopting projects:
`codeflow update` installs the starter's new `package.json` override and
lockfile; no behaviour changes. Non-goals: changing how `codeflow init` runs
Git for adopters, and any CI workflow edit.

## Deliverables

- the dependency fix: `docs-portal/package.json`, `docs-portal/package-lock.json`, `assets/docs-portal/starter/package.json`, `assets/docs-portal/starter/package-lock.json`
- the stale `http-cache-semantics` ignore removed: `docs-portal/osv-scanner.toml`, `assets/docs-portal/starter/osv-scanner.toml`
- the portal pins: `.codeflow/docs-portal.json`, `docs-portal/scripts/runtime-scripts.json`, `assets/docs-portal/starter/scripts/runtime-scripts.json`
- the fixture clone fix: the clone sites under `crates/*/tests/` and test code in `crates/*/src/`
- the durable scan: `crates/codeflow-core/tests/git_spawn_contract.rs`
- the release note: `CHANGELOG.md`

## Acceptance Criteria

- AC-1 When `npm audit` runs on the docs portal and the shipped starter lockfiles, the system shall report no advisory at the security review's threshold. Evidence: `npm audit` on both, and the hosted security review job.
- AC-2 When the docs portal is built and checked from a committed tree, the portal state and runtime script list shall match the new lockfile. Evidence: `codeflow test --mode full --only docs-portal-deps,docs-portal` and `manifest_consistency`.
- AC-3 When a test or test helper clones a local repository, the clone shall copy objects (`--no-hardlinks`) or use the transport (`--no-local` with `file://`), so a concurrent writer to the source cannot fail it. Evidence: the inventory of clone sites with each changed, and the affected suites passing.
- AC-4 When a new fixture clone of a local path lacks the flag, a test shall fail and name the site. Evidence: the scan in `git_spawn_contract.rs` failing before the sweep and passing after, with positive and negative scanner examples.
