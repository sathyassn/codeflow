# TSK-245: Keep CI green after a test fixture clone race

## Description

Test fixtures that clone a local repository race on hardlinks, which fails
CI on `main` and on open PRs for a cause outside their code. A local-path
clone hardlinks object files, newer Git checks each link against its source,
and the scaffold commit in a fresh `codeflow init` starts
`git maintenance run --auto --detach`, which can write the source
repository's objects while the clone runs (hosted failures on 2026-10-05 and
2026-10-06 in `readiness_journey` and `read_commands_offline`). This task
disables Git's automatic maintenance in Rust test processes, including Git
descendants of CodeFlow. A private workspace fixture helper makes every
fixture clone transport-only, so it reads through Git's object database
instead of copying or hardlinking an object directory during a repack.
Decoded Rust token scans review every clone literal and environment
replacement site. A scope check keeps non-Rust fixtures free of Git clones.
The npm advisory half of the original scope moved to TSK-246 so it could
land first. Effect on adopting projects: none; the helper is unpublished
and used only by workspace tests and an example. Non-goals: changing how
`codeflow init` runs Git for adopters, and any CI workflow edit.

Removal reason: the non-Rust runtimes have no clone or object-store copy,
so a maintenance guard there protects no outcome and forced a
multi-language scanner and a starter change. Their files return to base;
the portal tests remain byte-identical to the shipped starter.

## Deliverables

- the private transport-only clone builder: `crates/codeflow-fixture`, with a real Git transport and object-inode test
- the migrated fixture calls in Rust sources, tests and the release integration example
- the inherited maintenance-off environment: `.cargo/config.toml`
- the maintenance inheritance tests: `crates/codeflow-cli/tests/git_maintenance_contract.rs`, the CI scrub-and-restore trace in `ci_pin_platforms.rs`, and the slot-2 appender origin test in `workspace_mode.rs`
- the exact normalized-span and count allowances: `crates/codeflow-core/tests/fixtures/git_environment_allowlist.tsv` and `git_clone_allowlist.tsv`
- the decoded Rust guards and non-Rust scope check: `crates/codeflow-core/tests/git_spawn_contract.rs`

## Acceptance Criteria

- AC-3 Automatic Git maintenance shall be off in every process a Rust test starts, directly or through `codeflow`, including Git descendants: the forced Cargo environment in `.cargo/config.toml` sets `maintenance.auto=false` and `gc.auto=0` at command-line origin and clears legacy `GIT_CONFIG_PARAMETERS`. Evidence: a real `codeflow init --yes --full` under `GIT_TRACE2_EVENT` starts no `maintenance` or `gc` child and the two keys show command-line origin (`crates/codeflow-cli/tests/git_maintenance_contract.rs`); the CI scrub-and-restore path commits with no maintenance child (`crates/codeflow-cli/tests/ci_pin_platforms.rs`); the slot-2 appender keeps slots 0 and 1 (`crates/codeflow-cli/tests/workspace_mode.rs`). Outside this criterion: Node, Python and shell fixtures, because none clones or copies a repository object store (kept true by the AC-4 scope check), and deliberate concurrent writers such as `concurrent_issuers_in_two_clones_and_two_worktrees_never_share_a_number` in `crates/codeflow-core/tests/id_registry.rs`.
- AC-4 Fixture clones shall be transport-only by construction, and the inherited maintenance-off environment shall be reviewable at every Rust site that could replace it. (a) Every fixture clone in Rust sources, tests and examples goes through `codeflow_fixture::clone`, which emits `clone --no-local --quiet [closed options] -- <source> <destination>` and offers no local, shared or reference mode; a behavioural test shows its clone starts `upload-pack` and shares no object inode with the source, with a plain local clone as the discriminating control. A scan over decoded Rust tokens refuses the literal `clone`, or a literal containing the word, anywhere else, except listed non-invocation sites. (b) A scan over decoded Rust tokens refuses `env_clear`, `envs(...)`, `env` or `env_remove` with a non-literal key, and any literal naming `GIT_CONFIG_COUNT`, `GIT_CONFIG_KEY_n`, `GIT_CONFIG_VALUE_n` or `GIT_CONFIG_PARAMETERS` or a literal prefix of one, unless the site is listed with file, exact normalized call span, count and reason; a changed value, a new occurrence or a duplicate fails with its site. (c) Node, Python and shell fixture sources under `docs-portal/tests`, `scripts` and `tests` contain no `git clone`. Limits: text assembled at run time from fragments, procedural macros, a child program that clones on its own, and environment changes made by external programs.
