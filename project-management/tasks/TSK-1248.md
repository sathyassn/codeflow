# TSK-1248: Prove the commit standards target build cache on hosted runs after the writer reaches main

## Description

Source: the CI throughput study of 2026-11-02 and the Director's decision on PR 528 (TSK-1240, the commit standards build cache). TSK-1240 lands with its AC-2 and AC-6 open, because those criteria need hosted runs on `main`, and the cache writer cannot run there before it reaches `main`. This task owns that hosted proof, and TSK-1240's follow-ups cite it.

The cache is saved by the integration push's job-token dispatch under `main`'s cache scope and restored by commit standards on pull requests into the line. Non-goals: any change to the cache design or the workflow (TSK-1240), and admission (TSK-1239).

## Outcome

After this merges, the hosted behavior of the commit standards cache (hit, miss, moved target, main's scope) is recorded with run links and durations.

## Deliverables

- the evidence record: run links, hit or miss, durations, in this task's `## Findings`
- when a run does not behave as TSK-1240 requires: a defect record with the run evidence

## Acceptance Criteria

- AC-1 On two consecutive policy events, a hosted run shall show an exact cache hit on one and a miss on the other; evidence: run links and durations in the Findings.
- AC-2 A moved target shall rebuild; evidence: a hosted run whose target changed, with its link.
- AC-3 The integration push's job-token dispatch shall run on `main` and save under `main`'s cache scope; evidence: the run link.
- AC-4 A pull request into the integration line shall reuse `main`'s saved cache for commit standards; evidence: the hit and the time saved against a cold run. (journey)
