# TSK-1248: Prove the binary cache on main, and whether attestations work on a user-owned public repository

## Description

Source: the CI throughput study of 2026-11-02, the Director's decision on PR 528 (TSK-1240, the commit standards build cache), and the Director's ruling of 2026-11-03 that re-scoped this task to the post-merge proof of the binary cache. The proof cannot happen on the line, because it needs main's cache scope and signer identity. This task owns it, and TSK-1240's follow-ups name this task.

Non-goals: any change to the cache design or the workflow (TSK-1240), and admission (TSK-1239).

## Outcome

After this merges, a maintainer can read, with run links and durations, that main's binary cache hits and misses as TSK-1240 requires, and whether attestations work on a user-owned public repository, which decides whether jobs verify the restored binary or every job rebuilds.

## Deliverables

- the evidence record: run links, hit or miss, durations, in this task's `## Findings`
- the attestation result and the decision it sets: this task's `## Findings`
- when a run does not behave as TSK-1240 requires: a defect record with the run evidence
- The explained list and the run links: in the body of the pull request from the EPC-022 line to `main`, and in this record's acceptance block. (from TSK-1310)

## Acceptance Criteria

- AC-1 After main's push run saves its cache at SHA X, a pull request event targeting main with base X shall restore that cache with a shorter job time, and a push that moves main's SHA shall miss and rebuild; evidence: run links and durations in the Findings. (for TSK-1240 AC-2 and AC-6)
- AC-2 The record shall state whether attestations work on this user-owned public repository, from a hosted run on main, and which route that sets: jobs verify the restored binary, or every job rebuilds; evidence: the run link, its output and the route in the Findings. (journey)

## Criteria changes

Reasons for every removed or changed criterion line (Director ruling, 07:16 on 2026-11-03: main's run never saves a cache from integration output):

- Criterion AC-1 changed: it proved a hit and a miss on two consecutive policy events; it now proves a restore by a pull request event targeting main with base X after main's push run saved at X, and a miss on a push that moves main's SHA, because the re-scoped TSK-1240 keys by the exact main SHA with no fallback, so a second push to main never hits (round 1 finding, TSK-1248 cache journey), matching TSK-1240 AC-2 and AC-6.
- Criterion AC-2 changed: it proved a moved target rebuilds; the moved main SHA now sits in AC-1, and AC-2 proves the refused integration save of TSK-1240 AC-3.
- Criterion AC-3 changed: it proved the integration push's job-token dispatch saving under main's cache scope, which the ruling forbids; it now proves the evidence reuse and its refusals of TSK-1240 AC-7 and AC-8.
- Criterion AC-4 removed: a pull request into the line reusing main's saved cache depended on the integration-built save the ruling withdrew.

Reasons for the later re-scope (Director ruling, 2026-11-03, relayed by coord/ci: this task is the post-merge proof of the binary cache):

- Criterion AC-2 changed: it proved a refused integration save; it now records whether attestations work on a user-owned public repository, the question that decides whether jobs verify or every job rebuilds.
- Criterion AC-3 removed: exact-tree evidence reuse is outside the new scope; this task proves only TSK-1240's real hit and miss (its AC-2 and AC-6).

Reasons for the tag rewording (2026-11-05, for TSK-1186's stricter tag parsing):

- Criterion AC-1 changed: its closing reference read as a serves tag naming a task, TSK-1240, which TSK-1186 refuses because a serves tag names an epic criterion. AC-1 serves no epic criterion, so the reference now reads `(for TSK-1240 AC-2 and AC-6)`; what AC-1 requires is unchanged.
