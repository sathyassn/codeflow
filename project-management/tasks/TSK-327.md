# TSK-327: The pre-push destination query is isolated from local configuration and transport

## Description

The pre-push hook asks the destination which branches and tags it holds
(`ls-remote`) and uses the answer for three decisions: whether a pushed
branch's tree is exempt from the tree checks, where the range base for the
push set starts, and which policy authority the destination has. TSK-304
(PR 191) made the tree checks fail closed and hardened that query against
rewritten destinations given on the command line, but its reviews left three
inputs open. The TSK-304 record (Follow-ups, and `follow_ups` in its
acceptance block) and its security review rounds 1 to 3 name them, with
owner EPC-022 and revisit "before 3.2.0 ships":

- An on-disk `url.<x>.insteadOf` setting in the repository, global or system
  configuration can redirect the hook's `ls-remote` to another repository.
  The answer then decides the exemption, the range base and the destination
  authority for a push that goes elsewhere. This predates TSK-304.
- The range-base commands in `crates/codeflow-cli/src/cmd/push_set.rs`
  (`merge-base` and `rev-list --boundary`) read the commit-graph file, grafts
  and replace refs at TSK-304's head. TSK-287 owns this fix, and this task
  does not redo it. At TSK-287's reviewed commit 0cc98b23f (PR 194 now at
  8bb7a22ef), its AC-1 covers forged commit-graphs and disabled subprocess
  commit-graph reads, and its AC-2 covers range bases (`push_set.rs:1644`
  and `:1659` guard both git entry points; `history.rs:308` disables
  commit-graph reads). TSK-327 keeps the dependency so that invariant holds
  once TSK-304's push set and TSK-287 are combined, and it names a
  range-base path only if a concrete reproduction shows one that survives
  both.
- The destination query's ssh transport comes from the pushing environment.
  `batch_ssh_command` in `crates/codeflow-core/src/git/remote_query.rs`
  honours an inherited `GIT_SSH_COMMAND` and reads `core.sshCommand` with a
  plain `git` command (security review round 3, finding L2). The transport is
  the push's own, so the answer is no less trustworthy than the push, but the
  hook then depends on state the rest of the query isolates. The source
  rates the finding low and likely, advisory, and recommends only moving the
  `core.sshCommand` read to `judging_command`. This task asks for more: the
  query's transport selection follows a stated rule over all three
  selectors (below). The same function also falls back to `GIT_SSH`
  (`remote_query.rs:210` at TSK-304's head), and an inherited
  `GIT_SSH_COMMAND` masks `core.sshCommand` (`:185`), so a fix to one
  selector alone would leave another executable.

This task isolates the query: it runs with the configuration, transport and
history inputs the hook chooses, and a setting it cannot isolate is
reported as "cannot verify" and handled as an unchecked destination under
TSK-304's rule (refuse at `block`). Hosted CI on the pushed commit stays the
authority; this closes the local floor. Non-goal: changing which checks the
push set holds, or reading the destination without network access.

## Deliverables

- the isolated destination query: `crates/codeflow-core/src/git/remote_query.rs`
- the range-base verification test: `crates/codeflow-cli/tests/hooks_cli.rs`, with a change to `crates/codeflow-cli/src/cmd/push_set.rs` only for a surviving path that a reproduction shows
- tests: `crates/codeflow-cli/tests/hooks_cli.rs` and the unit tests of `crates/codeflow-core/src/git/remote_query.rs`
- docs: the `git.test_gate_on_push` and hook notes of `docs/policy-reference.md`
- release note: `changelog.d/TSK-327.md`

## Acceptance Criteria

- AC-1 When the repository, global or system configuration sets
  `url.<x>.insteadOf` for the destination, the hook's `ls-remote` shall
  query the destination the push uses, or the push shall be refused as an
  unchecked destination at `block`; evidence: a CLI test with a planted
  `insteadOf` pointing at a repository that advertises a different branch
  set, failing before the change and passing after. (serves EPC-022 AC-24)
- AC-2 With TSK-304's push set and TSK-287's guarded history reader
  combined, a clone holding a forged commit-graph file, a graft or a
  replace ref that changes the history between the pushed commit and the
  destination's tip shall give the range base and `rev-list --boundary`
  set computed without them, or refuse the push as unverifiable; evidence:
  one CLI test per input on the combined head, passing as the preserved
  invariant of TSK-287 AC-1 and AC-2. A change to `push_set.rs` is made
  only for a path that a concrete reproduction shows surviving both tasks,
  and the pull request names that path and the reproduction. (serves EPC-022
  AC-24)
- AC-3 The destination query shall select its ssh transport by this rule:
  it reads `GIT_SSH_COMMAND`, `core.sshCommand` and `GIT_SSH` through the
  hook's judging command, applies git's own precedence among them, and
  runs only the transport that precedence selects. When it cannot establish
  the selected transport, it shall refuse as cannot-verify. An unselected
  transport shall never run. Evidence: tests with a recording script for
  each selector alone (`GIT_SSH_COMMAND`, `core.sshCommand`, `GIT_SSH`),
  each showing the selected transport ran or the query refused as
  cannot-verify, and for each pair and for all three together, showing the
  lower-precedence recording script did not run; and a control with none of
  the three set, where the ordinary `ssh` query runs and the verdict is
  unchanged. (serves EPC-022 AC-24)
- AC-4 A push whose configuration has no `insteadOf`, no overlay and no ssh
  override shall make the same number of `ls-remote` calls and reach the
  same verdicts as before; evidence: the TSK-304 control tests and its
  advertisement call count, unchanged.
- AC-5 When a scratch adopter project with the installed hooks plants an
  `insteadOf` for its remote and pushes a commit that fails the push set,
  the push shall be stopped and nothing shall reach either repository
  (journey); evidence: the journey output with `git ls-remote` on both
  repositories unchanged. (serves EPC-022 AC-24)
