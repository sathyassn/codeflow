# TSK-1072: The privilege text check matches a chained launcher only as a whole word

## Description

Source: issue #404, session row 6 ("a heredoc Python body containing
`...; subprocess.run`"), refused under `security.privilege_escalation`
as "Semicolon chained su (pattern `; su`)".

The privilege check's semicolon rule is a substring match with no end
boundary: `cmd.contains(&format!("; {priv_cmd}"))`
(`crates/codeflow-core/src/security/privilege.rs:136`). So `; su`
matches `; subprocess`, `; sum`, `; sudoers.d` and any other word that
starts with a launcher name. The `&&` and `||` rules on line 128 need a
space after the launcher, and the pipe rules (`:81-91`) need whitespace.
The check runs on the raw line, heredoc bodies and quoted text included,
unless TSK-233's certified-prose grammar relieves the line
(`crates/codeflow-core/src/hooks/exec_guard.rs:121`).

Rechecked on 2026-10-29 with the line's binary at `bd721f39b`
(`codeflow hook exec-guard --contract 3`, payload directory a worktree
of this repository). Each line is refused with the `; su` pattern:

| Line | Verdict |
|---|---|
| `python3 -I - <<'EOF'` with body `import subprocess; subprocess.run(['true'])` | refused |
| `python3 -I -c "print('a; subprocess')"` | refused |
| `gh pr comment 1 --body "the guard refused text with ; su in prose"` | refused (a real launcher word as data: TSK-1073's class, not this task's) |
| `true; su -` | refused (a real launch; must stay refused) |
| `python3 -I -c "import subprocess as s` newline `s.run(['sudo', 'id'])"` | refused by the separate code-word family check (`security/outward.rs:27`), so that check, not this substring, refuses interpreter code that names a launcher |

Outcome: **the semicolon rule matches a launcher only where the shell
would read it as that launcher's name: a word that merely starts with
`su`, `sudo`, `doas`, `pkexec` or `runuser` is not a launcher.**

Scope: the raw-text matchers of the privilege check, and any sibling
raw matcher the investigation finds with the same in-word match. The
floor stays a raw-text floor. Non-goals: reading quoted data as data
(TSK-1073), launcher words inside interpreter code (refused on purpose
by the code-word family check, which this task does not change), and
the certified-prose grammar.

Placement: EPC-022 (4.0.0), under the standing direction that a defect
which forces an adopter workaround goes in the current release; it
needs no parser.

## Outcome

After this merges, an agent can run a heredoc or inline program whose text holds `; subprocess` or another word that only starts with a launcher name without a privilege refusal, while every real chained launch stays refused.

## Acceptance Criteria

- AC-1 Before any change, the builder shall record in the Findings, on the line's built binary: every raw-text matcher in the privilege, headless-peer and destructive-command checks that can match inside a longer word, with its file and line; which characters bash and zsh treat as continuing a command word after a launcher name (letters, digits, `_`, `-` and `.`), and which quote or escape forms the shell still reads as the launcher (such as `su''`, `su""` and `s\u`); and for each, whether another check already refuses the real launch; evidence: the Findings section, committed before the first code change.
- AC-2 The semicolon rule, and each sibling the Findings name, shall not match where the launcher name is followed by a character that continues the same plain word (`; subprocess`, `; sum`, `; sudoers`), and shall still match where the shell reads the launcher itself (`; su` at the end of the line, `; su -`, `; sudo id`, and each quote or escape form AC-1 shows the shell reads as the launcher where the rule matches it today); evidence: one unit test per form, the in-word forms failing before the change. (serves EPC-022 AC-161)
- AC-3 No line the line binary at the task's base refuses under `security.privilege_escalation` shall be allowed except a line whose only privilege finding was an in-word match of AC-2; evidence: TSK-397's replay corpus (`crates/codeflow-cli/tests/text_guard_invariant.rs`) run with this task's rows added, with the base binary's column beside the head's, each newly allowed row named with its in-word match. (serves EPC-022 AC-161)
- AC-4 (journey) With the installed build, an agent session shall run the issue's heredoc form (`python3 -I - <<'EOF'` with `import subprocess; subprocess.run(['true'])`) through exec-guard, and shall be refused `true; su -` and an inline program that runs `sudo`; evidence: the journey output.
