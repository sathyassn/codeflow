# TSK-428: A repository holds only what it needs long term

## Description

Issue #279, items 1 to 3 and 5. Nothing in the shipped instructions,
the reviewer's verdict or the gates asks whether a new file belongs in
the repository. Two adopting repositories accumulated 24 MB of tool
output as JSON under `docs/verification/`, a 4.3 MB research file in
its fourth draft, a retired prototype with committed `dist/` and a
vendored minified library, 117 per-run model-checker summaries, a 111 KB
manifest of hashes for files not carried, one-off session scripts and
byte-identical draft mirrors; every item passed review.

Outcome (amended 2026-10-27): **the managed quick gate enforces the
rule TSK-1030 states in three tiers: it refuses the block-tier classes
(build and cache output, run output, review records, per-task evidence
folders, superseded iterations) unless a TSK-424 exemption names a
reason, warns in the PR evidence on the judgement calls (large evidence
additions, byte-identical files, draft siblings, tool-output-like files,
uncited research), and refuses a live citation of removed evidence that
carries no resolvable commit pin.**

Rules: the instruction is TSK-1030's (3.2.0), saying that git history
keeps removed evidence and that evidence is summarised unless the raw
form is what is cited; the gate check is a
new repository-wide quick target (`dist/` and other build-output
folders, `*.log` and similar run output, added files above a
configured size under evidence paths, byte-identical tracked files)
with its thresholds in `.codeflow/test-config.json`; a relaxation is
a TSK-424 entry that `codeflow ci` reports.

Non-goals: CodeFlow's own managed-copy footprint (TSK-429); deleting
what adopters already hold.

Amended 2026-10-27 by the quality asks amendment. The instruction and
the review question (former AC-1 and AC-2) moved to TSK-1030 in EPC-022
(3.2.0), by the operator's decision of 2026-10-27 that the instruction
fix ships in 3.2.0 and the gate stays here. This task keeps the gate
and takes the issue's comments of 2026-10-27 (07:24Z and 22:46Z):

- Three tiers. **Block** the classes a path, name or file type
  identifies: build and cache output (`dist/` and the like), run output
  and `*.log`, review records and verdict files matched by name,
  per-task evidence folders such as `docs/verification/<task>/`,
  superseded iterations (a removed path added again, or a file whose
  status line says it is superseded), and a citation of a removed
  evidence path with no resolvable commit pin. **Warn**, never fail, on
  judgement calls: a large added file under a docs or evidence path, a
  file byte-identical to another tracked file, a `-r2`, `-v3` or
  `-final` sibling of an existing draft, JSON or text that looks like
  tool output, and research nothing cites; each warning is listed in
  the `codeflow ci` PR evidence for the reviewer to acknowledge.
  **Review**: the question TSK-1030 adds to `cf-reviewer`.
- Citation safety. When evidence is removed, a live citation of the
  removed path is refused unless it carries a commit pin that resolves
  in history and holds the file, so a clean-up never silently breaks
  old records. Managed baseline files and their exact mirrors are
  exempt from this check only, since they describe the upstream
  repository.
- Exceptions. Every exception is a TSK-424 register entry with its path
  or pattern, reason and expiry, reported in the PR evidence. No
  directory is exempt as a whole. The adopter judges allowances with
  the target branch's checker and allowances, so a pull request cannot
  admit its own exception; TSK-424 AC-4 instead accepts a head-introduced
  entry that carries every field and lists it for the reviewer. AC-9
  settles which applies to this check, with TSK-424's owner.
- Precedence. Path and name rules decide the block tier and are judged
  first; size and content heuristics only ever warn. A file that
  matches a block rule is refused whatever its size or content, and a
  file that matches only a warn rule passes with its warning. A
  per-task evidence folder is a path under a configured evidence root
  whose next segment is a task id (default root `docs/verification/`,
  so `docs/verification/TSK-001/...`); AC-9 confirms the default and
  how a project names its roots.
- Name patterns compare whole parts of the file name without its last
  extension, split at `-`, `_` and `.`, in lower case (the adopter's
  rule), so `confirmed` does not match `confirm`; AC-9 confirms or
  replaces it.

First-pass survey (planning, 2026-10-27, line tip `5f2fe3827`): no
shipped gate has a path, name or size rule for added files; the managed
`assets/base/gitignore` covers secrets, editor files and worktrees only;
`crates/codeflow-core/src/testing/` holds the contract scans TSK-385
added, the natural home of a repository-content check; this repository's
`docs/verification/` holds 91 MB in 60 folders and 79 records cite paths
in it, so citation safety decides whether its own clean-up is possible.
