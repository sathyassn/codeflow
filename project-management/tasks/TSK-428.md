# TSK-428: A repository holds only what it needs long term

## Description

Issue #279, items 1 to 3 and 5. Nothing in the shipped instructions,
the reviewer's verdict or the gates asks whether a new file belongs in
the repository. Two adopting repositories accumulated 24 MB of tool
output as JSON under `docs/verification/`, a 4.3 MB research file in
its fourth draft, a retired prototype with committed `dist/` and a
vendored minified library, 117 per-run model-checker summaries, a 111 KB
manifest of hashes for files not carried, one-off session scripts and
byte-identical draft mirrors; every item passed review.

The instruction is TSK-1030's (4.0.0): what belongs in a repository,
that git history keeps removed evidence, and that evidence is summarised
unless the raw form is what is cited. This task enforces it in the path
gate.

Rules (decided 2026-10-29, design revision 5 for issue #279, decisions
7, 9, 10 and 11):

- Placement. The checks are content classes of `path_policy`, judged by
  `codeflow ci` in the `pull_request_target` job from the authority's
  binary and policy, and by pre-commit and pre-push from the landed
  policy. They are never a `testing/` target or a job in
  `codeflow-ci.yml`, because those run head code on `pull_request` and a
  block tier there would let a pull request change the check that judges
  it (design N-5).
- Tiers. **Block** refuses; **warn** lists the finding in the `codeflow
  ci` PR evidence and passes; a warning acknowledged in the body informs
  the reviewer and is never a pass. Default tiers (decision 7, hybrid):
  block per-task evidence folders under the configured root (default
  `docs/verification/`, so `docs/verification/TSK-001/...`),
  `node_modules/`, `__pycache__/`, `.pytest_cache/`, `.mypy_cache/` and
  `.DS_Store`; warn `dist/`, `*.log` and other run output, single-tool
  caches, byte-identical duplicates, superseded iterations (an explicit
  superseded marker outside record frontmatter, or a removed path added
  again), large files, draft siblings (`-r2`, `-v3`, `-final`),
  tool-output-like JSON or text, uncited research, and a live record
  citing a path under the local evidence home. A class moves only by a
  reviewed policy change on the authority.
- No review-record class (decision 10: this repository holds 11
  legitimate review paths). The superseded marker warns (decision 11:
  three accepted ADRs would fail a block). No named catalogue and no
  public fixture format (decision 9).
- Scope. Junk classes use net scope: a path in the head tree that matches
  a class and is absent from the base tree. A file added and removed on a
  line never blocks its pull request, and an existing file is never
  judged by an unrelated pull request. Audit mode (`codeflow ci --audit`)
  lists the final tree and never gates. Secret names and the gitleaks
  content scan keep history scope, untouched here.
- Citation safety. When evidence is removed, a live citation of the
  removed path is refused unless it carries a commit pin that resolves to
  a commit reachable from the authority the run judges with and holding
  the file. Managed baseline files and their exact mirrors are exempt from
  this check only.
- Exceptions. Every exception is a TSK-424 register entry; for a blocking
  class it applies only when the authority holds it, so a pull request
  cannot admit the file it adds (design N-6). No entry exempts a
  directory as a whole.
- Exempt inputs. Content classes exempt only `.codeflow/policy.json`,
  `.codeflow/project.toml` and the two policy workflows; TSK-424's
  register file is not exempt unless a later operator amendment says so.
- Matchers are declarative only (folder segment, exact name, suffix, name
  token, root glob, size, duplicate blob, superseded marker), compiled
  into the binary, with no executable adapters. Name patterns compare
  whole parts of the file name without its last extension, split at `-`,
  `_` and `.`, in lower case, so `confirmed` does not match `confirm`.

Non-goals: CodeFlow's own managed-copy footprint (TSK-429); deleting
what adopters already hold; this repository's own `docs/verification/`
clean-up (TSK-1081).

History. Amended 2026-10-27 by the quality asks amendment: the
instruction and the review question (former AC-1 and AC-2) moved to
TSK-1030, and the gate took three tiers from the issue's comments of
that day, as a quick-gate target under `crates/codeflow-core/src/testing/`
with thresholds in `.codeflow/test-config.json`, a review-record block
class, a superseded-marker block class, and a baseline for existing
repositories. Amended 2026-10-29 by the content policy amendment, which
replaced each of those with the rules above for the reasons given there
(design N-5 and N-6; decisions 7, 10 and 11; net scope).

First-pass survey (planning, 2026-10-27, line tip `5f2fe3827`): no
shipped gate has a path, name or size rule for added files; the managed
`assets/base/gitignore` covers secrets, editor files and worktrees only;
this repository's `docs/verification/` holds 91 MB in 60 folders and 79
records cite paths in it, so citation safety decides whether its own
clean-up is possible.

## Outcome

After this merges, an adopter's path gate refuses junk that is never wanted in a repository and warns on judgement calls, judged from the default branch's code and policy, so a pull request cannot weaken the check or admit its own file.
