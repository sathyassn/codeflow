# TSK-428: A repository holds only what it needs long term

## Description

Issue #279, items 1 to 3 and 5. Nothing in the shipped instructions,
the reviewer's verdict or the gates asks whether a new file belongs in
the repository. Two adopting repositories accumulated 24 MB of tool
output as JSON under `docs/verification/`, a 4.3 MB research file in
its fourth draft, a retired prototype with committed `dist/` and a
vendored minified library, 117 per-run model-checker summaries, a 111 KB
manifest of hashes for files not carried, one-off session scripts and
byte-identical draft mirrors; every item passed review.

Outcome: **by default a file enters the repository only when it is
product or authority content, code with its tests and config, or
evidence a live record cites, in its smallest form; `cf-reviewer` asks
for every added file whether it is needed long term and in its smallest
form; and the managed quick gate refuses build-output folders, run
output, oversized additions under evidence paths and files
byte-identical to another tracked file unless a TSK-424 exemption
names a reason.**

Rules: the instruction goes in `cf-develop`, `cf-ship` and the
evidence rules (`cf-model-orchestrator/resources/quality/evidence.md`),
saying that git history keeps removed evidence and that evidence is
summarised unless the raw form is what is cited; the gate check is a
new repository-wide quick target (`dist/` and other build-output
folders, `*.log` and similar run output, added files above a
configured size under evidence paths, byte-identical tracked files)
with its thresholds in `.codeflow/test-config.json`; a relaxation is
a TSK-424 entry that `codeflow ci` reports.

Non-goals: CodeFlow's own managed-copy footprint (TSK-429); deleting
what adopters already hold.

## Deliverables

- the instruction: `cf-develop/SKILL.md`, `cf-ship/SKILL.md`, `cf-model-orchestrator/resources/quality/evidence.md` and the `cf-reviewer` agent in `assets/base/`, `.claude/skills` and `.agents/skills`, byte-identical
- the gate target: `crates/codeflow-core/src/testing/` (a repository-footprint check beside the contract scans TSK-385 added) and its thresholds in the test-config schema
- tests: runner tests over fixture trees and `crates/codeflow-cli/tests/test_gate_cli.rs`
- docs: `docs/policy-reference.md` and the test-config reference
- release note: `changelog.d/TSK-428.md`

## Acceptance Criteria

- AC-1 The instruction texts shall state what belongs in the repository, what stays out, that history keeps removed evidence and that evidence is summarised unless the raw form is cited; evidence: the text diff and a `cf-editorial-review` pass. (serves EPC-024 AC-5)
- AC-2 `cf-reviewer` shall ask, for every added file, whether it is needed long term and in its smallest form, and return a finding for an unneeded or oversized addition; evidence: the verdict format and a qualification case. (serves EPC-024 AC-5)
- AC-3 The quick gate shall refuse an added `dist/` folder, an added `*.log`, an added file above the configured size under an evidence path and an added file byte-identical to a tracked one, each naming the file and the exemption route, and shall pass when a TSK-424 entry names a reason; evidence: one test per class and the exemption test. (serves EPC-024 AC-5)
- AC-4 An existing repository adopting the check shall start from a baseline of its current state, so only new additions are judged; evidence: a fixture with pre-existing `dist/`.
- AC-5 (journey) With the installed build in a scratch adopter project, a commit adding a 2 MB JSON run output under `docs/verification/` shall fail the quick gate and pass after it is replaced by a summary table; evidence: the journey output.
