# TSK-1424: Integration lines require the line check names, and remote protect plans them

## Description

ADR-0097 places suites by event: a pull request into an integration line runs only the short checks, and `codeflow gates` and `windows` stay required on `main`, where they run. TSK-1321 (PR 620) builds that placement. After it, a line pull request publishes `codeflow gates (line)` and no `codeflow gates` or `windows` check (TSK-1321 AC-14). Two things still require the old names on lines:

- The live `integration/**` ruleset 25435656 requires `codeflow gates` and `windows`. Once a line has the placement, its pull requests can never meet that ruleset. This is operator decision 3 of the CI/CD coherence result of 2026-11-06 (workspace `coordination/briefs/cicd-coherence-result-2026-11-06.md`), which ADR-0097's Decision records: "the `integration/**` ruleset is to require only the short-check names ... The operator applies that change as a script."
- `codeflow remote protect` plans ruleset C ("codeflow line checks") with `LINE_TEST_VERDICTS = ["codeflow gates", "windows"]` (`crates/codeflow-core/src/remote.rs:139`, added to C at `:1048`). `main`'s `codeflow-ci.yml` still declares both names, so a later `remote protect` run would add them back to the line ruleset (its update only adds, `remote.rs:30`), and every adopter whose template gains line names (TSK-1352 AC-11) would get a line ruleset its pull requests cannot meet.

The ruleset change is a repository setting and a weakening of what lines require, so it is an operator script, run by the operator, never by an agent. The script exists: `coordination/scripts/operator/apply-tsk1321-workflows.sh`, jobs `ruleset-step-1` and `ruleset-step-2` (workspace repository). This task owns its proof and the matching product change.

Non-goals: the `main` ruleset, which keeps `codeflow gates` and `windows`; the names TSK-1368 restores; the placement itself (TSK-1321) and the adopter template's line names (TSK-1352 AC-11); up-to-date and merge-queue policy (TSK-1396).

## Outcome

After this merges, a pull request into an integration line that has the placement can land on its line checks, the line ruleset requires every short-check name it publishes, and `codeflow remote protect` plans the same names, so it never puts back a name a line no longer publishes.

## Deliverables

- the operator script: `coordination/scripts/operator/apply-tsk1321-workflows.sh` `ruleset-step-1` and `ruleset-step-2` (workspace repository), adopted as is or amended by coord/ci with a new reviewed digest; never run by an agent except with `--check`
- the line verdict list and its plan text: `crates/codeflow-core/src/remote.rs` (`LINE_TEST_VERDICTS`, ruleset C's body and plan lines), with its tests

- AC-2 The operator shall apply ruleset step 1 after PR 620 is on `main`, and ruleset step 2 once every line with an open pull request has the placement; after step 2 the `integration/**` ruleset shall require exactly the six names the script names, each pinned to GitHub Actions, with its non-fast-forward and deletion rules and empty bypass list unchanged, and the `main` ruleset shall be unchanged; evidence: `gh api repos/sathyassn/codeflow/rulesets/25435656` and `.../24379074` read back after each step, with the sha256 of each update body equal to the script's reviewed digest, and one line pull request with the placement that lands on its line checks after step 2.
- AC-3 `codeflow remote protect` shall plan ruleset C with the line verdict names a workflow on the default branch declares for a pull request into a line (`codeflow gates (line)` here), and shall never plan `codeflow gates` or `windows` for a line when a line verdict is declared; when no workflow on the default branch declares a line verdict, it shall plan `codeflow gates`, and `windows` where declared, as today, so a project without line names keeps today's protection (fail closed); its update shall stay add-only (it never removes a name from a live ruleset; the removal stays the administrator's edit on the host, here the operator script); and `doctor --check remote-perimeter` shall accept the line ruleset step 2 leaves and report a line ruleset that lacks a declared line verdict; evidence: tests for a default branch with line names, one without, and one with both `codeflow gates` and `codeflow gates (line)` declared, a test that an update over the step 2 body adds nothing, and a doctor test over the step 2 body.
- AC-4 The docs and the release note shall say which names a line ruleset requires and when, that `codeflow gates` and `windows` stay required on `main`, and that `remote protect` never removes a name; evidence: the doc diff, `changelog.d/TSK-1424.md` and a passing release preflight.
