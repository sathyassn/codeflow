# TSK-411: A pre-push gate block names the target that failed and how

## Description

Issue #250. On 2026-10-18 an adopter's pre-push gate (CodeFlow 3.1.1,
source `48104f48b`) blocked a push with `push set failed for: [empty]`
after the push set took 578.5 s against its 60 s budget on a machine with
load averages of 20 to 33. The person pushing could not tell what to fix;
a retry at lower load passed, and a later block on another branch named
its target after a 600 s timeout. The block message is built in
`crates/codeflow-core/src/hooks/git_hook.rs:1520-1545`: when the gate
outcome is `Completed` with `passed` false, the failed list is every
result whose `passed()` is false, so a run that ends unpassed with no
result marked failed (a target that timed out or was killed without a
recorded result, or an internal gate error) prints an empty list. The
cause is not confirmed; this task finds it by reproduction.

Outcome: **a `git.test_gate_on_push` block always names the target that
failed and how it failed (non-zero exit, timeout, killed, or an internal
error of the gate itself), and when no target failed the message names
the gate condition that caused the block.**

Non-goals: the push-set time budget and target serialization, which
TSK-331 owns; the gate target set of any project.

Added by the EPC-022 amendment of 2026-10-22 under the operator's release
rule of 2026-10-18 (a defect that blocks work belongs in 3.2.0).

## Deliverables

- the cause, reproduced, and the block message: `crates/codeflow-core/src/hooks/git_hook.rs` (the `test_gate_on_push` report) and the result recording in `crates/codeflow-core/src/testing/gate.rs` and `crates/codeflow-core/src/testing/runner/`
- tests: `crates/codeflow-core/src/hooks/git_hook.rs` unit tests and `crates/codeflow-cli/tests/hooks_cli.rs`
- the remedy text: `crates/codeflow-core/src/remedy.rs` (`PUSH_SET_FAILED`) and `docs/troubleshooting.md`
- release note: `changelog.d/TSK-411.md`

## Acceptance Criteria

- AC-1 The shape that produces an empty failed list shall be reproduced in a test (a target that times out or is killed without a recorded failed result, or an internal error of the gate, whichever the reproduction shows) and named in the pull request; evidence: the test, failing before the change. (serves EPC-022 AC-100)
- AC-2 When the push set blocks, the message shall name each failed target with how it failed: non-zero exit with the code, timeout with the limit, killed with the signal, or an internal gate error with its text; evidence: one test per failure kind. (serves EPC-022 AC-100)
- AC-3 When the gate blocks and no target is recorded as failed, the message shall name the gate condition that caused the block (for example an incomplete run, a target with no result, or a runner error) and never print an empty list; evidence: a test for each condition the reproduction finds. (serves EPC-022 AC-100)
- AC-4 The remedy shall point at the failed target by name and at `codeflow test --mode quick` to reproduce it, and the passing path shall print what it prints today; evidence: the remedy text and the existing passing-push tests.
- AC-5 (journey) With the installed hooks in a scratch adopter project, a push whose quick target times out under a short configured limit shall be blocked with the target and `timeout` named, and a push whose targets pass shall go through; evidence: the journey output.
