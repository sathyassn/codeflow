# TSK-1509: The managed workflow runs one codeflow test --mode pr judged by the default branch's config

## Description

Split from TSK-384 on 2026-11-15 by the Director's approval (16:44). This task is TSK-384's AC-9: the shipped `codeflow-ci.yml` drops its mode selection and verdict logic, and one `codeflow test --mode pr` resolves the effective mode and the targets from the default branch's copy of the test config (ADR-0091), never the head's. TSK-384 lands the sharded managed workflow (its AC-4 and AC-5: the shard matrix, the aggregate job, their rendered tests and hosted journey, and their baseline resync); this task then removes the mode selection and verdict logic from that already-sharded workflow and does not rebuild the shards. It waits for TSK-1355, which gives the gates job its read of the base authority, and for TSK-1352, which owns the effective mode. Workers may not edit the managed `.codeflow/.baseline/` and `.codeflow/manifest.json`, so their resync comes through an operator script written from reviewed copies of those files.

## Outcome

After this merges, an adopter's managed workflow holds no mode or verdict logic of its own: one `codeflow test --mode pr` call picks the mode and targets from the default branch's test config, so a pull request cannot drop a target or lower a floor to pass.
