# TSK-1010: Targets that share a named host resource never run at the same time, and each wait is recorded

## Description

Issue #322, filed against CodeFlow 3.1.1 (`48104f48b`). `codeflow test`
admits one heavy gate per machine (`crates/codeflow-core/src/testing/gate_guard.rs`),
so an adopter with eight parallel streams on a 64 GB, 18-core host lands
two or three candidates an hour. This task was first planned as an N-gates
setting plus named shared resources. Standalone TSK-1145 (capacity
admission, PR 483, open and not yet merged) replaces the one lock with
admission by host capacity (`execution.host_jobs`), so heavy gates run at
once by default, and adds `host_exclusive: true` for a target that must run
alone. The N-gates setting is therefore dropped from this task. What
TSK-1145 does not deliver, and what remains here, is named shared
resources: two targets that use the same fixed host resource (a port, a
Docker daemon name, a browser cache) never run at the same time, while
every other heavy run continues. `host_exclusive` stops all other heavy
runs, which is too coarse for that case.

This task builds on TSK-1145's admission and is not started before PR 483
lands. TSK-1145's record is not on this line yet, so `depends_on` cannot
name it without a dangling reference. The dependency is recorded here until
then; the revisit event is PR 483 merging, and the planning amendment that
follows it adds `TSK-1145 -> TSK-1010` to `depends_on` and the EPC-023
graph. Until that edge exists the task is a root in the graph but must not
be claimed.

Outcome: **a target can declare a named shared host resource, and targets
that declare the same name never run at the same time across gates, while
targets with no shared name and all other heavy runs overlap as TSK-1145
admits them.**

Rules:

- A target declares the fixed host resources it uses (provisional
  `shared_resources`: a list of names such as a port, a Docker daemon name
  or a browser cache), in the test config next to TSK-1145's
  `host_exclusive`.
- Admission takes one lock per declared name, in a fixed order so two gates
  cannot deadlock. A target waits for its names only; no other target waits.
- The lock holder record lists the holder of each name.
- A target that declares `host_exclusive: true` keeps TSK-1145's behaviour.

Non-goals: the capacity admission, `execution.host_jobs` and
`host_exclusive` (TSK-1145); an N-gates setting (dropped); CodeFlow's own
repository practice; quick and pre-push serialization (TSK-331).
