# TSK-1010: A project can let more than one heavy gate run at once on one machine

## Description

Issue #322, filed against CodeFlow 3.1.1 (`48104f48b`). `codeflow test`
admits one heavy gate per machine (`crates/codeflow-core/src/testing/gate_guard.rs`,
"another heavy gate is running on this machine"), with no setting to
raise it. An adopter with eight parallel streams on a 64 GB, 18-core host
lands two or three candidates an hour while the host runs at a load of
about 9. The manual route works (gates run one after another), so this
is a feature generalization for 4.1.0 under the release rule of
2026-10-18, not a 4.0.0 defect.

Outcome: **a project or user setting lets N heavy gates run at once on
one machine, default 1 (today's behaviour), while targets that declare a
shared host resource stay serial across gates.**

Rules:

- The setting (provisional `full_gate_concurrency`, default 1) lives where
  TSK-331's admission settings live, at project or user scope; a project
  value can lower a user value, never raise it past it.
- The admission lock becomes N slots. Each gate keeps its own isolated
  working state, as today.
- A target declares the fixed host resources it uses (provisional
  `shared_resources`: a port, a Docker daemon name, a browser cache);
  two gates never run targets that share a declared resource at the same
  time, and the rest run in parallel.
- The lock holder record (TSK-331 AC-13) lists every slot holder.

Non-goals: changing CodeFlow's own repository practice (this workspace
runs one full gate at a time by operator rule; the default stays 1);
quick and pre-push serialization (TSK-331).

## Deliverables

- the slots, the setting and the resource serialization: `crates/codeflow-core/src/testing/gate_guard.rs`, `crates/codeflow-core/src/testing/config/mod.rs`, `crates/codeflow-core/src/testing/gate.rs`
- the schema field: `assets/base/testing/test-config.schema.json`
- tests: `gate_guard.rs` unit tests and a `crates/codeflow-cli/tests/` test with two gates
- docs: `docs/test-gate.md`
- release note: `changelog.d/TSK-1010.md`

## Acceptance Criteria

- AC-1 With the setting unset or 1, a second heavy gate shall be refused or wait exactly as today; evidence: the existing admission tests passing. (serves EPC-023 AC-30)
- AC-2 With the setting at N, N heavy gates from different worktrees shall run at once and gate N+1 shall wait or be refused naming every holder; evidence: a test with N=2 and three gates. (serves EPC-023 AC-30)
- AC-3 Two concurrent gates whose targets declare the same shared resource shall not run those targets at the same time, and targets with no shared resource shall overlap; evidence: a test with timestamps per target.
- AC-4 A project value above the user value shall be capped at the user value and the cap reported; evidence: a config test.
- AC-5 (journey) With the installed build, two scratch worktrees with the setting at 2 shall run full gates concurrently to completion, and a third shall report both holders; evidence: the journey output.
