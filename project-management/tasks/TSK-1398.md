# TSK-1398: Agent sessions refuse the git and merge actions ADR-0075 records

## Description

ADR-0075 records refusals for agent sessions that no task built. An audit
of every refusal the ADR states, against the code and tests at the line's
96a01e17e, found most of them built and five missing or partly built:

| Refusal (ADR-0075 line) | At 96a01e17e | Why it was never built |
|---|---|---|
| `git pull` refused in agent sessions; integrate by fetch, then a merge or rebase (72, 332-334) | missing: no git-guard rule refuses pull itself | TSK-172 AC-10 and AC-26 carried it; TSK-172 was cancelled and TSK-188 and TSK-189 took its scope without it |
| a push that would bring a workflow change to its destination, judged from the destination's own refs (D9 at 267, 72) | missing: no push-side check | TSK-172, cancelled |
| server-side landing: deferred merge modes, the administrator override and pull requests that change enforcement entries refused (205-211, 317-320) | partly built: `check_gh_pr_merge` (`crates/codeflow-core/src/hooks/git_guard.rs:12229`) refuses only branch deletion and a protected base | TSK-172, cancelled |
| a merge or rebase whose changed paths select a custom merge driver, a defined filter or renormalization (196-202, 334-335) | partly built: a config write that sets such a driver or filter is judged (`crates/codeflow-core/src/security/git_config_writes.rs`), a merge that uses an existing one is not | TSK-172, cancelled; TSK-242 built the config side |
| delegated seats deny the unsandboxed retry natively (decision 6 amendment, 418) | missing: the delegate lane text still permits it (`.agents/skills/cf-delegate/resources/lane-lifecycle.md:56-59`) | TSK-174, cancelled |

An agent session is one where any name in `AGENT_MARKERS`
(`crates/codeflow-core/src/root_checkout.rs:54`) has a non-empty value; an
empty value counts as unset. The human-override variable does not lift any
refusal here, although `actor()` (`root_checkout.rs:108-114`) honours it, and
assigning it inside a session is already refused (`git_guard.rs:1383`). With
no marker set, as in a human terminal, every command here behaves as before.

Refusing every pull removes the only in-session way to move a protected
branch to its remote tip today, because git-guard refuses every merge there
without the integrate token (`git_guard.rs:10751-10766`) and every rebase
(`:10769-10782`). The Director's ruling of 2026-11-08 was C (no in-session
sync) if a three-part proof holds, else A (one narrow fast-forward-only
merge). Part (2) fails at 96a01e17e, so AC-1 records A. That failure is EPC-054's outcome. TSK-1078 AC-7 closes the four classic hooks and AC-8 closes `codeflow ci`'s range choice (`crates/codeflow-cli/src/cmd/ci.rs:418`, `:445`). C may be revisited only after both land and the AC-1 proof is run again. A does not wait for them.

The server-side landing and merge driver rules sit in decision 5, which the
2026-09-29 amendment drops as a whole (line 434), while the consequences at
317-320 and 334-335 still state both rules. This task keeps them, failing
closed, by the Director's ruling that the stricter reading of a security
decision wins, and its ADR amendment records that reading (AC-10).

TSK-1393 fixes the two remedy texts that recommend a rebasing pull
(`crates/codeflow-core/src/remedy.rs:459`, `:651`). This task is built after
it, and AC-2 moves every shipped text that still names a pull as the sync
route, whatever TSK-1393 ships included, to the route AC-1 settles.

The audit table lands in this record; the per-command detail for each
refusal lands in this task's own pull request with the fix.

Not in scope:
- TSK-1393's refusal of rebasing and merging pulls on a protected branch; this task widens the pull refusal to every branch in agent sessions and builds on it.
- The token and GitHub App half of D9, which is operator setup.
- The dropped mechanisms the amendment names (baseline, binding registry, readiness receipts, operator queue, fixture root).

## Outcome

After this merges, an agent session is refused, with the sanctioned route
named, every git and merge action ADR-0075 says agents do not take, while a
human terminal behaves as before.

## Acceptance Criteria

- AC-1 Before any guard change, the builder shall record in `## Findings`, with file:line evidence at the build's base, the three-part proof the Director's ruling names: (1) whether any CodeFlow verb or shipped instruction needs a current local protected branch (`work start`, `integrate`, `orient`, `task new`, the cleanup steps, the session-start hooks); (2) whether any guard, hook or `codeflow ci` policy authority reads the local protected branch so that a stale copy weakens it; (3) the cost to adopters, stated in the docs. Part (2) already fails at 96a01e17e: the classic git hooks load the checked-out tree's policy file (`crates/codeflow-core/src/hooks/policy.rs:1103-1105`, `crates/codeflow-cli/src/cmd/git_hook.rs:111`). So choice A applies: on a protected branch an agent session may run exactly one sync shape, a fast-forward-only merge whose only operand resolves to the checked-out branch's own configured upstream remote-tracking ref. Before allowing it, git-guard shall read the configured upstream's advertised head from the remote once, read-only, under a bounded timeout, and allow the merge only when the remote-tracking ref and the resulting tip both equal that head. It shall refuse when the read times out, cannot be read or differs, naming a human sync as the sanctioned path, and that refusal shall hold whether or not the reference-transaction hook runs. Anything beyond that shape is refused: another operand, a strategy or strategy option, a skip-hooks option, a command-line config entry or any config that changes merge behaviour. The merge rule's existing integrate-token exception (`git_guard.rs:10754-10758`) stays; the new allowance adds no other exception, and every other merge or rebase on a protected branch stays refused. Evidence: the `## Findings` proof; unit tests for the allowed shape, each refused variation, an unreadable, a timed-out and a differing advertised head, and the integrate-token merge as a control.
- AC-2 In an agent session, git-guard shall refuse `git pull` in every form on any branch, and a form the guard cannot classify shall be refused, naming fetch followed by the sync route AC-1 settles; plain fetch shall pass. Every shipped guard message and policy reference text that still names a pull as the sync route shall name that route instead. Evidence: unit tests failing before and passing after, per form and for an unclassified form, with fetch as the control, and a search at the head showing no shipped guard message or policy text names a pull as the route.
- AC-3 In an agent session, a push that would bring a change under `.github/workflows/` to its destination shall be refused before anything transfers, judged against the destination's own advertised refs read once, never a local tracking ref; when that evidence cannot be read, the push shall be refused naming the fetch or retry. Evidence: tests against a local bare remote with and without such a change, and with the destination unreadable.
- AC-4 In an agent session, git-guard shall refuse a server-side merge in a deferred mode, with the administrator override, or of a pull request whose commits change a file in the enforcement directories the guard already uses (`git_guard.rs:2417-2420`), or whose head differs from the base there; it shall pass an immediate merge with the head pinned when those files are unchanged; a case the guard cannot judge shall be refused. Evidence: tests with a stub `gh`.
- AC-5 In an agent session, a merge or rebase whose changed paths select a custom merge driver (by its effective definition), a non-built-in default driver, a defined filter or renormalization shall be refused before git runs it, naming the operator's route; a definition the guard cannot read shall be refused. Evidence: tests with the attribute and the config present, with the definition unreadable, and a plain merge as the control.
- AC-6 Each seat class `cf-delegate` launches shall be named in `## Findings`, delegated Codex and Grok seats and Claude Worker sessions among them, and each shall deny the model-chosen unsandboxed retry through its harness's native configuration. Host-state commands a Worker needs shall run through a sanctioned path that is not a retry the model chooses: a fixed exclusion list in the committed preset, naming exact commands with the argument shapes AC-12's journey needs, never a whole program. Every excluded command stays judged by exec-guard and git-guard. A native subagent of a primary session keeps the primary's preset. For adopters, the default denies the retry; a project allows it only from its committed base-branch policy, never the working tree or the environment, and an unreadable base-branch policy leaves the default deny. Evidence: a preset test per seat class, a guard test showing an excluded command still refused in a refused form, the policy tests for the committed-only opt-in and the unreadable policy, and the text diff in both lane mirrors and the baseline.
- AC-7 Before any preset changes, `## Findings` shall list each host-state command our delegated Workers run (at least `gh`, `git worktree add` and `codeflow task new`), how it runs today and how it runs after this task; evidence: the table, committed before the preset change.
- AC-8 Each refusal in AC-1 to AC-5 shall pass unchanged when no agent marker is set, and shall still refuse when a marker is set together with the human-override variable; evidence: both controls per refusal in the same tests.
- AC-9 The shipped harness permission presets shall no longer allow the pull command, so a preset never invites what the guard refuses; the guard stays the floor; evidence: the preset diffs (`assets/base/settings/*.json` and any other harness profile that allows it) and a preset test.
- AC-10 An ADR-0075 amendment shall record the AC-1 choice and its proof, and state that the server-side landing rule and the merge driver, filter and renormalization rule hold after the decision 5 drop; the policy reference shall list each refusal with its route; evidence: the ADR and `docs/policy-reference.md` diffs.
- AC-11 (journey) In a scratch adopter made by `codeflow init --standard` with the installed build, an agent session's pull, protected-branch sync per AC-1, workflow push, deferred server-side merge and driver-selecting merge shall each be refused or, for A's allowed shape, pass through the installed hooks and guards, and the same commands shall pass from a human terminal; evidence: the journey output in the pull request body.
- AC-12 (journey) A delegated Worker under the new presets shall open a task worktree, file a task record, push and open a pull request end to end; evidence: the run in the pull request body, naming each host-state command and the path it took.
