# TSK-297: The dependency audit accepts the unmaintained unsafe-libyaml advisory until the YAML parser is replaced

## Description

Since 2026-10-12 11:45 UTC OSV lists RUSTSEC-2024-0449: unsafe-libyaml is
unmaintained and its repository is archived. The advisory names no
vulnerability, no fixed version and no exploit. `unsafe-libyaml` 0.2.11
comes in through `serde_yaml_ng` 0.10.0 (`Cargo.toml:22`), which reads and
writes the front matter of every CodeFlow record. The `security review` job
runs `osv-scanner` 2.4.0 over the repository, so it now fails on `main`
(run 38244949739) and on every pull request. This task records a justified
suppression in a new `osv-scanner.toml` beside `Cargo.lock`, in the style of
the existing `docs-portal/osv-scanner.toml`: the entry names the advisory,
why it is accepted and when it must be triaged again (`ignoreUntil` of
2026-12-31). The advisory is informational and no exploit is known for 0.2.11,
but the parser is reachable: it reads files in the repository the command runs
in, including pull request files that `codeflow validate --docs` parses in CI
before merge, and files in adopter repositories that run the binary. This
codebase parses no HTTP response with it. The entry also ignores any later
alias of the id until the expiry; a different advisory id still fails the job.
Replacing the parser with a YAML parser written in safe Rust is a separate
change for 3.2.0, filed as TSK-298 on the EPC-022 line. Non-goal: removing
`serde_yaml_ng` or `unsafe-libyaml` here.

The audit takes suppressions only from the trusted commit (the pull request
base, or the pushed commit on a push), so this pull request's own
`security review` stays red until the file is on `main`. That is expected.
After the merge, the job on `main` is the proof that the hosted audit passes;
the evidence below is the same scanner and command run locally.

## Deliverables

- the suppression: `osv-scanner.toml`
- the gate partition entry that classifies the new file (a root config file that runs the whole gate when edited, like `dist-workspace.toml`): `.codeflow/test-config.json`
- this task record: `project-management/tasks/TSK-297.md`

## Acceptance Criteria

- AC-1 The root `osv-scanner.toml` shall hold one `[[IgnoredVulns]]` entry for `RUSTSEC-2024-0449` only, with an `ignoreUntil` of 2026-12-31 and a reason that says the advisory is informational (unmaintained) with no fixed version, no alias in the current OSV record and no known exploit for 0.2.11, that the parser reads files in the repository the command runs in (pull request files parsed by `validate --docs` in CI before merge, and adopter repositories), that this codebase parses no HTTP response with it, that any later alias of the id is ignored until the expiry while a different advisory id still fails, and that TSK-298 removes the parser and the entry in 3.2.0, and no other advisory or package shall be ignored. Evidence: the file.
- AC-2 When osv-scanner 2.4.0 runs the audit command (`scan -r --no-ignore .`) on a tree that holds the file, it shall exit 0 with the advisory filtered, and on the same tree without the file it shall exit 1 and report `RUSTSEC-2024-0449` on `unsafe-libyaml` 0.2.11 in `Cargo.lock`. Evidence: both runs, with exit status and the last output lines, quoted in the pull request.
- AC-3 (journey) When the workflow's trusted-commit step installs the suppression files of a commit that holds this file, the root `osv-scanner.toml` shall be written beside `Cargo.lock` and osv-scanner shall load it, so once the file is on `main` the `security review` job reads it. Evidence: the step's Python run against a clean clone of this branch head, then the audit command, with the "Loaded filter from" line and the exit status.
- AC-4 The gate's partition shall classify `osv-scanner.toml`, so that every tracked path stays classified. Evidence: `cargo test -p codeflow-cli --test test_gate_cli every_tracked_path_is_classified_by_the_conservative_partition`, which failed on the first push of this branch (CI run 38246773755, shard 1 and Windows shard 5) and passes with the entry.
