# TSK-062: evaluation cases for the visual doctrine

## Description

Grade the visual explanation doctrine in the evaluation kit so that an agent
that re-houses prose in boxes, picks a family that does not match the
relationship, carries a state by hue alone, answers a narrow width by
reflowing the wide marks, prints text over text, draws a mark under the
floor inside a state group, or declares a value its source does not hold is
caught by a blind case rather than by the operator. Add one hard requirement
per rule group (family choice, the no-box rule, the rendered two-channel
rule, narrow recomposition, overprint, the inner mark floor, fidelity, the
altitude contract, which includes the how-to rule) with source markers in the
grammar resource, and blind cases whose prompts never name the
rule under test, each with a faulty control that must fail, graded from a
rendered fixture (the figure declaration and its rendered SVG) rather than
from what the subject says.

Grade the explanation method (TSK-072) the same way, from a prompt and a
fixture, with requirements whose markers resolve verbatim in
`explanation-method.md`. The prompt never names the rule; the faulty control
is a plausible draft a careful reader would accept that fails the graded
signal:

| Case | Prompt (fixture) | Faulty control | Graded signal |
|---|---|---|---|
| Portal page from a source | write the guide page for a policy source with adoption, structure and a command table | the source reprinted under the three altitudes with one `cf-stage` of labelled boxes | reader and question per altitude; Concept says who it is for and what it is not; a family per panel that matches the relationship; lead above and caption below; twin present |
| Family by subject in chat | a new contributor asks which enforcement planes guard the git rules in this repository and which of them are active here (fixture: this repository's contract, where remote protection is unavailable) | a flow figure of a commit passing checks; or a layering figure that marks remote protection as active | layering family comparing the planes, the remote plane shown as not active here, a legend line, one caption line, short prose; positive control: a truthful layering answer that marks the remote plane inactive passes |
| Screenshot or figure, two sides | document the Display panel; document how the theme is applied before first paint | ASCII art of the panel; a screenshot of the page | first: a screenshot with skin, mode and scale named, alt text, no drawn arrows; second: a sequence figure and no screenshot |
| README figure medium | add an architecture figure to `README.md` | an SVG file under `docs/` linked from the README, or a Mermaid fence | a fenced text figure in a named family with legend and caption; a PNG only for a surface |
| Smallest carrier | explain three landing rules to the operator | a figure drawn for facts with no relationship | graded on completeness and proportionate form: every rule stated, no figure, bullets or a small table; no explanation of the formatting choice is required; positive control: a complete three-bullet answer with no lead passes |
| Method on a present | open a review of two migration options | narrative first, a comparison of text cards, the ask last | the five-second picture named, carrier first, one ask; the existing `complex-review-uses-declarative-presentation` case registered in the pack |

The copy guide's cases are TSK-073's, because they grade a file that exists
only after EPC-017 arrives; TSK-073 also registers the EPC-017 cases
(`operator-reply-is-plain-prose-and-bullets`,
`flow-reply-carries-fenced-figure`, `identifier-only-title-gets-words`) once
TSK-084 has brought them in. Registration and marker pins are maintenance
checks; they prove nothing about model behaviour. Non-goal: native trials;
those follow TSK-055's phase B route.
