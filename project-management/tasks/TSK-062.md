# TSK-062: evaluation cases for the visual doctrine

## Description

Grade the visual explanation doctrine in the evaluation kit so that an agent
that re-houses prose in boxes, picks a family that does not match the
relationship, carries a state by hue alone, answers a narrow width by
reflowing the wide marks, prints text over text, draws a mark under the
floor inside a state group, or declares a value its source does not hold is
caught by a blind case rather than by the operator. Add one hard requirement
per rule group (family choice, the no-box rule, the rendered two-channel
rule, narrow recomposition, overprint, the inner mark floor, fidelity, the
altitude contract, which includes the how-to rule) with source markers in the
grammar resource, and blind cases whose prompts never name the
rule under test, each with a faulty control that must fail, graded from a
rendered fixture (the figure declaration and its rendered SVG) rather than
from what the subject says.

Grade the explanation method (TSK-072) and the copy guide (TSK-073) the same
way, from a prompt and a fixture, with requirements whose markers resolve
verbatim in `explanation-method.md` or `copy-guide.md`. The prompt never
names the rule; the faulty control is a plausible draft a careful reader
would accept that fails the graded signal:

| Case | Prompt (fixture) | Faulty control | Graded signal |
|---|---|---|---|
| Portal page from a source | write the guide page for a policy source with adoption, structure and a command table | the source reprinted under the three altitudes with one `cf-stage` of labelled boxes | reader and question per altitude; Concept says who it is for and what it is not; a family per panel that matches the relationship; lead above and caption below; twin present |
| Family by subject in chat | a new contributor asks how the git rules are enforced | a flow figure of a commit passing checks | layering family, the remote plane marked as the boundary, a legend line, one caption line, short prose |
| Screenshot or figure, two sides | document the Display panel; document how the theme is applied before first paint | ASCII art of the panel; a screenshot of the page | first: a screenshot with skin, mode and scale named, alt text, no drawn arrows; second: a sequence figure and no screenshot |
| README figure medium | add an architecture figure to `README.md` | an SVG file under `docs/` linked from the README, or a Mermaid fence | a fenced text figure in a named family with legend and caption; a PNG only for a surface |
| Lead and caption | write the text around a fixture figure | the lead restates the caption; the caption repeats the title; a sentence explains the legend | the lead says what the reader looks at; the caption is the takeaway; legend keys are noun phrases |
| Microcopy | name the controls, the empty state and the no-results message of a search dialog | "Nothing here yet!", Title Case labels, "Oops, no matches" | verb-first labels, sentence case, an empty state that says what to type, no exclamation mark, digits |
| Summary before a table | write a task closeout from fixture evidence with test output and a coverage number | bullets only, or one paragraph of nine sentences | two to four sentences, then a table for the evidence, what was not tested named |
| Skill prose | write the first section of a new skill | a draft with a slogan, a contrast turn and an em dash | imperative plain sentences, no policy character, no slogan |
| ADR shape | record a decision to pin a sheet byte for byte | context as four paragraphs of history; the decision spread over three | context in two to five sentences naming the constraint; one decision paragraph; consequences with a cost |
| Smallest carrier | explain three landing rules to the operator | a figure drawn for facts with no relationship | no figure; bullets or a small table; the reply says why |
| Method on a present | open a review of two migration options | narrative first, a comparison of text cards, the ask last | the five-second picture named, carrier first, one ask; the existing `complex-review-uses-declarative-presentation` case registered in the pack |

Cases already graded elsewhere are registered, not copied:
`operator-reply-is-plain-prose-and-bullets`, `flow-reply-carries-fenced-figure`
and `identifier-only-title-gets-words` arrive with EPC-017 through step M.
Non-goal: native trials; those follow TSK-055's phase B route.

## Acceptance Criteria

- [ ] Eight hard requirements exist with markers that resolve verbatim in
      `figure-grammar.md`; evidence: the requirement fidelity test.
- [ ] At least twelve blind cases exist across the eight requirements, each
      with a faulty control that fails and at least two with a positive
      control that passes, graded on the fixture's declaration and rendered
      output; evidence: `validate-suite` and the grading inventory by set
      equality.
- [ ] A pack `visual-doctrine` registers them and states that registration
      proves nothing about live behaviour; evidence: `packs.json`.
- [ ] The method and copy requirements exist with markers that resolve
      verbatim in `explanation-method.md` or `copy-guide.md`, and the eleven
      cases in the table exist, each with a faulty control that fails and
      the two-sided screenshot case graded on both sides; they register in
      two packs, `explanation-method` and `copy-guide`, alongside the
      existing cases named above; evidence: the requirement fidelity test,
      `validate-suite` and the grading inventory by set equality.
- [ ] The kit tests and the workspace tests are green; evidence: the gate
      lines.
- [ ] Grok adversarial review of the cases for leakage of the rule under
      test into the prompt; evidence: the review record.
