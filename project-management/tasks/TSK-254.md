# TSK-254: CodeFlow's own CI never hangs and a PR push uses fewer runner slots

## Description

CodeFlow's own CI had no timeout on any job, so a stalled step held one of
the account's 20 runner slots for up to six hours. Five Linux gate parts hung
for 48 minutes to over three hours on 2026-10-07, all inside the Playwright
step's `apt-get` download from the Ubuntu mirror (run 435 fetched 126 MB in
33 minutes), and all five parts ran that step although only the `present`
part launches a browser. The policy workflow also ran twice per push (a
`synchronize` run and an `edited` run seconds apart) with no cancellation.
This task bounds every job; confines the Playwright browsers and their
system libraries to the `present` part, with cached apt archives, a bounded
attempt and one retry; cancels superseded policy runs per pull request while
the judging run reads the pull request's body at run time; and lowers the
read benchmark's own timeout from 2,400 to 900 seconds. What CI proves is
unchanged: the same targets, checks and verdicts run. The adopter templates
take the parts adopters run the same way (the policy workflow, and the
secret scan and security review job timeouts); the adopter `gates` job runs
the adopter's own suite, whose length this evidence cannot size, so it gets
no cap. Non-goals: merging Linux parts, path-based job selection, Windows on
main only and a larger runner plan (design options 3, 5, 6 and 12). Sized
from 1,825 job records over 2026-10-04 to 2026-10-07 gathered for the CI
speed design and its adversarial review.

## Deliverables

- job and step timeouts, the confined Playwright install and its apt cache: `.github/workflows/codeflow-ci.yml`
- the policy concurrency group and the run-time body read: `.github/workflows/codeflow-policy.yml`, `assets/base/ci/codeflow-policy.yml`
- adopter job timeouts for the secret scan and security review: `assets/base/ci/codeflow-ci.yml`, `assets/base/ci/README.md`
- the read benchmark timeout: `.codeflow/test-config.json`
- the structural checks: `scripts/gate-parity.py`, `scripts/test_gate_parity.py`, `scripts/test_gate_contracts.py`, `crates/codeflow-cli/tests/ci_pin.rs`
- the managed baseline resync: `.codeflow/.baseline/.github/workflows/`, `.codeflow/manifest.json`
- the release note: `CHANGELOG.md`

## Acceptance Criteria

- AC-1 When any job in `codeflow-ci.yml` or `codeflow-policy.yml` runs, it shall carry a `timeout-minutes` sized from the observed p95 and maximum with headroom (gate parts 45, Windows test partitions 45, Windows checks 25, Windows journeys 15, verdicts 5, secret scan and security review 30, allowlist canary 10, commit standards 20), so a hung job frees its runner inside 45 minutes; gate-parity shall refuse a `codeflow-ci.yml` job without one. Evidence: `scripts/gate-parity.py` on the tree, its new unit tests, `scripts/test_gate_contracts.py`.
- AC-2 When the Linux gate parts run, only the `present` part shall install the Playwright browsers and their system libraries; the install shall restore cached apt archives, bound each attempt at 10 minutes and retry once, and the `present` targets shall still pass. Evidence: the gate-parity check on the step, and a hosted run on this pull request where `codeflow gates (present)` passes from restored apt archives and the other parts show no Playwright step.
- AC-3 (journey) When the system-library install stalls, the `present` part shall fail inside the step timeout after one retry, and the job shall end well under an hour. Evidence: a temporary commit that makes the install sleep, the hosted run id with its step timings, then its revert.
- AC-4 When a pull request event starts a policy run while an earlier run for the same pull request is queued or running, the earlier run shall be cancelled; push, schedule and dispatch runs shall each keep a group of their own and never be cancelled; and the judging run shall read the pull request's body from the API at run time, so the newest body is judged in whatever order the events arrive. Evidence: the exact concurrency expression and body step pinned in `scripts/test_gate_contracts.py` and `crates/codeflow-cli/tests/ci_pin.rs`, and the body step's script run against this pull request.
- AC-5 When the full gate runs the read benchmark, its timeout shall be 900 seconds (the benchmark part's test step peaked at 9.1 minutes in 90 successful runs). Evidence: `.codeflow/test-config.json` and the passing benchmark part on this pull request.
- AC-6 When an adopter runs `codeflow update`, the policy template shall carry the same concurrency group and body read, and the CI template the same secret scan and security review timeouts; `codeflow update` shall stay a no-op on this repository. Evidence: `ci_pin`, `repository_update_noop` and `manifest_consistency`.
- AC-7 (journey) When the final head of this pull request is pushed, every required check (`codeflow gates`, `windows`, `secret scan`, `security review`, `commit standards`, `release impact`) shall pass. Evidence: the hosted run ids.
