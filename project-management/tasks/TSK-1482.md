# TSK-1482: Each regular host-state tool runs through a named route or reports why it cannot

## Description

This task carries TSK-1059's outcome into `main`, widened by the operator's decision of 2026-11-12 (RELEASE-PLAN.md): the shipped presets will rely on narrow routes, and the regular host-state tools must keep working. TSK-1059 is cancelled on the EPC-022 line with its scope naming this task. Its six criteria come over from the line's copy, amended where the design changed them. Part C decisions (i) to (v) of the TSK-397 design note still apply, including (iv): no route relies on a command exclusion.

The tools are the regular ones a session uses: `gh`, `git` over the network (fetch, push and the pre-push hook's lookup), the seat CLIs (`herdr` and `hc`), and the Codex app-server. Each gets one of three routes:

- inside the sandbox, with a least-privilege credential the harness masks where it supports masking;
- through a broker with a fixed grammar (TSK-1484 for hc);
- as a step the operator runs outside the session.

A tool with no sound route is reported as unavailable, with the reason. `herdr` and `hc` have no route in this task: their route is TSK-1484's broker, so this task reports them unavailable until TSK-1484 lands, and its builder builds no route for them.

The first step is A0: one recorded probe in the sandbox, on macOS and on Linux, for each route not yet proven. That covers `gh` with a masked token, `git` fetch and push with a masked token, the Codex app-server's state folders, the `codeflow recall` lock, and a fresh harness worktree followed by a `git switch`. The task is graded again after A0.

Each route is a default an adopter can turn off or extend in their own settings or policy. The docs name where. The operator accepted floor F1 on 2026-11-13, so it is fixed: CodeFlow never ships, writes or proposes a command exclusion, a Codex `allow` rule, a socket allowance or a Mach allowance for a program that runs code the agent chooses or that drives terminals; every helper CodeFlow ships to run outside the sandbox has a fixed grammar and a cross-family security review; and doctor names any such entry an adopter adds as running with full access.

The operator's GitHub choices of 2026-11-13 set the credential for the `gh` and `git` routes:

- Until TSK-1348's agent App installation token lands, the masked credential is a fine-grained token limited to the named repositories and to contents and pull requests write.
- If the masked-credential probe fails for `gh` or `git`, the fallback is a one-hour App installation token readable inside the sandbox, while such a token exists. Otherwise `gh` and `git` are reported as operator-run.
- `gh` is never excluded from the sandbox.

Non-goals: the shipped preset change itself (TSK-1483); the hc broker (TSK-1484); host qualification (EPC-037); worktree creation and writes to harness-protected paths, which stay operator-run.

## Outcome

after this merges, an agent session can run each regular host-state operation it needs through a named route, or is told that the operation is unavailable and why.
