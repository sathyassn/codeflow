# TSK-1030: The shipped instructions say what belongs in a repository

## Description

Issue #279 and its comments of 2026-10-23 and 2026-10-27. Agents under
CodeFlow treat the repository as the place to keep everything they
produce, and nothing in the shipped instructions or the reviewer's
verdict asks whether a new file belongs there. One shipped row invites
the opposite: `cf-method` `references/project-organization.md:670` (the
issue cites `:560` at 3.1.1; the row moved) names
`docs/verification/<task>/` as the home of "retained comparison
evidence" that lands on protected branches. One adopter's `main` grew to
492 files (26 MB) in 61 per-task folders under `docs/verification/`, and
the adopter copied the row into its own rules.

The operator placed the instruction fix in 3.2.0 on 2026-10-27; the
gate stays in TSK-428 (EPC-024, 4.2.0), because it needs TSK-424's
exemption register and baseline. This task takes TSK-428's former AC-1
(the instruction) and AC-2 (the review question), which are instruction
and review-question changes small enough to ship alone.

Outcome: **the shipped instructions state what belongs in a repository
and what stays out, required evidence lives in the PR body or the task
record, the `project-organization.md` row that names
`docs/verification/<task>/` is replaced, and `cf-reviewer` asks of every
added file whether it is needed long term and in its smallest form.**

Rules:

- What belongs: product or authority content, code with its tests and
  config, and evidence a live record cites that the PR body cannot
  carry, in summary form. What stays out: run output and per-run logs,
  review records and verdict files, superseded iterations, build and
  cache output, copies kept for reference, scratch and session working
  files, duplicate copies, and per-task verification folders. Git
  history keeps removed evidence, so a clean-up does not lose it.
- Vendoring gets one rule (the 2026-10-27 22:46Z comment): a copy a
  runtime needs is admitted through the project's dependency rule; a copy
  kept for reference is not.
- The replaced row points to `cf-ship/references/pr-evidence.md` for
  required evidence and keeps prototypes out of protected branches as the
  table already says.
- Consumer-facing examples that cite CodeFlow's own `docs/verification/`
  paths are dropped or reworded, so the folder stops looking expected.
- The block and warn tiers, citation safety for removed evidence and
  exceptions are TSK-428's (gate), not this task's.

Non-goals: the gate and its tiers (TSK-428); CodeFlow's own managed-copy
footprint (TSK-429); deleting what adopters or this repository already
hold (AC-1 records this repository's state and routes it).

## Acceptance Criteria

- AC-1 Before any change, the builder shall research what belongs in a repository broadly: current practice across the languages, frameworks and project types CodeFlow serves (build and cache folders per stack, lockfiles, generated code, vendoring, fixtures and snapshots, large binaries and Git LFS, research and decision records, evidence in PR bodies or CI artifacts), the CodeFlow guidance and checks in the survey above, and adjacent concerns (`.gitignore` templates, secret files, CodeFlow's own `docs/verification/` and the citations into it); and shall record the findings with sources and the chosen scope in the research note before any instruction changes; evidence: the note, committed before the first instruction change in the PR.
- AC-2 The instruction texts shall state what belongs in the repository and what stays out, that required evidence goes in the PR body or the task record, that a file under an evidence path lands only when a live record cites it and the PR body cannot carry it, in summary form, that git history keeps removed evidence, and one vendoring rule; evidence: the text diff and a `cf-editorial-review` pass. (serves EPC-022 AC-138)
- AC-3 The `project-organization.md` row that names `docs/verification/<task>/` shall be replaced by a rule that names no per-task folder and points to `pr-evidence.md`, and no shipped example or default shall present `docs/verification/` as a standard folder; evidence: the diff and a search of `assets/` showing no remaining such example. (serves EPC-022 AC-138)
- AC-4 `cf-reviewer` shall ask, for every added file, whether it is needed long term and in its smallest form, and return a finding for an unneeded or oversized addition; evidence: the verdict format and a qualification case. (serves EPC-022 AC-138)
- AC-5 Native instruction qualification under `/cf-evaluate-model` shall include a case where a builder puts run output in the PR body instead of committing it; evidence: the qualification record.
- AC-6 (journey) A fresh `codeflow init --standard` project and a project updated from 3.1.1 shall carry the new text, every pointer shall resolve, and `codeflow update` shall replace the old row; evidence: the journey output.
