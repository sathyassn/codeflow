# TSK-431: Per-project account profiles and limit reads for seats

## Description

Issue #234, items 1 and 2. Long multi-seat runs stop when one family's
subscription hits its 5-hour or weekly limit; the operator notices,
signs in to another account by hand and restarts the seats. Nothing in
CodeFlow reads the limit state or knows which account a project uses.
The issue rules out automatic rotation between one person's
subscriptions, which the vendors' terms forbid, and CodeFlow never
reads, copies or stores tokens.

Outcome: **a project can keep an untracked account-profile file that
maps each family to a config home (and optionally an API-key fallback
with a spend cap), CodeFlow launches each CLI with only its own
config-home variable set (`CLAUDE_CONFIG_DIR`, `CODEX_HOME`,
`GROK_HOME`), and CodeFlow reads each family's limit state where the
CLI exposes it (Claude Code's statusline `rate_limits`, Codex's
app-server rate-limit read and events, Grok Build's limit-hit error)
into one structure the routing of TSK-432 consumes.**

Rules: the profile file (provisional `.codeflow/local/accounts.toml`,
untracked through the managed ignore, or under the user's home) holds
paths and caps, never tokens; the launch table in
`cf-model-orchestrator/resources/routing/transport.md` and the Herdr
launch in `cf-herdr` pass the config home; the limit reader is
best-effort and says when a family exposes nothing. The Codex
app-server methods come from source and mirrors, not official docs
(the issue's not-verified list), so the reader is qualified on the
supported release.

Non-goals: the threshold policy, the fallback and resume (TSK-432);
any automatic switch between subscriptions.

## Deliverables

- the profile file and schema: `crates/codeflow-core/src/` (provisional `seats/accounts.rs`), the managed ignore entry in `assets/base/` and `docs/policy-reference.md`
- the launch change: `cf-model-orchestrator/resources/routing/transport.md` and `cf-herdr` in `assets/base/`, `.claude/skills` and `.agents/skills`, and the delegate lifecycle in `crates/codeflow-core/src/delegate/`
- the limit reader: `crates/codeflow-core/src/` (provisional `seats/limits.rs`) and `codeflow models` output
- tests: unit tests with fixture statusline and app-server payloads and `crates/codeflow-cli/tests/models_cli.rs`
- release note: `changelog.d/TSK-431.md`

## Acceptance Criteria

- AC-1 A profile file mapping a family to a config home shall make every managed launch of that family set only that family's config-home variable, and a file that names a token or credential shall be refused; evidence: launch tests reading the environment and a refusal test. (serves EPC-024 AC-8)
- AC-2 `codeflow models` shall show each family's limit state (used percentage and reset time for the 5-hour and weekly windows where exposed, or `not exposed`), read from the fixture payloads; evidence: CLI tests per family. (serves EPC-024 AC-8)
- AC-3 The Codex app-server read shall be qualified on the supported release in a native seat, and the record shall say what was read and from which method; evidence: the qualification record.
- AC-4 (journey) With the installed build and a profile pointing one family at a second config home, a Herdr seat of that family shall start under that home and `codeflow models` shall show its limit state; evidence: the journey output.
