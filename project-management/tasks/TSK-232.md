# TSK-232: The docs portal state pin matches the shipped starter

## Description

PR 53 (TSK-222) changed `docs-portal/tests/adapter.test.mjs` and its starter
copy under `assets/docs-portal/starter/tests/` without re-pinning
`.codeflow/docs-portal.json`, so `codeflow update` on `main` rewrites the
`pristine_sha256` of `tests/adapter.test.mjs` and leaves a dirty tree. This
task re-pins that one entry and adds a check that fails when any managed starter
file changes without its pin. The existing portal checks compare the starter with
the dogfood copy but never read the state file, which is why nothing caught
it. The state file is generated by `codeflow update` and is not an
enforcement path. Non-goal: changing how update computes or applies pins.

## Deliverables

- the re-pinned entry: `.codeflow/docs-portal.json`
- the state check and its perturbation test: `crates/codeflow-core/tests/manifest_consistency.rs`
- this record: `project-management/tasks/TSK-232.md`

## Acceptance Criteria

- AC-1 `.codeflow/docs-portal.json` matches what `codeflow update` writes from `assets/docs-portal/starter`: the starter version in both version fields, each manifest file's ownership, and for a managed file the sha256 of its starter bytes (a user-owned hash is frozen provenance and only has to be a sha256), and `codeflow update` run twice on the repository changes nothing the second time (`portal_state_matches_the_shipped_starter`, and the update output compared byte for byte).
- AC-2 When a managed starter file changes without its pin, or a pin is missing, a managed pin names a file the starter no longer ships, an ownership or version field is stale, the check fails and names the file or field; a user-owned starter default that changes does not fail it, as update keeps that hash (`portal_pin_drift_names_each_stale_missing_and_extra_pin`; `portal_state_matches_the_shipped_starter` fails on the unfixed `main` bytes and passes after the re-pin).
- AC-3 When `codeflow update` runs on a fresh clone of the branch head, which is the tree `main` becomes on merge, it changes no tracked file (journey).
