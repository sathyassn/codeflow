# TSK-1445: CodeFlow's own workflows follow the epic model

## Description

CodeFlow's own CI places suites by ADR-0097, which runs the full Linux suites on a line push. Under the operator's ruling of 2026-11-11 (ADR-0102), no line push starts a hosted run, a pull request into a line runs only the short checks (commit standards, the secret scan and the security review), and the Linux gates and every Windows job run only on the pull request into `main`. This task brings this repository's workflows, scripts and maintainer docs to that placement, with a push to `main` reusing its pull request's run only under ADR-0102's strict equality (AC-6). It builds on PR 620's placement (TSK-1321) and starts from whatever the transition's workflow change left on `main`. If `main`'s heavy checks are still relaxed when it lands (TSK-1452's temporary items), it keeps TSK-1451's temporary gate conditions for the pull request into `main`, and TSK-1452's restore brings in the placement above. Non-goal: the daily scheduled run on each active line, which is not a push; it follows the operator's ruling on it.

This is in the named class of changes that prove themselves only on the default branch: it lands alone, with a revert branch prepared and reviewed first, and TSK-1446 is its proof task, landing right after.

Landing on its target (`main`, alone):

- Reachable: the new placement for CodeFlow's own events.
- Inert: nothing.
- Other lines: not nothing: each CodeFlow line must merge `main` to take the workflow copies, as PR 620's design requires.

## Outcome

After this merges, a CodeFlow maintainer sees no hosted run on a line push, only the short checks on a pull request into a line, the full set with Windows on a pull request into `main`, and a push to `main` that reuses that run when nothing it proved changed.

## Deliverables

- the workflows and scripts: `.github/workflows/` and `scripts/`, with the placement parity check `scripts/test_ci_placement.py`
- the maintainer page: `docs/releasing.md`, "Where CI suites run"

- the hosted-run sentences of CodeFlow's own landing section: `AGENTS.md`

## Acceptance Criteria

- AC-1 `.github/workflows/` and `scripts/` shall change to the placement of ADR-0102: no hosted job on a push to any line; only commit standards, the secret scan and the security review on a pull request into a line; the Linux gates and every Windows job on a pull request into `main`; and a push to `main` that reuses its pull request's run only under ADR-0102's strict equality, else runs in full, with the secret scan on every push; evidence: the diff and `scripts/test_ci_placement.py`.
- AC-6 CodeFlow's own reuse job shall reuse a pull request's run on the push to `main` only when the pushed tree equals the run's tree, the workflow files and trust inputs equal those the run used, and each reused job ran and passed; the deciding script shall be read from the trusted base and pinned by digest. Each condition shall have a fixture that breaks it alone and gets a full run; evidence: the fixtures and their test output. These are the same conditions TSK-1444 ships for adopters; this task does not wait for it, and where TSK-1444 lands first this job may call its check instead.
- AC-2 ADR-0097 shall carry a dated note naming the rows ADR-0102 replaces, and `docs/releasing.md` and the hosted-run sentences of CodeFlow's own `AGENTS.md` landing section shall follow; evidence: the diff and the parity check.
- AC-3 A revert branch shall be prepared and reviewed before landing; evidence: its SHA in the pull request body.
- AC-4 The operator shall apply the workflow patch and the ruleset change, and no required check on `main` or a line shall be one that can pass by being skipped; evidence: the operator's commit and the script output.
- AC-5 The change shall have a cross-lineage review with the `cf-security-reviewer` checklist, since it changes which events run the trusted checks; evidence: the review row and its findings. (serves EPC-057 AC-3)
