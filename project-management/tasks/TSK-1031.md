# TSK-1031: The shipped instructions hold project tooling to the tests product code gets

## Description

The operator's quality asks of 2026-10-27, tests and coverage (D2).
Issue #299 asks that every test-running target meet the coverage floor;
TSK-1006 (EPC-024) builds that floor as a default, and TSK-1014 (this
epic) fixes the ignored `defaults.coverage`. Neither says that a
project's own tooling (scripts, build helpers, code generators, release
and CI helpers, hook scripts) is code held to the same tests and floor.
The shipped coverage rule speaks of "aggregate production-code coverage"
and lets generated, vendor, fixture and test code be excluded, so an
agent can read tooling as outside the rule, and adopters' tooling went
untested and unchecked (issue #275's evidence: 59 JSON loaders and 21
git wrappers in one repository's tooling).

This task is the instruction half, small on its own; the default floor
for tooling targets needs TSK-424's register and stays in TSK-1006.

Outcome: **the shipped instructions say that project tooling is code
that ships with tests, runs in a test target and counts toward the
coverage floor; `cf-stack` wires a test target for the project's tooling
when it has any; and `cf-reviewer` treats an untested tooling change as
it treats untested product code.**

Non-goals: the floor as an enforced default and its exemptions
(TSK-1006); the defaults fix (TSK-1014); this repository's own untested
scripts (AC-1 records them and routes them).

## Acceptance Criteria

- AC-1 Before any change, the builder shall research how tooling is tested broadly: current practice across the languages and project types CodeFlow serves (Python, TypeScript and JavaScript, Go, Rust, shell, OpenTofu and Rego repositories; monorepos with `tools/` or `scripts/` packages; code generators and their golden-file tests; build scripts such as `build.rs`, Makefiles and task runners; CI helper scripts), how coverage tools include or exclude such code, the CodeFlow guidance and templates in the survey above, and adjacent concerns (shell scripts that coverage tools cannot measure, generated output, this repository's own scripts); and shall record the findings with sources and the chosen scope before any instruction changes; evidence: the note or record section, committed before the first instruction change in the PR.
- AC-2 The coverage rule and the discipline rule shall state that project tooling is code: it ships with tests, runs in a test target, and counts toward the coverage floor where its language can be measured, with only generated, vendored, fixture and test code excludable under the existing owner, reason and removal condition; evidence: the text diff and a `cf-editorial-review` pass. (serves EPC-022 AC-139)
- AC-3 `cf-stack` shall wire a test-executing target for the project's tooling when the project has any, and say how to cover a language its coverage tool cannot measure; evidence: the skill diff and a scaffold run on a fixture with a `scripts/` folder. (serves EPC-022 AC-139)
- AC-4 `cf-reviewer` shall return a finding for a tooling change with no test, as for product code; evidence: the verdict text and a qualification case.
- AC-5 (journey) A fresh `codeflow init --standard` project and a project updated from 3.1.1 shall carry the new text with every pointer resolving; evidence: the journey output.
