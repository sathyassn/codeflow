# TSK-1031: The shipped instructions hold project tooling to tests and use the standard framework in proportion

## Description

The operator's quality asks of 2026-10-27, tests and coverage (D2).
Issue #299 asks that every test-running target meet the coverage floor;
TSK-1006 (EPC-024) builds that floor as a default, and TSK-1014 (this
epic) fixes the ignored `defaults.coverage`. Neither says that a
project's own tooling (scripts, build helpers, code generators, release
and CI helpers, hook scripts) is code held to the same tests and floor.
The shipped coverage rule speaks of "aggregate production-code coverage"
and lets generated, vendor, fixture and test code be excluded, so an
agent can read tooling as outside the rule, and adopters' tooling went
untested and unchecked (issue #275's evidence: 59 JSON loaders and 21
git wrappers in one repository's tooling).

This task is the instruction half, small on its own; the default floor
for tooling targets needs TSK-424's register and stays in TSK-1006.

Outcome: **the shipped instructions say that project tooling is code
that ships with tests, runs in a test target and counts toward the
coverage floor; `cf-stack` wires a test target for the project's tooling
when it has any; and `cf-reviewer` treats an untested tooling change as
it treats untested product code.**

Non-goals: the floor as an enforced default and its exemptions
(TSK-1006); the defaults fix (TSK-1014); this repository's own untested
scripts (AC-1 records them and routes them).
