# TSK-340: Status changes and repeated closeout have one valid acceptance sequence

## Description

Issues: #198 and #217. Both arise from a mismatch between the record lifecycle the CLI produces and the completion content/span that binding accepts. They require different repairs inside that shared contract.

- #198: `acceptance.rs:208` excludes only frontmatter status and Closeout; `:219` retains Blocker. `later_change` compares that projection at `:1388`. The status writer adds/removes Blocker at `workgraph/status_verb.rs:533` and `:544`.
- #217: `workgraph/lifecycle.rs:1084` requires the last superseded block to match the particular before-record's active block. Different CLI/range bases therefore impose different last-block requirements. `acceptance.rs:502` explicitly disallows normal stacking for a reopening range and forces direct transport at `:544`. `later_change` refuses every other changed path at `:1380`, including a later epic record.
- TSK-278's ACs concern a redaction-only change preserving results (`TSK-278.md:42`), not new acceptance after a reopen. Proposal F may remove the unnecessary rebinding trigger for imported changes, but the normal repeated-reopen and blocked-status sequence still needs proof.

Outcome: **A task can become blocked, complete, reopen and complete again, followed by epic Closeout, using ordinary commands that local and range validation both accept.**

Source inspection is from the accepted triage at `c5c6f6f671d2bf67a77113c656b3be446fb0bea1`; runtime reproductions remain implementation evidence.

## Acceptance Criteria

- AC-1 Generated Blocker additions/removals do not alter reviewed product scope. Criteria, deliverables, review evidence and unrelated record text remain protected.
- AC-2 Multiple superseded acceptance blocks retain their provenance in a single chronological representation accepted by status transitions, task PR CI and the final epic range. Reordering blocks by hand is not required.
- AC-3 Define and verify the completion span for a reopened task so a legitimate subsequent epic Closeout can follow it. A later unrelated product edit or acceptance rewrite still invalidates the appropriate binding.
- AC-4 (journey) Reproduce #198 and every #217 ordering symptom from the issue with ordinary commands, prove one documented successful sequence, and test tampered history/content as negative controls.
- AC-5 When a task completed, reopened with `codeflow task status <id> todo --reason`, and re-completed with `--acceptance` names a criterion waiver that is a records-only commit changing only that criterion's line strictly before `reviewed:` in the reopened range, `task status complete` and `codeflow ci` shall accept it as the never-reopened path does, or shall refuse naming the requirement ("a reopened task's waiver must name a planning commit on the target that amends this criterion"), whichever the completion span of AC-3 decides, with the choice documented; evidence: the issue #278 proof as a CLI fixture (the reopened branch, the same branch without the main merge, and the pre-reopen control), failing before the change. (serves EPC-022 AC-37)
- AC-6 A never-reopened task's in-branch waiver shall not be refused as "not on the target" because the branch name does not carry the task id; evidence: a fixture with a task branch named without the id, failing before the change. (serves EPC-022 AC-37)
- AC-7 When a task completed with an accepted criterion waiver, was reopened because a records-only commit after the reviewed commit changed another record (#354: a follow-up record removed), and is completed again naming the same waiver commit, which is records-only, changes only that task's record and is an ancestor of the reviewed commit, `task status complete` and `codeflow ci` shall decide it by AC-5's rule, and a refusal shall say what "on the target" requires and name the sanctioned route; evidence: a CLI fixture of #354's sequence, failing before the change. Added 2026-10-27 for issue #354: the same reopened-waiver sequence AC-5 owns, in a shape AC-5's fixture does not cover. (serves EPC-022 AC-37)
