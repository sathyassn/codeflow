# TSK-309: codeflow update never lowers the project's pinned version

## Description

`codeflow update` writes the binary's own version into `scaffold_version`
unconditionally (`crates/codeflow-core/src/scaffold/update.rs:371-373`), so
an update run by a binary older than the project's pin lowers the pin and
rewrites managed files with the older binary's assets, while the
`[scaffold_sha256]` table may still name the newer release.
`codeflow update --pin` already refuses a lower version
(`crates/codeflow-core/src/scaffold/release_pin.rs:418`, "the pin only
rises"), and `version_skew_warning` only warns
(`crates/codeflow-core/src/scaffold/version.rs:33-43`). Found by the adopter
feature design of 2026-10-13 (section 9, approved by the operator), which
homes the fix in this epic; the adopter epic's install-on-clone task relies
on a pin that never falls. This task makes `update` refuse, before it
writes anything, when the binary is older than the project's
`scaffold_version`, naming both versions and the remedy. The fix binds
binaries that carry it; an older released binary still behaves as before,
which the release note states. Non-goal: a `codeflow ci` check on a pull
request that lowers the pin.

## Deliverables

- the refusal: `crates/codeflow-core/src/scaffold/update.rs` (reusing `is_older` from `scaffold/version.rs`)
- tests: `crates/codeflow-core/tests/` beside the existing update tests
- docs: the `codeflow update` entry of `docs/cli.md` and the upgrade section of `docs/adoption.md`
- release note: `changelog.d/TSK-309.md`

## Acceptance Criteria

- AC-1 When the running binary's version is older than the project's
  `scaffold_version`, `codeflow update` shall refuse before writing any
  file, and the message shall name both versions and say to install the
  pinned version; evidence: a test that runs update with an older stamped
  version, failing before the fix and passing after, and shows the tree
  unchanged. (serves EPC-022 AC-19)
- AC-2 When the binary's version equals or is newer than the pin, `update`
  shall behave as today; evidence: the existing update tests unchanged and
  one test per case.
- AC-3 After a refusal, `.codeflow/project.toml`, its `[scaffold_sha256]`
  table and every managed file shall be byte-identical to before;
  evidence: a test that compares the bytes.
- AC-4 When an unparsable `scaffold_version` is found, `update` shall
  refuse with the value it read, never treat it as older; evidence: a test.
- AC-5 (journey) When the installed build of this change runs `codeflow update` in a
  scratch project whose pin is a later version, the command shall refuse
  and `git status` shall show no change; evidence: the journey
  output.
