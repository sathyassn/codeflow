# TSK-1285: A hook binary older than the repository says it is too old

## Description

A hook binary older than the repository it guards reads the repository's newer records and test config as user errors. On 2026-11-03 the installed codeflow 3.1.0 pre-push hook, run on a plain task-branch push to the 4.0.0 line (TSK-1039's branch at 46ac87541, fed on stdin, nothing pushed), refused with `git.test_gate_on_push`:

- "invalid test config ... targets[1].heavy: unknown field"
- `codeflow ci` work.acceptance_binding, work.criteria_frozen, work.valid_graph
- `codeflow validate --docs` failed

Each message tells the user to "fix the findings above", but nothing is wrong with the repository. The binary is too old. The same push passes with a binary built from the line first on PATH. Log: `/private/tmp/claude/prepush-310-repro.log` (copy it into the PR's evidence). The operator hit this on a TSK-1241 push.

A second case, on 2026-11-03 at 11:2x: the push of `plan/regroup-feature-epics` was refused by the installed codeflow 3.1.0 pre-push hook with "push set could not load test-config.json: ... targets[1].heavy: unknown field". The same push went through with the 4.0.0 worktree binary (`.worktrees/tsk-1085/target/debug`) first on PATH, without `CODEFLOW_HOOK_BINARY`. The beta install after the c3b2 landing fixes this host; this task fixes the message for every adopter whose binary lags.

## Outcome

After this merges, a person whose hook or CLI binary is older than the repository's records is told the binary is too old, which version the repository needs and how to upgrade, instead of being asked to fix findings that are not there; the refusal still fails closed.

## Deliverables

- the investigation and the chosen detection signal: this record's `## Findings` section
- the too-old refusal for each reader: the test config, record, policy and ledger readers under `crates/codeflow-core/src/` that the Findings name
- tests: CLI tests in `crates/codeflow-cli/tests/` per reader and the journey fixture
- release note: `changelog.d/TSK-1285.md`

## Acceptance Criteria

- AC-1 Before any change, the builder shall list every reader an older binary runs on a push or commit (test config, task and epic records, policy, model selection, the ledger), how each detects a newer schema today, and which marker the repository already carries (schema or contract version fields, `codeflow update` stamps), and shall record the chosen detection signal in this record before code; evidence: the `## Findings` section.
- AC-2 A binary that reads a test config, record or policy carrying a field or schema version it does not know, where the repository declares a newer CodeFlow, shall refuse with one message that names the binary's version, the version or source the repository needs and the upgrade path, and shall not print the per-field findings as user errors; evidence: CLI tests per reader, failing before the change.
- AC-3 Where the binary cannot tell that the repository is newer (no marker), it shall keep today's refusal and add one line saying the binary may be older than the repository, with the check to run; evidence: a test.
- AC-4 The refusal shall still fail closed: no newer-schema case lets a push or commit through; evidence: the tests in AC-2 and AC-3 assert a non-zero exit and an unmoved destination.
- AC-5 (journey) A scratch adopter at the new version, pushed with a binary built at the previous release, shall show the too-old message and the upgrade path, and the same push with the current binary shall pass; evidence: the journey output.
