# TSK-230: Present show skips processes with unreadable command lines

## Description

The Linux process scan in `codeflow-present` reads `/proc/<pid>/cmdline` of
every process of the current user to find the presentation browser it owns.
It failed the whole scan on the first command line that is not UTF-8 or is
over 64 KiB, so `codeflow present show` failed with "browser identity is not
UTF-8" whenever any unrelated process of the same user looked like that
(issue 60, hosted CI on PR 53, any Linux desktop). The scan now makes one streaming pass over each command line's raw bytes, in
fixed memory and at any length up to 8 MiB (above the kernel's 6 MiB limit for
a new process), and asks only whether its NUL-separated arguments hold
`--user-data-dir=<profile>` and `--cf-present-instance=<id>` byte for byte. A
process that does not is skipped, whatever its other bytes are, so no owned
process is hidden. A process that does keeps the strict checks (64 KiB parse
bound, UTF-8, exact arguments). A command line over 8 MiB cannot be told apart
and is refused, never taken for unrelated. Every bound stays: 64 KiB per
parsed command line, 8 MiB per inspected one, 65,536 processes and 64
candidates.

Scope: the inventory scan only. The single recorded-PID identity check
(`process_identity` on Linux and macOS) stays strict, as its existing tests
pin. The macOS inventory already decodes `ps` output lossily (TSK-142) and
needs no change. Non-goals: Windows, and any change to what counts as owned.
