# TSK-230: Present show skips processes with unreadable command lines

## Description

The Linux process scan in `codeflow-present` reads `/proc/<pid>/cmdline` of
every process of the current user to find the presentation browser it owns.
It failed the whole scan on the first command line that is not UTF-8 or is
over 64 KiB, so `codeflow present show` failed with "browser identity is not
UTF-8" whenever any unrelated process of the same user looked like that
(issue 60, hosted CI on PR 53, any Linux desktop). The scan now reads each
command line within the same 64 KiB bound and skips a process whose raw bytes
do not hold both identity arguments (`--user-data-dir=<profile>` and
`--cf-present-instance=<id>`); an owned argument is a byte-exact substring of
those bytes, so no owned process is hidden. A process that holds both keeps
the strict checks (bound, UTF-8, exact arguments). Every bound stays: 64 KiB
per command line, 65,536 processes, 64 candidates.

Scope: the inventory scan only. The single recorded-PID identity check
(`process_identity` on Linux and macOS) stays strict, as its existing tests
pin. The macOS inventory already decodes `ps` output lossily (TSK-142) and
needs no change. Non-goals: Windows, and any change to what counts as owned.
