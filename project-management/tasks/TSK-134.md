# TSK-134: full gate runs the suite once, one gate at a time

## Description

A full gate takes 12 to 32 minutes because `rust-workspace` and `rust-
coverage` both run the whole suite, three of six sampled failures were
timeouts from two gates running at once, and a killed gate leaves no trace.
This task runs the suite once under coverage plus the doctests that coverage
skips, adds a machine-wide lock so a second full gate refuses to start,
refuses a cargo target directory outside the worktree, and absorbs TSK-094's
per-target start line. Source: guardrails strand row 32 and missing checks;
Fable challenge F9 and F10.

## Affected surfaces and interfaces

- `.codeflow/test-config.json`, `scripts/gate-parity.py`, CodeFlow's own
  CI workflow; `crates/codeflow-core/src/testing/runner/mod.rs`,
  `crates/codeflow-cli/src/cmd/test.rs`.

## Acceptance Criteria

- [x] AC-1 The full gate shall run the test suite once, under coverage, plus
      `cargo test --doc`, and gate parity shall still hold between local and
      CI; evidence: the test config diff, a full gate log listing targets,
      and `gate-parity`.
- [x] AC-2 When a full gate is running on the machine, a second `codeflow
      test --mode full` shall refuse with a message naming the holder, and a
      stale lock from a dead process shall be reclaimed; evidence: runner
      tests for contention and stale-lock recovery.
- [x] AC-3 `codeflow test` shall warn about a `CARGO_TARGET_DIR` outside
      the worktree, naming the shared directory and why a per-worktree target
      matters for parallel work, and still run (amended by the primary during
      review: the gate lock already keeps two gates apart and a shared target
      directory is a legitimate adopter setup); evidence: a CLI test.
- [x] AC-4 TSK-094's criteria shall be met (a stderr start line per target
      in sequential and parallel mode, present when the process is killed,
      stdout and exit codes unchanged), and TSK-094 shall close pointing
      here; evidence: the tests named in TSK-094.
- [x] AC-5 (journey) In a freshly scaffolded project at every tier the lock
      and the target check shall apply to `codeflow test`, and the scaffolded
      test config shall not run the suite twice; evidence: `init_e2e` and a
      scaffold test-config test.
