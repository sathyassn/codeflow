# TSK-090: port the delegate task notice continuation to 3.0.0

## Description

When a delegated Claude turn backgrounds a Workflow or a Bash command, the
task finishes after the turn's `Stop` and Claude Code submits a
`<task-notification>` prompt. On the 3.0.0 candidate the delegate hook blocks
that prompt as unarmed, so the backgrounded result never reaches the run
record. The fix exists as `a56551dad` (engine, `delegate/continuation.rs`,
live Claude Code 2.1.283 fixtures) and `aa74edd83` (the rule in
`claude-turn-completion.md`, mirrors, baseline, manifest and CHANGELOG) on
`fix/delegate-paste-bytes`. That branch is based on
`integration/EPC-014-public-docs`, so this task ports the two commits onto the
3.0.0 base and resolves conflicts with the typed directive already on that
base (`d1236ad5c`, `19b712ae2`).

The port also adds a Stop-time origin check. Claude Code 2.1.283 gives the
`UserPromptSubmit` hook nothing that tells a native notice from the same text
typed into the session: the payload has no origin field, and the transcript
entry that records the origin is written only after the hook returns. So the
`Stop` that closes a continuation reads that entry, and writes the result only
when the transcript records the prompt as a native task notice with the exact
admitted bytes; otherwise the run is poisoned.

Target release: 3.0.0, by operator decision on 2026-09-26 after qualification
run E failed only its pipeline row on this defect. The work is on
`fix/delegate-task-notice-3.0.0` from the candidate head `e49726807`, is
reviewed by Codex and Grok, and is then proven live by the 3.0.0
qualification run. Non-goal: any other commit on `fix/delegate-paste-bytes`;
the harness commits belong to TSK-092.

## Affected surfaces and interfaces

- `crates/codeflow-core/src/delegate.rs`, `delegate/continuation.rs` and the
  `tests/fixtures/delegate/notice/` fixtures (CAP-014); the
  `codeflow hook delegate-turn` help in `crates/codeflow-cli/src/cmd/hook.rs`.
- Run record layout: `turns/<turn>/continuations/<task-id>/accepted.json`
  (with `delivery: task_notification`, the `prompt_id` and the SHA-256 of the
  notice bytes) and `result.json`; `poison.json` when the origin check fails.
- The session transcript Claude Code names in the hook payload, read only for
  a task notice and only within a size bound.
- `cf-delegate/resources/claude-turn-completion.md` in `assets/base`,
  `.claude/skills` and `.codeflow/.baseline`; `.codeflow/manifest.json`;
  `CHANGELOG.md`.
- ADR-0037, the canonical delegate prompt boundary: a notice is admitted
  without an armed turn.

## Acceptance Criteria

- [ ] When a turn's own tool call launched a task and that turn has stopped
      with no other continuation open, the hook shall admit exactly one
      `<task-notification>` envelope for that task id as a continuation and
      record `accepted.json` with `delivery: task_notification`, its
      `prompt_id` and the digest of its bytes; evidence: the ported
      `delegate::` tests driven by the recorded 2.1.283 fixtures.
- [ ] When the `Stop` carrying that `prompt_id` arrives, the hook shall write
      `result.json` only if the session transcript records the prompt with
      origin `task-notification`, `promptSource` `system` and `turnOrigin`
      `task_notification`, with bytes matching the recorded digest and an
      earlier `queue-operation` enqueue of the same bytes that no other
      native notice has already used; a typed copy of a real
      notice, a changed body or a missing entry shall poison the run and
      write no result; evidence: one test per case, driven by recorded 2.1.283
      transcripts.
- [ ] When a notice names an unknown or earlier task, carries text around
      the envelope, holds a second envelope, or arrives with no accepted turn,
      the hook shall block it with exit 2 and preserve run state; when an
      armed prompt arrives while a continuation is open, it shall wait until
      that continuation stops; evidence: one negative test per case.
- [ ] `wait --until terminal` still reports the turn's first `Stop`, and the
      resource says to read a backgrounded result from the continuation
      record and states the residual risk that the model may act on a forged
      notice within its continuation turn before the `Stop` check; evidence:
      the existing wait tests unchanged and the resource paragraphs.
- [ ] ADR-0037 carries a dated note recording the continuation admission, its
      conditions and the Stop-time origin check; evidence: the note.
- [ ] The resource is byte identical across `assets/base`, `.claude/skills`
      and the baseline, manifest hashes match, and the skill stays inside its
      byte ratchet; evidence: `manifest_consistency` and
      `artifact_budget_contract`.
- [ ] The CHANGELOG records the fix in the `[3.0.0]` section with a `patch`
      release impact annotation; evidence: the entry and its marker.
- [ ] Codex and Grok approve the change in a final review round before the
      live run, and the 3.0.0 qualification, on a binary built from the reviewed
      fix head `588bbda67`, shows the backgrounded task's notice admitted as
      a continuation and closed by a continuation `result.json` (run F) and
      passes its pipeline row (run G); evidence: the review records and the
      qualification report, named in the closeout.
