# TSK-090: port the delegate task notice continuation to 3.0.0

## Description

When a delegated Claude turn backgrounds a Workflow or a Bash command, the
task finishes after the turn's `Stop` and Claude Code submits a
`<task-notification>` prompt. On 3.0.0 the delegate hook blocks that prompt
as unarmed, so the backgrounded result never reaches the run record. The fix
exists as `a56551dad` (engine, `delegate/continuation.rs`, live Claude Code
2.1.283 fixtures) and `aa74edd83` (the rule in `claude-turn-completion.md`,
mirrors, baseline, manifest and CHANGELOG) on `fix/delegate-paste-bytes`.
That branch is based on `integration/EPC-014-public-docs`, so this task ports
the two commits onto the 3.0.0 base and resolves conflicts with the typed
directive already on that base (`d1236ad5c`, `19b712ae2`). The live
qualification of the integrated body is TSK-091's.

Target release: 3.0.0. Operator decision 2026-09-26, after qualification run E failed only the pipeline row on this defect: the fix goes into 3.0.0. The port is on `fix/delegate-task-notice-3.0.0` from the candidate head e49726807, reviewed by Codex and Grok before one live qualification run. Non-goal: any other commit on
`fix/delegate-paste-bytes`; the harness commits belong to TSK-092.

## Affected surfaces and interfaces

- `crates/codeflow-core/src/delegate.rs`, `delegate/continuation.rs` and the
  `tests/fixtures/delegate/notice/` fixtures (CAP-014).
- Run record layout: `turns/<turn>/continuations/<task-id>/accepted.json`
  and `result.json`, `delivery: task_notification`.
- `cf-delegate/resources/claude-turn-completion.md` in `assets/base`,
  `.claude/skills` and `.codeflow/.baseline`; `.codeflow/manifest.json`;
  `CHANGELOG.md`.
- ADR-0037, the canonical delegate prompt boundary: a notice is admitted
  without an armed turn.

## Acceptance Criteria

- [ ] When a turn's own tool call launched a task and that turn has stopped
      with no other continuation open, the hook shall admit exactly one
      `<task-notification>` envelope for that task id as a continuation,
      record `accepted.json` with `delivery: task_notification`, and write
      `result.json` on the `Stop` that carries its `prompt_id`; evidence: the
      ported `delegate::` tests driven by the recorded 2.1.283 fixtures.
- [ ] When a notice names an unknown or earlier task, carries text around
      the envelope, holds a second envelope, or arrives with no accepted turn,
      the hook shall block it with exit 2 and preserve run state; when an
      armed prompt arrives while a continuation is open, it shall wait until
      that continuation stops; evidence: one negative test per case.
- [ ] `wait --until terminal` still reports the turn's first `Stop`, and the
      resource says to read a backgrounded result from the continuation
      record; evidence: the existing wait tests unchanged and the resource
      paragraph.
- [ ] ADR-0037 carries a dated note recording the continuation admission and
      its conditions; evidence: the note.
- [ ] The resource is byte identical across `assets/base`, `.claude/skills`
      and the baseline, manifest hashes match, and the skill stays inside its
      byte ratchet; evidence: `manifest_consistency` and
      `artifact_budget_contract`.
- [ ] The CHANGELOG records the fix under the next patch release; evidence:
      the entry and `release.py check-pr` on the pull request.
