# TSK-1395: CodeFlow's git hooks run for every git command, whatever its working directory

## Description

`codeflow init` and `codeflow update` set `core.hooksPath` to a
project-relative folder. Git reads a relative hooks path against the
directory a command runs in, so whether CodeFlow's git hooks run depends on
how a git invocation names its repository and working directory. Found
while checking the TSK-326 coverage (PR 718).

The task writes a hooks path that reaches the managed hooks for every
invocation class, migrates existing projects in `codeflow update` with no
manual step, and makes `codeflow doctor` report a hooks path that is
relative, unresolvable or not the managed hooks, with the fix named.
Non-goals: which git subcommands the session guards judge (TSK-1393), and
the hook checks themselves.

## Outcome

After this merges, an adopter's CodeFlow git hooks run for every git
invocation in the project, however it names the repository, and
`codeflow doctor` names a hooks path that does not reach them.

## Deliverables

- the hooks path writer and its migration: `crates/codeflow-core/src/scaffold/`
- the doctor check: `crates/codeflow-core/src/doctor/mod.rs`
- tests: unit and CLI tests for the invocation classes, the migration and the doctor check
- the decision: an ADR that supersedes ADR-0055 item 5
- docs: `docs/adoption.md` and `docs/troubleshooting.md` where they describe the hooks path
- release note: `changelog.d/TSK-1395.md`

## Acceptance Criteria

- AC-1 Every hook CodeFlow installs (pre-commit, commit-msg, pre-push,
  pre-merge-commit, reference-transaction) shall run for each invocation
  class: from the project or a linked worktree, and invocations that name
  the repository other than by working directory; evidence: a test per
  class that fails on the line's binary where the class did and passes
  after, with the hook by invocation matrix kept outside this repository.
- AC-2 `codeflow init` and `codeflow update` shall write one absolute
  `core.hooksPath` to the managed hooks of the main working tree, which
  linked worktrees share (a bare repository with only linked worktrees
  takes the working tree the command ran in); this replaces the relative
  per-worktree path of ADR-0055 item 5 and doctor's warning against an
  absolute path, and the pull request states the tradeoff; evidence: a CLI
  test on a fresh project, the ADR and the pull request body.
- AC-3 When `core.hooksPath` is relative, does not resolve, or does not
  reach the managed hooks of a working tree of this repository (a moved
  repository or a removed worktree included), `codeflow doctor` shall
  report it and name the fix (`codeflow update`); evidence: doctor unit
  tests for each case and a passing case for the new form.
- AC-4 `codeflow update` shall rewrite a relative or stale CodeFlow
  `core.hooksPath` to the new form with no manual step, wire an unset one
  where the project records its hooks as wired, and leave a path to
  another hook manager's folder as it is; evidence: a CLI test on a project
  made with the line's previous behaviour, with a worktree created before
  the migration, and a moved-repository test.
- AC-5 The session guards' refusal of a `core.hooksPath` write shall hold
  for the new form; evidence: guard tests for a write of the absolute form
  and of a relative form, refused before and after.
- AC-6 (journey) When an adopter project is initialized with the
  worktree's built binary, the reference-transaction and commit hooks
  shall run for each invocation class, and a project made with the
  previous form shall reach the same result after `codeflow update`;
  evidence: a scratch adopter journey with its output.
- AC-7 The pull request shall state the threat closed in class words and
  why the design is the standard one; evidence: the pull request body.
