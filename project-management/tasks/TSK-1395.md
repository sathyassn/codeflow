# TSK-1395: CodeFlow's git hooks run for every git command, whatever its working directory

## Description

`codeflow init` and `codeflow update` set `core.hooksPath` to the
project-relative hooks folder. Git resolves a relative hooks path against
each command's working directory, so some invocations that name the
repository or working directory in other ways do not reach the managed
hooks. Every hook CodeFlow installs is affected. Found while checking the
TSK-326 coverage (PR 718).

The task writes a hooks path that reaches the managed hooks from every
invocation form, migrates existing projects in `codeflow update` with no
manual step, and makes `codeflow doctor` report a hooks path that does not
reach the managed hooks, with the fix named. Non-goals: which git
subcommands the session guards judge (TSK-1393), and the hook checks
themselves.

Disclosure: this record and the task's pull request describe invocation
classes only. The hook by invocation matrix lands in the task's own
pull request together with the fix (Director ruling, 2026-11-08).

## Outcome

After this merges, an adopter's CodeFlow git hooks run for every git
command in the project, however the working directory or repository is
named, and `codeflow doctor` names a hooks path that would let a command
skip them.

## Deliverables

## Acceptance Criteria

- AC-1 Every hook CodeFlow installs (pre-commit, commit-msg, pre-push, pre-merge-commit, reference-transaction) shall run for every form git supports for naming a command's working directory or repository: the working-directory forms, linked worktrees, the flag forms and the environment forms; evidence: the hook by invocation matrix, judged on the line's binary before the change and the worktree's binary after, and a test per form that fails before where the form did and passes after.
- AC-2 `codeflow init` and `codeflow update` shall write a hooks path that reaches the managed hooks from every invocation form, shared by linked worktrees; doctor's current absolute-path warning and ADR-0055 item 5 are superseded in the same change by a new ADR (approved by the Director on 2026-11-08); evidence: a CLI test, the doctor tests, the new ADR and the pull request body.
- AC-3 When `core.hooksPath` does not resolve or does not reach the managed hooks (a stale path after the repository moved included), `codeflow doctor` shall report it and name the fix (`codeflow update`); evidence: doctor unit tests for each case and a passing case for the new form.
- AC-4 `codeflow update` shall rewrite a project's previous or stale `core.hooksPath` to the new form with no manual step, and leave a hooks path that names a folder the project owns other than the managed hooks as it is; evidence: a CLI test on a project made with the line's previous behaviour, and a moved-repository test.
- AC-5 The session guards' refusal of a `core.hooksPath` write shall hold for the new form; evidence: guard tests for a write of the new form and of the previous form, refused before and after.
- AC-6 (journey) When an adopter project is initialized with the worktree's built binary, a write to a local protected ref made through each invocation form shall be refused by the reference-transaction hook, and a plain commit from a subfolder shall still run its hooks; a project made with the previous form shall reach the same result after `codeflow update`; evidence: a scratch adopter journey with its output.
- AC-7 The pull request shall state, in class words, the threat closed (git commands that skip every CodeFlow hook through how they name the repository or working directory) and why the design is the standard one; evidence: the pull request body.
