# TSK-1395: CodeFlow's git hooks run for every git command, whatever its working directory

## Description

`codeflow init` and `codeflow update` set `core.hooksPath` to the
project-relative hooks folder. Git resolves a relative hooks path against
the directory it runs from, which is the top of the working tree only when
git finds one. A git command whose working directory or repository is
named in other ways (from inside the git directory, or with the repository
given by flag or environment and no working tree) finds no hook there and
runs none, with no message. Every hook CodeFlow installs is affected, the
reference-transaction hook that guards local protected refs included, so a
local protected ref can be rewritten without a refusal. Found while
checking the TSK-326 coverage (PR 718).

The task writes a hooks path that reaches the managed hooks from every
working directory, migrates existing projects in `codeflow update` with no
manual step, and makes `codeflow doctor` report a hooks path that is
relative, unresolvable or not the managed hooks, with the fix named.
Non-goals: which git subcommands the session guards judge (TSK-1393), and
the hook checks themselves.

## Outcome

After this merges, an adopter's CodeFlow git hooks run for every git
command in the project, whatever its working directory and however the
repository is named, and `codeflow doctor` names a hooks path that would
let a command skip them.

## Deliverables

- the hooks path writer and its migration: `crates/codeflow-core/src/scaffold/` (provisional; the builder confirms where init and update write it)
- the doctor check: `crates/codeflow-core/src/doctor/mod.rs`
- tests: unit and CLI tests for the matrix, the migration and the doctor check
- the hook by invocation matrix: this record's `## Findings`
- docs: `docs/adoption.md` and `docs/troubleshooting.md` where they describe the hooks path
- release note: `changelog.d/TSK-1395.md`

## Acceptance Criteria

- AC-1 Every hook CodeFlow installs (pre-commit, commit-msg, pre-push,
  pre-merge-commit, reference-transaction) shall run for a git command whose
  working directory is the project root, a subfolder, the git directory or a
  folder inside it, a linked worktree or its own git directory, or whose
  repository is named by flag (`-C`, `--git-dir`, `--work-tree`) or by
  environment (`GIT_DIR`, `GIT_WORK_TREE`); evidence: a matrix of hook by
  invocation in `## Findings`, class-only, judged on the line's binary
  before the change and the worktree's binary after, with a test for each
  row that fails before where the row did and passes after. (serves EPC-022 AC-5)
- AC-2 `codeflow init` shall write a `core.hooksPath` that reaches the
  managed hooks from every working directory; the pull request states the
  design, why it is the standard one, and how it behaves for a moved or
  renamed repository, linked worktrees, Windows paths and a repository
  config an agent could change; evidence: a CLI test on a fresh project
  and the pull request body.
- AC-3 When `core.hooksPath` is relative, does not resolve, or does not
  reach the managed hooks (a stale path after the repository moved
  included), `codeflow doctor` shall report it and name the fix
  (`codeflow update`); evidence: doctor unit tests for each case and a
  passing case for the new form.
- AC-4 `codeflow update` shall rewrite a project's relative or stale
  `core.hooksPath` to the new form with no manual step, and leave a hooks
  path that names a folder the project owns other than the managed hooks
  as it is; evidence: a CLI test on a project made with the line's previous
  behaviour, and a moved-repository test.
- AC-5 The session guards' refusal of a `core.hooksPath` write shall hold
  for the new form; evidence: guard tests for a write of the absolute form
  and of a relative form, refused before and after.
- AC-6 (journey) When an adopter project is initialized with the
  worktree's built binary, a write to a local protected ref made from
  inside the git directory, and one made with the repository named by
  environment, shall be refused by the reference-transaction hook, and a
  plain commit from a subfolder shall still run its hooks; a project made
  with the previous form shall reach the same result after `codeflow
  update`; evidence: a scratch adopter journey with its output. (serves EPC-022 AC-5)
- AC-7 The pull request shall state, in class words, the threat closed (git
  commands that skip every CodeFlow hook through how they name the
  repository or working directory) and why the design is the standard
  one; evidence: the pull request body.
