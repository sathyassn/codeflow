# TSK-249: Work claims read only the remotes that hold the target

## Description

Fixes #80. Work claims and readiness count only local branches and branches on
origin, the target's fetch remote, or remotes explicitly named by policy. This
keeps unrelated archive branches from preventing new work while reporting them
as information. The scope covers the shared readiness readers, CLI output,
policy configuration and documentation. Landing detection and target resolution
are unchanged.

## Deliverables

- Shared remote scope and regression tests: `crates/codeflow-core/src/workgraph/readiness.rs`
- Informational CLI output and journey: `crates/codeflow-cli/src/cmd/work.rs`, `crates/codeflow-cli/tests/readiness_journey.rs`
- Policy key, schema and contract tests: `crates/codeflow-core/src/hooks/policy.rs`, `crates/codeflow-core/src/hooks/policy_schema.rs`
- Policy defaults and managed work guidance: `assets/base/policy.json`, `assets/base/rules/worktrees.md`
- User documentation and release impact: `docs/cli.md`, `docs/policy-reference.md`, `docs/capabilities.md`, `CHANGELOG.md`

## Acceptance Criteria

- AC-1 With `origin` and an `archive` remote holding an unlanded
  `task/TSK-194-...`, `work claim TSK-194` succeeds and reports the archive
  branch as information. Control: the same branch on `origin` still refuses
  with "already claimed by a visible branch" (the existing test).
  `crates/codeflow-core/src/workgraph/readiness.rs` tests beside the
  `upstream` fixtures at `:1825`.
- AC-2 (journey) `work next` with the archive branch lists the task Ready, not Active,
  with no conflict; with `git.claim_remotes: ["archive"]` it is Active.
  `crates/codeflow-cli/tests/readiness_journey.rs`.
- AC-3 A target on `upstream/main` (fork layout) counts `upstream` and
  `origin` branches as claims and nothing else; the existing diverged-upstream
  tests pass unchanged. `readiness.rs` tests at `:2064-2231`.
- AC-4 `claim_remotes` is the only source for both the local scan and
  `ls-remote`; a unit test asserts the two listings agree on the remotes
  they read.


Evidence names: AC-1 `an_archive_branch_is_information_and_does_not_refuse_a_claim`
and control `a_remote_claim_hidden_by_the_refspec_still_counts`; AC-2
`archive_branches_are_information_until_policy_names_the_remote` (journey);
AC-3 `a_fork_counts_origin_and_upstream_claims_but_not_archive`, plus the existing
fork and diverged-upstream tests; AC-4
`local_and_live_claim_listings_share_remote_scope`.
