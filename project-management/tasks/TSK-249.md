# TSK-249: Work claims read only the remotes that hold the target

## Description

Fixes #80. Work claims and readiness count only local branches and branches on
origin, the target's fetch remote, or remotes explicitly named by policy. This
keeps unrelated archive branches from preventing new work while reporting them
as information. The scope covers the shared readiness readers, CLI output,
policy configuration and documentation. Landing detection and target resolution
are unchanged.

## Deliverables

- Shared remote scope and regression tests: `crates/codeflow-core/src/workgraph/readiness.rs`
- Informational CLI output and journey: `crates/codeflow-cli/src/cmd/work.rs`, `crates/codeflow-cli/tests/readiness_journey.rs`
- Policy key, schema and contract tests: `crates/codeflow-core/src/hooks/policy.rs`, `crates/codeflow-core/src/hooks/policy_schema.rs`
- Policy defaults and managed work guidance: `assets/base/policy.json`, `assets/base/rules/worktrees.md`
- User documentation and release impact: `docs/cli.md`, `docs/policy-reference.md`, `docs/capabilities.md`, `CHANGELOG.md`
