# TSK-1088: The update procedure for an adapted project ships as a managed rule

## Description

Source: issue 74, its item 3 (the procedure) and its addendum (the
`docs/updating.md` proposal, organized by file kind), and the operator's
request quoted there: an agent in the consuming project reviews an update
against the project's own additions and applies it methodically, in order,
as tracked work. The procedure was part of TSK-247 (its AC-7) until
2026-10-30; it is its own unit because it is a managed instruction file
every tier installs, reviewed on its own, and it reads the `--plan` output
TSK-247 ships.

Today `docs/adoption.md` "Update" covers the binary upgrade, `codeflow
update`, resolving each `.new` and the pin order, and ends at "no `.new`
remains". Nothing tells an adopter's agent how to compare the project's
instruction sections, overrides, citations of managed lines, user-owned
JSON defaults and settings regions against a new release, in which order,
or what to record. This task ships that procedure as
`.codeflow/rules/updating.md` at every tier, rewrites "Update" in
`docs/adoption.md` around the file-kind table from the addendum, documents
`[scaffold] ignore`, and makes `cf-customize` name the procedure as the
step after an update.

Non-goals: generating `.agents/skills` from `.claude/skills` (an ADR-sized
change; recorded as a follow-up in the epic), a doctor cross-reference
check, and embedding changelog entries or ADRs in the plan output.

## Outcome

After this merges, an agent in an adopting project can take a CodeFlow
update as tracked work: preview it, classify every change by file kind,
settle or escalate each decision, apply it in the documented order with
the person's items listed separately, verify, and record what was decided.

## Deliverables

- the procedure: `assets/base/rules/updating.md`, its `[[entry]]` in `assets/base/scaffold-manifest.toml` at every tier, the installed `.codeflow/rules/updating.md` and its base
- the trigger line: `assets/base/agents/skills/cf-customize/SKILL.md` and its `.claude/skills` and `.agents/skills` mirrors
- docs: `docs/adoption.md` "Update" (the file-kind table, `[scaffold] ignore`, the link to the rule), `docs/capabilities.md` (CAP-002 row)
- release note: `changelog.d/TSK-1088.md`

## Acceptance Criteria

- AC-1 When `codeflow init` runs at each tier, or `codeflow update` runs on a project at any tier, `.codeflow/rules/updating.md` shall be installed and recorded; evidence: `manifest_consistency` and a `scaffold_test` case per tier.
- AC-2 The procedure shall carry each step issue 74 names, in this order: plan (`codeflow update --plan`, the changelog and decision records between the versions), classify every item by file kind (the addendum's table: managed blocks, project sections, edited and unedited managed files, mirrored skill trees, user-owned JSON, files outside the manifest, settings regions, records), decide (security boundaries and process additions go to the operator with before, after and a recommendation; the rest is settled from evidence and recorded), order (pin, update, conflicts with CI and workflows last and by a person where the project bars agents from them, overrides and docs that cite managed text, `cf-customize`, adopted policy keys; one reviewed pull request per trust boundary), run where the session can write and hand the person the plan's list for the rest, verify (no `.new`, doctor clean, the test gate, each cross-reference re-pointed, the guards' planted cases still refused, a fresh session loads the new instructions, one cross-lineage review) and record in the task's Closeout (version pair, each decision and who made it, each override kept, reworked or dropped, what was not verified); evidence: the reviewer's check of the rule against issue 74 and its addendum, item by item. (serves EPC-022 AC-172)
- AC-3 `docs/adoption.md` "Update" shall link the rule, present the file-kind table, document `[scaffold] ignore` with an example, and carry the 3.x to 4.0.0 step TSK-1087 wrote without contradiction; `docs/capabilities.md` CAP-002 shall name the procedure; evidence: the docs diff and `codeflow test --only docs-portal`.
- AC-4 `cf-customize` shall name `.codeflow/rules/updating.md` as the step after an update in one line, with the three copies byte-identical and within their ratchets; evidence: `manifest_consistency` and `artifact_budget_contract`.
- AC-5 When a `codeflow init --minimal` project at v3.1.1 is updated by this build, the version-skew warning shall name `--plan` and the procedure, `.codeflow/rules/updating.md` shall be present, and the reading-structure check shall stay within guideline; evidence: the journey recorded in the pull request.
