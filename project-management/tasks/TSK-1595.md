# TSK-1595: The identity layer is proven on Linux and macOS and documented for adopters

## Description

Owner: to be assigned by the Director. Staged 2026-11-23 for coord/records.

The epic's journey, its final speed run and the adopter docs: how layer 3
works, what it reads per platform, what it never stores, how to read the
doctor check, and how to exempt a legitimate value (a `LICENSE`
copyright line) through TSK-1588. It also sets layer 3 in CodeFlow's
own policy and proves on the installed build that TSK-1594 installs
the shipped default, `block` by the operator's decision of 2026-11-23,
on init and on update; a project can set `warn` or `off`, reported as a
relaxation.

Under the staged Q3 answer (option B), layer 3 runs at pre-push and in
the commit hooks only; it does not run in CI, and the journey proves
that CI invokes no identity reader. If the operator answers Q3
otherwise, AC-1's CI case changes before claim.

## Outcome

After this merges, an adopter can read one page on the identity layer,
and the installed build is proven on both platforms with placeholder
identities, including the combined speed bound of layers 2 and 3.

## Deliverables

- `docs/policy-reference.md` (Privacy, identity), `docs/troubleshooting.md` (an unreadable source)
- this repository's `.codeflow/policy.json` (`privacy.identity: block`)
- a journey script under `scripts/` that sets placeholder identities in a temporary home
- `changelog.d/TSK-1595.md`

## Acceptance Criteria

- AC-1 (journey) With the installed build in a scratch project, on macOS and on Linux, with placeholder identities set for the run (git configuration and environment in a temporary home; host names through the test seam where the platform name cannot be set unprivileged, named under not_verified): a push whose range adds each kind, in content and in an added file name, shall be refused at `block`; a push with an unreadable source (a failing stand-in) shall be refused; a `LICENSE` line holding the placeholder full name shall pass with an authority-held exception printed, and, with TSK-424's activation key unset, an authority-held exception shall apply and be printed for every identity rule of the SPC-018 R-31a list that the installed defaults put on; `codeflow ci`, in the form the trusted verdict job runs it, shall print that layer 3 was judged at pre-push only and invoke no identity reader (a reader that fails the run if called); `codeflow doctor --check privacy` shall name each source's state; and the content and path canary searches over the whole run shall find no identity value; evidence: the journey output per platform.
- AC-2 Install and update on the installed build: a fresh init at each tier shall write `privacy.identity: block` with the pattern section, and `codeflow update` over a project holding only the pattern section shall add the identity section and report it; this repository's policy shall set `privacy.identity` to `block`; the docs shall state what is read, that nothing is stored and that CI does not run layer 3 under the staged Q3 answer; evidence: the journey output, the diffs and `codeflow validate --docs`.
- AC-3 Final speed run for layers 2 and 3 together (SPC-018 R-9a): with the real hook wired, the privacy pass of the installed pre-push hook on the typical-change fixture, measured as wall-clock from the authority read through the range's diff, path and message reads and every identity read to the last finding, shall have a median of five runs under 500 ms on the hosted Linux runner and an Apple silicon macOS machine; any source served by a stand-in shall be named, with its real cost from TSK-1591 or b3 Findings added to the stand-in; evidence: both medians in the PR, with the measured span and every stand-in stated.
