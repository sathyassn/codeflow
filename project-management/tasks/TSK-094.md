# TSK-094: per-target start line in codeflow test

## Description

`codeflow test` prints nothing until every target has finished:
`run_sequential` and `run_parallel` in
`crates/codeflow-core/src/testing/runner/mod.rs` collect results and the CLI
(`crates/codeflow-cli/src/cmd/test.rs`) prints the per-target lines and the
gate verdict only at the end. When a gate is killed (a runner timeout, a
SIGTERM on a loaded CI machine, a manual interrupt), the log shows no trace of
which target was running or which had already passed. This task adds a start
line per target, written to stderr as it begins, in the same `[codeflow
test]` prefix the CI skip notice already uses, so an interrupted gate names
the target it died in. Found during the 3.0.0 release gates (workspace
`RELEASE-PLAN.md`, 2026-09-26 follow-ups).

Target release: 3.0.0 (additive output), delivered by TSK-134. Non-goal: live streaming of a
target's own output, a progress bar, or a change to the final summary or the
exit codes.

## Affected surfaces and interfaces

- `crates/codeflow-core/src/testing/runner/mod.rs` (`run_sequential`,
  `run_parallel`) or the CLI caller, whichever keeps the core free of direct
  printing if that is the existing rule there.
- Human-readable stderr of `codeflow test`; stdout and any machine-readable
  output stay unchanged. CAP-004.

## Acceptance Criteria

- [ ] AC-1 When `codeflow test` starts a target in sequential mode, it shall write
      one stderr line naming the target and the mode before the target's
      command runs; evidence: an integration test that runs two fixture
      targets and asserts the start line of each appears before that
      target's completion.
- [ ] AC-2 When targets run in parallel, each target's start line shall be written
      as its thread begins, and lines from different targets shall never
      interleave inside one line; evidence: a test with two parallel fixture
      targets asserting two whole start lines.
- [ ] AC-3 When the process is terminated while a target runs, the captured stderr
      shall already name that target; evidence: a test that kills the
      process during a sleeping fixture target and reads the partial stderr.
- [ ] AC-4 stdout, the final summary lines and the exit codes are unchanged, and
      targets skipped by filters or `ci_skip` print no start line; evidence:
      the existing `codeflow test` CLI tests pass unchanged, plus one skip
      assertion.
- [ ] AC-5 The CHANGELOG mentions the start line, and so does the CLI reference if
      one documents `codeflow test` output when this task starts (`docs/cli.md`
      exists on the EPC-014 line, not on the 3.0.0 base); evidence: the diff.
