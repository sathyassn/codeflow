# TSK-1079: Exempt paths still refuse links and gitlinks, and credentials.json is blocked

## Description

Source: the content policy design for issue #279, revision 5, unit U4,
closing findings D-2 (Grok's design item 4.5, widened by Grok review G6)
and D-12, which no task owned.

- `crates/codeflow-core/src/hooks/path_policy.rs:283-285` returns from
  `check_entry` when `exempt(&path)` holds, before the symlink rule at
  `:298-328`, which runs only for mode `0o120000`; a gitlink
  (`0o160000`) at any path never enters it. `exempt` (`:232-245`) admits
  every `.gitignore`, `.codeflow/policy.json`, `.codeflow/project.toml`,
  `.codeflow/bootstrap.sh`, `.codeflow/bootstrap.ps1`,
  `.codeflow/ci-setup.sh`, each one-component path under
  `.codeflow/git-hooks/` and the two workflows. A link at the executable
  paths (the bootstrap scripts, `ci-setup.sh`, which the gates job runs,
  and the hook shims) is medium severity; at the data paths, low.
- `credentials.json` is not a shipped blocked name
  (`path_policy.rs:16-38`); the managed gitignore's `*credentials*` is
  passed by `git add -f`.

A regular file at an exempt path stays exempt by design: the gate must not
block repair of its own inputs, and review and the hook-integrity digest
are the controls for a hostile regular file (a residual the ADR of
TSK-1077 states). This task closes only the link and gitlink shapes.

## Outcome

After this merges, an adopter's path gate refuses a symlink with an unsafe target or a gitlink at every exempt path, and refuses `credentials.json` anywhere, while a regular file at an exempt path still passes.
