# TSK-1079: Exempt paths still refuse links and gitlinks, and credentials.json is blocked

## Description

Source: the content policy design for issue #279, revision 5, unit U4,
closing findings D-2 (Grok's design item 4.5, widened by Grok review G6)
and D-12, which no task owned.

- `crates/codeflow-core/src/hooks/path_policy.rs:283-285` returns from
  `check_entry` when `exempt(&path)` holds, before the symlink rule at
  `:298-328`, which runs only for mode `0o120000`; a gitlink
  (`0o160000`) at any path never enters it. `exempt` (`:232-245`) admits
  every `.gitignore`, `.codeflow/policy.json`, `.codeflow/project.toml`,
  `.codeflow/bootstrap.sh`, `.codeflow/bootstrap.ps1`,
  `.codeflow/ci-setup.sh`, each one-component path under
  `.codeflow/git-hooks/` and the two workflows. A link at the executable
  paths (the bootstrap scripts, `ci-setup.sh`, which the gates job runs,
  and the hook shims) is medium severity; at the data paths, low.
- `credentials.json` is not a shipped blocked name
  (`path_policy.rs:16-38`); the managed gitignore's `*credentials*` is
  passed by `git add -f`.

A regular file at an exempt path stays exempt by design: the gate must not
block repair of its own inputs, and review and the hook-integrity digest
are the controls for a hostile regular file (a residual the ADR of
TSK-1077 states). This task closes only the link and gitlink shapes.

## Outcome

After this merges, an adopter's path gate refuses a symlink with an unsafe target or a gitlink at every exempt path, and refuses `credentials.json` anywhere, while a regular file at an exempt path still passes.

## Findings

Recorded on the task's base, `integration/EPC-022-the-3-2-0-milestone-fixes`
at `461827479`, before any code change.

- **Exempt set** (`crates/codeflow-core/src/hooks/path_policy.rs:232-247`):
  every path whose final component is `.gitignore`; exactly
  `.codeflow/policy.json`, `.codeflow/project.toml`,
  `.codeflow/bootstrap.sh`, `.codeflow/bootstrap.ps1`,
  `.codeflow/ci-setup.sh`, `.github/workflows/codeflow-policy.yml` and
  `.github/workflows/codeflow-ci.yml`; and each one-component path under
  `.codeflow/git-hooks/`. It runs on the normalized (NFC, ASCII-folded)
  path, so upper-case spellings are exempt too.
- **Rule order in `check_entry`** (`:266-330`): normalize the path, refusing
  an ambiguous one (`:276-282`); return early when `exempt` holds
  (`:283-285`); protected prefix (`:286-288`); blocked name, with a history
  note for a deletion (`:289-297`); then the symlink rule, only for a
  non-deleted mode `0o120000` entry (`:298-328`). An exempt symlink never
  reaches the symlink rule. No rule anywhere looks at mode `0o160000`, so a
  gitlink is judged only by its name and prefix, and at an exempt path by
  nothing.
- **Callers of `check_entry`:** `check_diff` (`:332-356`), used by
  `staged` (`:362-381`) and by `range` for ordinary commits (`:441-451`);
  and `range` for two-parent merges through the remerge reader
  (`:418-438`). Outside the file, `staged` is called only by the
  pre-commit hook (`crates/codeflow-core/src/hooks/git_hook.rs:145-146`),
  and `range` only by `codeflow ci`
  (`crates/codeflow-cli/src/cmd/ci.rs:551-552`). The pre-push hook
  (`git_hook.rs:1190`) does not call the path gate.
- **Callers that rely on the early return:** `exempt` has one other caller,
  the symlink target check (`:314`), which skips a link whose resolved
  target is a gate input. No production caller stages a link or gitlink at
  an exempt path: the repository tracks no `120000` or `160000` entry
  (`git ls-files -s`), and the scaffold writes hook shims and bootstrap
  scripts as regular files. The tests that pin the exemption stage regular
  files only: `all_gate_inputs_remain_exempt_under_hostile_policy`
  (`crates/codeflow-core/tests/path_policy.rs`),
  `hostile_policy_cannot_lock_inputs_and_exemptions_do_not_disable_secret_scan`
  (`crates/codeflow-cli/tests/path_policy_cli.rs`) and the unit test
  `exemptions_are_nfc_and_ascii_folded_and_root_anchored`. So moving the
  link and gitlink rules ahead of the exemption changes no caller that
  depends on it.
- **`credentials.json`:** absent from `DEFAULT_NAMES` (`:16-38`), which
  holds only `application_default_credentials.json` and
  `.aws/credentials`. The managed gitignore's `*credentials*`
  (`assets/base/gitignore:10`) is passed by `git add -f`.
- **Sibling noted, not changed here:** `.credentials.json` (the Claude Code
  credential file name) is also outside the shipped names; adding it is a
  public-behaviour choice beyond this task's criteria, reported to the
  coordinator.
