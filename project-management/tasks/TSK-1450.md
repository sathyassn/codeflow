# TSK-1450: CodeFlow's own rules state how epics land during the transition

## Description

ADR-0102, accepted, sets two delivery units, and TSK-1451 stops hosted runs on line pushes. CodeFlow's own `AGENTS.md` still says every task reaches its line through a pull request and that a landing waits for hosted verdicts on the line's tip, which no longer come once TSK-1451 is on a line. The operator ruled on 2026-11-20 that tested tasks merge directly into every epic line, with no pull request, and that pull requests are raised only into `main`, from lines mostly or from tasks where needed. This task writes the transition into the project-owned part of `AGENTS.md` and into dated notes on three accepted ADRs, so the written rule is on `main` right after the workflow change and before any line takes it. TSK-1438 edits the same section, but it rides EPC-055's line, which reaches `main` only when that epic is complete, so it cannot carry text that must be on `main` now. The planning landing that files ADR-0102 is a records change with no task of its own, and rules text needs one. Non-goal: managed text (the managed `AGENTS.md` block, `.codeflow/rules/git-rules.md`, the cf-method and cf-ship skills), which changes only when EPC-055 ships.

The new "Transition to epic delivery" bullet says, until EPC-055 ships:

- For tasks of every epic, on every line, it replaces the managed map's "one task is one PR", "open the PR" and "land a batch" rows and `git-rules.md` "Bodies of work" and "PR bodies". Standalone tasks and the epic's pull request to `main` keep them.
- A task of an epic with a line is built from the line's tip, reviewed whole at one commit by the other lineage, completed on its branch, merged into the line with a no fast forward merge and pushed, with no pull request. The verdict file names the merged head.
- A landing candidate is transport: reviewed task merges pushed together after one full local gate on the candidate.
- A line push has no hosted run, and no pull request into a line is opened. The epic's close check carries a Windows-only break.
- After each landing the landing owner checks `main` and, when it moved, merges it into the line on its own before any record change. A line tip made by that merge, or by cutting the line from `main`, has no gate of its own: the full local gate of the next candidate, built on it, covers it.
- The epic reaches `main` through one pull request after its close check, merged by the operator with a merge commit.
- Every line takes tasks by direct landing, with no pull request (operator, 2026-11-20). EPC-022, the one milestone line, reaches `main` through checkpoint pull requests from its line until its checkpoint is done (Director, 2026-11-20).
- A task has its own pull request into `main` only when it belongs to no epic and is urgent, a hotfix or similar, complete by itself. An epic is cut small and valid on `main` alone, about 5 to 10 tasks as a reference point, never a cap; a part needed on `main` sooner becomes its own small epic (operator, 2026-11-22).

A separate bullet, "Relaxed checks on `main` (TSK-1452)", has its own end, TSK-1452's restore, whether or not EPC-055 has shipped: while `main`'s heavy checks are relaxed (TSK-1452's temporary items), the Linux gates and every Windows job run only on the daily run on `main`'s tip and on a manual dispatch. A pull request into `main`, an epic's included, then carries its local evidence block, and its Windows evidence is the first daily or dispatched run on `main` that holds the change. After TSK-1452's restore, the Linux gates and every Windows job run on every pull request into `main` again.

The same model also goes into the process statements of `docs/delivery.md`, the guide page a human reader uses, and into the labels of its Concept figure (`docs-portal/figures/delivery/concept.json`). Today that page says one pull request per task and a full gate per batch (Concept lead, its bullets, the Architecture figure and actor bullets, and the Technical rows "Batch gate" and "The batch gate is red"). The rewrite states that every task of an epic lands on its epic's line with no pull request, that the epic reaches `main` through one pull request, that a task has its own pull request into `main` only when it belongs to no epic, is urgent and is complete by itself, and that an epic has about 5 to 10 tasks as a reference point and is valid on `main` alone and cut small. One plain paragraph marks the tooling still in build and names the task for each pending item: TSK-341, TSK-1434 to TSK-1437 (EPC-055), TSK-1444, TSK-1445 and TSK-1352 (EPC-057), TSK-1446 (a standalone proof once EPC-057 is on `main`) and TSK-1452 (standalone), so the page claims no behaviour that has not shipped. It also names EPC-022's checkpoint pull requests, the one exception to the model on CodeFlow's own repository. The Architecture examples of the task and reopen pull requests are labelled as `codeflow ci` as shipped, which adopters can use today and ADR-0102 keeps for their epics with no `main_landing` marker, while CodeFlow's own repository lands an epic's tasks with no pull request. Main's page is over the Technical word limit (1580 of 1500). TSK-1571 delivers the page trim; this task builds on it, starts from a `main` that holds TSK-1571's landed trim, and does not carry the trim itself. Technical prose otherwise stays word-neutral. The drafted text is workspace `coordination/coordinators/planning/staging-tsk1450-amendment/delivery-model-c.diff`, the version after its cross-lineage reads. When EPC-055 ships, TSK-1439 updates the statements about EPC-055's checks with the shipped behaviour; each other in-build notice stays until its own task ships.

## Outcome

After this merges, a CodeFlow maintainer or agent can read in CodeFlow's own `AGENTS.md` (project-owned part) and three accepted ADRs how a task reaches its line on every line with no pull request and no hosted line run, how a line reaches `main`, and when each sentence stops applying. A reader of the delivery guide (`docs/delivery.md`) sees the same model, with the tooling still in build marked and named by task.
