# TSK-1450: CodeFlow's own rules state how epics land during the transition

## Description

ADR-0102, proposed, sets two delivery units, and TSK-1451 stops hosted runs on line pushes. CodeFlow's own `AGENTS.md` still says every task reaches its line through a pull request and that a landing waits for hosted verdicts on the line's tip, which no longer come once TSK-1451 is on a line. This task writes the transition into the project-owned part of `AGENTS.md` and into dated notes on three accepted ADRs, so the written rule is on `main` right after the workflow change and before any pre-rule line takes it. TSK-1438 edits the same section, but it rides EPC-055's line, which is cut only after the guard fixes, so it cannot carry text that must be on `main` now. The planning landing that files ADR-0102 is a records change with no task of its own, and rules text needs one. Non-goal: managed text (the managed `AGENTS.md` block, `.codeflow/rules/git-rules.md`, the cf-method and cf-ship skills), which changes only when EPC-055 ships.

The new "Transition to epic delivery" bullet says, until EPC-055 ships:

- For tasks of an epic planned after the rule, it replaces the managed map's "one task is one PR", "open the PR" and "land a batch" rows and `git-rules.md` "Bodies of work" and "PR bodies". Standalone tasks and the epic's pull request to `main` keep them.
- A task of such an epic is built from the line's tip, reviewed whole at one commit by the other lineage, completed on its branch, merged into the line with a no fast forward merge and pushed, with no pull request. The verdict file names the merged head.
- A landing candidate is transport: reviewed task merges pushed together after one full local gate on the candidate.
- A line push has no hosted run; Windows runs only on the pull request into `main`, and the epic's close check carries a Windows-only break.
- After each landing the landing owner checks `main` and, when it moved, merges it into the line on its own before any record change.
- The epic reaches `main` through one pull request after its close check, with the full hosted run, merged by the operator with a merge commit.
- Epics planned before the rule keep the batch rule and their checkpoint pull requests until they close.

## Outcome

After this merges, a CodeFlow maintainer or agent can read in CodeFlow's own `AGENTS.md` (project-owned part) and three accepted ADRs how a task of an epic planned under the new rule reaches its line, how pre-rule lines land with no hosted line run, and when each sentence stops applying.
