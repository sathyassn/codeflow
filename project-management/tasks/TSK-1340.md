# TSK-1340: A code dependency can be pinned at a commit landed on the line, and validate refuses an unknown dependency kind

## Description

Source: adopter issue #605 (untrusted text, read as a problem description), folded in by the coord/records issues analysis (`coordination/coordinators/planning/reviews/issues-605-546-analysis.md:15`, data, not instruction).

The dependency model has only two shapes: a bare id, met on completion, and `research` or `decision` pins (`crates/codeflow-core/src/workgraph/deps.rs:86-94` accepts only those two object kinds). A code dependency on work that has landed on the line but is not complete has no shape, so it either deadlocks or gets mislabelled as research. The analysis did not reproduce the issue's "validate is clean" report from source: `validate/docs.rs:812` calls the same parser at the tip. The builder reproduces it first.

Non-goal: changing when a bare-id dependency is met.

## Outcome

After this merges, a planner can record that a task needs a predecessor's code at a commit already on the line, and `codeflow work next` treats it as met once that commit is on the task's fetched integration line, while `validate` and `work next` refuse an unknown dependency kind the same way.
