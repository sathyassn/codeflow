# TSK-364: A substituted hook binary cannot pass a hook silently

## Description

Source: both test integrity audits of 2026-10-17 at
`eaf2ed04e932186cdd26dc4a7e5740cc553acee3` (Codex medium finding on hook
dispatch; Fable finding F2 and probes 1 and 3; Fable minor M6).

Every installed git hook shim (`assets/base/git-hooks/*`, installed under
`.codeflow/git-hooks/`) runs `CODEFLOW_HOOK_BINARY` when it names an
executable file, checks only that it prints `hooks 3` to `git-hook
capabilities`, and then takes its verdict (`pre-commit:7` to `:24`). An
executable that prints that line and exits 0 disables the commit-time
secret scan, the commit format check and the pre-push gate. The code calls
the variable "a dispatch hint, not authentication"
(`crates/codeflow-core/src/git/mod.rs:21`); tests cover only a missing or
non-executable path (`crates/codeflow-cli/tests/hooks_cli.rs:7256`). No
test presents an impostor that answers the handshake. Hosted CI remains
the perimeter, but the in-session plane is advertised as a plane.

Two related local overrides are honoured without a record:
`CODEFLOW_INTEGRATE_TOKEN` is accepted when non-empty
(`crates/codeflow-cli/src/cmd/mod.rs:37`), and no test sets it empty, so
weakening that check to "set" survives; and `CODEFLOW_HUMAN_OVERRIDE=1`.
Neither use is written to the ledger.

Folded rather than duplicated: the in-session refusal of setting
`CODEFLOW_HOOK_BINARY` (prefix, `export`, `env`, `declare`) and of a `PATH`
that changes which `codeflow` resolves is TSK-324's AC-5 (EPC-023,
landing on this line). This task does not re-plan it; it starts after
TSK-324 lands and adds the parts TSK-324 does not cover. That order is
prose, because no EPC-022 task depends on an EPC-023 task.

Outcome: the trust contract of a designated hook binary is written down,
an impostor that answers the handshake cannot pass a hook silently through
any entry point, and override and integrate-token use is visible.

The contract choice is this task's, recorded in an ADR: either the shim
accepts a designated binary only when it matches a recorded digest (for
example the verified binary TSK-324 records under
`~/.codeflow/versions/`), or it accepts it as reduced local assurance that
every hook run prints and the ledger records. Either way no text may claim
the handshake authenticates a binary.

Product surface: adopter-facing scaffold (the shims) and engine (hooks,
ledger).

## Deliverables

- the contract: an ADR draft allocated with `codeflow adr new` (home `docs/decisions/`), and the hook binary section of `docs/adoption.md` and `docs/policy-reference.md` where they describe it
- the shims: `assets/base/git-hooks/*` and the harness wrappers in `assets/base/settings/default.json`, with installed copies and baseline resynchronised
- override recording: the ledger write for integrate-token and human-override use (`crates/codeflow-cli/src/cmd/git_hook.rs` and `crates/codeflow-core/src/hooks/`)
- tests: impostor tests in `crates/codeflow-cli/tests/hooks_cli.rs`, and an empty-token test for `cmd/mod.rs`
- release note: `changelog.d/TSK-364.md`

## Acceptance Criteria

- AC-1 With `CODEFLOW_HOOK_BINARY` naming an executable that prints `hooks
  3` and approves everything, a commit with a staged synthetic secret, a
  badly formatted commit message, a push to a protected ref and a
  protected reference update shall each be refused, or shall proceed only
  with a printed reduced-assurance line and a ledger record, as the ADR
  decides, through `pre-commit`, `commit-msg`, `pre-push`,
  `reference-transaction` and each harness wrapper; evidence: one test per
  entry point, failing before the change. (serves EPC-022 AC-62)
- AC-2 The genuine designated binary shall still work through every entry
  point; evidence: the control case of each test above.
- AC-3 An empty `CODEFLOW_INTEGRATE_TOKEN` shall not count as present, and
  each use of the integrate token or the human override in a hook shall
  write a ledger event naming the variable, the rule it skipped and the
  ref; evidence: an empty-token test that fails when the check is weakened
  to presence, and ledger assertions. (serves EPC-022 AC-62)
- AC-4 No doc, message or comment shall state that the capability
  handshake authenticates a binary; evidence: the diff and a search of
  `docs/`, `assets/` and `crates/`.
- AC-5 (journey) With the installed build and TSK-324 landed, an agent
  session that sets the variable is refused by the guard, and a hook run
  under an impostor set from the launching environment shows the outcome
  the ADR chose; evidence: both journeys' output.
