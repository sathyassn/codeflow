# TSK-071: present annotation coverage and feedback round trip

## Description

Make every block in a present document annotatable, and prove that the
feedback really reaches the agent. The catalog has sixteen block types
(narrative, bullets, callout, comparison, decision, table, status, code, diff,
tree, diagram, media, disclosure, tabs, feedback_prompt, html) and TSK-059
adds figure; the chrome (topbar, mode strip, float, composer, markers, rail)
is the only non-annotatable surface. Declare, in the authoring reference,
which gestures apply to each block type (text where the block renders
selectable words, element where it renders an anchorable part, area on every
block) and justify any cell that does not apply. Fix what the QA pass on the
real runtime found (its record is filed at its evidence path when it
completes) and whatever the matrix finds, in the runtime that TSK-060 has
rebuilt: selection, excerpt crops, element paths, region anchors, marker
placement and the feedback delivery. Prove, in the automated real-browser
suite against the real service, every applicable block by gesture cell: the
note is created, the envelope that `codeflow present feedback` returns
carries the note with its selector, and every element and area note carries a
PNG crop that covers the anchored bounds and is not blank. Prove the
lifecycle on the same session: `update` reanchors or orphans notes with the
reason, `resolve` closes a note, `history` lists the revisions and reviews,
`export` writes the document without chrome, `close` and `clear` tear down.
Cover the CLI code paths for these commands in the crate tests. Non-goal: new
block types; the figure block is TSK-059's and the chrome is TSK-060's.

## Affected surfaces and interfaces

After TSK-060 has landed: `crates/codeflow-present/web/src/selection.ts`,
`excerpt.ts`, `events.ts`, `export.ts`, `chrome.tsx` for annotation and
feedback defects only; `crates/codeflow-present/src/render.rs` annotation
attributes (`data-cf-block-id`, `data-cf-review-text-root`, anchors on
block parts), `src/state.rs` and `src/service.rs` feedback validation and
delivery; `web/scripts/real-browser-check.mjs` and the other
`*-browser-check.mjs` suites; `crates/codeflow-cli/tests/present_cli.rs`;
the annotation column of `cf-present/references/document-authoring.md` and
`resources/how-presentation-works.md` with mirrors and hashes; the present
rebuild and its checksum. The feedback envelope schema stays compatible; a
field addition is documented in the history schema. CAP-016.

## Acceptance Criteria

- [ ] The authoring reference carries a block by gesture matrix for all
      seventeen block types with text, element and area columns, every
      non-applicable cell justified by what the block renders, and the
      chrome listed as the only non-annotatable surface; evidence: the
      reference, its mirrors and a test that the matrix names every variant
      of the closed block enum.
- [ ] When the real-browser suite runs a fixture document that carries every
      block type, every applicable cell creates a note through the real
      gesture (a selection for text, a click for element, a drag for area)
      and `codeflow present feedback` returns an envelope with that note, its
      kind and its selector; a cell that fails names the block type, the
      gesture and the step; evidence: the suite output listing each cell.
- [ ] Every element and area note in that envelope carries a PNG crop whose
      pixel bounds match the anchored element or region at the capture scale
      within 2 px and whose content is not a single colour; a text note
      carries its quote with prefix and suffix; evidence: the suite's crop
      assertions and one saved crop per block type in the verification
      record.
- [ ] On the same session, `present update` with a changed revision reanchors
      the notes that still resolve and orphans the rest with a reason,
      `resolve` closes a note and `history` shows the revisions, the reviews
      and the resolution, `export` writes the document with no chrome and the
      markers absent, and `close` then `clear` leave no browser process,
      profile or state file behind; evidence: the suite output and
      `present_cli` tests per command.
- [ ] Every defect from the QA pass on the real runtime is fixed with a
      fixture that reproduced it, or is dispositioned with a reason in the
      closeout; evidence: the defect table with fixture names.
- [ ] `npm run check`, the browser checks, `cargo test -p codeflow-present`
      and `cargo test -p codeflow-cli --test present_cli` are green and the
      present checksum matches a clean rebuild; evidence: the recorded
      output with the head SHA.
- [ ] The design primary reviews the annotation experience on the fixture in
      three skins and two modes; Grok adversarial review of the matrix and
      the crop assertions; Codex review where the seat allows; evidence: the
      review records.
