# TSK-071: present annotation coverage and feedback round trip

## Description

Make every block in a present document annotatable, and prove that the
feedback really reaches the agent. The catalog is the closed block enum at
this task's merge base, with no fixed count. When the task was planned it had
sixteen block types (narrative, bullets, callout, comparison, decision, table,
status, code, diff, tree, diagram, media, disclosure, tabs, feedback_prompt,
html); TSK-059 has since added figure and TSK-087 removed diagram, and TSK-119
adds the `form` block after this task lands and extends the matrix itself; the
chrome (topbar, mode strip, float, composer, markers, rail) is the only
non-annotatable surface. Declare, in the authoring reference, which gestures
apply to each block type (text where the block renders selectable words,
element where it renders an anchorable part, area on every block) and justify
any cell that does not apply. Fix what the QA pass on the real runtime found
(its record is filed at its evidence path when it completes) and whatever the
matrix finds, in the runtime that TSK-060 has rebuilt: selection, excerpt
crops, element paths, region anchors, marker placement and the feedback
delivery. Prove, in the automated real-browser suite against the real service,
every applicable block by gesture cell: the note is created, the envelope that
`codeflow present feedback` returns carries the note with its selector, and
every element and area note carries a JPEG crop that covers the anchored bounds
and is not blank. Prove the lifecycle on the same session: `update` reanchors
or orphans notes with the reason, `resolve` closes a note, `history` lists the
revisions and reviews, `export` writes the document without chrome, `close`
and `clear` tear down. Cover the CLI code paths for these commands in the
crate tests. Non-goal: new block types; the figure block is TSK-059's and the
chrome is TSK-060's.

Plan v5 change (2026-09-26, present review parity proposal v2.1 section 4.2,
settled by the coordinator the same day): this task starts after TSK-118 and
lands before TSK-119 starts (Plan v5.1), and TSK-118 takes the element cells
of the `figure` block and of the `html` stage (entity targets inside figures
and hand-written SVG, with their crops), QA defect 5 in its figure form, and
the figure-part clicks of QA defect 6 (SVG shape or label anchoring the whole
`svg`). This task keeps the declared matrix for every block type, every other
suite cell, the lifecycle, the rest of defect 6 (code-line and diff-line
clicks anchoring the whole `pre`, and a plain drag over diff whitespace
pinning the whole diff) and QA defects 1 to 4 and 7 to 10, and runs against
the resolver TSK-118 lands. The QA report and its matrix are durable in the
workspace `design/present-parity/inputs/` (workspace commit `73faec2`):
`present-qa-report.md` and `block-gesture-matrix.tsv`.

Planning amendment (2026-09-27): the crop format of element and area notes
is JPEG, not PNG, in the Description and AC-3. The runtime has always
delivered those crops as JPEG: 3.0.0 refuses any other format, the v1
history schema pins `media_type` to `image/jpeg`
(`session-history-v1.schema.json`) and stays byte-identical, on this line
the server accepts PNG only on an entity note, and the v1 `feedback` view
drops every crop that is not JPEG, so that 3.0.x agents keep reading the
stream byte for byte (SPC-014 C1). A PNG crop on an element or area note
would never reach an agent on the default stream. The crop rule AC-3
shares with TSK-118 is the bounds and colour check; its format is JPEG for
element and area notes and PNG for entity notes (TSK-118). The criteria
move to `- AC-n`, wording otherwise unchanged.

## Acceptance Criteria

- AC-1 The authoring reference carries a block by gesture matrix for every
      block type in the closed block enum at this task's merge base, with no
      fixed count and including the v1 `decision` block, with text, element
      and area columns, every non-applicable cell justified by what the block
      renders, and the chrome listed as the only non-annotatable surface;
      evidence: the reference, its mirrors and a test that the matrix names
      every variant of the closed block enum.
- AC-2 When the real-browser suite runs a fixture document that carries every
      block type, every applicable cell other than the `figure` and `html`
      stage element cells (proved by TSK-118) creates a note through the
      real gesture (a selection for text, a click for element, a drag for
      area)
      and `codeflow present feedback` returns an envelope with that note, its
      kind and its selector; a cell that fails names the block type, the
      gesture and the step; evidence: the suite output listing each cell.
- AC-3 Every element and area note in that envelope, other than the element
      notes TSK-118 proves under the same crop rule, carries a JPEG crop whose
      pixel bounds match the anchored element or region at the capture scale
      within 2 px and whose content is not a single colour; a text note
      carries its quote with prefix and suffix; evidence: the suite's crop
      assertions and one saved crop per block type in the verification record.
- AC-4 On the same session, `present update` with a changed revision reanchors
      the notes that still resolve and orphans the rest with a reason,
      `resolve` closes a note and `history` shows the revisions, the reviews
      and the resolution, `export` writes the document with no chrome and the
      markers absent, and `close` then `clear` leave no browser process,
      profile or state file behind; evidence: the suite output and
      `present_cli` tests per command.
- AC-5 Every defect in `present-qa-report.md` is fixed with a fixture that
      reproduced it, or is dispositioned with a reason in the closeout,
      except defect 5 and the figure-part clicks of defect 6, which are
      TSK-118's; defect 6's code-line, diff-line and diff-whitespace cases
      are this task's; evidence: the defect table with fixture names.
- AC-6 `npm run check`, the browser checks, `cargo test -p codeflow-present`
      and `cargo test -p codeflow-cli --test present_cli` are green and the
      present checksum matches a clean rebuild; evidence: the recorded
      output with the head SHA.
- AC-7 The design primary reviews the annotation experience on the fixture in
      three skins and two modes; Grok adversarial review of the matrix and
      the crop assertions; Codex review where the seat allows; evidence: the
      review records.
