# TSK-1364: A cancelled CI run reports cancelled verdicts, not failed ones

## Description

The two verdict jobs that branch protection reads, `codeflow gates`
(`gates-verdict`) and `windows` (`windows-verdict`), run with `if: always()`
(`.github/workflows/codeflow-ci.yml:719` and `:1110` at the line tip
90540e3d8). When a newer run in the same concurrency group supersedes a run,
both still run, see their needed jobs cancelled, and conclude failure, so the
superseded run posts a red required check that nothing failed on. TSK-1313's
Findings for its AC-7 record this, and coord/ci found it on runs 42138888383
(PR 600), 42140361803 (PR 643), 42141599038 (PR 582) and 42136012297
(PR 638); coord/records read the 638 run live on 2026-11-05: its conclusion
is cancelled and its `windows` check reads fail. TSK-1313's newer-push
cancellation makes such runs common.

Scope: the verdict follows the run, not the needed jobs. Only a cancelled
run gives cancelled verdicts. In a run that is not cancelled, a cancelled
need still fails the verdict, because a job that hits its timeout also
concludes cancelled. A verdict never concludes success or skipped for a
cancelled run, because a skipped required check reads as passing.
Non-goals: which events cancel which runs (TSK-1313) and how the Windows
verdict reads its jobs (TSK-1321).

## Outcome

After this merges, a maintainer whose run a newer run supersedes sees its required checks reported as cancelled rather than failed, while a failed, timed-out or wrongly skipped job still fails them.

## Deliverables

- the verdict jobs: `.github/workflows/codeflow-ci.yml` (`gates-verdict`, `windows-verdict`), and the managed copy if the file ships to adopters
- the contract tests over the verdict jobs' conditions: `scripts/test_gate_contracts.py`
- the doc and record update: TSK-1313's Findings line for AC-7 and the docs that describe the false red
- the run evidence: the hosted superseded run named in AC-1, recorded in this task's completion

## Acceptance Criteria

- AC-1 When the run itself is cancelled (a newer run in its concurrency group superseded it), the `codeflow gates` and `windows` verdict jobs shall conclude cancelled, never success or skipped, because a skipped required check reads as passing; evidence: a contract test in `scripts/test_gate_contracts.py` over the verdict jobs' conditions, and one hosted superseded pull request run showing both verdicts cancelled.
- AC-2 When the run is not cancelled and any need failed, was cancelled (a timeout included) or was skipped where the verdict requires it, the verdict shall conclude failure as it does today; evidence: contract tests for a failed need, a timed-out need and a wrongly skipped need.
- AC-3 The TSK-1313 Findings line for AC-7 and the docs that describe the false red shall be updated to the new behaviour; evidence: the doc and record diff.
