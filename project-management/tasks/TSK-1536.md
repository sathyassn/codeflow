# TSK-1536: The guard lets a leading assignment stand before env -S

## Description

On main's runner code (`ec8d5c1ab3`) the guard refuses a harmless command
when a variable assignment comes before `env -S`, for example
`FOO=1 env -S 'git config --global user.name Probe'`. The refusal is an
over-refusal of the same kind TSK-1476 addresses: the guard cannot see that
the assignment only sets the environment of `env`, so it fails closed on a
command it could have judged. This task lets a leading assignment stand
before `env -S`, so the command is judged by the split string it runs, as the
same command without the assignment already is. A command that the guard
refused for its split string stays refused.

Scope: the guard's handling of leading assignments before `env -S`, with its
tests. Non-goal: any other launcher, and any relaxing of what `env -S`
itself may run.

Target moved to `main` on 2026-11-22 (the Director's ruling, option C, of 2026-11-21): the installed-hooks journey test `startup::installed_hooks_refuse_unresolved_forms_beside_a_named_target` is red on `main` at `17510e9bd4` ("wrong verdicts" panic at `startup.rs:991`), because `env_split_command` in `crates/codeflow-core/src/hooks/git_guard.rs` quotes every word before `-S`, so `FOO=1` becomes the program word. This record carries the narrow fix only, the line's commits `ffb38f6260`, `d73cb547b6` and `d675f8e19e` taken verbatim onto `main` at `709b9b4bea`, with AC-1, AC-2 and AC-6. AC-3 to AC-5 stay with the line's TSK-1536 at `0006408b99`. Interim gap until the next sync of `main` into the EPC-022 line: an assignment before `env -S` gets the verdict `main` gives the same form without it, and the line's stricter AC-4 and AC-5 verdicts arrive with that sync. On that sync, `crates/codeflow-core/src/hooks/git_guard.rs` conflicts, because both sides change the return of `env_split_command`; resolve it by taking the line's `env_split_command_keeping`. `docs/policy-reference.md` merges clean and keeps `main`'s edit; never check out the line's copy over the merge. `crates/codeflow-core/src/hooks/policy_schema.rs` and `crates/codeflow-cli/tests/refusal_journey/startup.rs` do not conflict, since `main` has not changed them since `ec8d5c1ab3`. ## Outcome

After this merges, an operator can run a command with a leading assignment
before `env -S` when its split string is allowed, and the guard still refuses
one whose split string is not.

## Deliverables

- the guard change: `crates/codeflow-core/src/hooks/`
- tests for the case, with a fail-before and a pass-after run: the unit test module in `crates/codeflow-core/src/hooks/git_guard.rs`
