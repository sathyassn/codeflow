# TSK-104: work classification for every product pull request and the light paths

## Description

Today the anchored preflight runs only on `task/` branches, and a pull
request can carry product changes with no work association. This task
classifies every product pull request as tracked (`Task: TSK-NNN`), direct
change (`Task: none: <reason>`), planning-only (records and plans only), or
a trusted automation profile, and blocks an unclassified one; runs the
preflight for tracked work on any branch; refuses direct changes on the
protected surfaces of design v4 section 7; and adds the light paths of
section 8: `task new --follow-up-of`, `epic new --integration`, and
`adr new` with the ADR template defaulting to `proposed`. It also carries
the spike path of section 3.1 row 1. The automation profiles themselves
(trusted actor, the skipped branch and commit checks, supplied PR
sections) are TSK-107's; this task gives them a
classification slot.

## Affected surfaces and interfaces

- `codeflow ci` PR-body checks and the scaffolded CI workflow; pre-commit
  preflight (CAP-003).
- `task new`, `epic new`, new `adr new`; `docs/decisions/template.md` and its
  scaffold copy (CAP-010).
- The adopter-facing path-set definition of SPC-013 R-114, created here
  and extended by TSK-106.
- Shared files this task edits: the CI workflow, the hooks and the ADR
  template. Ownership follows SPC-013 R-118.

## Acceptance Criteria

- [x] AC-1 When a product pull request carries none of the four
      classifications, CI shall block it; a planning-only pull request that
      touches product paths shall block; evidence: CI fixtures per class.
      Spec: R-70.
- [x] AC-2 When a pull request from any branch names `Task: TSK-NNN`, CI
      shall run the anchored preflight for that task, and block when the
      head branch carries a different task id; `work start` and pre-commit
      shall run it on any branch that carries a task id on a sanctioned
      prefix (`task/`, `fix/`, `feat/`, `spike/` and the rest), keyed on
      that id; evidence: preflight tests on `task/`, `fix/`, `feat/` and
      `spike/` branches carrying the id, a `fix/` pull request naming the
      release task, and a mismatched `Task:` line.
      Spec: R-72, R-76, R-110.
- [x] AC-3 When `Task: none: <reason>` touches watched contract paths,
      policy, hooks, dependency manifests or lockfiles, the record schema,
      or the adopter-facing path set, CI shall block; a project may forbid
      direct changes entirely but cannot narrow the refused set; evidence:
      CI fixtures per surface.
      Spec: R-71, R-114.
- [x] AC-4 `task new --follow-up-of TSK-NNN` shall record `follow_up_of` and
      write the record on a planning branch of the source's target;
      `epic new --integration` shall create the epic's integration branch;
      `adr new` shall issue the next ADR number through the registry and
      write the template with `status: proposed`; evidence: command tests.
      Spec: R-36, R-73, R-77.
- [x] AC-5 A task with `work_type: spike` on a `spike/TSK-NNN-<slug>`
      branch shall pass the preflight in the own-branch context and land
      only its findings under `docs/research/` and its own record, and CI
      shall block a spike pull request that changes anything else;
      evidence: spike journey and a spike pull request that adds product
      code.
      Spec: R-64, R-110.
- [x] AC-6 (journey) On a fresh project with the installed CLI, a follow-up,
      a leaf task, a small fix with `Task: none`, and a new ADR shall each
      take one command and at most one ordinary pull request; evidence: the
      section 10 journeys for classification and light paths.
      Spec: R-74, R-104.
- [x] AC-7 When one pull request both adds a task record and names that
      task in `Task:`, CI shall block it; evidence: CI fixture.
      Spec: R-78.
- [x] AC-8 This task shall create the one adopter-facing path-set
      definition that R-53 and R-71 read: the current
      `watched_contract_paths` plus `assets/`, hook sources, shipped
      templates, managed instruction blocks, the CLI command tree and every
      runtime adopters run, including `crates/codeflow-present`; it ships as
      a fixture the journeys use, in a structure TSK-106 extends; evidence:
      the definition, the fixture and a test that classifies one path of
      each member.
      Spec: R-114.
