# TSK-311: The program report shows every record on every fetched line

## Description

An adopter with many integration lines has no generated answer to "where
does the program stand": `codeflow status` reads the working tree only
(`crates/codeflow-cli/src/cmd/status.rs:7-17`), and `work next` judges a
record only on its own target's tip
(`crates/codeflow-core/src/workgraph/readiness.rs:633-657`)
(https://github.com/sathyassn/codeflow/issues/166). This task adds
`codeflow report program [--json] [--host] [--strict] [--epic] [--line]`, a
read-only report over every fetched ref that says, for each epic and task,
which copy is the truth and whether every other copy is the same version,
behind, ahead or divergent. It builds the two foundations the rest of
EPC-023 reads (design section 3):

- F1, the cross-ref record reader: one snapshot of ref names to object ids;
  parsed fields per distinct blob; the last-change commit per record path
  per distinct tip; full ref names as identity, with a label; unreadable
  records kept in totals as `unreadable`; a duplicate id with a different
  `uid` is a conflict row. It extends the `ids` inventory
  (`crates/codeflow-core/src/ids/inventory.rs`).
- F2, home and currency. A task's home is its `integration_target` as its
  copies on the trusted remote's default branch and integration lines
  declare it; disagreement, or two lines matching an epic, is `unknown`. An
  epic's home is its unique line, else the default branch. The home copy is
  the truth. The last-change commit of a record on a ref is the newest
  commit on that ref's first-parent chain whose blob differs from its first
  parent's or, for a merge, from either parent's; a merge whose result and
  both parents agree is no change. Each other copy carries agreement
  (`equal`, `differs`), currency (`equal` is `same`; for `differs`, with H
  the home's last change and C the copy's: `behind` when C is reachable
  from the home tip, else `ahead` when H is reachable from the copy's tip,
  else `divergent`; `unknown` when the home is unfetched or ambiguous or the
  history read refuses) and placement (`home`, `elsewhere`, `off home only`,
  `planned on default`, `branch only`).

Each row carries, for every epic and task on every fetched ref: the home,
the status at home, each other copy with its agreement, currency and
placement, the derived readiness (as `work next` derives it at the home,
`crates/codeflow-core/src/workgraph/readiness.rs`) and the branches that
hold it. Rollups are by epic and by line, and per epic the estimate
against the actual where recorded outcomes exist
(`crates/codeflow-core/src/estimate/outcomes/`). A fact the report cannot
supply is an explicit incomplete-data field: readiness is `unknown` when
the home is `unknown` or unfetched, and the estimate-against-actual fields
are `unavailable` when an epic has no outcomes, never zero and never
omitted.

Authority comes only from copies in the trusted remote's namespace (the
remote `landed_policy` selects) on the default branch and `integration/*`
lines; local branches, other remotes and forks are shown and never choose a
home. The report never fetches and prints its snapshot time; filters filter
output only; `--host` adds pull request facts, else `unknown`. Class and
lane grouping is TSK-314. Non-goal: any check or verdict; this is a report.

Amended 2026-10-22 on the move to EPC-022, for issue 280 item 2: each
line row also carries the drift facts TSK-420's reader derives (commits
behind the protected target, the last sync event and its date or the
cut point, the oldest unlanded task's age, and the flag against the
project's sync interval), read through that reader, never recomputed.
The per-stream view of open epics the issue's comment asks for is not
in this report: streams are clone-local coordination ledger state
(EPC-025), which a record-only report never reads; `codeflow coord
status` (TSK-440) shows it, and a tracked stream home would be TSK-313's
vocabulary (4.1.0) if the operator wants it here. Deferred, named.

## Acceptance Criteria

- AC-1 When `codeflow report program` runs, it shall read one snapshot of
  every fetched ref, print the snapshot time, never fetch, and write
  nothing; evidence: a test that moves a ref after the snapshot and shows
  the report unchanged, and a test with a remote that refuses connections.
  (serves EPC-022 AC-116)
- AC-2 The F2 worked cases shall each be a fixture with its expected
  result: a branch cut after the record change, both then changing
  unrelated files (`equal`, `same`); a revert at home while a copy holds the
  old bytes (`equal`, `same`); home merges a branch that completed the task
  and keeps `todo` (the branch copy `differs`, `behind`); home adopts the
  branch's version at a merge (`equal`, `same`); a merge whose parents hold
  the same blob and whose result differs (the merge is the last change); a
  branch that re-resolved its copy after home moved on (`ahead` or
  `divergent` by the reachability test); evidence: the fixtures.
  (serves EPC-022 AC-116)
- AC-3 Conflicting targets, a duplicate `uid`, an ambiguous epic, an
  unfetched home, a default-branch breakdown (`planned on default`), a
  fetched fork that plants a record (shown, never the home) and a history
  read that TSK-287's guarded reader refuses (`unknown`) shall each give the
  stated result; a ready task and a task waiting on a predecessor shall
  show the readiness `work next` gives them at the home, and a task whose
  home is `unknown` shall show readiness `unknown`; an epic
  with recorded outcomes shall show its estimate against the actual, and
  one without shall show `unavailable`; evidence: one fixture per case.
  (serves EPC-022 AC-116)
- AC-4 `--json` shall carry `schema_version`, the repository identity, the
  snapshot time, the ref snapshot, coverage diagnostics, records (with the
  status at home and the derived readiness), branches, and rollups by epic
  and line with the per-epic estimate against the actual, in a
  deterministic order, with copies, conflicts and unreadable records
  counted apart, incomplete-data fields always present, and `unknown` or
  `unavailable` never printed as zero; the fact model shall be frozen by a
  schema test that TSK-312 reuses; evidence: the schema test and a golden
  output.
- AC-5 The command shall exit 0 with incomplete coverage printed, and
  non-zero only under `--strict`; `--epic` and `--line` shall filter the
  output and never the totals; `--host` shall add pull request facts or
  print `unknown`; evidence: CLI tests.
- AC-6 The cost shall be one first-parent walk per distinct tip over the
  record roots, stopping when every path has its last change, measured on a
  fixture with 16 lines and about 200 records before the task closes;
  evidence: the measured time in the PR and the fixture.
- AC-7 The home and currency rule with its worked cases shall be written
  once in `project-organization.md` "The work lifecycle", mirrored byte for
  byte; evidence: the text and `manifest_consistency`.
- AC-8 When the installed build runs the report in a scratch repository
  with a default branch, two integration lines, a task branch and a fork
  remote, the rows and JSON shall match the expected facts, readiness and
  the per-epic estimate against the actual included, with `unknown` and
  `unavailable` where the fixture withholds them (journey); evidence: the
  journey output.
- AC-9 Each line row and its `--json` object shall carry the drift facts of TSK-420's reader (behind count, last sync event with its date or the cut point, oldest unlanded task age, the interval flag), equal to what `codeflow orient` shows for the same snapshot, with `unknown` where the reader cannot answer; evidence: a fixture with a synced and an unsynced line compared against `orient`. (serves EPC-022 AC-116)
