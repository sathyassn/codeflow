# TSK-270: the Linux gates verdict arrives within 12 minutes

## Description

CodeFlow's own Linux `codeflow gates` verdict takes 13.8 to 19.7 minutes on a
pull request (median 18.0 over five runs read at `c941877ba`), mostly in the
instrumented coverage part. The operator approved a speed-up on 2026-10-11,
to build after the 3.1.0 tag, from the release session's Linux CI plan. This
one unit has three steps: a measurement spike on hosted runs (sharding with
`cargo llvm-cov nextest --no-report` and `report --lcov`, merged accuracy
against one monolithic run on the same tree, build and CPU cost); removing
the builds and journey runs the Linux parts repeat; and, unless the spike
shows one coverage job already fits, two duration-balanced coverage shards
with a merge job that keeps the 90 percent aggregate line floor. The local
full gate keeps its single `rust-coverage` command, and adopters' scaffolded
CI does not change. Non-goal: the Windows path, which sets the whole-run
time.

## Deliverables

- the spike's measurements: provisional, recorded in this task's pull request body
- the gate parts and shards: `.github/workflows/codeflow-ci.yml`, `.codeflow/test-config.json`
- the shard planner, the coverage merge and their tests: provisional, under `scripts/`, named when built
- the pins: `scripts/gate-parity.py` and its tests
- the docs: `docs/architecture.md`, `docs/releasing.md`

## Acceptance Criteria

- AC-1 When the coverage, prose and benchmark parts run, none of them repeats a build or a journey run that another part already makes, and every journey still runs exactly once. Evidence: `.codeflow/test-config.json`, `gate-parity` and the hosted logs of the final head.
- AC-2 When the instrumented suite runs as shards, every listed test runs in exactly one shard, the merged line coverage equals a single-run percent on the same tree within 0.05 percentage points, and the 90 percent aggregate floor fails the verdict below it. Evidence: the spike's side-by-side numbers, the partition check on a hosted run, and merge tests at 89.9 and 90.0 percent, with an empty shard and with a missing shard.
- AC-3 The `codeflow gates` verdict fails when a part, shard or merge job fails, is cancelled or is skipped other than by the reuse decision. Evidence: `gate-parity` pins on the verdict and a test per case.
- AC-4 The local full gate and the shipped adopter CI are unchanged. Evidence: `rust-coverage` keeps its one `cargo llvm-cov nextest ... --fail-under-lines 90` command, `git diff -- assets/base/ci` is empty and `manifest_consistency` passes.
- AC-5 On three consecutive hosted pull request runs of the final head that are not queued, the `codeflow gates` verdict arrives within 12 minutes of the run start, with each part's time and the runner regime recorded (journey)
