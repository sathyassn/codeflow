# TSK-1473: The release journey tests clear every agent session marker before they commit

## Description

TSK-1397 made the test helpers clear every agent session marker before they commit, but its sweep missed `crates/codeflow-cli/tests/release_journey.rs`. That file's helper `with_env` (`release_journey.rs:43-71` at `main` 4cc6de60a) isolates the home, Git identity and PATH and removes Git and CodeFlow variables, but passes the agent session markers through to the `codeflow` commands it starts.

Two of the file's four tests fail when cargo is started outside the tree with `--manifest-path` from an agent session: the fixture's own pre-commit hook refuses the test's commit under `git.root_checkout_commits` because `CLAUDECODE` is set, and the git helper panics (`release_journey.rs:91`). They pass today only because `.cargo/config.toml:23-27` forces the markers empty, and cargo reads that file from the directory it starts in, not from `--manifest-path`. The product is not at fault: `root_checkout.rs:114` already treats an empty value as unset. coord/ci had to run the EPC-022 sync gate set at 989eddd49 with `CLAUDECODE` unset and disclose it.

Source: coord/ci, 2026-11-12 01:55 and 03:46, with logs in workspace `coordination/coordinators/parallel/logs/key14-claudecode-*-2026-11-12.log` (32d38a96). Not verified there: which directory started the first failing run, and nextest or a directly run test binary. TSK-1084 (complete) cleared the same markers for the guard fixtures, the same class one layer down.

## Outcome

After this merges, a maintainer can run the cargo suites from any agent session, however cargo is started, and the release journey tests pass without unsetting anything.

## Deliverables

- `with_env` clearing the line's `AGENT_MARKERS`: `crates/codeflow-cli/tests/release_journey.rs`
- the sweep of other helpers that start `codeflow` or `git` with an inherited environment, in the pull request
