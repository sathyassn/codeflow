# TSK-1051: Update and parse reports name places, never project values

## Description

TSK-1029 found that CodeFlow's printed reports and parse errors could show
values a project wrote, which can be secrets: a parser error quoted the
offending source line of the project's metadata file, and update's report
printed workflow step names and policy values. TSK-1029 fixed every line
`codeflow update` and its `--diff` export print, and the parse errors that
update reaches (project metadata, state files, the workspace policy, the
PR template policy, and the remote and CI pin policy reads), with two
shared helpers in `crates/codeflow-core/src/scaffold/mod.rs`:
`toml_error`, which names line and column and drops the quoted source,
and `unquoted`, which replaces any value a parser quotes with `<value>`.

This task applies the same rule to the rest of the product: every report
line `codeflow init` prints, and every parse error any other command
prints for a file the project writes (validation, ledger, testing,
workgraph, coordination, doctor, hooks, estimate and model modules), names
the file, line, column and schema names only, never a value or source
line from the project. It adds one contract test that plants a value in
each parsed project file and fails if any command's stdout or stderr
shows it, so a new parse site cannot regress silently.

Non-goal: changing what a command does with a malformed file (refuse,
warn or skip stays as it is); only the text it prints changes.

## Deliverables

- Redacted parse errors and init report lines: `crates/codeflow-core/src/` and `crates/codeflow-cli/src/`
- Contract test for printed diagnostics: `crates/codeflow-cli/tests/` (a new file; the builder names it)
- Changelog entry: `changelog.d/TSK-1051.md`

## Acceptance Criteria

- AC-1 When any CodeFlow command fails to parse a TOML, JSON, JSONL or YAML file the project writes, the error it prints shall name the file and, where the parser gives one, the line and column, and shall not contain any value or source line from that file. Evidence: a contract test plants a unique value in each parsed project file, both malformed and of the wrong type, and asserts the value is absent from stdout and stderr.
- AC-2 When `codeflow init` runs over a project with existing files, its report shall name paths and schema keys only, never a value read from the project. Evidence: an init end-to-end test with planted values in existing settings, policy and workflow files.
- AC-3 The shared helpers from TSK-1029 shall be the one route for these messages, with no second redaction helper. Evidence: review of the diff, and a search for direct formatting of TOML and JSON parser errors on project files that finds none.
- AC-4 The contract test runs the real binary over every parse site it covers. (journey)
