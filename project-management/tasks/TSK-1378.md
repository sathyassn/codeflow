# TSK-1378: A sync from main keeps a home that main moved and the line already names

## Description

The import check (`work.import_authority`) refuses a sync of the default branch into a line when a landing on the default branch changed a task's declared home (`verify_record_home`, `crates/codeflow-core/src/workgraph/acceptance/imports.rs:763-796`). Its one exemption, a reviewed planning move (`is_planning_move`, `imports.rs:430-441`), counts only a move on the checked head's own first-parent history. A sync's first parent is the line, so a home change that the default branch made through its own reviewed planning merge can never qualify, even when the line's record already names that same home. Found on 2026-11-07: the EPC-022 sync of main `acf0be5b6` (merge `0c738e269`) is refused on TSK-1177 at main's merge `2070fabb8` (PR 666, which retargeted eight tasks to main), although TSK-1177 names `main` on the line tip, on main and on the sync head.

The threat the check closes stays closed: a sync must never carry a home change that the line did not agree to, and a pull request or line branch must never re-home a task by its own commits. This task narrows the exemption to one more case only: the move landed on the default branch's own first-parent history, in a merge that is an admissible planning landing, and the line's record at the sync's first parent already names the same logical home as the imported record. Everything else still refuses, with the same message. Unlike the existing exemption, this one does not require the task to be `todo` or `blocked` at the landing: in the found case main retargeted TSK-1177 after completing it (complete with the line as its home at `c82c05b83`, complete with `main` at `2070fabb8`), and the line had already taken that home. The state rule protects a receiving branch from a home moved under it; here the receiving line already holds the same home, and the record's completion is still judged by the other import proofs. Proof binds to commit SHAs (the default tip the run already trusts, the landing commit and its first parent), never to a branch name.

Non-goals: any change to how the default tip itself is trusted; the other import proofs, which still run on every record; relaxing a line-side or pull-request-side re-home.

Widened 2026-11-12, merging TSK-1467 (cancelled into this task by the Director's ruling of 2026-11-12, about 01:58 EST, because both narrow the same exemption in `verify_record_home` for the same sync class). The EPC-022 sync of 2026-11-12 was refused on four records. TSK-1177 and TSK-1357 (moved to `main` by pull request 666) are this task's original case: the line names `main` too. TSK-341 and TSK-1352 (moved to `main` by pull request 772) are a second case: the line never changed the task, so its copy still names the line (TSK-341), or the line has no copy (TSK-1352). AC-6 and AC-7 add that case. The refusal also named only TSK-1177, because the check stops at the first record it refuses (`imports.rs:180-181` at `main` 4cc6de60a); AC-8 and AC-9 make it complete. Until this lands, the main records pull request of 2026-11-12 clears the four by a reviewed home note on each on `main`. Whether such a later change should clear a home move is AC-10.

## Outcome

after this merges, a Coordinator can sync main into an integration line when main moved a task's home through a reviewed planning merge and the line already names that home, and every other home change on a sync is still refused.

- AC-1 When a sync of the default branch into a line imports a task record whose declared home was changed by a landing on the default branch, the import check shall accept that home change only when all of these hold: the landing is on the first-parent history of the default-branch commit the run already trusts, found by commit SHA; the landing is an admissible planning landing (a reviewed merge whose own diff touches only records, as `admissible_planning_landing` decides today); and the line's own record at the sync's first parent names the same logical home as the imported record. In every other case the check shall refuse with "the landing changes the task's declared home"; evidence: the fixtures of AC-2 and AC-3.
- AC-2 A refusal stays for each of these, each a fixture that fails if the exemption accepts it: the existing `a_clean_sync_cannot_re_home_a_line_task` (main re-homes a line task), unchanged and passing; the reverse of the found case, where main moved the home by a reviewed planning merge but the line's record names a different home; a home change on the default branch made by a direct commit or by a merge whose diff touches more than records; a home change made by the line's or the pull request's own commits; and a run where a local branch named like the default branch points at a commit with the move but the trusted default tip does not contain it; evidence: those fixtures in `main_sync.rs` and `acceptance_cli/imports.rs`.
- AC-3 (journey) The found case shall pass: in a fixture, main completes a line task and then retargets it to main by a reviewed planning merge whose diff touches only records, the line takes that home, and a sync of main into the line is accepted by `codeflow ci` with no `work.import_authority` block; the fixture fails before the change and passes after it; and `codeflow ci` on the real EPC-022 sync shape (the sync of main into the line once this lands on main) reports no `work.import_authority` block on TSK-1177; evidence: the fixture's fail-before and pass-after output, and the ci output on the sync head.
- AC-4 The docs shall state the narrowed exemption and its limits in `docs/delivery.md` (the `work.import_authority` section) and `docs/capabilities.md` (the completion and release row), in the same words as the code's refusal and acceptance; evidence: the diff and `codeflow validate --docs`.
- AC-5 The pull request shall state the threat the check closes, why the narrowed exemption keeps it closed, and that the proof binds to commit SHAs; it gets a Grok review with the security checklist before it is marked ready; evidence: the body and the review file.
- AC-6 (added 2026-11-12 from TSK-1467) When a sync of the default branch into a line imports a task record whose declared home was changed by a landing on the default branch, the import check shall also accept the change when all of these hold: AC-1's first two conditions (the landing is on the trusted default tip's first-parent history and is an admissible planning landing); the task was `todo` or `blocked` with no acceptance block at the landing and at its first parent; and the line's copy of the record is unchanged since the merge base of the line and that landing, or absent there and since. Evidence: a fixture of the 2026-11-12 shape (a todo line task moved to `main` by a planning merge on `main`, the line then syncing `main`), refused before and passing after; AC-4's docs state this case too.
- AC-7 (added 2026-11-12 from TSK-1467) AC-6 shall fail closed, refusing with today's message and the cause, when any of its conditions cannot be proven: the landing is not on the trusted first-parent history (a second-parent or replayed commit), the landing is not a clean planning merge, the task was complete, superseded or malformed at either side, or the line changed its copy since the merge base. Evidence: one negative fixture per condition, reusing the cases of `a_home_move_outside_a_permitted_state_stays_refused` and `a_home_move_through_no_planning_landing_stays_refused`.
- AC-8 (added 2026-11-12 from TSK-1467) The refusal shall name every refused record in the range, not only the first, each with its own cause and repair. Evidence: a fixture with two refused records naming both.
- AC-9 (added 2026-11-12 from TSK-1467) The refusal for a task that was complete when its home moved and whose line copy names another home shall name the routes that clear it: the line takes `main`'s copy byte for byte through a planning merge on the line, or a reviewed change to the record lands on `main` after the move. Evidence: the message in AC-8's fixture.
- AC-10 (added 2026-11-12 from TSK-1467) Today any later reviewed change to a record on `main` clears an earlier home move made on `main`, because `verify_record_home` compares only the record's last landing with that landing's first parent (`imports.rs:784-796` at `main` 4cc6de60a). TSK-1312, TSK-1318 and TSK-1239 passed the EPC-022 sync this way, and the main records pull request of 2026-11-12 clears TSK-1177, TSK-1357, TSK-341 and TSK-1352 the same way, by the Director's ruling of 2026-11-12, about 01:01 EST. This task's cross-lineage design review shall decide whether that is intended. If it is not, this task closes it in the same change as AC-1 and AC-6, and a sync accepts a home move only under their conditions. If it is, `docs/delivery.md` shall say so. Evidence: the review's decision, and either a fixture showing a later change on `main` no longer clears a refused move, or the docs sentence.
