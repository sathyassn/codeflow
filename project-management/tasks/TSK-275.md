# TSK-275: codeflow ci gives one verdict for a range however it is spelled

## Description

`codeflow ci` gives different `work.acceptance_binding` verdicts for one
range when `--base` is a ref name or the commit id that ref points at
(https://github.com/sathyassn/codeflow/issues/141), and an explicit `--head` takes its branch context from the
checkout without saying so (https://github.com/sathyassn/codeflow/issues/130). After a sync merge of `main` into an
integration line, both lead the tool to recommend reopening tasks already
reviewed on `main`. At v3.1.0, `crates/codeflow-cli/src/cmd/ci.rs:471-477`
takes the acceptance target only from a named base, and
`crates/codeflow-cli/src/cmd/ci/acceptance.rs:276-281` picks the frozen or
amendable mode from it. This task resolves base, head and branch context
once, before any rule runs, and makes the output say where each came from.
The two issues share one cause and one code path, so they are one task.
Non-goal: attribution of commits that follow a merge (issue 69).

## Deliverables

- range and context resolution: `crates/codeflow-cli/src/cmd/ci.rs`, `crates/codeflow-cli/src/cmd/ci/acceptance.rs`
- tests: `crates/codeflow-cli/tests/ci_cli/`
- help and docs: the `--branch` help in `ci.rs`, `docs/cli.md`
- release note: `changelog.d/TSK-275.md`

## Acceptance Criteria

- AC-1 When one run names `--base` as a ref and another names the commit it
  resolves to, with the same `--head` and `--branch`, `codeflow ci` shall
  give the same verdict for every rule; evidence: a fixture of `main`
  merged into an integration line that holds a line-only file, run with
  both spellings (the issue 141 reproduction). (serves EPC-022 AC-1)
- AC-2 When the acceptance target cannot be derived from a commit-id base,
  the command shall reach the verdict the named base gives or refuse with a
  message naming `--into` or `--branch`, and never fall back silently to
  the frozen mode; evidence: one test per path. (serves EPC-022 AC-1)
- AC-3 When `--head` is given and the branch context comes from the
  checkout or CI metadata, the output shall name that context and its
  source, and before it recommends a reopen it shall tell the caller to
  pass `--branch` if the head belongs to another line; evidence: the issue
  130 reproduction from a detached checkout. (serves EPC-022 AC-1)
- AC-4 The `--branch` help and `docs/cli.md` shall say that the branch also
  selects the acceptance-binding mode (frozen or amendable); evidence: a
  help text test.
- AC-5 When an operator runs `codeflow ci --base <line tip> --head <sync
  merge>` with the installed build from a detached worktree of an
  integration line that merged `main`, the verdict shall be clean or name
  the context to pass, and shall not recommend reopening tasks reviewed on
  `main` (journey); evidence: a CLI journey on a scratch repository.
