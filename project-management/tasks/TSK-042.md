# TSK-042: verify portal composition per source

## Description

Today's browser verification samples the portal, so a single well-composed page
can carry a build in which most eligible sources are still re-rendered
Markdown. This task turns browser-verify into a per-source coverage gate:
after the TSK-037 page classes, the TSK-039 sources and the TSK-046 composed
views settle, every eligible source must show what its page class requires:
orient and architecture pages the altitude trio, record pages the composed
lookup carrier, and ADR pages the derived header with the append-only body
unchanged. A record page that is Markdown under the shell fails and is named,
and fixtures must prove the gate cannot be masked. It also
closes two holes the gate rests on: the portal validator accepting an empty
Pagefind entry file, and the adapter's HEAD-cleanliness check, which must
exempt harness litter without ever excusing a tracked or source-file change.
Non-goal: no page content is authored here and no page class is invented. The
gate enforces the doctrine and the sources as they already stand, and it lands
only after TSK-037, TSK-039, TSK-045 and TSK-046 conform.

## Affected surfaces and interfaces

`docs-portal/scripts/browser-verify.mjs`, `docs-portal/scripts/git-snapshot.mjs`,
the dirty-check in `docs-portal/scripts/lib.mjs`,
`docs-portal/scripts/evidence.mjs`, `docs-portal/tests/**` except
`composed-views.test.mjs`, the `assets/docs-portal/starter` mirrors of those
files with the same exception, and the portal validator
under `crates/codeflow-core/src/validate/` with its tests. CAP-015. The
validator's pass/fail contract is a gate other tasks depend on, so its
class rules are a public contract, not a local detail.

## Acceptance Criteria

- [ ] When any eligible source lacks what its page class requires,
      `browser-verify` shall fail the build and name the offending source;
      evidence: a fixture with one noncompliant eligible page fails and the
      failure message names that page.
- [ ] A compliant page shall not mask a noncompliant eligible page; evidence: a
      fixture containing both fails, proving coverage is per source and not
      sampled.
- [ ] Orient and architecture sources shall still be required to carry the
      altitude trio; evidence: a fixture orient page and a fixture architecture
      page each fail when a panel is removed.
- [ ] Record pages shall be required to carry the composed lookup carrier that
      TSK-046 emits, rather than being exempt; evidence: a composed record
      fixture passes and the same record shipped without its carrier fails.
- [ ] ADR pages shall be required to carry the derived header panels with the
      append-only body unchanged; evidence: an ADR fixture passes, one missing
      the header panels fails, and one whose body text differs from the source
      fails.
- [ ] A record page that is Markdown re-rendered under the portal shell shall
      fail and be named in the failure; evidence: the negative fixture fails and
      the message names that source.
- [ ] The class rules are explicit and enumerated in the verifier rather than
      inferred from a path heuristic; evidence: the rules are read from a single
      declared source and the tests assert their contents.
- [ ] The palette pills in both Display panels shall carry a canvas swatch and
      an accent swatch read from the live tokens; evidence: the swatch assertion
      in `npm run browser:verify` passes and fails when a swatch is hard coded.
- [ ] The starter mirror of the verifier and its tests is byte-identical to the
      live copies; evidence: the mirror equality check passes and fails when one
      copy is perturbed.
- [ ] The gate passes against the real portal only after TSK-037, TSK-039,
      TSK-045 and TSK-046 have landed on the integration branch, so it reviews
      the composed views on the new skins; evidence: a green run on the
      integration head, not on a fixture-only run.
- [ ] `codeflow validate --portal` shall itself reject an empty or malformed
      `dist/pagefind/pagefind-entry.json`, rather than leaving the defect to the
      browser search check that caught it during TSK-035; evidence: three
      validator tests, where a valid entry passes, an empty entry fails, a malformed
      entry fails.
- [ ] The adapter's HEAD-cleanliness check shall exempt a file only when it is
      untracked AND matched by the repository's `.gitignore` AND outside the
      configured source and runtime inputs, that is harness litter such as
      `.claude/.cc-writes` and `__pycache__`; a tracked modification stays dirty
      regardless of ignore patterns, and an untracked non-ignored source file
      stays refused; evidence: three fixture cases, tracked-but-ignored
      modification reads dirty, ignored untracked litter reads clean,
      non-ignored untracked source reads dirty.
