# TSK-042 — verify portal composition per source

## Description

Today's browser verification samples the portal, so a single well-composed page
can carry a build in which most eligible sources are still re-rendered
Markdown. This task turns browser-verify into a per-source coverage gate:
after the TSK-037 page classes and the TSK-039 sources settle, every eligible
source must show its required trio, with historical ADRs and records carrying
explicit exemptions, and fixtures must prove the gate cannot be masked.
Non-goal: no page content is authored here and no page class is invented — the
gate enforces the doctrine and the sources as they already stand, and it lands
only after TSK-037 and TSK-039 conform.

## Affected surfaces and interfaces

`docs-portal/scripts/browser-verify.mjs`, `docs-portal/tests/**`, and the
`assets/docs-portal/starter` mirrors of those files. CAP-015. The validator's
pass/fail contract is a gate other tasks depend on, so its exemption list is a
public contract, not a local detail.

## Acceptance Criteria

- [ ] When any eligible source lacks its page class's required trio,
      `browser-verify` shall fail the build and name the offending source;
      evidence: a fixture with one noncompliant eligible page fails and the
      failure message names that page.
- [ ] A compliant page shall not mask a noncompliant eligible page; evidence: a
      fixture containing both fails, proving coverage is per source and not
      sampled.
- [ ] Sources on the exemption list — historical ADRs and records — shall pass
      without a trio; evidence: an exempt-source fixture passes, and removing
      the exemption makes the same fixture fail.
- [ ] The exemption list is explicit and enumerated in the verifier rather than
      inferred from a path heuristic; evidence: the list is read from a single
      declared source and the tests assert its contents.
- [ ] The starter mirror of the verifier and its tests is byte-identical to the
      live copies; evidence: the mirror equality check passes and fails when one
      copy is perturbed.
- [ ] The gate passes against the real portal only after TSK-037 and TSK-039
      have landed on the integration branch; evidence: a green run on the
      integration head, not on a fixture-only run.
- [ ] Proposed amendment; needs both-seat approval at task start. Discovered
      2026-09-19: when a build's `dist/pagefind/pagefind-entry.json` is empty or
      unparsable, `codeflow validate --portal` or the adapter shall fail the
      build; evidence: a fixture with a zero-byte entry file fails validation.
      Rationale: a zero-byte entry file passed validation during TSK-035 and
      only the browser search check caught it.
