# TSK-146: SPC-013 split by area with stable requirement ids

## Description

SPC-013 is 85,000 bytes and 99 requirements (numbered R-1 to R-120 with
gaps) in one file, measured at `208f32565`; 138 files mention it, with 53
distinct `SPC-013 R-n` citations in records, docs and code. Every reviewer
and builder of an EPC-020 task reads a far larger contract than its task
needs, and every planning PR on the epic edits the same file. This task
splits SPC-013 into area files (lifecycle, acceptance, registry, lines and
release, guidance) with `SPC-013.md` kept as the record and index, and
changes no requirement's text or id. Documentation only: if the chosen
layout would need a validator change, the task stops and returns to
planning.

## Affected surfaces and interfaces

- `project-management/specs/SPC-013.md` and the new area files.
- `assets/base/rules/writing.md:157` (and its installed copies in
  `.codeflow/rules/` and `.codeflow/.baseline/`) quotes the header row of
  R-118's shared file table from `project-management/specs/SPC-013.md`,
  and TSK-131's test checks that each quoted example exists in its named
  source. R-118 is cross-cutting, so it stays in the index file and the
  shipped text does not change.
- `crates/codeflow-core/src/ids/entry.rs:418` names the SPC-013 path in a
  test.
- Shared files, per SPC-013 R-118: SPC-013 itself (this task after
  TSK-140's consolidation).

## Acceptance Criteria

- AC-1 When SPC-013 is split, every requirement id present at the split's
  base (99 at `208f32565`) and every planning resolution shall appear
  exactly once across the index and the area files, with its text
  byte-identical to the text at the split's base; evidence: a mapping
  check (script output in the pull request) from each id to its file.
- AC-2 When a record, doc, skill or test cites `SPC-013 R-n` or quotes
  SPC-013 text, the citation shall still resolve and every quote test
  shall pass, the `writing.md` example included; evidence: the
  mapping check over all citing files and the TSK-131 quote test.
- AC-3 `validate --docs` shall report the same records and findings
  before and after, with no validator change; evidence: both outputs.
- AC-4 When a task's work touches one area, its reading of SPC-013 shall
  be that area's file plus the index; evidence: the byte size of the
  index and of each area file in the Closeout, against 85,000.
