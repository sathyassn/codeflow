# TSK-222: The docs portal claim quarantine test passes on every run

## Description

The docs-portal test "unverified retired claims are quarantined without regaining authority" failed once in hosted CI (issue 51) and passed on rerun. Its "swap" case replaces the retired workflow claim by deleting the file and writing a new one. The product identifies a claim by device and inode number only (`sameFile` in `docs-portal/scripts/publication.mjs`). On a filesystem that reuses a freed inode number at once, such as ext4 on the Linux runner, the replacement can get the same inode, the product cannot tell it from the original, and `withWorkflowLease` returns "released" instead of failing with `CODEFLOW_WORKFLOW_CLAIM_QUARANTINED`. The assertion then sees `result?.code` as `undefined`. The fix is in the test, in this repository's copy and in the byte-identical shipped starter copy: the replacement is built under a temporary name while the original file still exists, so it cannot share the original inode, and the test asserts that precondition. Non-goal: changing the product's identity check. A swap that reuses an inode and carries the same valid lease is not distinguishable by inode, and that limit is recorded in the closeout rather than changed here.
