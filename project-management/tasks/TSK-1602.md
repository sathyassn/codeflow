# TSK-1602: Every existing exemption route is shown in every run and can move to the register

## Description

Owner: to be assigned by the Director. Staged 2026-11-23 for coord/records.

The operator's cross-cutting rule of 2026-11-23: every CodeFlow check is
configurable with sensible defaults, and its exemptions are tracked
records (exact path plus value or pattern, reason, approver, review or
expiry date), changed only through a reviewed pull request and always
shown in the output. TSK-424 (as amended by this plan) is the register.
Its own text excludes "the secret-scan and dependency-audit exemption
routes that exist today" (TSK-424 Non-goals, main `:103`). Today's
routes, read at `origin/main` d2307063f2 and the EPC-022 line tip
960eb7dbf4:

- `git.blocked_names` `except_under` with a reason (`policy-reference.md`
  main `:76`, tip `:81`);
- `git.protected_paths` `allow` with a reason; `git.ignored_files`
  `allow` with a reason (main `:77`, `:78`; tip `:82`, `:83`);
- `git.max_file_bytes` `except_under` (main `:79`, tip `:84`);
- `.gitleaksignore` fingerprints, read from the trusted commit
  (`policy-reference.md` "Secret-scan exemption pull requests", main
  `:1036`, tip `:985`; TSK-210, TSK-277);
- OSV-Scanner ignore entries with id, expiry and reason (TSK-297,
  TSK-1533).

None carries an approver, and most carry no expiry; several are not
printed when they apply. All already come from the default branch or the
trusted commit (ADR-0091 `:44`), which stays.

This task does not remove any route: the tool-native files (gitleaks,
OSV-Scanner) stay what the tools read. It makes every applied exemption
visible, reports each legacy entry that lacks the register's fields, and
lets a project move an entry into the register, after which the legacy
entry is generated from it.

Floors (TSK-1603). Every route above is an authorized exception, not a
floor operation: x2's floor list names the non-relaxable operations (for
example a head-held exception or a head lowering `git.secret_scan`), and
an authority-held `except_under`, `allow` or `.gitleaksignore` entry is
none of them. A migrated entry therefore stays valid, and TSK-424's floor
refusal (amended AC-20) does not refuse it.

Printed paths follow SPC-018 R-7a: a path that a privacy finding covers
is printed redacted, never in full.

## Outcome

After this merges, every run of a managed check that applies an
exemption from any route prints the entry, `codeflow doctor` lists each
legacy entry that lacks an approver or an expiry, and a project can hold
each such exemption as a register entry from which the legacy form is
derived.

## Deliverables

- an exemption-route inventory and adapters in `crates/codeflow-core/src/exemptions/` (TSK-424's module)
- the output line in the path gate, the secret scan step summary and the dependency audit step; `codeflow doctor --check exemptions`
- `codeflow exemptions migrate` (provisional) writing register entries for legacy ones, for the project to complete and commit
- docs: `docs/policy-reference.md`; `changelog.d/TSK-1602.md`

## Acceptance Criteria

- AC-1 Before any change, the builder shall record in `## Findings`, with file:line at the base, every route by which a managed check admits an exception or a lowered verdict, where it is read, whether it is read from the authority, and whether the run prints it; evidence: the Findings section, committed first.
- AC-2 Fail before: at the base, a commit admitted by a `blocked_names` `except_under` entry and a CI run passing on a `.gitleaksignore` fingerprint print no line naming the entry; evidence: the base outputs in the PR.
- AC-3 Pass after: each route's applied entries shall be printed in the run that applies them (hook, `codeflow ci` or the managed CI step), with path (redacted per SPC-018 R-7a when a privacy finding covers it), rule and reason, and the matched value never shown; evidence: one output test per route.
- AC-4 `codeflow doctor --check exemptions` shall list every legacy entry lacking an approver or an expiry, without failing, and name the migration command; evidence: doctor tests.
- AC-5 A migrated entry shall be a register entry with every field of its kind, the legacy form shall be derived from it and checked to match, and a mismatch shall fail `codeflow ci`; no exemption shall apply more widely or more narrowly after migration than before, and TSK-424's floor refusal shall accept every migrated authority-held entry; evidence: a test per route comparing the admitted set before and after, run with the floor check of TSK-1603 active.
- AC-6 No route shall start reading an exception from anywhere but the default branch at one commit or the trusted commit it reads today; evidence: the existing authority tests passing unchanged.
