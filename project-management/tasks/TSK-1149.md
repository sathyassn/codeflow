# TSK-1149: A task branch can push its own line sync before review

## Description

The pre-push `work.acceptance_binding` check, which TSK-1066 extended to a
task branch's pull request into an epic line, also ran on every push of
that task branch, because the hook hands `codeflow ci` the branch's
declared target. A task branch whose merge of its own target line needed
hand-resolved conflicts could not be pushed until a review of the head was
recorded (seen on PR 458 at 3242c26e2, merge edbe5a430: 8 findings). A
push keeps work durable; the review belongs at ready and at landing.

This task lets that push through and keeps every other judgment. In the
pre-push hand-off only (the hook's advertisement, no pull request body or
event), for a branch that carries a task and is neither protected nor an
epic line, `receiving_merges` skips a merge whose parents after the first
are all the target line's advertised tip or its ancestors. The facts used
are the merge's parents and the destination's advertised tip of the
target, never a name the pusher chooses. Non-goals: the pull request
check, the line push, the acceptance-block edit check from TSK-1066 and
the landing path are unchanged.

## Outcome

After this merges, a builder can push a task branch that merged its own
target line with hand-resolved conflicts, and `codeflow ci` at ready and
at landing still refuses those hunks until the head's review is recorded.

## Deliverables

- Push-only relaxation: `crates/codeflow-core/src/workgraph/acceptance/receiving_merges.rs`, `crates/codeflow-core/src/workgraph/acceptance.rs`, `crates/codeflow-cli/src/cmd/ci/acceptance.rs`, `crates/codeflow-cli/src/cmd/ci.rs`
- Real-hook tests: `crates/codeflow-cli/tests/acceptance_cli/line_sync_push.rs`

## Acceptance Criteria

- AC-1 When a task branch whose merge of its own target line needed hand-resolved conflicts is pushed through the installed pre-push hook, the push shall succeed and the destination shall hold the head; evidence: `line_sync_push::a_task_branch_pushes_its_hand_resolved_line_sync_and_ready_still_refuses`, failing before the change with the PR 458 refusal (journey)
- AC-2 When `codeflow ci` judges the same head as the pull request into the line without a review of it, it shall still refuse with `work.acceptance_binding` naming the merge and the file; evidence: the same test
- AC-3 When the pushed merge brings in anything the line's advertised tip does not hold, or the pushed branch carries no task, is protected, or is the line itself, the push shall keep today's refusal; evidence: `a_hand_resolved_merge_of_main_still_refuses_the_push`, `a_non_task_or_protected_branch_keeps_the_refusal`, `a_push_of_the_line_itself_keeps_the_refusal`
- AC-4 The TSK-1066 pull request and line push judgments shall be unchanged; evidence: `acceptance_cli sync_merges` passes unchanged
