# TSK-1137: capability migrate converts the legacy catalog into records in one run

## Description

The tool half of design unit U2. `codeflow capability migrate` registers the legacy numbers with minted `uid`s, extracts each entry's fence fields and following prose into a record (with page and anchor merge for entries that own a page), and refuses an ambiguous prose span before any write. On 2026-11-06 the re-grade at claim scored the merged scope Very Hard, 10, so AC-4 to AC-6 (the rerun, the converted-entry judgement and the clash repair) moved to TSK-1360 AC-1 to AC-3 and this task keeps the one-run conversion; ids AC-4 to AC-6 are not reused. Basis: the conversion verb and its byte-comparison fixtures. Security review owed: the verb writes repository files from parsed content. Non-goal: the rerun and repair path (TSK-1360) and running it on CodeFlow's own catalog (TSK-1138).

Design: `coordination/coordinators/capabilities/design-note.md` revision 5 (workspace repository) and its acceptance tests.

## Outcome

After this merges, a project with a legacy fence catalog can convert it to records with one command.

## Deliverables

- the verb: `crates/codeflow-cli/src/cmd/capability.rs` and `crates/codeflow-core/src/capability/migrate.rs`
- legacy registration through the ids registry
- fixtures for the conversion and the merge cases: `crates/codeflow-cli/tests/`

## Acceptance Criteria

- AC-1 `migrate` on a 17-entry fixture shall first register 17 numbers with minted `uid`s, then produce 17 records whose fields equal the fence fields and whose prose equals the following prose byte for byte, with page and anchor entries keeping their pages; evidence: a byte comparison test. (serves EPC-026 AC-5)
- AC-2 An ambiguous prose span shall refuse before any write; evidence: a fixture and a no-write assertion. (serves EPC-026 AC-5)
