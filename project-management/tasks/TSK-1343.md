# TSK-1343: A fork pull request named like a line never reaches the line class

## Description

Source: the delta review of PR 613 (TSK-1320) at `8a9d56424`, confirmed by the Director on 2026-11-05 and ruled the first item in the guards order. It is a CI admission trust defect, so it runs as CI/CD work.

A fork can name its branch after a line. `.github/workflows/codeflow-policy.yml:220` takes `HEAD_REF` from `pull_request.head.ref` and `:230` passes it to `codeflow ci --branch`. `epic_line_proof` (`crates/codeflow-core/src/workgraph/work_start.rs:729`) checks the name grammar, the records, the target and the first-parent shape. It has no check of the head repository, and it does not compare the head with the line's fetched tip. `Class::EpicLine` and `Class::RootBranch` lift the criteria freeze (`crates/codeflow-cli/src/cmd/ci/acceptance.rs:546`), and the open PR 613 adds trust in the range head for the line class.

The workflow can already tell a fork apart for the actor: `:222` sets `ACTOR` to `unknown` when the head repository differs. It does not do so for the branch class. Whether `unknown` narrows the path is not known; the fixture settles it.

Read and not run. Exposure at the Director's check on 2026-11-05: 0 forks and 0 open fork pull requests, on a public repository that allows forking. The operator's merge into `main` is the remaining barrier. The defect predates this work.

The check runs on `pull_request_target` from the default branch and refuses any other event (`codeflow-policy.yml:3-5,47-48,79`), and it never runs head code, so a fork's edit to the workflow does not change it. It also means the protection takes effect when this fix reaches `main`, since the job builds from the authority. GitHub blocks `pull_request_target` by default in public repositories from 2026-12-02; TSK-1347 keeps the check running, and a design change there is checked against this task.

The class is not the only trust a name grants. `ci.rs:677` (`verified_epic_line` feeds `record_checks`), `classification.rs:339-366` (`integration_line_eligible`), `workgraph/acceptance.rs:4346` (line bases) and `context.rs:400` key on the name and `epic_line_proof`, whatever the class, so a fork whose body says `Task: TSK-NNN` skips `Class::EpicLine` and still reaches `ci.rs:677`. Read, not run. An empty body with the root branch's name gives `Class::RootBranch` on the name alone (`classification.rs:273`).

GitLab has the same threat: `assets/base/ci/.gitlab-ci.yml:65-66` handles a pipeline that runs in a fork, and `ci.rs:2755-2758` takes the branch from the merge request's source branch. The Bitbucket and generic templates run the same check. None of the three passes a head repository today.

TSK-1089 would have given a maintainer's topic branch carrying only the line's commits the line's treatment, with heads that differ from the line's tip by design. It was cancelled on 2026-11-12 by the operator's decision D6 and its scope dropped, so this task has no such rule to keep for same-repository branches.

- Amended 2026-11-12 (coord/records), by the operator's decision D6 of about 10:36: TSK-1089 is cancelled and its scope dropped. Was: "TSK-1089, still to build, gives a maintainer's topic branch carrying only the line's commits the line's treatment, and its heads differ from the line's tip by design. This task keeps that rule for same-repository branches and closes it to forks."

Non-goals: a same-repository topic branch judged as the line. TSK-1089 owned it until it was cancelled on 2026-11-12 by the operator's decision D6, its scope dropped.

- Amended 2026-11-12 (coord/records), by the same decision. Was: "Non-goals: a same-repository topic branch judged as the line, which TSK-1089 owns."

## Outcome

After this merges, a pull request from a fork that names its branch after a line or root branch is refused or judged as ordinary work, whichever the sweep settles, so it never lifts the criteria freeze or gains the trust a line has. A maintainer's own line pull request is admitted as before.

A hosted run below means a run of `codeflow ci` judging a hosted pull request or merge request event.

- AC-1 Before any product change, a fixture shall run a hosted run with a fork's head repository, a head branch named like a line and like the root branch, and `ACTOR` set to `unknown`, each with no `Task:` line, an empty body and a `Task: TSK-NNN` body, and shall record which class and line treatment it reaches. The builder shall also list every site that grants line treatment by name, with a verdict for each, starting with the sites in the Description and those in TSK-1089's Description; evidence: the test and a `## Findings` entry. If the fixture narrows the finding, the entry says how and the binding is still added.
- AC-2 When a hosted run's head repository is not the base repository, `codeflow ci` shall never assign a line or root-branch class or any listed line treatment, whatever the branch is named; evidence: a test that fails before the change and passes after it, for both classes, including the `Task: TSK-NNN` body.
- AC-3 In a hosted run, the line class and each listed line treatment shall hold only when the head repository equals the base repository and the head SHA equals the line's fetched tip; neither the branch name nor any other value the requester chooses shall establish them; evidence: tests for a same-repository head that differs from the fetched tip, and for a matching head.
