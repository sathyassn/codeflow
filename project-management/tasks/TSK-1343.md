# TSK-1343: A fork pull request named like a line never reaches the line class

## Description

Source: the delta review of PR 613 (TSK-1320) at `8a9d56424`, confirmed by the Director on 2026-11-05 and ruled the first item in the guards order. It is a CI admission trust defect, so it runs as CI/CD work.

A fork can name its branch after a line. `.github/workflows/codeflow-policy.yml:220` takes `HEAD_REF` from `pull_request.head.ref` and `:230` passes it to `codeflow ci --branch`. `epic_line_proof` (`crates/codeflow-core/src/workgraph/work_start.rs:729`) checks the name grammar, the records, the target and the first-parent shape. It has no check of the head repository, and it does not compare the head with the line's fetched tip. `Class::EpicLine` and `Class::RootBranch` lift the criteria freeze (`crates/codeflow-cli/src/cmd/ci/acceptance.rs:546`), and the open PR 613 adds trust in the range head for the line class.

The workflow can already tell a fork apart for the actor: `:222` sets `ACTOR` to `unknown` when the head repository differs. It does not do so for the branch class. Whether `unknown` narrows the path is not known; the fixture settles it.

Read and not run. Exposure at the Director's check on 2026-11-05: 0 forks and 0 open fork pull requests, on a public repository that allows forking. The operator's merge into `main` is the remaining barrier. The defect predates this work.

Not checked: whether a fork's own edit to the workflow file changes what this check runs in a `pull_request` event. The builder records the answer in `## Findings`.

Non-goals: a same-repository topic branch judged as the line, which TSK-1089 owns and which keeps its own refusal.

## Outcome

After this merges, a pull request from a fork that names its branch after a line or root branch is judged as ordinary work, so it never lifts the criteria freeze or gains the trust a line has. A maintainer's own line pull request is admitted as before.

## Deliverables

- the binding in `epic_line_proof` and the root-branch class, and whatever `codeflow ci` input carries the head repository: `crates/codeflow-core/src/workgraph/work_start.rs` and `crates/codeflow-cli/src/cmd/ci/` (provisional; the builder places it)

## Acceptance Criteria

- AC-1 Before any product change, a fixture shall run a pull request event with a fork's head repository, a head branch named like a line and like the root branch, and `ACTOR` set to `unknown`, and shall record whether it reaches the line or root-branch class; evidence: the test and a `## Findings` entry. If the fixture narrows the finding, the entry says how and the binding is still added.
- AC-2 When a pull request's head repository is not the base repository, `codeflow ci` shall never assign a line or root-branch class, whatever the branch is named; evidence: a test that fails before the change and passes after it, for both classes.
- AC-3 The line class shall hold only when the head repository equals the base repository and the head SHA equals the line's fetched tip; neither the branch name nor any other value the requester chooses shall establish it; evidence: tests for a same-repository head that differs from the fetched tip, and for a matching head.
- AC-4 When `codeflow ci` cannot read the head repository, the base repository or the line's fetched tip, it shall refuse the line and root-branch classes and name what it could not read; evidence: one test per missing input.
- AC-5 A maintainer's own line pull request and a pre-push run of a line shall keep working; the builder states how a run with no pull request event is classed, and that path shall not let a hosted run reach the class; evidence: tests for both paths, and the statement in `## Findings`.
- AC-6 TSK-1089's refusal of a topic branch judged as the line shall hold; evidence: a test naming that case, or that task's test if it has landed.
- AC-7 The pull request shall state the threat this closes and why binding to these identities is the standard design; evidence: the PR body.
- AC-8 The change shall have a cross-lineage security review with the `cf-security-reviewer` checklist: Grok or Codex when a live probe at dispatch shows usage, else a fresh Claude Opus medium subagent with reduced assurance recorded; evidence: the review row and its findings record.
- AC-9 (journey) With the installed build in a scratch repository, a same-repository line head and a head recorded as coming from another repository shall each be run through `codeflow ci`, and only the first shall be judged as the line; evidence: the journey output, naming that no real fork was used.
