# TSK-1319: The Windows test plan stays runnable when a pull request adds tests

## Description

The Windows test plan check refused PR 552 (head e4cf6f7c6, run 41769024831, job 126374105887) because partition 1's filterset reached 32,530 characters against a limit of 32,167, which stopped all of that PR's Windows proof. This task keeps the plan runnable when a pull request adds tests, and makes the refusal name its real cause. It changes `scripts/windows-partitions.py` and its data only. It moves no limit and edits no workflow. The path is this repository's own CI, shipped to no adopter, so no criterion is a journey.

Findings, from the unchanged script on a rebuilt listing (run 41763959485's real test list plus the 20 Windows tests PR 552's diff adds): 517 of 5965 tests outside the measurements, as the job printed, and filtersets of 32,498 and 16,502 characters against the job's 32,530 and 16,515. The difference is module paths inferred from the diff.

- The line tip was already at 31,238 characters, 97 percent of the limit. PR 552 added 1,292 (1,260 in the rebuild), about 63 per test, and the rest of the distance was already used.
- `codeflow-core`'s exclusion list was 26,349 of those characters: 302 tests, 249 of them outside the measurements. Each new test was its own unit, so it left the binary's home partition and had to be excluded there by its full name, about 85 characters.
- Two long exclusion lists on one partition is not the cause: from 0 to 60 added tests, the homes of the four largest lists (`codeflow-core`, `hooks_cli`, `ci_cli`, `acceptance_cli`) stayed on separate partitions. Placement does move the length between neighbouring counts, by up to about 1,100 characters on the tip's plan (31,153 to 32,304 over 1 to 16 added tests), so a plan this close to the limit could cross it on a small step.
- The flat `default_seconds` guess was right in total (2,387 seconds against 2,325 real, five green runs) and wrong per binary: `codeflow-core` tests take 0.55 seconds against the guess of 4.8, so spreading them bought no balance, and `acceptance_journey` tests take 106 seconds.

## Outcome

After this merges, an author on the line who adds a normal number of tests gets a Windows plan that can run, and a refusal that names the binary and the exclusion list that caused it.

## Deliverables

- the placement, sizing and message changes: `scripts/windows-partitions.py`
- the tests: `scripts/test_windows_partitions.py`
- the refreshed measurements: `scripts/windows-test-times.json`

## Acceptance Criteria

- AC-1 The cause of PR 552's refusal shall be shown from a reproduction: the unchanged script on a listing rebuilt from run 41763959485's real test list plus the tests PR 552 adds; evidence: drift output matching job 126374105887's counts (517 of 5965), the filterset lengths, and which binary's exclusion list carries them.
- AC-2 A new test shall cost a filterset no characters unless moving it pays for them: a new test of a known binary shall be sized at that binary's measured mean, and shall stay with its binary's rest while the guessed time gathered there is small; a slow one and the overflow spread as before; evidence: unit tests, and the per-binary comparison of real and guessed seconds.
- AC-3 Fail before, pass after: a plan built from the committed measurements plus 300 planted fast new tests in `codeflow-core` shall fail `drift` on the filterset limit with the old script and pass with the new one; the PR 552 listing shall behave the same; evidence: both outputs.
- AC-4 No limit moves: FILTERSET_LIMIT (32167), UNMEASURED_SHARE (10 percent), UNMEASURED_PARTITION_MINUTES (1.2), PLAN_MINUTES (12), MARGIN_MINUTES (24) keep their values, and a new binary and a slow new test still spread; evidence: the diff and the existing tests; any change in what a check reads shall be stated in the PR.
- AC-5 The messages shall name the real cause: the refusal names the binary, the size of its exclusion list and how many of those tests are unmeasured; the `longest filterset` line counts a refused filterset; evidence: unit tests.
- AC-6 The measurements shall be refreshed with `measure` from named green runs so the next batch is not near a limit; evidence: run ids and `drift` output before and after on the real listing.
