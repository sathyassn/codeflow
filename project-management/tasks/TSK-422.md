# TSK-422: The coordination ledger has its contracts, store and follow command

## Description

Issue #272, items 2 and 4 and the comment of 2026-10-21, under
ADR-0086 as the operator decided on 2026-10-22 and as the independent
Codex review of the design (sound with changes, 22 findings, 14 high)
settled it. An orchestrating session owns a "task ledger" that CodeFlow
gives no shape, no closure rule and no home; in an adopting project a
hand-written ledger stopped after nine days, handed-over items went
quiet, a merge of lane stocktakes produced about 940 rows mostly
duplicating tracked work, and a deleted lane lost what only its
conversation held. This task ships the shared contracts first (actors,
references, transitions, transactions), then the store and the
`follow` command on them, with its own docs, help and tests.

Outcome: **the coordination ledger lives in the clone's common git
directory (`.git/codeflow/coord/`) as one append-only JSON Lines event
log with one sequence, liveness in overwritten status files, and
`codeflow follow` keeps follow-ups `FU-NNN` as full records with typed
links, derived due times, closure only on target-aware proof by an
allowed actor, exact-duplicate refusal, bounded and scanned text, and a
read-only status that never writes; and `codeflow work status` lists
per task the worktrees with uncommitted changes, unpushed commits and
commits on no branch.**

The contracts, decided by ADR-0086 and applied here:

- **Store** (location A): `events.jsonl` (the one coordination log:
  stream, follow-up, lane and coordinator events, one sequence), `status/`
  (overwritten liveness files, one per holder, never a log),
  `counters.json` (reserved FU and LN numbers, reserved before use,
  gaps allowed, never lowered), `coord.lock` (a stable sidecar lock,
  never removed or replaced) and `instance.json` (this ledger's UUID;
  FU and LN numbers are local display ids within it). Paths come from
  Git's own common-dir discovery (`hooks/repo.rs` `RepoInfo::discover`,
  `ids/state.rs`), never a literal `.git/`. The supported live scope is
  one clone on one machine; an exported reference is qualified by the
  instance UUID; import is recovery into an empty instance or an
  explicit reconciliation, never a live lease. No compaction in the
  first cut; the 10,000-event read path is measured.
- **Transactions.** One append is one commit, under the lock, with
  `sequence` assigned there; sync before success is reported; a
  retriable operation carries an idempotency key; a torn tail is
  repaired or quarantined under the lock before the next append;
  interior damage, a duplicate or decreasing sequence, a broken
  transition or an unknown state-changing schema version makes the
  ledger read-only with a diagnostic; events are validated on replay as
  on input; hooks wait a bounded time for the lock and report busy as
  distinct from empty; readers use the committed prefix; network and
  model work run outside the lock and revalidate the expected revision
  on commit. Tested on macOS, Linux and native Windows with `fs2`
  advisory locking; shared network filesystems are not supported.
- **Envelope**, field names in full: `schema_version`, `event`,
  `subject_id`, `sequence`, `recorded_at` (UTC, for people, never for
  order), `recorded_by` (role `coordinator`, a lane id or `operator`;
  an actor instance id always; harness, model and session id when
  known, unknowns explicit), optional `comment`; a mutation that
  depends on ownership carries the expected generation and entity
  revision and is refused when stale.
- **A follow-up is a full record** for a cold reader. Required:
  `title`, `description`, `done_when`, `source` (operator,
  coordinator, a lane id, a review, an issue, outside),
  `source_reference` where one exists, `stream` (the `WS-NNN` it
  belongs to, or the project intake list until a coordinator takes
  it), `holder` (`coordinator` or a lane id), `links` typed `context`, `prerequisite` or `fulfils` (each
  with repository identity and the record UID where one exists) or a
  `no_link_reason`, and an effective schedule (`next_check` supplied
  or filled by the documented default). Optional: `waits_on`,
  `awaiting_operator` (a condition, never a holder). Dropped from the
  first cut: `priority`.
- **Events**: `item_added`, `item_updated` (never `source`),
  `item_checked` (what was observed and the next check),
  `item_handed_over`, `item_closed` (evidence marked `asserted` or
  `machine_verified`, a reference a fresh session can open, the
  applicable revision and target), `item_dropped` (reason; the
  disposition of what it leaves), `item_reopened` (a reverted or
  invalidated proof keeps the old proof in history).
- **Links and due times.** A `prerequisite` changing state (claimed,
  complete, blocked, cancelled; a pull request merged, closed or its
  checks finished; a lane reporting, idle or stale; another follow-up
  closed; a time passed) makes the follow-up due, never closed. Only a
  declared `fulfils` condition whose evidence satisfies `done_when` on
  the target, judged through the existing target-aware readiness and
  acceptance machinery (`workgraph/readiness.rs`), closes it
  automatically, naming the observation source, repository, target,
  revision and time; completion on a feature branch never counts. A
  cancelled task makes its follow-ups due for relinking or an explicit
  drop. A dependency wait has a maximum recheck time and records the
  observed dependency version. Cycles and reference integrity are
  checked on every dependency change, under the lock.
- **A lane is optional.** A follow-up held by the stream's coordinator
  itself, with no lane, is tracked, checked and closed on the same
  proof as a lane-held one; direct work by the coordinator is work.
- **Permission matrix**, one for every action: any bound actor adds;
  the holder updates, checks and hands over; the holder closes and
  drops, and the stream's coordinator may drop with a reason; a
  cross-stream wait names another stream's item or lane by id and is
  read-only; the operator's
  answer is recorded with its source, never as the operator; the
  operator may run the commands by hand, recorded as the operator.
  Every actor is bound to its instance and generation.
- **Dedupe.** Only an exact duplicate (same source identity or
  idempotency key) is refused, atomically; similar follow-ups and
  matching open tasks, epic criteria and feedback items are suggested
  with a link or reject reason, never blocked.
- **Privacy.** Every free-text field is scanned after decoding and
  size-bounded without echoing a rejected secret; files and directories
  are private with symlink and path checks; rendering to terminal and
  Markdown is safe; an explicit purge and repair path exists; the
  opt-in snapshot is never committed automatically and is exported
  redacted; a reader never assumes a line was validated on write.
- **Read-only status.** `follow list` (table or `--md`, bounded: counts,
  the urgent subset and a pointer to the full list) never writes,
  claims a role, refreshes a heartbeat or creates a lock; a denied read
  is `unavailable`, no ledger is `empty`, a denied write is `unwritten`.
  Heartbeats are refreshed only by bound mutating operations (TSK-439
  names them); an unbound observer reads and gets no heartbeat.
- **Role binding.** This task ships the actor and binding contracts and
  binds actors in tests through a fixture; the commands that claim,
  release and adopt roles are TSK-439's, and the stream and status
  surfaces are TSK-439's and TSK-440's.
- **An aid, not a control.** Nothing here blocks git, records, CI or
  landing; a missing or damaged ledger only warns; the ledger reads
  task, epic and ADR state and never writes a record; records, pull
  request bodies and `codeflow ci` never cite FU, LN or WS ids and
  never read the ledger.

Non-goals: lanes, attempts, streams and the coordinator lease, with
their commands (TSK-439); the hook surfaces and `coord status`
(TSK-440); the rules and the fresh-context test
(TSK-423); compaction; cross-machine coordination; semantic duplicate
refusal.

## Deliverables

- the shared contracts: `crates/codeflow-core/src/coord/` (new; `actor.rs`, `reference.rs`, `transition.rs`, `store.rs` with the lock, sequence, sync, idempotency and tail-repair rules, `schema.rs` with the envelope and the per-event validation), with the schema documented in `docs/policy-reference.md`
- the follow command: `crates/codeflow-cli/src/cmd/follow.rs` (new; `add`, `update`, `check`, `hand-over`, `close`, `drop`, `reopen`, `list`, `snapshot`, `purge`) wired in `crates/codeflow-cli/src/main.rs`, with its CLI help
- the due derivation and target-aware fulfilment: `crates/codeflow-core/src/coord/due.rs` reusing `workgraph/readiness.rs` and the record readers
- `work status`: `crates/codeflow-cli/src/cmd/work.rs` and the worktree reader in `crates/codeflow-core/src/root_checkout.rs` or a sibling
- the ledger-free guarantee: a test module in `crates/codeflow-cli/tests/` that runs `ci`, pre-push, `task status`, `work claim`, `work start` and `integrate` with the store absent and damaged, and the validate and ci checks for FU, LN or WS ids in records and bodies
- tests: `crates/codeflow-cli/tests/follow_cli.rs` (new), `coord` unit tests, process-level lock tests on macOS, Linux and native Windows, and the 10,000-event benchmark under `crates/codeflow-core/benches/` or a test with a recorded figure
- the schema reference, shipped with the store: a field-level reference of the data model (every event's fields by log kind, the follow-up record, the lane, seat and attempt records, the coordinator claim with stream, actor instance and generation, the work stream) in `docs/coordination-ledger.md` (provisional) with a fenced ASCII figure of the entities (work stream; coordinator claim carrying stream, actor instance and generation; lane carrying its stream; seats and attempts under a lane; follow-up carrying stream, holder, coordinator or lane, and typed links to tasks, pull requests and records; every event in one log with subject id and sequence), mirrored in `cf-present` where the skill explains the model and linked from `docs/cli.md`
- docs: `docs/cli.md`, `docs/policy-reference.md` and the working-state line in `docs/architecture.md`
- release note: `changelog.d/TSK-422.md`

## Acceptance Criteria

- AC-1 `codeflow follow add` from any bound actor shall reserve `FU-NNN` ahead of use (gaps allowed, never lowered) and append a schema-valid `item_added` carrying the full record (title, description, done_when, source and reference, stream or the intake list, holder, typed links or no_link_reason, an effective schedule), the other verbs shall append `item_updated` (never `source`), `item_checked` (observation and next check), `item_handed_over`, `item_closed`, `item_dropped` and `item_reopened` by the permission matrix (a close by a non-holder, a drop without a reason, and an operator-role event from an agent session that carries its harness marker each refused; an agent that removes the marker and runs under a pseudo-terminal is a documented residual in `docs/coordination-ledger.md`, "The operator"), a malformed envelope or event shall be refused on input and on replay, and `list` shall show the folded state as a bounded table and as Markdown; evidence: CLI tests per verb and per refusal, and a cold-reader check that an item renders without its conversation. (serves EPC-025 AC-1)
- AC-2 A `prerequisite` link changing state (task claimed, complete, blocked or cancelled; pull request merged, closed or checks finished; lane reported, idle or stale; another follow-up closed; a time passed) shall make the follow-up due and never close it; only a `fulfils` condition whose evidence satisfies `done_when` on the target through the target-aware readiness machinery shall close it, recording source, repository, target, revision and time, and a completion on a feature branch shall not; a cancelled task shall make its follow-ups due; a reverted or invalidated proof shall reopen with the old proof kept; evidence: one test per transition, the branch-deletion case from the design kept open until deletion evidence exists, and a revert test. (serves EPC-025 AC-1)
- AC-3 The store shall be one `events.jsonl` with one sequence assigned under the stable sidecar lock, `status/` liveness files, `counters.json`, `instance.json` with a UUID, and no compaction; an append shall be synced before success, a retried operation with the same idempotency key shall not duplicate, a torn tail shall be repaired or quarantined before the next append, interior damage, a duplicate or decreasing sequence, a broken transition or an unknown state-changing schema version shall make the ledger read-only with a diagnostic, hooks shall wait a bounded time and report busy as distinct from empty, three concurrent appenders shall never corrupt it or repeat a sequence, and paths shall come from Git's common-dir discovery in standard, linked, relocated and read-only repositories and across two worktrees with different binary versions; evidence: process-level tests on macOS, Linux and native Windows with fault injection for each case. (serves EPC-025 AC-1)
- AC-4 Every free-text field shall be scanned after decoding and size-bounded without echoing a rejected secret, the files shall be private with symlink and path checks, rendering shall be safe, `purge` shall remove a named item's text from the live log and any derived index, `snapshot` shall export redacted and never commit, and a reader shall validate what it folds; evidence: tests with a planted token, control characters, an oversized field and a symlinked directory. (serves EPC-025 AC-1)
- AC-10 Every follow-up shall carry a stream field (a stream id or the project intake list, validated at the store level against fixture stream ids until TSK-439 ships the stream commands), an operator ask shall go to the stream concerned or to the intake list, and a cross-stream wait shall name another stream's item or lane by id and never write it; evidence: store-level tests with two fixture streams and an intake item. The stream commands, the two-coordinator journey and `codeflow coord status` are TSK-439's and TSK-440's. (serves EPC-025 AC-1)
- AC-5 Only an exact duplicate (same source identity or idempotency key) shall be refused, atomically and under concurrent adds; similar follow-ups and matching open tasks, epic criteria and feedback items shall be suggested with an explicit link or reject reason, never refused; cycles and reference integrity (record UID and repository identity where available, resolved through records and the registry, not titles) shall be checked on every dependency change; evidence: CLI tests over fixture records, a renamed-task test and an update-introduced cycle test. (serves EPC-025 AC-1)
- AC-6 `follow list` and every status read shall never write, claim a role or create a lock, shall report no ledger as empty, a denied read as unavailable and a denied write as unwritten, and shall fold once per invocation with the 10,000-event figure (large open set, concurrent appenders, one check) recorded; evidence: a read-only filesystem test, a strace or equivalent write count, and the benchmark figure. (serves EPC-025 AC-1)
- AC-11 A follow-up whose holder is the stream's coordinator, with no lane, shall be added, checked and closed on a `fulfils` proof exactly as a lane-held one is, with the same permission matrix and auto-close, and shall appear in `follow list` under the coordinator; evidence: a CLI test that runs the lane-held and the coordinator-held item through the same sequence and compares the folded states. (serves EPC-025 AC-1)
- AC-12 A field-level schema reference shall ship with the store, documenting every event kind's fields, the follow-up, lane, seat, attempt, coordinator claim and work stream records, with one fenced ASCII figure of the entities and their references by id, and `codeflow validate --docs` shall accept it; evidence: the document, the figure and a test that every event kind the schema validates is documented. (serves EPC-025 AC-1)
- AC-7 `codeflow work status` shall list, per task, each worktree with uncommitted changes, unpushed commits and commits on no branch, read from git, naming missing or pruned objects as not recoverable; evidence: a CLI test over a fixture with one of each. (serves EPC-025 AC-1)
- AC-8 The ledger shall be an aid and never a control: `codeflow ci`, pre-push, `task status`, `work claim`, `work start` and `codeflow integrate` shall give the same verdict with the ledger present, absent or damaged, a damaged ledger shall only warn, the coord module shall never write under `project-management/` or `docs/`, `codeflow validate --docs` shall flag a task, epic or ADR record and `codeflow ci` a pull request body that cites an FU, LN or WS id, and the guards shall allow CodeFlow's own writes under the coord directory and refuse an agent's direct edit under TSK-379's reach rule; evidence: a fixture run of each command with the store absent and with a corrupted log, a code search, validate and ci tests with a planted FU id, a planted LN id and a planted WS id, and guard tests. (serves EPC-025 AC-1)
- AC-9 (journey) With the installed build in a scratch adopter project with two worktrees, two actors bound through the test fixture with distinct actor instance ids (the role commands are TSK-439's) shall each add follow-ups, one linked `fulfils` to a task and one with a `no_link_reason`, the second actor shall close its own on a commit reference and be refused closing the first's, the task's landing on the target shall close the fulfilled item with machine-verified evidence, `follow list --md` from either worktree shall show the same folded state, and `codeflow ci` on a branch shall give the same verdict with the ledger removed; evidence: the journey output. (journey)

## Execution contract

- Source: issue #272, ADR-0086 and the Codex review of the design (F01, F04 to F09, F15 to F20 settled here).
- Likely release impact: minor (a new command and `work status` output).
- Builder: Claude Opus 5.5 at high, a native subagent of the primary's session. Not routine: the transaction, lock and closure contracts carry the epic.
- Reviewer: Codex GPT-6 Astra at high, interactive Herdr seat, one independent whole-unit pass; the primary routes Grok 4.7 at high as the cross-family reviewer when both Claude and Codex authored the unit.
- Seats are the plan's; they are confirmed at dispatch, and a change of builder or reviewer lineage is a reassignment in the batched epic amendment.
- Security review: yes, `cf-security-reviewer` (a writable store under the git directory, scanned text, the guards' reach rule and the ledger-free guarantee).
- Affected surface: adopter-facing CLI, `work status`, `validate --docs` and `codeflow ci` (the FU and LN id check), and the clone's git directory.
- Edges: a root of EPC-025; TSK-439, TSK-440 and TSK-423 depend on it. Shares `cmd/work.rs` with TSK-341 and TSK-416 (EPC-022), `readiness.rs` with TSK-339 and TSK-341, and `.git/` reach with TSK-379; one writer at a time.
