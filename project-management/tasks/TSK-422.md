# TSK-422: An orchestrator's follow-up ledger is a command whose rows close on proof

## Description

Issue #272, proposal items 2 to 4 and the comment of 2026-10-21. An
orchestrating session owns a "task ledger"
(`cf-model-orchestrator/SKILL.md:63`) that CodeFlow gives no shape, no
closure rule and no place in the session loop. In an adopting project
with six lanes, a hand-written ledger stopped being updated after nine
days, items the operator handed over went quiet, and status was
assembled from memory. Merging the lanes' stocktakes by hand produced
about 940 rows, most of them work already tracked as tasks or criteria
in other words. A half-hourly sweep scheduled inside the coordinator
session was lost with the session; a deleted lane recovered only what
its own tracker file held, losing uncommitted edits, running seats and
in-flight reviews.

Outcome: **a small command surface keeps the host's open commitments
as structured rows with a fixed schema in the project's untracked
state, refuses a row that duplicates an open CodeFlow record until the
author links or rejects the match, closes a row only on proof, and
`codeflow orient` and the SessionStart digest print the open, overdue
and operator-owned rows at every session start; and `codeflow work
status` lists, per task, the worktrees with uncommitted changes,
unpushed commits and commits on no branch.**

Decisions recorded here:

- **Command** (provisional `codeflow follow add|update|close|list`), one
  structured file (provisional `.codeflow/local/follow.json`, untracked
  through the managed ignore) with the fields: id, what, source,
  holder, task id or `needs task`, waits on, next check, running seat
  (seat, worktree, head) while one runs, and closure proof.
- **Closure on proof.** `close` takes a proof: a merged pull request or
  a commit, a recorded ruling, or the operator's answer quoted with its
  date; "handed to a lane" is not one. A row that points at a task
  closes when that task closes, with the task's proof, which `list`
  derives from the records.
- **Dedupe.** `add` compares the subject with open tasks, epic criteria
  and open rows and refuses a match until the author passes the id to
  link or a reason to reject it.
- **Surfacing.** `orient` prints the counts and the overdue and
  operator-owned rows, so the check survives any one session; an
  optional advisory hook prints the same list before a status reply
  (`codeflow hook follow-check`, wired only when a project opts in).
- **Recoverable lane state.** `work status` lists per task the
  worktrees with uncommitted changes, unpushed commits and commits on
  no branch, read from git, so a restarted session sees what it would
  otherwise lose.
- Open in the issue and settled here as reversible defaults: one file
  per project (hosts share it; the holder field tells them apart); rows
  are created by any seat, the host owns closure.

Non-goals: the managed rule and the orchestrator skill's use of the
ledger (TSK-423); tracking a snapshot in git (a project may add it);
the operator feedback tracker (#75).

Added by the EPC-022 amendment of 2026-10-22 under the operator's
decision of that day (project-management changes go in 3.2.0).

## Acceptance Criteria

- AC-1 `codeflow follow add` shall write a row with every schema field, `update` shall change holder, waits-on, next check and running seat, and `close` shall refuse without a proof and accept a merged pull request, a commit, a recorded ruling or a quoted operator answer; evidence: CLI tests. (serves EPC-022 AC-111)
- AC-2 `add` with a subject that matches an open task, an epic criterion or an open row shall refuse naming the match until the author links the id or rejects it with a reason, and a row linked to a task shall show as closed with that task's proof once the task is terminal; evidence: CLI tests over fixture records. (serves EPC-022 AC-111)
- AC-3 `codeflow orient` and the SessionStart digest shall print the open count, each row whose next check is past, and each row whose holder is the operator, and shall print nothing when the file is absent; evidence: CLI tests and the digest output. (serves EPC-022 AC-111)
- AC-4 `codeflow work status` shall list, per task, each worktree with uncommitted changes, unpushed commits and commits on no branch, read from git; evidence: a CLI test over a fixture with one of each. (serves EPC-022 AC-111)
- AC-5 The file shall live in the project's untracked state, the managed ignore shall cover it, and the advisory hook shall be off unless a project wires it; evidence: `git status` in a test project and the hook test.
- AC-6 (journey) With the installed build in a scratch adopter project, a session shall add three rows, link one to a task, close one on a commit, and a new session's SessionStart digest shall show the two open rows with one overdue; evidence: the journey output.
