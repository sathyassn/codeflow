# TSK-422: An orchestrator's follow-up ledger is a command whose rows close on proof

## Description

Issue #272, proposal items 2 to 4 and the comment of 2026-10-21. An
orchestrating session owns a "task ledger"
(`cf-model-orchestrator/SKILL.md:63`) that CodeFlow gives no shape, no
closure rule and no place in the session loop. In an adopting project
with six lanes, a hand-written ledger stopped being updated after nine
days, items the operator handed over went quiet, and status was
assembled from memory. Merging the lanes' stocktakes by hand produced
about 940 rows, most of them work already tracked as tasks or criteria
in other words. A half-hourly sweep scheduled inside the coordinator
session was lost with the session; a deleted lane recovered only what
its own tracker file held, losing uncommitted edits, running seats and
in-flight reviews.

Outcome: **a project-level follow-up ledger, kept locally and shared
by every worktree, session and orchestrating model of the project,
keeps the open commitments as structured rows with a fixed schema;
any session adds rows, a row's holder is a role that a session claims
and keeps alive, only the holder closes a row and only on proof, rows
of a holder that has gone quiet show as orphaned and are adopted by the
next session claiming that role, `add` refuses a row that duplicates an
open CodeFlow record until it is linked or the match is rejected, the
hooks every session runs surface owed, overdue and orphaned rows
without any session timer, and `codeflow work status` lists, per task,
the worktrees with uncommitted changes, unpushed commits and commits on
no branch.**

The operator shaped this on 2026-10-22 and is still questioning the
design, so this task drafts a new ADR (allocated with `codeflow adr
new`) that lays out the options with their trade-offs and marks each
decision as the operator's; this record proposes, it does not fix.
The ADR is needed because the ledger changes where CodeFlow keeps
working state and partly supersedes ADR-0076's "plan in the harness's
task tools", which are session-scoped and vendor-specific. The
criteria below hold whichever location the operator chooses.

Options and proposals the ADR lays out:

- **Location**, three options. A: clone-local, in the common git
  directory (`.git/codeflow/follow/`), where CodeFlow's ledger JSONL,
  locks and registry state already live, shared by every worktree,
  untracked. B: a tracked file under `project-management/`, which needs
  a pull request per change and is too heavy at minute-level churn. C:
  a git-ignored folder in the root checkout, readable as a plain file
  but tied to one checkout. Recommended: A, with `codeflow follow list`
  giving a table or Markdown view and an opt-in tracked snapshot for a
  project that wants history. Ownership: CodeFlow owns the schema, the
  CLI, the hooks and the rules; the project owns the entries.
- **Scope.** One ledger per project (per clone), not per host, so any
  orchestrating model or session reads the same list. Open for the
  operator.
- **Format.** JSON Lines events (`add`, `update`, `close`, `claim`,
  `heartbeat`), appended under a lock and validated against a schema,
  with a folded current view; Markdown is only the human view.
- **Fields,** as #272 and its comment state: id, what, source, holder,
  a CodeFlow id (task, epic criterion, decision) or a reason why none
  exists yet, waits on, next check, the running seat, worktree and head
  while work runs, and closure proof.
- **Who adds and who closes.** Any session, host or lane, may add rows
  (open for the operator). Only the holder closes a row, with a proof:
  a merged pull request or a commit, a recorded ruling, or the
  operator's answer quoted with its date; "handed to a lane" never
  closes a row. A row linked to a task closes when that task closes,
  with the task's proof, which `list` derives from the records.
- **Holders, sessions and interruptions.** A holder is a role (`host`,
  `lane:<task>`), never a session id. A session claims its role at
  start and keeps a heartbeat (the timeout is open for the operator;
  proposed 30 minutes). Rows of a holder whose heartbeat has stopped
  show as orphaned at the next session start and are adopted by the
  next session claiming that role, after an interruption, in a new
  session or under a different model. The coordinating session sweeps
  all rows and owns operator asks; a lane sees and closes its own rows
  and adds rows for what it hands back; a lone session is its own host;
  every session sees operator-owned rows.
- **Dedupe.** `add` compares the subject with open tasks, epic criteria
  and open rows and refuses a match until the author passes the id to
  link or a reason to reject it.
- **Enforcement through hooks every session runs,** never a session
  timer: the SessionStart `orient` shows owed, overdue and orphaned
  rows for the current role and the operator-owned rows; a Stop-hook
  check (`codeflow hook follow-check`) flags rows past their next check
  and a status turn with an operator ask and no row; any `codeflow`
  command can print the overdue count. An orchestrator timer (for
  example every 10 minutes) is an optional aid only.
- **Recoverable lane state.** `work status` lists per task the
  worktrees with uncommitted changes, unpushed commits and commits on
  no branch, read from git, so a restarted session sees what it would
  otherwise lose.
- The managed-block rule and the `cf-model-orchestrator` rule that
  require the ledger are TSK-423's, so each is one reviewable pull
  request; the ADR lands with this task.

Non-goals: the managed rule and the orchestrator skill's use of the
ledger (TSK-423); the operator feedback tracker (#75); fixing any open
decision before the operator does.

## Acceptance Criteria

- AC-1 `codeflow follow add` from any session shall append an `add` event with every schema field (a CodeFlow id or a reason why none exists), `update` shall append changes to holder, waits-on, next check and the running seat, worktree and head, `close` shall be accepted only from the row's holder role and only with a proof (a merged pull request, a commit, a recorded ruling or a quoted operator answer), refusing "handed to a lane", and the folded view shall show the current state; evidence: CLI tests, including a close by a non-holder and a malformed event refused by the schema. (serves EPC-022 AC-111)
- AC-2 `add` with a subject that matches an open task, an epic criterion or an open row shall refuse naming the match until the author links the id or rejects it with a reason, and a row linked to a task shall show as closed with that task's proof once the task is terminal; evidence: CLI tests over fixture records. (serves EPC-022 AC-111)
- AC-3 A session shall claim a role (`host` or `lane:<task>`) and keep a heartbeat, rows of a role whose heartbeat is older than the configured timeout shall show as orphaned and be adopted by the next session claiming that role, and two sessions writing at once shall never corrupt the store; evidence: CLI tests with an expired heartbeat and a concurrent-append test. (serves EPC-022 AC-111)
- AC-4 `codeflow orient` and the SessionStart digest shall print, for the current role, the owed, overdue and orphaned rows and every operator-owned row, from any worktree of the project, the Stop-hook `follow-check` shall flag rows past their next check and a status turn with an operator ask and no row, and any `codeflow` command shall be able to print the overdue count; none shall depend on a session timer; evidence: CLI tests from two worktrees, the digest output and the hook tests. (serves EPC-022 AC-111)
- AC-5 The store shall be reachable from every worktree of the project at the location the ADR's accepted option names, resolved by one function, shall never enter history unless the opt-in snapshot is used, and the tests of AC-1 to AC-4 shall pass unchanged for each of the three location options behind that function; evidence: the tests run per option and `git status` in a test project. (serves EPC-022 AC-111)
- AC-6 `codeflow work status` shall list, per task, each worktree with uncommitted changes, unpushed commits and commits on no branch, read from git; evidence: a CLI test over a fixture with one of each. (serves EPC-022 AC-111)
- AC-7 The ADR shall lay out the three locations with their trade-offs and the recommendation, the per-project scope, who adds and closes, the roles and heartbeat with its timeout, the hook-based enforcement, the ownership split and the part of ADR-0076 it supersedes, marking each decision as the operator's, and `codeflow validate --docs` shall pass; evidence: the ADR and the validate output.
- AC-8 (journey) With the installed build in a scratch adopter project with two worktrees, a host session shall add three rows and a lane session one, the lane shall close its own on a commit and be refused closing the host's, the host's heartbeat shall be allowed to expire, and a new session claiming `host` shall see the rows as orphaned, adopt them and show one overdue in its SessionStart digest; evidence: the journey output.
