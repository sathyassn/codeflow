# TSK-1532: The portal policy lookup count ignores prose tables

## Description

Source: the docs-portal failures on `main` and on `integration/EPC-022-the-3-2-0-milestone-fixes`, relayed to coord/records on 2026-11-17. Filed by coord/records.

Checked here, at origin/main `ec8d5c1ab3` and at the EPC-022 line `9a49389fe2`, as last fetched:

- The adapter records a derived lookup page's rows as the body rows of every table on the page: `tableRowCount` (`docs-portal/scripts/lib.mjs:1044-1048`), called at `docs-portal/scripts/adapter.mjs:288`. The starter's copies (`assets/docs-portal/starter/scripts/lib.mjs` and `adapter.mjs`) are the same blobs.
- The binary counts only what it derives: the schema rows of the generated region plus the rows of the git hook stage table, `Ok(generated.rows + dispatcher.len())` (`crates/codeflow-core/src/validate/portal/lookups.rs:288`). The generated region sits between two `codeflow-derived policy-reference` marker comments. The stage table has no marker; the binary finds it by its heading, `## Git hook stages` (`lookups.rs:23`, `hook_stage_names`).
- `codeflow validate --portal` compares the two counts and reports "derived lookup does not match its source and configured derivation" (`crates/codeflow-core/src/validate/portal/figures.rs:1429-1437`).
- So any authored table elsewhere on `docs/policy-reference.md` breaks the check. Counted from the page source: on `main`, 57edd358e2 (TSK-1448) added the "When a hook is skipped" table, and the page's tables hold 91 body rows against the binary's 89 (84 generated, 5 stages). On the line, 23865e4107 (TSK-1057) added "The policy baseline" with two tables, and the count is 101 against 92 (87 generated, 5 stages).
- This is the third such table. e8e58e975c (2026-10-08) rewrote a "Rules with no key" table as prose and left a comment on the page (`docs/policy-reference.md:2415-2416` on `main`) telling authors not to add tables. PR 847's e716135ecc rewrites main's "When a hook is skipped" table as bullets; it is not on origin/main `ec8d5c1ab3`.

As reported to coord/records, not checked here (no CI run was read):

- The hosted docs-portal job is red on `main` and on the line for this reason.

This task changes the counting rule so the adapter counts only the rows the binary derives, found by markers in the page source. Non-goals: changing what the policy reference says, the generated text, or how the skill catalog and the capability registry are counted.

## Outcome

After this merges, an author can add a prose table anywhere on the policy reference page and the docs-portal check stays green, on `main` and, after each line's next sync of `main`, on the integration lines.

## Deliverables

- the counting rule: `docs-portal/scripts/lib.mjs` and `docs-portal/scripts/adapter.mjs`, with the starter's copies `assets/docs-portal/starter/scripts/lib.mjs` and `assets/docs-portal/starter/scripts/adapter.mjs` kept identical
- the stage table marker: a marker comment pair around the git hook stage table in `docs/policy-reference.md`, and `crates/codeflow-core/src/validate/portal/lookups.rs` reading the stage table by that marker, so the adapter and the binary select it by one rule; the page's "No table here" comment, which this change makes stale, is removed
- the fixtures and tests: fixture pages under `docs-portal/tests/fixtures/` and tests in a file the docs-portal job already runs (`docs-portal/tests/composition.test.mjs` or `adapter.test.mjs`, listed at `.github/workflows/codeflow-ci.yml:1023`), with the starter's test copies kept identical; the `lookups.rs` unit tests updated for the marker
- the release note: `changelog.d/TSK-1532.md`

## Acceptance Criteria

- AC-1 When a prose markdown table is added outside the generated region and the stage table of a policy reference fixture page, before any change to the counting rule, the adapter's derived lookup count shall differ from the binary's and the check shall fail; evidence: the new fixture test run at the base, failing, with its output in the PR body.
- AC-2 When the adapter computes a policy reference page's rows, it shall count only the rows the binary derives in `lookups.rs`, the schema rows between the `codeflow-derived` markers and the git hook stage rows, each selected by a marker in the page source and not by a heading or a count of all tables; evidence: the changed code in `lib.mjs`, `adapter.mjs` and `lookups.rs`, and the fixtures.
- AC-3 When any prose table is added to the policy reference page outside the marked regions, the derived lookup count shall stay the same; evidence: fixture tests that include "The policy baseline" tables as on the EPC-022 line at 23865e4107, and a table in the restored shape of main's "When a hook is skipped" as in 57edd358e2, before e716135ecc, each passing at the head.
