# TSK-434: An integration branch can be deleted only after it is merged

## Description

Operator decision of 2026-10-22: agents should be able to delete an
integration branch, but only after it is merged. Today
`codeflow hook git-guard` allows `git push origin --delete
integration/EPC-099-test` (exit 0) with no merge check, and the pre-push
hook's deletion rule covers protected refs only (`git.delete_protected`,
`crates/codeflow-core/src/hooks/git_guard.rs:8681-8688` and
`git_hook.rs:890-895`); the only thing that stops the deletion is the
deletion rule in GitHub's "Integration hosted gates" ruleset, a remote
setting outside the guards. The cleanup rule TSK-402 widens is
instruction text (`worktrees.md`), not enforcement, and TSK-421's line
close lists a deletion without performing it.

Outcome: **git-guard and the pre-push hook refuse deleting a remote or
local `integration/**` branch unless the branch is fully contained in
its target, there is no open pull request from or into it, and it is not
a protected branch; a refusal names the missing proof, an allowed
deletion names the proof it checked, and protected branches and release
tags stay refused.**

Rules:

- **Containment** is ancestry on the fetched target: the branch tip is
  an ancestor of `origin/<target>`, where the target is the epic's
  protected branch (`main`) for an epic line, read from the epic record
  or, with none, the repository's default branch. A target the guard
  cannot fetch or read is a missing proof.
- **No open pull request** from or into the branch, read through the
  remote provider where one is configured (`codeflow remote`); where
  the provider cannot be asked, the proof is missing and the deletion
  refuses, naming the route (ask a person, or configure the provider).
- **Protected branches and release tags** (`main`, `master`, the policy
  globs, and tags the release policy names) keep today's
  `git.delete_protected` refusal whatever the proofs say.
- The same judgment covers `git push --delete`, `git push :<ref>`,
  `git branch -d`/`-D` of a local `integration/**` branch and the
  `refs/` spellings, on git-guard (the Claude, Codex and Grok planes) and
  on the pre-push hook; the message lists each proof with its result.
- Once this task lands and is reviewed, the operator removes the
  deletion rule from the GitHub "Integration hosted gates" ruleset; that
  ruleset change stays the operator's and is not part of this task.

Non-goals: deleting task branches (TSK-402's cleanup rule and TSK-319 in
4.1.0); closing a line's records (TSK-421).

Added by the EPC-022 amendment of 2026-10-22 at the operator's
direction of that day.

## Acceptance Criteria

- AC-1 `git push origin --delete integration/EPC-099-test` and its `:<ref>` spelling shall be refused by git-guard and the pre-push hook when the branch tip is not an ancestor of the fetched target, naming containment as the missing proof; evidence: hook tests with a fixture remote, failing before the change. (serves EPC-022 AC-115)
- AC-2 The same deletion shall be refused when an open pull request from or into the branch exists, or when the provider cannot be asked, naming that proof and the route; evidence: tests with a fixture provider answering open, none and unavailable. (serves EPC-022 AC-115)
- AC-3 When the tip is an ancestor of the fetched target, no open pull request exists and the branch is not protected, the deletion shall be allowed and the output shall name each proof checked with its result; evidence: a test reading the output. (serves EPC-022 AC-115)
- AC-4 `main`, `master`, every policy-protected glob and release tags shall stay refused whatever the proofs say, and a local `git branch -d`/`-D` of an `integration/**` branch shall get the same judgment as the remote deletion; evidence: tests per spelling and per plane.
- AC-5 `docs/policy-reference.md`, `git-rules.md` and `worktrees.md` shall state the rule and its proofs, and the operator's note shall say that the ruleset deletion rule is removed by the operator after this task lands and is reviewed; evidence: the doc text.
- AC-6 (journey) With the installed hooks in a scratch adopter project with a remote, an agent session shall be refused deleting a line that is one commit ahead of `main`, and shall delete it after the line is merged into `main`, with the proofs printed; evidence: the journey output with `git ls-remote` before and after.
