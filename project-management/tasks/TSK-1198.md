# TSK-1198: Hook shims refuse or verify an externally set hook binary

## Description

The git-hook shims run the program named by `CODEFLOW_HOOK_BINARY` when it is set. `assets/base/git-hooks/pre-push:7-19` (and its siblings `pre-commit`, `commit-msg`, `pre-merge-commit` and `reference-transaction`) check only that the file is a regular executable and that `git-hook capabilities` prints `hooks 3`. The variable is an internal hand-off: `crates/codeflow-core/src/git/mod.rs:24` calls it "a dispatch hint, not authentication", and codeflow clears any inherited value and sets its own running path for the git child processes it starts (per `coord/parallel` finding 7, `coordination/coordinators/parallel/throughput/FINDINGS.md`, section 7; the clearing in `main.rs` was not re-read when this record was filed). Set from outside codeflow, any script that prints `hooks 3` and exits 0 stands in for every git hook, which is a gate override. It is present on the 4.0 line and on `main`.

Security task, agreed by the Director at 12:50 on 2026-11-02, filed next to TSK-1184 because both are gate-authority defects. It fails closed. Operator-side rule meanwhile (the Director's security hold, 2026-11-02): never set the variable for a push; put the worktree's build first on `PATH`.

Non-goals: changing how codeflow's own dispatch passes the binary to the git child processes it starts, beyond what the fix needs.

## Outcome

After this merges, a git hook shim never runs a binary named by an environment variable it cannot verify, and a script cannot stand in for the hooks.

## Deliverables

- the dispatch hand-off and its tests: `crates/codeflow-core/src/git/mod.rs` and `crates/codeflow-cli/tests/`

## Acceptance Criteria

- AC-1 A shim given a hook binary from outside codeflow's own dispatch shall either refuse, failing closed with a message naming the sanctioned path (the codeflow on `PATH`), or verify it against an identity a requester cannot forge; evidence: a fixture where a stand-in script that prints `hooks 3` and exits 0 is set as the variable and stands in for the hooks before the change, and is refused after it.
- AC-2 The hand-off codeflow uses for its own git child processes shall keep working; evidence: a test that pins both sides, the internal hand-off accepted and an external value refused.
- AC-3 Sibling sweep: every other environment variable or config value that steers which binary a git hook, a harness hook (Claude, Codex, Grok) or a CI step runs shall be listed, and each shall be fixed the same way or recorded as sound with its reason; evidence: the list in the PR with a disposition per entry, and a test for each one fixed.
- AC-4 The adopter impact shall be stated, since the scaffolded shims ship in `assets/base`, with a changelog entry; evidence: `changelog.d/TSK-1198.md` and the PR body's release impact.
- AC-5 The PR shall state the threat it closes and why its design is the standard one, and shall get a cross-lineage security review with the seat's availability checked live; evidence: the PR body and the recorded review.
- AC-6 (journey) A real push through a scaffolded shim with the variable set to a stand-in script shall be refused with the message naming the sanctioned path, and the same push with the real codeflow first on `PATH` shall pass the hook; evidence: the push run logs, one refused and one accepted.
