# TSK-1249: Gates run inside the Claude sandbox without unsandboxed retries

## Description

Source: coordination/coordinators/parallel/reviews/tsk1156-round4-builder-report.md, "Harness autonomy gaps" item 4.

In the default Claude sandbox, `cargo fmt`, `clippy`, `cargo doc` and the `git_spawn_contract` test fail with "Operation not permitted" on secret-named test files, so a Claude builder runs the gates only unsandboxed. The task records each denied path and makes the four commands pass in the sandbox, either by changing the fixtures or by writing up a sanctioned grant for the operator to decide.

Security: a sandbox grant widens a boundary, so it is an operator decision and is only written up here, never applied. Non-goals: changing the sandbox preset.

## Outcome

After this merges, a Claude builder can run the four gate commands inside the default sandbox without an unsandboxed retry.

## Deliverables

- the record of each denied path with its command, in this task's `## Findings`
- either the fixture change in `crates/codeflow-cli/tests/` and `crates/codeflow-core/tests/`, or a written grant proposal for the operator

## Acceptance Criteria

- AC-1 Each denied path shall be recorded with the command that hit it; evidence: a `## Findings` section committed before the first code change.
- AC-2 Either the fixtures shall stop using secret-named paths, or the write-up shall name a sanctioned grant for the operator's decision, with its protection and cost; evidence: the diff, or the write-up.
- AC-3 `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo doc --workspace --no-deps` and the `git_spawn_contract` test shall pass inside the default Claude sandbox; evidence: the four runs.
- AC-4 `codeflow test --mode quick` shall pass in the default Claude sandbox; evidence: the run output. (journey)
