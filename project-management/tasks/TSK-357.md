# TSK-357: Rust build profiles cut disk and runtime without new tools

## Description

Source: the gate speed discovery of 2026-10-17 (ranked change 6), and the
primary's build-speed research of the same day (scratchpad
`build-speed-research.md`, read-only, nothing built), which replaced the
planned sccache pilot with this task by the primary's decision of
2026-10-17.

Where the time goes, from 32 passing essential runs in 6 worktrees:

- The essential Rust test step is 79 to 98 percent serial test-binary
  execution (94 to 100 binaries); its wall time ranged from 1,183 to 2,650
  seconds. TSK-354 moves it to nextest.
- Warm compile steps take 35 to 133 seconds (`rust-build` 35 to 96,
  `rust-clippy` 41 to 133), with outliers of 480 to 600 seconds under
  contention. Clippy waited on the build directory lock in 7 of 18 sampled
  runs; TSK-331 AC-9 gives clippy its own target directory.
- Disk: one worktree's `target/debug` holds 56 GB (30 GB `incremental`, 26
  GB `deps` with 453,923 `.o` files); worktree target directories total
  about 260 GB. On macOS the default `split-debuginfo = "unpacked"` leaves
  debug info in object files.
- The debug `codeflow` binary is 75.6 MB (release 18.2 MB), and the tests
  launch it thousands of times (123 `CARGO_BIN_EXE_codeflow` uses, 282
  `Command::new` in tests) with unoptimized dependencies. The first launch
  of a freshly linked binary took 1.06 seconds (one sample), then 0.01.
- `crates/codeflow-cli/build.rs` reruns on changes under `crates`,
  `assets`, `docs`, `project-management`, `.agents`, `.claude` and more,
  and emits three `rustc-env` values; whether that recompiles all 52 CLI
  integration test targets after a docs-only edit is unverified.

Outcome: Rust build profiles and test layout cut disk use and build and
test time without any new tool, each change kept only if its measurement
meets its criterion.

In order:

1. **Do first: debug info.** `[profile.dev] debug = "line-tables-only"`
   for workspace crates, `[profile.dev.package."*"] debug = false` for
   dependencies, and an opt-in `[profile.debugging]` (`inherits = "dev"`,
   `debug = true`) for debugger sessions. Cargo PR 17518 proposes the same
   default upstream.
2. **Pilot: optimized dependencies in dev.** `[profile.dev.package."*"]
   opt-level = 1`, measured on test wall time, since the tests spawn the
   debug binary thousands of times. The repository already does this for
   `sha2`.
3. **Pilot: fewer integration test binaries.** Consolidate the 77
   integration test files (52 in codeflow-cli, 24 in codeflow-core, 1 in
   codeflow-present) into a few binaries per crate, codeflow-core first,
   updating nextest filters that name binaries (`binary(present_cli)`,
   `binary(init_e2e)`, `binary(test_gate_cli)`) and any CI references.
4. **Check: the build-script cascade.** Whether a docs-only edit rebuilds
   the CLI binary and all 52 CLI test targets. If it does, the fix touches
   the embedded-identity design and is a separate decision; this task
   records the finding.
5. **Measure only: macOS XProtect first-launch scanning.** How much it adds
   per fresh binary and per test run. Exempting a terminal or agent host
   from XProtect weakens a system security control; that is the operator's
   decision, and this task only measures and reports.

Not adopted now, with the research verdict recorded: a compiler cache.
sccache's Rust cache key includes the working directory, so hits across
worktrees at different paths are unproven; it cannot cache incremental,
bin or proc-macro crates; and compile time is a minor share of the gate.
Revisit event: compile time becomes a material share of gate time after
TSK-354 and this task land. kache is not considered (created 2026-02-15,
one author with most commits). Shared target or build directories, other
linkers, Cranelift and the parallel frontend stay out, as the research
explains.

Non-goals: sharing any target or build directory between worktrees,
installing any tool, changing the hook binary's embedded identity, and any
XProtect setting. Product surface: this repository's `Cargo.toml` profiles,
test layout and gate config; no shipped default changes.

## Deliverables

- profiles: `Cargo.toml` (`[profile.dev]`, `[profile.dev.package."*"]`, `[profile.debugging]`)
- test consolidation, if adopted: `crates/codeflow-core/tests/` first, then `crates/codeflow-cli/tests/`, with `.config/nextest.toml` filters and CI references updated
- the measurement record: for each step, the commands, `cargo build --timings` totals, target directory size, cold and warm build times, essential and full Rust test wall time, and the adopt or reject decision with its figures (provisional home `docs/verification/build-profiles-2026-10.md`; the builder confirms)
- the build-script finding and the XProtect measurement in the same record
- the compiler cache verdict and its revisit event in the same record

## Acceptance Criteria

- AC-1 With the debug-info profiles, the pull request shall report target
  directory size, a cold `cargo build --workspace --all-targets` and a
  one-file-edit rebuild (each with `--timings`), and essential and full
  Rust test wall time, before and after on one quiet host; the change is
  kept only if the target size falls, warm builds are not slower, coverage
  output is unchanged and a panic backtrace still shows file and line, and
  is otherwise reverted; evidence: the figures and a backtrace sample.
  (serves EPC-022 AC-54)
- AC-2 With `opt-level = 1` for dependencies, essential Rust test wall time
  and the cold dependency build time shall be reported; the change is kept
  only if test wall time drops by at least 10 percent and the added cold
  build time is smaller than the test saving per gate; evidence: the
  figures. (serves EPC-022 AC-54)
- AC-3 Consolidating codeflow-core's integration tests shall keep the exact
  test membership and the nextest serial group, and shall be kept only if
  compile plus link time for that crate drops by at least 20 percent;
  codeflow-cli follows only if codeflow-core's pilot is kept; evidence: the
  membership lists before and after (equal), `--timings` totals and
  nextest wall time.
- AC-4 A docs-only edit followed by `cargo build --workspace --all-targets
  --timings` shall be measured, and the record shall state how many
  codeflow-cli units rebuilt; evidence: the timing report and the count.
- AC-5 The first-launch time of a freshly linked debug binary and the count
  of trivial tests over 0.2 seconds in one nextest run shall be recorded,
  with no XProtect setting changed; evidence: the measurements and the
  statement.
- AC-6 The record shall state the compiler cache verdict, its reasons and
  the revisit event, and the source revision, dirty flag and hook input
  digest reported by the built binary shall match the worktree after each
  kept change; evidence: the record and `codeflow --version` with the hook
  report. (journey)
