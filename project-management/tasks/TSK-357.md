# TSK-357: A shared compiler cache is piloted and measured for new worktrees

## Description

Source: the gate speed discovery of 2026-10-17, ranked change 6 and its
section "Compilation, scheduling and avoidable rebuilding".

Every worktree keeps its own cargo target directory, which the worktree
rule requires (`.codeflow/rules/worktrees.md`, never share a target
directory) and which this task keeps. A new worktree therefore compiles the
whole dependency graph cold. How much of a gate that is has not been
measured: in warm essential runs compilation took under 1 to 3 minutes and
test execution dominated. A content-addressed compiler cache such as
sccache could share immutable compilation results across worktrees without
sharing any output directory. Its documented limits matter here: Rust
incremental compilation is turned off for cached crates, crates that invoke
the system linker are not cached, and file-reading procedural macros need
care. `crates/codeflow-cli/src/embedded.rs` embeds `assets/` and
`crates/codeflow-cli/build.rs` embeds source revision, dirty state and the
hook input digest, so a stale cache entry would be a provenance defect.

Decided by the operator on 2026-10-17: run a measured sccache pilot.
Research of the same day (primary's scratchpad `sccache-research.md`)
found sccache 0.18.0 maintained (Apache-2.0, releases every 4 to 10 weeks
in 2026, one published advisory, CVE-2023-1521, fixed in 0.4.0) and
installable as a checksum-verified Homebrew bottle. Two facts shape the
pilot: its Rust cache key hashes the absolute working directory, and the
change that would make Rust hits portable across checkout paths
(`SCCACHE_BASEDIRS` for Rust, upstream PRs 2678 and 2794) is unmerged, so
cross-worktree hits must be measured, not assumed; and workspace crates
are cacheable only with `CARGO_INCREMENTAL=0`, which slows the edit loop.
Adopting sccache after the pilot remains the operator's decision.

Outcome: a measured pilot that either adopts a compiler cache for this
repository's local tooling, with its invalidation and provenance proven, or
rejects it with the numbers. Either result is a complete task.

Non-goals: shipping a cache to adopters, installing a tool without the
operator's normal tool-adoption decision, sharing target directories, and
any hosted CI cache change. Product surface: this repository's local
tooling only.

## Deliverables

- the pilot setup: sccache 0.18.0 from the Homebrew bottle with its version recorded, session-only settings (`RUSTC_WRAPPER=sccache`, `CARGO_INCREMENTAL=0`, a dedicated `SCCACHE_DIR` the sandbox allows, an error log), never committed to `.cargo/config.toml` during the pilot, local disk only, never as root
- the measurement: cold worktree, warm worktree and cross-worktree builds with the cache off and on, with and without `SCCACHE_BASEDIRS` set to the worktree parent, for the debug build, clippy and the coverage build, plus the edit loop with and without incremental, with hit, miss and non-cacheable counts, elapsed compile, link and test time, and disk use, in the pull request body with the commands
- removal steps: stopping the server, deleting the cache directory and uninstalling, run at the end if the pilot rejects
- the setting, only if adopted: repository-local cargo config or a documented opt-in (provisional home `.cargo/config.toml` or `docs/` contributor notes; the builder states which and why), never a global or shipped setting
- the decision: adopt or reject, with reasons, in the pull request and in the task Closeout

## Acceptance Criteria

- AC-1 The pilot shall report, for each of cold, warm and cross-worktree
  builds, the elapsed time with the cache off and on, the hit, miss and
  non-cacheable counts and the disk used, measured on a quiet machine (no
  landing gate holding the machine lock); evidence: the table and commands.
  (serves EPC-022 AC-54)
- AC-2 With the cache on, a change to a file under `assets/`, to the
  toolchain version, to `RUSTFLAGS` and to the coverage instrumentation
  shall each produce a binary that reflects the change; evidence: one
  rebuild per change and a check of the embedded asset or flag.
- AC-3 With the cache on, the built binary's reported source revision,
  dirty flag and hook input digest shall match the worktree, after a source
  edit and after a records-only edit; evidence: `codeflow --version` and the
  hook report before and after each edit.
- AC-4 The cache shall be adopted only if cross-worktree builds are faster
  and an incremental rebuild in one worktree is not slower by more than the
  cross-worktree gain over a typical task; otherwise it is rejected and
  nothing is installed or configured; evidence: the decision with its
  figures. (journey)
- AC-5 No target directory shall be shared, the sandbox and trust
  boundaries of `.claude/settings.json` shall be unchanged, and the cache
  directory shall hold no credential or environment material; evidence:
  the config diff and a listing of what the cache stores.
