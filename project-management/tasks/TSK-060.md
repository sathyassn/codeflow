# TSK-060: portal and present chrome on the design kit

## Description

Rebuild the real portal chrome and the real present chrome on the design
system kit that TSK-070 shipped, and put the kit's token values into the
products. Skins: Graphite (neutral, no blue cast, teal accent), Slate (blue
tinted canvas with near-white surfaces, copper accent) and Sage (a barely
tinted green-grey canvas, spruce accent); instrument, editorial and ink are
retired from every sheet, test and example. The three product token sheets
(the portal sheet, the starter copy and the token section of the present
sheet) carry the kit's `tokens.json` values for every role in every skin and
mode. Portal chrome, per the brief's section 4 and the kit's
`portal.reference.html`: the 52 px header with the navigation toggle, brand
mark, search field as a button, Display button and table of contents toggle;
the search dialog on Pagefind with grouped results, highlighted excerpts,
altitude chips and keyboard selection; the Display panel with font, size,
palette and appearance pills, live preview and persistence applied before
first paint; breadcrumbs that are links; the navigation panel with
disclosure groups, counts, collapse remembered, the peek sheet by hover,
keyboard and `[`, and drag and keyboard resize within bounds; the altitude
tabs in the body face, sentence case, weight 600 and an accent underline when
selected, writing the hash; the table of contents with soft-fill active
state and scroll-spy; the provenance line with a shape for freshness; the ID
preview card; the footer previous and next cards; the motion table with
reduced motion; the 375 px layout with sheets and no horizontal scroll.
Present chrome, per section 5 and `present.reference.html`: the topbar with
kicker, title, revision, note count, Settings opening the Display panel and
the Comment toggle; the section route; the Comment strip, float, composer,
markers, rail, verdict and submit, keeping the existing browser checks green.
The starter mirrors the portal chrome so a consumer's guide gets the same
shell. Retire the old names from the doctrine text too, after TSK-072 has
deduped it: instrument, editorial and ink as skins, Neutral, Cool and Warm as
palettes, and `technical` as an export alias go from the Appearance section
of both `utility-presentation-system.md` copies, the themes sections of both
`visual-craft.md` files, the themes bullet of `cf-docs-portal/SKILL.md`, the
utility tokens and export theme text of `document-authoring.md`, the accent
note in `cf-docs-portal/references/operations.md` and
`docs/architecture/utility-presentation.md`. Two public interfaces carry the
old names: `codeflow present export --theme` (values `editorial`,
`instrument`, `technical`, default `editorial`) and the portal config
`theme` (`signal` or `folio`, which Agent OS sets to `folio`). Keep both
compatible: accept `graphite`, `slate` and `sage`, keep the old values as
aliases (proposed: instrument and technical to Graphite, editorial to Slate,
ink to Sage; `signal` to Graphite, `folio` to Sage), and name the aliases
once, in a compatibility line of the architecture page. Removing an old
value instead is a breaking change that needs `feat!`, a `BREAKING CHANGE:`
footer and the operator's decision. Runs after TSK-059 and TSK-072 so the
three never write the same files. Non-goal:
the figure runtime, the figure gate, the page classes and the product
`figure.css` copies, which TSK-059 owns; annotation correctness across block
types, which TSK-071 proves after this task lands.
