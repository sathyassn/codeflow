# TSK-099: public repository cutover housekeeping

## Description

The operator moved CodeFlow to a new public repository with filtered history
(`sathyassn/codeflow`; the private one is now `codeflow-archive`), and work
moves there after 3.0.0 lands. Several repository texts still describe the
private repository or point at things the public history does not carry.
At `e49726807`:

- `SECURITY.md` line 18 names the archived 1.x line "at tag `v1-final`"; the
  public repository was seeded with tags `v2.0.0` and `v2.1.0` only.
- `README.md` lines 30 to 36 and `docs/adoption.md` lines 9 to 22 say v2.1.0
  is the latest published release and that the anonymous installer works
  only once the releases are public, with a private or early access route.
  (The release follow-up list says "adoption line 70"; on this base the
  publication text is at lines 9 to 22, and at lines 85 to 95 on the EPC-016
  line.)
- The project-specific section of `AGENTS.md` (lines 438 to 441) says remote
  branch protection is unavailable because the repository is private on
  GitHub Free; the public `main` is protected (pull requests only, no force
  push or delete).
- Commit-pinned source links: no committed file on this base carries a
  commit-pinned GitHub link, so the links to regenerate are generated
  guide output built before the cutover. Commit IDs quoted in records and
  verification notes refer to the archive history and are not rewritten.

This task makes those texts true for the public repository once 3.0.0 is
published there. Target release: 3.0.0, so the
texts are true the day it publishes (delivery plan of 2026-09-26 evening).
Non-goal: repository settings, which are the operator's (private
vulnerability reporting, branch protection, the archive's sealing).

Downstream, recorded here because CodeFlow's task system cannot own it:
Agent OS and its portal go public only after the public CodeFlow repository
has been checked (operator decision, 2026-09-25), with the deploy-key
replacement and exact v3 pin tracked as Agent OS item B3 in the workspace
`RELEASE-PLAN.md`. That work belongs to the `agent-os` and `agent-os-portal`
repositories; this task only has to be complete before their publication.

## Affected surfaces and interfaces

- `SECURITY.md`, `README.md`, `docs/adoption.md`, the project-specific
  section of `AGENTS.md`, and any `CONTRIBUTING` or releasing note that
  names the repository or its history.
- Generated guide output, rebuilt from the public history; nothing
  generated is committed.

## Closeout

Text changes on `task/TSK-099-public-truth`:

- README and adoption install sections name no release version for the
  latest install: they say what each release publishes from 3.0.0 on (four
  platform archives with `.sha256` files, shell and PowerShell installers),
  and the guide warns that older releases publish fewer assets. The pinned
  install example runs in a subshell with `set -e`, creates the destination
  and extracts or installs only after the checksum passes. The exact
  snippet (version set to `v2.1.0`, work and destination directories under
  the scratchpad) was run on 2026-09-26 with four controls: valid into a
  fresh destination (exit 0, `codeflow 2.1.0`), valid replacing an existing
  binary (exit 0), a tampered `.sha256` (exit 1, nothing extracted or
  installed) and a missing `.sha256` (curl exit 37, nothing extracted or
  installed). The private and early access routes are gone.
- SECURITY.md drops the `v1-final` tag (the public tags are `v2.0.0` and
  `v2.1.0`) and adds a fallback that works whatever the repository
  settings: a public "Security contact request" issue with no details.
  Private vulnerability reporting was disabled on 2026-09-26 (`gh api
  repos/sathyassn/codeflow/private-vulnerability-reporting` returned
  `{"enabled":false}`). CODE_OF_CONDUCT points at the SECURITY.md route
  instead of a "direct message", which GitHub does not offer.
- The AGENTS.md project section (finding F22) drops the charter as plan of
  record, the `archive/v1` quarry (absent from the public repository) and
  the "protection unavailable" rule.
