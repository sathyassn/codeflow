# TSK-1300: The shipped test configuration template sets explicit timeouts

## Description

The shipped test-config templates (`assets/base/testing/templates/*.json`) leave `timeout_seconds` to the runner default of 600 s (`crates/codeflow-core/src/testing/runner/mod.rs:51`), so an adopter cannot see the limit each target runs under. This task makes each template target state its timeout explicitly, with the values sized for the target type. The key is already configurable (`assets/base/testing/test-config.schema.json`); nothing new is capped.

## Outcome

After this merges, an adopter who starts from a shipped test-config template sees the timeout of each target and can change it.

## Deliverables

- the templates: `assets/base/testing/templates/*.json` and the baseline
- a schema test that pins them: beside the template tests in `crates/codeflow-core/tests/`
- release note: `changelog.d/TSK-1300.md`

## Acceptance Criteria

- AC-1 Every target in every shipped test-config template shall carry an explicit `timeout_seconds`, with each value's basis named in the pull request; evidence: the template diff.
- AC-2 A schema test shall fail when a template target has no `timeout_seconds`; evidence: the test failing before the change and passing after.
- AC-3 A changelog entry shall describe the change; evidence: `changelog.d/TSK-1300.md`.
- AC-4 The default, bounds and class of `timeout_seconds` shall come from the limits registry (TSK-1299), and the templates' values shall lie within them; evidence: the schema drift test of TSK-1299 and the template test.
  - Added 2026-11-03 by the regroup planning pull request (final edit); reason: the operator's declare-once rule for limits.
