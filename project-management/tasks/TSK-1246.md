# TSK-1246: Record PR 482's post-landing reuse evidence from the first line push

## Description

Source: the CI throughput study of 2026-11-02 (recommendation 1) and the Director's decision of 2026-11-02 about PR 482 (TSK-359). PR 482 holds the reuse design in full, including the tier-aware skip set, the apt-cache condition, the latest attempt and the rule that an integration result never stands for `main`. TSK-359 cannot show its own first reuse until a line push has run after it lands, so its hosted evidence arrives afterwards. The Director handles that through the landing chain's owed-completion route; this task records the evidence itself, so it is not lost.

The task changes no product code and does not touch TSK-359. It waits for the first green push run on the EPC-022 line after PR 482 lands and records what that run shows. Non-goals: any change to `scripts/ci-reuse.py` or the workflow, and any amendment of TSK-359.

## Outcome

After this merges, a reader can find, in one record, whether the first line push after PR 482 reused the pull request run and which runs prove it.

## Deliverables

- one records-only pull request carrying the evidence record: run ids, SHAs and links, in this task's `## Findings`
- when the push did not reuse: a defect record opened with the run evidence

## Acceptance Criteria

- AC-1 From the first green push run on the EPC-022 line after PR 482 lands, the task shall record evidence that the push reused the pull request run (TSK-359 AC-5) and the hosted push run named in TSK-359 AC-2, with both run ids, both SHAs, the tree id and the reused run named in the push verdicts; evidence: a `## Findings` section with run links. (serves EPC-022 AC-231)
- AC-2 The evidence shall be recorded in one records-only pull request that names the SHA of TSK-359's waiver amendment; evidence: the pull request body and the diff, which touches records only. (serves EPC-022 AC-231)
- AC-3 If the push did not reuse the pull request run, the task shall open a defect with the run evidence instead of recording a pass; evidence: the defect record or issue link and the run links, in the Findings.
- AC-4 (journey) The recorded evidence shall let a reader follow from TSK-359's AC-5 to the pull request run, then to the landing push run that reused it, and see the reuse named in the push verdicts; evidence: the run links in the Findings, opened in that order.
