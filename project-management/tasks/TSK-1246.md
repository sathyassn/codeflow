# TSK-1246: A line push reuses a pull request verdict only by tested tree, line, tier and latest attempt

## Description

Source: the CI throughput study of 2026-11-02 (`coordination/coordinators/parallel/throughput/`, recommendation 1), cross-checked by Codex GPT-6 Astra and Claude Fable 5.1 (`CHECK-codex.md` finding 2). TSK-359 (PR 482) binds a reused verdict to the merged pull request number, its base, the tested merge tree and the workflow content. This task adds what that design leaves open, and it is a separate task so that TSK-359 records its completion against the scope it was reviewed on.

The gaps: the reuse loop rejects every skipped job except the reuse job (`scripts/ci-reuse.py:167-171`), but an integration pull request run legitimately skips jobs that a `main` run does not run; the apt-cache condition (`scripts/ci-reuse.py:147`) is tied to the full workflow; a newer failed or partial attempt of the same run is not excluded; and nothing stops an integration-tier result from standing as evidence for `main`.

Outcome: a push reuses a hosted verdict only from the latest successful attempt of the run that tested the exact pushed tree for the pushed line and the same check tier, with the skips its tier declares, and an integration-tier result never stands for a push to `main`.

Security-relevant: the change decides when a hosted verdict stands in for a run. Non-goals: the binding TSK-359 already delivers, reusing local results, and the cache-priming design. Product surface: this repository's CI only.

## Outcome

After this merges, a line push reuses the verdict of the pull request run only when that run's latest attempt succeeded on the exact pushed tree, for that line and tier, and a `main` push never accepts an integration-tier result.

## Deliverables

- tier definitions: the required verdict jobs and the legitimate skips for each check tier, in `scripts/ci-reuse.py` and `.github/workflows/codeflow-ci.yml`
- reuse rules: the skip set, cache condition, latest-attempt and never-upward rules, with cases in `scripts/test_ci_reuse.py`
- the security review of the change

## Acceptance Criteria

- AC-1 Before any change, the builder shall record in the Findings, with run links, which jobs an integration pull request run skips that a `main` run does not, and the current behavior of `scripts/ci-reuse.py:147` and `:167-171` on an integration run; evidence: a `## Findings` section, committed before the first code change.
- AC-2 The required verdict jobs and the legitimate skips shall be defined per check tier; the reuse loop shall accept exactly the skips its tier declares and refuse an undeclared skip and a skip belonging to another tier; evidence: `scripts/test_ci_reuse.py` cases for each tier, an undeclared skip and a skip in the wrong tier. (serves EPC-022 AC-231)
- AC-3 The apt-cache condition shall not prevent a reuse that is otherwise sound on an integration line, and a changed cache input shall still refuse reuse; evidence: cases for an integration run with and without the cache job and for a changed cache input. (serves EPC-022 AC-231)
- AC-4 Reuse shall bind to the tree actually tested, the pushed target line, the check tier and the latest attempt of the run that tested it, which shall be successful; a newer failed or partial attempt of the same run, and an attempt of another run, shall refuse reuse; evidence: cases for a later failed attempt, a rerun that succeeded, a partial attempt and an attempt of another run. (serves EPC-022 AC-231)
- AC-5 A result from the integration tier shall never be accepted as evidence for a push to `main`; a `main` push shall reuse only a run of the `main` tier; evidence: a case with an integration-tier run offered for a `main` push, refused. (serves EPC-022 AC-231)
- AC-6 A cross-lineage security review carrying the `cf-security-reviewer` checklist shall cover the change, with the seat probed live at dispatch, and the pull request shall state the threat each rule closes and why its design is the standard one; evidence: the review verdict and the pull request body.
- AC-7 (journey) After TSK-359 and this task, a ready integration pull request run followed by its landing push shall show the push reusing the latest successful attempt with verdicts that name the reused run, and the same pair with a deliberately later failed attempt shall show the push running every job; evidence: both run link pairs.
