# TSK-427: CodeFlow's own code meets the typing defaults, and relaxations use the register

## Description

Issue #275, items 1 and 6 and the comment of 2026-10-22 on the
instruction side. Three shipped texts steer agents away from strictness:
`cf-model-orchestrator/resources/quality/design-implementation.md:24-33`
(types "where they prevent material errors", no stricter-compiler
migrations "merely to satisfy this rule"), `cf-develop/SKILL.md:41-44`
("never force a stricter compiler") and `cf-stack/SKILL.md:32-35` ("Do
not mandate TypeScript, a validator library"). Under them, reviews
passed Python at 5 % annotated with hundreds of `dict[str, Any]` and
hand-written validators.

Outcome (amended 2026-10-27): **CodeFlow's own code passes the typing
defaults in every language it holds, including typed data at its
boundaries, or the part that cannot yet is in the baseline with a fix
task and a named deferral; and the shipped texts route a relaxation of
the typing default through a TSK-424 register entry instead of the
interim route TSK-1032 wrote.**

Rules: TSK-1032 rewrites the three texts and adds the review check in
3.2.0; this task changes only their relaxation route to the register;
the vendored Python under `assets/` is
annotated and checked by pyright strict and Ruff in this repository's
gate.

Non-goals: the tooling (TSK-426); rewriting adopters' existing code.

Amended 2026-10-27 by the quality asks amendment (the operator's D3 and
D6 asks). The three texts, the review check, the qualification cases and
the journey (former AC-1, AC-2, AC-4 and AC-5) moved to TSK-1032 in
EPC-022 (3.2.0): they are instruction and review-question changes that
ship alone, with an interim relaxation route in the project-owned part
of `AGENTS.md`. This task keeps what needs TSK-424 and TSK-426:
CodeFlow's own code passing the defaults, with the rest admitted in the
baseline, and moving the relaxation route in the shipped texts from the
interim route to a TSK-424 register entry. It also takes the typed-data
rule for CodeFlow's own code: data crossing a boundary is parsed into a
typed model (serde types in Rust, typed models in Python and
TypeScript), or the untyped boundary is in the baseline with a fix task.
The title changed with the scope.
