# TSK-1408: Exec-guard allows an ordinary git clone in an adopter project

## Description

In a project scaffolded with `codeflow init --yes`, exec-guard built from the EPC-022 line refuses every `git clone`, https included, while 3.1.0 allows the same command. The TSK-1401 builder found it on 2026-11-09. Two refusals come from the same change. TSK-1002 (PR 346, merge 6a05e1c00) made exec-guard judge each program Git runs for a remote verb (commit 6332da679), and added a fail-closed reader for recursive and archive operations (commit c7852c53a).

- `security.secret_reads`, "cannot establish every source of an unmodelled recursive or archive operation": the program in `GIT_SSH_COMMAND` (for example the Claude sandbox's `ssh -o ... -o ProxyCommand="... ${VAR:?msg} ..."`) reaches the guard's fail-closed reader for recursive and archive operations, which takes an option of a program it does not model for archive syntax and the unset-check operator for a glob, then refuses the unresolved word.
- `security.outward_actions`, an account action: a credential helper in the user's git configuration, such as the `!gh auth git-credential` helper `gh auth setup-git` writes, is judged as a command of its own.

Both are over-refusals: they fail closed and let nothing through, but they break cloning, fetching and pushing in an adopter project, which makes this a 3.2.0 release blocker. This task makes exec-guard judge these runner programs by what they do. It keeps every clone refusal TSK-379 and TSK-1401 require. It narrows a guard, so it takes a security review and the operator's approval. Non-goal: git-guard's clone destination check, which TSK-1401 owns.

## Outcome

After this merges, an agent in an adopter project can clone, fetch and push over https and ssh with the usual sandbox environment and a `gh auth setup-git` credential helper, and the clones that write into enforcement paths are still refused.

## Deliverables

- the fix: `crates/codeflow-core/src/security/interpreter.rs` (archive and glob reading), `crates/codeflow-core/src/hooks/exec_guard.rs` and `crates/codeflow-core/src/hooks/git_guard/runners/` (runner judgment), as the design decides
- tests: an adopter-project fixture in `crates/codeflow-cli/tests/` and unit tests beside the changed readers
- docs: `docs/policy-reference.md` (how exec-guard judges the programs Git runs) and a changelog fragment `changelog.d/TSK-1408.md`

## Acceptance Criteria

- AC-1 Before any change, the builder shall record the design with evidence: which environment a real Claude, Codex and Grok hook process receives (whether `GIT_SSH_COMMAND` and similar variables reach it), every runner source exec-guard now judges for a remote verb, what 3.1.0 did with each, and, for each, who could write its source. Trust follows who could write the source: global or system configuration at its default path, and the harness sandbox's own environment, are the user's; the command line, an environment assignment on the line, the repository's own configuration, an include file the agent can write, and any selector that makes Git read a file the agent chose (`GIT_CONFIG_GLOBAL`, `GIT_CONFIG_SYSTEM`, `GIT_CONFIG_COUNT` with its keys and values, `GIT_CONFIG_PARAMETERS`, a relocated `HOME` or `XDG_CONFIG_HOME`) are the agent's; evidence: a Findings section committed before the first code change.
- AC-2 (journey) In a fresh `codeflow init --yes` project, exec-guard shall allow `git clone`, `git fetch`, `git pull`, `git push` and `git ls-remote` over https and over ssh when `GIT_SSH_COMMAND` holds an `ssh` command with `-o` options, including a `ProxyCommand` that uses `${VAR:?message}` as the Claude sandbox's value does; evidence: an adopter-project fixture test with the sandbox's value, failing before the change and passing after.
- AC-3 (journey) In the same project, exec-guard shall allow those verbs when the user's global git configuration names a credential helper of the form `gh auth setup-git` writes; evidence: the same fixture with an isolated fake helper script standing in for `gh auth git-credential`, in a scratch global configuration at its default path under the test's own home, failing before and passing after. The fixture never runs real `gh` or any real credential helper, and no test runs `git credential fill` or `approve` against a real helper.
- AC-4 The archive reader shall not treat an option of a program it does not model as archive syntax, and the unset-check operator inside a parameter expansion (`${VAR:?message}`, `${VAR?message}`) shall not count as a glob character; a pathname glob in the same word still counts, and a modelled archive or recursive operation (`tar`, `cp -r`, `rsync -a`, `zip -r` and the others the reader already models) shall be judged and refused as it is now; evidence: unit tests both ways, each new one failing before the change.
- AC-5 Every clone refusal TSK-379 and TSK-1401 require shall still hold: a destination inside `.git`, `.claude`, `.codeflow`, `.codex`, `.grok`, `.agents` or `.github` or in an existing repository's hooks directory, whether given, derived from the URL, through `--bare` or `--mirror` or under `-C`; a `--separate-git-dir` or `--template` copy into a protected path; a destination the guard cannot place; and the program-running clone options (`--upload-pack`, `--config`); with every other refusal those tasks require, among them TSK-1401 AC-2 (a raw last component that is an ordinary name while the directory Git creates is an enforcement directory, a bundle source, a starting directory that is itself an enforcement directory) and AC-4 (an operand the guard cannot classify, a derived name it cannot produce), and TSK-379's exec-guard refusal of a home destination git-guard allows; evidence: the fixtures and tests TSK-379 and TSK-1401 name for those refusals, by reference, passing at the head, plus the cases above in the adopter-project fixture, refused at the head.
- AC-6 A runner program the agent controls (given on the command line, in an environment assignment on the line, in the repository's own configuration, in an include file it can write, or through a selector AC-11 names) that reads a protected path or runs an account action shall still be refused, with the same rule as today; evidence: fixture cases for `GIT_SSH_COMMAND=...` on the line, `-c core.sshCommand=...` and a repository-level `credential.helper`, refused at the head.
- AC-7 Every runner source exec-guard judges (at least `GIT_SSH_COMMAND`, `GIT_SSH`, `core.sshCommand`, `GIT_ASKPASS`, `core.askPass`, `SSH_ASKPASS`, `credential.helper`, `credential.<url>.helper`, `GIT_PROXY_COMMAND`, `core.gitProxy`, `remote.<name>.uploadpack`, `remote.<name>.receivepack`, and a transport URL that names a program) shall be checked with a common real value from each place it can be written; each over-refusal found shall be fixed here; evidence: a table in the pull request body with each source, where it was written, whether that place is the user's or the agent's under AC-1, the value used, and the verdict before and after.
- AC-8 On every allowed payload in AC-2, AC-3 and AC-7, the head shall decide as 3.1.0 decides; any difference shall be named with its reason; evidence: the comparison in the pull request body, from the built head binary and the 3.1.0 binary.
- AC-9 `docs/policy-reference.md` shall say which programs Git runs that exec-guard judges, how a user-configured one differs from one the agent supplies, and the changelog fragment shall name the fix; evidence: the doc diff and `codeflow validate --docs`.
- AC-10 Security review: the cross-lineage reviewer applies the `cf-security-reviewer` checklist and confirms no refusal a test or criterion requires was lost; the pull request lists every rule the change narrows; evidence: the verdict file named in the pull request body.
- AC-11 A runner program read from a file the agent selects, through the global or system configuration variables, `GIT_CONFIG_COUNT` or `GIT_CONFIG_PARAMETERS`, a relocated `HOME` or `XDG_CONFIG_HOME`, or an include target the agent can write, shall count as agent-supplied under AC-6 on every remote verb, `git clone` and `git ls-remote` as well as `git fetch`, `git pull` and `git push`, and shall be refused when it reads a protected path or runs an account action; evidence: fixture cases for each selector carrying the fake helper of AC-3, refused at the head on clone and ls-remote, each failing before the change where the line allows it.
