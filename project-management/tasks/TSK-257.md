# TSK-257: Main's fixture contract passes again

## Description

`main` at `97ede7aa1` fails `cargo test -p codeflow-core --test git_spawn_contract`, which keeps `codeflow gates (coverage)` and two Windows test shards red on `main` and on every open PR. PR 97 (TSK-245) added the contract that every Rust fixture clone goes through `codeflow_fixture::clone` and that every environment replacement site carries a reviewed allowance. Three PRs that were green on their own bases landed around it without the contract: PR 93 (TSK-241) added a raw `git clone -b` in `crates/codeflow-cli/tests/feedback_cli.rs`, PR 112 (TSK-249) a raw `git clone --bare` in `crates/codeflow-cli/tests/readiness_journey.rs`, and PR 109 (TSK-248) an `env_remove(key)` loop in `crates/codeflow-cli/tests/support/line_adoption.rs`. This task routes both clones through the fixture helper the way PR 97 migrated the others and gives the `env_remove` loop a reviewed allowance, since the fixture needs those removals. The PR body records what would have caught the merge race and its cost. Non-goals: CI workflow or repository-setting changes, which are the operator's call, and the contract's scope, which TSK-245 settled (non-Rust runtimes are checked only for clones).

## Deliverables

- the two migrated fixture clones: `crates/codeflow-cli/tests/feedback_cli.rs`, `crates/codeflow-cli/tests/readiness_journey.rs`
- the reviewed environment allowance: `crates/codeflow-core/tests/fixtures/git_environment_allowlist.tsv`
- the recurrence analysis: the PR body

- AC-1 When `cargo test -p codeflow-core --test git_spawn_contract` runs on this branch, which contains `main` at `97ede7aa1`, every test shall pass. Evidence: the same command fails `fixture_clones_go_through_the_helper` and `fixture_processes_keep_the_inherited_git_configuration` at `97ede7aa1` and passes at this branch head.

- AC-3 When the suites holding the changed sites run, they shall pass end to end with the helper's transport-only clones. Evidence: `cargo test -p codeflow-cli --test feedback_cli --test readiness_journey --test hooks_cli --test ci_cli --test refusal_journey` output at the head (the last three are the suites that include `support/line_adoption.rs`). (journey)
