# TSK-383: Remote protect changes only the rules it owns, and doctor reads the live rules

## Description

Issue: #200. `codeflow remote protect` updates in place "every active repository ruleset that already targets a branch" (`crates/codeflow-core/src/remote.rs:15`, `:343`). In a repository that splits `main`'s rules across rulesets with different bypass lists, that run would add rules to each and change the intended separation. The dry run also plans protection for `master` when the policy lists it and no such branch exists. `codeflow doctor` warns that no host rules are recorded for `codeflow/registry` although an active ruleset already blocks force pushes and deletion there, because it reads the recorded receipt, not the live rules. The adopter's workaround is to accept the warning and never run the command. Deferred on 2026-10-17; the operator's rule of 2026-10-18 brings it into 3.2.0.

Outcome: **`remote protect` changes only rulesets it created or one the operator names, plans nothing for an absent branch, and `doctor` accepts live rules that already give the required protection.**

Constraints carried from the 2026-10-17 deferral: the preview is exact, and unrelated protections and bypass lists are preserved.

Added by the EPC-022 amendment of 2026-10-18 under the operator's release decision of that day (workspace `RELEASE-PLAN.md`, 2026-10-18 operator decision).

## Acceptance Criteria

- AC-1 `remote protect` shall change only rulesets it created (identified by a recorded id or a CodeFlow marker) and add its own ruleset beside others, never editing a ruleset it did not create unless `--adopt <ruleset>` names it; evidence: tests with split rulesets and different bypass lists, failing before the change. (serves EPC-022 AC-79)
- AC-2 `remote protect --branch <name>` shall limit the run to that branch, and a policy branch that does not exist on the remote shall be reported and not planned; evidence: tests.
- AC-3 `--dry-run` shall print the exact requests it would send, and a run shall send exactly those; evidence: a test comparing preview and sent requests.
- AC-4 `doctor` shall accept an active ruleset or branch protection that gives at least the required rules (no force push, no deletion, and the policy's other required rules) as the host rule for that branch, whether or not CodeFlow recorded it, and shall name what is missing otherwise; evidence: tests.
- AC-5 (journey) Against a stubbed host holding split `main` rulesets and a manual `codeflow/registry` ruleset, the installed build's `doctor` shall pass the registry check and `remote protect --dry-run` shall leave both `main` rulesets untouched; evidence: the journey output, and a live read-only `doctor` run against this repository's rules.
