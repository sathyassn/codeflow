# TSK-021 — validate and report typed worker routes

## Description

Implement SPC-009's ensemble schema v4, typed worker-route parser/validator and
truthful model-bindings doctor report, including canonical assets and managed
mirrors. Preserve QualifiedBinding v1, ProjectSelection v1 and existing primary
promotion semantics; do not add a runtime router, worker-state store or route
status mutation.

## Affected surfaces and interfaces

`crates/codeflow-core/src/model_qualification.rs`,
`crates/codeflow-core/src/doctor/mod.rs`, focused Rust unit/doctor/contract tests,
the canonical `current-ensemble.json` under `assets/base/agents/skills/` and its
`.claude`/`.agents` managed mirrors. Existing manifest and scaffold tests may be
updated only as required to keep those existing assets coherent.

## Acceptance Criteria

- [ ] Strict serde and semantic tests accept exactly SPC-009's schema v4 fields,
  workload/status/effort vocabulary and same-selector rule, and reject unknown,
  duplicate, unsafe, mismatched and incomplete routes.
- [ ] The design owner resolves to a standing Claude role; only its routes can
  declare `design-implementation`. Candidate entries are representable for
  disposable qualification fixtures, while real design execution requires
  scoped qualification with the required evidence. No deterministic test claims
  rendered fidelity qualification.
- [ ] Every shipped internal route has one typed entry with exact per-harness
  selectors and discrete efforts. Sol, Terra and Opus remain candidates unless
  compliant scoped evidence lands; no entry makes a cost or default claim.
- [ ] `doctor --check model-bindings` reports route ID, workload, status, selector
  and probe availability without promoting a route or claiming runtime-applied
  model/effort. Focused doctor tests pin absent/unavailable and candidate output.
- [ ] Canonical and managed ensemble copies are byte/coherently equal and the
  affected model-evaluation, manifest and scaffold contract tests pass.
- [ ] The exact implementation diff receives native Claude cross-lineage review
  before guarded integration into `integration/resource-aware-routing`.

## Execution contract

EPC-008 Plan v1 and SPC-009. The Codex engineering primary is accountable. It
may dispatch bounded Rust/JSON/test units through a same-family Sol/high
candidate route, records requested and observed values honestly, and inspects
and accepts the returned work; the routing reason is to preserve primary
capacity without lowering the quality floor. Native Claude independently reviews
the exact diff before integration. Use one task worktree, at most two active
coding workers overall and one heavyweight build. A material schema, status,
ownership or graph change requires a newly dual-approved plan.
