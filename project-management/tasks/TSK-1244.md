# TSK-1244: An agent can create a disposable sample repository through a sanctioned path

## Description

Source: the CI throughput study of 2026-11-02 (`coordination/coordinators/parallel/throughput/`: RECOMMENDATIONS.md, FINDINGS.md, CHECK-codex.md, CHECK-fable.md), cross-checked by Codex GPT-6 Astra and Claude Fable 5.1, and the operator's priority on CI throughput.

Today the git guard refuses `git init` of a new, empty folder with the rule `git.policy_authority` ("no readable repository ... unborn HEAD"), so no agent session can create a disposable sample repository. That blocked step 4 of TSK-431's AC-4 journey and would block the beta binary trial the operator wants before adopting a beta on this machine.

Two designs are open and the task chooses one with the threat model stated first: (a) a guard allowance for `git init` into a new, empty folder outside any repository, or (b) a `codeflow` command that creates the sample. Either way the guard keeps failing closed for everything else. The task changes a guard, so it is a security task: the threat each rule closes and why the design is the standard one go in the pull request.

## Outcome

After this merges, an agent session can create a disposable sample repository in a new empty folder by a documented path, and every other repository creation or read the guard refuses today is still refused.

## Deliverables

- the chosen path: `crates/codeflow-core/src/hooks/` (the git guard) or `crates/codeflow-cli/src/cmd/` (a sample command)
- the design note with the threat model, kept in this record's Findings
- tests: the allowed case and each refusal that must stay
- docs: `docs/policy-reference.md` and `docs/cli.md`, whichever the chosen path touches

## Acceptance Criteria

- AC-1 Before any change, the builder shall write the threat model and choose between the two designs, with the reasons; evidence: a `## Findings` section that names the attacks considered (a path that is not new or not empty, a folder inside an existing repository, a symlink or a `..` path, a protected or enforcement path, `GIT_DIR`, `--separate-git-dir`, `-C` and template forms, a target an attacker can swap between check and use) and the one design chosen, reviewed by the other lineage before the first code change.
- AC-2 The chosen path shall let a session create a repository in a new, empty folder outside any repository and make its first commit there, and nothing else; evidence: tests for the allowed case. (serves EPC-022 AC-236)
- AC-3 The guard shall still refuse, with the rule and sanctioned path it names today, every other case of AC-1's list, and shall refuse when it cannot resolve the folder; evidence: one test per case, failing closed.
- AC-4 The sanctioned path shall be written in the policy reference and the CLI reference with the refusal text pointing at it; evidence: the doc diff and `codeflow validate --docs`.
- AC-5 In a scratch folder with the installed build, an agent session shall create a sample repository, commit in it and remove it, and shall be refused in each AC-3 case; evidence: the journey output. (journey)
