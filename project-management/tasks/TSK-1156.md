# TSK-1156: Codex builder seats can claim, push and run their own gates

## Description

A Codex builder seat, launched with the builder posture in
`.agents/skills/cf-model-orchestrator/resources/routing/transport.md`, is
refused when it runs `codeflow work claim`, renames a branch, pushes, or runs
`codeflow test --mode essential`. Known so far: `codeflow work claim` writes
the repository's shared git config file, which the seat cannot write. Whether
writes under `~/.codeflow/gate-runs` still block a gate run is unconfirmed
(PR 419 dropped that grant from the Claude presets; ADR-0089 gives local run
records no credit). This task finds each refusal with its exact message,
fixes each one by a code change where that avoids widening the seat's
sandbox, and makes `codeflow doctor --preflight` and `--check permissions`
name what a Codex builder seat can and cannot do. Non-goals: authenticating
local run records (ADR-0089); any sandbox grant, which is written up as an
operator decision instead.

## Outcome

After this merges, a Codex builder seat can claim a task, push, and run its
quick and essential gates under its own profile, and doctor tells it what it
cannot do.

## Deliverables

- Investigation record of each refusal with its exact message: this task's PR body
- Fixes with tests (claim, rename, doctor): `crates/codeflow-core`, provisional until the investigation names the code
- Operator decision write-up for any remaining sandbox grant: this task's PR body

## Acceptance Criteria

- AC-1 Investigation first: a live check of what refuses a Codex seat launched with the builder posture in `.agents/skills/cf-model-orchestrator/resources/routing/transport.md:60` when it runs `codeflow work claim`, a branch rename, a push and `codeflow test --mode essential` at the line tip; each refusal is recorded with its exact message.
- AC-2 Each refusal found is fixed without widening the seat's sandbox where a code change can avoid it (for example, claim not needing a shared git config write from the seat, or a gate run that does not need a shared write); a fix shows fail-before and pass-after; `codeflow doctor --preflight` and `--check permissions` name what a Codex builder seat can and cannot do.
- AC-3 A Codex builder seat claims, pushes and runs `codeflow test --mode essential` end to end under the profile, and the output is in the PR. (journey)
- AC-4 Any grant that would still widen the sandbox is not made in this task; it is written up as an operator decision (protection, cost, alternative). Local run records stay uncredited.
