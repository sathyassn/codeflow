# TSK-1301: The pre-push destination probe's timeout and attempt count come from policy

## Description

The pre-push hook and `codeflow ci` read the destination's default branch with `git ls-remote --symref`, and waited a fixed 10 s per attempt (`LS_REMOTE_DEADLINE`, `crates/codeflow-core/src/git/remote_query.rs:15` at the line tip 1cbf73aea). GitHub answered in 11.3 s and 11.6 s on 2026-11-03, so ordinary pushes refused with `ci.destination_unavailable`. This task moves the waits into policy and declares every limit it touches in one place.

- Keys: `git.remote_query_timeout_seconds` (default 30), `git.remote_query_attempts` (default 3) and `git.remote_fetch_timeout_seconds` (default 120). Basis: GitHub's measured 11.3 s and 11.6 s against the old 10 s; 30 s leaves room above that, and 120 s is the earlier fixed fetch wait. Each is a whole number of at least 1. The only upper bound is what a u64 holds; any other value refuses at load, naming the key. No numeric cap is added, so these keys bound a silent query only as far as their values do: a very large value means effectively no limit, and one past the clock's range never expires (`remote_query.rs`). The policy reference says so.
- Declaration: `crates/codeflow-core/src/hooks/limits.rs` declares the three keys, the guard hook timeout (30 s), the guard deadline (20 s, a 10 s buffer under the hook timeout), the guard's remote lookup wait (10 s per lookup), the guard's pull request lookup wait (5 s; one of each leaves a 5 s buffer under the deadline) and the guard's refusal write wait (1 s), each with a default, bounds, a class (operational or security) and a reason. The policy defaults, the schema check, the loader and the guard code read only from it, in a shape the limits registry, TSK-1299 ("One limits registry, declared once", EPC-028), absorbs unchanged: the three probe keys and the five guard values. TSK-1301 lands first as its first consumer (operator rule, relayed by coord/ci). One literal remains by necessity: the harness files are JSON the harness reads, so `"timeout": 30` is written in each shipped guard entry; `doctor/guard_timeouts.rs` compares every one with the declared value, and its tests run on all shipped presets. The guards' 3 s bounds on local git reads (`security/git_config.rs`, `security/interpreter/git_staging.rs`, `hooks/git_guard/runners.rs`) use no network and are not moved here; TSK-1299 owns them, and the guard deadline covers them meanwhile.
- Callers: the pre-push push set, `codeflow ci` (release scope, own-line tip, target tip), `task status` (checkout scope), the id sync's absence check and every fetch of a missing tip use the configured values. The id sync's separate registry fetch (`ids/issue.rs:439`) stays outside the configured wait, under git's own waits; TSK-1299 owns the limits.
- Guard path, option (b): the session guards ask the remote only while its tracking refs are missing (`landed_policy::advertises_refs`). In that state no policy authority exists, so no configured value can reach a guard; the journey test `no_configured_wait_reaches_a_guard` proves it with the keys set to 1 s and to 60 s with 5 attempts, on the task branch with no authority and on the default branch, and `guard_code_names_no_configured_wait` pins that guard code names no configured limits. The guards' one other network wait is the git guard's `gh pr view` lookup, a declared 5 s that no key sets, which blocks on no answer. The guard uses its own declared 10 s wait per lookup, one attempt, and refuses with a message that names that wait, the 20 s deadline and the 30 s hook timeout and says to run `git fetch <remote>`; with the fetched refs the guard reads the policy locally and asks nothing. The 10 s is not shared: a command naming several repositories can make one lookup for each (`git_guard.rs`), and the 20 s deadline is what bounds the whole command, refusing if reached. The guard lets that fetch itself through after its own 10 s wait, and only a plain fetch: `ref_authority::recovery_fetch` judges the line as written, in a closed form, because the allowance runs before both guards' integrity checks. Threat closed: it judged a normalised form of the line, so a line doing more than the fetch could qualify and skip those checks. The fetch runs under git's own waits: no policy key limits it. On git older than 2.48 a fetch does not record `refs/remotes/<remote>/HEAD`, so `git remote set-head <remote> -a` is also needed, which itself asks the remote, and that refusal names it. Option (a), deriving the guard and harness timeouts from policy at `codeflow update`, was rejected: it rewrites the hook timeouts of three harnesses (Claude, Codex, Grok) and adopters' installed files, which is fragile, and a long guard wait stalls every guarded command. (b) keeps the guard fast and fail-closed.
- Misfit configuration: no configured value reaches the guard (above), and on the pre-push and `ci` paths no harness timeout applies, so no combination of the keys misfits a harness limit. The validator therefore refuses only values outside each key's declared bounds; the guard uses its own declared wait and fails closed. A validator refusal of a product such as 30 s times 3 attempts would refuse the shipped defaults themselves.
- Threat closed: every path the pre-push hook takes reads the waits from the default branch, never from the working copy or the pushed head (commit 78a29ee70, "read policy only from the default branch"). `push_set::probe_limits` reads the local authority, `refs/remotes/<remote>/HEAD`. The `codeflow ci` the hook starts runs only under `Judged::Target`, with `--policy-from` set to the destination default branch's tip; the other two states run no `ci`. A pushed head cannot lengthen or shorten the hook's lookup. Where no default branch supplies a policy (tracking refs missing, an unreadable authority, or no remote, whose local policy is `HEAD`'s), the shipped defaults apply, never `HEAD` or the working copy. A direct `codeflow ci` reads the policy at the authority its caller (`--policy-from`) or its range's base selects, as it does for every other rule, so a caller naming a head gets that head's waits; this cannot change a hook's wait, and the hosted policy workflow names the trusted commit. An unreadable destination still refuses.
- Siblings not folded: `crates/codeflow-core/src/coord/observe.rs:54-58` (Git 10 s, network 20 s; TSK-422, ADR-0086) and `crates/codeflow-core/src/ceremony/host.rs:16` (60 s `gh` call; TSK-149) are fail-soft observers: a timeout reports unknown and refuses nothing, so remote latency cannot block work there. Both tasks are complete; TSK-1299 owns moving them into the declaration. `MAX_ANSWER_BYTES` (16 MiB, `remote_query.rs`) is a memory bound, not a wait, and stays a constant for TSK-1299.

## Outcome

After this merges, an adopter whose remote answers slowly can push without refusals, and can tune the wait on the default branch's policy; an agent whose clone lacks tracking refs gets a guard refusal that names the fetch that clears it.

## Acceptance Criteria

- AC-1 When the destination does not answer within the configured wait and attempts, the pre-push hook and `codeflow ci` shall still refuse with `ci.destination_unavailable` and a failing exit status; evidence: `pre_push_waits_as_long_as_the_default_branch_policy_says` (its 1 s case) and, for a direct `codeflow ci`, `a_head_sets_no_wait_for_the_hook_and_ci_reads_the_authority_it_names`, in `crates/codeflow-cli/tests/policy_authority_journey.rs`.
- AC-2 The per-attempt wait, the attempt count and the fetch wait shall come from `git.remote_query_timeout_seconds`, `git.remote_query_attempts` and `git.remote_fetch_timeout_seconds`, defaulting to 30, 3 and 120, declared once with default, bounds, class and reason; evidence: `crates/codeflow-core/src/hooks/limits.rs` and its test, `remote_query_keys_accept_whole_numbers_from_one_and_refuse_the_rest`.
- AC-3 When a key holds zero, a negative or fractional number, a value over what a u64 holds or a non-number, the validator and the loader shall refuse it, naming the key, and nothing shall wrap or panic; evidence: `remote_query_keys_accept_whole_numbers_from_one_and_refuse_the_rest`, and the largest values in `a_slow_destination_answers_within_the_policy_timeout`, which prove an answering query neither wraps nor panics. They do not show a silent query is bounded: at such values it is not, as the policy reference states.
- AC-4 A timed-out lookup's refusal shall name the wait, the attempts, the measured time and the keys; evidence: `a_timeout_names_the_limits_the_measured_time_and_the_keys` and the journey test's 1 s case.
- AC-5 An answer slower than the old fixed wait shall refuse under that wait and pass under the shipped default; evidence: `a_slow_destination_answers_within_the_policy_timeout` (11.3 s against 10 s and 30 s, scaled by 50), the journey test (1.5 s against 1 s and 3 s) and a real-time run of a fake 11.3 s destination on the pre-push hook: the base build (1cbf73aea) refused after 30.6 s of three 10 s attempts, and the build at e996ee72b passed after 13.2 s.
- AC-6 Every caller of the remote query shall use the configured values: the pre-push push set, `codeflow ci`, `task status`, the id sync and the fetch of a missing tip; evidence: the PR diff.
- AC-7 On every path the pre-push hook takes, the keys shall be read from the default branch's committed policy, never from the working copy or a pushed head; a direct `codeflow ci` shall read them from the authority its caller or range selects, as it does every rule; evidence: `push_set::probe_limits`, `a_policy_with_no_default_branch_never_sets_the_waits` and `a_head_sets_no_wait_for_the_hook_and_ci_reads_the_authority_it_names`.
- AC-8 (journey) When the remote's tracking refs are missing and the remote never answers, a guarded command making one lookup shall refuse after the guard's 10 s wait, before its 20 s deadline, naming the wait and `git fetch <remote>`; the guard shall let that fetch through and no line that does anything more, and after it the same command shall pass with the remote still silent; evidence: `the_guard_refuses_a_silent_remote_after_its_wait_and_a_fetch_clears_it` and `only_a_plain_fetch_gets_the_recovery_allowance`.
- AC-9 The policy reference, the destination remedy and the changelog shall name the keys, their defaults and bounds, and the guard's wait with the fetch that clears it; evidence: `docs/policy-reference.md`, `crates/codeflow-core/src/remedy.rs`, `changelog.d/TSK-1301.md`.
