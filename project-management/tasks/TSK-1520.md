# TSK-1520: The standalone codeflow ids check and doctor's id check verify the commit graph once per run

## Description

The standalone `codeflow ids check` command and `codeflow doctor`'s id check open no `history::judgment()` scope, so every git history query they make reads the overlay and graph snapshot again and verifies the whole commit graph. `codeflow ci` already runs its id-registry check inside a scope and is not changed. Filed by coord/records on 2026-11-16 from coord/ci's cost report (workspace `coordination/coordinators/parallel/notes/ci-amendable-binding-cost-2026-11-16.md`, section "Cost of `codeflow ids check`", lines 171-187, added at commit `307fa9be2`); revised after Codex's review at `9400c6572` (`coordination/coordinators/planning/reviews/ids-check-single-graph-read-9400c6572-codex.md`, workspace `af7989260`), and again after its delta review at `99467a546` (`coordination/coordinators/planning/reviews/ids-check-single-graph-read-b-99467a546-codex.md`, workspace `45c17cdf7`).

The measurement (coord/ci, 2026-11-16, installed binary 4.0.0 `ad5971c8d`; cost report lines 173-181): one run of `codeflow ids check` with no base or head, in a scratch `git clone --shared` of `main` holding all 642 branch and remote-tracking refs (493 distinct tips, 21 of them landing lines), was stopped at the 1200 s cap with no verdict. From 4 minutes on, every sample was in `check > reconcile > inventory::landed_among > Git::is_ancestor > check_history > history::check_command > read_snapshot > history_graph::verify > verify_entries`, with `verify_entries` holding about 4,500 to 5,200 of 6,500 to 7,100 samples. Only that one run was allowed, so how the cost scales was modelled, not measured.

The path, on `main` at `ec8d5c1ab3` (on the EPC-022 line at `d9c709e21f` where noted):

- The `ids check` arm, `crates/codeflow-cli/src/cmd/ids.rs:119-163`, returns early when durable work tracking is off (`:124-128`); otherwise it calls `check::check` (`:139`) and then, with a base and head, `check::merge_rule` (`:150`). No `history::judgment()` appears in `cmd/ids.rs`, `crates/codeflow-core/src/ids/` or `crates/codeflow-core/src/doctor/` on either commit.
- `check::check` is `crates/codeflow-core/src/ids/check.rs:52`; it returns before any guarded history read on a shallow clone or when no registry is found (`check.rs:54-69`). `merge_rule` is `check.rs:252`.
- `inventory::landed_among` (`crates/codeflow-core/src/ids/inventory.rs:541-567`; `:575` on the line) calls `Git::is_ancestor` for each landing tip until the first one that holds the introduction (`inventory.rs:548-550`; `:583` on the line), so at most once per landing tip.
- `Git::is_ancestor` (`crates/codeflow-core/src/ids/git.rs:180-188`) runs `git merge-base --is-ancestor`. Before every `log`, `rev-list`, `merge-base`, `cherry` or `diff-tree` child, `Git::check_history` (`git.rs:44-53`) calls `history::check_command` (`crates/codeflow-core/src/workgraph/history.rs:348`; `:361` on the line), which runs `history::check` (`history.rs:104`; `:117` on the line).
- `history::check` reads the overlay and graph snapshot through `snapshot` (`history.rs:65-76`; `:78` on the line). Inside a `history::judgment()` scope (`history.rs:30-44`) the snapshot is memoized per repository; outside one, every call runs `read_snapshot` (`history.rs:81`; `:94` on the line), which runs `history_graph::verify` (`crates/codeflow-core/src/workgraph/history_graph.rs:307-365`) and reads every commit in the commit-graph (`verify_entries`, `history_graph.rs:267-303`).
- `codeflow ci` already runs `merge_rule` inside a scope: on `main`, `run_checks` opens it at `crates/codeflow-cli/src/cmd/ci.rs:369`, and `record_checks` (`ci.rs:698`, `:1252`) reaches `id_registry::dispatch` (`ci.rs:1322`), which calls `merge_rule` (`crates/codeflow-cli/src/cmd/ci/id_registry.rs:51`). On the line the scope is opened by `run_timed` at `ci.rs:387`, with `record_checks` at `:782` and `:1405`, `id_registry::dispatch` at `:1478` and `merge_rule` at `ci/id_registry.rs:55`.
- `codeflow doctor` calls `ids::check::check` at `crates/codeflow-core/src/doctor/mod.rs:3487` (`:3561` on the line) with no scope.

The fix: run the standalone arm's `check::check` and `merge_rule` together inside one `history::judgment()` scope, and `doctor`'s id check inside its own scope kept local to that check, so the overlay and graph snapshot is read and verified at most once per repository per run (coord/ci's fix 1). Both are read only (`cmd/ids.rs:48`; the check, ledger and inventory paths call no registry-writing operation), which the scope requires ("Do not retain this scope across Git mutations", `history.rs:29`).

The snapshot boundary this accepts, the same contract `codeflow ci` already has: inside the scope, overlays and the ordinary shallow boundary are read once per repository (`history.rs:65-91`), so an overlay or shallow boundary added after the snapshot is read need not be noticed during that run. `history::check` still runs `Verified::check` on every query (`history.rs:104-107`; `history_graph.rs:165-180`), and `check_command` still reads `GIT_SHALLOW_FILE` (`history.rs:348` onward). Equal verdicts are therefore claimed for fixed inputs, not for metadata that changes during a run.

Amended 2026-11-17 at review (Codex review of `fbf74cbc83`); the paragraph above stays as the earlier text. In the ids check the overlay state is read per query: every spawned history query is guarded by `history::check_query`, which reads the replace refs, graft files and the ordinary shallow file again for that query, from the same sources and with the same refusal text as a query outside a judgment. Only the commit-graph verification is shared across the run, and its identity is still checked per query. Judging Git children run with `GIT_NO_REPLACE_OBJECTS=1` (`history::command`), so a replace ref added after the last guard does not change the objects a child reads. AC-2's sentence on the snapshot boundary reads accordingly. Evidence: the overlay-state tests in `crates/codeflow-core/src/ids/check.rs`, which change each of the three inputs between `check` and `merge_rule` in one judgment, and check that a spawned query reads the recorded objects under a replace ref.

The two changes are independent.
- coord/ci's fixes 2 (one ancestry query per introduction and tip pair in `landed_among`) and 3 (record blobs read once per run, on the EPC-022 line through TSK-1306's `Uids`) are not part of this task.

Non-goals: no change to what `ids check`, `merge_rule` or `doctor` report or refuse on fixed inputs; no change to production behaviour in `history.rs` or `history_graph.rs` (the graph identity checks stay), with test-only access to the `SNAPSHOT_READS` counter allowed; no scope across all of `doctor`; no change to `codeflow ci`; no ancestry cache in `landed_among`; no change to how many git children list and read the code refs' records; no hard time bound (see AC-3).

## Outcome

After this merges, an operator or session running `codeflow ids check` or `codeflow doctor` gets the id check with the commit graph verified at most once per run instead of once per history query, with the same findings and exit code on the same inputs.
