# TSK-1308: A landed candidate branch is removed by tree-equality proof

## Description

A landing candidate branch whose tree landed on its line stays behind when the line got the same tree through another commit, so its commits are not reachable from the line and the ordinary merge proof fails. Local branches candidate/epc-022-c3b, c3b-full, c3b2, c3b3 and c3b4 are in that state on 2026-11-03. This task adds a sanctioned removal: a candidate branch can be removed when its tree equals a tree on the line's first-parent history, proved from the commit objects. Non-goal: any task branch, which keeps today's merge proof.

Scope amendment (Director's ruling, 2026-11-03 and 2026-11-04; AC-8 added for it): stale local refs also block pushes and claims. TSK-1039's push was refused by `work.criteria_frozen` because the local branch `candidate/epc-022-c3c6` (tip ee6da4b34, never landed, replaced by candidate c3d1) holds a merge of its pull request head at 6c884608d, and git-guard refuses `git branch -D` on it. `codeflow work claim TSK-1306` was refused because the local branch `task/TSK-1306-the-landing-gate-is-chosen-by-what-the-candida` (05f7e3cd9, from an earlier use of the id) counted as a claim. AC-1 decided the checks tell a leftover local copy from live work, so both branches and their commits stay; renaming them or adding a second ref by hand is ruled out.

AC-7 amended (coord/ci, 2026-11-04): the 2026-11-03 premise above was wrong for c3b-full, c3b2 and c3b3, whose trees differ from every commit on the line's first-parent history. The route refused them, failing closed, which is the correct outcome, so AC-7 now asks that each named branch be put through the route: removed when its tree is on the line, kept with the refusal recorded otherwise.

## Outcome

After this merges, whoever landed a candidate can remove its leftover branch with a recorded proof, without arguing from its name or age.

## Deliverables

- The proof and the removal route: provisional home in the worktree and branch cleanup code the `codeflow` CLI already has; AC-1 decides.
- Guidance: `.codeflow/rules/worktrees.md` "Cleanup".

## Acceptance Criteria

- AC-1 Before any change, the builder shall name the existing cleanup route and the guard rule that refuses this removal today, reproduced on a fixture; evidence: the refusal output and file:line.
- AC-2 A branch of the project's candidate naming shall be removable when its tip's tree equals the tree of a commit on the target line's first-parent history, checked from the commit objects at a freshly fetched tip; evidence: a positive fixture for a line that got the same tree through a different commit.
- AC-3 The removal shall be refused, naming the cause, when the trees differ, the tree is on a side branch only, the line or the branch cannot be read, the branch has an open pull request, a worktree uses it, or the branch is not of the candidate naming; evidence: one negative fixture per case.
- AC-4 The removal shall record the branch, its tip, the matching line commit and the tree in the ledger; evidence: an output and ledger test.
- AC-5 The candidate naming and the depth of history searched shall be project settings with defaults, not hardcoded; evidence: tests for the default and an override.
- AC-6 The cleanup guidance shall name this route as the merge proof for a candidate branch; evidence: the text diff.
- AC-7 (journey) Each branch named in the Description that still exists when this lands is put through this route: a branch whose tree is on the line is removed, and a branch the route refuses is kept with the refusal recorded; evidence: the command output. Cross-lineage security review, as this changes what a guard allows.
- AC-8 In a clone with a remote, a local branch that no remote holds and no worktree has checked out shall count neither as a completion outside a pushed range nor as a claim of `work claim`, and the claim shall name it as information; the same branch shall still count once a remote holds it or a worktree has it checked out, and every local branch shall count in a clone with no remote or when the refs or worktrees cannot be read; evidence: fixtures for each case, then TSK-1039's `codeflow ci` without `work.criteria_frozen` and `codeflow work claim TSK-1306` going ahead while `candidate/epc-022-c3c6` (ee6da4b34) and `task/TSK-1306-the-landing-gate-is-chosen-by-what-the-candida` (05f7e3cd9) still exist.
