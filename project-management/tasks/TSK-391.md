# TSK-391: Every Windows path spelling the guards meet is mapped or refused

## Description

Sources, all Windows path spellings the guards do not yet map, gathered into one outcome because they share the Windows path normalisation and each review said to revisit them together:

- SEC-371-01 (PR 235, TSK-371): the guard case walk fails closed again on a repository rooted at a bare drive (the base keeps its verbatim prefix, `strip_prefix` fails and the check returns `None`) and on a drive-relative token like `C:foo` with a missing first component (`crates/codeflow-core/src/hooks/git_guard.rs:3149-3172`, `:1916-1931`). Refuse both, as `testing/setup/wizard.rs:266` does.
- PR 238 (TSK-372): wildcards in a UNC server or share component are never expanded (`git_guard.rs:2563-2570`, `prefix()` at `:2429-2440`); verbatim UNC roots (`\\?\UNC\...`) keep the glob reading and its false refusal. Info.
- PR 237 (TSK-276) second confirm: 8.3 short-name aliases (`CLAUDE~1`, `CODEFL~1`, `DOCS-P~1`) in planning paths. TSK-276 refuses `~digit` only in a declared index's stem. Security low, speculative.
- SEC-377-3 (PR 246, TSK-377): device-namespace spellings other than the verbatim drive prefix (`\??\C:\...`, `\\localhost\C$\`, `\\?\UNC\localhost\C$\`) are not mapped in `portable_path.rs`; existing targets are rescued by canonicalize, files not yet created are not. Info.

Outcome: **every Windows path spelling the guards and the planning-path check meet is either mapped to the path it names or refused.**

First added to EPC-023 (4.1.0) on 2026-10-18; moved to EPC-022 (3.2.0) the same day after the Codex review of PR 249, under the operator's rule that every security gap and every defect that forces an adopter workaround or blocks work belongs in 3.2.0.

## Acceptance Criteria

- AC-1 A repository rooted at a bare drive and a drive-relative token with a missing first component shall be refused by the case walk, not passed through `None`; evidence: cases added to `disk_case_resolves_verbatim_temp_paths_and_keeps_patterns`. (serves EPC-022 AC-85)
- AC-2 A UNC prefix holding glob characters shall be refused as unreadable, and a verbatim UNC root shall not be read as a glob; evidence: tests.
- AC-3 Any planning path component holding `~` followed by a digit shall be refused by `amendment_path`, for every planning path and declared index; and a native Windows run with 8.3 names enabled shall record whether Git for Windows lets such an alias reach `.claude` or `.codeflow` (with `core.protectNTFS` at its default), or the case shall be marked unconfirmed in the record with the reason no native run was possible; evidence: tests and the native run or the unconfirmed mark. (serves EPC-022 AC-85)
- AC-4 The device-namespace spellings listed above shall map to their drive path or be refused, for existing and not-yet-created targets; evidence: tests.
- AC-5 (journey) On a hosted Windows runner, the installed build's guards shall refuse a write to `.claude/settings.json` through each spelling above; evidence: the run URL.
- AC-6 (was TSK-345 AC-1) On a native Windows runner, a test drives the guard with `/cygdrive/c/...` and MSYS2 or Cygwin `/home/<user>/...` spellings of a startup file and records whether each is refused. Evidence: the test and its Windows output.
- AC-7 (was TSK-345 AC-2) When a reproduced spelling is allowed, the guard refuses it after the fix, with a test that fails before the fix and passes after on Windows; when a shell is not supported instead, the docs say which shells the guard covers on Windows and why. Evidence: the test pair or the docs diff.
- AC-8 (was TSK-345 AC-3) Git Bash spellings (`/c/...`, `C:/...`) stay refused. Evidence: the existing Windows drive-spelling test still passes.
- AC-9 (was TSK-345 AC-4) On a native Windows runner, a command that writes a startup file through a Cygwin or MSYS2 home spelling is refused, or the documented unsupported shell is named in the refusal-coverage docs (journey)
- AC-10 (moved from TSK-392 AC-1) The lookup shall return the same result as today for every existing test case, including case variants and missing components; evidence: the existing tests. (serves EPC-022 AC-86)
- AC-11 (moved from TSK-392 AC-2) On the reference workload, the median 50,000-entry lookup shall be no more than twice the 50-entry median; evidence: the measurement before and after, on the same host, with the residual measured after TSK-386 recorded first.
- AC-12 (moved from TSK-392 AC-3) (journey) The interpreter guard suite run with 50,000 extra entries in its temp directory shall finish within 10 percent of its time with an empty temp directory on the reference host; evidence: both timed runs.
