# TSK-389: A lookup helper that keeps stderr open costs one timeout, not three

## Description

Source: TSK-305 review finding L-3 (2026-10-16). A process the local configuration starts during the default-branch lookup (an ssh command, a credential helper) that keeps stderr open turns a good lookup into three timeouts and leaves orphan processes. It fails closed, but it still holds every push for three timeouts, so it blocks work.

Outcome: **a lookup whose answer has arrived is not held by a helper that keeps stderr open, and no helper outlives the lookup.**

The builder chooses between not piping stderr past the main process's exit and a short bounded read after exit, and records why.

First added to EPC-023 (4.1.0) on 2026-10-18; moved to EPC-022 (3.2.0) the same day after the Codex review of PR 249, under the operator's rule that every security gap and every defect that forces an adopter workaround or blocks work belongs in 3.2.0.

## Acceptance Criteria

- AC-1 When a helper keeps stderr open after the lookup's answer, the lookup shall return within one bounded wait and leave no child process running; evidence: a test with a stub helper, failing before the change. (serves EPC-022 AC-86)
- AC-2 A lookup that really fails shall still refuse under its own rule; evidence: tests.
- AC-3 (journey) With the installed build, a push whose ssh command is a stub that keeps stderr open shall finish its destination check in one wait; evidence: the journey output with timings.
