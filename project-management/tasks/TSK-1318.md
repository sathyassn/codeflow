# TSK-1318: Windows fence test reads process handles and reports timing

## Description

The hosted Windows test `a_killed_gates_target_tree_ends_before_older_binaries_get_in` failed once at line tip `fe66d4c62` (codeflow-ci run 41763959485, job 126359726029): an older take of `full-gate.lock` succeeded while `tasklist` still listed a process of the killed gate's tree. That reading cannot separate a live process from a dying one or from a recycled process ID, and `tasklist` takes long enough that it acts as a hidden delay in the test. This task replaces the reading with process handles opened before the kill and reports the timing that TSK-1317 needs. It also corrects the three texts that claim more than the code provides (`docs/troubleshooting.md`, two comments in `crates/codeflow-core/src/testing/runner/mod.rs`).

Non-goals: changing the fence or the job object, which TSK-1317 owns; loosening the test's assertion, which needs a Director ruling; the other Windows callers of `still_runs`.

The test may fail more often after this change. That is accurate and is not a reason to rerun until green: a red run is diagnosed from its timing data (Director's ruling of 22:31 on 2026-11-03, relayed by coord/ci).

## Outcome

After this merges, coord/ci can read from any hosted Windows run how long a killed gate's process tree outlives the fence.

## Deliverables

- the handle-based reading and the timing report: `crates/codeflow-cli/tests/test_gate_cli.rs`
- the timing shown when the test passes, for this one test only: `.config/nextest.toml`
- the corrected guarantee: `docs/troubleshooting.md`, `crates/codeflow-core/src/testing/runner/mod.rs`
- the measured timing from hosted Windows runs: the PR body and TSK-1317

## Acceptance Criteria

- AC-1 When the test reads whether the target or its grandchild is alive, it shall use a handle to that process opened before the gate is killed and `WaitForSingleObject(handle, 0)`, so a recycled process ID or a listing delay cannot change the reading, and the assertion that no process of the tree is alive after a successful take shall stay as strict as it was; evidence: the test source and review of its diff.
- AC-2 When the assertion fails, the message shall name each process still alive by role and process ID and give the kill-to-take time and each process's kill-to-end time; when the test passes, the same timing shall appear in the hosted log; evidence: the test source, `.config/nextest.toml` and a hosted Windows job log.
- AC-3 The troubleshooting page and the two `runner/mod.rs` comments shall state what is guaranteed until TSK-1317 lands: the kill-on-close job ends the tree when the gate dies, and nothing orders the fence's release after the tree's end; evidence: the diff and `guide_altitude_budget`.
- AC-4 (journey) The changed test shall run on the hosted Windows partition, and the PR body shall report its timing and its result, pass or fail; evidence: the hosted job log. This host is macOS, so no local run can stand in for it.
