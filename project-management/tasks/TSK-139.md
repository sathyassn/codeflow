# TSK-139: qualify each designated catalog seat version natively

## Description

The managed catalog (`current-ensemble.json`, schema 5) designates seat
versions with empty `qualification` arrays, and `codeflow doctor --check
model-bindings` warns "designated version with no full-suite record" for
each of them. This task runs the native `cf-evaluate-model` full suite for
each designated seat version on each harness the catalog names, and adds the
approved result to that version's `qualification` evidence as each one
passes. A version that fails keeps its designation record unchanged and the
failure is reported to the operator; it is never recorded as qualified.

Trigger: the first release candidate after EPC-018 lands on `main`, and
again for each later designation of a new version.

Inputs from TSK-078's identity canary
(`docs/verification/tsk-078-autonomy-catalog.md`): the Claude pinned and
alias launches served the designated ids; the Grok launch requested
`grok-4.7` and its session record named `grok-4.7-build` as the served
model, which is recorded as drift until settled; `gpt-6-astra` and
`gpt-6-sol` were observed at high in the session records of running Codex
review seats (Codex records the requested model, not a served id); and
`gpt-5.6-sol` and `gpt-6-luna` were not observed at all, so they carry
reduced assurance until this task observes them.

Non-goal: changing designations, seats or duties.

## Affected surfaces and interfaces

- `assets/base/agents/skills/cf-model-orchestrator/resources/current-ensemble.json`
  (`qualification` arrays only) and its mirrors, baselines and manifest.
- Evaluation evidence under `docs/verification/`.

## Acceptance Criteria

- [ ] For each designated seat version and harness, a native full-suite result whose requested and observed model and effort match is approved, or the version is reported as not qualified with its reason; evidence: the scored result files and `eval_kit.py` validation output.
- [ ] Each passing version's catalog entry carries its qualification record, and `codeflow doctor --check model-bindings` no longer warns for it; evidence: the doctor output before and after.
- [ ] `gpt-5.6-sol` (high) and `gpt-6-luna` (medium), unobserved at TSK-078, are launched natively by pinned id with requested and observed model and effort recorded, or stay recorded as unavailable with the reason; evidence: the verification record.
- [ ] The Grok served-id question (`grok-4.7` requested, `grok-4.7-build` recorded) is settled as a naming of the same version or as drift under the ADR-0069 rule; evidence: the vendor record and the decision.
