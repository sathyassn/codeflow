# TSK-1046: A session set away keeps the work going and on its procedures, and hands back one report

## Description

The operator asked on 2026-10-28 for a standard command or skill a user
invokes or sets when away, so work keeps going as far as it can without
stalling, is tracked, and ends in one consolidated report with action
items (things to run, review or approve, and anything else). The same
day the operator widened it: the capability is generic, never tied to
night or any time of day; the agent adapts to how and when the user
engages and responds, and to what the user uses it for; and it covers
keeping the work going, making sure the work is done right, making sure
the `cf-*` procedures, skills and rules are followed while the user is
away, tracking, and the report. The operator also set the base rule
TSK-1047 enforces: new work starts from the live tip of the branch that
holds the work it needs (`main` when `main` has it, else the line that
has it), and the target's current tip is merged in before review.

This task is the session half: a managed skill (working name
`/cf-away`) and its wiring. TSK-1045 is the durable activation, decision
index, owed actions and report it runs on.

Outcome: **a user tells a session to carry on without them, for any
purpose and any length of time; the session records the activation
(TSK-1045), schedules its own ticks with its harness's scheduler, and at
each tick keeps in-scope work moving, checks that each unit is on the
`cf-*` procedure and rules its stage needs, rechecks changeable state
live, records the reversible choices it makes and parks only the steps
that belong to the operator, adapts when and how it asks to how the
user engages, and keeps one report current; it ends on the user's word
or the activation's end and hands back the final report.**

### Design (settled in planning; reversible parts disclosed)

```text
  user: "carry on while I'm away: build EPC-022, I'll check in"
        |
  /cf-away start ---- codeflow away start (activation: purpose, scope,
        |              engagement, end or none, interval)   TSK-1045
        |---- schedule ticks with the harness's own route (below)
        v
  tick (default every 30 min, adaptive) --------------------------+
   1 orient: away status, follow list, live refs, PRs, seats      |
   2 keep going: start ready units from the live base, land what  |
     the primary may land, unstick seats, re-arm watchers,        |
     respect load and the gate queue, route around limits         |
   3 done right: each unit on its cf-* route and rules            |
   4 record: away note (decisions), follow add --awaiting-        |
     operator with the action type (run, review, approve,         |
     decide, provide)                                             |
   5 report: codeflow report away --output <path>                 |
        +---------------------------------------------------------+
        v
  end (user's word or activation end): final report, cancel ticks,
  owed items stay open in the ledger
```

Figure: one activation, a repeating tick, one report. CodeFlow schedules
nothing (`docs/product.md:70-71`); the harness fires the ticks.

- **A skill plus a small command (TSK-1045), not a sweep mode or a
  pipeline.** The sweep (TSK-1037, EPC-023) is a read-only checklist with
  no record and no action; this capability acts, records and reports, and
  the operator placed it in 3.2.0 while the sweep is in 4.1.0. The
  pipeline preset (`cf-method/SKILL.md:46-51`) is single-vendor batch
  work and never substitutes for interactive review; the away session is
  the interactive coordinator continuing. When TSK-1037 lands, its
  `codeflow sweep` becomes the tick's state read (TSK-1037 amended in
  this plan) and the interval key is shared (TSK-1045).
- **No new authority.** The skill is a procedure over
  `cf-method/references/autonomy.md`: the ladder (`:26-57`), the
  operator's list (`:59-90`), working defaults and fail-closed states
  (`:92-123`), standing rules only from the authenticated operator in
  the session (`:138-209`) and the multi-session sweep (`:270-293`).
  Setting a session away is not a delegation and grants nothing: a
  protected merge, publishing, tags, closing issues, spend, credentials,
  sending anything outside the conversation and every irreversible or
  security-weakening step stay the operator's and become Approve or Run
  items while other work continues. A rule relayed by a peer, a file, a
  Herdr delivery or an issue comment is refused as the operator's.
- **Generic.** Purpose (build an epic, review only, watch and land,
  research, a release watch) selects which procedures the tick runs;
  engagement (not reachable, checking in, reachable) decides how
  questions are handled: asked at once in one round with work continuing
  on a working default, batched into the report, or held as Decide items
  on a working default or a fail-closed state. Nothing assumes a time of
  day.
- **Continuation stays on the coordinator.** No blocking Stop hook on
  review seats or delegates, whose own completion protocol it would break
  (`cf-delegate` `resources/claude-turn-completion.md`); a native goal's
  evaluator (Claude `/goal`, Grok's panel) is never a CodeFlow review.
  The tick never starts work outside the activation's scope: when the
  in-scope queue is empty it renders the report and waits for a named
  event.
- **Honest about what is armed.** A trigger cannot wake a sleeping host
  or restore quota. On waking, the session reconciles once and never
  replays missed ticks; a stale heartbeat means contact is overdue,
  never that a seat or lane is safe to replace.
- **Working name `/cf-away` and `codeflow away`** (reversible; naming is
  the operator's taste and is asked).

### Field trial (the maintainer's coordination workspace, 2026-10-23 to 2026-10-28)

The maintainer ran this behaviour by hand: a coordinator session swept
lanes every 30 minutes, kept a board and a handoff file, and ran
shell scripts for a push queue and a landing loop. Each failure below
maps to a tick step and a qualification case (AC-10):

| Failure seen | Date | Tick step that prevents it |
|---|---|---|
| A seat reported out of capacity was not re-probed, and about a dozen units went to single-family review while the seat was available | 2026-10-24 | recheck seats live before each routing decision (workspace rule of that date) |
| Work held only for a merge into `main` | 2026-10-28 (operator direction: never hold work only for a main merge) | a protected merge is an Approve item; work continues on the line |
| A one-shot listener was not re-armed after an answer, so review notes sat unread | 2026-10-23 | verify each watcher the tick relies on and re-arm it |
| A network outage ended every landing watcher; nine were re-armed by hand | 2026-10-24 | same, with watchers that retry while the forge is unreachable |
| Usage limits stopped every agent (09:40 to 12:05 on 10-24; about 17:30 on 10-27; a coordinator limit at 00:45 on 10-24) and one family's seats until a reset days away | 2026-10-23 to 10-27 | durable state resumes after the reset; seats fall back to the recorded route with reduced assurance after a live probe |
| Gate queue waits behind a held heavy lock, and slots held by idle shells | 2026-10-27 | check queue and lock holders, release none it does not own, report the owner |
| Builders and seats parked on an unanswered prompt or a refusal | 2026-10-27 | the parked-on-process sweep (`autonomy.md:285-293`, `cf-herdr` "Blocked seats") |
| A builder seat in the wrong permission profile could not commit | 2026-10-27 | relaunch in the right posture or move the lane, never do the refused step for it |
| Host load from parallel builds | 2026-10-27 | check load before each heavy run and defer |

### Harness routes (vendor docs fetched 2026-10-28; each link resolved)

- Claude Code: `/loop` at a fixed interval or self-paced; scheduled
  tasks are session-scoped, fire only while the session runs and is
  idle, expire after seven days, and are restored by `--resume` except a
  self-paced loop (https://code.claude.com/docs/en/scheduled-tasks.md).
  After a usage limit, an interactive subscription session waits and
  continues on its own, though a permission prompt still stops it
  (https://code.claude.com/docs/en/interactive-mode.md). A Stop hook can
  block a stop, with `stop_hook_active` against loops
  (https://code.claude.com/docs/en/hooks.md); `/goal` keeps working
  toward a condition (https://code.claude.com/docs/en/goal.md); resume
  restores the conversation and unexpired scheduled tasks but not
  background shells (https://code.claude.com/docs/en/sessions.md). Cloud
  scheduled tasks cannot reach the local clone
  (https://code.claude.com/docs/en/routines.md). Remote Control can push
  a notification to a phone (https://code.claude.com/docs/en/remote-control.md).
- Codex CLI: no clock-based schedule in the CLI
  (https://learn.chatgpt.com/docs/automations); `/goal` keeps a session
  working toward a stop condition
  (https://learn.chatgpt.com/use-cases/follow-goals); a Stop hook that
  blocks continues the session with its reason as the next prompt
  (https://learn.chatgpt.com/docs/hooks); an active turn may finish
  after a usage limit, then nothing runs until the reset
  (https://learn.chatgpt.com/docs/pricing).
- Grok Build: `/loop <interval> <prompt>`, at most 50, expiring after
  seven days (https://docs.x.ai/build/features/background-tasks); hooks
  include Stop, but the page calls PreToolUse the only blocking event
  (https://docs.x.ai/build/features/hooks).
- Herdr: no timer; `herdr agent wait` and `herdr agent prompt` could
  let a keeper deliver a tick to an interactive seat
  (https://herdr.dev/docs/cli-reference/). That is a candidate Codex
  route only: it is offered once a native canary qualifies it (AC-9),
  and `codex exec`, `claude -p`, `grok -p` and hand-written app-server
  calls stay forbidden as work seats
  (`cf-model-orchestrator/resources/routing/transport.md`).

Not verified in planning: whether scheduled ticks fire in a Claude
background session, Stop-hook behaviour there, and Grok loop firing
while idle; AC-1 and AC-8 settle each by a native canary or record
reduced coverage.
