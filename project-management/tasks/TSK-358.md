# TSK-358: Hosted Linux and Windows gates run on ready pull requests into integration lines

## Description

Source: the hosted-red diagnosis of 2026-10-17 ("Main merge impact and the
process gap") and the operator's direction of the same day, relayed by the
primary, to close that gap.

This repository's `.github/workflows/codeflow-ci.yml` runs its Linux and
Windows gate jobs on a pull request only when the base is `main` or
`master`: the `if:` of `gates`, `gates-coverage`, `gates-coverage-report`,
`gates-verdict`, `windows-build`, `windows-tests`, `windows`,
`windows-release-journey`, `windows-journeys` and `windows-verdict` (lines
102, 283, 364, 416, 455, 513, 571, 621, 638 and 680 at `eaf2ed04e`). A
task pull request into `integration/**` therefore lands with those jobs
skipped, and its first Linux and Windows result arrives after landing.
PRs 209 and 210 show this: their rollups mark every Linux and Windows job
SKIPPED, they merged at 17:27 UTC on 2026-10-17, and their pushes added new
failures to a line that had been red since 2026-10-12. The shipped template
(`assets/base/ci/codeflow-ci.yml`) has no such restriction; the
restriction is this repository's own.

Outcome: a pull request into an integration line gets hosted Linux and
Windows verdicts before it lands, once it is ready for review, and a draft
does not spend a run.

Cost, measured from run 39053855357 on 2026-10-17: about 157 runner minutes
per run (55.6 Linux, 101.7 Windows) across 29 jobs, about 31 minutes from
start to finish. The repository is public, so standard GitHub-hosted runner
minutes are not billed. The real costs are the account's concurrent job
slots, which every workflow shares (one run asks for up to 20 jobs at once:
12 Windows partitions, 5 gate parts and 2 coverage shards), the queueing
that causes for other runs, and about 31 minutes of waiting per ready push.
At this line's recent rate (17 merged pull requests from 2026-10-12 to
2026-10-17) that is a few extra runs a day; a new push to a ready pull
request cancels its run in progress (the workflow's `concurrency` group).
Until TSK-359 lands, the push that lands each pull request runs the jobs
again.

Non-goals: changing the shipped template, repository rulesets (the
operator's), the secret scan, canary and security review jobs, and hosted
reuse (TSK-359). Product surface: this repository's CI only.

## Deliverables

- triggers and conditions: `.github/workflows/codeflow-ci.yml` (`pull_request` types adding `ready_for_review`; each listed job's `if:` admitting a non-draft pull request into `integration/**`), with the header comment updated
- parity and tests: `scripts/gate-parity.py` and `scripts/test_gate_parity.py`, if they read job conditions
- contract text this makes stale: the hosted-evidence sentence in `AGENTS.md` under "Project-specific instructions" (written by TSK-360)
- operator proposal: the exact ruleset change that would require `codeflow gates` and `windows` on `integration/**`, in the pull request body for the operator to decide; no settings change

## Acceptance Criteria

- AC-1 When a pull request into `integration/**` is ready for review, every
  Linux gate part, both coverage shards, the coverage report, the Windows
  build, checks, all 12 partitions, journeys and release journey, and the
  `codeflow gates` and `windows` verdicts shall run on it; evidence: this
  task's own pull request run after it is marked ready, with the job list.
  (serves EPC-022 AC-55)
- AC-2 While a pull request into `integration/**` is a draft, none of those
  jobs shall run, the secret scan, gitleaks canary and security review
  shall run as before, and marking it ready shall start the gate jobs
  without a new push; evidence: this pull request's draft run and its
  `ready_for_review` run. (serves EPC-022 AC-55)
- AC-3 Pull requests into `main`, pushes, the weekly schedule and manual
  dispatch shall run the same jobs as before; evidence: the workflow diff
  and the gate parity tests.
- AC-4 The pull request shall state the measured runner minutes and wall
  time of its own ready run, whether the repository is still public, and
  the concurrency effect, so the cost stays visible; evidence: the figures
  with run links.
- AC-5 (journey) After TSK-351 has made the line green, this task's ready
  run on its own pull request shall conclude success for both verdicts
  before it lands; evidence: the run link and the line's next push run.
  (serves EPC-022 AC-55)
