# TSK-358: Hosted Linux and Windows gates run on ready pull requests into integration lines

## Description

Source: the hosted-red diagnosis of 2026-10-17 ("Main merge impact and the
process gap") and the operator's direction of the same day, relayed by the
primary, to close that gap.

At `eaf2ed04e`, this repository's `.github/workflows/codeflow-ci.yml` ran
its Linux and Windows gate jobs on a pull request only when the base is `main` or
`master`: the `if:` of `gates`, `gates-coverage`, `gates-coverage-report`,
`gates-verdict`, `windows-build`, `windows-tests`, `windows`,
`windows-release-journey`, `windows-journeys` and `windows-verdict` (lines
102, 283, 364, 416, 455, 513, 571, 621, 638 and 680 at `eaf2ed04e`). A
task pull request into `integration/**` therefore landed with those jobs
skipped, and its first Linux and Windows result arrived after landing.
PRs 209 and 210 show this: their rollups mark every Linux and Windows job
SKIPPED, they merged at 17:27 UTC on 2026-10-17, and their pushes added new
failures to a line that had been red since 2026-10-12. The shipped template
(`assets/base/ci/codeflow-ci.yml`) has no such restriction; the
restriction is this repository's own.

Outcome: a pull request into an integration line gets hosted Linux and
Windows verdicts before it lands, once it is ready for review. A draft skips the expensive gates and runs
security jobs plus verdicts that report the missing gates.

Cost, from one failed-run sample (run 39053855357 on 2026-10-17, which
failed): 157.25 summed job minutes (55.58 Linux, 101.67 Windows), 30m42s
from run start to its last update, of which about 16m14s passed before the
first job started and 14m27s was job execution; a fan-out of 19 jobs at
once (12 Windows partitions, 5 gate parts, 2 coverage shards). A green run
and queueing will differ; AC-4 measures this task's own run. The
repository is public, so standard GitHub-hosted runner minutes are not
billed. The real costs are the account's concurrent job slots, which every
workflow shares, the queueing that causes for other runs, and the wait per
ready push.
At this line's recent rate (17 merged pull requests from 2026-10-12 to
2026-10-17) that is a few extra runs a day; a new push to a ready pull
request cancels its run in progress (the workflow's `concurrency` group).
Until TSK-359 lands, the push that lands each pull request runs the jobs
again.

The operator decided on 2026-10-17 that a GitHub ruleset shall require
the hosted `codeflow gates` and `windows` checks on `integration/**`,
applied once TSK-377 has made the line green. The primary prepares the
ruleset and shows its exact content before applying it; this task carries
that as AC-6.

Non-goals: changing the shipped template, the secret scan, canary and
security review jobs, and broader hosted reuse (TSK-359). Reuse association checks found in
review are repaired here because integration pull request runs expose them. Product surface: this
repository's CI and its integration-line ruleset.

## Acceptance Criteria

  Linux gate part, both coverage shards, the coverage report, the Windows

  `codeflow gates` and `windows` verdicts shall run on it; evidence: this

  (serves EPC-022 AC-55)
- AC-2 While a pull request into `integration/**` is a draft, none of those
  expensive gate jobs shall run, while both verdict jobs shall run and fail clearly

  review shall run as before, and marking it ready shall start the gate jobs

  `ready_for_review` run. (serves EPC-022 AC-55)
- AC-3 Pull requests into `main` and pushes shall retain their gate
  selection. The weekly schedule shall run the full Linux and Windows gates

- AC-5 (journey) After TSK-377 has made the line green, this task's ready
  run on its own pull request shall conclude success for both verdicts
  before it lands; evidence: the run link and the line's next push run.
  (serves EPC-022 AC-55)
- AC-6 A ruleset requiring the `codeflow gates` and `windows` checks on
  `integration/**` shall be prepared with its exact content shown in the
  pull request before it is applied, shall be applied only after the line's
  tip has green verdicts for both checks, and shall then be verified with
  the live rules API (`gh api repos/sathyassn/codeflow/rules/branches/<line>`
  and the ruleset by id) as active and requiring both checks, with any
  bypass actor named; a pull request into the line with a red or missing
  check shall then show as blocked; evidence: the shown content, the
  apply time against the green run's time, the API read-back, and one
  blocked pull request's merge state. (serves EPC-022 AC-55)
