# TSK-1598: A local engine warns on person names in changed prose before push, within a time budget

## Description

Owner: to be assigned by the Director. Staged 2026-11-23 for coord/records.

SPC-018 R-24 to R-26a, layer 4, as the operator decided on 2026-11-23:
Presidio with the small spaCy English model runs locally only, before
push, and only warns. It covers changed prose lines only: docs, comments,
commit and pull request text. Its budget is about 2 to 3 seconds; over
budget it skips with a note and never delays or blocks the push. It does
not run in hosted CI unless later evidence shows it earns a place there. The
skip is the operator's explicit choice for a warn-only layer, not a
fail-open gap.

TSK-1372's non-goal, "detecting a real name in general, which cannot be
done reliably" (`TSK-1372.md:25` at `origin/main`), holds: the level
takes `off` or `warn` only. TSK-1372's criteria stay unchanged.

The adapter runs the engine as a local child process from `pre-push`,
passes only changed prose on standard input, reads entity spans back, and
verifies the pinned versions first, as the gitleaks engine is verified
(`policy-reference.md` "The commit-time gitleaks engine", main `:1093`).
That standard-input stream is the one required, allowed input of matched
text to another process (SPC-018 R-7): it stays in memory, is never
logged or written to a file, and goes to no process but the engine.
Comment lines are found with a fixed per-language comment syntax for the
languages `cf-stack` sets up.

Pull request text: pre-push has no pull request body. The one local
producer of one in CodeFlow is the body file given to `codeflow ci
--pr-body-file` (`crates/codeflow-cli/src/cmd/ci.rs` main `:95` to
`:97`), the local pull request preparation check. By SPC-018 R-26a,
layer 4 runs on that body file in a local run, warn only and within the
same budget, and never when the run is in hosted CI. Pull request text
written or edited elsewhere (the forge's web editor, another tool) is
outside the local scan, and the docs say so.

## Outcome

After this merges, with `privacy.names: warn` and the pinned engine
installed, pre-push warns on a person name in changed prose, naming path
and line; a local `codeflow ci --pr-body-file` run warns the same way on
the body file; it finishes within the budget or skips with one note; and
it never runs in `pre-commit` or in hosted CI.

## Acceptance Criteria

- AC-1 Before any change, the builder shall record in `## Findings`, with sources, the pinned Presidio and spaCy small-model versions, the engine's cold-start and per-line time on Linux and Apple silicon macOS, the score threshold chosen and its precision and recall on a placeholder corpus of at least 100 prose lines; evidence: the Findings section.
- AC-2 With a stand-in engine, a changed prose line holding a placeholder person name shall warn at pre-push naming path and line and never the name; `block` for this key shall be refused when the policy is read; evidence: adapter and schema tests.
- AC-3 Only changed prose shall reach the engine: added doc lines, added comment lines and commit messages at pre-push, and the body file at a local `codeflow ci --pr-body-file` run; code, lockfiles and data lines shall not; evidence: a test with a recording stand-in, and a CLI test that runs the installed `codeflow ci --pr-body-file` on a body holding a placeholder person name and gets the warning through the real path from the flag to the scan.
- AC-4 Budget and skip: `privacy.names_budget_ms` shall default to 2500 and accept 2000 to 3000 only; with a stand-in that runs past the budget, pre-push shall stop it at the budget, print one note naming the skip and the count of lines not checked, and complete the push with no further delay; the push's added time shall not exceed the budget plus 100 ms; evidence: a timing test with a slow stand-in, and the note text.
- AC-5 A missing engine, another version or a failing run shall be one warning that the layer could not run, and the push shall go on; evidence: tests per case.
- AC-6 Layer 4 shall not run in `pre-commit` or in a `codeflow ci` run in hosted CI (with or without `--pr-body-file`); evidence: tests with a stand-in that fails if called.
- AC-7 The child shall run with a cleared environment, the libraries' offline switches set, and no network; the prose shall reach it only on standard input and appear in no argument, environment variable, file or log; evidence: tests with a recording stand-in, and the runner source.
- AC-8 The docs shall state that the over-budget skip is the operator's explicit choice for a warn-only layer (2026-11-23), not a fail-open gap, and that pull request text written outside a local `codeflow ci --pr-body-file` run is not scanned; evidence: the doc sentences.
