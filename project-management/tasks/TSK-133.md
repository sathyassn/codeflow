# TSK-133: planning check once at work start and in CI

## Description

The planning-anchor checks run on every commit on `task/` branches with
levels hard-coded to block, refused honest work, and were sidestepped by
committing on a `fix/` branch the gate ignores. This task checks planning
once at `work start` and once in CI, for every work prefix, at a level set
by policy. It builds on TSK-103's readiness predicate and TSK-104's
preflight for any branch. Source: guardrails strand rows 3 and 21, top five
item 3.

## Affected surfaces and interfaces

- `crates/codeflow-cli/src/cmd/git_hook.rs` (pre-commit), `cmd/ci.rs`
  (`work.*` checks), `cmd/work.rs`; policy schema (level key).

## Acceptance Criteria

- [ ] AC-1 Pre-commit shall no longer re-validate the work graph and anchor
      on each commit; evidence: a hook test committing on a task branch with
      an unrelated graph defect.
- [ ] AC-2 `codeflow ci` shall run the planning checks for every work
      prefix, not only `task/`, at the level policy sets, with no hard-coded
      block; evidence: `ci_cli` tests for `task/`, `fix/` and `feat/` ranges
      and each level.
- [ ] AC-3 `work start` shall accept a task whose record is on its
      integration target line, the case refused on 2026-09-26, or cite the
      TSK-103 test that already proves it; evidence: a `work start` test on
      an integration-line fixture.
- [ ] AC-4 (journey) In a freshly scaffolded project at the full tier the same
      checks and default level shall apply, and `codeflow update` shall keep
      an adopter's explicit level; evidence: `init_e2e` and an update test.
