# TSK-1568: Quick gate runs every contract target and lists all failures

## Description

Source: requested by the Director on 2026-11-20, from Opus's finding M1 in the TSK-1554 whole-unit review and the TSK-1476 quick-gate letter. Filed by coord/records.

When `codeflow test --mode quick` is red, nobody can tell whether the red is the one known inherited failure or several, because the `contract-scans` target stops at the first failing contract test binary. Every pull request that binds an inherited red needs the full list of failures, and today each one has to rerun the remaining targets by hand.

Checked here, at origin/main `17510e9bd4` (the local remote-tracking ref; not fetched):

- The quick gate's `contract-scans` target runs `python3 -B scripts/contract-scans.py` (`.codeflow/test-config.json:185-190`, blob `22debe3e1f`).
- That script builds the cargo command (`scripts/contract-scans.py:45-49`, blob `ed997bf8d7`): one `cargo test -p codeflow-core --test <scan> ... --quiet` over every `crates/codeflow-core/tests` suite not in `OUTSIDE_SCANS` (32 suites at this commit: 45 discovered, 13 outside), then three single-test `codeflow-cli` commands (`:50-54`). None carries `--no-fail-fast`, so cargo stops after the first failing test binary.
- The script then returns at the first command that exits non-zero (`:74-75`), so the three `codeflow-cli` commands after a failing core command never run either.
- No `--no-fail-fast` appears in `crates/codeflow-core/src/testing` or `crates/codeflow-cli/src`; the target is a custom command, so the fix belongs in the script.
- The nextest profile sets `fail-fast = false` (`.config/nextest.toml:8`, `:25`), but `contract-scans` uses `cargo test`, not nextest, so that setting does not reach it.

Evidence of the effect:

- Opus's M1 on TSK-1554 (`coordination/coordinators/capabilities/reviews/tsk1554-whole-opus.md:98`, sha256 `ee2e53531510795b14f3681053641b3a757e88fee2fbeb8385bd55b92a6b71b4`): the quick log lists 32 `--test` targets, only 13 result blocks follow, and the run stopped at `manifest_consistency`; 19 targets never ran.
- The quick log it cites (`coordination/coordinators/capabilities/notes/tsk1554-build/quick-unsandboxed.log`, sha256 `dded3fcdbb8d334eb27240d1fdb21f166e2a1242045c3685828f209062153908`), lines 124-125: `error: test failed, to rerun pass '-p codeflow-core --test manifest_consistency'`, then `contract-scans: exit 101`.
- The TSK-1476 quick-gate letter works around it by running the script's four cargo commands itself with `--no-fail-fast` added (`coordination/scripts/operator/gate-tsk1476-2026-11-20-a.sh`, comment "Q6" at lines 187-195; working copy sha256 `bf6133ad9e5e065dba778c8aa20184ef4162dd84f6d003f4592cc7636d6e8ba9`, not yet committed; its committed version at workspace commit `dccb160eb` does not hold that comment).
- TSK-1538's record on its branch (`project-management/tasks/TSK-1538.md:89` at `0adb335e41`) shows the same hand rerun: the 19 remaining targets run with `--no-fail-fast`.

As reported, not checked here:

- How long the full 32-suite run takes when several targets fail; the TSK-1476 notes give 527.7 s for the whole target at `0bc4442f0f`.

Premise: read `scripts/contract-scans.py`, its tests in `scripts/test_contract_scans.py`, and the `contract-scans` entry in `.codeflow/test-config.json` before any change.

Non-goals:

- Changing which suites `contract-scans` selects, or moving any suite in or out of `OUTSIDE_SCANS`.
- Changing other targets or the full gate.
- Changing the exit status contract of the target.

## Outcome

After this merges, a red quick gate shows every failing contract target in one run, with how many targets ran and how many failed, so a pull request that binds an inherited red can cite the complete failure list from the gate log.

## Deliverables

- `scripts/contract-scans.py` runs every contract command to the end (`--no-fail-fast` on each cargo command, and no early return between commands) and ends with a summary of the targets that ran, the targets that failed and the failing tests
- tests in the script's existing test file, `scripts/test_contract_scans.py`: two failing targets both listed with a non-zero exit, and a passing run with exit zero
- the release note: `changelog.d/TSK-1568.md`

## Acceptance Criteria

- AC-1 When `contract-scans` runs and one or more contract test targets fail, the script shall run every selected target and every one of its commands to the end and print the failing tests and the target count (how many ran, how many failed); evidence: a test with two failing targets that shows both listed, and that fails before the change.
- AC-2 When any contract target fails, the script shall exit non-zero, and when all pass it shall exit zero, with the existing "ran no passing tests" refusal kept; evidence: the two-failure test's exit status and a passing-run test that exits zero.
- AC-3 (journey) When the repository's own `codeflow test --mode quick` runs at the head, its `contract-scans` log shall show every selected target's result and the summary line; evidence: the quick gate log at the head, quoted with line numbers.
- AC-4 When the change is made, it shall touch only `scripts/contract-scans.py`, `scripts/test_contract_scans.py`, the release note and any documentation of the target; evidence: the diff paths.
