# TSK-1059: Host-state operations are reachable without a blanket retry

## Description

This is a planning draft accepted from the TSK-397 design note, revision 4.1, Part C (pull request 331), where it is unit U6 (trusted operations for host-state work). The note called the unit 3.3.0; the release is 4.1.0. Part C is accepted as planning drafts only: the criteria below are drafts, and this unit takes its own whole-unit review when it is built. Part C decisions (i) to (v) apply: (i) explicit non-secret enforcement-file arguments are allowed on a qualified host under attested `W-enforcement`, and the secret-read classes override, never a file name; (ii) a patch update invalidates a record, because exact executable digests bind it and a changed binary is `Unknown` until the operator re-runs the ceremony; (iii) managed settings are a design requirement for qualification, not a vendor fact; (iv) no exclusion matcher ever, so a non-empty `excludedCommands` disqualifies and route A+ is dropped; (v) the ceremony runs through the Bash tool, never the `!` prompt, and its evidence is receipts, not operator attention.

`gh`, `herdr` and `codex` need host state that the sandbox withholds, and today a session reaches them only by a blanket unsandboxed retry. This unit finds a narrow route for each: a trusted operation with explicit authority, arguments, environment and descendants, or a documented route that the operator runs outside the session.

Route A is the session posture with the unsandboxed retry switched off (`allowUnsandboxedCommands: false`), so every unsandboxed retry is refused. This unit defines route A, reports which host-state workflows it makes unavailable (AC-6), and withdraws that report for a tool once a supported route for the tool lands.

Edges: a root. Amended 2026-11-05 by the value audit planning pull request: TSK-1056, which introduced route A and the "workflow unavailable" report, is cancelled; its AC-6 moved here as AC-6.

Non-goal: a general retry allowlist.

## Outcome

after this merges, a session can run the `gh`, `herdr` and `codex` operations it needs without a blanket unsandboxed retry, through a narrowly scoped trusted operation or a documented route the operator runs outside the session.

## Acceptance Criteria

- AC-1 `gh`, `herdr` and `codex` operations shall be reachable from a session through a narrowly scoped operation with explicit authority, arguments, environment and descendants, or through a documented route that the operator runs outside the session; evidence: one journey per tool.
- AC-2 `gh` through the keychain inside the sandbox and Herdr through a named `allowUnixSockets` entry shall each be evaluated, with their containment stated; evidence: the evaluation record, including what each route can reach.
- AC-3 Whenever no supported route exists for a tool under route A, the session shall be told that the workflow is unavailable and why; once this unit lands a route for a tool, the report of AC-6 shall no longer appear for it; evidence: a test with and without a route, observing the doctor or orient output.
  - Amended 2026-11-05: earlier text "the report that TSK-1056 introduces". Reason: TSK-1056 is cancelled and its report moved here as AC-6 (value audit planning pull request).
- AC-4 (added 2026-11-02, journey amendment: the task had no journey criterion; this one drives its own change with the built binary) When an agent session under route A in a scratch project asks for a `gh`, `herdr` or `codex` operation, it shall reach it through the narrowly scoped route or be told that the workflow is unavailable and why; evidence: the journey output. (journey)
- AC-5 With the unsandboxed retry switched off (`allowUnsandboxedCommands: false`), push, pull request, the App token helper, herdr and the Codex app-server shall still run through a narrow sanctioned route, and the command forms that route requires shall match `excludedCommands`; evidence: a test per tool with the retry off (issue 452).
  - Added 2026-11-03 by the regroup planning pull request (planning amendment, batch 3); reason: issue 452 (the sandbox is not a floor, and switching off the unsandboxed retry breaks these tools) has the same subject as this task; issue fold of 2026-11-03.
- AC-6 Under route A (retries refused, `allowUnsandboxedCommands: false` pinned), doctor and orient shall report that the `gh`, `herdr` and `codex` host-state workflows are unavailable and why, until TSK-1059 lands a supported route for a tool; evidence: a doctor and an orient test on a host with the pin and one without.
  - Moved 2026-11-05 from TSK-1056 AC-6, text unchanged, by the value audit planning pull request: TSK-1056 is cancelled, and this task now defines route A itself.
  - Amended 2026-11-05: text unchanged; how to read it after the move (PR 638 review, finding m1). "Pinned" means `allowUnsandboxedCommands: false` is set in a settings layer the project cannot override, the managed settings or the user settings, never only the project's `.claude/settings.json`; TSK-1056 AC-1 defined the managed-settings pin and is cancelled. "Until TSK-1059 lands a supported route for a tool" means, for each tool, until this task's route for that tool is in the installed build, as AC-3 states.
