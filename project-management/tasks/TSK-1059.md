# TSK-1059: Host-state operations are reachable without a blanket retry

## Description

This is a planning draft accepted from the TSK-397 design note, revision 4.1, Part C (pull request 331), where it is unit U6 (trusted operations for host-state work). The note called the unit 3.3.0; the release is 4.1.0. Part C is accepted as planning drafts only: the criteria below are drafts, and this unit takes its own whole-unit review when it is built. Part C decisions (i) to (v) apply: (i) explicit non-secret enforcement-file arguments are allowed on a qualified host under attested `W-enforcement`, and the secret-read classes override, never a file name; (ii) a patch update invalidates a record, because exact executable digests bind it and a changed binary is `Unknown` until the operator re-runs the ceremony; (iii) managed settings are a design requirement for qualification, not a vendor fact; (iv) no exclusion matcher ever, so a non-empty `excludedCommands` disqualifies and route A+ is dropped; (v) the ceremony runs through the Bash tool, never the `!` prompt, and its evidence is receipts, not operator attention.

`gh`, `herdr` and `codex` need host state that the sandbox withholds, and today a session reaches them only by a blanket unsandboxed retry. This unit finds a narrow route for each: a trusted operation with explicit authority, arguments, environment and descendants, or a documented route that the operator runs outside the session.

Edges: depends on TSK-1056 (U3), which introduces route A (retries refused, pinned by its managed-settings requirement) and owns the "workflow unavailable" report (its AC-6); this unit only withdraws that report for a tool once a supported route for the tool lands.

Non-goal: a general retry allowlist.

## Outcome

after this merges, a session can run the `gh`, `herdr` and `codex` operations it needs without a blanket unsandboxed retry, through a narrowly scoped trusted operation or a documented route the operator runs outside the session.

## Acceptance Criteria

- AC-1 `gh`, `herdr` and `codex` operations shall be reachable from a session through a narrowly scoped operation with explicit authority, arguments, environment and descendants, or through a documented route that the operator runs outside the session; evidence: one journey per tool.
- AC-2 `gh` through the keychain inside the sandbox and Herdr through a named `allowUnixSockets` entry shall each be evaluated, with their containment stated; evidence: the evaluation record, including what each route can reach.
- AC-3 Whenever no supported route exists for a tool under route A, the session shall be told that the workflow is unavailable and why; once this unit lands a route for a tool, the report that TSK-1056 introduces shall no longer appear for it; evidence: a test with and without a route, observing the doctor or orient output.
