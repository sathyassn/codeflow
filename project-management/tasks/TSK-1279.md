# TSK-1279: Heavy runs keep the caller's job cap and each target's declared workers and exclusivity

## Description

Reported by coord/parallel on 2026-11-03 at about 02:05, from the TSK-450 lane (evidence: `coordination/coordinators/planning/evidence/reserve-jobs/finding.md`, kept outside the repository). The command `sh coordination/scripts/nice10.sh codeflow reserve -- cargo test -p codeflow-cli --test ci_pin --test policy_cli`, run with the binary built at c2 head `8a32a233b`, exports `CARGO_BUILD_JOBS=2` (`coordination/scripts/nice10.sh:16`) at nice 10. It printed "codeflow reserve: 3 heavy runs share this host's 10 jobs; this command uses 3" and "[codeflow reserve] workers: jobs=3, nextest=3, rust-tests=1, oracle=3" (pid 13748, exit 101). The caller's cap of 2 jobs was raised to 3 under contention.

Related, from c2's gate log (`evidence/coverage-timeout/c2-gate.txt:1419`): `read-benchmark` ran with `jobs=3, nextest=3`, although its entry in `.codeflow/test-config.json` declares `"workers": 9` and `"exclusive": true`. TSK-1145 AC-4's key is `host_exclusive: true`, so `exclusive` may not be the key the admission reads, and the declared exclusivity was not honoured.

Follow-up of TSK-1145 (complete), which added capacity admission. Related: TSK-1278 covers worker sizing under load and the target timeout; this task covers the cap, the declared workers and exclusivity. Duplicate check (coord/planning): TSK-1128 (complete) covers reserve's lock hand-over, not job counts; TSK-1010 (EPC-023, todo) covers named shared resources; TSK-1189 covers wait records; no unpushed record in this pull request covers it.

Owner: coord/planning (builder to be staffed). Adopter-facing: the shipped test-config templates and reference carry the same key.

## Outcome

After this merges, a maintainer who sets a job cap or declares a target exclusive gets a run that stays within the cap and waits for the host, and the output says which cap it honoured.

## Deliverables

- the cap, workers and exclusivity handling in `codeflow reserve` and `codeflow test`, with tests: the files under `crates/codeflow-cli/` and `crates/codeflow-core/` that the builder confirms
- the config key and its use: `.codeflow/test-config.json`, the shipped templates under `assets/base/testing/` and the test config reference
- the release note: `changelog.d/TSK-1279.md`

## Acceptance Criteria

- AC-1 Before any code, the record shall say (file and line) how `codeflow reserve` and `codeflow test` pick jobs and nextest workers, whether either reads `CARGO_BUILD_JOBS` or another caller cap, and which config key marks a target host-exclusive (`exclusive`, as in this repository's `read-benchmark` entry, or `host_exclusive`, as TSK-1145 AC-4 says). Both cases (the cap raised, the exclusive target run with a shared share) shall be reproduced in tests that fail before the change. Evidence: the file:line notes and the failing tests.
- AC-2 A caller's explicit cap (`CARGO_BUILD_JOBS`, or a named codeflow setting the builder states) shall be an upper bound: admission may give fewer jobs, never more. `codeflow reserve` and `codeflow test` shall print the cap they honoured. Evidence: a test of each.
- AC-3 A target that declares host exclusivity shall run only when no other heavy run holds the host (it waits within the run's wait, or is reported not run), and shall never be started with a shared share. If the repository's config uses a key the admission does not read, admission shall either accept it or refuse the config with a message naming the right key, and shall never silently ignore it. Evidence: a test for the wait, one for the not-run report and one for the key.
- AC-4 A target's declared workers shall be a ceiling and a request. When admission gives fewer, the run shall say "workers N of M (host busy)" and the gate's result shall carry it. Evidence: a test of the message and the result.
- AC-5 Fail-closed behaviour shall be unchanged: an unreadable cap or config refuses, naming the cause. Evidence: a test of each.
- AC-6 This repository's `.codeflow/test-config.json`, the shipped templates and the test config reference shall use the key the admission reads. Evidence: the diff and a template check.
- AC-7 With the built binary, `sh nice10.sh codeflow reserve -- <cargo cmd>` under contention shall run with at most 2 jobs, and an exclusive target shall wait for the host. Evidence: both outputs, with the binary's path, version and source revision. (journey)
- AC-8 A changelog entry shall describe the change. Evidence: `changelog.d/TSK-1279.md`.
