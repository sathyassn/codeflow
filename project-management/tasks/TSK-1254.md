# TSK-1254: Bump pulldown-cmark to 0.13.6 for RUSTSEC-2026-0433 on EPC-024

## Description

Hosted "security review" fails every pull request on the EPC-024 line, because Cargo.lock pins pulldown-cmark 0.13.5, which RUSTSEC-2026-0433 (CVSS 7.5) lists as fixed in 0.13.6. TSK-1183 (PR 511) made this fix on the EPC-022 line only; this task brings the same fix to EPC-024. The workspace pins the crate exactly (`=0.13.5`), so `cargo update -p pulldown-cmark --precise 0.13.6` alone is refused ("failed to select a version for the requirement `pulldown-cmark = \"=0.13.5\"`"). The task therefore moves the one workspace pin and the one lockfile entry to 0.13.6 and changes nothing else. Non-goals: no code change, no advisory suppression or lock override, no other dependency update.

## Outcome

After this merges, the hosted security review passes on the EPC-024 line, and the markdown parser that reads repository and pull request files is the patched release.

## Deliverables

- Exact pin at 0.13.6: Cargo.toml
- Lockfile entry for pulldown-cmark at 0.13.6: Cargo.lock
- Release note fragment: changelog.d/TSK-1254.md
- Task record: project-management/tasks/TSK-1254.md

## Acceptance Criteria

- AC-1 When the lockfile is updated, it resolves pulldown-cmark 0.13.6 and no other package version changes. Evidence: `git diff Cargo.lock` shows only the pulldown-cmark version and checksum, and `git diff Cargo.toml` shows only the workspace pin; the checksum equals the 0.13.6 entry on the EPC-022 line.
- AC-2 When the markdown paths in codeflow-core, codeflow-cli and codeflow-present run their tests, they pass. Evidence: the test targets that touch `pulldown_cmark` modules (found with `cargo tree -i pulldown-cmark`, which lists the three crates), run through `codeflow reserve`, plus clippy and rustdoc for those crates.
- AC-3 When osv-scanner scans the repository at the head, it reports no RUSTSEC-2026-0433. Evidence: `osv-scanner scan -r --no-ignore .` output at the base and at the head. (journey)
