# TSK-1016: Dependencies carry no known zstd advisories

## Description

Fourteen RustSec advisories published in October 2026 affect `zstd` 0.13.3
(RUSTSEC-2026-0391), `zstd-safe` 7.2.4 (RUSTSEC-2026-0395 to 0406) and
`zstd-sys` 2.0.16 (RUSTSEC-2026-0410) in `Cargo.lock`. The dependency audit in
the security review job (osv-scanner, policy `git.dep_audit=block`) now fails
on every pull request into the EPC-022 line, and `security review` is a
required check on `main`.

`zstd` reaches the build only through `rust-embed`'s `compression` feature:
`rust-embed` 8 asks for `include-flate` 0.3 with its default features, and
`include-flate-compress` 0.3.4, the newest release, requires `zstd` ^0.13.3.
No published release takes `zstd` 0.14. Upstream merged that one-line bump
as commit `bfe8fcd57aed281988f1ee86edbc35fd5905239a` on 2026-09-14 and has not
released it. Dropping the `compression` feature would remove `zstd`, but the
embedded scaffold would then grow the release binary by about 4 MB and the
portal starter alone (1.75 MB unpacked) would break ADR-0048's 1 MiB
release-binary budget, which ADR-0058 keeps in force.

This task patches `include-flate-compress` in the root `Cargo.toml` to the
upstream maintainer's repository at that exact commit, so the lockfile
resolves `zstd` 0.14.3, `zstd-safe` 8.2.0 and `zstd-sys` 2.1.2. It adds no
audit suppression. The patch is removed when `include-flate` publishes a
release that takes `zstd` 0.14. Non-goal: other dependency upgrades.

## Deliverables

- the dependency fix: `Cargo.toml` (`[patch.crates-io]`), `Cargo.lock`
- the release note: `changelog.d/TSK-1016.md`

## Acceptance Criteria

- AC-1 When `Cargo.lock` is read, it shall resolve `zstd` 0.14.3 or later, `zstd-safe` 8.2.0 or later and `zstd-sys` 2.1.2 or later, take `include-flate-compress` from `https://github.com/SOF3/include-flate` at commit `bfe8fcd57aed281988f1ee86edbc35fd5905239a`, and change no other package beyond what that requires, and osv-scanner shall report none of the fourteen advisories with no suppression added. Evidence: `git diff Cargo.lock`, `cargo tree -i zstd`, and osv-scanner on the tree before and after.
- AC-2 When the release binary is built, the embedded scaffold and presentation assets shall still be read through `rust-embed` compression, and the workspace gates shall pass. Evidence: fmt, clippy `-D warnings`, rustdoc `-D warnings`, the tests that read embedded assets in `codeflow-cli` and `codeflow-present`, `codeflow test --mode quick`, and the release binary size before and after.
- AC-3 When the pull request runs, the hosted security review shall pass where it failed on the base. Evidence: the `security review` check on the pull request head. (journey)
