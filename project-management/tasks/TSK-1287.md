# TSK-1287: The working tier is named Worker in every record, doc and command

## Description

The operator decided on 2026-11-01 at about 10:25 that the working tier is named Worker: a Worker holds an assignment, and the name replaces Lane. It was never filed. ADR-0094 ("lanes as recorded sessions"), EPC-025, TSK-439, TSK-440, TSK-423, TSK-1126, `docs/coordination-ledger.md`, the skills and the CLI all say Lane. This task renames the tier everywhere a reader meets it and carries the rest of that decision. The ledger's own names (`LN-NNN`, `codeflow lane`, the `lane_*` events and flags) change on TSK-439's schema version 2 cutover with a compatible migration (TSK-439 AC-13, Director ruling of 2026-11-03), and the record of subagent Workers is TSK-439 AC-14; this task renames the guidance, docs and help around them, so it follows TSK-439.

The rest of the 2026-11-01 decision and the 2026-11-03 rulings it records:

- The tiers are the Director, Coordinators and Workers, as ADR-0094 defines them, amended.
- A Coordinator is named by its deliverable or feature.
- A Coordinator runs a bigger task as a Worker session and a small one as a native subagent Worker, and closes each when done.
- Workers default to native subagents for bounded work, and run as sessions only when the work is long-running, user-facing or uses another model family.
- The hierarchy is opt-in for large work; a lone session needs none of it.

Other uses of "lane": TSK-313 adds a project-declared `lane` field (issue 164), the track of people or agents a task belongs to, and its record calls a set of them lane classes; TSK-1095 used "lanes view" and "lane-hour" for the tier (its AC-4 and AC-6 are renamed by the regroup planning pull request). Non-goals: the ledger schema change itself (TSK-439); the effort rule per tier (TSK-1288); the sweep (TSK-1037).

Consolidated 2026-11-04 (operator ruling of 2026-11-04, consolidation planning amendment): this task absorbs TSK-1288, because the operator's tier decisions of 2026-11-01 and 2026-11-03 change the same guidance homes (`cf-model-orchestrator`, `cf-method`, the managed text and the CLI help) and are proven by the same fresh `init --standard` journey. TSK-1288's criteria follow this task's own, word for word, each with a `Moved` note naming its old id; its deliverables are listed under Deliverables with `(from TSK-1288)`, and its Description stays in its cancelled record.

Consolidated 2026-11-04 (second consolidation amendment, from the operator's sizing direction of 2026-11-04, relayed by coord/catalog): absorbed by TSK-423, because this task graded Easy (1 point) and shares TSK-423's guidance homes, cause and fresh `init --standard` proof. Its criteria AC-1 to AC-12 are now TSK-423 AC-7 to AC-18 in order (AC-n is TSK-423 AC-(n+6)), word for word with a `Moved` note each; its deliverables are in TSK-423's Deliverables marked `(from TSK-1287)`; its edges to TSK-439 and TSK-1292 are on TSK-423.
