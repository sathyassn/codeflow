# TSK-1604: Run CodeFlow's in-session guards under the Antigravity CLI (agy)

## Description

Source: operator decision, 2026-11-23 22:0x EST (`coordination/MODEL-USE.md` "Handover", workspace commit `8d45c5da2`), relayed by the Director; tracked as `TRK-agy-guard-support` in `coordination/coordinators/planning/TRACKER.md`. Target: CodeFlow v4 (preferred).

Coordinators and Workers now run on Gemini 4 Neon in the Antigravity CLI (`agy`). CodeFlow's `git-guard` and `exec-guard` run before each shell command in Claude Code, Codex, and Grok Build, and do not run under `agy`. Until they do, repository git hooks, CI, and branch protection are the only enforcement for `agy` sessions, and the command rules the guards enforce are followed by reading only.

Premise: before writing code, check whether `agy` exposes a pre-command hook point (CLI docs, config schema, or `agy --help`). If it does, wire `codeflow init` and `codeflow update` to install it failing closed; if it does not, record that fact with evidence and present the alternative (for example a wrapper shell) for operator decision.

Non-goals: weakening any existing Claude Code, Codex, or Grok Build guard wiring; blocking the Coordinator handover.

## Outcome

After this merges, `codeflow init` and `codeflow update` install fail-closed `git-guard` and `exec-guard` wiring for `agy` (or, if `agy` lacks a pre-command hook point, record that evidence and the operator-chosen alternative), and `codeflow orient` reports the `agy` guard state.

## Deliverables

- premise evidence: whether `agy` exposes a pre-command hook point and its contract
- `codeflow init` and `codeflow update` hook wiring for `agy` (when supported) or operator-approved alternative
- `codeflow orient` gates-line reporting for `agy` guard state
- guarded tests covering a refused command and a guard that cannot run under `agy` wiring
- release note: `changelog.d/TSK-1604.md`

## Estimate

- Grade: Medium; band: Medium; moved: none
- Split: not needed.
- Basis: premise check on `agy` hook surface, scaffold/adapter wiring in `init`/`update`/`orient`, and integration tests. Graded by coord/records; builder re-scores at claim.

## Acceptance Criteria

- AC-1 `codeflow init` and `codeflow update` shall install `agy`'s pre-command hook wiring, if `agy` has one, so `git-guard` and `exec-guard` run before every `agy` shell command and block on a refusal, failing closed when the guard cannot run; evidence: diff and integration tests showing installation, update idempotency, refusal, and fail-closed behavior.
- AC-2 `codeflow orient` shall report the `agy` guard state in its gates line, as it does for `claude` and `codex`; evidence: unit/CLI test output showing the `agy` guard state.
- AC-3 If `agy` has no pre-command hook point, the task shall record that fact with reproducible evidence and name the alternative (for example a wrapper shell), decided by the operator; evidence: findings section and operator decision record.
- AC-4 Tests shall cover a refused command and a guard that cannot run under the `agy` wiring; evidence: passing test logs.
- AC-5 Security-surface change: an independent cross-lineage review shall approve the exact head; evidence: verdict path in the acceptance block.
