# TSK-323: Ignored and oversized files are judged by the base revision's rules

## Description

The second step of https://github.com/sathyassn/codeflow/issues/174, on
TSK-322's path gate: a file the project's own ignore rules exclude, or a
file over a size limit, can still be committed. This task adds two keys,
both off by default and both read at the base revision, never the working
tree:

- `git.ignored_files` (`{level: off, allow: [{path, reason}]}`): the base
  revision's `.gitignore` files through a gitignore matcher; a tracked file
  is still tested; a `.gitignore` edit in the range admits nothing.
- `git.max_file_bytes` (`{limit, except_under}`): the optional size limit
  outside `except_under`; the tighter limit wins when sources compose.

Both honour TSK-322's built-in exemption and its normalization. The matcher
needs the `ignore` crate or an equivalent, a new dependency, so a tier-3
decision is recorded before any code (`Cargo.toml:36` holds
`unicode-normalization`; `ignore` is not yet a dependency). Non-goal: a
type rule beyond the name patterns TSK-322 already gives.

Amended 2026-10-29 by the content policy amendment (issue #279, design
revision 5, decision 8, taken by the operator that day with the
admission routes stated). This task stays a feature on this line by the
operator's placement of 2026-10-18 and is not relabelled. The defaults
change, because two keys that are off protect nobody on the day they
ship:

- `git.max_file_bytes` warns at 1 MiB, on by default, and blocks a new or
  changed file above 10 MiB for new scaffolds; an updated project sees a
  report line until it opts in.
- `git.ignored_files` is on at `warn` by default.
- Explicit settings are preserved. Both keys are read at the policy
  authority, the default branch at one SHA (TSK-1077), on the matcher
  TSK-428 extends in 4.2.0.

Above 10 MiB in a new scaffold, a commit that adds or changes such a file
is refused at pre-commit, pre-push and by `codeflow ci` in the hosted job.
The admission routes are: (1) Git LFS, since the gate sizes the blob git
holds, which for an LFS-tracked path is the pointer, so it passes with no
policy change; (2) a `limit` or `except_under` change in the policy on
`main` through a reviewed pull request; (3) from 4.2.0, a per-path
`admitted` row in TSK-424's register. A single-file exception does not
exist in 4.0.0 beyond naming the file's directory under `except_under`.
Legitimate large cases (model weights, datasets and fixtures, media,
vendored binaries, installers) belong in Git LFS, or in a release asset or
package registry the repository references by digest.
