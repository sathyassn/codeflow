# TSK-323: Ignored and oversized files are judged by the default branch's size and ignore rules

## Description

The second step of https://github.com/sathyassn/codeflow/issues/174, on
TSK-322's path gate: a file the project's own ignore rules exclude, or a
file over a size limit, can still be committed. This task adds two keys,
read at the policy authority, the default branch at one SHA (TSK-1077),
never the working tree or a pull request's base:

- `git.ignored_files` (`{level, allow: [{path, reason}]}`, default level
  `warn`): the authority's `.gitignore` files through a gitignore matcher;
  a tracked file is still tested; a `.gitignore` edit in the range admits
  nothing.
- `git.max_file_bytes` (`{limit, except_under}`): on by default; a new or
  changed file larger than 1 MiB warns; in a new scaffold, a new or
  changed file larger than 10 MiB is refused; an updated project gets
  report lines only, for both thresholds, until it opts in; an explicit
  `limit` or `except_under` in the authority's policy replaces the
  default.

Both honour TSK-322's built-in exemption and its normalization. The matcher
needs the `ignore` crate or an equivalent, a new dependency, so a tier-3
decision is recorded before any code (`Cargo.toml:36` holds
`unicode-normalization`; `ignore` is not yet a dependency). Non-goal: a
type rule beyond the name patterns TSK-322 already gives.

A refused file has three admission routes: (1) Git LFS, since the gate
sizes the blob git holds, which for an LFS-tracked path is the pointer,
so it passes with no policy change; (2) a `limit` or `except_under`
change in the policy on `main` through a reviewed pull request; (3) from
4.2.0, a per-path `admitted` row in TSK-424's register. A single-file
exception does not exist in 4.0.0 beyond naming the file's directory
under `except_under`. Legitimate large cases (model weights, datasets and
fixtures, media, vendored binaries, installers) belong in Git LFS, or in
a release asset or package registry the repository references by digest.

Amended 2026-10-29 by the content policy amendment (issue #279, design
revision 5, decision 8, taken by the operator that day with the
admission routes stated). Until then this record said both keys were off
by default and read at the base revision, with `ignored_files` at level
`off`. Reasons for the change: two keys that are off protect nobody on
the day they ship (decision 8 (b)), and the default branch is the only
policy authority (TSK-1077, decision 5). This task stays a feature on this
line by the operator's placement of 2026-10-18 and is not relabelled.

## Outcome

After this merges, an adopter is warned about ignored files and files larger than 1 MiB, and a new scaffold refuses files larger than 10 MiB with the routes to admit them, all judged by the default branch's policy.

## Deliverables

- the dependency decision: an ADR under `docs/decisions/` (number allocated with `codeflow adr new` in this task's PR)
- the two rules: TSK-322's path gate module, `crates/codeflow-core/src/hooks/policy_schema.rs`, `docs/policy-reference.md`, and the root `Cargo.toml` if the dependency is taken
- the scaffold defaults: the shipped policy for new scaffolds under `assets/base/` and the report path `codeflow update` uses for an updated project
- release note: `changelog.d/TSK-323.md`, naming the new defaults as a public behaviour change of 4.0.0
