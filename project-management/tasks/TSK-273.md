# TSK-273: the meaning-taken eval pack is qualified on native seats

## Description

TSK-266 added the `meaning-taken` evaluation pack (requirement CF-OUT-008)
so the guidance on what a reader could take content to mean can be
qualified natively, and left that run out of scope: only two smoke runs
with Grok subjects were recorded. This task runs the pack natively with
Claude and Codex subjects, three trials per case, graded by the other
lineage, and records the results. It also settles the runner's Grok version
gate: `evals/qualification/runner.py` accepts only Grok CLI 1.0.44 and 1.0.46
(`GROK_VERSIONS`, line 217), so a seat on another release is refused before
any key is sent. TSK-194 runs the full suite once per designated seat; this
task is the pack's own qualification and does not replace it. Non-goal:
changing the guidance or the pack's cases.

## Deliverables

- the scored results per subject and trial: provisional, under `docs/verification/`, named by the run directory
- the runner's accepted Grok versions and their tests: `evals/qualification/runner.py` and its tests

## Acceptance Criteria

- AC-1 The `meaning-taken` pack runs with Claude and Codex subjects, three trials per case, each graded by the other lineage, on a binary named by its source revision. Evidence: the scored result files and `validate-result` output.
- AC-2 Each failing case is read once by a human and given a disposition (guidance defect filed, fixture fault or accepted). Evidence: the results table.
- AC-3 The runner accepts the Grok CLI releases the designated Grok seat runs and refuses an unknown one before sending a key or prompt. Evidence: the runner's tests with an accepted and a refused version.
- AC-4 A native run of the pack on the current Grok CLI completes through the runner without a version refusal (journey)
