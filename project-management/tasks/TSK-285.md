# TSK-285: Package-manager script shell settings are guarded

## Description

npm runs every package script through the program its `script-shell`
setting names, read from `~/.npmrc`, a project `.npmrc` and the
environment; setting it makes every later `npm run`, `npm test` or install
script run a chosen program while the guards see only `npm test`
(https://github.com/sathyassn/codeflow/issues/89). yarn and pnpm have similar settings. A project `.npmrc` is a
repository file that adopters edit for registries and engines, so a
whole-file path rule would block ordinary work; this task guards the
runner keys and the commands that set them. It is split from TSK-284 for
that reason: a different file class, a key-level rule and a different
effect on adopters.

## Deliverables

- the design note: `docs/research/package-manager-runner-settings.md` (provisional)
- the guards: the command rules in `crates/codeflow-core/src/security/` and the edit check in `crates/codeflow-core/src/hooks/edit_guard.rs`
- docs: ADR-0075's sibling note, `docs/policy-reference.md`
- release note: `changelog.d/TSK-285.md`

## Acceptance Criteria

- AC-1 Before any guard code, a design note reviewed by the other lineage
  shall list the settings that choose a shell or script runner in npm, yarn
  and pnpm (config keys, files, environment variables such as
  `npm_config_script_shell`), how each is guarded (command refusal,
  key-level edit check, sandbox) and what the backstop cannot see;
  evidence: the note and its review row at a commit before the first guard
  commit.
- AC-2 `npm config set script-shell`, its yarn and pnpm counterparts, and
  the environment variable forms on a command line shall be refused,
  naming the rule and the sanctioned path; evidence: exec-guard tests per
  tool. (serves EPC-022 AC-5)
- AC-3 A native edit or shell write that sets a runner key in `~/.npmrc`, a
  project `.npmrc` or the yarn and pnpm files shall be refused, and an
  edit that leaves those keys unchanged shall be allowed; evidence:
  planted tests per file and an allow test for a registry line.
- AC-4 ADR-0075's sibling note, `docs/policy-reference.md` and the release
  note shall state the refusals and their effect on adopters; evidence:
  the doc diff.
- AC-5 (journey) When a session in a fresh project with the installed build runs `npm
  config set script-shell /tmp/x` or adds `script-shell=` to the project
  `.npmrc`, it shall be refused, and adding a registry line shall be
  allowed; evidence: a CLI journey.
