# TSK-1444: A push to the default branch reuses its pull request's run only under strict equality

## Description

Under ADR-0102 the full hosted run happens once, on the pull request into the default branch, and the push that lands it should not repeat what that run proved. The shipped GitHub template runs the full gate again on that push (`assets/base/ci/codeflow-ci.yml:26-35` on `main` at `f8aabc62c`). CodeFlow's own workflow already has a reuse job (`.github/workflows/codeflow-ci.yml:89-180` and `scripts/ci-reuse.py`), which has not had a security audit. This task gives the shipped template reuse on the push to the default branch only when the tree, the workflow files and the trust inputs are equal and each reused job really ran and passed; anything else runs in full. Non-goal: reuse on a line push, which has no hosted run (TSK-1352).

Landing on its target (`main`, alone, early):

- Reachable: the shipped template with reuse.
- Inert: adopters get it only through `codeflow update` after the release.
- Other lines: nothing.

## Outcome

After this merges, a project on CodeFlow's GitHub template gets one full hosted run per landing into the default branch, with the push that lands it reusing that run only when nothing it proved has changed.

## Acceptance Criteria

- AC-1 A push to the protected branch shall reuse a pull request run's gate verdict only under every condition TSK-359 AC-2 sets and only when that run's effective gate mode equals the push's effective mode, with sharded runs, once TSK-384 AC-5 provides them, compared per mode across the whole shard set; an essential-on-push opt-in changes the push's mode and never waives the equality; the reused verdict shall name the reused run and its mode; evidence: helper tests per condition and one hosted push run in a scratch adopter. (serves EPC-022 AC-134)

- AC-2 Every refusal case of TSK-359 AC-3, plus a mode mismatch (an essential pull request run against a full push, with and without the opt-in's change of push mode considered) and a helper read from the pushed tree, shall run every job; the secret scan, gitleaks canary and security review shall run on every push; evidence: one test per case and the hosted job list.
