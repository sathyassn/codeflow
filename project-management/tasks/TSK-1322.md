# TSK-1322: A failed claim push leaves no branch that blocks its retry

## Description

coord/ci reported on 2026-11-04 (11:36) that `codeflow work claim TSK-1318`, run in a sandbox that blocks git credentials with codeflow 4.0.0 at source 678d3fa48, created the local branch `task/TSK-1318-windows-fence-test-reads-process-handles-and-rep` at cecf1a03d and then failed its push to origin: "work claim: error: created task/TSK-1318-... locally; push to origin failed: ... could not read Username". The command was piped to `tail` without pipefail, so its exit code was not captured; the source maps the failure to exit 1 (`crates/codeflow-core/src/workgraph/readiness.rs:2031`, `crates/codeflow-cli/src/cmd/work.rs:318-324`).

The defect is what the failure leaves behind. `claim_on` creates the local branch before the push (`readiness.rs:2016`) and keeps it when the push fails, and a rerun with credentials then refused with "already claimed by a visible branch" (`readiness.rs:1984`), naming that local-only branch as if another session held the claim.

Non-goals: TSK-1308 (removing a landed candidate's leftover branch by tree-equality proof), and claims refused for a real remote branch or a branch with commits of its own, which stay refused.

## Outcome

After this merges, a builder whose claim fails to reach origin can run the same claim again and have it complete, instead of being refused by the branch the failed attempt left.

## Deliverables

- the claim change and its tests: `crates/codeflow-core/src/workgraph/readiness.rs`, `crates/codeflow-cli/src/cmd/work.rs` and their tests
- the changelog entry: `changelog.d/TSK-1322.md`

## Acceptance Criteria

- AC-1 When a claim's push to origin fails, `work claim` shall exit non-zero, print the push error, and leave no local branch it created; evidence: a test with an origin that refuses the push, checking the exit code captured directly, the message, and that the branch is absent.
- AC-2 A claim shall never count its own branch as another claim: a local branch at the claimed name that has no remote counterpart, points at the commit the claim would start from, and holds no commits of its own shall be completed by a retry (pushed, with exit 0), with the push kept create-only (`--force-with-lease=<branch>:`, `readiness.rs:2026`), so a remote branch that appeared meanwhile refuses; a local branch with its own commits, or a remote branch of that name, still refuses; evidence: a test per case.
- AC-3 (journey) With the change built, a claim run where the push cannot authenticate exits non-zero and leaves no branch, and the same claim run again with access succeeds; evidence: both commands with their exit codes captured directly.
- AC-4 A branch under rebase or bisect in any worktree (detached HEAD with rebase-merge/head-name, rebase-apply/head-name or BISECT_START naming it) shall count as checked out, so a claim or completion check never treats it as a leftover; evidence: a fixture with a worktree mid-rebase and one mid-bisect, the branch never pushed.
