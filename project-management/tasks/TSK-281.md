# TSK-281: Temporary-file writes never follow a link at the temp name

## Description

`file_lock::atomic_write` (`crates/codeflow-core/src/file_lock.rs:328-333`
at v3.1.0) writes a fixed `<path>.tmp` with `fs::write`, which follows a
symbolic link at that name. A branch that commits a link at
`.codeflow/test-config.schema.tmp` can redirect the test-config schema
write (`crates/codeflow-core/src/testing/setup/mod.rs:423`), and other
writers have their own temp paths (https://github.com/sathyassn/codeflow/issues/96 and its comment). TSK-244 fixed
the record writers through `crates/codeflow-core/src/contained.rs` and left
this class open. This task makes every CodeFlow temp write safe against a
planted link, or records why a location is trusted.

## Deliverables

- the writer: `crates/codeflow-core/src/file_lock.rs`, or a move onto `crates/codeflow-core/src/contained.rs`
- each caller named in the issue: `crates/codeflow-core/src/testing/setup/mod.rs`, `crates/codeflow-core/src/workgraph/record_template.rs` and the others the sweep finds
- tests: a planted-link test per in-repository caller
- release note: `changelog.d/TSK-281.md`

## Acceptance Criteria

- AC-1 When a symbolic link is planted at any temporary name a CodeFlow
  writer uses inside the repository, the write shall not follow it: the
  writer creates a unique temporary file exclusively without following
  links, or refuses naming the link; evidence: a planted-link test per
  in-repository caller, the test-config schema first. (serves EPC-022 AC-4)
- AC-2 Every writer named in the issue and its comment (test-config schema,
  `update --diff-out`, the record template check's scratch folder, the ID
  registry state and ledger, test gate output, recall, the home registry)
  shall be routed through `contained.rs`, fixed in `atomic_write`, or
  recorded as a trusted location with its reason; evidence: a table in the
  pull request with file:line per writer.
- AC-3 Atomic-write behaviour shall be unchanged: the target is replaced on
  success, nothing is left behind on failure, and concurrent writers stay
  serialized by the lock; evidence: the existing `file_lock` tests and a
  failure clean-up test.
- AC-4 When the installed build runs `codeflow test` in a project whose
  branch commits a link at `.codeflow/test-config.schema.tmp` pointing
  outside the repository, nothing shall be written through the link
  (journey); evidence: a CLI journey on a scratch repository.
