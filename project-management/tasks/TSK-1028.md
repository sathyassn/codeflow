# TSK-1028: Shared settings leave the status line and effort to each person

## Description

Issue #351 and its comment (CodeFlow 3.1.1). The scaffold writes two
personal preferences into the shared project settings, where they replace
each contributor's own choice: a branch-only `statusLine` and
`effortLevel: "high"` in `.claude/settings.json`, and
`model_reasoning_effort = "high"` in `.codex/config.toml`.

Read on the line tip `7172229aa`:

- the three Claude presets set both keys: `assets/base/settings/default.json:7`
  and `:576-579`, and the same in `acceptEdits.json` and
  `bypass-sandboxed.json` (`:7`, `:577`); the status line is
  `printf '%s' "$(git branch --show-current 2>/dev/null || echo codeflow)"`;
- `codeflow update` adds any shipped top-level key a project's file lacks
  (`crates/codeflow-core/src/scaffold/settings_merge.rs:200-207`), so a
  project that deletes `statusLine` or `effortLevel`, as the adopter did,
  gets them back on its next update. `env` and permissions have a
  baseline-guarded removal; these keys do not;
- `assets/base/codex/config.toml` sets `model_reasoning_effort = "high"`,
  and the file is managed (`assets/base/scaffold-manifest.toml:278-282`);
- every seat launch already passes its effort
  (`cf-herdr/SKILL.md:104-107`: Claude `--effort`, Codex
  `-c model_reasoning_effort=…`, Grok `--reasoning-effort`), so the pins
  set only what a person gets when they start a session by hand;
- the pins are a recorded decision: ADR-0056 says "Codex project settings
  pin high. Claude settings provide `effortLevel: high` as a starting
  default";
- a per-person override in `.claude/settings.local.json` is per checkout
  (gitignored, `assets/base/gitignore:17`) and is not carried into a new
  worktree, so with one worktree per task it has to be recreated for each
  task. Codex has no per-project personal file; the issue says its only
  per-person override is a `-c` flag (not verified here).

Outcome: **the shared Claude and Codex settings carry project policy only;
a contributor's status line and effort come from their own user settings,
and the docs say where each person sets them.**

Proposed change and tradeoffs:

- Stop shipping `statusLine` and `effortLevel` in the three presets and
  `model_reasoning_effort` in the Codex config. On update, remove a key
  from a project's file only when its value is exactly what CodeFlow
  shipped, proved by the recorded baseline; a value the project changed
  stays and is reported. This is the same rule `env` uses.
- Record the change as an ADR that supersedes ADR-0056's settings-pin
  sentence only; primaries still enter at high through their launchers.
  The cost: a person who starts a session by hand without their own
  effort setting gets the harness default, which may be lower than high.
  The alternative, keeping the pins and documenting them, is rejected
  because the shared Claude file outranks the user file and a
  `settings.local.json` override does not follow a person into each new
  worktree, so a person who wants `xhigh` has no durable way to keep it.
- Document, per harness, where a person sets status line and effort
  (`~/.claude/settings.json`, `.claude/settings.local.json` with its
  per-checkout limit, `~/.codex/config.toml`, the launch flags), with the
  comment's richer status line (model, version, output style, folder,
  branch, context use with a `jq` fallback) as an optional example, not a
  shipped default.
- Superseding an accepted ADR's decision is the operator's call; the
  build waits for that approval, recorded in this task's pull request.

## Acceptance Criteria

- AC-1 A fresh `codeflow init` with each preset shall write no `statusLine` and no `effortLevel` in `.claude/settings.json` and no `model_reasoning_effort` in `.codex/config.toml`; evidence: `settings_presets.rs` and scaffold tests, failing before the change. (serves EPC-022 AC-136)
- AC-2 `codeflow update` on a project whose shared file holds exactly the shipped `statusLine` or `effortLevel` shall remove it and report the removal, shall keep and report a value the project changed, and shall not add either key back later; evidence: settings-merge tests per case, including the adopter's deleted-key case, failing before the change. (serves EPC-022 AC-136)
- AC-3 Every seat launch in the transport guidance shall still pass its effort explicitly, so seat effort is unchanged; evidence: a test or check over `cf-herdr` and the transport table.
- AC-4 The docs shall state where a person sets status line and effort for Claude Code and Codex, the precedence that decides which wins, and that `.claude/settings.local.json` does not follow into a new worktree; evidence: the doc diff.
- AC-5 The ADR draft shall supersede ADR-0056's settings-pin sentence only, and the operator's approval shall be recorded in the pull request before the presets change; evidence: the ADR and the approval link.
- AC-6 (journey) In a scratch adopter project upgraded from 3.1.1, after `codeflow update` a Claude Code session shall show the contributor's own user status line and effort; evidence: the session's status line and `/config` output.
