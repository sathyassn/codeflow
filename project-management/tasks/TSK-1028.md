# TSK-1028: Shared settings leave the status line and effort to each person

## Description

Issue #351 and its two maintainer comments of 2026-10-27 (07:38Z and
21:04Z), CodeFlow 3.1.1. The scaffold writes personal preferences into the
shared project settings, where they replace each contributor's own
choice: a branch-only `statusLine` and `effortLevel: "high"` in
`.claude/settings.json`, and `model_reasoning_effort = "high"` in
`.codex/config.toml`.

The 21:04Z comment states the status line both consuming repositories now
carry as their workaround, and asks that it, or a configurable equivalent,
be the scaffold default, with a contributor's own line in
`.claude/settings.local.json`. Quoted from the comment:

```json
"statusLine": {
  "type": "command",
  "command": "input=$(cat); model=$(echo \"$input\" | jq -r '.model.display_name'); model_id=$(echo \"$input\" | jq -r '.model.id'); ver=$(echo \"$input\" | jq -r '.version'); style=$(echo \"$input\" | jq -r '.output_style.name // \"default\"'); cwd=$(echo \"$input\" | jq -r '.workspace.current_dir'); branch=$(git -C \"$cwd\" branch --show-current 2>/dev/null); inp=$(echo \"$input\" | jq -r '.context_window.current_usage.input_tokens // 0'); cr=$(echo \"$input\" | jq -r '.context_window.current_usage.cache_read_input_tokens // 0'); cc=$(echo \"$input\" | jq -r '.context_window.current_usage.cache_creation_input_tokens // 0'); cs=$(echo \"$input\" | jq -r '.context_window.context_window_size // 200000'); out=$(echo \"$input\" | jq -r '.context_window.current_usage.output_tokens // 0'); tot=$((inp + cr + cc + out)); pct=$((tot * 100 / cs)); printf \"\\033[2;36m%s\\033[0m \\033[2;90m(%s)\\033[0m \\033[2;90m|\\033[0m \\033[2;36mv\\033[0m\\033[2;37m%s\\033[0m \\033[2;90m|\\033[0m \\033[2;36m%s\\033[0m \\033[2;90m|\\033[0m \\033[2;34m%s\\033[0m\" \"$model\" \"$model_id\" \"$ver\" \"$style\" \"$(basename \"$cwd\")\"; [ -n \"$branch\" ] && printf \" \\033[2;90m(\\033[0m\\033[2;35m%s\\033[0m\\033[2;90m)\\033[0m\" \"$branch\"; if [ $pct -lt 50 ]; then col=32; elif [ $pct -lt 80 ]; then col=33; else col=31; fi; printf \" \\033[2;90m|\\033[0m \\033[2;%dmctx:%dk/%dk (%d%%)\\033[0m\\n\" \"$col\" \"$((tot/1000))\" \"$((cs/1000))\" \"$pct\""
}
```

It reads Claude Code's status JSON on stdin and prints the model display
name and id, the Claude Code version, the output style, the folder name,
the git branch when there is one, and the context used as tokens out of
the window and as a percentage: green below 50, yellow below 80, red from
80. It needs `jq`.

Read on the line tip `7172229aa`:

- the three Claude presets set both keys: `assets/base/settings/default.json:7`
  and `:576-579`, and the same in `acceptEdits.json` and
  `bypass-sandboxed.json` (`:7`, `:577`); the shipped line is
  `printf '%s' "$(git branch --show-current 2>/dev/null || echo codeflow)"`,
  unchanged since `fe644c345` (2026-06-12) per the 07:38Z comment;
- `codeflow update` adds any shipped top-level key a project's file lacks
  and keeps any value it has
  (`crates/codeflow-core/src/scaffold/settings_merge.rs:200-207`), so a
  project that deletes `statusLine` or `effortLevel` gets them back on its
  next update, and a project still holding the old shipped line never
  receives a new default. `env` and permissions have a baseline-guarded
  rule; these keys do not;
- `assets/base/codex/config.toml` sets `model_reasoning_effort = "high"`,
  and the file is managed (`assets/base/scaffold-manifest.toml:278-282`);
- every seat launch already passes its effort
  (`cf-herdr/SKILL.md:104-107`: Claude `--effort`, Codex
  `-c model_reasoning_effort=…`, Grok `--reasoning-effort`), so the
  effort pins set only what a person gets when they start a session by
  hand;
- the effort pins are a recorded decision: ADR-0056 says "Codex project
  settings pin high. Claude settings provide `effortLevel: high` as a
  starting default";
- `.claude/settings.local.json` outranks the shared file
  (`cf-customize/references/claude-context-policy.md:47-49`) but is per
  checkout (gitignored, `assets/base/gitignore:17`) and is not carried
  into a new worktree, so with one worktree per task a personal line
  there has to be recreated for each task. Codex has no per-project
  personal file; the issue says its only per-person override is a `-c`
  flag (not verified here).

Outcome: **the scaffold ships a useful project status line that degrades
cleanly without `jq`, effort is the contributor's own unless a project
opts in, and the docs say where each person sets their own values.**

Change and tradeoffs:

- Status line: ship the comment's line, or a configurable equivalent that
  shows the same fields, as the default in the three presets. Without
  `jq` it prints a short fallback (folder and branch) instead of an error
  or an empty line. A long inline command is hard to review; the builder
  may ship it as a managed script the setting calls, if update keeps that
  script current. On update, a project whose `statusLine` is exactly a
  value CodeFlow shipped, proved by the recorded baseline, moves to the
  new default; a line the project changed stays and is reported. The
  shared line still outranks a person's user settings, so the docs name
  `.claude/settings.local.json` as the personal route and state its
  per-checkout limit.
- Effort: `effortLevel` and Codex `model_reasoning_effort` become opt-in,
  offered by `cf-customize` and documented, and are no longer shipped. On
  update, a key whose value is exactly what CodeFlow shipped is removed;
  a project's own value stays. The cost: a person who starts a session by
  hand without their own effort setting gets the harness default, which
  may be lower than high; primaries launched through `cf-herdr` still
  enter at high.
- The effort change supersedes ADR-0056's settings-pin sentence, which is
  the operator's call; that part waits for the approval, recorded in this
  task's pull request.

## Acceptance Criteria

- AC-1 A fresh `codeflow init` with each preset shall write a `statusLine` that, given sample status JSON, prints the model name and id, Claude Code version, output style, folder, branch when present, and context used out of the window with a percentage coloured green below 50, yellow below 80 and red from 80, matching the issue's line; evidence: preset tests and a status line test on sample input, failing before the change. (serves EPC-022 AC-136)
- AC-2 With `jq` absent from `PATH`, the shipped status line shall print a short fallback (folder and branch) and exit 0, never an error or an empty line; evidence: the status line test run without `jq`.
- AC-3 A fresh `codeflow init` shall write no `effortLevel` in `.claude/settings.json` and no `model_reasoning_effort` in `.codex/config.toml`, and `cf-customize` shall offer each as a project opt-in with the ADR-0056 tradeoff stated; evidence: preset and scaffold tests failing before the change, and the skill text. (serves EPC-022 AC-136)
- AC-4 `codeflow update` shall replace a `statusLine` that is exactly a shipped value with the new default, remove an `effortLevel` or Codex `model_reasoning_effort` that is exactly the shipped value, keep and report any value the project changed, and never add a removed effort key back; evidence: settings-merge tests per case, including the adopter's deleted-key case, failing before the change. (serves EPC-022 AC-136)
- AC-5 Every seat launch in the transport guidance shall still pass its effort explicitly, so seat effort is unchanged; evidence: a check over `cf-herdr` and the transport table.
- AC-6 The docs shall state where a person sets their own status line and effort for Claude Code (`.claude/settings.local.json`, and `~/.claude/settings.json` for keys the project does not set) and Codex (`~/.codex/config.toml`, launch flags), the precedence that decides which wins, and that `.claude/settings.local.json` does not follow into a new worktree; evidence: the doc diff.
- AC-7 The ADR draft shall supersede ADR-0056's settings-pin sentence only, and the operator's approval shall be recorded in the pull request before the effort keys change; evidence: the ADR and the approval link.
- AC-8 (journey) In a scratch adopter project upgraded from 3.1.1, after `codeflow update` a Claude Code session shall show the new status line, then a contributor's own line from `.claude/settings.local.json`, and the contributor's own effort; evidence: the session's status line and `/config` output.
