# TSK-110: aggregate journey gate and benchmark

## Description

Each task ships its own deterministic journeys. This task adds the final
gate target that aggregates them (Plan v4 section 10) and the benchmark and
budgets of section 11. The gate runs every journey with a passing control
and a fault that fails for the stated reason, including the ones that span
tasks: repeated `codeflow update`, a no-remote project end to end, the
standard tier without records, and read commands making no network calls.
The benchmark covers 10,000 records across ten lines and thousands of stale
branches; its first run sets the latency and memory budgets, which are then
guarded against regression. No figure is claimed before it is measured.

## Affected surfaces and interfaces

- Test targets under `crates/`, the CI workflow (gate job, Windows job).
- Read commands: `status`, `work next`, `validate`, `orient` (CAP-010).
- Shared files this task edits: the CI workflow (gate job). Ownership
  follows SPC-013 planning resolution 8.

## Acceptance Criteria

- [ ] AC-1 One gate target shall run every Plan v4 section 10 deterministic
      journey, each with a passing control and a fault that fails for its
      stated reason, in CI including the Windows job; evidence: the
      gate run and its journey list mapped to section 10.
- [ ] AC-2 Read commands shall make no network call, parse each distinct
      tree once with batched object reads, and stay bounded on a hostile
      inventory; evidence: tests with the network denied and a hostile
      fixture.
- [ ] AC-3 The benchmark shall run 10,000 records across ten lines and
      thousands of stale branches, record a baseline, and set latency and
      memory budgets from it that CI then guards; evidence: the recorded
      baseline and the regression check.
- [ ] AC-4 (journey) Repeated `codeflow update`, a no-remote project end to
      end and a standard-tier project without records shall pass with the
      installed CLI; evidence: those journeys in the gate.
