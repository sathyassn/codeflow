# TSK-1021: File identity checks use the 128-bit FileIdentity everywhere

## Description

TSK-1020 review 4 found that `same_file::Handle` and the 64-bit file index
of `GetFileInformationByHandle` compare a volume serial number and a 64-bit
index, which Microsoft does not guarantee unique on ReFS, so two different
files can compare equal. TSK-1020 moved the bounded and confined readers to
`FileIdentity` (`crates/codeflow-core/src/bounded_file.rs`): the volume serial
and the full 128-bit file id from `GetFileInformationByHandleEx(FileIdInfo)`
on Windows, the device and inode on Unix, read from a handle the code opened,
refusing a failed query or an all-zero Windows id.

This task moves the remaining production file-identity comparisons that read
an opened handle to `FileIdentity`, makes every one fail closed, and gives
every other comparison an explicit disposition. Inventory, from a search of
`crates/` for `.dev()`, `.ino()`, `MetadataExt::dev`/`ino`, `nFileIndex`,
`same_file::` and stored identity structures, at
`0d7e840e198d046c7d4cfb8b905414ed4bcca0d9` (paths under
`crates/codeflow-core/src/` unless named):

| Site | What it compares | Disposition |
|---|---|---|
| `testing/gate_guard.rs:743` | `same_file::Handle` of the locked file and the lock path reopened through the anchored no-follow `contained::Tree` open at `:742` | Migrate (AC-1) |
| `model_qualification.rs:492`, `:522`, `:532` | Unix device and inode; Windows volume and 64-bit index (`:512`); length and time on other platforms; handles opened by `open_without_reparse_follow` (`:427`) | Migrate (AC-2) |

## Acceptance Criteria

- AC-1 When the gate lock check (`same_lock_file` in `testing/gate_guard.rs`) compares the lock path's file with the locked file, it shall compare the `FileIdentity` of the held lock handle and of the handle reopened through the anchored no-follow open it already uses, never re-resolving the held file's path, and shall refuse when either identity cannot be read. Evidence: unit tests where the path names the same file (pass) and another file (refusal); the error propagation cited by line.
- AC-2 When model qualification (`same_file_identity` in `model_qualification.rs`) compares an opened file with the file at its path, it shall compare the `FileIdentity` of the two handles `open_without_reparse_follow` opened, on every platform, with no length-and-time fallback, and shall refuse when either identity cannot be read. Evidence: unit tests with the same file (pass) and a replaced file (refusal); the error propagation cited by line.
- AC-3 When `crates/` is searched for file-identity comparisons (`.dev()`, `.ino()`, `MetadataExt::dev`/`ino`, `nFileIndex`, `same_file::Handle`, `GetFileInformationByHandle(`, and stored identity structures), every production comparison shall either use `FileIdentity` or appear in the pull request's inventory with the disposition and reason above, and none shall compare `same_file::Handle` values or the 64-bit `GetFileInformationByHandle` index. Evidence: the search commands and their output in the pull request body at its head.
- AC-4 When `FileIdentity` reads an identity whose id is zero, it shall refuse on every platform (an all-zero Windows file id, or inode 0 on Unix). Evidence: a unit test for each constructor's refusal.
- AC-5 When the comparison is tested, the existing synthetic test of two identities that share their low 64 bits and differ in the high bits (`bounded_file::identity_tests::identities_compare_the_volume_and_the_full_128_bit_id`) shall remain and pass, with the migrated callers using that same type. Evidence: the test named in the pull request's Testing section, passing on hosted Linux and Windows.
- AC-6 When the history graph records a file's identity (`workgraph/history_graph.rs`), it shall include the `FileIdentity` of the handle it opened, on every platform, so a replaced file is detected off Unix too, and a failed identity read shall report the file as changed. Evidence: a unit test where a file is replaced by one with the same size, time and contents and the change is detected.
