# TSK-1021: File identity checks use the 128-bit FileIdentity everywhere

## Description

TSK-1020 review 4 found that `same_file::Handle` and the 64-bit file index
of `GetFileInformationByHandle` compare a volume serial number and a 64-bit
index, which Microsoft does not guarantee unique on ReFS, so two different
files can compare equal. TSK-1020 moved the bounded and confined readers to
`FileIdentity` (`crates/codeflow-core/src/bounded_file.rs`): the volume serial
and the full 128-bit file id from `GetFileInformationByHandleEx(FileIdInfo)`
on Windows, the device and inode on Unix, refusing a failed query or an
all-zero id. Two identity checks still use the narrower forms:

- `crates/codeflow-core/src/testing/gate_guard.rs:743`, `same_lock_file`,
  compares `same_file::Handle` values to prove the gate lock path still names
  the locked file.
- `crates/codeflow-core/src/model_qualification.rs:512`, the Windows
  `same_file_identity`, compares the volume serial and the 64-bit index from
  `GetFileInformationByHandle`; its fallback for other platforms compares
  length and modification time, which is not an identity.

This task moves both to `FileIdentity`, shared from one place, and makes each
refuse when an identity cannot be read. Non-goals: other uses of the
`same_file` crate that are not identity checks, and any change to what each
check guards.

## Deliverables

- the two checks: `crates/codeflow-core/src/testing/gate_guard.rs`, `crates/codeflow-core/src/model_qualification.rs` (and `crates/codeflow-core/src/bounded_file.rs` if `FileIdentity` needs a wider visibility)
- tests beside each check
- the release note: `changelog.d/TSK-1021.md`

## Acceptance Criteria

- AC-1 When the gate lock check (`same_lock_file` in `testing/gate_guard.rs`) compares the lock path's file with the locked file, it shall compare their `FileIdentity`, and shall refuse when either identity cannot be read. Evidence: a unit test where the path names another file and the check refuses, and one where it names the same file and the check passes; the failed-identity path inspected in code.
- AC-2 When model qualification (`same_file_identity` in `model_qualification.rs`) compares an opened file with the file at its path, it shall compare their `FileIdentity` on every platform, with no length-and-time fallback, and shall refuse when either identity cannot be read. Evidence: a unit test with the same file (match) and a replaced file (refusal); the failed-identity path inspected in code.
- AC-3 When the code is searched, no file identity check in `crates/` shall compare `same_file::Handle` values or the 64-bit `GetFileInformationByHandle` index. Evidence: a search of `crates/` for `same_file::Handle` comparisons and `GetFileInformationByHandle(`, cited in the pull request, and the hosted Windows run passing the new tests.
