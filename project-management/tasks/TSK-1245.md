# TSK-1245: Completion judges a reopen against the fetched line, not a stale local branch

## Description

Adopter issue #520. An adopter's agent reopens and completes a task on an integration line. When the local branch of that line is behind `origin`, `work.acceptance_binding` refuses the completion. The agent cannot repair this: the guard refuses a fetch with a destination and refuses `update-ref`, so a person has to move the ref. A second occurrence was a pre-push check that read a stale local `main`. Related issues: #130, #165, #506.

Mechanism (from the read-only sweep at line tip `dd1913165`; line numbers rechecked on this branch on 2026-11-02, the other sites below to be rechecked by the builder):

- `crates/codeflow-core/src/workgraph/status_verb.rs:263` `bind_completion_of` resolves the target through `local_or_upstream` (`workgraph/work_start.rs:404`), which already selects the configured upstream, or a same-named origin tracking ref, when the local branch is strictly behind it; this step is not the defect.
- `crates/codeflow-core/src/workgraph/acceptance.rs:2279` `judge_reopened` takes target tips in the order upstream, origin, local (documented at `:2528`) and judges against every one of them, so a stale local tip counts. This is the defect: it judges a reopen against a tip that the fetched line has already passed.
- The model to follow is `import_authority`'s `home_tip` (`workgraph/acceptance/imports.rs:219`), which reads only the remote-tracking ref whenever the repository has a remote, and accepts the local branch only in a repository with no remotes.

Security task (admission lens): the check decides whether a reopen is legal, so the fix must bind to history a requester cannot forge. Ancestry on fetched history decides which local tip to drop, never a name or a date. Related, not covered here: TSK-1125 and TSK-1047 own code paths of their own; TSK-275 is complete; TSK-1182 sits elsewhere. It shares `acceptance.rs` with other work, so one writer at a time.

## Outcome

After this merges, an adopter's agent can complete a correct reopen on a line whose local branch is behind `origin`, and a stale local branch never changes a verdict.

## Deliverables

- the fix: `crates/codeflow-core/src/workgraph/acceptance.rs` (`judge_reopened`, `reopened_criteria`), `workgraph/status_verb.rs`
- the sweep test over every local-first reader, in `crates/codeflow-core/tests/` and `crates/codeflow-cli/tests/`
- the pre-push fixture for the stale local `main`
- release note: `changelog.d/TSK-1245.md`

## Acceptance Criteria

- AC-1 (journey) With the built binary, a local line behind `origin/<line>` and a correct reopen shall refuse before the change and complete after it, and a local line ahead of `origin` shall still be honoured; evidence: the built binary's runs in a fixture repository, the refusal before and the completion after, and the ahead case.
- AC-2 `judge_reopened` and `reopened_criteria` shall drop a local tip that is a strict ancestor of a fetched tip; ancestry shall decide this (`history::descendant_of`), never a name or a date, and diverged or unreadable ancestry shall refuse; evidence: fixtures for a strict ancestor, a diverged tip, unreadable history, and a forged commit date and a branch named like the line, each judged by ancestry alone.
- AC-3 (amended 2026-11-02, final review round 2, finding 1; earlier text asked every refusal to name a stale-local cause, which contradicts AC-1, where a stale local branch completes) The refusals that remain after AC-2, a diverged local and fetched tip, unreadable ancestry and an unresolvable fetched tip, shall each name their actual cause, the exact refs and SHAs involved, and a remedy that applies and runs under the guard without `update-ref` or a fetch with a destination (for example fetching the line with no destination, or working from a fresh worktree of the fetched line); a stale local tip shall never be reported as a cause, since it completes; evidence: one negative fixture per remaining failure asserting its message and that the remedy runs under the guard.
- AC-4 A sweep test shall cover each reader that takes a target tip: `readiness.rs:218`, `work_start.rs` `target_reference` (`:3151`), `cmd/ci.rs:1330` and `:2597`, and `git/conflict.rs:120`; the sweep found the ci and conflict readers already remote-first, and the builder records for each site whether it is remote-first, local-first or both; with a stale local branch no verdict shall change; a site already owned elsewhere shall be named in the PR and pointed to TSK-1125 or TSK-1047; evidence: one test per site with a stale local branch, and the table of sites with their order and owners.
- AC-5 The pre-push occurrence (a stale local `main`) shall be reproduced as a fixture, with `hooks/git_hook.rs:1489` `default_work_target_ref` traced; the fixture shall fail before the change or the PR shall show that it is fixed already, with the trace; evidence: the fixture run and the trace in the PR.
