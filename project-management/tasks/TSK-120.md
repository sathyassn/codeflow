# TSK-120: present answer submission and agent delivery

## Description

Node D of the present review parity package (Plan v5). Today
`present feedback --follow` loops until the session closes, so an agent
following feedback in the background is woken once, at close, with
everything at once; per-answer wake-up works on no harness (proposal
section 1). This task delivers each stored note, answer and amendment to
the agent as a typed event, to SPC-014: a bounded wait that exits on the
first pending event, `--format v2`, a non-consuming `responses list`, and
`present ack`, with delivery and acknowledgment as separate states the
reviewer sees (proposal sections 2 and 3.4). It qualifies each harness on
its real interactive path.

Boundary with TSK-119 (settled 2026-09-26): TSK-119 owns the `form` block
through the "stored" state, including page rendering, drafts, page and
server validation and stale handling. This task owns delivery to the
agent, the states after "stored" (waiting for agent, delivered,
acknowledged, failed) and the end-to-end browser to agent journey.
Non-goals: starting a background model to
simulate a listener, and replies with the agent's text (TSK-121).

- `crates/codeflow-cli/tests/present_cli.rs`, the browser suites. CAP-016.

## Acceptance Criteria

- AC-1 `present feedback <id> --wait` waits with no timeout by default,
      `--timeout S` bounds it, and it exits with distinct statuses (the
      SPC-014 values) for an event, a timeout and a closed session; evidence:
      `present_cli` tests per exit path (3.4).
- AC-2 Typed events (note, answer, amendment) appear on `feedback --format v2`
      and on `responses list`, which does not consume them; the v1 stream
      keeps its exact shape, and when v2 events are pending a notice goes to
      stderr, never into the v1 JSON lines; evidence: golden tests of both
      streams on the TSK-117 fixtures (3.4).
- AC-3 `present responses list <id>` filters by revision, form and status
      (pending, delivered, acknowledged), alone and combined, and listing
      never consumes an event: a `--wait` after any number of listings still
      returns the pending event; evidence: `present_cli` tests on a session
      with answers across two revisions, two forms and every status, and a
      list-then-wait control (section 2, forms and database rows; Codex R5,
      plan review round 1).
- AC-4 `present ack <event>` records acknowledgment; delivered and
      acknowledged are separate states, both visible to the reviewer;
      evidence: state tests and a browser case (3.4).
- AC-5 End to end in Claude Code: an answer submitted in the browser goes
      through the service to the session store and wakes a live interactive
      Claude Code session per answer through a background shell loop that
      re-arms on a timeout exit without waking the model, and the agent
      acknowledges it; one wait runs longer than ten minutes; evidence: the
      recorded session transcript and service log (4.2 row D, 3.4).
- AC-6 With no listener, a submitted answer shows "stored, waiting for agent"
      and is delivered on the next wait; after a service restart, pending
      events are delivered once and none is lost; evidence: no-listener and
      restart controls in crate tests and the suite (4.2 row D).
- AC-7 Codex and Grok are each qualified on the same path in their real
      interactive harness or recorded as not qualified with the reason, and
      an unqualified harness leaves the reviewer seeing "stored, waiting for
      agent"; no background model is started to simulate a listener;
      evidence: the qualification record (3.4).
- AC-8 The cf-present skill teaches the wait, re-arm and ack loop, and treats
      an answer as the operator's choice and never as authority to bypass a
      gate; evidence: the skill text with mirrors and the manifest test.
- AC-9 `npm run check`, the browser checks, `cargo test -p codeflow-present`
      and `cargo test -p codeflow-cli --test present_cli` are green and the
      present checksum matches a clean rebuild; evidence: recorded output
      with the head SHA.
