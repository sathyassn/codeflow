# TSK-1454: The guards place a Windows shell's folders where the shell opens them

## Description

TSK-1455 makes the guards on `main` place each Windows shell path where Windows opens it, and refuse a path it cannot place, failing closed. Some paths a Windows shell opens through its own mount table are among those it cannot place, so ordinary commands that write or change folder through them are refused on Windows after TSK-1455, though the shell opens a known folder for each. This task reads that mount table and places those paths in the folder the shell opens. A mount the guard cannot read with certainty stays refused.

Overlap: TSK-391 (todo, EPC-050) AC-6 to AC-9 check that the startup-file guard refuses writes through other home spellings of a startup file on Windows; this task's mount table places those spellings, and TSK-391's builder confirms its criteria through it rather than adding a second map. A search of open task criteria on 2026-11-11 found no other owner.

Source: the Director's ruling of 2026-11-11 before 09:43 EST, relayed by coord/ci: tracked in 4.0.0, not left as an untracked follow-up of TSK-1455. Sites as TSK-1455 leaves them, from its design note (workspace 385ef8cc, sections 3 and 4, rows 41 to 43).

## Outcome

After this merges, on a Windows host, a path that the shell opens through its mount table is judged at the folder the shell opens, so ordinary commands through such paths run again, while a write that reaches an enforcement file through a mount is still refused, and a mount the guard cannot read with certainty is still refused.
