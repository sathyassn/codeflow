# TSK-174: the one permitted sandbox exit

Unit 4 of 5 of the harness permissions work, TSK-171 to TSK-175 (decision record:
`ADR-0075`; design: `docs/verification/permission-presets-design-2026-09-28.md` section 3 and
the design record's revision 4, section 2, as carried in its section 3).

## Description

Claude's `allowUnsandboxedCommands: true` (ADR-0029) lets the model rerun a
failed command outside the sandbox. ADR-0029 relied on auto mode's
classifier to review the retry; in `bypassPermissions`, which ADR-0055
permits, nothing reviews it, so any command, including `bash -lc 'sudo -n
id'` or an interpreter that rewrites the enforcement files, can leave the
sandbox. The retry exists for one program: the Codex plugin companion, whose
app-server cannot initialize its state under `~/.codex` inside the sandbox.

This unit first tries to remove the need for the exit (spike 0). If that
fails, it permits exactly one exit: a primary Claude session may rerun,
outside the sandbox, an argument vector that an allowlist entry spells out in
full, with the executables pinned. Delegated seats never leave the sandbox
(TSK-173 writes their native deny). It also enforces the Herdr subcommand
grammar on every Herdr call, since the operator adopted D7 on 2026-09-28 as
adjusted (workspace `RELEASE-PLAN.md:538`): seats briefed only with `agent
prompt`, folder trust granted at launch through each seat's own flags,
Escape the only key sent to a registered seat, three housekeeping slash
commands, and shell panes and seat approval prompts left to the operator.
The grammar and the
D7 route do not depend on the companion: a companion pass of spike 0 empties
the companion's part of the list and leaves the Herdr part as it is.

What the exit still carries is stated: the companion hands a prompt to Codex,
whose thread runs Codex's legacy sandbox without the `cf-guard` secret
denies, so Codex's own floor is the control there.

## Affected surfaces and interfaces

- `hooks/exec_guard.rs`: the retry check.
- Policy: `security.sandbox_retry`, `security.sandbox_retry_allow` (reference
  entry in `docs/verification/evidence/permission-presets/policy/policy-asset.json`; the D7 entries in
  `docs/verification/evidence/permission-presets/policy/retry-allow-herdr.D7.json`).
- The Codex plugin skill text (prompts passed as several arguments).
- The Herdr grammar in exec-guard and the D7 entries in the workspace policy;
  refusals that need the operator record an operator-actions entry through
  the TSK-172 writer (TSK-175 AC-8).

## Acceptance Criteria

- AC-1 (spike 0, before any other work) Run the companion's `review` and
  `task` inside the Claude sandbox with `allowWrite` for only the `~/.codex`
  subdirectories the app-server writes, set as local relief; record which
  subdirectories, whether the app-server starts, whether Codex's nested
  sandbox applies inside Seatbelt, and whether both commands complete. Also
  record which Herdr calls fail inside the sandbox; no socket allowance is
  tried for Herdr, since any sandboxed process could then drive it. On a
  companion pass, the companion entry leaves `sandbox_retry_allow`, and only
  the companion's retry criteria reduce to "every companion retry refused":
  the companion clause of AC-3, AC-4, AC-5 and AC-7. AC-2 still runs, since
  refusing every retry depends on the guard seeing the retry field. AC-3's
  general clause, AC-6 and AC-8 stay in force unchanged; evidence: the
  recorded spike.
- AC-2 (retry canary, before AC-3) A PreToolUse hook recording its payload in
  a disposable project while a Claude session retries a sandbox-failed
  command shall show whether `tool_input` carries `dangerouslyDisableSandbox`;
  a second probe shall show whether a variable exported in one Bash call
  survives into the next. If the field is absent, this unit stops and the
  fallback goes to the operator as a change to ADR-0029; evidence: the
  recorded payloads.
- AC-3 When a Bash call carries `dangerouslyDisableSandbox: true`, exec-guard
  shall refuse it unless it matches an entry of `sandbox_retry_allow`.
  **General clause, for every entry:** it is a single simple command with no
  wrapper; the program is the entry's absolute `program_path`, outside every
  sandbox-writable directory; no program option appears that the entry does
  not name (none by default); the payload `cwd` is inside the project; no
  refused environment variable is set; no PATH entry of the Bash call's
  environment is sandbox-writable; and every other guard check passes, the
  Herdr grammar of AC-6 included for a `herdr` entry. **Companion clause:**
  the script canonicalizes to the entry's exact versioned path, outside every
  sandbox-writable directory, and the script and its `scripts/lib` modules
  match the recorded sha256 digests; the first argument is a subcommand the
  entry names and every later token is one of its flags, typed value options
  or positionals, with a lone argument judged after the companion's own
  split; and `codex` resolves to the entry's recorded child path; evidence:
  exec-guard tests with Claude payloads.
- AC-4 The refused cases shall include: `bash -lc 'sudo -n id'`; `node
  --experimental-loader file:///x.mjs <companion> review`; `node --loader
  ./h.mjs <companion> review`; `node <companion> task --write --cwd / x`;
  `node <companion> task --prompt-file <path>`; `node <companion> setup
  --disable-review-gate`; `node <companion> transfer --source <path>`; `node
  <companion> task "--cwd / --write fix it"`; `node <companion> task "fix the
  --cwd handling"` as one argument; a traversal path into the plugin cache;
  `cd x && node <companion> review`; a `cwd` outside the project; an
  unreviewed companion version (`99.0.0`) or a changed digest; and each
  permitted companion form shall pass, including a multi-argument prompt;
  evidence: tests.
- AC-5 PATH-shadow controls with inert canary executables (no real
  unsandboxed payload): a project-writable `node` earlier on PATH, and a
  project-writable `codex` that the companion would spawn, shall each be
  refused and their canaries untouched; a trusted toolchain shall pass;
  evidence: tests and the recorded canaries.
- AC-6 (D7 grammar) exec-guard shall enforce on every `herdr` call,
  sandboxed or not, the grammar of `docs/verification/permission-presets-design-2026-09-28.md` section 3:
  `workspace list`, `tab list`, `pane list`, `pane current`, `agent list`
  with no arguments; `agent get`, `agent read`, `agent wait` on a
  registered seat (a live agent that `delegate init` recorded for this task
  and `herdr agent list` shows; never a shell pane); `tab create
  --workspace <id>`; `agent start` with `--kind claude|codex|grok` and,
  after `--`, only the seat flags for that kind and role in the route table
  of `docs/verification/permission-presets-design-2026-09-28.md` section 1.5 (which since v11 launches every Grok seat
  in its own task worktree, builders with `cf-guard-worktree`; the v10
  main-root and `cf-guard` form for Grok builders is refused), including the launch-time trust form only for the seat's
  own worktree, with a `--settings` value only when TSK-173's recorded hash
  matches; `agent prompt` to a registered seat, with text that does not
  start with `!` and does not start with `/` unless its command word is
  exactly `/compact`, `/clear` or `/new` (so `/compact keep the test
  output` passes and `/compact-mode`, `/hooks`, `/hooks-trust`,
  `/permissions`, `/approvals`, `/model` and every other slash command are
  refused), the text judged after the normalization the harness applies
  before reading it (leading whitespace and line breaks removed, Unicode
  NFKC, so a full-width or other look-alike solidus counts as `/`), and,
  where a harness's normalization is not documented, any text whose first
  visible character is a solidus look-alike refused unless its command word
  is exactly allowlisted; and `agent send-keys <registered seat> Escape`, one key, nothing
  else. `pane run`, `pane send-text`, `pane send-keys`, `agent attach`,
  any other `agent send-keys` form and any subcommand not listed shall be
  refused. Refusals name the rule; a refused key or slash command aimed at
  an approval or trust prompt says it is the operator's and is queued for
  the operator. The grammar applies whatever spike 0 shows and whether or
  not the call is retried. The D7 list's pending Grok trust entry (`grok`
  pinned, cwd a registered seat worktree, the trust-only arguments TSK-175
  AC-2 qualifies) shall be refused until that form is recorded in it.
  Evidence: tests, including each permitted and refused slash form, the
  same forms after leading spaces and a newline, `／permissions` (U+FF0F)
  and `∕model` (U+2215), refused, a Grok builder `agent start` with the v10
  main-root `cf-guard` flags, refused, `Escape`
  against `Enter`, `y`, `Escape Escape` and a raw byte sequence, a target
  that is a shell pane, and a recorded check of whether `agent prompt`
  refuses a target that exited to its shell before delivery.
- AC-7 The plugin skill text shall pass a task prompt as several arguments,
  and the companion's refused subcommands and options shall be listed there;
  evidence: the diff.
- AC-8 (D7 beside an empty companion list) With the companion entry absent
  after a spike 0 pass and the D7 entries of
  `docs/verification/evidence/permission-presets/policy/retry-allow-herdr.D7.json` added: a retried `herdr
  agent list`, `herdr agent prompt <registered seat> <text>`, `herdr agent
  prompt <registered seat> /compact` and `herdr agent send-keys <registered
  seat> Escape` shall pass; a retried `herdr pane send-text`, `herdr agent
  send-keys <seat> Enter`, `herdr agent prompt <seat> /permissions` and
  `herdr agent send-keys <shell pane> Escape` shall be refused, as shall the
  same calls sandboxed; a retried companion `review` shall be refused; a
  retried `herdr` resolved from a sandbox-writable PATH entry, or not at its
  recorded `program_path`, shall be refused; the pending Grok trust entry
  shall be refused until qualified. With the companion entry present (spike
  0 failed), the same Herdr results hold beside the companion's own.
  Evidence: exec-guard tests over both list states.
- AC-9 (journey) In a freshly scaffolded project driven by the installed
  CLI, Claude Bash payloads fed to the scaffolded exec-guard hook shall show
  the retry rule: `ls` carrying `dangerouslyDisableSandbox: true` shall be
  refused as matching no `sandbox_retry_allow` entry, naming the rule, and
  the same `ls` without the field shall pass; `herdr pane send-text` and
  `herdr pane run` shall be refused by the Herdr grammar with and without
  the field, and `herdr workspace list` without it shall pass; evidence: an
  end-to-end test using the installed binary and the scaffolded hook files.
