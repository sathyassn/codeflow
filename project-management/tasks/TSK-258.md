# TSK-258: The installed manifest records no file digests

## Description

`.codeflow/manifest.json` records a `sha256` per installed file, and two pull requests that change the same managed file conflict on that one line in the manifest even when their real changes merge cleanly (issue 119). The digest is a cache of the committed pristine copy under `.codeflow/.baseline/`, so this task drops it: the manifest becomes schema 2 (`src`, `ownership`, `exec` per entry), and `update`, `init`, `prune_orphans` and `doctor --check managed-drift` compare bytes with the baseline in the order the code decides today. A schema 1 manifest is still read: its digest is honoured only for an entry whose baseline is missing, kept until that baseline is written, and never written as `null`; a schema above 2 is refused. With neither a baseline nor a digest, `update` proposes `<path>.new` instead of replacing, an unmodified orphan is kept and unmanaged, and doctor warns; doctor also warns instead of passing on an unreadable manifest. The published 3.0.0 binary cannot read a schema 2 manifest (missing `sha256`), so this is a breaking change and moves the next release to 4.0.0 with migration text. Design: issue 119 revision 3, section 9 unit 1. Non-goals: the changelog fragments unit, the unused `SecurityPolicy::protected_paths` list, branch protection.

## Acceptance Criteria

- AC-1 When two branches each change a different managed source file and resync, the system shall merge them without a conflict in `.codeflow/manifest.json`, and the update replay shall pass on the merge result. Evidence: `git merge-tree --write-tree` exits 0 on two scratch branches; `repository_update_noop` passes on the written tree. (journey)
- AC-2 When two branches change the same managed source file in different places and resync, the system shall merge them without a conflict in `.codeflow/manifest.json`. Evidence: `git merge-tree --write-tree` on two scratch branches editing `project-organization.md` exits 0 with no manifest in the conflict list.
- AC-3 When a schema 1 manifest is read, the system shall honour its digest only for an entry with no baseline, keep it until that baseline is written, drop it after, refuse a schema above 2 naming the version, and never store `"sha256": null`. Evidence: scaffold tests for (a) no baseline and a matching digest replaces, writes the baseline and stores no digest, (b) an ignored entry with no baseline keeps its digest, (c) the ignore removed, update replaces and then stores no digest, (d) schema 3 is refused naming the version, (e) the stored file has no `null` digest.
- AC-4 When the baseline is present, `update`, `init`, `prune_orphans` and doctor shall give the same outcome as before (Add, Adopt, Replace, Force, Kept, merge, conflict; the user-owned and no-record init arms; region and user-owned orphans never deleted). Evidence: the existing cases in `scaffold_test.rs`, `init_e2e.rs`, `permission_presets_update.rs`, the installed CLI journey and the doctor drift tests pass with digest assertions replaced by baseline-byte assertions.
- AC-5 When an entry has neither a baseline nor a digest, the system shall propose an unmodified managed file as `<path>.new`, keep and unmanage an unmodified managed orphan and report it, have `init` report `Unchanged` when the live file equals the shipped file and "locally modified" otherwise, and still apply Adopt and Force. Evidence: one new test per row.
- AC-6 When the manifest is unreadable, or a markdown or hash region has no baseline, `doctor --check managed-drift` shall warn and exit 0; it shall still pass on a missing manifest and skip JSON regions, and the `config` check shall still fail on `{broken`. Evidence: new doctor tests beside the drift tests; `check_config_fails_on_invalid_json` unchanged.
- AC-7 When this repository is resynced, the system shall remove every `sha256` key and change `schema_version`, and no other manifest field. Evidence: `git diff` of `.codeflow/manifest.json` against the parent shows only removed `sha256` lines and one schema line, besides the release stamp.
- AC-8 When the change ships, the changelog shall carry a major entry with Breaking yes and the 3.0.0 migration steps, the stamps shall read 4.0.0, and `scaffold-manifest.toml` and `docs/adoption.md` shall describe the record without a digest. Evidence: `release.py check-pr` and `check-state --structural` output; the diff.
