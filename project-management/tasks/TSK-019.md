# TSK-019 — replace portal baseline reconciliation with explicit ownership

## Description

Implement SPC-008's replace-only runtime, explicit whole-runtime transfer and
fail-closed schema migration. Preserve existing portal value and transactions;
do not redesign the UI or create package-distribution infrastructure.

## Affected surfaces and interfaces

Portal reconciliation and validation in codeflow-core, portal CLI in codeflow-cli,
state/identity schema and focused Rust/CLI/transaction tests. TSK-015 owns the
preceding shared bounded-reader extraction; no concurrent writers in those files.

## Acceptance Criteria

- [ ] Fresh/repeated setup creates no pristine copies; drift/collisions/edited
  retirement stop before any portal write/state advancement.
- [ ] Managed missing files repair; project-owned missing files remain absent
  and reported after adoption. Configuration seeds only on fresh adoption.
- [ ] Explicit confirmed transfer persists for the whole runtime; future
  updates preserve additions/deletions and frozen transferred-from provenance.
- [ ] V1/v2 transfer preserves edited/deleted runtime and config without an
  upgrade; freeze adopted, not incoming, provenance. Missing baselines are
  benign; authenticated removals are reported; tampered blobs remain untouched.
- [ ] Strict declared generator identity supports a legitimate renamed project
  generator without weakening managed pins or any existing evidence checks.
- [ ] Legacy journals recover before bounded authenticated baseline migration;
  adversarial paths/content/races and transaction fault injection preserve data.
- [ ] Managed release identities agree and lockfiles are never line-merged.
