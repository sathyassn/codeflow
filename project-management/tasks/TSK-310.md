# TSK-310: The release-integration workflow is retired

## Description

`.github/workflows/codeflow-release-integration.yml` runs daily at 03:17 UTC
and after each `codeflow-release` push run on an epic line. It still sets
`RELEASE_BRANCH: integration/release-3-0-0-r3`, a 3.0.0 release line with no
open task carrying `role: release-integration`, and has failed on every run
since 2026-10-12 06:45 (workspace `RELEASE-PLAN.md`, triage of 2026-10-13).
Nothing depends on it. `docs/releasing.md` "Integration after an epic-line
landing" and its reproduction command name the old branch too.

Operator decision, 2026-10-13: retire the workflow, because releases ship
from `main`, not from a release integration branch. The operator has
already disabled the workflow in GitHub Actions. Rotation to a new release
branch is not part of this task.

This task removes the workflow and its runbook rows, so nothing runs
against a missing branch, and says in `docs/releasing.md` that releases
ship from `main` and that a future release branch would bring the workflow
back through a reviewed change. The workflow's YAML is loaded from the
default branch, so the file change takes effect only once it reaches
`main`; until then the Actions disable keeps it from running.

## Deliverables

- the retirement: removal of `.github/workflows/codeflow-release-integration.yml`, or of its triggers if a reviewer shows a consumer of the file
- the runbook: `docs/releasing.md` ("Integration after an epic-line landing", "Rotating the release branch" and the reproduction command)
- the workflow list of the timeout check: `scripts/test_gate_parity.py`
- the consumers the review found (PR 188): the repository-only runner `crates/codeflow-cli/examples/release_integration.rs` and its tests in `crates/codeflow-cli/tests/release_line_cli.rs`, their `name_decode_scan` and `windows-test-times.json` entries, the capability guide section in `docs/capabilities/CAP-010-duo-model-orchestration.md`, and the runner instructions in the shipped `cf-ship` release-integration reference with its mirrors, baselines and manifest hashes
