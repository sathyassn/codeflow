# TSK-310: The release-integration workflow is retired or rotated

## Description

`.github/workflows/codeflow-release-integration.yml` runs daily at 03:17 UTC
and after each `codeflow-release` push run on an epic line. It still sets
`RELEASE_BRANCH: integration/release-3-0-0-r3`, a 3.0.0 release line with no
open task carrying `role: release-integration`, and has failed on every run
since 2026-10-12 06:45 (workspace `RELEASE-PLAN.md`, triage of 2026-10-13).
Nothing depends on it, and the operator was asked to disable it in Actions.
`docs/releasing.md` "Rotating the release branch" is the runbook for moving
it to a new release branch; `docs/releasing.md` "Integration after an
epic-line landing" and its reproduction command name the old branch too.

This task ends the false daily failure in one of two ways. Retire: remove
the workflow's triggers, or the workflow and its runbook rows, so nothing
runs until a release uses a release branch again, and say in
`docs/releasing.md` how to bring it back through the rotation runbook.
Rotate: follow the runbook's five steps to a 3.2.0 release branch with its
own open `role: release-integration` task. Which one is the operator's
choice, because it decides whether 3.2.0 is assembled on a release branch;
the recommendation is to retire, since 3.2.0 is planned as epic lines that
reach `main` by one human-merged pull request each. The workflow's YAML is
loaded from the default branch, so the change stops the scheduled runs only
once it reaches `main`; until then the Actions disable is the interim, and
this task records whether it is in place.

## Deliverables

- the operator's choice: this record's Description, as a dated line naming the decision
- the workflow change: `.github/workflows/codeflow-release-integration.yml`
- the runbook and reproduction command: `docs/releasing.md` ("Integration after an epic-line landing" and "Rotating the release branch")
- the workflow list of the timeout check, if the file is removed: `scripts/test_gate_parity.py`

## Acceptance Criteria

- AC-1 Before any change, this record shall name the operator's choice
  between retiring and rotating, with the date, and whether the workflow
  is disabled in Actions at that time; evidence: the dated line in this
  record and `gh workflow view codeflow-release-integration.yml` output.
  (serves EPC-022 AC-21)
- AC-2 After the change, no trigger of the workflow shall name a release
  branch that does not exist or that no open `role: release-integration`
  task owns; evidence: for retire, the workflow without its triggers or
  removed; for rotate, `git ls-remote --heads origin` showing the branch
  and the owner record at the default branch. (serves EPC-022 AC-21)
- AC-3 `docs/releasing.md` shall describe the state the change leaves,
  with no command or row that names `integration/release-3-0-0-r3` as the
  current branch; evidence: a search of the file.
- AC-4 The repository's workflow checks shall pass on the change,
  including the timeout check that lists the workflow files; evidence:
  `python3 scripts/test_gate_parity.py` and `codeflow ci` on the range.
- AC-5 For rotate only: the runbook's local reproduction shall run against
  the new branch without `--push` and report its owner; evidence: the
  command output. For retire, this criterion is not applicable and the
  record says so.
