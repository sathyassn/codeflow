# TSK-228: codeflow ci warns when a PR body is too long

## Description

The operator approved on 2026-10-03 that `codeflow ci` warns when a pull
request body is too long, after bodies grew to 4,000 to 7,000 words by
appending every review round. The warning joins the existing PR-body
presentation check, which already runs at warn whatever the policy level, so
it never blocks and adds no policy key. It counts the words a reader sees
(HTML comments left out, fenced blocks, tables and headings included), warns
over 1,000 words, names the count, the limit and the three largest `##`
sections, and says how to clear it. Non-goal: judging whether a long body is
justified, which stays with review.

## Deliverables

- the word count and the warning: `crates/codeflow-cli/src/cmd/ci/pr_body.rs`
- the remedy row: `crates/codeflow-core/src/remedy.rs`
- tests: `crates/codeflow-cli/src/cmd/ci/pr_body.rs`, `crates/codeflow-cli/tests/ci_cli/pr_body_fixtures.rs`, `crates/codeflow-cli/tests/remedy_clearing/main.rs`
- docs: cf-ship `pr-evidence.md` with its managed copies, the PR template, `assets/base/ci/README.md` (the check list), `docs/capabilities.md`, `CHANGELOG.md` (minor: compatible added behavior; the pending 3.1.0 section already carries minor, so no version moves)

## Acceptance Criteria

- AC-1 When `codeflow ci` counts a PR body's words, it leaves out HTML comments (one-line, multi-line and inline), counts the text of fenced code blocks, tables and headings, counts a link by its text, and does not count tag markup or image alt text (unit tests in `crates/codeflow-cli/src/cmd/ci/pr_body.rs`).
- AC-2 When the body has more than 1,000 words, `codeflow ci` reports one warning-level finding that names the count, the limit and the three largest `##` sections by heading with their word counts, and a remedy to rewrite the body to its final state, link records instead of copying them, keep one results block at the head and one review row per reviewer; a body of exactly 1,000 words reports nothing (unit tests, and the remedy cleared by a `remedy_clearing` test).
- AC-3 The finding never blocks: an over-long body with every other check clean exits 0 under the default policy and with `git.pr_sections` set to `block`, and draws no finding when `git.pr_sections` is `off` or `allow`; no policy key is added (`ci_cli` test of the binary with fail-before, `policy_schema` drift test).
- AC-4 The check reads the body the pre-push hook path and hosted CI pass to `codeflow ci`, so both warn the same way (the same `evaluate_pr_checks` call; `ci_cli` test of `--pr-body` and `--pr-body-file`).
- AC-5 cf-ship's PR evidence reference (every managed copy), the `codeflow ci` check list (`assets/base/ci/README.md`, `docs/capabilities.md`; `docs/cli.md` lists flags only) and a pending 3.1.0 CHANGELOG entry annotated minor state the limit and the warning, with the manifest and baseline in sync (`manifest_consistency`, `repository_update_noop`, `codeflow validate --docs`).
- AC-6 On a fresh `codeflow init` project, `codeflow ci --pr-body-file` with a body over 1,000 words prints the warning and exits 0, and with a short body prints no length warning (journey).
