# TSK-274: the startup-file guard reads Cygwin and MSYS2 home spellings

## Description

The shell startup class (TSK-242) refuses a command that writes a shell
startup file such as `~/.zshrc`. Diagnosing a flaky Windows test in the
3.1.0 release pull request (PR 132) showed two spellings the guard probably
misses on Windows; neither has been reproduced on Windows yet. First, `key`
and `drive_free` (`crates/codeflow-core/src/security/startup.rs:535` and
`:553`) strip a drive letter, `c:/` and the Git Bash form `/c/`, but not the
Cygwin form, so `/cygdrive/c/Users/u/.zshrc` is probably read as
`/cygdrive/c/users/...` and allowed. Second, under MSYS2 or Cygwin with
`HOME` at `C:\msys64\home\u`, a literal `/home/u/.zshrc` probably misses,
because only the class's absolute `/etc` entries are mapped through the
shell install folders (`startup.rs:329-330`). Git Bash is not affected.
This task reproduces both on a Windows runner, then fixes the guard or
documents which Windows shells it supports. The hosted Windows journeys come
with TSK-271, which this task should use when it lands (stated here rather
than in `depends_on`, because TSK-271's record is not on `main` yet).
Non-goal: other shells' spellings that have no reproduced miss.

## Deliverables

- the reproduction and its result: provisional, a Windows test in `crates/codeflow-core/src/security/startup_tests.rs` or a hosted job log, named when run
- the fix, or the documented supported shells: `crates/codeflow-core/src/security/startup.rs`, or the shell-startup rows of `docs/` that the fix or the decision makes stale

## Acceptance Criteria

- AC-1 On a native Windows runner, a test drives the guard with `/cygdrive/c/...` and MSYS2 or Cygwin `/home/<user>/...` spellings of a startup file and records whether each is refused. Evidence: the test and its Windows output.
- AC-2 When a reproduced spelling is allowed, the guard refuses it after the fix, with a test that fails before the fix and passes after on Windows; when a shell is not supported instead, the docs say which shells the guard covers on Windows and why. Evidence: the test pair or the docs diff.
- AC-3 Git Bash spellings (`/c/...`, `C:/...`) stay refused. Evidence: the existing Windows drive-spelling test still passes.
- AC-4 On a native Windows runner, a command that writes a startup file through a Cygwin or MSYS2 home spelling is refused, or the documented unsupported shell is named in the refusal-coverage docs (journey)
