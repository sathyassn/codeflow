# TSK-085: managed catalog switched to the current roster

## Description

Switch the product to the catalog: the managed `current-ensemble.json` moves
to schema 5 with the EPC-018 seed roster, every test and evaluation marker
that named the old binding moves to catalog-derived checks, and the decision
records are accepted and annotated. This is the join of the autonomy chain
and the catalog engine, and the one task that owns both the migration and the
tests that depend on it.

- Managed catalog: schema 5 with the EPC-018 seed table and duty table, in
  `assets/base` and its four mirrors. The seat-eligible versions in the
  seed table (the two Claude seat lines, the three Codex seat lines and the
  Grok seat line) carry their seat designation dated 2026-09-23 (the
  operator's Q2 answer); the worker-only line and the retired versions carry
  none; every version has an empty qualification field; the `design` duty is served by the Claude seat's
  first line only; adoption is `manual` unless Q1 is answered; the Grok trigger policy is today's
  `routing-policy.json` unless Q4 is answered. The Opus design pilot route
  and the prose fallback rule are removed. The engine's schema 4 path is
  removed.
- `orchestration_contract.rs`: delete the literal selector and class pins
  (near lines 263-273 and 736-738) and the hand stale-pin list (near line
  352), and add structural checks read from the catalog: every seat line can
  be eligible, every duty resolves on some supported host, `unit-review` owes
  Codex for Claude-authored units, `body-review` owes both standing seats,
  the design owner seat is Claude.
- Turn on TSK-080's scans for the real tree, with its exact exclusions.
- Evaluation kit: the ensemble requirement markers (near
  `requirements.json:1024-1032` and `:1088`) move to schema 5 markers; the
  design routing case (near `cases.json:2786`) and the Terra case (near
  `:5068`) are re-scoped to seat and duty signals with fictional model
  names; the design case gains four variants: both Claude lines available
  (design by the first line, Fable a labeled second opinion), review line
  absent (design proceeds, the missing second opinion recorded), candidate
  worker offered fidelity approval (refused), and the first line unavailable
  (the seat falls to Fable for orchestration, planning and review with
  reduced assurance; the design duty stays open; a matching
  `OPERATOR_OVERRIDE` record committed in the fixture's approved plan,
  naming the Claude seat's second line at high for that one task, is the
  positive control, and a fabricated or mismatched record accepted is a
  faulty control that fails); a new
  `drift-inherits-nothing` case whose faulty control proceeds with design
  work on a model whose observed id differs from the pinned id.
  Each keeps a faulty control that fails.
- A behavioural fixture: with the switched catalog, changing only the
  catalog data (a fixture copy) changes the selector and effort that
  `codeflow models resolve --json` returns for `unit-review` and `design`,
  a bucket exclusion changes the fallback, and a catalog with no eligible
  Codex version leaves the Claude-authored `unit-review` open; every resolved
  participant carries a pinned id, never an alias; and `design` with an
  xhigh trigger returns the seat at high plus an `xhigh-reasoning` worker
  at xhigh.
- Records: accept ADR-0069 with the roster, its date and the operator's
  designation of 2026-09-23.
  Write every dated Note in this epic: ADR-0024, ADR-0028, ADR-0039 (layer
  4), ADR-0041, ADR-0054 (item 2), ADR-0055 (item 2), ADR-0060 (design owner
  paragraph), and one Note on ADR-0035 citing ADR-0069 (seats) and ADR-0070
  (settled dissent, approval after a mid-run seat loss). ADR-0056 and
  ADR-0059 are not amended.

Non-goal: prose (TSK-081), Agent OS, a full native qualification suite (TSK-078 files
