# TSK-289: Review briefs sent through cf-consult refuse a narrowed scope

## Description

PR 126 (TSK-260) made `cf-herdr`'s `deliver.py --review <base>...<head>`
refuse a review brief narrower than the unit (exit 6,
`assets/base/agents/skills/cf-herdr/scripts/deliver.py:200-241` at v3.1.0).
Issue 121 (https://github.com/sathyassn/codeflow/issues/121) asked for the same check on the cf-consult brief path
too. A consult sent through another cf-delegate lane (the Codex plugin
lane, the native fallback, `codeflow delegate arm` for an interactive
Claude seat, or the tmux fallback) is held only by the rule pointer in
cf-consult and the verdict's `at <head>` line. This task makes every lane
that sends a review brief run one shared check. Non-goal: refusing a brief
that is not a review, such as a one-fix confirmation, which stays allowed
when it says so.

## Deliverables

- the shared brief check: beside `assets/base/agents/skills/cf-herdr/scripts/deliver.py`, or behind `codeflow delegate arm` in `crates/codeflow-core/src/delegate.rs` (provisional; the builder decides with the reviewer)
- the skill text: `assets/base/agents/skills/cf-consult/SKILL.md`, `assets/base/claude/skills/cf-delegate/SKILL.md` and its lane resources, mirrors and baseline
- tests: `evals/herdr-delivery/test_delivery.py` and `crates/codeflow-cli/tests/delegate_cli.rs`
- release note: `changelog.d/TSK-289.md`

## Acceptance Criteria

- AC-1 When a review brief for `<base>...<head>` is sent through any
  cf-consult lane and names a narrower range, a narrowed diff or another
  revision, it shall not be sent, and the refusal shall cite the review
  rule in `.codeflow/rules/workflow-discipline.md`; evidence: a test per
  lane. (serves EPC-022 AC-7)
- AC-2 `deliver.py --review` and the other lanes shall use one check, so
  the accepted and refused brief forms are the same on every lane;
  evidence: one fixture set run against every lane, the existing
  `test_review_refuses_a_brief_narrower_than_the_unit` cases included.
- AC-3 A brief sent without the review marker, such as a one-fix
  confirmation, shall still be sent; evidence: an allow test per lane.
- AC-4 cf-consult and cf-delegate shall name the check where they describe
  sending a review brief, byte-identical across `.claude/skills` and
  `.agents/skills`; evidence: `manifest_consistency` and the diff.
- AC-5 When a fresh standard project uses the installed build, a cf-consult
  review brief narrowed to a fix commit shall be refused on the plugin lane
  and the Herdr lane, and the whole-unit brief shall be sent (journey);
  evidence: a journey run on the installed scaffold.
