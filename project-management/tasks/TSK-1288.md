# TSK-1288: Reasoning effort is set per coordination tier

## Description

Consolidated 2026-11-04 into TSK-1287 by the consolidation planning amendment (operator ruling of 2026-11-04). Every criterion below moved there word for word, with a `Moved` note naming its old id: AC-1 is TSK-1287 AC-7, AC-2 is TSK-1287 AC-8, AC-3 is TSK-1287 AC-9, AC-4 is TSK-1287 AC-10, AC-5 is TSK-1287 AC-11, AC-6 is TSK-1287 AC-12. This record stays as history; build work happens under TSK-1287.

The operator set reasoning effort per coordination tier on 2026-11-03 at 10:43: "coordinator runs at high only if there is no director or if it's the only one". The rule:

- The Director runs at high.
- A Coordinator runs at high only when no Director exists, that is, when it is the top or only coordinating session.
- With a Director present, every Coordinator runs at its vendor's default, like every Worker.
- The user can always override.

No CodeFlow record or skill carries it. `cf-model-orchestrator` speaks of the primary at "default effort" (`SKILL.md:112`) and ADR-0015 (lines 65-67) still says each side runs at high effort with 2026-07 pins. TSK-1131 (PR 480, standalone) makes each session start at its vendor's recommended effort; this task amends that guidance after it lands and does not reopen PR 480. Non-goals: the effort a task's own criteria raise for a hard build or a security review, which stays the per-task rule in the routing references.

## Outcome

After this merges, a Director, a Coordinator and a Worker each start at the effort the operator set for their tier, and the user can still override it.
