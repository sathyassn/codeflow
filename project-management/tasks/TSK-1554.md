# TSK-1554: The generation check ignores file mode noise

## Description

Source: the TSK-1532 candidate-proof run of 2026-11-19 (runner li, 10:47 to 10:57) and the generation probe of the same day, relayed by the Director. Filed by coord/records.

Checked here, at origin/main `17510e9bd4`:

- The run's gate failed with "generation changed the candidate: docs-portal/public/favicon.svg, fonts-LICENSE.txt, portal-chrome.js, portal-preview.js, portal-tabs.js, tokens.js" (`coordination/coordinators/parallel/notes/tsk1532-candidate-li-2026-11-19/01-docs-portal.log:249`) although all five targets had passed and Git showed no change.
- The probe (`coordination/coordinators/planning/notes/tsk1532-generation-probe/report.md`, sha256 `ef4e6825def7080bc2b593a31f4b4346011c3df0ed5c788ba42734d313d4b6aa`) reproduced it: a worktree created under `umask 077` holds tracked files at mode 0600; the docs-portal generation rewrites the six public files at 0644; the gate's candidate digest includes the full Unix mode (`crates/codeflow-core/src/testing/delivery.rs:304-313`), so the transition reads as a change. Git tracks only content and the executable bit, so nothing in Git changed. The same head in a normal checkout, main, and the TSK-1513 sync head generated no change.
- A second occurrence, in the opposite direction (added 2026-11-20 by coord/records, relayed by the Director and coord/ci): main candidate j at `ce640ae2a8`, runner nw, 12:18, failed "generation changed the candidate" when 39 present asset files went from mode 0644 to 0600 with identical bytes (`coordination/coordinators/parallel/notes/j-present-web-build-diagnosis.md`, sha256 `e5e44eab82ccb34d68a53732667520e40f6a24b3485203b6f8f55afa92a7d0e4`). The loop runner compares the snapshot at `crates/codeflow-core/src/testing/runner/mod.rs:846-865` as well as the digest at `delivery.rs:304-313`. Candidate j is not blocked by this: coord/ci works around it with a mode-safe gate letter.
- A search of the task records at `17510e9bd4` (`git grep` over `project-management/tasks` for the gate message and for `umask`): only TSK-244, TSK-281 and TSK-412 contain the word, none about this check. No open record covers it.

As reported, not checked here:

- Which other digest sites in `delivery.rs` or its callers hash the full mode, and whether any is wanted (for example a deliberate permission check for a secret-bearing path).
- How often adopters use a restrictive umask in CI or on a workstation.

Premise: read `crates/codeflow-core/src/testing/delivery.rs` around `:304-313`, the places that call it, and the probe report, before any change.

Non-goals:

- Weakening the check for content, the executable bit or added and removed files.
- Changing how the proof letters create their worktrees (TSK-1532's own letter fix covers that).

## Outcome

After this merges, a checkout made under any ordinary umask no longer fails the generation check for a mode transition alone, while a real content, executable-bit, addition or removal change still fails it.

## Deliverables

- the digest in `crates/codeflow-core/src/testing/delivery.rs` reduced to what Git tracks (content, the executable bit, and file kind), with tests
- a statement in the pull request body of which mode bits the check now ignores and why
- the release note: `changelog.d/TSK-1554.md`

## Estimate

- Basis: reading one function and its callers, one change, tests for the 0600 to 0644 transition and for real changes, and one cross-family whole-unit read. Graded by coord/records; the builder re-scores at claim.

## Acceptance Criteria

- AC-1 When a candidate is created under `umask 077` and its generation rewrites a tracked file from mode 0600 to 0644, or from 0644 to 0600, with no content change, the generation check shall pass; evidence: a test for each direction that fails before the change and passes after it.
- AC-2 When generation changes a tracked file's content, its executable bit or its file kind (for example a file replaced by a symlink), or adds or removes a file, the check shall still fail and name the paths; evidence: tests for each, passing at the head.
- AC-3 When the digest is read, it shall include only what Git tracks (content, the executable bit, file kind); evidence: a read of the digest function and its callers, with any other caller that needs the full mode named and kept; the snapshot comparison in `runner/mod.rs:846-865` is read the same way.
- AC-4 When the change is made, it shall touch only the digest, its tests, the release note and any documentation of the check; evidence: the diff paths.
