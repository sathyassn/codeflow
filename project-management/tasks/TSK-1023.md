# TSK-1023: Review documents accept every task and spec id the allocator issues

## Description

Issue #356 (CodeFlow 3.1.1). `codeflow present check`, and so `present
open` and `present update`, refuses a review document whose
`provenance.task_id` is `TSK-1000` or higher, although the allocator issues
such ids. This repository passed TSK-999 on 2026-10-25 (TSK-1000 to
TSK-1029 exist), so its own review pages for those tasks cannot carry their
task id today.

Rechecked on 2026-10-27 on the line tip `7172229aa` with the 3.2.0 binary
built at TSK-397's head `caf728c70`: the issue's `TSK-647` document passes,
and the `TSK-1000` document fails with exit 9 and "provenance task_id must
be TSK-NNN or TSK-NNN-NNN". Two places cap each id segment:

- the Rust validator: `validate_provenance`
  (`crates/codeflow-present/src/document.rs:1622`), `valid_task_id`
  (`:1643`) through `valid_three_digits` (`:1659`, `value.len() == 3`),
  and `valid_fixed_id` with `("SPC-", 3)` and `("ADR-", 4)` (`:1631`);
- the shipped schemas, installed under `.codeflow/schemas/present/`:
  `assets/base/present/schemas/document-v1.schema.json:26-28`,
  `document-v2.schema.json:54,58,62`,
  `session-history-v1.schema.json:21-23` and
  `session-history-v2.schema.json:54,58,62`.

The work graph accepts three or more digits
(`crates/codeflow-core/src/workgraph/format_id.rs:49`,
`is_sequence_segment`), and the spec and task allocators format with
`{next:03}` (`crates/codeflow-core/src/workgraph/allocate.rs:150` and
`:166`). ADR ids are allocated with `{:04}`
(`crates/codeflow-core/src/workgraph/light_paths.rs:298`), so the
four-digit ADR cap only matters at ADR-10000; it is fixed in the same
change so the rules cannot drift.

Outcome: **a review document accepts every task, spec and ADR id the
allocators can issue, and a test fails if the present rules and the work
graph's id rules disagree.**

`codeflow-present` does not depend on `codeflow-core` (only `codeflow-cli`
depends on both). The builder either keeps a local rule in the present
crate with a cross-crate agreement test in `codeflow-cli`, or moves the
rule to a place both crates read; a new dependency edge is not required.
Non-goal: any other change to the provenance schema.

## Deliverables

- the validator: `crates/codeflow-present/src/document.rs` (`validate_provenance` and its helpers)
- the schemas: the four files under `assets/base/present/schemas/` named above, with the installed `.codeflow/schemas/present/` copies and the `.codeflow/.baseline` copies synchronized
- tests: the present contract tests in `crates/codeflow-present/` and one agreement test in `crates/codeflow-cli/tests/`
- release note: `changelog.d/TSK-1023.md`

## Acceptance Criteria

- AC-1 When a review document's `provenance.task_id` is `TSK-1000`, `TSK-12345` or a historical `TSK-NNN-NNNN`, its `spec_id` is `SPC-1000`, or its `adr_id` is `ADR-10000`, `codeflow present check`, `present open` and `present update` shall accept it; evidence: present tests per id, the `TSK-1000` case failing before the change with the issue's message. (serves EPC-022 AC-131)
- AC-2 Ids the work graph rejects (`TSK-99`, `TSK-0x12`, `SPC-12`, `ADR-123`, a trailing `-`, a third group) shall still be refused by the validator and by each schema; evidence: present tests per case.
- AC-3 A test shall fail when the present validator, any of the four schema patterns, or the allocators' formatted output disagree with `format_id.rs` on a sampled id set that holds three, four and five digit segments; evidence: the agreement test, shown failing against the current three-digit rules. (serves EPC-022 AC-131)
- AC-4 (journey) With the installed build in this repository, `codeflow present open` of a document tagged `TSK-1023` shall open and show the tag; evidence: the command output.
