# TSK-1410: A gate inside a coverage collector does not wrap its own collector

## Description

When `codeflow test` runs inside an outer coverage collector, each target's command inherits the collector's environment: the compiler wrapper and the instrumentation settings it exports. The runner removes only the git location variables before it starts a target (`crates/codeflow-core/src/testing/runner/mod.rs`, `configure_environment`). If the target runs a collector of its own, as TSK-1014's generated Rust full command `cargo llvm-cov` does, that collector builds with the outer wrapper and adds its own instrumentation on top, and the result repeats until the gate's timeout. Codex found it while reviewing PR 743: a test of `codeflow test` run under an outer `cargo llvm-cov` timed out after 600 seconds with the instrumentation flags repeated. PR 743 isolates its own test's child environment and leaves the runner as it is. Codex ruled out stripping every adopter compiler setting in the runner, because an adopter may set a wrapper or flags on purpose. This task decides the product behaviour and builds it.

## Outcome

After this merges, `codeflow test` run inside a coverage collector either completes its targets with one level of instrumentation or refuses at once with a message that names the cause and the remedy. It never wraps a collector inside a collector until the timeout.

## Deliverables

- the decision and the fix: the test runner in `crates/codeflow-core/src/testing/`
- tests: a fixture that runs a gate inside an outer collector environment, beside the runner's environment tests
- docs: the testing guide's coverage section and a changelog fragment `changelog.d/TSK-1410.md`

## Acceptance Criteria

- AC-1 Before building, the task shall record which behaviour it takes and why: detect a nested collector and refuse with a named cause, isolate only the outer collector's own variables for a target that runs a collector, or another behaviour with the same outcome. The choice shall keep a compiler wrapper or flags the adopter set on purpose (outside any collector) reaching every target as it does now; evidence: a Decision section in this record, reviewed with the build.
- AC-2 When `codeflow test` runs with an outer collector's environment and a target runs its own collector, the target shall complete with one level of instrumentation, or the run shall refuse before the target starts with a message naming the outer collector's environment and how to run the gate outside it; evidence: a fixture test with a fake collector that records how many times it was nested, failing before the change (the target nests or times out) and passing after.
- AC-3 A target that runs no collector, and a gate run outside any collector, shall keep their current environment and verdicts, and an adopter's own wrapper or flags set outside a collector shall still reach the target; evidence: the same tests.
- AC-4 The coverage section of the testing guide shall say how a gate behaves inside a coverage collector, and the changelog fragment shall describe the change; evidence: the doc diff and `codeflow validate --docs`.
