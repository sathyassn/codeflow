# TSK-312: codeflow status --json gives the shared fact model

## Description

`codeflow status` has no `--json` (`crates/codeflow-cli/src/cmd/status.rs:7-17`),
so a tool that wants the checkout's work facts parses text
(https://github.com/sathyassn/codeflow/issues/166). This task adds
`codeflow status --json` on the same versioned fact model TSK-311 defines
for `report program`, so one schema serves both: deterministic order, and
fields for incomplete data always present rather than omitted. The text
output is unchanged. Non-goal: new facts in the text view.

## Deliverables

- the JSON output: `crates/codeflow-cli/src/cmd/status.rs` and the shared fact model from TSK-311
- tests: `crates/codeflow-cli/tests/` beside the existing status tests, reusing TSK-311's schema test
- docs: `docs/cli.md`
- release note: `changelog.d/TSK-312.md`

## Acceptance Criteria

- AC-1 `codeflow status --json` shall emit the versioned fact model of
  TSK-311 for the checkout, with `schema_version` and the same field names;
  evidence: TSK-311's schema test run against `status --json`.
  (serves EPC-023 AC-1)
- AC-2 Two runs on the same repository state shall give byte-identical
  output, in a deterministic order, once the documented snapshot-time
  field is held fixed; the field itself still records each run's own
  observation time; evidence: a test that runs it twice, with records
  created in different orders, under a fixed clock (or comparing after
  normalizing only that field).
- AC-3 Fields for data the checkout cannot supply shall be present and
  marked incomplete, never omitted and never printed as zero; evidence: a
  test on a checkout with an unreadable record and no remote.
- AC-4 The text output of `codeflow status` shall be unchanged; evidence:
  the existing status tests unchanged.
