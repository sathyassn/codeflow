# TSK-271: native platform journeys run in hosted CI

## Description

TSK-205 AC-5 asks native runs to qualify the presentation utility's adapters
and the documentation portal on every platform. For 3.1.0 the operator
recorded WSL2 as not run and native Windows as partial (2026-10-11), because
the hosted jobs leave these journeys out: there is no WSL2 job; Windows runs
no presentation browser launch, export, process-tree cleanup or Unicode
known-folder path (`crates/codeflow-cli/tests/present_cli.rs` is
`#![cfg(unix)]`, and no presentation web check runs there); 15 of the 115
portal adapter tests are skipped on Windows; and no hosted job on any
platform runs the portal `npm run browser:verify`. On macOS, the
presentation browser check could not run Firefox on the release host: the
Playwright Firefox build `firefox-1538` times out at launch on macOS 27.0.1,
so 3.1.0 records macOS Firefox as not qualified there. This task adds those
journeys to CodeFlow's own hosted CI, so the next release qualifies them
from hosted runs. It depends on the Linux CI work (TSK-270), so the new
jobs fit the reshaped gate; that dependency is stated here rather than in
`depends_on` until TSK-270's record is on `main`. Non-goal: changing presentation or portal behaviour;
a journey that fails here is fixed in its owning task or filed.

## Deliverables

- the hosted jobs: `.github/workflows/codeflow-ci.yml`
- the Windows-capable presentation journeys: provisional, `crates/codeflow-cli/tests/present_cli.rs` or a Windows sibling, and `crates/codeflow-present/web/scripts/`
- the portal adapter tests made to run on Windows: `docs-portal/tests/adapter.test.mjs` and its starter copy `assets/docs-portal/starter/tests/adapter.test.mjs`
- the pins: `scripts/gate-parity.py` and its tests
- the platform rows: `docs/releasing.md`

## Acceptance Criteria

- AC-1 A hosted WSL2 job installs the Linux archive's binary and runs the presentation and portal journeys; its result is recorded as Linux, never as native Windows. Evidence: the job and a passing hosted run.
- AC-2 A hosted native Windows job launches a real browser for a presentation session, exports it, cleans up the process tree, and uses a profile under a Unicode known-folder path. Evidence: the `windows-latest` job log showing each step pass.
- AC-3 The 15 portal adapter tests skipped on Windows run there, or each remaining skip names the Windows behaviour that makes the test inapplicable and a Windows test covers the same risk. Evidence: the Windows test output and the diff of the skip conditions.
- AC-4 A hosted job runs the portal `npm run browser:verify` on Linux and on Windows. Evidence: both job logs.
- AC-5 The gate verdicts need the new jobs, and `gate-parity` pins them with their timeouts. Evidence: `gate-parity` and its tests.
- AC-6 On the final head's hosted pull request run, the presentation journey and the portal browser verification pass on native Windows and on WSL2 (journey)
- AC-7 The presentation browser check (`present-browser`) runs Firefox on macOS and passes, on a hosted macOS runner or locally with a Playwright Firefox build that starts on macOS 27. Evidence: the job log or the local gate run naming the Firefox build and the macOS version.
