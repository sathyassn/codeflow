# TSK-1587: Cloud account and tenant ids and chat and tracker ids are privacy findings

## Description

Owner: to be assigned by the Director. Staged 2026-11-23 for coord/records.

SPC-018 R-16 to R-18. An AWS account id in an ARN, an Azure tenant GUID,
a Google Cloud project number, a chat channel link or a tracker issue URL
on a named workspace host identifies an organisation or a person. These
values are not secrets, so the secret scan passes them. Every detector is
keyed on structure or an adjacent key, so a bare GUID or a 12-digit number
alone is not a finding. This task also adds `privacy.pattern_kinds` to
narrow layer 2, reported as a relaxation.

Non-goals: a project-maintained list of workspaces or accounts (layer 5
covers organisation terms).

## Outcome

After this merges, the account, tenant, chat and tracker kinds of SPC-018
R-16 and R-17 are findings at the `privacy.patterns` level, and a project
can narrow layer 2's kinds with the narrowing reported.

## Deliverables

- `crates/codeflow-core/src/privacy/patterns/accounts.rs` and `chat_tracker.rs` (new) with unit tests
- `privacy.pattern_kinds` in `policy_schema.rs`; its line in the privacy check's own relaxation output (SPC-018 R-2a), independent of TSK-424's activation key
- docs; `changelog.d/TSK-1587.md`

## Acceptance Criteria

- AC-1 Fail before: at the base, a commit adding an ARN with a 12-digit account, an Azure `tenant_id` GUID, a chat message link and a tracker issue URL on a named host (each assembled at run time) is accepted; evidence: the base output in the PR.
- AC-2 Pass after: each shall be a finding at the level; a bare GUID, a bare 12-digit number and a public project's issue URL on the forge this repository uses shall not be; evidence: detector and hook tests, positive and negative.
- AC-3 The placeholder forms (`123456789012` documented as the AWS example account, the all-zero GUID, `example.slack.example`-style hosts in the table) shall pass; evidence: tests.
