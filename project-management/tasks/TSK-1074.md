# TSK-1074: An away session can run on a harness route other than Claude Code's listable scheduled jobs

## Description

Source: the session system design, revision 12.3 of 2026-10-29, section 7
("E9, H2, H3, H7: deferred, not exercised in 4.0.0"). In 4.0.0 an away
activation is owned by a Claude Code session and ticked by a Claude Code
scheduled job that the activation can list, renew and delete (TSK-1045
AC-18, AC-20, AC-21). Two routes are refused and recorded as not
supported in TSK-1046's route reference:

- H2, H3: a Codex session as activation owner, with Codex `/goal` or a
  Herdr keeper as its clock. No qualified session and process identity
  source exists for Codex, and `/goal` continues a session but is not a
  clock.
- E9: a scheduled trigger kind with no list surface (for example Grok
  `/loop`, or any harness timer CodeFlow cannot list). Renewal and
  cleanup in TSK-1045 depend on listing the activation's own jobs, so a
  kind without a listing cannot be renewed or cleaned safely.

H7, the delegate heartbeat and Stop lifecycle, is TSK-440's (EPC-025)
and is not part of this task.

Non-goals: headless work seats, which stay forbidden on every route;
changing the Claude Code route.

## Outcome

After this merges, a user can set a Codex session, or a harness whose
trigger cannot be listed, away under the same admission, renewal and
report rules as a Claude Code session, on each route the route
reference marks supported.

## Deliverables

- investigation: a `## Findings` section in this record before any change
- the owner adapter: the identity adapter in `crates/codeflow-core/src/coord/away.rs` (TSK-1045)
- the route reference and skill text: `cf-away`'s `references/` under `assets/base/agents/skills/cf-away/`, mirrored and resynced (TSK-1046)
- tests: CLI tests and a native run record per newly supported route
- release note: `changelog.d/TSK-1074.md`

## Acceptance Criteria

- AC-1 Before any change, the builder shall record with sources, per harness: the session and process identity a Codex session exposes and whether it meets TSK-1045's owner rules, each clock-like route (Codex `/goal`, a Herdr keeper, Grok `/loop`) and whether it can be listed, renewed and deleted by id, and how each behaves at expiry and at a usage limit; evidence: the Findings section with resolved links.
- AC-2 A Codex session shall be accepted as owner only with a qualified session id and process source that passes TSK-1045 AC-18's walk and refusals, and refused otherwise with the reason; evidence: CLI tests for a qualified and an unqualified source.
- AC-3 A trigger kind shall be armed only when it offers a listing by id and a deletion by id, or a one-shot contract under which no copy can outlive the activation; any other kind is refused with "automatic continuation is not armed"; evidence: tests per kind.
- AC-4 Each route marked supported shall have a native interactive run of at least three ticks, a compaction, a resume and the deletion of its trigger; evidence: one run record per route.
