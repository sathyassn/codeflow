# TSK-1415: Remote protect admits only canonical integration line names, and doctor finds case twins

## Description

GitHub compares concurrency groups and many tools compare branch names without regard to case, so two integration lines whose names differ only in case (`integration/EPC-001-x` and `integration/epc-001-x`) can share a group and be confused for each other. Today only three things stop such a pair: `epic new` writes lower-case slugs, a record check sees the lines named in task records, and a live read by hand. The remote also holds a hand-named line, `integration/release-3-0-0-r3`, that no record names.

This task makes `codeflow remote protect` add a rule, in a ruleset it already owns, that admits a new branch under `integration/` only in a canonical form, and makes `doctor` report whether that rule is in force and read the remote's names under `integration/` live for case twins.

It was added to TSK-383 as AC-6 on 2026-11-05 (Director ruling after TSK-1313's review, then widened and rewritten from the PR 634 review). TSK-383 completed on the EPC-022 line through PR 700 with AC-1 to AC-5 verified before that amendment reached the line, so the criterion moves here as a follow-up instead of reopening a reviewed acceptance. TSK-1313 AC-8 states the constraint for concurrency groups; it is complete and takes no new work.

Non-goals: renaming existing lines, and branch names outside `integration/`.

## Outcome

After this merges, a maintainer who runs `codeflow remote protect` gets a remote that refuses a non-canonical integration line name, and `codeflow doctor` tells them whether that protection is in force and whether any two remote lines differ only in case.

## Deliverables

- the canonical-name rule in the owned rulesets: beside `codeflow remote protect` in `crates/codeflow-core` (provisional; the builder places it next to the existing ruleset writer)
- the doctor checks: beside the remote-perimeter doctor check (provisional; same rule)

## Acceptance Criteria

- AC-1 Before choosing the mechanism, the builder shall read live which rule the repository's plan supports for this (a branch-name pattern rule, or a creation restriction on a pattern) and record the read and the choice in `## Findings`; evidence: the read's output in the pull request body.
- AC-2 `remote protect` shall add, inside a ruleset it owns and with the same bypass list as the other rulesets it owns, a rule that admits a new branch under `integration/` only as `integration/EPC-NNN-<slug>` with `EPC` upper case and a lower-case slug, or as a lower-case name that does not start with `epc-`, and refuses every other name under `integration/`; evidence: a `--dry-run` test showing the rule in the planned requests, with `integration/EPC-001-x` and `integration/release-3-0-0-r3` allowed and `integration/epc-001-x` and `integration/EPC-001-X` refused.
- AC-3 `doctor` shall report the rule present or missing, and shall report the repository as unprotected against case-collision line names when the host offers neither mechanism; evidence: a doctor test for each of present, missing and unsupported.
- AC-4 `doctor` shall read the remote's branch names under `integration/` live and report any two that differ only in case, hand-named lines included, and shall fail, never report no twins, when the live read fails; evidence: a doctor test with a hand-named twin, and a doctor test where the live read fails.
