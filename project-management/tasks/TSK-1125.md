# TSK-1125: A work claim pinned to a predecessor accepts a local copy that is behind the pinned remote tip

## Description

Source: issue #459 (CodeFlow 3.1.1, source `48104f48b`), read on the line
tip `b6cf648d3`; the issue's line numbers have moved, and no open task
covers it.

`codeflow work claim <task> --on <TSK-A>@<sha>` refuses with "TSK-A
predecessor branch has advanced; rebase on its new reviewed head and
recheck" when the predecessor's remote-tracking branch is exactly at the
pin and a local branch of the same name sits at an earlier commit that
the pin contains. The local copy is behind, not ahead, so the message
names the wrong cause and its remedy (rebase on a new reviewed head)
does not apply. Deleting the local branch clears the refusal.

Sites, read on the line tip, all in
`crates/codeflow-core/src/workgraph/work_start.rs`:

- `PinBranches::read` (`:1100`) maps each remote-tracking branch to its
  tracking name with `tracking_branch` (`:1117-1121`) and inserts the
  commit into one tip set per task and branch name (`:1124-1129`). The
  local `task/X` and `origin/task/X` therefore share a set, and the set
  does not record which tip came from which side.
- `PinBranches::pin_name` (`:1188`) finds the one branch name whose set
  holds the pin, then refuses with "predecessor branch has advanced" when
  that set holds more than one tip (`:1196-1201`). It does not look at
  how the other tip relates to the pin.
- Callers of `pin_name` or `pin_branch` (`:1260`): `reviewed_pins_in`
  (`:1403`), the helpers at `:1502` and `:1523`, `work start` at `:1573`
  and `validate_dependencies` (`:2505-2506`). The claim reaches it
  through `resolve_pins` (`crates/codeflow-cli/src/cmd/work.rs:288-297`)
  and `reviewed_pins_in`.
- A second consumer holds the same refusal under another message.
  `stacked_pins` (`:1763`) collects, for each code dependency, every
  visible tip the pushed HEAD contains (`tips_of`, loop at `:1809`) and
  returns "this branch contains several tips" when more than one
  qualifies (`:1812-1828`). A claim cut from the pin has the pin and the
  stale ancestor both contained in HEAD, so it fails here. `codeflow ci`
  calls it on a push (`crates/codeflow-cli/src/cmd/ci.rs:700-708`, the
  note and empty list at `:1780-1787`), and the pre-push push set runs
  that command (`crates/codeflow-cli/src/cmd/push_set.rs:297-335`). On
  the error the predecessor's commits are judged in the range
  (`classification.rs:454-459`). Today's push check fails in this shape
  (`crates/codeflow-cli/tests/work_cli.rs:1854-1859`, `:2018-2046`);
  `a_claim_on_a_reviewed_head_passes_its_own_push_check` (`:1880`) passes
  only when the pin is honoured.

Design (Fable reviews it before the build): the refusal exists so a pin
is never used after its branch moved past it. A copy of the branch that
the pin contains has not moved past the pin, so it is not "advanced".
`pin_name` shall accept the pin when every other tip of the same branch
name is a strict ancestor of the pin, judged by `descendant_of`
(`crates/codeflow-core/src/workgraph/history.rs:288-293`, which returns
an error for an overlay, incomplete ancestry or a shallow boundary), so
an ancestry that cannot be read refuses (issue 79), never reads as
"behind". A tip that is ahead of the pin or diverged from it still
refuses; this replaces today's "advanced" message for those two cases
with one that names the branch, both tips (the pin and the other tip),
the relation and the fix. `stacked_pins` applies the same rule: extra
contained tips that are strict ancestors of the one tip the claim would
accept collapse to that tip, an ancestry error still returns the error,
and an ahead or diverged extra tip still returns an error, so the push
nomination honours the pin exactly when the claim does. Both share one
helper, so the two surfaces cannot drift. The choice binds to
commit ids and ancestry, never to a branch name, a remote name or which
side a tip came from. `pin_name` is shared with the pre-push and CI
pin checks, so the builder confirms in its findings that no consumer
relies on the old refusal for a behind copy, and the review carries the
`cf-security-reviewer` checklist.

Non-goals: adopting an agent's own branch as the claim (TSK-1093), the
pin-chain and clean re-merge rules (TSK-341), and the choice between a
stale pin and a moved branch for a pin that is not the tip of any copy,
which keeps its current refusal.

## Outcome

After this merges, an agent whose clone holds a stale local copy of a predecessor branch can claim a task pinned at that predecessor's pushed tip, while a copy that is ahead of the pin or diverged from it is still refused with a message that names the real cause.

## Deliverables

- the pin check: `PinBranches::pin_name`, `stacked_pins` and a shared ancestry helper in `crates/codeflow-core/src/workgraph/work_start.rs`
- tests: unit tests beside the pin tests near `work_start.rs:3700` and CLI fixtures in `crates/codeflow-cli/tests/work_cli.rs`
- docs: the `--on` row of `work claim` in `docs/cli.md` (`:246`)
- release note: `changelog.d/TSK-1125.md`

## Acceptance Criteria

- AC-1 When a local branch of the predecessor is a strict ancestor of its remote-tracking tip and that tip is the pin, `codeflow work claim <task> --on <TSK-A>@<pin>` shall accept the pin and cut the claim from the pin; the same holds when the remote-tracking copy is the older one and the local branch is the pin; evidence: a CLI fixture for each shape, refused before the change with "predecessor branch has advanced" and accepted after, and a unit test of `pin_name` for each shape that fails before the change.
- AC-2 When a copy of the predecessor branch is ahead of the pin or has diverged from it, `pin_name` shall still refuse, and the message shall name the branch, the pin, the other tip, whether it is ahead or diverged, and the fix (rebase on the new reviewed head, or delete or reset the stray copy); evidence: one negative fixture and unit test for ahead and one for diverged, each refusing before the change with "predecessor branch has advanced" and after it with the new message, asserted by text; neither ever accepts.
- AC-3 When the ancestry between the pin and another copy cannot be read, `pin_name` and `stacked_pins` shall refuse with the ancestry-read cause, never accept; evidence: a unit test with an unreachable tip for each, refusing before the change with "predecessor branch has advanced" (or "several tips" for `stacked_pins`) and after it with the ancestry-read cause.
- AC-4 `stacked_pins` shall honour the pin for the AC-1 shapes, so that a push of the AC-1 claim passes its push check through the pre-push `codeflow ci` form (no pull-request body; `--into` only with the advertisement hand-off), and shall still return an error for the AC-2 shapes (ahead, diverged) and the AC-3 shape (unreadable ancestry), each asserting the cause in the output and that the pin is not honoured; evidence: a fixture per shape beside `work_cli.rs:1880`, with the behind shapes failing before the change with "this branch contains several tips" and passing after, and the refused shapes refusing before and after.
- AC-5 The `work claim --on` row in `docs/cli.md` shall state that a copy of the predecessor behind the pin is accepted and an ahead or diverged copy is refused; evidence: the doc diff and `codeflow validate --docs`.
