# TSK-1125: A work claim pinned to a predecessor accepts a local copy that is behind the pinned remote tip

## Description

Source: issue #459 (CodeFlow 3.1.1, source `48104f48b`), read on the line
tip `b6cf648d3`; the issue's line numbers have moved, and no open task
covers it.

`codeflow work claim <task> --on <TSK-A>@<sha>` refuses with "TSK-A
predecessor branch has advanced; rebase on its new reviewed head and
recheck" when the predecessor's remote-tracking branch is exactly at the
pin and a local branch of the same name sits at an earlier commit that
the pin contains. The local copy is behind, not ahead, so the message
names the wrong cause and its remedy (rebase on a new reviewed head)
does not apply. Deleting the local branch clears the refusal.

Sites, read on the line tip, all in
`crates/codeflow-core/src/workgraph/work_start.rs`:

- `PinBranches::read` (`:1100`) maps each remote-tracking branch to its
  tracking name with `tracking_branch` (`:1117-1121`) and inserts the
  commit into one tip set per task and branch name (`:1124-1129`). The
  local `task/X` and `origin/task/X` therefore share a set, and the set
  does not record which tip came from which side.
- `PinBranches::pin_name` (`:1188`) finds the one branch name whose set
  holds the pin, then refuses with "predecessor branch has advanced" when
  that set holds more than one tip (`:1196-1201`). It does not look at
  how the other tip relates to the pin.
- `pin_branch` (`:1260`), `pin_branch` at `:1502`, `:1523` and `:1573`
  call it, so the claim, `work start`, the pre-push check and `codeflow
  ci` share the rule. `tips_of` (`:1809`) is a separate consumer and is
  not changed.

Design (Fable reviews it before the build): the refusal exists so a pin
is never used after its branch moved past it. A copy of the branch that
the pin contains has not moved past the pin, so it is not "advanced".
`pin_name` shall accept the pin when every other tip of the same branch
name is a strict ancestor of the pin, judged by the existing ancestry
helper so that an ancestry that cannot be read refuses (issue 79), never
reads as "behind". A tip that is ahead of the pin or diverged from it
still refuses, and the refusal names the branch and both tips (the pin
and the other tip, with the relation) and the fix. The choice binds to
commit ids and ancestry, never to a branch name, a remote name or which
side a tip came from. `pin_name` is shared with the pre-push and CI
pin checks, so the builder confirms in its findings that no consumer
relies on the old refusal for a behind copy, and the review carries the
`cf-security-reviewer` checklist.

Non-goals: adopting an agent's own branch as the claim (TSK-1093), the
pin-chain and clean re-merge rules (TSK-341), and the choice between a
stale pin and a moved branch for a pin that is not the tip of any copy,
which keeps its current refusal.

## Outcome

After this merges, an agent whose clone holds a stale local copy of a predecessor branch can claim a task pinned at that predecessor's pushed tip, while a copy that is ahead of the pin or diverged from it is still refused with a message that names the real cause.

## Deliverables

- the pin check: `PinBranches::pin_name` and its helpers in `crates/codeflow-core/src/workgraph/work_start.rs`
- tests: unit tests beside `PinBranches` (`:3705` and `:4610` are the existing ones) and CLI fixtures in `crates/codeflow-cli/tests/work_cli.rs`
- docs: the `--on` row of `work claim` in `docs/cli.md` (`:246`)
- release note: `changelog.d/TSK-1125.md`

## Acceptance Criteria

- AC-1 When a local branch of the predecessor is a strict ancestor of its remote-tracking tip and that tip is the pin, `codeflow work claim <task> --on <TSK-A>@<pin>` shall accept the pin and cut the claim from the pin; the same holds when the remote-tracking copy is the older one and the local branch is the pin; evidence: a CLI fixture for each shape, refused before the change with "predecessor branch has advanced" and accepted after, and a unit test of `pin_name` for each shape that fails before the change.
- AC-2 When a copy of the predecessor branch is ahead of the pin or has diverged from it, `pin_name` shall still refuse, and the message shall name the branch, the pin, the other tip and whether it is ahead or diverged, and the fix (rebase on the new reviewed head, or delete or reset the stray copy); evidence: one negative fixture and unit test for ahead and one for diverged, each asserting the message text, and each refusing before and after.
- AC-3 When the ancestry between the pin and another copy cannot be read, `pin_name` shall refuse with the cause, never accept; evidence: a unit test with an unreachable tip, refused with the ancestry-read cause before and after.
- AC-4 The pre-push check and `codeflow ci` shall reach the same verdict on the AC-1 and AC-2 shapes as `work claim` does; evidence: one fixture per form for the behind shape (accepted) and the ahead shape (refused).
- AC-5 The `work claim --on` row in `docs/cli.md` shall state that a copy of the predecessor behind the pin is accepted and an ahead or diverged copy is refused; evidence: the doc diff and `codeflow validate --docs`.
