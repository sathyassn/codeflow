# TSK-059: portal figure runtime and figure gate

## Description

Give the portal a figure runtime that draws the grammar: a shared module
(`docs-portal/scripts/figure.mjs`, the `shared/svg.js` lineage from the W5
board rewritten on the utility tokens) with scales, the closed mark vocabulary,
legend keying from the drawn set, the accessible description, the table twin
and per-width recomposition; a figure block the adapter emits from a figure
declaration file, in two binding modes: authored (positions declared in the
file) and derived (the adapter binds a data model from a named source such as
the capability registry, the policy schema, the ADR graph or the CLI help, and
records the derived values). Extend `browser-verify` with the figure gate:
every explanatory page has one figure per altitude; every figure has a legend
that keys every drawn state and nothing more, a description, a table twin, no
literal colour, every state mark at or above the declared floor at both
widths, the narrow render within the declared height multiple, and derived
figures pass a fidelity check against their source. Mirror the runtime into
the managed starter and teach the Rust validator the figure block's evidence.
Non-goal: authoring the guide's figures; TSK-061 owns those.

## Affected surfaces and interfaces

`docs-portal/scripts/figure.mjs` (new), `adapter.mjs`, `lib.mjs`,
`browser-verify.mjs`, `src/components/PortalFigure.astro` (new),
`portal.config.json` figure declarations, `docs-portal/figures/**` (the
declaration file shape, one example), `tests/**`; the starter mirrors under
`assets/docs-portal/starter/**` and `assets/docs-portal/manifest.json`;
`.codeflow/docs-portal.json` hashes; `crates/codeflow-core/src/validate/portal.rs`
and its tests. CAP-015.

## Acceptance Criteria

- [ ] When a page declares a figure in a family, the runtime draws it from the
      declaration with the grammar module and no page-local SVG; the nine
      specimen figures from TSK-058 render through it unchanged; evidence:
      `node --test` cases per family and the fixture page.
- [ ] When a figure is derived, the adapter records the source path, the
      derived values and the drawn values in the evidence manifest, and
      `validate --portal` compares them; a hand-edited drawn value fails;
      evidence: the validator test with a tampered fixture.
- [ ] When any explanatory page lacks a figure at an altitude, or a figure
      has an unkeyed mark, a literal colour, a mark under the floor at either
      width, a missing description or table twin, or a narrow height over the
      multiple, `browser:verify` fails and names the page, the altitude and
      the rule; evidence: fixtures where one compliant page cannot mask a
      noncompliant one.
- [ ] Every figure recomposes at 390 px by the declaration's narrow variant
      or the family's default recomposition, never by elongation; evidence:
      the height-multiple check and the design primary's review of the
      specimens at 390.
- [ ] The starter carries the runtime byte for byte and `portal setup` on a
      sample renders the specimen fixture; evidence: the starter equality
      test and a harness row.
- [ ] Editorial review of the declaration file format documentation, Grok
      adversarial review of the gate, Codex review where the seat allows;
      evidence: the review records.
