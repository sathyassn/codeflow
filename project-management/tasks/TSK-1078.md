# TSK-1078: Local git hooks judge at the landed policy level

## Description

Source: the content policy design for issue #279, revision 5, unit U3,
closing finding D-1 (Grok's design, item 4.4), which no task owned.

The pre-commit secret scan and conflict-marker check take their level
from the uncommitted working-copy policy:

- `crates/codeflow-cli/src/cmd/git_hook.rs:116` loads
  `Policy::load_effective(&root)`, which reads
  `<root>/.codeflow/policy.json`
  (`crates/codeflow-core/src/hooks/policy.rs:872-874`, `:944-945`);
- core `crates/codeflow-core/src/hooks/git_hook.rs:159` and `:163` skip
  the scan and the marker check when `is_active` is false, and `is_active`
  is `Block | Warn` (`policy.rs:62-64`), so `allow` skips as `off` does;
- the path gate already composes with the landed policy (`:145`;
  `landed_policy.rs:629-638`), and bootstrap grace keeps the scan on
  (`policy.rs:991-1022`); the commit-msg stage validates the file but a
  valid `off` passes.

An uncommitted `off` or `allow` therefore lets a content secret be
committed with pre-commit silent. Who can write the file: in a Claude
session `Edit(/.codeflow/policy.json)` is in `permissions.deny`, but
Claude's file tools run no edit-guard (`docs/policy-reference.md:1153`);
Codex and Grok run `codeflow hook edit-guard` (`.codex/hooks.json:14`,
`.grok/hooks/codeflow.json:14`); outside a session nothing does. This task
makes the edit harmless rather than blocking it: the landed level is the
floor and the worktree may only raise it.

The same load serves every classic hook the binary runs (pre-commit,
commit-msg, pre-merge-commit and pre-push; `crates/codeflow-cli/src/cmd/git_hook.rs:111`
at the line's 96a01e17e), so a committed policy that is stale, as on an
out-of-date local protected branch, or edited on the branch also sets
what those hooks apply. AC-7, added 2026-11-08 by the Director's ruling
on TSK-1398, extends the landed floor to every level and list those four
hooks apply, each in its strict direction, and AC-8 does the same for `codeflow ci`'s range choice,
which reads the same file (`crates/codeflow-cli/src/cmd/ci.rs:418`, `:445`).
TSK-1398 records that until both land, agents cannot drop the in-session
sync of a protected branch.

Non-goals: the path gate (already landed-composed); the hosted scan
(TSK-336).

## Outcome

After this merges, an operator can rely on pre-commit, commit-msg, pre-merge-commit, pre-push and `codeflow ci`'s range choice judging at least as strictly as the default branch's policy, whatever the uncommitted, stale or branch-edited policy file says.

- AC-1 With the authority at `block` and an uncommitted worktree `.codeflow/policy.json` at `off` or `allow`, pre-commit and pre-merge-commit shall still scan for secrets and conflict markers; evidence: tests for both levels and both hooks, failing before the change (core `git_hook.rs:159`, `:163` skip) and passing after. - AC-2 A worktree `block` over a landed `warn` shall block; evidence: a test. (serves EPC-022 AC-166)
- AC-3 An unreadable authority shall fail closed, as the path gate does (core `git_hook.rs:152-156`); evidence: a test with an unreadable authority object. (serves EPC-022 AC-166)
- AC-4 The `docs/policy-reference.md` rows for each field AC-6 records shall state the landed floor and that the worktree may only tighten it; evidence: the doc diff and `codeflow test --only docs-portal`.
- AC-5 (journey) On a scratch adopter with a planted content secret and a lowered worktree policy, a commit shall be refused at pre-commit; evidence: the journey output.
- AC-7 Each rule pre-commit, commit-msg, pre-merge-commit and pre-push apply shall be judged at no lower strength than the landed policy, each field moving only in its strict direction: a level shall not fall below the landed level; a list that adds a requirement (at least `git.protected_branches` and `git.commit_required_footers`) shall not lose a landed entry; a list that admits (at least `git.branch_prefixes` and `git.commit_ticket_keys`) shall not gain an entry the landed policy lacks. A checked-out file, whether stale, branch-edited or uncommitted, can therefore only tighten. An unreadable landed policy shall fail closed. Evidence: tests per hook that reads each field, each with a stale tree and with an uncommitted file, for a lowered level, a dropped protected branch, a dropped required footer, a dropped ticket key, an added branch prefix on pre-push and an added ticket key on commit-msg, failing before and passing after, and the AC-6 Findings extended to every field those hooks read from the policy file, each with its strict direction.
- AC-8 When `codeflow ci` chooses the range to judge, the landed `git.protected_branches` shall be the floor (a checked-out file may only add to it) and the landed `git.branch_prefixes` the ceiling (a checked-out file may only remove from it); an unreadable landed policy shall refuse the range choice; evidence: tests with a stale tree and with an uncommitted file that drop a protected branch and that add a branch prefix, and a test with the landed policy unreadable, failing before and passing after (`crates/codeflow-cli/src/cmd/ci.rs:418`, `:445` at 96a01e17e).
