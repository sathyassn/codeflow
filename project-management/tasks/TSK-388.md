# TSK-388: Remote branch names are shown without control characters

## Description

Source: TSK-305 review finding L-2 (2026-10-16). A default branch name supplied by the remote is printed raw, control bytes included (`crates/codeflow-core/src/workgraph/release_line.rs:232`). A hostile remote can write terminal escape sequences into a refusal an agent or person reads. Security, low.

Outcome: **every remote-supplied name CodeFlow prints is shown with control characters escaped.**

First added to EPC-023 (4.1.0) on 2026-10-18; moved to EPC-022 (3.2.0) the same day after the Codex review of PR 249, under the operator's rule that every security gap and every defect that forces an adopter workaround or blocks work belongs in 3.2.0.

## Deliverables

- the display escape: `crates/codeflow-core/src/workgraph/release_line.rs` and any other printer of remote-supplied ref names found by a search
- tests: unit tests
- release note: `changelog.d/TSK-388.md`

## Acceptance Criteria

- AC-1 When a remote's default branch name or another remote-supplied ref name holds control characters or escape sequences, every message that prints it shall show them escaped; evidence: unit tests per printer, failing before the change. (serves EPC-022 AC-85)
- AC-2 An ordinary name shall print unchanged; evidence: tests.
- AC-3 (journey) With the installed build, a push to a local bare remote whose `HEAD` symref names a branch with an escape sequence shall print the escaped form; evidence: the journey output.
