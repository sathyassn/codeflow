# TSK-402: A landed task reaches another line through a checked merge, and its landed branches can be cleaned up

## Description

Issue: #169, its defect portions. Two adopter workarounds:

- A carry of one landed, reviewed task change to another integration line has no checked route. A carry pull request fails `work.stable_planning_anchor` because the task's record lives on its home line (`crates/codeflow-cli/src/cmd/ci.rs:1466-1530`), so the adopter lands carries by a gated merge outside every check.
- The cleanup rule deletes a pushed branch only when its PR is `MERGED` and the tip equals the PR's recorded head (`assets/base/rules/worktrees.md:93-110`). A branch whose content landed by ancestry or as a patch-equivalent carry, with no merged PR, can never be deleted.

This task gives both a checked route that exists today. A carry is a merge of the task's reviewed head (or its home line) into the other line, which `codeflow integrate --no-ff` (TSK-293) can make; `codeflow ci` judges it by the source task's binding, which TSK-339 establishes for imported completions. A pushed branch may also be deleted when its tip is an ancestor of its destination line or `git cherry` shows no unapplied commit, with that proof recorded.

The one-commit carry class with byte comparison (TSK-318), and the remote branch inventory with compare-and-swap deletion (TSK-319), stay in EPC-023 (4.1.0); both now depend on this task.

Outcome: **an adopter can carry a landed task to another line through a pull request that `codeflow ci` checks and accepts, and can clean up a pushed branch whose content provably landed.**

Added by the EPC-022 amendment of 2026-10-18 after the Codex review of PR 249 (`target/review-PR249-codex-01.md`), under the operator's rule that every security gap and every defect that forces an adopter workaround or blocks work belongs in 3.2.0.

## Deliverables

## Acceptance Criteria

- AC-1 A pull request into line B whose range is only a merge of a task's reviewed head landed on line A (or of line A itself) shall be classified and accepted, judged by the source task's binding, while any added change in the range is judged as the receiving line's own; evidence: a CLI fixture in the shape of the issue's PR #123, failing before the change. (serves EPC-022 AC-90)
- AC-2 A merge carry that adds an unreviewed change, or names a task whose reviewed head it does not contain, shall be refused; evidence: negative fixtures.
- AC-3 The cleanup rule shall allow deleting a pushed branch whose tip is an ancestor of its destination line or whose commits `git cherry` shows as applied, with the proof recorded in the cleanup step, and shall list, never delete, a branch with neither proof; evidence: the rule text and, if a guard enforces the rule, guard tests.
- AC-4 (journey) With the installed build, a scratch adopter with two integration lines shall land a task on line A, carry it to line B through a merge pull request that `codeflow ci` accepts, and delete the carried branch under the ancestry proof; evidence: the journey output.
