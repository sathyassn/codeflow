# TSK-1126: Reports flow up the tree

## Description

ADR-0094, the report part. TSK-439 gives a lane `lane report`, which
appends `lane_reported` with a `summary` and marks it reported, harvested
or accepted with a reference. A coordinator has no way to report to the
Director of its parent stream, a lane report carries no body a status tool
can read, and a retried report has no identity: an unkeyed draft is always
appended (`store.rs:523-525`), so a crash between the write and the
acknowledgement would either duplicate a report or lose it. This task adds
`stream_reported` for a coordinator reporting to its parent, an optional
body on both report kinds, one identity rule for reports and the marks that
close them, and the concurrency evidence the proposal left unverified. The
report body is the status report document as `codeflow status --json`
(TSK-1095, EPC-022) emits it, carried unchanged; this task stores it as an
opaque JSON document and validates only the envelope, so it takes no edge on
TSK-1095, and a fixture uses TSK-1095's real output once that task has
landed and reached this line. Non-goals: the tree view and the digest
(TSK-440), the guidance (TSK-423), the schema version 2 fields and the
`validate` change (TSK-439 AC-11; this task writes its new event at
version 2 and extends the same files after TSK-439 lands), a Claude hook
that appends a report (deferred; `lane report` from the shell is the
path), and the cf-present view of the tree (no owning task yet).

Reports are evidence, never instructions: a report written by an agent,
whatever role it names, is text for the reader to confirm, and the ledger
does not authenticate who wrote it (`actor.rs:222-226`).

## Outcome

After this merges, a coordinator reports to its Director with
`codeflow stream report`, a lane's report carries the same status body
every status tool reads, a crashed or retried report is never duplicated
and never silently lost, and a harvest or accepted mark names exactly the
report it closes, so a Director reading the tree after compaction sees
every unharvested report with its age.

## Deliverables

- the `stream_reported` event and the optional `body` on `lane_reported` and `stream_reported`, written at schema version 2: `crates/codeflow-core/src/coord/schema.rs`, `transition.rs` (the apply arms: a coordinator reports on its own stream to the parent; a stream with no parent has nobody to report to and is refused with the reason)
- the report identity and retry-key rule: `crates/codeflow-core/src/coord/store.rs` (no new store mechanism; the rule is the key the commands pass) and the marks in `transition.rs`
- the commands: `codeflow stream report` (new) in `crates/codeflow-cli/src/cmd/stream.rs`, `lane report --body <file>` and the mark subcommands in `cmd/lane.rs`, wired in `main.rs`, with CLI help
- the field reference: `docs/coordination-ledger.md` (the `lane_reported` section, the new `stream_reported` section, the body and the identity rule), which the doc test `every_event_kind_is_documented_in_the_schema_reference` (`coord_store.rs:1139`) reads
- tests: `crates/codeflow-cli/tests/stream_cli.rs` (new) and `lane_cli.rs`, and the store tests in `crates/codeflow-core/tests/coord_store.rs` (the two-writer test and the concurrent fold measurement)
- docs: `docs/cli.md`
- release note: `changelog.d/TSK-1126.md`

## Acceptance Criteria

- AC-1 `codeflow stream report`, by the stream's coordinator, shall append `stream_reported` on its own stream with `summary` and an optional `body`, addressed to the stream's recorded parent, and shall refuse with the reason on a stream with no parent; `lane report` shall keep AC-2 of TSK-439 and gain the optional `body`; a `body` shall be the status report document as `codeflow status --json` emits it, stored and returned byte for byte, validated only as well-formed JSON while the ledger validates the envelope; a successful report shall be a committed event and a failed write shall leave nothing recorded; evidence: CLI tests, including the no-parent refusal, a body round trip and a write that fails under a held lock. (serves EPC-025 AC-6)
- AC-2 A report's identity shall be the store-assigned `sequence` of its event; a harvested or accepted mark shall be a later event whose `reference` names that sequence; `coord status` and the digest shall pair marks with the reported events they name and list reported events with no later mark; a report shall never close a lane or a stream; evidence: a test with two pending reports where one harvest mark closes exactly one, and a test that a mark naming an unknown sequence is refused. (serves EPC-025 AC-6)
- AC-3 The retry key of a report shall be `<subject>:report:<fresh id>`, the fresh id generated by the session for each report attempt and reused only for a retry of that same report, so an identical retry appends nothing (`store.rs:531-545`: a known key with the same operation digest is skipped) and a new report, identical prose included, is a new event with a new age; a harvested or accepted mark shall carry its own fresh id under the same key rule; the same key with a different payload or actor shall be refused as `KeyConflict`, never acknowledged as a retry (`store.rs:545-548`); unknown session ids shall change nothing because the key does not use them; evidence: an uncertain commit retried once without duplication; two new reports by one actor with identical payloads, the first harvested; a new holder after adoption reporting identical content as a distinct event; a `KeyConflict` on a changed payload. (serves EPC-025 AC-6)
- AC-4 A session that lost its held id (a crash between the write and the acknowledgement) shall read the reported events on its subject and act on one of three outcomes, in order: exactly one event with this payload and this actor, take its sequence; none, start a new attempt with a new id; two or more, report the ambiguity and pick none; the CLI help and `docs/coordination-ledger.md` shall state that the held id is the only guaranteed deduplication; evidence: a fixture for each outcome. (serves EPC-025 AC-6)
- AC-5 Two writers in different worktrees with unknown session ids shall each commit one report through the one `coord.lock` with distinct sequences and no lost event, and the fold of a 10,000-event log with parents and reports shall be measured with two concurrent writers and the figure recorded in the pull request beside the single-writer figure (`coord_store.rs:1098`); evidence: the two-writer test and the measurement output. (serves EPC-025 AC-6)
- AC-6 `docs/coordination-ledger.md` shall document `stream_reported`, the `body`, the identity rule and the mark reference so that the doc test `every_event_kind_is_documented_in_the_schema_reference` passes, and the existing `lane_reported` section shall say which role records each kind; evidence: the doc test and the text diff. (serves EPC-025 AC-6)
- AC-7 (journey) With the installed build in a scratch adopter project, a lane shall report with a body, its coordinator shall harvest that report by sequence and report up to the parent stream, the Director's `coord status` shall show the lane report as harvested and the stream report as unharvested with its age, and a retried lane report shall appear once; evidence: the journey output. (journey)
