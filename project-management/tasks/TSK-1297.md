# TSK-1297: Coordination check and heartbeat timing are project settings

## Description

The coordination check interval (`CHECK_INTERVAL_SECS`, 600 s, `crates/codeflow-core/src/coord/mod.rs:96`) and the heartbeat timeout (`HEARTBEAT_TIMEOUT_SECS`, 1800 s, `:99`) are fixed in code. Neither is a security or safety limit, so under the operator's rule of 2026-11-03 both become project settings with the current values as defaults and documented bounds.

## Outcome

After this merges, a project maintainer can set how often coordination checks run and when a heartbeat counts as overdue.

## Deliverables

- the keys `coord.check_interval_seconds` and `coord.heartbeat_timeout_seconds` (names settled by the policy key placement rule): `crates/codeflow-core/src/hooks/policy_schema.rs`, `crates/codeflow-core/src/coord/`
- docs: `docs/policy-reference.md` and the limits page of TSK-1299
- release note: `changelog.d/TSK-1297.md`

## Acceptance Criteria

- AC-1 `coord.check_interval_seconds` (default 600) and `coord.heartbeat_timeout_seconds` (default 1800) shall be declared in the limits registry (TSK-1299) as operational limits, with bounds only what correctness needs, and read from the project's policy through it, and an absent key shall keep the default; evidence: tests for each key, set and absent.
- AC-2 A value out of bounds or of the wrong type shall refuse, naming the key and its bounds; it shall never wrap or panic; evidence: one test per case.
- AC-3 Both keys shall appear in `docs/policy-reference.md` and on the limits page with default and bounds; evidence: the doc diff and `codeflow validate --docs`.
- AC-4 A changelog entry shall name the keys; evidence: `changelog.d/TSK-1297.md`.

## Execution contract

- Release: 4.0.0, in EPC-028. Edges: after TSK-1299 (the registry these keys are declared in).

Reason: the operator wants configurable limits now, and the release-scope rule puts every feature in the current release; the registry's first consumer, TSK-1301, is in stream 1 with EPC-028.
