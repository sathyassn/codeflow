# TSK-1430: The EPC-026 line carries the SQLite advisory fix

## Description

RUSTSEC-2026-0459 (`libsqlite3-sys` 0.35.0, fixed in 0.39.0) turns codeflow-ci's "security review" red on every pull request into the EPC-026 line (PR 763: run 42961215828, job 130327937799). The `admit` step needs the whole run green (`scripts/ci-reuse.py:495-497` at 6dd6d4c5a), so nothing lands on the line, TSK-1428's pull request included. TSK-1407 fixed the advisory on the EPC-022 line, and TSK-1412 mirrored it onto `main` as 464103b94 (`rusqlite` 0.37 to 0.41, which brings `libsqlite3-sys` 0.39.1). The line would get it through the TSK-1371 sync, but that sync needs TSK-1428 landed first. This task breaks that loop by mirroring 464103b94's dependency change onto the line.

The line's `Cargo.lock` is byte-identical to `main`'s at 464103b94's parent 7e23d7ca2 (an empty `git diff` between them). So after the change the line's lock can be byte-identical to 464103b94's, and the sync later finds these files already equal. The line's `Cargo.toml` differs from 7e23d7ca2's only in its `windows-sys` feature list, which stays as the line has it.

Non-goals: any source change, a second changelog fragment, any audit suppression, and copying TSK-1407's or TSK-1412's records. Its own record rides in its own pull request, because a records-only filing into the line fails the same audit and cannot land first.
