# TSK-1437: A marked epic's line reaches the default branch only when the epic is complete

## Description

Under ADR-0102 a marked epic reaches the default branch once, complete. Today nothing gates a line's pull request into the default branch on the epic's state: the line binding accepts any epic that is not cancelled or archived (`crates/codeflow-core/src/workgraph/work_start.rs:699-724` and `:1279` on `main` at `f8aabc62c`). This task adds the marker to the epic record and a gate in `codeflow ci` that passes a marked epic's line pull request only when the epic is complete, with its proof and whole-epic review on a commit that holds the default branch's tip. An epic without the marker keeps checkpoint pull requests until it closes: those epics, EPC-022 among them, are already in flight, and holding their finished work until a large epic closes would park it on a line.

How the marker is enforced:

- The marker is a field on the epic record, proposed as `main_landing` with the values `whole-epic` and `checkpoint-prs`; an absent field means `checkpoint-prs`, so every epic planned before the release is unmarked. The builder settles the final name and values. The epic template documents it and `codeflow epic new` can write it; TSK-1443 sets `whole-epic` as the default for new epics after the release.
- `codeflow ci` reads it only from the epic record at the default branch's tip, resolved once per run (the authority rule of ADR-0091), never from the line, the pull request head or the working tree.
- It is set or cleared only by a planning range into the default branch. A range into any other branch that adds, removes or changes it is refused.
- The planning anchor for a marked epic's criteria is the same default-branch copy, so a line cannot reword its own epic's criteria.

Landing on its target (EPC-055's line, then `main` with the epic):

- Reachable on the line: the marker and the gate.
- Inert: every existing epic is unmarked, so it lands checkpoints as today.
- Other lines: nothing; only epics planned after the release carry the marker.

Target: this record targets `main` until EPC-055's line is cut, after the guard fixes now in flight and PR 620 are on `main`, with TSK-1433 and TSK-1436; it is then retargeted to that line.

Waits for TSK-1158's and TSK-1061's work on `main`: their records are on `main`, their work is on the EPC-022 line.

## Outcome

After this merges, a maintainer can mark an epic so that its line reaches the default branch only when every task is complete and its proof and review hold the default branch's tip, while unmarked epics keep their checkpoint pull requests.

## Acceptance Criteria

- AC-1 Before any change, the builder shall record whether epic criteria are frozen after planning as task criteria are (`acceptance.rs:4891-4906` on `main` at `f8aabc62c`), and close the gap if they are not; evidence: a `## Findings` section and a fixture.
- AC-2 For a marked epic, `codeflow ci` shall refuse the line's pull request into the default branch while any task of the epic is todo or blocked, computed from the records; evidence: a one-open-task fixture (issue 770's done-when).
- AC-3 For a marked epic, the line's pull request shall be refused when the epic's criteria differ from the default branch's copy without a recorded amendment; evidence: a fixture (issue 770's done-when).
- AC-4 For a marked epic, the line's pull request shall be refused unless the proof commit contains the default branch's tip and the whole-epic review names that commit, with only the completion record after it; evidence: fixtures for a stale proof and for a later commit.
- AC-5 For a marked epic, the line's pull request shall be refused unless every removed criterion, moved task and cancellation has a reviewed disposition in TSK-1158's waiver form; evidence: fixtures.
- AC-6 A complete marked epic's line pull request shall pass; evidence: a fixture.
- AC-7 An unmarked epic's checkpoint pull request shall be judged exactly as today; evidence: a fixture that passes before and after the change.
- AC-8 Each planted negative shall be refused naming its cause: a line that sets the marker on its own epic record; a line that removes the marker; a pull request head whose epic copy carries the marker while the default branch's copy does not, which is judged unmarked and the head's change refused; and a default-branch copy that cannot be read, which is refused and never judged unmarked; evidence: one fixture each.
- AC-9 A task that lands alone into `main` shall be judged as today; evidence: a fixture.
- AC-10 The change shall have a cross-lineage review with the `cf-security-reviewer` checklist, with the threat each marker rule closes stated in the pull request; evidence: the review row and its findings. (serves EPC-055 AC-3)
