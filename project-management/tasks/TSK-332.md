# TSK-332: A docs portal workflow lease whose owner has exited is reclaimed at once

## Description

The docs portal's `check`, `build`, `dev` and `preview` scripts hold one
workflow lease, `.portal/workflow.lock`
(`docs-portal/scripts/publication.mjs:19`, `withWorkflowLease`). The lease
records only a token and two times (`publication.mjs:34`). A contender
treats it as live while its heartbeat is younger than
`WORKFLOW_LEASE_MAX_AGE_MS`, four hours (`publication.mjs:16`, `:50`),
although the owner writes a heartbeat every 30 seconds (`publication.mjs:66`
to `:73`). So a portal run that is killed (a timed-out gate target, a
closed terminal, `kill -9`) leaves a lease that refuses every `check` and
`build` with "portal build/check workflow already in progress" for up to
four hours, and nothing checks whether its owner still runs. The same file
ships to adopters as `assets/docs-portal/starter/scripts/publication.mjs`,
byte-identical today.

The outcome is that a lease whose owner process has exited is reclaimed at
once, with a message naming the dead owner, while a live owner still
blocks. The lease records its owner (process id and host, plus whatever
the builder needs against process id reuse, such as a process start time),
and a contender on the same host checks that owner before applying the age
rule. Where liveness cannot be decided (another host, a lease written by an
older version without an owner, a permission error on the check), the
four-hour rule stays. A reused process id reads as live, which blocks; that
is the safe direction.

Non-goals: the publication lease (`PUBLICATION_LEASE_MAX_AGE_MS`,
`publication.mjs:15`) and changing the four-hour age for leases whose owner
cannot be checked.

## Acceptance Criteria

- AC-1 A workflow lease shall record its owner's process id and host, and
  any marker the builder adds against process id reuse, in the existing
  lease file, with older leases still read; evidence: a unit test of the
  written lease and of reading a lease without the new fields.
  (serves EPC-022 AC-29)
- AC-2 When the lease's owner on this host has exited, the next `check` or
  `build` shall reclaim the lease at once and print one line naming the
  dead owner and the lease age; evidence: a test whose child process takes
  the lease and is killed with `SIGKILL`, after which a new workflow
  acquires the lease within one attempt. (serves EPC-022 AC-29)
- AC-3 While the lease's owner is alive, a second workflow shall still
  refuse with "portal build/check workflow already in progress", now naming
  the owner's process id; evidence: a test with a live owner.
  (serves EPC-022 AC-29)
- AC-4 When liveness cannot be decided (a lease from another host, a lease
  with no owner fields, or a check that fails with a permission error), the
  contender shall keep the four-hour age rule; evidence: a test per case.
- AC-5 Two contenders that find the same dead owner shall leave exactly one
  holder, and the existing lease and recovery tests shall pass unchanged;
  evidence: a race test in the style of the existing reclaim tests, and the
  `docs-portal` gate target.
- AC-6 The repository copy and the starter copy of `publication.mjs`, and
  of `adapter.test.mjs`, shall stay byte-identical; evidence: a byte comparison in the change's test
  run, and the starter manifest test in
  `crates/codeflow-core/tests/manifest_consistency.rs` passing.
- AC-7 (journey) A real `npm run build` in `docs-portal/` killed with
  `SIGKILL` mid-run shall be followed by a second `npm run build` that
  starts at once and prints the reclaim line, and the same in a scratch
  adopter portal made from the starter; evidence: both runs' output.
