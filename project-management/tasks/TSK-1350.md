# TSK-1350: A landing merge carries its ticket footer when the project requires one

## Description

Issue #601. A project that sets `git.commit_ticket_required: "block"` expects every commit to carry its ticket footer, but merge commits are exempt in both places that judge commits. The commit-msg hook returns before any check for a real merge whose subject starts with `Merge ` (`crates/codeflow-core/src/hooks/git_hook.rs:577-579` at a5cd83c69), and `codeflow ci` runs only the policy-characters check on a commit with more than one parent (`evaluate_commits`, `crates/codeflow-cli/src/cmd/ci.rs:2185`). In a project that lands each task onto a line as a no-ff merge, the merge commit is the record of the landing, so a landing without its `Refs:` footer passes the hook and line CI, and the adopter checks every landing merge by hand.

The issue asks for an opt-in setting. Git's default merge subject (`Merge branch ...`) stays exempt unless the project opts in. Non-goal: changing this repository's own policy, which is a policy change taken separately.

## Outcome

After this merges, a project that opts in gets every landing merge judged for its ticket footer by the commit-msg hook and by `codeflow ci`, with no hand check.

## Deliverables

- the policy key and its schema: `crates/codeflow-core/src/hooks/policy_schema.rs`, `.codeflow/policy.json` schema and the shipped default policy
- the hook check: `crates/codeflow-core/src/hooks/git_hook.rs`
- the ci check: `crates/codeflow-cli/src/cmd/ci.rs`
- the docs: `docs/policy-reference.md`
- release note: `changelog.d/TSK-1350.md`

## Acceptance Criteria

- AC-1 A policy key (`git.commit_ticket_merges`, provisional name; the builder settles it with the policy naming rules) with the levels the other git rules use, default off, shall apply the ticket rule of `git.commit_ticket_required` and `git.commit_ticket_keys` to merge commits; with it off, behaviour shall be unchanged; evidence: schema tests and a default-off test.
- AC-2 With the key on, the commit-msg hook shall judge a real merge (`MERGE_HEAD` present) for its ticket footer, whether the subject is git's default or the author's own; evidence: hook tests for a merge with and without the footer, each subject form, failing before and passing after.
- AC-3 With the key on, `codeflow ci` shall judge each commit with more than one parent in the range for its ticket footer, so a merge made outside the local hooks (a hosting service's merge button or API) is caught on the line push; evidence: ci tests for a two-parent commit with and without the footer, failing before and passing after.
- AC-4 The refusal shall name the merge commit, the rule and the footer keys that satisfy it; evidence: a CLI test of the text.
- AC-5 (journey) With the installed build in a scratch adopter project that opts in, a `--no-ff` landing merge without its footer shall be refused by the hook, and the same merge made by a hosting-service route shall be refused by `codeflow ci` on the line push; evidence: the journey output.
