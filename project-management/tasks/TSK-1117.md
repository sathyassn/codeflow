# TSK-1117: The register holds across a line's merge of main and on the merged tree

## Description

Issue #275's comment of 2026-10-29, lessons 3 and 6: two clean removals in
parallel pull requests can combine into a broken register, so the check
must run on the merged tree; and an integration line needs an adoption rule
when it merges `main`, or lines either cannot merge `main` or import
unchecked code. TSK-424 admits debt by stable occurrence identity at the
default-branch authority and shrinks it against the previously admitted
baseline; it judges one range at a time and has no rule for a line's merge
of `main`. This task adds both: `codeflow ci` and the hosted job judge the
register on the pull request's merge tree, and when a line merges `main`
new debt is allowed only for files that differ from that `main` commit,
recomputed from the line's previous tip, each entry naming the open task
that owns its fix, while anything the merge itself adds fails. Non-goal:
the boundary mode (TSK-1116).

## Outcome

After this merges, two parallel pull requests that are each clean cannot leave the register broken when both land, and an integration line can merge main without importing unchecked debt.

## Deliverables

- the merged-tree judgment: `crates/codeflow-cli/src/cmd/ci.rs` (the register check runs on the merge commit) and the hosted job step in `assets/base/ci/codeflow-policy.yml`
- the line-merge adoption rule: `crates/codeflow-core/src/exemptions/` (TSK-424's module), its report lines
- docs: `docs/policy-reference.md` (the register's merge rules), `.codeflow/rules/git-rules.md` "Bodies of work" (one sentence on syncing a line under the register)
- tests: two parallel removals (each clean, merged tree broken, refused), a line merge of `main` with a differing file (allowed with a fix task), an unchanged file (refused), debt the merge itself adds (refused)

## Acceptance Criteria

- AC-1 Before any change, the builder shall research register integrity across merges broadly: how baseline and suppression systems behave under parallel removals and merges (detekt and PHPStan baselines, Betterer, ESLint bulk suppressions), what GitHub exposes for a pull request's merge commit and when it is absent, how this repository's lines merge `main` today (TSK-421, TSK-1066, TSK-1089), TSK-424's identity and authority rules, and adjacent concerns (a rebase instead of a merge, a squash landing, a line that merges another line, a conflicting merge with no merge ref); and shall record the findings with sources and the chosen scope before anything else changes; evidence: the Findings section, committed before the first code change in the PR. Listed first because it runs first (the operator's rule of 2026-10-27).
- AC-2 `codeflow ci` and the hosted job shall judge the register on the pull request's merge tree (the merge commit of head into base), so two clean removals in parallel pull requests that combine into a broken register are refused on the second; when no merge commit exists the check shall fail closed naming the conflict; evidence: the two-removal fixture and the no-merge-ref fixture. (serves EPC-024 AC-21)
- AC-3 When a line merges `main`, new debt shall be allowed only for files that differ from that `main` commit, recomputed from the line's previous tip, each entry naming an open fix task; debt on an unchanged file and anything the merge itself introduces shall fail; evidence: one fixture per case. (serves EPC-024 AC-21)
- AC-4 The report shall name the tree judged (merge commit, base, head) and, for a line sync, the `main` commit and the previous tip; evidence: the report test.
- AC-5 `docs/policy-reference.md` and `git-rules.md` shall state both rules; evidence: the doc diff and `codeflow validate --docs`.
- AC-6 (journey) With the installed build in a scratch adopter, two pull requests each removing one register entry shall pass alone, the second shall fail once the first lands, and a line merging `main` with one changed file carrying new debt shall pass with the fix task named; evidence: the journey output.
