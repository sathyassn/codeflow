# TSK-1127: The shipped report specimens and portal layer samples conform to the approved shell and topic contracts

## Description

TSK-1097 AC-19 authors and ships the sample set the operator asked for on
2026-10-31 (the coordinator's handoff, section 5, 18:5x: proper samples to
review of the status report and its variants, of `cf-present` and of the
docs portal, and samples of everything): one present specimen per report
type, all ten (status report, epic close, security review, weekly
workspace digest, design review, feature, hand-off, incident, research or
decision, small project), and one sample page per portal layer (overview,
area, reference). TSK-1097 can prove them only on the surface that exists
when it lands: linear documents from the catalog, the bar's items (a) to
(i) and the token system. The bar's item (j) binds a recurring kind to
TSK-1120's layout contract and view-kind registry and to TSK-1121's
`topic` and stable ids, and the portal samples to TSK-1114's frame; all
three land after TSK-1097 (TSK-1120 and TSK-446 depend on it). This task
takes the same ten files and three pages once those contracts exist,
revises them to the approved shell (TSK-1122's `DESIGN_INTENT`, reached
through TSK-1120) and the topic contract, and produces the capture set the
operator reviews. It changes no runtime and no skill text; a gap it finds
in a contract is a finding for that contract's task.

```text
  TSK-1097: author ten specimens + three portal pages, current surface
      |                                  TSK-1122 approves the design
      |                                        |
      |                           TSK-1120 shell, registry
      |                                        |
      |                           TSK-1121 topic, stable ids     TSK-1114 portal frame
      |                                        |                        |
      v                                        v                        v
  TSK-1127: the same files conform to the approved shell, topic and frame;
            captures in every theme and mode; the operator reviews the set
```

Figure: the samples are written once, early, and bound to the final
contracts once, late; nothing is written twice.

Decisions, each reversible and disclosed here:

- Which kinds are recurring: the status report, weekly workspace digest,
  epic close and design review carry a `topic` and a registry kind; the
  security review, feature, hand-off, incident, research or decision and
  small project reports are linear documents unless the registry of
  TSK-1120 names a kind for them, in which case they take it. The builder
  records the final list in AC-1.
- The captures live with this task, under
  `project-management/design/TSK-1127/captures/`, with an index page, so
  the operator reviews one set at the final state; TSK-1097's own captures
  are its builder evidence for the earlier surface.
- The operator's review of the index page is the audience, never the
  acceptance: AC-4's acceptance is the checks, the gate and the
  other-lineage reviewer's read against the whole bar.

Non-goals: new specimens or new report types (TSK-1097, or an amendment);
the shell (TSK-1120), the topic (TSK-1121), the portal frame (TSK-1114);
the status report the runtime generates from live facts (TSK-1098).

## Outcome

After this merges, the operator and any adopter can open one index of the
ten report specimens and three portal layer samples, each rendered in
every theme and mode at desktop and phone width, and see the shipped
samples conforming to the approved shell, topic and portal contracts.
