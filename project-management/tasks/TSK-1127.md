# TSK-1127: The shipped report specimens and portal layer samples conform to the approved shell and topic contracts

## Description

The operator asked on 2026-10-31 (the coordinator's handoff, section 5,
18:5x) for proper samples to review of the status report and its variants,
of `cf-present` and of the docs portal, and samples of everything: one
present specimen per report type, all ten (status report, epic close,
security review, weekly workspace digest, design review, feature, hand-off,
incident, research or decision, small project), and one sample page per
portal layer (overview, area, reference). The set was first planned in
TSK-1097 (AC-19) on the surface that existed then, to be revised here once
the shell, topic and portal frame landed, which meant writing every file
twice. On 2026-11-01 the operator approved moving the whole set here, so
the thirteen files are authored once, on the approved contracts, and
TSK-1097 no longer waits for them. TSK-1097's AC-19 now points to this
record.

The bar's item (j) binds a recurring kind to TSK-1120's layout contract and
view-kind registry and to TSK-1121's `topic` and stable ids, and the portal
samples to TSK-1114's frame. This task starts after TSK-1097 (the bar, the
kit, the token system and the checks), TSK-1121 (the topic contract, with
TSK-1120's shell and TSK-1122's approved `DESIGN_INTENT` behind it) and
TSK-1114 have landed. It authors the ten specimens and three pages on those
contracts and produces the capture set the operator reviews. It changes no
runtime and no skill text; a gap it finds in a contract is a finding for that
contract's task.

```text

      |                                              |
```

Figure: the samples are written once, after the contracts they must follow,
so nothing is written twice and the path to TSK-1120 no longer carries them.

Decisions, each reversible and disclosed here:

- Which kinds are recurring: the status report, weekly workspace digest,
  epic close and design review carry a `topic` and a registry kind; the
  security review, feature, hand-off, incident, research or decision and
  small project reports are linear documents unless the registry of
  TSK-1120 names a kind for them, in which case they take it. The builder
  records the final list in AC-1.
- The ten types are a reversible choice taken from the design reference
  `dashboard-v2` (a session scratchpad of 2026-10-31, not committed;
  TSK-1122 commits the approved prototype). A type the operator drops is
  removed from the records in one amendment.
- Homes: the present specimens under `cf-present/resources/specimens/`,
  mirrored across the three skill homes; the portal layer samples under
  `assets/docs-portal/starter/samples/`, built by the starter's tests, since
  a fresh `codeflow init --standard` project has only the three scaffolded
  docs pages and the starter is the only home every adopter receives. This
  repository's portal stays the live example of the layers (TSK-446 AC-10).
- Each specimen is a real document to the bar, built on realistic facts that
  say they are a sample in the header, never a stub that only declares a
  main figure.
- The captures live with this task, under
  `project-management/design/TSK-1127/captures/`, with an index page, so
  the operator reviews one set at the final state.
- The operator's review of the index page is the audience, never the
  acceptance: AC-4's acceptance is the checks, the gate and the
  other-lineage reviewer's read against the whole bar.

Non-goals: new report types beyond the ten (an amendment); the shell
(TSK-1120), the topic (TSK-1121), the portal frame (TSK-1114); the bar and
the checks (TSK-1097); the status report the runtime generates from live
facts (TSK-1098).

ten report specimens and three portal layer samples, authored on the approved
contracts, each rendered in
every theme and mode at desktop and phone width, and see the shipped
