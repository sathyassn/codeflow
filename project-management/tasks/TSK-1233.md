# TSK-1233: A daily exact-SHA Windows run covers each active integration line

## Description

Source: the CI throughput study of 2026-11-02 (`coordination/coordinators/parallel/throughput/`: RECOMMENDATIONS.md, FINDINGS.md, CHECK-codex.md, CHECK-fable.md), cross-checked by Codex GPT-6 Astra and Claude Fable 5.1, and the operator's priority on CI throughput.

The Windows schedule runs weekly and covers `main` only (`.github/workflows/codeflow-ci.yml:22`). The twelve Windows test partitions run on every pull request (`:717`) and cost about 2 x 330 weighted minutes per pull request. They can move to pull requests into `main` only once a scheduled run covers the integration lines daily and reports the exact SHA it tested, because a daily result cannot prove that a newer tip passed (Codex check, finding 2).

Integration pull requests keep Windows clippy, doc and Node (`:744`, `:751`, `:760`, `:770`), the Python release journey (`:777`) and a chosen set of runtime journeys. The verdict job (`:849-870`) must accept that tier's skips.

Blocked on operator decision 3 of the study, choice (b): move the partitions to pull requests into main plus a daily line run, accepting that Windows runtime breaks surface later on integration lines. Non-goals: the Linux split (TSK-1232).

## Outcome

After this merges and the operator's decision is recorded, each active integration line gets a daily Windows run that names the SHA it tested, and integration pull requests no longer run the twelve Windows test partitions.

## Deliverables

- the schedule, the line dispatch and the SHA report: `.github/workflows/codeflow-ci.yml`
- the verdict job's tier skip set: the same workflow
- tests for the line selection and the report: the scripts the workflow calls

## Acceptance Criteria

- AC-1 Before any change, the builder shall record the active integration lines and how the daily run finds them, the weighted minutes of the Windows partitions per pull request and per scheduled run, and which runtime journeys integration pull requests keep, with the reason for each kept and each moved; evidence: a `## Findings` section, committed before the first code change.
- AC-2 A scheduled Windows run shall run daily for each active integration line and for `main`, and each run shall report the SHA it tested in its summary and verdict; evidence: the workflow diff and the links of one run per line.
- AC-3 Pull requests into an integration line shall keep Windows clippy, doc and Node, the release journey and the chosen runtime journeys, and the twelve test partitions shall run on pull requests into `main` only; this switch shall land after the first daily run on the line has passed; evidence: the workflow diff and one hosted run of each tier. (serves EPC-022 AC-232)
- AC-4 The verdict job shall accept exactly the integration tier's declared skips and refuse any other skip, and a daily result shall never be shown as proof of a SHA other than the one it reports; evidence: tests for an allowed skip, a refused skip and a result for an older SHA.
- AC-5 A pull request into an integration line shall pass with the partitions skipped by tier, and the next daily run on that line shall report the SHA it tested; evidence: the links of the pull request run and the daily run. (journey)
