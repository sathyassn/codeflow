# TSK-143: spec and decision wording matches shipped behaviour

## Description

ADR-0072's acceptance note says the enforcing registry check takes its
workflow from the target branch. GitHub runs a `pull_request_target`
workflow from the default branch, whatever the pull request targets, and
TSK-107 (review round 2, R2-1) made the enforcing jobs check out the pull
request's base commit so the target's pin and policy still judge it. The
shipped CI comments, `docs/architecture.md`, `docs/adoption.md` and the CI
README already say so. SPC-013 R-109 carried the same outdated sentence
and is corrected by the planning change that files this task, as is
SPC-002's `delegate init` form, which lacked the `--model` and `--effort`
options TSK-136 added. ADR-0072 is accepted and append-only, so its
correction is a dated amendment.

## Affected surfaces and interfaces

- `docs/decisions/ADR-0072-shared-id-registry.md` (a dated amendment
  after the accepted text).
- Shared files, per SPC-013 R-118: ADR-0072 (owner TSK-101), append-only.
