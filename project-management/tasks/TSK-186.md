# TSK-186: Count both new policy keys after the batch 2 landings

## Description

Three defects stop the EPC-020 line after the batch 2 landings.
TSK-170 added `git.conflict_markers` and TSK-145 added
`git.release_branch_pattern` to the policy key schema; each branch raised
the `SCHEMA` array length from 60 to 61 on its own, so the array now holds
62 entries but declares 61 and the workspace does not compile. TSK-170 also
starts git with `Command::new("git")` in five places, which the git spawn
contract from TSK-141 refuses: every git codeflow starts must be built by
`codeflow_core::git::command()` so its hooks run the calling binary. TSK-170
added `git.conflict_markers` to the shipped `policy.json` without resyncing
CodeFlow's own install, so `repository_update_noop` fails. The change sets
the length to 62, moves the five spawns to the one constructor, keeping
their arguments, stdio, environment and behavior, and resyncs the install
with `codeflow update`.

Non-goal: changing either key's meaning, default or validation, or what the
conflict-marker check judges.

## Affected surfaces and interfaces

- `crates/codeflow-core/src/hooks/policy_schema.rs` (the `SCHEMA` length).
- `crates/codeflow-core/src/hooks/conflict_markers.rs` and
  `crates/codeflow-cli/src/cmd/ci/conflict_markers.rs` (how git is started).
- `.codeflow/.baseline/.codeflow/policy.json` and `.codeflow/manifest.json`
  (the resync `codeflow update` writes).
