# TSK-1529: The hook tests build their fixture keys at run time

## Description

The commit-msg secret scan refused TSK-291's merge of the EPC-022 line: `possible secret (AWS access key id) staged at crates/codeflow-cli/tests/hooks_cli.rs:4154` (workspace `coordination/scripts/operator/merge-line-into-stalled-2026-11-17-run.txt:2738`). That line is a test fixture. `pre_commit_blocks_secret_and_protected_branch` (`hooks_cli.rs:4151-4167` at line tip 9168e8fe7d) writes a key shaped like the AWS documentation example, as one string literal, to `leak.txt` in a tempdir and checks that the pre-commit hook refuses it.

The same literal sits at `hooks_cli.rs:2728` on TSK-291's head ff5f6e487b. The line moved it to a new place in the file, so the merge's first-parent diff shows it as added, and the built-in pattern `\bAKIA[0-9A-Z]{16}\b` (`crates/codeflow-core/src/hooks/scan.rs:32-33`) matches it. The Director ruled on 2026-11-17 to fix the fixture rather than exempt it, and to add one sentence to the policy docs saying when a moved line counts as added.

Other fixtures in the same file already build the key at run time and do not trip the scan: `hooks_cli.rs:5552`, `:6129`, `:8606` and `:12167` at the line tip use `format!` over two parts. This task brings the remaining literal to the same form.

## Outcome

After this merges, a merge that moves or touches the hook integration-test fixtures passes the commit-msg secret scan with no exemption, the tests still prove the hooks refuse an AWS-shaped key, and the policy docs say that a moved line can count as added.

## Deliverables

- the fixture at `hooks_cli.rs:4154` building its key at run time, with its assertion checking the full refusal message: `crates/codeflow-cli/tests/hooks_cli.rs`
- the same treatment for every key-shaped literal the sweep finds in the listed test files
- one sentence in the hand-written "Which commits" bullet of `docs/policy-reference.md` (`:1028-1034` at the line tip), not in the generated `git.secret_scan` row at `:82`, which `codeflow validate --docs` checks against the binary
- the sweep (file list, commands and results, at the first head and the final head) and the diff check in the pull request

## Estimate

- Grade: Small; band: Small (under 2 h); moved: none
- Split: not needed; one outcome (no integration-test fixture holds a literal the built-in scanner flags)
- Basis: one fixture change with an existing in-file pattern to copy, a sweep over listed test files, one docs sentence and a diff check; drafted by coord/planning, not yet graded.
