# TSK-1182: A new branch cut from an integration line tip is judged by that line's class

## Description

Issue 506. A new non-task branch cut from an integration line tip is judged as if it wrote that line's history. `range_base` (`crates/codeflow-cli/src/cmd/push_set.rs:1403`) falls back to `bounded_by` (`:1678`), and `target_base` (`:1488`) and `own_line_tip` (`:1778`) follow. A candidate branch that syncs another line, or merges `main`, is blocked for criteria changes it did not make, and the block text tells the user to complete tasks the branch never touched.

This task binds such a branch to the integration line it was cut from, by fetched remote tips and exact SHAs, and applies that line's class. A real foreign criteria change inside the range is still blocked.

Security task. It decides which policy and class judge a push, so it touches hook authority and CI admission. It carries a cross-lineage Codex review with the `cf-security-reviewer` checklist as its attacker lens, the seat probed live at dispatch, and the PR states the threat each fix closes and why the design is the standard one.

Coordination: TSK-1154, TSK-1155 and TSK-1151 (PR 486) work in the same classification region. TSK-1155 lands first and this task depends on it. Add a TSK-1089 edge if its line-binding rule is reused.

Non-goals: changing how a task branch is classified, or weakening the block for a foreign criteria change.

## Outcome

after this merges, a person can push a new branch cut from an integration line tip, including one that syncs another line or merges `main`, and is judged by that line's class and only for the changes it made, while a branch with no unique nearest line is refused with the cause named.

## Deliverables

- the base and class selection: `crates/codeflow-cli/src/cmd/push_set.rs` (`range_base`, `bounded_by`, `target_base`, `own_line_tip`)
- tests: the issue's two repros as fixtures in `crates/codeflow-cli/tests/` and unit tests beside the selection
- the block text: no advice to complete tasks the branch did not touch
- docs: a dated note where the push classification is described
- release note: `changelog.d/TSK-1182.md`

## Acceptance Criteria

- AC-1 (journey) The issue's two repros (a candidate branch that syncs another line, and one that merges `main`) shall each be blocked before the change and push clean after it, and a real foreign criteria change inside the range shall still be blocked; evidence: three fixtures, the first two failing before and passing after, the third green before and after. (serves EPC-022 AC-47)
- AC-2 For a new branch with no task id, the base shall be the nearest fetched `refs/remotes/<dest>/integration/**` tip on the head's first-parent chain, and that line's class shall apply; evidence: a fixture with two lines where the nearer one is chosen.
- AC-3 The binding shall use fetched remote tips and exact SHAs, never the branch name; with no such ancestor, or with two or more ties, the push shall be refused with the cause named, failing closed; evidence: fixtures for a branch named like a line but cut from another, no ancestor, and a tie.
- AC-5 The selected line tip shall be authoritative, not merely nearest: the line is bound by `epic_line_binding` read at the trusted tip the destination advertises for that exact ref, resolved once at the start of the run (the remote-tracking ref as fetched for a local run), never a local branch, a requester-supplied anchor or a commit the head names, as TSK-1155 specifies (`TSK-1155.md:66-79`) and TSK-1089 does; a stale, fabricated, unfetched or unreadable tip shall refuse with the cause named, and the default branch stays the sole policy authority (ADR-0091); evidence: negative fixtures for a nearer fabricated tracking ref placed after a foreign criteria edit (the edit must still be found), a stale tip, an unfetched ref and an unreadable ref, and a sync merge that contains a foreign edit (still blocked), each beside clean sync and `main` controls that push.
- AC-4 The block text shall never tell the user to complete again tasks the branch did not touch; evidence: a CLI test of the text on the first repro.
