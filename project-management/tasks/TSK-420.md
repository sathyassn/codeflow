# TSK-420: orient reports each integration line's drift from main

## Description

Issue #280, item 2. In the reporting project, integration lines sit 12
to 1,201 commits behind `main`; a change on `main` stays missing on
every line until someone syncs each one by hand, and nothing shows which
lines have drifted. `codeflow orient` prints the session digest
(`crates/codeflow-cli/src/cmd/orient.rs`, `crates/codeflow-core/src/hooks/orient.rs`)
with branch, worktree and work counts and no line view; the program
report that would show every fetched line (#166, TSK-311) is 4.1.0 work.

Outcome: **`codeflow orient` and the SessionStart digest show, for each
integration line the remote advertises, how many commits it is behind
the protected target, when the target was last merged into it, and the
age of its oldest unlanded task, and flag a line that has gone longer
than a project-set interval without a sync.**

Rules:

- The lines are the remote-tracking `integration/*` refs after the fetch
  `orient` already performs where the remote is reachable; with no
  remote, the local lines, marked as local.
- "Behind" is `git rev-list --count <line>..<target>`. The line's own
  commits are its first-parent chain down to, and excluding, the merge
  base with the target; commits at or below the merge base are
  inherited and never count as the line's events. A sync event is an
  own merge commit whose other parent is on the target; "last sync" is
  the newest such event by its commit date (the date the merge was
  made, not the merged tip's age). The line's creation is reported
  only from real evidence of the ref's creation (the remote's branch
  creation record where the provider gives one, or the local reflog
  entry that created the ref); without it, creation is `unknown`. The
  oldest own commit may be shown, labelled `oldest divergent commit`,
  as the historical fact it is, and never stands for creation: a line
  named today over month-old divergent history has an old divergent
  commit and an unknown creation. A line with no own commit shows
  `fresh, no own commits`. A line whose creation is unknown and that
  has no sync event gets no time-based flag. A timestamp alone
  establishes neither a ref's creation nor a sync event; the commit
  date is read only for a sync merge identified independently by its
  parents. "Oldest
  unlanded task" is the earliest `created` among the line's tasks whose
  records on the line are not terminal.
- The interval is a policy key (provisional `git.line_sync_interval`,
  placed by TSK-280's rule, read by `orient`, default off) ; past it the
  line is flagged with the sync route TSK-421 names.
- The facts are exposed through one reader the sync route (TSK-421) and
  the program report (TSK-311) reuse; the view stays read-only.
- Streams are the coordination ledger's `WS-NNN` (EPC-025, TSK-439);
  this view does not read the ledger and lists epics only.

Non-goals: syncing or closing a line (TSK-421); the program report's
per-record view (TSK-311, which reuses this reader for its line rows).

Added by the EPC-022 amendment of 2026-10-22 under the operator's
decision of that day (project-management changes go in 3.2.0).

## Acceptance Criteria

- AC-1 With a remote advertising integration lines, `codeflow orient` shall print one row per line with behind count, last sync date or the creation state, and oldest unlanded task age, correct for each of: a line synced 2 days ago by an own merge; a line with own commits and no sync whose creation is known from the ref's creation evidence (shown) and one whose creation is unknown (`unknown`, the oldest divergent commit shown and labelled); a fresh line cut today at a target tip committed a month ago (`fresh, no own commits`, no flag); a line named today over month-old divergent history (`unknown` creation, the old divergent commit labelled, no flag); a fresh line that inherited target merge history (no sync reported); and a line that merged an old target tip today (today's date); evidence: a CLI test over a fixture remote with those lines. (serves EPC-022 AC-109)
- AC-2 With `git.line_sync_interval` set, a line past the interval since its last sync event (or since its creation when the creation is known from evidence and it has no sync) shall be flagged naming the sync route, a line whose sync event is within the interval shall not be, whatever the merged tip's age, a line with unknown creation and no sync shall never be flagged on time, and with the key unset nothing shall be flagged; evidence: tests for each. (serves EPC-022 AC-109)
- AC-3 With no reachable remote, the view shall show local lines marked as local and shall not fail the digest; evidence: a test with the remote unreachable.
- AC-4 The reader shall read history only through the guarded reader (an overlaid history refuses as TSK-287 states) and shall add at most one fetch to `orient`; evidence: a test with a grafted line and a count of fetch calls.
- AC-5 `codeflow orient` shall list each open epic with the count of its started tasks, so a second active build stands out (issue 280's comment of 2026-10-22); the grouping by work stream and the per-stream flag are `codeflow coord status` in EPC-025 (TSK-440), which reads the ledger's streams; evidence: a CLI test over fixture epics. (serves EPC-022 AC-109)
- AC-6 (journey) With the installed build in a scratch adopter project with two lines and two open epics in one stream, the SessionStart digest of a new Claude Code session shall show the drift rows and the open-epic list; evidence: the journey output.
