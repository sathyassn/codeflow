# TSK-190: Codex sessions and workspace umbrellas work as installed

## Description

An adopter's Codex session under the shipped default profile reaches tmux,
Herdr and a local dev server, and an umbrella at any tier runs `codeflow
ci` on its root branch as the workspace-mode guide says. Today `cf-guard`
is the default profile (`assets/base/codex/config.toml`) with
`dangerously_allow_all_unix_sockets = false` and `allow_local_binding =
false`, which kept four process-round cases (01, 07, 09, 21) from running
in the native trials of 2026-09-29, and `codeflow ci` refuses any
`integration/*` branch that is not a verified epic line, including the
`integration/workspace` root branch the guide recommends. This replaces
TSK-166 and the D1 spike of TSK-175.

## Affected surfaces and interfaces

- `assets/base/codex/config.toml` and its comment; the cf-model-orchestrator
  launch text.
- `crates/codeflow-cli/src/cmd/ci/classification.rs`, `ci/acceptance.rs`;
  `docs/workspace-mode.md`, `docs/adoption.md`; the 3.0.1 CHANGELOG.

## Acceptance Criteria

- AC-1 Under the default profile in `assets/base/codex/config.toml`, a
  Codex seat shall connect to a unix socket and bind a local port; the
  socket allowance shall be a named list if Codex supports one, else the
  profile flag with the loss (Docker and other host sockets, the
  private-network guard) recorded in the config comment and the CHANGELOG.
  Evidence: a `codex sandbox --` probe against a socket and a listening
  port on Codex 0.157.1; `codex_config` and `permission_presets_update`
  tests; the four process-round cases that need a Codex peer, Herdr or the
  loopback endpoint (01, 07, 09, 21; not run in runs 1 and 2) run valid
  under the default profile. (journey)
- AC-2 A reviewer launch shall still select a no-binding profile by flag,
  named in the cf-model-orchestrator launch text. Evidence: config test;
  skill text.
- AC-3 `codeflow ci`, acceptance amendability and readiness shall accept a
  range on the branch `git.root_branch` names as they accept a verified
  epic line, and still refuse any other `integration/*` branch that is not
  one. Evidence: tests in `ci/classification.rs` (the refusal at line 154
  of `0b3746af8`) and `ci/acceptance.rs` (lines 147 to 148) with
  `integration/workspace`, and a `ci` run on an umbrella fixture at the
  full tier. (journey)
- AC-4 `docs/workspace-mode.md` and `docs/adoption.md` shall state both
  behaviours; the two 3.0.0 known-issue lines shall be removed from the
  3.0.1 notes. Evidence: review; `validate --docs`.
