# TSK-190: Codex sessions and workspace umbrellas work as installed

## Description

A Codex seat under the shipped default profile can build in its workspace,
seats launch in the postures the operator settled in ADR-0075 (D1 builders,
D2 reviewers), and an umbrella at any tier runs `codeflow ci` on its root
branch as the workspace-mode guide says. Today `cf-guard`, the default
profile (`assets/base/codex/config.toml`), denies secret files with `**/`
globs, which makes Codex deny every directory delete, so a seat cannot run
`cargo build`; the launch text still starts reviewers with `on-request` and
`workspace-write`; and `codeflow ci` refuses any `integration/*` branch that
is not a verified epic line, including the `integration/workspace` root
branch the guide recommends. The network of `cf-guard` stays as D2 settled
it: closed unix sockets and no local binding. Herdr from a sandboxed
primary is D7 (TSK-174), and evaluation subjects, including the
process-round cases 01, 07, 09 and 21, are D10 (TSK-194). This replaces
TSK-166 and the D1 spike of TSK-175.

## Affected surfaces and interfaces

- `assets/base/codex/config.toml` and its comment (with the `.codex` and
  baseline copies); the cf-model-orchestrator, cf-herdr and cf-customize
  launch text; ADR-0075's delivery note.
- `crates/codeflow-cli/src/cmd/ci/classification.rs`, `ci/acceptance.rs`;
  `docs/workspace-mode.md`, `docs/adoption.md`; the pending 3.0.0
  CHANGELOG.

## Acceptance Criteria

- AC-1 Under `cf-guard`, the default and reviewer profile, a Codex seat
  shall delete and rename in its workspace and run `cargo build` and
  `cargo test`, while the secret-file denies still deny reading secrets at
  the project root and the network stays as it is (closed unix sockets, no
  local binding). Evidence: `codex sandbox` probes on Codex 0.159.1 (mkdir
  plus rmdir, a cargo build and test of a small crate, a denied read of a
  root `.env`, a refused unix socket and local bind); `codex_config`
  tests. (journey) Changed: D2 keeps the reviewer network closed, so the
  socket and binding allowance is withdrawn; the real defect was the delete
  denial.
- AC-2 Codex reviewer seats shall launch with `--ask-for-approval never`
  and no `--sandbox` flag, named in the cf-model-orchestrator and cf-herdr
  launch text, and builder seats with the D1 posture. Evidence: skill text;
  a `codex_config` contract test pinning the launch text. Changed: D2
  selects `cf-guard` by the absence of a flag, not a no-binding profile by
  flag.
- AC-3 `codeflow ci`, acceptance amendability and readiness shall accept a
  range on the branch `git.root_branch` names as they accept a verified
  epic line, and still refuse any other `integration/*` branch that is not
  one. Evidence: tests in `ci/classification.rs` (the refusal at line 154
  of `0b3746af8`) and `ci/acceptance.rs` (lines 147 to 148) with
  `integration/workspace`, and a `ci` run on an umbrella fixture at the
  full tier. (journey)
- AC-4 `docs/workspace-mode.md` and `docs/adoption.md` shall state both
  behaviours. Evidence: review; `validate --docs`. Changed: no 3.0.1 notes
  or known-issue lines exist on the line; both fixes land in the pending
  3.0.0 section.
- AC-5 Under `cf-builder`, launched from the main checkout root, a Codex
  seat shall fetch (with an absolute remote URL), add a worktree, stage,
  commit, run cargo and npm builds and push to a local bare remote
  unattended, while `.git/hooks` and `.git/config` stay unwritable; the
  result is recorded in the config comment and ADR-0075's delivery note,
  and the D1 text names `cf-builder` for builders only if it passes, else
  full access stays with the gap recorded. Evidence: `codex sandbox` probes
  on Codex 0.159.1 in a disposable repository with a bare remote. (journey)
  Added: this is the D1 spike this task took over from TSK-175.
