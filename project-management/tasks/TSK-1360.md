# TSK-1360: An interrupted capability migration reruns safely, and an offline id clash is repaired

## Description

The recovery and repair half of design unit U2, split from TSK-1137 at claim. The merged task re-graded Very Hard (10: S2 2, S4 3, S7 1, C 2, R 2), so the one-run conversion stayed in TSK-1137 and this task took the rerun and repair path. A rerun of `codeflow capability migrate` after an interruption verifies each existing record's `uid` against its binding, refuses a record whose payload differs from its fence, completes the rest and strips the fences only after every record verified, and `validate --docs` refuses committing the half-done state. A converted entry is judged as one identity, and an offline id clash is refused and repaired through `ids retarget`. Security review owed: the resume logic decides what is overwritten and what is stripped. Non-goal: the one-run conversion (TSK-1137) and running it on CodeFlow's own catalog (TSK-1138).

Design: `coordination/coordinators/capabilities/design-note.md` revision 5 (workspace repository). Split basis: `coordination/coordinators/capabilities/builders/tsk1137-build.md` (workspace commit 6109e034).

## Outcome

After this merges, a project whose capability migration was interrupted can rerun it to completion without losing or overwriting a record, and a project with an offline id clash can repair it and merge.

## Deliverables

- the resume and verification path: `crates/codeflow-core/src/capability/migrate.rs` and `crates/codeflow-cli/src/cmd/capability.rs`
- the interrupted-state refusal in `validate --docs`: `crates/codeflow-core/src/validate/docs.rs`
- the converted-entry judgement and clash repair fixtures: `crates/codeflow-cli/tests/`
