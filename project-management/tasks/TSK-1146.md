# TSK-1146: CodeFlow's capabilities are inventoried and classified across all four dimensions

## Description

CodeFlow's own initial catalog, built through the bootstrap flow it ships. After TSK-1138 has migrated the 17 existing entries, the bootstrap stages inventory and classification run for CodeFlow itself: every capability a user, an operator or a maintainer relies on is listed, whether user-facing, internal or technical, functional or non-functional (for example the guard behaviour, the install and update path, performance and sandbox limits), and each is classified by the facets, with the project vocabulary derived from CodeFlow. This task ends at a classified inventory with summaries and a reviewed list; evidence and `inventory: complete` are TSK-1148. Basis: an inventory pass over `docs/`, `crates/` and `assets/` and about 20 to 40 new records with a classification basis; if the inventory finds over 40 new records the builder splits by area at claim, as this grade assumes.

Design: `coordination/coordinators/capabilities/design-note.md` revision 5 and the operator's comments of 2026-11-01 (about 12:47 EST) in the same folder's `DIRECTION.md`.

## Outcome

After this merges, CodeFlow's catalog lists every user-facing, internal and technical capability, functional and non-functional, classified by facet, not only the original 17.

## Deliverables

- the new and existing records: `docs/capabilities/`
- the project vocabulary: `docs/capabilities/vocabulary.yaml`
- the inventory notes with each classification's basis: the bootstrap epic's tasks

## Acceptance Criteria

- AC-1 The inventory shall cover user-facing, internal and technical capabilities, functional and non-functional ones, with each record carrying the five generic facets, `area`, and project facets from the vocabulary; evidence: the facet counts per dimension in the PR and `codeflow validate --docs`. (serves EPC-026 AC-12)
- AC-2 Each new record shall carry a summary written for its users and a classification basis in the task notes; evidence: a sample review of ten records by the reviewer. (serves EPC-026 AC-12)
- AC-3 The run shall follow the shipped bootstrap epic shape (inventory, classification stages); evidence: the epic's stage tasks closed in order. (serves EPC-026 AC-12)
