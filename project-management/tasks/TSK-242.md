# TSK-242: Guards protect shell startup files from agent writes

## Description

No guard stopped an agent from writing a shell startup file (GitHub issue 86), so an agent could plant `ls() { sudo "$@"; }` in `~/.zshrc` and every later command-text guard would judge `ls`. This task makes the startup files a protected class, generated from one list in `crates/codeflow-core/src/security/actions.json`: the home startup files of bash, zsh, sh and ksh, fish, PowerShell and readline, the shell-adjacent files (`.ssh/rc`, tmux, screen, direnv's configuration and trust store), the system files under `/etc`, and `.envrc` in any directory. Containment comes from the harness sandboxes: the Claude presets' generated `Edit(...)` denies, which Claude also applies as sandbox write denies, and explicit `sandbox.filesystem.denyWrite` entries; and the Codex `cf-guard` profile's read-only entries, which `cf-builder` inherits, with Codex builder seats moving to `cf-builder`. The guards are the backstop on every harness: edit-guard refuses a native edit of the class and exec-guard refuses the shell writes it can see, both under the always-blocking rule `security.shell_startup`, with no policy key and no relief. Git-guard also refuses setting code-running git configuration keys at global or system scope under `git.hook_integrity`. Non-goal: proving that no program can write a startup file on a seat without a sandbox. The text guard cannot see a path built at run time, a script written in one call and run in another, or a program that writes the file on its own; the docs state this per harness. Sibling classes are tracked separately: issues 87 (programs planted in a `PATH` directory), 88 (git config include files), 89 (npm `script-shell`), 90 (session environment files) and 91 (LaunchAgents and user services).

## Decisions

- 2026-10-05, operator, relayed by the primary session: Codex builder seats move into the `cf-builder` sandbox profile, which cannot write home startup files, replacing ADR-0075 D1's full-access builder posture. Real containment is filesystem denies wherever a harness has a sandbox; the text guard is the backstop, and the PR states plainly what it cannot stop. The claim that only user-planted definitions remain is dropped.
- 2026-10-05, operator, relayed by the primary session: no relief. The rule always blocks: no `security.shell_startup_allow`, no `warn` or `off`; the user edits their own profile.
- 2026-10-05, operator, relayed by the primary session: adopt the review refinements (writers that name a startup path or write into the home or a startup directory refuse; startup environment assignments on a line that launches a shell refuse; no run-time following of sourced files, doctor reports them; typed anchors; an own rule id; `.envrc`, `.inputrc` and `.ssh/rc` stay in this task) and file the sibling classes as issues 87 to 91.
- 2026-10-05, design reviews by Codex GPT-6 Astra (high, interactive Herdr seat): round 1 unsound (a text guard cannot stop a path built at run time on a seat without a sandbox), round 2 sound with changes (reader exemptions judged by operation, glob words expanded through symbolic links, effective startup locations such as `ZDOTDIR`, `.zwc` companions and the fish XDG directory, read-only git and `cp` sources stay allowed, a per-harness containment statement); all adopted.

## Acceptance Criteria

- AC-1 When a native edit (Claude `Write` or `Edit`, Codex `apply_patch`, Grok `write` or `search_replace`) targets a startup file in any spelling (`~/`, absolute, relative from a home working directory, another letter case, through a symbolic link, under `ZDOTDIR`), edit-guard refuses it under `security.shell_startup` with the sanctioned path, and an ordinary file passes (unit tests in `edit_guard.rs` and the real hook in `crates/codeflow-cli/tests/`).
- AC-2 When a shell call writes a startup file by a visible form (a redirect, `tee`, `cp`, `mv`, `ln`, `install`, `rsync`, `dd of=`, `truncate`, `sed -i`, `perl -pi`, `awk`, `python3 -c`, `node -e`, an interpreter heredoc, `curl -o`, `wget -O`, `less -o`, `git config --file`, `patch`, a heredoc script then run, `xargs`, `find -exec`, a glob or brace word, a symbolic link), exec-guard refuses it under `security.shell_startup` through the real hook on the Claude, Codex and Grok payload contracts, and reads pass (`cat`, `grep`, `ls -la ~`, `diff`, `git diff -- .envrc`, `cp ~/.bashrc ./backup`, `source ~/.zshrc`); the forms pass on 3.0.0 and refuse after.
- AC-3 When a write target is unresolved (a variable, a substitution, `~user`, an unknown directory) and the line names a startup file or the target's directory is the home, `/etc` or a startup directory, the call refuses; the same forms in a project directory keep their verdict (unit tests).
- AC-4 When a placing program (`tar`, `unzip`, `rsync`, `cp -r`, `git` and the like) writes into the home, `/etc` or a startup directory, the call refuses; when `ZDOTDIR`, `HOME`, `BASH_ENV`, `ENV` or `PROMPT_COMMAND` is set on a line that launches a shell which reads startup files, the call refuses; `direnv allow` refuses (unit tests and the real hook).
- AC-5 When `git config --global` or `--system` sets a code-running key (`alias.*`, `core.pager`, `core.editor`, `core.sshCommand`, `core.fsmonitor`, `credential.helper`, `include.path` and the others listed in the PR), git-guard refuses it under `git.hook_integrity`; repository-scope settings and reads pass (unit tests).
- AC-6 The Claude presets carry the class as `Edit(...)` denies and `sandbox.filesystem.denyWrite` entries and the Codex `cf-guard` profile carries it as read-only entries, generated or checked from the one table (`settings_presets` and `codex_config` tests); `codeflow doctor` reports whether the class is in the presets in force and lists the sourced files outside it.
- AC-7 The TSK-233 corpus and the guard corpora change no verdict except lines that write the class, write into the home or `/etc`, set the startup environment for a shell, or set a listed git key (a differential run of both binaries, attached to the PR).
- AC-8 The Codex builder posture is `cf-builder` in the transport table and an ADR-0075 amendment; the docs state the class, the refusal, the sandbox containment per harness and what the backstop cannot stop; `CHANGELOG.md` has one 3.1.0 entry annotated minor; `codeflow validate --docs` passes.
