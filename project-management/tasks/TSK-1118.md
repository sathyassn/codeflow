# TSK-1118: Generated models match their schemas in the gate

## Description

Issue #275's comment of 2026-10-29 (the policy table's structured-data row
and custom part 4): JSON Schema is the source, typed models are generated
(Pydantic v2 through `datamodel-code-generator` in Repository A), the gate
regenerates them and byte-compares, and a standard validator covers what
generation cannot express (`if`/`then`, `uniqueItems`, exclusive unions).
TSK-426 AC-6 sets up a typed-model or validation library per profile and
no criterion regenerates models and compares them, so a hand-edited model
can drift from its schema unnoticed. This task adds a `schema-models` gate
target per profile that `cf-stack` configures: regenerate from each
declared schema and byte-compare with the committed model, failing on
drift and naming the schema; a validator step for what generation cannot
express; and CodeFlow's own schemas (`.codeflow/schemas/`,
`test-config.schema.json`) and their consumers under the same check or
admitted with a fix task. Non-goal: choosing the generator per language is
AC-1's research, not fixed here.

## Outcome

After this merges, an adopter's generated models cannot drift from their schemas without the gate failing, and the rules a schema states that generation cannot express are still validated.

## Deliverables

- the target: `assets/base/testing/templates/` (`schema-models` per profile) and its `cf-stack` setup in `assets/base/skills/cf-stack/SKILL.md`, both mirrors byte-identical
- the runner: `crates/codeflow-core/src/gate/schema_models.rs` (new): regenerate to a temporary tree, byte-compare, report per schema; the validator step configuration
- CodeFlow's own schemas under the check: `.codeflow/schemas/`, `.codeflow/test-config.schema.json` and the Rust and Python consumers, or TSK-424 admitted rows with fix tasks
- docs: `docs/test-gate.md`, `cf-develop` (one paragraph: edit the schema, never the model)
- tests: a drifted model (fails naming the schema), a regenerated model (passes), a schema rule generation cannot express (validator catches it), the `cf-stack` fixture per profile

## Acceptance Criteria

- AC-1 Before any change, the builder shall research schema-to-model generation broadly: generators per language and their determinism (`datamodel-code-generator` and Pydantic v2, `json-schema-to-typescript` and zod, `typify` and `schemars` for Rust, Go's generators), which JSON Schema features each cannot express and the standard validators that cover them, how projects keep generated code byte-stable (headers, formatting, ordering), TSK-426 AC-6's library matrix, CodeFlow's own schemas and consumers, and adjacent concerns (a generator version bump, generated files under the TSK-428 content classes, a schema with `$ref` across files); and shall record the findings with sources and the chosen scope before anything else changes; evidence: the Findings section, committed before the first code change in the PR. Listed first because it runs first (the operator's rule of 2026-10-27).
- AC-2 `cf-stack` shall configure a `schema-models` target per profile that regenerates each declared schema's model to a temporary tree with the pinned generator and byte-compares it with the committed model, failing on drift and naming the schema and the model; evidence: fixtures for a drifted and a regenerated model per profile AC-1's matrix marks applicable. (serves EPC-024 AC-22)
- AC-3 For every schema rule the profile's generator cannot express, the target shall run the standard validator on the fixture data the project declares, and a violation shall fail naming the rule; evidence: an `if`/`then` and a `uniqueItems` fixture. (serves EPC-024 AC-22)
- AC-4 CodeFlow's own schemas and their consumers shall pass the target in this repository's gate, or each exception shall be a TSK-424 admitted row with a fix task; evidence: the gate run and the register diff. (serves EPC-024 AC-4)
- AC-5 A generator version change shall never seed debt: drift from a new generator version fails until the models are regenerated in that pull request; evidence: a fixture with a bumped pin.
- AC-6 `docs/test-gate.md` and `cf-develop` shall state the rule (edit the schema, regenerate, never hand-edit a model); evidence: the text diff, both mirrors byte-identical.
- AC-7 (journey) With the installed build, a fresh `codeflow init --standard` Python and TypeScript project with one schema shall pass its quick gate, fail after a hand edit to the generated model, and pass after regeneration; evidence: the journey output.
