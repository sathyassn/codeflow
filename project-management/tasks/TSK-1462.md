# TSK-1462: Seat launches through the Herdr app pass the guards again once its dispatch is known

## Description

TSK-1344 makes the guards judge a command run through the Herdr app (`hc run`) the same as the bare command. The app can run a named launch definition in place of a program, and nothing in the command text proves which of the two a given run starts, so the guard cannot verify that the program it judges is the program that runs. Until the app's dispatch rules are known from its source or its owner, TSK-1344 refuses every such run the guard judges, including the seat launch lines this project uses for Codex and Grok seats. Those seats then start outside a guarded `hc run`, by the operator or a launch route the guards already judge.

This task restores a guarded seat launch: once the dispatch rules are known, the guards admit the forms the rules prove start only the named program, and judge the command each one carries.

Source: the Director's ruling of 2026-11-11 about 12:31, relayed by coord/ci shortly after: TSK-1344 (PR 706) refuses every run through the Herdr app that the guard judges, because the guard cannot tell from the command text which program the app will start; TSK-1344's AC-2 is amended, pending the operator, to drop the seat launch lines it required to pass, and its `follow_ups` names this task. Evidence: Codex seat C's design review of PR 706 (workspace `coordination/coordinators/parallel/reviews/pr706-design-codex.md`).

## Outcome

After this merges, a Codex or Grok seat launch through the Herdr app passes the guards in every form that the app's documented dispatch rules prove starts only the named program, and every other run through the app is still refused.

## Deliverables

- `## Findings`: the app's dispatch rules, from its source or its owner, with the version they hold for, covering every form the guard would admit
- the admission rule in the terminal-carrier guard (`crates/codeflow-core/src/security/terminal_carriers.rs`), admitting only the proven forms and judging their carried command
- tests with fail-before evidence for each admitted seat launch line and for each still-refused form
- the TSK-1344 AC-2 seat lines restored as passing lines, or recorded as not restorable with the reason

## Acceptance Criteria

- AC-1 Before any change, the builder shall establish the Herdr app's dispatch rules from its source or its owner, naming the version: for each form a seat launch uses, whether the app can resolve it to anything other than the named program, and which inputs (environment, configuration, the launch definition folder) can change that; evidence: `## Findings` with the sources.
- AC-2 The guards shall admit through `hc run` only the forms AC-1 proves start only the named program, judging the carried command by the same rules as the bare command; every other form stays refused, failing closed, naming the form that passes. Evidence: a fail-before test for each admitted seat launch line (the Codex and Grok lines TSK-1344 AC-2 named, each with and without `--outlive-parent`), and a test for each refused form.
- AC-3 If AC-1 shows that no form can be proven, no form is admitted, and the record says so with the evidence; the task then closes as not restorable. Evidence: the Findings and the closeout.
- AC-4 Behaviour for every other carrier and rule shall be unchanged. Evidence: the existing guard tests, `hooks_cli`, `codeflow test --mode quick`, clippy `-D warnings`, `cargo fmt --check`, and the Windows cross-check.
- AC-5 The whole unit shall have a cross-family security review with the `cf-security-reviewer` checklist, the seat checked live at dispatch; the pull request shall state why the admitted forms cannot start another program. Evidence: the review record and the PR body.
