# TSK-299: The git guard judges every writing program's output option

## Description

The git guard decides whether a command line writes a protected path by
looking at the programs in `WRITING_PROGRAMS`
(`crates/codeflow-core/src/hooks/git_guard.rs:1089`) and at the options it
knows name an output file. Three gaps in that judgment let a line write a
protected file that the guard would refuse if the same write were spelled as
a redirect, `tee` or `cp`. All of them exist in v3.1.0 and in the 3.1.1 sed
reader of TSK-290. They were found in the reviews of PR 158 (TSK-290,
https://github.com/sathyassn/codeflow/pull/158) and are not caused by it.

- **sort output option.** `sort` writes its result to the file named by
  `-o FILE`, `-oFILE` or `--output=FILE`, but the direct writer judge does
  not read that option as a write. A line that changes into a protected
  directory and then runs `sort` with such an option is allowed. The same
  holds when the `sort` is the command of a sed `e` command.
- **curl and wget output options.** `curl -o` and `--output`, and `wget -O`
  and `--output-document`, write a downloaded body to a named file, but
  neither program is in `WRITING_PROGRAMS`. From a directory the guard
  cannot resolve (for example after a change into a variable), the guard
  has no program to read the word from, so the write is allowed.
- **nested quoting.** A single-quoted sed script inside a nested `bash -c`
  or `eval` body, which itself sits inside an outer double-quoted string and
  is fed from a `$(...)` assignment, writes a file at run time. The guard
  does not read the script at that depth and allows the line.

Context only, not a criterion: a sed script whose write target comes from
the input, such as one that builds the path with `&` and runs it with the
`e` flag, is a path built at run time. `docs/policy-reference.md` already
says a path built at run time is past the guard and the OS sandbox's write
denies are the backstop. This task leaves that rule as it is.

This task closes the three gaps by judging every writing program's output
option, and checks that ordinary commands stay allowed. The sed `e` rows of
the first gap are part of this task only once this line contains TSK-290,
which reaches it from 3.1.1 through `main` (the condition TSK-286 states for
its sed rows). Non-goals: the deletion grammar (TSK-286), the git
configuration reader (TSK-283) and a general shell interpreter.

## Acceptance Criteria

- AC-1 When a line runs `sort` with `-o FILE`, `-oFILE`, `--output=FILE`
  or `--output FILE`, alone or among combined short flags, and the file is
  a protected path, the guard shall refuse it by the rule that refuses a
  redirect to that path, from a known directory and from a directory it
  cannot resolve; evidence: one refusal test per spelling in each case,
  and a native run of each spelling in a disposable directory showing that
  `sort` wrote the named file. (serves EPC-022 AC-5)
- AC-2 When the same `sort` is the command of a sed `e` command or the
  `e` flag of an `s` command with literal command text, the guard shall
  refuse it as in AC-1; evidence: refusal tests for both sed forms, run
  once this line contains TSK-290.
- AC-3 When a line runs `curl` with `-o`, `-oFILE`, `--output` or
  `--output=FILE`, or `wget` with `-O`, `-OFILE`, `--output-document` or
  `--output-document=FILE`, and the file is a protected path or the
  directory is one the guard cannot resolve, the guard shall refuse it;
  evidence: refusal tests for each spelling from a known protected
  directory and from an unresolved one, and a native run of `curl` against
  a local file URL and of `wget` against a local server in a disposable
  directory showing the named file was written. (serves EPC-022 AC-5)
- AC-4 When a single-quoted sed script sits in a nested `bash -c` or
  `eval` body inside an outer double-quoted string and is fed from a
  `$(...)` assignment, the guard shall read the script by sed's grammar
  and refuse a write to a protected path, or judge the line unproven and
  refuse it with a message that names the rule and the sanctioned path;
  evidence: a refusal test of that shape, the same shape run natively in a
  disposable directory to show the script writes at run time, and a test
  that the same shape with a read-only script is allowed or refused as
  unproven with the same message. (serves EPC-022 AC-5)
- AC-5 When a line runs `sort` without an output option, `sort` with
  `-o /dev/null`, `curl` or `wget` writing to standard output (`curl -sS
  URL`, `wget -qO- URL`), `curl -o` to a scratch path outside every
  protected path, or a sed script with no write or `e` command, the guard
  shall allow it as at 3.1.0; evidence: allow tests for each form, run
  with the same fixtures as AC-1 to AC-4.
- AC-6 A sweep of the programs a developer commonly runs shall list each
  program that has an option naming an output file (for example `sort`,
  `curl` with `-D`, `--output-dir` and `-o`, `wget` with `-o` and `-P`,
  `tar`, `zip`, `gzip`, `git` with `--output`), and a table shall mark each
  as judged, refused as unproven, or reads only, with the version tested;
  a test shall fail when a listed program has no row; evidence: the table
  and the test. (serves EPC-022 AC-5)
- AC-7 When the installed hooks judge each planted case from AC-1 to AC-4
  in a fresh project, each shall be refused with a message that names the
  rule and the sanctioned path, and each allowed form from AC-5 shall run
  (journey); evidence: a CLI journey with the installed build. (serves
  EPC-022 AC-5 and AC-12)
