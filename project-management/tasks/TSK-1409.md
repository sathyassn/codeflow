# TSK-1409: Git-guard judges the path a clone checks out into

## Description

Git-guard judges the paths `git clone` writes: the destination, a separate git directory and a template copy (TSK-379, narrowed by TSK-1401). Grok's security review of the TSK-1401 build found a gap that predates that task. The check does not judge every way a clone's checkout location can be chosen, so for some spellings the path the files are written to goes unjudged. The class is improper authorization. This task makes git-guard judge the checkout location as it judges the destination, and refuse when it cannot place it. Builders get the exact sites from coord/records, from the review verdict `coordination/coordinators/parallel/reviews/tsk1401-build-grok.md` (outside the repository). Non-goals: a location variable inherited from the hook's environment, which TSK-1130 AC-5 owns, and exec-guard's judgment of the programs Git runs, which TSK-1408 owns.

## Outcome

After this merges, a clone cannot write files into an enforcement path by choosing where it checks them out, whichever spelling chooses it.

## Deliverables

- the fix: git-guard's clone authority in `crates/codeflow-core/src/hooks/`
- tests: a fail-before test per spelling beside the clone written-path tests
- docs: the written-path rule in `docs/policy-reference.md` and a changelog fragment `changelog.d/TSK-1409.md`

## Acceptance Criteria

- AC-1 When a clone's checkout location is chosen by any spelling git-guard can see in the command (an assignment on the same line, a global option before the verb, a configuration value given on the command line), git-guard shall judge that location as it judges the clone destination, and shall refuse it when it is, or would be created inside, an enforcement path; evidence: a test per spelling, refused at the head and failing before the change.
- AC-2 When git-guard cannot place a clone's checkout location (an unresolved word, a value it cannot read), it shall refuse the clone (fail closed), as it does for a destination it cannot place; the error the location check raises shall be recorded for `git clone`, not only for transport verbs; evidence: a test per case, refused at the head and failing before the change.
- AC-3 A clone whose checkout location is an ordinary path outside every enforcement path, and a clone with no such setting, shall keep their verdicts; evidence: allow cases in the same tests.
- AC-4 Every location spelling Git accepts for `git clone` shall be listed with git-guard's verdict, and any spelling that also reaches another verb that creates or checks out a work tree (for example `git init`, `git worktree add`) shall be checked; each gap found shall be fixed here; evidence: the list in the pull request body.
- AC-5 `docs/policy-reference.md` shall name the checkout location among the paths a clone writes, and the changelog fragment shall describe the fix by class; evidence: the doc diff and `codeflow validate --docs`.
- AC-6 Security review: Grok (cross-family) applies the `cf-security-reviewer` checklist and confirms no refusal a test or criterion requires was lost; evidence: the verdict file named in the pull request body.
