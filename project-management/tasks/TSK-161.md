# TSK-161: portal verifier loads pages without keep-alive stalls

## Description

TSK-063's gate runs of the Agent OS guide found that the docs-portal
starter's `browser:verify` can stall on a navigation until the 30 s goto
timeout, and that the wedged Chromium then ignores SIGTERM and holds its
runner open. Controlled runs over the guide's 99 routes with `networkidle`
point at the server's keep-alive idle close racing the browser's socket
reuse. Against `astro preview` (Node's default 5 s keep-alive), two runs in
similar conditions (1-minute load about 20 to 60) gave 20 stalls in 198
navigations, some never recovering, and none in 297. During a stall curl
fetched the same page in under 15 ms and Chromium held a CLOSE_WAIT socket.
A server that closes idle sockets after 1 ms reproduces it, 4 in 495 with
route interception and 1 in 495 without, and a server that keeps idle
sockets for 5000 ms showed none in 198. Host load is not shown to cause the
stall; the stalls are intermittent. The mixed-fixture unit test serves over
a Node server with the default keep-alive and hangs the same way. This task
makes the verifier and its fixture tests serve pages with no idle close
during a run, so an intermittent socket race cannot turn one navigation
into a failed or hung gate. A navigation retry is a non-goal: it would hide
the race. The evidence is the "Verifier navigation stall" section of the
Agent OS record `docs/verification/guide-companion-figures-2026-09-28.md`
on branch `docs/guide-visual-doctrine` (7804d0c).

## Affected surfaces and interfaces

- `docs-portal/scripts/browser-verify.mjs` and the starter's test servers
  (`docs-portal/tests/`); the managed starter files, their pins in the
  scaffold manifest and consumers' `.codeflow/docs-portal.json`.

## Acceptance Criteria

- AC-1 During a verification run, the server that serves the built pages
  keeps idle connections open for the whole run, or closes each response's
  connection itself, so no page request reuses a socket the server closed;
  evidence: a verifier test that serves through the verifier's own server
  and asserts its keep-alive setting, and a stall probe that runs the same
  navigation loop against a server closing idle sockets after 1 ms and
  against the verifier's server.
- AC-2 The fixture tests that navigate with `networkidle` use the same
  serving rule; evidence: the mixed-fixture test green in Chromium, Firefox
  and WebKit.
- AC-3 The stall probe reproduces the stall against the 1 ms server and
  shows none against the verifier's server over at least 495 navigations;
  evidence: both runs recorded with their counts.
- AC-4 `npm run check` and `browser:verify` in `docs-portal`, `codeflow
  validate --portal` on a scaffolded guide and the scaffold manifest tests
  are green, and the starter pins are updated; evidence: recorded output
  with the head SHA.
