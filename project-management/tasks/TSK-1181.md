# TSK-1181: The acceptance_binding finding names a record edit after completion, not an outside branch

## Description

Issue 505. When a task completes at C, its record is edited at E, and the line is merged with no fast forward, `work.acceptance_binding` blocks the check but names the wrong cause and the wrong remedy: it says the commit is outside the range and suggests deleting a branch, although E is reachable from the head through the merge's second parent. The block verdict is right and stays. The message and the diagnosis change.

The open question is why E is classed `Landing::Elsewhere` (`crates/codeflow-core/src/workgraph/landing.rs` near `:95`, message at `:126`, suffix at `acceptance.rs:2195`) when the candidate reaches it. The builder answers it first and records the answer in this record before any code change: either the classification is wrong, and it is fixed here with the block still holding for the edited record, or only the message is wrong.

Coordination: TSK-1124 and TSK-1152 edit `crates/codeflow-core/src/workgraph/acceptance.rs`, and TSK-1129 (PR 478, record not on the line yet) shares it. Before building, check live whether any is open on the same lines; one writer at a time.

Not a security task: the block verdict is unchanged and only the message and diagnosis change. Non-goals: weakening the block, or changing any other finding.

## Outcome

after this merges, a person whose task record was edited after completion is told by `work.acceptance_binding` which edit and which completion are involved and that the fix is to reopen and complete again at a reviewed commit that includes the edit, and is never sent to delete a branch the head already contains.
