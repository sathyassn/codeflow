# TSK-1303: Bypass permissions is a named preset and the guards still hold under it

## Description

Issue 451 asks for `bypassPermissions` as a sanctioned host mode, with the hooks, deny rules and the sandbox kept as the floor. Today `codeflow init` and `doctor` know only the shipped presets. This task adds `bypassPermissions` as a named preset and proves the guards still refuse the non-relaxable command class under it. Issue 452 (the sandbox is not a floor once the unsandboxed retry is off) is in the same family and is owned by TSK-1059.

## Outcome

After this merges, a maintainer can choose bypass permissions as a named preset and know that the guards and the sandbox still hold under it.

## Deliverables

- the preset: the harness presets in `assets/base/` and `crates/codeflow-core/src/scaffold/`, with `codeflow init` and `codeflow doctor`
- tests and docs: preset tests, `docs/adoption.md`
- release note: `changelog.d/TSK-1303.md`

## Acceptance Criteria

- AC-1 `codeflow init` and `codeflow doctor` shall accept `bypassPermissions` as a named preset and report it by name; evidence: init and doctor tests.
- AC-2 Under that preset, the guards shall still refuse the non-relaxable command class, and the deny rules and the sandbox shall stay in force; evidence: a guard test run under the preset for each refusal class.
- AC-3 (journey) In a scratch project with the installed build, a maintainer selects the preset, and a refused command is still refused; evidence: the journey output.
- AC-4 A changelog entry shall describe the preset; evidence: `changelog.d/TSK-1303.md`.
