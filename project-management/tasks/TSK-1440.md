# TSK-1440: The epic graph is derived from task dependencies, with explicit links, and a circle is refused

## Description

Epics depend on each other through their tasks' edges, but nothing derives that graph or refuses a circle in it; the epic template has no dependency field. In CodeFlow's records 208 of 681 task dependencies cross an epic, and EPC-027 and EPC-028 form a live circle. This task makes `codeflow validate --docs` derive epic edges from cross-epic task edges, accept an explicit epic link with a reason and a condition, report records fixes, and refuse a circle, both there and in `codeflow ci` for a planning range that creates one. Non-goal: refusing a circle already on the default branch; TSK-1442 reports those.

Landing on its target (`main`, alone, early):

- Reachable: refusal of new circles, the derived graph and the explicit link field.
- Inert: a circle already on the default branch is reported, never refused.
- Other lines: nothing, until a planning range would create a circle.

Waits for TSK-1363 on `main`: TSK-1363 (task edges in the declared graph) is on the EPC-022 line only and changes `validate/docs.rs`, so it is not in `depends_on`; the builder starts once it is on `main`.

## Outcome

After this merges, a planner sees which epics depend on which, derived from the task edges and any explicit links, and is refused a planning change that would make a dependency circle between epics.

## Deliverables

- the derived graph, the link field check and the circle refusal: `crates/codeflow-core/src/validate/docs.rs` and the planning-range check in `codeflow ci` (`crates/codeflow-cli/src/cmd/ci.rs`)
- the explicit link field: `project-management/templates/epic.md` and `assets/base/pm/epic.md.tmpl`
- fixtures: `crates/codeflow-core/src/validate/` tests and `crates/codeflow-cli/tests/`
- release note: `changelog.d/TSK-1440.md`

## Acceptance Criteria

- AC-1 An epic shall depend on another epic when one of its open tasks depends on a task of the other whose work is not yet on the default branch, and an edge to a task whose work is already on the default branch shall constrain nothing; evidence: fixtures.
- AC-2 Records fixes shall be reported, never treated as waits: an open epic with no open task is reported as "close the epic" (on `f8aabc62c`: EPC-014, EPC-016, EPC-018, EPC-020, and EPC-021 in planning with no tasks); an open epic whose inbound edges all point at completed tasks holds no dependent epic once that work is on the default branch (EPC-022 is the main case: 26 epics depend on it through 108 task edges, all to completed tasks, while it stays open with 7 todo tasks); evidence: a fixture of each shape and the report on records pinned at `f8aabc62c`.
- AC-3 An explicit link field on the epic record shall name the epic, a reason and the condition that satisfies it (proposed `depends_on_epics`, with `until: complete` or a list of that epic's criteria; the builder settles the form), and the epic template shall carry it; evidence: a schema test and the template diff.
- AC-4 A circle in the derived or linked graph shall be refused in `codeflow validate --docs` and in `codeflow ci` for a planning range that creates it, naming the epics and one task edge per hop; evidence: a planted circle (issue 770's done-when).
- AC-5 A cancelled task's edges shall never count; evidence: a fixture (on CodeFlow's records the 13-epic circle falls to 4 without them).
