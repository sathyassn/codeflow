# TSK-1566: The pre-push hook's printed check command gives the hook's verdict

## Description

Owner: to be assigned by the Director. Staged by coord/records on the Director's request of 2026-11-20, for a key in the next filing batch (or a single record if no batch cuts within the hour).

When the pre-push hook refuses a push, it prints a `codeflow ci` command for the operator to rerun. That command leaves out `--run-level` and `--advertisement-stdin`. Run as printed, `codeflow ci` does not apply the line-sync exemption (TSK-1149), judges the merge's hand-resolved hunks, and refuses with 5 `work.acceptance_binding` blocks. The hook's own call, with the destination's advertisement on stdin, passes. So the printed command does not reproduce the hook's judgment.

Evidence, from coord/ci's rehearsal on a scratch `dest.git` (origin not touched), committed in the workspace under `coordination/coordinators/parallel/notes/pr738-push-letter/` (commit message "PR 738 push letter"):

- `hook.log`: the printed form, exit 1, 5 blocking `work.acceptance_binding`.
- `range.log`: the range form with no body, exit 1, the same 5 blocks.
- `hookadv.log`: the hook's real call with the advertisement on stdin, exit 0, clean.
- `ci-check.sh`: the driver. Context: merge branch `merge/pr738-line` (5710562a23) over origin head 30f5be236d, task TSK-1154 incomplete.

Code: `crates/codeflow-cli/src/cmd/push_set.rs` lines 688-712 at `ad5971c8d`. The comment there says the printed command is "the check at its own levels, as CI runs it, without the push gate's level, and asking the destination itself instead of reading the hook's hand-off"; the filter at lines 697-701 drops `--advertisement-stdin` and the `--run-level` pair. Current line tip: `--run-level` is also set at line 771 and handled in tests (`tests.rs` line 881).

Search done (2026-11-20): TSK-1149 records `follow_ups: "none"`; TSK-1155 (line 144-152) describes `--advertisement-stdin` as the hook's hand-off and says the hook judges a push to a line itself. No record at the line tip names the printed command. Second search (2026-11-20): the other staged records (none name it) and a history search of `project-management/tasks` on all branches for the printed command and `--advertisement-stdin`. The one related record is TSK-1252, whose AC-4 asks the docs and help to document `--destination` and `--advertisement-stdin` or hide them with a reason; it does not cover the printed rerun command, so this is not a duplicate. Not searched: open issues.

Not verified: the hook's verdict on origin itself (coord/ci rehearsed on a scratch destination only); Windows.

Non-goals: any change to the line-sync exemption or to `work.acceptance_binding`.
