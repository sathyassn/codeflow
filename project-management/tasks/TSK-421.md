# TSK-421: A line is synced from main and closed by one checked route each

## Description

Issue #280, items 3 and 5. Syncing a line from `main` is a hand-run
merge today (cf-method "Managing a body of work", drift control); each
sync trips record checks that judge `main`'s completed tasks again
(#176, #181, #197, #217, #218, #240, owned by TSK-306, TSK-339 and
TSK-340), and a sync that carries a `.github/workflows/` change needs a
person to push it, because the guards refuse agent writes there
(TSK-325). Nothing closes a line: a dormant or empty line keeps
collecting drift.

Outcome: **one command merges the protected target into a line, runs
the line's pre-push gate, and reports which merged paths a person must
push, and is safe to run whenever the target changes; and one command
closes a line after checking that nothing on it is unlanded, recording
the closure.**

Rules:

- **Sync** (provisional `codeflow line sync <line>`): fetches, merges
  `origin/<target>` into the line's checkout in a linked worktree with a
  no-fast-forward merge, refuses on a conflict naming the files, runs
  the quick gate through the same path the pre-push hook uses, and
  reports the merged paths under `.github/workflows/` and other
  person-pushed paths with the exact push a person runs. With no such
  paths it pushes the line as a durability push. A sync that lands no
  new commits is a no-op that says so. A clean sync produces a range
  `codeflow ci` and the pre-push hook accept without a waiver, which is
  what TSK-339 and TSK-340 deliver; this task adds the fixture that
  proves it on the sync route and returns any remaining re-judge to the
  plan as a finding. The epic or checkpoint pull request the synced
  line then opens into `main` is judged as TSK-433 states.
- **Close** (provisional `codeflow line close <line>`): refuses while
  any task whose `integration_target` is the line is not terminal, any
  pushed task branch targets the line with a tip not on it, or the
  line holds commits not on the target; otherwise writes the closure
  (date, final tip, the epic's PR to `main` where one exists) into the
  epic record's planning notes through a planning commit on the target,
  and lists the branch deletion TSK-402's cleanup rule then allows. It
  never deletes the branch itself.
- Both are agent-runnable under the guards: they use the sanctioned
  fetch, merge and push forms and never touch a protected branch.

Non-goals: deleting branches (TSK-402's cleanup rule); carrying one
task's landed change to another line (TSK-402); the drift view
(TSK-420).

Added by the EPC-022 amendment of 2026-10-22 under the operator's
decision of that day (project-management changes go in 3.2.0).

## Deliverables

- the two commands: `crates/codeflow-cli/src/cmd/line.rs` (new) wired in `crates/codeflow-cli/src/main.rs`, with the merge and gate run in `crates/codeflow-core/src/integrate.rs` or a sibling module, reusing the pre-push gate path in `crates/codeflow-core/src/hooks/git_hook.rs`
- the person-pushed path report: the same protected-path table the guards use (`crates/codeflow-core/src/security/`), read, not changed
- the closure record: the epic planning-notes writer in `crates/codeflow-core/src/workgraph/` and the `line close` class in `crates/codeflow-cli/src/cmd/ci/classification.rs`
- tests: `crates/codeflow-cli/tests/line_cli.rs` (new) with a clean sync, a conflict, a workflow-file sync, a no-op, a close with an unlanded task and a clean close; the clean-sync range through `codeflow ci` and the pre-push fixture
- docs: `docs/cli.md`, `cf-method/SKILL.md` "Managing a body of work" (drift control names the command) in `assets/base/`, `.claude/skills` and `.agents/skills`, and `.codeflow/rules/git-rules.md` "Bodies of work"
- release note: `changelog.d/TSK-421.md`

## Acceptance Criteria

- AC-1 `codeflow line sync <line>` on a line behind the target shall merge the target with a no-fast-forward merge, run the quick gate as the pre-push hook does, push the line when no person-pushed path was merged, and print the merged count; a sync with nothing to merge shall say so and change nothing; evidence: CLI tests. (serves EPC-022 AC-110)
- AC-2 A sync whose merge touches `.github/workflows/` or another person-pushed path shall not push, and shall print each such path and the exact push a person runs; a conflicting merge shall refuse naming the files and leave the line unchanged; evidence: CLI tests. (serves EPC-022 AC-110)
- AC-3 A clean sync's range shall pass `codeflow ci` and the pre-push hook with no waiver and no re-judge of the target's completed tasks, in the #176, #181, #217, #218 and #240 shapes; evidence: fixtures through both, each citing the owning task's fix, with any remaining refusal returned to the plan. (serves EPC-022 AC-110)
- AC-4 `codeflow line close <line>` shall refuse naming each unlanded task, each pushed task branch with a tip not on the line, and any line commit not on the target; a line with none shall get a closure entry in its epic's planning notes through a planning commit on the target and a list of the branches TSK-402's rule then allows deleting, with no deletion performed; evidence: CLI tests for each refusal and the clean close. (serves EPC-022 AC-110)
- AC-5 Both commands shall run under git-guard and exec-guard in an agent session without a refusal and without touching a protected branch; evidence: the guard tests on each command line they run.
- AC-6 (journey) With the installed build in a scratch adopter project with a remote, an agent session shall sync a line 10 commits behind, be told to hand a workflow-file merge to a person, and close an empty line; evidence: the journey output with `git ls-remote` before and after.
