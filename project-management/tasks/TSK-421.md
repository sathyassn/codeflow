# TSK-421: A line is synced, carried to another line and closed by one checked route each

## Description

Issue #280, items 3 and 5. Syncing a line from `main` is a hand-run
merge today (cf-method "Managing a body of work", drift control); each
sync trips record checks that judge `main`'s completed tasks again
(#176, #181, #197, #217, #218, #240, owned by TSK-306, TSK-339 and
TSK-340), and a sync that carries a `.github/workflows/` change needs a
person to push it, because the guards refuse agent writes there
(TSK-325). Nothing closes a line: a dormant or empty line keeps
collecting drift.

Outcome: **one command merges the protected target into a line, runs
the line's pre-push gate, and reports which merged paths a person must
push, and is safe to run whenever the target changes; and one command
closes a line after checking that nothing on it is unlanded, recording
the closure.**

Rules:

- **Sync** (provisional `codeflow line sync <line>`): fetches, merges
  `origin/<target>` into the line's checkout in a linked worktree with a
  no-fast-forward merge, refuses on a conflict naming the files, runs
  the quick gate through the same path the pre-push hook uses, and
  reports the merged paths under `.github/workflows/` and other
  person-pushed paths with the exact push a person runs. With no such
  paths it pushes the line as a durability push. A sync that lands no
  new commits is a no-op that says so. A clean sync produces a range
  `codeflow ci` and the pre-push hook accept without a waiver, which is
  what TSK-339 and TSK-340 deliver; this task adds the fixture that
  proves it on the sync route and returns any remaining re-judge to the
  plan as a finding. The epic or checkpoint pull request the synced
  line then opens into `main` is judged as TSK-433 states.
- **Close** (provisional `codeflow line close <line>`): refuses while
  any task whose `integration_target` is the line is not terminal, any
  pushed task branch targets the line with a tip not on it, or the
  line holds commits not on the target; otherwise writes the closure
  (date, final tip, the epic's PR to `main` where one exists) into the
  epic record's planning notes through a planning commit on the target,
  and lists the branch deletion TSK-402's cleanup rule then allows. It
  never deletes the branch itself.
- Both are agent-runnable under the guards: they use the sanctioned
  fetch, merge and push forms and never touch a protected branch.

Non-goals: deleting branches (TSK-402's cleanup rule); carrying one
task's landed change to another line (TSK-402); the drift view
(TSK-420).
