# TSK-115: make cf-present usable from the agent sandbox

## Description

Operator request of 2026-09-26: complex explanations use cf-present. Today
an agent cannot run `codeflow present` from its sandbox because the state
directory is blocked. This task makes the command usable there, prints the
openable handoff link on `open`, and adds a behavioural eval in which a
desktop agent chooses cf-present for a complex decision.

## Affected surfaces and interfaces

- `crates/codeflow-present` state location and `present open` output
  (CAP-016).
- The project sandbox settings the scaffold writes, if the state directory
  needs an allowance there.
- The model evaluation cases (CAP-013).

## Acceptance Criteria

- [ ] AC-1 When an agent runs `codeflow present open` from the scaffolded
      sandbox, the command shall succeed without a sandbox bypass; evidence:
      a sandboxed session transcript and a test of the state location.
- [ ] AC-2 `present open` shall print a handoff link the operator can open;
      evidence: output test.
- [ ] AC-3 A behavioural eval shall grade whether a desktop agent chooses
      cf-present for a complex decision, from tool effects; evidence: the
      case and one graded native run.
- [ ] AC-4 The change shall preserve ADR-0052's boundaries for present:
      session state stays private to the runtime, session identity and
      cleanup behave as that record states, and no broad writable root is
      added to the sandbox settings (any allowance names only the state
      directory present needs); evidence: the settings diff, a test of the
      state location and permissions, and a cleanup test.
