# TSK-115: make cf-present usable from the agent sandbox

## Description

Operator request of 2026-09-26: complex explanations use cf-present. Today
an agent cannot run `codeflow present` from its sandbox because the state
directory is blocked. This task makes the command usable there, prints the
openable handoff link on `open`, and adds a behavioural eval in which a
desktop agent chooses cf-present for a complex decision.

## Affected surfaces and interfaces

- `crates/codeflow-present` state location and `present open` output
  (CAP-016).
- The project sandbox settings the scaffold writes, if the state directory
  needs an allowance there.
- The model evaluation cases (CAP-013).

## Closeout

- State location: unchanged, so existing sessions stay readable. The
  Claude presets (and this repository's settings and baseline) add one
  `sandbox.filesystem.allowWrite` pair naming the present state directory
  on macOS and on Linux; `codeflow update` merges it. A Linux
  `XDG_STATE_HOME` outside the default is not covered. The Codex profile
  is unchanged.
- First use (review T115-1): the allowance cannot create the state
  root's missing parents, so `codeflow init` and `codeflow update`, which
  run outside the sandbox, create the root owner-only; a sandboxed
  command that finds it missing fails with a message naming
  `codeflow update`. Tests with a fresh HOME:
  `init_and_update_provision_the_present_state_root_in_a_fresh_home` and
  `first_use_without_a_writable_state_parent_names_the_provisioning_command`.
  A macOS Seatbelt probe that allows writes only inside the state root
  showed the guided failure before `init` and a working open, update,
  feedback, close and clear after it.
- Handoff: `present open --no-launch` and `present show --no-launch` print
  a percent-encoded `file:` link to the single-use bootstrap page. The
  runtime closes an unopened session after 120 seconds, so the link must
  be opened promptly; the skill and the output say so.
- Update outside a repository still fails by design (sessions are scoped
  to the project working tree); the error now says to run from there.
- R-118 extensions: skill `cf-present` step 3 items 3 and 4 (sandbox and
  handoff link, within the 8 KiB budget).
- Discoveries: `ps` is blocked in the Claude sandbox, so closing a session
  whose browser was launched outside the sandbox cannot prove process
  identity from inside it; every `codeflow` command in the sandbox prints
  `registry touch failed` because `~/.codeflow` is not writable there.
- Link expiry (finding, not changed here): an unopened handoff link
  closes the session after 120 seconds, which is short for an operator
  who is not watching. Changing it is a design decision for a later task.
- AC-3: run 1 failed on the missing revision in the handoff; after the
  handoff-line fix, run 2 passed (see AC-3).
- Discovery: an unsandboxed Codex companion call ran without a prompt in
  the eval fixture. The fixture sets `allowUnsandboxedCommands: true` and
  the operator's user settings allow `Bash(node:*)`, which matches it; an
  eval's sandbox boundary therefore depends on user-level settings.
- R-118: the eval case and fixture land on the integration branch in the
  structure its base already has; TSK-111's later structural change
  carries them.
