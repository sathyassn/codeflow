# TSK-306: A line's newer task version wins over a copy main inherited

## Description

Pre-push refuses a task branch on an integration line when `main` holds an
older version of the task record that the line itself held and later
amended (https://github.com/sathyassn/codeflow/issues/176). With `main`
and the line diverged, `judge` in
`crates/codeflow-core/src/workgraph/landing.rs` (from `:442`) finds no
judged point that is newer than every other (`:458-475`), falls to
`agreed` (`:523-559`), and refuses whenever the held criteria signatures
differ. It never asks whether one point's version was inherited and then
replaced on the other point's line. The issue states the search
backwards: `judge` looks for a point that descends from every other point,
not for their common ancestor. The current refusal is intended:
`held_versions_that_differ_still_give_no_answer` (`landing.rs:1354`)
builds this shape and expects unknown authority, so this task changes that
test and settles the inheritance rule. 3.1.1's issue 153 fix (TSK-295)
left this case unresolved; it did not cause it.

The fix adapts the inherited-supersession reasoning the recovered-record
path already has (`recovered` from `:562`, `inherited` at `:633`, and its
merge-resolution handling near `:668`, which tells choosing an old version
apart from inheriting it unchanged) to held records, and keeps refusing
competing introductions, ambiguous identities, unreadable history and
overlays. Copying the helper alone does not supply every safeguard of its
current caller. The issue's suggested rule, dropping a version whose bytes
appear somewhere in the other point's history, is not used: `main` may
revert to v1, reintroduce v1 independently or resolve a merge to v1 after
the line chose v2, and equal bytes do not make those decisions stale
(`triage-codex-02.md`, "The stale-record refusal"). This is a core
acceptance rule, never a project setting.

Recovery first. Merging current `main` into the line makes `main` an
ancestor of the line tip, so a task range based on the new tip has a newest
judged point (`landing.rs:458-475`) and takes the line's criteria without
`agreed`. That recovery is proved through the installed hooks before any
code, and the result is written in this record. If it fails through the
installed gates and no other sanctioned recovery exists, the operator
decides whether this fix moves to 3.1.2 (workspace `RELEASE-PLAN.md`, triage
of 2026-10-13). Merging `main` into the task branch alone, while the judged
line base stays old, is not the same recovery, and dropping
`--policy-from` or `--commits-from` is not a workaround.

## Acceptance Criteria

- AC-1 Before any code commit, the recovery shall be run through the
  installed hooks on a scratch repository with the issue's shape (a line
  that amended T to v2, `main` diverged and holding v1): merge current
  `main` into the line through its sanctioned route, then push a task
  branch that changes a non-criteria line of T. The record shall state
  whether the push passed, with the binary version, the revisions and the
  output summary; evidence: the dated note in this record at a commit
  before the first code commit.
- AC-2 When the judged points are not ordered by ancestry, one holds v1,
  and the other holds v2 on a line whose every introduction of v1 is an
  ancestor of its v2 and which later replaced v1 with v2, the judgement
  shall take v2 as the authority; evidence: a unit test of `judge`, in
  both point orders, and the issue 176 reproduction as a CLI fixture,
  failing before the fix and passing after. (serves EPC-022 AC-16)
- AC-3 The judgement shall still give no answer when both lines amended
  the task concurrently, when `main` reverted to v1 or reintroduced v1
  after the line's v2, when a merge resolved the record to v1 against the
  automatic remerge, when the history is replaced, grafted or shallow, and
  when two records share the task's identity; evidence: one unit test per
  case. (serves EPC-022 AC-16)
- AC-4 No decision shall rest on byte equality alone: a version whose
  bytes equal v1 but whose introduction is not an ancestor of the other
  line's v2 shall stay a competing version; evidence: a unit test with an
  independently reintroduced v1.
- AC-5 When the judgement gives no answer, the refusal shall name which
  judged point holds which version; evidence: a CLI test that reads the
  message.
- AC-6 When the installed pre-push hook pushes the issue's task branch,
  with `--policy-from` and `--commits-from` at the `main` tip as the hook
  passes them, the push shall pass and the output shall name the line's
  version as the authority and the judged candidate (journey); evidence:
  the journey output.
