# TSK-1087: Updates merge against the binary's bases and the tracked baseline directory is gone

## Description

Source: issue 119 (its manifest portion), the operator's option A of
2026-10-15 (an incompatible manifest, a major release) and `SPC-015`.
Supersedes TSK-258 and its draft PR 125, which dropped the digest but kept
`.codeflow/.baseline/`; that PR's tests and journeys are reused as the
reference for this task's own.

`.codeflow/manifest.json` records a `sha256` per installed file and
`.codeflow/.baseline/` holds a pristine copy of each (317 files here), so
two pull requests that change different managed files conflict in the
manifest and the baseline, and every landing on `main` sends the other open
pull requests back through a merge, a review and a gate (issue 119: six of
ten on 2026-10-08). This task switches `update`, `init`, `prune_orphans`
and `doctor --check managed-drift` to the bases the binary carries
(TSK-1086), writes the manifest in the schema `SPC-015` pins (no digest,
the version each file was installed from), keeps in a tracked sparse pack
only what the binary cannot reproduce, and removes `.codeflow/.baseline/`
from the project in the same `codeflow update`. A 3.x binary cannot read
the result, so the commit is `feat(scaffold)!:` with a `BREAKING CHANGE:`
footer and the change ships in 4.0.0 with migration guidance.

Landing order: this unit rewrites every manifest entry and deletes the
baseline tree, so any open pull request that resyncs managed assets
conflicts with it. It lands after the operator-named breaking peers
TSK-397 (PR 331) and TSK-1052, after TSK-401 (the other `update.rs` writer),
and the primary sequences it after every other asset-changing unit of this
release that is ready at the time; a unit that lands after it resyncs with
this build. Recovery: revert this PR; a project already migrated then
needs a 4.0.0 `codeflow update` or a restore from version control before
a 3.x binary reads it.

Non-goals: the read-only preview (TSK-247); the update procedure
(TSK-1088); the version stamp, which moves in the release preparation
pull request.

## Outcome

After this merges, two pull requests that change different managed files
merge without touching `.codeflow/manifest.json` or a baseline, and an
adopter on 3.x moves to 4.0.0 with one `codeflow update` that rewrites the
manifest and removes `.codeflow/.baseline/` from their repository.
