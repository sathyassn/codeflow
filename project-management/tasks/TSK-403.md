# TSK-403: Grok consult and review seats run read-only commands without prompts and refuse writes

## Description

Issue: #248. The Grok row of "Launch postures" (`cf-model-orchestrator/resources/routing/transport.md:58`) launches consult and review seats with `--permission-mode auto`. On 2026-10-18 three read-only seats stopped at shell-permission prompts on ordinary read-only commands (`shasum`, a probe folder the brief allowed, `codeflow status`). The host may not answer for the operator, so each seat waits for a person. The only option that removes the prompt, always-approve mode, is not read-only.

Outcome: **a Grok consult or review seat runs read-only commands without a prompt and is refused, not prompted, when it tries to write outside its probe directory, which also holds its reply file.**

The builder qualifies a read-only posture (the issue's option A, a read-only command profile, or option B, a read-only sandbox profile) on the current Grok CLI, and records which one Grok can enforce. Always-approve stays rejected. The permission boundary is not weakened: no posture may let a consult seat write repository files or reach the network for writes.

Added by the EPC-022 amendment of 2026-10-18 after the Codex review of PR 249 (`target/review-PR249-codex-01.md`), under the operator's rule that every security gap and every defect that forces an adopter workaround or blocks work belongs in 3.2.0.
