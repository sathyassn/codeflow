# TSK-1342: Every ref deletion in CodeFlow refuses or does not follow a symbolic ref

## Description

Source: the PR 600 F1 confirm review (`coordination/coordinators/parallel/reviews/tsk1308-f1-confirm-37adc82b6.md`, nit 3), which the Director ruled material on 2026-11-05.

On the line at `fd820f700`, `rename_standalone_branch` deletes the old branch with `update-ref -d refs/heads/{old}` and no `--no-deref` (`crates/codeflow-core/src/workgraph/readiness.rs:2090-2094`). When `old` is a symbolic ref, git deletes the branch it points to, which can be a protected branch. This is the same class as TSK-1308's F1, which PR 600 fixes for `codeflow work remove-candidate` by refusing a symbolic candidate and deleting with `--no-deref`.

This task fixes the class everywhere CodeFlow deletes a ref: `update-ref -d`, `branch -D` or `-d`, and git2 reference deletes, in product code, scripts and shipped assets. Each site either passes `--no-deref` (or the git2 equivalent that removes the named ref only) or refuses a symbolic ref before it deletes. Non-goals: the guards' parsing of a user's own `git branch -D` or `update-ref -d` command lines (the guard plane judges those already), and test fixtures that delete refs to set up a case.

## Outcome

After this merges, an adopter whose repository holds a symbolic branch can run any CodeFlow command that deletes a ref, and the branch the link points to, a protected branch included, is never deleted through the link.

## Deliverables

- the sweep of every ref-deletion site with file:line: this record's `## Findings`
- the fixes: each site the sweep names, starting with `crates/codeflow-core/src/workgraph/readiness.rs` (`rename_standalone_branch`); provisional, the sweep decides the rest
- the per-site symref fixture tests: beside each site's existing tests in `crates/codeflow-core/src/` and `crates/codeflow-cli/tests/`
- the guard against new unguarded deletions: a lint test in `crates/codeflow-core/tests/` (provisional home; the builder may place it with the existing source-scan tests)
- release note: `changelog.d/TSK-1342.md`

## Acceptance Criteria

- AC-1 Before any code change, the builder shall list every ref-deletion site in product code, scripts and shipped assets (`update-ref -d`, `branch -D` or `-d`, and git2 reference deletes) with file:line and whether it already passes `--no-deref` or refuses a symbolic ref; evidence: a `## Findings` section committed before the first code change, with the search commands used.
- AC-2 When a ref that CodeFlow deletes is a symbolic ref, each site in the sweep shall either remove only the named ref or refuse naming the symbolic ref, and the branch it points to shall keep its tip; evidence: one symref fixture test per site, pointing at a protected branch, that fails before the change and passes after it.
- AC-3 When a new ref deletion is added to product code, scripts or shipped assets without `--no-deref` or a symbolic-ref refusal, a test shall fail naming the file and line; evidence: the lint test and a negative case that shows it failing on an unguarded deletion.
- AC-4 The change shall have a cross-lineage security review that carries the `cf-security-reviewer` checklist: Grok when it has usage at dispatch, else a Claude Opus medium subagent with reduced assurance recorded; evidence: the review row in the PR and its findings record.
- AC-5 (journey) With the installed build in a scratch adopter project, each CodeFlow command the sweep names as deleting a ref shall be run where that ref is a symbolic branch pointing at `main`, and `main` shall keep its tip; evidence: the journey output with `git show-ref` before and after.
