# TSK-100: prove the shared id registry on a real host

## Description

Design v4 rests the id registry on a protected data branch,
`codeflow/registry`, and on the host refusing deletion and force push of
that branch without a pull-request requirement. That was verified only with
local bare remotes (design v4 section 2.3). This task proves the protocol end
to end on a real host before TSK-101 builds it: the data-branch rules
applied through the host API, seeding, issue, a lost
acknowledgement, a reservation file deleted by a plain commit and caught by
history-based allocation and by the registry check run from the code
branch's CI (SPC-013 R-109), admission of a
fork-style record, and whether the host offers a file-path push rule that
would add prevention for free. It is a gate: if the proof fails, EPC-020
stops and decision 1 returns to the operator, with option (b) (a scan of all
refs plus a CI check) as the known, weaker fallback for 3.0.0.

Per SPC-013 planning resolution 12, this task is a scripted proof and its
record: the script applies the host rules through the host API directly.
The `codeflow remote protect` data profile is product code in TSK-101.

Needs from the operator: one disposable repository on a host with branch
rules (a free public repository works). The same repository can later
serve the `remote protect --apply` test approved earlier and never run.
Agents never create or delete repositories.

## Affected surfaces and interfaces

- The disposable repository only; no change to this repository's remote.
- A proof script and its verification record; no CodeFlow product code.
- Evidence: a verification record under `docs/verification/`.

## Closeout

The proof ran on 2026-09-26 against the operator's disposable repository
`sathyassn/codeflow-registry-proof` with `scripts/proofs/registry-proof/run.sh`.
AC-1 to AC-6 pass and nothing failed, so decision 1 is not returned. AC-8
lacks one run: GitHub started no scheduled run in 79 minutes, so AC-8 and
AC-7 stay open until `run.sh evidence` records one. Record:
`docs/verification/tsk-100-registry-proof.md`; transcripts, host rule
listings and run logs: `docs/verification/evidence/tsk-100/`.

Review-relevant discoveries, detailed in the record:

- Under `pull_request`, a pull request that edits the check workflow gets a
  green check on a damaged registry (run 36276985397, PR #2). R-109's "a PR
  cannot select the binary that checks it" does not hold as arranged. This
  is a safety change to R-109 and R-14, so it returns to both primary seats
  before TSK-101 builds the workflow.
- The host reports the loser of a concurrent push as `[remote rejected]
  (cannot lock ref ... but expected ...)`; TSK-101's R-13 classifier must
  treat it as a moved tip.
- A binding lookup on the tip tells a maintainer to re-admit a deleted
  reservation; TSK-101 should read the first addition in history and name a
  typed restore.

Not tested: a cross-account fork, CodeFlow's hooks and git-guard on the data
branch, typed restore, offline sync, retarget, resume, hosts without branch
rules, and a shallow checkout. The disposable repository keeps its rulesets,
branches, pull requests #1 and #2 and a `*/15` schedule for the primary's
cleanup.
