# TSK-1265: The adopter CI template records hosted-run provenance so adopters can take hosted credit

## Description

Source: the Director's decision 3 of 2026-11-02 on the TSK-1188 design (`coordination/coordinators/parallel/reviews/tsk1188-design.md`, section 0): the adopter template is out of scope of TSK-1188, and this follow-up covers it.

TSK-1188 lets a landing take hosted credit for a green run of the exact candidate, bound by the merge tree, the workflow blob and the jobs the run ran. It reads that binding from provenance the workflow records. The shipped adopter template `assets/base/ci/codeflow-ci.yml` records none, so an adopter always falls back to the local gate. This task adds the provenance record to the template, in the form TSK-1188 reads, so an adopter whose workflow runs the gate on pull requests can take hosted credit.

Non-goals: the credit decision itself (TSK-1188), the other CI templates (`bitbucket-pipelines.yml`, `ci-generic.sh`) unless the builder finds TSK-1188's reader needs them, and this repository's own workflow.

## Outcome

After this merges, an adopter on the shipped GitHub template can have a landing take hosted credit for its own green pull request run.

## Deliverables

- the provenance record in the template: `assets/base/ci/codeflow-ci.yml`
- the manifest entry, baseline resync and update behaviour for the changed managed template: `assets/base/scaffold-manifest.toml` and the tests that read it
- the adopter-facing doc line: `docs/delivery.md` (provisional; the builder confirms against TSK-1188's doc changes)

## Acceptance Criteria

- AC-1 The shipped GitHub template shall record, for each run, the provenance TSK-1188 reads (the merge tree and the jobs run), and a workflow that records none shall make the landing fall back to the local gate; evidence: a template test and the TSK-1188 negative fixture for absent provenance.
- AC-2 `codeflow update` shall carry the changed template to an adopter without overwriting a hand-patched copy silently; evidence: an update test over a patched fixture and the refusal or merge text.
- AC-3 (journey) (changed with the sweep of operator direction 2026-11-02, no scratch GitHub repositories, relayed by coord/parallel.) In a local fixture adopter built from the shipped template, with the provenance of a recorded green run, a landing shall take hosted credit and name "hosted run <id>" in its landing record, and a landing with the provenance absent shall run the local gate; the hosted side is proven on a real adopter run when one exists, and is otherwise reported as not verified; evidence: the fixture output, and the run link where a real adopter run exists.
