# TSK-1132: The catalog loader and schema read one record per capability

## Description

The first half of design unit U1. One data-only loader reads capability records (`docs/capabilities/CAP-NNN-<slug>.md`, frontmatter plus prose) from a checkout or from a pinned tree object and returns equal records from both. The D1 schema validates: five closed generic facets (`status`, `stage`, `kind`, `quality`, `audience`), project facets `group` and `tags` from `docs/capabilities/vocabulary.yaml`, `area` from `project.toml`, a stable `uid`, and bounded values. The legacy fence file still parses beside a folder. Basis for the grade: about 700 lines across `crates/codeflow-core/src/capability.rs` and `validate/docs.rs` plus fixtures. Non-goals: id allocation and status lines (TSK-1133), tag resolution (TSK-362).

Design: `coordination/coordinators/capabilities/design-note.md` revision 5 (workspace repository) and its acceptance tests.

## Outcome

After this merges, CodeFlow reads and validates a catalog of one record per capability from a checkout or a tree, with the legacy file read beside it.

## Deliverables

- the loader and the D1 schema: `crates/codeflow-core/src/capability.rs`
- validation rules: `crates/codeflow-core/src/validate/docs.rs`
- the vocabulary file reader and its shipped example: `docs/capabilities/vocabulary.yaml`
- fixtures for each refusal: `crates/codeflow-core/tests/`
- the schema reference: `docs/capabilities.md`

## Acceptance Criteria

- AC-1 When a record has an unknown key, a non-numeric id, a duplicate id across two files, a duplicate `uid`, a value over its bound, a symlink or executable mode, a link path outside the folder, or malformed YAML, the loader shall refuse it naming the file; evidence: one fixture per case. (serves EPC-026 AC-1)
- AC-2 The same catalog read from a checkout and from a tree object shall give equal records; evidence: a test comparing both reads. (serves EPC-026 AC-1)
- AC-3 A legacy fence file and a folder with distinct identities shall parse together; the same identity in both layouts in a committed tree shall be refused naming both files, whether or not they share a binding and whether or not their payloads agree; evidence: fixtures for each combination. (serves EPC-026 AC-1)
- AC-4 Each catalog shall validate against its own revision's `areas` and `vocabulary.yaml`: a head that adds an area and a record in it passes, and a head record using an area absent from the head `project.toml` is refused; evidence: two fixtures. (serves EPC-026 AC-1)
- AC-5 A `shipped` record with only `gap:` evidence shall pass with `stage: unassessed` and be refused with `stage: stable`; evidence: two fixtures. (serves EPC-026 AC-1)
