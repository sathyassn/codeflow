# TSK-284: Files that run code in a later shell or login are protected

## Description

Three kinds of file make code run later without any command the guards
judge: a program written into a user directory on `PATH` ahead of the real
one (https://github.com/sathyassn/codeflow/issues/87); a session environment file under `environment.d` that sets
`PATH`, `BASH_ENV` or `ZDOTDIR` for every later shell (https://github.com/sathyassn/codeflow/issues/90); and a login
item such as `~/Library/LaunchAgents/*.plist`, a systemd user unit or an
autostart entry (https://github.com/sathyassn/codeflow/issues/91). Each is issue 86's class (planted startup state)
through a user folder, each is protected by path for native edits and shell
writes, and ADR-0075 tracks all three, so one design and one guard change
serve them. Package-manager settings (issue 89) are split into TSK-285
because a project `.npmrc` is a repository file adopters edit for ordinary
reasons and needs a key-level rule, not a path rule.

## Deliverables

- the design note: `docs/research/user-execution-paths.md` (provisional; the design decides whether an ADR is needed)
- the guards: `crates/codeflow-core/src/hooks/edit_guard.rs`, the protected path tables in `crates/codeflow-core/src/security/` (`startup.rs`, `actions.json`)
- the harness sandbox entries in the permission presets under `assets/base/`, with installed copies and baseline
- docs: ADR-0075's sibling note, `docs/policy-reference.md`
- release note: `changelog.d/TSK-284.md`

## Acceptance Criteria

- AC-1 Before any guard code, a design note reviewed by the other lineage
  shall settle which `PATH` directories count (writable by the user and
  searched before the system directories), the session environment
  folders, and the user persistence folders (LaunchAgents, systemd user
  units, autostart) on macOS, Linux and Windows, and for each state the
  guard, the harness sandbox entries and what the backstop cannot see; a
  choice that changes what adopters may write goes to the operator with a
  recommendation; evidence: the note and its review row at a commit before
  the first guard commit.
- AC-2 When a native edit or a shell write targets a file in one of those
  folders, the guards shall refuse it, naming the rule and the sanctioned
  path; evidence: a planted test per class and per write form (native
  edit, redirect, `cp`, `tee`, `install`). (serves EPC-022 AC-5)
- AC-3 Reads of those folders, and writes elsewhere, shall stay allowed;
  evidence: allow tests per class.
- AC-4 ADR-0075's sibling note, `docs/policy-reference.md` and the release
  note shall state the new refusals and their effect on adopters; evidence:
  the doc diff.
- AC-5 When an agent session in a fresh project with the installed build
  writes `~/.local/bin/git`, an `environment.d` file and a LaunchAgents
  plist, each write shall be refused (journey); evidence: a CLI journey
  with a scratch home folder.
