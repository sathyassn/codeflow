# TSK-1153: Hosted line CI reaches its verdicts in about 13 minutes

## Description

Hosted CI on the integration line takes 20.5 to 23.4 minutes. The critical
path is Windows: the 12 test partitions end between 7.5 and 16.4 minutes
because `scripts/windows-test-times.json` is stale (measured from runs
40825861843 to 40882623406), and the 2 coverage shards are unbalanced
(12.6 to 17.4 minutes). This task refreshes both measurement files from
runs 41312671579, 41323314449 and 41337769821 and runs coverage in 4
shards. No check is skipped, scoped or reused. Non-goal: the Windows
archive build is not cached (see AC-3).

Interface note: the change to `.github/workflows/codeflow-ci.yml` is applied
separately by coord/parallel from the diff in the PR body, because that file
is agent-protected. Until it is applied, `scripts/gate-parity.py` reports a
mismatch between the workflow's 2 shards and the data's 4.

## Outcome

After this merges, every session landing on the line gets the `codeflow gates` and `windows` verdicts in about 13 to 14 minutes instead of 20.5 to 23.4.

## Deliverables

- Refreshed Windows partition measurements: scripts/windows-test-times.json
- Refreshed coverage measurements for 4 shards: scripts/coverage-test-times.json
- Parity tests for 4 shards: scripts/test_gate_parity.py
- Workflow diff for 4 coverage shards, in the PR body: .github/workflows/codeflow-ci.yml
- Hosted timings after the diff is applied: the PR body

## Acceptance Criteria

- AC-1 When the Windows suite is partitioned from `scripts/windows-test-times.json`, the slowest of the 12 partitions shall plan within about 20% of the mean; replaying runs 41312671579, 41323314449 and 41337769821 gives 1.05 to 1.09 (the old data gave 1.49 to 1.67), and the hosted partitions confirm it.
- AC-2 When coverage runs on the hosted line, it shall run as 4 shards planned by `scripts/coverage-shards.py` from refreshed data, with the same merged coverage total and the same floor read from `.codeflow/test-config.json`.
- AC-3 Dropped by the operator (coord/parallel, 2026-11-01 14:52): the Windows test build job already restores dependencies with `Swatinem/rust-cache` (shared key `windows-tests`, keyed by Cargo.lock, toolchain and runner), so a second dependency cache adds nothing; a cache of the archive keyed on the whole tree would hit only on a rerun of the same tree. The archive is built every run.
- AC-4 When a push or pull request runs CI, every test and the coverage run shall still execute as before; the partition and shard checks prove each listed test ran exactly once; no check is skipped, scoped or reused.
- AC-5 Hosted wall time from push to the `codeflow gates` and `windows` verdicts is recorded for this PR's own runs, with their median against the 20.5 to 23.4 baseline; the epic's target of about 10 minutes is not claimed by this task.
- AC-6 Where `assets/base/ci/codeflow-ci.yml` has the same structure it gets the same change; it has no Windows partitions, coverage shards or nextest archive, so nothing applies there.
