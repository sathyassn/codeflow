# TSK-1053: Runner directory grammars

## Description

Source: the operator's TSK-1002 scope decision of 2026-10-28 (the option
D scope in Fable's note `target/tsk1002-option-d-scope.md` in the
`guard-bypass-classes` worktree, recorded in `RELEASE-PLAN.md`), with
Codex review 04's per-runner table and Fable review 06's runner section
(PR 346 at `399594818`) as input.

Package and project runners (`uv run`, `npm exec`, `poetry run` and the
like) start their command in a directory their options, environment or
configuration choose. The guard does not model them, so at `399594818`
every such runner makes the directory unknown
(`security/outward.rs:1661`, `unmodeled_launch`; `MODELED_LAUNCHERS` at
`:1623`), and TSK-1002's unknown-directory rule then refuses all inline
code under them. That refusal is sound but costly: agents run these
lines constantly. Under the option D scope, a runner's child directory
leaves the text guard's promise unless a grammar reads it; this task
writes those grammars.

This is a follow-up of TSK-1002. TSK-1002 is a standalone task whose
record is not on this line yet (PR 346, open at `399594818`), so the
`depends_on` edge to it is added by the epic amendment that follows PR
346's landing, and PR 346 names this task in TSK-1002's `follow_ups`;
until PR 346 lands this task is blocked.

Outcome: **the guards read where `uv run`, `npm`/`pnpm`/`yarn exec`,
`npx`, `poetry run`, `bundle exec`, `cargo run` and `direnv exec` run
their command, through one execution-context representation shared with
the existing directory grammars (`env -C`, `ruby -C`, `tar -C`), so
reader words and inline code under them are judged in the right
directory; an option the grammar does not list makes the directory
unknown and refuses as today.**

Directory rules to model, from the reviews and the runners' docs, each
confirmed by AC-1 before it is built:

| Runner | Child directory | Notes |
|---|---|---|
| `uv run` | the invoking directory | `--directory DIR` (also `uv --directory DIR run`) and `UV_WORKING_DIR` move it; `--project DIR` changes project discovery, not the directory; environment-file options change the command's environment |
| `npm exec`, `npx`, `pnpm exec`, `yarn exec` | the nearest project root, found by walking up from the invoking directory (ancestors only) | `-w`/`--workspace` (repeatable), `--workspaces`/`--ws`, `--include-workspace-root`, `--prefix`, `-C`/`--dir`, `--cwd`, `npm_config_*` variables and project configuration move it; `--call`/`-c` runs shell text |
| `poetry run` | the invoking directory | `-C`/`--directory DIR` moves it; `--project`/`-P` does not |
| `bundle exec` | the invoking directory; no directory option | `BUNDLE_GEMFILE` names a Ruby file Bundler evaluates; `RUBYOPT` passes Ruby options |
| `cargo run --` | the invoking directory | words after `--` are the built program's arguments, never a nested interpreter call or inline code; cargo's own directory options and a configured target runner need their own treatment |
| `direnv exec DIR` | `DIR` | it also loads `DIR/.envrc`, which is shell code |

Over-refusals this lifts, each refused at `399594818` (Fable review 06,
"The runner over-refusal"): `uv run python -c 'print(1)'`,
`poetry run python -c ...`, `bundle exec ruby -e ...`,
`npm exec -- node -e ...` and `cargo run -- python3 -c ...`.

Non-goals: what the launched program does once it runs (outside the
promise under option D); runs after a same-line write (TSK-1052);
runners not listed above, such as `pipx run`, `uvx`, `bunx`,
`pnpm dlx` and `yarn dlx`, which keep the unknown-directory rule.

## Acceptance Criteria

- AC-1 Before any change, the builder shall investigate and record in this record, per runner in the Description's table and at a named revision of the line that holds TSK-1002: the child directory; every option, environment variable and configuration key that moves it; the options that take a value, so the grammar knows where the command starts; how the command is found (bare names through `PATH`, `node_modules/.bin`, the virtual environment); the options that run shell text; and the documented version each fact comes from, starting from Codex review 04's table. Each directory fact shall be confirmed with a harmless directory oracle in a disposable fixture for every runner installed on the host, and the rest named as documentation-only; evidence: the record section, committed before the first code change.
- AC-2 Every runner grammar shall produce the same execution-context representation the existing directory grammars use, and reader words, inline code and the written-file filter shall all read the directory and launched command from it; no runner shall get its own prefix recognizer (the cause of Codex review 04 finding 3); evidence: a test per runner showing a reader word, inline code and a same-line written file judged from the one resolved directory. (serves EPC-022 AC-153)
- AC-3 Each directory rule AC-1 confirms shall be modelled: a moving option, variable or configuration naming a secret store shall make a reader word (`cat auth.json`) and inline code naming a relative secret refuse, and the same line with an ordinary directory shall pass; `uv run --project` and `poetry --project`/`-P` shall keep the directory; the `npm` project-root walk shall stay within ancestors of the invoking directory; a workspace selector shall resolve only through workspace configuration the guard reads, otherwise the directory is unknown; evidence: tests per runner and option, each moving case failing before the change where the base judged it in the wrong directory. (serves EPC-022 AC-153)
- AC-4 Fable review 06 Major 3's reader forms (`uv run --directory <store> cat auth.json`, `uv --directory <store> run cat auth.json`, `npm -C <store> exec -- cat auth.json`, `npm --prefix <store> exec -- cat auth.json`, `poetry -C <store> run cat auth.json`, `direnv exec <store> cat auth.json`) shall refuse with a message naming the resolved directory; each was allowed at `399594818`; evidence: tests.
- AC-5 `cargo run -- <words>` shall give the words after `--` the operand rules of any program (a secret operand still refuses under TSK-1002's rule) and never treat them as a nested interpreter or inline code; `bundle exec` shall judge `BUNDLE_GEMFILE` as a Ruby script operand and `RUBYOPT` by the Ruby option grammar, refusing switches it does not read; `direnv exec DIR` shall judge `DIR/.envrc` as a shell script operand; `npm exec --call` and its siblings shall judge their text as shell code; evidence: tests per form.
- AC-6 An option, variable or configuration the grammar does not list, before the command word, shall make the directory unknown, so reader words take the relative-secret rule and inline code refuses, as at the base; a runner outside the table keeps that rule; evidence: a test per runner with an unlisted option, and one per non-goal runner.
- AC-7 The five over-refusals in the Description shall pass, each refused at `399594818`; their siblings whose inline code names a protected path shall still refuse; evidence: tests failing before the change and passing after. (serves EPC-022 AC-153)
- AC-8 A replay of TSK-1002's refusal tests, the reviews' payloads and this task's fixtures, judged by the base and the head binaries, shall show every row that moves from refused to allowed in a reasoned list limited to inline code or reader words under a modelled runner with a known directory and no protected path; a same-line write before a runner shall keep the base's verdict; if TSK-397's replay harness has landed, it is the tool, run in both outcomes; evidence: the replay output with both revisions named.
- AC-9 `docs/policy-reference.md` shall list the modelled runners, their directory rules and the unknown-directory rule for every other runner; evidence: the doc diff and `codeflow test --only docs-portal`.
- AC-10 (journey) With the installed build in a scratch adopter holding a `uv` project, an npm workspace, a Poetry project, a Gemfile and a Cargo package, the over-refusal lines and AC-4's reader forms shall get AC-4 and AC-7's verdicts through the real hook protocol for Claude Code, Codex and Grok; evidence: the journey output.
