# TSK-1053: Runner directory grammars

## Description

Source: the operator's TSK-1002 scope decision of 2026-10-28 (the option
D scope in Fable's note `target/tsk1002-option-d-scope.md` in the
`guard-bypass-classes` worktree, recorded in `RELEASE-PLAN.md`), with
Codex review 04's per-runner table and Fable review 06's runner section
(PR 346 at `399594818`) as input, and Codex reviews 01 and 02 of PR 390
with the coordinator's decisions on them (2026-10-28).

Package and project runners (`uv run`, `npm exec`, `poetry run` and the
like) start their command in a directory their options, environment or
configuration choose. The guard does not model them, so at `399594818`
every such runner makes the directory unknown
(`security/outward.rs:1661`, `unmodeled_launch`; `MODELED_LAUNCHERS` at
`:1623`), and TSK-1002's unknown-directory rule then refuses all inline
code under them. That refusal is sound but costly: agents run these
lines constantly. Under the option D scope, a runner's child directory
leaves the text guard's promise unless a grammar reads it; this task
writes those grammars.

This is a follow-up of TSK-1002. TSK-1002 is a standalone task whose
record is not on this line yet (PR 346, open at `399594818`), so the
`depends_on` edge to it is added by the epic amendment that follows PR
346's landing. Two prerequisites are verified before this task is
unblocked: PR 346 has landed, and TSK-1002's landed record names this
task in `follow_ups` (neither PR 346's published record nor its newer
local history at `c1dccabd2` does yet, per Codex review 01 of PR 390).

The change: **the guards read where `uv run`, `npm`/`pnpm`/`yarn exec`,
`npx`, `poetry run` and `bundle exec` run their command, through one execution-context representation shared with
the existing directory grammars (`env -C`, `ruby -C`, `tar -C`), so
reader words and inline code under them are judged in the right
directory. A grammar applies only when the runner's and the launched
program's execution identities are established; an option the grammar
does not list, or an identity it cannot establish, leaves the directory
or the program unknown and refuses as today.**

Execution identity, as in TSK-1052: a name stands for a program only
when it resolves, at judgment time, to an executable the requester
cannot substitute. The guard checks the lookup state it can see,
same-line and inherited (`PATH`, hash bindings, aliases, shell
functions, exported functions), and the runner's own lookup for the
child (`node_modules/.bin` up the project walk, the project's virtual
environment, Bundler binstubs); the resolved file after links must lie
outside every location the session can write (the sandbox's write set
where TSK-397's `sandbox_state` establishes containment, every location
the session user can modify elsewhere). Fable review 06 suggested
identifying runners by name; the operator's security rule and design D's
removal of name-based exemptions (`tsk-397-design-D.md:61`) take
precedence, so no allowance here rests on a name alone. A child that
resolves inside a writable location, such as a regular `python` file in
`.venv/bin` or a `node` in `node_modules/.bin`, is an unmodelled
program.

Directory rules to model, from the reviews and the runners' docs, each
confirmed by AC-1 before it is built:

| Runner | Child directory | Notes |
|---|---|---|
| `uv run` | the invoking directory | `--directory DIR` (also `uv --directory DIR run`) and `UV_WORKING_DIR` move it; `--project DIR` changes project discovery, not the directory; environment-file options change the command's environment |
| `npm exec`, `npx`, `pnpm exec`, `yarn exec` | the nearest project root, found by walking up from the invoking directory (ancestors only) | `-w`/`--workspace` (repeatable), `--workspaces`/`--ws`, `--include-workspace-root`, `--prefix`, `-C`/`--dir`, `--cwd`, `npm_config_*` variables and project configuration move it; `--call`/`-c` runs shell text |
| `poetry run` | the invoking directory | `-C`/`--directory DIR` moves it; `--project`/`-P` does not |
| `bundle exec` | the invoking directory; no directory option | `BUNDLE_GEMFILE` names a Ruby file Bundler evaluates; `RUBYOPT` passes Ruby options |
| `cargo run --` | the invoking directory | words after `--` are the built program's arguments, never a nested interpreter call or inline code; cargo's own directory options and a configured target runner need their own treatment; the built program lives in writable build output, so its identity is not established |

Over-refusals this lifts where both identities are established, each
refused at `399594818` (Fable review 06, "The runner over-refusal"):
`uv run python -c 'print(1)'`, `poetry run python -c ...`,
`bundle exec ruby -e ...` and `npm exec -- node -e ...`.

`cargo run -- python3 -c ...` is not lifted. Its trailing words are the
built program's data, not inline code, and the guard classifies them
that way; but `cargo run` builds the program into writable output and
runs it (Cargo's `cargo run` documentation), so the built program's
identity is not established and it is judged as an unmodelled program.
Every `cargo run` row the base refuses keeps refusing, and the refusal
names the unestablished identity, not inline code. The classification
changes the reason, not the verdict.

`direnv exec DIR` is not modelled. Fable review 06 assigned it the child
directory `DIR`; Codex review 02 of PR 390 showed from direnv's source
(v2.35.0 `internal/cmd/cmd_exec.go`, `internal/cmd/rc.go`) that it uses
`DIR` to discover configuration, searching ancestors too, loads that
environment, resolves the child through the loaded `PATH`, and runs it
without changing the directory. The guard cannot establish that
environment or the child's identity from text, so under the operator's
rule to remove what cannot be made sound, `direnv exec` stays an
unmodelled runner with the unknown-directory rule.

Precedence where rules meet:

- TSK-397's strict branch: a grammar never relaxes a refusal the strict
  branch makes for a known directory; it only supplies the directory and
  the launched program.
- TSK-1052's rule: where containment is not established and a same-line
  write precedes the runner, TSK-1052's refusal prevails and the grammar
  decides nothing about the run.
- Neither precedence lets a line the base refuses become allowed outside
  the one reasoned list of AC-8.

Non-goals: what the launched program does once it runs (outside the
promise under option D); runs after a same-line write (TSK-1052);
allowing any `cargo run` row the base refuses; `direnv exec` and runners
not listed above, such as `pipx run`, `uvx`, `bunx`, `pnpm dlx` and
`yarn dlx`, which keep the unknown-directory rule.

## Outcome

After this merges, an agent can run inline code that names no protected path under `uv run`, `npm exec`, `npx`, `poetry run` and `bundle exec` without being refused wherever the runner and its program resolve to executables the session cannot replace, and the guards judge reads under each of those runners in the directory that runner uses.
