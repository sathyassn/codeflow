# TSK-1436: An epic's own completion stays bound across a clean merge of main

## Description

An epic's acceptance block is written at close, and `main` may move and be merged into the line after that. Today the epic block is refused after such a merge (`crates/codeflow-core/src/workgraph/acceptance.rs:1087-1112` on `main` at `f8aabc62c`, from issue 770's reading), so adopters set `git.work_records: warn` to get past it. This task keeps the epic block bound across a merge that passes TSK-1434's conditions. Non-goal: a new `work_records` switch; once this ships, adopters who set `warn` for this case can return it to `block`.

Landing on its target (`main`, alone, early):

- Reachable: an epic's close survives a clean merge of `main`.
- Inert: nothing else changes.
- Other lines: nothing.

## Outcome

After this merges, a maintainer can close an epic and still merge `main` into its line cleanly afterwards without the epic's completion being refused.
