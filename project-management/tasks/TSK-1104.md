# TSK-1104: Read-only git stays allowed while the policy authority is unresolved

## Description

Issue #440 (2026-10-31) reports the state the coordinator found on
2026-10-30 (queue item 27): while a planning amendment on a line retargets a
task record and `main` still holds the old target, `landed_policy::declared_target`
refuses every hook call on that task's branch, `git status` included, with
"landed task records disagree on the policy target". TSK-1077 (PR 441 at
`1ddbac7cc`) removes the cause: `landed_policy.rs` no longer reads task
records, `declared_target` and the records-disagree refusal are gone
(`crates/codeflow-cli/tests/policy_authority.rs:167`), and the
`ends_with("/<target>")` match the issue's last point names is gone from
`landed_policy.rs` (`cmd/ci/context.rs:384` keeps a `declared_target` for
range bounding, without `ends_with`). Verified by the TSK-1077 builder on
2026-10-31 07:50 and read again when this task was planned.

What stays open, and is this task: every guarded command still refuses when
the authority cannot be resolved at all (`hook.rs:260-268`, `479-487`,
`530-535`; `git_guard.rs` `check_authority`), `git status` and
`git rev-parse` included, while the guard already allows read-only git when a
target is unresolved (`git_guard.rs:6767-6776`, test at `10974-10997`). The
issue asks for read-only git while authority is in doubt, a journey test for
the amendment-in-flight state, and the refusal to name the refs and the
clearing step. Allowing anything while the authority is unknown is a security
decision, so this task records it with the exact command set and why none of
those commands can change refs, configuration, hooks or the working tree.
Non-goals: no mutating command is allowed without a resolved authority; the
policy source rules of TSK-1077 and TSK-1057 are unchanged.

## Outcome

After this merges, an agent whose policy authority cannot be resolved can still read the repository state with git and sees a refusal that names the refs involved and the step that clears it, while every mutating command stays refused.

## Deliverables

- the read-only allowance while the authority is unresolved: `crates/codeflow-core/src/hooks/git_guard.rs` (`check_authority`), `crates/codeflow-cli/src/cmd/hook.rs` (the three guard entry points)
- the refusal text naming refs and the clearing step: `crates/codeflow-core/src/hooks/landed_policy.rs`, `crates/codeflow-core/src/remedy.rs`
- the amendment-in-flight journey test: `crates/codeflow-cli/tests/refusal_journey/landed.rs`
- the planning rule for a retarget of records already on the default branch: the managed source `assets/base/agents/skills/cf-plan/SKILL.md`, with its installed `.claude/skills/cf-plan/SKILL.md` and `.agents/skills/cf-plan/SKILL.md` mirrors byte-identical and the manifest entries unchanged

## Findings

Read on the line tip `31f7df8f7` (TSK-1077 merged), 2026-11-01, before any
code change.

- Refusals before the command is parsed: `landed_policy::load` fails in
  `hook.rs` git-guard, exec-guard and edit-guard. git-guard and exec-guard
  exempt only `ref_authority::recovery_fetch` (one plain configured-remote
  `git fetch`); edit-guard exempts nothing. So `git status` is refused in
  all three, and exec-guard runs on every Bash call, so it blocks read-only
  git too.
- `git_guard.rs` `check_authority` re-runs `landed_policy::load` per target
  and refuses any command whose target authority fails to load; it runs
  only after `hook.rs` has loaded the session authority.
- The read-only set the guard already allows for an unresolved target is
  `discard_readonly_git` (status, diff, log, show, rev-parse, ls-files,
  ls-tree, merge-base, for-each-ref, show-ref, cat-file, check-ignore, help,
  version; never with `--output`). It is a fixed list, not derived.
- Causes of an unresolved authority (`landed_policy.rs`): unset
  `refs/remotes/<remote>/HEAD`, a HEAD naming a non-branch or a missing ref,
  a remote with refs but no tracking refs, an ambiguous remote. The
  messages already name the ref and the clearing command
  (`git remote set-head origin -a`, `git fetch`).
- Adjacent concerns: `help` starts a viewer program chosen by configuration,
  so it is left out here. `diff --ext-diff` or `--textconv`, a pager
  (`--paginate`, `-c core.pager=`, `GIT_PAGER`), `--output`,
  `--open-files-in-pager` and `--no-index` (reads files outside the
  repository) can run a program or write or read elsewhere. Global options
  (`-c`, `-C`, `--git-dir`, `--exec-path`) and leading assignments change
  configuration or location. A fetch with a credential helper is not
  read-only and stays out of scope; the recovery fetch is unchanged.
- Other tools (read 2026-11-01). Claude Code's permission system runs a
  built-in set of read-only commands without a prompt in every mode, still
  prompts for compound commands unless every part is allowed (separators
  `&&`, `||`, `;`, `|`, `|&`, `&`, newline), checks redirect targets, and
  prompts for `git` with an unquoted glob because a glob could expand to a
  write-capable flag
  (https://code.claude.com/docs/en/permissions, "Read-only commands" and
  "Compound commands"). That matches the chosen form: a fixed read-only
  list, every part judged, no redirects, no globs. The git configuration
  manual names settings that make read-only commands run programs
  (`core.fsmonitor`, `core.pager`, `diff.external`, `diff.<driver>.textconv`,
  `gpg.program`; https://git-scm.com/docs/git-config, only the first 100000
  characters of the page were read, so these names are from the tool's
  summary of that page and git's documented behaviour, not quoted lines).
  Those settings sit in repository configuration, whose writes the guards
  already refuse; the command-line routes to them (`-c`, `--ext-diff`,
  `--textconv`, `--paginate`, `--show-signature`) stay refused here. No
  git hooks manager or policy agent documentation was read.

Chosen scope: with the authority unresolved, git-guard and exec-guard allow
a line only when every simple command is a plain `git <subcommand> ...` with
a subcommand in the existing set minus `help`, no global option, no leading
assignment or launcher, none of the options above (abbreviations included),
and the line has no redirect, substitution, pipe or backtick. Everything
else keeps the present refusal, which now says read-only git stays allowed.
edit-guard is unchanged.
