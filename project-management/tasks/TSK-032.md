# TSK-032 — Integrate responsible autonomy contract

## Description

Integrate the approved responsible-autonomy kernel into CodeFlow's existing
always-loaded contracts and extend the existing quality, security, delegation
and customization owners with missing operational detail. Preserve ordinary
authorized research, tests and recoverable project work; do not create a new
safety subsystem or silently change default policy and harness permissions.

## Affected surfaces and interfaces

Canonical `assets/base/AGENTS.md.tmpl` and `AGENTS.minimal.md.tmpl`;
orchestrator `quality-contract.md`; `cf-security-reviewer`; `cf-delegate`;
`cf-customize`; evaluator requirements/source markers; focused orchestration,
settings, security, mirror and byte-budget tests; affected managed copies and
release documentation. Authority/data boundaries include purpose, action,
resource, destination/recipient, data class and material side effects. The
production Codex profile's technical no-prompt/full-access posture must be
described honestly and never confused with task authorization.

- [ ] Both canonical entry templates carry the complete compact kernel without
      raising current byte limits or deleting existing workflow, review, Git,
      safety, presentation or evidence duties.
- [ ] The detailed owners require authorized and minimized personal/confidential
      data use; synthetic/redacted fixtures; no leaks through prompts, URLs,
      logs, screenshots, traces, feedback, Git or peer handoffs; and no unrelated
      private search. A qualified route does not authorize every data class.
- [ ] External action is judged by effect rather than verb: reading/drafting is
      not sending/publishing/committing, changed scope or recipient receives a
      fresh grant, and uncertain non-idempotent mutation is inspected before
      retry. Already-authorized unchanged safe steps do not re-ask.
- [ ] Recovery guidance distinguishes reversible and compensating actions,
      preserves safeguards and evidence, avoids unauthorized cleanup, and stops
      the affected risky action when required authority or controls are absent.
      Existing non-relaxable prohibitions remain prohibited after operator
      approval; the agent explains the permitted alternatives and consequences.
- [ ] Delegation narrows authority and data to the bounded assignment while
      retaining useful already-authorized processing and accountable
      postcondition review.
- [ ] Customization/control wording distinguishes task authority from harness
      prompts and actual enforcement. Missing required hard controls withhold
      only the affected risky lane; no settings-only PII or communication
      protection claim is introduced.
- [ ] Focused semantic, source-marker, mirror and artifact-budget tests pass;
      existing non-relaxable clauses and evaluator IDs remain intact.
