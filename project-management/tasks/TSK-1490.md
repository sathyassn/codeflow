# TSK-1490: The guards read a command a program runs from an option value

## Description

Some programs run another command that is given to them as an option value. Each guard reads such a command only for the programs and options in its own inventory of known carriers, and some programs that run a command from an option value are in none of them. A command placed in one of those values is not judged as the same command written bare would be. Severity is high for this class (coord/catalog's rating); the detail stays in private review evidence until the fix is on `main`. The git hooks and the forge rules still apply where they cover the same action.

TSK-1476 closes this for one verb in its own module and leaves the carrier inventories unchanged. The gap is already on `main`. It was found by the review sweep of TSK-1476 (coord/catalog, 2026-11-12), and no open record holds it.

## Outcome

After this merges, a command that a known program runs from an option value gets, from each guard, the same verdict by the same rule as that command written bare. Both guards' command readers take their carriers from one inventory, and the documented launcher inventory matches it. Ordinary values that run no command keep today's verdict.

## Deliverables

- one inventory of the programs and options that run a command from an option value, extended to every such option of the programs the guards know, and read by git-guard's and exec-guard's command readers in place of their separate lists
- the documented launcher inventory in the code matched to it, with a test that fails when they differ
- tests fed as hook payload strings, following the private matrix; nothing under test is executed
- the change in the guard documentation in class words, and in the release notes' list of new refusals

## Estimate

- Grade: Medium; band: Medium (2 to 4 h); moved: none (new, from TSK-1476's review sweep)
- Split: not needed; one outcome (a carried command is judged as the bare one)
- Basis: one inventory replacing two readers' lists, an equivalence test per guard, and an inventory equality test, with a hook-entry journey. Graded by coord/records under issue 334's bands; the builder re-scores at claim.

## Acceptance Criteria

- AC-1 For each program and option in the inventory, each guard shall give a command carried in that option value the same verdict, by the same rule, as it gives the same command written bare. Evidence: per guard and per option, test rows from the private matrix in two groups: newly exposed cases, which fail before the change and pass after, and cases already refused before, kept as regression controls that pass before and after. Each row asserts the finding comes from the rule the bare command meets, not from an unrelated refusal.
- AC-2 Option values that run no command, and programs and options outside the extended inventory, shall keep today's verdict, as shall every form the new reading does not reach. Evidence: control rows passing before and after.
- AC-3 The launcher inventory documented in the code shall name every program and option the guards read this way, and a test shall fail when it and the guards' inventory differ. Evidence: the test and the diff.
- AC-4 The guard documentation shall describe the change in class words, and the release notes shall list it among the new refusals (operator decision D5, 2026-11-12). Evidence: the doc diff, the changelog fragment and `codeflow validate --docs`.
- AC-5 The change shall get one cross-family security review with the `cf-security-reviewer` checklist. The pull request shall state the threat it closes and why one inventory read by both guards' readers is the fail-closed design. No program, option, payload or command form shall appear in the pull request title, its body summary, any commit subject, the changelog fragment, the guard documentation or a test name until the fix is on `main`. Evidence: the review row, and the pull request as opened, checked by the reviewer.
- AC-6 (journey) With the built binary, a scratch project shall refuse, through the hook entry, a payload that places a refused command in such an option value, and shall pass the same program with an ordinary value. The output of each guard that judges the payload shall be captured, and each refusal shall be the rule the bare command meets. Evidence: both outputs.
