# TSK-182: Report a CI pin only for a recognized pinned install

## Description

`codeflow doctor`'s `ci-perimeter` check claims a verified target pin for
any CI file that contains the text `scaffold_version`
(`crates/codeflow-core/src/doctor/mod.rs:1571` at `352fcf9b2`). A workflow
whose only mention is a comment, or one that reads the pin from the head's
own `.codeflow/project.toml`, is reported as installing the version the
target pins, verified against its `sha256.sum`, though it does neither.
Codex found this in its engineering review of TSK-095 (`352fcf9b2`, finding
C095-2, P2); its probe ran the built doctor on both file shapes and got the
verified-pin message each time. The TSK-095 perimeter tests use
comment-only fixtures, so they keep the false assurance. The fix reports a
pin only for an install doctor can recognize as the shipped pinned,
checksum-verified structure, and reports any other install as unverified.
This is a false assurance in a reporting check, not a bypass of CI
enforcement.

Non-goal: proving what a CI runner does at run time. Doctor reads files;
it states what the file it recognizes installs, and says when it cannot
tell.

## Affected surfaces and interfaces

- `doctor`'s `ci-perimeter` check in `codeflow-core`
  (`doctor/mod.rs`, `doctor/ci_pin.rs`) and its tests; CAP-008 doctor
  reporting. The check's name and status levels stay; its message for an
  unrecognized install changes.
- No CI template, policy key or CLI flag changes.

## Acceptance Criteria

- AC-1 When the CI file doctor finds mentions `scaffold_version` only in a
  comment or in a step that installs no codeflow release, doctor's
  `ci-perimeter` check shall not report that CI installs the version the
  target pins or that it is checksum-verified, and shall say it cannot
  verify how that file installs codeflow; evidence: a doctor test with the
  review probe's comment-only workflow, red at the TSK-095 landing commit.
- AC-2 When the CI file reads `scaffold_version` from the checked-out head
  rather than from the target commit, the check shall report the install
  as unverified, not as target-pinned; evidence: a doctor test with the
  review probe's head-pin workflow, red at the TSK-095 landing commit.
- AC-3 When the CI file installs a pinned release without checking it
  against the release's `sha256.sum`, the check shall report the install
  as unverified; evidence: a doctor test with a pinned install whose
  checksum step is removed, red at the TSK-095 landing commit.
- AC-4 (serves EPC-020 AC-7) When the CI file is an unmodified shipped
  template (the GitHub `codeflow-ci.yml` or `codeflow-policy.yml`, or a copied
  `.gitlab-ci.yml`, `bitbucket-pipelines.yml` or `ci-generic.sh` whose
  shared pinned run matches the shipped text), the check shall keep the
  TSK-095 report: the pinned version, a missing or lowered pin, and the
  two-step order; evidence: the TSK-095 perimeter tests, with their
  comment-only fixtures replaced by the shipped template text.
- AC-5 When a recognized template has been edited inside its install or
  pinned-run section, the check shall report the install as unverified
  rather than infer enforcement from marker text; evidence: a doctor test
  that edits one line of the shared pinned run.
