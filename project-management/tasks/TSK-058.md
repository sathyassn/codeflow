# TSK-058: visual explanation doctrine and figure grammar

## Description

Write the visual explanation doctrine into the two presentation skills as a
figure grammar: nine figure families keyed to the relationship they encode
(flow, structure, layering, sequence, state, coverage, extent, derivation,
graph), twelve rules every figure obeys (one governing idea, every mark
keyed, two channels never hue alone and both measured off the render, legible
at render size with the floor measured on every inner mark, narrow recomposes
with its own mark set rather than elongates, declared facts derived from
source, no text boxes as the primary form, no text printed over text or over
a mark, a one-sentence caption, token-only colour, a description and a table
twin), and the altitude contract (which family answers which reader question
at Concept, Architecture and Technical; Concept owns what the subject is, who
it is for and what it is not; an ordinary how-to section carries a figure in
the sequence, state or extent family; prose around a figure is short and
plain, with bullets where they help and no em or en dash). Carry one inline SVG
specimen per family, distilled from the W5 board's `shared/svg.js` mark
vocabulary and its recorded lessons, and point at `docs/verification/tsk-014-w5/`
as the evidence board with its chat and Markdown baselines as the negative
controls. Add the chat rule to the lifecycle reference: the same families,
expressed in ASCII. Record the decision in a new ADR that supersedes the stage
grammar as the default form and carries the figure declaration schema as the
decision of record. The ADR number is allocated at task start from the
highest ADR across this tree, `integration/EPC-015-engineering-bar`,
`integration/EPC-017-operating-doctrine` (which holds ADR-0067) and
`origin/main`, and is never renamed. Non-goal: no runtime code; TSK-059 owns
that, including rendering the specimens through the runtime; the design
system kit is TSK-070's.

## Acceptance Criteria

- [ ] When an agent reads either presentation skill, it finds the nine
      families with the relationship each encodes, the geometry, and the
      non-colour channels that carry state, in one table; evidence: the
      resource file and a clause pin in `manifest_consistency.rs`.
- [ ] Each family has one inline SVG specimen that draws with the utility
      tokens only, carries a legend, a description and no literal colour, and
      obeys the twelve rules by inspection; evidence: the nine specimens in
      the resource file reviewed by the design primary in light and dark
      (rendering through the runtime is TSK-059's evidence).
- [ ] The twelve rules and the altitude contract are stated once, with the
      masked-title test, the inner mark floor, the two-channel measurement,
      the overprint rule, the narrow variant rule and the fidelity rule each
      given a threshold or a method that the token sheet, the grammar module
      or the portal configuration declares; evidence: the resource file, the
      ADR.
- [ ] Every bare "design-exploration board" reference across the eight
      files in the two skill trees resolves to `docs/verification/tsk-014-w5/`
      with its baselines named as controls, and the W5 lessons (confusable
      pairs, inner mark floor, overprint, elongation by reflow) appear as
      named anti-patterns; evidence: grep of both skill trees before and
      after, recorded in the closeout.
- [ ] The lifecycle reference carries the chat rule: family choice is the
      same, the medium changes the marks, an ASCII figure is drawn only when
      a relationship carries the point; evidence: the paragraph and its pin.
- [ ] Both skill copies, the `.agents` mirrors and the `assets/base` sources
      are byte identical and the manifest hashes match; `codeflow update` on
      a scaffolded sample carries the new resource; evidence:
      `manifest_consistency` and a harness `update` row.
- [ ] Editorial review of the resource and the ADR, and Grok adversarial
      review; every finding dispositioned; evidence: the review records.
