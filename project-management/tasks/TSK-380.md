# TSK-380: A search pattern given to rg or grep is never read as a write target

## Description

Issue: #242. A read-only search is refused as a shell-startup write. `rg --files | rg '/CHANGELOG.md$'` gets "`rg` takes `/CHANGELOG.md$`, which the guard cannot resolve, and its directory is `/`" under `security.shell_startup` (`crates/codeflow-core/src/security/startup.rs:2740-2750`). The argument is a search pattern, and the command writes nothing. The adopter's workaround is to avoid searching. The same reading applies to `grep` patterns.

Outcome: **a search tool's pattern argument is never read as a path it writes, and a read-only search is never classed as a shell-startup write.**

The pattern operand is the first operand of `rg`, `grep`, `egrep`, `fgrep`, `git grep` and `ag` when no `-e`, `-f` or `--regexp` supplies it, and every `-e` or `--regexp` value. Paths those tools write stay judged: `rg --pre <program>`, `grep` has none, and an output redirect is judged as any redirect.

Added by the EPC-022 amendment of 2026-10-18 under the operator's release decision of that day (workspace `RELEASE-PLAN.md`, 2026-10-18 operator decision).

- AC-1 When `rg`, `grep`, `egrep`, `fgrep`, `git grep` or `ag` receives a pattern that looks like an absolute or unresolved path (`'/CHANGELOG.md$'`, `'^/etc/.*'`, `"$HOME/x"`), as its first operand or through `-e` or `--regexp`, exec-guard and git-guard shall not refuse it under `security.shell_startup`; evidence: one guard test per tool and pattern form, failing before the change. (serves EPC-022 AC-76)

## Review repair decisions

Round 1 at `c03b082dc` (cf-security-reviewer changes_requested; Grok 4.7 approved with nits). The primary settled these choices; the repair follows them.

- F-1 (high): a pattern word is skipped only when the shell passes it as one argument with the text written: quoted, or free of unquoted `* ? [`, brace forms, `$` and backtick expansions (zsh pattern characters, a leading `~` and a leading `=` count too). Any other word is judged as before, on its raw token.
- F-2 (high): under GNU `parallel` no word is a pattern word unless `-q` or `--quote` is given; `parallel`'s options are parsed, so the command after `-j 4` is found.
- F-3 (low): a line that names `RIPGREP_CONFIG_PATH` anywhere (an assignment, `read`, `printf -v`, `declare`, `typeset`, `export` or any other use) keeps the `rg` first operand judged.
- P-1 (high, present on the base, folded in because this task owns the `rg` grammar): `--pre` or `--pre-glob` on the line makes `rg` a recursive writer of every root it searches, the implicit working directory included. exec-guard refuses a root that is a class file, a placement directory, unresolved, or one below which a `.envrc`, an escaping link or more than 4096 directories lie; git-guard refuses a root that holds enforcement files. `--pre` under `xargs` or `parallel` refuses. `rg --pre pdftotext needle docs/` stays allowed.
- Grok N1 (fix now): a wrapped `git grep` under `xargs` or `find -exec` reads its pattern as plain `git grep` does.
- Grok N2 and N3: dropped. Security P-2 (`parallel` `{= perl =}` replacement strings) is tracked under TSK-378 and stays out of scope.
