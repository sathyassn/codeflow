# TSK-1173: A claim is one step that records the task's start

## Description

Issue #334 item F and section 1.5 ("claim and start are one step"), under
operator decisions D1 and D4 (2026-11-01). Today `work claim` pushes an empty
branch and prints "check it out and run `codeflow work start`". The task's
start is only the first later commit, and a squash landing loses even that
(`ADR-0079:42-44`). This task makes the claim the one step that starts the
clock.

Outcome: **after this merges, `work claim` creates the task branch and its
worktree, commits `claimed:` and `claim_base:` into the task's record as one
commit, pushes the branch with that commit and runs the start preflight;
`estimate outcomes` takes the `claimed:` time as the start when it is the
task's own claim; `work start` stays the read-only re-entry check for a
resumed session and CI; and a claim with no later commit reads as an idle
claim with its age.**

Design (settle in the PR; recommendations from the start-clock research):

- One commit on the task branch writes `claimed: <RFC3339>` and
  `claim_base: <40-hex sha>` into the record frontmatter (the one-line edit
  `task status` already makes, `status_verb.rs`), using `git commit --only`
  on the record path. In git, so ADR-0079's derivation holds and a squash or
  rebase landing keeps the start; the record's own PR may change its record
  (ADR-0076). Rejected: a ledger event (not in git, lost on a clone) and the
  pushed branch's creation time (not stored in git).
- Order for a fresh claim: branch, worktree, the claim commit through
  `status_verb::replace_if_unchanged`, create-only push, preflight, with an
  attempt file in the worktree's git directory. The record is restored before
  any rollback; only a verified-disposable worktree and branch are rolled
  back, and never after the claim commit exists.
- Order for an adopted (TSK-1093) or renamed branch: push as it is,
  create-only, so a lost race leaves the local branch unchanged; then write
  the two lines in the worktree where it is checked out, commit with
  `--only`, and push that commit with a lease. A staged or modified record
  file refuses the claim. A re-run resumes only on the two cases the attempt
  file proves; a lost race never resumes.
- Start rule: the `claimed:` time; for an adopted or renamed branch the
  earlier of that and the first commit after `claim_base`, with provenance
  `known`, `declared` (the line readable, the commit or base not) or
  `unknown`. A hand-written line is read as declared, not as a claim.
  `refresh_claim` keeps the first time.
- `codeflow ci` classification is not changed. The task's own `claimed:` edit
  selects `Tracked` and meets no new admission requirement (read from
  `classification.rs:217-230` and `:926-1067`; this task proves it with
  fixtures).
- Hotspots read first: TSK-1093, TSK-1125, TSK-1047, TSK-341, TSK-416 and
  TSK-1105 (both this task and TSK-1105 edit `readiness.rs` and `work.rs`;
  one writer at a time, the Coordinator's call; this task first, since it
  sets the shape).

Non-goals: an idle threshold or automatic release (D3, decided: flag and
hand over only); a new verb (`ADR-0057:48`); changes to classification.

## Acceptance Criteria

- AC-1 `work claim` shall be one step (D4): it creates the task worktree (or, for a branch adopted under TSK-1093, uses the worktree that already holds it), commits the `claimed:` record, pushes and runs the preflight, and `work start` shall stay read-only for re-entry and CI, creating nothing; evidence: a CLI fixture showing the worktree, the claim commit and the preflight from one claim. (old TSK-1012 AC-5) (serves EPC-022 AC-200)
- AC-2 After `work claim`, the recorded claim time shall be the task's start when it is the task's own claim, and for an adopted branch the start shall be the earlier of the claim commit and the branch's first task commit (D1); evidence: a CLI fixture, and an adopted-branch fixture with work at 10:00 and adoption at 11:00 that reports 10:00. (old AC-3 and AC-5, start half)
- AC-3 A squash landing on a live target shall keep the start from the `claimed:` line, and a squash with the branch gone shall report provenance `declared`; evidence: a fixture that squashes. (proposal TSK-1173 AC-2)
- AC-4 A claim with no later commit shall read as an idle claim with its age; `refresh_claim` shall keep the first claim time; a hand-written `claimed:` line shall be read as declared; evidence: fixtures. (old AC-3, idle half)
- AC-5 A claim-only range, a standalone range, a stacked range and an adopted range that pass `codeflow ci` classification and the pre-push run today shall pass with the claim commit added, and a range that is refused today shall still be refused; evidence: fixtures in `crates/codeflow-cli/tests/`.
- AC-6 A lost create-only push race, a hook refusal, a worktree failure and a preflight failure shall each leave the state the design table names (the record restored; only a verified-disposable worktree and branch removed, never with `--force`; nothing rolled back once the claim commit exists; the attempt kept and reported with its path); evidence: a fixture per failure.
- AC-7 `worktrees.md` "Work-start check" shall carry the idle-claim handover (an abandoned claim is recorded `blocked`, committed and pushed on the task branch, then the Coordinator reassigns the inactive holder's existing worktree to the next Worker, who inspects uncommitted work before staging anything; no branch is deleted and no claim time is lost), and the claim shall set no automatic release and no idle threshold (D3); evidence: the rule diff and a test that a claim is never released by the tool.
- AC-8 (journey) In a scratch adopter, claim, start, complete and squash-land a task on a live target; the task shall be timed from its claim; evidence: the journey output. Line deletion is TSK-1012's journey, not this one's. (old AC-3 journey)
