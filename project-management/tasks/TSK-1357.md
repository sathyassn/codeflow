# TSK-1357: The read benchmark's memory budget scales with its fixture's input size

## Description

The release benchmark's job, `codeflow gates (release benchmark)`, failed on
checkpoint PR 607 (the EPC-022 line into `main`), in job 127518916751 at line
tip 1107c5974. The failure was at `crates/codeflow-cli/tests/read_benchmark.rs:562`:
`over budget: validate --docs: peak 128516 KiB, budget 124582 KiB`. The
cause is fixture growth, not a regression in `validate --docs`. The
benchmark's 10,000 task and 10 epic records are the records the CLI itself
writes, and the task and epic templates grew from 2625 and 2801 bytes at the
Linux baseline's commit (9f4316cae, 2026-10-01) to 4759 and 5241 bytes on the
line, 1.81 and 1.87 times. The memory budget did not change with them; it was
1.5 times the baseline peak plus 16 MiB.

Measured with the CLI of each commit and the fixture's own record
transformations, the fixture's record bytes are:

```
commit                          record bytes   ratio to Linux baseline
9f4316cae  Linux baseline        26,676,877    1.000
e945b5ac3  macOS baseline        41,042,447    (macOS baseline input)
879a7a7fc  main                  37,779,397    1.416
447d3ffd7  line tip              48,541,777    1.820
```

On the failing Linux run, `validate --docs` peaked at 1.782 times its baseline
(128,516 against 72,132 KiB), under the input's growth of 1.820 times. orient,
status and work next peaked at 1.25 to 1.31 times. A separate probe on macOS
measured `validate --docs` at 122,016 KiB on main 879a7a7fc and 142,304 KiB on
line 1107c5974, a ratio of 1.166, against a line to main input ratio of 1.285;
the other commands moved by -0.2 to +4.6 percent. In both comparisons the peak
grew less than the input, so the scaled budget passes.

The memory budget now scales with the fixture's input:
`1.5 × baseline peak × (record_bytes now / record_bytes at baseline) + 16 MiB`.
The fixed 16 MiB does not scale, and nothing else does. A peak fails when it
is over 1.5 times its baseline scaled by the input's growth, plus 16 MiB. The
same peak fails against the baseline's input.

Scaling alone would loosen the limit for any command whose memory grows more
slowly than the record bytes. On the line, orient, status and work next peaked
at 1.25 to 1.31 times their baselines while the input grew 1.82 times. Scaled
from the old baselines, their Linux budgets would have been about 2.2 times
today's peak, against 1.6 times before, so a regression of over 100 percent
(about 235 MiB) would have passed. The review of 0a4c91672 found this (F1).
So the peaks are recorded again at today's input, 48,541,777 record bytes, and
scaling covers only template growth after that. The Linux peaks come from one
hosted benchmark log, run 42132133846 at 02e7bd904, which writes the same
records as the line tip. The macOS peaks come from one local run at
0a4c91672. The git process counts and latency ratios are unchanged.

A baseline without `record_bytes` fails closed. The latency and
git-process budgets are unchanged. Each baseline gains `inventory.record_bytes`.
To measure the growth, the earlier baselines' input was derived from the commit
each was recorded at. The Linux baseline was recorded at
9f4316cae. The macOS baseline was recorded at e945b5ac3 and only renamed at
9f4316cae, and its task template was then 4161 bytes. Each value comes from
the debug CLI built at that commit: `init --full`, `ids seed`, `epic new` and
`task new` wrote the templates, and the record transformations of `inventory()`
in `read_benchmark.rs` at this task's build head were replayed over all 10,010
records. The build PR keeps that replay where a reviewer can rerun it, and
explains why the macOS records average about 4,104 bytes against its 4,161-byte
task template. The same replay at the line tip gives
48,541,777 bytes, which the benchmark reports as `inventory.record_bytes` at
this head. No Windows baseline exists: the benchmark is Unix only.

## Outcome

after this merges, the release benchmark can hold each read command's peak memory to a budget that grows with the records it reads and with nothing else

## Deliverables

- the input-scaled memory budget, its tests and its module docs: `crates/codeflow-cli/tests/read_benchmark.rs`
- the baselines' input sizes: `crates/codeflow-cli/tests/read_benchmark_baseline-linux.json`, `crates/codeflow-cli/tests/read_benchmark_baseline-macos.json`
