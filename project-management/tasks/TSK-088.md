# TSK-088: outcome-first working and reporting, with one attention marker

## Description

Agents keep the real result, and who it is for, in view while they work and
when they report, and the operator can see at a glance what needs them. The
operator asked for this on 2026-09-25. Two independent design reviews (Fable
and Astra) found that CodeFlow already has outcome language, but it does not
carry the purpose of a task through execution and into the reply: a worker
sees a scoped node, criteria and a test list, and its report opens with
process. The same day the operator clarified the summary rule: a summary
anchors the reader with just enough context, as judgment, not a sentence
count or a list of banned items.

The change amends existing passages; it adds no section and no policy key.

| Rule | Owner, amended in place |
|---|---|
| 1. Outcome while working: name the result, who uses it in their terms, and the evidence that would establish it; hold the larger result only where it changes scope, priority or completion; use it at each choice (next, skip, done, stop); a gate or criterion is evidence toward the result, never the result; separate done here from what depends on other work; recheck on change; stay within scope and authority | "Work to the outcome" in `AGENTS.md.tmpl` and `AGENTS.minimal.md.tmpl` |
| 2. Criteria met, result missed is a finding that returns to planning, not a pass | completion gate in `quality-contract.md`; `cf-reviewer.md` step 7, verdict format unchanged |
| 3. Frame a non-trivial subject by its own parts as its consumer meets them; files and steps are the means; answer the question asked; not a checklist | `workflow-lifecycle.md` "Establish the route" |
| 4. Report order: the result and where it stands, then what would change it and who resolves it, then what the reader must decide or do; steps, gates, counts and tooling last. An order, not headings; labels only where the same reader compares reports; labels forced onto a short answer are a defect | lifecycle reply rule; "Shape the deliverable" in both templates |
| 5. Report owners, one sentence each, existing lists kept as detail | orchestrator joint closeout, `cf-develop` step 6, `pr-evidence.md` readiness report and Summary, PR template Summary comment, `autonomy.md` running report |
| 6. One NEED YOUR ATTENTION group per operator reply, after the opening, items starting with Decide, Do, Confirm, Clarify or Note and self-contained; none when nothing is owed; never in PR bodies, documents, commits, outbound drafts or machine payloads; tied to the ladder's ask and notify rungs; a project may rename or drop it in its own instructions | lifecycle reply rule, `autonomy.md` ladder, both templates |
| 7. A summary anchors the reader: what this is, why it matters, where it stands, in a few lines; a key number, file name, data point or caveat belongs there when it is part of that context | both templates, lifecycle, `pr-evidence.md`, PR template, `editorial-smells.md`, ADR-0067 (append-only note), CF-OUT-002 and its cases |

The decision is recorded in a new ADR-0071, with an append-only dated note
on ADR-0070 (readiness report order and the marker on the ask and notify
rungs) and on ADR-0067 (the summary judgment).

Branch reconciliation. This branch carries the older "two to four
sentences" summary rule. `main` carries the 2026-09-24 context-only rule
(ADR-0067 note, CF-OUT-002 `summary_carries_details`, and the PR Summary
code span and path warnings in `crates/codeflow-cli/src/cmd/ci/pr_body.rs`).
This task replaces every rendering present on this branch. The main-side
text and the `pr_body.rs` warnings arrive with the merge-forward, so TSK-086
gains that reconciliation: the main-side wording yields to ADR-0071 and the
Summary code span and path warnings are dropped or reworded so a key file
name is not flagged; length warnings may stay as soft guidance.

Non-goals: Agent OS (its own repository and pull request), the workspace
contract, a new policy key, a machine-readable marker, and any change to the
reviewer verdict schema.
