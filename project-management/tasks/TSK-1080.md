# TSK-1080: Remote protect writes three owned rulesets and never weakens a rule

## Description

Source: the content policy design for issue #279, revision 5, unit U5,
section 2.3, and decisions 1, 3 and 6 (operator, 2026-10-29). Closes
findings D-11 and D-13.

Today `codeflow remote protect` leaves the two-pull-request
self-authorization open and writes into rulesets it does not own:

- `crates/codeflow-core/src/remote.rs:746-781` writes `pull_request` at
  zero approvals, strict checks, `non_fast_forward` and `deletion`, with
  no `update` rule and no bypass actors;
- `:803-843` and `:874-898` update every ruleset that targets the branch
  in place, sending only `{"rules": ...}` (`:842`), so a foreign ruleset
  keeps its bypass list and gains rules;
- the target is the literal `refs/heads/<pattern>` (`:790`), although the
  matcher knows `~DEFAULT_BRANCH` (`:1009`), so a renamed default branch
  loses its rules (D-13).

Live state, read with the operator's `gh` on 2026-10-29 at 18:43Z (state
that can change; the builder re-reads it): `main` has ruleset 24379074
(`~DEFAULT_BRANCH`, strict, six names pinned to the Actions app id 15368,
no bypass) and classic protection with `enforce_admins: false`;
`integration/**` has ruleset 25435656 (non-strict: `codeflow gates`,
`windows`, `commit standards`, `release impact`; `non_fast_forward`;
`deletion`; no bypass).

The task makes `remote protect` write three rulesets it owns by name and,
once created, by id, for a declared profile, check identity and line
pattern:

- **A, "codeflow authority updates"**, on `~DEFAULT_BRANCH`: `update` with
  `update_allows_fetch_and_merge: false`; bypass exactly one
  `RepositoryRole` (administrator under `solo-administrator`, the merging
  role under `independent-review`), `bypass_mode: always`.
- **B, "codeflow authority checks"**, on `~DEFAULT_BRANCH`: `pull_request`
  (solo: zero approvals; independent: one, stale reviews dismissed, last
  push approval); `required_status_checks` strict with every name pinned
  by `integration_id` (the App's id for the `authority:` names when
  `--check-app <id>` is given, Mode A; else the Actions app id for the
  `trusted:` names, Mode B); `non_fast_forward`; `deletion`; empty bypass.
- **C, "codeflow line checks"**, on the line pattern (`--lines`, default
  `integration/**`): `pull_request` at zero approvals; the `trusted:`
  names and `codeflow gates` and `windows`, each pinned to 15368;
  **strict**; `non_fast_forward`; `deletion`; **empty bypass list, with no
  bypass for the merging identity**; no creation rule (line creation stays
  unrestricted by the operator's decision of 2026-10-27 21:40). C is for
  the line's integrity: a line receives content only through a pull
  request judged by the default branch's workflow, never rewritten or
  deleted. It is not for secrecy: a task-branch push publishes content
  before any check runs, which TSK-1078's local scans and TSK-336's
  hosted scan address. The session design for away mode depends on C being strict
  with no bypass: the host then refuses a merge onto a line tip the
  checks did not run against, whoever merges.

`doctor --check remote-perimeter` fails while B's or C's bypass list is
non-empty, so a recovery window cannot stay open unnoticed.

Owed by the operator, not agent work (decision 3, Mode A). Steps 1 to 5
may be done any time and change nothing until TSK-336 runs on `main`;
step 6 runs after TSK-336 is on `main`, in one session; step 7 has no
ordering dependency:

1. Settings, Developer settings, GitHub Apps, New GitHub App: a name such
   as `codeflow-authority-codeflow`, no webhook, repository permission
   Checks read and write only, "Only on this account".
2. Install the App on `sathyassn/codeflow` only; note the App id.
3. Generate one private key on the App and download it.
4. Repository Settings, Environments, New environment
   `codeflow-authority`; deployment branches and tags: selected branches
   and tags, `main` only.
5. In that environment, add the secret `CODEFLOW_AUTHORITY_APP_KEY` (the
   key file's contents) and the variable `CODEFLOW_AUTHORITY_APP_ID`.
6. After TSK-336 is on `main`: run `codeflow remote protect --check-app
   <id> --lines "integration/**"` as the administrator; retire rulesets
   24379074 and 25435656; run `codeflow doctor --check remote-perimeter`
   and stop only when it is green with no recovery window open. From
   TSK-336's merge until this step ends, every pull request into `main`
   and the lines is unmergeable (fail closed, by design).
7. Decision 1's agent principal: create a non-administrator principal
   with Contents and Pull requests write and Actions read (no Workflows,
   Commit statuses, Checks, Administration, Environments or secrets
   access), install it, point every seat's `gh` and git at it and remove
   the operator's login from the seats' stores.

This task's hosted fixtures run against a scratch repository, never this
one; this repository's rulesets are written only by the operator's step 6.

Non-goals: a `git.authority_profile` policy key, stored state, a
`--reduce` command (a reduction is the administrator's edit on the host),
retiring foreign rulesets by code.

## Outcome

After this merges, an operator can run `codeflow remote protect` to get three owned rulesets that bind the default branch and the integration lines to checks only trusted code produces, without weakening any existing rule, and `doctor` stays red while a recovery window is open.
