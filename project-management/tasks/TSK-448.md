# TSK-448: The docs portal takes the fixed fast-uri and undici releases

## Description

Advisories GHSA-333x-w4r6-6crp, GHSA-w74x-v6f9-j3xg, GHSA-wjr9-j795-jxcr and
GHSA-xhq7-xmqj-769h affect `fast-uri` 3.1.8, a dev dependency in the docs
portal and the shipped starter lockfiles; the fix is in 3.1.9. The dependency
audit in the security review job (osv-scanner, policy `git.dep_audit=block`)
now fails on every push and pull request on the EPC-022 line. The portal
`package.json` pins it with an exact `overrides` entry, so this task moves
that override to 3.1.9 in the portal and the starter `package.json` and
lets npm update each `package-lock.json` with the smallest change, and re-pins the portal state and the runtime
script list if a lockfile hash changes. It adds no audit suppression and no
new override, because a fixed release exists. Effect on adopting projects:
`codeflow update` installs the starter's new lockfile. Non-goal: other
dependency upgrades.

Three more advisories were published after the first scan, GHSA-4qv8-2p9j-2685,
GHSA-f72v-6w45-q472 and GHSA-xjj6-f33q-929c, against `undici` 8.10.2 (fixed in 8.12.2). They fail the same audit
and sit in the same two lockfiles. This task takes both fixes, so the audit
passes. `undici` comes through astro's own range, so `npm update undici`
moves it with no override.

## Deliverables

- the dependency fix: `docs-portal/package.json`, `docs-portal/package-lock.json`, `assets/docs-portal/starter/package.json`, `assets/docs-portal/starter/package-lock.json`
- the portal pins, where a lockfile hash changes: `.codeflow/docs-portal.json`, `docs-portal/scripts/runtime-scripts.json`, `assets/docs-portal/starter/scripts/runtime-scripts.json`
- the release note: `changelog.d/TSK-448.md`

## Acceptance Criteria

- AC-1 When the docs portal and the shipped starter lockfiles are read, each shall resolve `fast-uri` at 3.1.9 and `undici` at 8.12.2 or later, the `fast-uri` override shall read 3.1.9 in both `package.json` files, the diff shall change only the `fast-uri` and `undici` entries and any entry the update itself requires, and osv-scanner shall report none of the seven advisories on either lockfile with no suppression added. Evidence: `git diff` of both lockfiles, and osv-scanner on both before and after.
- AC-2 When the docs portal is installed and built from the committed tree, and the shipped starter is checked, it shall build and the checks shall pass. Evidence: `npm ci && npm run build` in `docs-portal`, `codeflow test --mode full --only docs-portal-deps,docs-portal`, the `manifest_consistency` test, and `codeflow test --mode quick`.
- AC-3 When the shipped starter is installed and built in a temporary project, it shall build with `fast-uri` 3.1.9. Evidence: `npm ci && npm run build` on the starter's files in a temporary project, and the portal Rust tests that read the starter. (journey)
