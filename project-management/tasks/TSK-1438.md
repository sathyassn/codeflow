# TSK-1438: The rules and managed block name two delivery units

## Description

The rules and the managed block still say one pull request per task and land work in batches. The delivery model after the 20 Nov ruling has two units. A task lands alone through its own pull request into `main`. An epic with a line lands its tasks on the line directly, with no pull request; `main` is merged into the line after each task, a clean merge judged by git's own merge and a hand-resolved hunk reopening review only for that difference; the epic reaches `main` once, through one pull request from the line after the close check. A pull request into an integration line does not exist. A landing candidate is transport only and "batch" leaves the unit vocabulary. Each file starts from what is on `main` when the task is claimed (TSK-1358 rewrites the same rule-map rows; this task takes its text). Non-goal: the planning rows ("shape a request", "take a new request"), which TSK-1443 owns.
