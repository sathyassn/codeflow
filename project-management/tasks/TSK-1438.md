# TSK-1438: The rules and managed block name two delivery units

## Description

The rules and the managed block still say one pull request per task and land work in batches. Under ADR-0102 there are two delivery units: a task that lands alone, and a marked epic whose tasks land on its line with no pull request. This task rewrites the rules and the managed block to describe both, the transition for unmarked epics, and a landing candidate as transport only; "batch" leaves the unit vocabulary. Each file starts from what is on `main` when the task is claimed (TSK-1358 rewrites some of them on the EPC-022 line). Non-goal: the planning rows ("shape a request", "take a new request"), which TSK-1443 owns.

Files, from the stale-text table of the epic delivery breakdown (sources on `main` at `f8aabc62c`, each with its mirrors under `.claude/skills/`, `.agents/skills/` and `.codeflow/.baseline/`):

- `assets/base/rule-map.toml:365-484`: "open the PR", "land a batch on the integration line" and the build row.
- `assets/base/AGENTS.md.tmpl:54-59`, `assets/base/AGENTS.full.md.tmpl` and `assets/base/AGENTS.minimal.md.tmpl`: rendered from the rule map.
- `assets/base/rules/git-rules.md:113-166`: "Bodies of work" and "PR bodies".
- `assets/base/rules/workflow-discipline.md:204` and `:327-329`: gate per landing candidate, batch landing.
- `assets/base/rules/worktrees.md:96` and `:157-177`: integrating in batches.

- CodeFlow's own `AGENTS.md:56-61` and `:132-150`: one pull request per task, "Landings batch"; its hosted-run sentences are TSK-1445's.
