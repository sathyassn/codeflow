### Fixed

<!-- codeflow:release-impact patch -->
- **`codeflow work next` no longer offers a task whose work has already
  landed.** When a branch carrying a task id has merged into the task's
  target with work beyond the task's own record, and the record is still
  open, the task is listed as `landed` with the `codeflow task status <id>
  complete` command to settle it, in the text output and in `--json`
  (`state`, `landed_branches`, `suggested_command`). `codeflow work claim`
  refuses it, naming the landed branch and the command. A branch that only
  filed or amended the task's own record does not count, so that task stays
  ready. `codeflow status` lists landed tasks the same way and `orient`
  counts them. A fast-forward landing is not detected, and nothing changes a
  status.
