### Added

<!-- codeflow:release-impact minor -->
- **A project can override managed instructions and keep the overrides
  through updates.** `.codeflow/overrides.toml`, which `codeflow update`
  never writes, replaces an always rule's text or title, a "When you are
  about to" row's action, or the body of a skill section a shipped
  `codeflow:section` marker declares. Every unit carries a class in the
  shipped text: `overridable` units are applied, `fixed` units (the review
  rows, whose policy lives in `.codeflow/model-selection.json`) are refused
  with their reason, and the units of the git floor and the non-relaxable
  command class are refused by the floor's name. Any problem, such as an
  unknown or duplicate target, a multi-line row value, a section body that
  would end the section, hold a marker or leave a code fence or raw HTML
  block open, or a change outside the targeted units, refuses the whole update before anything is written. Update merges
  hand edits against the shipped text with the overrides applied, records
  what each override replaced beside the baseline, and journals each
  overridden write so an interrupted update is finished, dropped or refused
  on the next run, after every journal and record is checked and before
  anything is written. `codeflow doctor --check overrides` lists each
  override with the shipped text it replaces and fails on an undeclared
  edit or a pending journal; doctor checks the effective text against what
  the binary computes, never against a digest stored in the project. The first declared section is
  `cf-present#completion`; see "Override managed instructions" in
  `docs/model-upgrades.md`.
