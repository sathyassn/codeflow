### Added

<!-- codeflow:release-impact minor -->
- **A project can override managed instructions and keep the overrides
  through updates.** `.codeflow/overrides.toml`, which `codeflow update`
  never writes, replaces an always rule's text or title, a "When you are
  about to" row's action, or the body of a skill section a shipped
  `codeflow:section` marker declares. Every unit carries a class in the
  shipped text: `overridable` units are applied, `fixed` units (the review
  rows, whose policy lives in `.codeflow/model-selection.json`) are refused
  with their reason, and the units of the git floor and the non-relaxable
  command class are refused by the floor's name. Any problem refuses the
  whole update before anything is written: an unknown or duplicate target,
  a multi-line row value, a section body that would end the section, hold a
  marker, leave a code fence, raw HTML block, list or quote open, or use a
  form Markdown readers disagree on (a carriage return, a fence or HTML
  block inside a list or quote or under indentation, indented code), or a
  result that changes anything outside the targeted units or reads as
  different Markdown blocks there. Override text must render everything it
  carries: only Markdown whose whole source shows as visible text, or plain
  structure such as paragraphs, emphasis, lists, tables, quotes and
  autolinks, is accepted, and any other form is refused with its name and
  byte offset. Links and images are refused, because the page does not
  show where they point; write an address as an autolink
  (`<https://...>`). Every character of the source other than ASCII whitespace
  and punctuation must also have a place on the rendered page, so
  text the parser drops without showing it is refused too. Code spans
  show their source and are exempt, and so are code fences with no label
  or a label that is one of the code languages listed in
  `docs/model-upgrades.md`, in any letter case. Any other fence label is
  refused, because a fence's label is not shown and some labels make the
  page draw the fence instead of showing its source.
  An override is also refused when it would push the end of
  the managed block of `AGENTS.md` past Codex's instruction limit. That
  limit is 32 KiB, lowered by a smaller `project_doc_max_bytes` in
  `.codex/config.toml` or in the Codex user config, never raised by either,
  because Codex skips an untrusted project's config, a command line flag or
  nested project config can replace the project value, and a profile can
  replace the user value. Flags, profiles, nested project configs,
  cloud-managed and system config are not read, so a limit set only there
  is not seen. A
  config that could lower the limit and cannot be read refuses too. Update
  merges hand edits against the
  shipped text with the overrides applied, records what each override
  replaced beside the baseline, and journals each overridden write so an
  interrupted update is finished, dropped or refused on the next run, after
  every journal and record is checked and before anything is written. A
  record is used only when each unit in it is one the binary lets a project
  override, at the place the binary finds that unit in the baseline, with
  only the entry's fields replaced and the row's pointers unchanged. When a
  new version renames an overridden rule's title or a moment's first cell,
  update refuses the old record; retarget, rewrite or remove the entry,
  delete `.codeflow/.baseline/<file>.overrides.json` and run update again.
  `codeflow doctor --check overrides` lists each override with the shipped
  text it replaces and fails on an undeclared edit, a pending journal or a
  record update would refuse. The first declared section is
  `cf-present#completion`; see "Override managed instructions" in
  `docs/model-upgrades.md`.
