### Fixed

<!-- codeflow:release-impact patch -->
- **A task waiver accepts its own planning amendment that also updates the
  plan.** In a task's own pull request, a waiver may name an amendment of
  the criterion that also changes the epic plan or other planning records,
  the same test an amendment on the target already meets. Before, an
  amendment in the task's own range had to change only the task's record,
  so a project split one decision into a record-only commit and a plan
  commit. The amendment must still change planning records only and amend
  that criterion of that record; a refusal off the target still names what
  "on the target" means and the planning route (issue #465).
