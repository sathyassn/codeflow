### Changed

<!-- codeflow:release-impact none -->
- **CodeFlow's own CI no longer needs test time measurements.** The Windows test
  partitions and the Linux coverage shards place each test by the hash of its
  name, so a new test cannot make the plan stale. The Windows partitions go from
  twelve to sixteen, end a test that runs past 12 minutes, and still fail a
  partition that passes the 24 minute margin.
- **A pull request into an integration line runs only the short checks.** Linux
  coverage and every Windows job leave it, and both required verdicts pass with
  those suites not selected; pull requests into main, line and main pushes and
  the weekly and manual runs keep every suite, as does any event or base the
  tier step does not expect. The daily run adds Linux coverage beside its
  Windows jobs on main and each active line, and its verdict reports each
  line's coverage total and fails one under main's floor. This changes this
  repository's CI only. No `codeflow` command, file, setting or release asset
  changes.
