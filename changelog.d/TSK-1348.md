### Added

<!-- codeflow:release-impact minor -->
- **One command sets up the GitHub Apps for Mode A and the agents' own
  identity.** A repository administrator runs `codeflow remote setup-apps`
  under their own `gh` login and clicks twice per App: "Create GitHub App"
  and "Install". It creates the authority App (Checks write only), the
  environment `codeflow-authority` restricted to the default branch with the
  App's key secret and id variable, and the agent App (Contents and Pull
  requests write only), whose key stays in the operating system's credential
  store. It refuses a GitHub App token and a token without Administration
  write before creating anything, changes no git identity or commit setting,
  and lists every write with what undoes it. `codeflow remote agent-token`
  gives agent sessions an hour-long installation token for `gh` and
  `git push` without printing the key. Pull requests and merges made with
  that token show the App's bot name; commits keep their human author, and a
  session that sets the two values `agent-token --committer` prints records
  the App as committer. Every commit rule still applies to those commits. A
  second run reads the agent App as itself with its own key, and reports a
  private authority App as present but not verified. `codeflow remote
  import-agent-key` stores another computer's key from a file. The agent App
  is optional, and `docs/github-apps.md` is the guide. The seven-step web
  procedure in the policy reference's "Mode A setup" is replaced by the
  command and the clicks. `codeflow doctor --check remote-perimeter` and
  `codeflow remote protect` now read only a real HTTP 404 as absence, so a
  failure that merely mentions 404 or Not Found reports as unreadable.
  `agent-token` and `import-agent-key` reach GitHub through the proxy variables
  with curl's certificate trust unchanged, and their errors name the real cause:
  a network failure no longer reads as a missing installation, and a locked
  credential store no longer reads as a missing entry.
- **Agent pull requests show the developer as author by default.** Each
  developer runs `codeflow remote agent-login` once, which authorizes the
  agent App through GitHub's device flow with no personal access token or
  `gh` login, and keeps the grant in the credential store.
  `codeflow remote agent-token --user` prints that developer's user access
  token for `GH_TOKEN`, renewing it silently; only a refused or expired
  authorization asks the developer to log in again. Pushes keep the
  installation token, with `--user --git-credential` as an option, and
  commits keep the developer as author and the App's bot as committer.
  `setup-apps` names the one click a manifest cannot make, "Enable Device
  Flow".
