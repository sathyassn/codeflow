### Fixed

<!-- codeflow:release-impact patch -->
- **Pinned review lookups tolerate a slow provider.** Work claims and
  starts allow one review-provider lookup up to
  15 seconds, so a slow response can complete beyond the former five-second
  limit. Timeout, provider failure and oversized output still refuse the
  pin with a named reason. Process cleanup and host scheduling add overhead
  to the lookup deadline.
  The same 15-second limit per pin applies to `codeflow ci` inferred-stack
  checks, including pre-push, and `work next` stack hints.
  An explicit pin that cannot be verified also refuses `work start` when
  `git.work_planning` is `warn`; ordinary planning findings, including
  implicit stacking, still follow the policy.
