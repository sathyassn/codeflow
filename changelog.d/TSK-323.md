### Added

<!-- codeflow:release-impact minor -->
- **Ignored and large files are judged by the default branch's rules, on
  by default.** This is a public behaviour change of 4.0.0. Pre-commit
  and `codeflow ci` now judge every new or changed file with two more
  rules, read with the policy, the project settings and the `.gitignore`
  files of the policy authority, never the working tree or the change, so
  a `.gitignore` or policy edit in a change admits nothing until it lands:
  - `git.ignored_files` (default `warn`): a file the authority's ignore
    rules exclude is reported, and refused at `block`. A tracked file is
    still judged. `allow: [{path, reason}]` admits a prefix.
  - `git.max_file_bytes`: in a project a fresh `codeflow init` creates,
    which writes `file_size_rule = "refuse"` to `.codeflow/project.toml`,
    a file over 1 MiB warns and one over 10 MiB is refused. In a project
    `codeflow update` brings forward, both are report lines and nothing is
    refused; the update report says how to opt in. Setting `limit` or
    `except_under` on the default branch opts in and replaces that part of
    the default; `except_under` names directories, never a single file.

  Sizes are of the blob git records, so a Git LFS path passes by its
  pointer. A merge is judged on every file it records that no parent
  holds. A size refusal names the admission routes: Git LFS, a `limit`
  or `except_under` change on the default branch through a reviewed pull
  request, and from 4.2.0 a per-path admitted row in the exemption
  register. Neither rule judges the gate's own inputs. Set either key only
  once every binary that judges the repository, the CI pin included, is
  4.0.0 or later. The matcher is the `ignore` crate (ADR-0092).
