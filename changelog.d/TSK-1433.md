### Changed

<!-- codeflow:release-impact minor -->
- **A task that lands on its epic line with no pull request names a
  reviewer of another lineage.** When the branch `codeflow ci` judges is an
  epic line, on the line's push and on the line's pull request into the
  default branch, each completion the range brings must name its reviewer
  before the first comma or semicolon of its acceptance block's `review`
  field. If the record's `- Builder:` line names a lineage, that reviewer
  must be of another one. Lineages are read from the model catalog built
  into the binary. A reviewer of the builder's lineage, or a review that
  names no known lineage, is refused under `work.acceptance_binding`, with
  the steps to record a review by another lineage. Both forms give the same
  verdict. The commit binding and the approved verdict were already checked
  in both forms. A task's own pull request and a push of its branch are
  judged as before.
