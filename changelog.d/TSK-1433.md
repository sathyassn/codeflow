### Changed

<!-- codeflow:release-impact minor -->
- **A task that lands on a whole-epic line with no pull request records who
  built it and who reviewed it.** On the line of an epic whose record on the
  default branch sets `main_landing: whole-epic`, `codeflow ci` checks each
  completion the range brings, on the line's push and on the line's pull
  request into the default branch, with the same verdict in both. The
  acceptance block names the one lineage that built the task in the new
  `built_by` key (`claude`, `codex` or `grok`, from the model catalog built
  into the binary), and the reviewer named before the first comma or
  semicolon of `review` must be of another lineage. A reviewer of the same
  lineage passes only with the new `reduced_assurance` key: a statement
  that names each other lineage, recorded as probed and unavailable; its
  truth is not checked. Anything else is refused under
  `work.acceptance_binding`, with the steps to record the review again.
  The marker is read only at the default branch's commit; one the run
  cannot read, or with another value, is refused. A line push whose clone
  cannot resolve the default branch, for example when `origin/HEAD` names
  a branch the clone has not fetched, is refused on any epic line, marked
  or not; fetch the default branch first. Both keys are written by the
  agents under review, so the check catches mistakes, not a forged claim;
  checking a completion against its verdict file stays the adopter's
  landing process. An unmarked line, a task's own pull request and a push
  of its branch are judged as before, and both keys stay optional there. A
  task pull request into a marked line whose completion lacks `built_by`
  passes, and is refused later, on the line's push and on the epic's pull
  request into the default branch.
