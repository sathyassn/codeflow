### Fixed

<!-- codeflow:release-impact patch -->
- **The exec guard now judges the paths an interpreter is given as
  arguments.** In 3.1.1 and earlier, `exec-guard` refused a `python3 -c`
  whose code named an enforcement path, but it never read the
  interpreter's arguments, so `python3 - "<repo>/.claude/settings.json"`
  with a heredoc that wrote `sys.argv[1]` was allowed, and an agent could
  change the settings file where the guard hooks are wired
  (sathyassn/codeflow#173). The guard now reads the arguments of `python`,
  `python3`, `node`, `nodejs`, `perl` and `ruby`, a version suffix
  included: a script's arguments, every word after inline code or stdin
  `-`, `--name=value` options and attached short values in a cluster such
  as `-oFILE` and `-voFILE`, and inline code itself. It judges every
  directory the line may run the interpreter in: the session directory and
  every one any directory change may reach (`cd`, `command cd`,
  `builtin cd`, `pushd`, `chdir`, every `env -C` and `--chdir` spelling,
  `git -C`, composed `ruby -C`), whether or not the change succeeds, and
  for `find -execdir` each directory under the start its name, path and
  type tests let through. A change it cannot resolve makes the directory
  unknown. An argument naming an enforcement path, in this checkout or a
  linked worktree, refuses under `git.hook_integrity`, and one naming
  policy authority metadata refuses in every form whatever the level. An
  argument the guard cannot read, such as `"$W/.claude/settings.json"`,
  refuses when its spelled part could name an enforcement path or the line
  names one, as git-guard judges a writer's operands. Reading an
  enforcement file with an interpreter now needs a reader (`cat`, `jq`,
  `grep`) or a redirect into the interpreter's stdin. Within the modeled
  grammar (`cd`, `chdir`, `pushd`, the launchers `command`, `builtin`,
  `exec`, `nohup`, `nice`, `timeout`, `stdbuf`, `time`, `env`, `xargs`,
  `caffeinate`, `xcrun` and `ionice` with their options and GNU-prefixed
  names such as `genv`, the zsh precommands `noglob`, `nocorrect` and `-`,
  `git -C`, `ruby -C`, `find -execdir`) the directory set is exact;
  anything outside it, such as `source`, `.`, `sudo`, an unlisted option,
  an unknown word followed by `cd` or `env -C`, or an unknown program that
  launches an interpreter (`frobnicate env -C.claude python3 ...`), makes
  the directory unknown, and every known word is then judged by its trailing components. Only string literals in code are
  read as file names. The directory model is conservative: an odd shape like `cd .claude && cd .. && python3
  tool.py settings.json`, and a repo-root `find . -execdir python3 lint.py
  notes.txt`, which can really run in a hook directory, are refused. A path
  a script builds internally is still past the guard; the OS sandbox stays
  the backstop. The refusal comes from the local guard, so installing the
  3.2.0 `codeflow` on `PATH` brings it.
