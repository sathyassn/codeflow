### Changed

<!-- codeflow:release-impact minor -->
- **The shipped instructions require typed code and typed data at every
  boundary (issue 275).** By default, new and changed code is fully typed,
  and every escape type or suppression (`any`, `Any`, an unchecked cast,
  `# type: ignore`, `@ts-expect-error` and the like) carries its reason
  inline. Data crossing a boundary (files, network, process input,
  environment, database rows, user input, another module's untyped output)
  is parsed into a typed model that also validates it, with the typed-model
  library that is standard for the language: Pydantic in Python, zod in
  TypeScript, serde in Rust, structs with a validator in Go. A plain
  dataclass, `TypedDict`, `interface` or cast describes a shape without
  validating it. Shell
  code runs ShellCheck, parses its arguments explicitly and passes
  structured data to a typed language or checks it against its JSON
  Schema. Rego checks its input at run time with `json.match_schema`; a
  Rego schema annotation is a static check only. A new project or file
  that would otherwise be JavaScript is TypeScript, and an existing
  JavaScript codebase is type-checked in place with `checkJs` and JSDoc
  types. The build row of the `AGENTS.md` map states these code defaults
  and points to the rule, so a builder sees them on every build. `cf-develop` and
  `cf-stack` add a missing type checker, linter and typed-model library as
  part of the work, and `cf-reviewer` returns `changes_requested` for
  untyped new code, an unexplained escape type, unvalidated boundary data,
  or a hand-written validator where a standard or schema-generated model
  fits. A project that needs to opt out states its reason in the Stack
  standards of its own `AGENTS.md`. Six qualification cases in a new
  `typed-code` pack check the builder and reviewer behavior. Gates do not
  change.
