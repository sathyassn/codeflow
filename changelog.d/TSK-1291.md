### Changed

<!-- codeflow:release-impact minor -->
- **Ready pull requests are refused until their review is recorded.** Once
  `codeflow ci` knows a pull request is ready (the host's event, or
  `CODEFLOW_PR_IS_DRAFT=false`), a task pull request is refused as not
  landable until its task is complete with `reviewed:` at the head or an
  ancestor of it, whatever the range changes: code, records only, or a sync
  of its line. The refusal names the fix, a records-only commit on top of
  the reviewed head that runs `codeflow task status <id> complete`. A
  record-only cancellation needs a Reviews row approving its exact head.
  Pushes, drafts and local lints are not refused for this. The draft state
  moved from `CODEFLOW_PR_DRAFT`, which keeps its one meaning as the release
  preflight's PR body path.
<!-- codeflow:release-impact minor -->
- **Record and planning checks close gaps found in review.** A completed
  task's criteria correction may change nothing else in that record or in
  an epic. A criterion removal needs a line `AC-n removed: <reason>` with a
  real reason. A planning or cancellation range is held to the planning
  paths in every commit, a cancelled record must pass the task schema, and
  planning pull requests run the docs validation once, on the candidate
  head. A completed task's derived Reviews row lets the section be left out
  even where `git.pr_sections` requires it. Record and id checks turn on
  when the checkout or the range's base or head tracks durable work, in
  `codeflow ci` and in `codeflow ids check --base --head`.
<!-- codeflow:release-impact minor -->
- **One rule decides whether a pull request needs a Release impact
  section.** It is required into a protected branch or with a breaking
  commit, at the `git.pr_release_impact` level, and may be left out on an
  unprotected line, as `codeflow ci` already judged. The release check now
  reads the same rule from `codeflow ci`, so the two give a body the same
  verdict; it no longer refuses a line pull request without the section.
<!-- codeflow:release-impact minor -->
- **The shipped CI runs quick-only targets.** Targets that define `quick`
  but not the mode the hosted gate runs now run after it, so they keep an
  automatic run now that the pre-push hook runs no test target. A config
  whose enabled targets define only `quick` runs them in place of the gate,
  which would otherwise stop with no target to run; a failing check and a
  config with nothing to run still fail the step.
