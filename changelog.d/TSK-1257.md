### Fixed

<!-- codeflow:release-impact patch -->
- **`codeflow ci` reads task records only from the commits it judges.**
  Which task a branch carries, the target that task declares, and whether
  durable work tracking is on are read from the `--head` and `--base`
  trees, under the work prefixes of the policy the run judges with. The
  same command gives the same verdict from any directory and checkout. A
  record that exists only in the checkout no longer names the branch's
  task, and a checkout with no tracking state no longer switches the
  record and id checks off. A task branch whose head holds no record for
  its task is refused, and the refusal names the head commit. A task
  record that does not parse there is refused, and the refusal names the
  commit and the path. The pre-push hook reads the pushed commit's
  records, under the work prefixes of the policy that judges the push, to
  pick the range base, the target and the task's integration line. A push
  of an integration-line task branch from a root checkout on `main` is
  judged the same as a push from the task's worktree (issue #531).
- **A late completion that merges its target line is no longer refused
  for the line's files.** A completion after the landing merge may change
  planning records only. That rule now judges what the pull request itself
  changes: a merge of the target line that brings in another task's
  changelog fragment or skill file no longer counts against it, and a
  file the pull request's own commits change is still refused.
