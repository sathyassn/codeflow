### Added

<!-- codeflow:release-impact minor -->
- **Projects choose whether branches must be up to date, or use a merge
  queue.** The policy key `git.require_up_to_date` takes `true` (the
  default, also when absent), `false` or `"merge_queue"`. `codeflow remote
  protect` writes strict checks, checks that are not strict, or GitHub's
  merge queue rule on the default branch with the lines kept strict, and
  `codeflow doctor --check remote-perimeter` accepts the choice and names
  it. A value that relaxes the rule counts only when it is committed on the
  remote's default branch; a working-copy or environment value never does.
  A merge queue needs an organization-owned GitHub repository: a user-owned
  repository, `--check-app` and other providers keep the strict rule and
  say why, and a host that refuses the queue rule gets the strict rule
  instead. An update never lowers a live strict rule. The shipped CI and
  policy workflows now run every job for a merge queue entry, judging from
  the queue's base on the default branch; `codeflow update` installs them
  (ADR-0100, amending ADR-0081).
