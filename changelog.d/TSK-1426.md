### Fixed

<!-- codeflow:release-impact patch -->
- **The edit guard judges every Windows spelling of a path as the path
  Windows opens.** NT namespace (`\??\`), verbatim (`\\?\`) and device
  (`\\.\`) paths are mapped by their prefix to the drive or network share
  they name, and NT namespace paths no longer get an exception. The guard
  refuses a drive-relative edit path such as `C:name`, mixed or incomplete
  prefixes, `/` inside a verbatim path, device roots and paths that climb
  out of a device, and a network share outside the folders the session
  chose. A verbatim path with a trailing dot is still refused, and shell
  startup files are checked on the resolved target.
