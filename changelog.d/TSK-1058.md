### Fixed

<!-- codeflow:release-impact patch -->
- **The `Monitor` tool is judged like `Bash`.** A command given to Claude
  Code's `Monitor` tool reached no guard, because the shell guard matcher
  covered only `Bash` and `PowerShell`. The matcher is now
  `^(Bash|PowerShell|Monitor)$` in the three permission presets, and
  git-guard reads the command from a `Monitor` call. Run `codeflow update`
  to take the new matcher into an installed project. A `Monitor` input the
  guards do not recognise (no `command` and no `ws.url`, or an unknown
  field) is refused rather than passed, with a message that names the field.
  If a Claude Code update adds a field, the project owner lists it in the new
  `security.monitor_extra_fields` policy key, which is read only from the
  policy published on the default branch. The command form is confirmed by a
  native capture on Claude Code 2.1.318 (see
  `docs/verification/tsk-1058-monitor-tool-input.md`).
