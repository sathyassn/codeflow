### Added

<!-- codeflow:release-impact minor -->
- **A project can run each model family's seats under its own account
  folder and read the limit state of each family.** An untracked profile,
  `.codeflow/local/accounts.toml` (or `accounts.toml` in the CodeFlow home),
  maps Claude, Codex and Grok to a config home and, optionally, names an
  API-key variable with a spend cap. The cap is a figure the profile records
  and shows; nothing enforces it. The profile never holds a token: a
  credential key name, a secret-shaped value or an unknown key refuses the
  file. A seat launches with only its own family's variable
  (`CLAUDE_CONFIG_DIR`, `CODEX_HOME` or `GROK_HOME`) set or unset through
  `codeflow models launch-env`, and the published launch sequences stop when
  that fails. `codeflow delegate init --config-home` records the folder in
  each turn's provenance. `codeflow models limits` shows each family's used
  share and reset time for the 5-hour and weekly windows, or `not exposed`,
  from Claude Code's statusline, a Codex app-server rate-limit payload or a
  Grok limit-hit error stored by `codeflow models record-limits`, and shows
  a reading only for the config home that produced it. A limits file from an
  earlier build names no home, so it is ignored and replaced by the next
  recording. The managed
  `.gitignore` now ignores `.codeflow/local/`. CodeFlow does not switch
  accounts or move a sign-in.
