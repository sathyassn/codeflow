### Security

<!-- codeflow:release-impact minor -->
- **Gate evidence can no longer be redirected or forged by an agent
  session.** Every gate run now executes every eligible target: a local
  run record no longer lets a quick, essential or `--since` run skip a
  check, because any process of the user, an agent session or the
  candidate's own tests included, can write those records (ADR-0089).
  Projects that declared `input_class: content` targets lose their local
  skips and run those targets again; the declarations stay valid. `--since`
  is still accepted and narrows nothing. Run records are still written and
  copied to `~/.codeflow/gate-runs/<repo>/<run-id>/`, and run ids stay
  citable. The evidence preflight, the gate's lock files, the run record,
  each target's logs and report copies, and the durable copy now refuse a
  symbolic link, a Windows junction or a planted file at the build-output
  folder, the CodeFlow home or any folder or file beneath them, instead of
  writing through it. The copy also refuses a link, a hard link or a pipe
  inside the run folder, where it used to copy through the link or block
  forever, and a target's report is read only through that walk, from the
  project or the build-output folder, as a regular file with one name.
  The same walk removes a nextest target's stale report and checks
  declared producer outputs, so a link above either can no longer delete
  an outside file or stand in for a missing output. A refusal names the
  path and fails the gate. A `target` folder or CodeFlow
  home that is itself a link is now refused: point `CARGO_TARGET_DIR` or
  `CODEFLOW_HOME` at the real folder instead.
