### Security

<!-- codeflow:release-impact minor -->
- **A guard that does not answer in time blocks the tool call where the
  harness allows it.** Claude Code, Codex and Grok all let a tool call
  through when a hook times out, and the shell wrapper around each guard
  never runs once the harness kills it. Each guard (`git-guard`,
  `exec-guard`, `edit-guard`) now refuses on its own with exit 2 and a reason
  when it has reached no decision 20 seconds after it starts, which blocks in
  all three harnesses; a FIFO named by a git configuration include used to
  stall `git-guard` and `exec-guard` until the harness gave up. Every shipped
  guard hook entry now carries `"timeout": 30`, and the Claude presets add
  `"onFailure": "block"` (Claude Code 2.1.295 or later; an older version
  ignores the key), so a Claude timeout, crash or start failure also blocks.
  Codex and Grok have no such setting, so a guard process that does not start,
  or is starved past 30 seconds, still fails open there. The new
  `codeflow doctor --check guard-timeouts` warns when a guard entry in
  `.claude/settings.json`, `.claude/settings.local.json`, `.grok/hooks/` or
  `.codex/hooks.json` lacks the shipped timeout or, in Claude settings,
  `"onFailure": "block"`, and states the Codex and Grok residual.
  `codeflow update` gives existing guard entries in `.claude/settings.json`
  the shipped fields and moves the Grok and Codex hook files by its usual
  3-way merge; set the fields by hand in `.claude/settings.local.json`. Codex
  treats the changed guard entries as new hooks: approve them again in
  `/hooks`, and `codeflow doctor --check codex` confirms it.
