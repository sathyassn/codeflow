### Fixed

<!-- codeflow:release-impact patch -->
- **A binary older than the repository now says so.** When a commit, push,
  `codeflow ci`, `codeflow test` or `codeflow validate` cannot read the
  policy, test config or task and epic records, and `.codeflow/project.toml`
  declares a newer CodeFlow, the refusal is one message naming the binary's
  version, the version the repository needs and how to upgrade, in place of
  per-field findings. `codeflow ci` reads that version at the commit that
  judges the range, so a range cannot raise it to hide a finding. A
  repository that declares no version keeps today's refusal and adds one line
  saying the binary may be older. Every case still refuses; a newer version
  with everything readable refuses nothing, so the two-step upgrade stays
  open. The message reaches users from the first release that carries it: a
  binary already installed cannot print it, so for the 3.x to 4.0.0 step the
  upgrade path stays in these release notes: install the new binary first,
  and expect a 3.x binary's per-field refusal on a 4.0.0 repository until
  then.
