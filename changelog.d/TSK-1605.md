### Fixed

<!-- codeflow:release-impact minor -->
- **`work.import_authority` accepts unchanged-base syncs, docs-bearing planning landings, and an optional settled-history cutover (`TSK-1605`).** When syncing the default branch into a long-lived integration line, a task whose criteria the receiving line only inherited, through merges that decided nothing about them, no longer fails with `accepted criteria cannot be resolved`. A line whose history amended, removed or re-planned the criteria, or planned and withdrew the record on a merged branch, still competes, even when it later restored them, and an ambiguous or unreadable history still refuses. Planning landings that move a task's home or introduce a task on the default branch targeting a line now admit `docs/` alongside `project-management/` records (`PLANNING_LANDING_PATHS` = `[Record, Doc]`), while keeping `AGENTS.md`, product code, hooks, policy, CI, and templates blocked. An optional, off-by-default trusted-policy key `git.import_authority_settled_before` (a 40-hex commit SHA on the default target's first-parent history, read only from the default tip) lets operators mark historical default-branch completions at or before that commit as settled on a sync while keeping exact-blob, owned-path, clean-remerge, exact second-parent source, and post-cutover completion proofs enforced.
