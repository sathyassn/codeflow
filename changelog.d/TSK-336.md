### Fixed

<!-- codeflow:release-impact major -->
- **The hosted policy verdict runs only the default branch's code.** The
  `codeflow-policy` workflow's verdict job is now named `trusted: commit
  standards` and runs only on `pull_request_target`. For every pull
  request, whatever it targets, it checks that the run is for the default
  branch, checks out exactly that commit, installs the codeflow version the
  default branch pins, and judges with the default branch's policy and
  work-record baseline (`--policy-from`, `--baseline-from`). It fetches the
  pull request's base and head only as git data, and asserts after every
  step that the checkout has not moved. A pull request into an integration
  line is no longer judged by the line's policy or pin, and the job refuses
  when the default branch has no `.codeflow/policy.json`. Push, schedule
  and dispatch runs check the id registry in a new managed workflow,
  `codeflow-registry.yml`, under the name `registry check`, so they create
  no check under a `trusted:` name. Migration: a branch ruleset or protection rule that requires
  `commit standards` must require `trusted: commit standards` instead, and
  the default of `git.required_checks` now names it. `codeflow ci` also
  warns, under `ci.workflow_change`, when a change edits a managed
  workflow, naming the triggers, permissions and jobs it changes.
