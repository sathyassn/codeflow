### Added

<!-- codeflow:release-impact minor -->
- **A hosted gate run keeps each target's result where the GitHub API can
  read it.** The run record `codeflow test` writes,
  `target/codeflow-gate/<run id>/run.json`, has a new `outcomes` list: one
  entry per target the run was given, with its `name`, `state`
  (`passed`, `failed`, `stalled`, `timed_out`, `cleanup_incomplete`,
  `not_run`, `skipped_in_ci` or `skipped`) and `duration_ms`, plus the exit
  code of a target that ran and the reason for a skip. Failed, unrun and
  skipped targets are listed beside the passing ones. The record still
  holds each target's captured output, which the job log shows only for a
  failed target. The `codeflow-ci.yml` workflow CodeFlow ships now uploads
  that record after `codeflow test`, whether the gate passed or failed,
  as the artifact `codeflow-gate-<job>-attempt-<n>`, kept for 7 days. The
  upload never changes the job's result, and a gate that wrote no record
  only warns. List a run's artifacts with
  `gh api repos/<owner>/<repo>/actions/runs/<run id>/artifacts` and fetch
  one with `gh run download <run id> -n <name>` (issue 546).
