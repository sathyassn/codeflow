### Changed

<!-- codeflow:release-impact minor -->
- **The shipped pipeline verifies each change with targeted checks and the
  quick gate.** A fresh install's `.claude/workflows/pipeline.workflow.js`
  ends with the affected targeted checks (a check defined only in a heavier
  mode runs alone through `--only`) and then `codeflow test --mode quick
  --strict`, once per pass, and the primary runs one full gate on the
  landing candidate. The review stage leaves those checks to the verify
  stage when the run has one, and runs them itself when it does not. The
  pipeline no longer runs a whole `codeflow test --mode essential
  --strict` on every change. A NoTargets run and any nonzero exit still
  give `changes_requested`. The file stays user-owned: `codeflow update`
  never rewrites an existing copy, edited or not. When a copy still runs
  essential on every change, `codeflow update` and the new `codeflow doctor
  --check pipeline` warning name the two-line edit, keeping each line's
  indentation. First, in the review stage, replace the line that starts
  ``'Run `codeflow validate` and `codeflow test --mode quick --strict`;``
  with:

  ```js
  'Run `codeflow validate`' + (PRESET.includes('verify') ? ' and read the diff and the tests; the verify stage that follows runs the affected targeted checks and then the quick gate once for this revision, so never run `codeflow test` here' : ' and the affected targeted checks (a check defined only in a heavier mode runs alone through `--only`), then `codeflow test --mode quick --strict`') + '; any nonzero exit is an automatic changes_requested. `--strict` makes a NoTargets run (the loud "nothing to run" banner — zero tests executed) exit non-zero: that is not-verified, treat it as changes_requested, never as a pass.'),
  ```

  Then, in the verify stage, replace the line that starts
  `'Run the affected targeted checks, then` and runs `codeflow test --mode
  essential --strict` with:

  ```js
  'Run the affected targeted checks (a check defined only in a heavier mode runs alone through `--only`, such as `codeflow test --mode essential --only <target>`), then `codeflow test --mode quick --strict`; never run a whole essential or full gate here, since the primary runs one full gate on the exact landing candidate. Report the exact exit code of each as a finding; any nonzero exit is changes_requested. `--strict` makes a NoTargets run (the loud "nothing to run" banner — zero tests executed) exit non-zero: a no-op is not-verified, report it as changes_requested, never approved.',
  ```

  A project that wants an essential run on every change keeps its copy as
  it is; doctor keeps warning about it. When the old command is absent,
  doctor passes and says only that: what a user-owned copy's stages run
  otherwise is not checked.
