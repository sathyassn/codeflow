### Security

<!-- codeflow:release-impact minor -->
- **Refuse inline secret-scan allows.** The managed GitHub secret scan reads
  `git.secret_scan_inline_allow` from the trusted commit. Its default,
  `trusted`, keeps allowing inline `gitleaks:allow` on commits the trusted
  commit already holds. With `never`, those findings are reported too; other
  trusted exemptions still apply. A pull request's policy change cannot
  affect its own scan. The scan uses resolved commit ids and ends the revision list
  with `--`, so a tracked path named `HEAD` no longer stops it.
  Migration: upgrade and land the binary and CI pin before adding the new
  key; the shipped policy omits it for compatibility with older binaries.
  The scan also diagnoses legacy conflicted-merge `b/` fingerprints, with
  exact replacements for review only when the commit is readable with two
  parents, the prefixed path is absent and the unprefixed path exists.
  One-parent commits receive no replacement advice. Existing `b/` paths and
  unreadable commits are reported separately. Review and commit the
  suggested ignore entries; the scan never rewrites or automatically aliases
  an exemption.
