### Added

<!-- codeflow:release-impact minor -->
- **Agents can fetch from `origin` and push their own work branches.**
  exec-guard no longer refuses the GitHub CLI credential helper
  (`gh auth git-credential`) that Git starts on `git fetch` from `origin`
  and on a push of a work branch, in closed command forms only. The
  repository must have one remote, `origin`, with an unrewritten URL and no
  setting that widens the call, and the pushed name must sit under a
  `git.branch_prefixes` entry and not be protected, the default branch, an
  integration line, a release branch or the ID registry. The guard reads
  which credential helpers Git selects for `origin`, including the empty
  `helper =` that clears earlier helpers, so a host whose system
  configuration names `osxkeychain` is admitted once `gh auth setup-git` has
  cleared it. Every other push, tag, release and account action keeps its
  refusal. See "Agent fetch and push" in
  `docs/architecture/enforcement-planes.md`.
- **`git remote update`, `prune`, `show` and `set-head -a` now have their
  transport programs and credential helpers judged**, like `git fetch`;
  before, the guard did not read them for `git remote`. `git maintenance`
  and `git request-pull` are judged the same way. Local `git remote` calls
  such as `get-url` and `-v` are unchanged.
