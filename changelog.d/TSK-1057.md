### Added

<!-- codeflow:release-impact minor -->
- **A rewritten remote-tracking ref can no longer weaken the policy.** An
  operator can record a baseline of the landed policy with `codeflow policy
  baseline init`, run in a terminal outside any agent session. It reads the
  policy from a fresh query of the authority remote, never from the local
  tracking ref, and writes nothing until the operator confirms the commit
  it prints. The guards and git hooks then enforce the stricter of the
  tracking ref's policy and the baseline's. A ref that does not descend from
  the baseline's commit gets the baseline's policy, and so does a
  repository whose remote was removed. A baseline that is missing for a
  repository that was initialized, unreadable, or bound to another
  repository, remote URL or default branch blocks the policy check until
  the operator repairs it. `codeflow policy baseline refresh` moves it to a
  descendant whose policy is no weaker. Any other move needs `--reset` with
  a recorded reason. `codeflow policy baseline show` and `codeflow doctor`
  report its state. A repository without a baseline behaves as before.

### Changed

- **The Grok profile lets a seat read `~/.codeflow/authority`.** The
  shipped `.grok/sandbox.toml` no longer lists the operator-authority
  directory under `deny`, which also blocked reads. A Grok seat can now
  read it, as Claude and Codex seats already could, and still cannot write
  it. The guards read the policy baselines and the SSH configuration allow
  there; under the old profile the SSH allow had no effect in a Grok seat,
  and every guard would refuse once a baseline existed. The profile is
  installed only when absent: an existing copy keeps the old rule until
  the operator removes the three `.codeflow/authority` entries from both
  profiles' `deny` lists.
