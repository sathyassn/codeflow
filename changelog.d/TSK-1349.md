### Fixed

<!-- codeflow:release-impact patch -->
- **The guards refuse the git options that skip a hook, on every branch.**
  git-guard let `git commit --no-verify`, `git commit -n` and
  `git merge --no-verify` through off the protected branches, so a session
  could skip the commit-msg, pre-commit (with its secret scan),
  pre-merge-commit and pre-push hooks. Both git-guard and exec-guard now
  refuse, under `git.hook_integrity`, every option git documents as skipping
  a hook: `--no-verify` on `commit`, `merge`, `pull`, `push`, `rebase`, `am`
  and `p4 submit`, `-n` on `commit` and `am`, and `--no-post-rewrite` on
  `commit`. An abbreviation git accepts (`--no-verif`), `-n` inside a cluster
  (`commit -qn`, `commit -anm msg`), a later `--verify`, and a word the shell
  fills in where git reads options all refuse too. `-n` stays allowed where
  it means another option: `push -n` is `--dry-run`, and `merge`, `pull` and
  `rebase -n` are `--no-stat`. exec-guard now also refuses
  `-c core.hooksPath=…`, which only git-guard refused before. Both guards
  also refuse an include flag (`-c include.path=…`,
  `includeIf.<condition>.path`) and any setting of `GIT_CONFIG_GLOBAL`,
  `GIT_CONFIG_SYSTEM`, `GIT_CONFIG_COUNT`, `GIT_CONFIG_PARAMETERS` or
  `GIT_CONFIG_KEY_<n>`, whatever the value, a bare `export` with no git call
  included: each can point git at another hooks path, and a separate export
  would otherwise disarm the hooks of a later plain `git commit`. One form
  passes this check: `GIT_CONFIG_GLOBAL=/dev/null` or
  `GIT_CONFIG_SYSTEM=/dev/null`, spelled literally in front of one read-only
  git call. It names an empty file, ends with the call and runs no hook;
  exec-guard still refuses it under `security.secret_reads`. These hold
  behind any wrapper the guards read (`builtin`, `command`, `exec`, `nohup`,
  `env`, `env -S`, `eval`, `sh -c`), for a key in any letter case, and for
  the entry attached to the flag (`-ccore.hooksPath=…`). The refusal
  names the flag and the hooks it skips, and the sanctioned path: run the
  command without the flag and fix the cause a hook reports.
  `.codeflow/rules/git-rules.md` "Enforcement" lists the refused options;
  `codeflow update` rewrites it.

- **The guards protect every workflow file, not only `codeflow-ci.yml`.**
  A session could create or edit any other file under `.github/workflows/`
  and commit it, since the guards protected that one file. git-guard,
  exec-guard and the file-tool guard now refuse a write to any path under
  `.github/workflows/` or `.github/actions/` (a local action runs as
  workflow code), whatever its name or extension, after resolving
  letter case on any disk, non-ASCII spellings a disk folds (`workflowſ`),
  `..`, symbolic links and hard links; a path they cannot
  resolve refuses. Making a hard link to any enforcement file (`ln` without
  `-s`, `cp -l`) refuses too, and exec-guard now refuses the shell writes to
  enforcement files that git-guard refuses. The Claude presets deny
  `Edit(/.github/workflows/**)` and `Edit(/.github/actions/**)` and their
  sandbox denies writes to both directories, as does a newly installed Grok
  sandbox profile; `codeflow update` brings the Claude change to an
  existing install. `codeflow ci` warns
  on a change to any workflow or local action file, a new one included.
  Workflows change through the operator or `codeflow update`.

- **The guards read a name the way the disk does.** APFS folds `ſ`, the Kelvin
  sign and the `fl` ligature onto ASCII, so `cat ~/.awſ/credentials`,
  `echo x >> ~/.baſhrc`, `/usr/bin/ſudo ls` and a write to an absent
  `.github/workflowſ/` reached what the guards protect. git-guard, exec-guard
  and the file-tool guard now also judge each line or path in its ASCII
  spelling, and the commit path checks do the same. A non-ASCII file name
  inside `.github`, `.claude`, `.codeflow` or another protected dot directory,
  or a non-ASCII dot name at a checkout's top level, now refuses, because the
  guards cannot tell what every disk folds it to. Other non-ASCII names, such
  as `docs/café.md`, stay allowed.
