### Fixed

<!-- codeflow:release-impact patch -->
- **Review documents accept every task, spec and ADR id the allocators issue.**
  `codeflow present check`, `present open` and `present update` refused a
  `provenance.task_id` or `spec_id` with more than three digits, so a review
  page could not carry `TSK-1000` or `SPC-1000`. The validator and the
  installed `.codeflow/schemas/present/` schemas now take three or more
  digits for tasks and specs (and for each group of a historical
  `TSK-NNN-NNN`) and four or more for ADRs, with no upper limit. Short or
  malformed ids are still refused. Allocating the next ADR after `ADR-9999`
  now reads the whole number, so it no longer issues `ADR-10000` twice, and
  the id registry reads `ADR-10000` and longer record paths. Lists of ids
  (`work next`, `status`, feedback groups, record inventories, validation
  messages and the estimate history) now order by id number, so `TSK-1000`
  follows `TSK-999` instead of preceding it. The docs portal does the same:
  record pages, routes and the source list order ids by number, so published
  page order changes for ids above 999 (the page for `TSK-1000` now follows
  `TSK-999`). Run `codeflow update` to refresh the installed schemas and the
  portal scripts.
