### Added

<!-- codeflow:release-impact minor -->
- **The test config sets how long heavy work waits for a host-exclusive
  target.** `execution.heavy_wait_seconds` is back, default zero, and
  `--wait-seconds` overrides it for `codeflow test` and `codeflow reserve`. A
  run refused behind a queued host-exclusive target names it and says to
  retry.

### Fixed

<!-- codeflow:release-impact patch -->
- **Heavy gates and `codeflow reserve` keep the caller's Cargo job cap.**
  They honour inherited and target Cargo job caps, report reduced worker
  grants, and keep full-budget targets from competing with their own gate's
  siblings.

<!-- codeflow:release-impact patch -->
- **Timing-sensitive targets run alone on the host with `host_exclusive`.**
  `exclusive` continues to exclude sibling targets only. Exclusive requests
  release shared admission and queue in FIFO order, with bounded waits naming
  the holder. Later shared arrivals from queue-aware binaries defer to the
  request. Older binaries do not consult this queue and can still delay it
  until refusal; fairness across mixed binary versions is not guaranteed.

<!-- codeflow:release-impact patch -->
- **Unconfirmed process termination keeps its host allocation.** The
  allocation and exclusive lease stay held until termination is confirmed or
  the gate process exits.

<!-- codeflow:release-impact patch -->
- **Two gates first to use a lock folder no longer refuse.** They no longer
  fail with `gate lock unavailable: No such file or directory`. This fault
  predates the exclusive queue: macOS can report a missing file to the loser
  of a race to create one lock file.

<!-- codeflow:release-impact patch -->
- **A host-exclusive target that finds the host held reads as not run.** It
  reports `NOT RUN, host held`, names the holder and `--wait-seconds`, and
  still fails the gate.
