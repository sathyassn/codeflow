## Fixed

- Heavy gates and `codeflow reserve` honour inherited and target Cargo job
  caps, report reduced worker grants, and keep full-budget targets from
  competing with their own gate's siblings.
- Timing-sensitive targets use `host_exclusive`; `exclusive` continues to
  exclude sibling targets only. Exclusive requests release shared admission
  and queue in FIFO order, with bounded waits naming the holder. Later shared
  arrivals from queue-aware binaries defer to the request. Older binaries
  do not consult this queue and can still delay it until refusal; fairness
  across mixed binary versions is not guaranteed.
- Unconfirmed process termination retains the allocation and exclusive lease
  until termination is confirmed or the gate process exits.
- Two gates that are first to use a lock folder no longer refuse with
  `gate lock unavailable: No such file or directory`. This fault predates the
  exclusive queue: macOS can report a missing file to the loser of a race to
  create one lock file.
- A host-exclusive target that finds the host held now reports `NOT RUN, host
  held`, names the holder and `--wait-seconds`, and still fails the gate.
- `execution.heavy_wait_seconds` is back in the test config, default zero, as
  the wait for a host-exclusive target; `--wait-seconds` overrides it. A run
  refused behind a queued host-exclusive target names it and says to retry.
