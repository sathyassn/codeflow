### Changed

<!-- codeflow:release-impact minor -->
- **A non-trivial project is built on its standard framework, in
  proportion.** `cf-stack` now tells an agent to build a non-trivial
  project on the framework it already uses or the one its type treats as
  standard, for user interfaces, CLIs, services and tests alike. A project
  is non-trivial when it has more than one view, route or subcommand,
  shared or persisted state, input that needs validation, or synced data.
  A one-page tool, a trivial script or a static page with no interaction
  may stay plain until one of the named signals says it has outgrown that,
  such as code that rebuilds a router or state store, or several people
  maintaining it over a long life. A framework the project does not already use needs
  the owner's approval, and a working stack is never migrated for this rule
  alone. `cf-design` and the UI verification resource carry the
  user-interface part. The design-system kit READMEs in `cf-present` and
  `cf-docs-portal` now say why the kits are plain files and the runtimes
  use Preact and Astro Starlight, and that the kits are not a model for
  product code. `/cf-evaluate-model` gains cases for a multi-view surface on
  the project's framework and a one-page tool that stays plain.
