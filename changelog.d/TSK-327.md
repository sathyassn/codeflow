### Fixed

<!-- codeflow:release-impact minor -->
- **The pre-push destination lookup asks only the repository the push
  reaches.** Git hands the pre-push hook the URL the push uses, after its
  own rewrites. The hook's lookup of what the destination holds, and the
  fetch of an object it needs, read the configuration again, so a
  `url.<base>.insteadOf` matching that URL (an empty one matches every
  URL), a remote configured under that
  URL as its name or a legacy remotes or branches file of that name could
  send them to another repository, whose answer then chose the range and
  the policy for the push. Each now refuses the push as unverifiable under
  `ci.destination_unavailable`, naming the setting. A push with none of
  them makes the same single lookup and reaches the same verdicts as
  before. The lookup's ssh transport follows git's own
  precedence (`GIT_SSH_COMMAND`, `core.sshCommand`, `GIT_SSH`, then
  `ssh`), read as the push read it, `git -c` settings included, and only
  the selected one runs. The configuration is read as every git command
  reads it, so the deprecated `GIT_CONFIG` file cannot hide a setting. A
  destination with no branches is no longer taken as a first push when the
  push carried a `git -c` transport setting the lookup does not apply.
  The guards' check of an empty remote, which selects initialization
  policy, validates its URL the same way, and its own configuration read
  ignores `GIT_CONFIG` too, so that file can no longer hide a rewrite to a
  populated repository and make the guards read policy from `HEAD`.

<!-- codeflow:release-impact patch -->
- **A pre-push check that could hang now refuses at its deadline.** Each
  pushed range's `codeflow ci` runs within one deadline, the destination
  lookup wait times its attempts plus the fetch wait plus the push budget
  (270 s by default); a check still running then is ended and refuses the
  push, naming the keys that raise the deadline. A stalled promisor in a
  partial clone, or a helper that holds a stdin-fed read open, can no
  longer hold a push indefinitely. Before the check, the hook fetches the
  objects the id registry lacks in a partial clone, so a plain push from a
  `blob:none` clone still passes.

<!-- codeflow:release-impact patch -->
- **A process a hook, guard, check or doctor starts now ends with its
  owner.** Each such child leads a process group that also holds a small
  watcher, which ends the group when the process that started it ends,
  even when that process is killed. A read the pre-push check started is
  now ended when the hook ends the check at its deadline, and a helper
  that a successful read left running is ended when the read returns.
