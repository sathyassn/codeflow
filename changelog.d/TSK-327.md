### Fixed

<!-- codeflow:release-impact minor -->
- **The pre-push destination lookup asks only the repository the push
  reaches.** Git hands the pre-push hook the URL the push uses, after its
  own rewrites. The hook's lookup of what the destination holds, and the
  fetch of an object it needs, read the configuration again, so a
  `url.<base>.insteadOf` matching that URL, a remote configured under that
  URL as its name or a legacy remotes or branches file of that name could
  send them to another repository, whose answer then chose the range and
  the policy for the push. Each now refuses the push as unverifiable under
  `ci.destination_unavailable`, naming the setting. A push with none of
  them makes the same single lookup and reaches the same verdicts as
  before. The lookup's ssh transport follows git's own
  precedence (`GIT_SSH_COMMAND`, `core.sshCommand`, `GIT_SSH`, then
  `ssh`), read in the process that runs the lookup, and only the selected
  one runs.
