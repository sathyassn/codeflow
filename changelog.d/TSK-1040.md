### Fixed

<!-- codeflow:release-impact patch -->
- **A pull request body edit no longer cancels the required policy check.**
  The shipped `codeflow-policy.yml` queues every pull request event
  (`cancel-in-progress: false` with `queue: max`) instead of cancelling the
  run an edit supersedes, so a push followed by a body edit leaves the
  "commit standards" check on the pushed head completed. After its checks the
  job reads the pull request again and fails a run whose head, base branch or
  body changed while it judged them, and fails closed when that read fails. The
  body is
  logged as a sha256 digest, never as text. A group queues at most 100 runs,
  and older actionlint releases reject the `queue` key; the CI README lists
  the limits. Run `codeflow update` to receive it.

<!-- codeflow:release-impact patch -->
- **A `Task:` line naming a task with no record now always blocks.** On a
  branch that does not name the task, `codeflow ci` refuses it with a fixed
  message that does not repeat the value, even where `work_planning` is
  `warn`; it used to warn there. Name the task in the branch, or land its
  record first.
