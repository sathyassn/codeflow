### Changed

<!-- codeflow:release-impact minor -->
- **Heavy gate deadlines.** Heavy targets gain `stall_timeout_seconds`, with
  a default inactivity window of 300 seconds. Existing heavy targets now have
  an effective limit of four times their configured `timeout_seconds`.
  In this repository, `prose-exhaustive` increases from 7200 to 28800 seconds,
  `rust-workspace` from 3600 to 14400, `present-binary-delta` from 2400 to 9600,
  and `rust-coverage` from 1800 to 7200. Their configured base values are
  unchanged. Stalls, ceiling timeouts and incomplete cleanup report distinct
  failure causes; dependent targets preserve them. Progress lines show tests
  done and CPU state every five minutes. Cleanup is bounded by the new
  per-target `cleanup_grace_seconds`, default five seconds; a supervised
  group still running at half of it is killed, so a passing target is not
  reported as incomplete cleanup on a loaded host.
  Windows uses job CPU accounting. Linux uses existing cgroup v2 delegation
  when available, falling back to the ceiling when delegation is missing or
  accounting, population or membership observations become uncertain. macOS
  is ceiling-only, an accepted limitation for 4.0.0; an idle hung heavy target
  there can now wait four times longer before timing out.
  On Windows, a target that cannot join its kill-on-close job fails to spawn
  with an error naming the target.
