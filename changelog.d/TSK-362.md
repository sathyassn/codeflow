### Changed

<!-- codeflow:release-impact minor -->
- **`validate --docs` now checks that each capability's evidence exists.**
  A `verified_by` entry is typed: `test: <path>[::<name>]`,
  `journey: <path>[::<name>]`, `record: docs/verification/<path>` or
  `gap: <proof>: <reason>`. An entry that names a missing test, a renamed test,
  a source file alone, a command or a missing record is refused, naming the
  capability and the entry; nothing it names is run. A shipped record whose only
  evidence is a gap must carry `stage: unassessed`. A legacy
  `docs/capabilities.md` with no typed entry keeps validating, with a warning
  that names its capabilities, until its first typed entry; after that, every
  entry in the file must be typed. A folder record is always checked.
  CodeFlow's own 17 capabilities now use typed entries, and CAP-008 states that
  its tests stub the GitHub boundary.
