### Fixed

<!-- codeflow:release-impact patch -->
- **Git commands that write work-tree files can no longer put other content
  on an enforcement file (issue 633).** git-guard now judges `git checkout`
  and `git restore` of paths, `git checkout-index`, `git read-tree -u`, `git
  stash apply`, `pop` and `branch`, `git apply`, `git cherry-pick -n`, `git
  revert -n`, `git am`, and `git reset --hard`, `--keep` and `--merge` to a
  revision by the content they would write. It reads that content from the
  object store and refuses under `git.hook_integrity` when an enforcement
  path would receive anything other than HEAD's version. Whole-tree forms
  (`-- .`, `checkout-index -a`), Git pathspec wildcards, abbreviated
  options, patch mode, pathspec magic and a two-step index plant are all
  covered, in the session's worktree and in another one named with `git
  -C`. Restoring HEAD's content and restoring ordinary files from any
  revision still work. Branch switches, merge, rebase, pull and committing
  cherry-pick and revert keep their verdict.
