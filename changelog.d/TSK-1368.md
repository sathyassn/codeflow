### Fixed

<!-- codeflow:release-impact patch -->
- **`remote protect` requires the checks the policy workflow really
  produces.** A check name counts as a trusted verdict only when it is on
  an explicit list, `commit standards` and `trusted: release impact`, and
  the default branch's policy workflow declares it; a `trusted:` spelling
  alone counts for nothing. `remote protect` no longer refuses the default
  branch and line rulesets for want of a `trusted: secret scan` job that no
  workflow declares, and it now requires `secret scan` on the default
  branch, as a head-built check, wherever a workflow declares it. The
  default of `git.required_checks` names `commit standards`.
