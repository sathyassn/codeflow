### Fixed

<!-- codeflow:release-impact patch -->
- **The hooks stay usable while a settings file has a merge conflict.**
  When `.codeflow/policy.json` or `.codeflow/project.toml` has unmerged
  entries in the index and its working copy does not parse, the hooks read
  that file's copy at `HEAD` in its place and print one note naming it,
  instead of refusing every command. The commands that resolve or abandon
  the conflict, such as `git status`, `git checkout --theirs`, `git add`,
  `git commit` and `git merge --abort`, get their usual verdicts, and every
  guard still judges with the same policy authority, so a planted push to
  a protected branch is refused as before. A settings file that does not
  parse without a conflict in the index still refuses, and so does a
  conflict with no readable copy at `HEAD`; the refusal names the file and
  the recovery. The project settings parse error now names
  `.codeflow/project.toml`.
