### Fixed

<!-- codeflow:release-impact patch -->
- **The test gate no longer fails a candidate for a permission change Git
  does not track.** The generation check compared each tracked file's full
  Unix permission bits, so a generator that rewrote identical bytes under a
  different umask, for example 0644 to 0600 under `umask 077`, failed with
  "generation changed the candidate" although Git showed no change. The
  check now compares what Git records for a file: its content, its kind
  (regular file, link or submodule) and the owner execute bit. A change to
  any of those, an added or removed tracked path, and an unreadable tracked
  file still fail the check. The per-target check now also names a path
  that left the index during the target, as the whole-run check already
  did.
- **What the generation check no longer compares.** When a file's content,
  kind and owner execute bit are unchanged and it reads, the check ignores
  its owner read and write bits, all group and other permission bits,
  setuid, setgid and sticky. Git records none of these. The check does not
  enforce filesystem permission safety: setuid and access-permission
  changes can be security-relevant elsewhere, and this check does not
  detect them. As before, it does not measure owner identity, ACLs,
  extended attributes or timestamps, and it does not see a change restored
  before the next snapshot.
