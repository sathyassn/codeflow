### Fixed

<!-- codeflow:release-impact patch -->
- **Each landed task needs its own completion.** A later task's reviewed
  head no longer hides unfinished product work it imported from the line.
  A reopened task keeps credit for an earlier review only where that review
  still binds at the commit that made it, on that task's own chain.

<!-- codeflow:release-impact patch -->
- **Two line histories are now refused.** An epic line's pull request to
  `main` refuses a planning pull request that changes `.codeflow/policy.json` on the line
  (land that change through a task, or on the default branch first), and a
  re-completion whose `reviewed:` is the line tip after a fix landed from a
  separate branch (review the fix commit itself). A task branch that
  merges its own sub-branch, not the line, has that sub-branch's product
  work refused at landing; put that work on the task branch's own commits
  before review.

<!-- codeflow:release-impact patch -->
- **A task branch's landing credit follows the judged policy.** `codeflow
  ci` reads the task a branch carries with the branch prefixes of the
  policy it judges with, not the checkout's, so both policies give the same
  answer about which reviewed head is the branch's own.
