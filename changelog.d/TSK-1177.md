### Added

<!-- codeflow:release-impact minor -->
- **The policy workflow names who may produce a verdict, and fails closed
  on any other producer.** The `codeflow-policy` workflow gains an
  `authority` job for pull requests into the default branch. It is the only
  job that references the environment `codeflow-authority`, checks out
  nothing and runs no action. When that environment holds a GitHub App (the
  variable `CODEFLOW_AUTHORITY_APP_ID` and the secret
  `CODEFLOW_AUTHORITY_APP_KEY`), one step mints the App's installation
  token, masked, scoped to Checks write on the repository and revoked when
  the step ends, and creates an `authority:` check for each verdict job on
  the head commit, concluded from that job's result. Without the App it
  creates no check. Every verdict job, and the `authority` job, now ends by
  refusing another producer of a trusted name on the head: a check run of
  that name from another workflow, event or app, a commit status of a
  `trusted:` or `authority:` name, or an API error fails the check. The
  verdict jobs' read-only token gains read access to actions, checks and
  statuses for this. The hosted `codeflow ci` report adds one line after the
  verdict naming the commit that judged, the check identity (the App or
  GitHub Actions) and the default branch's host rules; it never changes the
  verdict. Migration: none for Mode B; for Mode A, install the App and set
  up the environment, then run `codeflow remote protect --check-app <id>`.
