### Added

<!-- codeflow:release-impact minor -->
- **The policy workflow can name an App as the only producer of a
  verdict.** The `codeflow-policy` workflow gains an `authority` job for
  pull requests into the default branch. It is the only job that
  references the environment `codeflow-authority`, checks out nothing and
  runs no action. When that environment holds a GitHub App (the variable
  `CODEFLOW_AUTHORITY_APP_ID` and the secret `CODEFLOW_AUTHORITY_APP_KEY`),
  one step mints the App's installation token, masked, scoped to Checks
  write on the repository and revoked when the step ends, and creates an
  `authority:` check for each verdict job on the head commit, concluded
  from that job's result. With ruleset B pinning those names to the App
  (`codeflow remote protect --check-app <id>`), this is Mode A, the only
  mode that closes forgery of a verdict check. Without the App the job
  creates no check, and the repository is in Mode B, a lower tier: every
  verdict job, and the `authority` job before it creates anything, refuses
  another producer of a trusted name that is on the head when it runs (a
  check run of that name from another workflow, event or app, a commit
  status of a `trusted:` or `authority:` name, or an API error). Mode B
  does not close forgery by a later producer: GitHub takes the newest
  check run of a name, so a workflow that runs after the verdict job can
  still satisfy a `trusted:` name pinned to GitHub Actions. `codeflow
  remote protect`, `codeflow doctor --check remote-perimeter` and the
  report line say so whenever Mode B is in force. The verdict jobs'
  read-only token gains read access to actions, checks and statuses for
  the refusal. The hosted `codeflow ci` report adds one line after the
  verdict naming the commit that judged, the check identity (the App, or
  GitHub Actions with the Mode B limit) and the default branch's host
  rules; it never changes the verdict. Migration: none for Mode B; for
  Mode A, install the App and set up the environment, then run `codeflow
  remote protect --check-app <id>`.
