### Fixed

<!-- codeflow:release-impact minor -->
- **The guards judge the program Git starts to reach a remote.** To reach
  a remote, Git can start a helper program chosen by the remote's address
  or its configuration, and the guards did not judge that program in every
  case. Both guards now work out, through one shared reading, what Git
  starts for each remote a command contacts. They refuse a helper program
  their policy does not admit, and refuse any command whose remote contacts
  they cannot work out, naming the rule and the way through. Both are new
  refusals under hook integrity. Commands that reach a remote over https,
  ssh or a local path keep their verdict. A project that relies on a helper
  program names it in the new `git.admitted_helpers` list of its policy.
  The guards read that list only from the policy landed on the remote's
  default branch, and it is empty by default. The same list can name a
  program Git starts for account access while it contacts a remote; the
  account finding is then skipped on commands that contact a remote, and
  every other finding stands. See the policy reference.
