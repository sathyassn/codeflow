### Fixed

<!-- codeflow:release-impact minor -->
- **The guards judge the helper program a remote's transport starts.** To
  reach a remote, Git can start a helper program chosen by the remote's
  address or its configuration, and the guards did not judge that program
  for every way Git selects it. Both guards now resolve, through one shared
  reading, the transport Git selects for every remote a command contacts,
  whether the command names it, gives an address or reaches it implicitly,
  for every destination and after the address rewrites Git applies. New
  refusal: a command whose transport starts a helper program refuses under
  hook integrity, naming the program and the remote, and a configuration
  the guard cannot read or a selection it cannot resolve refuses, naming
  the file or the remote. Transports Git runs itself or ships (https, ssh, a
  local path) keep their verdict. A project that uses a helper names it in
  the new admitted-helpers list of its policy; the guards read that list
  only from the policy landed on the remote's default branch, and judge an
  admitted helper as a program word. The same list admits a credential
  helper, such as the GitHub CLI's, that the account rule refuses when a
  fetch or push starts it; the account finding is then skipped for commands
  that contact a remote only, and every other finding stands. The list is
  empty by default. See the policy reference.
