### Fixed

<!-- codeflow:release-impact minor -->
- **The guards judge the program Git starts to reach a remote.** Both
  guards now work out, through one shared reading, what Git starts for each
  remote a command contacts. They refuse a helper program their policy does
  not admit, and refuse any command whose remote contacts they cannot work
  out, naming the rule and the way through. Both are new refusals under
  hook integrity. Commands that reach a remote over https,
  ssh or a local path keep their verdict. A project that relies on a helper
  program names it in the new `git.admitted_helpers` list of its policy.
  The guards read that list only from the policy landed on the remote's
  default branch, and it is empty by default. The same list can name a
  program Git starts for account access while it contacts a remote; the
  account finding is then skipped on commands that contact a remote, and
  every other finding stands. A repository whose index or last commit
  holds the definition for nested repositories, with none in the work tree,
  now refuses commands that may recurse into them; turning recursion off on
  the command line clears it. That definition is read from the top of
  the repository from any directory. A last commit that cannot be read
  refuses, as does a branch with no commit in a repository that keeps its
  branches in a form the guard cannot read, and a setting that changes
  which objects the last commit is read through counts as a possible
  nested repository. The reader collects possible index and object inputs
  across the whole line, including repeated and carried bodies, and judges
  known recorded, absent and inherited states independently. Unresolved
  inputs stay unread in every view and refuse when a contact needs the
  probe. They do not consume the alternate-value bound. More than 3 inputs
  with known alternate values refuse before probing; the line has at most
  27 environment views. Every braced expansion form not known to be literal
  is a possible evaluation and makes every probe input unresolved regardless
  of export or inheritance. Digits-only parameter offsets and subscripts
  remain known. The shell segmenter retains evaluation evidence through
  carried bodies and substitutions. Continued evaluation openers are read
  with the segmenter's lexical state before substitution text is replaced,
  while the original segment boundaries remain unchanged.
  The segmenter's quote, comment and heredoc
  rules distinguish executable expressions from data. Recognized arithmetic
  command operands, setters with expanding destinations and whole-shell
  export options add the same uncertainty. The reader is conservative;
  the recognized forms do not establish exhaustive shell coverage.
  Supported zsh builtin operand forms add arithmetic uncertainty.
  Continued unbraced parameter subscripts, including special parameter names,
  retain evaluation evidence. Operand checks retain the unfilled reading in its
  shell context; filled words add checks and never suppress that reading.
  The supported formatted-output readers share option-value boundaries.
  Nonliteral words in option or format positions retain arithmetic and
  object-input uncertainty, including words after a literal format while
  options remain open and expansions into several words. Quoted literals
  keep their provenance. Configuration uncertainty has its own reading of
  options that may conceal a destination. Option values with unsettled word
  counts add configuration uncertainty even when their first character is
  literal; quoted scalar formats retain their single-word provenance.
  Literal and literal-led data words do not add it. Supported top-level
  writes, loops and sourced commands invalidate tracked literals through
  leading assignments and recognized precommand modifiers or launchers.
  Unresolved prefixes and unread writer effects invalidate all tracked values.
  Writes inside grouped bodies are not fully tracked.
  Coverage remains conservative. Accepted refusals include a single expanding
  formatted-output word and expanding options or formats after literal
  assignments. Unread object inputs refuse ordinary fetches and pulls when
  recursion is on, even without inherited inputs. Literal string formats and
  explicit option terminators keep data outside the additional operand check.
  Unsettled option values can refuse commands even with recursion off.
  Quoted substitutions, complex quoted parameter forms and unquoted brace
  forms are conservative refusals in option values. Supported writer forms
  can lose tracking even without an actual write, including through external
  launchers whose child cannot change the parent shell.
  The tokens-only configuration reader retains its earlier conservative
  refusals where quote provenance is unavailable.
  Ordinary output without format or destination operands adds no such check.
  Numeric special parameters remain known in arithmetic operand
  positions. Explicit
  inline shell bodies retain their shell's operand rules; an unspecified
  shell retains the conservative supported readings.
  A direct assignment on the current Git command is certain; a carried
  prefix remains uncertain. Runner children independently keep or clear
  each known input, subject to the same 3-input bound. Generated indices
  and unproved callback indices stay unresolved. Clearing the whole
  environment marks every probe input unresolved for the line without
  consuming the bound; its own direct command keeps certain absent or
  assigned inputs. Earlier authority refusals remain when recursion is off.
  These conservative views can add refusals even when the actual child
  would not recurse. A very large
  index refuses every command that may recurse and reads the index (fetch,
  pull, a remote update and adding a remote that fetches). A push whose
  recursion may be on, by its command line or by a setting in any
  configuration scope, a user's own included, and in the check mode too,
  now refuses, because it recurses into the nested repositories of the
  revisions it sends, which the guards do not read. Anyone who sets push
  recursion on, in a project or for their own account, now needs the
  recursion-off option on each push; a push that leaves recursion off
  keeps its verdict. See the policy reference.
