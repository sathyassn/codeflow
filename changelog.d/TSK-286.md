### Fixed

<!-- codeflow:release-impact patch -->
- **The deletion guard reads `xargs`, `parallel` and `find` as the real
  tools do.** A native fixture now runs each tool on disposable files and
  checks that a deletion the guard allows removes what the guard judged.
  It found forms the guard allowed that reach a path it would refuse when
  typed directly. A shell run by `xargs` now sees every value at once, as
  `xargs` passes them, so `"$2"` names the second value. `parallel`
  command text is read as the shell text `parallel` runs. A `find` call
  that deletes is allowed in one shape only: starts named explicitly after
  options both BSD and GNU `find` read, no protected directory (such as a
  home or the temp root) at or below a start, and `rm`, `rmdir`, `unlink`,
  `shred` or `srm` by that bare name, with options and `{}`, as the
  command it runs; a read-only program such as `grep` may also run. The
  same holds for its `-print0` list piped to `xargs -0` or `parallel -0`.
  A `find` walk may reach, by a pipe, a substitution or a file, only
  `xargs`, `parallel`, a plain remover or a program that only reads, such
  as `grep`, `wc` or `sort`. These forms are now refused as unproven: an
  interpreter, `mv`, a shell or a launcher run on the matches, `rg` or
  `git grep` run on them (`--pre` and a pager run other programs), a walk
  piped, substituted or written to a file for `python3`, `awk` or a shell,
  `{}/x`, a `+` that does not follow `{}`, no start, an attached or
  clustered option, a `find` walk read by `read` or `mapfile`, `xargs`
  input from a file or an unread command, `find` output framed by blanks
  (a name holding a blank splits into other paths), `find -L`, `parallel`
  replacement strings such as `{.}`, and more than one `:::` list. `ls
  DIR` piped on is also read from the consumer's directory, where its bare
  names land. Relative paths are read from the directory the hook payload
  names, not the hook process's own. Use `find -print0` with `xargs -0`,
  or literal paths, for a recursive deletion.

<!-- codeflow:release-impact patch -->
- **A submodule path with a backslash and a remote name with a slash are
  read as git reads them.** On Unix, a `.gitmodules` path `a\b` is no
  longer taken for `a/b`, so a nested repository at `a/b` is reported. A
  remote-tracking ref is split at the configured remote name, so
  `refs/remotes/team/a/main` of the remote `team/a` is its landing line
  `main`.
