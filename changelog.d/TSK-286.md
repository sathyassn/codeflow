### Fixed

<!-- codeflow:release-impact patch -->
- **The deletion guard reads `xargs`, `parallel` and `find` as the real
  tools do.** A native fixture now runs each tool on disposable files and
  checks that a deletion the guard allows removes what the guard judged.
  It found forms the guard allowed that reach a path it would refuse when
  typed directly, and each is now refused: a shell run by `xargs` that
  reads `$2` (the guard read each value alone; `xargs` passes them
  together), `xargs` input from a file or an unread command, `find` output
  framed by blanks (a name holding a blank splits into other paths),
  `find -L`, a `find -execdir` command naming a relative path, a batched
  `find -exec … {} +` shell that reads `$2`, and `parallel` command text,
  which `parallel` runs in a shell, replacement strings such as `{.}`,
  and more than one `:::` list. `ls DIR` piped on is also read from the
  consumer's directory, where its bare names land. Use `find -print0`
  with `xargs -0`, or literal paths, for a recursive deletion.
- **A submodule path with a backslash and a remote name with a slash are
  read as git reads them.** On Unix, a `.gitmodules` path `a\b` is no
  longer taken for `a/b`, so a nested repository at `a/b` is reported. A
  remote-tracking ref is split at the configured remote name, so
  `refs/remotes/team/a/main` of the remote `team/a` is its landing line
  `main`.
