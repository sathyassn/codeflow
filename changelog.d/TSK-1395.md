### Fixed

<!-- codeflow:release-impact patch -->
- **CodeFlow's git hooks run for every git invocation in the project.**
  `codeflow init` now sets `core.hooksPath` to the absolute path of the main
  working tree's `.codeflow/git-hooks`, which every worktree shares, so the
  hooks run however an invocation names the repository and its working
  directory (ADR-0099, superseding ADR-0055 item 5's relative path).
  `codeflow update` moves an existing project's relative path, or a path a
  moved or renamed repository left behind, to the new form with no other
  step, and wires an unset path where the project records its hooks as
  wired; another hook manager's path is left alone. `codeflow doctor
  --check hooks` reports the relative form and a stale path and names
  `codeflow update`. A worktree no longer runs the shims from its own
  checkout.
