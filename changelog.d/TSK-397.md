### Changed

<!-- codeflow:release-impact major -->
- **Breaking: the exec guard applies a strict text rule to every shell
  call by default.** The strict rule judges every word after a program the
  guard cannot read through, with no program exempt by name (ADR-0088). On
  the 49-line everyday sample it refuses 43 lines where the relaxed rule
  refuses 31, for example `echo "$HOME"`, `cd "$TMPDIR" && ls` and
  `grep -rn "$PAT" src`.
  - The new policy key `security.text_guard` takes `strict`, the default
    and also the meaning of an absent key, or `relaxed`, which applies the
    previous rule. `relaxed` is the operator's choice; the guard verifies
    no sandbox. It is honoured only when it is read from the
    remote-tracking refs as last fetched (the default branch and any
    declared line, where `strict` wins), so it takes effect once it lands
    on every one of them and is fetched. A working copy, a local branch or
    tag, a remote `HEAD` that points outside the remote, a ref file that is
    a symbolic link and a repository without a remote stay strict. A
    Claude Code call also needs `relaxed` in its session project's policy.
  - The strict rule's refusals always block, whatever `git.hook_integrity`
    says; that level now applies only to the line's own findings.
  - Under `relaxed`, a recognized marked retry (`dangerouslyDisableSandbox`)
    and every call on native Windows still take the strict rule.
  - Migration: nothing is needed to take the strict rule. A project that
    wants the previous rule lands `"security": {"text_guard": "relaxed"}`
    in `.codeflow/policy.json` through a reviewed merge to its protected
    branch. `codeflow doctor --check sandbox` prints the rule in force
    and the ref it was read from. `codeflow init` and `codeflow update`
    never write the key.
  - Neither rule allows a line the previous rule refused, except a line
    made only of bare `cd`, `pushd` and `popd` builtins, which writes
    nothing (issue 342, below); the strict rule still refuses that line.
  - Limits: a program whose text the guard does not read, such as a
    script file, is contained only by the OS sandbox; the `Monitor` tool
    is outside the hook matcher; an unsandboxed retry the harness does not
    mark (Codex has no such field) follows the rule in force. The
    remote-tracking refs `relaxed` is read from are local state, not
    authenticated: a process that can write `.git` can set them. Neither
    rule sees the environment a command inherits (`PATH`, `HOME`, Codex's
    `shell_environment_policy`, secret-bearing variables).
<!-- codeflow:release-impact patch -->
- **The presets deny writes to the enforcement paths explicitly.** The
  shipped Claude presets list each enforcement path as a
  `sandbox.filesystem.denyWrite` entry beside its `Edit(...)` deny, and a
  new protected directory, `~/.codeflow/authority/`, is denied in the
  Claude presets, the Codex `cf-guard` profile and the Grok profiles. No
  command uses it yet. `codeflow update` delivers both.

### Fixed

<!-- codeflow:release-impact patch -->
- **A directory change is not a startup file write.** The shell's own
  `cd`, `pushd` or `popd` whose operand the guard cannot resolve is no
  longer refused under `security.shell_startup` (issue 342), on a line
  made only of bare `cd`, `pushd` and `popd` builtins with literal or
  plain `"$var"` arguments. Any other line keeps the write judgment. The
  line passes under `security.text_guard: relaxed`; the default strict
  rule refuses its run-time operand.
<!-- codeflow:release-impact patch -->
- **Commands the shell and the guard would read differently.** A command
  holding a NUL byte is refused. The headless-run check no longer guesses
  the program after an `xargs` option it cannot place (GNU's bare
  `--replace`, `--eof` and `--max-lines`, BSD's `-J`, `-R` and `-S`), and
  reads GNU-prefixed launchers such as `gxargs`.
