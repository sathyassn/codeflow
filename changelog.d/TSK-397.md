### Fixed

<!-- codeflow:release-impact patch -->
- **Shell directory changes the guard cannot follow.** Where a `cd` lands
  depends on shell state the exec guard cannot see: `cd` functions and
  aliases, zsh `chpwd` hooks, the shell's `HOME`, `CDPATH`, `PWD` and
  directory stack, and `cdable_vars`. Every shell directory change on a
  line (`cd` in any form, `chdir`, `pushd`, `popd`), and anything that can
  run one the guard does not read (`eval`, `source`, `.`, a `trap` action,
  `alias`, a hook assignment, or any other command before the interpreter
  call, which may be a shell function), now makes the directory unknown, so a later interpreter argument whose trailing path
  could name a protected file is refused, as is any line that names
  `CDPATH` or `cdpath` however it is quoted. `ruby -C` operands resolve
  symbolic links before `..`. Each closes a way to read a protected file
  through a relative path.
