### Fixed

<!-- codeflow:release-impact patch -->
- **Directory changes the guard cannot follow.** The exec guard keeps
  judging an interpreter's arguments from the starting directory after a
  `cd`, because where a `cd` lands depends on shell state the guard cannot
  see. It now also treats these as an unknown directory: a `..` in a `cd`
  target, a `cd` operand that reaches no existing directory (as with
  `cdable_vars`), zsh's two-operand `cd`, any `CDPATH` or `cdpath` mention
  however it is quoted or encoded, and any `cd` that a `CDPATH` could
  redirect, since the shell may hold one the guard never sees. `CDPATH`
  entries and `ruby -C` operands are resolved through symbolic links
  before `..`. Each closes a way to read a protected file through a
  relative path.
