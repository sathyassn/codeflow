### Fixed

<!-- codeflow:release-impact patch -->
- **Shell directory changes the guard cannot follow.** Where a command
  leaves the shell depends on state the exec guard cannot see: `cd`
  functions and aliases, zsh `chpwd` hooks and `autoload`, the shell's
  `HOME`, `CDPATH`, `PWD` and directory stack, and `cdable_vars`. A shell
  directory change on a line (`cd` in any form, `chdir`, `pushd`, `popd`),
  anything that can run one the guard does not read (`eval`, `source`, `.`,
  a `trap` action, `alias`, a hook assignment, a current-shell
  substitution such as `${ cmd; }`), and any other command on the line,
  which may be a shell function, now makes the directory unknown. A later
  interpreter argument whose trailing path could name a protected file is
  refused, as is `.`, `..` or any operand filled in at run time from such
  a directory, and any line that names `CDPATH` or `cdpath` however it is
  quoted. Every word is read by one shell lexer that knows quoting, ANSI-C
  `$'...'`, substitutions and here-documents. `ruby -C` operands resolve
  symbolic links before `..`.
<!-- codeflow:release-impact patch -->
- **One fail-closed rule for programs the guard does not know.** Wherever
  the guard stops reading a command, at its start or inside a launcher
  such as `env`, `nice` or `xargs`, the words after that program are judged
  as an interpreter's possible arguments, unless the program is on a short
  allowlist of programs that run nothing (`ls`, `cat`, `grep`, `rg`,
  `sort`, `printf`, `test`, `cd`, `git log` and others) and is used only
  with the options its entry lists. An option that runs a program, writes
  a file or evaluates a word (`rg --pre`, `sort --compress-program`,
  `sort -o`, `file -z`, `printf -v`, `test -v`), an abbreviation of a long
  option, an option filled in at run time, arguments `xargs` appends, and a
  line that defines an alias or function or changes `PATH` all make the
  program not exempt. A zsh extended pattern (`#`, `^`, `~`) in a program
  word, and a command substitution inside an array subscript, are read as
  run-time values. Ordinary commands with a run-time value outside the
  allowlist now refuse once the directory is unknown, for example
  `cargo test -p "$CRATE"`, `find "$D" -delete` and
  `git commit -m "$(cat <<'EOF' ...)"`. The guard decides early from the
  command text; what text cannot show (shell functions from a profile,
  inherited traps, unknown programs on `PATH`) is left to the OS sandbox,
  whose denials on protected paths are the backstop.
<!-- codeflow:release-impact patch -->
- **A directory change is not a startup file write.** The shell's own
  `cd`, `pushd` or `popd` whose operand the guard cannot resolve is no
  longer refused under `security.shell_startup` when run from `/` or the
  home (issue 342), on a line made only of bare `cd`, `pushd` and `popd`
  builtins with literal or plain `"$var"` arguments. Any other line,
  including a launcher, path, rebinding or loop form, keeps the write
  judgment.
