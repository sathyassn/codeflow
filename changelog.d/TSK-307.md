### Fixed

<!-- codeflow:release-impact patch -->
- **A misshapen acceptance file is refused by name.** `codeflow task status
  <id> complete --acceptance <file>` (and `epic status`) used to insert the
  file as it was. A file that lacked the top-level `acceptance:` key, such as
  one that began with the fields the Closeout comment lists, was then
  refused as "a complete record needs an acceptance block in its Closeout",
  which named the task record and read as a problem with it
  (sathyassn/codeflow#175). The command now reads the file first. It
  refuses a file without the top-level `acceptance:` key before it writes
  the record, and the message names the file, the key and the fields the
  key holds. A file that is not valid YAML and does not open with
  `acceptance:` is refused with the file name and the parse error. A file
  that opens with `acceptance:` goes on as before to the field checks,
  which report the real field problems; the field checks, not YAML, judge
  the block, so a value such as `none: nothing deferred` is still
  accepted. The `--acceptance` help and `docs/cli.md` now say that the file
  holds a top-level `acceptance:` key and list its fields. The only
  behaviour that changes is the refusal of a file that never worked.
