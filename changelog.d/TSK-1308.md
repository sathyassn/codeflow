### Added

<!-- codeflow:release-impact minor -->
- **A landed candidate branch is removed with a recorded proof.**
  `codeflow work remove-candidate <branch> --line <line>` removes a local
  landing candidate branch whose line got the same tree through another
  commit, which `git branch -D` cannot do because no other ref reaches its
  commits. It fetches the line from origin, which must be a protected
  branch or an `integration/` line, finds a commit on its
  first-parent history with the candidate's tree, and refuses, naming the
  cause, when the trees differ, the tree is only on a side branch, the line
  or branch cannot be read, a worktree uses the branch, a pull request is
  open from it, or its name is not a candidate's. The removal is recorded in
  the ledger as `candidate_removed`; `--dry-run` shows the proof first. The
  policy keys `git.candidate_prefix` (default `candidate/`) and
  `git.candidate_search_depth` (default 200) set the naming and the depth.

### Fixed

<!-- codeflow:release-impact patch -->
- **A leftover local branch no longer blocks a push or a claim.** In a clone
  with a remote, a local branch that no remote holds and no worktree has
  checked out, such as a replaced landing candidate or a task branch left
  from an earlier use of an id, no longer counts as a completion outside a
  pushed range (`work.criteria_frozen`, `work.acceptance_binding`) or as a
  claim of `codeflow work claim`, which names it as information. A
  published or checked-out branch still counts, and so does every local
  branch in a clone with no remote.
