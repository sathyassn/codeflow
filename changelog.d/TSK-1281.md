### Added

<!-- codeflow:release-impact minor -->
- **`codeflow test guards` names the tests that guard the paths a change
  touches.** A new top-level `guards` list in `.codeflow/test-config.json`
  maps path globs to the commands that run their guarding tests. The
  command reads the change from the merge base of `HEAD` with the task's
  line, or from `--since <rev>`, to the working tree, prints each touched
  path's tests and each path no rule covers as unguarded, and lists the
  targets the `narrow` and `input_class` declarations would select. It runs
  nothing, and no gate run applies that selection: every run still
  executes every eligible target (ADR-0089). The build guidance now names
  it for the targeted tests step. An older binary reading a config with
  `guards` prints a warning that it ignores the field and runs as before.
