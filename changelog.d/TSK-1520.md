### Fixed

<!-- codeflow:release-impact patch -->
- **`codeflow ids check` and `codeflow doctor`'s id check verify the commit
  graph once per run.** Before, each git history query they made, such as
  one ancestry test per landing tip, read the history overlays and verified
  the whole commit graph again, so a check over a repository with hundreds
  of refs could run for most of an hour. Both now run their history reads in
  one read-only judgment, as `codeflow ci` already did, so the graph is
  verified at most once per repository per run. Findings, their order, the
  refusal text and the exit code are unchanged on the same inputs. As in
  `codeflow ci`, a history overlay or shallow boundary added while the check
  runs need not be noticed until the next run, and a commit-graph rewritten
  while the check runs, for example by `git maintenance` or a fetch, now
  makes it refuse with exit 2 instead of passing on the next query; rerun
  the check.
