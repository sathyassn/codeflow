### Fixed

<!-- codeflow:release-impact patch -->
- **`codeflow ids check` and `codeflow doctor`'s id check verify the commit
  graph once per run.** Before, each git history query they made, such as
  one ancestry test per landing tip, read the history overlays and verified
  the whole commit graph again, so a check over a repository with hundreds
  of refs could run for most of an hour. Both now run their history reads in
  one read-only judgment, so the graph is verified at most once per
  repository per run. Replace refs, graft files and the shallow file are
  still read for every history query, and its Git processes ignore replace
  refs. Findings, their order, the refusal
  text and the exit code are unchanged on the same inputs. A commit-graph
  rewritten while the check runs, for example by `git maintenance` or a
  fetch, is detected at the next history query and refused:
  `codeflow ids check` exits 2 and `codeflow doctor` exits 1. Rerun the
  check.
