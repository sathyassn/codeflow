### Changed

<!-- codeflow:release-impact minor -->
- **The session guard refuses the release routes that went around `gh
  release`.** `exec-guard` now refuses, under `security.outward_actions`, a
  dispatch of a release workflow through `gh workflow run`, `gh api` or
  `curl` (dry runs included), a repository dispatch a release workflow
  listens for, a pending deployment approval, a release or tag created
  through the API or GraphQL, and writes to Actions policies, environments
  and rulesets. It also refuses a deployment write, enabling a release
  workflow, a change to a variable or secret a release workflow reads, and
  a branch protection write, and it reads `wget`, HTTPie and xh like `curl`
  and `GH_REPO` like `-R`. Each publishing job of CodeFlow's own release
  workflows now fails a re-run as its first step, and `docs/releasing.md`
  gives adopters the same step. A release workflow is read from the
  workflow files on the remote's default branch; a numeric workflow id, an unknown name, another
  repository or an unreadable file is refused. A push of a bare `v*` or
  digit-led name is refused even without a local tag. `docs/releasing.md`
  names the routes the guard cannot judge and the remote settings that
  hold for them.
