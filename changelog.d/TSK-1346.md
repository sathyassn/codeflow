### Changed

<!-- codeflow:release-impact minor -->
- **The session guard refuses the release routes that went around `gh
  release`.** `exec-guard` now refuses, under `security.outward_actions`, a
  dispatch of a release workflow through `gh workflow run`, `gh api` or
  `curl` (dry runs included), a repository dispatch a release workflow
  listens for, a pending deployment approval, a release or tag created
  through the API or GraphQL, and writes to Actions policies, environments
  and rulesets. It also refuses a deployment write, enabling a release
  workflow, a change to a variable or secret a release workflow reads, and
  a branch protection write. It judges a URL by its host whatever
  userinfo, port or case it carries, judges GraphQL on every API path and
  client, resolves gh's `{owner}/{repo}` from `-R`, `GH_REPO` or the
  current repository, and judges a gh alias as its expansion. An HTTP
  client write to a parsed host other than GitHub's is allowed; one with
  an unknown option, an unparsed destination or a redirect is refused,
  each `curl --next` request judged on its own. When a client's config
  file exists in the environment the call runs with, every call is
  refused unless it skips the file: `curl` needs `-q` first, and `wget`
  always needs `--no-config`, since its system `wgetrc` cannot be checked.
  HTTPie and xh have no such flag. `docs/releasing.md` gives
  adopters a first step that fails a re-run of a publishing job; CodeFlow's
  own release workflows get it once the operator applies the reviewed
  workflow change. A release workflow is read from the workflow files on
  the remote's default branch; a numeric workflow id, an unknown name,
  another repository, repositories that disagree or an unreadable file is
  refused. A push of a bare `v*` or digit-led name is refused even without
  a local tag. `docs/releasing.md`
  names the routes the guard cannot judge and the remote settings that
  hold for them.
