### Fixed

<!-- codeflow:release-impact patch -->
- **Coverage rules written in `defaults.coverage` now apply.** The test
  config schema has always said these rules apply "when targets omit
  them", but the gate ignored them, so a project that wrote its coverage
  floor once in `defaults.coverage` got no floor at all. A full gate now
  judges every target whose `coverage` block sets no rules by the default
  rules, exactly as if the target had written them: a shortfall or a
  missing coverage artifact fails the gate, and the summary marks the
  target "(rules from defaults.coverage)". A target's own non-empty rules
  replace the defaults. A project that already wrote defaults may see the
  floor it configured begin to fail its full gate. While the defaults are
  not empty, a test target with no `coverage` block gets one warning line
  in the full gate's coverage summary, naming it and the missing coverage
  producer; its verdict does not change. A `changed_files` default rule
  that a target would inherit is refused at load, as a target's own one
  already is. Nothing changes for a project whose defaults are empty.

<!-- codeflow:release-impact patch -->
- **The `example-rust.json` test-config template's coverage step now
  works.** cargo-llvm-cov does not create the folder of its
  `--output-path`, so the template's `target/llvm-cov/lcov.info` failed
  its first full gate on a clean checkout. The template now writes
  `target/lcov.info`, which cargo's own build folder holds; a config made
  from the old template keeps working once that folder exists, or can
  take the new path.

### Changed

<!-- codeflow:release-impact minor -->
- **`codeflow test setup` writes a coverage block for each detected
  stack.** A newly written config's detected target now runs its stack's
  coverage producer in full mode and names the artifact it writes:
  cargo-llvm-cov for Rust, coverage.py for pytest, `@vitest/coverage-v8`
  for Vitest, and the built-in coverage of Jest and `go test`. The block
  sets no rules, so it only collects until the project writes rules.
  Setup writes it only when it creates the config; an existing populated
  config, `codeflow update` and the gate's own detection for a project
  with no config are unchanged. `codeflow doctor` prints one line naming
  the producer to install when a target's full command runs one that is
  missing, since that full gate cannot pass until it is installed.
