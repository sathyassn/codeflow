### Fixed

<!-- codeflow:release-impact patch -->
- **Codex builder seats open again on Codex 0.163 and later.** Codex now
  loads config at startup without the project's `.codex/config.toml`, so the
  managed builder launch, which selected the project-only `cf-builder`
  profile with `-c default_permissions="cf-builder"`, stopped with "failed
  to load workspace requirements". The launch now also passes
  `-c 'permissions.cf-builder.description="CodeFlow builder seat"'`, which
  grants nothing on its own and merges unchanged into the project profile.
  `cf-builder` also writes `~/.codeflow/locks`, so a builder can run
  `codeflow reserve` and the gates; nothing else under the home folder is
  writable. `codeflow doctor --preflight` asks the installed Codex whether
  it accepts the builder overrides and reports a rejection. Update the
  launch line of any builder seat started by hand.
