### Fixed

<!-- codeflow:release-impact patch -->
- **Codex builder seats open again on Codex 0.163 and later.** Codex now
  loads config at startup without the project's `.codex/config.toml`, so the
  managed builder launch, which selected the project-only `cf-builder`
  profile with `-c default_permissions="cf-builder"`, stopped with "failed
  to load workspace requirements". The launch now also passes
  `-c 'permissions.cf-builder.description="CodeFlow builder seat"'`, which
  grants nothing on its own and merges unchanged into the project profile.
  `cf-builder` also writes `~/.codeflow/locks`, so a builder can run
  `codeflow reserve` and the heavy quick targets that take the shared lock;
  a full gate still cannot store its evidence under `~/.codeflow/gate-runs`
  from a builder seat. Nothing else under the home folder is writable.
  CodeFlow now opens its gate lock files without following links and
  rewrites them only through the locked file, so a link planted in a
  writable lock folder cannot redirect a later gate's writes.
  `codeflow doctor --preflight` asks the installed Codex whether it accepts
  the builder overrides, reports a rejection, and says whether the project
  config was seen to load. Update the launch line of any builder seat
  started by hand.
