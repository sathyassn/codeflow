### Added

<!-- codeflow:release-impact minor -->
- **The commit-time secret scan can run the pinned gitleaks rules.** With
  `git.secret_scan_engine: gitleaks`, the pre-commit hook runs the gitleaks
  release the managed CI scan pins (8.30.1) over the staged diff after the
  built-in patterns, reading the working tree's `.gitleaksignore` and
  `.gitleaks.toml`, so a match only the CI rules see is refused while the
  commit can still be reworded. The hook runs the binary only when its
  SHA-256 is the official release binary for the platform and it reports
  the pinned version; a missing, mismatched or unpinned binary refuses the
  commit at `block` and warns at `warn`. The hook never downloads it.
  `codeflow doctor --check secret-engine` reports the folders searched, the
  checksum and version found and the pin. The default, `builtin`, is
  unchanged. A staged finding's fingerprint names no commit, so a CI
  fingerprint never covers it; allowlist a known false-positive file by path
  in `.gitleaks.toml`.

### Fixed

<!-- codeflow:release-impact patch -->
- **A merge Git concludes itself is scanned for secrets.** Git runs no
  pre-commit hook for an automatic merge, so a merge driver that wrote a key
  neither parent held reached the commit unscanned. The commit-msg hook now
  runs the staged scan, built-in patterns and the gitleaks engine when
  chosen, when Git passes `MERGE_MSG`, and refuses a message file other than
  `MERGE_MSG` or `COMMIT_EDITMSG` instead of skipping the scan.
