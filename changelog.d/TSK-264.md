### Changed

<!-- codeflow:release-impact minor -->
- **Each pull request carries its pending changelog entry in its own
  fragment (issue 119).** CodeFlow's own pending entries moved out of the one
  pending section of `CHANGELOG.md`, where every open pull request inserted
  into the same lines and each landing forced a hand-resolved merge on the
  others, into one file per pull request under `changelog.d/`. A fragment
  holds its entries under `### Added`, `### Changed`, `### Deprecated`,
  `### Removed`, `### Fixed` or `### Security`, each with its impact marker.
  `scripts/release.py` composes the fragments into the pending section for
  `check-pr`, `check-state`, `preflight`, `sync` and the publishability
  check, by kind and then by file name, and refuses a malformed fragment by
  name. A tree holds its pending entries in fragments or in one written
  section, never both. `sync` stamps the version the fragments bump to and
  writes no section. The new `release.py assemble`, run in a reviewed pull
  request that declares `Impact: none`, writes the section and removes the
  fragments before publication, and `release-notes` refuses a source that
  still holds one. A typed repair may remove a whole fragment as a
  withdrawal. `scripts/changelog_split.py` moved the existing entries and
  moves an open pull request's entries at its next main merge. See
  "Pending entries, local checks and repairs" in `docs/releasing.md`.
