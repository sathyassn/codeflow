### Fixed

<!-- codeflow:release-impact patch -->
- **`codeflow ci` refuses a direct commit on a landing candidate before
  its gate.** A candidate for an `integration/EPC-*` line that held a
  commit made directly on it passed `codeflow ci` and the full gate, then
  the pre-push hook refused the push with `work.epic_line` (issue #489).
  `codeflow ci` now judges a candidate's head as the line's next tip with
  the hook's own rule and message when run with `--line-tip <LINE>`. The
  range always starts at the line's fetched tip `origin/<LINE>`, and the
  line must be bound by the records at that tip; a line it cannot
  establish, unreadable history and a malformed adoption entry each refuse.
  A run with no pull request and no push context whose base is the fetched
  tip of exactly one epic line reports the same finding as a warning. A
  pull request head, which lands by merge, and a push are judged as
  before. `codeflow update` rewrites the
  landing text in `git-rules.md`.
