<!-- codeflow:release-impact patch -->
- **Local history checks refuse rewritten parents.** Acceptance binding,
  journey scope, reopen detection, landing checks, reviewed stacks and
  range selection share a guarded history reader. A graft file or any ref
  under a replace-ref base, including nested and suffixed names, produces
  `cannot verify`; a walk that reaches a shallow boundary
  also refuses. Pre-push, `work start` and local `codeflow ci`, including a
  task-less branch without a PR body, no longer accept parent links supplied
  by those overlays. Each read-only judgment checks its history metadata
  once, keeping long parent walks from repeatedly scanning every ref.
  Remove the overlay or use a clean clone. `codeflow ci` and pre-push now
  refuse any shallow clone; run `git fetch --unshallow` or use a CI checkout
  with `fetch-depth: 0` to provide full history.
  Shallow checks include linked worktrees. Judging Git subprocesses ignore
  inherited repository and object-store redirects and disable commit-graph
  reads. The reader checks cached graph parents and ancestry metadata
  against commit objects; ordinary commit-graphs remain allowed, while a
  mismatched cache must be removed before retrying. Relative graft overrides
  resolve from the query directory. No policy or record migration is needed
  (TSK-287, issue 122).
