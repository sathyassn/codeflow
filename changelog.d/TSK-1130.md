### Fixed

<!-- codeflow:release-impact patch -->
- **A hooks path inherited from the environment is refused.** git-guard and
  exec-guard now refuse a Git call when `core.hooksPath` is set in the command
  scope, including through `GIT_CONFIG_COUNT` or `GIT_CONFIG_PARAMETERS` that
  the hook process inherited. Before, only an assignment written in the
  command was refused, so an inherited path could run its own hooks. A hooks
  path in a repository, global or system file is unchanged. Migration: unset
  the inherited variables, or put the path in a configuration file.
