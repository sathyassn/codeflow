### Fixed

<!-- codeflow:release-impact patch -->
- **A hooks path that the repository does not own is refused.** git-guard and
  exec-guard now refuse a Git call when the `core.hooksPath` in force comes
  from the command scope (including variables the hook process inherited),
  the global scope or the system scope, because the environment can select
  those files and the path replaces the repository hooks. Before, only an
  assignment written in the command was refused. A hooks path in the
  repository's own configuration is unchanged. The guards also refuse git when an
  inherited `GIT_DIR`, `GIT_COMMON_DIR` or `GIT_WORK_TREE` moves Git to another
  repository. Migration: move a global or
  system `core.hooksPath` into the repository's configuration, or unset it.
