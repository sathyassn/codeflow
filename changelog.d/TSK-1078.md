### Fixed

<!-- codeflow:release-impact patch -->
- **Landed policy in local hooks.** Classic git hooks enforce the default
  branch's landed policy as a floor.
  A stale, branch-edited or uncommitted policy file cannot lower a hook
  level, drop a landed requirement-list entry or raise a commit limit.
  Admitting lists intersect. Force-push checks retain both protection
  classifications; naming exemptions retain landed protection and candidate
  eligibility. A protected branch added only
  in the checkout adds prohibitions; it grants no trust, picks no range base
  or default branch, and exempts nothing from branch naming. A malformed
  ticket reference now blocks at every `commit_ticket_required` level, so a
  project that set `warn` with a ticket pattern sees that block where it saw a
  warning. Unreadable authority refuses the operation.
  CI range selection retains protected branches and ignores work prefixes
  added only in the checkout, reading them at the commit the run pins
  (`--policy-from`, `--base`, `--into`, the CI event's base or
  `CODEFLOW_DEFAULT_BRANCH`), or at the remote's default branch when
  nothing is pinned. CI candidate classification reads that floor before
  target or range resolution. Behaviour change: in a clone with a remote but no
  recorded remote default branch (`refs/remotes/origin/HEAD`), commit-msg,
  pre-merge-commit, pre-push and registry pushes now refuse until the operator runs `git remote set-head origin --auto`;
  the refusal names that command. Bootstrap grace keeps its existing
  suspensions. Pre-merge-commit now scans staged secrets and conflict markers
  before recording a merge, at the composed policy level. Merge commits that
  previously passed without these scans can now be refused. Off and allow
  remain inactive when neither policy raises the level.
