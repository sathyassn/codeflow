### Fixed

<!-- codeflow:release-impact patch -->
- **A task's own criteria change on its integration line passes the
  pre-push when `main` holds a different copy.** `codeflow ci` and the
  pre-push hook read the branch's task from the judged head, never the
  checkout, so the verdict is the same from `main`, a detached checkout or
  the task's worktree. Within a bound integration line that the
  destination confirms and the task's record declares, the task's own
  change is judged against the line's tip and the range base; `main`
  stays the policy and history authority, and a completion it or another
  ref holds still refuses. A change to another task's record that leaves
  its criteria as the base holds them is no longer refused for diverged
  copies on `main` and the line. A replacing push, and `codeflow ci` run
  before it, set aside the completion only that branch's own
  remote-tracking ref holds. A line-to-main range now notes a task record
  whose criteria `main` and the line each amended, with the version the
  merge keeps (issues #304, #354, #380, #420, #454).
