### Changed

<!-- codeflow:release-impact minor -->
- **Only the operator installs or refreshes a project's enforcement
  files.** The guards now refuse an agent's run of the init and update
  verbs through the binary named `codeflow`, in every path spelling, launcher
  and folder the guards read, and name the operator as the one who runs
  them. The binary's own help and version forms, called by its bare name,
  stay allowed. Text that names the verbs stays allowed only in a small set
  of forms that print or search, such as `echo`, a `printf` of plain
  strings and `grep`; the same text anywhere else, a commit message
  included, is refused, so put it in one of those forms or leave the
  binary's name out of a search. The text is judged as the shell passes
  it, as plain `printf`, `echo` and `print` output writes it, and as a value
  the line assigns, each alone and all of a line's output joined in order.
  Off those forms, a `printf`, `echo`, `print` or `$'...'` word with an
  escape (a `\n` in a `printf` format excepted), a conversion other than a
  bare `%s`, a width or flag, or more arguments than conversions refuses
  whatever it names, since the guard does not model what it writes; write
  such text literally. Separate outputs on one line that join into the
  verbs refuse too; write them with separate calls. Guard, hook, doctor
  and remedy messages that pointed to either verb now say the operator runs
  it. An agent that ran either verb before now asks the operator instead. A
  renamed or copied binary, and text another program builds and hands to a
  process that is already running, are not identified by the guards; the
  release notes list them with the other limits and the accepted
  over-refusals, and the policy reference names the layers that still
  hold.
