### Changed

<!-- codeflow:release-impact major -->
- **Only the operator installs or refreshes a project's enforcement
  files.** The guards now refuse an agent's run of the init and update
  verbs through the binary named `codeflow`, in every path spelling, launcher
  and folder the guards read, and name the operator as the one who runs
  them. The binary's own help and version forms, called by its bare name,
  stay allowed. Text that names the verbs stays allowed only in a small set
  of forms that print or search, such as `echo`, a `printf` of plain
  strings and `grep`; the same text anywhere else, a commit message
  included, is refused, so put it in one of those forms or leave the
  binary's name out of a search. The text is judged as the shell passes
  it, as plain `printf`, `echo` and `print` output writes it, and as a value
  the line assigns. Where a line hands text it produces to a shell or
  interpreter on the same line, through a pipe, a here-string, a
  substitution, `eval` or a similar route, that text must be one `printf`,
  `echo` or `print` of plain literal text, or a literal here-string or
  here-document. Text the line spells that any other program on the line
  receives, by its input, a file operand, an argument or an output stream,
  takes the same form unless the guard knows that program only reads it as
  data; no interpreter, and no program with an option that runs a program,
  such as `sort`, counts as one. A plain file counts as running that file
  on a line that writes no file. A line of more than one command that
  writes text it spells to a file is now refused, whatever else is on it,
  because a program can run a file the line never names, the shell finds a
  program by its name on the path, where the line may write a file, and the
  shell itself runs text it evaluates. Everyday lines refused this way
  include `printf x > f && git add f`, `mkdir -p d && printf x > d/f`,
  `printf x > f; echo done` and `printf 'all:\n' > Makefile; make`. Write
  the file on one line and run the next command on the next line. One
  command that writes after everything it runs, such as `printf x > f`,
  stays allowed, and so does a file written with a program's own output,
  such as `cargo build > build.log 2>&1 && grep error build.log`. Text the
  shell evaluates as arithmetic is now judged as command text, so
  arithmetic that reads a program's output, or a variable holding it, is
  refused; run the program on its own line and compare the number it
  prints as literal text on the next, such as `[ 12 -gt 3 ]`. Comparing
  the output with `test` or `[` passes this check, but the strict text
  rule (`security.text_guard`) refuses it at its default `strict`, as it
  refuses a command substitution in an argument. A variable that
  arithmetic reads is refused too when the shell sets it from text on the
  line, or when the line assigns it in a way no word on it shows, and text
  the shell expands as a prompt has each substitution in it judged as a
  command line. These refusals follow the level of
  `git.hook_integrity`: `warn` reports them and `off` drops them. A later
  policy option will let a project relax the spelled-write refusal on its
  own, without lowering `git.hook_integrity`. Any
  other line that hands text in another form refuses whatever it names, so
  write the commands literally. Guard, hook, doctor
  and remedy messages that pointed to either verb now say the operator runs
  it. This is a breaking change: a project whose agents ran either verb
  loses that flow on upgrade. The way through is that the operator runs the
  verb, from a terminal outside the agent's session, and an agent that needs
  a refresh asks the operator. A
  renamed or copied binary, text a line writes to a process started
  earlier that runs what it reads, and another program's output that
  reaches a program the guards do not know, are not identified by the
  guards; the
  release notes list them with the other limits and the accepted
  over-refusals, and the policy reference names the layers that still
  hold.
