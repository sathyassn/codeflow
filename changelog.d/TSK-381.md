### Fixed

<!-- codeflow:release-impact patch -->
- **Research pins survive a deleted line.** A research or decision
  dependency stays met after the producer's integration branch is deleted:
  `work next`, `work claim` and `work start` accept a pin that holds the
  producer's completed record when it is on the producer's target, the
  consumer's target or the default branch. In a repository with any
  remote, each target is read at a remote-tracking ref: the branch's
  configured upstream when it is a `refs/remotes/<remote>/<branch>` ref of a
  configured remote, else `origin/<branch>`. A local `main` that is behind
  no longer refuses a landed pin, and no local branch, ahead, unpushed or set
  as an upstream, proves a landing; a local branch counts only in a
  repository with no remote. A missing object, an open or absent record at
  the pin and a pin on no target still refuse, and the refusal names the
  refs it read (#236).

<!-- codeflow:release-impact patch -->
- **Case-different ref names are guarded.** git-guard and the
  reference-transaction hook compare the `refs/heads/` and `refs/remotes/`
  prefix of a ref name, and protected branch names, with ASCII case folded,
  so on a case-insensitive filesystem `REFS/REMOTES/origin/main`,
  `Refs/Heads/main` and `refs/heads/MAIN` no longer pass as other refs. They
  fail closed: a distinct branch named `Main` is refused on a case-sensitive
  filesystem too. Because a filesystem such as APFS also folds some non-ASCII
  characters to ASCII letters (`ſ` names the same file as `s`), the guards
  treat a branch name with a non-ASCII byte as protected, and refuse an
  `update-ref` or `symbolic-ref` name with a non-ASCII byte or a `refs/`
  prefix that matches only without regard to case; the hook still lets a
  fetch write such names under exactly `refs/remotes/` and `refs/tags/`.
  Non-ASCII ref names are rare; work on one is refused by these guards. The
  edit guard folds case for paths under the git directory, refuses any such
  path with a non-ASCII component, and refuses direct writes under
  `.git/refs/heads`, which would move a branch without a ref transaction. Other non-ASCII folds that no guard models, and other planes
  such as pre-push and CI, keep exact matching.
