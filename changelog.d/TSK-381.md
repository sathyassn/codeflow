### Fixed

<!-- codeflow:release-impact patch -->
- **Research pins survive a deleted line.** A research or decision
  dependency stays met after the producer's integration branch is deleted:
  `work next`, `work claim` and `work start` accept a pin that holds the
  producer's completed record when it is on the producer's target, the
  consumer's target or the default branch. In a repository with any
  remote, each target is read at a remote-tracking ref: the branch's
  configured upstream when it is a `refs/remotes/<remote>/<branch>` ref of a
  configured remote, else `origin/<branch>`. A local `main` that is behind
  no longer refuses a landed pin, and no local branch, ahead, unpushed or set
  as an upstream, proves a landing; a local branch counts only in a
  repository with no remote. A missing object, an open or absent record at
  the pin and a pin on no target still refuse, and the refusal names the
  refs it read (#236).

<!-- codeflow:release-impact patch -->
- **Case-different ref names are guarded.** git-guard and the
  reference-transaction hook compare the `refs/heads/` and `refs/remotes/`
  prefix of a ref name, and protected branch names, with ASCII case folded,
  so on a case-insensitive filesystem `REFS/REMOTES/origin/main`,
  `Refs/Heads/main` and `refs/heads/MAIN` no longer pass as other refs, and
  an `update-ref` or `symbolic-ref` name whose `refs/` prefix matches only
  that way is refused. They fail closed: a distinct branch named `Main` is
  refused on a case-sensitive filesystem too. On a case-insensitive
  filesystem (the macOS and Windows defaults) a local branch or an
  `update-ref` or `symbolic-ref` name with non-ASCII characters is refused
  as well, because such a filesystem may fold one to an ASCII letter (`ſ`
  names the same file as `s`). A fetch may still write such names under
  `refs/remotes/` and `refs/tags/`; there the hook refuses a written ref
  whose folded name, or a directory along it, collides with another
  spelling, and a tracking name that folds onto a protected branch it does
  not name, so a fetch of a remote `MAIN` beside `main`, or of
  `INTEGRATION/x` beside `integration/y`, fails instead of landing on the
  other ref. A line that keeps its value, as `git pack-refs` and `git gc`
  write, still passes. That refusal is the control against a fetched alias:
  on a case-insensitive filesystem, readiness needs the hook installed with
  `local_ref_protection` at `block`. Readiness and the sync allowance also
  read a remote-tracking ref only under the exact spelling git lists, which
  catches an alias only while the genuine ref is packed. The guards probe the
  git directory once per invocation, a probe that cannot decide counts as
  case-insensitive, and a command run in another repository (`-C`,
  `--git-dir`, `GIT_DIR`, `cd`) is judged by that repository's own probe, an
  unreadable one counting as case-insensitive; on a case-sensitive git
  directory non-ASCII ref names are ordinary names. The edit guard folds
  case for paths under the git directory, refuses any such path with a
  non-ASCII component, and refuses direct writes under `.git/refs/heads`,
  which would move a branch without a ref transaction. Other non-ASCII folds
  that no guard models, and other planes such as pre-push and CI, keep exact
  matching.
