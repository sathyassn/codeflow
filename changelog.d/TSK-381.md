### Fixed

<!-- codeflow:release-impact patch -->
- **Research pins survive a deleted line.** A research or decision
  dependency stays met after the producer's integration branch is deleted:
  `work next`, `work claim` and `work start` accept a pin that holds the
  producer's completed record when it is on the producer's target, the
  consumer's target or the default branch. In a repository with any
  remote, each target is read at a remote-tracking ref: the branch's
  configured upstream when it is a `refs/remotes/<remote>/<branch>` ref of a
  configured remote, else `origin/<branch>`. A local `main` that is behind
  no longer refuses a landed pin, and no local branch, ahead, unpushed or set
  as an upstream, proves a landing; a local branch counts only in a
  repository with no remote. A missing object, an open or absent record at
  the pin and a pin on no target still refuse, and the refusal names the
  refs it read (#236).

<!-- codeflow:release-impact patch -->
- **Case-different ref names are guarded.** git-guard, the
  reference-transaction hook and the edit guard close the ways a
  case-insensitive filesystem (the macOS and Windows defaults) lets one ref
  name land on another ref's file:
  - **Prefix folding.** The `refs/heads/` and `refs/remotes/` prefix of a
    ref name is compared with ASCII case folded, so `REFS/REMOTES/origin/main`
    and `Refs/Heads/main` no longer pass as other refs, and an `update-ref` or
    `symbolic-ref` name whose `refs/` prefix matches only that way is
    refused.
  - **Protected-name folding.** Protected branch names are matched with ASCII
    case folded, so `refs/heads/MAIN` is refused as `main`. This fails
    closed: a distinct branch named `Main` is refused on a case-sensitive
    filesystem too.
  - **Non-ASCII local names where the directory folds.** Where the git
    directory folds names, a local branch or an `update-ref` or
    `symbolic-ref` name with non-ASCII characters is refused, because such a
    filesystem may fold one to an ASCII letter (`ſ` names the same file as
    `s`). On a case-sensitive git directory such names are ordinary.
  - **Fetched tracking names.** A fetch may still write non-ASCII names under
    `refs/remotes/` and `refs/tags/`. Where the git directory folds names,
    the hook refuses a written ref whose name, or a directory along it,
    folds onto another spelling once case and Unicode normalization are
    ignored (an NFD `café` onto an NFC one). It also refuses a tracking ref
    whose branch, the part after the longest configured
    `refs/remotes/<remote>/` prefix, folds onto a protected branch it does
    not name; under no configured remote every possible branch is judged.
    A fetch of a remote `MAIN` beside `main`, or of `INTEGRATION/x` beside
    `integration/y`, fails as a whole, while `feat/MAIN` fetches.
  - **Housekeeping passes.** A transaction line that keeps its value, as
    `git pack-refs` and `git gc` write, still passes.
  - **Retargeted commands.** The guards probe the git directory once per
    invocation, and a probe that cannot decide counts as case-insensitive.
    A command run in another repository (`-C`, `--git-dir`, `GIT_DIR`, `cd`)
    is judged by that repository's own probe, an unreadable one counting as
    case-insensitive.
  - **Readiness needs the hook.** The hook's refusal is the control against
    a fetched alias: on a case-insensitive filesystem, readiness needs the
    hook installed with `local_ref_protection` at `block`. Readiness and the
    sync allowance also read a remote-tracking ref only under the spelling
    git stored, listing every ref and comparing names byte for byte, which
    catches an alias only while the genuine ref is packed or absent.
  - **Edit guard.** The edit guard folds case for paths under the git
    directory, refuses any such path with a non-ASCII component, and refuses
    direct writes under `.git/refs/heads`, which would move a branch without
    a ref transaction.

  Other non-ASCII folds that no guard models, and other planes such as
  pre-push and CI, keep exact matching.
