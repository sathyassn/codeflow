### Fixed

<!-- codeflow:release-impact patch -->
- **`present show` and `present close` work on a busy Mac.** The browser
  process inventory read the whole macOS process listing and refused it
  above 4 MiB, which a busy host exceeds, so both commands refused. The
  listing is now read line by line with no total bound. Each line keeps at
  most 64 KiB, and a longer line is skipped unless it holds the session's
  instance argument, in which case the inventory refuses. A process listing
  that fails still refuses. The Windows inventory now lists only browser
  processes that can be the session's, so many open browser windows no
  longer fill its bound, and the Linux scan's process count bound is raised
  to the kernel's own process id limit.
