### Fixed

<!-- codeflow:release-impact patch -->
- **A Codex builder seat can take the gate lock.** A builder seat starts in
  the main checkout root and gets the `cf-builder` profile as that checkout
  has it, which can predate a CodeFlow update; a seat launched as the launch
  table said could then not write `~/.codeflow/locks`, so `codeflow reserve`
  refused with "gate lock unavailable". The builder launch now also passes
  `-c 'permissions.cf-builder.filesystem={"~/.codeflow/locks"="write"}'`,
  which Codex merges into the root's profile. A builder runs `codeflow
  reserve` and quick-mode heavy targets under the shared lock; full gates
  and their evidence stay with the primary, and no Codex seat writes
  `~/.codeflow/gate-runs`. Review seats (`cf-guard`) write neither folder.
  `codeflow doctor --preflight` now runs a write probe under `codex sandbox`
  with the builder launch overrides and the managed config, from the main
  checkout root, covering both gate lock folders and the common `.git`
  objects and refs. It exits 1 when a write is refused or Codex refuses the
  overrides, and says builder readiness is not established when the probe
  gives no result. `codeflow doctor --check permissions` reports what the
  Codex profiles grant on the two home folders, resolving grants on a
  covering folder, and inside a Codex sandbox treats the unwritable
  evidence folder as by design and points at the builder relaunch for the
  lock folders. Update the launch line of any builder seat started by hand.

<!-- codeflow:release-impact patch -->
- **A Codex builder seat no longer reaches private or cloud metadata
  addresses.** `cf-builder` had local binding on, and Codex then skips its
  proxy's private-network checks, so a builder seat could connect to
  addresses such as `192.168.1.1` and `169.254.169.254`. `cf-builder` now
  keeps local binding off, as `cf-guard` does, and the builder launch passes
  `-c permissions.cf-builder.network.allow_local_binding=false` for a main
  checkout with the older table. A builder seat can no longer serve on a
  local port, so tests that start a local server run on the primary.
