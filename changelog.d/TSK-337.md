### Fixed

<!-- codeflow:release-impact patch -->
- **A Codex builder seat can take the gate lock and record a full gate.**
  A builder seat starts in the main checkout root and gets the `cf-builder`
  profile as that checkout has it, which can predate a CodeFlow update; a
  seat launched as the launch table said could then not write
  `~/.codeflow/locks`, so `codeflow reserve` refused with "gate lock
  unavailable". The builder launch now also passes
  `-c 'permissions.cf-builder.filesystem={"~/.codeflow/locks"="write","~/.codeflow/gate-runs"="write"}'`,
  which Codex merges into the root's profile. `cf-builder` itself now also
  writes `~/.codeflow/gate-runs`, so a Codex seat in the production posture
  can run `codeflow test --mode full` and keep its evidence; that folder is
  per-account evidence such a seat could also forge, as under the Claude
  presets. Review seats (`cf-guard`) write neither folder, since they run no
  gate. `codeflow doctor --preflight` now runs `codeflow doctor --check
  permissions` under `codex sandbox` with the builder launch overrides from
  the main checkout root, and exits 1 when a grant is not effective there or
  Codex refuses the overrides. `codeflow doctor --check permissions` reports
  what the Codex profiles grant on the two folders and, inside a Codex
  sandbox, points at the builder relaunch. Update the launch line of any
  builder seat started by hand.
