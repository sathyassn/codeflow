### Security

<!-- codeflow:release-impact minor -->
- **Git configuration used by guards.** Alias and follow-tags checks share
  a bounded reader for effective Git configuration. Exec-guard alone refuses
  release aliases supplied through configuration environment variables.
  Alias lookup follows Git's case rules. Unresolved shell variable
  destinations, namerefs and configuration-variable append or subscript
  writes refuse later configuration-dependent decisions.
  On configuration-dependent lines, non-Git segments naming configuration
  variables also refuse unless the name is a plain shell read; this can
  refuse data mentions. Brace/glob destinations, variable redirections and
  assignment expansions in unquoted heredocs cannot hide those writes.
  `codeflow doctor --check git-config-includes` reports include files that
  may be writable or configuration it cannot verify; include-file writes
  remain unguarded. Guards may now refuse configuration-dependent commands
  they allowed before.
  Repository discovery can still block on a non-regular include before the
  reader's deadline; this remains a tracked follow-up.
  Migration: the operator repairs unreadable configuration or include paths;
  run guarded Git operations without command-local configuration environment
  changes.
