### Added

<!-- codeflow:release-impact minor -->
- **`remote protect` takes `--branch` and `--adopt`.** `--branch <name>`
  limits a run to the owned rulesets that target that branch. `--adopt
  <ruleset>` hands one existing ruleset, by id or name, to `remote protect`
  when it targets exactly the branches of an owned ruleset; it is renamed to
  the owned name and only gains rules. Where two owned rulesets target the
  same branches, `--adopt <ruleset>=<owned name>` says which. Any other
  target is refused and the ruleset is left as it is.

### Fixed

<!-- codeflow:release-impact patch -->
- **`remote protect --dry-run` prints the exact requests a run sends.** It
  reads the host with GET calls only and prints each request's method, path
  and body; a run sends exactly those. Without a readable host it prints the
  intended rules and says they are not the exact requests.

<!-- codeflow:release-impact patch -->
- **A protected branch the host does not have gets no ruleset.** A policy
  entry that names one branch, such as `master`, is reported and not planned
  when the host answers that the branch does not exist. Globs, the default
  branch and the registry are still planned.

<!-- codeflow:release-impact patch -->
- **`doctor` reads the live rules on `codeflow/registry`.** An active
  ruleset or branch protection that blocks force pushes and deletion for
  everyone passes the registry check, whoever created it: a ruleset counts
  only when its bypass list is read and empty, and branch protection only
  when it binds administrators. Otherwise doctor names what is missing and
  who can bypass it. Rules that cannot be read are a warning with the read
  error and the step that restores the read, whatever `remote protect`
  recorded.

<!-- codeflow:release-impact patch -->
- **`remote protect` keeps the excludes of a ruleset it owns.** An update
  no longer drops them; the report names them, and an exclude that leaves
  out a branch the ruleset must cover is refused with the ruleset left
  unwritten. An answer from the host that changes a sent condition or rule
  is reported, never taken as written.

<!-- codeflow:release-impact patch -->
- **`remote protect` and `doctor` act on one repository.** Both use the
  repository `origin` fetches from. A push URL that names another
  repository is refused, `gh` is asked about that repository by name and an
  answer for another one is refused, and an inherited `GH_HOST` or
  `GH_REPO` never reaches `gh`. `remote protect` sets `GH_HOST` to the host
  `origin` names, an Enterprise host included, and refuses a host `gh` has
  no working login for. `doctor` reads github.com only, as before.
