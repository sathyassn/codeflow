### Security

<!-- codeflow:release-impact patch -->
- **The path gate refuses links and gitlinks at its own inputs, and
  `credentials.json` anywhere.** Pre-commit and `codeflow ci` already let
  the gate's inputs change freely (every `.gitignore`, the policy and
  project files, the bootstrap and CI setup scripts, the hook shims under
  `.codeflow/git-hooks/` and the two CodeFlow workflows), and that
  exemption also let a symlink or a gitlink sit at those paths unjudged.
  A symlink there is now judged like any other: an absolute, parent or
  invalid target refuses, and so does a target that resolves to a blocked
  name or protected path. A gitlink there always refuses. A regular file
  at a gate input stays exempt, so the gate can still repair itself.
  `credentials.json` joins the shipped blocked names, at any depth and in
  any case; a project that tracks a public file by that name needs a
  narrow, explained `git.blocked_names` `except_under` entry in the target
  policy before upgrading.
