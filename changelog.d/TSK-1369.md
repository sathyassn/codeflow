### Changed

<!-- codeflow:release-impact none -->
- **The core library tests give the same results with `CARGO_TARGET_DIR`
  set or unset.** With the variable set to an absolute path, as builders set
  it, two `codeflow-core` unit tests failed and the gate tests wrote their
  run evidence into the folder cargo builds CodeFlow into, outside each
  test's temporary project. The library's unit tests now read the variable
  as unset, the folder logic takes its value as a parameter so its own tests
  need no environment, and the display journey's helper clears the variable
  for the `codeflow` it starts.
  The gate still keeps its evidence in the folder `CARGO_TARGET_DIR` names,
  and a CLI test now checks that. This changes test code only. No `codeflow`
  command, file, setting or release asset changes.
