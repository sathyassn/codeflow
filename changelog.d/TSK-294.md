### Added

<!-- codeflow:release-impact minor -->
- **A project can route dependency-audit exceptions through its own reviewed
  check.** A project that records audit exceptions in a register of its own,
  such as one with an owner, an expiry and a reason per row, commits
  `.codeflow/audit-exceptions.sh` instead of editing the managed audit step.
  When the trusted commit (the pull request's base, or the pushed commit)
  holds the hook and the audit finds advisories, the step exports that
  commit's files, runs the hook there and passes when the hook accepts every
  finding, listing each one. A pull request that adds or changes the hook or
  its register is judged by the base, so it cannot accept its own findings.
  The failure advice names the hook when it exists; without it, the advice
  and the `osv-scanner.toml` route are unchanged. Run `codeflow update` to
  receive the workflow. See `assets/base/ci/README.md`, "Project exception
  hook" (issue 149).
