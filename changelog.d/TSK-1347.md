### Added

<!-- codeflow:release-impact minor -->
- **Doctor reports when GitHub would block the policy check on a public
  repository.** From 2026-12-02 GitHub blocks `pull_request_target` in
  public repositories unless an Actions event policy allows it, and
  `codeflow-policy.yml` runs only on that event, so without a policy no
  pull request can merge. `codeflow doctor --check remote-perimeter` now
  reads the repository's Actions event policies (and the organization's,
  for an organization-owned repository) and warns when none allows the
  event for a workflow that runs on it, printing the policy to create;
  when a policy that targets the workflow leaves out an event it runs on;
  and when an allowing policy also covers other workflows, which is any
  workflow target besides that one path. The printed command appears only
  when the workflow path and event names are plain shell words. A
  workflow it cannot parse no longer stops the judgment of the others; it
  is named as not judged. A policy list or policy it cannot read, which
  needs administration rights, is a note, never a pass. Doctor changes no setting. `assets/base/ci/README.md`,
  `docs/adoption.md` and `docs/policy-reference.md` state the one-time
  administrator step and its command. Private and internal repositories
  are not affected.

<!-- codeflow:release-impact minor -->
- **`codeflow remote protect` creates the Actions event policy on a public
  repository.** When the policy workflow runs on `pull_request_target` and
  no policy named `codeflow policy check` exists, it creates one for
  `codeflow-policy.yml` alone that allows each event the workflow runs on.
  An existing policy of that name is left as it is, never widened. Without
  an administrator's token the run reports the policy as not written and
  lists it in the manual checklist. Private repositories get no policy.

### Changed

<!-- codeflow:release-impact patch -->
- **A policy run for a superseded head stops early.** Each verdict job in
  `codeflow-policy.yml` first reads the pull request's current head. A run
  started for a head the pull request has moved past fails before anything
  is checked out, so runs kept in the queue clear quickly and the current
  head's run starts sooner. It never passes; a failed or unclear read
  judges in full. Runs are still never cancelled. GitHub runs this event
  from the default branch's copy of the file, so the early stop starts
  once the updated file is on the default branch.

<!-- codeflow:release-impact minor -->
- **Doctor fails when the authority App's key can reach head-branch code.**
  `codeflow doctor --check remote-perimeter` now fails, where it used to
  warn, when the `codeflow-authority` environment admits any branch other
  than the default branch. It also fails when an Actions secret named
  `CODEFLOW_AUTHORITY_APP_KEY` is set at repository level, among the
  organization secrets shared with the repository, or in another
  environment, since workflows outside the authority job could then read
  the key and post `authority:` checks under the App's id. A secret or
  environment list it cannot read is a note, never a pass. A failing check
  makes `codeflow doctor` exit with status 1; keep the key only in the
  `codeflow-authority` environment and limit that environment to the
  default branch.

### Fixed

<!-- codeflow:release-impact patch -->
- **Doctor reads long workflow files whole.** `codeflow doctor --check
  remote-perimeter` kept only the last 64 KiB of each answer from the host,
  so a longer workflow, such as the shipped `codeflow-ci.yml`, lost its start
  and was reported as not YAML, or as a workflow with no events if the rest
  happened to parse. It now reads an answer whole, up to 16 MiB, and reports
  a longer one as unread.
