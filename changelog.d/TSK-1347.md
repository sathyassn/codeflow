### Added

<!-- codeflow:release-impact minor -->
- **Doctor reports when GitHub would block the policy check on a public
  repository.** From 2026-12-02 GitHub blocks `pull_request_target` in
  public repositories unless an Actions event policy allows it, and
  `codeflow-policy.yml` runs only on that event, so without a policy no
  pull request can merge. `codeflow doctor --check remote-perimeter` now
  reads the repository's Actions event policies (and the organization's,
  for an organization-owned repository) and warns when none allows the
  event for a workflow that runs on it, printing the policy to create;
  when a policy that targets the workflow leaves out an event it runs on;
  and when an allowing policy also covers other workflows. A policy list
  or policy it cannot read, which needs administration rights, is a note,
  never a pass. Doctor changes no setting. `assets/base/ci/README.md`,
  `docs/adoption.md` and `docs/policy-reference.md` state the one-time
  administrator step and its command. Private and internal repositories
  are not affected.

### Changed

<!-- codeflow:release-impact minor -->
- **Doctor fails when the authority App's key can reach head-branch code.**
  `codeflow doctor --check remote-perimeter` now fails, where it used to
  warn, when the `codeflow-authority` environment admits any branch other
  than the default branch. It also fails when an Actions secret named
  `CODEFLOW_AUTHORITY_APP_KEY` is set at repository level, among the
  organization secrets shared with the repository, or in another
  environment, since workflows outside the authority job could then read
  the key and post `authority:` checks under the App's id. A secret or
  environment list it cannot read is a note, never a pass. A failing check
  makes `codeflow doctor` exit with status 1; keep the key only in the
  `codeflow-authority` environment and limit that environment to the
  default branch.
