### Changed

<!-- codeflow:release-impact major -->
- **The model catalog moves to schema 6 and ships new default seats and
  efforts (4.0.0).** `codeflow models resolve` now returns
  `claude-opus-5-5` at high for the Claude seat, `gpt-6.1-sol` at medium
  for the Codex seat, falling back to `gpt-6-sol` and then `gpt-5.6-sol`,
  and `grok-4.7` at medium for the Grok seat. The Grok seat rises to high
  when a security, release or extra-family review trigger applies. Sonnet
  and Luna still resolve when a route names them. The model usage rules
  are catalog fields instead of skill prose: each product line carries
  `launch` (`seat`, `subagent-only` or `either`), each seat its default
  `effort` and the `high_when` policies that raise it, and the catalog's
  `effort_floors` set each worker duty's floor, with a required `default`
  and an `xhigh-reasoning` floor of `xhigh`. Every ordinary route to a seat
  runs at that seat's `effort`; a duty's seat route names no effort of its
  own. A seat request for a `subagent-only` line, such as Fable or GPT-6
  Astra, is refused with a message that names the field, and an override
  route that names one is refused the same way. `cf-model-orchestrator`
  reads these values from `codeflow models resolve` instead of stating
  them.
  Migration: run `codeflow update` after upgrading the binary. Until then
  `codeflow models resolve`, `codeflow doctor` and `codeflow doctor
  --preflight` refuse the installed schema 5 catalog with a message that
  names both schemas and `codeflow update`. The update replaces a catalog
  you never edited; it merges an edited one three ways and applies a clean
  merge. Only a conflicting merge, or a missing baseline, leaves your file
  as it is and writes a `.new` file beside it to resolve. A committed design authority (`.codeflow/model-selection.json`
  schema 2) that names Fable as design co-owner or consultant stays valid:
  Fable now approves or advises on `design-approval` as a subagent consult
  of the Claude seat, and no longer fills the `design` duty itself, because
  its line is `launch: subagent-only`.

### Added

<!-- codeflow:release-impact minor -->
- **The harness choice of model and effort applies, and CodeFlow records
  it.** `codeflow models resolve --effective <model>@<effort> --session
  <id>` records the model and effort the session's harness runs at as an
  `effective_model` event in that session's sessions-ledger file, beside
  the summary its `SessionEnd` hook writes under the same id. The
  resolution is unchanged; the output adds only an `effective_session`
  object (JSON) or one `effective session:` line (text). `--session` has
  no default: CodeFlow learns a session id only from the `SessionEnd` hook
  payload, so it cannot detect the current one. CodeFlow never
  re-launches a session to change its model or effort. The skill and
  `docs/delegation.md` state the rule.

### Fixed

<!-- codeflow:release-impact patch -->
- **Two harness session ids no longer share one sessions-ledger file.**
  Before, `alpha` and `ses-alpha` both wrote `sessions-ses-alpha.jsonl`,
  and on a case-insensitive filesystem, such as the macOS default, `Alpha`
  opened that same file too, so their records mixed. The ledger name is
  now `ses-` and the id encoded: `_` becomes `__`, an uppercase letter
  becomes `_` and its lowercase, and any other character outside `a`-`z`,
  `0`-`9` and `-` becomes `~` and its hex bytes. `Alpha` writes
  `sessions-ses-_alpha.jsonl`, `ses-alpha` writes
  `sessions-ses-ses-alpha.jsonl`. A lowercase id, such as the UUIDs Claude
  Code and Codex use, keeps the name it had. `--session` accepts at most
  100 characters, so the longest name stays under 255 bytes.
  Existing ledger files keep their names. A session that ended before the
  upgrade still compacts, because its records and file name carry the
  same identity. A session that was running across the upgrade, with an id
  the encoding changes, is split: its earlier records stay under the old
  name, its `session_end` goes to the new one, and the old fragment stays
  uncompacted.
