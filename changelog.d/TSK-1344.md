### Security

<!-- codeflow:release-impact minor -->
- **The guards judge a command run through the Herdr app as if it were
  typed bare.** exec-guard and git-guard now read `hc run`, `hc exec`,
  `hc machine add --via`, `herdr pane run` and `herdr agent start`, and
  judge the command each carries by the same rules as the bare command:
  headless peer runs, every Git rule, and the destructive, privileged and
  outward rules. `hc run --cwd <dir>` and `hc exec --cwd <dir>` are judged
  against the repository in that directory. A template `hc run` starts by
  name is judged by its `command`. `hc file write` and `hc file edit` are
  held to the Edit tool's path rules, and `hc file read`, `hc put` and
  `hc update --from` are judged as reads of the file they name. An `hc`
  subcommand or option the guard does not know, a template it cannot read,
  a word it cannot fill in, and any carried command whose directory it
  cannot establish are refused and named: `--on` another machine,
  `herdr pane run`, `herdr agent start`, and `herdr pane split` with
  `--cwd` or `--env`. Text typed into a terminal by `hc send` or `hc keys`
  is not judged; the policy reference states why and which floor holds.
  Forms that passed before may now be refused. The interactive `hc run`
  seat launch lines still pass. `herdr pane run` and `herdr agent start`
  now refuse, so start seats with `hc run`; TSK-1345 updates the cf-herdr
  skill to match.
