### Security

<!-- codeflow:release-impact major -->
- **Breaking: the guards judge a command run through the Herdr app as if
  it were typed bare, and every `hc run` refuses.** exec-guard and git-guard
  now read `hc exec`, `hc machine add --via`, `herdr pane run` and
  `herdr agent start`, and judge the command each carries by the same rules
  as the bare command: headless peer runs, every Git rule, and the
  destructive, privileged and outward rules. `hc exec --cwd <dir>` is judged
  against the repository in that directory. `hc file write` and
  `hc file edit` are held to the Edit tool's path rules, and `hc file read`,
  `hc put` and `hc update --from` are judged as reads of the file they name.
  An `hc` subcommand or option the guard does not know, a word it cannot
  fill in, and any carried command whose directory it cannot establish are
  refused and named: `--on` another machine, `herdr pane run`,
  `herdr agent start`, and `herdr pane split` with `--cwd` or `--env`. Text
  typed into a terminal by `hc send` or `hc keys` is not judged; the policy
  reference states why and which floor holds.
  `hc run` can start a template instead of the words given, and the guard
  cannot verify from the command which one, so every `hc run` refuses,
  whatever its options and operands, including the interactive seat launch
  lines, and a help word does not pass. Migration: start the program outside
  a guarded session, or through the host's own terminal. A guarded `hc run`
  form returns when the Herdr app's dispatch contract is known. `herdr pane
  run` and `herdr agent start` also refuse in a guarded session, because the
  directory they run in is unknown. Forms that passed before may now be
  refused.
