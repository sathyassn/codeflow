### Changed

<!-- codeflow:release-impact major -->
- **Breaking: a program word filled in at run time is judged under the
  programs the guards protect.** When the word in the program position is
  an environment value or a pattern the guards cannot fill in, such as
  `$TOOL` or `./bin/*/tool`, git-guard and exec-guard judge the command,
  with its arguments as written, under the names `gh`, `claude`, `codex`
  and `grok`; under `git` when an argument is a Git builtin, or when the
  first one names an alias of the repository, whose commands and the
  programs they make Git run are judged as for literal `git`; as a shell
  when the first argument holds `-c`; and as a launcher of each later
  word. A line is refused when any of these
  readings is refused, and the refusal ends with the way through: write the
  program name literally in place of the word. Under the shipped default
  policy exec-guard already refused every line below, so a line is newly
  refused only in a project that relaxes the rule that refused it there,
  mostly `security.secret_reads`:
  - **Read as a headless peer run** (`security.headless_peer_runs`):
    `$MKDIR -p dir`, `"$CP" -p a b`, `$X -p text`,
    `$DOCKER run -p 8080:80 img`, `$SSH -p 2222 host`,
    `$MYSQL -u root -p`, `$NPM exec tsc`, `$PNPM exec vitest`,
    `$DOCKER exec -it c sh`, `$KUBECTL exec pod -- ls`,
    `$TOOL review file`, `$AGENT agent` and `$X ultrareview`.
  - **Read as a launcher of a program named by a substitution**
    (`git.commit_to_protected` on a protected branch):
    `$PYTHON "$(git rev-parse --show-toplevel)/scripts/x.py"` and
    `$EDITOR "$(git rev-parse --show-toplevel)/notes.md"`.
  - **Read as Git after a command that may move the shell**
    (`git.hook_integrity`, when Git would run a pager or editor):
    `$X /tmp; $GIT diff`, `$X /tmp && $GIT log` and `$A $B diff`.
  - **Why this is a major change:** `security.secret_reads: off` and
    `warn` are supported policy values, and under them these lines ran on
    3.1.1. Most of them run no guarded program, so the change is not limited
    to closing a bypass: it refuses ordinary lines a project could run
    before, as this release's strict text rule does. A refusal under the
    default policy does not make the change compatible for a project that
    relaxed the rule.
  - **Migration:** write the program name literally where a refusal names
    the word, for example `mkdir -p dir` in place of `$MKDIR -p dir`.
    Nothing changes for a project on the default policy.
