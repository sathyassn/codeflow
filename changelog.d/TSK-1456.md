### Changed

<!-- codeflow:release-impact major -->
- **Breaking: a program word filled in at run time is judged under the
  programs the guards protect.** When the word in the program position is
  an environment value or a pattern the guards cannot fill in, such as
  `$TOOL` or `./bin/*/tool`, git-guard and exec-guard judge the command,
  with its arguments as written, under the names `gh`, `claude`, `codex`
  and `grok`; under `git` when an argument is a Git builtin, or when the
  first one names an alias defined where the command runs, in the
  directory and environment its launchers and assignments give it, whose
  commands and the programs they make Git run are then judged as for
  literal `git`; as a shell
  when the first argument holds `-c`; and as a launcher of each later
  word. A line is refused when any of these
  readings is refused, and the refusal ends with the way through: write the
  program name literally in place of the word. Under the shipped default
  policy exec-guard already refused the lines in the following list, so
  those lines are newly refused only in a project that relaxes the rule
  that refused them there, mostly `security.secret_reads`:
  - **Read as a headless peer run** (`security.headless_peer_runs`):
    `$MKDIR -p dir`, `"$CP" -p a b`, `$X -p text`,
    `$DOCKER run -p 8080:80 img`, `$SSH -p 2222 host`,
    `$MYSQL -u root -p`, `$NPM exec tsc`, `$PNPM exec vitest`,
    `$DOCKER exec -it c sh`, `$KUBECTL exec pod -- ls`,
    `$TOOL review file`, `$AGENT agent` and `$X ultrareview`.
  - **Read as a launcher of a program named by a substitution**
    (`git.commit_to_protected` on a protected branch):
    `$PYTHON "$(git rev-parse --show-toplevel)/scripts/x.py"` and
    `$EDITOR "$(git rev-parse --show-toplevel)/notes.md"`.
  - **Read as Git after a command that may move the shell**
    (`git.hook_integrity`, when Git would run a pager or editor):
    `$X /tmp; $GIT diff`, `$X /tmp && $GIT log` and `$A $B diff`.
  - **Read as Git running an alias the guards cannot look up**
    (`git.commit_to_protected` at git-guard, `git.hook_integrity` at
    exec-guard): the first argument is no Git builtin and the guards cannot
    read the configuration where the command would run, as in
    `$MAKE -C build all` or `env -C build $TOOL notes.md` while `build`
    does not exist yet, `$MAKE -C "$DIR" all`, and `env -u HOME $TOOL build`.
    A command Git would reject before reading an alias keeps its verdict
    (`$CC -o out main.c`, `$SHELL -c 'echo hi' x`). A Git builtin behind an
    `env` option is refused as literal `git` is there, as in
    `env -C dir $TOOL status` (`git.hook_integrity`).
  - **Why this is a major change:** `security.secret_reads: off` and
    `warn` are supported policy values, and under them these lines ran on
    3.1.1. Most of them run no guarded program, so the change is not limited
    to closing a bypass: it refuses ordinary lines a project could run
    before, as this release's strict text rule does. A refusal under the
    default policy does not make the change compatible for a project that
    relaxed the rule.
  - **Migration:** write the program name literally where a refusal names
    the word, for example `mkdir -p dir` in place of `$MKDIR -p dir`.
    Under the default policy these lines stay refused as before. A line
    that names `git` literally can still be judged differently, as the
    entry under Fixed says.

<!-- codeflow:release-impact major -->
- **New git-guard refusal under the default policy**
  (`git.commit_to_protected`): a leading word that is not an ordinary
  assignment and holds a brace expression the guards will not expand now
  refuses the line as unreadable. This covers a word past their size limit,
  a comma list past their count limit, or braces nested past their depth
  limit. The line is refused even when the command after the word is one
  the guards allow. Ordinary assignments remain allowed by this check.
  Numeric or letter sequences the guards still read as one word do not
  trigger this refusal.

### Fixed

<!-- codeflow:release-impact major -->
- **The Git runner reader**, which both guards use for the programs Git runs,
  applies what the launchers in front of a command do to its environment:
  the variables they assign, and the ones they remove or clear, so it reads
  the configuration Git reads. A `git` line can therefore be refused, under
  every policy, where 3.1.1 read it with the session's environment and
  allowed it: when the configuration the command's own environment selects
  makes Git run a guarded program, when a launcher removes a Git location,
  `GIT_EXEC_PATH` or `GIT_CEILING_DIRECTORIES` that the session sets, or
  when a `--config-env` variable the command assigns holds a value the
  shell fills in at run time.

<!-- codeflow:release-impact major -->
- **git-guard expands a `git` alias** with the same reading: the environment
  and the directory the command's launchers and assignments give it,
  including an `env -C` behind a launcher such as `nice`. A `git` line that
  runs an alias can therefore be refused, under every policy, where 3.1.1
  judged the alias defined in the session's environment or in the starting
  directory and allowed the line.
