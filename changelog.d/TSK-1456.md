### Changed

<!-- codeflow:release-impact patch -->
- **A program word filled in at run time is judged as each program it
  could be.** When the word in the program position is an environment
  value or a pattern the guards cannot fill in, such as `$TOOL` or
  `./bin/*/tool`, git-guard and exec-guard judge the command under the
  names `gh`, `claude`, `codex` and `grok`, under `git` when an argument is
  a Git command, as a shell when the first argument holds `-c`, and as a
  launcher of each later word. A line is refused when any of these readings
  is refused, and the refusal ends with the way through: write the program
  name literally in place of the word. Under the shipped default policy
  exec-guard already refused every line below, so a line is newly refused
  only in a project that relaxes the rule that refused it there, mostly
  `security.secret_reads`:
  - **Read as a headless peer run** (`security.headless_peer_runs`):
    `$MKDIR -p dir`, `"$CP" -p a b`, `$X -p text`,
    `$DOCKER run -p 8080:80 img`, `$SSH -p 2222 host`,
    `$MYSQL -u root -p`, `$NPM exec tsc`, `$PNPM exec vitest`,
    `$DOCKER exec -it c sh`, `$KUBECTL exec pod -- ls`,
    `$TOOL review file`, `$AGENT agent` and `$X ultrareview`.
  - **Read as a launcher of a program named by a substitution**
    (`git.commit_to_protected` on a protected branch):
    `$PYTHON "$(git rev-parse --show-toplevel)/scripts/x.py"` and
    `$EDITOR "$(git rev-parse --show-toplevel)/notes.md"`.
  - **Read as Git after a command that may move the shell**
    (`git.hook_integrity`, when Git would run a pager or editor):
    `$X /tmp; $GIT diff`, `$X /tmp && $GIT log` and `$A $B diff`.
