### Security

<!-- codeflow:release-impact minor -->
- **`codeflow remote protect` writes three rulesets it owns and never
  weakens a rule (issue 279).** It writes "codeflow authority updates"
  (only the administrator role, or the maintain role under
  `--profile independent-review`, moves the default branch) and "codeflow
  authority checks" on `~DEFAULT_BRANCH`, so a renamed default branch keeps
  its rules, and "codeflow line checks" on the integration lines
  (`--lines`, default `integration/**`). The checks are strict, pinned to
  the GitHub App given by `--check-app` for the `authority:` names or to
  GitHub Actions for the `trusted:` names, and have no bypass; they are
  refused until the default branch's policy workflow declares those names.
  Each other protected branch gets its own `codeflow protect <pattern>`
  ruleset. A ruleset with any other name is no longer written, and classic
  branch protection is no longer written. Every write sends the whole
  ruleset; an update never lowers an approval count, removes a rule,
  changes which app produces a check or widens a bypass list, and a second
  run writes nothing. `codeflow doctor --check remote-perimeter` now fails
  while the authority or line checks list a bypass actor (an open recovery
  window), compares the owned rulesets with `--profile`, and reports
  classic protection that does not bind administrators, a non-strict or
  pull-request-free rule on the lines, an `authority:` check accepted from
  GitHub Actions, an authority environment open to other branches or
  referenced by a second job, and a foreign ruleset that requires a name
  no workflow on the default branch produces.
