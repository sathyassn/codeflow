### Changed

<!-- codeflow:release-impact minor -->
- **Project tooling is held to the same tests and coverage floor as product
  code.** The shipped coverage rule and the discipline rules' "Prove it at
  every surface" now say that a project's scripts, build helpers, code
  generators, release and CI helpers and hook scripts ship with tests that
  run in a test target, and count toward the coverage floor where their
  language can be measured. Only generated, vendored, fixture and test code
  stays excludable, under the existing owner, reason and removal condition.
  `cf-stack` wires a test target for the project's tooling when it has any,
  points the coverage tool at the tooling source, and says how to prove a
  language its coverage tool cannot measure, such as shell. `cf-develop`
  asks for tooling tests in the same change, and `cf-reviewer` returns a
  finding for a tooling change with no test, as it does for product code.
  The `monorepo-multi-target.json` template's description now names its
  `tools/` target as project tooling. A new `tooling-tests-and-framework`
  pack in `/cf-evaluate-model` qualifies the reviewer behaviour.
