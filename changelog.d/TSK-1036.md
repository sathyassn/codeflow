### Fixed

<!-- codeflow:release-impact patch -->
- **A blocked task can be unblocked and completed in its own pull
  request.** `codeflow ci`, pre-push and `codeflow work start` accept a task
  pull request that moves its task from `blocked` to `todo`, and on to
  `complete` or `cancelled`, for an epic task and a standalone one; the
  output shows the Blocker the range removes, and an open `depends_on`
  predecessor still refuses it. The refusal of a blocked task now names
  this route (issue #365).
<!-- codeflow:release-impact patch -->
- **A range is judged one status step per commit.** Each commit is judged
  against each of its parents, so a sync merge of `main` that brings
  `blocked -> todo -> complete` into a line passes in one merge or in
  several (issues #400 and #424). A direct `blocked -> complete` in one
  commit stays refused, and a terminal status left inside one range, such
  as `todo -> cancelled -> todo`, is now refused. History that cannot be
  read refuses with its cause: fetch full history for a shallow clone,
  fetch or repair the object store for a missing object, or fix an
  unparsable record version.
