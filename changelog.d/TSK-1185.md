### Fixed

<!-- codeflow:release-impact patch -->
- **A line sync orders a superseding task record by its ancestry.** A sync
  was refused with "none of them is newer than the others" when a planning
  edit's branch forked before a merge that only carried the older criteria
  past an even older copy, or past a side that never held the record.
  `codeflow ci` and the pre-push hook now order the two versions by which
  commits wrote them, on the fetched history, and read no branch name or
  date. A sync still refuses when both lines wrote their own criteria, or
  when a merge rejected a newer version by keeping the older one.

<!-- codeflow:release-impact patch -->
- **A parallel commit no longer counts as reopening a completed task.** A
  landing was refused because an active completion "is missing" from the
  archive when a commit that still held the task as todo merged in after
  the completion. Only a commit that descends from the completion now counts
  as a reopen, and such a reopen still needs the completion in the archive.

<!-- codeflow:release-impact patch -->
- **A clean merge is judged by git's own merge.** A landing was refused for
  an "unreviewed merge resolution" on a merge git made cleanly, because the
  check remerged with libgit2, whose diff can conflict where git's does not.
  It now runs `git merge-tree --write-tree` and a merge is clean only when
  its tree is exactly that conflict-free result. A hand edit still refuses,
  and so does a merge it cannot read. This needs Git 2.41 or later: an older
  Git is refused as a version problem, with the upgrade step, and `codeflow
  doctor --check git-version` and `codeflow ci` report it early.

<!-- codeflow:release-impact patch -->
- **A completed task's home can be corrected to where it landed.** A sync was
  refused with "the landing changes the task's declared home" after a planning
  landing corrected a completed task to the home that holds its reviewed work.
  That correction is now admitted when it changes only `integration_target`
  and the reviewed commit is already on the home, and the completion is proved
  at its original landing. A later edit no longer hides a home change: the
  commit that made the change is judged.

<!-- codeflow:release-impact patch -->
- **A line takes main's records by main's bytes.** A sync or a task's pull
  request into a line was refused when it carried a record exactly as
  `main` holds it, because the line proved the completion again or froze
  the record. In the hosted policy check, a record whose tree entry equals
  the one at `main`'s verified commit is now taken without proof or freeze,
  and each such record is reported. This relaxes four things: a line no
  longer proves again a completion `main` admitted; it takes `main`'s text
  for a record whose home is not the line, even one the line edited; a sync
  takes `main`'s version of a line-homed record the line has not edited; and
  a home move made by a planning landing on `main`'s first-parent chain
  counts, an exception to the TSK-1004 rule that refused such a move. It
  applies on a pull request that resolved a merge of `main` by hand as well
  as on a sync. A line-homed record the line edited, a home that differs
  without such a move, another mode, an unreadable record and the other
  paths in the range keep the full checks. The rule runs only when the
  commit `--policy-from` names is the default branch's tip by the check's
  own query of `origin`; the pre-push hook, and any run that cannot verify
  that, keep the full checks.
