### Fixed

<!-- codeflow:release-impact patch -->
- **A line sync orders a superseding task record by its ancestry.** A sync
  was refused with "none of them is newer than the others" when a planning
  edit's branch forked before a merge that only carried the older criteria
  past an even older copy, or past a side that never held the record.
  `codeflow ci` and the pre-push hook now order the two versions by which
  commits wrote them, on the fetched history, and read no branch name or
  date. A sync still refuses when both lines wrote their own criteria, or
  when a merge rejected a newer version by keeping the older one.

<!-- codeflow:release-impact patch -->
- **A parallel commit no longer counts as reopening a completed task.** A
  landing was refused because an active completion "is missing" from the
  archive when a commit that still held the task as todo merged in after
  the completion. Only a commit that descends from the completion now counts
  as a reopen, and such a reopen still needs the completion in the archive.

<!-- codeflow:release-impact patch -->
- **A clean merge is judged by git's own merge.** A landing was refused for
  an "unreviewed merge resolution" on a merge git made cleanly, because the
  check remerged with libgit2, whose diff can conflict where git's does not.
  It now runs `git merge-tree --write-tree` and a merge is clean only when
  its tree is exactly that conflict-free result. A hand edit still refuses,
  and so does a merge it cannot read. This needs Git 2.41 or later: an older
  Git is refused as a version problem, with the upgrade step, and `codeflow
  doctor --check git-version` and `codeflow ci` report it early.
