### Fixed

<!-- codeflow:release-impact patch -->
- **`codeflow ci` judges a private repository's ordinary pull request
  without a credential.** In a GitHub Actions `pull_request_target` run,
  the default branch comes from the event or the new `--default-branch`
  flag, and its tip from the clone's `refs/remotes/origin/<branch>`, so
  a checkout with `persist-credentials: false` no longer fails asking the
  repository. Any other run ignores the flag, because its workflow can be
  changed by the pushed commit, and asks the repository as before. A
  release range still asks; when that fails for want of a credential, the
  error names the fix. The managed `codeflow-policy` workflow passes the
  flag; `codeflow update` brings it (issue #527).
