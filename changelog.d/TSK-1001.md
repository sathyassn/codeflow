### Changed

<!-- codeflow:release-impact minor -->
- **Ready pull requests are refused until their review is recorded.** Once
  `codeflow ci` knows a pull request is ready (the host's event, or
  `CODEFLOW_PR_IS_DRAFT=false`), a code range for a task with no acceptance
  block is refused as not landable, and a record-only cancellation needs a
  Reviews row approving its exact head. Pushes, drafts and local lints are
  not refused for this. The draft state moved from `CODEFLOW_PR_DRAFT`,
  which keeps its one meaning as the release preflight's PR body path.
<!-- codeflow:release-impact minor -->
- **Record and planning checks close gaps found in review.** A completed
  task's criteria correction may change nothing else in that record or in
  an epic. A criterion removal needs a line `AC-n removed: <reason>` with a
  real reason. A planning or cancellation range is held to the planning
  paths in every commit, a cancelled record must pass the task schema, and
  planning pull requests run the docs validation on the candidate head. A
  completed task's derived Reviews row lets the section be left out even
  where `git.pr_sections` requires it.
<!-- codeflow:release-impact minor -->
- **The shipped CI runs quick-only targets.** Targets that define `quick`
  but not the mode the hosted gate runs now run after it, so they keep an
  automatic run now that the pre-push hook runs no test target.
<!-- codeflow:release-impact minor -->
- **Release impact and merge admission judge with trusted definitions.**
  A new `release impact (trusted)` check, in its own workflow on
  `pull_request_target`, refuses an unprotected base, builds and runs only
  the base commit's evaluator, reads the pull request as git data, and pins
  and rechecks the head, base and body it judged; the `pull_request`
  `release impact` check stays until the trusted one is required. Merge
  admission verifies each run's GitHub-signed OIDC provenance with PyJWT
  and cryptography pinned by hash, binds the head, base, body and draft
  state the policy check judged, and refuses a pull request that moved or
  whose head another pull request shares. The coverage shards' and Windows
  partitions' test filters are now computed from the base revision in a job
  that runs no pull request code, and the coverage floor, the journey map
  and the result checks come from the base. The gate's targets and their
  commands still come from the pull request's own `.codeflow/test-config.json`,
  run by the codeflow it builds; taking them from the base needs a
  `codeflow test` option that reads another config, which is not in this
  change.
