### Fixed

<!-- codeflow:release-impact minor -->
- **The guards refuse git refs, remotes, programs and environment supplied
  as data.** A variable assigned from a command substitution or `read`, an
  inherited variable, and the input `xargs`, `parallel`, `fd -x` or `find
  -exec` supplies, also in a command `watch`, `flock` or `script -c` runs, are
  refused as unresolved by git-guard and exec-guard wherever they reach a
  git ref or remote operand, a git subcommand or `-c` value, a git
  environment assignment or the program position, before the push, alias,
  transport and release decisions read them. Before, a program read from a
  file (`$V push origin HEAD:main`), an environment assignment read from a
  file (`env "$V" git push origin`) and one supplied by `xargs -I{}` passed
  git-guard. A variable the line assigns a literal is judged as that
  literal, so a tag name held in a variable is now refused as a tag push by
  exec-guard. Git-guard reads integer bracket arithmetic in a ref
  (`HEAD:v$[2]`) as its value and judges the resolved ref. Write the value
  in the command, or compute it first and pass it as a literal.
