### Fixed

<!-- codeflow:release-impact minor -->
- **The guards refuse git refs, remotes, programs and environment supplied
  as data.** A variable assigned from a command substitution or `read`, an
  inherited variable, and the input `xargs`, `fd -x` or `find -exec`
  supplies, also through a shell `-c` script one of them runs, and a data
  variable in a git command `watch`, `flock` or `script -c` runs, are
  refused as unresolved
  in the program position, a git environment assignment, a git subcommand
  or `-c` value, and the operands of the subcommands each guard judges:
  git-guard the subcommands it judges for protected refs, exec-guard
  `push`, `tag`, `config`, `update-ref`, `remote` and `credential`. An
  input substituted into a shell script a supplier runs is refused even
  when the input is written on the line. GNU `parallel` is allowed only in
  one closed shape: `--plain`, options from a small set the guards read, a
  template written on the line, and a fixed program that is not git, a
  shell, `eval` or a program that runs another command. Any other
  `parallel` call is refused by both guards and is unproven in
  exec-guard's deletion check, so in agent sessions `parallel` cannot run
  git, a shell, `eval` or a command carrier. An
  unquoted brace list or sequence in such a word (`git push origin
  {feat/x,main}`) is refused the same way, and on `git branch` the name
  after `-m` is judged, not skipped as a message. Before, a program read
  from a file (`$V push origin HEAD:main`), an environment assignment read
  from a file (`env "$V" git push origin`) and one supplied by `xargs -I{}`
  passed git-guard. A variable the line assigns a literal is judged as
  that literal, so a tag name held in a variable is now refused as a tag
  push by exec-guard. Git-guard reads integer bracket arithmetic in a ref
  (`HEAD:v$[2]`) as its value and judges the resolved ref. Write the value
  in the command, or compute it first and pass it as a literal.
