<!-- codeflow:release-impact patch -->
- **Consistent CI ranges.** `codeflow ci` resolves base and head commits and
  branch context before checking a range. A branch's declared target supplies
  the local base before the protected-branch fallback. Ref names and commit
  IDs select consistent acceptance context; ambiguous commit IDs and detached
  runs name the context to pass instead of recommending a task reopen. Named
  bases retain target intent and protected PR checks. First pushes keep the
  destination target when their merge base has no branch name. A declared target
  counts only when it is a protected branch or an epic line that records on a
  protected branch or at the line's `origin/<line>` ref bind to the branch's
  epic; a local-only line never counts, and any other target selects neither
  the base nor the acceptance target. None can hide changes by containing the
  head. Declared bases use only `origin/<name>`; local protected branches
  never supply them. Missing remote refs warn and keep the protected fallback.
  CodeFlow cannot verify host protection offline: protect `integration/*` and
  every name in `protected_branches` on the host. A bare run reads the local
  remote-tracking ref; git-guard refuses update-ref of `refs/remotes/*`.
  The pre-push hook applies the same judgement and uses a second protected
  name only when its advertised tip equals the destination default's tip.
  Default targets retain protected PR checks. Pre-push validates target names
  and keeps context failures blocking; planning branches use the same epic
  target locally and in the hook.
