### Changed

<!-- codeflow:release-impact minor -->
- **The shipped Claude status line shows effort, pull request, plan usage
  and worktree (issue 402).** When Claude Code supplies them, the line adds
  the effort level beside the model, `PR <n>` with its review state, the
  5-hour and 7-day usage as `5h <n>%` and `7d <n>%` coloured like the
  context, and `wt:<name>` after the branch. A field Claude Code does
  not supply is left out, so a session without any of them prints the same
  line as before. The line makes no network or `gh` call, and it prints
  the text it is given without running any of it: a folder or branch name
  with control characters or shell syntax shows as plain text. `codeflow update`
  moves a line still equal to a shipped one and keeps and reports a line the
  project changed; a person's own line goes in `.claude/settings.local.json`.

<!-- codeflow:release-impact minor -->
- **Bypass permission mode is a sanctioned host mode, set outside the
  repository (issue 451, ADR-0093).** Claude Code ignores
  `bypassPermissions` in a project settings file since v2.1.257 and starts
  the session in Manual mode, so the `bypassPermissions` preset no longer
  ships `permissions.defaultMode` and `codeflow init` prints the routes that
  work: `claude --permission-mode bypassPermissions` for one session, or
  CodeFlow's session file for every CodeFlow session. The new
  `codeflow claude-session --install`, which `codeflow init` offers after
  the bypass answer, writes `~/.codeflow/claude/session.json` and a
  `claude` shell function that starts Claude Code with it through
  `--settings` inside CodeFlow projects, and nowhere else. Under that file
  the sandbox, the host list and the deny rules bind: a repository's
  settings cannot turn them off. Bypass mode goes into the file only after
  you type yes, and is not offered when managed settings disable it; the
  line that sources the function is added to `~/.zshrc` or `~/.bashrc`
  only on a second yes, and `--uninstall` removes exactly what was added.
  The install also offers, one item at a time, optional additions to your
  own `~/.claude/settings.json` (sandbox on, credential-file denies, hidden
  token variables, and the Herdr exclusion when Herdr is installed), with a
  private backup in `~/.codeflow/claude/backups` and a record. For the VS Code
  extension the install writes a process wrapper, which refuses as the
  function does, and prints the `claudeCode.claudeProcessWrapper` setting
  to add. The session file makes a missing sandbox stop the session, and
  the shipped presets deny these files to the agent's edit tools. A session started another way, such as from the desktop app,
  shows you a warning at start. `codeflow update` removes a `bypassPermissions` or
  `auto` mode from the shared file when the recorded baseline shows CodeFlow
  shipped it, and keeps and reports one the project set itself. A project
  `default` or `acceptEdits` outranks the user file, so the docs say which
  preset to use with a user-level bypass. `cf-customize` proves the mode
  with a live canary: the guards, deny rules and the sandbox each refuse a
  planted action. The docs state what still protects you in bypass and what
  does not.

### Security

<!-- codeflow:release-impact major -->
- **The shipped Claude sandbox no longer reruns a refused command outside
  it, denies tool token stores and reaches only development hosts (ADR-0093,
  operator decision 2026-10-31).** Every preset sets
  `sandbox.allowUnsandboxedCommands: false`, and only the `gh` subcommands
  CodeFlow uses (named `pr`, `run` and `issue` verbs, not `run download`,
  `pr checkout` or `issue develop`, which write to your machine; `api`,
  `repo view`, `release view`, `release list`, `search`, `auth status`) and a plain `git push` run
  outside the sandbox, by name in `sandbox.excludedCommands`, each only as
  a single command with no pipe, redirect, `cd` or `$(...)`. New deny rules
  refuse the `gh` and push forms that would run code outside the sandbox
  or print the token (extensions, aliases, `config set`, `--show-token`,
  codespaces, keys, secrets, variables, `repo clone`, `browse`,
  `--receive-pack`, `--exec`, `ext::`). Exec-guard lets a `gh api` call
  run without a prompt only in one plain read form: a GET to one REST
  endpoint with output options such as `--paginate`. Every
  other form makes Claude Code ask you, in every mode, fields with
  `-X GET` included. It refuses a `gh api` call with a word naming DELETE
  anywhere, a `gh auth` call with the token flag anywhere or an option
  before its subcommand, and a word the shell fills in. On every `gh`
  call it admits `--jq` only as a plain field selector, such as
  `.head.sha` or `.[] | .name`, and refuses a template, since gh runs
  these programs outside the sandbox where they can print the token. It
  reads every word of the call for them, so a word such as `-Ftitle=x`
  that could be one is refused too; spell the value as a separate word.
  Ask and deny rules
  in the presets name the common spellings too. The sandbox denies writes to
  `.codeflow/git-hooks`, and `GH_TOKEN`, `GITHUB_TOKEN`, `NPM_TOKEN` and
  `NODE_AUTH_TOKEN` are removed from sandboxed commands.
  The Read tool and the sandbox deny the token stores of `gh`, git, Docker,
  gcloud, Azure, npm and the macOS keychains. The `secret` and
  `credentials` read rules match exact names and data-file extensions only,
  so a source file such as `secret_scan.rs` is readable in the sandbox
  again. `sandbox.network.allowedDomains` lists GitHub, crates.io and
  rustup, npm, PyPI, the Go module proxy, the Playwright downloads and the
  Claude docs instead of `*`; in bypass mode an unlisted host still connects unless you set
  `sandbox.network.strictAllowlist` and list the hosts in your user
  settings or a `--settings` file. `codeflow update`
  applies all of this and keeps the hosts, tools and values your project
  set. Breaking: a tool that needs host state, such as `docker`, `herdr` or
  the Codex plugin, a `gh` subcommand off the list, a `git push` inside a
  compound call or script, or a host off the list, now fails in the
  sandbox, and a `gh api` write prompts. Migration: push with a plain
  `git push` and select `gh` fields with a plain `--jq` path; add a project tool or host in
  `.claude/settings.local.json`, for example `{"sandbox":
  {"excludedCommands": ["docker *"], "network": {"allowedDomains":
  ["registry.example.com"]}}}`; add `herdr *` or the Codex plugin command
  in your own user settings, as `cf-customize` shows.
