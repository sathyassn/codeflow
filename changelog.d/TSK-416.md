### Fixed

<!-- codeflow:release-impact patch -->
- **A stale local branch no longer decides what a check judges.** A bare
  target or line name now reads the fetched `origin/<name>` before a local
  branch of the same name, in `work next`, `work claim`, `work start`, the
  dependency and pin checks, the waiver check of `task status complete`
  and the reopen judgment. A local branch decides only where nothing of
  that name is fetched, and the output then names it in full
  (`refs/heads/<name>`). `work claim` cuts from the fetched tip and
  refuses, naming both commits, when the local branch holds commits the
  fetched line lacks. A copy of a predecessor branch behind its reviewed
  pin is accepted by `work claim --on` and the push check; a copy ahead
  of the pin or diverged from it still refuses, naming its shape. A
  diverged target names both commits and a remedy that runs under the
  guard. A failed review lookup names its cause (no pull request,
  authentication or network) and the provider's redacted message. A
  reopen reason is written as a quoted scalar, so any text reads back as
  written.
