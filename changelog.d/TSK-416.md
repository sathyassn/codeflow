### Fixed

<!-- codeflow:release-impact patch -->
- **A stale local branch no longer decides what a check judges.** A bare
  target or line name now reads the fetched copy of that branch: the same
  branch on the remote the local branch tracks, else `origin/<name>`, ahead
  of a local branch of the same name. This holds in `work next`, `work
  claim`, `work start`, the dependency and pin checks, the waiver check of
  `task status complete` and the reopen judgment. An upstream naming
  another branch, as git sets when a line is cut from `origin/main`, is
  never read for the line. A local branch behind the fetched line never
  decides. One ahead of it is still honoured by `work next`, `work start`
  and a reopen's completion, and is named in full (`refs/heads/<name>`), as
  is a local branch where nothing of that name is fetched. `work claim`
  cuts from the fetched tip and refuses, naming both commits, when the
  local branch holds commits the fetched line lacks. A copy of a
  predecessor branch behind its reviewed pin is accepted by `work claim
  --on` and the push check; a copy ahead of the pin or diverged from it
  still refuses, naming its shape. When every copy is behind the pin, the
  refusal says the branch is behind the pin and to push or wait for the
  reviewed head, instead of asking for a rebase. `work start --on` accepts
  a pin whose `depends_on` edge the task adds in its own committed record,
  and still checks the pin; an edge only in the working tree is not read,
  and the refusal names where to add it. A diverged target names both commits
  and a remedy that runs under the guard. A fetched ref that names no
  readable commit refuses, naming the ref, the object it points at and a
  remedy, in every reader of a target and in `codeflow ci`'s base, and a
  failed claim fetch names that ref. `task status --base origin/<line>`
  reads the fetched ref, never a local branch spelled like it, and refuses
  when one exists. A failed review lookup names its
  cause (no pull request, authentication or network) and the provider's
  redacted message. A reopen reason is written as a quoted scalar, so any
  text reads back as written.

<!-- codeflow:release-impact patch -->
- **A line's pull request no longer reports its own merges as a completion
  outside the range.** When `codeflow ci` judges a line into its target, a
  merge inside the line that rewrites a completed task's record, such as a
  planning branch taking the line, is part of the range the line's proved
  tip holds. Before, the check hid only the commit that added the
  completion and refused with "records a completion of this task outside
  this range". Only a commit that carries the bound completion and that an
  exact proved tip holds counts as the range's own; a branch holding the
  same merge, a ref named like the line at another commit, and an earlier
  completion the bound one does not carry still refuse.
