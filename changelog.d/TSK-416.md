### Fixed

<!-- codeflow:release-impact patch -->
- **A stale local branch no longer decides what a check judges.** A bare
  target or line name now reads the fetched copy of that branch: the same
  branch on the remote the local branch tracks, else `origin/<name>`, ahead
  of a local branch of the same name. This holds in `work next`, `work
  claim`, `work start`, the dependency and pin checks, the waiver check of
  `task status complete` and the reopen judgment. An upstream naming
  another branch, as git sets when a line is cut from `origin/main`, is
  never read for the line. A local branch behind the fetched line never
  decides. One ahead of it is still honoured by `work next`, `work start`
  and a reopen's completion, and is named in full (`refs/heads/<name>`), as
  is a local branch where nothing of that name is fetched. `work claim`
  cuts from the fetched tip and refuses, naming both commits, when the
  local branch holds commits the fetched line lacks. A copy of a
  predecessor branch behind its reviewed pin is accepted by `work claim
  --on` and the push check; a copy ahead of the pin or diverged from it
  still refuses, naming its shape. A diverged target names both commits
  and a remedy that runs under the guard. A failed review lookup names its
  cause (no pull request, authentication or network) and the provider's
  redacted message. A reopen reason is written as a quoted scalar, so any
  text reads back as written.
