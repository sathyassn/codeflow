### Changed

<!-- codeflow:release-impact minor -->
- **A push gets its verdict sooner, and the hook says where the time went.**
  The pre-push hook runs its own ref rules before any `codeflow ci` and
  stops at the first refusal: a refusal skips the later branches' checks
  and the release preflight, and the output says what did not run. Each
  `codeflow ci` it runs still runs every check, so the hook reports the
  same findings CI does. A push that passes runs every check, as before.
  `codeflow ci --timings` prints the time each check took, and a push over
  its budget names the slowest step and, for a `codeflow ci` step, its
  three slowest checks. The budget is the
  new policy key `git.push_budget_seconds` (default 60, a whole number of at
  least 1), read from the default branch's committed policy; it only
  reports and never refuses a push. The record checks read each record once
  per commit instead of once per record they judge, parse each record file
  once per run however many revisions hold it, and the workgraph validation
  reads the merge history once instead of once per completed standalone
  task, so a records-only push spends much less time in `codeflow ci`.
