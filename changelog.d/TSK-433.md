### Fixed

<!-- codeflow:release-impact patch -->
- **An epic line's pull request into `main` judges the line's own
  completions as its own.** A task of the line that was completed,
  reopened and completed again inside its own pull request, with a
  criteria change, now binds at its line landing, as the task pull request
  into the line was judged. Before, the line's own tip, which is the head
  of the range, counted as a target the run is not judged against, and
  every such task was refused twice. The same holds for a task of another
  verified epic line that joined the judged line and whose tip the range
  head contains. A line tip beyond the range head, a joined line that fails
  the epic-line proof, a task that targets `main`, a forged completion and
  a record changed after its landing are still refused.
- **Acceptance findings say what they compared.** A finding about changes
  after a task's reviewed commit now reads "2 paths changed between the
  reviewed commit `<R>` and `<at>`, first: `<path>`", so a large count from a
  sync merge is visible. When `codeflow ci` runs without a pull request body
  on an `integration/` line that fails the epic-line proof, it prints the
  reason once, and a finding about a completion bound at the range head
  names "the range head `<sha>`" instead of "the completion". Update any
  script that matches the old "`<path>` changed after the reviewed commit"
  wording.
