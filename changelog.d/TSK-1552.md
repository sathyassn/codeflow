### Fixed

<!-- codeflow:release-impact patch -->
- **The present-browser test reports a browser that does not start.** When
  Firefox or WebKit failed to start in the present runtime's browser check,
  the target waited out Playwright's launch timeout and failed with a bare
  timeout. The browser check now starts Firefox and WebKit through one
  launch step that, on a failed start, names the browser build, the macOS
  version and the launch log, with the start error first. The WebKit
  version is read from the framework's Info.plist, the message reads are
  bounded and fall back to the engine, log and cause, and a cleanup failure
  is reported with the start failure, after it. The browser still does not
  start on hosts where it did not start before; the target now says so
  plainly.
