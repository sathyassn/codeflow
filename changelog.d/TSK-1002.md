### Fixed

<!-- codeflow:release-impact patch -->
- **The guards refuse every spelling of a checkout write or secret read.**
  They refuse checkout writes and secret reads hidden by shell
  substitutions, variables, links, file options or executable input, and
  check ignored names and recursive copy, search and archive inputs
  conservatively. Executable inputs and path selections the guards cannot
  verify are refused, with a remedy for narrowing search roots or selected
  files. A shell construct the guards read only in part, such as a
  directory change inside a command substitution or a glob after a
  directory change they cannot follow, is refused as cannot-verify. A Git
  list on stdin is read only from literal input, one name per line, so a
  path list piped from a program or separated by NUL is refused; Git
  pathspec magic (`':!docs'`) and a quoted pathspec glob a secret name
  could match (`git diff -- '*.rs'`) are refused; name the paths instead.
  A Git line that sets a `GIT_*` variable the guards do not classify,
  such as `GIT_WORK_TREE` or `GIT_CONFIG_COUNT`, or a `--git-dir` or
  `--work-tree` other than the repository's own, is refused; a program
  in `GIT_PAGER`, `GIT_EDITOR` or `GIT_EXTERNAL_DIFF` is judged as a
  command,
  and so is a Git object named by id or tag that is not a commit
  (`git cat-file -p 7898192`); name it as `REV:PATH` instead.
  Ordinary resolved writes, literal data, public file globs and home
  metadata commands stay available; explicit NUL-delimited xargs streams
  keep Windows filenames, and unmapped Windows path spellings are refused.
  What a program does once it runs, such as a file the line wrote, is not
  promised by these text checks; it is left to the sandbox.
