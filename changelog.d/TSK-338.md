<!-- codeflow:release-impact patch -->
- **A first adoption pushes and completes in its own pull request.** When a
  repository's default branch already exists without `.codeflow/policy.json`,
  as a new hosted repository's "Initial commit" does, the adoption task
  branch now passes the pre-push hook, `task status complete` and
  `codeflow ci`. Until the policy lands, release branches are named by the
  built-in pattern `integration/release-*`, as for a remote with no default
  branch yet. This applies only when no commit in the default branch's
  history has carried a policy. A policy that was there and was removed
  still refuses, and so does a clone that cannot prove the absence because
  it is shallow, grafted, replaced or missing objects (issue 182).
