### Changed

<!-- codeflow:release-impact minor -->
- **Review runs at four stages and each guidance rule has one home.** The
  managed rules now review at plan settlement (epics only), PR ready, the
  hand-resolved hunks of a landing candidate and epic close. Between stages
  the finder confirms a fix on the delta, and one final holistic pass comes
  before approval. A class fix gets a sibling sweep before its first
  review. A security change gets one other-lineage review that uses the
  security checklist. The routing policy drops the complexity and depth
  triggers. `cf-reviewer` runs only when no other-lineage seat exists.
  Planned work has a stated pace, owned by the `cf-method` workflow
  lifecycle reference: at least one task per build lane per hour, preferably
  two. The push rule is now one push at ready. Batch landing, the plain
  writing rule and the delivery flow each have one home, and findings live
  in one record linked from the PR. `codeflow doctor --preflight` prints the
  seat, sandbox and tool evidence the orchestrator preflight reads, each
  value marked configured, observed or unavailable. `codeflow update`
  rewrites the managed block, rules, skills and agents.
