### Fixed

<!-- codeflow:release-impact patch -->
- **The guard opens each repository once per hook call for ordinary
  paths.** Exec-guard checks every word of the code a nested shell runs
  (`bash <<< ...`, `bash <(...)`, `... | bash`, `source <(...)`) from every
  directory the line may run in, and each check opened the owning
  repository again. The guard now keeps a repository's successful reading
  for the rest of the hook call and reuses it for words that cannot name
  that repository's enforcement files. A path that could name them, and
  any lookup after a failed open, still opens the repository again, so a
  repository that is broken or changes during the call is refused as
  before. No verdict changes.

<!-- codeflow:release-impact patch -->
- **Git-guard reads each line once per hook call.** For every segment of a
  line, git-guard read the whole line again: to learn whether it names
  `RIPGREP_CONFIG_PATH`, which literals it assigns, how each command's
  words are quoted, and which path words it holds. It now keeps each of
  these readings for the rest of the hook call. No verdict changes.
