- **The guards judge a command a program runs from an option value as the
  same command written bare.** New refusals: when a program the guards
  know runs a command given as one of its option values, git-guard and
  exec-guard now give that command the verdict and the rule it gets
  written on its own, at the project's configured levels, so a command the
  project refuses is refused there too. Both guards read these values from
  one inventory in the code, and a test keeps the documented list equal
  to it. An option value written in a command language the guards do not
  read, such as an editor's own commands, and a build tool setting that
  names a program the tool runs, are refused under `git.hook_integrity`;
  a value that only opens the file at a line number passes. An abbreviated
  or differently cased spelling of such an option is refused under the
  same rule. The build tool's settings are judged by their decoded names,
  so an ordinary setting passes whatever its value, and an environment
  setting gets the verdict of the same variable assigned before the tool.
  The way through: edit files with the harness's file tool, set such a
  program in the project's committed build configuration, and write the
  option's full documented name. Ordinary values that run an ordinary
  command keep today's verdict. A command a program reads from its own
  configuration files or environment is not read this way.
