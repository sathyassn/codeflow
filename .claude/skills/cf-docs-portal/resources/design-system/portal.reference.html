How a change lands

Source AGENTS.md at 02908d5f3a1cgenerated 2026-09-22 14:10fresh

Two landing paths

A change reaches main by one of two paths. A person makes the last step on both.

What holds on both paths

  • A single task ships as one pull request.
  • A body of work lands on integration/<epic> first, so each review stays small.
  • A red required check stops travel on either path.
  • Agents never push, merge or reset a protected branch.

Records: CAP-016 describes this guide; EPC-016 rebuilds it.

Four enforcement planes

Four planes check the same policy at different moments.

What each plane reads

  • Git hooks and the session git-guard read .codeflow/policy.json before a commit or push goes through.
  • CI runs the same rules as the shared codeflow ci checks.
  • The remote rules are derived from the same policy, as ADR-0017 records.

Installed files do not prove enforcement; verify hook execution, CI results and the remote rules.

What each plane checks

The grid shows which plane enforces which rule.

The policy lives in .codeflow/policy.json at the repository root. Hooks and CI read it through the same codeflow ci checks, so a rule changes in one place.

Start a task in a worktree

Three assertions come before the first mutation.

The commands for TSK-060:

git worktree list
git branch --show-current
git fetch origin
git worktree add .worktrees/tsk-060 -b task/TSK-060-portal-themes origin/main
codeflow work start TSK-060
  • Wrong branch is the failure to prevent.
  • New work starts off the current tip unless the task pins a base.

When a gate blocks

A blocked change has one route: fix the cause, then continue.

  • Never use --no-verify, edit hooks or export gate tokens.
  • An unfinished CI job is missing evidence, not a failure.
  • Push the branch after each committed unit so work survives a machine failure.

Commit message limits

The rules are lengths and a shape.

feat(portal): add display panel

- add font, size, palette and appearance pills
- apply stored choices before first paint
- keep palette controls out of the header

A breaking change adds ! after the type, as in feat!:, and ends with a BREAKING CHANGE: footer that explains the migration.
