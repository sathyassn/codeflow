### Release-automation changes since 3.0.0

- Pending entries live in `changelog.d/` fragments until `assemble` folds
  them into `CHANGELOG.md` (ADR-0082).
- `main` requires branches to be up to date before merge (ADR-0081); any
  landing after the candidate forces a new merge, a new assembly and a new
  review.
- The release workflow has a `windows` verdict job, and a gate run on the same
  tree is reused instead of repeated (`scripts/windows-partitions.py`,
  `scripts/ci-reuse.py`).
- Every job in every workflow carries a timeout, enforced by
  `scripts/gate-parity.py` (TSK-254).

Hosted token and event delivery, draft, tag, upload and announce, the public
digest verification and the platform builds are not executed before the
dispatch. They stay open checklist items.
