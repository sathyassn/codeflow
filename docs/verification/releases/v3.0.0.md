## Security and public-history boundary

A fresh authenticated remote mirror at CodeFlow main `d1f3e074` contained 815
refs and 2,627 unique commits. Its current main tree excluded runtime state, but
historical `.state/**`, `.claude/memory/**`, and `*.profraw` objects remained
reachable from main, branch, and hosted PR refs. A configured all-ref Gitleaks
8.30.1 scan found no secret, while a raw scan produced 52 fully classified
fixture/prose findings and no unknown credential. Ref, inventory, and redacted
report SHA-256 digests are respectively:

- `01ff7a89c3d3a3ddbb6996e070fa55ad2208a02517871a5da56bb33624b36f2e`
- `83d7e47822c8adfac4725a4608f47110069d577538c8219b70637ddd4ad38d95`
- `95f4c027f40baee2c20b9fae511f7d010205bfd03efe20006131cc75ce5ad4b8`

The existing CodeFlow remote is therefore not approved for an in-place public
visibility change. The safest path is a new sanitized public repository from
selected clean refs while the original remains a sealed private archive.
History rewrite, repository creation, visibility changes, force-pushes, and
hosted-cache deletion require explicit operator authorization. Root-only ignore
rules and a tracked-tree test prevent recurrence without imposing CodeFlow's
runtime paths on consumers.
