# CodeFlow v3.0.0 pending-source command envelope

This is the repeatable local and cross-build envelope for the reviewed source
that currently carries the undated `3.0.0` pending section. It does not create
or imply a tag, release, installer, native-platform result, or publication
approval. Record the final commit and tool versions when the commands run; do
not reuse results from an earlier source snapshot.

## Release-state and repository checks

~~~sh
set -e
test -z "$(git status --porcelain)"
source_sha=$(git rev-parse HEAD)

python3 scripts/test_release.py
python3 -m coverage run --branch scripts/test_release.py
python3 -m coverage report -m scripts/release.py
python3 scripts/release.py check-state --ref "$source_sha" \
  --repository sathyassn/codeflow

cargo dist generate --mode ci --check
cargo dist plan --output-format=json > /tmp/codeflow-v3-dist-plan.json
jq -e '
  .announcement_tag == "v3.0.0"
  and (.releases[0].artifacts | index("codeflow-cli-aarch64-apple-darwin.tar.xz") != null)
  and (.releases[0].artifacts | index("codeflow-cli-x86_64-apple-darwin.tar.xz") != null)
  and (.releases[0].artifacts | index("codeflow-cli-x86_64-unknown-linux-gnu.tar.xz") != null)
  and (.releases[0].artifacts | index("codeflow-cli-installer.sh") != null)
  and (.releases[0].artifacts | map(select(test("windows|\\.ps1$"))) | length == 0)
' /tmp/codeflow-v3-dist-plan.json >/dev/null

codeflow test --mode full --strict
codeflow validate --docs
cargo audit
gitleaks git . --config .gitleaks.toml --log-opts="--all" \
  --redact --no-banner
~~~

The release-state check reads GitHub releases and tags through the authenticated
`gh` client. A checked-in `--host-state` fixture is for offline tests only; it
is not publication evidence. The latest stable public release must have an
exact source marker and asset digests. Drafts, prereleases, unresolved tags,
and partial attempts do not advance the baseline.

## Cross-build and native boundary

~~~sh
cargo xwin check --workspace --target x86_64-pc-windows-msvc
cargo xwin build --workspace --release --target x86_64-pc-windows-msvc
cargo zigbuild --workspace --release --target x86_64-unknown-linux-gnu
cargo build --workspace --release
test "$(target/release/codeflow --version)" = "codeflow 3.0.0"
~~~

Record cargo-xwin, cargo-zigbuild, Zig, Rust, host OS, and architecture beside
the result. 3.0.0 publishes no Windows target, so the `cargo xwin` lines are
optional evidence for TSK-197, not a 3.0.0 gate. These commands prove static
analysis, compilation, and linking; they do not replace native macOS, Linux,
Windows, WSL2, or installer canaries.

## Consumer canaries

Use the final release binary in disposable greenfield and v2.1 brownfield
repositories. Run initialization/update twice, validation, repository-integrity,
managed-drift, model-binding, and test-config diagnostics. Preserve hashes for
owner README/product content and an instruction outside the managed AGENTS
region. Confirm the second run is idempotent and that non-adopters receive no
portal or presentation runtime.

The compatible `cf-ship` starter also needs disposable new-project, adopted
tooling, independent version-domain, and ambiguous/non-SemVer diagnostics. It
must never date the source CHANGELOG section, add a post-publication cut commit,
or treat CodeFlow scaffold metadata as the consumer product version.

## Publication boundary

After the final ordinary work PR is human-merged and every checklist item has
current evidence, a human may dispatch cargo-dist's generated Release workflow
for `v3.0.0` with `--ref main`. No command in this envelope performs that
dispatch. Never create or move a tag, overwrite an asset, reuse a public
version, or turn an unresolved partial attempt into a different release.
