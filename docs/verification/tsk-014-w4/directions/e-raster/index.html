Pre-rendered raster through the existing media block

No contract change at all. The agent renders its own figure out of band and embeds a bounded PNG. This is what the product can do today, and it is on the board because a direction that costs nothing deserves to be beaten on the evidence rather than assumed away.

The image below was produced by tools/build-raster.mjs, which opens direction B, screenshots its first figure at 1440px in light mode at 2×, and pastes the bytes in. That is exactly the sequence an agent would have to run.

The plan, as a picture of a plan

What it cannot express

Everything below is a property of the bytes, not an opinion about them. Each one is measured on this page at load.

The narrow context

At 390px the image is scaled to fit. Nothing recomposes, because there is nothing to recompose: the composition is a grid of pixels laid out for a 1440px frame. Compare this render at the narrow viewport with direction B's, where the narrow band is a different scene.

The dark context

The figure stays light in dark mode. It cannot do otherwise — the mode was resolved once, in another process, before the reader's preference existed.

The accessible equivalent

An alt string, and nothing else. There is no structure to traverse, no text to select or search, no state to key, and nothing a screen reader can enter. The media block's own contract caps that string at 4 KiB, which is where the entire accessible account of the figure has to fit.
