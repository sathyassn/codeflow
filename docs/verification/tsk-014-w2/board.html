Implementation feasibility

What each encoding would cost inside the accepted document contract. Basis: the closed block catalogue in .codeflow/schemas/present/document-v1.schema.json — narrative, bullets, callout, comparison, decision, table, status, code, diff, tree, diagram, media, disclosure, tabs, feedback_prompt, html — with SPC-004 §2 (block catalogue), §11 (one sandboxed HTML escape, no component SDK) and the diagram.kind enum flowchart, sequence, timeline, state, class, entity_relationship, mindmap. This annotation lives here, in the neutral record, and never inside a candidate.

CandidateVerdictBasis
p1-a wave lanesneeds one new typed block No block carries typed nodes and edges with derived lanes. diagram renders Mermaid source, which cannot express readiness waves, stream lanes, chain membership or room, and tree is single-parent only.
p1-b blocking matrixexpressible today table carries the rows, columns and derived cells; the sticky identity columns and overflow cue are renderer behaviour, not schema.
p1-c critical ribbonneeds one new typed block Bars positioned across a wave axis with earliest/latest extents have no equivalent; diagram.kind: timeline is a Mermaid timeline, not a slack-bearing schedule, and a table loses the positional encoding that carries the whole reading.
p2-a evidence gridexpressible today table plus per-cell text; the four cell states are content, and the absence shading is a renderer style over an existing state value.
p2-b provenance railneeds one new typed block A per-claim rail with a travelled extent, a stopping point and untravelled remainder has no analogue. tree cannot express a stop, and status is a flat item list. The sandboxed html escape could carry it, but SPC-004 §11 scopes that to one session-local escape, not a reusable evidence form.
p3-a finding-anchored deltaneeds one new typed block diff carries one raw unified-diff string plus an optional caption — no per-hunk annotation, no verdict state, no round marker, and no way to bind a finding to the region it concerns. code has the same shape. A table placed beside a diff would separate every annotation from the region it judges, which is the entire encoding.
p3-b convergence ledgerexpressible today, with the transitions flattened table carries findings × rounds and derived cell text, so "re-opened, answers R5" survives as words, and the off-axis origin is just one more column with a header. What does not survive is the drawing: the return arcs, and the dashed arrival entering the round a cause landed in, are renderer geometry with no schema equivalent. columns being a flat array of strings also flattens the rounds / not a round spanning header, so the one column deliberately off the axis reads as another round. Without those, the difference between answered and merely extended — and between a self-caused and an outside re-opening — stops being visible and has to be read. The secondary diffs fit disclosure wrapping diff.
d1-a concept dependency pathexpressible today — as the baseline it is measured against One narrative of nested Markdown carries the chain, and nesting supplies indentation. But tree_node is label plus children with no detail field, so the per-concept quotation and the right-hand unlocks column both collapse into ordinary nested prose — which is the ordinary-Markdown baseline. Expressible, and expressible only by giving up what distinguishes it.
d1-b task-first entrypartly expressible today diagram.kind: flowchart is Mermaid and can carry the path-with-refusal-branches topology directly. It cannot carry the fan's six verbatim error strings, the first-versus-repeat distinction, or the typographic weight that makes the widest branch the answer; those would fall back to a table, splitting one composition into two blocks.
d1-c contract mapexpressible today, with the zone header flattened table carries rules × planes, the marks and the refuses column; the boundary division, the hatched unarmed column and the narrow re-wrap that keeps all five plane cells with each rule are renderer behaviour over the same block and the same cell values. columns is a flat array of strings with no column-group, so the feedback / perimeter spanning header — the thing that makes the boundary a boundary rather than a border — has to be folded into each column label, and it is the only part of this encoding the contract cannot carry.
d2-a chain in placeneeds one new typed block No block carries a claim with a per-authority reach extent. comparison takes 2–4 independent columns of Markdown, not brackets over one claim; status is a flat item list. disclosure does supply the progressive part. The bracket extent — reach shown rather than asserted — has no analogue.
d2-b evidence-adjacent marginexpressible today at material loss A two-column table row-aligns each claim with its artifact, which is the adjacency. What it cannot do is render reserved empty space: an unbacked claim becomes an empty cell, indistinguishable from a cell nobody filled in, and the record's own prose stops reading as prose. comparison is worse — its columns are independent lists with no row alignment at all.

Feasibility is not visual approval. A verdict of expressible today says only that the accepted contract could carry the encoding; it says nothing about whether the encoding communicates, which is what G1–G8 exist to test and what the operator decides.
